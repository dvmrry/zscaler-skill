The ZCC provider is a Plugin Framework provider whose forwarding profile resource round-trips a large nested object through a hand-written expand function (plan to request) and flatten function (response to state). Most defects here come from the two halves disagreeing: a setting that can be read but not written, or one that is written but never read. The request type posted by the SDK is a separate struct from the response type, and nothing forces them to list the same fields.

Settings that Terraform accepts but never sends. Each of these is Optional and Computed, so a configured value is accepted and the API's answer is written back to state. {{action-fields-exposed-and-read}} {{tunnel-fields-exposed-and-read}} {{action-fields-never-sent}} {{tunnel-fields-never-sent}} {{trusted-network-lists-read-only}} {{configured-values-silently-ignored}} When one of these attributes shows a perpetual diff, or a setting you configured has no effect on the client, check the request type first. Zero-value clears on the fields that are sent are in [[shared.sdk-go.zero-value-writes]].

Settings the provider hides from drift. The provider restores some fields from prior state because its comments say the API drops them (for web privacy the fields are still sent; only the read-back is replaced). That keeps plans quiet, but it also means a real change made in the console is never shown. {{zpa-latency-overlay-masks-drift}} {{unified-tunnel-overlay-covers-every-attribute}} {{prior-state-overlays-elsewhere}} The data sources have no such restoring step, and report false for `evaluate_trusted_network`, `enforce_secure_pac_urls` and `enable_fqdn_match_for_vpn_bypasses`. {{data-sources-report-false-for-dropped-fields}} {{strict-versus-lenient-boolean-strings}} Do not use a ZCC data source's boolean as a policy input for the fields named above without confirming it against the resource or a raw API read.

Errors that look like absence or success. {{failopen-read-error-removes-state}} {{create-ignores-success-flag}} {{create-can-adopt-same-name-profile}} After a failed refresh of the fail-open policy, confirm the policy still exists in the console before trusting a plan that proposes to create it. Reads removed because an ID is outside the first page of a list are in [[shared.sdk-go.list-pagination]].

Blocks that collapse. {{duplicate-network-type-collapses}} {{duplicate-network-type-not-rejected}} Keep `network_type` unique in each block list.

Defects on the SDK side. {{intorstring-truncates-fractions}} {{trusted-network-create-sleeps-blindly}} {{emergency-access-create-clears-activate-now}} {{sdk-defects-reach}} The trusted-network sleep is reachable from the provider at the pin on v1-API tenants; the other two are not reached by either provider's resources. Legacy-client routing for the same package is in [[zcc.sdk-go.legacy-routing]]; ZIA's equivalent field-fidelity mechanisms are in [[zia.terraform.field-fidelity]].

Not established: whether the ZCC v2 create and update responses carry every field, since the trusted network resource builds state from them without a re-read (gap partial-create-update-response).
