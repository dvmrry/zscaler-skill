# Shadow IT Report (also SaaS Security Report, ZINS): shadow IT discovery, risk index and API surface (portfolio.saas-security-report)
Also called: saas security report; shadow it; shadow it report; shadow it discovery; shadow it summary; zins; z-insights; zinsights; saas security; sanctioned apps; unsanctioned apps

The report's own page, which calls it Shadow IT, breaks applications down by status, sanctioned, unsanctioned, unclassified or under review, and by their number of users. [portfolio.saas-security-report:ssr-what] Zscaler says the report supports up to 50K cloud applications. [portfolio.saas-security-report:ssr-scale] Its listed benefits include discovering and managing shadow IT applications used by the organization's users, departments or locations, and scrutinizing applications across multiple risk attributes. [portfolio.saas-security-report:ssr-features]

Each application carries a risk index from 1 (lowest risk) to 5 (highest risk). [portfolio.saas-security-report:ssr-risk-index] The Zscaler-computed index is unavailable for custom cloud applications [portfolio.saas-security-report:appinfo-risk-override]. The report can show the last 1 day, 7 days, 15 days, month or quarter, and its default period is the last 7 days. [portfolio.saas-security-report:ssr-default-period]

The report's page is at Data Security > Inline CASB > Shadow IT. [portfolio.saas-security-report:ssr-path] The report can be scheduled daily, weekly or monthly, and downloaded as a CSV file; scheduled reports are managed on the Scheduled Reports page under Analytics > Reports > Interactive Reports. [portfolio.saas-security-report:ssr-export]

**Application Information page.** The Application Information page shows information on the specific application selected on the Shadow IT page. [portfolio.saas-security-report:appinfo-shadow-it-page] On the Application Information page the Zscaler-computed risk index (1-5, 1 the lowest risk and 5 the highest) can be altered and overridden with the Edit icon; the Zscaler-computed index is unavailable for custom cloud applications, whose risk index can nevertheless be edited or reset. [portfolio.saas-security-report:appinfo-risk-override] The Application Information page's Application Status is sanctioned, unsanctioned, unclassified or under review. [portfolio.saas-security-report:appinfo-status-values] The total bytes shown might not equal the sum of upload and download bytes, because the uploaded and downloaded bytes distribution data might not be available for the Web Search application. [portfolio.saas-security-report:appinfo-bytes-caveat] The Users table shows data for up to 1,000 entries and Download CSV file gives the data for all entries; the Location table shows unauthenticated location-specific data for the application and is visible only for reports generated by the Zscaler service. [portfolio.saas-security-report:appinfo-1000-rows] Policies Applied lists all the policies configured specifically for the application in the Zscaler Admin Console and stays blank if none are configured for it. [portfolio.saas-security-report:appinfo-policies-applied] For data to be populated the application must have at least one integration (Risk Attributes > Basic Information); the Risk Attributes and 3rd-Party Integrations information is unavailable for custom cloud applications; and seeing more needs an Internet & SaaS (ZIA) super admin in an organization that has Zscaler 3rd-Party App Governance. [portfolio.saas-security-report:appinfo-3p-integrations] The attribute values it shows from 3rd-Party App Governance are in [Cloud Application Risk Profiles in Cloud App Control](kb:zia.cloud-app-control.risk-profiles).

IoT device visibility is in the IoT Report, not this one: The Internet of Things (IoT) Report shows the device inventory and its insights discovered from unauthenticated web traffic. [portfolio.saas-security-report:ssr-iot-report] [gap:portfolio.saas-security-report:ssr-iot]. Whether it is powered by ZIA traffic is open [gap:portfolio.saas-security-report:ssr-zia]. Whether it is observability only, with no enforcement, is open [gap:portfolio.saas-security-report:ssr-enforcement].

The Analytics API's production GraphQL endpoint is `https://api.zsapi.net/zins/graphql`, and the API can be accessed via the OneAPI gateway. [portfolio.saas-security-report:ssr-endpoint] The vendored Python SDK's ShadowItAPI client targets the Z-Insights SHADOW_IT domain and posts to `/zins/graphql`. [portfolio.saas-security-report:ssr-sdk] The GraphQL API itself, its auth and its scope are in [The Analytics (Z-Insights) GraphQL API: endpoint, access and scope](kb:shared.analytics.graphql).

The legacy statement that neither SDK has a zins namespace is contradicted for Python [gap:portfolio.saas-security-report:ssr-no-sdk]. [divergence:portfolio.saas-security-report:report-name] The rename history is not captured [gap:portfolio.saas-security-report:ssr-rename]. The 8,500-app figure in older marketing is in no capture [gap:portfolio.saas-security-report:ssr-8500]. [portfolio.saas-security-report:ssr-scale]

What to check:
1. Before comparing shadow IT counts, confirm the time period and filters; the default period is the last 7 days.
2. For an API question, check the zins package and the GraphQL endpoint before saying there is no SDK; the Python SDK has one.

Sources disagree (name both sides):
- The report's own page and the audit-log page call it the Shadow IT Report, while the NSS page still says SaaS Security Report; whether they mean the same report is not stated. The Gen AI, Posture Management, 3rd-Party App Governance and Activities pages also use SaaS Security Report, as a container for other pages. [divergence:portfolio.saas-security-report:report-name]
  - zscaler-help: The report's own page names it the Shadow IT Report.
  - zscaler-help: Audit logs name the report the Shadow IT Report.
  - zscaler-help: The NSS page still names a SaaS Security Report.
  - zscaler-help: The Gen AI Security Report page places the Application Information page in the SaaS Security Report.
  - zscaler-help: The Application Information page says it is opened from the Shadow IT page.
  - zscaler-help: The Posture Management page gives its path as Analytics > Reports > SaaS Security Report > Posture Management.
  - zscaler-help: The 3rd-Party App Governance Report page gives its path as Analytics > Reports > SaaS Security Report > 3rd-Party App Governance.
  - zscaler-help: The Activities page calls itself a page within the SaaS Security Report page and also gives its path as Data Security > DSPM > Activities.
  Impact: Searching documentation or audit logs by one name may miss material recorded under the other, and the pages use SaaS Security Report both for the Shadow IT report and as a container for posture, app governance, assets and activity pages, so an answer has to say which page it means.
