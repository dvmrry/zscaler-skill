# Incidents in Agentic SOC: the Incidents page, detail tabs, verdicts, statuses, custom incidents and customization (soc-workbench.incidents)

The Incidents page table displays columns by default, including ID, Severity, Type, Title, Created, Alerts Count, Sources, Assignee, Status and Verdict. [soc-workbench.incidents:page-columns] From the Incidents page you can modify multiple incidents at once (for example updating the status, merging incidents and adding comments), save a view, export the table to a CSV file, and see the number of incidents by status, severity and verdict as charts. [soc-workbench.incidents:page-actions] Incidents can also be created by hand from alerts [soc-workbench.incidents:custom-incident]; the alerts are in [Alerts in Agentic SOC: the Alerts page, severity score composition, alert-score factors and severity categories](kb:soc-workbench.alerts) and the rules that group alerts into incidents in [Incident rules that group alerts into incidents, and incident workflows, in Agentic SOC](kb:soc-workbench.incident-rules). [soc-workbench.incidents:detail-tabs]

**Detail page.** An incident's detail page has tabs Details, Affected Entities, Timeline, Attack Path (events overlaid on the MITRE ATT&CK matrix), Analysis (leads explored by the Investigation Agent), Alerts (the alerts and sources the Enrichment and Correlation Agents used to create the incident), Activity (an audit log) and Comments. [soc-workbench.incidents:detail-tabs] Agentic SOC provides a default view of alert and incident details that you can customize (the default configuration) or supplement by creating new configurations, selecting Incident from the Entity drop-down menu. A tab's Type is Fields, 2 Columns, Text or Table, and Save keeps the existing configuration while Save as New Type saves a new one. [soc-workbench.incidents:customize-detail-pages]

**Verdicts and statuses.** The Taking Action on Incidents page lists six verdicts that analysts and agents can set: Benign, False Positive, Inconclusive, Malicious, Suspicious and True Positive. The verdict is in the top-left region of the Incident Detail page. [soc-workbench.incidents:verdicts] The Taking Action on Incidents page lists these statuses that analysts and AI agents can set: Discovered, Opened, Acknowledged, Not Remediated (with the reasons Testing, False Positive and Authorized Activity), Confirmed and Closed. Confirmed means the incident is closed and the assigned verdict is confirmed correct; Closed means it is closed without passing judgment on the verdict. The status is in the top-right region of the Incident Detail page. [soc-workbench.incidents:statuses] Incident and alert statuses have a default set, and you can configure existing statuses (for example reorder and rename) and create new ones on the Statuses page, choosing Alert or Incident from the Entity Type drop-down menu. A new status is added within one of the existing buckets with Add Status, and when you add a bucket with Add Bucket, its Closed and Remediated options select whether the bucket automatically includes the status. [soc-workbench.incidents:status-customization] The statuses the Ready to Remediate and Remediated names refer to are not defined [gap:soc-workbench.incidents:status-definitions].

**Playbooks.** Playbooks are typically executed when an incident requires remediation, such as when the verdict is Malicious or the status is updated to Ready to Remediate, and the Threat Response Recommendation Agent suggests playbooks in the AI Response Actions section of the incident details view. Recommendations carry labels such as Success, Proposed or Failed, and when an execution partly succeeds or fails across entities, View shows each entity's execution status. [soc-workbench.incidents:playbook-recommendation]

**Custom incidents.** A custom incident is created from one or more alerts selected on the Alerts page by clicking Create Incident; the Create Incident from Alerts drawer takes a Severity, a Status, a Title (entered, or the one Agentic SOC generates automatically) and a Verdict. [soc-workbench.incidents:custom-incident] The Creating a Custom Incident page gives the example statuses Discovered, Remediated and Confirmed and the example verdicts Accepted, Executed and Partial for the drawer's drop-downs, while the Taking Action on Incidents page has its own lists of verdicts and statuses that analysts and agents can set. [soc-workbench.incidents:custom-incident-examples] The Taking Action on Incidents page names the status Ready to Remediate in its playbook paragraph, while its own list of statuses that analysts and AI agents can set does not include it. [soc-workbench.incidents:ready-to-remediate-scope] How the drawer's examples relate to the lists is open [gap:soc-workbench.incidents:drawer-example-values].
