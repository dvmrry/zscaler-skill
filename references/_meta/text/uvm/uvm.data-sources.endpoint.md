# UVM endpoint, Microsoft and vulnerability-scanner data sources: CrowdStrike, Defender for Endpoint, Entra ID, Intune, Qualys, Rapid7 and Tenable connectors (uvm.data-sources.endpoint)

See [UVM data sources: shared connector facts, availability, and the Jira, Zscaler, Okta, Code42, NetBox, runZero, SecurityScorecard and SFTP connectors](kb:uvm.data-sources) and [Unified Vulnerability Management (UVM): what it does with findings, and what can be automated](kb:uvm.overview).

**CrowdStrike.** The CrowdStrike connector has 5 streams: Vulnerabilities, Managed Hosts, Environmental Assets, Incidents and Alerts; Incidents and Alerts data is used to enrich Vulnerabilities and Assets data. [uvm.data-sources.endpoint:cs-streams] CrowdStrike CSPM and CrowdStrike Identity Protection are separate connectors from the CrowdStrike connector, each with its own page. [uvm.data-sources.endpoint:cs-separate-connectors] Creating the CrowdStrike API keys needs the Falcon Administrator role; the CrowdStrike, CrowdStrike CSPM and CrowdStrike Identity Protection pages say so for the client ID and secret, and the Falcon Insights page says a Falcon Administrator role or the correct permissions. [uvm.data-sources.endpoint:cs-falcon-admin] The Assets Types menu offers Hosts and IoT; by default both are retrieved. [uvm.data-sources.endpoint:cs-assets-types] On the CrowdStrike connector the cloud region menu (CrowdStrike Managed Hosts stream) lists US1, US2, EU1, USGOV1 and USGOV2 with their base URLs, and defaults to US1 if unselected. [uvm.data-sources.endpoint:cs-cloud-regions-crowdstrike] On the CrowdStrike page, the API scopes visible when creating keys depend on the products the organization is subscribed to and the cloud region, and the page says a discrepancy suggests the connector might not be compatible with the current CrowdStrike configuration. [uvm.data-sources.endpoint:cs-scope-visibility] Among the CrowdStrike options are a Product drop-down menu (EPP, IDP, Mobile, XDR, Overwatch and CWPP, defaulting to All Products) and a Split Finding by Apps checkbox that separates records containing more than one app into individual entries. [uvm.data-sources.endpoint:cs-stream-filters]

**CrowdStrike CSPM and Identity Protection.** The CrowdStrike CSPM connector has two streams, Indicators of Misconfiguration (IOM) and Indicators of Attack (IOA); the API client needs the Read scope for CSPM Registration, and the Cloud Provider menu selects AWS, Azure or GCP. [uvm.data-sources.endpoint:cs-cspm-streams] The CrowdStrike Identity Protection connector has two streams, Security Assessment and Domain Users; the API client needs Identity Protection Assessment Read, Identity Protection GraphQL Write and Identity Protection Entities Read (for domain users). [uvm.data-sources.endpoint:cs-idp-streams] A checkbox on the CrowdStrike Identity Protection page is available in the CrowdStrike Identity Protection Security Assessment stream. [uvm.data-sources.endpoint:cs-idp-ad-filter]

**CrowdStrike Falcon Insights.** The CrowdStrike Falcon Insights connector retrieves raw telemetry, system events and alerts for the Agentic SOC application, and requires active Internet & SaaS (ZIA) and Agentic SOC accounts plus an active Falcon Data Replicator add-on subscription from CrowdStrike. [uvm.data-sources.endpoint:cs-falcon-insights-scope] Falcon Data Replicator forwards CrowdStrike data to an S3 bucket; the feed's default settings should not be changed because that can leave Agentic SOC without the data needed for threat analysis. [uvm.data-sources.endpoint:cs-fdr-feed] The Falcon Insights API client needs the scopes Alerts Read and Write, Detections Read and Write, Hosts Read and Write, Host Groups Read, NGSIEM Read and Write, and Threatgraph Read. [uvm.data-sources.endpoint:cs-fdr-api-scopes] Agentic SOC supports multi-CID CrowdStrike accounts where each CID has its own FDR feed and S3 bucket, cannot support an aggregated FDR feed for multi-CID accounts, and needs a separate Falcon Insights connector for each CID. [uvm.data-sources.endpoint:cs-multi-cid] The Falcon Insights Cloud Region menu lists US1, US2, EU1 and USGOV1 with their base URLs. [uvm.data-sources.endpoint:cs-falcon-regions] Whether Falcon Insights supports a USGOV2 region is open [gap:uvm.data-sources.endpoint:falcon-insights-usgov2].

**Microsoft Defender for Endpoint.** The Microsoft Defender for Endpoint connector has 5 streams (Assets, Vulnerabilities, Software Vulnerabilities by Machine, Alerts, Incidents), chosen by feature plan and use case, and they retrieve endpoint data only. [uvm.data-sources.endpoint:defender-streams] Defender vulnerabilities can also be retrieved through Microsoft's Export API, which delivers the same data as the Vulnerabilities stream in a file-based bulk format; access is requested from the Zscaler Account team or Zscaler Support. [uvm.data-sources.endpoint:defender-export-api] For Defender for Endpoint, the Incidents stream uses the Microsoft Threat Protection API, while the Vulnerabilities, Alerts, Assets and Software Vulnerabilities by Machine streams use the WindowsDefenderATP API; Application or Delegated permissions are added to the app registration and consent is granted for each permission. [uvm.data-sources.endpoint:defender-api-by-stream] The Defender page lists, under the WindowsDefenderATP API, Machine.Read.All and Machine.ReadWrite.All (Application) and Machine.Read and Machine.ReadWrite (Delegated), and, under the Microsoft Threat Protection API, Incidents.Read.All and Incident.ReadWrite.All (Application) and Incident.Read and Incident.ReadWrite (Delegated). [uvm.data-sources.endpoint:defender-permissions] The Defender for Endpoint source can filter the ingested data by severity on the Vulnerabilities stream and filter out resolved incidents with a checkbox on the Incidents stream. [uvm.data-sources.endpoint:defender-filters] Defender for Endpoint authentication needs the Application (client) ID and Directory (tenant) ID, a client secret and a URL. [uvm.data-sources.endpoint:defender-auth-params]

**Microsoft Entra ID.** The Microsoft Entra ID connector is in limited availability; contact Zscaler Support to learn more. [uvm.data-sources.endpoint:entra-la] The Entra ID connector has 4 streams: Administrative Units, Applications, Devices, and Users & Groups. [uvm.data-sources.endpoint:entra-streams] The Entra ID connector needs Microsoft Graph application permissions: AdministrativeUnit.Read.All for Administrative Units, Application.Read.All for Applications, Device.Read.All for Devices, and User.Read.All for Users & Groups; a further Application row lists Group.Read.All with no stream named. [uvm.data-sources.endpoint:entra-permissions] Entra ID authentication needs a Client ID, Client Secret and Tenant ID; the client secret is created under App registrations > Certificates & secrets and the tenant ID is on the Properties tab of the Overview page. [uvm.data-sources.endpoint:entra-auth-params]

**Microsoft Intune.** The Microsoft Intune Assets stream retrieves Intune devices that are mapped to assets, and needs an active Microsoft Intune subscription on the tenant. [uvm.data-sources.endpoint:intune-assets-stream] For Intune Assets the app role is declared with allowed member type Applications and value DeviceManagementManagedDevices.Read.All, and the app role is created while signed in to the Microsoft Entra admin center as a Cloud Application Administrator or greater. [uvm.data-sources.endpoint:intune-assets-role] When adding the Intune Assets client secret, the page says to select a 24-month expiration, and the secret value is not displayed again after leaving the page. [uvm.data-sources.endpoint:intune-assets-secret] For an authorization error on Intune Assets after setup, assign the DeviceManagementManagedDevices.Read.All application permission on Microsoft Graph through the Microsoft APIs tab, then rerun the source with Process Now. [uvm.data-sources.endpoint:intune-assets-troubleshoot] For Intune Assets, an existing SecOps app for API can have the application roles assigned, and this does not apply to the SAML application. [uvm.data-sources.endpoint:intune-saml-note] The Intune Audit Events connector needs an active Intune feature plan for the Microsoft Graph API for Intune, its parameters include Directory (tenant) ID and Application (client) ID, and its permissions step selects the intune read role. [uvm.data-sources.endpoint:intune-audit]

**Qualys VMDR and PC.** The Qualys VMDR & PC connector has 3 streams: Assets (hosts data), Vulnerabilities (vulnerabilities and potential vulnerabilities categories) and Policy Compliance (compliance posture info records). [uvm.data-sources.endpoint:qualys-vmdr-streams] For Qualys VMDR & PC, Assets and Vulnerabilities use the API server URL as the platform URL and Policy Compliance uses the API gateway URL. [uvm.data-sources.endpoint:qualys-url-by-stream] The Qualys VMDR & PC user needs the Manage VM module for Vulnerabilities and Assets and the Manage PC module for Policy Compliance; Zscaler recommends a new user with the Scanner role. [uvm.data-sources.endpoint:qualys-permissions] The Qualys VMDR & PC page says that a connector that fails after creating a user with the specified permissions may need the user activation completed, which includes logging into the Qualys console with the new user's credentials. [uvm.data-sources.endpoint:qualys-activation] The Qualys VMDR & PC page has checkboxes to exclude vulnerabilities found on inactive kernels, vulnerabilities found on inactive ports and services, and vulnerabilities that are not exploitable due to the host configuration. [uvm.data-sources.endpoint:qualys-vuln-checkboxes] The Qualys VMDR & PC page lists the vulnerability statuses New, Active, Re-Opened or Fixed. [uvm.data-sources.endpoint:qualys-vuln-status] Qualys classifies vulnerability severities from 1 to 5: 1 minimal, 2 medium, 3 high, 4 critical and 5 urgent. [uvm.data-sources.endpoint:qualys-severity] The Qualys VMDR & PC page has checkboxes to include Asset Reporting Format (ARF) data in vulnerability reports or detection results, to have the latest security updates supersede previous ones, and to save all ports with the same vulnerability (otherwise only the first port with the vulnerability is processed), and a Retrieve Information Gathered Findings (higher volume) option. [uvm.data-sources.endpoint:qualys-vuln-options] A Qualys filter excludes specific groups of assets from the scope of data retrieval, with multiple values separated by commas; using it requires also specifying the scope of assets to be retrieved in the include filter, and the include filter requires the same for the exclude filter. [uvm.data-sources.endpoint:qualys-tag-filters]

**Qualys WAS.** The Qualys WAS connector has 2 streams: Assets (web applications within the user's scope) and Vulnerabilities (findings including vulnerabilities, sensitive content and gathered information). [uvm.data-sources.endpoint:qualys-was-streams] For Qualys WAS the API reader user has role Reader with the API checkbox, the Manage VM module and Manage web applications permissions, and after creation is edited to grant full access to the WAS module; only assets from the selected asset groups are ingested. [uvm.data-sources.endpoint:qualys-was-user] The Qualys WAS page says that if the connector fails after creating a user with the specified permissions, the user activation must be completed, which includes logging into the Qualys console with the new user's credentials; it also says to check the new account's email for a message titled Registration - Start Now. [uvm.data-sources.endpoint:qualys-was-activation]

**Rapid7 InsightVM.** The Rapid7 InsightVM connector has 3 streams (Vulnerabilities, Assets, Policy Compliance); Policy Compliance is in limited availability. [uvm.data-sources.endpoint:rapid7-streams] The Rapid7 InsightVM API key is generated by a platform admin with at least View Only (Shared) privileges and View Site Asset Data and View Group Asset Data permissions, and inherits the permissions of the user who created it. [uvm.data-sources.endpoint:rapid7-apikey] The Rapid7 region code is read from the prefix of the InsightVM URL (us.idr.insight.rapid7.com means us), is typically two letters and sometimes a number (e.g., us, us1, eu). [uvm.data-sources.endpoint:rapid7-region] A Rapid7 menu lists Critical, Low, Severe, Informational, None, Moderate and is available in the Rapid7 InsightVM Vulnerabilities stream. [uvm.data-sources.endpoint:rapid7-severity]

**Tenable Vulnerability Management.** The Tenable Vulnerability Management connector has 3 streams: Vulnerabilities (broken down by CVE), Issues (vulnerabilities with no associated CVEs) and Assets; Issues and Vulnerabilities are identical except that Issues has no CVE information. [uvm.data-sources.endpoint:tvm-streams] For Tenable Vulnerability Management the keys come from a user with role Basic User and a permission of Can View on All Assets, with API Key authentication enabled. [uvm.data-sources.endpoint:tvm-user] A Tenable Vulnerability Management checkbox splits raw data records based on the output field so that each resulting record contains a unique output, and another allows including vulnerabilities with info-level severity, which are otherwise automatically filtered out. [uvm.data-sources.endpoint:tvm-options] A Tenable Vulnerability Management field retrieves vulnerabilities that were last found by the vendor in the past input number of days, by default the past 30 days, and is available in the Vulnerabilities and Issues streams. [uvm.data-sources.endpoint:tvm-days] Tenable reports vulnerabilities at the plugin level, which includes a group of related CVEs, and the SecOps platform decomposes each Tenable plugin into its constituent CVEs; the page's example plugin is split into 48 distinct CVEs aggregated into a single ticket. [uvm.data-sources.endpoint:tvm-count-mismatch]

**Tenable Security Center.** The Tenable Security Center connector has 2 streams (Vulnerabilities broken down by CVE, and Assets) and needs a server URL, access key and secret key; secret keys cannot be viewed after generation. [uvm.data-sources.endpoint:tsc-streams] A menu on the Tenable Security Center page selects the severity level of vulnerabilities to include in the scope of the ingested data and is available in the Tenable Security Center Vulnerabilities stream. [uvm.data-sources.endpoint:tsc-severity]

**Tenable Nessus.** The Tenable Nessus connector retrieves vulnerability findings where each record is a finding on a specific asset, with a separate record created for each CVE when a finding includes multiple CVEs. [uvm.data-sources.endpoint:nessus-records] The Tenable Nessus API key user needs User Role Basic [16] or higher and Can View access control on the exported asset objects; Administrator [64] users can export without explicit Can View. [uvm.data-sources.endpoint:nessus-permissions] On the Tenable Nessus page, a number of days sets the days to retrieve data for during each run, and by default the connector retrieves data from the last day if no value is specified. [uvm.data-sources.endpoint:nessus-days] A Tenable Nessus API key consists of an access key and a secret key, and cannot be copied or viewed after generation. [uvm.data-sources.endpoint:nessus-apikey]

Not known (open gaps):
