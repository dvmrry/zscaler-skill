# Feeding UVM with AnySource: retrieval methods, file structure and the fields to include (uvm.anysource)
Also called: anysource; anysource connector; upload file api; uvm ingestion; uvm connectors; anytarget; uvm file upload

AnySource is the generic connector for tools that have no dedicated vendor connector. A data source uses either a dedicated vendor connector or the AnySource connector; AnySource uploads files directly to the platform, stores them in their original format, and maps them to the platform's data model. [uvm.anysource:connector-choice]

**Retrieval.** AnySource's file upload methods are Upload File, AWS S3, GCP, Webhook and Upload File API. [uvm.anysource:retrieval-methods] The Upload File API's endpoint and format are not documented in any capture [gap:uvm.anysource:upload-file-api]. Creating the source otherwise follows [Data from external tools (vulnerability scanners, asset inventories, cloud providers) is ingested by creating a data source from a tile on the Sources page; its setup has Details, Retrieval, Scheduling, Remediation Detection Settings and Suppression Rules sections and an optional connectivity Test, and data is retrieved on the next data run unless Process Now is used.](kb:portfolio.secops-platform:data-sources).

**File structure.** Each source keeps a consistent field mapping, so all files uploaded to a source should match the structure of its original file, such as headers and file type. [uvm.anysource:consistent-structure] The ingestion layer accepts a wide variety of file formats and structures, so preprocessing is generally not required. [uvm.anysource:no-preprocessing]

**AWS S3.** When a new file is added to the bucket, an alert is triggered and the file is retrieved; configuring an integration with S3 data is a three-step process. [uvm.anysource:s3-mechanism] Step one creates a role Zscaler can use: generate a unique identifier that Zscaler's service uses to assume the role, then run the Cloud Formation Role Stack; the RoleARNID value appears under the stack's Output tab. [uvm.anysource:s3-role-stack] The CloudFormation template provides permissions for AWS, and a deployment connecting to AnySource only can edit the script to modify or remove unnecessary permissions. [uvm.anysource:s3-stack-permissions] Step two creates an SQS queue named avalor-s3-event-forwarder, whose Queue ARN is saved for the next step and whose Queue URL is sent to the Zscaler Account team to complete configuration. [uvm.anysource:s3-sqs-queue] If the organization uses KMS encryption, the key policy must allow the role to use the key with kms:Decrypt and kms:GenerateDataKey* actions. [uvm.anysource:s3-kms] In the bucket notification steps, All object create events is selected under Event Type and SQS Queue as the Destination with the SQS queue ARN; the steps are repeated for every bucket to ingest data from. [uvm.anysource:s3-bucket-notification] To create the data source, the customer sends the Zscaler Account team the AWS account ID, Region, Bucket and Role ARN, plus optional Path, External ID and File pattern (regex). [uvm.anysource:s3-source-details] The External ID is optional: it is the unique identifier created when creating the role for Zscaler, an additional security measure; using one is considered best practice but is not mandatory. [uvm.anysource:s3-external-id] The Path and File pattern fields can be used separately or together, and the file pattern is entered in regex format (for example, a *.jsonl pattern retrieves only files with a .jsonl extension in that source). [uvm.anysource:s3-path-pattern]

**Fields.** Unlike vendor connectors such as CrowdStrike Managed Hosts or ServiceNow Assets, AnySource needs the fields chosen explicitly: for a manual upload you can include them directly in the file, and field selection is typically handled through the parsing logic you define for the Upload File API; core identifiers (ID, name, first and last seen) support correlation across sources. [uvm.anysource:explicit-fields] Recommended asset fields are name or hostname, type, IP addresses, operating system, owner, location, status, tags, installed software and criticality. [uvm.anysource:asset-fields] Recommended finding fields are vulnerability name or ID, severity (score and category), description, affected asset, CVE, threat intel, tags, first and last seen timestamps, recommendations, and affected component. [uvm.anysource:finding-fields]

**Other integrations.** Zscaler's UVM product page lists 150+ prebuilt integrations, native connectors to 150+ data sources spanning CVEs, threat intel feeds, identity, applications, cloud services and user behavior; an AnySource connector for integrating new data sources, even flat files or webhooks; and an AnyTarget connector that pushes workflows, tickets or other outputs to any downstream system. [uvm.anysource:integration-count] The connector list itself is not captured: [Which source connectors and outbound integrations the SecOps platform offers](kb:portfolio.secops-platform:connector-catalog).

What to check:
1. Whether every file uploaded to one AnySource source has the same structure (headers, file type) as the first; a different layout needs its own source.
2. Whether the file carries core identifiers (ID, name, first and last seen) so records correlate with other sources.
