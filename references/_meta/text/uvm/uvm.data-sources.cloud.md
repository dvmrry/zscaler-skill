# UVM cloud data sources: the AWS, Azure, Google Cloud Platform and Google Sheets connectors, and the Aqua Security, Lacework and Cyera cloud-security connectors (uvm.data-sources.cloud)
Also called: uvm aws connector; uvm azure connector; uvm gcp connector; uvm cloud security connectors

The AWS connector's streams are AWS Accounts, EC2, ECR, ECR Findings, EKS Clusters API, Inspector Findings, Network, RDS, S3 Buckets and Security Hub API; AWS resources, including accounts, are mapped as assets. [uvm.data-sources.cloud:aws-streams] Shared connector facts are in [UVM data sources: shared connector facts, availability, and the Jira, Zscaler, Okta, Code42, NetBox, runZero, SecurityScorecard and SFTP connectors](kb:uvm.data-sources); the generic procedure is in [Data from external tools (vulnerability scanners, asset inventories, cloud providers) is ingested by creating a data source from a tile on the Sources page; its setup has Details, Retrieval, Scheduling, Remediation Detection Settings and Suppression Rules sections and an optional connectivity Test, and data is retrieved on the next data run unless Process Now is used.](kb:portfolio.secops-platform:data-sources).

**AWS authentication.** Secret Key authentication uses an AWS access key and secret key to fetch data from a single AWS account, cannot be used for the AWS Accounts stream; AWS shows the secret access key only on the creation page. [uvm.data-sources.cloud:aws-auth-secret-key] If you already have two access keys, Create access key is deactivated and one must be deleted before a new one can be created. [uvm.data-sources.cloud:aws-access-key-limit] Role ARN - Single Account fetches data from a single account or, for an admin with the appropriate access, from all organizational accounts; role ARN permissions are required for each AWS stream, and the External ID is optional. [uvm.data-sources.cloud:aws-auth-role-single] Role ARN - Multiple Accounts uses Role ARNs, with an optional External ID; the page says to create an AWS StackSet, which deploys and manages CloudFormation stacks across multiple accounts and regions, signed in to an organization or management account. [uvm.data-sources.cloud:aws-auth-role-multi] The StackSet is created with create-stack-set (stack set name ZscalerStackIntegration, SERVICE_MANAGED permission model, auto-deployment enabled) and deployed with create-stack-instances, where the organization root ID deploys to all accounts and a region must be specified. [uvm.data-sources.cloud:aws-stackset-commands]

**AWS Network.** For the AWS Network stream, network data types need these permissions in the CloudFormation file: Internet Gateway ec2:DescribeInternetGateways, Nat Gateway ec2:DescribeNatGateways, Load Balancer elasticloadbalancing:DescribeLoadBalancers, VPC CIDR ec2:DescribeVpcs, VPC Subnets ec2:DescribeSubnets, Addresses ec2:DescribeAddresses and Network Interfaces ec2:DescribeNetworkInterfaces; to retrieve network data from all accounts the permissions go on the root/organization account. [uvm.data-sources.cloud:aws-network-permissions] A drop-down menu available in the AWS Network stream selects the data types to include in the ingestion scope. [uvm.data-sources.cloud:aws-network-filter] [gap:uvm.data-sources.cloud:aws-deployment-guide]

**Azure Blob.** The Azure Blob connector uploads files from Azure storage to the SecOps platform, and files in unsupported formats are not processed. [uvm.data-sources.cloud:blob-scope] Azure Blob authentication is the storage account connection string, and a role with the required permissions is selected, such as the built-in Storage Blob Data Reader role. [uvm.data-sources.cloud:blob-auth] The user or service principal associated with the connection string needs two Azure RBAC permissions: List Containers (Microsoft.Storage/storageAccounts/blobServices/containers/read, role scoped to the storage account or above) and List Blobs (Microsoft.Storage/storageAccounts/blobServices/containers/blobs/read). [uvm.data-sources.cloud:blob-rbac] The storage account must allow network access from all networks or from selected IP addresses; for the US the page lists 3.137.47.190/32, 3.15.110.62/32 and 3.129.232.141/32, and for the EU it refers to the Zscaler Config. [uvm.data-sources.cloud:blob-network] On the Azure Blob page, if no containers are specified data is retrieved from all containers in the storage account; tags are added in the format key : value, where the value can be empty, and if tags are specified only blobs that include at least one of the listed tags are retrieved. [uvm.data-sources.cloud:blob-filters]

**Azure Cloud Assets and Microsoft Defender for Cloud Findings.** The Azure Cloud Assets connector retrieves asset information across Azure subscriptions and cloud data only; Defender for Cloud findings and Defender for Endpoint are separate connectors. [uvm.data-sources.cloud:cloud-assets-scope] The Azure Cloud Assets and Microsoft Defender for Cloud Findings connectors authenticate with an Azure app registration (Accounts in this organizational directory only) giving the Application (client) ID, Directory (tenant) ID and a client secret; both pages say the client secret is not displayed again after you leave the page. [uvm.data-sources.cloud:app-registration] Both the Azure Cloud Assets and Microsoft Defender for Cloud Findings pages have the application assigned the Microsoft Graph application permission PrivilegedAccess.Read.AzureResources, with admin consent if required. [uvm.data-sources.cloud:graph-permission] The Azure Cloud Assets and Defender for Cloud Findings pages say multiple subscription IDs can be entered in the platform, give steps to assign the Reader role to a single subscription, and say data is retrieved from all subscriptions in the organization, where multiple subscriptions can be organized into a single management group to set access control in bulk. [uvm.data-sources.cloud:subscription-scope] An Azure management group ID is the directory unique identifier used to submit commands on the group and cannot be edited after creation. [uvm.data-sources.cloud:mgmt-group-id] The Microsoft Defender for Cloud Findings connector retrieves security findings for cloud assets (vulnerabilities, compliance issues and recommended remediations) and its Findings Types drop-down selects CVEs, Misconfigurations or both. [uvm.data-sources.cloud:defender-findings] The Azure Cloud Assets page's authentication steps say "The Microsoft Defender for Cloud Authentication window appears." [uvm.data-sources.cloud:cloud-assets-auth-window-name]

**Google Cloud Platform.** The GCP connector has three streams: Assets, Misconfigurations and Vulnerabilities; supported asset types are storage buckets, Artifact Registry repositories and Docker images, Compute instances and Kubernetes clusters. [uvm.data-sources.cloud:gcp-streams] Each GCP stream needs its API enabled in the project: Cloud Asset API for Assets, Security Command Center API for Misconfigurations and Container Analysis API for Vulnerabilities. [uvm.data-sources.cloud:gcp-apis] The GCP page assigns the service account the Viewer role from the Basic category, or the Cloud Asset Viewer role (or a custom role that includes cloudasset.assets.listResource), a role that includes securitycenter.findings.list, and the Container Analysis Occurrences Viewer role (or a custom role that includes containeranalysis.occurrences.list). [uvm.data-sources.cloud:gcp-roles] Zscaler recommends the Viewer role or all three stream-specific roles so the connector's internal health checks and connection validation succeed even if only some streams are enabled. [uvm.data-sources.cloud:gcp-roles-recommendation] GCP authentication uses a service account JSON key created with the JSON key type. [uvm.data-sources.cloud:gcp-auth] On the GCP page, one checkbox restricts the connector's scope to the Google Cloud project where the service account resides and, left unselected, allows ingest from all projects the service account has access to; another checkbox excludes Google-managed system projects, which typically have IDs starting with sys-. [uvm.data-sources.cloud:gcp-project-filters] The GCP source's Admin Email to Impersonate field is left empty because the connector does not require an admin email to impersonate. [uvm.data-sources.cloud:gcp-admin-email]

**Google Sheets.** The Google Sheets connector retrieves data from a specified spreadsheet (Spreadsheet ID) and optionally filters by sheets, a comma-separated list of names, retrieving all sheets if empty. [uvm.data-sources.cloud:sheets-scope] Google Sheets authentication needs the Google Sheets API enabled, an OAuth client ID of application type Web application with https://developers.google.com/oauthplayground entered, and a refresh token obtained after selecting Google Sheets API v4 with all scopes and authorizing the APIs. [uvm.data-sources.cloud:sheets-auth] The Google Sheets spreadsheet ID is the part of the spreadsheet URL between d/ and /edit. [uvm.data-sources.cloud:sheets-id]

**Aqua Security.** The Aqua Security connector has 7 streams: CWPP Functions, Hosts and Images Vulnerabilities, Containers, CSPM, Hosts and Images. [uvm.data-sources.cloud:aqua-streams] The Aqua Security page has one authentication type that connects using an API key and one that connects using an Aqua Security username and password, the latter for a user carrying the OOTB Application Scope Viewer role or higher (or a custom role with equivalent access). [uvm.data-sources.cloud:aqua-auth] An Aqua Security API key takes roles OOTB API Keys Viewer and OOTB Application Scope Viewer or higher (or equivalent custom roles), an optional IP allowlist and optional expiration; without an expiration date it defaults to one year from creation. [uvm.data-sources.cloud:aqua-key] On the Aqua Security page, custom field names use the system names provided by Aqua Security (e.g., aqua_id, aqua_severity) in the CWPP Functions, Hosts and Images Vulnerabilities streams, and the Gateway drop-down lists only previously configured gateways, requested through a support ticket. [uvm.data-sources.cloud:aqua-fields]

**Lacework.** The Lacework connector retrieves vulnerability findings (CVE details, affected assets, risk scores and fix information); the Number of days to fetch field sets days retrieved per run. [uvm.data-sources.cloud:lacework-scope] Lacework API keys can be generated by an admin user or a user with write permission for API keys, and creating a service user needs organization administrative privileges; the Account ID is the Lacework account name (subaccount) from the console URL https://<Account ID>.lacework.net or the downloaded API key JSON. [uvm.data-sources.cloud:lacework-auth]

**Cyera.** The Cyera connector has two streams, Assets and Issues, and requires a Cyera Admin role and an active Cyera DSPM license. [uvm.data-sources.cloud:cyera-scope] Cyera credentials are generated by logging in to the Cyera portal, clicking Integrations in the left-side navigation and selecting Zscaler, with Token Expiration durations such as 1, 7, 30, 90 or 365 days, and the token must be refreshed on expiry for continuous connectivity. [uvm.data-sources.cloud:cyera-token]
