# UVM ticketing outegrations (Jira, ServiceNow, Freshservice, Azure DevOps), the ServiceNow CMDB outegration, their webhooks and mapping (uvm.outegrations.ticketing)
Also called: ticketing outegration; Jira outegration; ServiceNow outegration; Freshservice outegration; Azure DevOps outegration

The Jira outegration setup has four steps: Connect, Settings, Mapping and the Jira Webhook, and the process includes configuring a Jira webhook to enable bidirectional synchronization. [uvm.outegrations.ticketing:jira-steps] The ServiceNow outegration has four steps, with Step 4 (Configure the ServiceNow Webhook) optional, and authenticates by OAuth 2.0, User Name Password Client ID Client Secret, Basic Authentication or Jwt OAuth2. [uvm.outegrations.ticketing:sn-steps] Freshservice outegration mapping has three components: the initial dispatch of tickets, an optional sync from ticket to Freshservice, and an optional sync from Freshservice to ticket that also requires a Freshservice webhook. [uvm.outegrations.ticketing:fs-three-mappings] The shared setup procedure is in [UVM outegrations: setup procedure, storage and streaming, Splunk, Teams and Email, and Tenable scan outegrations](kb:uvm.outegrations); the product is in [Unified Vulnerability Management (UVM): what it does with findings, and what can be automated](kb:uvm.overview); sources are in [UVM data sources: shared connector facts, availability, and the Jira, Zscaler, Okta, Code42, NetBox, runZero, SecurityScorecard and SFTP connectors](kb:uvm.data-sources).

**One configuration per type.** The Jira outegration requires a separate configuration for each Jira issue type (e.g., Bug, Task, Feature). [uvm.outegrations.ticketing:type-separate] The ServiceNow outegration requires a separate configuration for each ServiceNow Table Type (e.g., Remediation Task, Incident). [uvm.outegrations.ticketing:type-separate-sn] The Azure DevOps outegration requires a separate configuration for each Azure DevOps ticket type (e.g., Bug, Task, Feature). [uvm.outegrations.ticketing:type-separate-ado]

**Jira.** Jira Data Center users must first set up a gateway before the standard Jira outegration setup; Jira Cloud and Data Center setups are otherwise mostly similar. [uvm.outegrations.ticketing:jira-dc-gateway] The Jira webhook applies to Jira Cloud and Jira Data Center, needs the Administer Jira global permission, and uses the URL https://webhook.avalor.io/integration/<Account ID>/jira, a project = <Your Project Key> filter, and the Issue updated and deleted events. [uvm.outegrations.ticketing:jira-webhook] The Jira Cloud and Data Center authentication parameters are open [gap:uvm.outegrations.ticketing:collapsed-step-bodies].

**ServiceNow.** The ServiceNow webhook needs Zscaler API token credentials (Client ID and Client Secret) and the account ID, obtained by submitting a support ticket in the SecOps platform. [uvm.outegrations.ticketing:sn-webhook-prereq] The ServiceNow webhook is an after business rule on Update and Delete, on Incident [incident] for the Incidents table, Requested Item [sc_req_item] for Requests, Policy Exception [sn_compliance_policy_exception] for Exceptions, or the relevant table name for any other table. [uvm.outegrations.ticketing:sn-webhook-rule] The ServiceNow webhook script requests a token from https://auth.us01.app.avalor.io/oauth2/token and sends payload.changedFields to https://webhook.avalor.io/integration/inbound/<Account ID>/servicenow with a Bearer token. [uvm.outegrations.ticketing:sn-webhook-script] The webhook hosts are open [gap:uvm.outegrations.ticketing:avalor-hosts].

**ServiceNow CMDB.** The ServiceNow CMDB outegration updates CMDB records, such as adding missing assets, requires the ServiceNow Assets connector to be configured first, and has Connect, Settings and Mapping steps. [uvm.outegrations.ticketing:cmdb]

**Azure DevOps.** Azure DevOps outegration authentication uses a multitenant Entra ID app registration with redirect URI https://app.avalor.io/oauth and the permissions Azure DevOps vso.project_manage and vso.work_write plus Microsoft Graph offline_access and User.Read. [uvm.outegrations.ticketing:ado-auth] The Azure DevOps outegration needs Client ID, Client Secret, Tenant ID, organization name and project name; Refresh Token and Access Token are optional. [uvm.outegrations.ticketing:ado-params] In the Azure DevOps outegration the item is created from Ticket in UVM, and Policy Violation or Violation Ticket in AEM. [uvm.outegrations.ticketing:ado-entity] For Azure DevOps, Work Item Type selects the work item whose schema is retrieved from the Azure DevOps project and made available for mapping, and the mapping schema lists Required, Input Type and Available Options for fields. [uvm.outegrations.ticketing:ado-work-item] The initial Azure DevOps outegration mapping includes preconfigured default mappings for each part, which can be modified. [uvm.outegrations.ticketing:ado-defaults] In the Azure DevOps mapping the Summary field is required and must be mapped before the outegration can be saved, and it expects a TEXT input type. [uvm.outegrations.ticketing:ado-summary-required] Azure DevOps outegration mapping has three mapping components, and the Azure DevOps to ticket sync requires an Azure DevOps webhook. [uvm.outegrations.ticketing:ado-three-mappings] An Azure DevOps webhook is only needed to sync updates from Azure DevOps to the ticket; it is not required for the initial ticket dispatch or for syncing updates from the ticket to Azure DevOps. [uvm.outegrations.ticketing:ado-webhook-scope] The Azure DevOps webhook is a Service Hooks Web Hooks subscription with URL https://webhook.avalor.io/integration/{avalor-account-id}/azure_DevOps, tested before finishing. [uvm.outegrations.ticketing:ado-webhook] The Azure DevOps Mapping Preview window shows a sample of the tickets in the account, organized by ticket ID. [uvm.outegrations.ticketing:preview]

**Freshservice.** The Freshservice outegration authenticates with an API key (shown under the Delegate Approvals section) and the tenant domain (e.g., acme.Freshservice.com). [uvm.outegrations.ticketing:fs-params] In the Freshservice outegration the item is created from Ticket in UVM and Violation Ticket in AEM, and the Create Freshservice Ticket button shows Always, Never or For specific tickets. [uvm.outegrations.ticketing:fs-entity] The Create Freshservice Ticket button appears in the individual entity drawer and on the entity page of the application (e.g., the Tickets page in UVM, the Violation Tickets page in AEM). [uvm.outegrations.ticketing:button-locations] A Freshservice webhook is only needed to sync updates from Freshservice to the ticket, not for the initial dispatch or ticket-to-Freshservice sync. [uvm.outegrations.ticketing:fs-webhook-scope] The Freshservice webhook is a Workflow Automator ticket automator with events Ticket is updated and deleted and a Trigger Webhook POST action to https://webhook.avalor.io/integration/<Account ID>/Freshservice, empty credentials, JSON and Simple encoding, and content fields including Ticket ID (numeric), Urgency, Subject, Description, Priority, Impact and Status. [uvm.outegrations.ticketing:fs-webhook-setup]

**Mapping.** A mapping value in the Freshservice outegration is configured by Field (Dictionary), Smart Text (free text and fields in double curly brackets, e.g., {{Ticket Assignee}}) or Script (Python scripts). [uvm.outegrations.ticketing:mapping-methods] The Kafka outegration mapping value is configured by Field (Dictionary) or Expression, and the Expression Editor handles use cases requiring more advanced configuration. [uvm.outegrations.ticketing:mapping-methods-kafka] The field dictionary creates mappings between specific values of the field on the right and values of the field on the left (e.g., Freshservice priority Urgent, High, Medium, Low to Ticket Severity values). [uvm.outegrations.ticketing:fs-dictionary] On the Freshservice outegration page, a SecOps ticket field can be set as mandatory with the Set as Mandatory checkbox in the Column Menu, and dispatching a ticket without a value in a mandatory field triggers an error message. [uvm.outegrations.ticketing:mandatory] Freshservice ticket dispatch attachments can be configured in the initial dispatch and the ticket-to-Freshservice sync, in the formats CSV, PDF, JSONL or Excel. [uvm.outegrations.ticketing:attachments] Freshservice comment synchronization in the ticket-to-Freshservice sync has Sync Comments (pushes the ticket's comments to the Freshservice ticket) and Sync Trigger Comments (a comment posted when a monitored field changes From a value To a value). [uvm.outegrations.ticketing:comments-sync]
