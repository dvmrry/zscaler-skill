# UVM asset-inventory, attack-surface and ServiceNow data sources: Axonius, Armis, Flexera, Halo, HCL BigFix, Datto, Freshservice, Claroty xDome, Dragos, Bitsight, CyCognito, Ionix, Mandiant ASM, Horizon3.ai, Digital Shadows and ServiceNow connectors (uvm.data-sources.inventory)

See [UVM data sources: shared connector facts, availability, and the Jira, Zscaler, Okta, Code42, NetBox, runZero, SecurityScorecard and SFTP connectors](kb:uvm.data-sources) and [Unified Vulnerability Management (UVM): what it does with findings, and what can be automated](kb:uvm.overview).

**Axonius.** The Axonius connector retrieves asset inventory data; API credentials can come from a user or a service account, the user's role must have API access enabled, and in the URL https://10.20.0.111/api/ the expected input for the URL is 10.20.0.111. [uvm.data-sources.inventory:axonius]

**Armis.** Armis has three streams (CVE, Devices, Reports); the Reports stream is an additional way to retrieve device and vulnerability data using preconfigured reports and takes a Report ID, and Days to Fetch applies to Devices. [uvm.data-sources.inventory:armis-streams] The Armis API token's user needs Vulnerability > Read for the CVE stream, Device > Read for Devices and Report > Read for Reports; the Tenant is the host in https://<Tenant>.armis.com. [uvm.data-sources.inventory:armis-permissions]

**Flexera Assets.** Flexera Assets authentication needs a refresh token created from a regional site (app.flexera.com, app.flexera.eu or app.flexera.au), a Zone of US, EU or APAC, and the numeric Organization ID at the end of the org URL. [uvm.data-sources.inventory:flexera]

**Halo Assets.** Halo Assets needs a HaloITSM application (Client ID and Secret, Login Type Agent) created by a HaloITSM administrator with the read:assets permission, and the associated user must have access to all asset fields. [uvm.data-sources.inventory:halo-permissions] Halo Assets has checkboxes that include site-specific metadata and asset group metadata for each asset; the tenant is the unique subdomain found in the HaloITSM Console URL. [uvm.data-sources.inventory:halo-options]

**HCL BigFix Computers.** The HCL BigFix - Computers connector uses basic credentials of a Console Operator account with Web Reports/REST API access, Can Submit Queries Yes, Custom Content Yes, View All Computers and Can Read permissions across relevant sites and computer properties. [uvm.data-sources.inventory:bigfix-permissions] The HCL BigFix Port field defaults to the REST API port 52311 unless the deployment uses a custom port. [uvm.data-sources.inventory:bigfix-port]

**Datto.** The Datto connector has two streams (Alerts and Devices); API access must be enabled in Setup > Global Settings > Access Control, and the user needs to be an administrator or have permissions to access Setup and manage Global Settings and Users. [uvm.data-sources.inventory:datto] The Datto Include Muted Alerts option retrieves muted open alerts in addition to the default unmuted open alerts, but the page says this filter is available in the Datto Devices stream. [uvm.data-sources.inventory:datto-muted] [divergence:uvm.data-sources.inventory:datto-muted-stream]

**Freshservice.** The Freshservice page says to log in to the Freshservice Support Portal as an administrator, to include the .freshservice.com suffix but exclude the https:// prefix and any trailing slashes, and to enter a timestamp in YYYY-MM-DDTHH:MM:SSZ format; any data created or updated before that timestamp is not ingested. [uvm.data-sources.inventory:freshservice] The Freshservice page says to enter a comma-separated list of key-value pairs in the format param1=val1,param2=val2 (e.g., type=Service Request,include=stats). [uvm.data-sources.inventory:freshservice-query]

**Claroty xDome for Healthcare.** Claroty xDome for Healthcare (formerly Medigate) has two streams (Assets and Vulnerabilities); the API user must be created by an admin with at least read permissions for the sites the API accesses. [uvm.data-sources.inventory:claroty]

**Dragos.** The Dragos page describes connecting using an API key and connecting using a Dragos username and password; the Dragos user needs the asset:read and vulnerability:read permissions, and generating an API key requires an admin user. [uvm.data-sources.inventory:dragos-auth] The Dragos Severity filter (Vulnerabilities stream) retrieves all severity levels by default. [uvm.data-sources.inventory:dragos-severity]

**Bitsight.** One Bitsight stream retrieves enriched observation data related to risk types that impact a company's rating and Bitsight Observations retrieves granular observation-level data; its token must belong to a user with read access, a Company API token needs an admin or VRM admin user. [uvm.data-sources.inventory:bitsight-streams] On the Bitsight page, grade values include good, fair, warn, bad and neutral and by default all grades are retrieved if none are specified; leaving a field empty retrieves data from the parent company; a field is available in the Bitsight Observations stream. [uvm.data-sources.inventory:bitsight-filters]

**CyCognito.** CyCognito has two streams, Issues and Assets; creating the API key requires an admin or IT user with Read only key access, and the URL is the instance base URL prefixed with api. [uvm.data-sources.inventory:cycognito-streams] If left empty, the CyCognito Asset Status (Assets stream) defaults to retrieving only assets with a new status, and the Issues Status (Issues stream) defaults to retrieving only issues with a new status. The Asset Status values listed are New, Changed, Normal and Removed; the available Issues Status values are New, Normal, Issue-Removed, Asset-Removed and Asset-Not-Alive. [uvm.data-sources.inventory:cycognito-status] CyCognito Assets Type covers IP addresses, domains, certificates, web applications and IP address ranges. [uvm.data-sources.inventory:cycognito-asset-types]

**Ionix.** On the Ionix page, each record can be exploded to multiple CVE entries, by default only vulnerabilities marked as Open are retrieved, and a checkbox is available in the Findings stream. [uvm.data-sources.inventory:ionix]

**Mandiant ASM.** The Mandiant ASM Select Retrieval Option either lists selected project IDs (comma-separated) or pulls from all projects. [uvm.data-sources.inventory:mandiant-retrieval] On the Mandiant ASM page, available severity levels include Critical, High, Medium, Low and Informational, and selecting Medium retrieves issues classified as Medium, High, and Critical. [uvm.data-sources.inventory:mandiant-severity] The Mandiant ASM Issues Status and Entity Types lists are retrieved via the API and reflect the statuses and types in the customer's Mandiant ASM environment. [uvm.data-sources.inventory:mandiant-lists]

**Horizon3.ai.** Horizon3.ai has three streams (Assets, Flat Impacts, Weaknesses Evidence), the API key is created with Read-Only permission level, and by default all pentest types are selected (Internal pentest, External asset discovery, External pentest, Network Enumeration, AD Password Audit, Phishing, AWS pentest, K8s pentest). [uvm.data-sources.inventory:horizon3] The Horizon3.ai page lets the connector retrieve data from only the latest completed penetration test, or from all available penetration tests in the Horizon3 account. [uvm.data-sources.inventory:horizon3-pentest]

**Digital Shadows.** Digital Shadows has two streams (Digital Shadows and Digital Shadows Assets); an API key requires a user with the Managing of API Accounts permission, and a field offering Alerts, Incidents, or both retrieves Alerts by default and is available in the Digital Shadows stream. [uvm.data-sources.inventory:digital-shadows] The Digital Shadows Account ID is found under Key words > Account > SearchLight Account ID on the API documentation page once API access is enabled. [uvm.data-sources.inventory:digital-shadows-account]

**ServiceNow streams and authentication.** There are three ServiceNow connector streams; the ServiceNow Connector page covers Assets and Users and a separate Generic page covers the ServiceNow Generic stream. [uvm.data-sources.inventory:sn-streams] The ServiceNow connector authenticates by OAuth 2.0, Username Password Client Id Client Secret, Basic Authentication or Jwt OAuth2. [uvm.data-sources.inventory:sn-auth-methods] The ServiceNow connector's Username Password Client Id Client Secret method needs a ServiceNow Security Admin user, while Basic Authentication needs a user with the ITIL role or higher, both with permissions to access the relevant table. [uvm.data-sources.inventory:sn-users] For Jwt OAuth2 the Subject identifies the user in the sys_user table and must match the user's email if the JWT profile's User field is the default (email), or the value in the changed field; the Key ID is generated when a new verifier map is created. [uvm.data-sources.inventory:sn-jwt] The ServiceNow Basic Authentication method has a Verify SSL checkbox that allows configuring a root CA certificate to trust during SSL negotiation, in the CA certificate field. [uvm.data-sources.inventory:sn-verify-ssl] On the ServiceNow Assets and Users page, the OAuth 2.0 method lists a Refresh Access Token. [uvm.data-sources.inventory:sn-oauth-assets] On the ServiceNow Generic page, the OAuth 2.0 method lists Refresh Token and Access Token and a Tenant ID. [uvm.data-sources.inventory:sng-oauth] The ServiceNow Instance Name retrieval field is the hosted instance name from the URL; for https://acme.service-now.com/ it is acme. [uvm.data-sources.inventory:sn-instance]

**ServiceNow Assets and Users.** The ServiceNow Assets stream has four related-data checkboxes (Applications, Application Services (Discovered), Business Applications, IT Services); without Service Mapping any of the four can be selected, and with Service Mapping configured only one of Applications or Application Services, with Business Applications only together with Application Services. [uvm.data-sources.inventory:sn-app-data] The related-data checkbox named for Application Services and the one named in the troubleshooting steps differ [divergence:uvm.data-sources.inventory:sn-service-data-checkbox]. The ServiceNow Users stream has an Include User's Related Group checkbox that retrieves the related group for each retrieved user. [uvm.data-sources.inventory:sn-users-group]

**ServiceNow Generic.** The ServiceNow Generic page takes the name of the table to retrieve from ServiceNow and the list of fields retrieved from the table, and a value of true includes a record in a domain that the ServiceNow user is not configured to access while false excludes it. [uvm.data-sources.inventory:sng-fields]

What to check:
1. Which ServiceNow related-data checkbox the Service Mapping troubleshooting step refers to, since the checkbox list and the troubleshooting steps name different checkboxes.
2. Which Datto stream the Include Muted Alerts option belongs to.

Sources disagree (name both sides):
- The ServiceNow Assets related-data checkbox list names Include Related Application Services (Discovered) Data; the troubleshooting step for missing business applications names a Business Services (Discovered) Data checkbox. [divergence:uvm.data-sources.inventory:sn-service-data-checkbox]
  - zscaler-help: The Assets stream's checkboxes are Include Related Applications Data, Include Related Application Services (Discovered) Data, Include Related Business Applications Data and Include Related IT Services Data.
  - zscaler-help: If business applications do not show, check whether ServiceNow Service Mapping is enabled; if it is, you might need to select the Business Services (Discovered) Data checkbox in addition to the Business Application Data checkbox and rerun the source.
  Impact: Business Services (Discovered) Data and Application Services (Discovered) Data are different data; the page lists no Business Services checkbox, so the troubleshooting step refers to a checkbox the list does not show.
- The Datto connector page ties the option to include muted open alerts to the Datto Alerts stream in its stream list, and says the Include Muted Alerts filter is available in the Datto Devices stream. [divergence:uvm.data-sources.inventory:datto-muted-stream]
  - zscaler-help: The stream list describes the Datto Alerts stream as having an option to include muted open alerts.
  - zscaler-help: The Include Muted Alerts filter text says the filter is available in the Datto Devices stream.
  Impact: The page does not say which of the two Datto streams the Include Muted Alerts checkbox applies to.
