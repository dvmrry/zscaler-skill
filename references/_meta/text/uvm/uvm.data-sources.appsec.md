# UVM application-security, code and cloud-security data sources: Apiiro, Black Duck, Burp Suite, Endor Labs, GitHub, Invicti, JFrog Xray, Legit Security, Prisma Cloud, Wiz, Snyk, Veracode, Quokka, SentinelOne and Tanium connectors (uvm.data-sources.appsec)

See [UVM data sources: shared connector facts, availability, and the Jira, Zscaler, Okta, Code42, NetBox, runZero, SecurityScorecard and SFTP connectors](kb:uvm.data-sources) and [Unified Vulnerability Management (UVM): what it does with findings, and what can be automated](kb:uvm.overview).

**Apiiro.** Apiiro has three streams: SCA (open-source and third-party component vulnerabilities), Secrets, and Terraform Misconfiguration; the Apiiro token needs Read or Full Control scope. [uvm.data-sources.appsec:apiiro-streams] The Apiiro Risk Level filter (SCA and Terraform Misconfiguration streams) has Low, Medium, High, Critical, Ignored, Accepted and AutoIgnored, selected by default. [uvm.data-sources.appsec:apiiro-risk]

**AttackForge.** The AttackForge connector retrieves vulnerability data accessible to the API key's user; an administrator must grant that user access to RESTful API methods, and the instance domain name is entered without http:// or https://. [uvm.data-sources.appsec:attackforge]

**Black Duck SCA.** Black Duck token generation requires an admin user; the API user should have the Global Code Scanner role, membership of the relevant project and the Project Code Scanner project role, and Read Access Only scope is sufficient. [uvm.data-sources.appsec:black-duck-token] On the Black Duck source, data is fetched only for the versions listed using the {version_link}/vulnerable-bom-components endpoint; the page also says the connector retrieves data from the canonical version of each project, the default version defined in Black Duck. [uvm.data-sources.appsec:black-duck-versions]

**Burp Suite Issues.** The Burp Suite Issues connector retrieves sites, scans and issues; the API user must be created by an Enterprise Edition administrator with the API key login type, be in the Scan viewer group or a group using the Scan viewer role, and hold a role with View sites and View site details permissions. [uvm.data-sources.appsec:burp] The Burp Suite URL has the format https://<Server IP>:<Port>, and the path after the port number must be removed if Copy API link is used. [uvm.data-sources.appsec:burp-url]

**Endor Labs.** On the Endor Labs source, the Query API serves the Containers, SAST, SCA Findings and Secrets streams (optimized for large volumes and namespace traversal) while the REST API serves the Vulnerabilities stream. [uvm.data-sources.appsec:endor-api] An Endor Labs API key needs the Read-only role or higher, the user selects an expiration date of 30 to 90 days, and by default is scoped to the current namespace and its child namespaces. [uvm.data-sources.appsec:endor-key] The Endor Labs Use Zscaler namespace traversal checkbox (Containers, SAST, SCA Findings and Secrets streams) retrieves from child namespaces when selected and only the listed namespaces when unselected; Namespace takes comma-separated parent or child namespaces. [uvm.data-sources.appsec:endor-namespace]

**Invicti.** On the Invicti source, the connector ingests raw HTML content by default and, when an option is selected, parses and cleans HTML tags to provide plain-text responses; by default it ingests only basic issue details, and the page describes the specific technical request sent by the Invicti scanner and the response received. [uvm.data-sources.appsec:invicti] Invicti authentication requires a user ID and an API token; the page adds that this does not apply if you use single sign-on (SSO). [uvm.data-sources.appsec:invicti-auth]

**JFrog Xray.** The JFrog Xray connector authenticates with the username and password (or API key) of a JFrog service account (v3.80 or later) assigned the Manage Watches and Manage Reports roles, and the URL has no trailing slashes or subpages. [uvm.data-sources.appsec:jfrog] The page says the UI Access and Can Update Profile options can be disabled for the JFrog service account user. [uvm.data-sources.appsec:jfrog-least-priv]

**Legit Security.** The Legit Security connector has two streams: Legit (all issue types except incidents) and Legit Incidents; the Tenant ID is the subdomain in the Legit Security URL. [uvm.data-sources.appsec:legit-streams] On the Legit Security source, the connector filters out issues with the type SnykIssue or ScaIssue, and when Specific is selected the Legit and Checkov sources are selected by default. [uvm.data-sources.appsec:legit-filters]

**GitHub Advanced Security.** The GitHub Advanced Security connector has two streams, Code Scanning and Secret Scanning, and retrieves alerts at the organization level for the specified organization. [uvm.data-sources.appsec:ghas-streams] For GitHub Advanced Security the authenticated user must be an owner or security manager for the GitHub organization, and the PAT must belong to an Organization Owner or Security Manager. [uvm.data-sources.appsec:ghas-role] A fine-grained PAT is the recommended GHAS token; it needs the Code scanning alerts, Secret scanning alerts and Security events permissions at Read-only minimum. [uvm.data-sources.appsec:ghas-fine-grained] A classic GHAS token needs the security_events checkbox under repo and the read:org checkbox under admin:org. [uvm.data-sources.appsec:ghas-classic] The State filter limits the scope of the ingested data to specific alert states: the page lists Open, Closed, Dismissed or Fixed in one place and Open or Resolved in another; if no filter is applied, all data is retrieved. [uvm.data-sources.appsec:ghas-state] One GitHub Advanced Security filter offers Critical, High, Medium, Low, Warning, Note or Error and, if no filter is applied, alerts of all severities are retrieved; another offers False Positive, Won't Fix, Revoked, Pattern Edited, Pattern Deleted or Used In Tests. [uvm.data-sources.appsec:ghas-severity-resolution] The secret types options are Generic (for example ec_private_key, mysql_connection_string) only, or both default and generic; if no option is selected, the connector only retrieves alerts for Default secret types. [uvm.data-sources.appsec:ghas-secret-types]

**GitHub Repositories.** The GitHub Repositories connector retrieves repository metadata (name, owner and organization, visibility, URL and timestamps) for the specified repositories and organizations, optionally enriched with custom properties. [uvm.data-sources.appsec:repos-scope] The GitHub Repositories connector offers a fine-grained PAT tied to a user (quick to start, rotated on expiry, needing Metadata Read-only); a second option is described as recommended for organization-managed access and better control than user PATs. [uvm.data-sources.appsec:repos-auth] GitHub App authentication needs the App ID, Installation ID, private key (PEM) and organization; the app needs Repository permissions > Metadata > Read-only, and OAuth-based user authorization is not supported. [uvm.data-sources.appsec:repos-app] On the GitHub Repositories source, only repository records with updated_at on or after a configured time are synced; a space-delimited list of repository selectors (e.g., org/repo1 org/repo2) syncs repositories, org/* syncs all repositories in an organization, and the Fetch Custom Properties checkbox includes repository custom properties configured in the GitHub organization. [uvm.data-sources.appsec:repos-filters]

**Prisma Cloud.** The Prisma Cloud connector has 2 streams: Container Issues (container scan compliance reports) and All Findings (deployed scan vulnerability reports). [uvm.data-sources.appsec:prisma-streams] The Prisma Cloud All Findings stream has a Scan Types filter with Images, CI Images, Registry, Host and Serverless Function. [uvm.data-sources.appsec:prisma-scan-types] By default only Prisma Cloud system admins can create access and secret keys; a reader role with Account Group Read Only permission group and the Allow user to create API Access Keys option lets another user do so. [uvm.data-sources.appsec:prisma-keys] A Prisma Cloud access key never expires unless Enable Expiration is selected, and if Enable Expiration is selected with no date the key expires within a month; the key is not accessible after the window closes. [uvm.data-sources.appsec:prisma-key-expiry] The Prisma Cloud server URL appears in the Path to Console section on the Utilities tab, is entered as https://<region>.cloud.twistlock.com/<customer>, and if authentication fails /api/v1 is appended. [uvm.data-sources.appsec:prisma-server-url]

**Prisma Cloud CSPM.** The Prisma Cloud CSPM connector retrieves vulnerabilities and asset data on cloud resources, and the admin console URL, which varies by cluster and is in the Prisma Cloud CSPM fulfillment email, is converted to the matching API URL. [uvm.data-sources.appsec:prisma-cspm]

**Wiz.** The Wiz connector lists Wiz Assets (cloud resources, optionally enriched with exposed resources data), Wiz Issues (active threats with severity, affected resources and remediation recommendations) and Wiz Configuration Findings streams. [uvm.data-sources.appsec:wiz-streams] The stream count the page states and the streams its Asset Type filter names differ [divergence:uvm.data-sources.appsec:wiz-stream-count]. For the Wiz Assets stream, the Client ID must carry read:resources, plus read:network_exposure if Include Network Exposure Info is selected; permissions for the other streams are in the deployment guide. [uvm.data-sources.appsec:wiz-permissions] Permissions for the other Wiz streams are open [gap:uvm.data-sources.appsec:wiz-other-stream-permissions]. In the Wiz source, retrieving all projects requires global permissions in Wiz; otherwise report generation fails. [uvm.data-sources.appsec:wiz-project] The Wiz page lists the values Toxic Combination, Threat Detection and Cloud Configuration; Critical, High, Medium, Low and Informational; and Open, In Progress, Resolved, Rejected or All Statuses, and a checkbox that retrieves additional metadata for each Wiz issue, resulting in large data ingestion volumes. [uvm.data-sources.appsec:wiz-issue-filters] The Wiz page has a field for the number of days to retrieve configuration findings that were first analyzed within that timeframe, and lists the values Open, In Progress, Resolved, Rejected and Critical, Low, Severe, Informational, None, Moderate. [uvm.data-sources.appsec:wiz-config-filters] The Wiz Asset Type filter applies to the Wiz Vulnerability Findings stream (e.g., Virtual Machine, Container, Container Image, Serverless) and filters cloud resources by Entity Types normalized by Wiz; with no filter applied, all available asset types are included. [uvm.data-sources.appsec:wiz-asset-type] Wiz enforces a 50,000 row limit on full report runs, so the Wiz Issues stream can return fewer results than expected; incremental exports support up to 500,000 rows. [uvm.data-sources.appsec:wiz-row-limit] A Wiz checkbox adds enrichment for exposed resources data and is available in the Wiz Assets stream. [uvm.data-sources.appsec:wiz-network-exposure]

**Snyk.** The Snyk connector has two streams and needs an API Token and Org ID. [uvm.data-sources.appsec:snyk-auth]

**Veracode.** The Veracode connector has 3 streams: Veracode (Static Analysis, Dynamic Analysis, Manual Penetration Testing and SCA findings), Veracode SCA (SCA findings only, not combined with other types) and Veracode Applications (limited availability). [uvm.data-sources.appsec:veracode-streams] Veracode setup needs an API service account with the Results API role or a user with the Reviewer or Security Lead role; an API service account must be a newly created Non-Human User, since an existing user cannot be changed into one. [uvm.data-sources.appsec:veracode-account] Veracode API credentials are an API ID and secret key that are shown once, and HMAC authentication is performed in the SecOps platform with no action needed in Veracode. [uvm.data-sources.appsec:veracode-creds] The Veracode page selects one or more severity levels, a lifecycle status (Open or Closed) and scan types (Static Analysis (SAST), Dynamic Analysis (DAST), Manual Analysis, Software Composition Analysis (SCA)). [uvm.data-sources.appsec:veracode-filters]

**Quokka.** The Quokka source uses an API key for a user with the permissions View Analyzed Apps, View Reports, View Shared Apps, Change API Key, Android Analysis, iOS Analysis, GDPR Report, OWASP Report, NIAP Report and SBOM Report; the stream retrieves findings data. [uvm.data-sources.appsec:quokka]

**SentinelOne.** On the SentinelOne connector page, the SentinelOne Assets, Alerts and CNS Findings streams are in limited availability. [uvm.data-sources.appsec:s1-streams] On the SentinelOne page, EDR alerts originate from managed endpoints and XDR alerts extend beyond the endpoint; if neither are selected, both types are ingested. [uvm.data-sources.appsec:s1-alert-type] On the SentinelOne page, Endpoint (managed devices) is included by default, and Network Discovery (unmanaged network assets) and Cloud require active SentinelOne module subscriptions. [uvm.data-sources.appsec:s1-asset-type] On the SentinelOne page, if none are selected both vulnerabilities and misconfigurations are ingested, and a severity selection applies only to misconfiguration findings, with all severities ingested if none are selected. [uvm.data-sources.appsec:s1-cns]

**Tanium.** The Tanium source needs an API Key, Domain and roles and permissions, and has an optional Sensors field for sensor names, where a sensor is a script that runs on endpoints to gather data in response to a Tanium question. [uvm.data-sources.appsec:tanium]
