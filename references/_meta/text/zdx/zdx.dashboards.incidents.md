# ZDX incidents: the incident area types, their epicenters, key metrics and detection minimums (zdx.dashboards.incidents)
Also called: incidents dashboard; zdx incident; zdx incidents; incident epicenter; blackout; brownout; intermediate isp incident; system software hangs; system software crashes

An incident is an issue that affects the device performance of multiple users, and the Incidents Dashboard is where the console shows them. Incidents are issues that impact the device performance of multiple users; ZDX uses AI and machine learning to detect and identify them with the metrics that correlate best to the issues. The Incidents Dashboard displays them in 7 area types: Device, Wi-Fi, Last Mile ISP, Intermediate ISP, ZIA (Internet & SaaS) Public Service Edge, ZPA (Private Access) and Application. [zdx.dashboards.incidents:what-incidents] The Incidents Dashboard needs a ZDX subscription level that supports Incidents and View Only permission for the Incidents Dashboard; the subscription table lists Incidents as not supported on Standard, Microsoft 365 and Advanced and supported on Advanced Plus. [zdx.dashboards.incidents:subscription]

**The dashboard.** The Incidents Dashboard's time range defaults to 14 days, and it counts the total incidents detected and the impacted users from the total incidents within that range. [zdx.dashboards.incidents:time-range-counts] An incident's details give its severity and duration and the number of impacted users, geolocations and applications, and a Top Impacted Users list of up to 11 users. An alert rule for an incident can be configured with Set Up Alert, and Share Snapshot captures a static image of the current incident details view. [zdx.dashboards.incidents:incident-details]

**Epicenters.** An incident's epicenter depends on its type. For Device it is the geographical area of impacted Windows devices with system software hangs and crashes, for Wi-Fi the geographical area of impacted SSIDs, and for Last Mile ISP the area of impacted users with the ISP, with Blackout (connectivity issues) and Brownout (performance degradation) as its subtypes. For a ZIA Public Service Edge it is the Public Service Edge's location at the Zscaler Data Center, for ZPA the geographical area of impacted users with ZPA plus the App Connector and Public Service Edge locations, and for Application the area of impacted users, which can go across multiple countries. [zdx.dashboards.incidents:epicenters] An Intermediate ISP incident represents network issues between ISPs or within an ISP backbone: Internal (affected hops inside a single ISP or ASN), between two ISPs or ASNs at the peering point, or from the peering ISP to a Zscaler Data Center. Its epicenter is the data center location if probes are routed through a Zscaler Data Center, and the approximate geolocation of affected users if probes are direct. [zdx.dashboards.incidents:intermediate-isp]

**Device incidents.** Device incidents are about Windows devices: System Software Hangs are devices that have become unresponsive to user input on applications despite ongoing computer activity, and System Software Crashes are devices with no computer activity because the software has crashed. Their key metrics are the distribution of impacted operating systems and software, the CPU and memory usage percentage of impacted Windows devices, and an event trend of hangs or crashes over time. [zdx.dashboards.incidents:device-subtypes]

**Key metrics by type.** Wi-Fi incident key metrics are the ZDX Score variation through the access point, its maximum and average latency, packet loss at the first access point (hop 1) and after it (hops 2 to 4), and the average signal strength of users going through the access point. [zdx.dashboards.incidents:wifi-metrics] Last Mile ISP Blackout key metrics give an overview of connectivity issues with an ISP: the application's ZDX Score, the total probe errors and the Cloud Path probe errors. Brownout key metrics give an overview of performance degradation with an ISP: the ZDX Score drop, DNS latency, leg latency and packet loss. [zdx.dashboards.incidents:last-mile-metrics] Intermediate ISP key metrics plot a network path from the affected leg to show where the incident occurred, and give the aggregated ZDX Score across impacted users and their configured applications, latency on internal ISP hops or across peering points, leg latency, lost packets along the leg, end-to-end latency and DNS resolution time. [zdx.dashboards.incidents:intermediate-isp-metrics] ZIA Public Service Edge key metrics give each impacted user's ZDX Score aggregated across their configured applications, first-hop and second-hop latency around the SME from the ZIA Public Service Edge perspective, the number of ZIA transactions and ZIA connectivity errors through the affected Zscaler Data Center, and the Cloud Path and Web probe errors at that data center. [zdx.dashboards.incidents:zia-pse-metrics] ZPA App Connector key metrics give an overview of App Connector traffic, connectivity and latency for impacted users, including the average first-hop and second-hop latency across all users going through Private Access and the App Connector Cloud Path probe errors at the Zscaler Data Center. ZPA Public Service Edge incidents also list the Public Service Edge Web probe errors at the Zscaler Data Center. [zdx.dashboards.incidents:zpa-metrics] Application incident key metrics include the number of HTTP errors the application has encountered over time, the ratio of server response time (time to first byte) to page fetch time, the latency from the Public Service Edge to the application, and the number of redirections going through the application over time. [zdx.dashboards.incidents:application-metrics] The article's metrics table lists other metrics for Wi-Fi than its Wi-Fi section [divergence:zdx.dashboards.incidents:wifi-key-metrics].

**What counts as an incident.** The article says these metrics and thresholds are predetermined. Each incident type has a minimum number of impacted devices with bad scores and the dimensions that determine an impacted area: Application 50 (Country, Application); Last Mile ISP Blackout 20 (Geohash, ISP); Brownout minimum 10 across all customers and 5 per customer (Geohash, ISP); Intermediate ISP minimum 10 users per ASN and 10 users per customer (Geohash, ISP, CCID, ASN, ZIA Data Center); ZIA Public Service Edge minimum 100 across all customers and 10 per customer (ZIA Data Center); Wi-Fi 4 (ZIA Location, SSID); ZPA App Connector minimum 10 per customer per App Connector; ZPA Public Service Edge minimum 100 across all customers and 10 per customer (ZPA Data Center); Device System Software Crash 50 and Hang 50 (Devices). [zdx.dashboards.incidents:detection-thresholds] The alert article scopes the minimums differently [divergence:zdx.dashboards.incidents:minimum-scope]. What a bad score is and what severity levels exist are open [gap:zdx.dashboards.incidents:severity-and-bad-score].

What to check:
1. Whether the incident type's minimum number of impacted devices was reached before expecting an incident for a smaller group of affected users.
2. Whether the tenant's subscription supports Incidents before treating an empty Incidents Dashboard as no incidents.

Sources disagree (name both sides):
- The incident detection minimums: the Incidents Dashboard scopes them across all customers and per customer, while the alert-triggering article scopes them globally (across an organization) and locally (per location), and gives different numbers for a ZIA Public Service Edge incident. [divergence:zdx.dashboards.incidents:minimum-scope]
  - zscaler-help: A ZIA Public Service Edge incident needs a minimum of 100 impacted devices across all customers and 10 per customer; a Brownout 10 across all customers and 5 per customer.
  - zscaler-help: An incident requires a minimum number of impacted devices globally (across an organization) or locally (per location), with Global Minimum and Local Minimum columns in the incident table.
  - zscaler-help: The alert article's table row for a ZIA Public Service Edge incident reads 15, 120, 16, 120, Triggered under Global Minimum, Local Minimum, Global Total, Local Total and Alert Result.
  Impact: The dashboard says across all customers and per customer, the alert article says across an organization and per location, and for ZIA Public Service Edge the numbers differ (100 and 10 against a global minimum of 15 and a local minimum of 120); neither article reconciles them, so which one decides whether an incident exists or an alert triggers is not settled.
- In the Incidents Dashboard article, the metrics table row for Wi-Fi lists ZPA metrics, while the article's Wi-Fi section lists access point metrics. [divergence:zdx.dashboards.incidents:wifi-key-metrics]
  - zscaler-help: The table row gives the Wi-Fi key metrics as ZDX Score, first and second hop latency around ZPA and ZPA App Connector Cloud Path probe errors.
  - zscaler-help: The Wi-Fi section gives access point latency, packet loss per hop and signal strength as the key metrics.
  Impact: The metrics table row for Wi-Fi is not a safe source for Wi-Fi key metrics; the section's list is the one that matches the incident type.
