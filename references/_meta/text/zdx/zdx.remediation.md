# ZDX Remediation: remote PowerShell scripts, jobs, signing, prerequisites and troubleshooting (zdx.remediation)
Also called: remediation; zdx remediation; remote scripts; remediation jobs; custom script signing; predefined scripts; script templates; ZSAScript; script orchestrator service; remote powershell zdx

Remediation is ZDX's way of running remote PowerShell scripts on devices; its job error messages are in [Remediation job error messages and their ZUPM_WORKFLOW_ECODE reasons, grouped by what they report](kb:zdx.remediation.errors). Remediation lets IT admins anticipate potential issues and resolve them proactively by deploying remote scripts before end users report a problem: scripts are configured to run on devices and scheduled to run remotely at an appropriate time, PowerShell scripts can be run remotely to schedule system updates, gather information on the issue or fix it on impacted devices, and IT admins can view all configured scripts and Remediation jobs that are In Progress, Completed or Scheduled. [zdx.remediation:remediation-what]

**Requirements.** Using Remediation needs the appropriate ZDX subscription level, Remediation enabled, and admin permissions per page: Script Management (configure or view scripts on the Scripts page), Script Templates (import or view predefined scripts from the Scripts Templates page), Remediation Jobs (run or view jobs from the Remediation Jobs page) and Remediation Settings; a script does not run on a selected device that lacks the appropriate version compatibility and supporting OS. [zdx.remediation:remediation-requirements] On the device, PowerShell's Execution Policy must not be restricted (set with Set-ExecutionPolicy AllSigned or RemoteSigned at LocalMachine scope, checked with Get-ExecutionPolicy -List), and the article lists ZSAScriptOrchestratorService.exe and ZSAScriptExecutor.exe under the Zscaler\ZSAScriptOrchestratorService folder of %ProgramFiles(x86)% and of %ProgramFiles% as device prerequisites. [zdx.remediation:device-prerequisites]

**Subscription.** In the subscription table Remediation Settings are supported on Standard, Microsoft 365, Advanced and Advanced Plus; Standard, Microsoft 365 and Advanced get limited support for predefined scripts for Zscaler platform use and no custom scripts, while Advanced Plus gets additional predefined scripts (for example Service Desk or general purpose) and custom scripts; all tiers allow 1,000 configured scripts, 100 enabled scripts and 1,000 jobs, and Remediation data retention is 180 days on Advanced Plus and not supported on Standard, Microsoft 365 and Advanced. [zdx.remediation:remediation-tiers]

**Settings.** Enabling Remediation for users needs the minimum required versions of Zscaler Client Connector and ZDX Module, a ZDX subscription level that supports Remediation, the Full permission level for Remediation Settings, and End User Notifications enabled for Zscaler Client Connector. [zdx.remediation:settings-prerequisites] Selecting Enable Remediation creates user criteria for Remediation; the General settings of Remediation jobs include and exclude specific users, user groups, locations, location groups, departments and devices, and deleted or unknown users cannot be selected for the include and exclude criteria. [zdx.remediation:settings-criteria] In the Security setting, enabling Require Definitive Certification Revocation Status ensures each script is checked for certification validity, and when enabled a script cannot run on any device if its certification revocation status is invalid. [zdx.remediation:revocation-status] Who can change them is a role permission: [Role permissions for Remediation are chosen per page: the Scripts page, the Script Templates page (Full allows admins to import the templates as scripts), the Remediation Jobs page and the Remediation Settings page.](kb:shared.admin-rbac.zdx:remediation-permissions).

**Scripts.** Predefined scripts are certified, ready-to-use script templates that need no signing, can be imported only once, and when revoked (outdated because a newer version is on the Scripts > Templates page) cannot run and must be deleted and re-imported; custom scripts must be signed with a certificate before running; Zscaler recommends testing all scripts in a non-production environment first. [zdx.remediation:script-kinds] A script's status is Enabled, Disabled or Revoked, a script disabled from remediation job use cannot be run until it is enabled, and its type is Custom or Predefined. [zdx.remediation:script-status] A script is configured for the Windows operating system and uploaded as a PS1 file of at most 512 KB; it can run with elevated permissions on the system account, take parameters that are mandatory by default, and show end user notifications before running; a script runs for a maximum of 10 minutes, and the maximum number of scripts depends on the subscription. [zdx.remediation:script-config]

**Signing.** Each customized and uploaded script must carry a signed certificate to run on a device: the code signing certificate must be valid, not expired and added to the Trusted Publishers directories, with the CA that generated it uploaded to Trusted Root Certification Authorities and the certificate to Trusted Publishers; the CA can be an existing one in the organization or a self-signed CA for code signing; and a script that does not run on acceptance because of an expired or invalid certificate must be uploaded again with a valid script certificate. [zdx.remediation:signing] A custom script routes output to ZDX with the custom cmdlets set-zresult and set-zoutput; when the -Test flag is passed its output goes through PowerShell's write-output commands instead; only ASCII or UTF-8 without Byte Order Mark encoding is accepted in the Admin Console; scripts can be signed to run under AllSigned and RemoteSigned permissions, and each should be signed with a timestamp so the signature records when the code signing certificate expires. [zdx.remediation:script-authoring]

**Jobs.** A job's criteria select Devices, Users, User Groups, Locations, Location Groups or Departments, with Script Run Settings in seconds and a maximum wait in minutes, hours or days for devices to be online; a job can be scheduled for later, can be edited on the page if it is Scheduled, and can be deleted from any table to cancel or abort it. [zdx.remediation:job-config] A job's status is In Progress (currently running the remote script on selected devices), Scheduled, Completed - Aborted (stopped while running the script, possible if the job has not entered its ending phase) or Completed (successfully completed running the script on all selected devices). [zdx.remediation:job-status] Job details count the devices that completed the job (Success) and failed to run the script (Failed) against the number targeted, with an error message and script output per device; if a job is aborted ZDX tries its best effort to stop the script, and Rerun Job runs the job as a new job with prefilled criteria. [zdx.remediation:job-details]

**When a script does not run.** Devices can be grayed out during device selection because of incompatible version compatibility or inactive devices; a script may not run when the selected device is unavailable (not powered on, or not connected to Wi-Fi), when the device runs a Client Connector version older than 4.8.0.151 or a ZDX Module older than 4.6.0, when an admin aborted the job mid-way, or when Internet & SaaS (ZIA) policy blocks it (ps1 files blocked, or the URL policy blocking unknown URLs, for which the help says to allow ps1 files and the remediation URL into a URL category); a script signed with an expired or invalid certificate cannot run and must be signed again with an appropriate expiration and valid credentials. [zdx.remediation:troubleshooting]
