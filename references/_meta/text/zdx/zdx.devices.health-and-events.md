# ZDX device health metrics and device events (zdx.devices.health-and-events)
Also called: zdx health metrics; device health metrics; zdx cpu memory metrics; zdx wifi metrics; zdx device events; zdx events; device event categories; zdx network change event

Health metrics show what the device itself was doing; events show what changed on it. The device health-metrics read returns a device's health metrics trend, including CPU, Memory, Disk I/O, Network I/O, Wi-Fi and Network Bandwidth among others, for the last 2 hours if no time range is given. [zdx.devices.health-and-events:health-metrics] The complete category list is not published [gap:zdx.devices.health-and-events:health-category-list].

**Events.** The device events read returns a device's events trend, covering Zscaler, Hardware, Software and Network event changes, and defaults to the last 2 hours if no time range is given. [zdx.devices.health-and-events:events] Each event's category is one of Zscaler, Network, Software or Hardware. [zdx.devices.health-and-events:event-categories] Each event gives the name of the attribute, the event that occurred, and the attribute's previous and current values. [zdx.devices.health-and-events:event-values] The Go SDK's comment describes the same four categories, [The Go SDK describes ZDX per-device events as Zscaler, Hardware, Software and Network event changes for a device, each with prev and curr values, and says the endpoint defaults to the last 2 hours when no time range is given.](kb:shared.audit-logs:zdx-device-events).

**In the console.** On the console's user details page each device event is categorized by severity as Informational (non-critical details, like a notification), Warning (a component or application not in an ideal state that could lead to a critical error), Error (problems without needing immediate attention) or Critical (needs immediate attention, often system-wide, indicating failures or unresponsive applications). A side panel gives timestamps, category and attribute changes, and the category filter offers Zscaler, Hardware, Software and Network. [zdx.devices.health-and-events:event-severity] Whether the API's events carry a severity is open [gap:zdx.devices.health-and-events:severity-in-api]. On the user details page the Network and Disk options of Device Health are preselected by default. For users with an Advanced Plus subscription, the most impacted processes are also displayed for applicable CPU, Memory, Disk I/O and Network I/O, regardless of which graph is selected, with a maximum of 5 processes for each element within a given 5-minute interval. [zdx.devices.health-and-events:user-details-health] The crash reports name the user detail metrics available to analyze as examples: Applications, CPU Utilization, Memory, Battery Level, Disk, Network Bandwidth and User Device Events. [zdx.devices.health-and-events:report-metric-examples]

**Device Events reports.** Device events are captured in the Zscaler Admin Console to provide aggregated insights into common system and software crashes that impact users and their devices; the System Crashes and Software Crashes reports are shown for the previous 30 days by default, and the System Crashes report's time range selection is 2 Hours to 30 Days. They need an Advanced subscription level, the required minimum or later versions of Client Connector and ZDX Module and an admin role configured to view them; the subscription table lists Device Events Reports as not supported on Standard and Microsoft 365 and supported on Advanced and Advanced Plus. [zdx.devices.health-and-events:events-reports] The System Crashes report displays impacted Windows devices that experience system crashes: Blue Screens (system reboots due to a stop code or bug check code) and Unexpected Shutdown/Reboots (system reboots without a stop code, such as a long power button press), listed by impacted operating system, geolocation, vendor and model with total devices. [zdx.devices.health-and-events:system-crashes-report] The Software Crashes report shows software crashes for both Windows and macOS devices, while software hangs are shown for Windows devices only, with each software's publisher, whether a UI is impacted, total crashes, total hangs and impacted devices. The user details page can be accessed from the previous 14 days. [zdx.devices.health-and-events:software-crashes-report] The Device Health Score and profiles are in [The Device Health Score and the hardware and usage profiles of the Devices Overview](kb:zdx.devices.health-score).

**Time ranges.** Unlike most report reads, the device events read does not require a time range, [Most Report API endpoints and some Alert API endpoints require a 2-hour time range, so a longer period takes one request per 2-hour window; /devices/{deviceid}/events, /alerts/{alert_id} and /alerts/{alert_id}/affected_devices need no time range.](kb:shared.log-export.zdx:two-hour-window).

**Response key.** The contract puts the events list under `events`, while the Go SDK reads `instances`, [zdx.sdk-go.service-defects:events-key](kb:zdx.sdk-go.service-defects:events-key).

What to check:
1. Whether a device change (Client Connector, hardware, software or network) coincides with the score drop, from the device's events.
2. Whether CPU, memory, disk or Wi-Fi health on the device explains the drop before blaming the network.
