# ZDX collections: default collections, membership, ranking, criteria, deletion and limits (zdx.probes.collections)
Also called: zdx collection; zdx collections; unified communication collection; predefined apps collection; custom apps collection; default managed collection; default hosted collection; managed collection

A collection is how the console groups applications with their probes. A collection organizes applications with their probes: configuring an application assigns it to a collection and then configures its probes, and a collection can instead be created first and the application and probe added later. [zdx.probes.collections:what] The End User collection starts with three collections, the Unified Communication Collection, the Predefined Apps Collection and the Custom Apps Collection, and these default collections cannot be deleted. [zdx.probes.collections:default-collections]

**Membership.** A configured application in an End User collection can be in several collections, while a configured application for Managed Monitoring can exist in only one collection, so removing it from that collection also removes all its associated probes. [zdx.probes.collections:membership] The managed side's default collection is named two ways [divergence:zdx.probes.collections:managed-default-collection-name].

**Ranking.** When an end-user application is assigned to several collections its probes are ranked by collection, 1 being the highest priority: Unified Communication, then Predefined Apps, then Custom Apps, in alphabetical order if the application is in several Custom Apps collections. Customized collections can be dragged and dropped to change their ranking; default collections cannot. [zdx.probes.collections:ranking] How drag-and-drop ranking combines with the alphabetical rule, and what ranking changes for an application in several collections, is not stated [gap:zdx.probes.collections:collection-ranking].

**Criteria.** Each end-user collection can configure Inclusion and Exclusion criteria based on the probing criteria; under End User Collection Settings the Exclusion Criteria and Probing Criteria cover fields that include User Groups, Location Groups, Zscaler Locations and Departments. [zdx.probes.collections:collection-criteria] What an application in a collection does with its own probing criteria is in [Any application under a collection follows the collection's probing criteria instead of its own probing criteria.](kb:zdx.probes.criteria:collection-overrides). An end-user collection's settings include optional tags and an optional description. [zdx.probes.collections:collection-fields] Whether managed collections have criteria is open [gap:zdx.probes.collections:managed-collection-criteria].

**Removing, deleting and disabling.** An application cannot be removed from the Unified Communication Collection, nor from the Predefined Apps Collection if its status is Pending Onboard; removing an application from a collection removes it only for that collection. [zdx.probes.collections:remove-app] For End User Monitoring an application can be deleted from a custom collection or the Custom Apps Collection but not from the Unified Communication Collection or the Predefined Apps Collection, and its probes must be deleted before it; on the Managed Monitoring page the probe must be deleted before the application. [zdx.probes.collections:delete-app] Per Managing Collections, deleting a collection also removes any applications and their associated probes under it, except that deleting an End User collection removes an application that is in several collections only from the deleted one; for Managed Monitoring the probes attached to an application must be deleted before a collection can be deleted. [zdx.probes.collections:delete-collection] Deleting a managed collection is described two ways [divergence:zdx.probes.collections:managed-collection-delete], and so is deleting a probe on its own [divergence:zdx.probes.collections:probe-deletion]. Disabling a collection disables the applications within it, and for an End User application that is in another collection only for the disabled collection; disabling an application disables all its probes, and for End User collections disables it for all collections; after any change in status the changes must be activated. [zdx.probes.collections:enable-disable]

**Counts and limits.** The End User and Managed views have similar collection configurations and probe metrics, and some views might not show depending on the ZDX role and subscription level; for End User Monitoring the Configuration page gives the total number of enabled and disabled probes (Total) and the limited number of probes that can be configured (Limits). [zdx.probes.collections:probe-counts] The number of applications and probes that can be configured depends on the subscription level, and the subscription table's Collections row gives 1,000 in each of its four columns. [zdx.probes.collections:limits]

**In the API.** The contract's collection operations are not read here [gap:zdx.probes.collections:collections-api].

Sources disagree (name both sides):
- The managed side's default collection is named differently: About Configuration calls it the Default Managed Collection, and Understanding Collections the Default Hosted Collection. [divergence:zdx.probes.collections:managed-default-collection-name]
  - zscaler-help: The Managed collection starts with the Default Managed Collection.
  - zscaler-help: Understanding Collections names a Default Hosted Collection, alongside its statement that a configured application in the Hosted collection can only be in one collection.
  Impact: A search or an answer that uses one name misses the other; the pages do not say Hosted and Managed Monitoring are the same thing, though the Hosted collection's one-collection rule matches the Managed one.
- Deleting a managed collection: Managing Collections requires the probes attached to an application to be deleted first, while Managing Zscaler Managed Probes says deleting a collection deletes all its probes and companion probes. [divergence:zdx.probes.collections:managed-collection-delete]
  - zscaler-help: For Managed Monitoring the probes attached to an application must be deleted before the collection.
  - zscaler-help: Deleting a collection deletes all its probes and their companion probes.
  Impact: Whether a managed collection with probes can be deleted directly, or only once its probes are gone, depends on which page is right; the pages do not say.
- Whether a probe can be deleted on its own: Managing Collections says probes cannot be deleted by themselves, while Configuring a Probe gives a delete-probe procedure and Managing Zscaler Managed Probes says a probe and its companion can be deleted. [divergence:zdx.probes.collections:probe-deletion]
  - zscaler-help: Probes are removed only by deleting the collection or the application; they cannot be deleted by themselves.
  - zscaler-help: Configuring a Probe gives a procedure for deleting a probe for an application.
  - zscaler-help: A managed probe and its companion probe can be deleted.
  Impact: The same Managing Collections article also requires an application's probes to be deleted before the application, so its own limitation and its deletion order disagree; whether a probe can be deleted alone is not settled.
