# The four Diagnostics session types in the console: Deep Tracing, Hi-Fi Cloud Path, Bandwidth Test and Packet Capture Probing (zdx.diagnostics.session-types)
Also called: deep tracing session; hi-fi cloud path; high fidelity cloud path; bandwidth test; packet capture probing; pcap session; special application diagnostics; diagnostics session options; force reverse cloud path

A console Diagnostics session is one of four types, chosen when it is started; the sessions as a whole are in [ZDX Diagnostics Sessions (deep traces): what they are and where each part is covered](kb:zdx.diagnostics). Which minimum versions of Client Connector and ZDX Module a session needs depends on its type; Packet Capture Probing can be selected as an add-on with Deep Tracing, Bandwidth Test or Hi-Fi Cloud Path, which cannot be added to each other, and Packet Capture Probing cannot be selected when there are no compatible devices. [zdx.diagnostics.session-types:types-and-combinations]

**Duration and device.** For a Bandwidth Test no session duration can be set; with Packet Capture Probing selected together with Bandwidth Test, Deep Tracing or Hi-Fi Cloud Path the Run Session For option takes 5, 15, 30 or 60 minutes, and with Packet Capture Probing alone also 24 or 48 hours. [zdx.diagnostics.session-types:duration-options] A device that has an ongoing troubleshooting session or a version incompatibility appears grayed out in the device menu. [zdx.diagnostics.session-types:device-grayed-out] How long a Deep Tracing or Hi-Fi Cloud Path session runs on its own is not stated [gap:zdx.diagnostics.session-types:standalone-durations].

**Deep Tracing.** A Deep Tracing session analyzes issues a user, device or application faces when connecting to the network: with Device Probing enabled device data is available, and with it disabled user device statistics are not collected; the session needs at least one probe (Web or Cloud Path) and a Cloud Path probe can take optional thresholds for Packet Loss (in %) and Latency (in ms); selecting a Cloud Path probe configured to follow a Web probe selects that Web probe; network applications require only a single Cloud Path probe and no Web probe; and a special application added by a URL or tenant URL, for an application without an existing probe, is not included in the sessions limit. [zdx.diagnostics.session-types:deep-tracing-options] Deep Tracing results show Web Probe Metrics (Page Fetch Time, Zscaler Time to First Byte, DNS Resolve Time and Availability) unless no Web probe was selected, and the Cloud Path section only if a Cloud Path probe was selected, with a gap in the charts and an error message when there is no data for two consecutive time points; Device Health (CPU Utilization, Memory, Battery Level, Disk and Network), Top Processes by CPU, Disk I/O, Memory and Network I/O with the Process ID, and User Device Events are listed unless Device Probing was disabled; network applications have no Web Probe Metrics. [zdx.diagnostics.session-types:deep-tracing-results]

**Hi-Fi Cloud Path.** A Hi-Fi (High Fidelity) Cloud Path session is one where a Cloud Path run sends a high number of packets: Packet Count is the number of probe packets sent per hop discovery with the same TTL value, between 20 and 300 (default 300); Protocol is ICMP, TCP or UDP, with a port number for TCP or UDP; the time interval and the timeout (the time to wait for a response to a probe packet before considering loss) must each be within 1000 to 3000; Destination is IP/FQDN or Zscaler Service Edge; and a setting forces a reverse traceroute when a network device blocks the forward Cloud Path, or otherwise calculates reverse latency from the Public Service Edge for Internet & SaaS to the egress. [zdx.diagnostics.session-types:hifi-options]

**Packet Capture Probing.** Packet Capture Probing takes a Packet Capture Filter of destination IP addresses and/or ports, a Network Interface (default All Interfaces), a Frame Size Limit from 100 to 65,536 bytes (default 1514) and, for ZDX version 4.5 and later, a Disk Space Limit of 100 MB, 200 MB, 500 MB, 1 GB, 2 GB or 4 GB for the PCAP file; its result gives the file path, packet capture filter and network interface, and is viewed in the History table once the session completes. [zdx.diagnostics.session-types:pcap-options] Whether the console's capture filter is the contract's PCAP filter expression is not stated [gap:zdx.diagnostics.session-types:pcap-filter-link].

**Results of Hi-Fi Cloud Path and Bandwidth Test.** Hi-Fi Cloud Path results give the Zscaler data center's name, proxy hostname and the ZDX cloud name and the ISP the user device is connected to, with a map of where the impacted device and data center are; Bandwidth Test results give the data center's proxy hostname and the user's ISP, with the same map. [zdx.diagnostics.session-types:hifi-bandwidth-identity] A Bandwidth Test shows download and upload bandwidth speeds for the tunnel when the device is on Z-Tunnel 1.0 or Z-Tunnel 2.0, and DNAT download and upload speeds when the device is connected directly with IPSec and GRE tunnels, which needs the minimum ZDX Module version; its basic diagnostics are a Fragmentation Test (whether fragmentation is supported), UDP Connectivity and DNS Connectivity latency, and ICMP latency and jitter. [zdx.diagnostics.session-types:bandwidth-results]

**Versions.** The minimum versions are not given in these articles [gap:zdx.diagnostics.session-types:minimum-versions]; [Minimum Client Connector and ZDX Module versions per OS and ZDX feature](kb:zdx.compatibility.supported-versions) gives them in part.
