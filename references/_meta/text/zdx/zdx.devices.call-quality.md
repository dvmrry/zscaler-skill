# ZDX call-quality metrics per device and meeting (zdx.devices.call-quality)
Also called: zdx call quality; call quality metrics; cqm; zdx teams call quality; zdx zoom call quality; call-quality-metrics; meet_id

Call quality comes from the meeting platforms rather than from probes, [The ZDX cloud integrates with the Microsoft Graph API or Zoom to read meeting and call quality data, and customer-specific onboarding is needed before ZDX can read it.](kb:zdx.cloud-architecture:call-quality), once a tenant is onboarded, [For unified communication applications a tenant must be onboarded before their probes can be configured; the onboarding articles cover Microsoft Teams, Webex and Zoom call quality.](kb:zdx.applications:uc-tenant-onboarding). The call-quality read returns the Call Quality metric trend for a device for a CQM application, for the last 2 hours if no time range is given. [zdx.devices.call-quality:cqm-read]

**Per meeting.** Each entry is a meeting, with its meeting ID, meeting session ID and subject, and a `metrics` array of series. [zdx.devices.call-quality:meeting-fields]

**Platforms.** Microsoft Teams, Webex and Zoom Call Quality each allow monitoring actual one-to-one calls or meetings among two or more participants in a configured tenant. For Teams, the Call Quality ZDX Score can reflect either a Mean Opinion Score (MOS) average or metric thresholds for latency, jitter and packet loss, and user and device information from Microsoft for call participants is mapped to ZDX users and devices. [zdx.devices.call-quality:platforms-monitored] Microsoft Teams call data is retrieved using the Microsoft Graph API when a call has ended; the Graph API only provides data for the entire call after it has completed, so partial data for meetings in progress is not captured, and call data might take 15 minutes to 1 hour to be available after a meeting has ended. [zdx.devices.call-quality:teams-data-timing] Webex call data is retrieved using the Webex API and captured in real time, available 5 minutes after the start of a call; call data for meetings in progress is captured every 5 minutes and shown as In Progress, and complete call data is available approximately 10 minutes after a call has ended. [zdx.devices.call-quality:webex-data-timing] Zoom call data is retrieved using the Zoom API and captured in real time as a meeting is in progress, every 5 minutes, with complete call data available approximately 10 minutes after the call has ended. Zoom Call Quality receives webhook notifications from Zoom when a meeting starts or stops, ZDX then makes periodic QoS user API calls, and only meetings with two or more participants that last more than one minute are collected and displayed. [zdx.devices.call-quality:zoom-data-timing] Zoom Call Quality needs a Zoom API tenant or Zoom QSS tenant onboarded, a ZDX subscription and ZDX admin access, and the Zoom scopes dashboard_meetings:read:admin (meeting data), meeting:read:admin (webhook start and stop meeting notifications) and user:read:admin (user data). Due to the Zoom API rate limit of 60,000 per day, Zoom Call Quality might be impacted by other applications using the API, which could cause some meeting information to be unavailable. The subscription table lists ZDX Autosense (Zoom Call Quality) as not supported on Standard and Microsoft 365 and supported on Advanced and Advanced Plus. [zdx.devices.call-quality:zoom-requirements]

**The Call Quality page and the Meetings dashboard.** A Microsoft Teams Call Quality page filters by time range, Departments, Zscaler Locations, User Groups, Geolocations, Location Groups and Last Mile ISPs; the time range is between 2 Hours and 48 Hours or a custom range, with a default of 2 Hours. It shows the ZDX Score for Call Quality over the entire duration of a call for all users, the meeting participant locations, the impacted meetings with the lowest ZDX Score at the top, and the Cloud Path probes configured as part of the Call Quality application. [zdx.devices.call-quality:call-quality-page] For Microsoft Teams, meetings are not reported if none of the participants are monitored ZDX users, and the internal meeting ID is displayed, not the actual meeting topic name. Participants who join from multiple devices or leave and rejoin are counted per session, up to 1,000 meetings are displayed, and blank ZDX Score and MOS fields indicate that no score is available; Zoom also displays a meeting UUID and the meeting ID visible to the end user. [zdx.devices.call-quality:meeting-reporting-rules] A MOS is displayed only if metrics for latency, jitter and packet loss are all available. A meeting's sessions and user devices give the session ID, device OS, IP address, geolocation and audio type, and some Teams IP addresses might be truncated by Microsoft for privacy reasons; details are unavailable for external users, guest users, ZIA users without ZDX enabled, devices that do not map to a registered ZDX device, users not monitored for Call Quality, and users with insufficient information to map to a ZDX device. [zdx.devices.call-quality:meeting-details] The values for Audio, Video and Sharing Quality are displayed with latency and jitter ranges starting at 0 ms, and average loss and maximum loss from 0 to 100%. [zdx.devices.call-quality:user-detail-ranges] The Meetings dashboard provides an overview of the performance of meetings and video conferencing applications in the organization. Its MOS Score is the Mean Opinion Score of the meeting on a scale of 1 (worst) to 5 (best), calculated from metrics such as latency, jitter and packet loss, and its list gives the host, the number of active participants as reflected in the session data, and per participant the session ID, device OS, IP address, geolocation and individual MOS and ZDX scores. [zdx.devices.call-quality:meetings-dashboard]

**Scoring.** If metrics for latency, jitter and packet loss are all available, the MOS, which uses a transmission rating factor (R-Factor) derived from those metrics, determines the ZDX Score: a MOS of 0 to 3.6 is Poor, greater than 3.6 but less than 4.34 is Okay, and 4.34 or greater is Good. [zdx.devices.call-quality:mos-bands] If only one or two of the metrics is available, metric thresholds are used: latency above 500ms, jitter above 30ms or packet loss above 0.1% are the thresholds listed, and the ZDX Score uses the lowest metric-based score of the available metrics (latency 550ms scored 30 and jitter 26ms scored 70 give 30). If all three metrics are unavailable, the ZDX Score for Call Quality cannot be calculated and data is not displayed. [zdx.devices.call-quality:metric-thresholds] The MOS scale starts at 1 while the Poor band starts at 0 [gap:zdx.devices.call-quality:mos-range].

**Zoom monitoring criteria.** For Zoom, Inclusion Criteria monitors and displays meetings only for the selected ZDX users, and Exclusion Criteria excludes selected users from monitoring. If the host is excluded the meeting metrics are not monitored; if another participant is excluded the meeting metrics are visible but the excluded participant's monitoring metrics are not. [zdx.devices.call-quality:zoom-criteria]

**Open.** Which applications populate this read and which metric names appear in its series are not enumerated [gap:zdx.devices.call-quality:cqm-scope].
