# Web probe error messages in ZDX: what each reports and what the help suggests (zdx.probes.web-probe-errors)
Also called: web probe errors; web probe error icons; web probe is rate limited; http response code not a success code; tcp connection reset web probe; http connect request failed zdx

Web probe errors are the messages shown for a Web probe in the user details; the probe is defined in [ZDX probes: Web and Cloud Path probes, what they measure and how they run](kb:zdx.probes), and the Cloud Path equivalents are in [Reading the Cloud Path: the Hop View and Command Line View, tunnels, protocols, edges, and the error messages](kb:zdx.probes.cloud-path). Web probe errors show as icons in the Web probe Metrics section of the user details, as a warning (action might be necessary to achieve accurate results), a critical error (could affect the user experience) or a Private Access Web probe that is rate limited. [zdx.probes.web-probe-errors:error-icons]

**DNS and TCP.** A domain that is invalid or not resolvable fails DNS resolution after redirection, which could be an issue with the application or its domain; the help says to verify the domain configured in the application is still valid and to check the application redirection. [zdx.probes.web-probe-errors:dns-failure] Direct TCP errors: reset (could be a firewall or security policies, lack of server resources, server error or congestion), timed out waiting for a response (check the configured application and network devices that might silently drop SYN packets), aborted after a TCP reset message was received once the connection was established (high numbers can point to network or server problems), refused (no port is listening or a firewall is blocking it; check the port and that security policies allow it) and a generic TCP connection error (contact Zscaler Support). [zdx.probes.web-probe-errors:direct-tcp]

**Method and response code.** An unsupported HTTP method error means Zscaler does not currently support the request method, since only the GET method can be configured from the UI; the help suggests checking the Web probe configuration and considering adding a 40X or 50X code to build a valid success code. [zdx.probes.web-probe-errors:http-method] An HTTP response code outside the configured list of successful codes fails the probe; the help says the Web probe is configured to consider HTTP connections in the ranges 100-199, 200-299 and 300-399 successful, and suggests reconfiguring the success codes to include 400-499 client errors, and 500-599 server errors if those are also transiently received. [zdx.probes.web-probe-errors:response-code] The API contract's default success codes differ from this list, see [ZDX probes: Web and Cloud Path probes, what they measure and how they run](kb:zdx.probes).

**Through the Public Service Edge.** HTTP CONNECT errors come from the Public Service Edge for Internet & SaaS: reset or timed out when it received no response from the destination server (check authentication and a valid policy, or the URL in the Web probe configuration), aborted or refused after a TCP reset from the destination server (check the URL, port and security policy), an invalid HTTP response code (contact Zscaler Support), and a generic failure to send the connection (verify the Public Service Edge is not blocked by the firewall). [zdx.probes.web-probe-errors:connect-errors]

**To the application.** Errors during the HTTP request to the application: reset or aborted by the application server (probably due to a high load on the application), timed out (no response from the server in the configured timeout, 60 seconds by default), refused (verify the configured port is open on the server and whether a firewall in the path blocks the connection) and a generic application server error. [zdx.probes.web-probe-errors:app-request-errors] HTTPS errors: a failure due to an invalid certificate received from the application server (verify its validity and that it has not expired), an SSL context exception, and a generic SSL error that could have multiple possible causes; the row "An SSL context exception error occurred" says the application server SSL handshake has a generic exception and lists an improperly formatted SSL certificate, an improperly installed certificate, a wrong cipher and a problem in the certificate's chain of trust as possible causes. [zdx.probes.web-probe-errors:https-errors]

**Timeout and rate limiting.** A Web probe request times out when the HTTP request exceeds the configured timeout (60 by default; verify the URL or change the timeout); a Web probe is rate limited when it failed due to Private Access rate limiting to control the probe threshold, and for internal applications through Private Access the help says to configure probes only for users, user groups and departments that use the application. [zdx.probes.web-probe-errors:timeout-and-rate-limit] Rate limits throttle the number of successful connections per application segment for Public Service Edges for Private Access or Private Service Edges for Private Access when using web probes for ZDX integrations: 50 web probe requests per second to the server for an individual Public Service Edge, and 35 for an individual Private Service Edge. In the page's example, with a maximum rate limit of 50 requests per second only 50 successful connections are allowed to the server within each second. The limits protect application servers, and adjusting them is done through Zscaler Support. [zdx.probes.web-probe-errors:private-access-rate-limit] Whether the per-second limit counts per application segment per Service Edge instance or across instances is open [gap:zdx.probes.web-probe-errors:rate-limit-threshold].
