# Z-Tunnel 1.0 and 2.0: what each carries and how a profile selects one (zcc.z-tunnel.versions)
Also called: z-tunnel 1.0 vs 2.0; z-tunnel 2.0; z-tunnel 1.0; ztunnel; users still on z-tunnel 1.0; tunnel version selection; why is this traffic not tunneled

Tunnel mode carries traffic in a Z-Tunnel, and the version decides which traffic that can be.

**The two versions.** Z-Tunnel 1.0 is a CONNECT-based proxy for proxy-aware or port 80/443 traffic, and Z-Tunnel 2.0 a DTLS or TLS packet tunnel for all ports and protocols: [Z-Tunnel 1.0 forwards traffic by CONNECT requests, like a traditional proxy, sending all proxy-aware traffic or port 80/443 traffic depending on the forwarding profile; it is selected in a forwarding profile in Tunnel mode with the packet filter driver enabled.](kb:zia.traffic-forwarding.zcc:z-tunnel-1), [Z-Tunnel 2.0 sends packets over DTLS or TLS and can carry all ports and protocols; using it means deploying a supported Client Connector version, selecting Z-Tunnel 2.0 in a Tunnel-mode forwarding profile with the packet filter driver enabled, and configuring bypasses in App Profiles.](kb:zia.traffic-forwarding.zcc:z-tunnel-2). Traffic Z-Tunnel 1.0 does not carry, such as QUIC, does not reach Zscaler: [So when the only traffic sent to Zscaler is Client Connector traffic on Z-Tunnel 1.0, or TCP 80 and 443 over a tunnel, QUIC UDP does not reach Zscaler at all, and no Zscaler Firewall Filtering rule inspects or blocks it.](kb:zia.saas-apps.quic-conferencing:tunnel1-udp-leaves).

**Selecting one.** In Tunnel mode the forwarding profile's Tunnel Version Selection chooses the Z-Tunnel version, and the field appears only when the Packet Filter-Based driver is selected; choosing Z-Tunnel 2.0 opens the Advanced Z-Tunnel Configuration settings. [zcc.z-tunnel.versions:version-select-needs-pf] The driver setting and the 4.8 rule are in [The profile's Tunnel Driver Type applies to Windows devices in Tunnel mode: Route-Based creates a virtual network adapter and uses OS routing; Packet Filter-Based, the default, uses Windows filtering, allows more granular control over traffic, reduces interoperability issues for applications that manage network adapters, lets VPN clients interoperate better with the app, and is required for packet capture.](kb:zcc.forwarding-profiles.internet-actions:driver-types) and [Client Connector 4.8 and later for Windows does not use the route-based driver: it always uses the packet filter-based driver, whatever the profile says.](kb:zcc.forwarding-profiles.internet-actions:driver-48). Because the version is a forwarding profile setting, a tenant can run Z-Tunnel 1.0 and 2.0 at once for different users through different forwarding profiles and app profiles, as the vendor's rollout does with a separate test profile. [zcc.z-tunnel.versions:per-profile-version]

**Z-Tunnel 1.0 on a 2.0 profile.** A profile set to Z-Tunnel 2.0 still sends web traffic over Z-Tunnel 1.0 when 2.0 cannot be set up and the setup failure behavior falls back to 1.0, when Redirect Web Traffic is on without Use Z-Tunnel 2.0 for Proxied Web Traffic, and when a request arriving on the Client Connector listening proxy matches an app profile PAC statement that sends it to a specific Public Service Edge. [zcc.z-tunnel.versions:web-on-1-under-2] The NAT requirement behind the first case is [Z-Tunnel 2.0 needs a NAT device that uses a single IP for all connections from one device; otherwise control and data connections can land on different Service Edges, Z-Tunnel 2.0 fails to establish and the client falls back to Z-Tunnel 1.0.](kb:zia.traffic-forwarding.zcc:z-tunnel-2-single-ip-nat). Whether other traffic also lands on 1.0 is open [gap:zcc.z-tunnel.versions:other-1-0-cases].

Transport, MTU and setup failure settings are in [Z-Tunnel 2.0 transport: DTLS and TLS, fallback, MTU, and what happens when the tunnel cannot be set up](kb:zcc.z-tunnel.transport); bypasses in [Bypasses for Z-Tunnel 2.0: VPN gateway bypasses, destination exclusions and inclusions, domain bypasses](kb:zcc.z-tunnel.bypasses); the rollout sequence in [Rolling out Z-Tunnel 2.0 and migrating from 1.0](kb:zcc.z-tunnel.deployment).

What to check:
1. Which Tunnel Version the device's profile selects for its network type, and that the driver is packet filter-based.
2. For a 2.0 profile whose web traffic shows as Z-Tunnel 1.0: the NAT in front of the device, the setup failure behavior, the listening proxy options, and whether the request matched a PAC statement that names a Service Edge.
