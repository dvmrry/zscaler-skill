# Who installs the SSL inspection certificate on Client Connector devices, per platform (zcc.ssl-inspection.certificate-install)
Also called: install zscaler ssl certificate; install_ssl_certs; installCerts; zcc root ca install; zscaler certificate ios; zscaler certificate android; zscaler certificate macos big sur; when does zcc install the certificate

Inspected traffic is re-signed with a Zscaler certificate, so the device must trust the Zscaler root: [With the default Zscaler intermediate certificate every client must have the Zscaler root certificate installed; otherwise browsers and applications show warnings or the traffic cannot be inspected properly.](kb:zia.ssl-inspection.certificates:root-must-be-trusted). Depending on the platform, either Client Connector or the MDM installs the Zscaler SSL certificate that SSL inspection needs. [zcc.ssl-inspection.certificate-install:who-installs]

## By platform

| Platform | Who installs the certificate |
| --- | --- |
| Windows and Linux | For Windows, Linux and macOS, Client Connector installs the certificate automatically when Install Zscaler SSL Certificate is enabled in the platform's app profile (on macOS only before Big Sur 11; see big-sur). [zcc.ssl-inspection.certificate-install:desktop-toggle] |
| macOS | Install Zscaler SSL Certificate is not supported on devices running macOS Big Sur (11) and later. [zcc.ssl-inspection.certificate-install:big-sur] The macOS deployment guides push the CA certificate needed for SSL inspection with a certificate configuration profile from the MDM (a Certificate payload in Jamf Pro with Allow all apps access, a Trusted certificate template in Intune), using the Zscaler root certificate downloaded from Internet Access > Resources > SSL Intermediate Certificate, or a custom root or intermediate. [zcc.ssl-inspection.certificate-install:macos-mdm-profile] In the Workspace ONE UEM macOS guide, the unzipped root certificate file is renamed to a .crt extension, uploaded and attached in the profile, and Allow access to all applications is enabled. [zcc.ssl-inspection.certificate-install:workspace-one-macos] |
| Android | On Android, Client Connector does not install the certificate automatically and Zscaler recommends installing the root through the MDM; it installs certificates only on Samsung devices with administrator privileges, from Install Certificates in the app's More window. [zcc.ssl-inspection.certificate-install:android] From Android 7.0, non-default certificate authorities are not trusted by apps unless the app's developer explicitly allows it, so the Zscaler certificate is not trusted by such apps. [zcc.ssl-inspection.certificate-install:android-7] |
| iOS | On iOS, Client Connector does not automatically install the certificate, because Apple requires certificates installed by an application to be untrusted by default; Zscaler recommends installing the root through the MDM. [zcc.ssl-inspection.certificate-install:ios] For iOS, the Intune guide pushes the CA certificate for SSL inspection with a certificate profile for the iOS/iPadOS platform using the Trusted Certificate template and the uploaded .crt file; the certificate is the default Zscaler Central Authority certificate (found under Internet Access > Resources > SSL Intermediate Certificate, in the ZscalerRootCerts.zip file to unzip) or a custom Root CA certificate. [zcc.ssl-inspection.certificate-install:ios-intune-profile] Which MDM payload the vendor recommends for other MDMs is open [gap:zcc.ssl-inspection.certificate-install:ios-payload]. |
| ChromeOS | Only user traffic can be inspected: [ChromeOS does not trust managed or user-installed certificates for OS-level communication, so only user traffic can be inspected; the traffic between the device and Google's ChromeOS services must be exempted, using a custom URL category of the required domains.](kb:zia.ssl-inspection.certificates:chromeos). The ChromeOS Flex guide says the certificates must be installed manually on ChromeOS Flex, Android and iOS devices, or using the Google Admin console; for ChromeOS Flex, the certificate is uploaded in the Google Admin console under Devices > Networks for an organizational unit, in the Certificates section, selecting the platform for which the certificate acts as a certificate authority. [zcc.ssl-inspection.certificate-install:chromeos-flex] |

On mobile devices the certificate goes through MDM in any case: [Installing the certificate on mobile devices requires Mobile Device Management, which is also commonly the best way to deploy Client Connector.](kb:zia.ssl-inspection.certificates:mobile-mdm). Named deployment channels beyond the macOS profiles above remain open in [SSL/TLS inspection certificates: who signs, and where the root must be trusted](kb:zia.ssl-inspection.certificates).

## When Client Connector installs it

The certificate is imported on enrollment, when the admin modifies the app profile and the device checks in for it, when Client Connector updates, and when the user clicks Update Policy; each time, Client Connector gets the certificate link from the Admin Console and attempts the installation. [zcc.ssl-inspection.certificate-install:install-events] When a certificate is already deployed and a new one is uploaded, Client Connector installs it with a native Windows method, replacing the existing certificate if it is new or different and leaving it alone if it is the same. [zcc.ssl-inspection.certificate-install:replacement]

**In the app profile and the API.** The setting, and the custom certificate that can replace Zscaler's, belong to the app profile: [With Install Zscaler SSL Certificate enabled, the app installs the Zscaler certificate automatically, or the organization's custom certificate if one was uploaded; deployments using the app for Private Access only skip the option.](kb:zcc.app-profiles.ssl-certificate:install-option); the iOS profile has no such setting: [The iOS app profile has no certificate setting: the iOS section of the help, the API's `iosPolicy` block and the Go SDK's iOS block carry none.](kb:zcc.app-profiles.ssl-certificate:no-ios-option). The Go SDK sends the macOS key in snake_case, and its model says the camelCase form was silently ignored: [The Go SDK sends the macOS block's password and certificate keys in snake_case (`disable_password`, `install_ssl_certs`, `logout_password`, `uninstall_password`), with `install_ssl_certs` a JSON number; its model says earlier camelCase tags were silently ignored by the API and produced `{"success":"false","id":0}` on `/edit`.](kb:zcc.api.web-policy-wire:mac-snake-or-ignored).

What to check:
1. Whether Install Zscaler SSL Certificate is enabled in the app profile for the device's platform (Windows, Linux, macOS before Big Sur).
2. On macOS 11 or later, iOS and Android, whether the MDM pushes the root certificate.
3. After uploading a new certificate, whether the device has since enrolled, checked in for a modified profile, updated, or had Update Policy clicked.
