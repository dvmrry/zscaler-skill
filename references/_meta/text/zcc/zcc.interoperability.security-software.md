# Allowlisting Client Connector in antivirus and host firewalls: paths, processes, firewall directions and the 100.64 range (zcc.interoperability.security-software)
Also called: processes to allowlist; antivirus allowlist; host firewall rules; installed footprint

Endpoint protection can block Client Connector unless its binaries and processes are allowlisted. Zscaler recommends that users' devices have inbound rules that allow the Client Connector binaries and processes, and for some endpoint protection products such as antivirus and personal firewalls additional allowlists might need updating for full functionality. Because the app modifies the networking component of the operating system, Symantec Tamper Protection can trigger a false positive for the Zscaler service; the page says the warning can be ignored but the allowlist for Symantec Tamper Protection must be updated. [zcc.interoperability.security-software:why-allowlist]

**Windows paths.** If an organization uses Group Policy Object (GPO) to push policies to both Windows 32-bit and 64-bit systems, the file paths of both versions must be in the GPO policy; the 32-bit files reside in the %ProgramFiles(x86) folder even on a 64-bit system, and Zscaler recommends migrating Windows 32-bit devices to 64-bit. Program files are typically on the C drive, with exceptions such as the D drive on Amazon WorkSpaces. [zcc.interoperability.security-software:windows-paths-by-bitness] The 64-bit Windows allowlist includes, by full path under %ProgramFiles%\Zscaler, ZSAHelper, ZSATray, ZSAMTAuthApp, ZSATrayManager, ZSATunnel, ZSAService, ZSAUpdater and ZSAUpm, the updater and checksum verifier, the WebView2 setup file, ZDPService.exe and the ZEPInstaller folder, plus the Edge WebView2 runtime's msedgewebview2.exe under %ProgramFiles(x86)%. [zcc.interoperability.security-software:windows-64-paths]

**macOS and Linux paths.** On macOS the allowlist includes /Applications/Zscaler/Zscaler.app/, the UPMServiceController, the com.zscaler.zscaler Client Connector identifier, /Library/Application Support/Zscaler/ZDP and, only with Transparent Proxy-based Traffic Interception, com.zscaler.zscaler.TRPTunnel, with all binaries under each path; the autoupdate ZscalerUpdater file is required only for Client Connector 3.7 and earlier for macOS. It also lists /opt/zscaler/bin/zsaservice, zstunnel, ZSTray and zsupdater, and /opt/zscaler/ZSAUpm/bin/ZSAUpm. [zcc.interoperability.security-software:macos-linux-paths]

**Host firewall rules.** With a GPO-managed or AV-managed host firewall, firewall rules can be configured for ZSATunnel.exe processes for all ports, protocols, network interfaces and network addresses. Client Connector also uses the carrier-grade NAT range 100.64.0.0/16 for internal health checking and for the Private Access service; if Zscaler sees a conflicting IP address it changes the range (for example to 100.65.0.0/16), anywhere from 100.64.0.0/16 to 100.83.0.0/16. [zcc.interoperability.security-software:cgnat-range] The synthetic IP range page says an organization can configure Client Connector to use an IP range beyond the default range of 100.64.0.0/16 for its Private Access applications, entered, as a range between 100.64.0.0/16 and 100.127.0.0/16 (the page writes the upper bound with a stray period), in the Zscaler Client Connector Synthetic IP Range field on the Endpoint Integration tab. [zcc.interoperability.security-software:synthetic-range] If the LAN operates on the same synthetic IP range that Client Connector uses for Private Access, Drop Non-Zscaler Packets in Synthetic IP Range makes Client Connector block non-Zscaler packets destined for the synthetic IP range; the option is disabled by default, and when disabled non-Zscaler packets are bypassed. [zcc.interoperability.security-software:drop-non-zscaler] The Windows firewall bypasses listed are ZSATunnel.exe inbound and outbound, and outbound for ZSATray.exe, ZSATrayManager.exe, ZSAUpdater.exe, ZSAService.exe, Zscalerappupdater.exe, ZDPService.exe and ZEPInstaller.exe. Client Connector automatically adds required rules to Windows Defender Firewall, but if the Local Policy Merge GPO setting is enabled the rules are ignored and the firewall rules must be set up via the GPO; with Microsoft Defender Antivirus, any excluded paths and processes from the allowlist must be configured as custom exclusions. [zcc.interoperability.security-software:windows-firewall-directions]

On macOS, if machine tunnels are used with Transparent Proxy-based Interception mode enabled, inbound traffic to ZscalerTunnel must be allowed in firewall rules to allow access to Private Access apps, and FileVault must be disabled to allow Private Access connections before a user logs in. The macOS rules listed are Zscaler, ZscalerService and ZscalerUpdater outbound; ZscalerTunnel and UPMServiceController inbound and outbound; the autoupdate ZscalerUpdater inbound; and zdpd outbound. [zcc.interoperability.security-software:macos-firewall] Client Connector for Linux relies on the iptables command-line tool to configure the necessary rules within Netfilter. The vendor's commands, entered in the specified order, delete all rules, allow all outgoing connections, loopback connections, DHCP traffic, optionally SSH traffic, internal connections to the Client Connector adapter at 100.64.0.1, and established and related incoming connections, then deny everything else incoming. [zcc.interoperability.security-software:linux-iptables]

**When a local firewall or antivirus error appears.** For a local FW/AV error after entering the rules, the vendor says to examine %windir%\system32\logfiles\firewall\pfirewall.log for drop entries for 100.64 addresses; drop entries mean the Windows Firewall rules are not applied correctly to allow Zscaler to communicate, and the rules must be revised based on the processes listed. [zcc.interoperability.security-software:fw-av-error-check]

**What the processes do.** Windows process roles per the article: ZSATray is the app UI; ZSATrayManager manages the tray process and checks signatures for communication between tray and system services; ZSATunnel handles traffic tunneling; ZSAService is the main service and the watchdog of all other services; ZSAUpdater monitors automatic updates; ZSAUpm is the Digital Experience (ZDX) service; zscalerchecksumverifier ensures the update being launched is legitimate; NetworkAdapter is the network adapter used in Tunnel (Route-Based); ProgramData\Zscaler stores logs, PCAPs and configuration; LogonUI is used for pre-Windows login in Private Access; ZDPService.exe evaluates DLP policy rules and determines the protection action; ZEPInstaller.exe prevents end users from stopping, modifying and deleting Zscaler products and services; ZSAMTAuthApp.exe supports authentication for the Machine Tunnel feature. [zcc.interoperability.security-software:windows-processes] macOS process roles per the article: Zscaler provides the app interface; ZscalerService manages background service operations and communication between components; ZscalerTunnel handles network traffic tunneling; ZscalerUpdater manages software updates; UPMServiceController supports Digital Experience (ZDX) functionality; zdpd supports endpoint data protection functionality; com.zscaler.zscaler.TRPTunnel handles transparent proxy-based traffic interception. [zcc.interoperability.security-software:macos-processes]

**What installation creates.** On Windows, installation creates the Zscaler-Network-Adapter folder and three services: ZSAService (a management service), ZSATunnel (a packet handling service that tunnels traffic to the Zscaler service) and ZSAUpdater (the update service). On macOS the Zscaler folder is in the list of applications, and on Linux the /opt/zscaler directory is created. [zcc.interoperability.security-software:installed-footprint]

**Open.** How the 100.64 range is chosen when it changes, and where the active range shows, is open [gap:zcc.interoperability.security-software:cgnat-range-selection].

What to check:
1. For a local FW/AV error after rules were entered, the Windows firewall log for drop entries to 100.64 addresses.
2. For a Windows device with the Local Policy Merge GPO setting enabled, whether the required firewall rules come from the GPO rather than from Client Connector.
3. Whether a GPO that serves both 32-bit and 64-bit Windows carries the paths of both builds.

Not known (open gaps):
- How the 100.64 range is chosen when it shifts, and where the active range can be seen [gap:zcc.interoperability.security-software:cgnat-range-selection]: settled by lab-test or support-ticket
