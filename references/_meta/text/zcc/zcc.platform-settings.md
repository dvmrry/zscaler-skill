# Platform Settings: the per-OS console settings for sign-in, IPv6, ZDX upgrades, default UI and unattended-mode passwords (zcc.platform-settings)
Also called: Edit Platform Settings; platform settings zcc; WebView2 authentication; browser-based authentication; Enable IPv6 Resolution for Zscaler Domains; Allow ZDX Client Upgrade via CLI; WBC User Agent; Zscaler Client Connector Window Resizing

The Platform Settings page lists different settings per OS. Windows: Browser-Based Authentication, WebView2 authentication, authentication window resizing, the global default log mode, IPv6 resolution for Zscaler domains, ZDX Module upgrades through the CLI, and passwords for unattended mode. macOS: the authentication browser type, the global default log mode and IPv6 resolution. Linux: Browser-Based Authentication and the global default log mode. iOS: Browser-Based Authentication, the global default log mode and Use Device Groups in Service Entitlement. Android: Browser-Based Authentication, the global default log mode, IPv6 resolution and Use Device Groups in Service Entitlement. [zcc.platform-settings:per-os-settings] The page lists the simplicity of setting the global default log mode for all new policies at once, instead of having to configure the setting for each new customer. [zcc.platform-settings:global-log-mode] The log mode itself is in [Client Connector log modes as users and the API see them: Verbose, user choice, logMode and logLevel](kb:zcc.logging.log-modes).

**IPv6.** Enable IPv6 Resolution for Zscaler Domains lets Client Connector connect to IPv6 Zscaler servers from an IPv6-only device. It is available only on Client Connector 4.8 and later for Windows, 4.7 and later for macOS and 4.1 and later for Android, and Zscaler Support enables it. [zcc.platform-settings:ipv6-resolution] On a dual-stack network a device whose OS has an IPv4 address prefers IPv4, so using only IPv6 means removing a statically assigned IPv4 address or having the DHCP server issue only IPv6 addresses. App Connector and Private Service Edge for Private Access software must be at 24.353.5 or later, and on-premises firewalls must pass IPv6 traffic and allowlist the IPv6 addresses of the Zscaler infrastructure. When these are complete, Zscaler Support is contacted to request IPv6 support for the tenant, and the remaining prerequisites include new IdP and service provider endpoints and an updated PAC file. [zcc.platform-settings:ipv6-prerequisites] IPv6 support needs a forwarding profile with a Tunnel Driver Type of Packet Filter-Based. With Internet & SaaS, Drop IPv6 in Dual Stack Network and Drop IPv6 in IPv6 Only Network are disabled, Drop IPv6 Include Traffic When Not Supported is enabled, and an app profile has Destination Inclusion for IPv6 rules, for which Zscaler recommends [2000::/3] to cover all global routable IPv6 addresses. [zcc.platform-settings:ipv6-profiles]

**ZDX module upgrades.** On Client Connector 4.7 and later for Windows, Allow ZDX Client Upgrade via CLI under General Settings must be enabled before a downloaded package can upgrade the ZDX Module through the CLI, which deploys a ZDX upgrade separately from a Client Connector upgrade. [zcc.platform-settings:zdx-cli-upgrade]

**Default UI.** A Platform Settings setting determines which version of the app is the default for users, and its default value is enabled. It affects only users on Client Connector 5.0 and later, who see the Modern UI when it is enabled; when it is disabled all users see the Classic UI. Users on earlier versions see only the Classic UI. The default UI can also be set per app profile, which Zscaler Support enables. [zcc.platform-settings:default-ui] Which operating systems list this setting on the Platform Settings page is open [gap:zcc.platform-settings:default-ui-listing].

**Unattended-mode passwords.** On Client Connector 4.2.1 and later for Windows, Platform Settings can require a generated password to uninstall, upgrade or revert Client Connector from a command line in unattended mode. Each enabled password expires after a chosen number of hours (at most 48) or days (at most 90), and Generate creates a new password for each enabled one. These passwords are not used when users uninstall, update or revert the app on their own devices; the passwords for those actions are set on the app profile. [zcc.platform-settings:unattended-passwords] The install side of unattended mode is in [Silent install, upgrade, revert and uninstall parameters, and launch behavior](kb:zcc.install.windows-unattended).

**Where users sign in.** If an organization uses advanced multi-factor authentication for SAML, its users can authenticate in their browser instead of in Client Connector, which still manages Internet & SaaS traffic and Private Access. Zscaler must enable the feature; on Windows, Linux, iOS and Android the option is Browser-Based Authentication. [zcc.platform-settings:browser-based] On macOS the authentication browser type offers Default, Browser Based Authentication and WebAuthn Popup Browser. Default authenticates with the default system-embedded browser that Client Connector uses. Browser Based Authentication authenticates with a web browser and uses the default web browser if enabled and Safari if disabled, for authenticating with a client certificate and a FIDO2 compliant key. WebAuthn Popup Browser authenticates with a restricted pop-up browser, for client certificates and FIDO2 compliant keys; selecting it shows the Use Default Browser field, automatically enabled, so the default web browser is used. WebAuthn Popup Browser applies to Client Connector 4.7 and later for macOS and to Authentication Service only. [zcc.platform-settings:macos-browser-types] On Windows, users authenticate either with Browser-Based Authentication, so that Client Connector opens in the device's default browser, or with WebView2 as the embedded browser; if both options are selected, Browser-Based Authentication overrides WebView2. [zcc.platform-settings:windows-precedence] The install parameters for the same choices are in [Install parameters for how users sign in to Client Connector](kb:zcc.install.authentication-options). What Authentication Service means is open [gap:zcc.platform-settings:authentication-service].

**WebView2.** For an organization using advanced MFA for SAML or FIDO2, users can authenticate with WebView2 in their embedded browser. It needs Client Connector 4.2 or later for Windows, .NET Framework 4.5 or later and WebView2 103.0.1264.42 or later; if an existing WebView2 is earlier than the minimum, Client Connector pulls the latest version from Microsoft's CDN using the bootstrap installer in its install package. [zcc.platform-settings:webview2-prerequisites] For the bootstrapper to download and install WebView2, the Microsoft CDN domains .delivery.mp.microsoft.com and .cdp.microsoft.com must be bypassed in strict enforcement mode or any other security policies, and MicrosoftEdgeWebview2Setup.exe, at %ProgramFiles%\Zscaler\ThirdParty\WebView2\, allowlisted in antivirus and other security policies. WebView2 launches its own processes, which Client Connector must bypass in strict enforcement mode, and its installation is shared by other apps that use the WebView2 runtime. [zcc.platform-settings:webview2-bypasses] Two optional WebView2 settings are available only on Client Connector 4.4 and later for Windows: SSO using Windows Primary Account logs users in automatically in an Azure AD environment that uses Windows as the IdP, and when it is disabled users enter their credentials separately; Ignore Client Cert errors for Webview2 has Client Connector continue authenticating when the IdP requires a client certificate for mutual authentication but the device has none or an invalid one. [zcc.platform-settings:webview2-sso-and-certs] Allow WebView2 to follow System Proxy is deselected to connect directly to the internet and is available only on Client Connector 4.5 and later for Windows. Additional IdP Domains, for when the user login domain differs from the IdP domain, are added to the Auth Server allowlist in the embedded WebView2 browser along with the user login domain added by default; it is available only on 4.6 and later for Windows, and before 4.8 requires the Imprivata integration. [zcc.platform-settings:webview2-proxy-and-domains] Display certificate selection popup on desktop, available only on Client Connector 4.7 and later for Windows, shows a list of certificates in a pop-up window when several authentication certificates for the IdP are available; if disabled, the selection window displays only when users are viewing the app. If it is selected, app profile options can control what displays when users reauthenticate to Private Access. [zcc.platform-settings:webview2-cert-popup] Which app profile options control the reauthentication display is open [gap:zcc.platform-settings:reauth-app-profile-options].

**Window and user agent.** On Client Connector 4.6 and later for Windows, enabling Zscaler Client Connector Window Resizing under Authentication Settings makes the app resize the page as necessary to show all the configured multi-factor authentication options, then return to its original dimensions after authentication. [zcc.platform-settings:window-resizing] Client Connector can be given a user agent suffix that the IdP reads as strings it expects during authentication to identify the user agent. The suffix can be global or per domain: on the User Agent page under WBC User Agent, the Global User Agent Suffix field takes the suffix to append, and the Select Domain drop-down menu selects a domain provisioned for the organization. [zcc.platform-settings:user-agent-suffix] The user agent suffix leaves questions open [gap:zcc.platform-settings:user-agent-suffix-details].

**Device groups.** The Platform Settings page lists Use Device Groups in Service Entitlement for iOS and Android without describing it; the device groups pages do: [Use Device Groups in Service Entitlement enables Zscaler services selectively, only on managed devices that meet specific posture configurations during enrollment, and applies to Internet & SaaS, Private Access and Digital Experience; Client Connector evaluates device posture during enrollment and keep-alive intervals and enables or disables services according to the user group and device group configuration set in the Admin Console.](kb:zcc.entitlements.device-groups:mobile-evaluation) [gap:zcc.platform-settings:device-groups-entitlement].

What to check:
1. For a Windows sign-in problem, whether both Browser-Based Authentication and WebView2 are selected, since Browser-Based Authentication then overrides WebView2.
2. For a WebView2 sign-in failure, whether the Microsoft CDN domains are bypassed and the bootstrapper is allowlisted.
3. For an IPv6-only device that does not connect, the IPv6 prerequisites and the forwarding profile settings before Platform Settings.
