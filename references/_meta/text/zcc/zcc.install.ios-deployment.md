# Deploying Client Connector on iOS through an MDM: managed app configuration, the VPN profile, per-app VPN, dual tunnel, SSO and ZDX (zcc.install.ios-deployment)
Also called: zcc ios mdm; zcc jamf pro ios; zcc intune ios; zcc workspace one ios; zcc mobileiron ios; zcc maas360 ios; managed app configuration zcc ios; zcc dual tunnel ios; tunnelsecondary

The iOS version of Client Connector cannot be downloaded and installed manually from the Admin Console; it must be downloaded and deployed with the organization's MDM. The iOS install-options page lists guides for Microsoft Intune, Jamf Pro, Workspace ONE UEM, MobileIron and MaaS360. [zcc.install.ios-deployment:mdm-only] The iOS guides are written against Jamf Pro 10.37.2, Microsoft Intune service release 2048, Workspace ONE UEM 20.7.0.0 (2007) and MaaS360 10.72. [zcc.install.ios-deployment:guide-versions]

**Getting the parameters to the app.** The Jamf Pro guide describes managed app configuration as a set of key-value pairs in XML format used to configure iOS applications. The guides use Intune's Use configuration designer settings format, Workspace ONE's Send Configuration, MobileIron's Apple Managed App Settings for Zscaler configuration parameters, and MaaS360's Key/Value app config source, where MaaS360 variables can populate the fields. [zcc.install.ios-deployment:managed-app-config] The keys that are specific to iOS are in [iOS and Android-only install keys](kb:zcc.install.mobile-options), and the shared enrollment keys in [Install parameters that identify the tenant and user at enrollment](kb:zcc.install.enrollment). Jamf Pro's sample configuration dictionary sets cloudname, ownership, strictEnforcement (the string 0), userDomain and an excludeList naming company.jamfcloud.com, aadcdn.msftauth.net, login.microsoftonline.com, oktacdn.com and samlsp.prod.zpath.net; the values are the guide's examples. [zcc.install.ios-deployment:jamf-sample]

**Enrollment on the device.** After the MDM installs the app, the Jamf Pro guide says users must manually launch Client Connector to complete enrollment; the Intune, Workspace ONE and MaaS360 guides say users must launch the app and log in to enroll; the MobileIron guide says users must open it once for the configurations to be applied for the first time. [zcc.install.ios-deployment:launch-to-enroll]

**The VPN profile.** The Workspace ONE guide says Client Connector automatically creates a VPN profile on the device if one is not present, which prompts the user to install it and lets the user reject it; pushing the VPN profile as Custom VPN pre-deploys it, so the user is not prompted and cannot remove the profile. [zcc.install.ios-deployment:vpn-profile] In the Workspace ONE guide the Custom VPN profile has identifier com.zscaler.zscaler, user authentication Certificate, VPN On Demand enabled with new on-demand keys and override prevented; its on-demand rule uses interface type Any and action Connect, with On Demand Action Always Establish, and the OS launches the Client Connector VPN when the rule matches. [zcc.install.ios-deployment:workspace-one-vpn]

**Intune.** In the Intune guide Zscaler recommends a device configuration profile for custom policy settings, though an app configuration policy can be used instead. With a device posture check of the Ownership Variable, a device configuration profile can carry all settings except ownership, which must be set with an app configuration policy. [zcc.install.ios-deployment:intune-recommended-profile] The Intune on-demand VPN device configuration profile uses the VPN template with connection type Zscaler. Its Custom domain name sets the user domain so users skip the enrollment page for the single sign-on login page; it also takes Enable strict enforcement, the organization's cloud name and Excluded URLs, such as the IdP, the MDM server or anything else needed before enrollment, with authsp.prod.zpath.net required for Private Access. Its on-demand rules get a Connect VPN rule restricted to All domains as the primary rule. [zcc.install.ios-deployment:intune-profile-settings] Intune's assignment settings can uninstall Client Connector automatically if the device is removed from Intune (Yes for Uninstall on device removal) and stop users removing it (No for Install as removable). [zcc.install.ios-deployment:intune-assignment] The certificate profile for SSL inspection is in [For iOS, the Intune guide pushes the CA certificate for SSL inspection with a certificate profile for the iOS/iPadOS platform using the Trusted Certificate template and the uploaded .crt file; the certificate is the default Zscaler Central Authority certificate (found under Internet Access > Resources > SSL Intermediate Certificate, in the ZscalerRootCerts.zip file to unzip) or a custom Root CA certificate.](kb:zcc.ssl-inspection.certificate-install:ios-intune-profile). The strict enforcement requirements in the same guide are in [Strict enforcement, the policy token, and the fail-close configuration](kb:zcc.install.strict-enforcement).

**Per-app VPN.** In the Intune guide, adding a specific application to Intune and associating it with a per-app VPN configuration profile makes selected applications protected by Internet & SaaS; for example, access to private applications can be allowed only from a specific browser. The profile's automatic VPN type is Per-app VPN, Safari URLs can trigger it for chosen domains, and domains entered in Excluded Domains are excluded from the per-app VPN. [zcc.install.ios-deployment:per-app-vpn] The per-app VPN keys are in [For per-app VPN deployments on iOS, newBindFlow enables a multithreaded binding of Client Connector's microservices to its virtual interface (on by default), and PAVConnectionSynced delays the per-app VPN connection until Client Connector is connected (off by default).](kb:zcc.install.mobile-options:ios-per-app-vpn).

**Single sign-on.** With Entra ID as the IdP, Client Connector can integrate with the Microsoft Enterprise SSO plug-in so users need not log in during enrollment or reauthentication; the device configuration profile must exclude specific URLs for the plug-in. The Intune Device features profile uses the Microsoft Entra ID SSO app extension type with the bundle IDs com.apple., com.microsoft. and com.zscaler. (all required), browser_sso_interaction_enabled set to 1 so the app can use Safari to authenticate, disable_explicit_app_prompt set to 1 to reduce prompts, and AppPrefixAllowList with the same three prefixes. [zcc.install.ios-deployment:enterprise-sso]

**Dual tunnel.** With the dual tunnel feature, organizations can capture per-app traffic through a secondary tunnel and send it to Private Access applications, while all other apps still tunnel to Internet & SaaS through the primary tunnel. The Jamf Pro guide says Client Connector must already be installed on the device, and that the two VPN profiles then appear in the Device VPN and Per-App VPN sections. [zcc.install.ios-deployment:dual-tunnel] In the Jamf Pro dual tunnel guide the primary VPN profile has identifier com.zscaler.zscaler, provider bundle identifier com.zscaler.zscaler.tunnel, custom data tunnelType with value ZIA and provider type Packet-Tunnel; the secondary profile has provider bundle identifier com.zscaler.zscaler.tunnelsecondary and custom data tunnelType with value APP. [zcc.install.ios-deployment:dual-tunnel-jamf] In the Intune dual tunnel guide the primary profile is a Custom template that uploads the Dual Tunnel Primary VPN mobileconfig file; the secondary uses an automatic VPN type of Per-app VPN with VPN server address perappvpn, split tunneling disabled, VPN identifier com.zscaler.zscaler, the custom attribute tunnelType with value APP and provider type packet-tunnel, and is assigned to a third-party app. [zcc.install.ios-deployment:dual-tunnel-intune] Which custom data keys the profiles accept besides tunnelType, and the Client Connector version dual tunnel needs, are open [gap:zcc.install.ios-deployment:dual-tunnel-keys].

**ZDX.** The Jamf Pro ZDX guide applies to devices running iOS 16 and later and needs Client Connector already installed. Its content filter has filter type Plug-in, identifier com.zscaler.zscaler, organization Zscaler, per-app networking and socket filter enabled; the filter is selected in the app's Per-App Content Filter section, after which the Zscaler Content Filter shows as running and the app shows the ZDX service running. [zcc.install.ios-deployment:zdx-jamf] The Workspace ONE ZDX guide also applies to iOS 16 and later with Client Connector already installed. Its custom payload has PayloadType com.apple.webcontent-filter, PluginBundleID com.zscaler.zscaler and FilterSockets true; the ContentFilterUUID value must match the value in the XML text in the earlier section, and the Zscaler Content Filter then shows as running. [zcc.install.ios-deployment:zdx-workspace-one]

**Open points.** The Intune guide's Minimum operating system value is a form value rather than a support statement [gap:zcc.install.ios-deployment:intune-min-os], and the Microsoft Enterprise SSO plug-in URL list is left to Microsoft's documentation [gap:zcc.install.ios-deployment:sso-plugin-urls].
