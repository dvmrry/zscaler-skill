# Client Connector's Firefox integration setting (zcc.firefox.integration)
Also called: firefox integration; enable firefox integration; firefox use system proxy settings zcc; firefox bypasses zscaler; firefox not using zcc proxy; endpoint integration tab
Former IDs: zcc-39, zcc-41, zcc-42, zcc-43

Client Connector can set Firefox's proxy configuration for it, through one switch in the Admin Console. When Firefox integration is enabled, Client Connector attempts to configure Firefox on macOS and Windows devices to follow Zscaler settings, by enabling Firefox's "Use system proxy settings" feature. [zcc.firefox.integration:what-it-does]

**Enabled.** Enabled, it overrides Firefox's proxy settings and prevents the user from changing them. [zcc.firefox.integration:locks-settings] Which Firefox preferences it writes, and how, is open [gap:zcc.firefox.integration:preference-keys], and so is whether they survive a Firefox upgrade [gap:zcc.firefox.integration:upgrade-persistence].

**Disabled.** Disabled, Client Connector ignores Firefox and neither overwrites nor creates any Firefox configuration. [zcc.firefox.integration:disabled-ignores] With the integration disabled, the Zscaler proxy settings have to be added to Firefox's own configuration. [zcc.firefox.integration:disabled-manual-proxy] The certificate consequence is in [Firefox traffic and certificate trust with and without the integration](kb:zcc.firefox.proxy-and-trust). The enterprise mechanisms for setting Firefox's proxy without Client Connector are open [gap:zcc.firefox.integration:external-enforcement].

**Where it is set.** The setting is Enable Firefox Integration on the Endpoint Integration tab under Infrastructure > Advanced Settings > Endpoint Configuration. [zcc.firefox.integration:where-configured] It is therefore one tenant-wide setting: it is not part of an app profile, a forwarding profile or the install parameters, and no per-group scope is documented. [zcc.firefox.integration:tenant-wide] The Endpoint Integration page (Infrastructure > Advanced Settings > Endpoint Configuration) configures how Client Connector interacts with applications installed on the device; on it an admin can configure Firefox integration, the port for Client Connector to listen on, a VPN-Trusted Network Adapter Name and a VPN Service Name for Flow Logging, the Client Connector Synthetic IP Range, and Drop Non-Zscaler Packets in Synthetic IP Range. [zcc.firefox.integration:endpoint-page] The page says to avoid port conflicts with other applications by configuring the port for Client Connector to listen on. [zcc.firefox.integration:listening-port] The port's default and allowed range are open [gap:zcc.firefox.integration:listening-port-range]. The adapter names are in [If a VPN is not from a common vendor and its NIC adapter text does not match what is usually detected, its name can be entered in the VPN-Trusted Network Adapter Criteria field on the Endpoint Integration tab so Client Connector can detect a VPN-Trusted Network; hard-coded VPN adapter names can be removed there with the Delete icon next to the VPN name.](kb:zcc.forwarding-profiles.network-types:vpn-adapter-names), the VPN service names for flow logging in [By default, traffic bypassed from Client Connector is not logged. When flow logging is enabled in App Profiles with VPN selected to capture traffic logs for bypassed data, a VPN service name must be added if the VPN service is not already listed, in the VPN Services for Flow Logging field on the Endpoint Integration tab, to classify traffic flow into a VPN tunnel; the name can be up to 65 characters, and the page says to contact Zscaler Support to enable this feature.](kb:zcc.logs.flow-logging:vpn-service-names), and the synthetic IP range settings in [The synthetic IP range page says an organization can configure Client Connector to use an IP range beyond the default range of 100.64.0.0/16 for its Private Access applications, entered, as a range between 100.64.0.0/16 and 100.127.0.0/16 (the page writes the upper bound with a stray period), in the Zscaler Client Connector Synthetic IP Range field on the Endpoint Integration tab.](kb:zcc.interoperability.security-software:synthetic-range) and [If the LAN operates on the same synthetic IP range that Client Connector uses for Private Access, Drop Non-Zscaler Packets in Synthetic IP Range makes Client Connector block non-Zscaler packets destined for the synthetic IP range; the option is disabled by default, and when disabled non-Zscaler packets are bypassed.](kb:zcc.interoperability.security-software:drop-non-zscaler).

**Which Firefox.** Firefox integration does not support Mozilla Developer Preview or Firefox downloaded from the Microsoft Store. [zcc.firefox.integration:unsupported-variants] Linux is not covered [gap:zcc.firefox.integration:linux]. Differences between ESR and the release channel [gap:zcc.firefox.integration:release-channel], and between Client Connector versions [gap:zcc.firefox.integration:version-scope], are open too.

**Why Firefox needs it.** That Firefox ignores the operating system's proxy unless told otherwise is the premise of the setting, but no source states it [gap:zcc.firefox.integration:firefox-default-proxy].

What to check:
1. When Firefox traffic bypasses Zscaler while other browsers do not, whether Enable Firefox Integration is selected on the Endpoint Integration tab.
2. Whether the Firefox build is a Microsoft Store download or Mozilla Developer Preview, which the integration does not support.
3. Whether the device is Windows or macOS; the integration is documented for those two only.
