# Strict enforcement, the policy token, and the fail-close configuration (zcc.install.strict-enforcement)
Also called: strictEnforcement; STRICTENFORCEMENT; policyToken; POLICYTOKEN; block internet until enrolled; se fail close; importSEFailCloseConfig; failCloseConfigThumbprint; excludeList; zcc fail close at enrollment

Strict enforcement keeps a device off the internet until its user has enrolled with Client Connector. It depends on a second parameter, the policy token, which decides what the device can reach while it waits.

**What it blocks.** strictEnforcement (MSI `STRICTENFORCEMENT`) requires users to enroll with the app before they can reach the internet, and blocks traffic when the user has not yet logged in after a new install, after a user logs out, and after an administrator removes the device. It defaults to disabled. [zcc.install.strict-enforcement:what-it-blocks] It does not affect users who stay logged in and turn the Internet & SaaS service off. [zcc.install.strict-enforcement:not-logged-in-disable] It works only when the forwarding profile action for Client Connector is Tunnel or Tunnel with Local Proxy. [zcc.install.strict-enforcement:tunnel-only] What a blocked user is told comes from the fail-open policy: [For clients installed in Strict Enforcement mode (Windows 4.6 and later), Notify End User shows a message to users who try to reach the internet before logging in, repeated after a rate limit (default 2 minutes), with text of at most 200 characters.](kb:zcc.forwarding-profiles.fail-open:strict-enforcement-notify).

**What it needs.** Enabling it requires cloudName and policyToken on Windows and macOS; on iOS it requires policyToken, cloudname is required with it, and excluded URLs must also be defined. [zcc.install.strict-enforcement:requires] Strict enforcement is an install parameter on Windows, macOS and iOS only; the Android and Android on ChromeOS parameter table has no strictEnforcement or policyToken key. [zcc.install.strict-enforcement:android-absent]

**The policy token.** policyToken (MSI `POLICYTOKEN`) names the app profile policy enforced before the user enrolls, with all of that policy's settings, including the bypass of the IdP login page. The custom PAC file of that policy must bypass the IdP login page so the user can reach the IdP to log in before enrolling. On iOS it applies, and is required, only with strict enforcement. [zcc.install.strict-enforcement:policy-token] After an app profile is saved, a policy token is automatically generated for the profile; it is viewed by clicking the Edit icon beside the profile on the App Profiles tab. [zcc.install.strict-enforcement:policy-token-generated] After enrollment the token's policy gives way to the user's own app profile: [The policy that policyToken names applies only until the user enrolls; it is then replaced by the app profile policy that matches the user by group.](kb:zcc.install.precedence:policytoken-replaced). The same token is what makes a machine tunnel reach Private Access before login: [The policyToken install parameter is required when a machine tunnel is configured and users should reach Private Access applications before logging in to the device. The app profile policy it names must use a custom PAC file that bypasses the IdP login page.](kb:zpa.machine-tunnels.requirements:policytoken-required).

**Locking the device out of its own login.** So under strict enforcement, if the policy the token names does not bypass the IdP login page, a device that has not enrolled cannot reach the IdP to enroll, and its traffic stays blocked. [zcc.install.strict-enforcement:missing-idp-bypass] An app profile option, Strict Enforcement mode - allow only PAC exclusions, makes Client Connector block all traffic except PAC file exclusions while that policy is used in strict enforcement mode; the PAC file must then also allow the IdP URLs. It applies to Client Connector 4.7.0.223 and later, 4.8.0.140 and later, and 4.9 and later. [zcc.install.strict-enforcement:allow-only-pac-exclusions] How a device in that state is recovered is open [gap:zcc.install.strict-enforcement:misconfig-recovery]. On a Windows 365 Cloud PC the vendor's answer is a snapshot restore: [When Client Connector is installed in strict enforcement mode on a Cloud PC, the policy named in POLICYTOKEN must carry these bypasses, or users lose access to the Cloud PC; once access is lost, the only way back is restoring a previous snapshot.](kb:zcc.install.azure-virtual-desktop:strict-snapshot).

**iOS.** On iOS, excludeList lists domains and IP addresses that Client Connector never tunnels, with or without strict enforcement. With strict enforcement it should hold the MDM server and anything else the user needs before enrolling; with Private Access it must include authsp.prod.zpath.net. Excluded URLs for strict enforcement can be defined there or in a device configuration policy. [zcc.install.strict-enforcement:ios-exclude-list] So on an iOS device under strict enforcement, a destination needed before enrollment that is in neither excludeList nor a device configuration policy, such as the MDM server, is blocked until the user enrolls. [zcc.install.strict-enforcement:ios-unlisted-blocked] The Intune iOS guide says that deploying Strict Enforcement requires defining policyToken, adding at least one entry to the excluded URLs list, and enabling Disable iCloud Private Relay and Drop QUIC Traffic in the Strict Enforcement App Profile. Its Excluded URLs list includes the Private Access hosts authsp.prod.zpath.net, samlsp.private.zscaler.com and samlsp-pdx2.private.zscaler.com, and hosts required for Intune, Apple and the organization's IdP. [zcc.install.strict-enforcement:ios-intune-requirements] In the same guide, destination IPs are bypassed by adding them to the IP Exclusion List and web destinations, such as the IdP login page, by adding the domain names to the custom PAC file associated with the policy; the policy token is copied by saving the app profile and reopening it. [zcc.install.strict-enforcement:ios-strict-profile-bypasses] If Client Connector blocks sites after being installed with Strict Enforcement, the Intune iOS guide says to inspect the ZSATunnel_[DATETIME].log file for the string Proxy=PROXY; if the file has a Local captive mode! Dropping Https request message for a hostname, adding that hostname to the Excluded URLs field in the device configuration profile resolves it. [zcc.install.strict-enforcement:ios-troubleshooting] The rest of the Intune iOS guide is in [Deploying Client Connector on iOS through an MDM: managed app configuration, the VPN profile, per-app VPN, dual tunnel, SSO and ZDX](kb:zcc.install.ios-deployment).

**Citrix.** With non-persistent Citrix VDIs on Windows, strict enforcement needs hideAppUIOnLaunch set to 0 so Client Connector can remind users to enroll before they reach the internet. [zcc.install.strict-enforcement:citrix-hide-ui]

**Fail-close file (Windows).** On Windows from Client Connector 4.6, importSEFailCloseConfig (MSI `IMPORTSEFAILCLOSECONFIG`) passes a predownloaded file of fail-close settings to use in strict enforcement mode, and failCloseConfigThumbprint (MSI `SEFAILCLOSECONFIGTHUMBPRINT`) passes that file's public key. Each requires the other and strict enforcement. [zcc.install.strict-enforcement:se-fail-close] The fail-close settings are entered in the app profile for use when Client Connector is in strict enforcement mode and in a fail-close state: if it cannot retrieve the config profile after an initial enrollment attempt, it uses them until the config profile is retrieved from the Zscaler cloud. They cover process-based application bypass, IP address bypasses, an exit or uninstall password, and lockdown on tunnel process exit, and a Thumbprint, the public key to use with the fail-close settings configuration file. The feature needs Client Connector 4.6 or later on Windows with the Install WFP Driver option enabled. [zcc.install.strict-enforcement:fail-close-file-contents] The app profile can also make the device fail close while a tunnel starts or restarts: [A fail-close option makes the app fail close while a tunnel is starting or restarting, for example after login, Repair App or Restart Service.](kb:zcc.app-profiles.advanced-settings:fail-close-lockdown). Whether the settings hold during a cloud outage after enrollment is open [gap:zcc.install.strict-enforcement:fail-close-scope].

What to check:
1. Whether the forwarding profile action is Tunnel or Tunnel with Local Proxy; strict enforcement does nothing otherwise.
2. Whether cloudName and policyToken are both set, and whether the custom PAC file of the policy the token names bypasses the IdP login page.
3. On iOS, whether the MDM server, the IdP and, for Private Access, authsp.prod.zpath.net are excluded through excludeList or a device configuration policy.
4. Test the token and its policy on a few devices before a fleet rollout; recovery from a lock-out is not documented.
