# Client Connector system requirements, resource usage, update intervals and deployment prerequisites (zcc.install.system-requirements)
Also called: zcc system requirements; zcc resource usage; zcc update intervals; client connector disk ram cpu; zcc battery usage; zcc prerequisites; zcc ssl bypass list domains

Client Connector does not need an additional license or subscription, as ZIA and ZPA licensing includes it; the deployment guide's steps run: system requirements, process allowlisting on client firewall and AV, firewall allowance to the Zscaler cloud, app-store download, optional installer options, then deployment through device management. [zcc.install.system-requirements:licensing-and-deployment-steps]

**Requirements per platform.** The configuration guide's Windows requirements list disk usage of 200 MB, memory usage of 150 MB, Microsoft .NET Framework 4 and later, and allowlisting Client Connector processes with firewall bypasses. [zcc.install.system-requirements:requirements-windows] The configuration guide's macOS requirements list disk usage of 200 MB and memory usage of 150 MB, say that with Tunnel mode in the forwarding profile the system firewall must be disabled, and list allowlisting Client Connector processes with firewall bypasses. [zcc.install.system-requirements:requirements-macos] The configuration guide's Linux requirements list disk usage of 200 MB, memory usage of 150 MB and an x86-64 architecture processor. [zcc.install.system-requirements:requirements-linux] The configuration guide's iOS requirements are compatibility with iPhone, iPad and iPod touch, and 20 MB for installation plus space for logs. [zcc.install.system-requirements:requirements-ios] The configuration guide's Android requirement is 21 MB for installation plus space for logs. [zcc.install.system-requirements:requirements-android] The configuration guide's Android on ChromeOS requirement is 21 MB for installation plus space for logs. [zcc.install.system-requirements:requirements-android-chromeos]

**Expected resource usage.** On Windows and macOS the app is expected to use approximately 200 MB of disk for installation plus space for logging (sized by log retention), 70 to 150 MB of RAM (possibly higher on VDI systems), 0 to 5% CPU (temporarily higher when processing traffic), with no noticeable battery impact. [zcc.install.system-requirements:resource-desktop] On Linux the app is expected to use approximately 181 MB of storage for installation, approximately 0.5% of RAM, and 0 to 5% CPU when idle and 7 to 15% during traffic. [zcc.install.system-requirements:resource-linux] On Android, Android on ChromeOS and iOS the app is expected to use approximately 20 MB of storage for installation and between 10 and 20% of battery life; it uses cellular data on mobile devices when not on Wi-Fi. [zcc.install.system-requirements:resource-mobile] The battery usage applications on Android, Android on ChromeOS and iOS are described as not entirely accurate; the article adds that Client Connector always forwards traffic and its perceived battery usage percentage can be much higher, and recommends timing battery drain with and without the app. [zcc.install.system-requirements:battery-measurement] Resource figures for the ZDX Module and VDI systems are open [gap:zcc.install.system-requirements:resource-zdx-vdi].

**Update intervals.** Client Connector downloads the PAC files of the app and forwarding profiles every 15 minutes, connects for policy updates every 80 minutes and checks for software updates every 2 hours (the app update article limits configurable app updates to Windows, macOS and Linux; iOS and Android are updated through their app stores or MDM); the intervals are not configurable, and a manual policy update from the device applies immediately. A change to the PAC file URLs is picked up by the 80-minute cycle. [zcc.install.system-requirements:update-intervals] How the update settings choose the version the check installs is in [Deploying Client Connector on macOS: the package, the preference domain, updates and removal](kb:zcc.install.macos-deployment); whether the 2-hour check itself depends on an auto-update policy is open [gap:zcc.install.system-requirements:update-check-policy].

**Prerequisites per service.** For Internet & SaaS, authentication needs either an authentication mechanism with users provisioned on ZIA or, when none is installed, the Client Connector Portal as the Identity Provider; the organization firewall must allow the necessary connections, with detail at config.zscaler.com/<Zscaler Cloud Name>/zscaler-app, and SSL inspection for Client Connector users is optional. [zcc.install.system-requirements:internet-saas-prerequisites] For Private Access, SAML-based authentication must be configured with users provisioned, and the Client Connector Portal cannot be the IdP for ZPA; if a PAC file is used for Client Connector, the URLs must be added to the SSL exemptions list on the proxy as well. [zcc.install.system-requirements:private-access-prerequisites] For ZDX on Windows and macOS, all destination domains must be placed on the allowlist in the SSL bypass list. [zcc.install.system-requirements:zdx-prerequisite-domains] For Private Access traffic, the Client Connector enrollment and authentication domains listed on config.zscaler.com/private.zscaler.com/zpa and the organization's IdP domains must be in the SSL bypass list; with Okta as the IdP, Okta-specific domains must also be included. [zcc.install.system-requirements:ssl-bypass-domains]

**Endpoint protection and identity provider traffic.** Zscaler states it has allowlist agreements for Client Connector with specific endpoint protection vendors such as Trend Micro and Kaspersky Labs, and that for some endpoint protection products like anti-virus and personal firewall additional allowlisting might be needed for full functionality. [zcc.install.system-requirements:endpoint-protection-allowlist] The processes themselves are in [Allowlisting Client Connector in antivirus and host firewalls: paths, processes, firewall directions and the 100.64 range](kb:zcc.interoperability.security-software). The deployment guide says authentication traffic must go directly to the IdP destination URL, including PAC-file, GRE-tunnel and IPSec-tunnel authentication traffic, and IdP traffic through Zscaler must not be intercepted for inspection (adjust SSL Inspection and Authentication exemptions). [zcc.install.system-requirements:idp-traffic-considerations]

**Operating the deployment.** The deployment guide's operations prerequisites are: an SOP for adding domain bypasses in the PAC file, a process to test configuration changes (such as diverting traffic to a different data center or bypassing a PAC file), testing with separate app profiles or PAC files applied to test users, and a process to clean up test profiles and PAC files. [zcc.install.system-requirements:operations-prerequisites]

**What the end user sees.** Client Connector forwards traffic to the Internet & SaaS service and also allows use of Private Access, ZDX and Endpoint DLP; each service's connection status is shown on its own page (Internet Security Status, Private Access Service Status, Digital Experience Service Status, Data Protection Service Status). [zcc.install.system-requirements:end-user-services-and-status] For errors shown in the Status, the end-user article offers Retry (next to the Status) or Repair App (More page, Troubleshoot menu); an error with an error code that is not in the Status goes to the organization's support team. [zcc.install.system-requirements:end-user-troubleshooting] How the app disables itself on a trusted network or Wi-Fi hotspot is in [The Client Connector app as users see it: Classic UI and Modern UI menus, status, enrollment and notifications, by OS where the pages cover it](kb:zcc.end-user).

What to check:
1. Which source a disk or memory figure comes from: the configuration guide's per-platform requirements or the resource-usage article's expected use; for Android the guide says 21 MB and the usage article approximately 20 MB, and for Linux the guide says 200 MB and the usage article approximately 181 MB.
2. The interval a policy or PAC change waits on: PAC files every 15 minutes, policy every 80 minutes, a manual update from the device immediately.

Not known (open gaps):
- Whether the 2-hour software update check depends on an auto-update policy [gap:zcc.install.system-requirements:update-check-policy]: settled by source-read
- Resource usage of the ZDX Module and on VDI systems [gap:zcc.install.system-requirements:resource-zdx-vdi]: settled by source-read or lab-test
