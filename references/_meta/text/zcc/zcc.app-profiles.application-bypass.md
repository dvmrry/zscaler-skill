# Application Bypass: adding custom IP-based and process-based applications for an app profile to bypass (zcc.app-profiles.application-bypass)
Also called: application bypass; IP bypass; process bypass; process-based application bypass; IP-based application bypass; predefined IP-based applications

Application Bypass is where custom IP-based and process-based applications for an app profile to bypass are added. Application Bypass is the Admin Console page (Infrastructure > Client Connector > IP Bypass) where the available predefined IP-based applications can be viewed and IP-based and process-based applications can be added; the applications to bypass are selected in App Profiles under Traffic Steering. [zcc.app-profiles.application-bypass:what-it-is] The page lists the IP-based applications Client Connector bypasses with their Last Edited Timestamp, and the View icon shows the Protocol, Port and IP Address of a bypassed IP-based application. [zcc.app-profiles.application-bypass:page-view]

**Domains.** Domain-based bypasses cannot be configured on the Application Bypass page; to bypass a specific domain, it can be added to a custom PAC file. [zcc.app-profiles.application-bypass:no-domain-bypass] The PAC file side is in [Client Connector's two PAC files: what the forwarding profile PAC and the app profile PAC do in Tunnel and Tunnel with Local Proxy modes, and the forwarding PAC in Enforce Proxy](kb:zcc.pac-files) and [Bypasses for Z-Tunnel 2.0: VPN gateway bypasses, destination exclusions and inclusions, domain bypasses](kb:zcc.z-tunnel.bypasses).

**IP-based applications.** In addition to predefined applications (the page's examples are Microsoft Teams and Zoom), an IP-based application is added on the IP-Based tab with Custom, with a name and, for IPv4 or IPv6 addresses, ports (valid port numbers 1-65535, a range such as 80-100, or an asterisk, separated by commas), a protocol (an asterisk represents any protocol) and the addresses or subnet, separated by commas. [zcc.app-profiles.application-bypass:ip-based] The page says Android only supports IP-based bypasses and does not support ports and protocols; all traffic associated with the specified IP is bypassed. [zcc.app-profiles.application-bypass:android-ip-only]

**Process-based applications.** The process-based page says process-based applications are defined with information such as paths, app identifiers, executable signatures and certificate attributes, to help identify applications that can frequently change; it says they can be selected in App Profiles to bypass traffic for both Z-Tunnel 1.0 and Z-Tunnel 2.0, and that after the application is added to the app profile it must be restarted before traffic is bypassed. [zcc.app-profiles.application-bypass:process-based] Which tunnel versions Application Bypass covers is given differently by the pages [zcc.z-tunnel.bypasses:application-bypass-tunnel-versions](kb:zcc.z-tunnel.bypasses:application-bypass-tunnel-versions).

**On Windows.** On Windows (Infrastructure > Client Connector > Process Bypass), the Path field takes the executable file names for the application: a single asterisk matches any full single path component, a wildcard cannot be used for partial components, two asterisks (**) match any number of consecutive path components (the page's example is **\ms-teams.exe), environment variables such as %APPDATA%\Zoom\bin can be used, and several entries can be added at once separated by commas. [zcc.app-profiles.application-bypass:process-windows-path] The console location for adding a process-based application is named differently by two pages [divergence:zcc.app-profiles.application-bypass:process-console-location]. A Windows process-based application can also have Matching Criteria, with one or more options selected from a drop-down menu: SHA2 Signature (an application name and the hash of the executable file), Certificate Signer (a certificate name and the certificate thumbprint) and Certificate Subject (a certificate name and a name that matches the subject of the certificate). [zcc.app-profiles.application-bypass:process-windows-matching] On Windows, Install WFP Driver must be enabled in App Profiles to use Process-Based Application Bypass. [zcc.app-profiles.application-bypass:process-windows-wfp]

**On macOS.** On macOS, the page says that to use the feature Transparent Proxy-based Traffic Interception must be enabled, that it applies to Client Connector version 4.8 for macOS and later, and to contact Zscaler Support to enable it. The App Identifier is entered as TeamIdentifier.BundleIdentifier or BundleIdentifier, with a maximum of five bundle identifiers in a single application, or as the full path to the app if it has no bundle identifier, where wildcards are not allowed. [zcc.app-profiles.application-bypass:process-macos] The MDM route for earlier versions and Route-based Interception is in [macOS system extensions, VPN payloads and privacy profiles for Client Connector](kb:zcc.install.macos-extensions).

**Open.** The full list of predefined applications and the limits on custom applications are open [gap:zcc.app-profiles.application-bypass:predefined-and-limits].

What to check:
1. For a process-based bypass that has no effect: whether the application was restarted after it was added to the app profile, on Windows whether Install WFP Driver is enabled in the app profile, and on macOS whether Transparent Proxy-based Traffic Interception is enabled and the client is 4.8 or later.

Sources disagree (name both sides):
- The About Application Bypass page lists adding process-based applications among the actions on the Application Bypass page (Infrastructure > Client Connector > IP Bypass); the process-based page gives Infrastructure > Client Connector > Process Bypass for adding one. [divergence:zcc.app-profiles.application-bypass:process-console-location]
  - zscaler-help: Process-based applications are viewed and added on the Application Bypass page at Infrastructure > Client Connector > IP Bypass.
  - zscaler-help: A process-based application is added from Infrastructure > Client Connector > Process Bypass.
  Impact: The pages may describe one page with two menu entries or different pages; neither says which, so the console path for adding a process-based application depends on which page is read.
