# App profile failover: disaster recovery, cloud unreachable, captive portals (zcc.app-profiles.failover)
Also called: zcc disaster recovery; enableZiaDR; zia dr app profile; zcc fail open app profile; captive portal detection; zia cloud not reachable; z-tunnel failover; allowUnreachablePac

The app profile handles four different situations, and they should not be confused.

**The Zscaler cloud is down (disaster recovery).** Disaster Recovery for Internet & SaaS gives users access while the Internet & SaaS service is down, and only to enrolled users. [zcc.app-profiles.failover:zia-dr-scope] When enabled, the profile chooses what happens during it: direct internet access bypassing the app, no internet access (all traffic dropped at the endpoint), policy-based access for web traffic allowing or blocking URLs through a custom PAC file, or, on Windows 4.8 and later, policy-based access on all ports, which also uses a custom PAC file and forwards the selected traffic over Z-Tunnel 2.0. [zcc.app-profiles.failover:zia-dr-actions] Disaster recovery is activated or tested by updating a DNS TXT record value, and Activate Test Mode is for app profiles whose selected users or groups are part of a group that tests disaster recovery. [zcc.app-profiles.failover:dr-activation] Disaster Recovery for Private Access gives users access to applications while the Private Access service is down, and is available only to enrolled users. [zcc.app-profiles.failover:zpa-dr-scope] What disaster recovery is for, and how Private Access activates it, is in [Disaster recovery mode and Private Service Edge groups](kb:zpa.private-service-edges.disaster-recovery).

**The disaster recovery PAC file.** Allow Zscaler Preselected Destinations (Recommended), when enabled, lets users access only the URLs present in the Zscaler-provided global database allowlist and blocks the rest. A custom PAC URL (with the http:// or https:// prefix) can be configured for destinations users can access when the Internet & SaaS service is down; configured together with the global database URL, both URL lists are allowed and the custom destinations URL takes precedence in any conflict, and traffic can also be forwarded to a proxy server. If both the Allow Zscaler Preselected Destinations and Custom Destinations fields are enabled, the return drop; syntax must be removed from the custom PAC file statement because it blocks the URLs in the global allowlist. [zcc.app-profiles.failover:policy-based-access-lists] When configuring the custom DR PAC file, access to the Private Access IP range 100.64.0.0/16 and the Private Access domains zpath.net and zpatwo.net must be allowed to prevent blocking Private Access traffic. [zcc.app-profiles.failover:private-access-allow] For the private business continuity cloud, the Custom DR PAC URL must point to the private PAC server (https://<private pac domain>.pac.zsbcs.net/<insert the rest of the PAC URL>); as of the 2026-11-04 capture the page says the private business continuity feature is in limited availability. The PAC file can return PROXY to the Zscaler-managed business continuity subcloud to maintain policies in the business continuity environment. [zcc.app-profiles.failover:private-bc-pac] The sample PAC files scope their PROXY return by client version in two ways [divergence:zcc.app-profiles.failover:proxy-return-version]. An organization with Internet & SaaS only cannot download the DNS Record Generator. TXT Record Signing Public Key takes a valid public key uploaded with Upload, and only PEM files can be uploaded. Zscaler recommends that disaster recovery be tested periodically with just a few users. [zcc.app-profiles.failover:dns-txt-and-testing] The linked DNS TXT record article is open [gap:zcc.app-profiles.failover:dns-txt-article].

**The cloud or the tunnel cannot be reached (failover).** Failover settings on the app profile take precedence over the global App Fail Open settings, from Client Connector 4.6 for Windows and 4.8 for macOS. [zcc.app-profiles.failover:profile-failover-overrides-global] For ZIA Cloud Not Reachable and for Z-Tunnel 1.0 failover, the profile can follow the global setting (the default), allow direct internet access, disable internet access (HTTP/HTTPS blocked, other traffic allowed), or fall back to the Internet & SaaS disaster recovery settings. [zcc.app-profiles.failover:profile-failover-options] The tenant-wide App Fail Open settings these override are in [Client Connector fail-open: captive portals, unreachable Service Edges and tunnel failures](kb:zcc.forwarding-profiles.fail-open).

**A captive portal is in the way.** On Windows 4.5 and later the profile enables captive portal detection; with Fail Open on, the app keeps its services disabled for 1 to 60 minutes after detecting a captive portal and then re-enables them. [zcc.app-profiles.failover:captive-portal] Fail Open enables a fail-open state when a captive portal is detected: with it enabled, the app blocks all traffic until the user registers in the captive portal using the embedded browser, which must first be enabled on the profile (Embedded Captive Portal). [zcc.app-profiles.failover:captive-portal-fail-open] By name, these settings are the web policy keys `enableCaptivePortalDetection`, `enableFailOpen` and `captivePortalWebSecDisableMinutes`, which the Go SDK sends on the web policy body. [zcc.app-profiles.failover:captive-portal-keys]

**The PAC file cannot be reached.** The Python SDK documents `allowUnreachablePac` as whether traffic is allowed when the PAC file is unreachable; the Go SDK calls it a legacy flag that the API still echoes on reads though the admin UI no longer renders it. [zcc.app-profiles.failover:allow-unreachable-pac]

How the disaster recovery block is spelled on the wire, where the sources disagree, is in [zcc.api.web-policy-wire:dr-key-names](kb:zcc.api.web-policy-wire:dr-key-names).

What to check:
1. Whether the outage is the Zscaler cloud (disaster recovery, activated by DNS TXT record) or reachability from this device (failover).
2. For failover, whether the app profile sets its own behavior or follows the global App Fail Open setting, and whether the client version honors the profile setting.
