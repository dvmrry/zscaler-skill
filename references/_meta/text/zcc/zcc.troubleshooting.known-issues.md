# Version- and OS-bound Client Connector known issues, with the vendor's workarounds and fix versions where given (zcc.troubleshooting.known-issues)
Also called: zcc known issues; client connector known issue; client connector upgrade issue; zcc fixed in version

Each claim here is bound to the Client Connector release or OS the vendor names. Fix versions that the vendor does not give are open [gap:zcc.troubleshooting.known-issues:fix-versions].

**Android and ChromeOS.** Android 17 requires apps to explicitly request permission before accessing the local network. When a device running Client Connector 5.0 for Android upgrades to Android 17 and reboots, the OS might start the Zscaler VPN service in the background before the user has granted the Local Network permission. The OS does not display interactive permission prompts for background services, so users might not see the prompt until they open the app, and network connectivity might be affected in the meantime. The user opens Client Connector from the home screen or launcher and taps Allow; administrators configure the MDM/EMM policy to auto-grant ACCESS_LOCAL_NETWORK, which appears under Nearby devices / Local network. [zcc.troubleshooting.known-issues:android-17-local-network] Client Connector version 4.0 for Android has a known issue where DNS resolution through the Public Service Edge for Internet & SaaS would sometimes fail if DNS domains are not added to the Domain Inclusion field in App Profiles. The workaround is a wildcard (*) in the Domain Inclusion field, entered in the Traffic Steering section on the DNS tab, which has Client Connector tunnel all DNS domains through Internet & SaaS. [zcc.troubleshooting.known-issues:android-40-dns-domain-inclusion] On Client Connector for Android on ChromeOS, after clicking the Sign in button in Settings, Chromebook users are not redirected to the captive portal when one is detected, because of an issue with Google ChromeOS. Instead, users can click Open Captive Portal in Client Connector for either Internet & SaaS or Private Access until this issue is resolved. [zcc.troubleshooting.known-issues:chromeos-captive-portal] In Client Connector for Android on ChromeOS version 1.12, users could not log in when connected to an IPv6-only cellular network; the workaround is to request a dual-stack mobile data network from the cellular provider. [zcc.troubleshooting.known-issues:chromeos-112-ipv6-only-login] In Client Connector for Android on ChromeOS version 1.12, users switching from LTE to Wi-Fi experience DNS resolution failure while Client Connector is running; the vendor says this is a known issue due to Google's upgrade to ChromeOS version 111, and states that it will be fixed in ChromeOS version 114 (a planned fix, as stated by the article). [zcc.troubleshooting.known-issues:chromeos-112-lte-wifi-dns]

**iOS.** Client Connector 4.4 and 4.4.1 for iOS have a known issue that might cause users to lose access to Zscaler services (Internet & SaaS, Private Access, Digital Experience). It affects iOS users when device groups are used for service entitlements on Client Connector for Windows, macOS, Linux or Android, but not for iOS: they lose the Zscaler service tabs at the bottom of the window and access to every service configured for device group-based service entitlement. The vendor lists as not affected: tenants that have not configured device group-based service entitlements for any OS, that have configured them for iOS only, or that use Authentication Service. [zcc.troubleshooting.known-issues:ios-44-device-group-entitlements] The vendor's workaround for Client Connector 4.4 and 4.4.1 for iOS is for customers who have configured device group-based entitlements for any platform other than iOS, to prevent disruption for iOS users until this issue is resolved: in the Admin Console at Infrastructure > Client Connector > iOS, on the Platform Settings tab, enable any option without clicking Save, disable the option, and click Save; then instruct affected users to click More and Update Policy; users with Private Access entitlements must re-register and authenticate with the IdP to access private applications. [zcc.troubleshooting.known-issues:ios-44-workaround]

**Windows.** On Client Connector versions 4.3, 4.4 and 4.5 for Windows with WebView2 enabled, embedded web pages can appear blank if display settings have changed or displays are attached or removed. The issue affects SAML authentication during login, reauthentication, acceptable use policy, license agreement, data loss protection notifications, and self-service notifications. Terminating the ZSATray.exe process via Task Manager or restarting the system resolves it temporarily; it is fixed in version 4.3.0.255, 4.4.0.346 and 4.5.0.296 for Windows. [zcc.troubleshooting.known-issues:webview2-blank-page] In Client Connector version 4.1.0.82 for Windows, Microsoft Outlook and Microsoft Teams are not accessible when using Tunnel with Local Proxy while connected to Internet & SaaS, because the option to Disable Loopback Restriction fails in some scenarios. The issue was fixed in version 4.1.0.98 for Windows. [zcc.troubleshooting.known-issues:outlook-teams-loopback] In Client Connector version 4.1.0.89 for Windows, the nslookup command, which targets a DNS request to a specific DNS server by domain, fails on devices running Client Connector with only an IPv4 address if the DNS domain is a Private Access application (for example *.company.com). The issue was fixed in version 4.1.0.98 for Windows. [zcc.troubleshooting.known-issues:nslookup-ipv4-private-access] When using the Google Chrome browser version 116 or Mozilla Firefox browser version 117 for browser-based authentication, Client Connector for both Windows and Linux does not automatically launch; the user must click Launch on the browser to complete authentication. [zcc.troubleshooting.known-issues:browser-auth-no-autolaunch]

**Linux.** Using the Client Connector GNOME tray icon in Linux distributions requires enabling the third-party GNOME extension AppIndicator and KStatusNotifierItem Support. When enabling this extension with openSUSE 15.3 and 15.4 Leap with GNOME Desktop, there is a known issue where the tray icon does not display on the screen. [zcc.troubleshooting.known-issues:linux-gnome-tray-icon]

**Legacy: end-of-life releases and operating systems.** What the legacy findings leave open for current packages is open [gap:zcc.troubleshooting.known-issues:legacy-scope].

**Legacy: Windows.** Legacy (3.7 for Windows): Client Connector 3.7 for Windows requires Windows 10 or 11; if upgrades are attempted on devices running Windows 7, 8 and 8.1, the upgrade fails without disruption to the user, and the devices continue to run older versions of Client Connector. [zcc.troubleshooting.known-issues:legacy-windows-37-os-floor] Legacy (Windows 10 version 2004): Windows 10 version 2004 and later only supports up to 50 DNS suffixes per system, so when DNS search domains are configured in the ZPA Admin Portal, no system may exceed 50 DNS suffixes. [zcc.troubleshooting.known-issues:legacy-windows-2004-dns-suffixes] Legacy (2.1.2 for Windows): some users may be unable to log in to Client Connector when they have updated to the recent Microsoft patches and are facing connectivity issues with Active Directory (AD). The vendor says this is due to a failure in the Microsoft cryptography API that tries to reach out to AD for verification, that it is also observed with Outlook when Client Connector is not installed, and that ensuring AD connectivity resolves it in some scenarios; it recommends upgrading to Client Connector 2.1.2.112 or later for Windows (released after September 10, 2020) to reduce the impact. [zcc.troubleshooting.known-issues:legacy-ad-login-crypto-api]

**Legacy: macOS.** Legacy (2.2.4 for macOS): Client Connector version 2.2.4 is compatible with M1 processors in Mac devices by using the Rosetta translation process. New installations on M1 systems are fully supported through the Mac device's user interface but, for version 2.2.4, not fully supported using the command line; the vendor's command line example runs the installer through `arch -x86_64 /bin/sh Zscaler-osx-2.2.4.0-installer.app/Contents/MacOS/installbuilder.sh`. [zcc.troubleshooting.known-issues:legacy-m1-rosetta] Legacy (macOS Big Sur): to upgrade to macOS Big Sur, Client Connector must first be upgraded to version 2.2.4 or later; Apple requires password confirmation for the user's account before Client Connector can install and trust the root certificate, and as a workaround certificates can be installed via MDM for trust. [zcc.troubleshooting.known-issues:legacy-macos-big-sur] Legacy (macOS Catalina): to upgrade to macOS Catalina, you must use Client Connector 2.1 or later, and the vendor says Client Connector 2.1 and Catalina are no longer supported. With Cisco AnyConnect on macOS Catalina, you must use Cisco AnyConnect 4.8 or later. Separately, the vendor notes a known interoperability issue between Cisco AnyConnect 4.7 and macOS Catalina. [zcc.troubleshooting.known-issues:legacy-macos-catalina]

**Legacy: Linux.** Legacy (3.7.1 for Linux): some endpoint devices cannot upgrade to Client Connector 3.7.1 for Linux because of an AppArmor conflict when the OpenSSL service accesses openssl.cnf; the vendor's resolution, which it says will be fixed in a future release, is to open the ZSAUpdater AppArmor policy file /etc/apparmor.d/opt.zscaler.bin.zsupdater, inserts the policy `/etc/ssl/openssl.cnf r,` and reloads it with `sudo apparmor_parser -r /etc/apparmor.d/opt.zscaler.bin.zsupdater`. [zcc.troubleshooting.known-issues:legacy-linux-371-apparmor] Legacy (1.2 for Linux): Client Connector for Linux 1.2 requires changes to the DNS configuration for older third-party VPNs, like Pulse Secure and Cisco AnyConnect, for ZIA only mode. The changes are not required with both Internet & SaaS and Private Access, or with modern VPN clients like Openconnect. The vendor says to run the /opt/zscaler/scripts/config_vpn_dns.sh script with root permission, for example `sudo ./config_vpn_dns.sh tun0 "10.11.12.13 10.11.12.14" corp.testco.com`. [zcc.troubleshooting.known-issues:legacy-linux-12-vpn-dns] Legacy (1.1 to 1.2 for Linux): before upgrading to version 1.2 for Linux, Client Connector for Linux 1.1 needs an adjustment to address an issue with auto-updates for Ubuntu users, and until the changes are made an auto-update to Linux 1.2 will not work. The vendor's steps download the zip from https://d32a6ru7mhaq0c.cloudfront.net/zcc-update-apparmor-from-1-1-0.zip and run `sudo ./zcc-update-apparmor-config.sh`. [zcc.troubleshooting.known-issues:legacy-linux-11-autoupdate]

**Legacy: Android and updates.** Legacy (Android 10): to upgrade to Android 10 you must upgrade your devices (excluding Samsung devices) to Client Connector 1.5.2 for Android, and your Samsung devices to Client Connector 1.5.3 for Android. [zcc.troubleshooting.known-issues:legacy-android-10] Legacy (1.9 for Android): a device currently running a 32-bit version must first remove the current version of Client Connector (version 1.7.2 or earlier) before installing Client Connector version 1.9 for Android. [zcc.troubleshooting.known-issues:legacy-android-19-32bit] Legacy (1.4.3): starting on December 4th, 2018 at 3:00PM PST, users on Client Connector versions earlier than 1.4.3 see Connection Error in the Private Access section and are unable to connect to Private Access. For failed updates, the vendor says the most common issues are usually due to antivirus software on the device; for Admin Console based updates, devices must be able to connect to Amazon CloudFront to download the new version (users should be able to ping and telnet into d32a6ru7mhaq0c.cloudfront.net); and if MDM, SCCM, or GPO is used to update devices that have not yet upgraded, the same installation parameters used during the original installation must be used. [zcc.troubleshooting.known-issues:legacy-143-update]
