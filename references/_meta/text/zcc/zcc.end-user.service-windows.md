# What the Private Access, Internet Security, Digital Experience and Data Protection windows of the app show (zcc.end-user.service-windows)
Also called: Private Access window; Internet Security window; Digital Experience window; Data Protection window; Endpoint DLP window; Request exemption; Disable Endpoint DLP OTP; VPN Tunnel section; Restart ZDX Service

**Private Access.** The Classic Private Access window on Windows shows Username; Service Status, where Turn Off turns off the Zscaler Tunnel and disables the Private Access service while the user stays logged in, until Turn On; Authenticate Early, to reauthenticate Private Access before authentication expires; Time Connected; Network Type (Trusted Network, VPN-Trusted Network, Split VPN-Trusted Network or Off-Trusted Network); Authentication Status; Broker, the IP address of the server traffic is forwarded to; Client, the device's local IP address; Protocol (TLS or DTLS); and Total Bytes Sent and Total Bytes Received through the Z-Tunnel in real time. [zcc.end-user.service-windows:private-access-classic] The Classic Private Access window on macOS has a VPN Tunnel section that displays only when the device is connected to the Zscaler cloud using a VPN connection. On Windows the section is likewise displayed only then, and has these fields: VPN Service Edge, the IP address of the VPN Service Edge traffic is forwarded to (shown as Network Service Edge in previous versions); Client IP, the address the VPN Service Edge assigned for the session; and the bytes sent and received through the VPN Tunnel. [zcc.end-user.service-windows:vpn-tunnel-section]

**Network type on Android.** In the Classic UI on Android and on Android on ChromeOS the Private Access window gives the network type as Trusted Network or Off-Trusted Network, as does the Classic Internet Security screen on Android; the Modern UI's Private Access screen on Android lists Trusted Network, VPN-Trusted Network, Split VPN-Trusted Network and Off-Trusted Network. [zcc.end-user.service-windows:android-network-types]

**iOS.** On iOS the Classic Private Access screen shows Network Status (Trusted Network, VPN Trusted Network, Split VPN Trusted Network or Off-Trusted Network), Broker, the broker Client Connector is connected to, Tunnel Version and Tunnel SDK Version; depending on the organization's policies a password might be required. [zcc.end-user.service-windows:ios-private-access]

**Modern UI.** In the Modern UI the Private Access window on Windows shows Service Status (a password might be required if configured by the IT admin), Authentication Status, Authenticate Early, Time Connected, Network Type, Tunnel Version (the type of tunnel and the associated protocol), Client (the device's local IP address), Server (the IP address of the server traffic is forwarded to), and Total Traffic Received and Total Traffic Sent through the Z-Tunnel in real time; on Android and Android on ChromeOS the tunnel field is Protocol. [zcc.end-user.service-windows:modern-private-access]

**Modern UI, Internet & SaaS.** In the Modern UI the Internet & SaaS window on Windows shows Service Status (Turn Off disables the service while the user stays logged in, possibly with a password, until Turn On), Time Connected, Network Type (Trusted Network, VPN Trusted Network, Split VPN Trusted Network or Off-Trusted Network), Tunnel Version, Server (the IP address traffic is forwarded to), Client (the client IP address), and Total Traffic Sent and Received through the app in real time. [zcc.end-user.service-windows:modern-internet-saas]

**Internet Security.** The Classic Internet Security window on Windows shows Username; Service Status, where Turn Off disables the Internet & SaaS service while the user stays logged in (a password might be required) until Turn On; Server, the IP address of the server traffic is forwarded to; Client, the client IP address; Time Connected; Tunnel Version; and Total Bytes Sent and Received through the app. On Android and on Android on ChromeOS the server field is Proxy Server and Tunnel Version shows the version and protocol. [zcc.end-user.service-windows:internet-security-classic]

**Digital Experience.** The Classic Digital Experience window on Windows shows Service Status, where Turn Off turns off the Z-Tunnel and disables the Digital Experience service while the user stays logged in, until Turn On; Authentication Status; Server; Time Connected; and ZDX Service Version. Its troubleshooting actions are Clear ZDX Data, to clear the ZDX data the app stored, and Restart ZDX Service, which on Android 3.8 and later and on Android on ChromeOS 3.8 and later can be tapped only once within a 30-second period. In the Modern UI, Clear removes historical data collected by Digital Experience and Restart restarts the core services for Digital Experience monitoring. [zcc.end-user.service-windows:zdx-window]

**Data Protection.** The Data Protection window, for Windows and macOS devices, shows connectivity information and troubleshooting steps for the Data Protection feature, including Product Version, the current version of the feature. The service can be disabled with the Password to Disable Endpoint DLP in App Profiles or with a one-time password, which is the password listed under Disable Endpoint DLP OTP in Compliance Status. [zcc.end-user.service-windows:data-protection-window] An admin can enable Endpoint DLP using the Client Connector Portal; the page points to Configuring Client Connector Profiles for the steps to enable the Install Endpoint DLP feature. In the app, the Data Protection page refers to the Endpoint DLP feature, where end users can view the connection status of the service and perform troubleshooting. [zcc.end-user.service-windows:dlp-data-protection-page] The Endpoint DLP policy refreshes every 15 minutes, and Update DLP Policy refreshes it immediately. Open Quarantine Folder contains files moved there as a result of a block action for the personal cloud storage rules (for example Dropbox) or by other channels where the file source information is missing (for example copying an extracted ZIP file to a removable storage device). [zcc.end-user.service-windows:dlp-policy-and-quarantine]

**Endpoint DLP requirements.** The Client Connector Endpoint DLP integration page says the feature is supported on devices running Client Connector 4.3 and later for Windows and 4.2 and later for macOS, and that it is only supported on macOS Monterey (12) and later. [zcc.end-user.service-windows:dlp-integration-versions] The macOS floor is given two ways [divergence:zcc.end-user.service-windows:endpoint-dlp-macos-floor].

**Endpoint DLP notifications.** When a user violates an Endpoint DLP rule and user notifications are enabled, the user receives a message on the endpoint based on the triggered rule. For the Allow notification the user can click Learn more or Do Not Disturb, and it disappears automatically in 10 seconds; for the Block notification the user can click Learn more and then, under the More options drop-down menu, choose Do Not Disturb or Request Exemption; if the admin has set rules with a confirm action, end users receive a Confirm notification requesting action, and the user has 5 minutes to select an option, after which Zscaler blocks the activity. [zcc.end-user.service-windows:dlp-notifications] The page introduces the Block notification with the trigger it gives the Allow notification [divergence:zcc.end-user.service-windows:dlp-block-trigger]. Users can turn off Endpoint DLP user notifications under Zscaler Client Connector > More > Settings > Show all notifications; even then the Endpoint DLP notifications are still logged on the Notifications page. [zcc.end-user.service-windows:dlp-mute]

**Exemption.** A user blocked by Endpoint DLP for a rule violation can request an exemption from the block action and be monitored instead. In the Classic UI, Request exemption prompts for a password, the one-time password also works in offline mode, and the page says exemptions are granted for 12 hours. In the Modern UI the user enables the option, enters a Disable Reason on the Request exemption window and clicks Continue, might be prompted for a password, and a granted exemption shows a message that traffic is monitored but not blocked with an expiration time that the page gives as 12 hours after the exemption is granted. [zcc.end-user.service-windows:dlp-exemption] The length of an exemption is given two ways [divergence:zcc.end-user.service-windows:exemption-duration]; the console setting is [The Exemption Duration for Endpoint DLP and Device Control, during which user activities are not blocked but are monitored, can be set to 5 Minutes, 10 Minutes, 15 Minutes, 60 Minutes, 2 Hours, 6 Hours, or 12 Hours.](kb:zia.dlp.endpoint-settings:exemption-duration). How a user enters exemption mode is partly answered here; whether it relates to the `zdpmode` log field and to the password that disables Endpoint DLP is still open [How a user enters exemption mode](kb:zia.dlp.endpoint-settings:exemption-mode).

What to check:
1. Which UI (Classic or Modern) and which OS the user is on before reading a field name off these windows, since the names differ between them.
2. For how long a user's Endpoint DLP exemption lasts, the divergence and the Exemption Duration setting rather than the end-user page alone.

Sources disagree (name both sides):
- The Client Connector Endpoint DLP integration page says Endpoint DLP is only supported on macOS Monterey (12) and later; the ZIA step-by-step Endpoint DLP page lists endpoints running macOS 14, 15 or 26. [divergence:zcc.end-user.service-windows:endpoint-dlp-macos-floor]
  - zscaler-help: Endpoint DLP is only supported on devices running macOS Monterey (12) and later versions.
  - zscaler-help: The prerequisites list endpoints running macOS 14, 15, or 26 (Sonoma, Sequoia, or Tahoe) (existing claim zia.dlp.endpoint-enforcement:prerequisites).
  Impact: The oldest macOS release Endpoint DLP supports is Monterey (12) on one page and 14 on the other; the pages do not say whether the second is a list of tested releases or a floor.
- Inside the Endpoint DLP integration page, the Allow notification and the Block notification are each introduced with the same trigger, a rule configured for the Allow action. [divergence:zcc.end-user.service-windows:dlp-block-trigger]
  - zscaler-help: The Allow notification is displayed for a rule configured for the Allow action with the End User Notification set to Show.
  - zscaler-help: The Block notification is displayed for a rule configured for the Allow action with the End User Notification set to Show, which repeats the Allow notification's trigger.
  Impact: The page does not state what rule configuration produces the Block notification, so it cannot be used to say when a user sees it.
- The Classic and Modern end-user Endpoint DLP pages give the exemption as 12 hours, while the Endpoint Data Scan settings page makes the Exemption Duration selectable from 5 minutes to 12 hours. [divergence:zcc.end-user.service-windows:exemption-duration]
  - zscaler-help: Classic UI: exemptions are granted for 12 hours.
  - zscaler-help: Modern UI: the expiration time is 12 hours after the exemption is granted.
  - zscaler-help: The console's Exemption Duration can be set to 5 Minutes, 10 Minutes, 15 Minutes, 60 Minutes, 2 Hours, 6 Hours or 12 Hours (existing claim zia.dlp.endpoint-settings:exemption-duration).
  Impact: An exemption length other than 12 hours is configurable on the console page but stated as a fixed 12 hours on both end-user pages; the pages do not say whether the end-user text assumes the maximum setting or ignores the setting.
