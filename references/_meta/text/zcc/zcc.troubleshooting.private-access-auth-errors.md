# Private Access authentication errors Client Connector users might see during enrollment: 2008 and the 42xxx codes the vendor lists (zcc.troubleshooting.private-access-auth-errors)
Also called: private access authentication errors; zpa enrollment error codes; zcc 42000 errors; zcc saml error codes

These are the error messages users might see from Client Connector during the Private Access enrollment process. [zcc.troubleshooting.private-access-auth-errors:scope] 2008 (invalid redirection URL) occurs when a user delays Private Access authentication; the action is to authenticate again, and contact Zscaler Support if it persists. [zcc.troubleshooting.private-access-auth-errors:2008-delayed-auth]

**User identity.** 42000 (Inconsistency in user credentials) occurs when the user attempts to reauthenticate to Private Access and either enters a different username from the one provided during initial enrollment, or the IdP SAML response has a different NameID from the one sent during initial enrollment. The vendor says to verify that the NameID is the one Private Access received at initial enrollment, or to have the user log out and re-enroll into Private Access. [zcc.troubleshooting.private-access-auth-errors:42000-identity-changed] 42001 occurs when a user attempts to log in to Client Connector without a domain name, so Private Access cannot identify the user's organization. The vendor says to verify the user entered a valid domain as part of the username (for example, joe@safemarch.com), unless the App installer was configured so that the domain name is not required, in which case the user would only enter joe. [zcc.troubleshooting.private-access-auth-errors:42001-no-domain] 42029 occurs when the username has no domain associated with the organization; 42035 when the username's domain does not match any of the organization's domains; 42039 when the Private Access service cannot verify the service provider (SP) configuration for the domain. 42030 and 42031 occur due to missing information in the account associated with the Private Access service. For 42029, 42030, 42031 and 42035 the action is to contact Zscaler Support. [zcc.troubleshooting.private-access-auth-errors:domain-and-account]

**Identity provider setup.** 42002 occurs when Private Access is not configured correctly and cannot identify the IdP for enrolling the user; verify an IdP is configured for Private Access and can communicate with it. 42042: the IdP is disabled on Private Access; enable it at Administration > Identity > Private Access > IDP Configuration. 42043: the IdP is misconfigured (configuration incomplete). 42044: the SSO type and usage for the IdP configuration do not match. [zcc.troubleshooting.private-access-auth-errors:idp-setup] 42033 and 42034 occur when the Private Access service cannot validate the SAML response for the Private Access admin (42033) or user (42034); the action is to verify an IdP is configured for Private Access administrator SSO or user SSO respectively. 42037 occurs when the IdP is not enabled for admin SSO. [zcc.troubleshooting.private-access-auth-errors:admin-vs-user-sso] 42020 occurs when the IdP entity ID is not properly configured in the Admin Console, and the entity ID is case sensitive. 42036 occurs when the Private Access service cannot verify the entity ID for the IdP configuration. For both, review the entity ID of the IdP configuration in the Admin Console. [zcc.troubleshooting.private-access-auth-errors:entity-id] 42017 occurs when the IdP sends Private Access a SAML response without the Private Access authentication service initiating it; only service provider (SP) initiated SSO is supported with Private Access. 42018: the service failed to look up the SAML request corresponding to the response (contact Zscaler Support). 42019: the assertion consumer endpoint of the authentication service is not properly configured in the IdP (review the SP configuration in the IdP). [zcc.troubleshooting.private-access-auth-errors:sp-initiated-only]

**SAML response validation.** 42006 occurs when SAML response validation fails, which could be due to the system clock being out of sync, an expired IdP certificate, a failure in the SAML response signature validation, or issues around IdP lookup by IdP entity ID. 42013: the IdP SAML response does not match the expected object type (update the IdP configuration). 42014: the status in the SAML response is unsuccessful (review the user's information in the IdP and have the user retry). 42015: failed to validate the SAML response signature, because the IdP certificates are not configured correctly or the public certificate Private Access uses to validate the response has expired (check the IdP certificate's expiration date and upload a valid one). 42022: the SAML response has no NameID (ensure NameID is part of the subject). [zcc.troubleshooting.private-access-auth-errors:saml-response-validation] 42016 occurs when the response issue time is too old or in the future, because the IdP and the Private Access authentication service clocks have a large skew; the maximum accepted skew time is 120 seconds. 42021 occurs when assertion validation fails (the assertion is too old, or fails a notBefore or notOnOrAfter condition), which may be due to timing issues or unsupported assertion conditions such as OneTimeUse. 42032: the service does not support the OneTimeUse condition; update the IdP configuration to not issue a OneTimeUse SAML assertion. [zcc.troubleshooting.private-access-auth-errors:clock-skew-and-conditions]

**Certificates.** 42007 occurs when the certificate signing request in Private Access fails during enrollment; the vendor says to verify that the signing certificate chosen for enrolling devices is valid, notes that Private Access provides a default signing certificate, and says to check the Admin Console that it is still available. 42023, 42024 and 42025: the Client Connector CA (signing) certificate has expired, is missing, or its private key is missing; provision a valid CA certificate. 42026: Client Connector fails to get a valid certificate (contact Zscaler Support). [zcc.troubleshooting.private-access-auth-errors:enrollment-ca] 42046 occurs when the IdP's signing certificates in Private Access have expired; update the IdP configuration to upload a valid signing certificate from the IdP. 42047 and 42048 occur when the SAML request signing certificate configured in the Admin Console has expired (42047) or is not valid (42048); edit the IdP configuration to change the certificate used by the IdP to another certificate, and then update the IdP. [zcc.troubleshooting.private-access-auth-errors:idp-and-sp-signing-certs]

**Enrollment exchange and internal errors.** 42004 occurs when Client Connector does not send the expected information to Private Access during enrollment, and 42005 when Private Access cannot correctly interpret the information Client Connector sent; for both, verify SSO for Private Access is configured correctly. 42010 occurs when Private Access does not receive the expected information during enrollment; it is an internal error, so contact Zscaler Support. 42028 occurs when the Private Access authentication service receives a request with missing or unexpected information; contact Zscaler Support. [zcc.troubleshooting.private-access-auth-errors:enrollment-exchange] 42038 (Failed to insert into Object Store) and 42040 (Failed to encrypt) are internal errors; 42045 occurs when the IdP issues a SAML assertion that is larger than expected. For all three the action is to contact Zscaler Support. [zcc.troubleshooting.private-access-auth-errors:internal] 42027 occurs when the organization has provisioned more users than the number allowed by its subscription; the vendor says to verify that the existing Private Access subscription meets the organization's needs. [zcc.troubleshooting.private-access-auth-errors:user-limit-42027]

**What is not defined.** The codes 42003, 42008, 42009, 42011, 42012 and 42041 are absent from the table [gap:zcc.troubleshooting.private-access-auth-errors:absent-codes]. Where the user sees the code is not stated, and several codes share the message Internal Error: Contact Administrator [gap:zcc.troubleshooting.private-access-auth-errors:shared-message]. How large a SAML assertion must be to trigger 42045 is not stated [gap:zcc.troubleshooting.private-access-auth-errors:assertion-size]. What the client does with a stale assertion after enrollment is not settled by 42016 and 42021 [gap:zcc.troubleshooting.private-access-auth-errors:stale-assertion-later].
