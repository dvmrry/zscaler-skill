# App profile passwords: logout, disable, exit and uninstall, per platform (zcc.passwords-and-otp.app-profile-passwords)
Also called: uninstall password; logout password; disable password zia; disable password zpa; exit password; revert password; zcc cli disable password; fail-close exit password; profile passcode ios; password not prompting; disable password; prevent users from disabling zcc; zcc uninstall protection
Former IDs: zcc-93, zcc-94

An app profile can require a password before a user logs out of, disables, exits or uninstalls Client Connector. On Windows the app profile holds optional passwords that users must enter to log out, to disable Internet & SaaS, to disable Private Access, to exit the app from the system tray (3.5 and later), to uninstall, to disable ZDX and to disable Endpoint DLP. [zcc.passwords-and-otp.app-profile-passwords:optional-passwords]

**Platform differences.** The macOS app profile has Logout, Disable ZIA, Disable ZPA, Disable ZDX, Exit, Uninstall and Endpoint DLP disable passwords. [zcc.passwords-and-otp.app-profile-passwords:macos-zdx] On Linux the logout password is described as the password to log out of or uninstall the app. [zcc.passwords-and-otp.app-profile-passwords:linux-logout-uninstall] iOS has logout and service-disable passwords plus a profile passcode users must enter to connect to the VPN. [zcc.passwords-and-otp.app-profile-passwords:ios-passcode] The iOS app profile's password list has no uninstall, exit or ZDX password. [zcc.passwords-and-otp.app-profile-passwords:ios-passwords] The Android app profile has Logout, Disable ZIA, Disable ZPA and Disable ZDX passwords, and an Uninstall password that applies only to Client Connector 3.8 or earlier. [zcc.passwords-and-otp.app-profile-passwords:android-passwords] On Windows Client Connector 3.5 or earlier, the app profile's Exit password works as the ZIA disable password; the same entry gives the Exit password's own behavior for 3.5 and later, so at 3.5 the article contradicts itself. [zcc.passwords-and-otp.app-profile-passwords:windows-exit-through-3-5] What happens to a password the API sets on a platform whose app profile has no such field is open [gap:zcc.passwords-and-otp.app-profile-passwords:ui-gate-per-os].

**Other passwords in the profile.** On Windows (4.6 and later, with the WFP driver), the app profile's fail-close settings hold a separate exit or uninstall password that applies while the app is in a fail-close state. [zcc.passwords-and-otp.app-profile-passwords:fail-close-password] With Enable Zscaler Client Connector Revert (3.9 and later on Windows, 4.1 and later on macOS), users can revert to the previous Client Connector version after entering the Revert Password. [zcc.passwords-and-otp.app-profile-passwords:revert-password] With the command line interface enabled (4.4 and later on Windows, 4.3 and later on macOS), the profile can require a password to disable Private Access through the CLI, and also Internet & SaaS and ZDX on Windows 4.8 and later and on macOS 5.0 and later; the admin generates these passwords in the profile, and they expire after two hours. [zcc.passwords-and-otp.app-profile-passwords:cli-disable-passwords] Anti-tampering, which stops users from killing the app rather than asking for a password, is in [In the Windows app profile, anti-tampering prevents end users from stopping and modifying Zscaler endpoint products. If a user disables it with a one-time password, Reactivate Anti-Tampering After (In Mins), 1 to 1440 minutes, re-enables it after that time; the default 0 leaves it to the user to re-enable, or to Client Connector when the app exits and relaunches. The page marks these settings as applying to Client Connector 4.1 and later for Windows. On Windows 4.5 and later, Override Anti-tampering Install Parameter applies the profile's setting regardless of the install-time option.](kb:zcc.app-profiles.advanced-settings:anti-tampering).

**When a change reaches the device.** At the next profile download: [The app checks for app profile updates and downloads changes whenever the user logs out and back into the app or restarts the computer.](kb:zcc.app-profiles.propagation:download-on-relogin).

**Per device instead.** Each device's one-time passwords can stand in for these: [On Client Connector 4.0 and later for Windows, 4.1 and later for macOS and 4.2.1 and later for Linux, the device details page shows OTPs that can be used in place of app profile passwords: Logout, Revert, Uninstall, Exit (exit from the tray without disabling Internet & SaaS), Disable ZIA, Disable ZPA, Disable ZDX, Deception Settings (disables Deception; Windows 4.0 and later), Disable Anti-Tampering (Windows 4.1 and later, macOS 5.0 and later) and Disable Endpoint DLP (Windows 4.3 and later, macOS 4.2 and later).](kb:zcc.passwords-and-otp.otp:otp-meanings). Support-side settings are in [ZCC end-user support options (App Supportability)](kb:zcc.support-options).

**Open questions.** The Python SDK writes macOS passwords under snake_case keys, not the camelCase keys it reads, and what the API does with them is open [gap:zcc.passwords-and-otp.app-profile-passwords:macos-password-key-asymmetry]; the model's read and write keys are [The Python `MacOSPolicy` model reads the password from `disablePassword` but writes it as `disable_password`, and reads and writes the certificate setting as `installCerts`.](kb:zcc.sdk-python.wire-keys:mac-read-write-asymmetry). How a password reads back through the API, and whether an empty value removes the gate, is open [gap:zcc.passwords-and-otp.app-profile-passwords:password-read-and-clear].

What to check:
1. Whether the platform's app profile lists the password in question at all, since the lists differ by platform and Android's uninstall password applies only up to 3.8.
2. Whether the device has downloaded the changed profile yet, which happens at log-out and log-in or restart.
3. On Windows 3.5 or earlier, whether the Exit password is acting as the ZIA disable password.
