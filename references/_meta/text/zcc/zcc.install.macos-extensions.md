# macOS system extensions, VPN payloads and privacy profiles for Client Connector (zcc.install.macos-extensions)
Also called: zcc system extension; TRPTunnel; com.zscaler.zscaler.TRPTunnel; com.zscaler.zscaler.pktfilter; PCBCQZJ7S7; zscaler team id; transparent proxy-based interception; route-based interception; zcc pppc full disk access; managed login items zcc; process-based application bypass macos
Former IDs: zcc-15, zcc-19, zcc-20, zcc-75

Beyond the package and its install parameters, depending on the interception mode and features, the guides add configuration profiles that approve Client Connector's network extensions and grant its privacy permissions.

**Two interception modes.** Client Connector on macOS intercepts traffic locally either by Route-based Interception or by Transparent Proxy-based Interception. The latter uses the macOS Transparent Network Proxy Extension, through the TRPTunnel network extension (`com.zscaler.zscaler.TRPTunnel`), and the vendor lists as benefits no reliance on routing tables, better performance, Z-Tunnel 2.0 compatibility with third-party VPN clients, and no inbound firewall rules unless machine tunnels are used. [zcc.install.macos-extensions:interception-modes] The Workspace ONE guide words the inbound firewall benefit differently [divergence:zcc.install.macos-extensions:trp-inbound-rules-qualifier]. Transparent Proxy-based Interception is supported from Client Connector 4.5.2 on macOS Tahoe 26.2 and later, with exceptions: Private Access VPN for legacy apps needs 4.8, the Client Connector firewall 4.7, the Private Access machine tunnel 4.5.2.372, 4.7.0.380, 4.8.0.281 or 4.10.0.36 and later, and ICMP interception for domain-name-based Private Access apps 4.5.2.355, 4.7.0.351 or 4.8.0.252 and later. [zcc.install.macos-extensions:trp-support]

**Profiles for Transparent Proxy-based Interception.** The Transparent Proxy-based configuration profile has a System Extensions payload with Team Identifier `PCBCQZJ7S7` and the extension `com.zscaler.zscaler.TRPTunnel`, as a non-removable system extension (macOS Sequoia 15 and later; Allowed on earlier releases), and a VPN payload of connection type Custom SSL with identifier `com.zscaler.zscaler`, provider bundle identifier `com.zscaler.zscaler.TRPTunnel`, provider type App-proxy, and users prohibited from disabling on-demand VPN. The vendor also offers it as a preconfigured mobileconfig file. [zcc.install.macos-extensions:trp-profile] On the console side, the macOS app profile selects a forwarding profile with Z-Tunnel 2.0, enables Reconnect Tunnel on System Wakeup and, for this mode, Enable Transparent Proxy-based Traffic Interception; the forwarding profile's Drop IPv6 in Dual Stack Network option should stay off so IPv6 that macOS generates is not discarded. [zcc.install.macos-extensions:trp-console-steps] With Transparent Proxy-based Interception, video and audio UDP streams of collaboration apps that rely on STUN, and STUN itself, should be bypassed through predefined or custom IP-based application bypass or IP exclusions in app profiles; STUN is bypassed by TCP and UDP port 3478. [zcc.install.macos-extensions:stun-bypass] A machine tunnel in this mode has its own firewall and FileVault prerequisites: [With Transparent Proxy-based Interception mode enabled, a machine tunnel needs inbound traffic to ZscalerTunnel allowed in firewall rules, and FileVault disabled so Private Access connections work before a user logs in.](kb:zpa.machine-tunnels.requirements:transparent-proxy-prereqs).

**Private Access VPN for legacy apps.** Private Access VPN for legacy apps uses a separate VPN payload with provider bundle identifier `com.zscaler.zscaler.pktfilter` and provider type Packet-tunnel; it is supported with Route-based Interception on all supported releases and with Transparent Proxy-based Interception from 4.8. [zcc.install.macos-extensions:legacy-apps-vpn] For devices running macOS releases older than macOS Sequoia, the Workspace ONE guide says to review the commented sections and edit as required in both the ZCC-TRP-CONFIG mobileconfig file and the mobileconfig file for the Private Access VPN for Legacy Apps custom VPN profile. [zcc.install.macos-extensions:older-than-sequoia]

**Full Disk Access.** Endpoint DLP needs Full Disk Access to work properly: a Privacy Preferences Policy Control profile allows SystemPolicyAllFiles for the bundle IDs `com.zscaler.zdp.pd`, `com.zscaler.zdp.esd` and `com.zscaler.zdp.agent`, with notifications enabled for the agent. [zcc.install.macos-extensions:fda-dlp] Endpoint DLP requires Full Disk Access, and the MDM profiles that grant it must be deployed to endpoints before Endpoint DLP is installed; the Workspace ONE guide also says any existing Endpoint DLP MDM profiles must be removed before uploading a new profile. [zcc.install.macos-extensions:fda-before-dlp] The macOS versions Endpoint DLP supports are in [What the Private Access, Internet Security, Digital Experience and Data Protection windows of the app show](kb:zcc.end-user.service-windows). The two vendor guides disagree on one code requirement [divergence:zcc.install.macos-extensions:dlp-agent-code-requirement]. Whether any other feature needs Full Disk Access is open [gap:zcc.install.macos-extensions:full-disk-access-scope].

**Keeping it running.** Managed login items stop users disabling Client Connector on their devices: rules for bundle identifier and label `com.zscaler.tray`, and bundle identifier and label prefix `com.zscaler`, with Team Identifier PCBCQZJ7S7. [zcc.install.macos-extensions:managed-login-items]

**Process-based bypass.** Process-based application bypass is set in the Admin Console app profile with Transparent Proxy-based Interception from 4.8; with Route-based Interception, or Transparent Proxy-based on 4.7 and earlier, it is a preconfigured mobileconfig whose VPN payload lists bundle identifiers under BypassAppProcesses (an identifier with both a Team ID and a Bundle ID is written <Team ID>.<Bundle ID>), enabled by Process-Based Application Bypass using MDM in the app profile. [zcc.install.macos-extensions:process-bypass] With Transparent Proxy-based Traffic Interception, the Workspace ONE guide says process paths can also be used for application identification in the MDM mobileconfig, applying only to Client Connector 4.5.2.121 and later and 4.7.0.87 and later for macOS. [zcc.install.macos-extensions:process-path-versions]

**Open points.** What happens when the extension is not pre-approved is open [gap:zcc.install.macos-extensions:unapproved-extension], and so is profile timing [gap:zcc.install.macos-extensions:profile-timing]. The firewall's content filter payload is in [Client Connector's firewall on macOS: the system extension and content filter profiles, VendorConfig rules and the app profile switches](kb:zcc.install.macos-firewall); whether anything else registers a content filter is open [gap:zcc.install.macos-extensions:content-filter]. The Team ID and bundle identifiers are no longer open [gap:zcc.install.macos-extensions:team-and-bundle-ids].

What to check:
1. Which interception mode the macOS app profile enables, and whether the device's macOS and Client Connector versions support it.
2. Whether the system extension profile names Team ID PCBCQZJ7S7 and com.zscaler.zscaler.TRPTunnel, and whether the VPN payload uses App-proxy with the same provider bundle identifier.
3. For Endpoint DLP on macOS, whether a Full Disk Access profile covers all three com.zscaler.zdp identifiers.

Sources disagree (name both sides):
- The Jamf Pro guide says Transparent Proxy-based Interception removes the need for inbound firewall rules if not using machine tunnels; the Workspace ONE UEM macOS guide lists the benefit without the machine-tunnel qualifier. [divergence:zcc.install.macos-extensions:trp-inbound-rules-qualifier]
  - zscaler-help: It removes the need for inbound firewall rules if not using machine tunnels.
  - zscaler-help: It removes the need for inbound firewall rules, with no machine-tunnel qualifier.
  Impact: Read without the qualifier, the Workspace ONE wording suggests no inbound firewall rules are ever needed; the Jamf Pro wording limits that to deployments without machine tunnels, and the pages do not say whether the omission is intentional.
- For the Endpoint DLP agent identifier `com.zscaler.zdp.agent`, the Jamf Pro guide's code requirement names the same identifier, while the Intune guide's code requirement names `com.zscaler.zep.at`. [divergence:zcc.install.macos-extensions:dlp-agent-code-requirement]
  - zscaler-help: The code requirement for com.zscaler.zdp.agent begins identifier "com.zscaler.zdp.agent".
  - zscaler-help: The code requirement in the same column begins identifier "com.zscaler.zep.at".
  Impact: A PPPC entry whose code requirement does not match the signed agent does not grant it Full Disk Access, so copying the Intune table may leave Endpoint DLP without the access it needs.
