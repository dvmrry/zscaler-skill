# App Supportability sign-in settings: IdP username autofill, automatic Private Access reauthentication and registering devices with the ZPA IdP username (zcc.support-options.authentication)
Also called: automatically populate username for idp authentication; login_hint; automatic zpa reauthentication; automatically attempt zpa reauthentication; register device with zpa idp username; integrated windows authentication; iwa

The App Supportability page has settings for IdP username autofill, automatic Private Access reauthentication and registering devices with the ZPA IdP username. Client Connector can fill the username field of the organization's IdP login form automatically, using either JavaScript or the login_hint parameter, when Automatically Populate Username for IdP Authentication is enabled. [zcc.support-options.authentication:username-autofill]

**Username autofill.** Using JavaScript runs JavaScript in the IdP page during the SAML workflow to autofill the username; it is not available on Client Connector 5.0 and later for macOS. [zcc.support-options.authentication:javascript-option] Using login_hint SAML attribute has Client Connector send the login_hint parameter to both Internet & SaaS and Private Access during authentication, and they pass it to the IdP as the SAML Subject (NAMEID) to pre-populate the user name. If both options are selected, the login_hint parameter takes precedence over JavaScript. [zcc.support-options.authentication:login-hint-option] If Using login_hint SAML attribute is enabled, Username Format selects what is sent: SAM Account Name (the security account manager account name combined with the registry domain, as in jsmith@safemarch.com) or User Principal Name (the signed-in identity from a domain-joined device, or the SAM account name when the device is not domain-joined), which the page says reduces single sign-on disruptions when the IdP expects a UPN. A line after these items says it applies only to Client Connector 4.9 and later for Windows and that Zscaler Support enables the feature. [zcc.support-options.authentication:username-format] Whether the 4.9 line scopes the whole login_hint option or only Username Format is open [gap:zcc.support-options.authentication:username-format-scope], and so are the JavaScript option's platforms beyond macOS 5.0 [gap:zcc.support-options.authentication:javascript-platforms].

**Automatic Private Access reauthentication.** Automatic Private Access reauthentication is only available on Client Connector 3.0 and later for Windows and macOS. Its steps are to configure the IdP for single sign-on (SSO) and enable Integrated Windows Authentication (IWA); the page says IWA works with most browsers but not over some HTTP proxy servers. [zcc.support-options.authentication:reauth-availability] When automatic Private Access reauthentication is enabled, Client Connector attempts to log in silently when users must reauthenticate to Private Access; if the attempt is unsuccessful, users are prompted to reauthenticate with their credentials in Client Connector. [zcc.support-options.authentication:reauth-behavior] Timeout for Automatic ZPA Reauthentication (in seconds) sets the time it takes for the browser to reauthenticate automatically: 30 seconds by default, or 60, 90 or 120 seconds. [zcc.support-options.authentication:reauth-timeout] Whether the feature exists on Linux or mobile is open [gap:zcc.support-options.authentication:reauth-platforms].

**Integrated Windows Authentication.** For IWA in Mozilla Firefox on Windows, the SSO domain is added to network.negotiate-auth.trusted-uris and network.automatic-ntlm-auth.trusted-uris is also configured. On macOS, network.negotiate-auth.delegation-uris and network.automatic-ntlm-auth.trusted-uris are configured, and the toggles for network.automatic-ntlm-auth.allow-proxies and network.negotiate-auth.allow-proxies are clicked to set them to true. [zcc.support-options.authentication:iwa-firefox] For Google Chrome 8.0 and later, IWA is automatically enabled on Windows and macOS and the function is allowlist-driven; the policy is changed only through the command prompt (Windows, with --auth-server-whitelist) or terminal window (macOS, after creating a Kerberos ticket with kinit, with defaults write com.google.Chrome AuthServerWhitelist). For macOS devices running OS X, IWA is enabled automatically for Safari, after a Kerberos ticket is obtained. For Microsoft Edge 77 and later the SSO domain is entered as a Local Intranet site under Internet Options > Security. Admins use their organization's preferred method, for example a Microsoft Group Policy Object, to enable IWA for all users. [zcc.support-options.authentication:iwa-other-browsers] The reauthentication page says Client Connector enforces system proxy settings, all applications on the device must comply with these settings, and administrators review any custom proxy settings within applications and then restrict them. [zcc.support-options.authentication:system-proxy]

**Per app profile.** On Client Connector 4.8 and later for Windows the feature can be enabled per app profile and by network type, and it also needs IWA. In the app profile, Follow Global Settings ZPA Reauthentication applies the App Supportability tab's setting and then prevents configuring Private Access reauthentication on that profile; Automatically Attempt ZPA Reauthentication by Location selects network types (On-Trusted, VPN-Trusted, Off-Trusted or Split VPN-Trusted), and Client Connector updates access when a network switch occurs; the timeout does not restart on a network switch. [zcc.support-options.authentication:reauth-per-profile] In the Windows app profile, two options refine automatic reauthentication: Prevent Auto Reauth During Device Lock prevents it on a locked device until the device is unlocked (not affecting sleep mode without auto-lock, hibernate mode or a restart; 4.8 and later for Windows), and Instantly Enforce ZPA Reauth, when Force ZPA authentication to expire and Automatic ZPA Reauthentication are enabled, starts reauthentication immediately after a forced expiration instead of waiting for the user's next attempt to access Private Access. [zcc.support-options.authentication:reauth-lock-and-expiry] The expiry setting itself is in [What the less common app profile settings do](kb:zcc.app-profiles.advanced-settings).

**Registering with the ZPA username.** Register device with ZPA IdP Username registers a device in the Admin Console with the username entered for Private Access authentication instead of the username used for enrollment in the app. [zcc.support-options.authentication:register-with-zpa-username] What it changes in the device record, and its versions and platforms, are not stated [gap:zcc.support-options.authentication:register-device-effects].

What to check:
1. For automatic Private Access reauthentication that does not happen, the client version and platform, whether IWA is enabled for the browser, and whether the app profile follows the global setting or sets its own.
2. For a username that is not prefilled, which option is selected (login_hint takes precedence over JavaScript) and whether the client is macOS 5.0 or later, where the JavaScript option is not available.
