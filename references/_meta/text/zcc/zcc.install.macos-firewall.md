# Client Connector's firewall on macOS: the system extension and content filter profiles, VendorConfig rules and the app profile switches (zcc.install.macos-firewall)
Also called: zcc macos firewall; zcc firewall macos; ZscalerSample.mobileconfig; enforceTrafficViaTunnel; allowTrafficToDefaultGateway; detectAltInterfaceTraffic; alwaysAllowed; block lan access macos; VendorConfig firewall

On macOS devices, admins must create a system extension profile via a mobile device management (MDM) solution, configure firewall rules, and also enable firewall settings in the Admin Console. [zcc.install.macos-firewall:parts]

**System extension profile.** The system extension profile uses team identifier PCBCQZJ7S7: in Intune an Extensions template, where the team identifier allows the profile to be installed silently, and in Jamf Pro System Extensions with the type Allowed Team Identifiers. Although the Zscaler system extension is built into Client Connector, it must be configured in Jamf to activate it. [zcc.install.macos-firewall:system-extension]

**Content filter profile.** In Jamf Pro the firewall is a Content Filter payload with identifier com.zscaler.zscaler, service address zscaler.com, organization Zscaler and a socket filter with bundle identifier com.zscaler.zscaler.pktfilter and designated requirement identifier "com.zscaler.zscaler.pktfilter" and anchor apple generic; the general, outbound and inbound firewall parameters go in the Custom Data section. In Intune a Custom template uploads ZscalerSample.mobileconfig with the firewall parameters configured. [zcc.install.macos-firewall:content-filter]

**The rules.** The VendorConfig section of ZscalerSample.mobileconfig has top-level dictionaries general, inbound and outbound; within the inbound and outbound dictionaries are dictionaries for untrusted or trusted networks, each key holding an optional array of rule dictionaries. The page's inbound example uses the keys trustednet, trustedsplitvpnnet, trustedvpnnet and untrustednet. [zcc.install.macos-firewall:structure] A firewall rule's action is allow or block. An app match must exactly match teamid.bundleid, or the bundleid for an app with no Team ID; protos specifies the IP protocol the flow must match (for example tcp and/or udp or icmp); ips lists remote IP addresses and subnets, delimited by a space or comma, and may mix IPv4, IPv6 and lanlocal; ports specifies the UDP or TCP ports that match, and is ignored if protos is icmp. The system extension does not filter incoming ICMP. [zcc.install.macos-firewall:rule-parameters] In the page's example the untrustednet array has three separate rules (apps, ips, ports), each independent of the other two: traffic from Opera matches only the first rule and the second and third are not evaluated, and the third is evaluated only if the traffic is not from Opera and is not destined for the listed addresses or lanlocal. Key types can be combined for more specific rules, such as disallowing Opera traffic only if the destination is 1.2.3.4:5432:. [zcc.install.macos-firewall:evaluation]

**General parameters.** The general parameters are enforceTrafficViaTunnel (if true, when the tunnel is inactive, restricts network traffic while the Z-Tunnel is not running), allowTrafficToDefaultGateway (if false, traffic to the default gateway is blocked, which can prevent the device interacting with captive portals and other services the default gateway device provides), detectAltInterfaceTraffic (if true, detects traffic that attempts to bypass the routing table; not supported on Client Connector 4.5.2 and later for macOS) and alwaysAllowed (inbound and outbound traffic defined with it is always allowed even when enforceTrafficViaTunnel is true). The sentence after alwaysAllowed says that parameter applies to Z-Tunnel 1.0 and 2.0 and is supported on 4.5.2 and later for macOS. [zcc.install.macos-firewall:general-parameters] If the persistent key is true, the firewall remains on even when the user logs out of Client Connector; if false, firewall rules are no longer applied at logout. The parameter does not affect the firewall while the user is logged in; for persistent firewall filtering then, the Persistent Zscaler Firewall option on the user's app profile is enabled. [zcc.install.macos-firewall:persistence]

**App profile and changes.** In the app profile, Enable Zscaler Firewall determines which network traffic is allowed and blocked and is disabled by default; the optional Persistent Zscaler Firewall setting, for persistence while the user is logged in, is also disabled by default. When Client Connector performs a policy update the firewall feature is enabled and the rules are enforced; to change firewall parameters or rules, edit the configuration profile and redeploy it to macOS devices using Jamf Pro, with no change required to the app profile for existing rules. [zcc.install.macos-firewall:console-settings] For existing legacy configuration profiles in Jamf Pro, Application and Custom Settings must be removed and the general, inbound and outbound firewall rules added to the Content Filter payload; this applies to Client Connector for macOS 4.5.0.211, 4.3.1.102 and later. [zcc.install.macos-firewall:jamf-legacy-profiles] The Windows counterpart for LAN blocking is in [Location-based policies: rulesets that steer traffic and set endpoint firewall rules by network type, and the lists they use](kb:zcc.location-policies).

**Open points.** Which interception mode the firewall needs is open [gap:zcc.install.macos-firewall:interception-mode] (the version floor under Transparent Proxy-based Interception is in [Transparent Proxy-based Interception is supported from Client Connector 4.5.2 on macOS Tahoe 26.2 and later, with exceptions: Private Access VPN for legacy apps needs 4.8, the Client Connector firewall 4.7, the Private Access machine tunnel 4.5.2.372, 4.7.0.380, 4.8.0.281 or 4.10.0.36 and later, and ICMP interception for domain-name-based Private Access apps 4.5.2.355, 4.7.0.351 or 4.8.0.252 and later.](kb:zcc.install.macos-extensions:trp-support)). What lanlocal covers is open [gap:zcc.install.macos-firewall:lanlocal], and so is whether the rules apply per network type as the example keys name them [gap:zcc.install.macos-firewall:network-keys].
