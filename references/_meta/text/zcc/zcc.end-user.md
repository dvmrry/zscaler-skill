# The Client Connector app as users see it: Classic UI and Modern UI menus, status, enrollment and notifications, by OS where the pages cover it (zcc.end-user)
Also called: Classic UI; Modern UI; Modern Experience; Status Orb; system tray menu; Quick Actions; Do Not Disturb; Authenticate Early; Export Logs; end user guide

The Classic UI is the version of the app available with Client Connector versions earlier than 5.0, and the Modern UI is the modernized UI available with version 5.0. In the Modern UI the Modern Experience setting can be disabled to display the Classic UI. [zcc.end-user:classic-and-modern] The console setting that picks the default is in [Platform Settings: the per-OS console settings for sign-in, IPv6, ZDX upgrades, default UI and unattended-mode passwords](kb:zcc.platform-settings). The app recognizes when it is connected to a trusted network, such as a corporate office network, and depending on the organization's configuration can disable Internet & SaaS, Private Access, ZDX and Endpoint DLP services accordingly; it disables its services for a period of time and re-enables itself after the user has had a chance to complete the steps necessary to connect. In the Classic UI's Windows navigation, the app does not show an option for a service the organization is not subscribed to. [zcc.end-user:self-disabling]

**Windows tray menu.** The Classic UI's Windows system tray icon menu offers Open Zscaler, Authenticate (without opening the application), Authenticate Early (reauthenticate before authentication expires), Register (complete the device enrollment), Notifications, Export Logs, Report an Issue (if the organization has enabled it) and Exit. For Client Connector 4.9 and later with the Zscaler Notification Framework, Notifications offers Mute for 30 minutes, 1 hour or 2 hours, or Until Resumed, which makes the option display as Notifications (Paused). The page says Export Logs saves logs as a text file on the device. On the Quick Actions page's Windows list, Do Not Disturb pauses pop-up notifications and displays as Notifications [Paused] when Until Resumed is selected. [zcc.end-user:windows-tray-options]

**Other platforms.** In the Classic UI, the macOS menu bar icon offers Open, Export Logs, Report an Issue and Exit, and the Linux icon's right-click menu offers Open Zscaler, Export Logs, Report An Issue and Exit. On Android and on Android on ChromeOS the icon displays with an exclamation point when authentication expires and Reauthenticate displays only when authentication expires; on Android the menu also offers Export Logs and Report an Issue, if the organization has enabled that option. [zcc.end-user:other-os-menus] On the Quick Actions page's Android list, pressing and holding the icon offers Authenticate Early (reauthenticate Private Access before authentication expires), Export Logs, Report an Issue (if the organization has enabled it), and Do Not Disturb options listed as Disabled (turn notifications off), Enabled (turn notifications on), 30 Minutes, 1 Hour and 2 Hours. On Android on ChromeOS the options include Authenticate Early, Export Logs and the Disabled and Enabled options. [zcc.end-user:android-quick-actions]

**Exporting logs.** The pages say Export Logs saves a text file in some places and a ZIP file in others [divergence:zcc.end-user:export-logs-format]. The Troubleshoot section's own wording is in [The Classic Troubleshoot section on Windows has Start Packet Capture (if the admin enabled packet captures); Report an Issue (if the admin enabled in-app support access); Export Logs, which exports logs to a ZIP file to email to the organization's support admin; Restart Service, which restarts the app; Repair App, where the app attempts to repair itself by reinstalling app drivers and services and which Zscaler recommends trying before reporting an issue; Revert App (if the admin enabled the revert option), which reverts to the previous version and might require a password; Disable Tamper Protection, which asks for the Disable Anti-Tampering OTP; Clear Logs; and Log Mode.](kb:zcc.end-user.troubleshooting:windows-troubleshoot-section).

**Leaving the app.** In the Classic UI on Windows, logging out might require a password set by the organization's admin and the user must complete enrollment again on logging back in, closing the window does not log the user out, and Exit exits the app and disables the Zscaler service, possibly with a password. In the Modern UI, signing out also means completing enrollment again, while the Exit icon closes the app without signing the user out and the services continue to run. [zcc.end-user:logout-close-exit]

**Status and version.** In the Modern UI, the Status Orb shows the status of the security services: green when all enabled services are connected and active, orange when one or more enabled services requires user action (for example authentication), and blue when one or more enabled services is currently unavailable, with an additional message of more information such as the internet not being connected or a service connecting. A red number on the Notifications icon counts pending notifications. [zcc.end-user:status-orb] The Classic UI's About information includes Update App, which updates to the latest version approved by the organization and is not available on Android; App Policy, the name of the app profile assigned to the device; and Update Policy, which manually refreshes internet security policies and the PAC file. The Modern UI information page also lists UI Language, whose default is based on the app profile and which applies to Client Connector for Windows, and Theme, Light or Dark or following the Device Theme setting. [zcc.end-user:about-window] The fields of the service windows are in [What the Private Access, Internet Security, Digital Experience and Data Protection windows of the app show](kb:zcc.end-user.service-windows).

**Enrolling.** In the Windows steps for enrolling in the Classic UI, the username must be in email format unless the organization's admin configured the settings to log in without entering the organization's domain, the user might be required to enter a password or might be redirected to the organization's single sign-on form, and if the organization has configured an Acceptable Use Policy the user must accept it to proceed to enrollment. [zcc.end-user:enrollment-flow] In the Android steps for enrolling in the Classic UI, the user is prompted to allow Zscaler to send notifications (recommended: Allow) and, based on how the organization installed Client Connector, to allow access to contacts (recommended: Allow), and is told when post notification permission is missing; the enrollment screen also offers Export logs and entering the cloud name to connect to. After enrollment the app must be allowed to establish a VPN tunnel, and if it is not allowed the user must restart the app to see the prompt again. [zcc.end-user:android-enrollment] Adding a partner tenant from the app is in [Private Access partner logins: who may log in to whose tenant, and what the user does and sees](kb:zcc.partner-tenants).

**Notifications window.** In the Windows steps for viewing notifications in the Classic UI, each notification lists the Application relevant to the action that triggered it, the Time it was received and the Message; for example, an upload to Dropbox.com in violation of a cloud app control policy shows Dropbox.com in the Application column. Clear All clears all notifications from the page. [zcc.end-user:notifications-window] On Android, the Delete icon in the top-right corner clears all notifications from the screen, and notifications can be viewed from Today, the Last 7 Days, the Last 10 Days, or All. [zcc.end-user:mobile-filter] In the Windows steps for viewing notifications in the Classic UI, users can manually enable or disable pop-up notifications (the default is set by the admin, and the setting does not affect Private Access reauthentication notifications), override the default configured in the Admin Console to show Private Access reauthentication notifications, and pause notifications with Do Not Disturb (DND) Mode in 30-minute, 1-hour or 2-hour increments; on Client Connector 4.9 they can select Enabled to pause notifications indefinitely until they select Disabled. [zcc.end-user:user-settings] For Client Connector 3.8 and later for Windows, the Zscaler Notification Framework can be used instead, and notifications then cannot be disabled in Windows settings. [zcc.end-user:framework-on-windows]

**Self Service.** After the admins have configured the Self Service settings, users receive notifications when issues are detected and need attention. Each contains a brief diagnosis and recommendation that might resolve the CPU or Wi-Fi issue, appears as a dialog window on the user's screen and is also recorded on the Notifications page; users can enable the toggle for Show Self Service notification popups under Settings and can give feedback on whether the recommendation helped. [zcc.end-user:self-service] The pop-up message catalog is in [Client Connector pop-up messages: type, meaning, user action and duplicate suppression](kb:zcc.notifications.pop-ups).

**Troubleshooting from the app.** The Troubleshoot section, Report an Issue and Zscaler Diagnostics are in [What users get to troubleshoot: the Troubleshoot section, Report an Issue and Zscaler Diagnostics at the login screen](kb:zcc.end-user.troubleshooting).

**Open questions.** The Modern UI pages describe Windows, with Android and Android on ChromeOS for Private Access and quick actions, and not macOS, Linux or iOS [gap:zcc.end-user:modern-ui-coverage]. The Do Not Disturb options Disabled and Enabled read inverted against a pause [gap:zcc.end-user:dnd-options-meaning].

What to check:
1. Whether the user is on the Classic or the Modern UI, since menu and field names differ and Client Connector before 5.0 shows only Classic.
2. Before telling a user where an exported log file is or what format it has, the divergence over text file versus ZIP.
3. Whether the user chose Exit or Sign Out, since Exit leaves the services running in the Modern UI and Sign Out needs enrollment again.

Sources disagree (name both sides):
- End-user pages for the tray menu, menu bar and Android quick actions, say Export Logs saves logs as a text file, and the App Supportability overview says users can export logs as a text file, while the Troubleshoot pages and the logging controls article say the exported logs are a ZIP file. [divergence:zcc.end-user:export-logs-format]
  - zscaler-help: Classic UI, Windows tray menu: logs are saved as a text file.
  - zscaler-help: Classic UI, macOS menu bar: logs are saved as a text file.
  - zscaler-help: Classic UI, Linux tray menu: log files are saved as text files.
  - zscaler-help: Classic UI, Android: logs are saved as a text file.
  - zscaler-help: Modern UI quick actions, Android: logs are saved as a text file.
  - zscaler-help: Modern UI quick actions, Android on ChromeOS: logs are saved as a text file.
  - zscaler-help: App Supportability overview: users given access to logging controls can export logs as a text file.
  - zscaler-help: Classic UI Troubleshoot section, Windows: logs are exported to a ZIP file.
  - zscaler-help: Classic UI Troubleshoot section, macOS: logs are exported to a ZIP file.
  - zscaler-help: Classic UI Troubleshoot section, Linux: logs are exported to a ZIP file.
  - zscaler-help: Modern UI Troubleshooting page: logs are exported to a ZIP file.
  - zscaler-help: Admin logging controls article: exporting from the system tray icon shortcut menu saves a ZIP file (existing claim zcc.logging.user-access:visible-capabilities).
  Impact: The tray menu and the Troubleshoot section both offer Export Logs but the pages give the output as a text file and as a ZIP file; the file format a user gets from each entry point is not settled by the pages.
