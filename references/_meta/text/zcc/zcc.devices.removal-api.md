# Removing devices and machine tunnels through the API and SDKs (zcc.devices.removal-api)
Also called: removeDevices; forceRemoveDevices; removeMachineTunnel; SoftRemoveDevices; ForceRemoveDevices; RemoveMachineTunnel; remove_devices; force_remove_devices; remove_machine_tunnel; stale machine tunnel

Three POST calls remove devices: a soft remove, a force remove, and a machine-tunnel remove. Paths and SDK function names are generated; the states they act on are in [Enrolled device states and what moves a device between them](kb:zcc.devices.lifecycle).

**Soft and force remove.** What each call does and the criteria it needs: [`POST /removeDevices` soft-removes enrolled devices from the portal, marking their state as device removal pending.](kb:zcc.api.devices-wire:soft-remove), [`POST /forceRemoveDevices` force-removes enrolled devices from the portal, but only devices in the registered or device-removal-pending state.](kb:zcc.api.devices-wire:force-remove), [Both removal calls select devices by criteria in one request, at least one of which must be given: a user name, a list of Client Connector versions, an OS type, or a list of UDIDs. The response reports the number of devices removed.](kb:zcc.api.devices-wire:remove-by-criteria). The platform codes for `osType` are in [The contract gives numeric platform codes for `osType` on the soft- and force-remove endpoints (`removeDevices`, `forceRemoveDevices`): 1 iOS, 2 Android, 3 Windows, 4 macOS, 5 Linux, where null means all OS types; the Go SDK defines the same device-type constants.](kb:zcc.api.conventions:os-type-codes).

**Page size.** Both remove calls take a `pageSize` query parameter that defaults to 30; the soft-remove contract gives a maximum of 5000. [zcc.devices.removal-api:remove-page-size] The Go `SoftRemoveDevices` and `ForceRemoveDevices` always send `pageSize`: a caller's value of 0 or less becomes 50 and a value over 5000 becomes 5000, so the Go default is 50, not the API's 30. [zcc.devices.removal-api:go-remove-page-size]

**Python request body.** The Python `remove_devices` and `force_remove_devices` translate an `os_type` name to its numeric code as a string and send it as `osType` in the body, or in the query string when the call also passes `query_params`; the contract types `osType` as an integer. [zcc.devices.removal-api:python-remove-os-type] The `remove_devices` docstring example passes `os_type='3'`, but the Python decorator maps only platform names (ios, android, windows, macos, linux), so a numeric code maps to nothing and the decorator raises `ValueError` before it calls the wrapped method. [zcc.devices.removal-api:python-remove-example-os-code-raises] The Python `remove_devices` docstring example passes `username=`, which goes on the wire unchanged as `username` because only underscored keys are camel-cased, while the contract's body key is `userName`; the `force_remove_devices` example uses `user_name=`, which becomes `userName`. [zcc.devices.removal-api:python-remove-username-example] Whether the API accepts `username` for `userName` is open [gap:zcc.devices.removal-api:username-key-accepted].

**Machine tunnels.** A changed machine token does not replace existing machine tunnels: [Changing the machine token, or applying a different app profile, does not override existing machine tunnels; the token must be removed from the app profile and the tunnel removed in Enrolled Devices, or the app reinstalled.](kb:zcc.entitlements.zpa:machine-token-change). The machine-tunnel remove call takes either `hostName` (a comma-separated list) or `machineToken` as query parameters, not both; its contract also defines a body with a `hostNames` array and `machineToken`. [zcc.devices.removal-api:machine-tunnel-call] The Go SDK sends the hostnames differently from the contract [zcc.api.devices-wire:machine-tunnel-hostnames](kb:zcc.api.devices-wire:machine-tunnel-hostnames). The Python `remove_machine_tunnel` camel-cases both its query parameters and its keyword arguments, so its example's `host_names=[...]` goes in the body as `hostNames`, the contract's body key. Its docstring's Args instead document a `hostnames` keyword and a `query_params.hostname` key; neither has an underscore, so both go out unchanged as `hostnames` and `hostname`, matching neither the contract's `hostNames` body key nor its `hostName` query key. [zcc.devices.removal-api:python-machine-tunnel-keys] What a machine-tunnel removal leaves in place is open [gap:zcc.devices.removal-api:machine-tunnel-removal-scope].

What to check:
1. Whether the request names at least one criterion (user, version, OS type or UDID), and for a force remove whether the devices are Registered or Removal Pending.
2. For a Python removal by user, whether the body carried `userName` rather than `username`.
3. For a Go machine-tunnel removal by hostname that did nothing, whether the server read the body key the SDK sends.

Not known (open gaps):
- Whether the remove calls accept `username` in place of `userName` [gap:zcc.devices.removal-api:username-key-accepted]: settled by lab-test. Blocks: removing a user's devices through the Python SDK as documented
- What removing a machine tunnel leaves on the device record [gap:zcc.devices.removal-api:machine-tunnel-removal-scope]: settled by lab-test or support-ticket. Blocks: deciding between a machine-tunnel removal and a device removal
