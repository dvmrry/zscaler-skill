# How Client Connector decides it is on a trusted network (zcc.trusted-networks.detection)
Also called: trusted network criteria; trusted network detection; why is the user off-trusted in the office; why is the user on-trusted at home; condition match any all; evaluate trusted network; predefined trusted networks; split vpn trusted detection; skip trusted criteria match

Trusted-network detection decides whether a device is On-Trusted, which in turn picks the forwarding action. It is configured on the forwarding profile, either inline or by selecting predefined trusted networks.

**Why it exists.** Trusted network detection lets Client Connector recognize the organization's network segments and disable itself there, so traffic is tunneled by the internet gateway over GRE or IPSec; when it detects it is not on a trusted segment, it tries to connect to the nearest ZIA Service Edge. [zcc.trusted-networks.detection:refarch-purpose] What the app then does on a trusted network is the profile's On-Trusted action: [Forwarding profile actions for Internet & SaaS (ZIA): Tunnel, Tunnel with Local Proxy, Enforce Proxy, None](kb:zcc.forwarding-profiles.internet-actions).

**The conditions.** A forwarding profile's Trusted Network Criteria define the network information and conditions a network must meet for Client Connector to verify that it is one of the organization's trusted networks. [zcc.trusted-networks.detection:criteria-defined] DNS Server lists the DNS servers the corporate network sends requests to, comma-separated (IPv6 from Windows 3.4); the app verifies at least one DNS server. [zcc.trusted-networks.detection:dns-server] DNS Search Domains lists the primary search domains of the adapter used to connect to Zscaler; the app verifies only the primary domains assigned to the active network adapter. [zcc.trusted-networks.detection:dns-search-domains] Hostname and IP names a hostname and the IP addresses it resolves to on the corporate network; the app verifies at least one of those IP addresses. [zcc.trusted-networks.detection:hostname-ip] The vendor says not to use a domain covered by a Private Access application segment for this condition, unless the domain's bypass in the Client Connector Access section is Always. [zcc.trusted-networks.detection:hostname-not-private-access] Among the other conditions Add Condition offers are Network Range (subnets and private IPs), Default Gateway (the default gateway to the internet) and DHCP Server. [zcc.trusted-networks.detection:other-conditions] Egress IP matches the network's egress IP address, which distinguishes a location that otherwise matches another location's criteria; it applies only to Client Connector 4.6 and later for Windows. [zcc.trusted-networks.detection:egress-ip] A trusted network on the Trusted Networks page can match the Wi-Fi network name (SSID); a special character such as $ or ^ in the name is preceded by a backslash (Z$calerWiFi* is entered as Z\$calerWiFi\*), and the condition applies only to Client Connector 5.0 and later for Windows. [zcc.trusted-networks.detection:wifi-name]

**Combining them.** With more than one condition, Condition Match sets whether the app validates only one of them (Any) or all of them (All) to decide the network is trusted. [zcc.trusted-networks.detection:any-all] Predefined Trusted Networks (Windows 2.1 and later) selects several networks whose criteria are defined on the Trusted Networks page; it cannot be used together with DNS Server, DNS Search Domains or Hostname and IP conditions, and the reference architecture calls it the only criterion used when configured. [zcc.trusted-networks.detection:predefined] So the profile's Any/All applies across its own inline conditions; a profile that selects predefined trusted networks does not also combine them with DNS Server, DNS Search Domains or Hostname conditions. [zcc.trusted-networks.detection:profile-match-scope] How several predefined networks combine, and what `predefinedTnAll` selects, is open [gap:zcc.trusted-networks.detection:multiple-networks].

**Static over dynamic.** Zscaler recommends static conditions, DNS Server and DNS Search Domains, over Hostname and IP, which is dynamic: the hostname must resolve to the configured IP, resolution can fail during network transitions, and the app may then decide the network is untrusted and apply the wrong forwarding profile action. [zcc.trusted-networks.detection:static-recommended]

**Evaluation options.** Evaluate Trusted NW against All Default Route Adapters evaluates the criteria against every adapter with a default route, and uses the adapter with the lowest metric when more than one matches. [zcc.trusted-networks.detection:eval-all-adapters] Enable Split VPN-Trusted Network makes Client Connector detect a split-tunnel VPN in addition to full-tunnel VPN-Trusted detection. [zcc.trusted-networks.detection:enable-split-vpn] Skip Trusted Criteria match for VPN Adapters stops requiring the criteria to match on VPN adapters: the adapter's presence triggers network detection. [zcc.trusted-networks.detection:skip-criteria-vpn] On the wire, `skipTrustedCriteriaMatch` is the Skip Trusted Criteria match for VPN Adapters option, and by their names `enableAllDefaultAdaptersTN` and `enableSplitVpnTN` are the other two evaluation options. [zcc.trusted-networks.detection:option-fields] What `evaluateTrustedNetwork` turns off is open [gap:zcc.trusted-networks.detection:evaluate-switch].

**When it runs.** Any time a network adapter connects to a network, Client Connector reassesses the trusted and untrusted criteria and decides whether it should be active. [zcc.trusted-networks.detection:reassess-on-connect] Other triggers, debouncing and caching are open [gap:zcc.trusted-networks.detection:transition-handling].

**Where criteria go wrong.** Criteria that also match outside the office are open [gap:zcc.trusted-networks.detection:criteria-overlap], as are an SSID condition on wired devices [gap:zcc.trusted-networks.detection:wired-ssid], whitespace in comma-separated values [gap:zcc.trusted-networks.detection:criteria-whitespace] and egress-IP timing at network bring-up [gap:zcc.trusted-networks.detection:egress-ip-timing].

ZPA's trusted network objects and the TRUSTED_NETWORK policy operand are separate records fed from this detection: [Trusted networks in ZPA and in Client Connector](kb:zpa.trusted-networks.zcc-relationship), [The TRUSTED_NETWORK operand in ZPA policy rules](kb:zpa.trusted-networks.policy-operand). The standalone Client Connector trusted network object is [The Client Connector trusted network object and its v1 API](kb:zcc.trusted-networks.object).

What to check:
1. Which conditions the active profile uses and whether Condition Match is Any or All; with Any, check each condition alone against the user's network.
2. Whether the profile relies on Hostname and IP, which can fail during network transitions and yield the untrusted action.
3. Whether the Hostname condition uses a domain covered by a Private Access application segment.
4. For VPN users: the profile's evaluation options (all default-route adapters, Split VPN-Trusted, skip criteria for VPN adapters).
5. Whether the profile's `evaluateTrustedNetwork` is set, without assuming what it disables.
