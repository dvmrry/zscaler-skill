# SSL inspection for Client Connector users: what Client Connector does and what ZIA does (zcc.ssl-inspection)
Also called: zcc ssl inspection; client connector ssl inspection; browser shows original certificate not zscaler; ssl inspection not happening zcc; zcc certificate trust; does zcc decrypt traffic

For Client Connector users, SSL inspection is split between the device and the cloud. Enabling SSL inspection for Client Connector devices lets the Zscaler service decrypt and inspect HTTPS traffic between the browser and the device and between the device and the destination server. [zcc.ssl-inspection:service-decrypts]

**Client Connector's part.** The vendor describes the decryption as done by the Zscaler service; Client Connector's documented roles in SSL inspection are forwarding the traffic and installing the certificate, and no source describes inspection on the device itself. [zcc.ssl-inspection:no-local-inspection] Which traffic reaches ZIA is the forwarding profile's job: [A forwarding profile tells Client Connector how to treat traffic from users' systems in different network environments, for the Internet & SaaS and Private Access services.](kb:zcc.forwarding-profiles:purpose). The certificate side: [Who installs the SSL inspection certificate on Client Connector devices, per platform](kb:zcc.ssl-inspection.certificate-install). Whether Client Connector has an SSL-specific bypass separate from its app and IP bypasses is open [gap:zcc.ssl-inspection:agent-ssl-bypass].

**ZIA's part.** The service must be enabled to perform SSL inspection for Client Connector users on each relevant platform; the page refers to Configuring SSL/TLS Inspection Policy for more. [zcc.ssl-inspection:enable-per-platform] Location-specific SSL inspection settings are separate from the Client Connector SSL inspection settings. [zcc.ssl-inspection:location-separate] Client Connector's SSL inspection feature (installing the certificate so the service can inspect forwarded web traffic) applies to Internet Security only; the overview says Private Access does not support it. SSL inspection for mobile traffic must be enabled on the ZIA side. [zcc.ssl-inspection:private-access-none] On the Private Access side, AppProtection inspects HTTPS traffic inline: [AppProtection does inline inspection of application flows in real time for malicious content, including HTTPS traffic through real-time inspection of encrypted traffic.](kb:zpa.appprotection:inline-inspection). The policy itself is in [ZIA SSL/TLS inspection](kb:zia.ssl-inspection).

**Exemptions.** SSL exemptions configured in the Admin Console also apply to traffic Client Connector forwards. [zcc.ssl-inspection:exemptions-apply] URLs are exempted by putting them in a custom URL category and selecting that category in an SSL/TLS inspection rule whose action is Do Not Inspect. [zcc.ssl-inspection:exempt-how] Apple recommends bypassing specific iOS URLs from SSL inspection, and Google recommends bypassing specific URLs from SSL inspection; the page refers readers to the Apple Support page and to Chrome Enterprise and Education Help. [zcc.ssl-inspection:vendor-bypass-lists] What to exempt and what a bypass costs: [Writing SSL/TLS inspection exemptions without exempting too much](kb:zia.ssl-inspection.exemptions), [What stops working when traffic bypasses SSL/TLS inspection](kb:zia.ssl-inspection.bypass-impact). Pinned applications cannot be inspected at all: [Applications that pin a certificate reject any other certificate, so Zscaler cannot inspect them; the guide names Apple, many Microsoft 365 apps, Adobe, Cisco WebEx and the Dropbox app, and says pinning is common in iOS and Android apps. The remedies are to replace the application, bypass it only if it is valuable enough to justify the risk, or deny it.](kb:zia.ssl-inspection.uninspectable:cert-pinning).

**All three must line up.** SSL inspection works without disrupting a Client Connector user only when three things line up: the forwarding profile sends the traffic to ZIA, an SSL/TLS inspection rule for the device's platform inspects it, and the device, and the application, trusts the root the service signs with. [zcc.ssl-inspection:three-conditions]

## The browser shows the site's own certificate, or a certificate error

| ZIA log for the transaction | What the browser shows | Reading |
| --- | --- | --- |
| None | The site's own certificate | No ZIA log and the site's own certificate in the browser mean the traffic never reached ZIA, for example because the forwarding profile's action on that network was None or an app profile bypass such as a VPN gateway bypass sent it direct; no inspection can happen, and the certificate shown is correct. [zcc.ssl-inspection:diag-not-forwarded] |
| Present, not decrypted | The site's own certificate | A ZIA log without decrypted detail and the site's own certificate mean the transaction was not decrypted: a Do Not Inspect rule or exemption matched, or inspection is not enabled for that platform. [zcc.ssl-inspection:diag-do-not-inspect] |
| Present, decrypted | A Zscaler-issued certificate | Inspection working: [When inspecting, the Public Service Edge acts as a short-lived intermediate CA and issues a certificate on demand for each requested application, which the browser accepts because the Zscaler trust chain is in the device's certificate store.](kb:zia.ssl-inspection.certificates:per-request-certificates). |
| Present, decrypted | A certificate error | A decrypted ZIA log with a certificate error in the browser means the root is missing from the trust store the browser or application uses. [zcc.ssl-inspection:diag-untrusted-root] |

QUIC skips TCP and so skips inspection; Zscaler recommends blocking it: [Google's QUIC protocol skips the TCP handshake and uses UDP while Zscaler's inspection relies on TCP session information, so Zscaler recommends blocking QUIC; the browser or device then falls back to TCP connections. Both the Zscaler firewall and Client Connector can block it.](kb:zia.ssl-inspection.uninspectable:quic). Z-Tunnel 1.0 does not support QUIC, and an app profile option drops it so the application falls back to TCP: [On the iOS and Android profiles, Drop QUIC Traffic exists because Z-Tunnel 1.0 does not support QUIC (UDP 443): when enabled, Z-Tunnel 1.0 drops QUIC packets so the application can fall back to TCP 443. The API document describes `policyExtension.dropQuicTraffic` the same way.](kb:zcc.app-profiles.advanced-settings:drop-quic). One field report of a browser bypassing inspection on one tenant only is open [gap:zcc.ssl-inspection:webkit-no-logs].

What to check:
1. Whether ZIA logged the transaction at all; if not, the forwarding profile action and the app profile bypasses for the device's network, before any SSL setting.
2. Whether an SSL/TLS inspection rule for the device's platform inspects the destination, or a Do Not Inspect rule or custom exemption category matches it.
3. For certificate errors on decrypted traffic, whether the root is in the store the application uses.
