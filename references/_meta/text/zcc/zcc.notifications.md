# Client Connector notifications: which surface the user saw (zcc.notifications)
Also called: zcc notifications; client connector notifications; zcc end user notifications; zcc eun; block page vs zcc notification; zcc pop-up; zcc toast; zpa reauth notification; notify users before zpa authentication expires; per-app vpn tunnel notification; end-user notifications
Former IDs: zcc-28, zcc-29

Three different things reach a Client Connector user as a notification, and each is configured in a different place. The Client Connector notification settings cover the notifications users receive by default (in the system tray and in the Zscaler Notification Framework), the Acceptable Use Policy, a custom IT-support banner, a reminder for SecureAgent users, and notification templates, which are for Windows only. [zcc.notifications:notification-page]

1. **Client Connector's own notifications.** The tenant-wide switches are in [Tenant-wide Client Connector notification switches](kb:zcc.notifications.global-settings), per-profile templates in [Client Connector notification templates: per-profile notification settings](kb:zcc.notifications.templates), and the pop-up system itself in [The Zscaler Notification Framework: Client Connector's own pop-ups](kb:zcc.notifications.framework). The pop-up messages themselves are in [Client Connector pop-up messages: type, meaning, user action and duplicate suppression](kb:zcc.notifications.pop-ups).
2. **ZIA policy notifications delivered through the client.** ZIA can notify users of a policy action through Client Connector on the endpoint. This is supported for Inline Web DLP, Endpoint DLP, Cloud App Control, Firewall Filtering, DNS Control and IPS Control. [zcc.notifications:zia-eun-via-zcc] Each of those policies has a default message, custom messages can be tied to individual rules, and the notification shows only when it is enabled in the rule. An organization can have at most 64 custom messages across policies. [zcc.notifications:zia-eun-messages] URL Filtering is not among the policies that notify through Client Connector; a blocked URL category is reported by the browser-based block notification. [zcc.notifications:url-filtering-not-listed]
3. **Browser notifications.** Browser-based notifications (block, caution, AUP and quarantine) are provided by the Zscaler service, and their messages can be customized in multiple languages. Over HTTPS a block notification is shown only with SSL/TLS inspection; otherwise the user gets a 403 error in transparent mode or a Connection Refused error in explicit mode. [zcc.notifications:browser-eun] How inspection decides what the browser receives is in [Where SSL inspection sits in ZIA web policy evaluation (the two passes)](kb:zia.ssl-inspection.pipeline).

**App profile switches.** An app profile can warn users that their Private Access authentication is about to expire, as Notify Users before ZPA Authentication Expires on Windows and ZPA ReAuth Notification on Linux, iOS and Android; the Advanced Notification time sets how far ahead, from 5 to 1440 minutes. [zcc.notifications:zpa-expiry-warning] On iOS, Show per-app VPN Tunnel Notification tells the user that a per-app VPN tunnel is being established. [zcc.notifications:ios-per-app-vpn-notification] By name, the web policy contract carries the expiry warning as `policyExtension.advanceZpaReauth` (whether advance ZPA reauthentication is enabled) and `policyExtension.advanceZpaReauthTime` (the time before expiration at which Client Connector notifies the user), and the iOS tunnel notification as `iosPolicy.showVPNTunNotification`. [zcc.notifications:notification-wire-keys] How the Go SDK models the iOS keys is in [The Go SDK's model says its iOS UI capture carries `ipv6Mode`, `showVPNTunNotification`, `useTunnelSDK4_3` and related keys at the top level as well as inside `iosPolicy`, with `useTunnelSDK4_3` a JSON number at the top level and a quoted string inside `iosPolicy`. The Python SDK's iOS web policy payload fixture (`ios_policy.json`, one of the real payloads its serializer tests use) has none of `ipv6Mode`, `showVPNTunNotification`, `useTunnelSDK4_3` or `deviceType` at the top level.](kb:zcc.api.web-policy-wire:ios-top-level).

**Acceptable Use Policy.** The client's AUP is in [The Client Connector acceptable use policy prompt](kb:zcc.acceptable-use).

**Custom banner.** A custom banner on the top of the Client Connector app can show information about the organization's IT support resources, such as local help desk contact information or a link to submit an internal help desk ticket; the feature is available only on Client Connector 4.6 and later for Windows. It is configured on the Custom Banner Notification tab (Administration > End User Notification > Client Connector), which takes plain text, static HTML tags, images accessible from the internet and URLs, up to 200 alphanumeric characters, and offers a preview of the banner message. [zcc.notifications:custom-banner] Whether the banner is per app profile or tenant-wide, whether HTML tags count toward the 200 characters, and platforms other than Windows are not stated [gap:zcc.notifications:banner-scope].

**Language and branding.** Display language is in [Language of the Client Connector app, its notifications and the AUP](kb:zcc.notifications.localization). An app profile's Enable Custom Theme puts the company name and logos from the Client Connector Theme page in the app header and in pop-up notifications instead of the Zscaler logo. [zcc.notifications:custom-theme] The Client Connector Theme page (Infrastructure > Client Connector > Client Connector Theme) puts the company's logo and name in place of the Zscaler logo on the app header and in pop-up notifications; the page says the feature is available only on Client Connector 4.9 and later for Windows and that Zscaler Support enables it. [zcc.notifications:custom-theme-page] The organization name on the theme page is appended to the notification logo on pop-up notifications; without it, notifications display the default Zscaler branding even if a notification logo is uploaded. [zcc.notifications:theme-org-name] The Company Logo (top left of the app header) and the Notification Logo (top left of pop-up notifications) must each be a .PNG file that does not exceed 50KB; a logo can be uploaded in one or both fields. [zcc.notifications:theme-logos] Selecting Enable Custom Theme on an app profile shows the logos and company name in the app and in pop-up notifications for users with that profile; the custom theme does not display for end user notifications (EUNs) from Internet & SaaS, which are customized in the Admin Console. [zcc.notifications:theme-scope] Whether the theme exists for any operating system but Windows, and whether it differs between the Classic and Modern UI, is open [gap:zcc.notifications:theme-platforms].

**Open questions.** What the app window shows is in [The Client Connector app as users see it: Classic UI and Modern UI menus, status, enrollment and notifications, by OS where the pages cover it](kb:zcc.end-user); whether admins can change the in-app status text is not sourced [gap:zcc.notifications:in-app-status]. Whether a certificate trust failure produces a Client Connector notification is open for every platform except macOS, which has a pop-up for it [Other listed pop-ups include Service has been administratively disabled, Services are down because the network is disconnected, Failed to report issue, Issue reported, the App Updates messages (Failed to check for updates, ZDX updates or ZDP updates, to retry later; Latest available app is already running; New update is available, which auto-updates the app now), the Internet & SaaS Data Loss Protection notification, where Learn More opens a report of the violation and the message can be customized in the Admin Console, and, for macOS only, The SSL certificate could not be trusted automatically, asking the user to trust the certificate from the keychain.](kb:zcc.notifications.pop-ups:other-messages) [gap:zcc.notifications:cert-trust-ux]. Whether showing or dismissing a notification is logged anywhere is open [gap:zcc.notifications:delivery-logging]; whether AUP acceptances are logged is [Whether AUP acceptances are logged](kb:zcc.acceptable-use:acceptance-logging). Whether a blocked DLP transaction shows both a browser page and a client notification is open [gap:zcc.notifications:dlp-browser-and-client]; in default mode the DLP notification needs a Block action, and with Evaluate All Rules its type follows the rule's action [In default mode, a rule can enable an end user notification (EUN) triggered by the rule, with a default or custom message displayed to users, and EUN is supported only with Block actions and requires an Advanced DLP rule. The Evaluate All Rules article describes the same setting as a Show/Hide choice for an EUN message on endpoints, whose message type depends on the rule's action.](kb:zia.dlp.incident-forwarding:end-user-notification).

What to check:
1. Which surface the user saw: a Client Connector pop-up, a ZIA policy notification delivered through the client, or a page in the browser.
2. For a blocked HTTPS site that shows a 403 or Connection Refused error instead of a block page, whether SSL inspection applied to it.
3. For a URL Filtering block, look for the browser notification rather than a client pop-up.
