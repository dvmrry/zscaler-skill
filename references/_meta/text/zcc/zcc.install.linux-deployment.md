# Deploying Client Connector on Linux: run file, Debian and RPM packages, dependencies, zscaler-config and log locations (zcc.install.linux-deployment)
Also called: zcc linux install; zscaler-config; zscaler linux run file; zcc debian package; zcc rpm package; zscaler-installation.log

Client Connector for Linux can be installed manually with the application package, the Debian package or the Red Hat Package Manager (RPM) package, or through a device management method that supports Linux devices. Installation needs administrator permission, and the Debian package is obtained from Zscaler Support. [zcc.install.linux-deployment:packages]

**Linux prerequisites.** Client Connector for Linux relies on the systemd-resolved service to manage DNS, so /etc/resolv.conf, a symbolic link to /run/systemd/resolve/stub-resolv.conf, should not be modified when deploying it; it also requires NetworkManager and its CLI, nmcli. [zcc.install.linux-deployment:dns-and-networkmanager] As long as the device is connected to the network, the installer installs the necessary package dependencies automatically; if they do not install, they can be installed manually by entering all of them on one command line without line breaks. CentOS 9 Stream and RHEL 9 have an additional package, systemd-resolved, from the EPEL repository, which must be installed separately; for CentOS the EPEL repository must be enabled for Qt packages, and qt5-qtwebengine is also part of EPEL. [zcc.install.linux-deployment:dependencies] The Linux page's dependency section names Debian 11 and 12, Ubuntu 20, 22.04.5 LTS and 24 LTS, Fedora 41 and 42, CentOS 8 Stream, 9 Stream and 10, Rocky Linux 9.7 and 10.01, RHEL 8.x, 9.1 and 9.2, 9.3 to 9.5 and 10, Arch Linux and OpenSUSE Leap. [zcc.install.linux-deployment:distributions] Which dependency list belongs to which is open [gap:zcc.install.linux-deployment:dependency-lists].

**The run file.** The Linux run file is downloaded from the Client Connector App Store on the Client Connector Portal, made executable with chmod, and installed with sudo ./Zscaler-linux-<version number>-installer.run, leaving the token form empty. It takes the install options --cloudName, --deviceToken, --hideAppUIOnLaunch, --policyToken, --strictEnforcement, --userDomain and --enableFips. [zcc.install.linux-deployment:run-file] On Linux, --deviceToken applies only to Zscaler Internet Access (ZIA) and is not supported by Zscaler Private Access (ZPA); --hideAppUIOnLaunch, --strictEnforcement and --enableFips default to 0 (disabled). [zcc.install.linux-deployment:option-notes] The options are described for the other platforms in [Install parameters that identify the tenant and user at enrollment](kb:zcc.install.enrollment) and [Strict enforcement, the policy token, and the fail-close configuration](kb:zcc.install.strict-enforcement).

**The Debian package.** The Debian package is a silent installer that does not allow any arguments to pass next to it; installation parameters are configured in interactive or silent mode. The packages are named zscaler-client_<version number>_amd64.deb and zscaler-client-debug_<version number>_amd64.deb; Zscaler recommends installing systemd-coredump first, and a run-file installation must be uninstalled before the Debian package is installed. [zcc.install.linux-deployment:debian] The zscaler-config script edits the parameters in /opt/zscaler/.config.ini; only administrators can use it to edit the configuration after the Debian package is installed, and it requires root permission. It can be run without parameters (sudo zscaler-config), or with the flags -c Cloud Name, -d User Domain, -f Enable Fips, -h Help, -l hideAppUIOnLaunch, -p User password, -r externalRedirect, -s strictEnforcement, -t policyToken, -T deviceToken, -u username and -w waitForInput. [zcc.install.linux-deployment:zscaler-config] What several of its parameters do is open [gap:zcc.install.linux-deployment:config-parameters].

**The RPM package.** Client Connector for Linux supports the RPM distributions RHEL, Fedora, CentOS and openSUSE. Zscaler_package_installation.sh identifies the distribution and installs the corresponding dependencies, and Zscaler-client-<release version>-1.x86_64.rpm installs the Client Connector binaries. The CLI steps for Client Connector 3.7.1 and later for openSUSE use sudo zypper install zscaler-client-3.7.1.51-1.x86_64.rpm. [zcc.install.linux-deployment:rpm]

**Logs.** On Linux, tray logs are in <user home>/.Zscaler/Logs, Zscaler system logs in /var/log/zscaler/.Zscaler/Logs, and installer errors in /var/log/zscaler/zscaler-installation.log. [zcc.install.linux-deployment:logs] The collection paths are also in [Getting Client Connector logs to support: Report an Issue, Fetch Logs, packet captures](kb:zcc.logging.collection).
