# Deploying Client Connector on macOS: the package, the preference domain, updates and removal (zcc.install.macos-deployment)
Also called: zcc macos pkg; com.zscaler.installparams; installation-parameters plist; com.zscaler.tunnelparams; clearDnsCacheOnT2Start; zccToForegroundDuringAuth; jamf zcc deployment; intune zcc macos; zcc macos uninstall; Uninstaller.sh; zcc app store update macos; macos install customization; zcc macos deployment
Former IDs: zcc-16, zcc-17, zcc-18, zcc-21, zcc-22, zcc-23

On macOS, Client Connector is a pkg delivered by an MDM, with its install parameters pushed as a managed preference. The vendor's macOS customization article is an index: deploying Client Connector with a pkg and PLIST settings from an MDM varies by MDM, and the steps are in the Microsoft Intune and Jamf Pro deployment guides. [zcc.install.macos-deployment:guides]

**The package.** The pkg is downloaded from the Admin Console under Infrastructure > Client Connector > App Store (New Releases tab, macOS), then uploaded to the MDM: as a package assigned through a policy in Jamf Pro, or as a macOS app (PKG) in Intune. [zcc.install.macos-deployment:pkg-source] In the Workspace ONE UEM guide the .pkg is taken from the New Releases tab (macOS), and the Workspace ONE Admin Assistant creates .pkg, property list (PLIST) and image files for uploading; the guide clicks Cancel to not assign the app at that time, because other MDM payloads must first be deployed to the devices. [zcc.install.macos-deployment:workspace-one] Client Connector 4.5.2 and later support macOS Sonoma 14.0 and later. [zcc.install.macos-deployment:min-macos] In Intune's detection rules the guide sets Ignore app version to Yes, and says to correct the version by hand if Intune fills `com.zscaler.installer.uninstall` with the wrong one. [zcc.install.macos-deployment:intune-detection] To reinstall the same version through Jamf Pro for a device or user, flush all policy logs in the computer's history, or delete the device or user from Jamf Pro and reinstall through the client. [zcc.install.macos-deployment:jamf-reinstall]

**Install parameters.** Install parameters are pushed as a custom settings profile (Application & Custom Settings in Jamf Pro, the Preference file template in Intune) with the preference domain `com.zscaler.installparams`. [zcc.install.macos-deployment:preference-domain] In the vendor's sample property list the keys sit inside a dictionary under the key `installation-parameters`, and every value, numeric flags included, is a string (for example `strictEnforcement` as the string 0). [zcc.install.macos-deployment:plist-shape] The Workspace ONE custom settings profile uses PayloadType com.zscaler.installparams with the keys inside installation-parameters; in its sample hideAppUIOnLaunch is the string 0, externalRedirect the string false, launchTray the string 1 and enableFips the string 0. [zcc.install.macos-deployment:workspace-one-plist] The keys themselves are described in [Install parameters that identify the tenant and user at enrollment](kb:zcc.install.enrollment), [Strict enforcement, the policy token, and the fail-close configuration](kb:zcc.install.strict-enforcement) and [Silent install, upgrade, revert and uninstall parameters, and launch behavior](kb:zcc.install.windows-unattended).

**Tunnel parameters.** A second preference domain, `com.zscaler.tunnelparams`, takes a `tunnel-parameters` dictionary: clearDnsCacheOnT2Start clears the device's DNS caches when the tunnel restarts (Route-based Interception only, not Transparent Proxy-based), and zccToForegroundDuringAuth brings the Client Connector window to the foreground during WebView-based authentication. A logged-in user must restart the app or its service for them to apply. [zcc.install.macos-deployment:tunnel-params]

**Extensions, VPN payloads and privacy profiles.** [macOS system extensions, VPN payloads and privacy profiles for Client Connector](kb:zcc.install.macos-extensions). The SSL inspection certificate is a separate MDM profile: [The macOS deployment guides push the CA certificate needed for SSL inspection with a certificate configuration profile from the MDM (a Certificate payload in Jamf Pro with Allow all apps access, a Trusted certificate template in Intune), using the Zscaler root certificate downloaded from Internet Access > Resources > SSL Intermediate Certificate, or a custom root or intermediate.](kb:zcc.ssl-inspection.certificate-install:macos-mdm-profile).

**Updates.** The App Store the vendor's macOS guides refer to is the Client Connector App Store in the Admin Console (Infrastructure > Client Connector > App Store). App updates are configured there for Windows, macOS and Linux only, per user group, with a version to install per OS, rolled out to the selected groups at the same time or as a phased rollout that upgrades devices gradually; iOS and Android updates come from the App Store, Google Play or the MDM. After enrolling, the app checks for an update every two hours and installs one if available. [zcc.install.macos-deployment:app-store-updates] Such an update keeps the install parameters already on the device: [An app update configured in the Client Connector App Store keeps the installation parameters already set on the device, such as strictEnforcement or policyToken.](kb:zcc.install.precedence:update-retains). How an MDM-pushed package interacts with an App Store version policy is open [gap:zcc.install.macos-deployment:mdm-push-vs-app-store].

**Uninstall.** On macOS, Client Connector is uninstalled manually by running UninstallApplication from the Zscaler folder, or from a shell with `sudo sh /Applications/Zscaler/.Uninstaller.sh` followed by the uninstall password configured in the app profile. [zcc.install.macos-deployment:uninstall] If the system extension feature is activated using a command line, it must be deactivated manually. Uninstallation of Client Connector does not remove the system extension feature. [zcc.install.macos-deployment:system-extension-residue] What else an uninstall leaves behind is open [gap:zcc.install.macos-deployment:uninstall-residue].

**Open points.** Whether launchTray set to 0 also holds back the system extension and tunnel is open [gap:zcc.install.macos-deployment:launchtray-zero-extension]. Whether a given set of profiles and keys makes the install fully silent is open [gap:zcc.install.macos-deployment:silent-install-recipe]. Which package architectures are shipped for Apple silicon is open [gap:zcc.install.macos-deployment:apple-silicon-package]. Where installation and runtime logs are written is open [gap:zcc.install.macos-deployment:install-logging].

What to check:
1. Whether the MDM profile uses the preference domain com.zscaler.installparams with the keys nested under installation-parameters.
2. Whether the device runs a macOS release the Client Connector version supports.
3. Which version the device's user group is assigned in the Client Connector App Store, before pushing a package from the MDM.
