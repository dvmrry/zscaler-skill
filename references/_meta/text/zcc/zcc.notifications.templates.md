# Client Connector notification templates: per-profile notification settings (zcc.notifications.templates)
Also called: notification templates; notification template; legacy notification settings template; notificationTemplateId; notificationTemplateContract; delay posture failure notifications; posture failure notification; zia firewall dns ips notifications; do not disturb button; modern notification template; legacy notification template
Former IDs: zcc-24, zcc-25, zcc-27

Templates let different groups of users get different notification settings. A notification template holds Client Connector notification settings and is assigned to groups of users through the app profile. [zcc.notifications.templates:purpose] There are two types of template. A Modern template sets, for each selected platform, which individual notifications or groups of notifications display and for how long; users can only pause them with Do not Disturb. Modern templates need Client Connector 5.0 and later and are enabled by Zscaler Support. A Legacy template sets which notification types display, users can turn some notifications on or off, and it applies to versions earlier than 5.0. Templates became generally available in May 2026, and on Windows 4.8 to 4.10 additional templates can be created and assigned to Windows app profiles. [zcc.notifications.templates:availability] An Android app profile has a Notification Template option, available only for Client Connector 5.0 and later for Android; the same entry says users on 4.2 or earlier get the Legacy Notification Settings template whatever is selected. [zcc.notifications.templates:android-profiles] Existing settings from the End User Notifications tab were migrated to a Legacy Notification Settings template, whose name cannot be changed. [zcc.notifications.templates:replaces-tab]

**Assignment.** An app profile's template applies only to Client Connector 4.8 and later for Windows; users on 4.7 or earlier get the Legacy Notification Settings template whatever the profile selects. [zcc.notifications.templates:older-clients-legacy] In the API an application profile carries its template as `notificationTemplateId` and embeds the template's settings as `notificationTemplateContract`, whose integer `zpaReauthNotificationTime` the contract describes as whether the ZPA reauthentication notification at a specific time interval is enabled. [zcc.notifications.templates:app-profile-binding] Whether a template can still be marked as the default for new app profiles is open [gap:zcc.notifications.templates:default-template].

**Settings shared with the global tab.** A template carries the same switches as the global tab: pop-ups by default (users can turn them off in the More window), app updates, service status, ZIA notifications, ZPA reauthentication and its 2 to 1440 minute interval, the 5 to 60 second timer and persistent notifications. [zcc.notifications.templates:same-settings] In a template, ZIA Notification Persistent makes Endpoint DLP notifications persistent. [zcc.notifications.templates:zia-persistent-endpoint-dlp]

**Template-only settings.** Delay Posture Failure Notifications holds back device posture failure pop-ups for up to 300 seconds (default 0), so that a check that fails only while, for example, CrowdStrike is still starting does not alarm the user. It delays only the pop-up, not the message in the app's Notifications window. [zcc.notifications.templates:posture-delay] Whether that delay counts from tunnel establishment, as the setting's name says, or from a reboot, as its description says, is open [gap:zcc.notifications.templates:delay-trigger]. Do not Disturb adds a Do not Disturb button to Client Connector pop-ups. It is disabled by default, applies only to Windows and macOS, and needs the Zscaler Notification Framework. It is a Common Setting of the template; where Modern templates are not enabled on the tenant, it is set in the legacy settings. [zcc.notifications.templates:do-not-disturb] ZIA Firewall, DNS and IPS notifications can each be shown in the app's Notifications window and, separately, as pop-ups; all three also need Enable ZIA Notifications. [zcc.notifications.templates:zia-channels] Show Device Posture Failure Remediation Notification shows a pop-up when a Private Access app is blocked because a posture in the access policy failed and the access policy enables Device Posture Failure Notification; its Learn More link opens the posture profile's message in the app. [zcc.notifications.templates:posture-remediation]

**API and SDKs.** The Go SDK's template model nests ZIA settings (firewall, DNS and IPS, each with a pop-up flag, plus persistence) under `ziaNotificationTemplate` and ZPA settings (posture failure, reauthentication, its interval and the posture-failure delay) under `zpaNotificationTemplate`, beside top-level fields such as `isDefaultTemplate`, `durationInSeconds` and `enableDoNotDisturb`. [zcc.notifications.templates:go-model-fields] The model fields correspond by name to the console settings: `durationInSeconds` to Custom Timer, `enableDoNotDisturb` to Do not disturb, `delayPostureFailureSeconds` to the posture-failure delay, and `enableDevicePostureFailure` to a posture-failure notification switch. [zcc.notifications.templates:field-to-setting] The Python SDK has no notification-template service; its application-profile model only carries the assigned template's ID and contract. [zcc.notifications.templates:python-no-service]

What to check:
1. Which Client Connector version the device runs: 5.0 and later gets the template's Modern settings and earlier versions its Legacy settings, while the app profile page sends Windows 4.7 or earlier to the Legacy Notification Settings template whatever the profile names.
2. Which template the user's app profile assigns, by `notificationTemplateId`, before reading notification settings.
3. For a posture-failure pop-up that never appeared, the template's delay and the two-minute duplicate suppression.
