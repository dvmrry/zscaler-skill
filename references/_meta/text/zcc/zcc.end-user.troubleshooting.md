# What users get to troubleshoot: the Troubleshoot section, Report an Issue and Zscaler Diagnostics at the login screen (zcc.end-user.troubleshooting)
Also called: Troubleshoot section; Repair App; Revert App; Disable Tamper Protection; Report an Issue form; Zscaler Diagnostics; Tunnel Status window; Start Packet Capture; Run Zscaler Diagnostics

The Classic Troubleshoot section on Windows has Start Packet Capture (if the admin enabled packet captures); Report an Issue (if the admin enabled in-app support access); Export Logs, which exports logs to a ZIP file to email to the organization's support admin; Restart Service, which restarts the app; Repair App, where the app attempts to repair itself by reinstalling app drivers and services and which Zscaler recommends trying before reporting an issue; Revert App (if the admin enabled the revert option), which reverts to the previous version and might require a password; Disable Tamper Protection, which asks for the Disable Anti-Tampering OTP; Clear Logs; and Log Mode. [zcc.end-user.troubleshooting:windows-troubleshoot-section] The page says Export Logs writes a ZIP file, which other end-user pages and the logging controls word differently [zcc.end-user:export-logs-format](kb:zcc.end-user:export-logs-format).

**Restart Service.** The end-user pages and the support-options article disagree about whether restarting affects enforcement [divergence:zcc.end-user.troubleshooting:restart-enforcement]; the admin setting that shows the option is in [Restart Service and Repair App for end users](kb:zcc.support-options.restart-and-repair).

**Other operating systems.** On macOS the Classic Troubleshoot section has Start Packet Capture, Report an Issue, Restart Service, Clear Logs, Log Mode, Export Logs, Revert App and Run Zscaler Diagnostics, which provides a one-time snapshot of the system's network state by performing various diagnostic tests and can also be run with the CLI. On Linux it has Export Logs, Start Packet Capture, Restart Service, Clear Logs and Log Mode. On Android and on Android on ChromeOS Restart Service can be clicked only once within a 30-second period, and iOS names the log setting Log Level. [zcc.end-user.troubleshooting:other-os-sections]

**Modern UI.** The Modern UI Troubleshooting page on Windows has Restart Service, Repair App (the app attempts to repair itself by reinstalling app drivers and services), Start Packet Capture, Report an Issue, Revert App, Export Logs (to a ZIP file to email to the support admin), Log Mode, Advanced Settings (Zscaler Deception information if enabled for the user), Disable Tamper Protection (which asks for the Disable Anti-Tampering OTP) and Clear Logs, which removes the existing application logs. [zcc.end-user.troubleshooting:modern-troubleshooting]

**Where the logs are.** In the Classic UI Windows steps, to see where the logs are stored the user clicks Report an Issue and then Show/Hide logs. [zcc.end-user.troubleshooting:log-location] The mode a user picks lasts for one session: [A log mode a user changes in the Troubleshoot section is effective for that connection session only; at the start of the next connection session the app returns to the default log mode set by the organization. The Windows sections of the Classic UI and Modern UI pages both say this.](kb:zcc.logging.log-modes:session-only).

**Report an Issue.** In the Windows Report an Issue form, the field to the right of Name is prepopulated with the email addresses of the organization's designated support admins, multiple addresses are separated with commas, and the support admins are always copied even if the field is left blank. Problem is a category chosen from a drop-down menu, with Other selected by default, and Private Access is for problems with the Private Access service. Priority is a severity level, with Normal selected by default: Urgent means the app cannot be used at all, High that it can be partially used but critical functions are not working, and Low that it can be used but minor functions are not working. Logs are always attached automatically, and the user can also see where encrypted logs are stored on the device. [zcc.end-user.troubleshooting:report-form-fields] In the Android Report an Issue form the catch-all problem category is Others. On Android and on Android on ChromeOS comments cannot exceed 250 characters and an attached file should not exceed 1 MB; in the section that follows Android on ChromeOS, the Name takes alphabetic characters only and comments cannot exceed 1024 characters. [zcc.end-user.troubleshooting:report-form-mobile-limits] Whether the option appears is an admin setting: [The Report an Issue option appears in the app user interface only if the IT admin has enabled it in the Client Connector support configuration. On submitting the form, depending on the organization's setup, the app might send an email to the organization's support admin or submit a ticket directly to Zscaler Support, of which the support admin receives a copy, and the user receives an email acknowledging the support request.](kb:zcc.support-options:report-an-issue-visibility).

**At the login screen.** Zscaler Diagnostics gives the same information as the Troubleshooting article, except that users can reach it without being logged in to Client Connector on a Windows or macOS device. It is available with Client Connector 3.2 or later for Windows, where the Windows policy setting for ZPA Machine Authentication must be enabled so users can authenticate and start the machine tunnel. On Windows the user enters the IdP credentials for Username and Password, or, on a separate device such as a mobile phone, enters the link shown in a browser and then the passcode, or scans the QR code. [zcc.end-user.troubleshooting:zscaler-diagnostics] After successful authentication the Tunnel Status window shows current information about the machine tunnel, including the number of packets sent or received and whether the tunnel runs on a trusted network, and users can stop the machine tunnel with Turn Off. On Windows, Restart Service restarts the machine tunnel and Update Policy manually refreshes the machine tunnel policy, and Include Packet Captures includes packet capture files when using Report an Issue. On macOS the machine tunnel starts from the Zscaler icon in the bottom-left corner of the login screen, which is visible only when a device logs out or reboots and not when a user locks the screen. [zcc.end-user.troubleshooting:tunnel-status-window]

What to check:
1. Which UI and OS the user is on, since the Troubleshoot section differs between Classic and Modern and between platforms.
2. Before relying on a restart not affecting enforcement, the divergence with the article that says Restart Service fails open briefly.
3. For a user who cannot log in on Windows or macOS but needs the machine tunnel, whether ZPA Machine Authentication is enabled in the Windows policy.

Sources disagree (name both sides):
- The end-user troubleshooting pages say restarting Client Connector does not impact security enforcement, while the restart and repair support-options article says Restart Service or Repair App makes Client Connector fail open briefly. [divergence:zcc.end-user.troubleshooting:restart-enforcement]
  - zscaler-help: Classic UI, Windows: restarting does not impact security enforcement.
  - zscaler-help: Classic UI, macOS: restarting does not impact security enforcement.
  - zscaler-help: Classic UI, Linux: restarting does not impact security enforcement.
  - zscaler-help: Modern UI, Windows: restarting does not impact security enforcement.
  - zscaler-help: Zscaler Diagnostics at the Windows login screen: restarting the machine tunnel does not impact security enforcement.
  - zscaler-help: Using Restart Service or Repair App causes Client Connector to fail open briefly (existing claim zcc.support-options.restart-and-repair:brief-fail-open).
  Impact: Whether a user's restart opens a brief unfiltered window depends on which statement holds; the pages do not reconcile enforcement not being impacted with failing open.
