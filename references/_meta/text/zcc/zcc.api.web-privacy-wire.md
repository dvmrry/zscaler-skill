# ZCC web privacy (User Privacy) calls: string flags, fields the contract lacks, and key casing (zcc.api.web-privacy-wire)
Also called: getWebPrivacyInfo; setWebPrivacyInfo; web privacy 1 0 strings; enableFQDNMatchForVpnBypasses; enableFqdnMatchForVpnBypasses; enforceSecurePacUrls; enableAutoLogSnippet; get_web_privacy; set_web_privacy_info; GetWebPrivacyInfo; UpdateWebPrivacyInfo; web privacy booleans are strings; zcc_web_privacy

Web privacy is one tenant-wide settings object, read with `getWebPrivacyInfo` and written with `setWebPrivacyInfo`. Web privacy is a single settings record, not a list: the API document's GET takes no parameters and returns an object, the Go SDK returns a single struct, and the Terraform provider documents it as a singleton. [zcc.api.web-privacy-wire:single-object] What the individual settings do is in [What each User Privacy setting collects or allows](kb:zcc.web-privacy.collection).

**Values.** The contract and the Go SDK type every web privacy field as a string, the on/off settings included. [zcc.api.web-privacy-wire:string-flags] The Terraform provider writes each web privacy toggle that the plan sets as "1" or "0" and reads each back as true only when the value is "1", except `enforceSecurePacUrls` and `enableFQDNMatchForVpnBypasses`, whose read-back keeps the prior plan or state value when one is set; the Python docstring example passes the same strings. [zcc.api.web-privacy-wire:provider-sends-01]

**Fields beyond the contract.** The Go web privacy type also carries `enableAutoLogSnippet`, `enforceSecurePacUrls` and `enableFQDNMatchForVpnBypasses`, none of which the contract's get or set schema lists. [zcc.api.web-privacy-wire:contract-lacks-three] The Python `WebPrivacy` model reads none of the three, so `set_web_privacy_info`, which returns that model, drops them from its result even when the caller sent them. [zcc.api.web-privacy-wire:python-model-lacks-three] The Python read returns a dictionary rather than the model: [On success `get_web_privacy` returns the camel-cased response dictionary itself, not a `WebPrivacy` model or a tuple, so it carries any non-null key the API sends, including ones the model lacks.](kb:zcc.sdk-python.return-shapes:web-privacy-get-dict). The Go SDK sends the FQDN-match-for-VPN-bypasses setting as `enableFQDNMatchForVpnBypasses`, but a Python caller who passes the snake_case keyword `enable_fqdn_match_for_vpn_bypasses` sends `enableFqdnMatchForVpnBypasses`, because the Python converter camel-cases word by word and has no exception for this key. A Python caller can pass the Go spelling as the keyword instead, since a key without an underscore is sent as given; the contract omits the field, so which spelling the API reads is not shown. [zcc.api.web-privacy-wire:fqdn-key-casing]

**Writes.** The Go `UpdateWebPrivacyInfo` sends the PUT without reading its response and then returns a fresh GET of the settings. [zcc.api.web-privacy-wire:go-update-rereads] The Python write sends any keyword it is given: [Python's `set_web_privacy_info` sends whatever keyword arguments it is given, camel-cased by the executor's selective ZCC conversion, so keys outside its model can be written, but it returns a model object that holds only the modeled settings.](kb:zcc.sdk-python.return-shapes:python-set-kwargs). How the provider fills two of these fields from state, and why its data source reports them false, is in [The same pattern, a field the provider believes the API drops being filled from prior state instead of the response, appears in more places: `evaluate_trusted_network` and `is_same_as_on_trusted_network` on forwarding profiles, and `enforce_secure_pac_urls` and `enable_fqdn_match_for_vpn_bypasses` on web privacy. While the belief holds this avoids spurious diffs; if the API starts returning the field, or the belief is wrong, drift on it is never shown. In the web privacy resource the fields are sent; only their read-back is replaced.](kb:zcc.terraform.field-fidelity:prior-state-overlays-elsewhere) and [The forwarding-profile and web-privacy data sources map the raw response with no fallback, while the matching resources say the response does not carry `evaluateTrustedNetwork`, `enforce_secure_pac_urls` and `enable_fqdn_match_for_vpn_bypasses`. A missing key decodes as zero or empty, so the data source reports false for those fields even when the profile or setting is true.](kb:zcc.terraform.field-fidelity:data-sources-report-false-for-dropped-fields).

What to check:
1. Whether a hand-built body sent the toggles as the strings "1" and "0" rather than JSON booleans.
2. Whether a Python write of the FQDN match setting used the snake_case keyword, which goes out under a different casing from the Go SDK's key.
3. When a setting reads back off, check whether the key is one the contract omits and the client fills from elsewhere.
