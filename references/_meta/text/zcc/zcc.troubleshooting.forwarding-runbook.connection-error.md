# Runbook: Connection Error and Server Down Error, getSmeProxyState values and Tunnel 2.0 logs (zcc.troubleshooting.forwarding-runbook.connection-error)
Also called: Connection Error; Server Down Error; getSmeProxyState

**Meaning and identification.** Client Connector shows a connection error when it fails to connect to Internet & SaaS or Private Access services because Zscaler data centers are unreachable; symptoms are the Internet Security window showing Connection Error or the logs showing Server Down Error, with intermittent or no internet access. [zcc.troubleshooting.forwarding-runbook.connection-error:meaning] The Connection Error identification says to review Client Connector logs for PAC file parsing and connection attempts to gateway.<cloudname>.net, searching the keywords getSmeProxyState and Tunnel Forwarding Status. [zcc.troubleshooting.forwarding-runbook.connection-error:log-keywords]

**Tunnel 1.0 logs.** For Tunnel 1.0 the runbook shows a ZSATunnel log where the app parses the PAC file and lists the primary and secondary data centers; in its sample the saved proxy string is PROXY 165.225.120.17:80; PROXY 165.225.122.17:80; DIRECT. [zcc.troubleshooting.forwarding-runbook.connection-error:tunnel-1-pac-parse] For Tunnel 1.0 the app monitors the primary proxy IP every 30 seconds; if keepalives fail with all data centers returned from the PAC file it goes into the connection error state, which can be followed by searching getSmeProxyState in ZSATunnel logs. [zcc.troubleshooting.forwarding-runbook.connection-error:tunnel-1-keepalive] In the Tunnel 1.0 section, searching getSmeProxyState in ZSATunnel logs shows the connection state over time; the four statuses listed are TUNNEL_FORWARDING, CONNECTING, SERVER_DOWN_ERROR and LOCAL_PROXY_FORWARDING; the runbook's Endpoint Firewall or Antivirus Error section has ZApp Status log lines that also show getSmeProxyState:FIREWALL_BLOCK_ERROR. [zcc.troubleshooting.forwarding-runbook.connection-error:proxy-state-values] What each status means is open [gap:zcc.troubleshooting.forwarding-runbook.connection-error:state-values-undefined].

**Tunnel 2.0 logs.** Z-Tunnel uses DTLS or TLS to send packets to the Zscaler service; Tunnel 2.0 uses a control channel that is always TLS and a data channel whose protocol follows the Tunnel 2.0 mode set by Primary Transport Selection in the forwarding profile. [zcc.troubleshooting.forwarding-runbook.connection-error:tunnel-2-channels] A Tunnel 2.0 ZSATunnel status line carries getSmeProxyState and a T2State block with Tx, Rx, IP, SME, Protocol and Status; one sample's Status holds ZSCCM:TUNNEL_FORWARDING and ZSDDC:CONNECTING. [zcc.troubleshooting.forwarding-runbook.connection-error:tunnel-2-state-log] A Tunnel 2.0 fallback to Tunnel 1.0 is shown in the sample log by a connect timeout to 147.161.179.24:443 and the line 'SME List is empty. Fallback to ZTunnel 1.0'. [zcc.troubleshooting.forwarding-runbook.connection-error:tunnel-2-fallback-log] If a device intercepts SSL connections, the sample Tunnel 2.0 log shows ZST2M::ZT2A::initialize: Data Channel establishment Failed. and Auth::Lib::certificateErroCallback: Invalid certificate. [zcc.troubleshooting.forwarding-runbook.connection-error:ssl-interception-log]

**Causes and resolution.** Possible causes listed are a network firewall or endpoint device blocking Zscaler IP ranges or specific ports, SSL interception or a network proxy interfering with Zscaler communication, and incorrect PAC file configuration. [zcc.troubleshooting.forwarding-runbook.connection-error:causes] For Z-Tunnel 2.0 the runbook says to make sure UDP traffic is not restricted because Z-Tunnel 2.0 uses UDP for DTLS communication, and to switch the tunnel protocol to TLS and test. [zcc.troubleshooting.forwarding-runbook.connection-error:udp-and-tls] Firewall or SSL interception devices should bypass Zscaler IP ranges, and traffic to gateway.<cloud_name>.net should be allowed on standard ports 80 and 443; the example PAC URL is http://pac.<cloud_name>.net/<cloud_name>.net/proxy.pac. [zcc.troubleshooting.forwarding-runbook.connection-error:bypass-inspection]
