# What the less common app profile settings do (zcc.app-profiles.advanced-settings)
Also called: drop quic traffic; dropQuicTraffic; truncate large udp dns response; clear kerberos dc; purgeKerberosPreferredDCCache; anti-tampering zcc; tunnel internal client connector traffic; tunnelZappTraffic; reactivate zia after; reauth_period; on-net policy; onNetPolicy; policyExtension; send disable service reason; v8 pac parser

Most settings in `policyExtension` have their own description in the API document. These are the ones whose effect is worth knowing before changing them.

**QUIC and DNS.** On the iOS and Android profiles, Drop QUIC Traffic exists because Z-Tunnel 1.0 does not support QUIC (UDP 443): when enabled, Z-Tunnel 1.0 drops QUIC packets so the application can fall back to TCP 443. The API document describes `policyExtension.dropQuicTraffic` the same way. [zcc.app-profiles.advanced-settings:drop-quic] Truncate ZPA Large UDP DNS Response truncates DNS responses over 512 bytes so the query is retried over TCP. [zcc.app-profiles.advanced-settings:truncate-dns]

**Kerberos.** Clear Kerberos DC (`purgeKerberosPreferredDCCache`) clears the cached list of Kerberos preferred domain controllers when the app connects to and disconnects from Private Access; Windows 4.5 and later only. [zcc.app-profiles.advanced-settings:clear-kerberos-dc]

**Keeping the app on.** In the Windows app profile, anti-tampering prevents end users from stopping and modifying Zscaler endpoint products. If a user disables it with a one-time password, Reactivate Anti-Tampering After (In Mins), 1 to 1440 minutes, re-enables it after that time; the default 0 leaves it to the user to re-enable, or to Client Connector when the app exits and relaunches. The page marks these settings as applying to Client Connector 4.1 and later for Windows. On Windows 4.5 and later, Override Anti-tampering Install Parameter applies the profile's setting regardless of the install-time option. [zcc.app-profiles.advanced-settings:anti-tampering] The Anti-Tampering article says anti-tampering prevents non-admin end users from stopping, modifying and deleting Zscaler products, services, files, and Windows registry keys, and that admins enable or disable it in app profiles. [zcc.app-profiles.advanced-settings:anti-tampering-scope] Anti-tampering is supported only on Windows and macOS desktop operating systems, not on Windows Server. It does not run in safe mode by design, and Zscaler recommends disabling safe mode for all end users and allowing safe mode access only to the administrator. [zcc.app-profiles.advanced-settings:anti-tampering-platforms] The anti-tampering framework is part of the ZEP module, installed by ZEPInstaller.exe, which is 32-bit on a 32-bit OS and 64-bit on a 64-bit OS, is embedded as a resource in the Client Connector installer, and is unpacked to /programfiles/zscaler on the local drive. [zcc.app-profiles.advanced-settings:anti-tampering-zep] Reactivate ZIA After turns Internet & SaaS back on 1 to 1440 minutes after a user turns it off; 0 disables reactivation. [zcc.app-profiles.advanced-settings:reactivate-zia] Send Disable Service Reason, off by default, lets users describe why they disabled a service; the reason shows in device details, and the API exports disable reasons as a CSV report. [zcc.app-profiles.advanced-settings:send-disable-reason] A fail-close option makes the app fail close while a tunnel is starting or restarting, for example after login, Repair App or Restart Service. [zcc.app-profiles.advanced-settings:fail-close-lockdown] Two more fail-close options apply to Windows 4.7 and later: Lockdown on Firewall Error fails close while a firewall or antivirus program blocks the app's traffic (an End FW/AV Error), and Lockdown on Driver Error fails close while a Windows Lightweight Filter (LWF) driver error keeps the app from starting a tunnel. [zcc.app-profiles.advanced-settings:lockdown-on-errors] By name, these two options are `policyExtension.zccFailCloseSettingsLockdownOnFirewallError` and `zccFailCloseSettingsLockdownOnDriverError`, which the Go SDK carries and the API document's edit body does not. [zcc.app-profiles.advanced-settings:lockdown-error-keys]

**Traffic handling.** Tunnel Internal Client Connector Traffic (`tunnelZappTraffic`) sends the app's own traffic, such as app and policy updates, through Zscaler; it applies only in no-default-route deployments (Windows 2.12 and later), PAC requests still go direct, and when disabled internal traffic goes direct. The Go SDK's UI-captured macOS and iOS defaults set it to 0. [zcc.app-profiles.advanced-settings:tunnel-internal-traffic] Its default on Windows is open [gap:zcc.app-profiles.advanced-settings:tunnel-internal-default]. Intercept ZIA traffic makes the app intercept Internet & SaaS traffic from all network adapters; it applies only to Tunnel mode with the Packet Filter Based driver. [zcc.app-profiles.advanced-settings:intercept-all-adapters] The V8 JavaScript based PAC parser option compiles PAC JavaScript with Google's V8 engine; Windows 4.9 and later use it regardless of the setting. [zcc.app-profiles.advanced-settings:v8-pac]

**DNS handling.** The API document describes four DNS keys in `policyExtension`: `useDefaultAdapterForDNS` binds the trusted-hostname DNS lookup to the adapter whose trust is being evaluated, `disableDNSRouteExclusion` concerns excluding DNS servers from the routing table, `prioritizeDnsExclusions` puts Domain Exclusions ahead of Domain Inclusions, and `enforceSplitDNS` makes the app handle DNS traffic for the desired (ZPA) domains only. [zcc.app-profiles.advanced-settings:dns-settings]

**Reauthentication.** The Python SDK documents `reauth_period` as the re-authentication period in hours. [zcc.app-profiles.advanced-settings:reauth-period-hours] The API document says seconds instead: [zcc.api.web-policy-wire:reauth-period-unit](kb:zcc.api.web-policy-wire:reauth-period-unit). Force ZPA authentication to expire can trigger Private Access expiry on system sleep or hibernation, system restart, a network IP change, a Windows logon session start (Windows 4.5 and later) and a Windows session lock held for 1 to 60 minutes (Windows 4.6 and later). The API document carries these as `policyExtension.zpaAuthExp*` keys; it describes `zpaAuthExpSessionLockStateMinTimeInSecond` in minutes although the key name says seconds. [zcc.app-profiles.advanced-settings:zpa-auth-expiry]

**Display.** Highlight Active Control (`highlightActiveControl`) displays an outline around an actively selected control in the app; Windows 2.1.2 and later. [zcc.app-profiles.advanced-settings:highlight-active-control]

**Location-based policies.** With Location Policy Override (Windows 4.8 and later, with the WFP driver installed), a profile assigns a location ruleset per network type: On-Trusted and Off-Trusted are required, VPN-Trusted and Split VPN-Trusted default to the On-Trusted ruleset. The Go SDK always sends both VPN entries, with id 0 when none is bound. [zcc.app-profiles.advanced-settings:location-rulesets] The Go SDK models `endToEndDiagnostics` as a toggle per network context (trusted, VPN-trusted, off-trusted, split-VPN-trusted) that the macOS web policy carries at the top level and also embeds as JSON in `policyExtension.zdxLiteConfigObj`. [zcc.app-profiles.advanced-settings:end-to-end-diagnostics]

**On-Net policy.** `onNetPolicy` is not a separate On-Net policy: the API document describes it as the policies that define how the app treats traffic in the ZIA and ZPA services, with the forwarding profile's properties. The application-profile PATCH body carries it and the web policy edit body does not; Python's web policy model reads its trusted-network fields (`conditionType`, `predefinedTrustedNetworks`, `predefinedTnAll`) and Go's application-profile model carries it untyped, while Go's web policy struct has no such key. [zcc.app-profiles.advanced-settings:on-net-policy-sdk] It is the profile's forwarding profile, embedded: [In the API contract's application-profile listing, each policy embeds a forwarding profile object as `onNetPolicy`, with the trusted network criteria and both action lists.](kb:zcc.api.web-policy-wire:onnetpolicy-embedded).

**Data Protection.** `enableZdpService` turns on the Zscaler Data Protection (ZDP) service, which installs the ZDP endpoint. [zcc.app-profiles.advanced-settings:zdp-service]

**Android cellular settings.** Android profiles carry cellular data quota settings: a quota, optionally enforced only while roaming, reset on a chosen monthly billing day, and a Wi-Fi SSID for testing and simulating data usage. Zscaler has ended support of bandwidth quota control for Client Connector 1.5.3 and later for Android. The quota page says the quota affects cellular data only, not Wi-Fi, and that business applications must be allowlisted to be exempt from it. [zcc.app-profiles.advanced-settings:android-quota] Bypass Traffic for MMS Applications makes the app bypass standard Android messaging apps, including Android Messages. [zcc.app-profiles.advanced-settings:android-mms] The traffic bypasses article says Zscaler recommends bypassing Android application traffic. Enabling Bypass Traffic for MMS Applications ensures Android does not interfere with MMS, which also uses mobile data. An app's identifier is found after the ID parameter in the URL of its Play Store details, and for custom applications not in the Play Store the package name is added instead; if the package name is not known, PAC file-based exclusion can bypass specific hostnames and IP addresses, with the PAC URL added to the Custom PAC URL field while adding an Android app profile. [zcc.app-profiles.advanced-settings:android-bypass] By name, three keys in the API document's `androidPolicy` block match help settings: `allowedApps` the Android Applications on Allowlist (app identifiers excluded from the quota calculation), `bypassAndroidApps` Bypass Traffic for Specific Application (an app identifier to bypass), and `customText` the Block Notification Message shown when the quota is exceeded. [zcc.app-profiles.advanced-settings:android-key-candidates] What `enforced` does, and whether those name matches hold, is open [gap:zcc.app-profiles.advanced-settings:android-field-roles].

What `enableFlowBasedTunnel` does is open [gap:zcc.app-profiles.advanced-settings:unverified-field-roles].
