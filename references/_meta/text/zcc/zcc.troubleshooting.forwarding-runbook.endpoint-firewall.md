# Runbook: Endpoint FW/AV Error and FIREWALL_BLOCK_ERROR, 100.64.0.0/24 health checks and the Windows firewall rule (zcc.troubleshooting.forwarding-runbook.endpoint-firewall)
Also called: Endpoint FW/AV Error; FIREWALL_BLOCK_ERROR

**Symptoms.** Listed symptoms of endpoint firewall or antivirus interference are Endpoint FW/AV Error or FIREWALL_BLOCK_ERROR in the Internet Security window, log lines Firewall detected retries expired or [WFP]: Bad health, and connectivity issues or dropped packets related to the reserved Zscaler range 100.64.0.0/24. [zcc.troubleshooting.forwarding-runbook.endpoint-firewall:symptoms] Some ISPs tend to throttle DTLS traffic, which leads to SERVER_DOWN_ERROR and FIREWALL_BLOCK_ERROR in the ZSATunnel logs; the runbook advises switching to TLS in such cases. [zcc.troubleshooting.forwarding-runbook.endpoint-firewall:dtls-throttle] The packet capture file CaptureLWF<timestamp>.pcap can confirm whether communication is failing. [zcc.troubleshooting.forwarding-runbook.endpoint-firewall:capture-file]

**Process and transport checks.** The runbook says ZSATunnel.exe, ZSATray.exe, ZSAService.exe and ZDPService.exe must be excluded from firewall and antivirus scanning and policy restrictions. [zcc.troubleshooting.forwarding-runbook.endpoint-firewall:allowlist-processes] The runbook says to test the TLS transport by creating a profile that uses Z-Tunnel 2.0 with TLS transport. [zcc.troubleshooting.forwarding-runbook.endpoint-firewall:tls-profile]

**Health check route.** Client Connector health check traffic must be excluded from any third-party VPN IP range so the 100.64.0.0 range routes via the physical interface; in PowerShell, Find-NetRoute -RemoteIPAddress 100.64.0.6 should show Wi-Fi or ethernet (InterfaceAlias) and not the VPN adapter, and specific routing rules should exclude 100.64.0.0/24 from VPN adapters. [zcc.troubleshooting.forwarding-runbook.endpoint-firewall:health-check-route]

**Windows firewall.** By default Client Connector adds a firewall rule for ZSATunnel.exe allowing all ports and protocols on the domain, private and public profiles; the Zscaler App Rule should exist and be enabled for all profiles. [zcc.troubleshooting.forwarding-runbook.endpoint-firewall:os-firewall-rule] In Windows firewall an ANY block rule that would catch Client Connector traffic takes precedence even if less specific than the Client Connector rule; Zscaler recommends removing or disabling any rule blocking inbound connectivity to local port 9000 or port 80. [zcc.troubleshooting.forwarding-runbook.endpoint-firewall:block-rule-precedence] The firewall rule can be validated from the Client Connector log AppInfo.xml or with the CLI command netsh advfirewall firewall show rule name = "Zscaler App Rule". [zcc.troubleshooting.forwarding-runbook.endpoint-firewall:rule-validation] The runbook says to temporarily disable third-party VPN clients such as Cisco AnyConnect and endpoint security tools to find conflicts, and, if persistent after upgrading Client Connector to the latest version, to uninstall and reinstall Client Connector. [zcc.troubleshooting.forwarding-runbook.endpoint-firewall:third-party-and-reinstall]
