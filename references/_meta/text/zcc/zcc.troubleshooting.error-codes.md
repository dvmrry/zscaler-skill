# Client Connector error codes: cloud authentication, cloud, Admin Console and Report an Issue (zcc.troubleshooting.error-codes)
Also called: zcc error codes; client connector error code; cloud authentication error codes; Zscaler Admin Console error codes; report an issue error codes; internal error contact administrator

The in-use error codes come in four tables: Cloud Authentication Error Codes, Cloud Error Codes, Zscaler Admin Console Error Codes and Report an Issue Error Codes. [zcc.troubleshooting.error-codes:tables] What the page leaves undefined is listed at the end [gap:zcc.troubleshooting.error-codes:code-coverage].

**Cloud authentication codes, negative numbers.** -1 (Failed to Initialize Authentication: PAC Download Failed) occurs when the device fails to download the PAC file, which stops Client Connector from authenticating the user; it is likely the device could not connect to the cloud when downloading it. -2 (Invalid Custom PAC File) occurs when the device downloads an invalid PAC file, for example one with an incorrect format; check the syntax of the arguments within the PAC file. [zcc.troubleshooting.error-codes:pac-init] -3 (VPN Detected) occurs if Client Connector detects an active VPN on the device; check the forwarding profile configuration. -4 (Authentication Disabled) occurs if the organization has not configured an authentication source. -5 (Failed to Identify Authentication Service) occurs if Client Connector cannot determine the configured authentication type, for example differentiating between a Hosted Database user and an Active Directory user. For -4 and -5, check the Authentication Profile configuration. [zcc.troubleshooting.error-codes:auth-init] -6 (Login Failed) and -11 (Credentials are not Valid) occur when the user enters incorrect credentials. -7 (Network Connection not Available) occurs when Client Connector cannot find an active network on the device. -8 (Network Connection Failed) occurs when Client Connector is unable to connect to the cloud; go to config.zscaler.com/<Zscaler Cloud Name> to check the connection and to config.zscaler.com/<Zscaler Cloud Name>/zscaler-app to verify the device can connect to the listed IP addresses. -13 (DNS Resolution failed) occurs due to an issue with the hostname conversion to IP address; verify the DNS server and use packet capture for further analysis. [zcc.troubleshooting.error-codes:credentials-and-network] -9, -10 and -14 (Internal Error: Contact Administrator) are generic errors; the action is to export logs and contact Zscaler Support. [zcc.troubleshooting.error-codes:auth-generic]

**Cloud codes, 1 to 28.** Cloud error codes 1, 19 and 23 are generic errors and 7, 9, 10, 11, 14, 15, 24 and 25 are triggered by the cloud servers; all show "Zscaler Client Connector Internal Error, Please Contact Administrator." and the action is to export logs and contact Zscaler Support. [zcc.troubleshooting.error-codes:cloud-generic] 2 (Zscaler Internet Security Authentication Error) occurs when the user's cookie is expired or no longer valid. 8 occurs when the device does not send a cookie to the server. 27 occurs when a device sends an invalid authentication token, and 28 when it does not send one. For 2, 27 and 28 the action is to have the user reauthenticate to Client Connector, and if the issue persists export logs and contact Zscaler Support; for 8, export logs and contact Zscaler Support. [zcc.troubleshooting.error-codes:cookie-and-token] 3 (Enrollment Version Error) occurs when the device runs a version not supported by the cloud; upgrade to the latest version of Client Connector. 4 (Bad Timestamp Error) occurs when there is a time mismatch between the device and the server; check the system time. 5 occurs when the device does not send its version to the cloud, and 6 when it does not send a timestamp to the server; for both, export logs and contact Zscaler Support. [zcc.troubleshooting.error-codes:version-and-time] 12 occurs when the Internet & SaaS service is disabled for the organization, or the organization has not subscribed to a Client Connector license. 20 (License not Subscribed) occurs when a device tries to connect to the cloud using an organization that does not exist. 22 occurs when the organization is not licensed or the status of its account is Agreement Pending. 1000 and 1001 occur when the organization is not licensed or does not exist. For all, export logs and contact Zscaler Support. [zcc.troubleshooting.error-codes:license-and-org] 13 occurs when a device with an invalid device type connects to the cloud; 16, 17, 18 and 26 occur when the server is provided invalid device information. For all, export logs and contact Zscaler Support. [zcc.troubleshooting.error-codes:device-info] 21 (User has exceeded number of devices limit) occurs when the user tries to enroll more than 16 devices under one username; the action is to remove devices for that user from the Admin Console. [zcc.troubleshooting.error-codes:device-limit] Whether the device-limit code agrees with the device record is in [Enrolled device states and what moves a device between them](kb:zcc.devices.lifecycle).

**Cloud codes, 1000 and above.** 1002 and 1019 (Credentials are not Valid) occur when the user enters incorrect credentials. 1012 (Failed to Authenticate, Please try again) occurs when user information cannot be found. 1006 occurs when the cloud is unable to process the credentials provided. 1003 and 1004 are generic errors and 1007 is triggered by the cloud servers. [zcc.troubleshooting.error-codes:cloud-credentials] 1005 (IdP Authentication Failed) occurs when the cloud receives an invalid SAML response; verify the SAML configuration and check the SAML process end-to-end. [zcc.troubleshooting.error-codes:saml-1005] LDAP Authentication Failed codes: 1008 occurs when the Zscaler Authentication Bridge (ZAB) is not connected; 1009 is an internal error; 1013 occurs when the user is not found or has been deleted; 1014 when LDAP services are down for the organization; 1015 when the Central Authority (CA) is not ready to authenticate; 1016, 1017 and 1018 when the cloud fails to communicate with LDAP. For these, verify the LDAP configuration and ensure network connectivity. 1010 and 1011 occur when the cloud is unable to process the credentials provided by the user; verify the LDAP configuration and that the credentials entered are valid. [zcc.troubleshooting.error-codes:ldap] 1060 occurs when a required Client Connector driver or service is missing or failed to install after a partial install or upgrade; repair or reinstall Client Connector to restore the driver. [zcc.troubleshooting.error-codes:driver-1060] 10060 occurs when Client Connector fails to connect to the network; check network connectivity. 10101 (Failed to Discover Service for Given User) occurs when it fails to fetch user cloud information; verify the user's credentials, that the user exists in the user authentication source, and that the company name is provisioned correctly. 10104 (Service Configuration not Found) occurs when it fails to fetch the policy; export logs and contact Zscaler Support. 10108 (Failed to Enroll Device) occurs when device registration fails, either from an inability to reach the server or an error response from it, and applies to Internet & SaaS and Private Access; check network connectivity and whether there is a trust post for the cloud status. 10110 occurs when the user enters a username that cannot be found. 10111 occurs due to an issue in the processing of a request; retry the failed operation. 10112 is a generic error. [zcc.troubleshooting.error-codes:discovery-and-enrollment]

**Admin Console codes, 3005 to 3026.** Admin Console codes: 3005 occurs when the device sends an invalid request (ensure Client Connector is current and traffic is not modified between the device and the server). 3006 occurs when the user enters a password that does not match the username; 3007 when the user enters a username that cannot be found; 3008 when the user attempts to log out and the app has no record of a logged in user; 3009 when the user's password has expired (reset it and check the Authentication Profile's password expiration setting); 3010 when the user changes the password and enters the old password incorrectly; 3015 when the entered new password does not meet the password strength requirements (check the Authentication Profile's password strength settings). [zcc.troubleshooting.error-codes:console-request-and-password] 3011 (User not Subscribed to Service) occurs when the device attempts to connect to the cloud and the organization is not licensed. 3014 (Service Subscription has Expired) occurs when the organization's license has expired. 3018 (Already Subscribed to Zscaler service) is triggered on the cloud when attempting to create a new domain that already exists. [zcc.troubleshooting.error-codes:console-license] 3012 occurs when the device connects to the cloud and sends an invalid device identifier that does not match any enrolled device. 3013 (Device is not Registered) occurs if the user connects from a device that is not available in the Admin Console. For both, have the user reauthenticate to Client Connector. [zcc.troubleshooting.error-codes:console-device-identity] 3016 (PAC URL is not Valid) and 3020 (Invalid PAC File URL) occur when an invalid PAC file URL is specified in the forwarding profile; verify the URL is correct and resolves to a PAC file. 3017 (PAC File is not Valid) and 3021 (Invalid PAC File Content) occur when an invalid PAC file is specified in the forwarding profile; check the syntax of the arguments within the PAC file. [zcc.troubleshooting.error-codes:console-pac] 3019 (Profile Name Already in Use) occurs when attempting to create an app profile with the same name as an existing app profile; change the name of the new app profile or remove the existing one. [zcc.troubleshooting.error-codes:console-profile-name] 3022 occurs when the device tries to retrieve an updated profile and already has the latest profile; ignore it. 3023 occurs if the device attempts to download the policy and the download fails, and also for admins browsing the forwarding profile or app profiles pages; attempt to update the policy from the device again. 3025 occurs when the device attempts to update its policy with a policy that no longer exists; download the policy again, and if that fails log out and reauthenticate to Client Connector. 3026 occurs if the session expires while the device downloads a policy, and if the download is interrupted and then resumes, it might not be completed; ensure the device has connectivity, then update the policy again. [zcc.troubleshooting.error-codes:console-policy-download]

**Admin Console codes, 3024 and above.** 3024 (Device not Supported) occurs if the connecting device is not a recognized and supported platform, or if a supported platform attempts to connect as a different platform, for example a Windows device attempting to connect as a macOS device; ensure the user is running the correct and current version of Client Connector. 3051 (Invalid Device) occurs when an iOS or Android device attempts to connect to a macOS or Windows endpoint; ensure Client Connector is current. [zcc.troubleshooting.error-codes:console-platform] 3027 occurs when an iOS device sends an invalid push notification token; have the user reauthenticate to Client Connector, and if that fails, reinstall it. [zcc.troubleshooting.error-codes:console-ios-push] 3049 (Failed to register with Private Access) occurs when the device attempts to register for Private Access and the certificate signing process fails; 3050 (Failed to deregister with Private Access) occurs when removing or deregistering a device from the Admin Console and the cloud fails to remove it. Each is followed by a more specific Private Access authentication error code. 3053 (Failed to register with Internet & SaaS) occurs when registration for Internet & SaaS fails; check whether there is a trust post for the cloud status and contact Zscaler Support. 3054 (Failed to Deregister Device) occurs if the user logs out or the admin removes a device and the cloud fails to remove it. 3068 (Service is disabled) occurs if the Private Access service is disabled for the user. [zcc.troubleshooting.error-codes:console-registration] 3071 occurs when too many requests are logged into the server, so Client Connector could not enroll; it retries automatically (the message says in 12 seconds), and the retry time interval value is dynamic and might vary depending on the Admin Console's load. [zcc.troubleshooting.error-codes:enroll-throttle-3071] 3100 occurs when the device is already registered with another tenant under the same cloud; remove the device from the prior tenant via the Admin Console, then log in to Client Connector again to register with the current tenant. [zcc.troubleshooting.error-codes:other-tenant-3100] 3102 (Device is in quarantined state) occurs when the user logged in from a quarantined device. The resolution is in the Admin Console at Infrastructure > Connectors > Client > Partner Devices, selecting the View icon of the device, after which the device is removed from quarantine and the user is allowed to log in. [zcc.troubleshooting.error-codes:quarantined-3102] The Private Access error codes that follow 3049 and 3050 are in [Private Access authentication errors Client Connector users might see during enrollment: 2008 and the 42xxx codes the vendor lists](kb:zcc.troubleshooting.private-access-auth-errors).

**Report an Issue codes.** Report an Issue codes 8790 to 8798 all show "Failed to report an issue" and the action is to export logs and contact Zscaler Support. 8790 is a generic error. Form fields: 8791 occurs when the user has not entered a username in the Name field, 8792 when the Name entry is too long; 8793 when no destination email address is provided, 8794 when the email address is too long; 8795 when no subject is provided, 8796 when the subject is too long; 8797 when the list of email addresses in the CC field is too long; 8798 when the message in the Comments field is too long. [zcc.troubleshooting.error-codes:report-an-issue-form] Report an Issue codes for internal values that are too long, each showing "Failed to report an issue" with the action to export logs and contact Zscaler Support: 8799 the internal field for the Problem field, 8800 the Priority value, 8801 the internal value for the account type, 8802 the internally generated ticket ID number, 8803 the internal organization identifier, 8804 the internally provided email address for the admin, 8810 the internal value for the application version. [zcc.troubleshooting.error-codes:report-an-issue-internal] Report an Issue codes for the log attachment, each showing "Failed to report an issue" with the action to export logs and contact Zscaler Support: 8805 occurs when there is no log file to attach, 8806 when no log file is present in the submission, 8807 when an invalid log file is attached, 8808 when the size of the specified log file is too large, 8809 when the cloud responds with an invalid response. [zcc.troubleshooting.error-codes:report-an-issue-logs] Collecting the logs the table asks for is in [Getting Client Connector logs to support: Report an Issue, Fetch Logs, packet captures](kb:zcc.logging.collection).
