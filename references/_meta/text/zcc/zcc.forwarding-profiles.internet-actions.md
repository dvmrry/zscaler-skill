# Forwarding profile actions for Internet & SaaS (ZIA): Tunnel, Tunnel with Local Proxy, Enforce Proxy, None (zcc.forwarding-profiles.internet-actions)
Also called: forwarding profile action for zia; internet and saas forwarding action; tunnel with local proxy; enforce proxy mode; zcc none mode; why did zia not see this traffic; traffic bypassed zia on trusted network; tunnel driver type; packet filter based driver; route based driver; system proxy settings zcc; drop ipv6 zcc; dynamic zia service edge assignment
Former IDs: zcc-05, zcc-100

This is the half of the forwarding profile that decides what happens to a device's internet traffic. It is set once per network type.

**The choice.** For each network type (On-Trusted, VPN-Trusted, Off-Trusted, Split VPN-Trusted) the profile sets one Internet & SaaS action: Tunnel, Tunnel with Local Proxy, Enforce Proxy or None. [zcc.forwarding-profiles.internet-actions:four-actions] VPN-Trusted and Off-Trusted can be set to Same as "On-Trusted Network" to apply the On-Trusted behavior to them. [zcc.forwarding-profiles.internet-actions:same-as-on-trusted] Zscaler recommends Tunnel (Packet Filter-Based) on Windows and Tunnel with Local Proxy on macOS, which avoid interoperability issues with VPN clients, and Tunnel with Local Proxy if Tunnel (Packet Filter-Based) causes issues. [zcc.forwarding-profiles.internet-actions:recommended-modes]

**What each mode does.**
- **Tunnel.** In Tunnel mode the app tunnels traffic at the network layer, capturing it by setting IP routes on the device, and forwards all port 80/443 traffic to Zscaler through the Zscaler Tunnel (Z-Tunnel). [zcc.forwarding-profiles.internet-actions:tunnel-mode] Which Z-Tunnel version and transport it uses: [Z-Tunnel 1.0 and 2.0: what each carries and how a profile selects one](kb:zcc.z-tunnel.versions), [Z-Tunnel 2.0 transport: DTLS and TLS, fallback, MTU, and what happens when the tunnel cannot be set up](kb:zcc.z-tunnel.transport).
- **Tunnel with Local Proxy.** In Tunnel with Local Proxy mode the app sets proxy settings on the device so that all proxy-aware traffic is tunneled to Zscaler, by installing a PAC file that sends all traffic to the local host. [zcc.forwarding-profiles.internet-actions:local-proxy-mode]
- **Enforce Proxy.** In Enforce Proxy mode the app enforces the system proxy settings as specified, without tunneling any traffic, and all applications on the device must comply with them. [zcc.forwarding-profiles.internet-actions:enforce-proxy-mode]
- **None.** In None mode the app does not tunnel any traffic at all. [zcc.forwarding-profiles.internet-actions:none-mode]

**None on a trusted network.** A profile whose On-Trusted action is None sends nothing through the app on any network classified On-Trusted, so a device that matches the trusted network criteria away from the office reaches the internet without the app's tunnel, with no policy change involved. [zcc.forwarding-profiles.internet-actions:trusted-none-skips-zia] So for a profile whose On-Trusted action is None, the accuracy of the trusted network criteria is what keeps devices in the tunnel off site: [How Client Connector decides it is on a trusted network](kb:zcc.trusted-networks.detection).

**The default profile.** When no other forwarding profile is configured, Zscaler's default profile uses Tunnel on On-Trusted and Off-Trusted networks and disables System Proxy settings so users cannot bypass the app; on a VPN-Trusted network (full-tunnel VPN running) it does not forward traffic to Zscaler and disables all proxy settings. [zcc.forwarding-profiles.internet-actions:default-internet]

**Windows driver.** The profile's Tunnel Driver Type applies to Windows devices in Tunnel mode: Route-Based creates a virtual network adapter and uses OS routing; Packet Filter-Based, the default, uses Windows filtering, allows more granular control over traffic, reduces interoperability issues for applications that manage network adapters, lets VPN clients interoperate better with the app, and is required for packet capture. [zcc.forwarding-profiles.internet-actions:driver-types] Client Connector 4.8 and later for Windows does not use the route-based driver: it always uses the packet filter-based driver, whatever the profile says. [zcc.forwarding-profiles.internet-actions:driver-48]

**System proxy settings.** In Tunnel mode the system proxy Proxy Action Type is one of: Enforce (monitor system proxy changes and reapply, so users cannot tamper), Apply on Trusted Network Type Change (apply only when the network type changes), Apply on Any Network Change (apply on any network change, without monitoring afterwards), or Never. [zcc.forwarding-profiles.internet-actions:proxy-action-types] In Tunnel with Local Proxy and Enforce Proxy modes the Proxy Action Type is fixed at Enforce, so the app reapplies its proxy settings on network changes and users cannot tamper with them. [zcc.forwarding-profiles.internet-actions:proxy-enforce-fixed] A PAC file reaches the profile through the system proxy settings, as PAC URL Location: a PAC URL (at most 512 characters, https:// when Enforce Secure PAC URLs is on) that the app downloads directly, or a registry key on the device that holds the URL. [zcc.forwarding-profiles.internet-actions:pac-url-location] How these settings interact with the mode chosen for the same network type is open [gap:zcc.forwarding-profiles.internet-actions:system-proxy-vs-action].

**Unreachable domains.** Block Unreachable Domains Traffic drops or bypasses domains that are not reachable from the Internet & SaaS Public Service Edge. [zcc.forwarding-profiles.internet-actions:block-unreachable]

**IPv6.** Drop IPv6 in Dual Stack Network makes the app intercept and drop IPv6 packets from a dual-stack network (on Windows only in LWF mode); the vendor says to disable it when using IPv6, because when enabled it takes precedence over all IPv6 settings. [zcc.forwarding-profiles.internet-actions:drop-ipv6-dual-stack] Drop IPv6 in IPv6 Only Network makes the app intercept and drop IPv6 packets from an IPv6-only network, which keeps IPv6-only traffic from bypassing the app when IPv6 is not enabled or IPv6 inclusions are not configured; it too takes precedence over all IPv6 settings when enabled. [zcc.forwarding-profiles.internet-actions:drop-ipv6-only] Drop IPv6 Include Traffic When not supported drops IPv6 traffic that matches the destination inclusions when IPv6 is not provisioned for the company or the Public Service Edge. [zcc.forwarding-profiles.internet-actions:drop-ipv6-include] Client Connector 4.1 and later for Windows tunnels IPv6 in dual-stack and IPv6-only networks over both Z-Tunnel 1.0 and 2.0; because the infrastructure supports only IPv4, IPv6-only network addresses are converted to IPv4. [zcc.forwarding-profiles.internet-actions:ipv6-tunneling] What each drop setting does on the wire, and which field carries it, is partly open [gap:zcc.forwarding-profiles.internet-actions:ipv6-flags].

**Service Edge selection.** Dynamic ZIA Service Edge Assignment, off by default, sets a probe interval (30 to 600 seconds, default 60), a probe sample size (retries before failover, default 5) and a threshold rank (1 to 5) on the change in latency between the primary and secondary Service Edges; past the threshold the app switches between them, and rank 1 switches most aggressively. [zcc.forwarding-profiles.internet-actions:dynamic-zia-se]

What to check:
1. The device's network type, then the Internet & SaaS action the active profile sets for that type (including a Same as On-Trusted Network choice).
2. When ZIA saw no traffic from a user: whether the action for the device's network type was None, and whether that network type was On-Trusted because of over-broad criteria.
3. For IPv6 traffic that bypassed or broke: the Drop IPv6 settings of the active action, which override other IPv6 settings when enabled.
