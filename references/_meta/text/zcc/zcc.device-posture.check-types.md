# Device posture check types: what each checks, where it applies, and how it passes (zcc.device-posture.check-types)
Also called: posture types; posture check types; crowdstrike zta score posture; detect crowdstrike posture; firewall posture check; registry key posture check; client certificate posture; server validated client certificate; ownership variable posture; unauthorized modification posture; jamf detection posture; zcc version posture; partner tenant posture

Each posture type in a device posture profile checks one property on the device and passes or fails. The per-platform view of the same facts is in [Which device posture types each platform supports](kb:zcc.device-posture.platform-support).

**Platforms.** A device posture profile names one or more platforms (Windows, macOS, Linux, Android, iOS); a posture type that a selected platform does not support is unavailable in the profile. [zcc.device-posture.check-types:platform-selection] Apply when added as Partner Tenant (Client Connector 4.6 and later on Windows, 5.0 and later on macOS) evaluates the posture type for the Private Access tunnel used to connect to a partner tenant; otherwise the type is evaluated only for the Private Access and Internet & SaaS tunnels. [zcc.device-posture.check-types:partner-tenant] Which types run on the pre-login machine tunnel is in [Device posture on the ZPA machine tunnel](kb:zpa.machine-tunnels.posture).

## Certificates

Certificate Trust applies to all five platforms and passes when the device trusts the uploaded certificate (a root CA, intermediate or client certificate); on iOS the device must trust it directly, and an intermediate does not work. [zcc.device-posture.check-types:certificate-trust] Client Certificate applies to Windows, macOS and Linux, and its Android support ends with Client Connector 5.0; it passes when the user store holds a certificate issued by the CA uploaded to the profile and the user has the matching key pair. [zcc.device-posture.check-types:client-certificate] With Non-Exportable Private Key enabled on a certificate posture type, Client Connector checks whether the private key can be exported, and validation fails if it can. [zcc.device-posture.check-types:non-exportable-key] With Perform CRL Check enabled, a revoked client certificate fails the check. On Windows, Client Connector uses the CRL cached by a Microsoft API; from 4.8 on Windows it can instead download, validate and cache the CRL itself on a 0 to 30 minute interval, a feature Support enables. [zcc.device-posture.check-types:crl-check] Server Validated Client Certificate (Client Connector 4.4 and later on Windows, 5.0 and later on macOS) applies to Private Access only: the server sends a challenge, and the client, after locating the private key and the root CA on the certificate chain, sends the signed challenge back. On macOS the certificate must be in the System keychain, not the Login keychain, and certificates that need user interaction such as PIN smart cards are not supported. [zcc.device-posture.check-types:server-validated-cert] Linux client certificate placement: [Setting up the Client Certificate posture check on Linux](kb:zcc.device-posture.linux-client-certificate).

## Device state

File Path applies to Windows or macOS and passes when the file exists on the device; it is not available in a profile with more than one platform, where Certificate Trust must be used instead. [zcc.device-posture.check-types:file-path] Registry Key applies to Windows only and matches a key path or a value (name and data). The check runs in the user context, so a key users cannot read, such as under HKLM, must be created where they can. [zcc.device-posture.check-types:registry-key] Firewall applies to Windows or macOS and passes when at least one of the public, private and domain firewall profiles is active; third-party firewalls are not checked and do not satisfy it. [zcc.device-posture.check-types:firewall] A known issue with the firewall check on macOS Sequoia is in [Client Connector versions for macOS have a known issue with firewall posture checks on macOS Sequoia: due to changes in how macOS stores firewall configuration in macOS Sequoia, the firewall posture check for Zscaler Internet Access (ZIA) and Zscaler Private Access (ZPA) fails. The same vendor page says both that it is recommended to remove the firewall posture check from the policy until a fix is available, and that customers using earlier versions must upgrade to Client Connector version 4.2.0.294, 4.3.0.237 or 4.3.1.56 to ensure the fix is applied.](kb:zcc.device-posture.failure-modes:macos-sequoia-firewall). Full Disk Encryption applies to Windows, macOS and Android, and to Linux from Client Connector 1.4, and passes when full disk encryption is enabled; on Linux it checks the disk or partition holding a given file path. [zcc.device-posture.check-types:full-disk-encryption] Domain Joined applies to Windows or macOS and passes when the device is joined to the named domain or workgroup. [zcc.device-posture.check-types:domain-joined] AzureAD Domain Joined applies to Windows only and checks that the device is joined to the Azure AD tenant ID given; a device can be domain joined, Azure AD joined, or both (hybrid). [zcc.device-posture.check-types:azuread-joined] OS Version applies to Client Connector 3.6 and later on Windows and macOS, 1.4 and later on Linux, and 3.7 and later on Android; on Windows it passes when the machine runs the selected edition's build or later. [zcc.device-posture.check-types:os-version] Zscaler Client Connector Version applies to Client Connector 4.8 and later on Windows and macOS, takes up to five versions of 4.8 or higher, and with Exact Match requires one of the exact versions. [zcc.device-posture.check-types:zcc-version-type]

## Mobile

Ownership Variable applies to Android or iOS and passes when the device holds the configured alphanumeric variable (at most 32 characters), which the device management system pushes at installation. [zcc.device-posture.check-types:ownership-variable] Unauthorized Modification applies to Android or iOS and passes when the device has no unauthorized modification such as jailbreaking or rooting. [zcc.device-posture.check-types:unauthorized-modification]

## Processes, EDR and antivirus

Process Check applies to Client Connector 2.1.2 and later on Windows or macOS and 1.3 and later on Linux, and matches a process by absolute path and one or more signer certificate thumbprints. [zcc.device-posture.check-types:process-check] Detect Carbon Black, Detect CrowdStrike and Detect SentinelOne apply to Client Connector 2.1.2 and later on Windows or macOS and pass when that agent is running on the device. [zcc.device-posture.check-types:edr-detect] When no signer thumbprint matches, the Carbon Black, CrowdStrike and SentinelOne checks still pass if the agent is installed and turned on in Windows Security (Client Connector 4.5 and later on Windows) or installed with its process running (4.3 and later on macOS). [zcc.device-posture.check-types:edr-no-thumbprint-fallback] Detect Microsoft Defender applies to Client Connector 2.1.1 and later on Windows or macOS and 1.4 and later on Linux, and passes when Microsoft Defender Advanced Threat Protection is running; on Linux the Defender executable path is given. [zcc.device-posture.check-types:defender] Detect Antivirus applies to Client Connector 3.6 and later on Windows or macOS. On Windows a blank AV name passes on any running antivirus and a named one must be running; on macOS the antivirus name, including its system extension name, is required. [zcc.device-posture.check-types:detect-antivirus] From Client Connector 4.9 on Windows, Process Check and the Carbon Black, CrowdStrike, SentinelOne and Microsoft Defender checks can require up to three software versions, with Exact Match requiring an exact version; Support enables this. [zcc.device-posture.check-types:version-field]

CrowdStrike ZTA Score applies to Client Connector 3.4 and later on Windows or macOS, needs CrowdStrike running with its ZTA feature enabled in CrowdStrike, and passes when CrowdStrike's overall score is greater than or equal to the configured score (1 to 100). [zcc.device-posture.check-types:crowdstrike-zta-score] CrowdStrike ZTA Device OS Score and CrowdStrike ZTA Sensor Setting Score apply to Client Connector 4.6 and later on Windows and 4.8 and later on macOS, and compare the configured score against CrowdStrike's OS score or sensor setting score instead of the overall score. [zcc.device-posture.check-types:crowdstrike-zta-subscores] Jamf Detection applies to Client Connector 4.3 and later on macOS and checks that Jamf is running, or a Jamf risk level (Secure, Low, Medium, High); the Jamf daemon can keep running after the MDM profile is removed unless the framework is removed on unenrollment. [zcc.device-posture.check-types:jamf]

What to check:
1. Whether the failing type is supported on the device's platform and Client Connector version at all, before reading the check's own logic.
2. For a Firewall failure, whether only a third-party firewall is running, which does not count.
3. For a Registry Key failure, whether the key sits where the logged-in user can read it, since the check runs in the user context.
4. For a client certificate failure, whether Non-Exportable Private Key is on with an exportable key, or the certificate was revoked with CRL checking on.
5. For a CrowdStrike ZTA failure, whether the CrowdStrike agent is running and ZTA is enabled in CrowdStrike, and which score (overall, OS or sensor) the profile compares.
