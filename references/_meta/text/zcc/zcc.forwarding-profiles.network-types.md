# The four network types Client Connector detects: On-Trusted, VPN-Trusted, Split VPN-Trusted, Off-Trusted (zcc.forwarding-profiles.network-types)
Also called: on-trusted network; off-trusted network; vpn-trusted network; split vpn-trusted network; network type; why is the user off-trusted on vpn; vpn not detected zcc; vpn interface description keywords; network environments

Every forwarding-profile action is chosen per network type, so the first question in any forwarding answer is which type the device was in. Client Connector recognizes four.

**On-Trusted.** On-Trusted Network is when the user is connected to a private network that belongs to the organization; for the app to detect it, the Trusted Network Criteria must be set. [zcc.forwarding-profiles.network-types:on-trusted] How the criteria are matched is in [How Client Connector decides it is on a trusted network](kb:zcc.trusted-networks.detection).

**VPN-Trusted.** VPN-Trusted Network is when the user reaches a trusted network through a VPN in full-tunnel mode: the VPN must capture all of the user's traffic by installing a default route in the device's routing table. [zcc.forwarding-profiles.network-types:vpn-trusted] The app does not treat the network as VPN-Trusted, and treats the user as Off-Trusted, when the VPN captures all traffic without installing a default route, when the default interface description does not contain Cisco, Juniper, Fortinet, PanGP or VPN, or when the VPN runs in split-tunnel mode (routes for some subnets only, or a DNS for specific requests). [zcc.forwarding-profiles.network-types:vpn-trusted-exclusions] macOS does not check the interface description for keywords; it only checks whether the VPN created a utun, PPP or GPD interface. [zcc.forwarding-profiles.network-types:macos-interface-check] If a VPN is not from a common vendor and its NIC adapter text does not match what is usually detected, its name can be entered in the VPN-Trusted Network Adapter Criteria field on the Endpoint Integration tab so Client Connector can detect a VPN-Trusted Network; hard-coded VPN adapter names can be removed there with the Delete icon next to the VPN name. [zcc.forwarding-profiles.network-types:vpn-adapter-names] New VPN adapter names are sent to Client Connector when policies are updated on devices, and Client Connector detects the new VPN adapter as a trusted network on the next network change or when services start. [zcc.forwarding-profiles.network-types:vpn-adapter-propagation] Whether the hard-coded names are the built-in keywords, whether the criteria matter on macOS, and how a name is matched are open [gap:zcc.forwarding-profiles.network-types:adapter-criteria-scope].

**Split VPN-Trusted.** Split VPN-Trusted Network is when the user reaches a trusted network through a split-tunnel VPN. It does not apply when the VPN runs as a default adapter, when the VPN interface description lacks Cisco, Juniper, Fortinet, PanGP or VPN (the user is then Off-Trusted), or when the Trusted Network Criteria evaluated against the VPN adapter do not match. [zcc.forwarding-profiles.network-types:split-vpn-trusted] So a split-tunnel VPN user is Split VPN-Trusted only when the profile has Enable Split VPN-Trusted Network on and its criteria match the VPN adapter; otherwise the split-tunnel VPN is one of the cases treated as Off-Trusted. [zcc.forwarding-profiles.network-types:split-vpn-needs-detection]

**Off-Trusted.** Off-Trusted Network is when the user is connected to an untrusted network. [zcc.forwarding-profiles.network-types:off-trusted] Whether Off-Trusted is simply what remains when nothing else is detected, and which type wins when two could apply, is open [gap:zcc.forwarding-profiles.network-types:classification-order].

**Where it shows.** When a user connects to a network, the app determines its network type and displays it on the Internet Security window and the Private Access window. [zcc.forwarding-profiles.network-types:network-type-displayed] The same network type also selects the app profile's location-based ruleset: with Location Policy Override, rulesets for traffic steering and endpoint firewall rules apply by the user's network type; a ruleset must be selected for On-Trusted and Off-Trusted, while VPN-Trusted and Split VPN-Trusted default to Same as On-Trusted. With Endpoint Firewall Management, host firewall rules come from the ruleset assigned for the active network type, and the Python SDK models the app profile's location ruleset policies with one entry each for `trusted`, `offTrusted`, `vpnTrusted` and `splitVpnTrusted`. [zcc.forwarding-profiles.network-types:firewall-ruleset-per-network-type]

On the wire each action block carries the type as an integer `networkType` whose values are not documented by the vendor: [ZCC forwarding profile calls: integer codes, read and write types, and where the contract and SDKs differ](kb:zcc.api.forwarding-profile-wire).

What to check:
1. Which network type the app displayed on the Internet Security and Private Access windows at the time of the problem.
2. For a VPN user shown as Off-Trusted: whether the VPN installs a default route, and on Windows whether the adapter description contains Cisco, Juniper, Fortinet, PanGP or VPN; on macOS whether it created a utun, PPP or GPD interface.
3. For a split-tunnel VPN user: whether Enable Split VPN-Trusted Network is on in the profile and the trusted network criteria match the VPN adapter.
