# Client Connector on non-persistent Citrix VDIs: the single-user model, the VDI install parameters and the master VM (zcc.install.citrix-vdi)
Also called: citrix vdi zcc; non-persistent vdi zcc; citrix upm zcc; master vm zcc; citrix provisioning services zcc

Client Connector supports only a dedicated, single-user VDI model; for multi-session VDIs, Client Connector for VDI is required. The MSI and EXE install-options pages both say so. [zcc.install.citrix-vdi:single-user-only] The multi-session product is a separate one: [Installing Client Connector for VDI: download, MSI options, golden images, OnboardOnStart, Intune and processes to allowlist](kb:cloud-connector.vdi.install).

**Advice for non-persistent Citrix VDIs.** For non-persistent Citrix VDIs, Zscaler recommends not logging in to Client Connector on the master VM; the strict enforcement install option requires the hide-app-UI-on-launch option disabled so the app can remind users to enroll before they reach the internet; and the user domain option requires Integrated Windows Authentication (IWA). The MSI and EXE pages say the same with their own option names. [zcc.install.citrix-vdi:best-practices] The two install-option rules are also in [With non-persistent Citrix VDIs on Windows, strict enforcement needs hideAppUIOnLaunch set to 0 so Client Connector can remind users to enroll before they reach the internet.](kb:zcc.install.strict-enforcement:citrix-hide-ui) and [userDomain (MSI `USERDOMAIN`) is the organization's domain name; with several domains it is the primary domain, which is valid only with a single IdP across those domains. It must be the exact domain in the SAML NameID. It lets users skip the enrollment page; when SSO is enabled they go straight to the SSO login page, and where SSO is integrated with the app (IWA on Windows, the Microsoft Enterprise SSO plug-in on macOS) users also skip the SSO page and are enrolled and logged in automatically. With non-persistent Citrix VDIs on Windows, this option requires IWA.](kb:zcc.install.enrollment:user-domain).

**Where the configuration lives.** VDI=1 (EXE --vdi 1) makes Client Connector store its configuration data in the %USERPROFILE%\AppData\Roaming\Zscaler user profile store instead of the default %ProgramData%\Zscaler, so a profile management tool such as Citrix UPM can roam and restore it. [zcc.install.citrix-vdi:vdi-flag] What else the flag changes is open [gap:zcc.install.citrix-vdi:vdi-flag-scope]. In environments with roaming profiles such as non-persistent VDIs, CONFIGTIMEOUT=300 makes the app wait the specified interval for its configuration data to be restored when it is not found, because a profile management solution might need extra time to restore it. If the VDI deployment does not use a profile management solution, the MSI and EXE pages say the parameter is not necessary. [zcc.install.citrix-vdi:config-timeout] The parameter's unit and default are in [configTimeout (MSI `CONFIGTIMEOUT`) sets how many seconds Client Connector waits for the configuration file if it is not already present; the default is 0.](kb:zcc.install.windows-unattended:config-timeout).

**The filter driver.** INSTALLLWFDRIVER=1 (EXE --installLWFDriver 1) installs the lightweight filter driver used for traffic interception during installation. Without it, the MSI page says Client Connector does not install the driver until a forwarding profile configures it during policy download, which might cause network connection disruption and VDI disconnection. [zcc.install.citrix-vdi:install-lwf] LWFBOOTSTART=1 configures the LWF driver to load at system boot instead of the default at system startup, which the MSI page says prevents a blue screen during OS boot where the OS is booted over the network, such as in Citrix Provisioning Services. With Citrix Provisioning Server the option is required (--LWFBootStart in the EXE). [zcc.install.citrix-vdi:lwf-boot-start] The driver switches themselves are in [Windows filter driver install parameters (LWF)](kb:zcc.install.windows-driver).

**The master VM.** On the master VM, Citrix UPM is configured to back up and restore {UserProfileFolder}\AppData\Roaming\Zscaler, and the installer runs with the sample parameters msiexec/i ZCC_installer.msi USERDOMAIN=<AD domain> CLOUDNAME=<cloudname> VDI=1 CONFIGTIMEOUT=300 INSTALLLWFDRIVER=1 LWFBOOTSTART=1, or --vdi 1 --configTimeout 300 --installLWFDriver 1 --LWFBootStart 1 for the EXE; the MSI page calls the parameters samples. [zcc.install.citrix-vdi:master-vm]

**Open points.** How the revert option, which is not supported for non-persistent VDI ([If a recent upgrade was not successful for some users, they can revert to the previous Client Connector version. The feature applies to Client Connector 3.9 and later for Windows and 4.1 and later for macOS, only admins can enable the option, and the revert option is not supported for non-persistent VDI.](kb:zcc.install.revert:scope)), interacts with these parameters is open [gap:zcc.install.citrix-vdi:revert-interaction].
