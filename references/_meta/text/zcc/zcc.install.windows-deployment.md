# Deploying Client Connector on Windows: the MSI and MST, the EXE, command lines and Active Directory GPO (zcc.install.windows-deployment)
Also called: zcc msi install; zcc mst transform; orca mst zcc; zcc exe install options; zcc gpo deployment; deploy zcc active directory

The MSI file is for installing Client Connector manually on a device or deploying it through GPO, SCCM or other device management methods that support MSI files. To add install options (for example to enable strict enforcement) to the MSI, an MST file must first be created. [zcc.install.windows-deployment:msi] The EXE file is for installing Client Connector manually on a device or through device management methods that do not support MSI files; options follow the EXE's absolute path in the --<install option> format. [zcc.install.windows-deployment:exe]

**The MST.** Windows installers use an MST file to customize an original MSI package during installation. It is made with Orca, which is in the Microsoft Windows SDK, by choosing Transform > New Transform and adding Zscaler parameters and values in the Property table; it can be deployed through a Group Policy Object or a compatible device management tool such as Microsoft Intune or Jamf Pro. [zcc.install.windows-deployment:mst]

**The MSI from a command line.** Zscaler recommends the MST file for installing with custom options. For a device management tool that does not support MST (the page gives SCCM or PSEXEC as examples) or a manual MSI installation, the MSI can be run from the command line as msiexec /i "<complete path>" /quiet <install options>, where /quiet installs in silent mode. [zcc.install.windows-deployment:msi-cli]

**Naming the EXE for a domain.** Prefixing the EXE file name with the organization's domain name (for example safemarch.com-Zscaler-windows-1.1.0.000213-installer) achieves the same function as the --userDomain install option. The page says to use it only if the organization's domain is registered on a single cloud, and SSO must be enabled; if SSO is integrated with Client Connector using a mechanism like Integrated Windows Authentication (IWA), users can also skip the SSO login page and are automatically enrolled and logged in. [zcc.install.windows-deployment:exe-domain-prefix] The matching install option is described in [Install parameters that identify the tenant and user at enrollment](kb:zcc.install.enrollment). Whether the MSI has an equivalent other than the user domain parameter is open [gap:zcc.install.windows-deployment:msi-domain-prefix].

**Active Directory.** In Active Directory, either the MSI or the EXE can be used, but Zscaler recommends the MSI because it integrates well with GPO. For the MSI, a GPO created and linked on the OU installs it from User Configuration > Policies > Software Settings > Software installation, with deployment type Assigned, deployment option Install this application at logon and installation user interface Basic; Client Connector is then deployed the next time users log in to their computers. [zcc.install.windows-deployment:ad-msi] For the EXE in Active Directory, the GPO runs a script under Computer Configuration > Policies > Windows Settings > Scripts > Startup whose Script Name is the EXE's absolute path and whose Script Parameters field is left blank for no install options or holds them; gpupdate.exe /force is then run and the OU's computers are remotely rebooted. The installer must be on a network share on the Domain Controller that the relevant domain Administrators and Authenticated Users can access. [zcc.install.windows-deployment:ad-exe]

**Changing a parameter later.** Changing an install parameter after installation means reinstalling: [The MSI and EXE install-options pages each say that modifying any of the listed install parameters after installation requires reinstalling the app with the new values.](kb:zcc.install.precedence:reinstall-to-change). Silent install, upgrade and uninstall parameters are in [Silent install, upgrade, revert and uninstall parameters, and launch behavior](kb:zcc.install.windows-unattended); non-persistent Citrix VDIs in [Client Connector on non-persistent Citrix VDIs: the single-user model, the VDI install parameters and the master VM](kb:zcc.install.citrix-vdi).

Not known (open gaps):
