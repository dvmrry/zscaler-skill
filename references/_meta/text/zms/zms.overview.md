# Zscaler Microsegmentation (ZMS): agents, local enforcement, region and provisioning (zms.overview)
Also called: zms; zscaler microsegmentation; zero trust microsegmentation; zpa microsegmentation; east-west segmentation; workload segmentation agents; microsegmentation agent nftables; microsegmentation windows filtering platform; microsegmentation client connector same host; zms kubernetes; zms packaging; zms licensing; zms vs zpa

Zscaler Microsegmentation (ZMS) segments traffic between workloads inside private applications, with policy enforced by agents on each host. This subject covers what it is and how it is deployed; the admin portal, provisioning keys and the GraphQL API have their own subjects.

**What it is.** Zscaler Microsegmentation is a platform in the Zscaler Admin Console for visualizing traffic flows within private applications and segmenting them, a multi-tenant SaaS divided into the Zscaler cloud and deployed agents that together collect and analyze application flow and telemetry data. [zms.overview:what-it-is] The product page frames Microsegmentation as eliminating lateral movement of threats by restricting east-west traffic with zero trust principles; its FAQ says microsegmentation governs network access between resources, such as server-to-server (east-west) traffic. [zms.overview:east-west] The agents sit on Windows or Linux hosts, virtual or physical, cloud based or in a data center, and collect information about application activity. [zms.overview:agents-hosts] Agents download the latest access policies from the Zscaler cloud and translate them into rules for local OS enforcement points, for example Windows Filtering Platform and Linux nftables. [zms.overview:local-enforcement] Agent Groups, Resource Groups and AppZones group machines and their applications to be monitored for certain data flows. [zms.overview:groupings]

**Client Connector.** Microsegmentation agents and Zscaler Client Connector are not compatible and should not be installed on the same host. [zms.overview:zcc-incompatible]

**Where it runs.** The backend is hosted by the Zscaler cloud and available across the US region; data collection is localized to the administrator's region of choice, data retention is a 14-day rolling period, agents can be deployed to resources in any region, and installed agents operate in continuous mode. [zms.overview:region-and-retention] Microsegmentation is provisioned for an organization by contacting the Zscaler Account team. [zms.overview:provisioning] Whether it requires ZPA is open [gap:zms.overview:zpa-prerequisite].

**Recommendations and deployment options.** The product page describes granular visibility, AI-powered group recommendations and local enforcement in an agent-based architecture, automated policy recommendations based on real-time traffic and workload insights with AI-assisted rule suggestions, and host-based segmentation that creates granular segmentation policies for traffic at the application level. [zms.overview:recommendations-marketing] How flows that recur monthly or quarterly affect a recommendation is open [gap:zms.overview:recommendation-lookback]; the 14-day window is in [How Microsegmentation flow-based policy recommendations are generated, organized and accepted](kb:zms.policy-recommendations). Zscaler's Zero Trust Cloud product page, which lists microsegmenting workloads with AI-powered recommendations and local enforcement among its use cases, says Zero Trust Cloud can be deployed by taking full control of the cloud infrastructure or by consuming the capabilities as a gateway service. [zms.overview:deployment-options-marketing] What either option involves is open [gap:zms.overview:deployment-options].

**Open questions.** Agent behavior without the cloud is open [gap:zms.overview:offline-enforcement], as are coexistence with other host firewalls [gap:zms.overview:host-firewall-conflicts], agent updates [gap:zms.overview:agent-updates], Kubernetes granularity [gap:zms.overview:kubernetes-granularity], cloud-native controls and workload identity [gap:zms.overview:cloud-native-integration], the move from monitoring to enforcement [gap:zms.overview:monitor-to-enforce] and whether traffic is inspected [gap:zms.overview:inspection].

What to check:
1. Whether Zscaler Client Connector is installed on a host that is meant to run a Microsegmentation agent.
2. Which local enforcement point holds the agent's rules on the host (Windows Filtering Platform or nftables).
3. Whether observed flows older than the 14-day retention matter to the question.
4. Whether the question is about users reaching private applications (Private Access) or about traffic flows within private applications and east-west threat movement (Microsegmentation); an answer may need both.
