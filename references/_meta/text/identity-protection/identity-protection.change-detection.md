# Active Directory and Entra ID change detection in Identity Protection: monitored issues, cycle, Impact values and remediation (identity-protection.change-detection)
Also called: ad change detection; active directory change detection; entra id change detection; change detection policy; good bad info impact

Change detection classifies a change's Impact as Good (safe), Bad (risky) or Info (significant, good or bad depending on the environment). [identity-protection.change-detection:impact-values]

**Active Directory.** To view AD change detection data, you need to configure an AD domain for a scan and enable change detection, or configure a change detection policy for custom change detection. [identity-protection.change-detection:ad-prerequisite] The AD Change Detection article says it uses the AD scan results and that the scan runs every 15 minutes, and the notification page names it the AD change detection scan; two scans are needed because the first creates the base results and changes in the second are compared with them and labelled Good, Bad or Info. [identity-protection.change-detection:ad-scan-interval] [gap:identity-protection.change-detection:change-detection-scan-identity] AD Change Detection monitors for eleven issues: Kerberoastable accounts, AS-REP roasting vulnerability, passwords set to never expire, password not required, exposed attributes, privileged account delegation, unconstrained delegation, constrained delegation, privileged account added or removed, DCSync vulnerability and AdminSDHolder permissions. [identity-protection.change-detection:ad-monitored-issues] Zscaler ITDR can customize active-change monitoring for ACLs, passwords and group membership properties for users, ACLs, members and group membership for groups, and ACLs and group membership for computers. [identity-protection.change-detection:ad-custom-properties] The AD Custom tab lists changes by Change Date, Identity, Policy Name, Identity Type (User, Computer or Group) and Changed Properties; its identity history view lets you compare the previous and current property change details. [identity-protection.change-detection:ad-custom-tab] AD change remediation is available only for users with bad changes; Revoke Group Membership is not available for bulk remediation. [identity-protection.change-detection:ad-remediation-scope] A ServiceNow ticket can be created for an AD change only if it is a bad change. [identity-protection.change-detection:ad-servicenow]

**Custom policies.** Editing an AD or Entra ID custom change detection policy determines what is detected in the monitored AD domain or Entra ID tenant respectively (the domain or tenant is monitored based on the changes made to the policy), and deleting a policy, after confirmation, removes it from the ITDR Admin Portal. [identity-protection.change-detection:custom-policy-edit-delete]

**Entra ID.** Entra ID Change Detection uses the Entra ID scan results, and ITDR makes API calls to Entra ID every 15 minutes to detect changes in identity properties. [identity-protection.change-detection:entra-api-interval] Zscaler ITDR can customize active-change monitoring of properties of users, service principals, Entra roles and RBAC and custom roles. [identity-protection.change-detection:entra-monitored-properties] Entra ID change detection marks a user exempted from MFA and a guest assigned a privileged role as bad impact, and revoking a service principal's permissions to access private data as good impact. [identity-protection.change-detection:entra-impact-examples] An Entra ID change's issue details include a Raw Event in JSON from the tenant's log provider, which can be downloaded as a JSON file. [identity-protection.change-detection:entra-raw-event] A ServiceNow ticket can be created for a bad Entra ID change. [identity-protection.change-detection:entra-servicenow]

What to check:
1. Whether an AD change is a bad change before offering remediation or a ServiceNow ticket.
2. Whether two AD change detection scans have run, since the first creates the base results.
