# Endpoint Credential Exposure in Identity Protection: dashboard, scan types, cleanup and reports (identity-protection.credential-exposure)
Also called: endpoint credential exposure; exposed endpoint credentials; cleanup credentials; credential cleanup; exposure scan types

The Endpoint Credential Exposure dashboard filters scans by date and shows endpoints assessed, identities with exposure, the top 5 exposed credentials and the top 10 identities. [identity-protection.credential-exposure:dashboard-contents] The dashboard donut chart groups exposed credentials by risk type, for example Browser Credentials, Windows Credentials and Privilege Escalation. [identity-protection.credential-exposure:risk-types-chart] Downloading the endpoint credential exposure scan data returns a .zip file of CSV files, one set per exposure type listing endpoints and exposed credential details. [identity-protection.credential-exposure:scan-data-download]

**MITRE ATT&CK exposures and identities.** Exposed endpoint credential issues can be viewed grouped by MITRE ATT&CK techniques, and the page lists fourteen entries: Initial Access, Execution, Persistence, Reconnaissance, Privilege Escalation, Defense Evasion, Credential Access, Discovery, Lateral Movement, Command and Collection (CnC), Exfiltration, Impact, Collection and Resource Development. [identity-protection.credential-exposure:mitre-groupings] The MITRE ATT&CK Exposures tab of ITDR > Dashboard > Endpoint Credential Exposure lists the issues under tabs (All, Initial Access, Execution, etc.); the As of Date calendar selects the scan date whose total number of exposed credential issues is shown, and a severity level of Low, Medium, High or Critical filters the issues. [identity-protection.credential-exposure:mitre-view-navigation] Each exposed-credential issue in the MITRE ATT&CK view shows a Type Of Risk (examples: Privilege Escalation, Admin Auto Logon Credentials, AWS Credentials Exposure), a Severity of Critical, High, Medium or Low, and a Who is affected list of identities; the Actions menu copies columns and downloads the exposed credentials as CSV or JSON. [identity-protection.credential-exposure:mitre-issue-fields] Identities storing exposed credentials are listed in a table reached from Top Identities on the Dashboard tab or the Identities tab; Identity is the name of the system, Type of risk is the exposure risk type, and the As of Date calendar selects the scan date. [identity-protection.credential-exposure:identities-table]

**Roadmap.** The endpoint Risk Reduction Roadmap uses a severity slider, an As of Date calendar selects the scan date, and its affected objects are identities with exposed endpoint credentials. [identity-protection.credential-exposure:roadmap]

**Scan types.** The All Exposures page shows Total, Cleaned Up and Available to cleanup for each exposure type and can be filtered by scan date. [identity-protection.credential-exposure:all-exposures-columns] Cleanup Credentials is supported for eight exposure types: Cached Domain Logon Credentials, AWS Credentials, Saved VNC Passwords, Saved Windows Credentials, Admin AutoLogon Settings, Database Connections, Azure Credentials and Google Cloud Credentials. [identity-protection.credential-exposure:cleanup-supported-types] Cleanup Credentials is not supported for fifteen exposure types, which are listed with the check each performs (for example SSH Keys, LSA Protections and WDigest Settings). [identity-protection.credential-exposure:cleanup-unsupported-types] The privilege-escalation page names three credential misconfigurations that can lead to escalation: not following least privilege, user account control misconfiguration such as ConsentPromptBehaviourAdmin set to 0, and AutoLogon security misconfiguration. [identity-protection.credential-exposure:privilege-escalation-causes] How a finding gets its severity is not stated [gap:identity-protection.credential-exposure:severity-rating-method].

**Cleanup.** Selected exposed credentials are queued for cleanup; the agent fetches the updated policy by checking the queue in the ITDR Admin Portal and applies the cleanup, and the Cleanup Status column tracks the state (Can be cleaned, Failed). [identity-protection.credential-exposure:cleanup-process] Which agent applies the cleanup is open [gap:identity-protection.credential-exposure:cleanup-agent].

**Findings and reports.** Exposed-credential tables can be downloaded as CSV or JSON, and a ServiceNow ticket can be created from the Detailed Findings page. [identity-protection.credential-exposure:detail-export-formats] The Endpoint Credential Exposure executive report downloads as a PDF and shows endpoints scanned, findings by severity and the top 5 priority findings. [identity-protection.credential-exposure:executive-report] The executive report groups credentials in focus into Browser Infostealer Risk, DevOps Credential Risk, Notable Credential Risk, Privilege Escalation Risk and Other Credentials. [identity-protection.credential-exposure:executive-report-categories]

What to check:
1. Whether an exposure type is one of the eight for which Cleanup Credentials is supported before offering a cleanup.
2. For a cleanup that did not complete, whether the Cleanup Status column shows Can be cleaned or Failed.

Not known (open gaps):
- How an exposed credential gets its Critical, High, Medium or Low severity [gap:identity-protection.credential-exposure:severity-rating-method]: settled by source-read or support-ticket
- Which agent applies a credential cleanup [gap:identity-protection.credential-exposure:cleanup-agent]: settled by source-read
