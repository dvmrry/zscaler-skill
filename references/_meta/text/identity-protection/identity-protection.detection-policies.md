# How ITDR threat detection policies, custom change detection policies and email notifications are configured (identity-protection.detection-policies)
Also called: threat detection policies; custom change detection policy; itdr notifications

A threat detection policy is applied to an endpoint only if its selection criterion matches; the policy list shows Name, Selection Criterion and Policies (the number of ITDR attack detection modules configured), and the Enabled option deploys the policy to applicable endpoints. [identity-protection.detection-policies:policy-model] Landmine policies in Zscaler Deception that have ITDR Active Directory capabilities enabled are migrated to ITDR threat detection policies, with a unique ID appended to the policy name that can be edited. [identity-protection.detection-policies:landmine-migration]

## Threat detection policies

**Selection.** A new threat detection policy defaults to the Catch All selection criterion for all endpoint agents; the Fallback criterion applies to any system with no other policy criteria and is not applied if Catch All is specified. [identity-protection.detection-policies:selection-default-and-fallback] Threat detection endpoint selection also offers User, Group, Hostname (Specific), Hostname (RegEx), DNS Hostname (Specific), DNS Hostname (RegEx), User OU (RegEx) and Computer OU (RegEx). [identity-protection.detection-policies:selection-criterion-types] A Dynamic Rule selection criterion matches on the attributes Process List, Browser History, Installed Programs, Interesting Files or Recent Commands, and a policy with several dynamic rules is applied if any one rule matches. [identity-protection.detection-policies:dynamic-rule-attributes] How the Contains values of a dynamic rule are matched is open [gap:identity-protection.detection-policies:dynamic-rule-matching].

**Evaluating.** Evaluate Policies generates a sample policy report from a User ID and Hostname (it also shows the OS) plus optional Group, Computer OU, User OU, Domain, Display Name and Dynamic Rules, and when a user or system matches two or more policies the report shows the attack detection modules of all matching policies. [identity-protection.detection-policies:evaluate-policies]

**Active Directory module.** The AD threat detection module detects DCSync, DCShadow, Zerologon (CVE-2020-1472), Session Enumeration, Kerberoast and LDAP Reconnaissance attacks via the endpoint agent. [identity-protection.detection-policies:ad-attack-types] The AD module's per-policy options include Monitor Privileged Accounts, Monitor Decoy Accounts, Kerberoast Detection (Anomaly) for non-decoy service accounts, Kerberoast Detection (Decoy) for decoy service accounts, and Suspicious LDAP Activity for LDAP reconnaissance. [identity-protection.detection-policies:ad-module-options] Before configuring an AD threat detection module, an AD domain must be scanned with at least one scan report; in some modules such as monitoring privileged accounts, a newly identified AD object takes about 60 minutes before endpoint agents monitor it. [identity-protection.detection-policies:ad-module-prerequisite-and-delay]

**Propagation.** Changes to a threat detection policy can take a few hours to reflect on the endpoints. [identity-protection.detection-policies:policy-propagation]

## Custom change detection policies

AD custom change detection policies detect changes to users, groups and computers in a chosen domain, while Entra ID custom policies detect changes to users, service principals and roles in a chosen tenant; both can notify specific users by email, in addition to the default changes ITDR detects. [identity-protection.detection-policies:custom-change-policy-scope] An AD custom change detection policy takes a domain, and for each user, group or computer a distinguished name plus properties to watch (for example ACLs, Password Changes and Group Memberships). [identity-protection.detection-policies:ad-custom-policy-fields] For an Entra ID custom change detection policy, examples of selectable change types are, for users, Role Assignments, Password Changes, Changes in MFA, Being marked 'Risky', Delegated consent grants to applications, Administrative Units and Group Memberships; for service principals, Changes to secret/cert, Added/revoked Admin Consent and Changed ownership; for roles, Additions and removals. [identity-protection.detection-policies:entra-custom-policy-change-types] Each AD and Entra ID custom change detection policy has a Notify section with an Enabled option and a user list for emailing the selected users when the policy's conditions detect changes. [identity-protection.detection-policies:custom-policy-email-notify] The full lists of properties and change types are open [gap:identity-protection.detection-policies:custom-policy-lists].

## Notifications

ITDR notifications cover five alert types: AD posture and Entra ID posture send executive summary reports after successful scans, AD and Entra ID change detection send bad change details, and endpoint credential scan sends the endpoint credential exposure executive report. [identity-protection.detection-policies:alert-types] The Notifications page's Type column uses the values Active Directory Posture, Active Directory Change Detection, Credential Scanning, Entra Posture and Entra Change Detection. [identity-protection.detection-policies:type-column-values]

**Posture notifications.** AD posture and Entra ID posture notifications email the executive summary report to the selected recipients after the selected domains or tenants are successfully scanned. [identity-protection.detection-policies:posture-notification-delivery]

**Change detection notifications.** AD and Entra ID change detection notification emails carry bad change details including the affected identities, issue details and remediation details. [identity-protection.detection-policies:change-notification-content] AD and Entra ID change detection notifications take a Number of emails in a 24-hr window of 20 or less; if the number of emails exceeds the limit, Zscaler pauses the notifications and sends an email recommending a review of the configuration. [identity-protection.detection-policies:email-rate-limit] An AD change detection notification can be restricted to chosen Scan Categories (for example Vulnerable to AS-REP roasting, Privileged Accounts, Kerberoastable Accounts) or use Enable All, and the vendor notes the AD change detection scan runs every 15 minutes. [identity-protection.detection-policies:ad-change-notification-scope] An Entra ID change detection notification can be restricted to chosen Scan Categories (for example Users without MFA, Excessive Global Admins, Privilege guest accounts) or use Enable All. [identity-protection.detection-policies:entra-change-notification-scope] The full Scan Categories lists and what Enable All does with a category selection are open [gap:identity-protection.detection-policies:scan-categories].

**Credential scan notifications.** An endpoint credential scan notification is sent on a frequency of Daily, Weekly, Monthly or Quarterly at a chosen trigger time and carries the executive summary report. [identity-protection.detection-policies:credential-notification-schedule]
