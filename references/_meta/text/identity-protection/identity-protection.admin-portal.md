# What the ITDR Admin Portal help pages and the SecOps ITDR Config page describe: sign-in and navigation, users and roles, account settings, ITDR Config, tables, queries, Advanced Settings, logs and Investigate (identity-protection.admin-portal)
Also called: itdr admin portal; zscaler itdr admin portal; itdr investigate; itdr advanced settings; itdr users and roles

The Deception copies of these pages are [Deception Admin Portal: sign-in, navigation, users and roles, account settings, allowed IPs and QoS events](kb:deception.admin-portal), [Deception Investigate: the dashboard, containment actions, event logs and evidence](kb:deception.investigate), [Endpoint settings (installer, lure refresh, update groups, safe processes) and Admin Portal settings (audit, error and debug logs, license, event and evidence export and delete, retention)](kb:deception.endpoint-settings) and [Deception query language: operators, constants, precedence and flags used in filters, rule conditions and ThreatParse rules](kb:deception.query-language); the ITDR facts are below.

## Signing in and navigation

The page's "Accepting the End User Subscription Agreement (EUSA)" item, which follows its "For Customers Using SSO" section, says the ITDR Admin Portal displays an EUSA at first login that must be accepted to activate the license; the provisioning email contains a link to the ITDR instance, a link to set the password and a security code. [identity-protection.admin-portal:first-sign-in-eusa] For Authentication Service-enabled customers there is no separate UI for ITDR in Authentication Service; ITDR configuration is done through the Deception UI, and the Deception tile on the Authentication Service landing page opens the ITDR Admin Portal. [identity-protection.admin-portal:authsvc-no-itdr-ui] With Authentication Service enabled, Logout logs the user out of the ITDR Admin Portal only, and signing in again does not require entering the user credentials. [identity-protection.admin-portal:logout-with-authsvc] For an account configured with SSO, the ITDR page tells the user to click the sign-in button with the IdP name on the Sign In page, then log in at the IdP and be redirected back to the ITDR Admin Portal. [identity-protection.admin-portal:sso-sign-in-button]

On the Accessing and Navigating page, the ITDR item in the left-side navigation opens the Identity Posture, Credential Exposure and Change Detection dashboards and is where AD domain scans, credential exposure scans and threat detection policies are configured. [identity-protection.admin-portal:nav-itdr-item] [In the release note dated June 23, 2025: the dashboards Identity Posture, Change Detection, Entra ID and Identity Risk Summary were renamed Active Directory Posture, Active Directory Change Detection, Entra ID Posture and Risk Summary.](kb:identity-protection.release-notes:2025-06-23-dashboard-renames) In the ITDR Admin Portal the System Messages icon is described as showing audit logs and system messages, and the Account Settings icon as resetting 2FA, editing the profile, changing the time zone and changing the password. [identity-protection.admin-portal:nav-system-messages] Orchestrate is where rules are automated, events are forwarded to SIEM and other log aggregation repositories, threats are contained, alerts are enriched and API tokens are created; Settings configures users and roles and shows license consumption and audit trails; the Search icon searches ITDR modules and sub-modules. [identity-protection.admin-portal:nav-orchestrate-settings-search] The Investigate page is the landing page showing logged forensics and attacker information graphically, used to monitor and analyze event activities that adversaries conduct on the AD domain and endpoints. [identity-protection.admin-portal:investigate-landing]

## Users and roles

The ITDR predefined roles table describes Super admin as having complete control over users, roles, APIs, modules and audit logs; Administrator as analyzing events and orchestrating actions; Analyst as investigating events, blocking or allowlisting an attacker and exporting logs; and Responder as analyzing events and orchestrating actions. [identity-protection.admin-portal:predefined-roles-table] With Authentication Service enabled, Add Users on the ITDR Users page redirects to the Authentication Service Admin Portal, where users are added under Directory > Users and assigned to the Deception service. [identity-protection.admin-portal:authsvc-user-path] In the User Details window, Time Zone sets how alert timestamps are displayed and Session Inactivity Timeout, the time after which an inactive session is logged out, is 30 minutes by default. [identity-protection.admin-portal:session-timeout-time-zone] In the ITDR per-user Email Notifications Preferences window, Fine-Tune Notifications has License (alerts when the license is about to expire) and Security Alerts (alerts when user settings are changed, for example when a password is disabled globally). [identity-protection.admin-portal:notification-categories] The ITDR Users & Roles area has an IdP Providers page (Settings > Users & Roles > IdP Providers) for configuring identity providers for SSO, and a Zscaler Remote Assistance page showing Zscaler Support users with Read-only or Admin role. [identity-protection.admin-portal:idp-providers-tab]

## Account settings

On the ITDR Account Settings page, Notification Preferences customizes email notification preferences for information relating to the license and security alerts. [identity-protection.admin-portal:notification-preferences-account] The ITDR Account Settings page states that Reset 2FA and Change Password are available only if the Disable Password Login option was selected while adding a user. [identity-protection.admin-portal:account-settings-2fa-password] Resetting 2FA is done on the Account Settings page by entering the password and the current 2FA code from the authenticator app, scanning a new QR code and submitting the 6-digit one-time password. [identity-protection.admin-portal:reset-2fa-steps] The ITDR user profile is a name and a time zone, configured when an administrator provisions the account; the name is displayed during specific configurations and used when submitting a ticket to Zscaler Support, and the time zone is used when sending automated email alerts. [identity-protection.admin-portal:user-profile] Changing the ITDR password on the Accounts Settings page needs the current password and a confirmed new password; an estimator rates the new password's strength with a color meter (green strong, red weak), and a confirmation email is sent after the change. [identity-protection.admin-portal:change-password]

## ITDR Config in the SecOps platform

In the Identity Protection documentation, ITDR settings are reached in the SecOps platform at Identities > ITDR Config, but the detailed configuration is managed in the legacy ITDR Admin Portal. [identity-protection.admin-portal:itdr-config-location] The overview describes the same configuration differently [divergence:identity-protection.admin-portal:itdr-config-where-managed] ([Identity Protection is managed and fine-tuned through the SecOps platform, whose Settings page adjusts scan configurations with an explanation of each option; where deeper configuration is needed, some links redirect to the legacy ITDR experience.](kb:identity-protection.overview:legacy-redirect)). The ITDR Config page has four sections: ITDR Manage, ITDR Settings, Endpoint Settings and Server Agent Settings. [identity-protection.admin-portal:itdr-config-sections] ITDR Manage configures identity scans and policies across AD, Entra ID and Okta, and lists AD Posture Scan, AD Privileged Account Tracking, Endpoint Credential Exposure Scan, Entra ID Posture Scan, Threat Detection Policies, Okta, AD Change Detection and Entra Change Detection. [identity-protection.admin-portal:itdr-config-manage-items] ITDR Settings holds eight safelists (AD Issue, AD Object, AD Change Detection Issue, AD Change Detection Object, Entra ID Issue, Entra ID Object, Entra ID Change Detection Issue and Entra ID Change Detection Object) that exclude known, trusted or accepted issues and objects from risk scores and reduce alert noise. [identity-protection.admin-portal:itdr-config-safelists] ([How the AD and Entra ID issue, object and change detection safelists work](kb:identity-protection.safelists)) Endpoint Settings has Agents, Agent Configuration and Agent Update Groups; Server Agent Settings has Domains, Agents, Agent Update Groups and Configuration. [identity-protection.admin-portal:itdr-config-agent-settings]

## Tables and queries

Table data in the ITDR Admin Portal can be exported or downloaded as a CSV or JSON file using the Export as CSV, Download as CSV or Download as JSON options in the Actions drop-down menu. [identity-protection.admin-portal:table-export] Copy Table in the Actions menu copies chosen columns from tables, up to 1,000 rows, to the clipboard for pasting into CSV, JSON, Notepad or other compatible files. [identity-protection.admin-portal:table-copy-limit] The Using Tables page names Detailed Findings and Recommendations, Change Detection and Scan Reports as pages where data is shown in tables. [identity-protection.admin-portal:table-where-used] The ITDR query-language page lists Filter in Dashboard, Conditions in Orchestration Rules and Event Filters in SIEM Integrations as modules where it builds custom conditions or filters; its I-flag note still mentions ThreatParse rules in Miragemaker as a place the flag can be used. [identity-protection.admin-portal:query-modules] The query editor is on the Investigate dashboard (interactive query builder at the top), in the Rule Details window reached from Orchestrate > Rules, and in the SIEM integration details window reached from Orchestrate > SIEM Integrations. [identity-protection.admin-portal:query-editor-locations]

## Advanced Settings and logs

The ITDR Advanced Settings page is described as letting you view license details, manage event logs and configure a retention policy for logs; its Manage Events & Evidence tab exports events as serializable JSON for a From/To window and deletes either all events or only those marked as safe for a window. [identity-protection.admin-portal:advanced-settings-tabs] The ITDR License tab shows Client, Plan, Expiration, Retention Policy, Decoys (configured out of the plan total), Landmine Users (configured out of the plan total) and Admin Portal Version. [identity-protection.admin-portal:license-tab-fields] The ITDR retention policy defaults to 365 days and can be reduced; events marked as safe are retained for 7 days and Okta system logs for threat detection for 14 days, and the page says the retention period of those events or logs cannot be modified. [identity-protection.admin-portal:retention-values] The Evidence file and internal-component sections of the Deception page are not on this page [gap:identity-protection.admin-portal:advanced-settings-evidence].

The ITDR Logs page (Settings > Logs) has Audit Logs (exportable as CSV, with Timestamp, Username, Module and Description), error logs (with Timestamp, Category, Module, Message, Metadata, Error, Count and Actions) and Debug Logs (downloadable for the last 2 hours, 24 hours or 7 days). [identity-protection.admin-portal:logs-page-tabs] Requesting debug logs creates an archive for the chosen time range, which is ready to download after a couple of minutes. [identity-protection.admin-portal:debug-log-download]

## Investigate

On the ITDR Investigate page, alerts can be filtered with queries and predefined time ranges, and the dashboard can be customized by filtering events on level of details and threat level. [identity-protection.admin-portal:investigate-dashboard-filters] The ITDR copy says the details pane is unique for each Zscaler ITDR object (Zscaler ITDR Admin Portal, Decoy Connector, Decoy Group and Decoy) and attacker; the object pane shows triggered ThreatParse rules and attacker risk scores. [identity-protection.admin-portal:investigate-details-pane-objects] The attacker details pane shows the attacker's risk score, first and last event timestamps, triggered ThreatParse rules and any triage incidents from the endpoint if available, and its Actions menu can contain, block or delete threats or mark an attack as safe. [identity-protection.admin-portal:investigate-attacker-pane] The ITDR Actions menu can forward an attacker's details to CrowdStrike Falcon Insight, Amazon GuardDuty, Threat Protection with Okta AI, Zscaler Internet Access (ZIA) and Zscaler Private Access (ZPA), after the settings for these tools are enabled on the Containment page. [identity-protection.admin-portal:investigate-containment-targets] Marking an event as safe removes the attacker from the default view; when an attacker is marked as safe it can take up to an hour to show; marking an attacker's IP address as safe marks all past events from it as safe while new events from that IP are still generated and displayed; Show marked as safe is enabled from the Select Query drop-down menu. [identity-protection.admin-portal:investigate-mark-safe-behavior] Deleting an attacker removes all previously triggered events related to it and permanently deletes the ThreatParse data linked to it, while the tags associated with the attacker are retained; the blocklist option redirects to the Blocklist page to create a rule. [identity-protection.admin-portal:investigate-delete-attacker]

In the ITDR copy, View Extended Details shows the tabs ThreatParse (attack details mapped to MITRE ATT&CK with a risk score), Chronology (temporal overview and heatmap) and Event Logs. [identity-protection.admin-portal:investigate-extended-details-tabs] Whether the Deception tabs for network and evidence exist in ITDR is not stated [gap:identity-protection.admin-portal:extended-details-tabs]. The ITDR extended-details intro says attacker activities are recorded as events and that you can evaluate the attacker's actions and how they interact with the Zscaler ITDR elements, naming endpoint credentials and Entra ID. [identity-protection.admin-portal:investigate-extended-details-elements] The Chronology page has an events-over-time graph and an activity-over-a-week heatmap in which a brighter spot represents a high volume of activity. [identity-protection.admin-portal:investigate-chronology-threatparse]

On the ITDR Event Logs page, Delete All removes at most 100K events at a time, deleting selected events works well when there are fewer than 100 events, and Test Rule accepts a maximum of 10 selected events. [identity-protection.admin-portal:investigate-event-log-delete-and-test] ITDR Event Logs can be exported as Attacker Summary in JSON or CSV, Events as JSON, Event Fields as JSON, Events as CSV, STIX v1.2, STIX v2.1 and Snort Rules, and up to 50 columns can be added to the table. [identity-protection.admin-portal:investigate-event-log-export-and-columns] The ITDR Event Logs basic event information lists Timestamp, Attack Type, Attacker ID (the attacker's IP address), Decoy Name, Decoy Group, Decoy Port, Decoy Connector and Kill Chain Phase. [identity-protection.admin-portal:investigate-event-log-columns]

What to check:
1. For the notification categories a user can enable, the ITDR window's License and Security Alerts rather than the Deception categories.
2. For which containment targets the ITDR Actions menu lists, the five named on the Controlling Threat Events page.
3. For the tabs on View Extended Details in ITDR, the three the page lists.
4. For where users are added when Authentication Service is enabled, the ITDR page's Directory > Users path.

Sources disagree (name both sides):
- One page says ITDR settings are at Identities > ITDR Config with detailed configuration managed in the legacy ITDR Admin Portal; another says Identity Protection is managed through the SecOps Settings page, with some links redirecting to the legacy experience for deeper configuration. [divergence:identity-protection.admin-portal:itdr-config-where-managed]
  - zscaler-help: The ITDR Config page is on the SecOps platform, but the detailed configuration is managed in the legacy ITDR Admin Portal.
  - zscaler-help: The SecOps Settings page adjusts scan configurations; only when deeper configuration is required do certain links redirect to the legacy ITDR experience.
  Impact: The pages name different places (ITDR Config page versus Settings page) and different extents of what stays in the legacy portal (detailed configuration versus deeper configuration reached through some links); neither says whether they are the same page or how the two scopes compare.
