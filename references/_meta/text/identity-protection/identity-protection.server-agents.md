# What the ITDR Admin Portal help describes for server agents on domain controllers: domains, session tracking, password analysis, remediation, threat detection, install and update groups (identity-protection.server-agents)
Also called: server agent; itdr server agent; server agent settings; domain controller agent; password analysis; session tracking

The ITDR server agent monitors Active Directory users and computer activities; session tracking can be enabled in the server agent policy to monitor logon activities, and password analysis to identify compromised or weak passwords by checking hashes against leaked databases, common patterns and custom dictionaries while monitoring for password reuse or rotation. [identity-protection.server-agents:purpose] Server agents are installed on domain controllers; Download Agent offers Windows (EXE) and Windows (MSI) installation types and downloads the latest version. [identity-protection.server-agents:download-installer] Whether ITDR needs agents beyond Client Connector differs between pages [divergence:identity-protection.server-agents:additional-agents].

## Server Agent Settings

Server Agent Settings (Settings > Server Agent Settings) has Domains, Agents, Agent Update Groups and Configuration tabs. [identity-protection.server-agents:settings-tabs] The Domains tab lists each domain with Total DCs (domain controllers assigned), Active, Inactive, Not Installed (domain controllers without a server agent) and Capabilities Installed. [identity-protection.server-agents:domains-table] The server Agents table lists System Name, Domain Name, First Seen, Last Seen, OS Version, Version, Server Type (the type of AD server), DC Type (the type of domain controller) and IP. [identity-protection.server-agents:agents-table] On the server Agents tab, Show all agents shows inactive server agents along with active ones when enabled and is disabled by default. [identity-protection.server-agents:show-all-agents] The Agents tab actions include Uninstall All Agents, Uninstall Selected, Delete Selected and Trigger Logs (fetching the activity log data used for troubleshooting), and an error log icon is available for critical events. [identity-protection.server-agents:agent-actions] The Configuration tab takes password keywords, up to 100 entries typed in, with a text file upload required for more than 100 entries. [identity-protection.server-agents:configuration-keywords] The server Agent Update Groups tab enables phased updates, adds groups, and lists each group's Name, Selection Criterion, Update Progress (the total number of server agents updated in the group) and Update Enabled (checkmark for enabled, X for disabled). [identity-protection.server-agents:update-groups-table] When a server agent counts as inactive is not stated [gap:identity-protection.server-agents:inactive-definition].

## Per-domain features

- **Session tracking.** Session tracking monitors logon activities for privileged accounts in the domain, and once enabled its details are viewed on the AD User Details page. [identity-protection.server-agents:session-tracking]
- **Password analysis.** Password analysis is enabled per domain with Enabled, an Agent chosen from the drop-down menu and a scan Frequency of Weekly, Monthly or Quarterly, and its details are shown in the Password Analysis dashboard. [identity-protection.server-agents:password-analysis] What the Agent selection changes is not stated [gap:identity-protection.server-agents:password-analysis-agent].
- **Remediation.** Running remediations for risky AD identities through a server agent requires remediation to be enabled on the server agent domain, and only one server agent can be selected to run the remediation action. [identity-protection.server-agents:remediation-enable] Which remediation actions the server agent runs is not stated on the page [gap:identity-protection.server-agents:remediation-actions].
- **Threat detection.** The domain Threat Detection dialog offers Enable All, Brute Force, Malicious Dpapi Usage, Suspicious Group Additions, Suspected Kerberoasting, Suspected Kerberoasting (Encryption Downgrade) and Suspected Asrep Roasting options. [identity-protection.server-agents:threat-detection-options-a] The domain Threat Detection dialog also offers Suspicious Adminsdholder Modification, Suspected Dcsync, Suspected Dcshadow, Account Reconnaissance, Password Spray, External IP Authentication (DC) and Kerberos Service Ticket Anomaly options. [identity-protection.server-agents:threat-detection-options-b] Kerberos Service Ticket Anomaly detection requires identifying abnormal events by first establishing a baseline of normal behavior for two weeks. [identity-protection.server-agents:kerberos-ticket-baseline] Server-agent threat detection enriches an attacker and target user with group memberships, Entra role assignments, basic info, AD and Entra posture checks, credential exposures, password analysis results and past threat detections. [identity-protection.server-agents:threat-detection-context]

## Managing and installing server agents

The server agent registration token registers a domain controller with the ITDR Admin Portal during installation, after which a session key is generated for subsequent requests; regenerating the token means the old token can no longer install a server agent, so any automated installation should be stopped first. [identity-protection.server-agents:registration-token] Server agent configuration can be exported as CSV or JSON for all agents or filtered agents, filtered by system, OS version, server agent version or IP address; two export options export only the agents shown in the table, which displays only the active server agents, and Show All Agents in the Actions menu is the option to include inactive agents. [identity-protection.server-agents:export-config] After Actions > Trigger Logs on a server agent, a Download icon appears under the Actions column after 15 minutes, and the logs download as a compressed .zip file. [identity-protection.server-agents:agent-logs] Server agents can be uninstalled individually, selected, or all at once; the server agent tries to remove policies from the servers for three days before uninstalling itself. [identity-protection.server-agents:uninstall] Deleting a server agent removes its entry from the ITDR Admin Portal only and does not uninstall the agent, and server agents cannot be deleted if their Last Seen value is under 7 days. [identity-protection.server-agents:delete]

Domain controllers for a server agent need Windows Server 2012 R2 or later (active or Read-only Domain Controller), .NET Framework 4.8 or later, 4 GB free memory, 500 MB disk space (5 GB for Password Analysis), 256 Kbps bandwidth (1 Mbps for Password Analysis), and HTTPS port 443 connectivity to ib.smokescreen.io and the Zscaler Deception Admin Portal. [identity-protection.server-agents:install-prerequisites] Which service each egress host carries is not stated [gap:identity-protection.server-agents:egress-hosts]. The server agent installer parameters are /qn (silent mode, required), /CMC=<instance name> (hostname of the ITDR Admin Portal, required), /REGKEY=<Registration Token> (required) and /PROXIES=<Proxy String> (optional, comma-separated with no white spaces). [identity-protection.server-agents:install-parameters] The server agent tries the PROXIES list left to right; if all fail it tries the SYSTEM user's proxy and then a direct no-proxy connection; credentials with special characters must be URL-encoded. [identity-protection.server-agents:proxy-order] To use a PAC file the server agent is directed to a URL where the PAC file is hosted, in the form http://<ip/host>/<pacfile>.pac. [identity-protection.server-agents:proxy-pac]

## Update groups

A server agent update group selects by Hostname List (exact match) or Hostname RegEx, and Zscaler recommends an enabled catch-all "All systems" group with .* after testing so all servers are upgraded. [identity-protection.server-agents:update-group-criteria] Phased updates are enabled or disabled with the Enable Phased Updates and Disable Phased Updates buttons, and enabling stops any automatic updates for agents that are not part of the groups. [identity-protection.server-agents:phased-updates] On the server Agent Update Groups page, the page says to click the checkmark icon under the Actions column to disable phased updates for a group and the X icon to enable them. [identity-protection.server-agents:update-group-icons] What the Update Enabled icon shows after a click is not stated [gap:identity-protection.server-agents:update-icon-result]. The endpoint agents' update groups are in [What the ITDR Admin Portal help describes for endpoint agents: Endpoint Settings, agent configuration, update groups, safe processes and the Client Connector for Windows deployment](kb:identity-protection.endpoint-agents).
