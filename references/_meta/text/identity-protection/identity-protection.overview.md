# Identity Protection (ITDR): how it reads identity stores and endpoints, what it needs, and what can be automated (identity-protection.overview)
Also called: identity protection; itdr; identity threat detection and response; zscaler itdr; ad posture scan; entra id posture scan; credential exposure scan; identity threat detection; identity protection api

Identity Protection detects anomalous activity such as compromised credentials, suspicious logins and sensitive data theft, and gives continuous, unified visibility into identity risks; its architecture page calls it an identity threat detection and response (ITDR) solution integrated with the SecOps platform. [identity-protection.overview:what-it-is] It is part of the Zscaler SecOps platform and works alongside UVM, AEM and SOC Workbench. [identity-protection.overview:secops-part]

**Features.** Its listed features are detecting identity risks (compromised accounts, suspicious sign-ins, leaked credentials, authentication anomalies), containing identity attacks, fixing weak passwords, exposed credentials and excessive privileges, a single identity view across sources, and custom dashboards and reports. [identity-protection.overview:features]

## Components and what each needs

Its key architecture components include an Identities App in the SecOps platform for management and analysis, an ITDR Connector that streams ITDR data into the data fabric, the Data Fabric Cluster that processes raw data, and the Zero Trust Exchange, whose access policy controls block compromised users when an identity attack is detected. [identity-protection.overview:components] Through the Zero Trust Exchange, access policy controls block compromised users when an identity attack is detected, and the ZIA and ZPA integration adds visibility, enrichment and containment. [identity-protection.overview:zte-containment] Connectors ingest posture scans, change detections, alerts and identity records, and integrate with identity providers such as Okta and Microsoft Entra to consume identity data directly from the customer's IdP. [identity-protection.overview:connectors]

- **Active Directory.** An AD posture scan targets a named AD domain and requires Zscaler Client Connector on a domain-joined Windows machine; it runs LDAP queries to map schema, users, computers, OUs and other objects, then checks them for misconfigurations and vulnerabilities. [identity-protection.overview:ad-posture] The what-is page says an AD domain scan can be assigned to a Zscaler Client Connector or an endpoint agent, and after the scan the result is viewed on the Identity Posture dashboard, where the assessment results include a domain risk score, focus areas, a list of the riskiest users and computers, and MITRE ATT&CK kill chain mapping. [identity-protection.overview:scan-assignee-and-results] [In the release note dated June 23, 2025: the dashboards Identity Posture, Change Detection, Entra ID and Identity Risk Summary were renamed Active Directory Posture, Active Directory Change Detection, Entra ID Posture and Risk Summary.](kb:identity-protection.release-notes:2025-06-23-dashboard-renames) [Active Directory posture in Identity Protection: dashboard, issues, roadmap, reports, remediation, privileged account tracking and password analysis](kb:identity-protection.ad-posture) [Scan setup and results: the AD posture scan, AD Privileged Account Tracking and the endpoint credential exposure scan](kb:identity-protection.posture-scans)
- **Entra ID.** An Entra ID posture scan connects the Entra ID tenant and uses a deployment script that creates the needed resources there (resource group, app, storage account, service principal) and enables diagnostic settings to enable change detection using logs; the audit logs are analyzed and the results appear in the Identities app. [identity-protection.overview:entra-posture] [Entra ID posture in Identity Protection: dashboard, issues, roadmap, reports and remediation](kb:identity-protection.entra-posture) [How an Entra ID tenant is connected to ITDR: deployment script, permissions, certificates and scan setup](kb:identity-protection.entra-connection)
- **Okta.** The Okta integration enriches identity metadata, detects real-time changes on an Okta identity, and can act on it, for example activate or suspend a user or clear its sessions. [identity-protection.overview:okta]
- **Change detection.** Identity change detection monitors critical changes in AD domains and Entra ID tenants in real time; in addition to real-time alerting it gives remediation guidance as video tutorials, commands and scripts. [identity-protection.overview:change-detection] How fast changes are detected differs between the pages [divergence:identity-protection.overview:change-detection-timing]. The what-is page says identity change detection checks run every 15 minutes from Zscaler Client Connector installed on the endpoints or landmine agents for the AD domain, and that detected changes are marked as having a good or bad impact. [identity-protection.overview:change-check-cycle] [Active Directory and Entra ID change detection in Identity Protection: monitored issues, cycle, Impact values and remediation](kb:identity-protection.change-detection) [How ITDR threat detection policies, custom change detection policies and email notifications are configured](kb:identity-protection.detection-policies) [How the AD and Entra ID issue, object and change detection safelists work](kb:identity-protection.safelists)
- **Endpoints.** The credential exposure scan checks endpoints for identity material stored locally, such as usernames, passwords, API keys, SSH keys and certificate files. [identity-protection.overview:credential-exposure] Whether this scan needs Client Connector is not stated on the current page [gap:identity-protection.overview:credential-scan-agent]. Identity threat detection is enabled as an endpoint policy on designated machines with Zscaler Client Connector installed; detectors such as DCSync, DCShadow and Kerberoasting are enabled through policies, and Client Connector signals Identity Protection when it sees a pattern. [identity-protection.overview:threat-detection] The what-is page names DCSync, DCShadow, Kerberoasting, session enumeration, privileged account access and LDAP enumeration as examples of available threat detectors, and says the security team can use them to identify a threat on the designated endpoint. [identity-protection.overview:detector-examples] [Endpoint Credential Exposure in Identity Protection: dashboard, scan types, cleanup and reports](kb:identity-protection.credential-exposure) [Scan setup and results: the AD posture scan, AD Privileged Account Tracking and the endpoint credential exposure scan](kb:identity-protection.posture-scans)
- **Identity details.** [Identity detail pages and Identity Search in Identity Protection: AD user, Entra ID identity, Okta enrichment and cross-platform search](kb:identity-protection.identity-details)
- **Identities menu.** [The Identity Findings page and finding details drawer in the Identities menu: list columns, widgets, drawer tabs, remediation and safelisting](kb:identity-protection.identity-findings) [The Findings Overview and Remediation dashboards in the Identities menu: widgets, filters, views and PDF export](kb:identity-protection.findings-dashboards) [The Tenants page and tenant details drawer in the Identities menu: list columns, views, drawer tabs and which tenants are shown](kb:identity-protection.tenants) [The Identity Protection Alerts page in the Identities menu: list, bulk update, alert drawer, verdicts and score calculation](kb:identity-protection.alerts)

## Setup, agents and the admin portal

The ITDR step-by-step configuration guide runs in this order: log in to the Admin Portal, configure users and roles, configure single sign-on, configure threat detection policies, integrate with Okta, assess AD posture, assess Entra ID posture, set up the endpoint credential exposure scan, analyze the assessment report, enable change detection, and remediate risky identities and changes. [identity-protection.overview:setup-step-order] The ITDR step-by-step configuration guide says risky AD and Entra ID identities and bad changes can be remediated directly from the ITDR Admin Portal. [identity-protection.overview:remediation-scope] [identity-protection.overview:legacy-redirect] The what-is page lists as a benefit that ITDR integrates with Zscaler Client Connector to unlock new capabilities without the need for additional agents or virtual machines. [identity-protection.overview:no-extra-agents-claim] [identity-protection.server-agents:additional-agents](kb:identity-protection.server-agents:additional-agents)

**SecOps platform guide.** The Step-by-Step Configuration Guide for Identity Protection in the SecOps platform has five steps: Set Up Your Account (sign-in credentials arrive by email once the organization is provisioned), Configure Users & Roles, Assess the Security Threats, Monitor Threats Using Dashboards and Reports, and Remediate Identity Risks. [identity-protection.overview:secops-guide-steps] The SecOps guide's assess workflow is: evaluate overall findings on the Findings Overview dashboard (categorized by severity, type, affected tenants, identity providers, remediation ease, exploitability and impacted assets), then view users, tenants, identity findings and alerts. [identity-protection.overview:secops-guide-assess-workflow]

## Dashboards and investigation

The Risk Summary dashboard shows a unified risk score of 0 to 100 (100 is critical) for a chosen AD domain and for a chosen Entra ID tenant, with the top 3 critical issues in each, plus the top 3 critical exposed endpoint credentials. [identity-protection.overview:risk-summary-widgets] The Risk Summary dashboard maps risks to MITRE ATT&CK techniques on a kill chain, and its risk at-a-glance widgets list the top 10 AD users and computers and the top 10 Entra ID identities with the highest risks. [identity-protection.overview:risk-summary-attack-mapping] How the 0 to 100 score is computed is not stated [gap:identity-protection.overview:risk-score-method].

The Investigate dashboard shows all events generated by the Zscaler ITDR Admin Portal and can be filtered with built-in or custom queries. [identity-protection.overview:investigate-dashboard] The Active Directory Threat Detection filter applies this query to the Investigate dashboard, selecting itdr events and endpoint events with sub_type cbf and cbf.is_ad_decoy_credential true, or sub_type kerberoast or ad_enumeration. [identity-protection.overview:ad-threat-detection-filter]

## Automation

No vendored client covers Identity Protection or ITDR: the Go and Python SDKs, the Terraform providers, the Ansible collections, the MCP server, the OneAPI Postman collection and the captured Automate contract have no such service; the MCP server's ZIdentity tools manage users and groups, not identity risk. [identity-protection.overview:no-client-surface] Identity reports go through the platform's Reporting API ([A saved report can be exported programmatically through the Reporting API, a GraphQL-based interface that exports the data to an AWS S3 bucket or returns a downloadable link; the client authenticates for an access token, submits a request to start the report and polls for its status.](kb:portfolio.secops-platform:reporting-api)); any other API, and parity with legacy ITDR, is open [gap:identity-protection.overview:api-and-legacy-parity].

What to check:
1. For a missing AD posture result, whether Client Connector is installed on a domain-joined Windows machine for that domain.
2. For missing identity threat detections, whether the threat detection endpoint policy is applied to designated machines that run Client Connector, and which detectors it enables.
3. Which timing the page being read gives for change detection before stating how quickly a change is detected.
4. Whether a setting is configured in the current SecOps Settings page or in the legacy ITDR experience it links to.

Sources disagree (name both sides):
- The architecture page describes change detection as real-time monitoring; the change detection articles describe near real-time visibility on a 15-minute cycle. [divergence:identity-protection.overview:change-detection-timing]
  - zscaler-help: Identity Protection provides real-time monitoring of critical changes in AD domains and Entra ID tenants.
  - zscaler-help: AD Change Detection gives near real-time visibility, from an AD scan that runs every 15 minutes.
  - zscaler-help: The page itdr-understand-zscaler-itdr-architecture (Understand the Zscaler ITDR Architecture) says ITDR provides real-time monitoring of critical changes in AD domains and Entra ID tenants.
  Impact: The pages give different descriptions of how quickly a change is detected (real-time against near real-time on a 15-minute cycle) and do not say how they reconcile.
