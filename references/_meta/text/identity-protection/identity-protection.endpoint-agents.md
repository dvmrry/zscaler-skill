# What the ITDR Admin Portal help describes for endpoint agents: Endpoint Settings, agent configuration, update groups, safe processes and the Client Connector for Windows deployment (identity-protection.endpoint-agents)
Also called: endpoint settings; endpoint agent; itdr endpoint agent; agent update groups; safe processes; ZSAITDR

Endpoint Settings is described as managing agent details and safe processes, customizing agent configuration and configuring phased agent updates, and as enabling an LDAP-based AD scan and a credential exposure scan on endpoints. [identity-protection.endpoint-agents:purpose] The Endpoint Settings page states that the endpoint agent's CPU consumption is capped at 25%. [identity-protection.endpoint-agents:cpu-cap] The Deception copies of these pages are [Endpoint settings (installer, lure refresh, update groups, safe processes) and Admin Portal settings (audit, error and debug logs, license, event and evidence export and delete, retention)](kb:deception.endpoint-settings) and [Landmine agent and agentless: install, requirements, proxies, management and OS feature support](kb:deception.landmine-agents); the ITDR facts are below.

## Agents

The Agents table lists, for each system, System Name, System User Name, Client Connector User, Matched Policies (threat detection policies applied on the endpoint), First Seen (when the agent was installed), Last Seen (when it last connected to the ITDR Admin Portal), OS Version, Version, the endpoint credential exposure policy name and status, and IP. [identity-protection.endpoint-agents:agents-table-columns] The Endpoint Credential Exposure Policy Status column shows values such as Completed Successfully, Completed Partially, Failed, Processing and Not Started, and clicking Failed or Completed Partially opens the error logs, which show Timestamp, Type, Message and Detail. [identity-protection.endpoint-agents:credex-policy-status] Inactive agents are endpoint agents with a last check-in time older than 7 days; the Show all agents option in the Actions menu is disabled by default and, when disabled, only active agents are displayed. [identity-protection.endpoint-agents:show-all-agents] The Agents tab offers a Troubleshooter download for managing endpoint agents with CLI commands, and error logs are generated when a critical event occurs on the agent, with a View Error Logs icon showing the latest log entry. [identity-protection.endpoint-agents:troubleshooter-error-logs] Endpoint agent configuration details can be exported as CSV or JSON for all agents or filtered agents; the all-agents options export only the agents shown in the table, so Show all agents must be selected to include inactive agents, and the filters cover system name, user, policy, operating system version, ITDR Admin Portal version and IP address. [identity-protection.endpoint-agents:export-config] The threat detection policy details view for a system shows the policy name and the status (True if enabled, False if disabled) of the AD threat detection modules DCSync, DCShadow, Zerologon, Session Enumeration, Monitored Privileged Accounts, Kerberoast Detection and LDAP Detection. [identity-protection.endpoint-agents:policy-details-ad-modules] Triggering logs from Actions > Trigger Logs makes a Download icon appear under the agent's Actions column after a few minutes, and the logs download as a compressed .zip file. [identity-protection.endpoint-agents:agent-logs-download] Uninstall makes the agent remove the policies from the endpoint, trying for up to three days, before uninstalling itself; Force Uninstall removes the policies on a best-effort basis and then uninstalls itself. [identity-protection.endpoint-agents:uninstall-modes] Endpoint agents cannot be deleted if their Last Seen value is less than 7 days. [identity-protection.endpoint-agents:delete-agent]

## Agent configuration

The Installer Customizations section sets the endpoint agent service Name (default ZSAITDR), Display name (default Zscaler ITDR) and Description, to prevent the agent from being fingerprinted; the service name should be unique and existing service names checked beforehand. [identity-protection.endpoint-agents:installer-defaults] Auto-Cleanup Duplicate Agents deletes endpoint agents with duplicate hostnames from the ITDR Admin Portal, retaining the most recently connected hostnames and those connected for less than 7 days; agents deleted this way are not uninstalled from the system. [identity-protection.endpoint-agents:auto-cleanup]

## Agent update groups

The Agent Update Groups table lists each group's Name, Selection Criterion, Update Progress (the total number of agents updated in the group) and Update Enabled (X icon for disabled, checkmark icon for enabled). [identity-protection.endpoint-agents:update-group-table] An agent update group selects endpoint agents by Hostname List (exact match with the listed hostnames) or Hostname RegEx (match against a regular expression), and Zscaler recommends an enabled catch-all "All systems" group with the expression .* after testing so all endpoints are upgraded. [identity-protection.endpoint-agents:update-group-criteria] Enable Phased Updates on the Agent Update Groups tab stops any automatic updates for endpoint agents that are not part of a group; group update status downloads as CSV and a group's hostnames export as a TXT file. [identity-protection.endpoint-agents:phased-updates-effect] On the endpoint Agent Update Groups page, the page says to click the X icon under the Actions column to disable phased updates for a group and the Checkmark icon to enable them. [identity-protection.endpoint-agents:update-group-icons] The server agents' update groups are in [What the ITDR Admin Portal help describes for server agents on domain controllers: domains, session tracking, password analysis, remediation, threat detection, install and update groups](kb:identity-protection.server-agents).

## Safe processes

The Safe Processes table lists Name, Enabled, Executable File Path (absolute), Executable File Regex, Executable File Hash (for example md5, sha1 and sha256), Certificate Issuer, Certificate Serial, Certificate Thumbprint and Type, where internal safe processes carry an Internal label; internal ones are predesignated by Zscaler ITDR and can be shown or hidden. [identity-protection.endpoint-agents:safe-process-table] A safe process takes a unique Name, a Selection Type of Executable File Path (absolute) or Executable Path Regex, and an executable file hash, certificate issuer, serial and thumbprint; marking trusted processes as safe prevents generating false positives. [identity-protection.endpoint-agents:safe-process-configure] Regular expressions can be used for path values when the processes to be marked safe have names with a predictable string of characters, such as a version number; the page's regex example is *mcafee.*\.exe. [identity-protection.endpoint-agents:safe-process-regex-use] For internal safe processes only enabling or disabling is supported, and internal safe processes cannot be deleted. [identity-protection.endpoint-agents:safe-process-internal] Whether the process-tree option and detection types of the Deception safe-process page exist here is not stated [gap:identity-protection.endpoint-agents:safe-process-controls].

## Deploying with Zscaler Client Connector for Windows

The Client Connector deployment page states that ITDR uses Deception configuration because there is no separate service entitlement for ITDR in Zscaler Client Connector, and that there is no separate ITDR UI in the Client Connector Portal. [identity-protection.endpoint-agents:cc-no-separate-entitlement] The prerequisites for deploying ITDR with Client Connector for Windows are SSO configured in ZIA, Client Connector at 4.3.0.264, 4.4.0.383 or 4.5.0.344 or later, and ITDR capabilities enabled on Client Connector by contacting the Zscaler Account team. [identity-protection.endpoint-agents:cc-prerequisites] Step 1 says to enable Zscaler Deception Enabled by Default in the Client Connector Portal to enable ITDR for all Client Connector users upgraded to 3.9 or later for Windows, or to disable it and select a group from the User Groups drop-down menu to enable ITDR for a specific group of users. [identity-protection.endpoint-agents:cc-enable-default-version] Which Client Connector version applies differs within the page [divergence:identity-protection.endpoint-agents:cc-minimum-version]. The Deception copy of the Client Connector for Windows deployment page says to enable Deception for users upgraded to Deception version 4.6 or later for Windows. [identity-protection.endpoint-agents:deception-cc-version]

The Client Connector prerequisites require outbound HTTPS access from the proxy and/or firewall to the ITDR Admin Portal on port 443 (<your_subdomain>.illusionblack.com) and to dwv281inkfqg3.cloudfront.net on port 443. [identity-protection.endpoint-agents:cc-egress] What each egress host carries is not stated [gap:identity-protection.endpoint-agents:egress-hosts]. Step 2 customizes the endpoint installer Name, Display Name and Description in the ITDR Admin Portal under Settings > Endpoint Settings > Agent Configuration to prevent fingerprinting, and step 3 says to click Zscaler Deception in the left-side navigation and click Sync if the Zscaler Deception installer settings (Name, Display Name and Description) shown on that page do not match the values entered. [identity-protection.endpoint-agents:cc-installer-sync] Step 4 requires the Logout Password, Exit Password and Password to access Deception Settings in the Windows policy, and step 5 verifies the configuration by entering that password in Advanced Settings, after which the Service Status is Running. [identity-protection.endpoint-agents:cc-policy-verify]
