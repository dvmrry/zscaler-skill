# Identity detail pages and Identity Search in Identity Protection: AD user, Entra ID identity, Okta enrichment and cross-platform search (identity-protection.identity-details)
Also called: ad user account details; entra id identity details; identity search; identity details; threatparse

**AD user details.** The AD user Summary tab shows Password Reuse Detected as the number of other AD accounts sharing the affected user's password, excluding the affected user. [identity-protection.identity-details:ad-user-password-reuse] To view Okta account details on the AD user page, ITDR must be integrated with Okta and the user must exist in Okta; if the user does not exist in Okta, the Okta tile shows No Data. [identity-protection.identity-details:okta-enrichment] The Actions menu on the AD user page offers Contain with ZPA, Contain with ZIA, Suspend, Unsuspend, Activate, Deactivate, Reset Password, Clear User Sessions and Reset Authenticators; Deactivate removes access to apps authenticated via Okta. [identity-protection.identity-details:okta-actions] Okta event severity is Debug, Info, Error or Warn, and event result is Allow, Challenge, Deny, Failure, Skipped, Success or Unknown. [identity-protection.identity-details:okta-event-values] Okta system logs shown for threat detection are retained for 14 days and then permanently deleted; the retention period cannot be modified. [identity-protection.identity-details:okta-log-retention] ThreatParse is a technology built into ITDR that reconstructs attacks in natural language by translating log information into plain English, linking it to MITRE ATT&CK and including risk scores assigned to attackers. [identity-protection.identity-details:threatparse] For each threat, the ThreatParse details page shows a description, attack examples, mitigations, the MITRE ATT&CK ID and tactic, an event occurrence summary and attacker information such as the username and password submitted. [identity-protection.identity-details:threatparse-details-page] The ITDR integration with ZIA and ZPA works with SCIM user provisioning and authentication method only. [identity-protection.identity-details:access-risk-scim] Session tracking can be enabled in the server agent policy to monitor logon activities for all AD administrators and privileged accounts. [identity-protection.identity-details:session-tracking]

**Entra ID identity details.** The Entra ID identity details page shows MFA status as Is Capable, Is Registered, Methods Registered and Default Method; the last two show no data if MFA methods are not configured. [identity-protection.identity-details:entra-identity-mfa] The Entra ID identity details page shows User Type (Member or Guest), a View Roles link to Entra roles and Azure RBAC built-in or custom roles, and on-premises AD details including Security Identifier and Sync Enabled. [identity-protection.identity-details:entra-identity-fields] The Entra ID identity details page shows Change Data, the details of a detected change such as the operation name, caller IP address, data source information and role details. [identity-protection.identity-details:entra-change-impact-and-raw]

**Identity Search.** Identity Search requires an AD or Entra ID posture scan with attribute collection enabled; Okta integration is required to correlate Okta identities. [identity-protection.identity-details:identity-search-prerequisites] Identity Search is enriched by an endpoint credential exposure scan and by a threat detection policy. [identity-protection.identity-details:identity-search-enrichment] Identity Search searches AD, Entra ID and Okta identities and filters by AD, Entra ID, Okta, Is Privileged, MFA not enabled and Credential Issues; results download as CSV or JSON. [identity-protection.identity-details:identity-search-filters] The Identity Search identity details show Recent Changes as the total number of recent active changes detected in the last 7 days. [identity-protection.identity-details:identity-search-recent-changes] The Identity Search identity details list exposed endpoint credentials for AD identities, and a Severity field takes the values Critical or High. [identity-protection.identity-details:identity-search-credentials] Retention of ITDR or posture-scan data is not stated [gap:identity-protection.identity-details:posture-data-retention].
