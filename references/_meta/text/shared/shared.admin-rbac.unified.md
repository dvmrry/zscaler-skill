# Unified RBAC: Admin Console roles, access levels, permission categories, scopes, assignments and obfuscation (shared.admin-rbac.unified)
Also called: unified rbac; unified role-based access control; experience center roles; admin console role management; SuperAdmin ReadOnly roles; unified role assignments; unified obfuscation

Unified Role-Based Access Control (RBAC) is in limited availability and is reached through the Zscaler Account team. [shared.admin-rbac.unified:limited-availability] Unified RBAC roles manage access to pages and features in the Zscaler Admin Console with granular permissions, and each role can take an optional scope that specifies to what, when or where it applies; the Role Management page is at Administration > Role Management > Role Management. [shared.admin-rbac.unified:roles-and-scope]

**Predefined roles and the role list.** Two predefined roles exist by default: SuperAdmin (full access to all permissions) and ReadOnly (view-only access to all permissions); the role list marks a role Custom when the organization created it and Predefined when the Zscaler service created it. [shared.admin-rbac.unified:predefined-roles] The role list shows per role the number of permissions, scopes and assignments (admins the role is assigned to); not all permissions can be assigned a scope, roles can be filtered by the permissions they manage, and roles with no assignments can be hidden. [shared.admin-rbac.unified:role-list] Only roles with no assignments can be deleted, and a duplicated role is created with no assignments: existing assignments are not copied. [shared.admin-rbac.unified:delete-duplicate]

**Access levels.** For each permission category, subcategory and individual permission a role is granted No Access, View Only or Full Access; a mix within a category shows the category as Mixed, some individual permissions offer only No Access and View Only or only No Access and Full Access, and a category or subcategory menu offers only the options shared by all its individual permissions. [shared.admin-rbac.unified:access-levels] The Create Role page displays permissions only for features the organization has access to. [shared.admin-rbac.unified:only-subscribed-features]

**Permission categories.** The permission categories on the Create Role page are Platform (general settings and preferences for the console, alerts and audit logs), Authentication, Users and Department, API Key Management, Supportability, Dashboards, Private Access, AI, Analytics, Zscaler Cloud Configuration, Digital Experience Configuration, Policy, Integrations, Infrastructure, and Logs and Reports. [shared.admin-rbac.unified:permission-categories] Platform covers Role Management, Admin Management, advanced global settings (including Advanced Policy Settings and IPv6 Configuration), Backup & Restore, Company Information, User Portal AUP, Micro Tenant, Alerts (Internet & SaaS Alerts, Security and UEBA Alerts, Platform Alerts and Digital Experience Alerts) and Audit Logs (Internet & SaaS, Private Access, Client Connector, Experience Center and Role Management). [shared.admin-rbac.unified:platform-permissions] Among the permissions, API Key Management covers the Private Access API Key and the Client Connector Public API; Supportability covers support features, with the page pointing to Enabling Remote Assistance; the Adaptive Access permission manages dynamic risk score permissions; and Integrations covers Microsoft Cloud App Security, Azure Virtual WAN, Internet Access Crowdstrike, Microsoft Defender for Endpoint and Workflow Automation. [shared.admin-rbac.unified:selected-permissions]

**Scopes.** A role's optional scope is one of Locations, Location Groups, Departments, Applications (only with compatible Digital Experience permissions) or Time Duration, from 2 Hours to 48 Hours or Full Access for the role to always be available; Time Duration is available only with compatible Digital Experience permissions and applies only to those permissions. [shared.admin-rbac.unified:scopes] What happens when a Time Duration runs out, and what the Applications scope limits, are not stated [gap:shared.admin-rbac.unified:time-duration-expiry] [gap:shared.admin-rbac.unified:applications-scope].

**Saving and assigning.** Creating, editing, duplicating and deleting a role each end by activating the change. [shared.admin-rbac.unified:activation] Assignments are added to a role after it is created: an assignment selects Users, User Groups or API Clients, then the admin entitlements the role applies to, and the change is activated. [shared.admin-rbac.unified:assignments] How several roles held by one admin combine, and how these roles relate to the per-product roles and to the admin entitlements chosen at assignment, is not stated [gap:shared.admin-rbac.unified:role-combination].

**Obfuscation.** Information can be obfuscated for roles with compatible Internet & SaaS (ZIA) and Digital Experience permissions. [shared.admin-rbac.unified:obfuscation-scope] Obfuscation is enabled on a role's Obfuscation tab with Add Obfuscation, only for roles with Internet & SaaS or Digital Experience permissions that expose obfuscatable information types; the change is saved and activated. [shared.admin-rbac.unified:obfuscation-fields] In the Configure Obfuscation pane, Digital Experience offers Username, Device Name, Wi-Fi Name, IP Address and Location Name, and Internet & SaaS offers Username, Device Name and AI Prompt. [shared.admin-rbac.unified:obfuscation-types] Whether an obfuscated value can be revealed is not stated [gap:shared.admin-rbac.unified:obfuscation-reveal]. The ZIA role model's obfuscation is in [Who sees real user names, device information and Gen AI prompts in ZIA: role obfuscation and auditors](kb:shared.admin-rbac.zia-obfuscation).

**Open.** The role object behind the roles endpoints is unmined [gap:shared.admin-rbac.unified:roles-api-unmined], and only the permission categories and the permissions named here were extracted [gap:shared.admin-rbac.unified:permission-leaves]. What these roles record is in [Admin audit logs across Zscaler products: what exists and how to get it](kb:shared.audit-logs).

Role changes are recorded in the role management audit log: [Experience Center and Role Management audit logs: what is recorded, categories, actions, record fields, lockout, retention, search and export](kb:unified.audit-logs).

What to check:
1. For an admin who cannot open or change a page in the Zscaler Admin Console, the role's access level (No Access, View Only or Full Access) for the permission that covers it, and whether the tenant uses Unified RBAC at all.
2. For a role that cannot be deleted, whether it still has assignments.
3. For an admin who has a role but no access, that the role has an assignment and that the change was activated.
4. For an admin whose Digital Experience access is time-limited, the role's Time Duration scope.
