# ZSDK Private Service Edges, groups, provisioning keys and enrollment (shared.zsdk.private-service-edges)
Also called: zsdk private service edge; zsdk private service edge group; zsdk private service edge provisioning key; zsdk publish ips; zsdk publicly accessible; zsdk private cloud

Private Service Edges register with the ZSDK cloud to download the policies and configuration they enforce, and manage the connections from App Connectors; they are used where Public Service Edges are not conveniently located between users and applications, or to keep application data traffic local for compliance. [shared.zsdk.private-service-edges:registration-and-purpose] Zscaler distributes Private Service Edge images for deployment in enterprise data centers and local private cloud environments (for example VMware). [shared.zsdk.private-service-edges:distribution-forms] A user connecting to a Private Service Edge is located by its public IP address and the country-based policy for the mapped country is enforced; if the Private Service Edge group location is updated for an existing connection, the Public Service Edge uses the old location until its next new connection, and GeoIP configuration override is not supported for Private Service Edges. [shared.zsdk.private-service-edges:location-and-country-policy]

## Connections and addresses

Publish IPs or Domains are what clients and App Connectors use to connect to the Private Service Edge, falling back to the Listen IPs if unspecified; with no Listen IPs configured the Private Service Edge listens on all interfaces. [shared.zsdk.private-service-edges:publish-and-listen-ips] Publish IPs or domains are used mainly to name the ZSDK Private Cloud and find it through DNS, and second when the system uses a static external IP address (for example AWS) that is not part of the Private Service Edge. [shared.zsdk.private-service-edges:publish-ips-use-cases] Added but undeployed Private Service Edges are not listed on the Private Service Edges page, which shows the last known public and private IP addresses of a disconnected one. [shared.zsdk.private-service-edges:undeployed-not-listed]

## Groups

Publicly Accessible determines whether the group's trusted network mapping is also available publicly to users outside those trusted networks. Zscaler recommends Enabled so remote users can reach the Private Service Edge over a public IP address, and Disabled when it has a public IP or a published IP set to the public IP of a SNAT such as a firewall; disabled without a trusted network, the nearest on-premises and roaming users are given its IP address, and the Private Service Edge should be reachable over a public IP address to avoid connectivity issues for remote users. [shared.zsdk.private-service-edges:publicly-accessible] Client Connector Trusted Networks mapped to a Private Service Edge group are used to prioritize Private Service Edges when users connect from those networks. [shared.zsdk.private-service-edges:trusted-networks] The Private Service Edge groups article says groups require disaster recovery to be enabled to ensure business continuity, and that a new group is not needed for every added Private Service Edge. [shared.zsdk.private-service-edges:group-considerations] Whether that requirement squares with disaster recovery being off by default is open [gap:shared.zsdk.private-service-edges:group-dr-requirement]. The Publicly Accessible recommendations overlap for an edge with a public IP address [gap:shared.zsdk.private-service-edges:public-ip-recommendation], and the Client Connector wording is unconfirmed for ZSDK [gap:shared.zsdk.private-service-edges:client-connector-wording]. Disaster recovery itself is in [ZSDK disaster recovery: scope, prerequisites, settings and DNS records](kb:shared.zsdk.disaster-recovery).

## Provisioning keys and enrollment

A Private Service Edge provisioning key is a text string generated when a ZSDK Private Service Edge is added; a prompt for it appears when deploying and it acts as an ID the ZSDK cloud uses to verify the Private Service Edge's authenticity, and it identifies the group the Private Service Edge must deploy to. [shared.zsdk.private-service-edges:provisioning-key-purpose] Private Service Edge provisioning keys let administrators deploy Private Service Edges into the associated group, limit how many times a key is used, view the key utilization count, edit the maximum number of uses and edit the signing certificate used to enroll Private Service Edge certificates. [shared.zsdk.private-service-edges:provisioning-key-capabilities] A Private Service Edge provisioning key is generated with a specified number of times it can be used to deploy Private Service Edges; ZSDK displays the number of times a key is used on the Private Service Edge Provisioning Keys page, and once a key is used the maximum number of times, an administrator can instead associate multiple provisioning keys to a single Private Service Edge group. [shared.zsdk.private-service-edges:provisioning-key-exhaustion] The Private Service Edge Provisioning Keys page lists, per key, Name, Maximum # of Private Service Edges, Provisioning Key Utilization Count, Private Service Edge Group and the copyable Provisioning Key; no filters are applied by default and a key can be downloaded in TXT format. [shared.zsdk.private-service-edges:provisioning-keys-page-columns] A Private Service Edge provisioning key name becomes the prefix of each Private Service Edge enrolled with it, with the nth enrollment numbered (AWS Oregon-1, AWS Oregon-2). [shared.zsdk.private-service-edges:provisioning-key-naming] A Private Service Edge provisioning key is unique to each group, has a maximum reuse count that can be modified after the Private Service Edge is added, and cannot be copied once its utilization count is reached; the signing certificate signs all Private Service Edges deployed with the key. [shared.zsdk.private-service-edges:provisioning-key-rules] The enrollment certificate for a Private Service Edge must have the same root certificate as the ones used to enroll App Connectors and Zscaler Client Connector; the preloaded certificates are Root, Client, Connector and Service Edge, and they are 2,048-bit RSA certificates supporting TLS 1.2 with cipher suite ECDHE-RSA-AES128-GCM-SHA256. [shared.zsdk.private-service-edges:signing-certificate]

A Private Service Edge generates a hardware-fingerprint-encrypted private key and a CSR on first install, authenticates the CSR with its group's provisioning key, and receives a TLS client certificate pinned to its hardware fingerprint; once enrolled it is paired with a single customer account, cannot be enrolled again and must not be cloned. [shared.zsdk.private-service-edges:enrollment-process] Zscaler recommends deploying Private Service Edges in pairs for continuous availability during software upgrades, and the deployment article points to the ZPA Private Service Edge Deployment Prerequisites for sizing and platform requirements. [shared.zsdk.private-service-edges:deployment-pairs]

## History

Release notes date ZSDK Private Service Edges and disaster recovery to April 15, 2025, when Disaster Recovery could be enabled for a Private Service Edge group. [shared.zsdk.private-service-edges:release-history]

What to check:
1. Whether the Private Service Edge group's Publicly Accessible setting matches how users reach it, and whether the edge has a public IP address or a published IP set to a SNAT's public IP, where the recommendations overlap.
2. Whether the provisioning key has reached its utilization count, and whether the enrollment certificate has the same root as those used for App Connectors and Zscaler Client Connector.
3. Whether a Private Service Edge was cloned, since a clone's keys no longer match the virtual hardware fingerprints.

Not known (open gaps):
- Whether a Private Service Edge group must have disaster recovery enabled [gap:shared.zsdk.private-service-edges:group-dr-requirement]: settled by lab-test or support-ticket
- How Publicly Accessible Enabled relates to a Private Service Edge that has a public IP address [gap:shared.zsdk.private-service-edges:public-ip-recommendation]: settled by lab-test or support-ticket. Blocks: answering which Publicly Accessible setting a Private Service Edge with a public IP address should use
- Which client the Zscaler Client Connector wording on Trusted Networks and signing certificates refers to [gap:shared.zsdk.private-service-edges:client-connector-wording]: settled by source-read or lab-test
