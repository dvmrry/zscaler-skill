# How Multi-Tenant Portal partner admins, RBAC role templates and scopes work, and the Edit and Delete steps for portal items (shared.multi-tenant-portal.administration)

**Admins.** Partners can create admin users with different permissions to manage intended tenants or tenant groups; the Admins page can assign or revoke an admin's management of tenants or tenant groups. [shared.multi-tenant-portal.administration:admin-purpose] The Admins list shows a Login ID assigned per the admin's organization domain, the Number of Tenants assigned to the admin, and Actions (preview, edit and delete). [shared.multi-tenant-portal.administration:admins-columns] The Add Admin window takes a Login ID (with a domain chosen from the organization's configured domains, forming a unique email-format login ID), an Admin Name, an Email ID, a Role template, a Cloud, Tenants from the respective cloud, Comments, and a Password confirmed by retyping. [shared.multi-tenant-portal.administration:add-admin-fields] The Comments field for a new admin takes additional notes or information, and its content (the page calls it the description) cannot exceed 10,240 characters. [shared.multi-tenant-portal.administration:admin-comments-limit]

**Roles.** The Multi-Tenant Portal for Partners has RBAC role templates that can allow or restrict access to its function modules, for example full access to Tenants but view-only access to Policy Templates. [shared.multi-tenant-portal.administration:rbac-templates] The Roles page can create customized RBAC templates for the portal's function modules and for the products the portal manages, and assign role templates to admin users. [shared.multi-tenant-portal.administration:role-product-templates] The Roles list has Full Access and View-Only Access columns, where Full Access lists sections the role can access fully and View-Only Access lists sections it can view but not edit. [shared.multi-tenant-portal.administration:roles-columns] The Roles page lets an admin preview the super admin's permissions. [shared.multi-tenant-portal.administration:role-preview] The Add Role window takes a Role Name, Permissions defined for different sections, and a Description. [shared.multi-tenant-portal.administration:role-add-fields] The permission sections and built-in role names are not listed [gap:shared.multi-tenant-portal.administration:role-sections].

**Scopes.** A scope can cover multiple tenants across various clouds and be assigned to specific admins, and admins can view and manage tenants only within their assigned scope. [shared.multi-tenant-portal.administration:scope-definition] The Scopes list shows the number of tenants covered by each scope (No. of Tenants) and Actions to edit or delete each scope. [shared.multi-tenant-portal.administration:scope-columns] A scope covers tenants selected per cloud (the tenant list depends on the cloud selected, and Add Cloud adds more clouds); the Add Scope article says scopes are assigned to one or more admins in the Authentication Service Admin Portal as required. [shared.multi-tenant-portal.administration:scope-create] For partners migrated to Authentication Service, the Authentication Service Admin Portal manages all scope and role assignments, under Administration > Entitlements > Partner Portal. [shared.multi-tenant-portal.administration:scope-auth-service] How scopes are assigned for partners not migrated to Authentication Service is not stated [gap:shared.multi-tenant-portal.administration:scope-assignment-unmigrated].

**Editing and deleting.** The Editing and Deleting Items article, whose examples are configured users and policy templates, says an edit made with the Edit icon is saved with Save or Save & Sync, a deletion through the Edit icon uses Delete & Sync, and a deletion through the Delete icon ends with Confirm. The Managing Roles article ends a role edit with Save and a role deletion with Delete. [shared.multi-tenant-portal.administration:edit-delete-sync] What Sync does and when to choose it is not stated [gap:shared.multi-tenant-portal.administration:sync-meaning].
