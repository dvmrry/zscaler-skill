# ZDX admin roles: predefined and custom roles, permissions, obfuscation and admin scope (shared.admin-rbac.zdx)
Also called: zdx admin; zdx admins; zdx role management; zdx super admin; zdx read-only admin; zdx service desk tier 1; zdx admin scope; digital experience role management; zdx obfuscated user name; zdx default admin

A ZDX admin is a sign-in with a role, which holds the permissions, and a scope, which limits whose data and which settings the admin reaches. Each admin on the ZDX Administrators page has a Login ID (the email address used to log in), a scope (Organization, Location, Applications, or Department), a Login Type (a configured password or SAML), a Password Expired indicator, and a Status of Enabled or Disabled. [shared.admin-rbac.zdx:admin-record] The predefined ZDX roles are ZDX Super Admin (read, add, edit, delete and manage permissions; the default admin account uses it), ZDX Read-Only Admin (read permissions only) and ZDX Service Desk Tier 1 (read permissions to the Users Dashboard and access to the User Search). A predefined role cannot be edited or deleted, an admin with ZDX Super Admin level privileges can create a custom role, and Zscaler recommends adding roles before admins because each admin needs one. [shared.admin-rbac.zdx:predefined-roles] The default ZDX admin has the Organization scope over the entire organization, every additional admin must be assigned a scope, a Location scope can be limited by assigning a Zscaler Location, and a Department scope by assigning a department. [shared.admin-rbac.zdx:scopes]

**Who the admin is.** Zscaler Support sets up a default admin role and sends an email requesting a password reset for it; the default admin role shows all functions of ZDX and is needed to onboard ZDX but is not recommended for day-to-day use, its settings cannot be changed although a role type is still needed to create other admins and role types, and Zscaler recommends creating your own admin user, used as the primary user details for better auditing and tracking; the new role is to pair with the default admin. [shared.admin-rbac.zdx:first-time-provisioning] The first-time provisioning article edits the new role to have the highest level of permissions: Dashboard View Only, Configuration Full, Admin Management Full, User & Device Names Visible, Locations View Only and User Management View Only. [shared.admin-rbac.zdx:first-time-role] On tenants subscribed to Authentication Service, the ZDX Administrators page lists admins as read-only and certain options on the Role Management and Administrators pages are not available because of read-only permissions; ZDX admins can be configured in the Zscaler Admin Console, and the Administrator Management page shows a link to Authentication Service. [shared.admin-rbac.zdx:auth-service-read-only] If the Zscaler-hosted admin database authenticates admins, password expiration can be enabled for all admins logging in to Internet & SaaS and Digital Experience (ZDX); admins can instead be authenticated via SAML against an external admin database, where the service supports identity provider (IdP)-initiated SAML, supports SAML 2.0 and later, and does not enforce password expiration. [shared.admin-rbac.zdx:admin-authentication] An action can be chosen for when SCIM deletes a linked user account: Do Nothing leaves the ZDX admin account in place and Delete Account deletes it as well. [shared.admin-rbac.zdx:scim-delete-action] If a user switches departments or locations, the user's data is reported for the latest configured department or location. [shared.admin-rbac.zdx:reported-department] What the Applications scope limits is open [gap:shared.admin-rbac.zdx:applications-scope].

**Adding and managing admins.** Managing a ZDX admin by adding, editing or deleting needs the Full permission level for Administrator Management. A new admin's Login ID takes the format <admin-name>@<company-name>.com and cannot be overwritten, its role is selected from the available options, and its password must contain at least 10 characters including 1 number, 1 uppercase, 1 lowercase and 1 special character, with no whitespace. [shared.admin-rbac.zdx:add-admin] An admin can view a configured admin outside their own scope and role with the View icon, but with only view permission cannot manage it (for example delete, edit or create). [shared.admin-rbac.zdx:view-outside-scope] If a ZDX admin is created with the same credentials as an existing Internet & SaaS admin, the ZDX credentials override what was created for Internet & SaaS except the Login ID, so the Internet & SaaS password will have changed at the next login there. [shared.admin-rbac.zdx:credential-overwrite] Admins can be added in ZDX who are also admins in Internet & SaaS; with different permissions for the two, certain functions are limited (for example an admin cannot edit their own ZDX role), and Internet & SaaS credentials cannot be used to log in to ZDX (for example, when the organization is not using that service). [shared.admin-rbac.zdx:cross-product-limits]

**Roles.** Where an organization uses Unified Role-Based Access Control (RBAC), administrator roles for ZDX are managed on a different Role Management page; Unified RBAC is a feature in limited availability, reached through the Zscaler Account team. [shared.admin-rbac.zdx:unified-rbac] A ZDX role the admin has Full access to shows the Edit and Delete icon, with View Only access it shows a View icon and cannot be edited or deleted, and the role list describes the information a role can view (Visible) and cannot view (Obfuscated). [shared.admin-rbac.zdx:role-access-icons] Access permissions for some features of a ZDX role depend on the subscription level. [shared.admin-rbac.zdx:tier-dependent-permissions] A ZDX role is given a time duration chosen from a list of hour values that includes 12, 24 and 48 hours; the default is Full Access. [shared.admin-rbac.zdx:time-duration] What the duration limits is open [gap:shared.admin-rbac.zdx:role-time-duration]. The ZDX Service Desk Role is divided into tiers that each allow varying access based on the permissions assigned; Tier 1 has the following permissions, including User Dashboard, and when an admin has access to User Name the admin can access User Search. [shared.admin-rbac.zdx:service-desk-tiers] The OneAPI getting-started page words Tier 1 differently: [ZDX API hosts and sign-in: the OneAPI gateway, the direct ZDX host, and which paths go where](kb:zdx.api.hosts-and-auth). Tiers beyond Tier 1 are not documented [gap:shared.admin-rbac.zdx:service-desk-tiers-beyond-1].

**Permissions in a custom role.** A role's permission for the predefined dashboards and overviews is View Only (all dashboards and overviews) or Custom (specific ones), with a separate choice for the Performance dashboard, Application Overview, Application details, Users Overview, User Details, Incidents dashboard, Probe Assignment system-generated report, ZIA Private Service Edge Health dashboard, Network Intelligence dashboard and Device Events reports. If the Dashboard permission setting is View Only or the UCaaS permission setting is View Only or Full, the ZDX Dashboard and applications can be viewed. [shared.admin-rbac.zdx:dashboard-permission] The permission for device and user information has a Custom choice with specified permissions for User Name, Location, Device Name or IP Address, and one for the device's Wi-Fi Name. If the User Name permission is Visible an admin has access to User Search and can download a CSV table for Software Inventory; if it is Obfuscated the admin has neither. If the Device Name permission is Obfuscated the admin cannot download that CSV table, and location obfuscation occurs on the Users Overview and User Details pages only. [shared.admin-rbac.zdx:obfuscation] An admin cannot configure for users when the User Name permission is set to Obfuscated, and if User Name and Device Information are set to Obfuscated, Diagnostics is not accessible. [shared.admin-rbac.zdx:obfuscation-blocks] If Zscaler Client Connector's Collect Machine Hostname Information or Collect Device Owner Information is disabled, ZDX obfuscates BSSID, SSID, Device Name and hostname. [shared.admin-rbac.zdx:zcc-privacy-obfuscation] The UCaaS permission is Full (manage and view Call Quality applications and Call Quality Meetings pages), View Only (view them but not manage them) or Custom (manage and view specific ones), with separate permissions for Call Quality Configuration pages, Call Quality Meetings pages and Call Quality Applications pages. [shared.admin-rbac.zdx:ucaas-permission] Under the Analytics permission, Full or View Only lets admins view Analytics pages but not manage them and Custom lets them manage and view specific ones; for the QBR page, the System-Generated Reports page and the Zscaler Managed Monitoring page Full or View Only only views, Full on the ZDX Snapshots page manages it, and Full on the Data Explorer page manages the admin's own views, while an admin cannot manage another admin's Data Explorer views. [shared.admin-rbac.zdx:analytics-permission] Role permissions for Remediation are chosen per page: the Scripts page, the Script Templates page (Full allows admins to import the templates as scripts), the Remediation Jobs page and the Remediation Settings page. [shared.admin-rbac.zdx:remediation-permissions] The permission for the Applications and Probes configuration gives with Full full access to Configuration Access, including enabling data collection for Software and Device Inventory on the Inventory Settings page and configuring Zscaler Managed Probes. [shared.admin-rbac.zdx:configuration-access] One permission covers Administrator Management, Role Management, Location Management and Audit Logs, with Full allowing full access to Administrator Management; although roles are created in Role Management, they are managed by Super Admins. Separate permissions cover Zscaler locations (View Only views them) and Users, Groups and Departments in User Management (View Only views what has been set up). [shared.admin-rbac.zdx:administrator-management-permission] With Full on Diagnostics an admin manages and views Diagnostics sessions and views and exports the results; with View Only the admin views session details but cannot export the results. [shared.admin-rbac.zdx:diagnostics-permission] For alerts, Full lets admins configure and view alerts and receive alert notifications, View Only lets them view alerts and receive notifications depending on rule configuration, and None allows neither managing, viewing nor receiving them; labels can be assigned to an alert rule and a Workflow Automation created or assigned as a delivery method. Webhooks has its own permission, where Full allows creating, managing and viewing webhooks. [shared.admin-rbac.zdx:alerts-permission] Further permissions in a role cover Remote Assistance for ZDX (Full gives full access to Remote Assistance Management for ZDX, View Only views what has been set up there), Self Service (Full manages Self Service notifications for users and access to the Self Service dashboard, View Only views the dashboard), the Wi-Fi Dashboard (View Only views it), the Device Health dashboard (Full or View Only views it), Inventory Management (the Software, Hardware, and Process Settings pages), ZAgent, Zscaler Client Connector configurations and VIP information. [shared.admin-rbac.zdx:other-permissions] The permission names differ between the articles [gap:shared.admin-rbac.zdx:permission-names].

**Scope in practice.** In the article's example, an admin whose scope is Germany and France must make a selection for the alert rule's Locations criteria and can choose only those two, and the rule applies only to users, department or group members who are in Germany or France. [shared.admin-rbac.zdx:scope-alert-rules-location] In the article's example, only an admin with scope over both Germany and France can configure an alert rule whose locations are Germany and France. [shared.admin-rbac.zdx:scope-covers-rule] In the article's example, an admin whose scope is the HR and IT departments must select Departments for the alert rule from only those; a selected department applies the rule to all its users whichever users are selected, a selected user group applies it to all group members regardless of department, and Zscaler recommends avoiding All User Group as the user group. [shared.admin-rbac.zdx:scope-alert-rules-department] If admins have permission to manage admins, their scope limits the scope they can assign other admins; in the article's example, an admin assigning a department-category scope can choose any (or all) departments. [shared.admin-rbac.zdx:scope-limits-delegation] Only admins with scope over the entire organization can configure organization-wide alert rules, inventory settings and information; configuring Inventory or Self Service settings, changing the Integration settings (Data Collection, SaaS App Tenants and Webhooks) and changing Authentication settings each need Organization scope. [shared.admin-rbac.zdx:organization-scope-only] On the ZDX Dashboard, Applications, User and Inventory pages an admin can only view impacted users and their devices within their scope; for Diagnostics an admin configures sessions for users in scope and for probes configures them for applications in scope. In User Management an admin scoped to specific departments views only those departments' users (Organization scope or location scope views all users), in Location Management an admin scoped to specific locations views only those (Organization scope or department scope views all), and scope does not affect My Profile. [shared.admin-rbac.zdx:scope-views] In the article's example, an admin scoped to the HR department sees on the ZDX Dashboard only the applications that are assigned to HR. [shared.admin-rbac.zdx:scope-dashboard-apps] An alert rule or setting is associated with an admin's role and admin scope rather than a particular admin, so when an admin leaves the organization and their account is deleted, the alert rules they created are not affected and remain. [shared.admin-rbac.zdx:rules-outlive-admin]

**Limits.** In the ZDX organization limits, Admin Users per Organization is 10K admins (admin users can reside in Internet & SaaS or Private Access), Active Admins is 255 (admins connected to the cloud are considered active) and API Keys is 50. [shared.admin-rbac.zdx:org-limits]

What to check:
1. For an admin who cannot see or change something, the role's permission for that page and the admin's scope, which are separate.
2. For missing user, device or location names, whether the role has the User Name, Device Name or Location permission set to Obfuscated, and whether Client Connector's privacy collection settings are disabled.
3. For an admin who cannot configure an alert rule, whether the rule's locations or departments fall inside the admin's scope.
4. For a Service Desk Tier 1 admin, read its permissions from the Service Desk article's list and the role's own Obfuscated and Visible settings rather than from the OneAPI page's wording.
