# Which technology partner guides cover ZIA, and what each guide says the integration does (shared.technology-partners.zia)

**Log streaming to SIEM and analytics partners.** The Cribl guide describes two ZIA log mechanisms: NSS, which uses Syslog over TCP and needs a Zscaler NSS VM, and Cloud NSS, an optional Zscaler-managed service that uses HTTP and HTTPS with no VM. [shared.technology-partners.zia:cribl-nss-vs-cloud-nss] In the Exabeam guide, logs come from NSS VMs that pull from the Nanolog and stream over syslog or TCP, or from Cloud NSS, which pushes logs directly over HTTPS. [shared.technology-partners.zia:exabeam-nss-transports] In the IBM QRadar guide, NSS uses a VM to stream ZIA and ZPA traffic logs, and a Cloud NSS subscription allows cloud-to-cloud streaming through an HTTPS API feed. [shared.technology-partners.zia:qradar-cloud-nss] [divergence:shared.technology-partners.zia:cloud-nss-transport] The Arctic Wolf guide configures ZIA and ZPA to send NSS and Cloud NSS messages to Arctic Wolf sensors; Cloud NSS streams ZIA logs to a compatible cloud SIEM without an NSS VM for Web or Firewall. [shared.technology-partners.zia:arctic-wolf-cloud-nss] [divergence:shared.technology-partners.zia:zpa-log-path] For Expel MDR, Zscaler must send logs via NSS and Cloud NSS to an Expel-approved SIEM such as Splunk, Microsoft Sentinel or Sumo Logic, and Expel reads the logs from that SIEM. [shared.technology-partners.zia:expel-siem-required] The Hunters integration requires Zscaler to send logs via NSS to a Hunter Data Collector. [shared.technology-partners.zia:hunters-nss-collector] The Elevate Security integration uses the Zscaler cloud Nanolog Streaming Service (NSS) to push activity into the Elevate Security Platform. [shared.technology-partners.zia:elevate-cloud-nss] Gurucul integrates with ZIA via NSS (secure Syslog to its collection endpoint, needing a Zscaler NSS VM) or via Cloud NSS using either AWS S3 Integration or HTTP Endpoint. [shared.technology-partners.zia:gurucul-nss-cloud-nss] ZIA logs can be brought into Google SecOps using a webhook. [shared.technology-partners.zia:google-secops-webhook] The Living Security guide integrates ZIA with the Living Security Human Risk Management Platform; Cloud NSS allows streaming ZIA logs directly into a compatible cloud-based SIEM without deploying an NSS VM for Web or Firewall. [shared.technology-partners.zia:and-living-security] ZIA logs reach LogRhythm SIEM by traditional syslog or a cloud-to-cloud transport; the traditional syslog transport requires an NSS VM that pulls logs from the Nanolog stores and sends them to an on-premises SIEM via TCP. [shared.technology-partners.zia:and-logrhythm] In the Microsoft Defender for Cloud Apps guide, NSS converts filtered ZIA logs to the configured output format so Microsoft Defender for Cloud Apps can parse them and streams them using an Authentication Token generated in the Defender for Cloud Apps portal; the original logs are retained on the Nanolog. [shared.technology-partners.zia:and-microsoft-defender-cloud-apps] The Microsoft Sentinel guide sends ZIA NSS messages to Microsoft Azure Sentinel; NSS applies configured filters and converts logs to an output format the SIEM can parse. [shared.technology-partners.zia:and-microsoft-sentinel] The NetWitness guide configures Zscaler to send logs via NSS to a NetWitness Platform XDR Data Collector. [shared.technology-partners.zia:and-netwitness] In the Secureworks guide, Zscaler is configured to send logs to a Taegis XDR Data Collector via NSS and Cloud NSS. [shared.technology-partners.zia:and-secureworks] The KnowBe4 SecurityCoach integration needs a SecurityCoach organization and API key and a log stream from ZIA to SecurityCoach; the data then appears under the SecurityCoach tab of the KMSAT console. [shared.technology-partners.zia:knowbe4-log-stream] The Darktrace integration ingests weblogs from a ZIA device to simulate connection data, and connection events created from those logs are available for core Darktrace analysis. [shared.technology-partners.zia:darktrace-weblogs] Onboarding Exaforce involves configuring API roles, registering API clients, connecting the Zscaler instance through the Exaforce Console and setting up log source feeds. [shared.technology-partners.zia:exaforce-api-onboarding] Datadog ingests ZIA and ZPA telemetry and has an app that visualizes the data in dashboards. [shared.technology-partners.zia:datadog-telemetry] The Command Zero solution queries ZIA and ZPA data so analysts can ask hunting questions about users blocked by policy violations, users attempting to access anonymizing services, and users attempting to access URLs categorized as malicious content. [shared.technology-partners.zia:command-zero-queries]

What to check:
1. Which Cloud NSS transport the partner guides name: the Cribl and Plixer guides say HTTP and HTTPS, the Exabeam guide says HTTPS, the IBM QRadar guide says an HTTPS API feed and the Devo guide says syslog over TCP with an NSS Virtual Machine.
2. Whether ZPA logs reach a SIEM through NSS or Cloud NSS: the IBM QRadar and Arctic Wolf guides say they do, while the Zscaler LSS overview says ZPA uses LSS and NSS resides in ZIA.
3. Whether the Anomali ThreatStream integration forwards more than 25,000 observables per day to ZIA.
4. Whether the Fortinet guide is being used for production configuration; the guide says it should not be.
5. Whether Microsoft Copilot users log in with personal accounts, where the page says Microsoft uses encrypted tokens (JWE) that Zscaler cannot decrypt.

Sources disagree (name both sides):
- The Cribl and Plixer guides say Cloud NSS uses HTTP and HTTPS to send logs, while the Exabeam guide, the IBM QRadar guide and the NSS overview name HTTPS only, and the Devo guide pairs Cloud NSS with syslog over TCP and an NSS Virtual Machine. [divergence:shared.technology-partners.zia:cloud-nss-transport]
  - zscaler-help: Cribl: Cloud NSS is an optional service managed by Zscaler and uses HTTP and HTTPS to send logs.
  - zscaler-help: Plixer: Cloud NSS is an optional service that uses HTTP and HTTPS to send logs.
  - zscaler-help: Exabeam: Cloud NSS pushes logs directly from Zscaler over HTTPS.
  - zscaler-help: IBM QRadar: Cloud NSS streams through an HTTPS API feed into an HTTPS API-based log collector.
  - zscaler-help: Devo: ZIA sends logs via Cloud NSS, and NSS uses syslog over TCP, which requires a Zscaler NSS Virtual Machine.
  - zscaler-help: NSS overview: Cloud NSS uses an HTTPS API feed to push logs to an HTTPS API-based log collector on the SIEM.
  Impact: Only the Cribl and Plixer guides name plain HTTP for Cloud NSS, and only the Devo guide ties it to syslog over TCP and an NSS Virtual Machine; an answer about the Cloud NSS transport cannot rest on one guide alone.
- The IBM QRadar and Arctic Wolf guides describe ZPA logs as streamed by NSS or Cloud NSS, while the Zscaler LSS overview says ZPA logs use LSS and NSS resides in ZIA. [divergence:shared.technology-partners.zia:zpa-log-path]
  - zscaler-help: IBM QRadar: NSS streams traffic logs from ZIA and ZPA to QRadar.
  - zscaler-help: Arctic Wolf: ZIA and ZPA send NSS and Cloud NSS messages to Arctic Wolf sensors.
  - zscaler-help: LSS overview: LSS captures Private Access logs; NSS resides in Internet & SaaS (ZIA).
  Impact: A ZPA log-streaming answer cannot rest on the QRadar or Arctic Wolf wording alone; other partner guides (Vectra, Sekoia) name LSS for ZPA.
