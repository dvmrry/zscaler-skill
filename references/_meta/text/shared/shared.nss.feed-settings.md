# NSS feed destination and delivery settings by feed kind: TCP, HTTP, Cloud NSS and MCAS (shared.nss.feed-settings)
Also called: nss feed settings; siem rate; siem ip fqdn; max batch size; json array notation; feed output type; nss configure-nssas; cloud nss oauth; api url; duplicate logs setting

Each feed is a connection between the NSS and the SIEM, and a configured NSS server is required to add an NSS feed. [shared.nss.feed-settings:feed-is-connection] Which settings each kind of feed has is not quotable from the articles [gap:shared.nss.feed-settings:settings-by-kind].

**TCP feeds.** A TCP feed's SIEM destination can be given as an FQDN: the NSS re-resolves the FQDN only when the existing connection goes down, allowing failover from one IP to another by updating the DNS entry. The feature cannot be used for DNS-based load balancing. [shared.nss.feed-settings:siem-fqdn] SIEM Rate should be left as Unlimited unless the output stream must be throttled due to licensing or other constraints; a limit must be between 100 and 1,000,000, and one that is too low for the traffic volume causes log loss. [shared.nss.feed-settings:siem-rate] A TCP web feed's output is a comma-separated (CSV) list by default, with Tab-separated as an alternative and feed output types for specific SIEMs in the same menu. The Firewall feed article says Name-Value Pairs or Tab-separated can be chosen if the SIEM accepts them. [shared.nss.feed-settings:tcp-output-types] What the Duplicate Logs setting replays is in [On a TCP web feed, Duplicate Logs sets the number of minutes the NSS sends duplicate logs so that no logs are skipped during downtime. Zscaler recommends 5 minutes, or more if required, which allows the NSS to send up to 60 minutes (one hour) of logs to the SIEM after the connection is restored.](kb:shared.nss.reliability:duplicate-logs-recommendation).

**HTTP feeds.** In addition to TCP-based feeds, NSS logs can optionally be streamed to a SIEM over HTTP connections, and the AWS guide lists `nss configure-nssas` among the steps to add HTTP-based feeds. Self-signed or internally issued certificates that pass the SIEM connectivity test can also be used only after they are configured in the VM instance. [shared.nss.feed-settings:http-enable] In the HTTP Firewall, HTTP SaaS Security and HTTP Sandbox Verdict NSS feed articles, a self-signed certificate is configured by running `nss add-cert-to-trust <self-signed certificate>` in the VM instance, with the path of the certificate from the NSS node in place of the placeholder. [shared.nss.feed-settings:http-self-signed-command] The HTTP Firewall, HTTP SaaS Security and HTTP Sandbox Verdict NSS feed articles each say that before configuring HTTP NSS feeds, the tasks for the virtual appliance in the NSS Deployment Guides for the platform must be completed. [shared.nss.feed-settings:http-prerequisite] An HTTP feed takes an API URL, the HTTP/S URL of the SIEM log collection API endpoint, HTTP header values such as a token, and a Max Batch Size, a size limit for an individual HTTP request payload to the SIEM's best practice. [shared.nss.feed-settings:http-destination] An HTTP web feed's Feed Output Type says the output is JSON, and Tab-separated is also offered. When JSON is selected, JSON Array Notation is enabled by default, which orders individual logs in a list separated by commas and surrounded by square brackets, and the article says the setting can be disabled. [shared.nss.feed-settings:http-json] The batch size has no unit or default stated [gap:shared.nss.feed-settings:max-batch-size].

**Cloud NSS feeds.** A Cloud NSS web feed has a SIEM Type chosen from a list and a JSON output by default. [shared.nss.feed-settings:cloud-settings] The URL, certificate trust and OAuth default are in [In the console, a Cloud NSS feed's API URL is the HTTP/S URL of the SIEM log collection API endpoint. The HTTPS URL must be configured with a publicly trusted SSL certificate, since self-signed or internally issued certificates do not pass the SIEM connectivity test, and OAuth 2.0 Authentication is enabled by default if applicable to the SIEM type.](kb:zia.api.cloud-nss-feeds:cloud-url-cert). The SIEM types and which use OAuth 2.0 are not listed [gap:shared.nss.feed-settings:siem-types]. The API side is [Cloud NSS feed settings: HTTPS-only URLs and OAuth fields](kb:zia.api.cloud-nss-feeds).

**MCAS feeds.** An MCAS NSS feed is a connection between the NSS and MCAS; its SIEM IP Address is the local host IP address, pre-populated and not editable, and its Feed Output Format fields are pre-populated and cannot be edited. An NSS virtual appliance deployed before the Internet Access (ZIA) 5.6 release needs the latest version of Java installed in its VM. [shared.nss.feed-settings:mcas-fixed]

**HTTP and Cloud feeds by log type.** The HTTP Firewall, Cloud DNS, HTTP SaaS Security and Cloud Posture Management feed articles each say a new feed's Status is Enabled by default and can be set to Disabled to activate it at a later time; the wording is "It is Enabled by default", "The NSS feed is Enabled by default" or "The Cloud NSS feed is Enabled by default" depending on the article. [shared.nss.feed-settings:status-default] The Feed Output Type wording differs by article. The HTTP Firewall article says the output is JSON and Name-Value Pairs or Tab-separated can be chosen if the SIEM accepts them; the Cloud DNS article says JSON by default with the same two choices; the HTTP SaaS Security article says JSON, with Tab-separated, Custom (a different delimiter such as a dash) and output types for specific SIEMs in the menu; the Cloud Posture Management article says JSON by default, with Tab-separated or Custom. [shared.nss.feed-settings:output-types-by-log-type] Whether the output types an article does not offer exist for that log type is open [gap:shared.nss.feed-settings:output-types-not-offered]. The HTTP Firewall, HTTP Sandbox Verdict, Cloud DNS and Cloud Posture Management feed articles each say that when JSON is selected the JSON Array Notation setting is enabled by default, individual logs are ordered in a list separated by commas and surrounded by square brackets, and the setting can be disabled. [shared.nss.feed-settings:json-array-all-log-types] The HTTP Firewall and Cloud DNS feed articles say the SIEM Rate Limit (Events per Second) is only applicable if Limited is selected under SIEM Rate, must be between 100 and 1,000,000, and that a limit too low for the traffic volume causes log loss. The Cloud Posture Management article says the same about a too-low limit. [shared.nss.feed-settings:siem-rate-http-cloud] The SIEM Rate range on the DLP, Sandbox, App Governance and Posture articles is open [gap:shared.nss.feed-settings:siem-rate-range-other-logs]. The HTTP Firewall article says the HTTPS URL can be configured with a publicly trusted SSL certificate and that self-signed or internally issued certificates that pass the SIEM connectivity test can also be used only after they are configured in the VM instance; the Cloud Firewall article says the HTTPS URL must be configured with a publicly trusted SSL certificate, that self-signed or internally issued certificates do not pass the SIEM connectivity test, and that OAuth 2.0 Authentication is enabled by default if it is applicable to the SIEM type. [shared.nss.feed-settings:cert-by-kind]

**Replay on HTTP and Cloud.** What an HTTP or Cloud NSS feed replays after an outage beyond the batch retry is open [gap:shared.nss.feed-settings:http-cloud-duplicate-logs].
