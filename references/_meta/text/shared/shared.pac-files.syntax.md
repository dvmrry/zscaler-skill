# Writing a PAC file for Zscaler: function, return statements, ports and performance rules (shared.pac-files.syntax)
Also called: pac syntax; findproxyforurl; pac return statement; pac proxy ports; port 9400; port 9443; port 9480; pac performance; isinnet dns lookup; pac best practices; pactester

Zscaler's articles on writing PAC files mix JavaScript rules, Public Service Edge facts and performance advice. The variables a hosted file can use are in [Zscaler PAC file variables: gateways, hosts, load-balancing tokens, subclouds and Client Connector](kb:shared.pac-files.variables).

**Structure.** The required first line is [A PAC file must start with the FindProxyForURL(url, host) function, which decides which URLs, hostnames or IP addresses are redirected to a proxy; a file can return DIRECT for destinations that should bypass the service.](kb:zia.proxy-mode.explicit:pac-function). Beyond the FindProxyForURL(url, host) first line, the writing article says url holds the full destination URL and host its domain name or IP address, the host variable is generally preferable, and if no URL or host is specified every request uses the return argument. [shared.pac-files.syntax:function-first-line] Zscaler's Writing a PAC File article says a return statement accepts one of two values, DIRECT (bypass the proxy and go to the destination) or PROXY (send the request to a proxy), written in uppercase inside quotation marks and followed by a semicolon. [shared.pac-files.syntax:return-values] Each PROXY statement names the proxy's fully qualified hostname or IP address and a port; IP addresses are discouraged because they can change, and Zscaler recommends its gateway variables instead. [shared.pac-files.syntax:proxy-target] The JavaScript in a PAC file is parsed top-down and the first match wins; statements match against host names or IP addresses. [shared.pac-files.syntax:top-down] Client Connector's disaster recovery PAC files also take BLOCK: [In the custom PAC file of the Windows app profile's Internet & SaaS disaster recovery options (Policy Based Access, Web only and All Ports), DIRECT allows a destination and BLOCK, or any return value other than DIRECT, blocks it; Zscaler's sample files set var drop = "BLOCK" and allow listed hosts matched with localHostOrDomainIs.](kb:zcc.app-profiles:dr-pac-block).

**Ports.** Public Service Edges accept web requests on ports 80, 443, 9400, 9443 and 9480. Port 9400 is an alternative when a host on the path redirects traffic before it reaches the Service Edge, and should only be returned if it is open outbound; 9443 is for remote users whose HTTPS the service should proxy and inspect; 9480 exempts traffic from a known location from authentication, while remote users on it are still forced to authenticate. [shared.pac-files.syntax:pse-ports] Dedicated proxy ports are [Dedicated proxy ports](kb:zia.forwarding-control.proxy-ports), and what the service does with explicit-mode traffic is [Explicit proxy mode: CONNECT and the PAC file](kb:zia.proxy-mode.explicit).

**Known and unknown locations.** When the service receives traffic it checks whether it is from a known location (one configured in the Admin Console) or an unknown location (remote user traffic). Typically, traffic from a known location is sent to port 80, where the service performs SSL inspection according to the location's policies, and remote user traffic is forwarded to port 9443, where the service always performs SSL inspection; the exemption of URL and URL categories is applicable only to traffic generated from known locations. [shared.pac-files.syntax:location-ports] The article gives location-detection options for a PAC file, each with its stated trade-off. One matches ${SRCIP} against a list of gateway addresses and is accurate and independent of the computer configuration, but the list must be updated when locations change. Another relies only on the computer configuration and is simple and quick, but the private IP address range might overlap with other company networks such as a coffee-shop Wi-Fi hotspot. A third is efficient when DNS resolution is the same across all company locations, but might slow browsing if DNS servers respond slowly, and does not work for a remote user on a VPN whose hostname is resolved by the internal DNS server. Zscaler recommends creating a copy of the default PAC file and customizing it as necessary. [shared.pac-files.syntax:location-detection-methods] The samples in that article have defects [gap:shared.pac-files.syntax:location-sample-defects].

**Bypassing internal destinations.** The vendor's examples return DIRECT for internal hosts and networks with isInNet (for example 192.168.0.0/255.255.0.0) and bypass a single host with the mask 255.255.255.255; an internal host reached through a Public Service Edge is denied. [shared.pac-files.syntax:internal-bypass] isInNet on a host name triggers a DNS lookup, which can hurt performance when DNS is unavailable, and an unresolvable name makes the client wait for the DNS timeout; used for the client address, it returns the device's first IP address, which can be an IPv6 or virtual-adapter address. [shared.pac-files.syntax:isinnet-dns] To avoid those lookups the vendor puts a regular-expression test before isInNet so the network checks run only when the host is an IP address, and bypasses named hosts with a regular-expression variable tested against host, which needs no DNS lookup. [shared.pac-files.syntax:regex-guard]

**Performance.** Execution speed depends on how the arguments are built, not on file length; PAC files execute serially, so the vendor advises avoiding excessive exclusions and putting high-probability checks, such as private IP address lookups, at the beginning. [shared.pac-files.syntax:serial-execution] Numerous OR statements slow processing; the vendor recommends grouping them inside IF statements so they are parsed in batches, for example one outer test for *.google.com with the specific hosts inside it, and checking IP addresses in a separate if. [shared.pac-files.syntax:grouping] The vendor advises care with isResolvable(), dnsResolve() and isInNet() because of potential DNS performance issues. [shared.pac-files.syntax:dns-functions] The use of regular expressions should be minimized and kept efficient; complex ones used to make a file smaller can make it less efficient. [shared.pac-files.syntax:regex-cost]

**Authoring.** Edit PAC files in a plain text editor rather than Microsoft Office Word, whose smart quotes can break the file; every opening bracket and parenthesis needs its closing one (losing count is among the most common mistakes); comments begin with //; and external or global variables and functions should be avoided. [shared.pac-files.syntax:editor-and-brackets] Some browsers may execute PAC files case-sensitively; the vendor adds var lhost = host.toLowerCase(); host = lhost; at the top of the file, immediately below the opening curly bracket. [shared.pac-files.syntax:lowercase] Keep the file small and efficient: configure SSL exceptions in the Admin Console rather than in the PAC file, and validate support for built-in JavaScript functions before using them. [shared.pac-files.syntax:keep-small]

**Testing.** Test every condition before deployment with pactester or another PAC parser, and also use the console's Verify PAC File option. [shared.pac-files.syntax:testing] ip.zscaler.com shows whether the browser reached the web server directly or through a Public Service Edge. [shared.pac-files.syntax:ip-zscaler-check] The console's verification statuses are [For each file the Hosted PAC Files page shows its hosted URL, a status of Verified or Error-Accepted (saved with errors the admin accepted at verification), the Number of Hits in the last 30 days and the Currently Deployed Version; files can be previewed and exported as text, PAC or JS.](kb:shared.pac-files.hosting:page-columns) and [The console checks PAC syntax with Verify PAC File but still lets a file with errors be saved; the Python SDK validates content before it adds a file.](kb:zia.traffic-forwarding.pac:validation).

**When no proxy answers.** The vendor's examples end the return list with DIRECT after the primary and secondary gateways, so a request that reaches neither gateway goes to the destination without passing through the service; for traffic that must always be inspected, that last entry is a bypass. [shared.pac-files.syntax:trailing-direct] Browser-engine behavior the vendor does not document (runtime errors, IPv6 matching functions) is open [gap:shared.pac-files.syntax:browser-engine-behavior], and the legacy list of destinations to always bypass is open [gap:shared.pac-files.syntax:always-bypass-list].

What to check:
1. Whether the file starts with FindProxyForURL on the first line and every return value is an uppercase quoted DIRECT or PROXY with a host and port.
2. Whether an earlier statement matches the request before the one expected to, since the file is evaluated top-down and the first match wins.
3. Whether the returned port is open outbound from the user's network, especially 9400.
4. Whether the browser reaches the service, by visiting ip.zscaler.com with the file loaded.

Inferred, not quoted (say so when an answer rests on one):
- [shared.pac-files.syntax:trailing-direct] Tier B: The vendor return statements quoted in manual-failover and gateway-host end with DIRECT; the claim assumes the browser tries the PROXY entries in order and uses DIRECT only when none responds, which is standard PAC handling but not stated by a vendor source.
