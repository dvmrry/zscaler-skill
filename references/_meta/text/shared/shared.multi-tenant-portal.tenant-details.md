# What the Multi-Tenant Portal Tenant Details page shows for a tenant: subscriptions, limits, defaults, API keys, clusters, contacts and Executive Insights (shared.multi-tenant-portal.tenant-details)

**General.** The Tenant Details page is view-only and cannot be modified within the Multi-Tenant Portal; configuration changes go through Zscaler Support. [shared.multi-tenant-portal.tenant-details:view-only] The account settings page words changes to the tenant's account differently [divergence:shared.multi-tenant-portal.tenant-details:view-only-wording]. The View On control gives access to the tenant's ZIA Admin Portal, and to other admin portals such as ZDX and Zscaler Cloud Connector if the tenant is provisioned on them. [shared.multi-tenant-portal.tenant-details:view-on] General account information includes the Primary Account Owner, Tenant Since, the Internal Domain (generated when the tenant account is created with Zscaler) and the CMC Hostname associated with the tenant. [shared.multi-tenant-portal.tenant-details:general-fields] Show Partner Logo is a white labeling indicator of whether the partner logo is enabled or disabled in the admin portals the tenant has access to. [shared.multi-tenant-portal.tenant-details:show-partner-logo]

**Subscriptions.** A subscription's Status is one of on trial, expired, not subscribed, subscribed or temporarily extended, and the ADD-ON tag beside a service name marks an additional service included in the package. [shared.multi-tenant-portal.tenant-details:subscription-status] The subscription list shows each service's SKU (the ID of the service) and the Number of Licenses the tenant owns. [shared.multi-tenant-portal.tenant-details:subscription-columns]

**Limits.** The Self-provisioned IP Limit shown for a tenant is 100, 1,000, 10K, or 100K; Self-service GRE and IP Provisioning, if enabled, lets the tenant provision GRE or IP addresses in the ZIA Admin Portal. [shared.multi-tenant-portal.tenant-details:self-provisioned-ip] The Custom URL Category Limit shown for a tenant indicates the number of URL categories configurable in the ZIA Admin Portal and can be either 56 or 256. [shared.multi-tenant-portal.tenant-details:custom-url-category-limit] The URL category figure differs from the ZIA pages [divergence:shared.multi-tenant-portal.tenant-details:custom-url-category-count]. The Custom File Type Limit shown for a tenant is the number of custom file types for file type policies and can be 512, 1,024 or 2,048; the default value is blank. [shared.multi-tenant-portal.tenant-details:custom-file-type-limit] Large PAC Files (up to 2MB) indicates whether 2MB PAC files are supported, against a normal limit of 256 KB; PAC Files up to 1K raises the per-organization maximum to 1,000 (1,024 PAC files) when enabled and is 256 when disabled. [shared.multi-tenant-portal.tenant-details:pac-limits] The NSS Subscriptions Multiplier shows the number of NSS for a tenant; for example, a value of 8 means the customer can configure 8 different NSS of each type. [shared.multi-tenant-portal.tenant-details:nss-multiplier] EDM Primary Key Max Duplicates across Schemas, when enabled, indicates the number of supported duplicate primary keys for a schema file, with a maximum of 512. [shared.multi-tenant-portal.tenant-details:edm-duplicates] The EDM duplicate figure is scoped differently on the ZIA pages [divergence:shared.multi-tenant-portal.tenant-details:edm-duplicate-scope]. High Group Limit indicates whether a user can belong to more than 100 groups; if enabled, the limit is up to 128. [shared.multi-tenant-portal.tenant-details:high-group-limit] The group figure differs from the ZIA pages [divergence:shared.multi-tenant-portal.tenant-details:group-limit]. A customer can create up to 512 cloud application instances, and a maximum of 1,024 keyword type identifiers per cloud application instance is allowed, each no longer than 128 characters. [shared.multi-tenant-portal.tenant-details:cloud-app-instances] The instance figure omits the ZIA pages' Support raise [divergence:shared.multi-tenant-portal.tenant-details:cloud-app-instance-limit]. Custom Filehash lets customers configure their own custom file blocklists based on MD5 hashes in the ZIA Admin Portal, up to a maximum of 10K MD5 hashes. [shared.multi-tenant-portal.tenant-details:custom-filehash] Tenant details list the Sandbox Cluster, where files are quarantined and scanned for malicious activities, plus daily limits for sandbox unique files analyzed and for sandbox API file submissions. [shared.multi-tenant-portal.tenant-details:sandbox-fields]

**Options.** DC Exclusion, if enabled, restricts customer data forwarding to all data centers within the country, and DC Exclusion for Traffic Forwarding shows the Traffic Forwarding Method option for DC Exclusion in the ZIA Admin Portal. [shared.multi-tenant-portal.tenant-details:dc-exclusion] Custom Cloud App Support, when enabled, allows customers to configure their own applications in the ZIA Admin Portal and cannot be disabled if any custom cloud applications have been added to a tenant. [shared.multi-tenant-portal.tenant-details:custom-cloud-app] The Authentication Service Admin and Authentication Service User options, when enabled, allow admin or user access to the Authentication Service Admin Portal; by default, both are disabled. [shared.multi-tenant-portal.tenant-details:auth-service-flags] AND Functionality for URL Filtering Categories and JWT Auth for Workload are options shown on tenant details, each disabled by default. [shared.multi-tenant-portal.tenant-details:and-urlcat-jwt] Schedule QBR generates the Quarterly Business Report (QBR) every quarter, if configured. [shared.multi-tenant-portal.tenant-details:schedule-qbr] SaaS Security Collaborator Count, when enabled, specifies the number of users who can access certain files in a SaaS application. [shared.multi-tenant-portal.tenant-details:saas-collaborator-count] Limited RBA and SMAA Servers have only a one-line description [gap:shared.multi-tenant-portal.tenant-details:unexplained-rows].

**Clusters, keys and contacts.** Tenant details list the Preferred Nanolog Cluster where tenant logs are recorded, the SMCDSS DLP Cluster used for Exact Data Match schema files, and the Nanolog cluster for logs forwarded from Virtual Service Edge. [shared.multi-tenant-portal.tenant-details:clusters] Tenant details show an API Key for the public ZIA APIs, a Sandbox API Key for the Sandbox APIs, and an EC API Key for the public EC APIs, each shown if generated. [shared.multi-tenant-portal.tenant-details:api-keys] Activation details show whether the ZIA, ZDX, Zscaler Cloud Connector, ZCSPM Admin, BI and Risk Analytics password reset emails are enabled or disabled, and the Activation Email Recipient receives the activation or password reset email for the enabled fields. [shared.multi-tenant-portal.tenant-details:password-reset-emails] Executive Insights must be enabled for the tenant account to receive the Insights reports; details show the addresses receiving the report at generation and 7 days after, and the allowed external email domains. [shared.multi-tenant-portal.tenant-details:executive-insights] Tenant details show primary and secondary contacts for Billing, Technical or Business divisions and, if provisioned, for ZDX, Zscaler Cloud Connector, Zscaler Deception, Zscaler Risk Analytics, BI and ZCSPM, with an alternate phone number for a contact if any. [shared.multi-tenant-portal.tenant-details:contacts]

Sources disagree (name both sides):
- The Tenant Details page gives the Custom URL Category Limit as 56 or 256, while the ZIA pages give 64 custom categories, raisable to 1,024 through Zscaler Support. [divergence:shared.multi-tenant-portal.tenant-details:custom-url-category-count]
  - zscaler-help: The Custom URL Category Limit is either 56 or 256.
  - zscaler-help: Up to 64 custom categories can be created, and Zscaler Support can raise the limit to a maximum of 1,024.
  Impact: A tenant showing 56 or 256 does not match the 64 default the ZIA pages state, and neither set of pages says how the two relate.
- The Tenant Details page says a High Group Limit flag raises the per-user group limit from 100 to 128, while the ZIA pages give 127 by default and 128 without mentioning such a flag. [divergence:shared.multi-tenant-portal.tenant-details:group-limit]
  - zscaler-help: High Group Limit indicates whether the user can belong to more than 100 groups; if enabled, the limit is up to 128.
  - zscaler-help: The limits table gives 127 groups per user by default.
  - zscaler-help: The SCIM article says the total number of groups associated with a single user cannot exceed 128.
  Impact: Whether a tenant without High Group Limit enabled is capped at 100, 127 or 128 groups per user is not stated.
- The Tenant Details page says a customer can create up to 512 cloud application instances, while the ZIA limits page gives 512 with a possible increase to 4,096 through Zscaler Support and 2,048 identifiers across all instances. [divergence:shared.multi-tenant-portal.tenant-details:cloud-app-instance-limit]
  - zscaler-help: A customer can create up to 512 cloud application instances, with a maximum of 1,024 keyword identifiers per instance.
  - zscaler-help: 512 cloud application instances, with a possible increase to 4,096 through Zscaler Support, and at most 2,048 instance identifiers across all instances.
  Impact: The Tenant Details page states 512 as the ceiling, and does not reconcile 1,024 identifiers per instance with the 2,048 total across all instances.
- The Tenant Details page gives the EDM primary key duplicate maximum as 512 across schemas, while the ZIA EDM article gives 512 for an individual template and 2,048 across multiple templates. [divergence:shared.multi-tenant-portal.tenant-details:edm-duplicate-scope]
  - zscaler-help: EDM Primary Key Max Duplicates across Schemas has a maximum of 512.
  - zscaler-help: 512 duplicate keys for an individual EDM template and 2,048 across multiple EDM templates.
  Impact: The 512 labelled as across schemas is a per-template figure on the ZIA page, and it is not stated which scope the Tenant Details field sets.
- The Tenant Details page says its information cannot be modified within the portal, while the account settings page says you can make changes to the information associated with your tenant's account. [divergence:shared.multi-tenant-portal.tenant-details:view-only-wording]
  - zscaler-help: Tenant Details information is view-only and cannot be modified within the portal; changes go through Zscaler Support.
  - zscaler-help: You can make changes to the information associated with your tenant's account.
  Impact: The account settings sentence is under the page for the partner's own account settings, so which tenant information it means is not stated.
