# Getting a PAC URL onto clients and keeping it there: GPO, browsers, enforcement, firewall (shared.pac-files.client-delivery)
Also called: distribute pac file url; pac file gpo; enforce pac setting; identify pac file on device; recommended.pac; pac firewall requirements

The hosted side of a PAC file is in [Hosted PAC files: the console page, Obfuscate URL, limits and how changes reach clients](kb:shared.pac-files.hosting); this subject is how clients get the URL and what keeps traffic on it. The service recommends deploying the recommended.pac file to the organization's devices. [shared.pac-files.client-delivery:recommended-file]

**Distributing the URL.** If an organization uses Active Directory along with Microsoft Internet Explorer, Microsoft Edge, Google Chrome, Mozilla Firefox or Opera, Group Policy Objects can distribute a PAC file URL to all Windows (Professional, Enterprise, Education and Ultimate Editions only) and Windows Server devices in the organization. When Internet Explorer is configured to use a PAC file, browsers such as Microsoft Edge, Google Chrome and Opera follow the same configuration, but Mozilla Firefox does not follow the system proxy configuration and requires a separate method. It might take up to 20 minutes for the GPO to be replicated to a Windows client machine. [shared.pac-files.client-delivery:gpo-distribution] The PAC file setting can be enforced so that users cannot modify it even when logged in as an administrator. The enforcement steps enable the policies Disable changing Automatic Configuration settings and Prevent changing proxy settings; the Firefox steps end with users no longer able to modify the proxy settings in Mozilla Firefox. Separately, an optional distribution step applies the GPO to the entire computer irrespective of the signed-in user by enabling Make proxy settings per-machine (rather than per-user). [shared.pac-files.client-delivery:gpo-enforcement] Delivery by WPAD, DHCP option 252 or MDM is open [gap:shared.pac-files.client-delivery:other-delivery].

**First use and captive portals.** Based on the authentication configuration, users must log in to the service at least once for the service to start protecting their web traffic. If users log in to a captive portal, such as those on public Wi-Fi networks, they must close the browser and open it again to reload the PAC file. The page also says the browser tries to fetch the PAC file only when there is a PAC URL timeout. [shared.pac-files.client-delivery:first-login-and-captive-portal] The client cache question is under [PAC file forwarding: limits, versions and what it cannot cover](kb:zia.traffic-forwarding.pac).

**Firewalls.** The PAC firewall requirements are on config.zscaler.com, under Firewall Config Requirements and its Traffic Forwarding Requirements section. To restrict web access entirely to the Zscaler service, the page says to configure firewalls to allow outbound traffic from the clients only to the service, to prevent traffic from bypassing the service and accessing the internet directly unless explicitly allowed, and to implement firewall rules that force users with admin rights to browse through the service only so they cannot install non-standard browsers to bypass it. [shared.pac-files.client-delivery:firewall-backstop]

**Finding the PAC file a device uses.** The PAC file configured on a device can be found, for example, from traffic captures of the PAC file requests or the registry entry. The article says the browser tools belong to the browsers and are not related to Zscaler: in Chrome the saved JSON file is searched for proxySettings, in Firefox the URL appears in the value of network.proxy.autoconfig_url, and in Safari Automatic Proxy Configuration shows the PAC file addresses in use. The Chrome example shows "effective":{"pac_url":"http://pac.zscalerbeta.net/zscalerbeta.net/proxy.pac"}, an example only. [shared.pac-files.client-delivery:find-configured-pac]
