# ZIA admin role permissions: logs limit, dashboard, reporting, insights and alerts access, and the feature categories (shared.admin-rbac.zia-permissions)
Also called: zia admin role permissions; adding internet and saas admin roles; reporting access full view only none; insights access permission; executive insights app permission; role management permissions zia

An Internet & SaaS admin role sets, feature by feature, what the admins who hold it can do in the Admin Console; the role model itself (rank, scope) is in [ZIA admin roles and scope: rank, permissions, functional scope and the one-scope rule](kb:shared.admin-rbac.zia). Each feature permission is Full (edit), View Only, None or Custom (Full, View Only or None per Internet & SaaS feature); a feature set to None does not show up in the Admin Console for that admin role. [shared.admin-rbac.zia-permissions:permission-levels]

**Adding a role.** An organization can add up to 64 admin roles. [shared.admin-rbac.zia-permissions:role-limit] Configuring admin roles needs permission to the Role Management feature and organizational admin scope; admin rank and scope do not apply to SD-WAN partner API clients. [shared.admin-rbac.zia-permissions:prerequisites]

**Logs, dashboards, reports and insights.** Logs Limit (Days) sets how many days of logs an admin in the role can view; by default admins can view logs for an unrestricted amount of time. [shared.admin-rbac.zia-permissions:logs-limit] Dashboard Access is Full (view, edit and delete dashboards) or View Only (view all dashboards). [shared.admin-rbac.zia-permissions:dashboard-access] Reporting Access Full gives all features of Interactive Reports and Scheduled Reports and is required to get detailed transaction logs from View Logs in Insights; only admins with the super admin role can schedule executive reports or delete any custom report, and other admins delete only their own. The View Only entry lists viewing standard reports and other admins' custom reports in Interactive Reports and full access to Scheduled Reports. None removes access to Reporting and Insights: the Analytics menu and the Insights Access permission option disappear. [shared.admin-rbac.zia-permissions:reporting-access] Insights Access View Only gives full access to Insights, but detailed transaction logs still need Full Reporting Access; None removes the Insights page from the Analytics menu. The option appears only when the role has Full or View Only Reporting Access. [shared.admin-rbac.zia-permissions:insights-access] Admins with Full or View Only permissions for the Dashboard, Reporting Access and Insights Access can only view those features if the corresponding functional scope is enabled. [shared.admin-rbac.zia-permissions:functional-scope-gate] Which functional scope that is open [gap:shared.admin-rbac.zia-permissions:functional-scope-which].

**Alerts.** Alerts Access controls an admin's access to the Alerts dashboard, Alerts Rules and Webhooks as Full (view and edit), View Only or None; for features disabled for the role, the Alerts page displays a View Restricted message. [shared.admin-rbac.zia-permissions:alerts-access]

**Executive Insights App.** Enable Permissions for Executive Insights App is disabled by default. Enabling it gives the role access to the Executive Insights App and turns on the Data Loss Prevention, Security, and Firewall, DNAT, DNS & IPS scopes regardless of the rest of the configuration, plus the Policy and Resource Management option for Access Control (Web and Mobile). If it is enabled with Reporting Access set to None, Reporting Access becomes View Only on save. [shared.admin-rbac.zia-permissions:executive-insights-switch] The Executive Insights App role is one of Zscaler's default roles: it grants the permissions and scope for the Executive Insights App but not the Admin Console, and its Executive Insights permission setting cannot be modified. An admin who needs both gets a new admin role with Executive Insights App Access enabled. [shared.admin-rbac.zia-permissions:executive-insights-default-role] What the Policy and Resource Management option is, is open [gap:shared.admin-rbac.zia-permissions:policy-resource-management].

**Feature categories.** The role form groups permissions into a Policy & Components section, a Cloud Configuration & Integration section, a Traffic Forwarding section (Traffic Forwarding, Traffic Forwarding Methods and Traffic Forwarding Components) and an Administration Controls section (Administration Controls and Backup Controls). Within Policy & Components the categories are the security, access control, data-protection, decryption, URL category and shared-policy components features; choosing Full, View Only or None for each of them applies the permission to all its features. [shared.admin-rbac.zia-permissions:permission-sections] Custom Security permissions cover Malware Protection, Advanced Threat Protection, Sandbox, IPS Control, Mobile Malware Protection, Secure Browsing and Endpoint Context. [shared.admin-rbac.zia-permissions:security-features] Custom Access Control permissions cover URL Filtering Policy, Cloud App Control, Firewall Control, DNS Control, NAT Control, File Type Control, Mobile App Store Control, Bandwidth Control and FTP Control, with Tenant Profiles and Bandwidth Classes as Policy Components. [shared.admin-rbac.zia-permissions:access-control-features] Custom Data Protection permissions cover Data Loss Prevention, Endpoint DLP, Data At Rest Scanning and SaaS Security Posture Management, with DLP Dictionaries & Engines, Notification Templates, SaaS Application Tenants and DLP Incident Receiver as Policy Components. [shared.admin-rbac.zia-permissions:data-protection-features] Custom Decryption permissions cover SSL/TLS Inspection, with Intermediate CA Certificates and Root Certificates as Policy Components. [shared.admin-rbac.zia-permissions:decryption-features] One URL category option lets an admin edit predefined URL categories through the Custom URLs, URLs Retaining Parent Category, Keywords Retaining Parent Category and Review Matches fields, with Custom URLs, Custom Keywords and all fields in custom categories view-only. Another lets an admin create and edit custom categories through the URLs Retaining Parent Category and Keywords Retaining Parent Category fields. The Override Existing Categories field can be assigned only if the Custom URL Category Management field has Full access, and gives full access to custom categories including Custom URLs and Custom Keywords, with predefined categories view-only. [shared.admin-rbac.zia-permissions:url-category-permissions] Custom Shared Policy Components permissions cover IP & FQDN Groups, Browser Isolation, Device Management and Time Intervals; permission to Zero Trust Browser (formerly Isolation) also includes access to Zscaler integrated Votiro CDR services. [shared.admin-rbac.zia-permissions:shared-policy-components]

**Integrations, cloud configuration, forwarding, administration and reporting data.** Integrations permissions cover Microsoft Cloud App Security, SD-WAN, Azure Virtual WAN, CrowdStrike, Microsoft Defender for Endpoint and Workflow Automation; an application appears only if the organization has access to or a subscription for it. [shared.admin-rbac.zia-permissions:integrations] Cloud Configuration permissions cover Nanolog Streaming Service, Virtual Service Edges and API Key Management; Business Continuity has its own Full, View Only, None or Custom permission. [shared.admin-rbac.zia-permissions:cloud-configuration] Traffic Forwarding permissions cover Forwarding Control; Traffic Forwarding Methods (Static IPs, GRE Tunnels, Locations, VPN Credentials Management, Hosted PAC Files); and Traffic Forwarding Components (Proxies & Gateways, Zscaler Client Connector Portal, Subclouds & DC Exclusion, Traffic Capture). The Custom permission is available for the methods and the components. [shared.admin-rbac.zia-permissions:traffic-forwarding] Administration Controls permissions cover Advanced Settings, Administrator Management, Audit Logs, User Management, Remote Assistance Management, Alerts, Authentication Settings, Identity Proxy Settings and Role Management; Backup Controls cover Backup and Restore. [shared.admin-rbac.zia-permissions:administration-controls] Reporting Data takes View Only, None or Custom over Security, Web Data, DLP, Firewall, URL Categories, IoT Discovery and Sandbox. For example, View Only on Web Data gives Web Insights and Web Logs on the Analytics page, and None on Web Data hides the Web Insights option. [shared.admin-rbac.zia-permissions:reporting-data]

**What this does not cover.** Who sees real user names, device information and Gen AI prompts is in [Who sees real user names, device information and Gen AI prompts in ZIA: role obfuscation and auditors](kb:shared.admin-rbac.zia-obfuscation). The role an API client holds is in [ZIA API roles, SD-WAN partner API roles and SD-WAN partner API clients](kb:shared.admin-rbac.zia-api-roles). How the role's limits on the logs period are set is open [gap:shared.admin-rbac.zia-permissions:logs-limit-values]. Sources beyond the help pages are unchecked [gap:shared.admin-rbac.zia-permissions:other-source-classes].

What to check:
1. For an admin who cannot see detailed transaction logs in Insights, whether the role's Reporting Access is Full, since Insights Access alone does not give them.
2. For an admin missing the Analytics menu, the Insights page or a reporting option, the role's Reporting Access, Insights Access and Reporting Data permissions.
3. For an admin who sees a View Restricted message on the Alerts page, the role's Alerts Access.
4. Before turning on Executive Insights App access for a role, which scopes and options the setting enables on its own.
