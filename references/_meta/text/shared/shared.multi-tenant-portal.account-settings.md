# What the Multi-Tenant Portal partner account settings hold: white labeling and logo, SAML SSO certificates and URLs, domains, partner support and password reset (shared.multi-tenant-portal.account-settings)

The Settings page shows the Partner ID generated when the account was created with Zscaler, the account status, and the Partner Type (the type of partner account). [shared.multi-tenant-portal.account-settings:settings-page-info] The values of Partner Type are not listed [gap:shared.multi-tenant-portal.account-settings:partner-type-values]. The Internal Domain field shows the domain generated when creating the partner account, a default domain for the partner's first login; a partner can have a maximum of 16 partner domains, and changing or adding a partner domain requires Zscaler Support. [shared.multi-tenant-portal.account-settings:domains]

**White labeling.** Enabling White Labeling white labels the tenants' Admin Portals; the items the partner can white label are Partner Support, Partner CSS Color Scheme (Magenta), Partner UI Logout URL, Account Logo and Background Color. [shared.multi-tenant-portal.account-settings:white-label-items] An account logo must be 300 x 220 pixels or less, 10 KB or less, and a .png, .jpg or .gif file; the logo is used to white label the tenants' ZIA Admin Portal if white labeling is enabled. [shared.multi-tenant-portal.account-settings:logo-limits] The Partner UI Logout URL is the URL that tenants see when they log out of the ZIA Admin Portal, and it is only available for white-labeled partners. [shared.multi-tenant-portal.account-settings:logout-url] Whether white labeling covers the ZIA Admin Portal alone or the tenants' admin portals generally differs by page [divergence:shared.multi-tenant-portal.account-settings:white-label-scope].

**Single sign-on.** SSO to the tenants' ZIA Admin Portal requires an SSO certificate from the partner's SAML service provider; the uploaded certificate is the public key extracted from it, as a binary-encoded DER file with a .der extension and no other periods in the file name. [shared.multi-tenant-portal.account-settings:sso-tenant-zia] The page lists, for SSO to the tenants' ZIA Admin Portal, the Assertion Consumer Service (ACS) URL https://admin.<Cloud_Name>/ssologin.do and the Entity ID https://admin.<Cloud_Name>. [shared.multi-tenant-portal.account-settings:sso-tenant-zia-urls] The IdP-initiated workflow names a different ACS URL target [divergence:shared.multi-tenant-portal.account-settings:tenant-zia-acs-url]. SSO to the Multi-Tenant Portal for Partners requires an SSO certificate from the partner's SAML service provider; the uploaded certificate is a Base64-encoded PEM file with a .pem extension and no other periods in the file name. [shared.multi-tenant-portal.account-settings:sso-portal] For SSO to the Multi-Tenant Portal for Partners the ACS URL is https://partners.zscalerscm.net/partnersso.do (depending on the IdP used), and Zscaler recommends https://partners.zscalerscm.net/ as a default value for the Entity ID, though any value unique to a customer or partner IdP can be used. [shared.multi-tenant-portal.account-settings:sso-portal-urls] The Multi-Tenant Portal supports IdP-initiated SSO, in which access and authentication take place through the partner's IdP portal. [shared.multi-tenant-portal.account-settings:idp-initiated]

**Support and passwords.** The Partner Support setting selects the support type tenants see in their Admin Portals, with a support email address if Email is selected or a support website URL if Portal URL is selected. [shared.multi-tenant-portal.account-settings:partner-support] Reset Password and Send Activation Email resets the default admin account password and sends a reset link; multiple Activation Email Recipients can be entered, and for partners migrated to Authentication Service the Reset Password feature moves under Administration in the Authentication Service Admin Portal. [shared.multi-tenant-portal.account-settings:password-reset] The End User Subscription Agreement selected in settings can be viewed as a notification for the partner's customers when logging in to the ZIA Admin Portal. [shared.multi-tenant-portal.account-settings:subscription-agreement]

Sources disagree (name both sides):
- The logo page ties the partner account logo to the tenant's ZIA Admin Portal, while the account settings page and Tenant Details page describe white labeling across the tenants' Admin Portals. [divergence:shared.multi-tenant-portal.account-settings:white-label-scope]
  - zscaler-help: The partner account logo is used for white labeling the tenant's ZIA Admin Portal.
  - zscaler-help: White Labeling white labels the Admin Portals of the partner's tenant accounts.
  - zscaler-help: Show Partner Logo indicates whether the partner logo is enabled in the admin portals the tenant has access to.
  Impact: Whether the logo and Partner UI Logout URL appear in tenant admin portals other than the ZIA Admin Portal is not stated.
- The SSO to Tenants' ZIA Admin Portal settings give the ACS URL as https://admin.<Cloud_Name>/ssologin.do, while the IdP-initiated workflow for the same SSO sends the assertion to the Partner Portal ACS URL. [divergence:shared.multi-tenant-portal.account-settings:tenant-zia-acs-url]
  - zscaler-help: The ACS URL/Destination URL is https://admin.<Cloud_Name>/ssologin.do.
  - zscaler-help: In the IdP-initiated workflow the browser sends the SAML assertion to the Partner Portal ACS URL.
  Impact: The page does not say whether the IdP-initiated tile posts to the ssologin.do URL or to the partners portal ACS URL.
