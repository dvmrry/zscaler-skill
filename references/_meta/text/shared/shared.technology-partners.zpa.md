# What the technology-partner deployment guides (grouped by the extractor split, not by product: mostly ZPA and mixed ZIA/ZPA guides, plus some ZIA log, SaaS and identity guides) say each partner integration does (shared.technology-partners.zpa)
Also called: zpa technology partners; zia and zpa partner integrations; partner deployment guides zpa; app connector partner guides

In the Microsoft Azure traffic forwarding guide, customer traffic destined for internal private resources can be connected over ZPA by placing a ZPA application connector inside the Azure environment. [shared.technology-partners.zpa:azure-wvd-zpa-connector] The partner guide pages are routed from [Zscaler technology partner guides: which subject holds which partner guides (split by partner name, not strictly by product)](kb:shared.technology-partners).

**Connectors in partner environments.** In the CoreWeave guide, deploying ZPA App Connectors in a CoreWeave Virtual Private Cloud (VPC) environment enables secure Least Privileged Policy based access to workloads. [shared.technology-partners.zpa:coreweave-app-connectors] The SUSE guide explains how to deploy Zscaler App Connectors on SUSE Enterprise Linux using Podman, which is the default container management and orchestration tool on SUSE Linux Enterprise. [shared.technology-partners.zpa:and-suse-enterprise-linux-podman]

**Posture and access.** In the Google Chrome Enterprise browser guide for unmanaged devices, Chrome Enterprise Device Trust Connectors are inputs in ZPA posture control for Access policy validation before granting access to a web-based private application, for organizations requiring device posture access policies for unmanaged devices. [shared.technology-partners.zpa:chrome-enterprise-posture] The IGEL guide uses clientless ZIA and ZPA features with IGEL OS: IGEL OS offers a platform to access Zscaler Isolation and Privileged Remote Access (PRA) from the user's browser of choice, without traditional virtual desktop infrastructure (VDI). [shared.technology-partners.zpa:igel-isolation-pra] In the Silverfort guide, the Zscaler Adaptive Access Engine receives user risk signals from Silverfort, which shares the context signal User Risk Level with it. [shared.technology-partners.zpa:and-silverfort] In the Okta and CrowdStrike guide, the Zero Trust Exchange service and Okta Workforce Cloud can use data derived from the Falcon ZTA score to automatically update policies as needed to secure access to private apps and internet apps based on the device posture and health scores. [shared.technology-partners.zpa:okta-and-crowdstrike]

**ZIA Sandbox EDR lookup (a ZIA feature, filed here by the extractor split).** In the Microsoft Defender guide, the integration leverages Microsoft Defender for Endpoint APIs to provide EDR visibility for Sandbox-detected malware: the Zscaler service calls the Microsoft Defender for Endpoint API and requests information for endpoints that were exposed to the malicious file. [shared.technology-partners.zpa:and-microsoft-defender]

**Identity and provisioning.** In the Okta guide, SAML is the preferred authentication method for both Internet & SaaS and Private Access; Okta is configured as the SAML identity provider (IdP), authenticating a user and passing the authorization credentials to Zscaler services as a SAML service provider (SP). [shared.technology-partners.zpa:and-okta] In the PingOne guide, SAML is the preferred method for authentication for both ZIA and ZPA, with Ping Identity configured as the SAML identity provider (IdP); provisioning is described as the automation of provisioning and de-provisioning of users and security groups to Zscaler services. [shared.technology-partners.zpa:and-pingone] In the SailPoint guide, SailPoint uses the SCIM integration between Zscaler and SailPoint to import all users and groups from the Zscaler instance to the customer's SailPoint instance, for the purpose of providing visibility of identity and entitlements. [shared.technology-partners.zpa:and-sailpoint] The Saviynt guide explains how to integrate the Saviynt Enterprise Identity Cloud (EIC) and the collaboration platform hosted by ZIA and ZPA to execute importing, provisioning and de-provisioning tasks. [shared.technology-partners.zpa:and-saviynt-connector] In the Trend Micro guide, when a user exceeds a defined risk threshold, Trend Vision One triggers an action to add them to an Internet & SaaS Restricted User Group, and can place the user into a Private Access Restricted User Group through SCIM provisioning. [shared.technology-partners.zpa:and-trend-micro] The Microsoft Entra ID passwordless guide covers two use cases: Windows Hello for Business for dedicated Windows 10/11 computers, and the Microsoft Authenticator app for shared devices, non-Windows devices or unmanaged Windows 10/11 computers; its sample deployment uses Microsoft Entra ID Hybrid Joined Devices with a Cloud Kerberos Trust Group Policy. [shared.technology-partners.zpa:and-microsoft-entra-id-passwordless]

**Logs and detections.** In the Cybereason guide, ZIA telemetry and critical events are streamed to Cybereason XDR, where suspicious events are correlated into Malicious Operations (MalOps); ZPA data sent to Cybereason XDR is exported as logs with a dedicated app connector and Log Streaming Service (LSS). [shared.technology-partners.zpa:cybereason-lss] In the Gurucul guide, ZPA can send logs to Gurucul using the Syslog endpoint through Log Streaming Service (LSS). [shared.technology-partners.zpa:gurucul-lss] The Darktrace integration ingests User Activity logs produced by ZPA, allowing connectivity patterns seen in network traffic to be matched back to remote users. [shared.technology-partners.zpa:darktrace-zpa-user-activity] In the Sekoia guide, Sekoia Defend receives NSS and Cloud NSS logs from Internet & SaaS, and LSS logs from Private Access. [shared.technology-partners.zpa:and-sekoia] In the Splunk guide, Zscaler can stream logs into customer environments via Zscaler-supplied virtual machines, which attach to the Zscaler cloud using outbound connections and receive encrypted and tokenized logs. [shared.technology-partners.zpa:and-splunk] The Sumo Logic App for ZIA collects logs via Cloud NSS to populate pre-configured searches and dashboards. [shared.technology-partners.zpa:and-sumo-logic] In the TEHTRIS guide, TEHTRIS SIEM can ingest raw log data from ZIA and ZPA using the Zscaler Nanolog Streaming Service (NSS). [shared.technology-partners.zpa:and-tehtris] The TEHTRIS guide names NSS for ZPA logs where the Sekoia and Cybereason guides name LSS [divergence:shared.technology-partners.zpa:zpa-log-transport]. The Panther guide says ZIA Admin Audit logs can be ingested into Panther by using either an HTTP source or an AWS S3 bucket. [shared.technology-partners.zpa:and-panther] In the Plixer guide, Zscaler Cloud Nanolog Streaming Service (NSS) is an optional service that uses HTTP and HTTPS to send logs, with no need to deploy a VM; once ZIA or ZPA log ingestion is configured and enabled, Plixer Scrutinizer can run preconfigured and custom reports against the collected log data. [shared.technology-partners.zpa:and-plixer] In the Vectra guide, customers using Internet & SaaS with Vectra have two options: on-premises capture, and a PCAP ingestion method that is currently in public preview; the LSS logs are preferably sourced from a dedicated app connector group used only for LSS. [shared.technology-partners.zpa:and-vectra] In the Portal26 guide, the integration transmits prompt data through ZIA to an incident receiver hosted by Portal26; the Zscaler Incident Receiver can run on AWS EC2, an Azure VM or on-premises, the Zscaler service sends policy-violation information to it via ICAP, and it sends the policy-violating content and a JSON file with the metadata for the inline web and CASB DLP policy scan. [shared.technology-partners.zpa:and-portal-26]

**Automation and workflows.** The Zscaler and HashiCorp Deployment Guide (ZPA with HashiCorp Terraform) gives DevOps teams guidelines on use cases for including ZPA in DevSecOps security and compliance workflows, and part of the configuration requires a ServiceNow template. [shared.technology-partners.zpa:hashicorp-terraform-servicenow] In the Cimcor guide, CimTrak's real-time detections and alerts trigger automated, targeted policies in Zscaler, in response to critical security events, changes in a system's hardening status, or when the system fails to meet DISA STIGs/CIS benchmarks. [shared.technology-partners.zpa:cimcor-cimtrak-triggers] The Tines guide provides instructions on integrating ZIA and ZPA with the Tines SOAR solution. [shared.technology-partners.zpa:and-tines] The VMware Carbon Black guide describes the integration of the two platforms as providing end-to-end visibility and protection from endpoint to applications in the cloud, with cross-platform workflows that reduce dwell time and mean-time-to-remediate (MTTR). [shared.technology-partners.zpa:and-vmware-carbon-black] In the Reach Security guide, Reach is fully agentless: it ingests metadata from the customer's Zscaler products and analyzes it within Reach's Amazon Web Services (AWS) cloud. [shared.technology-partners.zpa:and-reach-security]

**Data protection and connectivity.** The Smartsheet guide uses the SaaS Security Data at Rest Scanning Data Loss Prevention (DLP) policy, which uses Zscaler DLP engines to scan content for Smartsheet against criteria such as file type or collaboration scope. [shared.technology-partners.zpa:and-smartsheet] The LANCOM guide describes the configuration of a VPN connection to the Zscaler cloud; deploying IPSec allows the use of dynamic WAN addresses on the client side. [shared.technology-partners.zpa:and-lancom]

Sources disagree (name both sides):
- The TEHTRIS guide says ZPA logs reach TEHTRIS through NSS; the Sekoia and Cybereason guides say ZPA sends logs through LSS. [divergence:shared.technology-partners.zpa:zpa-log-transport]
  - zscaler-help: TEHTRIS: log data from ZIA and ZPA is ingested using NSS.
  - zscaler-help: Sekoia: Private Access sends logs via LSS.
  - zscaler-help: Cybereason: ZPA data is exported with a dedicated app connector and LSS.
  Impact: Do not state from the TEHTRIS page alone that ZPA logs go through NSS; the Sekoia and Cybereason pages attribute ZPA log export to LSS. The QRadar, Arctic Wolf and Sumo Logic pages (in other partner subjects) use NSS wording too.
