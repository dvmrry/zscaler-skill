# Why a Zscaler Terraform plan shows no diff, or a replacement: diff suppression, ForceNew and code-only checks (shared.terraform.plan-diffs)
Also called: DiffSuppressFunc; noChangeInMultiLineText; normalizeMultiLineString; DiffSuppressFuncCoordinate; terraform description not cleared; terraform plan no diff zscaler; terraform forcenew zscaler; terraform destroy recreate zscaler; terraform latitude longitude diff

Which arguments force replacement (ForceNew), conflict with each other, or are validated against a fixed list is generated per resource by `node scripts/kb.mjs surface <resource name>`. This collects the behavior the schema listing does not show.

## Multi-line text in the ZIA provider

The ZIA provider's `normalizeMultiLineString` trims the text and each line, doubles every `$` (`$` becomes `$$`) and appends a newline; `noChangeInMultiLineText` returns true (no difference) whenever the new text is empty, and otherwise compares the two normalized values. [shared.terraform.plan-diffs:zia-multiline-functions] In the ZIA provider, 39 resource files attach `noChangeInMultiLineText` as a DiffSuppressFunc, on `description` in 37 attachments and also on notification text fields such as `html_message`, `plain_text_message`, `subject` and `rule_text`; the URL Filtering rule pairs it with `normalizeMultiLineString` as its StateFunc. [shared.terraform.plan-diffs:zia-multiline-scope] On those ZIA attributes a value cannot be cleared by removing it or setting it to an empty string: the empty new value is suppressed as no difference, so no update is planned. [shared.terraform.plan-diffs:zia-multiline-cannot-clear] The URL Filtering case is [The provider suppresses a diff on a URL Filtering rule's description when the old and new text are equal after trimming each line and normalizing the trailing newline.](kb:zia.api.url-filtering-wire:tf-description-diff-suppression), and the ZTC provider carries the same pair of helpers ([The matching diff-suppress function returns true whenever the new text is empty, before it looks at the old text. By its own logic a change from a non-empty value to an empty one is never a difference.](kb:cloud-connector.terraform.provider-behavior:multiline-diff-suppress-ignores-clears)). Whether the ZIA API itself normalizes whitespace in these fields is open [gap:shared.terraform.plan-diffs:api-whitespace-normalization].

## Other suppressed diffs in the ZPA provider

The ZPA provider's `DiffSuppressFuncCoordinate` treats two coordinates as equal when they match after rounding to six decimal places, and it is attached to `latitude` and `longitude` on the App Connector group, Service Edge group and Private Cloud group resources. [shared.terraform.plan-diffs:zpa-coordinates] The connector group case is [The Terraform provider suppresses a plan difference on a connector group's latitude or longitude when the old and new values are equal after rounding to six decimal places.](kb:zpa.app-connectors.connector-groups:tf-coordinates-six-decimals). Service Edge group membership is ignored unless configured: [The Terraform Service Edge group resource declares service_edges optional and computed with a warning that membership is managed externally, and suppresses any diff on it unless the field is set in configuration.](kb:zpa.private-service-edges.terraform:service-edges-diff-suppressed-when-unset).

## Replacement

VPN credential identity fields force a new credential ([Neither the credential type nor, once set, its FQDN (UFQDN) or IP address (IP) can be changed on update: the Python SDK rejects the attempt, and the Terraform resource marks `type`, `fqdn` and `ip_address` ForceNew, so a change deletes and recreates the credential.](kb:zia.traffic-forwarding.vpn-credentials:immutable), [A pre-shared key is required for UFQDN and IP credentials; the Terraform resource marks it sensitive and forces replacement when it changes, and the data source's read-back is commented out.](kb:zia.traffic-forwarding.vpn-credentials:psk-required)). Provider v4.4.6 removed ForceNew from `select_connector_close_to_app` ([Terraform provider v4.4.6 removed `forceNew` from `select_connector_close_to_app` on `zpa_application_segment`, and the current schema declares it as an optional bool.](kb:zpa.app-segments.settings:forcenew-removed), [In the Terraform Browser Access resource, select_connector_close_to_app is a plain optional boolean without ForceNew.](kb:zpa.browser-access.tooling:tf-select-connector-not-forcenew)). The Cloud App Control rule type is not ForceNew in the schema ([In the provider schema the type argument is an optional string built by getAppControlType, described as the supported App Control types, and the resource's type entry carries no ForceNew flag.](kb:zia.terraform.cloud-app-control-rule:tf-rule-type-optional)). What a replaced policy rule does to rule order is open [gap:shared.terraform.plan-diffs:replaced-rule-order].

## Checks that live in code, not the schema

A Browser Access app that sets `certificate_id` with `ext_label` or `ext_domain` is rejected in the resource code ([In the Terraform Browser Access resource, a clientless app that sets certificate_id together with ext_label or ext_domain is rejected with the error "'certificate_id' cannot be set when either 'ext_label' or 'ext_domain' is configured".](kb:zpa.browser-access.tooling:tf-certificate-conflicts-ext-fields)); server groups check servers against dynamic discovery on create and update ([The Terraform provider rejects a server group with dynamic discovery off and no servers, on create and on update when servers or dynamic_discovery change.](kb:zpa.server-groups.discovery-mode:tf-dsd-off-needs-servers)); a credential rule needs exactly one of credential or pool ([The credential rule schema requires exactly one of `credential` or `credential_pool`, and the update code, when its request has neither (a block whose `id` is empty), copies the credential or pool from the rule it just read; it then returns an error only if neither carries an ID.](kb:zpa.terraform.policy-rule-writes:credential-update-restores-remote-association)); Service Edge grace distance fields go together ([grace_distance_value and grace_distance_value_unit are RequiredWith grace_distance_enabled in the schema, and each is RequiredWith the other, so setting either value or unit requires the other two fields.](kb:zpa.private-service-edges.terraform:zpa-terraform-grace)). A provider validator shows what the provider accepts, which can differ from the API, as with BRAVE ([Before v4.8.9 the provider's `user_agent_types` validator accepted OPERA, FIREFOX, MSIE, MSEDGE, CHROME, SAFARI, MSCHREDGE and OTHER, and omitted BRAVE. v4.8.9 adds BRAVE to the list (#607).](kb:zia.terraform.url-filtering-rules:validator-omits-brave)).

What to check:
1. When a ZIA description or notes change does not plan, whether the new value is empty, which the diff suppression always treats as no change.
2. Whether the argument being changed is marked force_new in the generated surface for that resource, before applying a change to a rule or credential.
