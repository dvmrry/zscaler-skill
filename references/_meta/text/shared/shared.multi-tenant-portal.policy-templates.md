# How Multi-Tenant Portal policy templates are created, assigned to tenants and tenant groups, reordered, edited in ZIA and deleted (shared.multi-tenant-portal.policy-templates)

A partner can create multiple policy templates and apply them to tenant accounts. [shared.multi-tenant-portal.policy-templates:definition] A tenant or tenant group can be associated to only one policy template. [shared.multi-tenant-portal.policy-templates:one-template] The policy template list shows No. of Tenants (tenants assigned the same template) and the actions Edit, Delete and Edit Policy Template in ZIA. [shared.multi-tenant-portal.policy-templates:list-columns]

**Creating a template.** The Add Policy Template window takes a Name, a Cloud (where the tenant is provisioned), Tenants (listed based on the cloud selected, with Add Cloud to add another cloud) and Tenant Groups, and is saved with Save and Edit Policies. [shared.multi-tenant-portal.policy-templates:add-fields] A policy template description is optional and cannot exceed 256 characters. [shared.multi-tenant-portal.policy-templates:description-limit] The Allow Policy Rule Reorder option is disabled by default, so the policy is enforced at top priority; if enabled, ZIA Admin Portal admins can change the order of the policy in the Rule Order option. [shared.multi-tenant-portal.policy-templates:rule-reorder]

**Editing in ZIA.** The Edit Policy Template on ZIA action redirects to the ZIA Admin Portal, where policies can be saved and synchronized for multiple tenants under multiple clouds. [shared.multi-tenant-portal.policy-templates:edit-in-zia] The Rule Order option in a URL Filtering rule edited through a policy template is only editable if Allow Policy Rule Reorder is enabled in the Multi-Tenant Portal. [shared.multi-tenant-portal.policy-templates:rule-order-editable] In a URL Filtering rule edited through a policy template, Rule Label, Source IP Groups, Users, Groups, Departments, Locations, Location Groups, Devices, Device Groups, Device Trust Level and HTTP Header Profiles are not synchronized with the user and are not editable. [shared.multi-tenant-portal.policy-templates:unsynced-fields]

**Deleting.** Deleting a policy template removes it from the Multi-Tenant Portal database, but the configured template and policies remain in the ZIA policy configurations; the ZIA admin gets full access to the template, which was initially read-only. [shared.multi-tenant-portal.policy-templates:delete-behaviour] The Edit and Delete steps for portal items are in [How Multi-Tenant Portal partner admins, RBAC role templates and scopes work, and the Edit and Delete steps for portal items](kb:shared.multi-tenant-portal.administration).
