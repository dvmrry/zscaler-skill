# What the products on the Logs and Fair Use pages define as their logs, and what extra data they capture (shared.logs-fair-use.log-contents)

ZIA logs are defined as network traffic metadata for your SaaS applications. [shared.logs-fair-use.log-contents:zia-def] For the ZIA Data Loss Prevention service on any channel (Inline, Endpoint, Email, API CASB, Private Applications), logs also capture metadata for certain end-user activities such as copying to removable storage or network shares, printing, sharing a file and uploading a document; Email DLP logs include senders, recipients and subjects. [shared.logs-fair-use.log-contents:zia-dlp] By default, end-user prompts to supported generative AI applications are not captured in ZIA logs; they are captured only if an administrator enables the toggle in the Admin Portal, and Gen AI Security logs include classifications of prompts. [shared.logs-fair-use.log-contents:zia-genai] Endpoint Context service logs also capture telemetry about user devices, which may include software process level information. [shared.logs-fair-use.log-contents:zia-endpoint-ctx] The hub is [Where to find a Zscaler product's log retention, log contents, license unit and fair-use limit](kb:shared.logs-fair-use).

**ZPA.** ZPA defines its logs as User Logs, App Connector Logs, AppProtection Logs, API Discovery Logs (derived from AppProtection Logs), Audit Logs (configuration changes via the ZPA Admin Portal), Privileged Session Recordings, Privileged Session Files and Zscaler Microsegmentation Agent Logs. [shared.logs-fair-use.log-contents:zpa-types] If you order the VPN Connectivity service, ZPA logs also include VPN Connector Logs and VPN Service Edge Logs; ZPA logs do not include your internal system logs. [shared.logs-fair-use.log-contents:zpa-vpn] Zscaler Microsegmentation Agent Logs hold host and cloud details (hostname, OS name and version, network addresses, cloud name/account/region, VPC/VNET and subnet details, user-defined cloud tags), traffic connection information and host resource telemetry (CPU, memory, file descriptor utilization). [shared.logs-fair-use.log-contents:zpa-zms-agent] The ZPA Agent operates through the ZAgent service. [shared.logs-fair-use.log-contents:zpa-agent]

**ZDX.** ZDX logs are the telemetry metadata collected via ZDX probes and Microsoft 365 probes plus metadata that correlates with logs of other Zscaler SaaS products such as ZIA or ZPA. [shared.logs-fair-use.log-contents:zdx-def] Enabling ZDX Remediation (remote scripts on user devices) allows collection of script output and device telemetry data; ZDX Snapshot captures the current state of a UI page and gives a URL for view-only access. [shared.logs-fair-use.log-contents:zdx-remediation]

**Cloud posture and AI products.** DSPM processes cloud configuration data, CSP activity audit logs and cloud user directory information; subject to configuration and enablement it also scans and classifies cloud data stores (raw data is not saved, only static metadata) and scans CSP-hosted VM OS drives for installed packages and CVEs. [shared.logs-fair-use.log-contents:dspm-scan] ZPC processes cloud configuration data, CSP activity audit logs, cloud network logs and cloud user directory information; with the vulnerability scanning subscription (ZPC Vulnerability or ZPC Advanced) it also analyzes VM OS drives and container images, and with the IaC subscription (ZPC IaC or ZPC Advanced) it analyzes IaC scripts, subject to customer configuration and enablement. [shared.logs-fair-use.log-contents:zpc-scan] For AI Asset Management for AI Infrastructure, logs are cloud configuration data, CSP activity audit logs and cloud user directory information, plus (subject to configuration) static metadata of data in cloud data stores and VM OS-drive scans for packages and CVEs. [shared.logs-fair-use.log-contents:ai-infra-def] For AI Asset Management Platform, logs are network traffic metadata for your SaaS applications and also capture telemetry about user devices, which may include software process level information. [shared.logs-fair-use.log-contents:ai-platform-def] AI Guard logs are prompts, responses and other metadata; application name, policy triggered and timestamp are stored, end user prompts and prompt responses are stored if you opt in to Store Prompt/Responses, and LLM details are also stored if AI Guard is deployed as a proxy. [shared.logs-fair-use.log-contents:ai-guard] AI Scanning Platform logs capture information such as testing prompts, responsive outputs and AI model/application configuration data. [shared.logs-fair-use.log-contents:ai-scan-def]

**Agentic SecOps and exposure products.** For Agentic SecOps Platform products including Agentic SOC, logs are configuration and transaction data for actions by users you authorize; for Agentic SOC this includes duplicates of applicable Zscaler SaaS product logs such as ZIA or ZPA used to identify suspicious threat patterns; some Agentic SecOps Platform products define logs differently. [shared.logs-fair-use.log-contents:secops-def] Breach Predictor logs are duplicates of the configuration and transaction data collected via logs from other Zscaler SaaS products such as ZIA or ZPA, used to identify suspicious and potentially malicious threat patterns. [shared.logs-fair-use.log-contents:breach-def] Threat Hunting logs are duplicates of applicable Zscaler SaaS products' logs. [shared.logs-fair-use.log-contents:threat-hunting-def] For AEM, logs are configuration and transaction data for actions by users you authorize within the AEM SaaS Application. [shared.logs-fair-use.log-contents:aem-def] For UVM, logs are configuration and transaction data for actions by users you authorize within the UVM SaaS Application. [shared.logs-fair-use.log-contents:uvm-def] For Identity Protection, logs are configuration and transaction data for actions by authorized users within the application; when enabled, data is queried from your identity provider and stored with processed analytics on the Agentic Security Operations Platform. [shared.logs-fair-use.log-contents:idp-def] EASM logs are the public internet-facing assets that EASM discovers and scans; the page lists web pages, SSL/TLS certificates and IP addresses among them. [shared.logs-fair-use.log-contents:easm-def]

**Client and connector products.** Client Connector logs are Packet Capture Logs, Client Connector Logs and Tunnel Logs; packet capture can be globally enabled or disabled, and Client Connector log verbosity is configurable. [shared.logs-fair-use.log-contents:zcc-types] Client Connector logs might also contain local performance and diagnostic metrics (Zscaler Client Connector Telemetry); if the log tenant is in the European Union you can enable it in the Client Connector Portal settings page, for all others it is enabled by default with an opt-out on the same page. [shared.logs-fair-use.log-contents:zcc-telemetry] Cloud & Branch Connector logs are Session, Tunnel, DNS and Audit Logs; Audit Logs cover configuration changes made via the Cloud & Branch Connector Admin Portal or API. [shared.logs-fair-use.log-contents:cbc-types] Zero Trust Gateway logs are defined as Session, Tunnel, DNS and Audit Logs; its Audit Logs are configuration changes made via the Cloud & Branch Connector Admin Portal or API. [shared.logs-fair-use.log-contents:ztg-types] Zscaler Cellular Edge logs are Session, Tunnel, DNS and Audit Logs; its Audit Logs are configuration changes via the Cloud & Branch Connector Admin Portal or API. [shared.logs-fair-use.log-contents:cellular-edge] Zscaler SIM logs source information from the mobile network operators and include IMSI, IMEI and CDR information; SIM Event Logs record events such as SIM authenticated time, SIM location and network change, and SIM Data Usage Logs hold bytes transferred and time of usage; these apply only to the Zscaler SIM services. [shared.logs-fair-use.log-contents:cellular-sim] ZSDK logs are User Logs, App Connector Logs and Audit Logs (configuration changes via the ZSDK Admin Portal), and do not include your internal system logs. [shared.logs-fair-use.log-contents:zsdk-types] Endpoint AI Security logs are metadata and telemetry from AI-driven activity on managed endpoints, policy decisions, asset inventory, and content such as user prompts and tool inputs/outputs; if you opt out of prompt and tool input/output capture, tool calls are still logged but not the prompts or responses. [shared.logs-fair-use.log-contents:endpoint-ai-def]

**Zero Trust products.** Zero Trust Branch logs are Session Logs (traffic flow for sessions from endpoints connected to the Zscaler segmentation network) and Audit Logs (configuration changes in the Zero Trust Branch Admin Portal or API). [shared.logs-fair-use.log-contents:ztb-def] Zero Trust Device Segmentation (formerly Airgap) logs are Session Logs and Audit Logs; Audit Logs are configuration changes made in the Device Segmentation Admin Portal or API. [shared.logs-fair-use.log-contents:devseg-def] Zero Trust Browser logs are Agent Logs, Workspaces Logs and Zero Trust Extension Tenant Dashboard Logs; the page gives Info as the default log level in the Workspaces Logs entry and says its verbosity is configurable by the user. [shared.logs-fair-use.log-contents:ztbrowser-types] Zero Trust Extension Tenant Dashboard Logs capture telemetry such as policy evaluation for browsing, heartbeat, authentication, audit and diagnostic logs, plus configuration change logs such as policy modifications and administrative audit logs. [shared.logs-fair-use.log-contents:ztbrowser-dash] The Zero Trust Browser Agent Logs entry says the default logging level is Info and that Agent Logs capture information related to the agent and posture collection activities. [shared.logs-fair-use.log-contents:ztbrowser-agent] For the Cloud Browser Isolation feature, Zero Trust Browser logs may capture passwords users enter for password-protected files, which is required to view the file within Zero Trust Browser. [shared.logs-fair-use.log-contents:ztbrowser-passwords]

**Other products.** Authentication Service Audit Logs are activity records of configuration and authentication changes in a Zscaler administrative UI or API, including administrator and user sign-in and sign-out attempts, including unsuccessful ones. [shared.logs-fair-use.log-contents:auth-audit-def] Adaptive Access Engine logs are Signal History (security context signals from products such as ZIA and third-party security products that typically indicate a level of risk for a user or device) and Audit Logs (configuration changes in the Admin Portal and via the Adaptive Access Engine API). [shared.logs-fair-use.log-contents:aae-def] Business Insights logs are SaaS Application Usage Logs and Workplace Insights Logs, generated from ZIA logs and from Business Insights connectors you configure to collect usage data from SaaS providers. [shared.logs-fair-use.log-contents:bi-def] Network Observability logs are the network telemetry collected from Network Observability probes and your network devices. [shared.logs-fair-use.log-contents:network-obs-def] SSPM logs are user and application activity metadata for your SaaS applications and third-party SaaS application integrations. [shared.logs-fair-use.log-contents:sspm-def] Health360 logs are product usage data, policy and configuration data, and product health data processed to generate insights about your use of Zscaler products. [shared.logs-fair-use.log-contents:health360-def] Experience Center logs are records of administrative access and usage within Experience Center. [shared.logs-fair-use.log-contents:experience-center-def] Deception logs are Security Telemetry Logs (from interactions between suspected attackers and auto-generated decoys) and Audit logs (configuration changes on the Deception Admin Portal); they do not include your internal system logs. [shared.logs-fair-use.log-contents:deception-def] With the Deception log streaming service ordered, logs can be streamed in real time to an on-premises solution and sent to multiple systems for retention as long as you choose. [shared.logs-fair-use.log-contents:deception-stream]
