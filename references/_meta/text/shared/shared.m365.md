# Microsoft 365 Conditional Access through Source IP Anchoring (shared.m365)
Also called: m365 conditional access; microsoft 365 conditional access zscaler; entra id conditional access named locations; azure ad conditional access sipa; office 365 trusted location zscaler; unexpected mfa m365 zia; m365 sign-in blocked behind zscaler

Microsoft 365 Conditional Access policies that trust a set of source IP ranges see Zscaler addresses, not corporate ones, once sign-ins go through Internet & SaaS. Source IP Anchoring is the vendor's answer for that use case, and this subject walks it end to end.

1. **Why is it needed?** The vendor's use case: [Source IP Anchoring addresses Microsoft 365 Conditional Access that lets users in only from a trusted location such as a corporate network (with multifactor authentication) and blocks other locations; anchoring associates the traffic with the trusted location.](kb:zia.saas-apps.conditional-access:ca-use-case) Without anchoring, the sign-in arrives from a shared Public Service Edge address: [Sign-ins routed through ZIA's shared Public Service Edge addresses fail an IP-based named-location check, because the destination sees a Zscaler address rather than a corporate one; anchoring makes it see the App Connector's address.](kb:zia.saas-apps.conditional-access:shared-edge-ips-fail-named-location) With it, the destination sees the App Connector's address: [With Source IP Anchoring the destination sees the IP address of the Private Access App Connector deployed for it as the source. Traffic goes through the intranet to internal destination servers and through the internet to external ones.](kb:zia.forwarding-control.sipa:purpose)
2. **What has to be anchored?** Only the sign-in: [Anchoring only the initial login traffic to the Microsoft Azure AD domain is sufficient; after sign-in the application traffic uses an authenticated token and does not need to be redirected.](kb:zia.saas-apps.conditional-access:anchor-login-only) The segment names the Microsoft sign-in hosts: [The Office 365 application segment for anchoring names login.microsoftonline.com (login.windows.net or login.microsoft.com are alternatives), on TCP 80 and 443.](kb:zia.saas-apps.conditional-access:login-hosts) With the anchored segment limited to the Microsoft sign-in hosts, the application traffic that follows sign-in does not take the anchored path through the App Connector. [shared.m365:narrow-scope]
3. **How is it configured?** The Private Access and Internet & SaaS steps, and where the Microsoft 365 article departs from the general one: [Configuring Source IP Anchoring for Microsoft 365 sign-in](kb:shared.m365.sipa-setup).
4. **Why does a sign-in still get challenged or blocked?** Failure paths, and the Microsoft-side behavior no captured source settles: [Why a Microsoft 365 sign-in is still challenged or blocked with Source IP Anchoring](kb:shared.m365.troubleshooting).

## Prerequisites and limits

- **Licensing.** [Source IP Anchoring does not need a Private Access license, but a Source IP Anchoring subscription is required.](kb:zia.forwarding-control.sipa:licensing) What the API returns when anchoring is configured without the subscription is open [gap:shared.m365:missing-subscription-error].
- **Z-Tunnel 1.0 users.** [To support Source IP Anchoring for Z-Tunnel 1.0 traffic, Enable Firewall for Z-Tunnel 1.0 and PAC Road Warriors must be on in Advanced Settings.](kb:zia.forwarding-control.sipa:ztunnel1-option)
- **Segment settings that exclude anchoring.** Double Encryption: [Double Encryption cannot be enabled when Browser Access or Source IP Anchoring is selected for any application, and should be disabled for extranet application segments.](kb:zpa.app-segments.settings:double-encryption-exclusions) Inspect Traffic with ZIA: [Source IP Anchor and Inspect Traffic with ZIA cannot both be enabled on a segment; Source IP Anchor must be disabled first.](kb:zpa.app-segments.settings:sipa-inspect-zia-exclusive) Multimatch: [Multimatch is not supported for applications that have Source IP Anchoring enabled, and with Multimatch enabled the Health Reporting of an application segment can only be On Access or None.](kb:zpa.app-segments.multimatch-requirements:sipa-health-reporting) Whether Browser Access excludes it too is open: [Whether Source IP Anchor and Browser Access can be combined on a segment](kb:zpa.app-segments.settings:sipa-browser-access).
- **Other stable-address paths.** Whether a Cloud Connector (ECZPA) gateway or a Dedicated IP gateway can stand in for the App Connector here is open [gap:shared.m365:other-anchors]. Dedicated IP is a separate forwarding method: [A Dedicated IP rule chooses a dedicated IP gateway; selecting the Default gateway lets the Zscaler service pick the optimal data center. The default gateway is created when dedicated IP addresses are allocated, cannot be edited or deleted, and directs traffic to the geographically nearest data center that has a dedicated IP address assigned.](kb:zia.forwarding-control.methods:dedicated-ip-gateway), [BYOIP and Source IP Anchoring are different mechanisms: BYOIP brings a customer-owned, ROA-authorized prefix into the Dedicated IP service, while Source IP Anchoring makes the Private Access App Connector's address the source. Licensing and mechanism assumptions for one do not carry to the other.](kb:zia.forwarding-control.byoip:not-sipa).
- **Country criteria in Private Access.** [For Cloud Connectors, Source IP Anchoring traffic and Private Access multi-hop, the country criterion uses the last NATed layer 3 public IP address, so SIPA traffic takes its country from the Internet & SaaS Public Service Edge's public IP.](kb:zpa.policy.criteria:country-last-nat-ip)
- **Disaster recovery.** While Internet & SaaS is in disaster recovery mode, the admin changes the anchoring configuration to Source IP Anchoring Direct and reverts it afterwards: [Source IP Anchoring Direct is a set of Private Access configurations that keeps Source IP Anchoring forwarding working while ZIA is in disaster recovery mode; the Source IP Anchoring configurations must be changed to it for the duration of the event.](kb:zia.forwarding-control.sipa-direct:definition), [When the disaster recovery event ends, revert both client forwarding rules (Forward to ZPA back to Bypass ZPA, and back to Only Forward Allowed Applications) and restore the Source IP Anchoring access policy rules.](kb:zia.forwarding-control.sipa-direct:revert-rules)

The general Source IP Anchoring reference, not converted yet, is [Source IP Anchoring across ZIA and Private Access: path, pieces and interactions](kb:shared.source-ip-anchoring).
