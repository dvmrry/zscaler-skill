# A fixed egress address: Source IP Anchoring, Dedicated IP or BYOIP (shared.source-ip-anchoring.egress-options)
Also called: dedicated ip; enatdedip; dedicated ip gateway; static egress ip; customer-attributable egress ip; sipa vs dedicated ip; dedicated ip failover

Several Zscaler options replace the shared Zscaler egress address with one tied to the organization. Some applications and vendors accept traffic only from a preset list of source IP addresses and drop traffic from any other address, and some restrict access geographically by IP, so traffic is denied when Zscaler has no Public Service Edge in the address range in question. [shared.source-ip-anchoring.egress-options:ip-requirements] The reference architecture names three forwarding methods that meet such requirements, each needing additional work and subscriptions: registering Zscaler IP addresses with the vendor; Source IP Anchoring, where an App Connector in a public cloud (AWS, Azure, GCP) or the on-premises data center becomes the source address; and a ZIA Virtual or Private Service Edge in the organization's data center, managed by Zscaler, which allows NAT as traffic leaves the Service Edge. [shared.source-ip-anchoring.egress-options:three-methods] Dedicated IP, a Forwarding Control method, is a further option the reference architecture does not list there. Dedicated IP puts the organization's address on the egress at a Zscaler data center, an address dedicated to the tenant there, whereas Source IP Anchoring egresses from the organization's own App Connector. [shared.source-ip-anchoring.egress-options:anchor-vs-dedicated] The BYOIP case is [BYOIP and Source IP Anchoring are different mechanisms: BYOIP brings a customer-owned, ROA-authorized prefix into the Dedicated IP service, while Source IP Anchoring makes the Private Access App Connector's address the source. Licensing and mechanism assumptions for one do not carry to the other.](kb:zia.forwarding-control.byoip:not-sipa).

**Source IP Anchoring.** The address is the App Connector's [With Source IP Anchoring the destination sees the IP address of the Private Access App Connector deployed for it as the source. Traffic goes through the intranet to internal destination servers and through the internet to external ones.](kb:zia.forwarding-control.sipa:purpose), and the feature needs its own subscription [Source IP Anchoring does not need a Private Access license, but a Source IP Anchoring subscription is required.](kb:zia.forwarding-control.sipa:licensing); the sources disagree on whether Private Access is also needed [shared.source-ip-anchoring:subscriptions](kb:shared.source-ip-anchoring:subscriptions). Zscaler recommends sending only the applications, URLs or IP addresses that need a set source address through anchoring and forwarding the rest directly from the Service Edge; forwarding all traffic to a public cloud can become cost-prohibitive in bandwidth and App Connector VMs, and for all traffic from static addresses Zscaler recommends Virtual or Private Service Edges at campus locations. [shared.source-ip-anchoring.egress-options:anchor-selectively]

**Zscaler addresses or Service Edges.** Registering Zscaler ranges with the vendor is in [If a vendor accepts Zscaler IP addresses, the reference architecture says to update the application with the Zscaler IP address range, listed by cloud at config.zscaler.com/<cloud>/cenr. It can be a subset when access comes only from fixed site locations: from the primary and secondary data centers up to the entire Public Service Edge range; the vendor's requirements decide.](kb:shared.multi-cluster.egress-addresses:vendor-ranges); Virtual Service Edges are in [The Virtual Service Edge cluster: limits, object, build order and Location binding](kb:zia.virtual-service-edge.clusters) and Private Service Edges in [ZIA Private Service Edge](kb:zia.private-service-edge).

**Dedicated IP.** The Dedicated IP feature is enabled for a tenant through the Zscaler Account team. Gateway objects forward traffic through a dedicated IP address provisioned to the organization, and Forwarding policies use them for traffic that matches a rule's criteria. [shared.source-ip-anchoring.egress-options:dedicated-ip-enable] With the default gateway, the egress source address is the dedicated IP address assigned to the tenant at the data center. Traffic can be serviced at one data center and egress from another: a tenant with dedicated addresses only in San Jose is serviced in Los Angeles but egresses from San Jose, without forwarding to San Jose explicitly. [shared.source-ip-anchoring.egress-options:dedicated-egress] How the default gateway picks a data center: [A Dedicated IP rule chooses a dedicated IP gateway; selecting the Default gateway lets the Zscaler service pick the optimal data center. The default gateway is created when dedicated IP addresses are allocated, cannot be edited or deleted, and directs traffic to the geographically nearest data center that has a dedicated IP address assigned.](kb:zia.forwarding-control.methods:dedicated-ip-gateway). A dedicated IP gateway has a primary and a secondary data center; with Auto, the secondary is chosen by proximity to the Public Service Edge servicing the traffic. When that Public Service Edge cannot reach the NAT instance in the primary data center, failover to the secondary happens automatically; manual failover to a backup data center is not supported. [shared.source-ip-anchoring.egress-options:dedicated-failover] Excluding a subcloud does not affect data center selection for dedicated IP addresses: subclouds manage the data centers that service ingress traffic, and dedicated IPs are used on the egress path. [shared.source-ip-anchoring.egress-options:subcloud-independent] The addresses can be customer-owned: [Customer-owned Dedicated IP addresses (BYOIP)](kb:zia.forwarding-control.byoip). What an unlicensed tenant sees when it uses the method is open [gap:shared.source-ip-anchoring.egress-options:unlicensed-dedicated-ip].

**In Terraform.** The method values and their required fields are in [Forwarding methods and their required fields](kb:zia.forwarding-control.methods), and the ZPA method's apply-time delay in [Terraform behavior of ZPA-method forwarding rules](kb:zia.forwarding-control.terraform).

What to check:
1. If the destination must see an address the organization controls on its own network, use Source IP Anchoring; if an address dedicated to the organization at a Zscaler data center is enough, Dedicated IP.
2. For Dedicated IP, list which data centers hold the organization's dedicated addresses and the gateway's primary and secondary data centers: traffic can egress from a different data center than the one that serviced it.
