# Which Zscaler source addresses a destination can see, and what to allowlist (shared.multi-cluster.egress-addresses)
Also called: zscaler egress ip ranges; allowlist zscaler ips; egress ip changes between clusters; named locations zscaler ip; which ip does zia egress from

Traffic forwarded Direct leaves with the Zscaler service address [Direct forwards the traffic to the destination server using the Zscaler service IP address.](kb:zia.forwarding-control.methods:direct-meaning). When ZIA processes traffic, its source IP address is changed to that of the Service Edge processing it, which is needed for the traffic to flow back through the same Service Edge. [shared.multi-cluster.egress-addresses:source-is-processing-edge] Under Multi-Cluster Load Sharing, traffic forwarded with the Zscaler service address can reach a destination from a cluster in any of the network address blocks listed for the data center, so the source address the destination sees is not limited to one block. [shared.multi-cluster.egress-addresses:egress-any-block]

**Allowlists.** If a vendor accepts Zscaler IP addresses, the reference architecture says to update the application with the Zscaler IP address range, listed by cloud at config.zscaler.com/<cloud>/cenr. It can be a subset when access comes only from fixed site locations: from the primary and secondary data centers up to the entire Public Service Edge range; the vendor's requirements decide. [shared.multi-cluster.egress-addresses:vendor-ranges] A destination that allowlists Zscaler addresses for traffic forwarded with the service address needs every network address block that the cenr list gives for the data centers its users reach, not only the block of the cluster seen in one test. [shared.multi-cluster.egress-addresses:allowlist-all-blocks] Conditional Access built on named locations has the same problem, and Zscaler's answer there is anchoring: [Conditional Access blocks users behind ZIA: Source IP Anchoring](kb:zia.saas-apps.conditional-access).

**Taking cluster choice out of it.** Source IP Anchoring and Dedicated IP give a source address that does not depend on which cluster inspected the traffic: anchored traffic leaves with the App Connector's address, and Dedicated IP traffic with the address dedicated to the tenant at a data center. [shared.multi-cluster.egress-addresses:organization-address-independent] The options compared: [A fixed egress address: Source IP Anchoring, Dedicated IP or BYOIP](kb:shared.source-ip-anchoring.egress-options).

What to check:
1. Build a source-IP allowlist from every network address block that config.zscaler.com/<cloud name>/cenr lists for the data centers in use, not from addresses seen in one test.
2. If the destination needs one stable address, check whether the rule forwards with ZPA (Source IP Anchoring) or Dedicated IP rather than Direct.
