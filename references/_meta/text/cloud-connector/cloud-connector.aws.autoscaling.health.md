# Cloud Connector autoscaling health: custom health metric, the Zscaler Lambda, grace period (cloud-connector.aws.autoscaling.health)
Also called: cloud_connector_aggr_health; MISSING_DATAPOINTS_UNHEALTHY; cloud connector asg instance terminated unhealthy; cloud connector lambda aws autoscaling; HC_UNHEALTHY_THRESHOLD; cloud connector asg reboot terminated; health_check_grace_period cloud connector

Autoscaling replaces Cloud Connectors it judges unhealthy, and the judgement combines EC2 status checks with a Zscaler health metric evaluated by a Zscaler Lambda.

**Two health signals.** Autoscaling runs EC2 status checks on InService VMs at one-minute intervals; any failed check makes the status Impaired. [cloud-connector.aws.autoscaling.health:ec2-status-checks] Each Cloud Connector posts a custom health metric every minute to the Zscaler custom namespace in CloudWatch, 0 for unhealthy and 100 for healthy, shown in logs and reports as cloud_connector_aggr_health. [cloud-connector.aws.autoscaling.health:custom-health-metric] The reference ASG module's `health_check_type` defaults to EC2 and accepts EC2 or ELB. [cloud-connector.aws.autoscaling.health:module-health-check-type]

**How unhealthy is decided.** The Lambda evaluates the health metric over a sliding window of 10 consecutive minutes by default and marks a VM unhealthy when it is unhealthy for 5 consecutive minutes or for 7 of the 10. [cloud-connector.aws.autoscaling.health:sliding-window] The reference Lambda module hardcodes HC_DATA_POINTS 10, HC_UNHEALTHY_THRESHOLD 7, HC_UNHEALTHY_CONTIGUOUS_DP 5 and MISSING_DATAPOINTS_UNHEALTHY true in the function environment. [cloud-connector.aws.autoscaling.health:module-health-env] A VM that publishes no health metrics is treated as unhealthy by default; changing MISSING_DATAPOINTS_UNHEALTHY in the Lambda's environment makes the Lambda ignore missing data points. [cloud-connector.aws.autoscaling.health:missing-datapoints]

**The Lambda.** EventBridge triggers the Lambda every minute to check VM health, on EC2 instance termination events and on lifecycle termination events; the module implements these as a rate(1 minute) schedule, an EC2 Instance-terminate Lifecycle Action rule for the group names, and an EC2 state-change rule for terminated. [cloud-connector.aws.autoscaling.health:lambda-triggers] Each Lambda run lasts at most three minutes (the module sets timeout 180 seconds and 256 MB), and it logs to a CloudWatch log group whose retention defaults to three days. [cloud-connector.aws.autoscaling.health:lambda-runtime] After a termination the Lambda calls the Admin Console REST API to remove the VM from its Cloud Connector group, cleans up the VM's Internet & SaaS and Private Access resources, completes the lifecycle action, and manages termination of warm-pool VMs. [cloud-connector.aws.autoscaling.health:lambda-cleanup] Its permissions are in [Cloud Connector on AWS: IAM for the instance, the autoscaling Lambda, and the deployer](kb:cloud-connector.aws.iam).

**Grace period.** A new Cloud Connector gets a grace period, 900 seconds by default, after entering service before its health is checked; if it is not healthy when the period ends, autoscaling removes it from the Admin Console by API and terminates it. [cloud-connector.aws.autoscaling.health:grace-period] The reference ASG module's `health_check_grace_period` defaults to 900 seconds. [cloud-connector.aws.autoscaling.health:module-grace]

**Manual actions.** A VM terminated manually from the EC2 console is replaced, and stopping or rebooting an ASG member from the EC2 console could cause it to be terminated. [cloud-connector.aws.autoscaling.health:console-actions]

**CloudFormation template.** The CloudFormation autoscaling group uses EC2 health checks with a grace period of 900 seconds, which the changelog says was set to prevent instance termination when an instance moves to InService. [cloud-connector.aws.autoscaling.health:cfn-asg-health] The CloudFormation template's Lambda uses the handler zscaler_cc_lambda_service.lambda_handler on arm64 with 256 MB and a 180-second timeout, takes its code from the S3 bucket and key parameters, runs python3.12 (python3.11 in the aws-us-gov and aws-cn partitions) and logs to a CloudWatch group retained 3 days by default. [cloud-connector.aws.autoscaling.health:cfn-lambda-config] The template sets the Lambda's health environment to HC_DATA_POINTS 10, HC_UNHEALTHY_THRESHOLD 7, HC_UNHEALTHY_CONTIGUOUS_DP 5 and MISSING_DATAPOINTS_UNHEALTHY true. [cloud-connector.aws.autoscaling.health:cfn-lambda-health-env] The template invokes the Lambda from three EventBridge rules: the EC2 instance-terminate lifecycle action of the group, any EC2 instance state change to terminated (the pattern has no group filter), and a rate(1 minute) schedule. [cloud-connector.aws.autoscaling.health:cfn-lambda-triggers]

What to check:
1. Whether the terminated instance stopped publishing cloud_connector_aggr_health, since missing data points count as unhealthy by default.
2. Whether the health metric was 0 for 5 consecutive minutes or 7 of the last 10.
3. Whether someone stopped or rebooted the instance from the EC2 console.
4. Whether the Lambda's CloudWatch log group shows the run, within the default three-day retention.
