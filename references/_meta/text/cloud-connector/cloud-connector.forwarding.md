# Cloud Connector traffic forwarding (cloud-connector.forwarding)
Also called: cloud connector traffic forwarding; cloud connector forwarding rules; ecRdr; ztc_traffic_forwarding_rule; where does cloud connector send this traffic; cloud connector workload cannot reach internet; workload going direct instead of through zscaler

Traffic Forwarding forwards selected traffic to specific destinations: through Internet & SaaS or Private Access, bypassing them for a portion of workload traffic, or dropping selected workload traffic, configured as rules. [cloud-connector.forwarding:purpose] "Where did Cloud Connector send this flow?" is answered in the order below.

1. **Which rules apply to this Connector and flow?** Scope by location or Connector group, then services, sources and destinations; FQDN criteria need the workloads' DNS to pass through the Connector: [Cloud Connector forwarding rule criteria: scope, services, sources, destinations, FQDNs](kb:cloud-connector.forwarding.criteria).
2. **In what order are rules evaluated?** Ascending rule order with disabled rules holding their slot; whether the first match ends evaluation is open: [Cloud Connector traffic forwarding rule order, status, rank and rule type](kb:cloud-connector.forwarding.rule-order), [Whether traffic forwarding evaluation stops at the first matching rule](kb:cloud-connector.forwarding.rule-order:first-match).
3. **What does its method do?** ZIA, ZPA, Direct, Drop or Local, and how they appear in the API: [Cloud Connector forwarding methods: ZIA, ZPA, Direct, Drop, Local, and their API tokens](kb:cloud-connector.forwarding.methods).
4. **Did a predefined rule handle it?** The default Internet & SaaS rule, the Private Access rules and the gateway-mode Direct rules: [Predefined Cloud Connector traffic forwarding rules](kb:cloud-connector.forwarding.predefined-rules).

For ZIA-method traffic, the tunnels to the Service Edges and what happens when they fail: [Cloud Connector tunnels to Service Edges: primary, secondary, tertiary, fail-close and fail-open](kb:cloud-connector.overview.gateway-failover). The default Internet Access and Log and Control gateways, and the Internet Access gateway's Fail Close setting: [Internet Access and Log and Control gateways: default gateways and proxy types; Fail Close and the 32-object limit for Internet Access gateways](kb:cloud-connector.forwarding.gateways).

Once traffic reaches the Zero Trust Exchange, the admin can apply Internet & SaaS or Private Access policy to it, depending on its destination: [Zscaler Zero Trust Cloud traffic is forwarded directly to the ZTE, where the admin can apply Internet & SaaS (ZIA) or Private Access (ZPA) policies depending on the traffic's destination, for full security inspection and identity-based access control of cloud, branch and data center communications.](kb:cloud-connector.sdwan:traffic-to-zte). A workload that cannot reach an internet destination can therefore be a forwarding question (a Direct or Drop rule matched) or a ZIA policy question after the forward, where Connector traffic arrives at a workload location: [AWS workload sublocation scopes (VPC endpoint, VPC, account, namespace)](kb:zia.locations.workload-scopes), [ZIA URL Filtering](kb:zia.url-filtering), [ZIA SSL/TLS inspection](kb:zia.ssl-inspection). A Private Access flow continues on the ZPA side: [ZPA application segments](kb:zpa.app-segments).

Two other policies run beside traffic forwarding: DNS policies and gateways ([Cloud & Branch Connector DNS handling: DNS policies and DNS gateways](kb:cloud-connector.dns)), and Log and Control Forwarding for the Connector's own logs and control traffic ([Log and Control Forwarding: how a Connector's logs and control traffic reach the Zscaler cloud](kb:cloud-connector.forwarding.log-and-control)).

ZIA's Forwarding Control is a separate policy in a different product: [ZIA Forwarding Control and Source IP Anchoring](kb:zia.forwarding-control). Terraform behavior of these rules: [ZTC traffic forwarding and DNS rules in Terraform: forward methods, ZPA segment IDs, workload groups, WAN selection and labels](kb:cloud-connector.terraform.forwarding-rules), [How the ZTC (Cloud Connector) Terraform provider applies rule order](kb:cloud-connector.terraform.rule-order), [How the ZTC Terraform provider detaches references before deleting objects](kb:cloud-connector.terraform.delete-detach).

What to check:
1. For a workload that cannot reach an internet or SaaS destination, which rule matched the flow and its method: a Direct or Drop match is a forwarding-rule problem; a ZIA match moves the question to ZIA policy (URL Filtering, SSL Inspection) for the workload's location.
2. For traffic going direct that should go to ZIA, the enabled Direct or Drop rules ordered ahead of the predefined default Internet & SaaS rule; where that rule sits and whether the first match ends evaluation are not stated.
