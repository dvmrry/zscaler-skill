# Cloud Connector on AWS: VM size, EC2 instance type, and matching the provisioning template (cloud-connector.aws.instance-sizing)
Also called: cloud connector instance type aws; cc_instance_size; ccvm_instance_type; cloud connector small medium large; m6i.large cloud connector; cloud connector m5 c5 migrate; no appliances were created errorlog

Two choices must agree: the VM size in the provisioning template and the EC2 instance type the template or module launches.

**What the deployment guide supports.** The AWS deployment guide lists Small VMs on m5n.large, c5a.large, m6i.large (recommended), c6i.large, m7i.large or m7i-flex.large, and Medium and Large VMs, both deprecated, on m5n.4xlarge, m6i.4xlarge (recommended) or c6i.4xlarge. [cloud-connector.aws.instance-sizing:vm-sizes] Zscaler recommends the Small VM size in the provisioning template and the m6i instance for best performance and security, with the latest available AMI. [cloud-connector.aws.instance-sizing:small-recommended] The EC2 M5 and C5 instance families are no longer available from the AWS Marketplace or Zscaler deployment templates, and existing Cloud Connectors on them (such as m5.large or c5.large) should be redeployed on a supported instance. [cloud-connector.aws.instance-sizing:m5-c5-retired] AWS Marketplace restricts Cloud Connector to instances Zscaler validated, a list Zscaler reviews periodically, and Zscaler cannot guarantee that VMs on unsupported instances function properly. [cloud-connector.aws.instance-sizing:marketplace-validated]

**Size must match the template.** The instance size given to the deployment (small, medium or large) must match the VM size of the cloud provisioning template; if the provisioning URL's sizing and the deployment template's sizing differ, the deployment is unsuccessful. [cloud-connector.aws.instance-sizing:size-must-match] The reference CCVM module's `cc_instance_size` accepts small, medium or large, defaults to small, and is described as determined by and needing to match the provisioning template. [cloud-connector.aws.instance-sizing:module-size-variable] Autoscaling takes only the small size: [Cloud Connector Auto Scaling groups on AWS: scaling metric, policy, capacity limits](kb:cloud-connector.aws.autoscaling).

**What the reference Terraform module accepts.** The reference CCVM module defaults `ccvm_instance_type` to m6i.large and its validation accepts only t3.medium, m5n.large, c5a.large, m6i.large, c6i.large, c6in.large, m7i.large, m7i-flex.large, m5n.4xlarge, m6i.4xlarge, c6i.4xlarge and c6in.4xlarge. [cloud-connector.aws.instance-sizing:module-instance-types] The module's list is wider than the guide's [divergence:cloud-connector.aws.instance-sizing:small-instance-list]. The CCVM module pairs medium and large only with m5n.4xlarge, m6i.4xlarge, c6i.4xlarge or c6in.4xlarge; when size and type do not pair, it creates no Cloud Connector instance and a local-exec appends a message beginning "Cloud Connector parameters were invalid. No appliances were created." and naming cc_instance_size and ccvm_instance_type to errorlog.txt in the root module directory. [cloud-connector.aws.instance-sizing:module-size-pairing] A size and type mismatch therefore surfaces as an apply that creates zero Cloud Connectors and a line in errorlog.txt, not as a validation error at plan time. [cloud-connector.aws.instance-sizing:mismatch-applies-cleanly]

**Interfaces.** The number of network interfaces follows the size: [Cloud Connector on AWS: network interfaces, device indexes, source/destination check](kb:cloud-connector.aws.interfaces).

**CloudFormation templates.** The CloudFormation templates default the EC2 instance type to m6i.large and accept t3.medium, c5a.large, m5n.large, m6i.large, c6i.large, c6in.large, m7i.large, m7i-flex.large, m5n.4xlarge, m6i.4xlarge, c6i.4xlarge and c6in.4xlarge; template rules require one of m5n.4xlarge, m6i.4xlarge, c6i.4xlarge and c6in.4xlarge for the medium and large sizes. [cloud-connector.aws.instance-sizing:cfn-instance-types] The changelog records that version 1.0.0 made m6i.large the default for small and m6i.4xlarge for medium and large, added the m5n, m6i and c6i families and removed the m5 family, 1.3.1 added c6in, and 1.3.2 removed t3a.medium and c4.4xlarge. [cloud-connector.aws.instance-sizing:cfn-instance-history]

What to check:
1. Whether the VM size in the provisioning template equals the instance size given to the CloudFormation template or Terraform module.
2. Whether the EC2 instance type is one the deployment guide lists for that size, and not an M5 or C5 type such as m5.large or c5.large.
3. After a Terraform apply that created no Cloud Connector, whether errorlog.txt in the root module directory reports invalid parameters.

Sources disagree (name both sides):
- Which EC2 types a Small Cloud Connector may use: the deployment guide lists six, while the reference Terraform module and the CloudFormation templates each accept twelve. [divergence:cloud-connector.aws.instance-sizing:small-instance-list]
  - zscaler-help: Small VMs require m5n.large, c5a.large, m6i.large, c6i.large, m7i.large or m7i-flex.large.
  - tfmod-aws-cloud-connector: The small size also accepts t3.medium, c6in.large and the 4xlarge types m5n.4xlarge, m6i.4xlarge, c6i.4xlarge and c6in.4xlarge.
  - cft-aws-cloud-connector: The CloudFormation Starter template accepts twelve types, including t3.medium and c6in.large.
  Impact: A module or CloudFormation deployment can pass validation on a type the guide does not list (t3.medium, c6in.large), and the guide says Zscaler cannot guarantee unsupported instances work.
