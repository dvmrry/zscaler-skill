# Reaching and signing in to the Cloud Connector API: OneAPI, legacy ZTC credentials and government clouds (cloud-connector.api.authentication)
Also called: ztw authentication; ztc_username ztc_password ztc_api_key ztc_cloud; cloud connector api legacy login; connector.zscaler.net api; ztw fedramp; ztc provider gov cloud; ztw oneapi

The Cloud & Branch Connector API is reached two ways: through the OneAPI gateway with a bearer token, or through the legacy connector host with portal credentials and a session. This subject records how each client picks a path and where the government-cloud question stands.

**OneAPI path.** The Go SDK's OneAPI client classifies any path starting with `ztw` as the ZTW service and sends it through a dedicated `ZTWHTTPClient` with its own rate limiter. [cloud-connector.api.authentication:go-oneapi-routes-ztw] The Python SDK's unified client builds the `ztw` service on its OneAPI request executor by default. With `use_legacy_client` set, the `ztw` accessor returns the supplied legacy ZTW helper instead, and raises a RuntimeError if no helper was supplied; it does not fall back to OneAPI. [cloud-connector.api.authentication:python-oneapi-default] How the token itself is obtained is in [How a client gets and uses a OneAPI access token](kb:shared.oneapi.authentication).

**Legacy path.** The Go SDK's legacy ZTW configuration reads `ZTC_USERNAME`, `ZTC_PASSWORD`, `ZTC_API_KEY` and `ZTC_CLOUD` (and an optional `ZSCALER_PARTNER_ID`), and returns an error if any of the four is empty. [cloud-connector.api.authentication:go-legacy-credentials] The legacy Go client's base URL is built from the cloud name as `https://connector.<cloud>.net/api/v1`. [cloud-connector.api.authentication:go-legacy-host] The legacy API reference names its public server as `https://{host}:{port}/api/v1`, with `connector.zscaler.net` as the default host and 443, 8443 or 1443 as the port. [cloud-connector.api.authentication:help-legacy-server] The legacy Go client checks its session before each request and sends the session ID in a `JSessionID` header. [cloud-connector.api.authentication:legacy-session-header]

**The legacy API key.** The organization's API key is initially provisioned by Zscaler, enabled, and displayed with the base URL on the Cloud & Branch Connector API page (Administration > API > Legacy API > Cloud & Branch Connector API); the base URL and key are required to authenticate via the API and create a session. [cloud-connector.api.authentication:legacy-key-provisioned] An organization can only have one API key and must delete the existing key before adding a new one; the new key is immediately valid. [cloud-connector.api.authentication:one-key] An edited key must be alphanumeric (A-Z, a-z, 0-9) and exactly 12 characters, cannot be the same as the current key, immediately invalidates the old key after confirmation, and the edit cannot be undone. [cloud-connector.api.authentication:edit-key-rules] For an admin managing multiple organizations in the Admin Console who wants the same key string across them, Zscaler recommends editing the key instead of adding a new one or regenerating it. [cloud-connector.api.authentication:same-key-across-orgs] After confirmation a regenerate immediately generates a random key string and invalidates the old one, and a delete immediately removes and invalidates the key; the regenerate cannot be undone. [cloud-connector.api.authentication:regenerate-delete] The key page's Last Modified By description disagrees with the edit and regenerate procedures [divergence:cloud-connector.api.authentication:key-modified-by]. The key can be disabled if the organization exceeds the threshold number of API calls allowed or its code violates Zscaler's terms and conditions; then the ability to add, regenerate or delete the key is removed and a Disabled status appears, and Zscaler Support or the service provider must be contacted to re-enable it. [cloud-connector.api.authentication:key-disabled] If the API subscription expires, the Cloud & Branch Connector API page can still be accessed but cannot be modified, and the existing key is still valid but disabled until it is re-enabled after the subscription is renewed. [cloud-connector.api.authentication:subscription-expiry] The threshold of API calls is not given [gap:cloud-connector.api.authentication:key-call-threshold]. Which admins may view or change the key is a role permission: [API Key Management lets admins view, remove, edit or regenerate the base URL and key; its View Only level shows the key without letting the admin edit, remove or regenerate it.](kb:shared.admin-rbac.cloud-connector:api-key-mgmt).

In legacy mode several Go ZTW services are sent through the ZIA legacy client, which the ZTC provider never builds: [The ZTC provider's legacy mode builds only a ZTW legacy client, so the generic ZIA-routed calls above find no ZIA legacy client and return the SDK's "legacy client not set" error. In that mode the activation status read (resource and data source) and the provisioning URL create, update, and delete fail while the other ZTC resources, which use the `...Resource` methods, work (except ZPA-resource lookups, which also go through the generic path).](kb:cloud-connector.sdk-go.service-defects:legacy-ztw-only-client-fails-generic-calls).

## Government (FedRAMP) clouds

The Go SDK builds dedicated government routes for every OneAPI service, ZTW included: [The Go SDK maps the cloud values `gov` and `govus` (case-insensitive) to the token hosts zidentitygov.net and zidentitygov.us and to the API gateways `https://api.zscalergov.net` and `https://api.zscalergov.us`, instead of the commercial zslogin and zsapi hosts.](kb:shared.oneapi.government-clouds:go-gov-routing). The ZTC provider passes its cloud setting through to those routes, [The provider passes a non-empty `zscaler_cloud` to the SDK unchanged, and v0.2.0 is built with SDK v3.8.40, which already builds the gov and govus OneAPI routes, so setting `zscaler_cloud` to `gov` or `govus` sends authentication and API calls to the government hosts.](kb:cloud-connector.terraform.provider-config:provider-carries-gov-routes), while the FedRAMP version floor its documentation gives is not a release of that provider, [The version floors the documentation gives, v4.0.0 for legacy compatibility and >=v4.7.25 for FedRAMP, are not releases of this provider, whose changelog runs through 0.x releases to 0.2.0; they read as copied from another provider's documentation.](kb:cloud-connector.terraform.provider-config:version-floors-not-ztc).

Whether a government ZTW tenant accepts OneAPI is open: [Whether a ZTW tenant on the gov or govus cloud accepts OneAPI calls through the ZTC provider](kb:cloud-connector.terraform.provider-config:fedramp-live-acceptance).

What to check:
1. Which path a failing client is on: a OneAPI client (vanity domain, client ID and secret or key) or the legacy ZTC_USERNAME, ZTC_PASSWORD, ZTC_API_KEY and ZTC_CLOUD credentials, since the hosts and failure modes differ.
2. For a government tenant, whether OneAPI acceptance for ZTW has been confirmed by a release note, the vendor or a tenant test before moving it off legacy credentials.
3. For a legacy client that suddenly fails to authenticate, whether the key shows Disabled (call threshold, terms violation or an expired API subscription) or was edited, regenerated or deleted, which invalidates the old key immediately; who last modified the key is a divergence between the pages.

Sources disagree (name both sides):
- The API management page describes the key's Last Modified By column as "Only Zscaler modifies the key", while the key management page gives admins procedures to edit, regenerate and delete the key. [divergence:cloud-connector.api.authentication:key-modified-by]
  - zscaler-help: API management page: only Zscaler modifies the key.
  - zscaler-help: Key management page: an admin edits the key and regenerates it with a random key string, so the key changes by admin action.
  Impact: Neither page says whether the column describes the initial provisioning only or records admin edits, so the column cannot be relied on to say who changed the key.

Not known (open gaps):
- The API call threshold that disables the legacy key, and whether OneAPI clients need the key [gap:cloud-connector.api.authentication:key-call-threshold]: settled by source-read or support-ticket
