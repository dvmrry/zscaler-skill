# VDI devices, dynamic VDI groups and VDI templates (authentication type, system user, provisioning URL and token) (cloud-connector.vdi.groups-and-templates)
Also called: vdi device management; vdi groups; dynamic vdi group; vdi templates; vdi provisioning url; vdi access token; system user

## Devices and groups

The VDI Devices tab on the VDI Device Management page (Infrastructure > Client Connector > VDI Device Management > VDI Devices) displays all the devices in the organization that have Client Connector for VDI deployed, with Hostname, OS Type, OS Version and Platform; the app uses the OS type it detects to add the device to a group. [cloud-connector.vdi.groups-and-templates:devices-tab] VDI devices that have Client Connector for VDI deployed are categorized under groups based on the match criteria, policies can be applied to a group of devices grouped by user-defined criteria, and a default VDI group can be viewed. The guide says VDI groups let administrators dynamically apply MTU and forwarding profile values to VDI applications as they register VDI devices and groups. [cloud-connector.vdi.groups-and-templates:groups-purpose] The VDI Groups list shows Name, Description, Platform, Servers, Hostname Prefix, Locations (the Zscaler location associated with the group), VDI Forwarding Profile, OS Type, OS Version, Type, Last Modified By and Last Modified On. [cloud-connector.vdi.groups-and-templates:groups-columns] Group Type and Servers, the Platform values, and the default group's contents are open [gap:cloud-connector.vdi.groups-and-templates:group-column-values].

Add Dynamic VDI Group takes a Name, an MTU (default 1,400 bytes) and an optional Description; device criteria are Locations (one or more), OS Type (only WINDOWS_OS is currently supported) and Hostname Prefix (the prefix Client Connector for VDI detects); the VDI Forwarding Profile tab selects the VDI forwarding profile applied to the group. [cloud-connector.vdi.groups-and-templates:group-form] Where the MTU is set is recorded in [Client Connector for VDI: the multi-session Windows agent that tunnels users' traffic to Cloud and Branch Connector](kb:cloud-connector.vdi); the forwarding profile a group applies is in [VDI forwarding profiles: include and exclude lists, refresh, Private Access and DNS inclusion, Azure, FSLogix and Citrix bypasses](kb:cloud-connector.vdi.forwarding-profiles).

## Templates

VDI templates provide the VDI provisioning URL and the VDI access token required for installing Client Connector for VDI; a template is a set of configurations applied to the VDI that dictate its behavior, and templates can be reused in multi-region deployments. The guide says a template holds the provisioning URL, authentication token and end user authentication method. [cloud-connector.vdi.groups-and-templates:templates-purpose] The VDI Templates page (Infrastructure > Client Connector > VDI Templates) lists Template Name, Description, Auth Type (IdP or Hosted DB), IdP Name (if IdP was selected), System User, Provisioning URL and Last Modified On, and can be filtered by System User and by Last Modified By. [cloud-connector.vdi.groups-and-templates:templates-columns] The VDI provisioning URL and access token are copied by clicking the VDI template that was created; if no token value is present, Generate Token creates one. [cloud-connector.vdi.groups-and-templates:generate-token] The installer takes the URL and token as PROVURL and TOKEN: [Installing Client Connector for VDI: download, MSI options, golden images, OnboardOnStart, Intune and processes to allowlist](kb:cloud-connector.vdi.install).

The authentication type selected for a template must match the one Internet & SaaS is currently using: IdP only if Internet & SaaS is configured for SAML authentication, and Hosted DB only if it is configured for Form-Based authentication. [cloud-connector.vdi.groups-and-templates:auth-type-match] The Configuring VDI Templates article says that if IdP is selected, enable SCIM in Private Access and use the same IdP in Internet & SaaS and Private Access, and leave the Domains field empty; the lists of IdPs and system users in the drop-down menus are retrieved from the Internet & SaaS configuration. The guide says to assign an IdP and a System User to the template for Internet & SaaS. [cloud-connector.vdi.groups-and-templates:idp-auth] If Hosted DB is selected for a template, a System User is selected for the template, and the hosted database information is defined in the Internet & SaaS configuration. [cloud-connector.vdi.groups-and-templates:hosted-db-auth]

System users are assigned to traffic leaving the VDI session that cannot be attributed to the current user, and admins can create security policies around the system user to permit, deny or restrict where system traffic can reach. Enabling the feature creates a default system user, which appears in the Internet & SaaS logs as system-level traffic that the current user did not generate; a user configured on the IdP can be selected as the system user, which is useful for assigning different system users by the location of the VDI infrastructure. [cloud-connector.vdi.groups-and-templates:system-user] Whether that traffic is the same as NT AUTHORITY\SYSTEM traffic is open in [Client Connector for VDI: the multi-session Windows agent that tunnels users' traffic to Cloud and Branch Connector](kb:cloud-connector.vdi). The Configuring VDI Templates field list names no MTU field [gap:cloud-connector.vdi.groups-and-templates:template-mtu-field].
