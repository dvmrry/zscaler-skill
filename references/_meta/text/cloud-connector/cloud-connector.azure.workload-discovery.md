# Cloud Connector on Azure: workload discovery service, partner configuration, event grid and account details (cloud-connector.azure.workload-discovery)
Also called: azure workload discovery; workload discovery service azure; WDS azure; azure event grid cloud connector; azure partner configuration zscaler; azure storage queue cloud connector

Workload discovery services for Azure are in Limited Availability; to learn more, the page says to contact Zscaler Support. [cloud-connector.azure.workload-discovery:limited-availability] It is the Azure counterpart of [Cloud Connector on GCP: workload discovery service](kb:cloud-connector.gcp.workload-discovery); the console account pages are described here, and the API side is in [Cloud Connector partner integration endpoints: AWS accounts in the contract, Azure and GCP outside it](kb:cloud-connector.api.partner-integrations-wire).

**Before adding an account.** Before an Azure account is added, the managed identity must be updated with the Cloud Connectors to be deployed, IAM roles and permissions configured, the region verified as supported, a resource group created to host the account's event grid topic, and a storage account created in which Cloud Connector creates storage queues (the Cloud Connector requires one). [cloud-connector.azure.workload-discovery:prerequisites] In the IAM setup the app registration selects Accounts in this organizational directory only as its supported account type, leaves the optional Redirect URI unconfigured, and the client secret's Value must be copied and saved immediately after creation because it cannot be viewed or copied after the page is refreshed or accessed later. [cloud-connector.azure.workload-discovery:iam-app-registration] Permissions in Azure can come from the built-in Reader role (assigned to the subscription) or from a custom role created with baseline permissions Start from scratch, whose JSON actions read subscription resources, virtual networks, virtual network virtual machines, network interfaces, virtual machines and resource groups; the access assignment selects User, group, or service principal, and IAM roles and permissions can be configured with Terraform or in Azure. [cloud-connector.azure.workload-discovery:iam-role]

**Partner configuration.** To distribute tags through the event grid, an Azure partner configuration must be created and Zscaler must authorize it before onboarding; Zscaler is currently added as a non-verified partner, with partner registration ID ad8a5905-16a9-48f8-9f1e-30d750625b8e. [cloud-connector.azure.workload-discovery:partner-configuration] After the partner authorization expires, the Zscaler service cannot create a partner topic or partner destination in the tenant, but a partner topic or destination it already created remains operational; when the same user creates the authorization in Azure and the Azure account in the Admin Console, Zscaler recommends a 7-day expiration. [cloud-connector.azure.workload-discovery:authorization-expiry]

**The account.** An Azure account is added at Zero Trust Cloud > Common Resources > Azure with a service principal credential: the Directory (tenant) ID, the Client/Application ID and the Client/Application Secret. [cloud-connector.azure.workload-discovery:account-credentials] The Subscription Groups tab selects the regions and the subscriptions from which the Zscaler service reads the resource tag. [cloud-connector.azure.workload-discovery:subscription-groups] Selecting a Cloud Connector group is optional; without one the workload discovery service only discovers assets and cannot use the tags in policies, and the groups selected must receive the workload traffic from the chosen subscriptions and regions. [cloud-connector.azure.workload-discovery:groups-optional] An optional namespace limits the IP addresses sent to the Cloud Connector so that duplicate IP addresses do not map incorrectly. [cloud-connector.azure.workload-discovery:namespace]

**Event grid and storage queues.** The event grid is optional and depends on storage account creation in Azure; Zscaler creates event grid topics in the regions selected there to be notified of real-time tag updates, and the service can only attempt to create a partner topic and partner destination after the Resource Group and Subscription ID are provided. [cloud-connector.azure.workload-discovery:event-grid] For each region selected on the Event Grid tab, a subscription and storage account are chosen, in which the Cloud Connector creates a storage queue for the event grid; an optional prefix names the queue. [cloud-connector.azure.workload-discovery:storage-queue] When the event grid is used, post-configuration is mandatory: the partner topic and/or partner destination must be activated in the resource group of every region, and a system topic must be created manually or with the Terraform template, with topic type Azure Resource Notifications - Resource Management events (only one per subscription), Cloud Event Schema v1.0, the Resource Created or Updated event type, a Partner Destination endpoint, and a Global location that is selected by default and cannot be changed. [cloud-connector.azure.workload-discovery:post-config]

**Account details.** The Azure account details page says supported Azure regions include westeurope, eastus, eastus2, uksouth, northeurope, centralindia, southeastasia, australiaeast, germanywestcentral, southcentralus, westus2 and canadacentral. [cloud-connector.azure.workload-discovery:supported-regions] The Azure account details page says only certain attributes can be used in policies and marks Image ID, Platform, Security Group ID, Security Group Name and VNet as usable; for VNet, the field in workload groups is labeled VPC but takes VNet ID values. [cloud-connector.azure.workload-discovery:policy-attributes] For each subscription the region view shows the numbers of duplicate and private IP addresses discovered, the messages received over the partner destination and sent over the partner topic, and a discovery service status of Starting, Success or Error. [cloud-connector.azure.workload-discovery:inventory-counts] The permission status of the Azure account is Pending, Allowed or Denied and updates when Refresh is clicked; Last Sync is the last time the account was refreshed and is Pending if it was never refreshed. [cloud-connector.azure.workload-discovery:permissions] The workload discovery service communicates through API calls and a publish-subscribe mechanism based on the event grid and storage queue; the event grid list shows each topic and destination status as Activated, Created or Unavailable, and the messages a partner destination has received since its creation. [cloud-connector.azure.workload-discovery:event-grid-status]

**Not settled.** No polling interval is given [gap:cloud-connector.azure.workload-discovery:polling-interval]. The custom role JSON is printed without a comma [gap:cloud-connector.azure.workload-discovery:role-json-comma], the westus region cannot be isolated in the list [gap:cloud-connector.azure.workload-discovery:westus-entry], and the system topic's Terraform template is not captured [gap:cloud-connector.azure.workload-discovery:system-topic-terraform]. API, SDK and Terraform coverage of Azure accounts is tracked in [Cloud Connector partner integration endpoints: AWS accounts in the contract, Azure and GCP outside it](kb:cloud-connector.api.partner-integrations-wire).

What to check:
1. Whether the tenant has Azure workload discovery enabled by Zscaler Support, since it is Limited Availability.
2. Whether the managed identity, resource group, storage account and IAM roles exist before the account is added, and whether the region is supported.
3. When the event grid is used, whether Zscaler authorized the partner configuration before onboarding and whether it expired before Zscaler created the partner topic and destination.
4. When the event grid is used, whether the partner topic and destination were activated in every region and the system topic was created, since both are mandatory post-configuration.
5. Whether the account's Permission shows Allowed for each subscription after Refresh, and the discovery service status.
