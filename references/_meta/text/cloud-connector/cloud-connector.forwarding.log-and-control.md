# Log and Control Forwarding: how a Connector's logs and control traffic reach the Zscaler cloud (cloud-connector.forwarding.log-and-control)
Also called: log and control forwarding; log and control gateway; ecRules/self; ztc_traffic_forwarding_log_rule; cloud connector enrollment traffic; cloud connector logs not reaching zscaler; ECSELF gateway

What the policy governs: [The Log and Control Forwarding policy controls how a connector's traffic logs and operational messages are forwarded to the Zscaler cloud, covering enrollment, policy changes, software updates and sending logs.](kb:cloud-connector.nss-va.log-control-path:lc-scope). A default Log and Control Forwarding rule with a default gateway action is created automatically, and it cannot be duplicated or deleted. [cloud-connector.forwarding.log-and-control:default-rule] The policy configures the primary and secondary gateways used to set up control channels and forward logs. [cloud-connector.forwarding.log-and-control:gateways]

**Where it sends.** This policy carries only the first leg of a log's path to a SIEM; NSS carries the second: [A connector log reaches a SIEM over two legs: the connector forwards it to the Zscaler cloud under the Log and Control Forwarding policy, and an NSS VM streams it from the Nanolog to the SIEM. A Log and Control Forwarding rule configures only the first leg; the NSS VM authenticates with its own certificate and is configured by NSS servers and feeds.](kb:cloud-connector.nss-va.log-control-path:two-legs).

**Rule fields.** Log and Control rules are evaluated in ascending numerical order; a disabled rule is skipped but keeps its place. [cloud-connector.forwarding.log-and-control:rule-order] Whether evaluation stops at the first match is open: [Whether Log and Control Forwarding evaluation stops at the first matching rule](kb:cloud-connector.nss-va.log-control-path:rule-first-match). A rule's name is at most 31 characters; its source is all locations or up to 8, or all or specific Cloud & Branch Connector groups; its action is a Log and Control Gateway; its description is at most 10,240 characters. [cloud-connector.forwarding.log-and-control:rule-fields] Whether the API enforces the console's name and description limits is open [gap:cloud-connector.forwarding.log-and-control:limit-enforcement].

**In the API.** In Terraform, a log forwarding rule's `forward_method` has the single supported value `ECSELF`, and the rule names its gateway in `proxy_gateway`. [cloud-connector.forwarding.log-and-control:tf-forward-method] The Log and Control gateway is a forwarding gateway on the API's `/gateways` endpoint: its `type` enum is PROXYCHAIN, ZIA and ECSELF, with ECSELF described as the Log and Control gateway. [cloud-connector.forwarding.log-and-control:gateway-type] The contract's DNS gateway object (`/dnsGateways`) has no `type` member; it carries `dnsGatewayType` instead, with the values OFW_PDNS_REDIR_GW and EC_DNS_GW. [cloud-connector.forwarding.log-and-control:dns-gateway-no-type] The Go SDK's dns_forwarding_gateway package nevertheless gives /dnsGateways a `type` whose comment names ECSELF: [The two SDK structs differ: both carry `dnsGatewayType`, but only the `dns_forwarding_gateway` struct also has a `type` field, whose comment (repeated above `failureBehavior`, `primaryIp` and `ecDnsGatewayOptionsSecondary` too) says the supported types are ZIA and ECSELF.](kb:cloud-connector.terraform.gateways:structs-differ); whether the API uses it is open: [What the DNS gateway API does with a create that omits dnsGatewayType](kb:cloud-connector.terraform.gateways:dns-gateway-type-semantics).

What happens to logs when the gateway is unreachable: [What happens to connector logs when the Log and Control Gateway is unreachable](kb:cloud-connector.nss-va.log-control-path:log-upload-starvation). Effects on enrollment and policy delivery, and on Connectors no rule covers, are not stated [gap:cloud-connector.forwarding.log-and-control:channel-failure]. Names of predefined log rules are not captured: [Names of the predefined log-forwarding rules](kb:cloud-connector.terraform.rule-protection:predefined-log-rule-names).

What to check:
1. Which Log and Control rule covers the Connector's location or group, and which Log and Control gateway it uses.
2. For logs expected in a SIEM, the NSS configuration rather than this policy.
