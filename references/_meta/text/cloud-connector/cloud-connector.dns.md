# Cloud & Branch Connector DNS handling: DNS policies and DNS gateways (cloud-connector.dns)
Also called: cloud connector dns; branch connector dns; cloud connector dns not working; cloud connector dns subsystem

DNS handling on a Connector is two configured objects, with a third policy that carries the Connector's own traffic. To use DNS gateway and DNS policy functions, the help says to design the network so that workloads', servers' and endpoints' DNS queries route through the Cloud or Branch Connector. [cloud-connector.dns:route-through]

1. **DNS policies.** Rules evaluated against each DNS request and response that allow, block, or redirect it: [Cloud & Branch Connector DNS policies: scope, criteria, actions, predefined rules](kb:cloud-connector.dns.policies).
2. **DNS gateways.** The resolvers a redirecting rule sends queries to, and what happens when they do not answer: [Cloud & Branch Connector DNS gateways: resolvers, failure behavior, predefined gateways](kb:cloud-connector.dns.gateways).
3. **Log and Control Forwarding.** Not DNS itself: the channel for the Connector's logs, enrollment and policy updates: [Log and Control Forwarding: how a Connector's logs and control traffic reach the Zscaler cloud](kb:cloud-connector.forwarding.log-and-control).

**Branch Connector resolution by forwarding action.** On the Branch Connector DNS page, when a DNS request arrives at any destination IP address for an FQDN request that matches a Private Access application, Branch Connector intercepts it and responds with a customer-defined synthetic IP address from the customer-defined IP pool. [cloud-connector.dns:bc-resolution-zpa] On the Branch Connector DNS page, Branch Connector encapsulates the request with a client source IP and destination DNS IP address (for example 8.8.8.8) and forwards it to Internet & SaaS, and the Internet & SaaS DNS control and firewall filtering policies need to allow the DNS response back to the workload. [cloud-connector.dns:bc-resolution-zia] On the Branch Connector DNS page, a custom traffic forwarding policy matching the client source IP, the destination IP address (for example 8.8.8.8) or the network service (UDP 53) with the forwarding action set to direct makes Branch Connector forward the request to the destination, changing the source from the client to its own service IP address (Source NAT). [cloud-connector.dns:bc-resolution-direct] On the Branch Connector DNS page, when a request arrives from a workload configured with a custom DNS server destination that matches a Zscaler Global Public Service Edge IP (for example 185.46.212.88) and a custom traffic forwarding policy matches the client source IP, the destination IP or the network service (UDP 53) with the forwarding action set to direct, the source IP is replaced with Branch Connector's own service IP and the destination with the current DNS server configured on the Branch Connector. [cloud-connector.dns:bc-resolution-global-vip] Which DNS server counts as the current one in the last case is open [gap:cloud-connector.dns:global-vip-current-dns]. The pool is in [IP pools for Private Access DNS resolution in Cloud & Branch Connector: default pool, per-location pools and entries](kb:cloud-connector.shared-objects.ip-pools).

**Cloud Connector resolution by forwarding action.** The Cloud Connector DNS page has the same four rows, compared by page text only [gap:cloud-connector.dns:cc-same-handling]. On the Cloud Connector DNS page, one row has Cloud Connector intercept requests and respond with a customer-defined synthetic IP address from the customer-defined IP pool. [cloud-connector.dns:cc-resolution-zpa] On the Cloud Connector DNS page, one row has Cloud Connector encapsulate the request with a client source IP and destination DNS IP address (for example 8.8.8.8) and forward it to Internet & SaaS. [cloud-connector.dns:cc-resolution-zia] On the Cloud Connector DNS page, one row has Cloud Connector forward the request to the destination IP address, modifying the source IP from the client to its own service IP address (Source NAT). [cloud-connector.dns:cc-resolution-direct] On the Cloud Connector DNS page, when the request arrives from a workload configured with a custom DNS server destination that matches a Zscaler Global Public Service Edge IP address (for example 185.46.212.88) and a custom traffic forwarding policy matches with the forwarding action set to direct, Cloud Connector performs both source and destination NAT: the source IP is replaced with Cloud Connector's own service IP address and the destination IP with the current DNS server configured on the Cloud Connector. [cloud-connector.dns:cc-global-vip]

**DNS use cases.** In the Private Access DNS use case on the networking-flows page, the Cloud Connector matches the DNS query against known Private Access app segments and on a match queries the Zscaler service for a synthetic IP address; queries that do not match can reach a direct traffic forwarding rule, and the Cloud Connector forwards them to an upstream DNS server for resolution. [cloud-connector.dns:zpa-dns-use-case] In the Internet & SaaS DNS use case, when the DNS matches an Internet & SaaS traffic forwarding rule the DNS query is tunneled to the Internet & SaaS gateway for DNS resolution, and the resolved IP is returned to the workload when the Internet & SaaS DNS Control allows it. [cloud-connector.dns:zia-dns-use-case] DNS forwarding operates when workloads are configured to send DNS through Cloud Connectors, but the networking-flows page says this is not required in every instance. [cloud-connector.dns:dns-not-always-required]

DNS through the Connector also decides whether wildcard and FQDN forwarding criteria can match non-web traffic: [Rules with wildcard domains or FQDNs need the workloads' DNS queries routed through the Cloud or Branch Connector; for HTTP/HTTPS traffic DNS is not required, but UDP and non-web traffic require it.](kb:cloud-connector.forwarding.criteria:dns-required).

These are Cloud & Branch Connector features, distinct from ZIA DNS Control: [Cloud & Branch Connector has its own DNS Policies feature, configured on its own page (Zero Trust Cloud > Policy > DNS Forwarding), with rules evaluated in ascending order.](kb:cloud-connector.dns.policies:cbc-has-dns-policies), [Cloud & Branch Connector DNS gateways are a Cloud & Branch Connector feature with their own page (Zero Trust Cloud > Gateways > DNS Gateway): they redirect DNS requests received by the Connector to specific DNS servers.](kb:cloud-connector.dns.gateways:cbc-gateways-differ).
