# Cloud Connector behind AWS Gateway Load Balancer: target group, health probe, stickiness, cross-zone (cloud-connector.aws.gwlb)
Also called: gwlb target unhealthy cloud connector; cloud connector health probe port 50000; cchealth; gwlb flow stickiness cloud connector; gwlb cross zone cloud connector; gwlb rebalance cloud connector; geneve 6081 cloud connector; http_probe_port

With GWLB, Cloud Connectors are targets of a GENEVE target group and receive traffic only while their HTTP health probe answers. The values below are the reference Terraform module's unless a claim cites Help.

**Targets.** The reference GWLB module's target group listens on port 6081 with protocol GENEVE, and its target type is instance when `asg_enabled` is true and ip otherwise. [cloud-connector.aws.gwlb:target-group] Without autoscaling the module registers every Cloud Connector forwarding service interface IP as a target; with autoscaling the ASG module attaches each Auto Scaling group to the target group. [cloud-connector.aws.gwlb:target-registration] Help's check for a GWLB target shown unhealthy: the target IP must be the service interface at device index 0 for non-autoscaling deployments and the EC2 instance ID for autoscaling ones, and the Admin Console dashboard shows the health status and error codes. [cloud-connector.aws.gwlb:target-help]

**Health probe.** The target group health check is HTTP to the probe port at path /?cchealth. [cloud-connector.aws.gwlb:health-check] `http_probe_port` is the port Cloud Connector cloud-init opens as the listener for the GWLB HTTP probe; it defaults to 50000 and must be 80 or between 1024 and 65535. [cloud-connector.aws.gwlb:probe-port] By default the module probes every 10 seconds and marks a target healthy after 2 successful checks and unhealthy after 3 failed ones; its descriptions give ranges of 5 to 300 seconds and 2 to 10 checks but declare no validation. [cloud-connector.aws.gwlb:probe-thresholds] Help gives a different template default for the interval [divergence:cloud-connector.aws.gwlb:probe-interval-default], also stated in [Zscaler deployment templates use a recommended default health-check interval: 15 seconds on the Azure Load Balancer and 30 seconds on the AWS Gateway Load Balancer. The defaults are meant to take unhealthy Cloud Connectors out of rotation efficiently.](kb:cloud-connector.overview.load-balancing:probe-intervals). The probe port is also opened in the service security group: [Cloud Connector on AWS: firewall requirements and the reference security groups](kb:cloud-connector.aws.security-groups).

**Flow handling.** `flow_stickiness` defaults to 5-tuple and accepts 5-tuple, 3-tuple or 2-tuple; 5-tuple is implemented by disabling target-group stickiness, 3-tuple as source_ip_dest_ip_proto and 2-tuple as source_ip_dest_ip. Help recommends 5-tuple. [cloud-connector.aws.gwlb:stickiness] `rebalance_enabled` defaults to true, which sets target failover to rebalance existing flows both on deregistration and when a target turns unhealthy; false sets no_rebalance. [cloud-connector.aws.gwlb:rebalance] `deregistration_delay` defaults to 0 seconds, the time before a deregistering target moves from draining to unused (range 0 to 3600). [cloud-connector.aws.gwlb:deregistration-delay]

**Cross-zone.** The module leaves GWLB cross-zone load balancing off by default (`cross_zone_lb_enabled` false). [cloud-connector.aws.gwlb:cross-zone-default] With cross-zone load balancing the GWLB spreads requests across Cloud Connectors in all enabled availability zones; without it, only across those in the workload's zone. Cross-zone forwarding incurs additional AWS charges. [cloud-connector.aws.gwlb:cross-zone-semantics]

**Endpoint service.** The endpoint module creates the GWLB endpoint service allowing the current AWS account's root principal when no principals are given, and does not require manual acceptance of endpoint connections by default. [cloud-connector.aws.gwlb:endpoint-service]

**CloudFormation templates.** The CloudFormation GWLB add-on takes the EC2 instance IDs of the Cloud Connectors and the HTTP probe port, which must match the one configured in the deployment stack, and registers the instances as IP targets of a GENEVE target group on port 6081. [cloud-connector.aws.gwlb:cfn-gwlb-addon] The GWLB add-on's macro registers the primary IP of each instance's device-index-0 interface and reports a failure when the listed Cloud Connectors differ in instance type or sit in more than one VPC. [cloud-connector.aws.gwlb:cfn-gwlb-addon-checks] Both CloudFormation GWLB templates default cross-zone load balancing to true, target failover to rebalance and flow stickiness to 5-tuple. [cloud-connector.aws.gwlb:cfn-gwlb-defaults] The Terraform module differs on cross-zone [divergence:cloud-connector.aws.gwlb:cross-zone-template-default]. The autoscaling template's target group has target type instance on port 6081 GENEVE, probes HTTP path /?cchealth on the probe port every 10 seconds with a healthy threshold of 2 and an unhealthy threshold of 3, and has a deregistration delay of 0. [cloud-connector.aws.gwlb:cfn-asg-target-group] The autoscaling template's endpoint service requires no acceptance of new endpoints by default and allows the account's root principal unless service principals are given. [cloud-connector.aws.gwlb:cfn-asg-endpoint-service] The macro creates a VPC endpoint per availability zone from the endpoint template, each in the first subnet of its zone, and the stack outputs the endpoint IDs for use as route next hops. [cloud-connector.aws.gwlb:cfn-asg-endpoint-per-az] The template files are described in [Cloud Connector on AWS: CloudFormation templates, order, and parameter defaults](kb:cloud-connector.aws.cloudformation).

What to check:
1. Whether the target is the right kind: the service interface (device index 0) IP for non-autoscaling deployments, the EC2 instance ID for autoscaling ones.
2. Whether the probe port in the target group equals HTTP_PROBE_PORT in the Cloud Connector user data and is allowed from the VPC CIDR.
3. Whether cross-zone load balancing is off while the only healthy Cloud Connectors are in another zone than the workload.
4. For a CloudFormation GWLB add-on that fails or has no targets, whether the listed instances share one instance type, one size and one VPC, and whether the probe port matches the deployment stack.

Sources disagree (name both sides):
- The default GWLB health-check interval for Cloud Connector targets: Help says Zscaler deployment templates use 30 seconds, the reference Terraform module and the CloudFormation templates use 10. [divergence:cloud-connector.aws.gwlb:probe-interval-default]
  - zscaler-help: Zscaler deployment templates use a recommended default health-check interval of 30 seconds on the AWS Gateway Load Balancer.
  - tfmod-aws-cloud-connector: The reference GWLB module's health_check_interval defaults to 10 seconds.
  - cft-aws-cloud-connector: The CloudFormation GWLB templates probe every 10 seconds, with a healthy threshold of 2 and an unhealthy threshold of 3.
  Impact: An unhealthy target leaves rotation about three times faster with the module default than Help's 30 seconds implies; check the deployed target group rather than assuming either value.
- Whether GWLB cross-zone load balancing is on by default: the reference Terraform module leaves it off, the CloudFormation templates turn it on. [divergence:cloud-connector.aws.gwlb:cross-zone-template-default]
  - tfmod-aws-cloud-connector: The reference GWLB module's cross_zone_lb_enabled defaults to false.
  - cft-aws-cloud-connector: Both CloudFormation GWLB templates default cross-zone load balancing to true.
  Impact: The same product deployed by the two repositories spreads flows across availability zones in one and keeps them zone-local in the other; check the deployed load balancer attribute before explaining cross-zone traffic or charges.
