# Cloud Connector on AWS: CloudFormation templates, order, and parameter defaults (cloud-connector.aws.cloudformation)
Also called: cloud connector cloudformation template; pre-deployment template cloud connector; zs_cc_cf_template_simple; zs_cc_cf_template_asg_gwlb; cloud connector cloudformation autoscaling; cloud connector add-on template private access route 53; ZS/CC/credentials

Zscaler's CloudFormation templates deploy Cloud Connector into a VPC the customer already has. The Terraform path is in [Zscaler's Terraform modules for Cloud Connector on AWS: examples, defaults, FIPS, Transit Gateway](kb:cloud-connector.aws.reference-modules). The repository's CloudFormation templates are version 1.3.5, which its changelog dates 2026-09-18. [cloud-connector.aws.cloudformation:template-version] AWS GovCloud (US) support arrived in template version 1.1.0, and AWS China (Beijing) and (Ningxia) support through the China Marketplace in 1.3.3. [cloud-connector.aws.cloudformation:china-govcloud]

**Which templates, in which order.** The CloudFormation templates create the resources to deploy and operate Cloud Connector in an existing VPC. [cloud-connector.aws.cloudformation:existing-vpc] A standard deployment (no autoscaling) uses the Pre-Deployment Template, the Starter Deployment Template, and optionally the GWLB add-on and the Private Access add-on; an advanced (autoscaling) deployment uses the Pre-Deployment Template, the Starter Deployment Template with Autoscaling and GWLB, and optionally the Private Access add-on. [cloud-connector.aws.cloudformation:template-sets] The template files are zs_cc_cf_template_zscc_macro (Pre-Deployment), zs_cc_cf_template_simple (Starter), zs_cc_cf_template_zpa_r53 (Private Access add-on), zs_cc_cf_template_gwlb (GWLB add-on) and zs_cc_cf_template_asg_gwlb (Starter with Autoscaling and GWLB). [cloud-connector.aws.cloudformation:template-names] The Pre-Deployment Template stack must be deployed before any Cloud Connector CloudFormation deployment, and an out-of-date Pre-Deployment stack must be updated and replaced. [cloud-connector.aws.cloudformation:pre-deployment-first]

**The macro.** The Pre-Deployment Template creates a CloudFormation macro named ZSCC-Macro, and the Starter, GWLB add-on, Private Access add-on and autoscaling templates each call it as a transform with the operation ZSCCSIMPLE, ZSCCGWLB, ZSCCZPA or ZSCCASG respectively. [cloud-connector.aws.cloudformation:macro-transform] When no AMI is given the macro finds the newest AWS Marketplace image by product code, using a separate product code in China regions, and it reads the Secrets Manager secret by name, ZS/CC/credentials unless the secret-name parameter says otherwise. [cloud-connector.aws.cloudformation:macro-lookups] The autoscaling template's macro checks that every Cloud Connector subnet is in the chosen VPC and in one of the chosen availability zones and that each chosen zone has a subnet, and VPC endpoint subnets, when given, override the Cloud Connector subnets with one picked per zone. [cloud-connector.aws.cloudformation:asg-input-validation]

**Standard (no autoscaling) parameters.** The HTTP Monitor Probe Port parameter must be defined to check the liveliness of the Cloud Connectors and to achieve high availability. [cloud-connector.aws.cloudformation:probe-port-required] In the Starter Deployment Template, EBS encryption, the Cloud Tag Collection IAM policy, and a management security group rule permitting egress TCP/12002 to Zscaler Support servers all default to true; Help says disabling the support rule is not recommended. [cloud-connector.aws.cloudformation:standard-defaults] The Add-on Template with High Availability, which takes route tables with affinity for each Cloud Connector and a Lambda package from S3, is deprecated. [cloud-connector.aws.cloudformation:ha-addon-deprecated] In the Starter template the EC2 instance type defaults to m6i.large, the size to small and the HTTP monitor probe port to 50000 (allowed values 80 and 1024 to 65535), and the instance has an EBS-optimized gp3 volume on /dev/sda1. [cloud-connector.aws.cloudformation:simple-defaults] Both the Starter and autoscaling templates take a FipsEnabled parameter, default "False" with allowed values "True" and "False", which the changelog says enables FIPS mode via user data. [cloud-connector.aws.cloudformation:fips-parameter] Both deployment templates constrain the secret-name parameter, default ZS/CC/credentials, to the pattern ^ZS/CC/[a-zA-Z0-9/_+=.@-]+$: names under the ZS/CC/ path prefix. [cloud-connector.aws.cloudformation:secret-name-prefix] The GWLB add-on template is compatible only with the Starter Deployment Template, because autoscaling deployments include the Gateway Load Balancer automatically, and Zscaler's recommended deployment method is GWLB. [cloud-connector.aws.cloudformation:gwlb-addon-compat]

**Autoscaling template.** An autoscaling deployment needs a provisioning template with autoscaling Enabled, which Zscaler Support enables, and an S3 bucket in the deployment region holding the Zscaler Cloud Connector Lambda ZIP file, whose bucket name and key are stack parameters. [cloud-connector.aws.cloudformation:asg-prerequisites] In the autoscaling template, availability-zone-based autoscaling groups default to true (one group per zone), the secret name defaults to ZS/CC/credentials, the instance size is small with other sizes not yet supported for autoscaling, and leaving the AMI blank deploys the latest Marketplace AMI. [cloud-connector.aws.cloudformation:asg-defaults] For the autoscaling template Zscaler recommends a target CPU value of 80%, warm pool instances in the Stopped state to reduce cost, and 5-tuple flow stickiness; the tag-collection policy setting applies only when CloudFormation creates a new IAM role. [cloud-connector.aws.cloudformation:asg-recommendations] How the group then scales is in [Cloud Connector Auto Scaling groups on AWS: scaling metric, policy, capacity limits](kb:cloud-connector.aws.autoscaling).

**Private Access add-on.** The Private Access add-on creates an outbound Route 53 resolver and up to 10 resolver rules, one per domain, takes the Cloud Connector's service ENI, and uses the Private Access cloud name ZPA for production clouds and ZPA-Beta for all others. [cloud-connector.aws.cloudformation:zpa-addon] The Private Access add-on takes up to 6 resolver endpoint subnets and up to 6 target IPs, requires that the routes from those subnets to the target IPs go via Cloud Connector, and defaults the target IPs to 185.46.212.88 and 185.46.212.89. [cloud-connector.aws.cloudformation:zpa-addon-params] The Private Access add-on creates system-type resolver rules for the Zscaler cloud domain, the Private Access cloud domain (prod.zpath.net for ZPA, zpabeta.net for ZPA-Beta), zscaler.com, freebsd.org, ntp.org and amazonaws.com, plus a forwarding rule per application domain whose resolver security group allows all protocols in and out from 0.0.0.0/0. [cloud-connector.aws.cloudformation:zpa-addon-rules] Help and the template disagree on the inputs [divergence:cloud-connector.aws.cloudformation:zpa-addon-inputs].

**After the stack.** After the CloudFormation deployment, the route table and associated subnet must be modified so traffic from the private workload subnet goes to Cloud Connector; by default traffic leaves the workload subnet without it. [cloud-connector.aws.cloudformation:route-after-stack] The route targets are in [Cloud Connector on AWS: steering workload traffic by route table, ENI or GWLB endpoint](kb:cloud-connector.aws.traffic-steering). A deployed Cloud Connector appears on the dashboard, and the Cloud & Branch Connector Monitoring page shows the name, group, location, geolocation and status of the deployed AMIs. [cloud-connector.aws.cloudformation:monitoring-page]

What to check:
1. Whether the Pre-Deployment Template stack exists and is current before the starter template was deployed.
2. Whether the workload route table was edited after the stack completed.
3. Whether the HTTP Monitor Probe Port parameter was set.
4. For autoscaling, whether the Lambda ZIP is in an S3 bucket in the deployment region and the template was left at one autoscaling group per availability zone.
5. For the Private Access add-on, whether the routes from the resolver endpoint subnets to the target IPs go via Cloud Connector, and whether the inputs match the deployed template rather than Help.
6. Whether the GWLB add-on was layered onto an autoscaling stack, which already contains a Gateway Load Balancer.

Sources disagree (name both sides):
- What the Private Access add-on takes as input: Help lists a Cloud Connector service ENI and up to 10 domain names, the template lists neither and bounds the domains by length. [divergence:cloud-connector.aws.cloudformation:zpa-addon-inputs]
  - zscaler-help: The add-on takes the Cloud Connector's service ENI and up to 10 domain names.
  - cft-aws-cloud-connector: The template's parameters are the Zscaler cloud name, ZPA cloud name, VPC, resolver endpoint subnets and target IPs, plus application domain names limited to 4096 characters; it has no service ENI parameter.
  Impact: A deployment written from Help supplies a service ENI the current template does not ask for, and a domain list is bounded by 4096 characters in the template, not by a count of 10; read the template version actually deployed.
