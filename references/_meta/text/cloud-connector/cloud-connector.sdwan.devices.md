# Branch device inventory and per-device settings: ZIA tunnel mode, support tunnel, DNS cache, traffic forwarding bypass (cloud-connector.sdwan.devices)
Also called: ZT devices page; virtual branch devices; physical branch devices; VM group; appliances group; support tunnel; bypass traffic forwarding engine; auto populate dns cache

Zero Trust Branch Devices are installed in an organization's on-premises locations such as branches and data centers, enabling Zero Trust connectivity from any unauthenticated users, servers or IoT/OT devices; the ZT Devices page (Infrastructure > Branch Connector > ZT Devices) lists each device's appliance name, serial number, device model (ZT400, ZT600 or ZT800), location, template and status. [cloud-connector.sdwan.devices:zt-devices] Editing a Zero Trust Branch Device sets its name and description, with the serial number, location and template shown view-only; Zscaler Initiated On-Demand Support Tunnel, when enabled, gives Zscaler Support control over the tunnel's start and stop, and Establish Support Tunnel, when enabled, allows Zscaler Support to access the device through the tunnel. [cloud-connector.sdwan.devices:support-tunnel]

**Virtual and physical device lists.** The VM Group page (Infrastructure > Branch Connector > VM Group) lists each device's availability zone, operational status (Inactive or Active), HA status (Disabled or Enabled), branch type (the hypervisor host type), upgrade window and upgrade status. [cloud-connector.sdwan.devices:virtual-list] The Physical Branch Devices page (Infrastructure > Branch Connector > Appliances Group) lists each device's serial number, operational status (Inactive or Active), HA status (Disabled or Enabled), branch type (the hardware device type), upgrade window and upgrade status. [cloud-connector.sdwan.devices:physical-list] An individual virtual device's edit window can enable or disable the device, shows the date and time it last received a heartbeat, and shows the current version and scheduled version of its software alongside its Software Upgrade Schedule; a physical device can likewise be enabled or disabled. [cloud-connector.sdwan.devices:device-status-and-versions] The schedule itself is in [Cloud & Branch Connector software upgrades: weekly window, stagger and release channels](kb:cloud-connector.upgrades). A virtual device's edit window shows the management outgoing gateway IP address, management IP address and management primary DNS server, the internal gateway IP address and primary DNS server, and the service IP, virtual IP and load balancer IP addresses; a physical device's window also shows a secondary DNS server. [cloud-connector.sdwan.devices:device-network-view]

**Tunnel to Internet and SaaS.** In the Group section of the edit window for a virtual branch device, and likewise for a physical one, the ZIA Tunnel Mode is set to Unencrypted or DTLS as the encryption type used when forwarding traffic to Internet & SaaS; an option that switches the tunnel type to TLS automatically if the tunnel becomes unhealthy can only be enabled if Unencrypted UDP or DTLS is selected as the ZIA Tunnel Mode and is enabled by default. An individual virtual device's edit window shows the ZIA Tunnel Mode view-only. [cloud-connector.sdwan.devices:zia-tunnel-mode] The defaults of the tunnel mode itself, whether Unencrypted and Unencrypted UDP are one option, and whether a tunnel returns to DTLS after falling back are not stated [gap:cloud-connector.sdwan.devices:tunnel-mode-defaults].

**Physical device settings.** On the physical device's edit window, Auto Populate DNS Cache, when enabled, activates advance DNS resolution of the application service fully qualified domain names (FQDNs); by processing the response of the DNS queries, Branch Connector builds an IP cache that helps policy match even when the DNS queries do not pass through the device. [cloud-connector.sdwan.devices:auto-populate-dns-cache] On the physical device's edit window, Bypass Traffic Forwarding Engine, when enabled, allows all local and internet-destined traffic to flow without policy validation or content inspection if the policy enforcement engine fails or is stopped for upgrades; when it is enabled, applications protected by Private Access cannot be accessed. The feature is disabled by default. [cloud-connector.sdwan.devices:bypass-forwarding-engine] Cloud Connector fail-close and fail-open behavior is separate: [Cloud Connector tunnels to Service Edges: primary, secondary, tertiary, fail-close and fail-open](kb:cloud-connector.overview.gateway-failover). Whether virtual devices have these two settings is not stated [gap:cloud-connector.sdwan.devices:virtual-device-settings]. The defaults of the support tunnel settings and Auto Populate DNS Cache, and what the support tunnel connects to, are not stated [gap:cloud-connector.sdwan.devices:support-tunnel-defaults].

What to check:
1. Whether Bypass Traffic Forwarding Engine is enabled on a physical device, since enabling it lets traffic flow without policy validation or content inspection and blocks access to Private Access applications.
2. Whether Zscaler Support has been given control of the support tunnel on the device.

Not known (open gaps):
- Default ZIA Tunnel Mode and the Unencrypted naming [gap:cloud-connector.sdwan.devices:tunnel-mode-defaults]: settled by lab-test or support-ticket. Blocks: Predicting which tunnel encryption a device uses.
- Whether virtual devices have Auto Populate DNS Cache and Bypass Traffic Forwarding Engine [gap:cloud-connector.sdwan.devices:virtual-device-settings]: settled by lab-test or support-ticket. Blocks: Applying the physical-device settings to a virtual deployment.
- Support tunnel and DNS cache defaults [gap:cloud-connector.sdwan.devices:support-tunnel-defaults]: settled by lab-test or support-ticket. Blocks: Judging what Zscaler Support can reach by default.
