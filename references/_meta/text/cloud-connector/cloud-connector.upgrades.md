# Cloud & Branch Connector software upgrades: weekly window, stagger and release channels (cloud-connector.upgrades)
Also called: cloud connector upgrade window; cloud connector upgrade schedule; branch connector upgrade; sunday midnight upgrade; release channel stable latest beta; upgrade manager cloud connector; scheduleupgrade; cloud connector upgrade now

Connector software upgrades itself on a weekly schedule set per group; OS images are a separate path. This subject covers the software schedule and the controls over it.

**Cadence.** When Cloud or Branch Connectors are deployed, their software is upgraded to the latest version; an upgrade patch can include OS upgrades and Zscaler software upgrades. [cloud-connector.upgrades:deploy-latest] Cloud and Branch Connectors check for new software versions every week and, if one is available, upgrade automatically. [cloud-connector.upgrades:weekly-auto] By default the upgrade window starts every Sunday at midnight, local time of the deployed connector. [cloud-connector.upgrades:default-window] Which clock local time means is open [gap:cloud-connector.upgrades:local-time-basis].

**Within a group.** All connectors in a Cloud Connector group or Branch Connector group are updated within a two-hour window, and their upgrades are staggered to prevent service impact. [cloud-connector.upgrades:two-hour-staggered] Groups exist in part so a group can be upgraded while keeping redundancy: [Groups let you apply policies to a set of deployed Cloud Connectors and upgrade the Cloud Connectors in a group while keeping redundancy during the upgrade.](kb:cloud-connector.overview.groups:group-purpose). How many connectors restart at once, and what that leaves a small group, is open [gap:cloud-connector.upgrades:stagger-depth]. What happens after a failed upgrade is open [gap:cloud-connector.upgrades:failed-upgrade-retry].

**Release channels.** The cloud provisioning template selects a release channel (Stable, Latest or Beta), which determines the version a deployed Cloud Connector runs: Stable is widely adopted and proven, Latest is the most recent production release, and Beta gives early access and might contain bugs and instability. Channels are managed on the Upgrade Manager tab of the Groups page. [cloud-connector.upgrades:release-channels]

**Changing the schedule.** On the Cloud Connector Groups overview, selected groups or connectors can be given an upgrade schedule (a day and time for periodic software updates) or a new release channel, and each group shows its Upgrade Window. [cloud-connector.upgrades:group-actions] The API's Update Schedule Upgrade Time operation sets a day of week, start time and end time for lists of group IDs and VM IDs. [cloud-connector.upgrades:schedule-api] The help's group API reference has a bulk operation that updates the release channel of Cloud Connector VMs, taking STABLE, LATEST or BETA for lists of group IDs and VM IDs. [cloud-connector.upgrades:release-channel-api] The same reference has a bulk operation that enables or disables Cloud Connector VMs (ENABLE or DISABLE), returning the VMs that failed. [cloud-connector.upgrades:vm-status-api] The two API references list different upgrade operations [cloud-connector.api.ec-groups-wire:upgrade-operations](kb:cloud-connector.api.ec-groups-wire:upgrade-operations). Whether any operation starts an upgrade immediately is open [gap:cloud-connector.upgrades:upgrade-now]. The Zscaler MCP server's ZTW toolset has 19 tools, none of which reads or changes Cloud Connector groups or their upgrades. [cloud-connector.upgrades:mcp-no-ecgroup]

**Upgrade Manager.** The Upgrade Manager page filters by Cloud (AWS, Azure or GCP), Auto Scaling (True or False), Release Channel (Stable, Latest or Beta) and Upgrade Status (Bootstrapping, No Pending Upgrade, Scheduled, Blocked or Failed), and shows the number of Cloud Connectors and groups on the Stable, Latest and Beta versions and the distribution of Cloud Connectors in different upgrade states. [cloud-connector.upgrades:upgrade-manager-filters] On the Upgrade Manager, actions apply to two or more selected groups or multiple selected individual Cloud Connectors: Schedule Upgrade (a day and time for periodic software updates), Enable, Disable (which stops traffic from processing without deleting the Cloud Connector) and Upgrade Release Channel (update the release channel by selecting Stable, Beta or Latest). [cloud-connector.upgrades:upgrade-manager-actions] What Blocked and Bootstrapping mean, and how the states map to the API's, is open [gap:cloud-connector.upgrades:upgrade-state-meanings]. In the Edit Cloud Connector Group window, the Release Channel section's Choose release channel drop-down selects Stable, Latest or Beta; in the Edit Cloud Connector window for an individual Cloud Connector, the Upgrade Information section shows the Current Version of the Cloud Connector and the Scheduled Version to be applied when it upgrades next. [cloud-connector.upgrades:group-release-channel] When a GCP instance deployed in an instance group is deleted it is replaced by a new one, and the new instance appears in the Upgrade Manager's table section for it. [cloud-connector.upgrades:gcp-replaced-instance]

**Related.** OS images, which this schedule does not replace, are in [Cloud Connector OS upgrades: redeployment and the ZscalerOS 24 end of support](kb:cloud-connector.upgrades.os-images); the software update repository's certificate renewal is in [The pkg-repo.zscaler.com certificate renewal: minimum images, autoscaling templates and why connectors might not update automatically](kb:cloud-connector.upgrades.repo-certificate). Watching an upgrade is in [Watching Cloud Connector upgrades: VM record fields, upgrade metrics and upgrade events](kb:cloud-connector.upgrades.monitoring). ZPA App Connectors upgrade by a separate mechanism with a 4-hour window: [The update runs in a 4-hour window that starts at the scheduled time; after one component succeeds another eligible one is chosen, until the window expires or every component in the group has updated.](kb:zpa.app-connectors.upgrades:four-hour-window).

What to check:
1. The group's Upgrade Window before reading an alert near the window as an outage.
2. Which release channel the group's connectors are on before comparing their versions.
3. Whether the group has enough connectors to keep serving while the staggered upgrade restarts members.
