# NSS feeds for Cloud & Branch Connector: limits, output and SIEM destination (cloud-connector.nss-va.feeds)
Also called: cloud connector nss feed; nss feed limit; session feed limit 8; nss feed json; nss siem fqdn; nss duplicate logs; nss siem rate; nss feed filters cloud connector

A feed is one connection from an NSS server to a SIEM for one log type. Its settings decide what is sent, in which format and to which address.

**How many.** Up to 16 NSS feeds can be added for each NSS, and Session logs are limited to 8 of them per NSS. Event log feeds can be configured up to 16. [cloud-connector.nss-va.feeds:feed-limits] Up to 16 NSS feeds can be configured for DNS logs. [cloud-connector.nss-va.feeds:dns-feed-limit] Up to 16 NSS feeds can be configured for Metrics logs. [cloud-connector.nss-va.feeds:metrics-feed-limit] Each feed can have its own list of fields, format and filters. [cloud-connector.nss-va.feeds:per-feed-config]

**Format.** Feed output is a CSV list by default; Name Value Pairs, Tab Separated, JSON or Custom can be selected instead (stated in the Session and Event feed articles). [cloud-connector.nss-va.feeds:output-types] A feed's time zone defaults to the organization's time zone and applies to the time field in the output; the configured time zone can also be output as a separate field. [cloud-connector.nss-va.feeds:timezone] How a Session feed records sessions individually or in aggregates is in [Cloud Connector session records: aggregation and rule attribution](kb:cloud-connector.logs.session-records).

**Destination.** A feed streams to a SIEM IP address or FQDN on a SIEM TCP port. With an FQDN the NSS re-resolves the name only when the existing connection goes down, which allows failover from one IP to another without relying on a DNS update, and the FQDN cannot be used for DNS-based load balancing. [cloud-connector.nss-va.feeds:siem-destination] SIEM Rate is Unlimited by default; Limited caps the stream at a configured number of events per second, for SIEM licensing or other constraints. [cloud-connector.nss-va.feeds:siem-rate] Whether a feed can deliver to an HTTPS endpoint is open [gap:cloud-connector.nss-va.feeds:https-destination].

**Gaps in delivery.** Duplicate Logs sets the number of minutes for which the NSS sends duplicate logs, so that no logs are skipped during downtime; in the Event feed article it is Disabled by default. [cloud-connector.nss-va.feeds:duplicate-logs] The buffer that covers a SIEM outage is in [NSS servers for Cloud & Branch Connector: certificate, buffering and sizing](kb:cloud-connector.nss-va.servers).

**Filters.** A Session feed can be filtered by policy action and rule name (both per the traffic forwarding rules), by location, Branch Connector group, Branch Connector and client IP address, by network service, and by gateway. [cloud-connector.nss-va.feeds:session-filters] An Event feed can be filtered by location, by Cloud or Branch Connector group and by Cloud or Branch Connector VM. [cloud-connector.nss-va.feeds:event-filters] A DNS feed filters by policy action, including Redirect to ZPA (limiting the logs to requests resolved with the IP pool), by rules in the DNS Control policy, by DNS responses (domain names, IPv4 and IPv6 addresses) and by session duration in seconds. [cloud-connector.nss-va.feeds:dns-feed-filters] A Metrics feed selects VM, Instance and/or Resource record types, where Instance metrics apply at an individual data processing instance level (there are multiple instances in a single Cloud or Branch Connector) and Resource metrics at an individual resource level (physical and logical resources used by all data processing instances); it can be limited to specific Cloud or Branch Connector VMs. [cloud-connector.nss-va.feeds:metrics-feed] On the DNS feed page there is no limit on the number of locations that can be selected, and item lists show up to 500 items on a page. [cloud-connector.nss-va.feeds:item-lists] A large number of filters, or complex filters such as string searches, can impact the performance of the NSS. [cloud-connector.nss-va.feeds:filter-cost]

**DNS feed defaults.** On the DNS feed page the NSS type is NSS for Firewall, Cloud and Branch Connector by default and the status is Enabled by default; the output is a CSV list by default, with Custom, JSON, Name Value Pairs or Tab Separated selectable if the SIEM accepts them; and the setting for the number of minutes the NSS sends duplicate logs is Disabled by default. [cloud-connector.nss-va.feeds:dns-feed-defaults] The HTTPS-push Cloud NSS feeds are in [Cloud NSS feeds for Cloud & Branch Connector logs: HTTPS destination, output and per-log-type filters](kb:cloud-connector.nss-va.cloud-feeds).

**Feed format guidelines.** The Cloud & Branch Connector general guidelines for NSS feeds recommend not including more than 50 fields in a feed to accommodate syslog message size limits, encode any URL character at or below 0x20, or equal to and above 0x7F, as %HH, say to use tabs as field delimiters, say field names are case-sensitive, and allow up to 16 NSS feeds for each NSS. [cloud-connector.nss-va.feeds:cbc-guidelines] In the Cloud & Branch Connector page's example the SIEM went offline at 6:29:00 PM, the NSS detected the lost connection at 6:30:00 PM and the connection was restored at 6:40:00 PM; with Duplicate Logs set to 5 minutes the NSS resends the logs from 6:25:00 onward and sends 5 minutes of duplicate logs, with it disabled from 6:30:01 onward, and each log record has a unique ID stored in the recorded field that is used to discover duplicate logs. [cloud-connector.nss-va.feeds:cbc-duplicate-example] The same worked example on the ZIA page gives different times and a different account of the duplicates [divergence:cloud-connector.nss-va.feeds:duplicate-logs-example].

What to check:
1. How many feeds the server already carries, and how many of them are Session feeds, before adding one.
2. Whether the feed's filters exclude the records the SIEM is missing, for example a Session feed limited to Branch Connector groups or to one gateway.
3. Whether a SIEM destination given as an FQDN has changed address while the old connection stayed up, since the NSS re-resolves only when the connection goes down.

Sources disagree (name both sides):
- The Cloud & Branch Connector and ZIA general-guidelines pages give the same Duplicate Logs outage example (SIEM offline 6:29:00 PM, detected 6:30:00 PM, restored 6:40:00 PM) with different resend times and a different account of the duplicates. [divergence:cloud-connector.nss-va.feeds:duplicate-logs-example]
  - zscaler-help: Disabled, the NSS resends from 6:30:01 onward; at 5 minutes it resends from 6:25:00 onward and sends 5 minutes of duplicate logs.
  - zscaler-help: Disabled, the NSS sends from 6:30:00 PM onwards and does not recover 6:29:00 to 6:30:00 PM; at 5 minutes it duplicates 6:25:00 to 6:28:59 PM and recovers 6:29:00 to 6:30:00 PM.
  Impact: Which logs a SIEM receives after an outage with Duplicate Logs disabled differs by one second between the pages, and for the 5-minute setting one page counts all 5 minutes as duplicates while the other splits them into 4 minutes duplicated and 1 minute recovered. The ZIA page's version is the claim shared.nss.reliability:duplicate-logs-example.
