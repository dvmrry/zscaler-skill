# Deploying Branch Connector VMs on VMware, Linux KVM and Hyper-V: prerequisites, sizing, HA host settings, user data and IaC (cloud-connector.sdwan.virtual-deployment)
Also called: branch connector vmware; branch connector kvm; branch connector hyper-v; branch connector ova; branch connector vhdx; branch connector user data; userdata.cfg; branch connector and app connector vm

The Branch Connector Images page in the Zscaler Admin Console provides the ability to download Branch Connector or Branch Connector & App Connector virtual machine images; Branch Connector images include App Connectors that have not yet been provisioned, and deploying Branch Connector & App Connector requires selecting the combined instance and configuring the deployment properties accordingly. [cloud-connector.sdwan.virtual-deployment:images] The VMware page has the administrator download the Branch Connector Open Virtual Appliance (OVA) image file for VMware ESXi, the Hyper-V page the Branch Connector Virtual Hard Disk v2 (VHDX) image, and the Linux KVM page the Branch Connector image, all from the Branch Connector Images page. [cloud-connector.sdwan.virtual-deployment:image-formats] The image download page is also covered in [For Branch Connector VMs the images are hosted in the Admin Console for download, and the devices are reprovisioned with the latest images.](kb:cloud-connector.upgrades.os-images:branch-images).

**Prerequisites.** The VMware page requires a dedicated username and password for the Branch Connector deployment, created in the Zscaler Admin Console, with a password of at least 8 characters including at least one uppercase letter, one number and one special character, and says the deployment fails if the password does not meet these requirements; the Linux KVM and Hyper-V pages require a dedicated password. All three pages say the password must not contain a $, &, >, <, ;, ' or ". [cloud-connector.sdwan.virtual-deployment:admin-prereqs] The VMware page says to grant admins full access to Branch Connector provisioning permissions, the Linux KVM page that admins must have full access to Branch Connector Provisioning permissions, and the Hyper-V page that admins must have full access to Branch Connector configuration permissions. [cloud-connector.sdwan.virtual-deployment:admin-permissions] Whether the provisioning and configuration permissions are one permission is not stated [gap:cloud-connector.sdwan.virtual-deployment:permission-names]. The VMware, Linux KVM and Hyper-V pages each say Branch Connector uses an API key to authenticate and register the VM with the Zscaler service. [cloud-connector.sdwan.virtual-deployment:api-key] On VMware the VM requires VMware vSphere Hypervisor (ESXi) version 7.0 or later, or the minimum version stated by Broadcom. [cloud-connector.sdwan.virtual-deployment:esxi-version] The KVM and Hyper-V host versions are not stated [gap:cloud-connector.sdwan.virtual-deployment:host-versions].

**Sizing.** On the VMware, Linux KVM and Hyper-V pages a Branch Connector VM requires, for Small, 4 GB of memory, 2 CPU cores, a 128 GB data disk and 2 NICs, and for Medium 8 GB of memory, 4 CPU cores, a 128 GB data disk and 4 NICs; the Hyper-V procedure enters 4096 for a Small VM or 8192 for a Medium VM, 2 or 4 virtual processors, and a total of two network adapters for Small or 4 for Medium. [cloud-connector.sdwan.virtual-deployment:sizing-branch-connector] On the VMware Branch Connector & App Connector page a combined VM requires, for Small, 16 GB of memory, 4 CPU cores, a 128 GB data disk and 3 NICs, and for Medium 32 GB of memory, 6 CPU cores, a 128 GB data disk and 5 NICs. [cloud-connector.sdwan.virtual-deployment:sizing-combined-vmware] The combined sizing differs between the pages [divergence:cloud-connector.sdwan.virtual-deployment:combined-vm-sizing].

**High availability host settings.** For Branch Connector deployed in high availability on VMware, the Promiscuous mode option must be enabled (set to Accept) on the vSwitch or at the port group level, and the MAC address changes and Forged transmits options must be enabled on the vSwitch or port group. Branch Connector uses the Common Address Redundancy Protocol (CARP) to process traffic across multiple Branch Connector instances; when promiscuous mode is enabled other VMs might be able to detect traffic going through the service interface, and Zscaler recommends a port group for the Branch Connector service interfaces. If multiple physical ports exist on the same vSwitch, the Net.ReversePathFwdCheckPromisc advanced option must be enabled (set to 1) on the ESXi host, or multicast traffic loops back to the host and CARP does not function properly. [cloud-connector.sdwan.virtual-deployment:esxi-ha-vswitch] On Hyper-V, MAC Address Spoofing must be enabled on each network adapter for Branch Connector deployed in high availability, and Zscaler recommends enabling it for non-HA deployments as well; the procedure selects Generation 1 as the VM generation to support the VHDX file, deselects Use Dynamic Memory for this virtual machine, and moves IDE above CD in the boot device Startup order list. [cloud-connector.sdwan.virtual-deployment:hyperv-specifics] The template side of the pair is in [When High Availability Deployment is enabled, two Branch Connectors share a virtual IP address on their forwarding interfaces in active or standby mode; traffic sent to the shared virtual IP address reaches the active Branch Connector and, if the primary stops responding, fails over automatically to the second. For both to access the same default gateway, the virtual IP address must be on the same broadcast domain as the forwarding interface.](kb:cloud-connector.sdwan.configuration-templates:vm-ha-vip).

**VMware and KVM procedure.** A VMware OVA deployment takes the Branch Connector Provisioning URL as the Provisioning Template URL, the API Key from the API Key Management page, a Management Interface Type of static or DHCP (the IP address and subnet prefix are entered if static and left blank if DHCP) and an SSH public key for logging in without a password; for Branch Connector & App Connector, an App Connector Provisioning Key is configured in the Admin Console, the Management Interface Type is static, a Provision Key is entered, and the Control Interface Type is static with the IP address and subnet prefix of the control interface. [cloud-connector.sdwan.virtual-deployment:ova-properties] Deploying on VMware from the OVA with a cloud-init ISO requires the Power on automatically option to be disabled; the procedure skips the additional properties for the VM because values entered on that page are not configured, selects Datastore ISO file from the CD/DVD Drive 1 drop-down menu with the Connect and Connect at power on checkboxes, and Zscaler recommends enabling the Synchronize guest time with host option after deploying Branch Connector. [cloud-connector.sdwan.virtual-deployment:esxi-cloud-init-steps] On Linux KVM the procedure selects Import existing disk image in the New VM window, selects Free BSD 11.4 as the operating system, and selects CDROM device as the Device type. [cloud-connector.sdwan.virtual-deployment:kvm-specifics]

**User data.** On VMware, deployments using cloud-init Config Drive require a text file of user data for the Branch Connector VM, applied to the VM as an ISO file mounted via a virtual CD-ROM drive during deployment, and deployments using an OVA file and OVA template instead have the OVA import process provide the user data; the file is named userdata.cfg and formatted in YAML. The Linux KVM and Hyper-V pages also require a text file containing user data information for the Branch Connector VM. [cloud-connector.sdwan.virtual-deployment:user-data-required] The VMware page's Branch Connector with Management DHCP Template has a ZSCALER block with cc_url and http_probe_port, where a comment says the optional http_probe_port changes the port for load balancer status checks from the default value 50001 to 50035; the template also carries api_key, password, username and a network config with physical interface subnets of type dhcp, and a static variant gives an address, gateway and nameserver addresses. [cloud-connector.sdwan.virtual-deployment:user-data-template] The VMware page applies the user data to the VM as an ISO image with one of three procedures, Windows, macOS or Linux, and in each the user data file must be named user-data. The Windows procedure uses oscdimg.exe with the volume label cidata (-lcidata), the macOS procedure uses mkisofs with -volid cidata, and the Linux procedure runs the geniosimage command with -volid cidata. [cloud-connector.sdwan.virtual-deployment:user-data-iso] The VMware page's user data names the interface driver for the chosen virtual NIC: vtnet for Windows VirtIO, em for Intel e1000, igb for Intel Gigabit, ix for Intel 10 Gigabit, vmx for VMware Vxnet3 and hn for Hyper-V. [cloud-connector.sdwan.virtual-deployment:network-drivers] The VMware Branch Connector & App Connector page gives a Branch Connector & App Connector with Static Management IP Template, which has an IP configuration for the App Connector interface and a zscaler_app_connector block with enable 'yes' and the provisioning key. [cloud-connector.sdwan.virtual-deployment:combined-user-data] How the App Connector is provisioned on KVM and Hyper-V, whose combined pages show the plain Branch Connector templates, is not stated [gap:cloud-connector.sdwan.virtual-deployment:combined-kvm-hyperv]. The allowed range of the probe port is not stated [gap:cloud-connector.sdwan.virtual-deployment:probe-port-range].

**Page defect.** The VMware page's Linux ISO procedure installs the genisoimage package with the command sudo apt install genisoimage but its ISO command runs geniosimage; the page's commands disagree on the tool name. [cloud-connector.sdwan.virtual-deployment:doc-erratum-geniosimage]

**After deployment and IaC.** On the VMware page the Branch Connector Monitoring page provides information on the name, group, location, geolocation and status of the VMs deployed in the branch account. [cloud-connector.sdwan.virtual-deployment:post-deploy] Infrastructure as Code (IaC) deployment templates are available in GitHub to assist in deploying Branch Connector or Branch Connector & App Connector in VMware ESXi or Linux KVM, and are not available for Branch Connector deployment on Hyper-V platforms; the VMware ESXi section lists four starter templates: bc, bc_ha (high availability), bc_ac (with App Connector) and bc_ha_ac (with App Connector and high availability). [cloud-connector.sdwan.virtual-deployment:iac-templates] The VMware ESXi deployment template pages list resources including a key pair for SSH access, two Zscaler Branch Connector VMs, a control interface and an App Connector provisioning key; the Linux templates list a cloud-init provisioning ISO and a KVM storage volume. [cloud-connector.sdwan.virtual-deployment:iac-resources] The IaC repositories are not mirrored in this knowledge base [gap:cloud-connector.sdwan.virtual-deployment:iac-repos].

What to check:
1. Which image variant (Branch Connector or the combined Branch Connector & App Connector) and which hypervisor the deployment uses, since sizing differs between the pages.
2. For a VMware deployment in high availability, the vSwitch or port group security settings and, with multiple physical ports on the vSwitch, the host advanced option.
3. That the deployment password avoids the characters the pages exclude, since a password that does not meet the VMware requirements fails the deployment.

Sources disagree (name both sides):
- Four positions on the CPU and NIC counts of a combined Branch Connector & App Connector VM: the VMware page, the Hyper-V prerequisites, the Hyper-V procedure on the same page, and the Linux KVM page. [divergence:cloud-connector.sdwan.virtual-deployment:combined-vm-sizing]
  - zscaler-help: VMware: Small 16 GB, 4 cores, 3 NICs; Medium 32 GB, 6 cores, 5 NICs.
  - zscaler-help: Hyper-V prerequisites: Small 16 GB, 2 cores, 3 NICs; Medium 32 GB, 4 cores, 5 NICs.
  - zscaler-help: Hyper-V procedure on the same page: 4 virtual processors for Small and 6 for Medium, 3 network adapters for Small and 4 for Medium.
  - zscaler-help: Linux KVM combined page: the plain Branch Connector figures, 4 and 8 GB of memory, 2 and 4 cores, 2 and 4 NICs.
  Impact: The same combined image has four sets of CPU and NIC counts, and the KVM page also differs on memory; the pages do not say which governs, so a VM sized from one page may not match another.
