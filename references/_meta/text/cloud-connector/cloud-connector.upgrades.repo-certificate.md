# The pkg-repo.zscaler.com certificate renewal: minimum images, autoscaling templates and why connectors might not update automatically (cloud-connector.upgrades.repo-certificate)
Also called: pkg-repo.zscaler.com certificate; software update repository certificate; digicert g2 certificate chain cloud connector; cloud connector cannot connect to software update repository; cloud connector ca bundle update

The article covers the TLS server certificate of the software update repository (pkg-repo.zscaler.com) for Cloud Connector, which expires; when it is renewed, the repository uses a new DigiCert G2 certificate chain. [cloud-connector.upgrades.repo-certificate:what-changes]

**Existing connectors.** Existing, active Cloud Connectors update automatically through regularly scheduled upgrades, and those running version 1.146.5 or later have received the automatic CA bundle update and are not affected; the version is the Current Version in the Upgrade Information section of the Upgrade Status tab. [cloud-connector.upgrades.repo-certificate:existing-auto] Existing Cloud Connectors do not need to be redeployed as long as they remain current through regular, automatic scheduled upgrades, but some improvements might only be available through newer image releases, so Zscaler recommends that all new deployments use the latest marketplace images and that existing instance fleets be refreshed periodically. [cloud-connector.upgrades.repo-certificate:redeploy]

**New deployments.** For new deployments the article gives AWS image version ZS42.1.0 or later (deployed AMI name starting with zs-cc-ga-03092026), Azure image version 42.1.0 or later and GCP image version zs-cc-ga-03092026 or later; unless older image versions are hard-coded in custom IaC templates, the main requirement is to rerun or refresh the templates so later deployments use the latest images. [cloud-connector.upgrades.repo-certificate:minimum-images] In the article's Terraform snippet the AMI filter value is 2l8tfysndbav4tv2nfjwak3cu, or axnpwhsb4facossmbm1h9yad6 when var.aws_region is cn-north-1 or cn-northwest-1, with owners set to aws-marketplace. [cloud-connector.upgrades.repo-certificate:ami-product-code]

**Autoscaling.** For autoscaling group (ASG) deployments the launch or instance template must be updated to reference the new marketplace image; if not, new instances cannot connect to the software update repository, and newly scaled-out instances use the old image, which is unable to connect after the expiration. [cloud-connector.upgrades.repo-certificate:asg-templates] On AWS the AMI ID is updated in the launch template, a new launch template version is created and the ASG updated to use it; on Azure the image reference in the VMSS model is updated and a model update triggered; on GCP a new instance template with the updated image is created and the MIG updated to use it. [cloud-connector.upgrades.repo-certificate:per-cloud-update] Updating the AWS launch template does not automatically replace existing EC2 instances; future scale-out or health-based replacement instances are deployed from the new AMI, and the Instance Refresh feature replaces instances in the ASG automatically as a rolling update that maintains availability. [cloud-connector.upgrades.repo-certificate:no-replace-running] The article's AWS launch template example changes the image_id from ami-0b11365e64b30005e (old ZS6.1.26.2) to ami-07c8a4afe978a3087 (new ZS42.1.0), and says applying the change has no effect on running Cloud Connector appliances on the ASGs using the launch template. [cloud-connector.upgrades.repo-certificate:worked-example] The old image in that example is not in the version table [gap:cloud-connector.upgrades.repo-certificate:old-image-not-listed].

**Why a connector might not update automatically.** The article lists reasons a connector might not update automatically: firewall and/or SSL inspection connectivity issues, modifying the scheduled upgrade windows to circumvent automatic updates, Zscaler-controlled block filtering (removed by contacting Zscaler Support), and appliance issues such as process errors, crashes or disk partition space issues. [cloud-connector.upgrades.repo-certificate:why-not-updating]
