# Cloud Connector on AWS: firewall requirements and the reference security groups (cloud-connector.aws.security-groups)
Also called: cloud connector security group aws; cloud connector outbound ports aws; cloud connector 12002 support; 167.103.95.222; cloud connector geneve security group; cloud connector to cloud connector communication; mgmt_ssh_enabled; all_ports_egress_enabled

The management interface and the service interfaces each get their own security group in the reference module. Help states the product requirement; the module states one concrete rule set.

**Product requirement.** The Cloud Connector instance needs only outbound connections to the Zscaler cloud and no inbound connections from it; the account's outbound requirements are at config.zscaler.com under the cloud name and cloud-branch-connector. [cloud-connector.aws.security-groups:outbound-only] Help's troubleshooting for an AWS Cloud Connector in an inactive state includes that the security group or network ACL is not blocking the Cloud Connector's TCP/UDP 443; its checks on the connectivity from Cloud Connector to Internet & SaaS include that no security group or network ACL blocks outbound TCP/UDP 443 to the Internet & SaaS cloud. [cloud-connector.aws.security-groups:tcp-udp-443] Cloud Connectors in a group or cluster communicate with each other over their service interfaces, for example to synchronize FQDN and wildcard FQDN information, so no firewall or security group may block traffic between them across the VPC and its availability zones. [cloud-connector.aws.security-groups:cc-to-cc]

**Management security group (module).** The reference security group module allows SSH (TCP 22) from the VPC CIDR to the management interface when `mgmt_ssh_enabled` is true, its default; without it the only access is SSM. [cloud-connector.aws.security-groups:mgmt-ssh] The management group's egress rules are TCP 443 and UDP 123 to 0.0.0.0/0 (required), all TCP ports to 167.103.95.222/32 for the Zscaler repo server (required), and UDP 53 to 0.0.0.0/0 (recommended). [cloud-connector.aws.security-groups:mgmt-egress] When `support_access_enabled` is true (default), the management group allows TCP 12002 to `zssupport_server`, which defaults to 199.168.148.101/32 for commercial clouds and is the resolution of remotesupport.<cloud>.net. [cloud-connector.aws.security-groups:mgmt-support]

**Service security group (module).** The service group allows, from the VPC CIDR, TCP on the HTTP probe port for health probes and TCP 443 for internal VPC cluster communication, both marked required. [cloud-connector.aws.security-groups:service-ingress] The service group also allows all protocols from the VPC CIDR so service interfaces can communicate freely; the rule is labelled optional, but its count condition is the same as the service security group's own (`byo_security_group` false), with no `gwlb_enabled` term. [cloud-connector.aws.security-groups:service-intra-vpc] When `gwlb_enabled` is true (default), the service group allows UDP 6081 GENEVE traffic in from and out to the VPC CIDR. [cloud-connector.aws.security-groups:service-geneve] The service group's egress rules are TCP 443, UDP 443 and UDP 123 to 0.0.0.0/0 (required) and UDP 53 to 0.0.0.0/0 (recommended). [cloud-connector.aws.security-groups:service-egress] When the module creates the service group (`byo_security_group` false) and `all_ports_egress_enabled` is true (default), the service group allows all protocols out to 0.0.0.0/0; the module says this is only required for direct or bypassed non-HTTPS traffic through Cloud Connector. [cloud-connector.aws.security-groups:service-all-egress]

**CloudFormation.** The CloudFormation templates create the TCP/12002 support rule by default: [Cloud Connector on AWS: CloudFormation templates, order, and parameter defaults](kb:cloud-connector.aws.cloudformation).

**CloudFormation groups.** The Starter template's management group allows egress TCP 443 and UDP 123 to 0.0.0.0/0, marked required, and SSH (TCP 22) in from the CIDR given in the MgmtSSHCidr parameter, marked recommended. [cloud-connector.aws.security-groups:cfn-mgmt-sg] The Starter template's service group allows in from 0.0.0.0/0 TCP on the HTTP probe port (default 50000), TCP 443, UDP 6081 GENEVE and all protocols, and out to 0.0.0.0/0 TCP 443, UDP 443, UDP 123, UDP 6081 and all protocols. [cloud-connector.aws.security-groups:cfn-service-sg] The two repositories scope the sources differently [divergence:cloud-connector.aws.security-groups:ingress-source]. In the autoscaling template an existing security group can be given for each of the management and service interfaces, an empty value creating a new one; the TCP/12002 support rule is created only when the support rule is enabled and the CreateMgmtIntfSecurityGroup condition holds. [cloud-connector.aws.security-groups:cfn-byo-sg] The Starter and autoscaling templates carry 199.168.148.101/32 as the TCP/12002 support rule's address; the macro resolves the address of remotesupport.<cloud>.net, reads the cloud name from the provisioning URL, and rewrites the rule's CidrIp. [cloud-connector.aws.security-groups:cfn-support-ip]

What to check:
1. Whether security groups and network ACLs allow outbound TCP and UDP 443 from the Cloud Connector, using the cloud's config.zscaler.com page for destinations.
2. Whether Cloud Connectors in the same group can reach each other on their service interfaces.
3. For GWLB, whether UDP 6081 and the health probe port are allowed from the VPC CIDR on the service group.
4. Whether direct or bypassed non-HTTPS traffic fails because the all-ports egress rule was disabled.
5. For an autoscaling stack with a supplied management security group, whether it already allows egress TCP/12002 for Zscaler Support, since the template then creates no support rule.

Sources disagree (name both sides):
- Where the management SSH rule and the service ingress rules accept traffic from: the reference Terraform module limits them to the VPC CIDR, the CloudFormation Starter template takes the SSH source from a parameter and opens its service ingress rules to 0.0.0.0/0. [divergence:cloud-connector.aws.security-groups:ingress-source]
  - tfmod-aws-cloud-connector: The reference security group module allows SSH to the management interface from the VPC CIDR.
  - cft-aws-cloud-connector: The Starter template allows SSH (TCP 22) to the management group from the CIDR given in the MgmtSSHCidr parameter, and labels its all-protocol service ingress rule intra-VPC while using 0.0.0.0/0.
  Impact: A CloudFormation stack exposes the service ports to any source the network allows, which the Terraform module does not, and its SSH source is whatever CIDR the deployer supplies; the effective exposure depends on the subnet's routing and any network ACL, so check the deployed groups.
