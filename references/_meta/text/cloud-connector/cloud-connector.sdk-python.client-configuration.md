# The Python SDK against Cloud and Branch Connector: legacy client settings and session logout on exit (cloud-connector.sdk-python.client-configuration)
Also called: client.ztw; LegacyZTWClient; ZTW_USERNAME python; ztw python context manager activation; ztw python deauthenticate; python sdk ztw legacy

How the unified Python client routes ZTW calls to OneAPI or to a legacy helper is in [Reaching and signing in to the Cloud Connector API: OneAPI, legacy ZTC credentials and government clouds](kb:cloud-connector.api.authentication). This subject holds the legacy helper's settings and what leaving a client session does to staged changes.

**Legacy client.** `LegacyZTWClient` takes `username`, `password`, `api_key` and `cloud` from its config, falling back to `ZTW_USERNAME`, `ZTW_PASSWORD`, `ZTW_API_KEY` and `ZTW_CLOUD`, and a partner ID from `partnerId` or `ZSCALER_PARTNER_ID`. [cloud-connector.sdk-python.client-configuration:legacy-env-vars] The legacy ZTW helper sends requests to https://connector.<cloud>.net and authenticates at its /api/v1/auth path. [cloud-connector.sdk-python.client-configuration:legacy-host] That is the same connector host the Go SDK's legacy ZTW client uses. [cloud-connector.sdk-python.client-configuration:same-legacy-host-as-go] The Python legacy variables are named ZTW_* while the Go SDK's legacy configuration and the ZTC provider read ZTC_*, so one set of environment variables does not serve both SDKs. [cloud-connector.sdk-python.client-configuration:env-names-differ-from-go]

**Leaving a with block.** When a OneAPI client's with block exits and the last service it called was ZTW, the request executor ends the session at /ztw/api/v1/auth, but only if a POST, PUT or DELETE was sent during the session. [cloud-connector.sdk-python.client-configuration:exit-deauth-after-mutation] The SDK's code comment and its 1.5.9 changelog say ZTW, like ZIA, needs this explicit logout to activate staged configurations, and that the context-manager logout ensures staged configurations are activated on exit. [cloud-connector.sdk-python.client-configuration:sdk-says-logout-activates] So a Python script that writes ZTW objects inside a with block may see its staged changes go live when the block exits, without calling activate, while a read-only script does not log out; the Go SDK has no such step and activates only on an explicit call. [cloud-connector.sdk-python.client-configuration:exit-can-activate] Whether the service also activates on its own, and the ZIA equivalent, are in [Reading Cloud & Branch Connector activation status](kb:shared.activation.cbc) and [When the Python SDK ends a ZIA session and what that does to staged changes](kb:zia.sdk-python.activation-and-session).

What to check:
1. For the legacy Python client, that ZTW_USERNAME, ZTW_PASSWORD, ZTW_API_KEY and ZTW_CLOUD are set (or passed in the config), not the ZTC_* names the Go SDK and the provider read.
2. Whether a Python script that wrote ZTW objects ran inside a with block, whose exit logs out and, per the SDK, activates the staged changes.
