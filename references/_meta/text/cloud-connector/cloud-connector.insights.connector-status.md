# Cloud Connector status: what Active, Inactive and Disabled mean, and the per-VM API record (cloud-connector.insights.connector-status)
Also called: cloud connector inactive; cloud connector status active; cloud connector disabled; operationalStatus; ecVMs status; cloud connector vm size; formFactor; cloud connector nat ip; status active but load balancer unhealthy

The console status of a connector reports its management-plane contact, not whether it forwards traffic. The API's per-VM record carries more state, with value spaces only partly documented.

**Console status.** Cloud and Branch Connectors can be filtered by status Active, Inactive or Disabled, while the monitoring table's Status column shows Active or Inactive. [cloud-connector.insights.connector-status:status-values] The same three values on the group page are in [A Cloud Connector's operational status is Active, Inactive, or Disabled.](kb:cloud-connector.overview.groups:operational-status). A Cloud Connector is Inactive when it cannot contact its management plane; with a healthy data plane this has no service impact and the connector still processes data. [cloud-connector.insights.connector-status:inactive-meaning] The monitoring page says Cloud Connectors are Disabled only when an admin has disabled them in the Admin Console. [cloud-connector.insights.connector-status:disabled-by-admin] Disabling stops traffic without deleting the connector: [Disabling a Cloud Connector or a group stops traffic from processing; it does not delete the Cloud Connector.](kb:cloud-connector.overview.groups:disable-not-delete). In the Geoview, an inactive connector shows the reason for its inactive status. [cloud-connector.insights.connector-status:geoview-reason]

**Against load-balancer health.** The console status and load-balancer health are different signals: the status follows management-plane contact, while the cloud load balancer keeps or removes a connector by its HTTP health probe answer. The console status therefore does not show whether the load balancer keeps the connector in rotation. [cloud-connector.insights.connector-status:status-not-lb-health] The probe and failover model itself is in [How cloud load balancers spread traffic across Cloud Connectors and take unhealthy ones out](kb:cloud-connector.overview.load-balancing).

**Per-VM API record.** In the API's VM record, `status` is a list whose values are drawn from DISABLED, REGISTERED, RESERVED1, PKG_REPO_REGISTERED, ENABLING, DISABLING, DELETING, DELETING_LAST and DELETED. [cloud-connector.insights.connector-status:vm-status-enum] The VM record's `operationalStatus` is a string with no enum in the API reference. [cloud-connector.insights.connector-status:operational-status-free] What the status flags and the integer upgrade status mean, alone and together, is open [gap:cloud-connector.insights.connector-status:vm-status-codes]. The upgrade fields of the same record are in [Watching Cloud Connector upgrades: VM record fields, upgrade metrics and upgrade events](kb:cloud-connector.upgrades.monitoring).

**Size and HA.** The monitoring table's VM Size column shows Small or Medium, and the Branch Connector details page says Small and Medium VM sizes are supported, Small by default. [cloud-connector.insights.connector-status:vm-size-column] A Large size exists: the cloud provisioning template offers Small, Medium or Large on Amazon Web Services, the AWS deployment article lists Medium and Large VMs as deprecated, and the API's `formFactor` takes SMALL, MEDIUM or LARGE. [cloud-connector.insights.connector-status:large-size] On the Cloud Connector details page, VM Size is set to Small by default and is the only size currently supported. [cloud-connector.insights.connector-status:details-vm-size] The pages list different supported sizes [divergence:cloud-connector.insights.connector-status:vm-sizes]. The monitoring table's HA Status column applies only to Branch Connector; the API's VM record has an `haStatus` of INIT, ACTIVE, STANDBY or DISABLED. [cloud-connector.insights.connector-status:ha-status]

**NAT IP.** The VM record's `natIp` is described as the NAT IP of the VM; on the Branch Connector details page the NAT IP Address is the public IP address of the management interface when it is behind a NAT device. [cloud-connector.insights.connector-status:nat-ip] Which address a Cloud Connector's traffic carries in ZIA records is open [gap:cloud-connector.insights.connector-status:nat-ip-in-zia].

**Details page.** The Cloud Connector details page has tabs; its fields include the Deployment Type (AWS, Azure or GCP), the Status (Active or Inactive), the Last Seen Time and the First Deployed Time. [cloud-connector.insights.connector-status:details-general] The details page includes the ZIA Gateway (the Internet & SaaS (ZIA) proxy gateway IP address) and the ZPA Broker (the default Private Access (ZPA) IP address). [cloud-connector.insights.connector-status:details-gateways] The details page includes the Virtual Network (the VPC or VNet of the Cloud Connector), the GWLB Service Name, the Account ID (the AWS account ID, the Azure subscription ID or the GCP project name) and Roles Assigned to CC (the IAM or access roles and permissions associated with the Cloud Connector). [cloud-connector.insights.connector-status:details-cloud] The details page includes DNS Server 2 (the secondary DNS server IP address), Service IP Address 1 (the primary service IP address) and a Management IP Address described as the management gateway IP address. [cloud-connector.insights.connector-status:details-forwarding-mgmt] The edit window defines Management IP Address differently [divergence:cloud-connector.insights.connector-status:management-ip-address]. The captured page lists no CPU, memory or session fields, and Host ID is not defined [gap:cloud-connector.insights.connector-status:details-page-fields]; CPU and memory are streamed as [Cloud Connector metrics logs: VM, instance and resource samples](kb:cloud-connector.logs.metrics-records).

**Edit window.** In the edit window an individual Cloud Connector can be enabled or disabled with Status, and Last Heartbeat Received On shows the date and time the Zscaler service last received a heartbeat, or keepalive communication, from it. [cloud-connector.insights.connector-status:heartbeat] The edit window also shows the Configuration Template Name (the name of the Cloud Connector provisioning template), the Connector VM Size, the Management Outgoing Gateway IP Address (the default gateway IP address), the Internal Gateway IP Address and the Service IP. [cloud-connector.insights.connector-status:connector-edit-fields]

What to check:
1. Whether an Inactive connector is still forwarding, from the load balancer's health view or Tunnel Insights, before treating Inactive as an outage.
2. Whether a Disabled connector was disabled by an admin, since disabling stops traffic processing.
3. The connector's own VM record (status list and operationalStatus) when the console view is not enough, without reading meaning into undocumented flag combinations.

Sources disagree (name both sides):
- The Cloud Connector details page defines Management IP Address as the management gateway IP address (details-forwarding-mgmt), while the edit window defines the same label as the IP address of the Cloud Connector. [divergence:cloud-connector.insights.connector-status:management-ip-address]
  - zscaler-help: Management IP Address is the management gateway IP address.
  - zscaler-help: Management IP Address is the IP address of the Cloud Connector.
  Impact: Whether the field is the connector's own management address or its management gateway is not settled by the pages, so an answer that uses a Management IP Address from either screen needs to say which page it read.
- The Cloud Connector details page says Small is the only size currently supported, while the provisioning template offers Small, Medium or Large on AWS and the monitoring page lists Small or Medium. [divergence:cloud-connector.insights.connector-status:vm-sizes]
  - zscaler-help: Small is set by default and is the only size currently supported.
  - zscaler-help: On AWS the template offers Small, Medium or Large, with Small the default when autoscaling is enabled.
  - zscaler-help: The monitoring table's VM Size column is Small or Medium.
  Impact: Which sizes a Cloud Connector can run is not settled by the pages. The AWS deployment article lists Medium and Large VMs as deprecated (large-size), which may explain the details page, but no page says so.
