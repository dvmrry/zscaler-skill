# Cloud Connector on AWS: steering workload traffic by route table, ENI or GWLB endpoint (cloud-connector.aws.traffic-steering)
Also called: workload traffic not going through cloud connector aws; route table cloud connector aws; gwlb endpoint route cloud connector; eni route target cloud connector; cloud connector security vpc; cloud connector hub and spoke aws; cloud connector route failover lambda; cloud connector bypassed aws

Workload traffic reaches Cloud Connector only because a route table sends it there. The route target is either one Cloud Connector's service ENI or a Gateway Load Balancer endpoint.

**The route.** The workload route is a 0.0.0.0/0 destination whose target is, for non-GWLB deployments, the network interface of the Cloud Connector service interface and, for GWLB deployments, the Gateway Load Balancer endpoint. [cloud-connector.aws.traffic-steering:route-targets] The CloudFormation templates do not themselves create the workload subnet's route to Cloud Connector. [cloud-connector.aws.traffic-steering:cloudformation-leaves-routes] The post-stack route edit is [After the CloudFormation deployment, the route table and associated subnet must be modified so traffic from the private workload subnet goes to Cloud Connector; by default traffic leaves the workload subnet without it.](kb:cloud-connector.aws.cloudformation:route-after-stack). The reference Terraform network module points workload and Route 53 subnet route tables at the Cloud Connector service ENIs by default, or at the GWLB endpoints when `gwlb_enabled` is true; the base_1cc example's README says its workload subnet route is repointed to the Cloud Connector service ENI. [cloud-connector.aws.traffic-steering:module-routes]

**Subnet layout.** Zscaler recommends deploying Cloud Connector in a private subnet, whose traffic goes through a NAT gateway with an elastic IP rather than directly to an internet gateway. [cloud-connector.aws.traffic-steering:private-subnet] The guide's private-subnet layout has a Cloud Connector subnet whose default route goes to the NAT gateway, a workload subnet whose route is later pointed at the Cloud Connector, and a public NAT subnet whose default route goes to the internet gateway. [cloud-connector.aws.traffic-steering:subnet-layout]

**GWLB is the recommended path.** Zscaler's recommended deployment method is the Gateway Load Balancer, which distributes traffic across multiple Cloud Connectors and achieves high availability; the autoscaling deployment places a GWLB in front of the Cloud Connectors as the entry point for endpoint traffic. [cloud-connector.aws.traffic-steering:gwlb-recommended] The reference modules create one GWLB endpoint per listed subnet, and the `base_cc_gwlb`, `base_cc_gwlb_zpa`, `base_cc_gwlb_asg` and `base_cc_gwlb_asg_zpa` examples place one endpoint in each Cloud Connector subnet with workload routes pointing at the endpoint in the same AZ. [cloud-connector.aws.traffic-steering:gwlb-endpoint-per-subnet] Help's sublocation topologies show workload VPC endpoints connected over AWS PrivateLink to the GWLB, which passes traffic to and from the Cloud Connectors in a security VPC. [cloud-connector.aws.traffic-steering:security-vpc] In the centralized model, spoke VPC traffic goes to an AWS Transit Gateway, which passes it to the endpoint subnet in a hub VPC; the Terraform examples have a matching Transit Gateway hub-and-spoke mode. [cloud-connector.aws.traffic-steering:transit-gateway-hub] Target-group health, stickiness and cross-zone settings are in [Cloud Connector behind AWS Gateway Load Balancer: target group, health probe, stickiness, cross-zone](kb:cloud-connector.aws.gwlb). Whether GWLB preserves the workload source IP to Cloud Connector is not stated [gap:cloud-connector.aws.traffic-steering:source-ip-preserved].

**ENI routing and failover.** The deprecated HA examples (`base_2cc`, `base_2cc_zpa`, which builds on it, and `cc_ha`, where Lambda HA failover is a toggle) deploy a Lambda that probes each Cloud Connector's HTTP probe port and fails workload route tables over between two Cloud Connectors; its IAM policy allows ec2:ReplaceRoute only on resources whose Name tag matches the deployment's route-table pattern. [cloud-connector.aws.traffic-steering:legacy-lambda-failover] An ENI route sends the subnet's traffic to one Cloud Connector instance, so without a failover mechanism such as the deprecated Lambda, losing that instance leaves the route pointing at nothing that forwards. [cloud-connector.aws.traffic-steering:eni-single-target]

**Not captured.** The AWS reference architecture guide is a PDF whose body was not captured [gap:cloud-connector.aws.traffic-steering:reference-architecture].

What to check:
1. Whether the workload subnet's route table has 0.0.0.0/0 pointing at the Cloud Connector service ENI (non-GWLB) or at a GWLB endpoint (GWLB), and not at a NAT gateway or internet gateway.
2. For GWLB, whether the workload route points at the GWLB endpoint in the same availability zone.
3. For ENI routing, whether the route still names a live instance's service ENI, and whether a failover Lambda exists to rewrite it.
4. Whether the Cloud Connector subnet's default route goes to a NAT gateway (private subnet) or the internet gateway (public subnet).
