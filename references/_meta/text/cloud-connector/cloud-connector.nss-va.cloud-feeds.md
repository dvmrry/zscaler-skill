# Cloud NSS feeds for Cloud & Branch Connector logs: HTTPS destination, output and per-log-type filters (cloud-connector.nss-va.cloud-feeds)
Also called: cloud nss feeds cloud connector; nss cloud feeds; cloud nss branch connector; cloud nss session feed; cloud nss dns feed; cloud nss metrics feed

Cloud NSS feeds are the HTTPS-push feeds for Cloud & Branch Connector logs. Cloud NSS streams logs from the Zscaler Cloud & Branch Connector Admin Portal directly into a compatible cloud-based SIEM without the need to deploy an NSS VM. [cloud-connector.nss-va.cloud-feeds:no-vm-needed] Cloud & Branch Connector help has pages for adding Cloud NSS feeds for Session, DNS, Event and Metrics logs; a Cloud NSS feed specifies the log data the Cloud NSS sends to the SIEM, with one or more fields for the logs and one field for alerts. [cloud-connector.nss-va.cloud-feeds:cloud-feeds-exist] The Session, Event and Metrics feed pages add Cloud NSS feeds under Data Explorer > Log Streaming > NSS Cloud Feeds; on the Session and DNS feed pages the NSS type is NSS for Firewall, Cloud and Branch Connector by default, and on the Session page the status is Enabled by default. [cloud-connector.nss-va.cloud-feeds:nss-type-and-location] Whether they need their own subscription is open [gap:cloud-connector.nss-va.cloud-feeds:subscription].

**Destination.** On the Session feed page a Cloud NSS feed sends to a SIEM type chosen from a list, at the HTTPS URL of the SIEM log collection API endpoint, with HTTP header keys and token values; OAuth 2.0 Authentication is enabled by default if applicable to the SIEM type, and Max Batch Size limits an individual HTTP request payload to the SIEM's best practice. [cloud-connector.nss-va.cloud-feeds:https-destination] On the Session feed page SIEM Rate stays Unlimited unless the output stream must be throttled for licensing or other constraints; a limit must be between 100 and 1,000,000, and one too low for the traffic volume causes log loss. [cloud-connector.nss-va.cloud-feeds:siem-rate] Max Batch Size has no unit, default or range, and the SIEM Type list is not given [gap:cloud-connector.nss-va.cloud-feeds:batch-size].

**Output.** On the Session, DNS, Event and Metrics feed pages the Feed Output Type is JSON by default, with Name-Value Pairs or Tab-separated as alternatives if the SIEM accepts them; on the Session page, with JSON, JSON Array Notation is enabled by default and lets the NSS stream a batch of logs as a JSON array. [cloud-connector.nss-va.cloud-feeds:output] On the Session feed page an optional Feed Escape Character is hex encoded when it appears in a URL, hostname or referrer URL, and the eedone field is YES for a record created using custom encoding; the Time Zone is the organization's by default, and direct GMT offsets can also be specified. [cloud-connector.nss-va.cloud-feeds:escape-and-timezone] The defaults of the DNS feed page, whose default NSS type is "NSS for Firewall, Cloud and Branch Connector", are in [NSS feeds for Cloud & Branch Connector: limits, output and SIEM destination](kb:cloud-connector.nss-va.feeds). A Cloud NSS feed treats HTTP 200 or 204 from the SIEM as a successful upload and 400 as a parsing error that drops the batch; on any other HTTP code it repeatedly attempts to upload the same batch until it receives a 200, 204 or 400 response, up to one hour, after which the batch is dropped. [cloud-connector.nss-va.cloud-feeds:retry-on-http-codes] What the Cloud pages omit, including behaviour while the SIEM is unreachable, is open [gap:cloud-connector.nss-va.cloud-feeds:vm-feed-differences].

**Session feeds.** A Session Cloud NSS feed records Full Session Logs (all sessions of the rule individually, except HTTP/HTTPS), Aggregate Logs (sessions grouped by user, rule, network service and network application, recorded periodically within a 15-minute time window) or both. [cloud-connector.nss-va.cloud-feeds:session-log-type] A Session Cloud NSS feed filters by policy action and rule name (in accordance with the traffic forwarding rules), by locations (with no limit on how many), by Cloud or Branch Connector and their groups, by client IP addresses (worded as client destination IP addresses, and for an aggregate that of the last session), by network services and by gateway. [cloud-connector.nss-va.cloud-feeds:session-filters] The Client IP filter is worded differently from the VM feed page [gap:cloud-connector.nss-va.cloud-feeds:client-ip-wording].

**DNS, Event and Metrics feeds.** A DNS Cloud NSS feed filters by policy action (Allow, Block for requests and responses the service dropped, Redirect to ZPA), DNS Filtering rule name, locations and sublocations, client IP and server IP addresses, domains, server ports (individual ports and ranges), DNS request types, DNS response types and session duration in seconds. [cloud-connector.nss-va.cloud-feeds:dns-filters] An Event Cloud NSS feed filters by locations and sublocations, Cloud or Branch Connector groups and Cloud or Branch Connector VMs; the Metrics feed page has the same three filters. [cloud-connector.nss-va.cloud-feeds:event-filters] A Metrics Cloud NSS feed selects record types VM, Instance and/or Resource: VM is metrics at the virtual machine level, Instance at an individual data processing instance level, and Resource at an individual resource level. [cloud-connector.nss-va.cloud-feeds:metrics-record-type]

**Open.** How many Cloud NSS feeds per log type are allowed is not stated [gap:cloud-connector.nss-va.cloud-feeds:feed-count]. Three captures once listed here as Cloud NSS pages are cited instead in [NSS feeds for Cloud & Branch Connector: limits, output and SIEM destination](kb:cloud-connector.nss-va.feeds) [gap:cloud-connector.nss-va.cloud-feeds:uncited-captures].
