# The Cloud Connector (ZTW) API from a client's side: hosts, sign-in, limits, coverage and wire notes (cloud-connector.api)
Also called: cloud connector api; ztw api; cbc api; cloud and branch connector api; how to automate cloud connector; ztc api; cloud connector api divergences

Endpoint lists, HTTP methods, request and response fields, Go and Python SDK functions and ZTC Terraform resources are generated from the captured contract, the SDKs and the provider: run `node scripts/kb.mjs surface ztw` and read `vendor/zscaler-api-specs/automate-zscaler/openapi/zcloudconnector.openapi.json`. This subject family holds only the behavior around them and the places where those sources disagree.

**Calling the API.** Hosts and signing in, on the OneAPI gateway or the legacy connector host, are in [Reaching and signing in to the Cloud Connector API: OneAPI, legacy ZTC credentials and government clouds](kb:cloud-connector.api.authentication). Limits and how the clients back off and retry are in [Cloud Connector API rate limits and how the Go and Python clients back off and retry](kb:cloud-connector.api.rate-limits). The base path, the contract's default responses, paging and decoding are in [Conventions of the Cloud Connector API capture: base path, default responses, paging and decoding](kb:cloud-connector.api.conventions). Which client covers what is in [Which clients cover which parts of the Cloud Connector API: Python v1 and v2, Go, Terraform](kb:cloud-connector.api.client-coverage).

**Wire notes by area.** Activation: [Cloud Connector activation on the wire: activate, forced activate, and what the clients send](kb:cloud-connector.api.activation-wire). Cloud Connector groups and upgrades: [Cloud Connector group endpoints on the wire: release channels, VM status and upgrade scheduling](kb:cloud-connector.api.ec-groups-wire). Provisioning URLs: [Cloud Connector provisioning URLs on the wire: what the template sets, VM size and cloud provider fields](kb:cloud-connector.api.provisioning-wire). Partner integrations (cloud accounts): [Cloud Connector partner integration endpoints: AWS accounts in the contract, Azure and GCP outside it](kb:cloud-connector.api.partner-integrations-wire). Forwarding and DNS rules: [Cloud Connector rule endpoints on the wire: which forwarding and DNS rule fields each client sends](kb:cloud-connector.api.rules-wire). Forwarding and DNS gateways: [Cloud Connector forwarding and DNS gateways on the wire: two DNS gateway models, type and subcloud fields](kb:cloud-connector.api.gateways-wire). Locations: [Cloud Connector locations on the wire: the profile values and what Terraform can manage](kb:cloud-connector.api.locations-wire).

**Clients.** Go SDK service defects are in [Cloud Connector (ztw) Go SDK service functions with wrong assertions, nil payloads, or routing defects](kb:cloud-connector.sdk-go.service-defects) and its coverage in [What the Go SDK's ZTW packages leave out: commented-out functions, uncovered endpoints and activation](kb:cloud-connector.sdk-go.coverage); the Python SDK's coverage and client settings are in [What the Python SDK's ZTW modules cover beyond the Go SDK, and where they stop](kb:cloud-connector.sdk-python.coverage) and [The Python SDK against Cloud and Branch Connector: legacy client settings and session logout on exit](kb:cloud-connector.sdk-python.client-configuration). The ZTC provider's configuration and field handling are in [ZTC Terraform provider configuration: OneAPI or legacy credentials, environment variables, defaults and government clouds](kb:cloud-connector.terraform.provider-config) and [ZTC Terraform provider: configuration, field handling and read behavior](kb:cloud-connector.terraform.provider-behavior), with rule order, delete handling and predefined-rule protection in [How the ZTC (Cloud Connector) Terraform provider applies rule order](kb:cloud-connector.terraform.rule-order), [How the ZTC Terraform provider detaches references before deleting objects](kb:cloud-connector.terraform.delete-detach) and [Whether the ZTC Terraform provider protects predefined traffic rules](kb:cloud-connector.terraform.rule-protection). Behavior shared by all Go products is in [How the Go SDK builds requests and interprets responses: client options, bodies, status codes, bulk deletes](kb:shared.sdk-go.request-handling), [How the Go SDK retries requests (and replays writes)](kb:shared.sdk-go.retries), [How the Go SDK pages through ZPA, ZCC and ZTC lists, and when it stops early](kb:shared.sdk-go.list-pagination) and [Why Terraform cannot clear some fields: omitted zero values and empty objects in SDK writes](kb:shared.sdk-go.zero-value-writes).
