# AWS Zero Trust Gateway: adding one, allowed accounts, endpoint service name, zone status, configuration, analytics, events and traffic simulation (cloud-connector.aws-ztg)
Also called: aws zero trust gateway; aws ztg; aws gateway zero trust cloud; zero trust gateway endpoint service name; zero trust gateway traffic simulation aws; aws gateway allowed accounts

AWS gateways are in Limited Availability and are enabled by contacting Zscaler Support; they are added at Zero Trust Cloud > Zero Trust Gateway > AWS. [cloud-connector.aws-ztg:limited-availability] What an AWS gateway is, and how it differs from a Cloud Connector VM, is in [Zero Trust Gateways versus Cloud Connectors: who runs what, and where it is available](kb:cloud-connector.overview.zero-trust-gateways); the Zscaler-side registration of an endpoint is [After an AWS Zero Trust Gateway is added, traffic is routed to it by creating a VPC endpoint of type "Endpoint services that use NLBs and GWLBs" from the gateway's Endpoint Service Name, in a chosen VPC and availability zone, and then pointing route-table entries at that Gateway Load Balancer endpoint.](kb:cloud-connector.overview.zero-trust-gateways:aws-endpoint-registration).

**Adding one.** An AWS gateway can be deployed in only one region, which cannot be modified after the gateway is created, and at least two availability zones must be selected. [cloud-connector.aws-ztg:one-region] The gateway's location is created from a selected location template; its location object is created and synced between Cloud Connector and Internet & SaaS policy pages, and its name is visible in all policies where the location object is available. [cloud-connector.aws-ztg:location]

**Allowed accounts.** The Zscaler service denies endpoint connection requests from AWS accounts not present in the gateway's allowed accounts list; if no AWS account is configured while adding the gateway, the gateway must be edited later before connecting endpoints. [cloud-connector.aws-ztg:allowed-accounts] Allowed accounts and account groups are those onboarded earlier on the Partner Integrations page, and AWS accounts not onboarded there are entered as 12-digit account IDs, up to 128; for each of Allowed Accounts, Allowed Accounts Groups and Additional AWS Accounts the page says the gateway accepts requests originated by endpoints from the same region as the gateway. [cloud-connector.aws-ztg:account-sources]

**Details page.** The gateway details page shows the Endpoint Service Name (the AWS endpoint service hosted by the Zscaler service, needed to create an endpoint in the customer's AWS account), the Zero Trust Gateway ID (the Zscaler internal ID) and the manually added accounts permitted to connect. [cloud-connector.aws-ztg:endpoint-service-name]

**Operating one.** The Status tab reports for each availability zone the gateway's ability to reach Internet & SaaS (Internet), to forward direct traffic (Local Egress) and to reach Private Access (Private Applications), refreshed when the page is refreshed; Healthy means the backend traffic in the zone is functioning as expected, Unhealthy that traffic is dropped because no healthy backend is processing, and Degraded that traffic might have lost redundancy but is still forwarded. [cloud-connector.aws-ztg:zone-status] The Endpoints tab lists each endpoint connected to the gateway and allowed to send it traffic, with the time the gateway accepted it; the VPC column, and a namespace based on the VPC tag with key zs:namespace, are only available if the workload discovery service and partner integrations are enabled, and the VPC endpoint's account ID must be onboarded to the partner integration. [cloud-connector.aws-ztg:endpoints] The gateway can reject a configuration that is activated if it makes the gateway unable to function properly; on the Config tab each version's status is Active or Inactive, a latest version that is not active might have been rejected, and two versions can be compared with Compare Versions. [cloud-connector.aws-ztg:config-rejection] The Analytics tab displays values from CloudWatch for the gateway's gateway load balancer (GWLB) by Timeframe, Stat and Type: Processed Bytes (traffic to and from the destination, not health checks), Active Connection (concurrent client-to-destination connections) and Reset Count (the page's wording: TCP counts the GWLB sends when no backend processing is available). [cloud-connector.aws-ztg:analytics] The Events tab lists events (for example Accepted connection for VPC Endpoint or Removed connector for VPC Endpoint) with a category such as VpcEndpoint. [cloud-connector.aws-ztg:events] Traffic simulation sets up a virtual environment in the Zscaler AWS account that is created after approximately 5 minutes and lasts one hour (Renew adds one more hour); the test runs once the environment is in the CREATE_COMPLETE state with HTTP or HTTPS as protocol and optional Verbose (-v) and Insecure (-k) curl options, the result appears as AWS curl output, and a test created in one gateway is available in all AWS gateways created in that Cloud Connector account in all regions. [cloud-connector.aws-ztg:traffic-simulation]

**Compared with GCP.** The GCP gateway's operations page uses the same zone-status model, configuration-rejection rule and traffic-simulation lifecycle: [Operating a GCP Zero Trust Gateway: health states, configuration rejection, traffic tests](kb:cloud-connector.gcp-ztg.operations). Whether the two clouds share one operating contract is partly open in [Whether AWS and GCP Zero Trust Gateways share one operating contract](kb:cloud-connector.overview.zero-trust-gateways:aws-gcp-parity).

What to check:
1. Whether Zscaler Support has enabled AWS gateways for the tenant, since they are Limited Availability.
2. Whether the endpoint's AWS account is in the gateway's allowed accounts and the endpoint is in the gateway's region, since requests from other accounts are denied.
3. Whether the gateway rejected the latest activated Internet & SaaS configuration, using the Config tab's version status.
4. The per-zone Status tab for Internet, Local Egress and Private Applications reachability before concluding where traffic is dropped.
5. Whether a traffic simulation environment exists (it lasts one hour) and is in CREATE_COMPLETE before running a test.
