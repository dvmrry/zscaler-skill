# Namespaces and the zs:namespace VPC tag: overlapping IPs in workload discovery (cloud-connector.workload-discovery.namespaces)
Also called: zs:namespace; duplicate ip workload discovery; No of Duplicates IP; overlapping cidr tags cloud connector; default namespace; tag-based policy wrong workload overlapping ip

The Zscaler service maps user-defined tags and cloud-provider attributes to the workload IP address, and the mapping is decentralized at the Cloud Connector level. With no overlapping CIDR blocks, Cloud Connector maps an IP address to a set of tags; with overlapping blocks the maps are divided into subsets in which every CIDR block is unique to the namespace. [cloud-connector.workload-discovery.namespaces:mapping-decentralized] In AWS a namespace is a set of VPC endpoints; the VPCs in a namespace should not have overlapping IP addresses, and the namespace is an additional data point to tell identical source IP addresses apart when egress traffic reaches Cloud Connector. [cloud-connector.workload-discovery.namespaces:namespace-definition]

**Assigning a namespace.** To group VPCs or accounts in a namespace, each VPC gets the same namespace VPC tag: key `zs:namespace`, value a string the operator chooses. [cloud-connector.workload-discovery.namespaces:vpc-tag] The discovery service finds the `zs:namespace` tag through standard tag discovery and assigns all workloads in that VPC to the namespace; it also discovers any Gateway Load Balancer endpoints in that VPC and assigns them to the namespace, building a table of endpoint to namespace. No configuration in the Admin Console is needed for this. [cloud-connector.workload-discovery.namespaces:discovery-assigns] Without a detected user-defined namespace, all workloads belong to the default namespace; the configuration help adds that workloads are created in the default namespace if no GWLB exists or no namespace is defined, unless the VPC carries `zs:namespace`. [cloud-connector.workload-discovery.namespaces:default-namespace]

**Duplicates.** When Zscaler detects a duplicate IP address, only one is shown and all others are disregarded; the region view's No of Duplicates IP counts them, and the help says to resolve duplicates in a region with namespaces. [cloud-connector.workload-discovery.namespaces:duplicate-ip-one-shown] Which of the duplicates is kept is not stated [gap:cloud-connector.workload-discovery.namespaces:which-duplicate-kept]. Two overlapping VPCs that both lack the tag fall into the default namespace together, so the shared address appears twice in one namespace and all but one entry is disregarded. If only one of them is tagged, the two sit in different namespaces. [cloud-connector.workload-discovery.namespaces:untagged-overlap] Giving two overlapping VPCs the same namespace value puts duplicate addresses inside one namespace, which the namespace definition rules out, so the duplicates are not resolved. [cloud-connector.workload-discovery.namespaces:shared-namespace-overlap]

**The documented example.** In the documented example two overlapping VPCs in different accounts are tagged `zs:namespace=project-green` and `zs:namespace=project-blue`; discovery maps VPC endpoints to namespaces, and the same IP address 172.31.0.1 gets a separate tag list per namespace, indexed by address plus namespace. [cloud-connector.workload-discovery.namespaces:example-mapping] The example's two tables disagree: the endpoint table puts vpce-111 in project-blue and vpce-444 in project-green, while the address table indexes vpce-111's entry under project-green and vpce-444's under project-blue. [cloud-connector.workload-discovery.namespaces:example-inconsistent]

**Where the tag must sit.** The sources describe only the VPC tag; the effect of the same tag on an instance or other resource is unknown [gap:cloud-connector.workload-discovery.namespaces:non-vpc-tag]. Namespace sublocation scopes, which group traffic by namespace for policy, are in [AWS workload sublocation scopes (VPC endpoint, VPC, account, namespace)](kb:zia.locations.workload-scopes).

What to check:
1. Whether No of Duplicates IP is non-zero in the account's region view.
2. Whether every VPC whose CIDRs overlap another's carries a `zs:namespace` tag, with different values for VPCs that overlap.
3. Whether the VPC holds the GWLB endpoint the traffic uses, since discovery assigns that endpoint to the VPC's namespace.
