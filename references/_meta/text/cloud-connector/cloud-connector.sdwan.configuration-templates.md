# Branch Connector configuration templates: VM and hardware settings, HA, WAN uplinks, LAN, DHCP and static routes (cloud-connector.sdwan.configuration-templates)
Also called: branch configuration template; branch connector provisioning template; VM provisioning; device provisioning; branch connector group template

A Branch Connector configuration template is required for both virtual machines and hardware devices; for a virtual device the administrator provides the configuration URL to the virtual device, and for a physical device the Zero Touch Provisioning process retrieves the configuration URL. [cloud-connector.sdwan.configuration-templates:required-for-both] Branch configuration templates are editable before and after provisioning and deployment, and the branch configuration URL is copied with the arrow in the Template Name field. [cloud-connector.sdwan.configuration-templates:editable-anytime]

**Template list.** Templates for virtual devices are on Infrastructure > Branch Connector > VM Provisioning and for physical devices on Infrastructure > Branch Connector > Device Provisioning; the list shows Branch Type (the hypervisor host Red Hat Linux, VMware ESXi or Microsoft Hyper-V, or the hardware device ZT400, ZT600 or ZT800), the hardware device's serial number, Status (Staged, Not Deployed or Deployed) and VM Size, which applies only to VMs. [cloud-connector.sdwan.configuration-templates:pages-and-columns] The status vocabulary differs from the one on the zero touch provisioning page [divergence:cloud-connector.sdwan.configuration-templates:template-status-values]. The template list's Gateway column shows whether a hardware device was deployed as a gateway (Yes or No), and gateway mode is only supported on hardware devices; a hardware template selects Yes at Deploy as Gateway to deploy the device in gateway mode. [cloud-connector.sdwan.configuration-templates:gateway-hardware-only] Modes and zero touch provisioning are in [Zero Trust SD-WAN devices: gateway and one-arm modes, zero touch provisioning](kb:cloud-connector.sdwan.device-modes).

**Location and group.** A template's Location tab selects an Existing or New location; the location is created in Internet & SaaS and can be used as a policy parameter in Internet & SaaS, Private Access and the Zscaler Admin Console. [cloud-connector.sdwan.configuration-templates:location-in-zia] Branch Connector groups apply policies to a group of deployed Branch Connectors, upgrade the members to maintain redundancy while upgrades are being executed, and share Private Access synthetic IP address resolutions among the group members. [cloud-connector.sdwan.configuration-templates:group-purpose] For Branch Connectors to function in high availability, each Branch Connector is configured with a separate configuration template with the same Location Name and Branch Connector Group Name. [cloud-connector.sdwan.configuration-templates:ha-separate-templates]

**Virtual machine templates.** When a New Branch Connector group is selected on a hypervisor template, its Branch Connector VM Size is Small or Medium; selecting Medium automatically enables High Availability Deployment, which cannot then be disabled, and a Medium VM requires Manual settings in the Forwarding Interface field to enable high availability. [cloud-connector.sdwan.configuration-templates:vm-size] When High Availability Deployment is enabled, two Branch Connectors share a virtual IP address on their forwarding interfaces in active or standby mode; traffic sent to the shared virtual IP address reaches the active Branch Connector and, if the primary stops responding, fails over automatically to the second. For both to access the same default gateway, the virtual IP address must be on the same broadcast domain as the forwarding interface. [cloud-connector.sdwan.configuration-templates:vm-ha-vip] When Manual is selected on a hypervisor template's Branch Connector Details tab, the forwarding interface takes, when High Availability Deployment is disabled, an outgoing gateway IP address and a primary service IP address; when it is enabled, a secondary service IP address and a load balancer IP address; and a virtual IP address that the two Branch Connectors in a high availability pair share. [cloud-connector.sdwan.configuration-templates:vm-forwarding-interface] On a hypervisor template's App Connector tab an App Connector group name and a provisioning key name are selected; the App Connector Interface is automatically set to Manual, and the tab takes the App Connector's IP address and default gateway IP address. [cloud-connector.sdwan.configuration-templates:app-connector-tab] The hypervisor-side requirements for the high availability pair are in [For Branch Connector deployed in high availability on VMware, the Promiscuous mode option must be enabled (set to Accept) on the vSwitch or at the port group level, and the MAC address changes and Forged transmits options must be enabled on the vSwitch or port group. Branch Connector uses the Common Address Redundancy Protocol (CARP) to process traffic across multiple Branch Connector instances; when promiscuous mode is enabled other VMs might be able to detect traffic going through the service interface, and Zscaler recommends a port group for the Branch Connector service interfaces. If multiple physical ports exist on the same vSwitch, the Net.ReversePathFwdCheckPromisc advanced option must be enabled (set to 1) on the ESXi host, or multicast traffic loops back to the host and CARP does not function properly.](kb:cloud-connector.sdwan.virtual-deployment:esxi-ha-vswitch).

**Hardware templates.** On a hardware template the serial number drop-down shows only devices associated with the organization and for the specified platform type; the management interface provides out-of-band access and is enabled by default, receives its IP address by DHCP by default, and defaults to 192.168.1.1/24 if the DHCP client is enabled and receives no DHCP offer. [cloud-connector.sdwan.configuration-templates:hw-mgmt-interface] The per-model management port is in [The Branch Connector details help names the hardware models ZT400, ZT600 and ZT800 (the management interface is fixed by the model: GE1 for ZT400 and ZT600, GE3 for ZT800), and the API contract's `modelType` enumerates `ZT600`, `ZT800` and `ZT400` for a connector VM's hardware information.](kb:cloud-connector.sdwan.device-modes:hardware-model-names).

**WAN interfaces.** At least one interface or subinterface must be assigned to the WAN interface and a second is optional; the parent interface MTU defaults to 1,500 bytes; WAN interfaces receive IP addresses via DHCP by default, where the DNS server fields are optional and override any DNS received via DHCP, and with DHCP disabled they are required. [cloud-connector.sdwan.configuration-templates:wan-interfaces] At least one WAN interface must be Active and only two WAN interfaces can be configured. With one Active and one Standby interface, data traffic goes over the active links and failover is triggered when probes detect a 100 percent loss on the current active link; Zscaler also sends probes on the standby link and maintains tunnels to Internet & SaaS and Private Access on it for fast switchover. With both Active, Zscaler actively monitors the health of the links and determines the best link, and for specific applications the device-wide traffic distribution method can optionally be overridden using traffic forwarding rules. [cloud-connector.sdwan.configuration-templates:uplink-mode] In the WAN section up to 10 tagged VLAN interfaces can be added per parent interface, with a VLAN ID from 1 to 4094 (the 802.1q tag for the network); the subinterface MTU is 1496 by default and must be 4 bytes less than the MTU of the parent interface. [cloud-connector.sdwan.configuration-templates:subinterfaces] Traffic Distribution is Balanced or Best Link; Balanced is the default and distributes traffic across all WAN links using a flow-based distribution algorithm, and Best Link uses a link determined using probes that measure loss, latency and jitter. The setting is only applicable when there is more than one WAN interface and/or subinterface and both are set to active and operational, and any WAN link selected via traffic forwarding rules takes precedence for the matching traffic over this catch-all device-level setting. [cloud-connector.sdwan.configuration-templates:traffic-distribution] How WAN selection is applied by forwarding rules is in [WAN Selection is None by default, which follows the Traffic Distribution setting of the branch configuration template; Balanced distributes traffic evenly and Best Link always uses the best-performing WAN link. It applies only to hardware devices deployed in gateway mode.](kb:cloud-connector.forwarding.methods:wan-selection).

**LAN interfaces.** A Zero Trust Branch Device deployed in gateway mode must have at least one interface assigned to a LAN; shutting down a LAN interface brings down the physical port and all of its subinterfaces, while shutting down a subinterface does not affect the parent interface or any other subinterface; the LAN parent interface MTU defaults to 1500 bytes. [cloud-connector.sdwan.configuration-templates:lan-interfaces] HA on a LAN interface takes the ID configured on the HA pair device, a virtual IP address belonging to the same network as the interface, and the same passphrase as the pair device; Preferred is No by default, and setting it to Yes on more than one device in an HA pair can cause unreliable behavior. [cloud-connector.sdwan.configuration-templates:lan-ha] The LAN DHCP server is disabled by default; if HA is enabled, the ranges on the two devices in an HA pair must match. The default lease time is 86400 seconds, the default maximum lease time is 604800 seconds and the maximum permissible value is 3155673600 seconds; an option configurable when HA is enabled synchronizes the DHCP leases. [cloud-connector.sdwan.configuration-templates:lan-dhcp-defaults] LAN DHCP options accept up to 4 DNS server IP addresses and up to 4 domain names, each separated by commas; a custom option has a Code from 1 to 255, a string value for which Zscaler only supports spaces and commas as delimiters with a maximum length of 256, or one to four IP addresses. A DHCP server takes a maximum of 32 static leases, and in HA each static lease must be entered twice. [cloud-connector.sdwan.configuration-templates:lan-dhcp-options] A custom DHCP option's Code field takes a number between 1 and 255, and the page links a list of supported DHCP options whose entries include, for example, 1 subnet-mask, 42 ntp-servers, 66 tftp-server-name, 150 tftp-server-address and 213 v4-access-domain. [cloud-connector.sdwan.configuration-templates:dhcp-option-codes] For LAN DNS, selecting Yes at Use WAN DNS Server uses the DNS server from the WAN interfaces as the DNS server for LAN; the App Connector uses the LAN DNS servers to resolve the original IP of an application at the branch, and the LAN DNS servers can also be referenced in the DNS gateway object, which is then used in DNS policies. [cloud-connector.sdwan.configuration-templates:lan-dns] See also [The primary and secondary DNS server are each chosen as a Custom DNS Server (an IP address, IPv4 only), the LAN Primary DNS Server, or the LAN Secondary DNS Server; the LAN choices reference DNS servers in the gateway-mode Branch Connector Configuration Template.](kb:cloud-connector.dns.gateways:server-choices).

**Routes and one-arm mode.** In the hardware template branch for a device deployed in gateway mode (Deploy as Gateway set to Yes), a maximum of 32 static routes are permitted and the default static route cannot be configured; the next hop of a static route is resolvable over one of the connected LAN interfaces and/or subinterfaces. [cloud-connector.sdwan.configuration-templates:static-routes] In non-gateway mode deployments another router forwards traffic to the Zero Trust Branch Device; the template's HA Deployment Status is set to Active-Standby by default, and a Virtual IP Address is entered. [cloud-connector.sdwan.configuration-templates:one-arm-template] Whether the device runs dynamic routing is tracked in [Whether a gateway-mode device runs dynamic routing protocols](kb:cloud-connector.sdwan.device-modes:routing-protocols).

**The April 10, 2023 cutover.** The ZPA console's About Branch Connectors page says all existing Branch Connectors appear as Cloud Connectors in the Admin Console after April 10, 2023, and that a new Branch Connector must be configured to be visible on the Branch Connector and Branch Connector Groups pages. Provisioning templates created before April 10, 2023 are no longer valid and must not be used; new provisioning templates must be used to properly provision a Branch Connector. [cloud-connector.sdwan.configuration-templates:april-2023-cutover] What became of the earlier Branch Connectors is not stated [gap:cloud-connector.sdwan.configuration-templates:pre-2023-branch-connectors].

**Not stated.** The memory, cores and NICs per size are in [On the VMware, Linux KVM and Hyper-V pages a Branch Connector VM requires, for Small, 4 GB of memory, 2 CPU cores, a 128 GB data disk and 2 NICs, and for Medium 8 GB of memory, 4 CPU cores, a 128 GB data disk and 4 NICs; the Hyper-V procedure enters 4096 for a Small VM or 8192 for a Medium VM, 2 or 4 virtual processors, and a total of two network adapters for Small or 4 for Medium.](kb:cloud-connector.sdwan.virtual-deployment:sizing-branch-connector); the throughput of each size, and failover timing for VM, LAN and WAN uplink failover, are not stated [gap:cloud-connector.sdwan.configuration-templates:capacity-and-timing]. Whether the LAN subinterface DHCP server is also disabled by default, and the HA ID range, are not stated [gap:cloud-connector.sdwan.configuration-templates:lan-details].

What to check:
1. Whether the template for a VM or hardware device is the one the device was given, since the configuration URL comes from the template.
2. For a pair of Branch Connectors in high availability, that each has its own template with the same Location Name and Branch Connector Group Name.
3. Which status vocabulary the console shows for a template before looking for a Ready to Deploy value.

Sources disagree (name both sides):
- The Understanding Zero Trust Branch Devices page moves a template from Staged to Ready to Deploy; the Branch Configuration Templates list gives the statuses Staged, Not Deployed and Deployed. [divergence:cloud-connector.sdwan.configuration-templates:template-status-values]
  - zscaler-help: The template status changes from Staged to Ready to Deploy.
  - zscaler-help: The statuses are Staged, Not Deployed or Deployed, with no Ready to Deploy.
  Impact: An operator looking for Ready to Deploy in the template list may not find it; neither page maps the two vocabularies.
