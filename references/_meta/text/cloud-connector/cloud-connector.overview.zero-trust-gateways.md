# Zero Trust Gateways versus Cloud Connectors: who runs what, and where it is available (cloud-connector.overview.zero-trust-gateways)
Also called: zero trust gateway; ztg; aws zero trust gateway; gcp zero trust gateway; azure zero trust gateway; is a zero trust gateway a cloud connector; managed cloud connector

A Zero Trust Gateway is a separate deployment type from the Cloud Connector VM that the rest of this area describes.

- **AWS.** AWS Zero Trust Gateways are a Zscaler cloud-native service offering in public clouds; they are in Limited Availability and are enabled by contacting Zscaler Support. [cloud-connector.overview.zero-trust-gateways:aws-managed] After an AWS Zero Trust Gateway is added, traffic is routed to it by creating a VPC endpoint of type "Endpoint services that use NLBs and GWLBs" from the gateway's Endpoint Service Name, in a chosen VPC and availability zone, and then pointing route-table entries at that Gateway Load Balancer endpoint. [cloud-connector.overview.zero-trust-gateways:aws-endpoint-registration] Adding one and operating it: [AWS Zero Trust Gateway: adding one, allowed accounts, endpoint service name, zone status, configuration, analytics, events and traffic simulation](kb:cloud-connector.aws-ztg).
- **GCP.** GCP Zero Trust Gateways are a Zscaler cloud-native service offering in public clouds that is supported in GCP. [cloud-connector.overview.zero-trust-gateways:gcp-managed] It is likewise Limited Availability: [GCP gateways are in Limited Availability, and Zscaler Support enables the feature.](kb:cloud-connector.gcp-ztg:limited-availability). Creating and operating one: [GCP Zero Trust Gateway: managed service boundary and restrictions](kb:cloud-connector.gcp-ztg).
- **Azure.** The captured Cloud & Branch Connector help has Zero Trust Gateway articles for AWS and GCP and none for Azure, and the supported-regions article lists only AWS and GCP regions. [cloud-connector.overview.zero-trust-gateways:no-azure-article] Whether an Azure Zero Trust Gateway can be created is open [gap:cloud-connector.overview.zero-trust-gateways:azure-availability].

Both the AWS and GCP gateway pages describe securing workloads through the Zscaler Zero Trust Cloud as a SaaS offering without managing security infrastructure, removing the need to deploy NAT gateways, security infrastructure, load balancers and VMs. [cloud-connector.overview.zero-trust-gateways:no-infrastructure] An AWS gateway's operational status is Enabled or Disabled, but AWS gateways cannot be disabled. [cloud-connector.overview.zero-trust-gateways:aws-cannot-disable] The two clouds' pages share the service description but do not establish the same IAM, endpoint, interception, control or API contract [gap:cloud-connector.overview.zero-trust-gateways:aws-gcp-parity].

**Shared service.** The Zero Trust Gateway service shares Cloud Connector features and benefits, is delivered as a SaaS service in AWS and GCP, and lets traffic forwarded to it egress to the internet and/or Zscaler cloud from the Zscaler AWS or GCP account. [cloud-connector.overview.zero-trust-gateways:shares-cc-features] The page describes Layer 4 security controls for east-west traffic (subnet-to-subnet and VPC-to-VPC) in the AWS cloud, Layer 4 controls to secure ingress traffic for public applications hosted in AWS, and tag-based policies for Layer 4 controls. [cloud-connector.overview.zero-trust-gateways:l4-aws]

**Gateway page.** The Zero Trust Gateway page filters gateways by AWS Regions and GCP (the filter defaults to Any, meaning no filter), an Entitlement Status chart shows the number of availability zones in which gateway instances can be deployed with Total Entitled the number licensed, and a Health Status chart shows the health of deployed gateways. [cloud-connector.overview.zero-trust-gateways:gateway-dashboard] In the page's example of two regions, each with three availability zones and two gateways, the number of deployed entitlements is 6. [cloud-connector.overview.zero-trust-gateways:entitlement-example] Clicking a gateway in the Geo View shows its Deployment Type, Name, Region, Location, Endpoints and Service Status, and the reason is displayed if the gateway is inactive. [cloud-connector.overview.zero-trust-gateways:geo-view] The monitoring table gives the gateway's cloud provider type (AWS and GCP are supported), service status (Healthy, Unhealthy or Not Available) and the numbers of availability zones and endpoints associated with it. [cloud-connector.overview.zero-trust-gateways:monitoring-table]

**Tunnel mode.** When editing a Zero Trust Gateway group, the admin selects Unencrypted UDP or DTLS under ZIA Tunnel Mode. [cloud-connector.overview.zero-trust-gateways:tunnel-mode]

Both types appear in the Cloud Connector groups list, distinguished by group type: [The groups list distinguishes two group types, Cloud Connector and Zero Trust Gateway, and can be filtered by cloud (AWS, Azure, GCP) and by whether autoscaling is on.](kb:cloud-connector.overview.groups:group-types). The Local forwarding method is available to both: [The Local forwarding method is available only for Cloud Connector and Zero Trust Gateways, not for Branch Connector.](kb:cloud-connector.forwarding.methods:local-availability). Regions where gateways are offered: [Regions where Zero Trust Gateways are supported (AWS and GCP)](kb:cloud-connector.regions.zero-trust-gateways).

What to check:
1. Whether the deployment in question is a customer-deployed Cloud Connector VM or a Zscaler-managed Zero Trust Gateway (group type), before applying VM lifecycle, scaling or health-probe answers.
2. Whether Zscaler Support has enabled Zero Trust Gateways for the tenant (Limited Availability).
