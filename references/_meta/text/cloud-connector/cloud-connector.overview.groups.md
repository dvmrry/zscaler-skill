# Cloud Connector groups: what they are for, autoscaling names, status and disabling (cloud-connector.overview.groups)
Also called: cloud connector group; edge connector group; ec group; auto scaling group cloud connector; vmss cloud connector; managed instance group cloud connector; disable cloud connector; cloud connector operational status

Cloud Connector groups are created automatically when a Cloud Connector is deployed in AWS, Azure, or GCP. [cloud-connector.overview.groups:auto-created] Groups let you apply policies to a set of deployed Cloud Connectors and upgrade the Cloud Connectors in a group while keeping redundancy during the upgrade. [cloud-connector.overview.groups:group-purpose] A forwarding rule can be scoped to groups: [Cloud Connector forwarding rule criteria: scope, services, sources, destinations, FQDNs](kb:cloud-connector.forwarding.criteria).

**Autoscaling.** Autoscaling is called Auto Scaling in the AWS Marketplace, Virtual Machine Scale Sets (VMSS) in the Azure Marketplace, and a Managed Instance Group (MIG) with autoscaling in the Google Cloud Marketplace; the Admin Console's "autoscaling" covers all three, and enabling any of them requires contacting Zscaler Support. [cloud-connector.overview.groups:autoscaling-names] Deploy an autoscaling group only with an autoscaling (ASG) template, and a non-autoscaling deployment only with a non-ASG template. [cloud-connector.overview.groups:template-match]

**Group types.** The groups list distinguishes two group types, Cloud Connector and Zero Trust Gateway, and can be filtered by cloud (AWS, Azure, GCP) and by whether autoscaling is on. [cloud-connector.overview.groups:group-types] How a Zero Trust Gateway differs from a Cloud Connector: [Zero Trust Gateways versus Cloud Connectors: who runs what, and where it is available](kb:cloud-connector.overview.zero-trust-gateways).

**Cleanup and forced delete.** A group's edit window shows the number of Cloud Connectors belonging to the Cloud Connector group (No. of Connectors). [cloud-connector.overview.groups:group-info] Auto Cleanup Frequency selects how often Cloud Connector groups are automatically deleted (Never, 60 Days, 90 Days or 120 Days); Auto Cleanup is in Limited Availability and is enabled by contacting Zscaler Support. [cloud-connector.overview.groups:auto-cleanup] The Cleanup Activity page, in Limited Availability, shows inactive Cloud Connector groups scheduled for deletion, with a status of Scheduled, Delete failed or Deleted and who deleted the group (the user or system). [cloud-connector.overview.groups:cleanup-activity] What makes a group inactive for cleanup, what a deletion removes and the default of Forced Delete are not stated [gap:cloud-connector.overview.groups:cleanup-details]. The Forced Delete checkbox allows the deletion of Cloud Connectors even if they are used by Internet & SaaS or Private Access traffic forwarding policies; if the deleted connector was the only location the policy is bypassed, and if not the policy continues to apply to the remaining locations or Cloud Connector groups. [cloud-connector.overview.groups:forced-delete]

**Status, disable, delete.** A Cloud Connector's operational status is Active, Inactive, or Disabled. [cloud-connector.overview.groups:operational-status] An Inactive connector has lost contact with its management plane but still processes traffic: [A Cloud Connector is Inactive when it cannot contact its management plane; with a healthy data plane this has no service impact and the connector still processes data.](kb:cloud-connector.insights.connector-status:inactive-meaning). Disabling a Cloud Connector or a group stops traffic from processing; it does not delete the Cloud Connector. [cloud-connector.overview.groups:disable-not-delete] Deleting a Cloud Connector cannot be undone. [cloud-connector.overview.groups:delete-irreversible] Upgrades of the connectors in a group are staggered within a two-hour window: [All connectors in a Cloud Connector group or Branch Connector group are updated within a two-hour window, and their upgrades are staggered to prevent service impact.](kb:cloud-connector.upgrades:two-hour-staggered). Whether a disabled VM keeps running, and whether an autoscaling group maps one-to-one to a Cloud Connector group, is not stated [gap:cloud-connector.overview.groups:status-semantics].

What to check:
1. The group's operational status (Active, Inactive or Disabled) and whether it was disabled, which stops traffic processing.
2. Whether an autoscaling deployment used an autoscaling template, and a static one a non-autoscaling template.

- Effect of Disable on the VM, and autoscaling-group to Cloud Connector group mapping [gap:cloud-connector.overview.groups:status-semantics]: settled by source-read or lab-test. Blocks: interpreting an Inactive status and planning a staged disable
