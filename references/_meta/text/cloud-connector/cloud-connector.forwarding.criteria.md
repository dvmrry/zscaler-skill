# Cloud Connector forwarding rule criteria: scope, services, sources, destinations, FQDNs (cloud-connector.forwarding.criteria)
Also called: cloud connector forwarding criteria; cloud connector wildcard fqdn; cloud connector fqdn rule not matching; source workload groups; destination workload groups; application service groups; cloud connector dns required for fqdn; app connector looping; cloud connector network services; cloud connector network service groups

The rule form groups its criteria into General, Services, Applications, Source and Destination; which sections appear depends on the forwarding method. How criteria combine within and across fields is not stated [gap:cloud-connector.forwarding.criteria:combination-logic].

**General.** A rule can name up to 8 locations or sublocations; with none it applies to all locations. On the ZIA-method form, a rule uses either Location/Sublocation or Cloud & Branch Connector Groups, not both. [cloud-connector.forwarding.criteria:location-or-groups] A rule can name up to 32 Cloud or Branch Connector groups; with none it applies to all groups. [cloud-connector.forwarding.criteria:groups-32]

**Services and applications.** Any number of network services and predefined or custom network service groups can be selected; with none selected the rule applies to all. [cloud-connector.forwarding.criteria:services] Application Service Groups are predefined groups the Zscaler service provides; the form lists Office365, Zoom, Webex, RingCentral, LogMeIn, BlueJeans, Amazon Web Services, Azure, GCP, Zscaler Cloud Endpoints and Talk_Desk. [cloud-connector.forwarding.criteria:app-service-groups] Whether Zscaler updates the endpoints behind these groups under existing rules is not stated [gap:cloud-connector.forwarding.criteria:app-service-group-updates].

**Source.** Source IP Groups can be any number of source IP address groups or App Connector source IP addresses (none selected applies to all); Source IP Addresses take an individual address, a subnet, or a range. [cloud-connector.forwarding.criteria:source-ip] On the rule form, source workload groups can be referenced as a source for the Local, Direct, Internet & SaaS and Private Access methods, and apply only to Cloud Connector traffic forwarding policies. [cloud-connector.forwarding.criteria:source-workload-scope] Both workload-group criteria need workload discovery, and destination workload groups apply only to the Local method: [Cloud Connector traffic forwarding rules have separate Source Workload Groups and Destination Workload Groups criteria, both available only when the workload discovery service is enabled; destination workload groups apply only to Cloud Connector forwarding policies and only to the Local forwarding method.](kb:zia.workload-groups.rule-scoping:cloud-connector-source-dest). In the Private Access, Direct, Drop and Local procedures, the form advises preventing App Connector looping by excluding the IP addresses the App Connector uses to open connections, or including the IP addresses of all non-App Connector devices. [cloud-connector.forwarding.criteria:app-connector-looping] Workload groups themselves: [ZIA Workload Groups: scoping rules to cloud workloads](kb:zia.workload-groups).

**Destination.** Any number of destination IPv4 groups can be selected; with none selected the rule applies to all destination IP address groups. [cloud-connector.forwarding.criteria:dest-ipv4-groups] The IP Address Or WildCard FQDN field takes individual IPs, subnets, ranges, wildcard domains and FQDNs; the Connector cannot distinguish between multi-homed servers, the same destination IP host with more than one FQDN. [cloud-connector.forwarding.criteria:fqdn-entries] A wildcard domain is written with a leading asterisk, such as `*.example.com`; `*abc.example.com` and `abs.*.example.com` are invalid, and invalid items cannot be matched. [cloud-connector.forwarding.criteria:wildcard-syntax] Wildcard domains and FQDNs are limited to 16K per organization and 8,000 per rule. [cloud-connector.forwarding.criteria:fqdn-limit] For Private Access destinations, Apply to All App Segments covers all existing and future segments; otherwise any number of application segments and segment groups can be chosen, and with none chosen the rule applies to no segments. [cloud-connector.forwarding.criteria:zpa-destinations]

**DNS for FQDN matching.** Rules with wildcard domains or FQDNs need the workloads' DNS queries routed through the Cloud or Branch Connector; for HTTP/HTTPS traffic DNS is not required, but UDP and non-web traffic require it. [cloud-connector.forwarding.criteria:dns-required] The DNS features that receive those queries: [Cloud & Branch Connector DNS handling: DNS policies and DNS gateways](kb:cloud-connector.dns).

Criteria named in the legacy reference but absent from the captured form are listed in [gap:cloud-connector.forwarding.criteria:legacy-criteria].

What to check:
1. For a rule with wildcard domains or FQDNs that should match UDP or non-web traffic, whether the workloads' DNS queries route through the Cloud Connector.
2. Whether the wildcard entries are valid (`*.example.com`, not `*abc.example.com` or `abs.*.example.com`), since invalid entries never match.
3. For workload-group criteria, whether workload discovery is enabled for the tenant, and for destination workload groups whether the rule's method is Local.
4. For ZPA-method rules, whether App Connector source addresses are excluded to prevent looping.

Not known (open gaps):
- How forwarding rule criteria combine [gap:cloud-connector.forwarding.criteria:combination-logic]: settled by source-read or lab-test. Blocks: deciding whether a flow matches a rule with several criteria
- Whether rules pick up endpoint changes in Zscaler-maintained application service groups [gap:cloud-connector.forwarding.criteria:app-service-group-updates]: settled by source-read. Blocks: explaining a rule that starts matching new destinations without a change
- Criteria named by the legacy reference but not on the captured form [gap:cloud-connector.forwarding.criteria:legacy-criteria]: settled by source-read or tenant-data. Blocks: listing the full set of criteria a rule can use
