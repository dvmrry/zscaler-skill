# Cloud Connector on AWS: IAM for the instance, the autoscaling Lambda, and the deployer (cloud-connector.aws.iam)
Also called: cloud connector iam policy aws; cloud connector instance profile; cloud connector secretsmanager getsecretvalue; cloud connector putmetricdata; cloud connector ssm session manager iam; cloud connector cloud tags iam sns sqs; cloud connector deployment permissions aws

Three principals need AWS permissions: the Cloud Connector instance, the autoscaling Lambda, and the person or pipeline deploying. The instance and Lambda policies below are the reference Terraform module's.

**Cloud Connector instance profile.** The CloudFormation starter template creates an instance profile with an IAM role and policy permissions for Secrets Manager, Systems Manager and workload tags. [cloud-connector.aws.iam:cfn-instance-profile] The reference IAM module allows the instance secretsmanager:GetSecretValue on the provisioning secret only, looked up by name. [cloud-connector.aws.iam:cc-get-secret] It allows ssm:UpdateInstanceInformation and the ssmmessages Create/Open Control and Data Channel actions on all resources, for SSM Session Manager console access. [cloud-connector.aws.iam:cc-ssm] It allows cloudwatch:PutMetricData only with the condition cloudwatch:namespace equal to Zscaler/CloudConnectors, plus cloudwatch:GetMetricStatistics, cloudwatch:ListMetrics and ec2:DescribeTags on all resources. [cloud-connector.aws.iam:cc-metrics] Only when `asg_enabled` is true, it adds lifecycle describe actions on all resources and autoscaling:CompleteLifecycleAction and RecordLifecycleActionHeartbeat restricted to `asg_arns` when given, otherwise any resource. [cloud-connector.aws.iam:cc-lifecycle] Only when `cloud_tags_enabled` is true (default false), it adds sns:ListTopics, ListSubscriptions, Subscribe, Unsubscribe and sqs:CreateQueue, DeleteQueue on all resources, optionally narrowed by `iam_tags_condition`, for tag-change subscriptions. [cloud-connector.aws.iam:cc-tags] The Secrets Manager read requirement from Help is in [Cloud Connector on AWS: provisioning template, URL, Secrets Manager credentials, user data](kb:cloud-connector.aws.provisioning).

**Autoscaling Lambda.** The autoscaling Lambda's role may read the provisioning secret and call autoscaling:CompleteLifecycleAction, RecordLifecycleActionHeartbeat and SetInstanceHealth, restricted to `asg_arns` when given, otherwise any resource. [cloud-connector.aws.iam:lambda-secret-lifecycle] It may also describe instances, lifecycle hooks, Auto Scaling groups and warm pools, read CloudWatch metrics (GetMetricStatistics, ListMetrics, GetMetricData) and EC2 tags, and write to its own log group. [cloud-connector.aws.iam:lambda-read]

**Deployer.** The deployment guide requires a valid AWS account with Administrator permissions. [cloud-connector.aws.iam:deployer-aws-admin] For a deployment where the security admin IAM user's permissions are wrong, Help's checklist has that user with full access to the AWS Management Console, Secrets Manager, CloudWatch Events, CloudFormation and Lambda, plus a published policy of IAM, SSM, Route 53 Resolver, Secrets Manager, logs, S3 and Marketplace actions. [cloud-connector.aws.iam:deployer-cloudformation] For Terraform, Help says to verify the credentials and that the user can create VPC, NAT gateway, GWLB, IAM, EC2, Elastic IP, route table, subnet and security group resources. [cloud-connector.aws.iam:deployer-terraform]

**CloudFormation templates.** The Starter template's instance role is assumable by EC2 and carries the template's managed policies `CcGetSecretsPolicy` and `CcSsmControlPolicy` and, when cloud tags are enabled, `CcCloudTagsPolicy`. [cloud-connector.aws.iam:cfn-simple-role] The autoscaling template creates its IAM role and instance profile, together with the CloudWatch metrics and autoscaling lifecycle policies, only when the instance-profile parameter is left empty; otherwise it uses the instance profile ARN supplied. [cloud-connector.aws.iam:cfn-asg-profile] The role the autoscaling template creates attaches Secrets Manager read, SSM control, CloudWatch metrics (cloudwatch:GetMetricStatistics, ListMetrics, PutMetricData and ec2:DescribeTags) and autoscaling lifecycle policies (CompleteLifecycleAction, RecordLifecycleActionHeartbeat and SetInstanceHealth among them), plus the workload-tag policy when enabled. [cloud-connector.aws.iam:cfn-asg-role-actions] The macro rewrites the Secrets Manager read policy so GetSecretValue applies to the ARN of the named secret, and in the autoscaling template does the same for the Lambda's policy. [cloud-connector.aws.iam:cfn-secret-scope] The workload-tag policy (`CcCloudTagsPolicy`) that the Starter and autoscaling CloudFormation templates create when the tag parameter is true (its default) allows sqs:DeleteMessage, ReceiveMessage, GetQueueUrl, GetQueueAttributes, SetQueueAttributes, DeleteQueue, CreateQueue and sns:Subscribe, ListSubscriptions and Unsubscribe on all resources. [cloud-connector.aws.iam:cfn-tags-policy] The module and the templates default the tag policy differently [divergence:cloud-connector.aws.iam:cloud-tags-default]. The Pre-Deployment macro runs with its own role: The macro Lambda's execution role allows, on all resources, ec2:DescribeImages, ec2:DescribeSubnets and ec2:ReplaceRoute among other actions, but secretsmanager:GetSecretValue only on secrets under the ZS/CC/ name prefix; secretsmanager:ListSecrets was dropped. [cloud-connector.aws.iam:cfn-macro-role] The template mechanics are in [Cloud Connector on AWS: CloudFormation templates, order, and parameter defaults](kb:cloud-connector.aws.cloudformation).

What to check:
1. Whether the instance role can read the provisioning secret by name.
2. Whether PutMetricData is allowed for the Zscaler/CloudConnectors namespace, without which the scaling and health metrics never arrive.
3. Whether the tag-subscription policy exists when workload tags are expected, since the Terraform module leaves it off by default.
4. For an autoscaling CloudFormation stack with a supplied instance profile, whether that profile carries the CloudWatch metrics and lifecycle-action permissions, since the template creates those policies only for its own role.

Sources disagree (name both sides):
- Whether the workload-tag IAM policy is created by default: the reference Terraform module leaves it off, the CloudFormation templates and Help turn it on. [divergence:cloud-connector.aws.iam:cloud-tags-default]
  - tfmod-aws-cloud-connector: The reference IAM module's cloud_tags_enabled defaults to false, so the tag policy is not created unless asked for.
  - cft-aws-cloud-connector: The CloudFormation templates default the tag parameter to true and create the tag policy.
  Impact: A Terraform deployment has no tag-collection permissions unless cloud_tags_enabled is set, while a CloudFormation deployment has them; missing workload tags on a Terraform deployment can be this default.
