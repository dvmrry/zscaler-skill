# NSS for Cloud & Branch Connector: how connector logs reach a SIEM (cloud-connector.nss-va)
Also called: cloud connector nss; cbc nss; nss virtual appliance cloud connector; nss va cloud connector; nss for firewall cloud and branch connector; cloud connector siem streaming; branch connector nss

Cloud and Branch Connector logs leave the Zscaler cloud for a SIEM through the Nanolog Streaming Service. This subject says what is needed and walks to the server, feed and forwarding-path subjects.

**What it is.** For Cloud & Branch Connector, NSS uses a VM to stream traffic logs in real time from the Zscaler Nanolog to a SIEM, and an NSS server is the representation of that VM in the Admin Console. [cloud-connector.nss-va:what-nss-is] Both Cloud Connector and Branch Connector can generate Session, DNS, Event and Metrics logs, and an NSS feed specifies which log data the NSS sends to the SIEM. [cloud-connector.nss-va:log-types] The fields of each log type are in [Cloud Connector logs: which log types exist and where to read them](kb:cloud-connector.logs).

**Subscription.** Managing Cloud & Branch Connector NSS requires a subscription to NSS for Firewall, Cloud and Branch Connector. [cloud-connector.nss-va:subscription] The NSS VM is deployed from the NSS deployment guides for Azure, AWS and vSphere; for Cloud & Branch Connector only their NSS for Firewall configurations apply, and the NSS for Web configurations are to be ignored as not applicable. [cloud-connector.nss-va:firewall-config-only]

**Servers and feeds.** Registering the VM, its certificate, buffering and sizing are in [NSS servers for Cloud & Branch Connector: certificate, buffering and sizing](kb:cloud-connector.nss-va.servers). Feed limits, output formats and the SIEM destination are in [NSS feeds for Cloud & Branch Connector: limits, output and SIEM destination](kb:cloud-connector.nss-va.feeds). How the connector's own Log and Control Forwarding policy relates to this path is in [Log and Control Forwarding and NSS: the two legs that carry connector logs](kb:cloud-connector.nss-va.log-control-path).

**Across an outage.** The Cloud & Branch Connector SIEM integration page says NSS buffers the logs in VM memory to increase its resiliency to transient network issues between the SIEM and NSS, and if the connection drops NSS replays logs from the buffer according to the Duplicate Logs setting. [cloud-connector.nss-va:nss-to-siem-buffer] The same page says that if the connectivity between the cloud and NSS is interrupted, NSS misses logs that arrived at the Nanolog cluster during the interruption and they are not delivered to the SIEM, and that after the connection is restored the NSS one-hour recovery allows the Nanolog to replay logs up to one hour prior. [cloud-connector.nss-va:cloud-to-nss-recovery] For Cloud & Branch Connector the SIEM integration page says to consider only the NSS for Firewall configurations in the integration guides and to ignore the NSS for Web configurations because they are not applicable. [cloud-connector.nss-va:siem-guides-firewall-only] For the ZIA model see also [What NSS delivers across an outage: VM buffer, Duplicate Logs and one-hour recovery](kb:shared.nss.reliability); the ZIA page's version of the Duplicate Logs example differs from the Cloud & Branch Connector page's, in [NSS feeds for Cloud & Branch Connector: limits, output and SIEM destination](kb:cloud-connector.nss-va.feeds) (divergence duplicate-logs-example).

**Cloud NSS.** The HTTPS-push Cloud NSS feeds for Cloud and Branch Connector logs are in [Cloud NSS feeds for Cloud & Branch Connector logs: HTTPS destination, output and per-log-type filters](kb:cloud-connector.nss-va.cloud-feeds); whether they need a subscription of their own is open [gap:cloud-connector.nss-va:cloud-nss-for-cbc]. The NSS model shared with ZIA (Nanolog tunnel, one-hour recovery, Cloud NSS) is in [VM-based NSS and Cloud NSS: subscriptions, transport and what each needs](kb:shared.nss.delivery-modes).

What to check:
1. Whether the tenant holds the NSS for Firewall, Cloud and Branch Connector subscription before troubleshooting a missing feed.
2. Which log type the SIEM is missing (Session, DNS, Event or Metrics), since each has its own feed.

Not known (open gaps):
- Whether Cloud NSS for Cloud and Branch Connector logs needs its own subscription [gap:cloud-connector.nss-va:cloud-nss-for-cbc]: settled by source-read or support-ticket. Blocks: choosing between an NSS VM and Cloud NSS for a cloud-hosted SIEM
