# Internet Access and Log and Control gateways: default gateways and proxy types; Fail Close and the 32-object limit for Internet Access gateways (cloud-connector.forwarding.gateways)
Also called: internet access gateway; internet & saas gateway; log and control gateway; fail close gateway setting; cloud connector gateway proxy automatic manual override

A default Internet & SaaS gateway with a predefined primary and secondary proxy is automatically created and cannot be deleted; gateways allow users to choose the primary and backup Zscaler data centers to be used for specific workload locations. [cloud-connector.forwarding.gateways:iag-default]

**Proxy choices.** A gateway's primary proxy can forward through an automatic proxy (Automatic), through selected data centers (Manual) or through a specified IP address or domain name (Override); the secondary proxy is used when the primary is unreachable and switches back to the primary upon confirmation of reachability. [cloud-connector.forwarding.gateways:proxy-types] What Automatic selects is not described [gap:cloud-connector.forwarding.gateways:automatic-proxy]. A gateway description cannot exceed 10,240 characters, and up to 32 gateway objects can be created. [cloud-connector.forwarding.gateways:iag-limits]

**Fail Close.** On the Internet Access gateway page, Fail Close Enable (the default) drops the traffic when both proxies are unreachable, and Disable allows the traffic directly to the server without forwarding it to the proxy service when both proxies are unreachable. [cloud-connector.forwarding.gateways:iag-fail-close] The high-availability article's fail-open option may describe a different setting from this one (divergence fail-open-path in [Cloud Connector tunnels to Service Edges: primary, secondary, tertiary, fail-close and fail-open](kb:cloud-connector.overview.gateway-failover)), so the two are not equated here.

**Log and Control gateway.** The log and control gateway allows traffic logs and operational messages to be controlled and forwarded to the Zscaler cloud; a default log and control gateway with a predefined primary and secondary proxy is automatically created and cannot be deleted. [cloud-connector.forwarding.gateways:lc-gateway] A Log and Control gateway defines a primary and a secondary proxy, each chosen as an automatic proxy, selected data centers or a specified IP address or domain name, and the secondary is used when the primary proxy is unreachable. [cloud-connector.forwarding.gateways:lc-proxy-types] Whether Log and Control gateways have a fail-close setting or share the 32-object limit is not stated [gap:cloud-connector.forwarding.gateways:lc-limits-fail-close].
