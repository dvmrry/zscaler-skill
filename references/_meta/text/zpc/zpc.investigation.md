# ZPC investigation and dashboards: query predicates, reports and the executive report (zpc.investigation)
Also called: Posture Control investigation; ZPC dashboards; ZPC executive report; ZPC scheduled reports

**Investigation.** Investigation runs queries on data collected by ZPC without creating alerts, and a result can be saved as an investigation or as a custom security policy. [zpc.investigation:investigation-purpose] On the Saved tab of the Investigation page ZPC shows when each query was last run (Last Run), and on the History tab each query Description. [zpc.investigation:investigation-tabs] A saved investigation has an Investigation Details drawer that shows the investigation query structure. [zpc.investigation:investigation-details-drawer] An investigation starts from a cloud type and a focus on either Assets or Identities. [zpc.investigation:investigation-focus]

**Asset predicates.** The asset relationship predicates are Can be accessed by Identity, Has Package and Has Identity, and the network access predicates are Internet Facing, Public Exposure Details and Publicly Accessible. [zpc.investigation:asset-network-predicates] Asset property predicate operators depend on the property type; Boolean accepts = and ≠, and Date accepts =, <= (Before or on) and >= (After or on). [zpc.investigation:property-operators-by-type] ZPC consolidates asset attributes from the cloud service providers into asset metadata; for example, hard drives connected to EC2s are collected and presented as part of the metadata although AWS does not include them in the EC2 metadata. [zpc.investigation:metadata-consolidation] One asset predicate returns true if the Kubernetes cluster is running, and the page says it is only available for investigating Kubernetes clusters. [zpc.investigation:k8s-running-predicate] One asset predicate returns true if the asset has at least one vulnerability found by the ZPC vulnerability scanner, and another returns true if the asset has at least one file containing sensitive data detected by the ZPC data security scan. [zpc.investigation:vuln-and-data-predicates]

**Identity predicates and results.** An identity authentication predicate returns Yes if the IAM user has a password, No if it does not, and Unknown for identities ZPC has no visibility into, and the page says it is available only for AWS identity focus queries. [zpc.investigation:aws-password-predicate] For AWS, when an access key is used more than once in a 15-minute span, only the first use is recorded in the field behind the predicates for the access key last-used timestamp, region and service. [zpc.investigation:access-key-15-minute] One identity predicate returns a numerical value between 1-100 which is the identity power score, and another returns true if the power score for the identity is above 80. [zpc.investigation:power-predicates] Investigation results can be exported as an Excel file; identity-focused results include Used(%), the entitlement count percentage the identity is accessing, and Last Activity. [zpc.investigation:investigation-results]

**Dashboards.** The Cloud Threats Dashboard groups alerts into Security Event (security events that have already occurred, such as crypto mining or suspicious activity) and Security Exposure (potential exposure, such as dormant accounts or authentication misconfiguration). [zpc.investigation:threats-categories] The Cloud Threats Dashboard Alerts by Risk Level chart offers durations of last 7, 15, 30, 60, 90 or 180 days, while the security event trend covers the last 7 days and its top policies list shows the top 5. [zpc.investigation:threats-ranges] The Cloud Assets Dashboard Cloud Type Trend offers durations of last 7, 15, 30, 60 or 90 days, and it lists the top 10 asset types and top 10 asset categories by number of assets. [zpc.investigation:assets-dash-ranges] On the Cloud Assets Dashboard an asset fails even if a single security policy against it fails, risk level is Low, Medium, High or Critical based on open alerts, and the total asset count is the number of assets ingested by ZPC for metadata collection. [zpc.investigation:assets-dash-status] The Cloud Identities Dashboard All Identities trend offers durations of last 7, 15, 30, 60 or 90 days, and it shows top 10 roles and top 10 accounts by identity count and top 10 identities by resource count. [zpc.investigation:identities-dash-ranges] The Cloud Identities Dashboard describes federated identities as users defined on a user directory such as Okta who are authorized to use cloud service providers, and says a removed federated user loses all roles and permissions. [zpc.investigation:identities-dash-federated] The IaC Dashboard shows policy violations by scan plugin and by cloud type categorized by severity, and clicking a scan plugin opens the Alerts > All Alerts List tab filtered by that plugin. [zpc.investigation:iac-dash] The Vulnerability Dashboard covers container registry and cloud workload vulnerabilities across AWS, Microsoft Azure and Google Cloud Platform, correlated with CVEs from the national vulnerability database and prioritized by CVSS score. [zpc.investigation:vuln-dash-scope] On the Container Registry Images tab of the Vulnerability Dashboard, the time range is 1, 7, 15 or 30 days and the severity levels Critical, High, Medium, Low and Unknown are determined from the CVSS score. [zpc.investigation:vuln-dash-ranges-severity] The Compliance Dashboard shows policy compliance trends over the last 7, 15, 30, 60 or 90 days for the selected benchmark, and benchmark title, policy count and compliance score for laws and regulations and custom benchmarks. [zpc.investigation:compliance-dash]

**Reports.** Excel reports can be downloaded for Cloud Alerts, IaC Alerts, Cloud Assets and Vulnerabilities, while compliance reports are scheduled and generated. [zpc.investigation:excel-report-types] In the alerts report download steps, a requested report that is not yet generated shows the status Pending. [zpc.investigation:report-download-pending] The About Scheduled Reports page says ZPC can view or schedule reports for all available benchmarks, and that the Scheduled Reports page (Administration > Scheduled Reports) lists the scheduled compliance reports and creates new ones; the Enabling or Disabling page describes schedules that generate "compliance or alert" reports. [zpc.investigation:scheduled-reports-purpose] On the Scheduled Reports page a schedule can be searched in the searchable columns and edited or deleted, and the visible table columns can be chosen. [zpc.investigation:scheduled-reports-actions] A reporting schedule can be edited by choosing the Edit icon for the fields to change, or deleted after a confirmation message, from Administration > Scheduled Reports. [zpc.investigation:scheduled-reports-edit-delete] A scheduled compliance report has a unique name, an Excel or PDF format, one or more active benchmarks, and recipient email addresses. [zpc.investigation:scheduled-compliance-report] A warning icon appears next to the Schedule Name if there is an issue with the schedule scope, such as the assigned Business Unit having been deleted. [zpc.investigation:schedule-warning-icon] A compliance or alert report schedule is enabled by default when first created, and disabling it pauses the report from being generated and sent to the recipient. [zpc.investigation:schedule-default-enabled]

**Executive report.** The Executive Report is a high-level overview for executives of cloud account security posture and mitigation progress, which can be shared as a PDF. [zpc.investigation:exec-report-purpose] Executive report asset status can be viewed for the last 7, 15 or 30 days, and asset status and cloud alerts display the last 7 days by default. [zpc.investigation:exec-report-ranges-defaults] In the executive report, up to five policies can be selected at a time for Open Alerts by Policy and up to five benchmarks for Compliance. [zpc.investigation:exec-report-selection-limits] The executive report ranks the top 10 risky accounts by number of critical alerts, the top 10 failed resource types, and the top 10 accounts by number of resources. [zpc.investigation:exec-report-top10] The executive report shows the number of cloud workloads scanned for known vulnerabilities, and Vulnerability Images Scanned is an average. [zpc.investigation:exec-report-scanned] A scheduled executive report has a unique schedule name, a report that defaults to the default Executive Report page, recipients, and an Enabled or Disabled status. [zpc.investigation:exec-schedule] Editing a saved executive report offers Save as New Report, which saves the edit as another customized report, or Save Changes. [zpc.investigation:exec-save-options] A scheduled executive report can be edited by changing the Schedule Name, Report, Recipients, Status or Frequency. [zpc.investigation:exec-scheduled-editable]
