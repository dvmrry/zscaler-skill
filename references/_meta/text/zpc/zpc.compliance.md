# ZPC compliance: benchmarks, ignore rules and security policies (zpc.compliance)
Also called: Posture Control compliance; ZPC benchmarks; ZPC security policies; compliance ignore filter

**Supported benchmarks.** The Supported Benchmarks page says ZPC supports benchmarks such as Cybersecurity Benchmarks, Laws and Regulations, and Industry benchmarks. [zpc.compliance:benchmark-types] ZPC compiles the policies from all benchmarks into a Zscaler Best Practices benchmark for gauging compliance across all available benchmarks. [zpc.compliance:best-practices-benchmark] The supported-benchmarks tables list these Center for Internet Security foundations benchmark versions: AWS v1.5.0 and v2.0.0; Microsoft Azure v1.4.0, v1.5.0 and v2.0.0; Google Cloud Platform v1.3.0 and v2.0.0; OCI v1.2.0. [zpc.compliance:cis-foundations-versions] The supported-benchmarks table for Kubernetes lists Center for Internet Security Kubernetes Benchmark v1.6.1 and v1.7.1 and the Google Kubernetes Engine (GKE) Benchmark v1.4.0. [zpc.compliance:k8s-benchmark-versions] The supported-benchmarks AWS, Azure and GCP tables each list Cloud Security Alliance CCM v4.0.1, General Data Protection Regulation, HIPAA, ISO/IEC 27001, NIST SP 800-53 Rev. 5, NIST CSF 1.1, PCI DSS v3.2.1 and SOC2 - AICPA TSC 2017; the AWS table also lists the EKS v1.3.0 benchmark and the Azure table the AKS v1.3.0 benchmark. [zpc.compliance:cloud-tables-shared-benchmarks]

**Benchmarks.** Each benchmark in the compliance benchmark table shows its type (predefined or custom), policy count, compliance score percentage, and a State toggle that enables or disables the benchmark. [zpc.compliance:benchmark-table-fields] The Creating a New Benchmark page says a custom benchmark is built from 300+ security policies, can be filtered by business units, clouds and accounts, and needs categories added in the Selected Policies pane before policies can be moved from the Available Policies pane. [zpc.compliance:custom-benchmark-creation] On the benchmark details page a policy status is Passed, Failed, No Resources, Manual, Disabled or Ignored; a security policy passes only when all assets pass. [zpc.compliance:policy-status-values] The benchmark details page describes policy severity as a static value of Critical, High, Medium or Low signaling the severity of policy failure. [zpc.compliance:policy-severity-static] The benchmark details page shows a passed and failed policy trend over the last 30 days and exports the details as a PDF file; for a newly enabled benchmark the trend appears only after 24 hours. [zpc.compliance:benchmark-details-trend-export] For a disabled compliance benchmark, ZPC lets you view the last date the compliance information was generated. [zpc.compliance:disabled-benchmark-date]

**Compliance policy details.** Allow Skip on a compliance security policy is enabled by default and lets developers skip the policy in their code repository or CI/CD tool by adding skip comments; if disabled, skip comments have no effect. [zpc.compliance:compliance-policy-allow-skip] The Compliance tab of the compliance security policy details page shows the benchmark name, domain and control section. [zpc.compliance:compliance-policy-tabs]

**Ignore rules.** Each compliance ignore rule shows a Rule Scope listing the security policies, cloud accounts, tags, assets and regions it applies to, and an End Date on which the rule is going to be disabled. [zpc.compliance:ignore-rule-fields] Ignoring a compliance security policy also ignores all its relevant assets and sets the policy status to Ignored; ZPC counts ignored policies as passed in the compliance score. [zpc.compliance:ignore-policy-effect] Ignoring an asset sets its status to Ignored, and ZPC counts ignored assets as passed in the compliance score; ignoring an asset for one policy does not stop ZPC evaluating other compliance policies against it. [zpc.compliance:ignore-asset-effect] If a compliance security policy is ignored, assets can be manually included for evaluation against that policy, and including a policy also includes all its relevant assets. [zpc.compliance:include-assets-after-policy-ignore] An automatic compliance ignore rule has Policies, Cloud Accounts, Tags, Assets and Regions scope filters, each defaulting to its All option (All Policies, All Accounts, All Tags, All Assets, All Regions). [zpc.compliance:auto-ignore-scope-defaults] In an automatic ignore rule, policies can be scoped by severity or selection, cloud accounts by provider (AWS, Azure, GCP or Kubernetes), tags by native cloud service provider tags, and assets by asset type or asset category. [zpc.compliance:auto-ignore-scope-options] The Ignore Rule End Date is optional and sets when the rule should no longer be applied; ZPC ignores all assets and policies matching the filter for the compliance score evaluation. [zpc.compliance:auto-ignore-end-date-effect]

**Ignore rule editing.** A compliance ignore rule can be edited, deleted, enabled or disabled; it is enabled or disabled with the State toggle on the Ignore Rules tab of the Compliance page (Cloud Posture > Compliance), which opens an Enable Ignore Rule or Disable Ignore Rule window. [zpc.compliance:ignore-rule-toggle]

**Security policies.** The About Security Policies page says ZPC offers over 400 security policies across multiple cloud service providers, covering both runtime and buildtime environments, and that the security policies cannot be modified but custom security policies can be created. [zpc.compliance:policy-catalog] The About Security Policies page lists a theme attribute (Compliance, Security Exposure, Security Events or Blank) and a threat category attribute (Ransomware, Misconfiguration or Account Takeover) for security policies. [zpc.compliance:policy-attributes] Policy Focus indicates whether a policy focuses on an asset or identity misconfiguration. [zpc.compliance:policy-focus] On the Cloud Policies tab, a disabled policy is not run against the collected configuration metadata. [zpc.compliance:cloud-policy-state-disabled] On the IaC Policies tab, the Allow Skip toggle is enabled by default and lets developers skip the policy by adding skip comments in their code repository or CI/CD tool; if disabled, skip comments have no effect. [zpc.compliance:iac-allow-skip] The security policy details Alerts tab shows alert status as Open, Closed or Resolved and the resource name (Identity Name or Asset Name). [zpc.compliance:policy-details-alerts-tab] The Managing Security Policies page says ZPC offers enabling or disabling a policy and setting policy severity for individual and bulk security policies, and the steps for each start from the Cloud Policies or IaC Policies tab. [zpc.compliance:policy-state-severity-change]

**Custom policies.** Deleting a custom security policy closes all alerts previously generated by it. [zpc.compliance:delete-custom-closes-alerts] Editing custom-policy information such as title or remediation procedure is reflected in the Alerts page and Cloud Threats dashboard, while editing the query logic closes all existing alerts and generates new ones from the new logic. [zpc.compliance:edit-custom-effects] Remediation of alerts from a policy can be allowed when Support Remediation is enabled for the policy, and bulk changes need policies whose Supports Remediation column is Yes. [zpc.compliance:remediation-prereq] Compliance details can be entered on a custom policy only when its query logic is focused on assets and the asset type predicate is defined. [zpc.compliance:custom-policy-compliance-prereq] The Creating Custom Security Policies page says custom security policies extend coverage beyond the 300+ predefined policies, including to asset types without predefined policies; a policy focuses on Assets or Identities. [zpc.compliance:custom-policy-scope]
