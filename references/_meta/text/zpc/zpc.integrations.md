# How Posture Control third-party integrations work: cloud storage, Amazon Security Lake, ITSM and Slack (zpc.integrations)
Also called: ZPC integrations; Posture Control third-party integrations; ZPC Amazon Security Lake; ZPC Slack integration; ZPC Jira integration; ZPC ServiceNow integration

ZPC can be integrated with SIEM and ITSM tools, cloud storage services (such as Amazon S3) and ChatOps tools like Slack. [zpc.integrations:tool-types] ZPC can be integrated with Amazon S3, Azure Blob Storage and Amazon Security Lake, and the integration lets ZPC send alert data logs to them. [zpc.integrations:cloud-storage-list] Whether Amazon Security Lake appears in the Integrations page list is open [gap:zpc.integrations:integrations-list-asl]. Only ZPC administrators can configure cloud storage integrations. [zpc.integrations:admin-only] On the Integrations page the cloud storage integrations list shows Status (Success, Failed, Paused or Pending, the outcome of the previous data transfer) and Data Transfer (Enabled or Disabled). [zpc.integrations:status-values] For the cloud storage integrations on the Integrations page, data transfer is enabled by default and can be disabled with a toggle to pause without deleting the integration; a transfer already in progress completes before it is disabled. [zpc.integrations:data-transfer-default] The Log Type of cloud storage and ITSM integrations is Alert or Audit Logs, and the ITSM list shows IT Service (Jira or ServiceNow) and Hostname. [zpc.integrations:log-type] The Slack integrations list shows Channels as the number of channels added for sending notifications. [zpc.integrations:slack-channels-column] Limits and roles for integrations are open [gap:zpc.integrations:integration-limits].

**Amazon S3 and Azure Blob Storage.** For Amazon S3, the S3 bucket policy copied from ZPC must be applied to the bucket, the Folder Location is optional, and Test Connection verifies the connection. [zpc.integrations:s3-setup] For the Amazon S3 integration the bucket's default encryption must be Amazon S3 managed keys (SSE-S3); selecting AWS Key Management Service (SSE-KMS) makes the connection fail. [zpc.integrations:s3-encryption] A new Amazon S3 integration shows Pending because no data has been sent; alert rules must be configured and associated with the integration for ZPC to send data logs, after which the status changes to Success. [zpc.integrations:s3-pending-status] For Azure Blob Storage, ZPC uses a storage account connection string, and a Container Location folder name is optional but the folder must first be created in Blob Storage. [zpc.integrations:blob-setup] A new Azure Blob Storage integration shows Pending until alert rules are associated and ZPC sends data logs, after which the status changes to Success. [zpc.integrations:blob-pending-status] ZPC data logs conform to the Splunk Common Information Model (CIM), and S3 or Azure Blob Storage can be integrated with Splunk using the Splunk Add-on for AWS or Splunk Add-on for Microsoft Cloud Services. [zpc.integrations:splunk-cim] Editing an Amazon S3 integration requires testing the connection again, and changing the Amazon S3 Bucket Name or Folder Location requires testing again; for Amazon Security Lake the page lists the Integration Name, IAM Role, Amazon S3 Bucket Name, Folder Location and Bucket Region as editable. [zpc.integrations:edit-cloud-storage] A cloud storage integration associated with alert rules cannot be deleted until the alert rules are moved to another integration; the Delete button stays disabled. [zpc.integrations:delete-cloud-storage]

**Amazon Security Lake.** Zscaler is regarded as a source integration for Amazon Security Lake, which uses OCSF for the alert information and requires the Parquet file format for stored alerts. [zpc.integrations:asl-overview] The Security Lake custom source must use the Security_Finding event class, is created in the region where the AWS console is connected (which must be specified in the ZPC Security Lake integration), and its data source name determines the S3 path for alert files. [zpc.integrations:asl-custom-source] The custom source takes the ZPC AWS Account ID and External ID copied from the Cloud Storage page in the ZPC Admin Portal, and the ARN IAM role from the custom source is entered in ZPC as the IAM Role. [zpc.integrations:asl-ids] For Amazon Security Lake, Test Connection validates that the S3 bucket exists. [zpc.integrations:asl-test-connection] Alerts are written to Security Lake as Parquet files; a new file is posted when the file size reaches 256 MB or after 5 minutes, under the folder structure region=<awsregion>/accountid=<cloudaccountid>/eventDay=<YYYYMMDD>. [zpc.integrations:asl-partitioning] A Security Lake alert rule is created with Alert Type Cloud, and its scope can be filtered by Business Units, Clouds, Accounts, Regions or Tags and its policies by Compliance, Severity, Threat Category and Policy Type. [zpc.integrations:asl-alert-rule] The OCSF static values are category_name Findings, category_uid 2, class_name Security Finding, class_uid 2001, metadata.product.name zpc, metadata.product.vendor_name zscaler and metadata.version 2.2. [zpc.integrations:asl-ocsf-static] In the cloud alert payload, OCSF severity maps from the risk field, finding.uid from alert_id, finding.title from policy_name and time from csp_event_timestamp. [zpc.integrations:asl-ocsf-cloud-map] In the IaC alert payload, OCSF time maps from alert_created_dt, severity from severity, and cloud.provider from scan_plugin. [zpc.integrations:asl-ocsf-iac-map] OCSF activity and status map from the alert_status field and status_detail from alert_status_description. [zpc.integrations:asl-ocsf-status] Why some OCSF mapping rows are blank or NA is open [gap:zpc.integrations:asl-ocsf-blanks]. If ZPC alert data is in the Security Lake S3 bucket but the Glue Crawler fails to parse it, the page says this typically occurs when the custom source uses the wrong event class and must use the Security Finding event class. [zpc.integrations:asl-troubleshoot-glue] A Failed status on the Security Lake integration indicates ZPC does not have permission to access the Amazon Security Lake S3 bucket. [zpc.integrations:asl-troubleshoot-failed] If new alerts are in the ZPC Admin Portal but not exported to Security Lake, the page says to check the alert rule notification configuration and the alert rule scope. [zpc.integrations:asl-troubleshoot-not-exported] The S3 access policy is not given [gap:zpc.integrations:asl-policy].

**ITSM.** The Adding ITSM Integrations page says ZPC can be integrated with ServiceNow or Jira to transfer the audit logs for further analysis and remediation; it gives misconfiguration as the trigger for ServiceNow tickets. [zpc.integrations:itsm-purpose] ZPC leverages ServiceNow APIs to create incidents when a security policy violation occurs; setup needs the ServiceNow hostname, username and password, and the instance must be online. [zpc.integrations:servicenow] The Jira integration works with Jira cloud versions that support the required authentication mechanism and APIs to create a Jira task, and requires an OAuth 2.0 (3LO) app configured in the Atlassian Developer console first. [zpc.integrations:jira-oauth] For the Jira OAuth app, example scopes are read:jira-work (read project and issue data) and write:jira-work (create and edit issues), the Callback URL is the application URL copied from the ZPC Admin Portal, and the Client ID and Client Secret are entered in ZPC. [zpc.integrations:jira-scopes-callback] If Jira login is not possible after clicking Authorize, ZPC shows an Authorization in Process message, and the page says to check and use the correct Jira Client ID and Client Secret. [zpc.integrations:jira-authorize-failure] Editing an ITSM integration allows changing the ServiceName and using Reset Validation to validate the ServiceNow hostname and credentials. [zpc.integrations:itsm-edit] An ITSM integration associated with alert rules cannot be deleted until the alert rules are moved to another integration. [zpc.integrations:delete-itsm]

**Slack.** The Slack integration needs an Incoming Webhook (only one webhook per Slack channel), and ZPC allows 10 channels per integration, with another integration needed for more. [zpc.integrations:slack-limits] When editing a Slack integration the Integration Name can be changed and more channels added, but existing channel and webhook details cannot be edited. [zpc.integrations:slack-edit] A Slack integration associated with alert rules cannot be deleted until the alert rules are moved to another integration. [zpc.integrations:delete-slack]

What to check:
1. Whether the S3 bucket's default encryption is Amazon S3 managed keys (SSE-S3), since selecting AWS Key Management Service (SSE-KMS) makes the connection fail.
2. Whether alert rules are still associated with an integration before deleting it: an integration associated with alert rules cannot be deleted until they are moved to another integration.
3. Whether the Security Lake custom source uses the Security_Finding event class.

Not known (open gaps):

- Limits and roles for integrations [gap:zpc.integrations:integration-limits]: settled by source-read
