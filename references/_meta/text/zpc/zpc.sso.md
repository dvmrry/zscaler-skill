# How SAML single sign-on, IdP configuration, JIT provisioning and trusted IPs work in ZPC (zpc.sso)
Also called: ZPC SAML; ZPC IdP configuration; ZPC JIT provisioning; Breakglass Admin; ZPC trusted IP management; trusted IP list

ZPC supports SAML 2.0 for provisioning and authenticating users, so users can access ZPC directly from the IdP portal. [zpc.sso:saml2] The hub is [What Zscaler Posture Control (ZPC) is to administer: portal access, setup order, notifications and audit logs](kb:zpc.overview).

**IdP configuration.** Only one IdP configuration can be added for a single tenant, and the Add IdP Configuration button is no longer shown once one exists; it can still be edited or deleted. [zpc.sso:one-idp] A user with admin privileges can add or manage IdP configurations, after SAML for SSO has been configured for the organization. [zpc.sso:add-permission] Only the Default Super Administrator can edit or delete an IdP configuration, and deleting it may result in SSO login failure. [zpc.sso:edit-delete-permission] Who may edit or delete is in dispute [divergence:zpc.sso:idp-edit-permission]. The Edit IdP Configuration window offers Login Name Attribute, Enable JIT and Auto Update group based on IdP, in addition to the name, issuer and SSO URL. [zpc.sso:edit-fields] The SAML IdP certificate must be obtained from the IdP beforehand and uploaded in the ZPC Admin Portal when adding the IdP configuration, where it is used to verify the IdP's digital signature. [zpc.sso:idp-certificate] The XML Metadata contains the Name Identifier Format, the Entity ID and the Assertion Consumer Service (ACS) URL, which is the ZPC destination URL where the SAML response must be sent by the IdP. [zpc.sso:metadata] ZPC only supports email address as the Name ID format. [zpc.sso:name-id] In the IdP configuration, SSO is enabled by default for all users in the tenant; while enabled, users can log in only through SSO, and while disabled all users receive an email to reset their password and log in locally; the Default Super Administrator can use either method. [zpc.sso:sso-enabled-default] With Auto Update Group Based on IdP selected, user and group information is updated automatically from the IdP and the default groups (Default admin and Default Read only) associated with the user are not impacted. [zpc.sso:auto-update-groups] If the IdP is enabled but login fails because of IdP issues, an administrator can use Sign in as Breakglass Admin on the Login page with local credentials. [zpc.sso:breakglass]

**Flows and JIT.** The SP-initiated flow starts when the user tries to access ZPC and ZPC sends a SAML request to the IdP; in the IdP-initiated flow the user logs in from the IdP portal by clicking the ZPC application icon and the IdP sends a SAML response to ZPC's ACS URL. [zpc.sso:flows] JIT provisioning works only with IdP-initiated login: ZPC needs an IdP-initiated login to retrieve user information from the IdP and does not work with SP-initiated login. [zpc.sso:jit-idp-initiated] With SAML JIT provisioning, ZPC retrieves user information such as first name or role name from the SAML response, and adds a user that does not exist to the database with the role information, activated and able to access the portal. [zpc.sso:jit-behavior] Before configuring JIT provisioning, a group must exist in ZPC with the same name in the IdP and users assigned to it; this step is mandatory to avoid errors, and IdP groups take priority over ZPC groups. [zpc.sso:jit-group-prereq] If a JIT user belongs to multiple IdP groups, at least one group with the same name must exist in ZPC so the user can log in with SSO. [zpc.sso:jit-multi-group] Group roles are in [Who can do what in ZPC: administrators, groups, roles, modules, business units and API keys](kb:zpc.roles).

**Groups for SSO.** A group added for SSO must use the same name as the group on the IdP portal, and the IdP group overrides the local ZPC group. [zpc.sso:group-sso-name] The Add Group window has a Single Sign-On option that lets users in the group log in to the ZPC Admin Portal directly from their IdP's portal. [zpc.sso:group-sso-checkbox]

**IdP guides.** The SAML configuration page has IdP guides for Okta, PingOne, OneLogin and Azure AD, and a fifth guide for CyberArk Identity; the introductory sentence names only the first four. [zpc.sso:idp-guides] In the Okta and Azure AD guides, the Name ID format is set to email address and Azure's source attribute to user.mail. [zpc.sso:okta-azure-nameid] In the OneLogin guide the ACS (Consumer) URL Validator is https://app.us.zpccloud.net/auth/saml/acs. [zpc.sso:onelogin-validator] In the CyberArk guide the NameID Format is left at its default of Unspecified. [zpc.sso:cyberark-nameid] The Name ID format is in dispute [divergence:zpc.sso:name-id-format]. For CyberArk, user login names must equal the email address or SAML authentication fails; CyberArk roles function as groups. [zpc.sso:cyberark-login] For JIT group attributes in Microsoft Entra ID, the group claim uses Cloud-only group display names, or SAMAccountName when syncing from on-premises Active Directory through Entra ID Connect, with claim name Group and namespace http://schemas.xmlsoap.org/claims. [zpc.sso:entra-group-claim] The ACS host outside the OneLogin validator and where Login Name Attribute appears are open [gap:zpc.sso:sso-hosts-fields].

**Trusted IPs.** ZPC excludes trusted IPs when examining publicly exposed assets or identities, which eliminates false alerts generated for those IPs. [zpc.sso:tip-purpose] Only the Super Admin role can access, edit or delete trusted IPs. [zpc.sso:tip-super-admin-only] Trusted IP changes take up to 12 to 16 hours to reflect across the ZPC modules. [zpc.sso:tip-propagation-delay] A trusted IP list is entered in a downloadable template as a .csv or .xlsx file and uploaded under a list name. [zpc.sso:tip-upload-format] A trusted IP list is applied to Business Units, to Cloud Accounts (providers or individual accounts), or to All Cloud Accounts, which covers all existing and new cloud accounts. [zpc.sso:tip-scope-options] Selecting Alerts on the trusted IP scope step ignores all alerts on external exposure of the cloud resources associated with the trusted IP list. [zpc.sso:tip-alerts-scope] Deleting a trusted IP list updates ZPC inventories and public exposure indicators so that the associated cloud resources are viewed as publicly exposed security risks. [zpc.sso:tip-delete-effect] Uploading a new trusted IP list file overrides the existing file and affects ZPC inventories, public exposure indicators and public exposure alerts. [zpc.sso:tip-upload-overrides] The Scope column of the Trusted IP Management page shows the cloud resource (All accounts, Accounts, Business Units) associated with each list. [zpc.sso:tip-list-scope-column] Upload limits and the cause of the delay are open [gap:zpc.sso:tip-limits]. Public exposure is in [How Posture Control alerts work: types, statuses, attributes, threat categories, alert rules, ignore filters and remediation](kb:zpc.alerts) and [ZPC cloud assets: asset types, categories and asset details](kb:zpc.cloud-assets).

What to check:
1. JIT works only when the user logs in via an IdP-initiated SSO.
2. SSO is enabled by default for all users, and the Default Super Administrator and Breakglass Admin can still use local credentials.
3. Trusted IP changes take up to 12 to 16 hours to reflect across the ZPC modules.

Sources disagree (name both sides):
- The Adding IdP Configuration page says a user with admin privileges can add or manage IdP configurations, while the Editing or Deleting page says only the Default Super Administrator can edit or delete one. [divergence:zpc.sso:idp-edit-permission]
  - zscaler-help: A user with admin privileges can add or manage IdP configurations.
  - zscaler-help: Only the Default Super Administrator can edit or delete an IdP configuration.
  Impact: Which administrators may change an existing IdP configuration is not settled by the two pages.
- The Configuring SAML SSO page says ZPC only supports email address as the Name ID format, while its CyberArk steps keep the NameID Format at Unspecified. [divergence:zpc.sso:name-id-format]
  - zscaler-help: ZPC only supports email address as the Name ID format.
  - zscaler-help: In the CyberArk guide the NameID Format is retained at Unspecified.
  Impact: Which Name ID format a given IdP must send is not settled by the page.
