# What Zscaler Posture Control (ZPC) is to administer: portal access, setup order, notifications and audit logs (zpc.overview)
Also called: ZPC; Zscaler Posture Control; ZPC Admin Portal; ZPC system notifications; ZPC audit logs; ZPC step-by-step configuration guide

The step-by-step guide lists Step 1 log in to the ZPC Admin Portal, Step 2 onboard cloud accounts, Step 3 configure administrators and roles, Step 4 configure single sign-on, and Steps 6 to 11 for alert rules, security policies, third-party integrations, scheduled reports, IaC integrations and vulnerability integrations. [zpc.overview:guide-steps] The product-level description is in [Zscaler Posture Control (ZPC) and Cloud Protection: what ZPC covered, and its end of life](kb:portfolio.cloud-protection).

**Signing in.** After an organization is provisioned for ZPC, the administrator receives an email with the tenant ID and a link to reset the password, and signs in with the registered email ID as Login ID. [zpc.overview:first-login] The ZPC Admin Portal displays the End User Subscription Agreement (EUSA) at first login; clicking Cancel logs the user out automatically. [zpc.overview:eusa] The My Profiles page shows the email address, group, role, My Tenants and My Downloads; a user in several groups sees the list of groups and selects one to access ZPC modules by that group's roles and permissions. [zpc.overview:profile] ZPC supports Chrome, Firefox and Edge (two most recent versions of each) on Windows 10 and 11, and Chrome, Firefox and Safari (two most recent versions of each) on OS X and macOS; older versions and other browsers should be compatible but are not actively tested. [zpc.overview:browsers] ZPC lists OS X 9, OS X 10 and macOS 10 as the supported Apple operating systems. [zpc.overview:mac-os-versions]

**The portal.** The Administration item of the ZPC Admin Portal is where Cloud Accounts, Version Control & CI/CD Systems, Workstations & IDEs, Container Registry & Workloads, Integrations, Business Unit Management, Audit Logs, Single Sign On, Scheduled Reports and API Keys are configured and managed. [zpc.overview:admin-menu] Table settings changed in the ZPC Admin Portal are stored in the browser's local storage and are lost if the cache is cleared or another browser is used; Reset on the column menu does not reset the sort order. [zpc.overview:tables] ZPC offers four filters by default: Business Units, Cloud (AWS, Azure, GCP, Kubernetes), Accounts (selectable by account name or ID) and Regions. [zpc.overview:common-filters] The Help Browser is available on all pages of the ZPC Admin Portal; customizations are kept until logout or session expiry, and closing it clears the navigation history. [zpc.overview:help-browser]

**The configuration guide.** According to the step-by-step guide, the IaC feature and the Vulnerability Integration feature are available based on the ZPC subscription. [zpc.overview:guide-subscription] The step-by-step guide says ZPC offers over 400 security policies across multiple cloud service providers, including Amazon Web Services, Microsoft Azure and Google Cloud Platform. [zpc.overview:guide-policies] ZPC sends data logs (alerts) to cloud storage services such as Amazon S3 buckets, Azure Blob Storage, Splunk or Amazon Security Lake, and offers incident management by integrating with ITSM tools, cloud storage services and ChatOps tools. [zpc.overview:guide-third-party] What Step 5 is is open [gap:zpc.overview:guide-step-5].

**System notifications.** The Notification Center reports whether ZPC lost connectivity with the public cloud infrastructure, reports were not delivered, alerts were not sent to third-party tools, and vulnerability or IaC scans failed with the reason. [zpc.overview:notification-triggers] ZPC automatically deletes resolved notifications after 30 days and deletes a cloud account's notifications when the account is deleted; IaC notifications are retained only for 7 days. [zpc.overview:notification-retention] Each notification shows Module (Data Collection or Vulnerability Management), Severity (Critical, High, Medium, Low) and Status (Open, Resolved). [zpc.overview:notification-fields] Which module covers IaC scan failures and who receives notification emails is open [gap:zpc.overview:notification-module].

**Audit logs.** Administrators can view the audit logs for the past 60 days. [zpc.overview:audit-retention] Each audit log event shows Event ID, Event Timestamp in UTC, Tenant Name, User, Login Type (Local or SAML), Interface, Role Name, IP, User Agent, Action, Data Object Type, Data Object Name, Module and Sub Module. [zpc.overview:audit-fields] Audit log data can be exported to a CSV file and filtered, for example with the Event Time filter to see the last 24 hours. [zpc.overview:audit-export-filter] Audit logs record sign-in and sign-out attempts, adding or removing cloud accounts, configuring alerts, IaC integrations, vulnerability management, enabling or disabling policies, downloading reports and configuration changes during a session. [zpc.overview:audit-what-is-logged] ZPC records actions in the Administration, Alerts, IaC Integration, Policies, Reports, Vulnerability Management and Kubernetes Cluster modules. [zpc.overview:audit-event-modules] The audit log events include Edit SSO, Enable SSO for Group, Disable SSO, Delete SSO and Enable Just-in-Time (JIT) Provisioning. [zpc.overview:audit-sso-events] The audit log events under IaC Policies include Allow Policy and Skip Policy. [zpc.overview:audit-iac-policy-events] The name given to an API key appears in the audit logs as the entity performing the API actions. [zpc.overview:audit-api-key-name] What the retention and export leave unsaid is open [gap:zpc.overview:audit-log-scope].
