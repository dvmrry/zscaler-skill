# Who can do what in ZPC: administrators, groups, roles, modules, business units and API keys (zpc.roles)
Also called: ZPC RBAC; ZPC predefined roles; ZPC custom role; ZPC business units; ZPC API keys; Default Super Admin; Default Read Only

In ZPC, roles are always assigned to groups, and all users in a group have the same role. [zpc.roles:role-to-group] The hub is [What Zscaler Posture Control (ZPC) is to administer: portal access, setup order, notifications and audit logs](kb:zpc.overview).

**Groups and administrators.** Each group is assigned a single role and can be assigned to multiple business units; users can belong to multiple groups and switch between them. [zpc.roles:group-model] The default groups available are Default Super Admin with read, add, edit and delete privileges, and Default Read Only with only read privileges. [zpc.roles:default-groups] A user can select a default group after logging in so that the same group is used at the next login. [zpc.roles:default-group-selection] If an administrator belongs to a group not associated with any business unit, the Administrators and Groups page shows a message indicating the group is invalid. [zpc.roles:invalid-group] ZPC provides a default admin role with full access to the ZPC Admin Portal, assigned to the default admin and assignable to other admins. [zpc.roles:default-admin-role] Zscaler recommends adding groups before administrators because each administrator must be assigned a group. [zpc.roles:add-groups-first] Choosing Reset Password in the Edit Administrator window sends the administrator an email to reset their password. [zpc.roles:reset-password] An administrator can edit their own account but cannot delete it. [zpc.roles:admin-self-delete] A group that contains administrators can be deleted only after its administrators are moved to other groups. [zpc.roles:delete-group-with-admins] Group names for single sign-on are in [How SAML single sign-on, IdP configuration, JIT provisioning and trusted IPs work in ZPC](kb:zpc.sso). What "Super Admin" refers to is open [gap:zpc.roles:super-admin].

**Predefined roles.** ZPC's predefined roles are Administrator, SecOps, Compliance Auditor, View Only Administrator, IaC Administrator, IaC Developer, IT Administrator, Vulnerability Administrator, Vulnerability Viewer, Kubernetes Onboarding and LocalPlatformAgent. [zpc.roles:predefined-list] Predefined roles cannot be edited or deleted. [zpc.roles:predefined-immutable] Administrators with a View Only role cannot perform any CRUD operation or export data, and the Actions column and Export icon are hidden for them. [zpc.roles:view-only] In the predefined roles table, Administrator has All modules, sub modules and permissions; View Only Administrator has All modules and sub modules with View Only and Save Investigation permissions; SecOps has All sub modules and permissions on Alerts, Cloud Posture, Investigation and Policies. [zpc.roles:matrix-admin-viewonly-secops] The predefined roles table has rows for Compliance Auditor (Cloud Posture, Compliance, All), Scheduled Reports (All), IaC Administrator (Administration: Version Control & CI/CD Systems, Workstations & IDEs, All), Policies (IaC Policies, All), Alerts (IaC Alerts, All) and IaC Developer (Administration: Workstations & IDEs, All). [zpc.roles:matrix-compliance-iac] The predefined roles table has rows for IT Administrator (Administration: Scheduled Reports, Integrations, Workstations & IDEs, Version Control & CICD Systems, Single Sign-On, Container Registries & Workloads, Cloud Accounts, Business Unit Management, Audit Logs, All), Role Management (Edit Role, View Role, Export Role) and Analytics (Executive Report, All). [zpc.roles:matrix-it-admin] The predefined roles table has rows for Vulnerability Administrator (Administration: Container Registries & Workloads, All; Cloud Posture: Vulnerability Management, All), Vulnerability Viewer (the same two entries, View Only), Kubernetes Onboarding (Administration: Cloud Accounts, Add, Edit and View KSPM Integrations) and LocalPlatformAgent (System Role), described as a system role used by subsystems for local scanning agent. [zpc.roles:matrix-vuln-k8s] The flattened table is open [gap:zpc.roles:role-table-flattened].

**Modules and custom roles.** Modules are ZPC features whose data can be filtered by cloud accounts associated with business units, and global modules are those where data is not segregated by cloud account and business units do not apply. [zpc.roles:modules-defs] The ZPC modules table has rows for Cloud Posture (Cloud Assets), Cloud Identity, Compliance, Vulnerability Management, Alerts (Cloud Alerts) and Analytics (Executive Report). [zpc.roles:modules-list] The global modules table has rows for Administration (Administrators and Groups), Cloud Accounts, Role Management, Integrations, Scheduled Reports, Workstations and IDEs, Version Control and CICD Systems, Single Sign On, Container Registries and Workloads, Business Unit Management, Trusted IP Management, Audit Logs, System Notifications, Investigation, Policies (Cloud Policies), IaC Policies, Alerts (IaC Alerts) and Ignore Rules. [zpc.roles:global-modules-list] A custom role has a unique name and, per module or global module, a permission of Access, View Only or None. [zpc.roles:custom-role-permissions] A custom role assigned to a group can be deleted only after another role is assigned to the group. [zpc.roles:delete-role-in-use]

**Business units.** Business units are logical containers for cloud accounts that govern ZPC from a role-based access control (RBAC) perspective, and are mapped to groups that are assigned specific roles and permissions. [zpc.roles:bu-definition] By default the Default Super Admin and Default Read Only groups are assigned to all business units. [zpc.roles:bu-default-groups] Adding a business unit takes a Name and the groups to assign it to, and users in those groups can view data and perform tasks on cloud accounts within the business unit. [zpc.roles:bu-add-fields] Deleting a business unit that has cloud accounts requires moving them to another business unit; otherwise ZPC moves them to a default business unit. [zpc.roles:bu-delete-moves-accounts] The Business Unit Management page lists each business unit with its groups, Account Count (number of cloud accounts) and Created On date. [zpc.roles:bu-list-columns] Editing a business unit lets you change its Name or select a different group. [zpc.roles:bu-edit] The accounts they contain are in [How ZPC cloud accounts and organizations are onboarded: AWS, Azure, GCP and OCI](kb:zpc.cloud-accounts).

**API keys.** An API key is required to access ZPC's publicly available APIs, and only the API key is required for authentication before accessing them. [zpc.roles:key-auth] A maximum of 100 API keys can be created. [zpc.roles:key-max-100] An API key can only be viewed, copied or downloaded as CSV when it is created and is not available in the ZPC Admin Portal after the window is closed. [zpc.roles:key-shown-once] Whether the key stays accessible after creation is in dispute [divergence:zpc.roles:key-availability]. The Revocation Date of a new API key can be Never, 7 Days, 15 Days, 1 Month or 3 Months, and defaults to 7 Days. [zpc.roles:key-revocation-date] An API key is created with a name and a group and role, and Zscaler recommends the least permissive role; symbols such as ampersands (&) and asterisks (*) are not supported in the name. [zpc.roles:key-name-and-role] Revoked API keys no longer authenticate to the ZPC API but remain in the table, and revoking cannot be undone. [zpc.roles:key-revoke] Deleting an API key cannot be undone; the key is permanently deleted and a new one must be created. [zpc.roles:key-delete] An API key's Status shows whether it is active, inactive or revoked. [zpc.roles:key-status] What makes a key inactive is open [gap:zpc.roles:key-inactive]. The ZPC API is in [How the ZPC API is reached, authenticated, rate limited and queried for alerts](kb:zpc.api).

What to check:
1. The default groups and the predefined roles list.
2. Deleting a business unit that has cloud accounts requires moving them to another business unit, otherwise ZPC moves them to a default business unit.
3. Revoked API keys no longer authenticate to the ZPC API.
4. Whether the key is accessible after creation, where the two ZPC pages differ.

Sources disagree (name both sides):
- One ZPC page says API keys are always accessible from the page but only displayed at creation; the creating page says the key is not available in the Admin Portal once the window is closed. [divergence:zpc.roles:key-availability]
  - zscaler-help: API keys are always accessible from the page, and only displayed when first created.
  - zscaler-help: The key is not available to access in the ZPC Admin Portal after the window is closed.
  Impact: Store the key when it is created rather than relying on retrieving it from the page later.
