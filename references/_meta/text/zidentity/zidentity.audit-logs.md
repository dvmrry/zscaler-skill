# Authentication Service audit logs and log streaming: what is recorded, record fields, filters and export, and NSS streaming (zidentity.audit-logs)
Also called: Authentication Service audit logs; ZIdentity audit logs; Data Explorer Audit Logs Authentication Service; Authentication Service Log Streaming; ZIdentity Admin Audit Log; stream Authentication Service logs to SIEM

Authentication Service keeps its own audit log, read in the console and streamed through NSS. Authentication Service audit logs record user activity in Authentication Service: configuration changes, user management (creating, updating and deleting users), tenant management, authentication settings changes, service assignments and authentication events, including changes an administrator makes to policies or configurations through Authentication Service or the APIs. [zidentity.audit-logs:what-is-recorded]

**Authentication events.** The key authentication events tracked include password logins by users or admins, authentication through external IdPs (for example SAML or OIDC), completion of MFA, and MFA performed within Authentication Service by IdP-managed users; events from logins through Client Connector or the browser can also be monitored on the Audit Logs page. [zidentity.audit-logs:authentication-events]

**Reading the log.** The Audit Logs page (Data Explorer > Audit Logs > Authentication Service) filters by time range, action, category, subcategory, interface or result, searches by resource, admin ID or client IP, and downloads a CSV whose times are in PDT. [zidentity.audit-logs:page-filters-export] Each entry has a timestamp, an action, a category (the Admin Console page), a sub-category (the entity under the category, such as users and groups under User Management), a resource, the admin ID (the user's login ID), the client IP, the interface (UI, Zscaler Client Connector or API) and the result (Success, Failure or Partially Failed). [zidentity.audit-logs:record-fields] Actions are Create, Update, Delete, Password Change, Reset Password, Import, Link, Unlink, Admin or User Login and Admin or User Logout; categories are User Management, Guest Domains, Tenants, Authentication Settings and Authentication. [zidentity.audit-logs:actions-and-categories] Selecting a configuration change shows visual differences between the pre- and post-change configuration, for updates and for additions or deletions. [zidentity.audit-logs:config-diff]

**What is not recorded or not known.** Retention is open [gap:zidentity.audit-logs:retention], and so are the objects of Link and Unlink [gap:zidentity.audit-logs:link-objects]. Whether admin role and administrative-entitlement assignments are recorded is the open question in [Whether admin role assignments appear in the Authentication Service audit log](kb:zidentity.admin-rbac:assignment-audit). There is no pull API: [No audit log endpoint is documented for Authentication Service: its API specification has no audit path and neither SDK has an audit client for it.](kb:shared.audit-logs:zid-no-audit-api).

**Log streaming.** NSS and Cloud NSS integration lets Authentication Service stream authentication, admin audit and SCIM logs in real time to SIEMs linked with Zscaler services such as ZIA; on the Log Streaming page (Data Explorer > Log Streaming > Authentication Service Log Streaming), enabling Authentication Service Log Streaming streams them to the Internet & SaaS tenant, whose linked tenants are listed with their IDs. [zidentity.audit-logs:log-streaming] Enabling log streaming needs Full permission on the Log Streaming module. [zidentity.audit-logs:log-streaming-permission] Log streaming requires allowlisting the Authentication Service IP ranges for the Zscaler cloud, listed in Zscaler Cloud Configuration Requirements; the page's example maps the login URL acme.zslogin.net to the zslogin.net cloud. [zidentity.audit-logs:log-streaming-allowlist] The feeds are ZIA NSS feeds: [The initial Authentication feed takes up to 5 hours to stream, on TCP and Cloud NSS, and appropriate Log Streaming role permissions must be enabled in the Authentication Service. The SCIM article says the initial SCIM feed also takes up to 5 hours, and that this delay does not occur if Audit Logs are already configured and streaming.](kb:shared.nss.feeds:auth-scim-delay), [The Cloud NSS Authentication and SCIM articles each say one Cloud NSS feed can be configured for that log type.](kb:shared.nss.feeds:cloud-one-feed), [The admin audit feed's Application filter on TCP feeds offers Branch Connector Portal Audit Log, Client Connector Portal Audit Log, ZIA Portal Audit Log and ZIdentity Admin Audit Log; the HTTP and Cloud NSS articles also list Risk360 Admin Portal Audit Log and ZDX Portal Audit Log.](kb:zia.audit-logs.streaming:application-filter).

**Permission.** Viewing the log is the Audit Logs module: [Audit Logs has only View Only (view audit logs) and None.](kb:zidentity.admin-rbac.permissions:audit-logs-view-only).

What to check:
1. Whether the activity was done through the UI, Client Connector or API, and whether it is an authentication event or a configuration change, to pick the filter.
2. Before relying on a streaming feed, whether Authentication Service Log Streaming is enabled, which needs an admin with Full on the Log Streaming module, and whether the Authentication Service IP ranges are allowlisted, which the page says to ensure.

Not known (open gaps):
- How long Authentication Service audit logs are kept [gap:zidentity.audit-logs:retention]: settled by source-read or support-ticket. Blocks: knowing how far back an audit question can be answered
- What the Link and Unlink actions apply to [gap:zidentity.audit-logs:link-objects]: settled by lab-test or source-read. Blocks: reading a Link or Unlink record
