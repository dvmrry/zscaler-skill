# Authentication Service authentication methods: MFA and FIDO2 setup, admin MFA registration and skip, and the password policy (zidentity.authentication-methods)
Also called: Authentication Methods page; Multi-Factor Authentication page; FIDO2 as primary authenticator; passwordless Authentication Service; Enforce Zscaler Admin MFA; Email OTP not enabled; password policy; Password Policy page; password reuse; password expiration

This covers how Authentication Service authenticates people to its own console and what the password policy sets. MFA is required by default for all admins, and Zscaler strongly recommends keeping it enabled; users can be authenticated with a password and a second factor (time-based OTP (TOTP) and Fast IDentity Online (FIDO) authentication), and passwordless authentication can be configured by setting up FIDO2 as the primary authenticator. [zidentity.authentication-methods:mfa-default-admins]

**Passwordless.** With Allow FIDO2 as Primary Authenticator enabled, users can skip the password and configure any FIDO2 method available on their device at their next login, for a passwordless Authentication Service account. [zidentity.authentication-methods:fido2-primary] When FIDO2 as primary authenticator is disabled, users log in with their MFA credentials if MFA is enabled (users without MFA configured can request a password reset and set up MFA), and with only their passwords if MFA is disabled (users who forgot or never set a password use Password Reset). [zidentity.authentication-methods:fido2-disabled]

**Second factors.** When an admin sets up MFA, the page lists the authentication types TOTP Authenticator, Security Key or Biometric (the FIDO2 methods available on the device; the page names Windows Hello and YubiKey as examples of services certified with FIDO2) and Email OTP. [zidentity.authentication-methods:factor-types] Email OTP is not enabled by default, because it is not recommended for MFA under NIST guidelines; to enable it, you can raise a Zscaler Support ticket. Choosing it needs no email verification, since the address was verified at the start of registration. [zidentity.authentication-methods:email-otp-off] Whether SMS is a factor is open [gap:zidentity.authentication-methods:sms-factor].

**Service enrollment.** Enable Multi-Factor Authentication (MFA) for Service Enrollment, on the Authentication Methods page, is shown only when the user single sign-on (SSO) feature is enabled for the tenant, and can be disabled for users. [zidentity.authentication-methods:mfa-for-service-enrollment] What it enforces when on is open [gap:zidentity.authentication-methods:service-enrollment-mfa].

**Admin registration.** An admin whose organization configures an Authentication Service account for them (with a Zscaler service's access and the functional scope of their role) receives an email from Zscaler Support to set up MFA; an Authentication Service admin follows its setup link to a sign-up page and enters a password. [zidentity.authentication-methods:admin-setup-email] An external IdP admin, after authenticating at the external IdP, must verify their identity before registering for Authentication Service MFA, either by a link sent to the registered email address or by an OTP sent to the super admin email address; each is valid for 15 minutes, and Skip gives a 7-day grace period before verification is required. [zidentity.authentication-methods:external-idp-admin-verification]

**Skipping.** An admin can skip MFA for a grace period of 7 days, after which MFA must be configured in Authentication Service; admins using MFA through their external IdP can disable the Enforce Zscaler Admin MFA option to prevent additional authentication verification from Authentication Service. [zidentity.authentication-methods:skip-mfa-grace] The same option is labelled Enforce Zscaler MFA for Admins in [The Enforce Zscaler MFA for Admins option makes admins who use an external IdP authenticate with MFA in Authentication Service, whether or not MFA is configured on the external IdP; an email is sent to all super admins in Authentication Service when the option is disabled.](kb:zidentity.overview.external-idps.configuration:enforce-admin-mfa). The Skip Until limit an admin sets on a user is a separate setting, scoped to hosted admins: [The Skip Until field displays the current date and time; by default MFA can be skipped for 8 hours, and the maximum limit is 5 days.](kb:zidentity.users.security-settings:skip-duration), [Skipping two-factor authentication lets Authentication Service administrators log in to the subscribed Zscaler service with only a password for a short duration (the help's example: a user without the device that receives their one-time passcode); the Skip Second Factor Authentication option is only available for hosted admins and not for admins authenticating via the external IdP.](kb:zidentity.users.security-settings:skip-hosted-admins-only). Whether the 7-day grace and Skip Until share a timer is open [gap:zidentity.authentication-methods:skip-timers].

**Password policy.** The password policy is the set of rules for creating or resetting the passwords of users accessing the Zscaler Admin Console; its Configuration Type is Default or Custom, and Zscaler recommends Default. [zidentity.authentication-methods:password-policy-type] A Custom policy sets the minimum password length and the minimum numbers of lowercase letters, uppercase letters, numeric characters and special characters, and can forbid the company name, username, first name or last name in the password. [zidentity.authentication-methods:password-custom-composition] Whether it governs end-user passwords too is open [gap:zidentity.authentication-methods:policy-scope], and the Default values and the length and character bounds are not given [gap:zidentity.authentication-methods:default-values].

**Reuse, lockout and expiry.** Reject reuse of previous passwords defaults to 5 and can be set from 3 to 10; turned off, users can reuse old passwords. Passwords changed after a 24-hour gap fall under this criterion and any password changed within 24 hours is ignored; in the page's example, the second password change is ignored and can be reused. [zidentity.authentication-methods:password-reuse] Deactivate user after unsuccessful attempts deactivates the account after that many failed logins; the default is 10, settable from 3 to 10. [zidentity.authentication-methods:password-lockout] The password expiration period, after which users can reset their passwords, is set in days from 15 to 365. [zidentity.authentication-methods:password-expiration]

**Who sets and changes passwords.** The policy can allow administrators to create or change a user's password, and can force users to change their password after the initial login. [zidentity.authentication-methods:password-admin-and-first-login] The per-user password options are in [A user must be added before security settings are configured; Change Password Settings must be enabled to modify the password configuration. Set By User makes the user set their own password and sends a password reset email, and the user can choose and configure the required authentication method; Set by Administrator has the admin set the password; Auto-generated generates one for the user, and the Copy and View icons copy or view the password.](kb:zidentity.users.security-settings:password-options) and [With Set by Administrator and with Auto-generated, Prompt for Password Change After the Initial Login is selected by default; for Set by Administrator the user then changes the password following the guidelines in the password policy.](kb:zidentity.users.security-settings:prompt-change-default).

**Permission.** The Authentication Methods permission module covers both the Password Policy and the Authentication Methods pages: [The Adding Admin Roles page maps modules to console pages: Authentication Methods covers Password Policy and Authentication Methods; Users & Groups covers Users, User Groups and Attributes; IP Locations & Groups covers Trusted IP Locations and Trusted IP Location Groups; Linked Services covers Linked Services; Service Entitlements covers End User Entitlements; Audit Logs covers Data Explorer > Audit Logs > Authentication Service; API Clients & Resources covers API Clients and API Resources; Token Validator covers Token Validators; Log Streaming covers Authentication Service Log Streaming.](kb:zidentity.admin-rbac.permissions:module-pages).

What to check:
1. Which factor a user can choose, from the three types the page lists, and that Email OTP needs a Support ticket to be enabled.
2. Whether a MFA skip is the admin's own 7-day grace at registration or the Skip Until an admin set on a user, since the pages do not link them.
3. For a reused-password rejection, that only passwords changed after a 24-hour gap count toward the reuse limit.
