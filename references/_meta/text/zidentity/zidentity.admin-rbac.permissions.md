# Authentication Service permission modules and levels, and the cross-module dependencies (zidentity.admin-rbac.permissions)
Also called: ZIdentity permission matrix; Authentication Service permissions; Restricted Full; Restricted View; Restrictive View; admin cannot see sign-on policy; admin cannot change user email; admin cannot assign roles; ZIdentity module permissions

Each Authentication Service role sets a permission level per module, and some modules only work when another module is granted too. A user can hold one or several Authentication Service roles; with several, the permission levels are hierarchical and the effective level of each permission is the highest across the user's roles. [zidentity.admin-rbac.permissions:multiple-roles]

**Modules and levels.** The modules in the Admin Roles and Permissions matrix are Admin Sign on Policy, Authentication Methods, Users and Groups, User Credentials, Roles, External Identities, IP Locations & Groups, Authentication Session, Administrative Entitlements, Service Entitlements, Audit Logs, Guest Domain, Remote Assistance, Branding, API Clients & Resources, Executive Insights, Token Validators and Log Streaming. [zidentity.admin-rbac.permissions:modules] The matrix rows quoted here use the levels Full, Restricted Full (Administrative Entitlements and API Clients & Resources), View Only and None, and the External Identities row also describes a Restricted View level that shows each IdP's configuration except the Bearer Token. The page's own example of combining roles names a Restrictive View level for External Identities. [zidentity.admin-rbac.permissions:levels] The Adding Admin Roles page describes four access levels per module: Full (full access), View Only (view details only), Restricted View (view specific details) and None (no access). [zidentity.admin-rbac.permissions:add-role-levels]

**Module pages.** The Adding Admin Roles page maps modules to console pages: Authentication Methods covers Password Policy and Authentication Methods; Users & Groups covers Users, User Groups and Attributes; IP Locations & Groups covers Trusted IP Locations and Trusted IP Location Groups; Linked Services covers Linked Services; Service Entitlements covers End User Entitlements; Audit Logs covers Data Explorer > Audit Logs > Authentication Service; API Clients & Resources covers API Clients and API Resources; Token Validator covers Token Validators; Log Streaming covers Authentication Service Log Streaming. [zidentity.admin-rbac.permissions:module-pages] Its module list is scoped to that page, as the matrix list in [zidentity.admin-rbac.permissions:modules] is scoped to the matrix. Guest Domains takes Full, View Only or None. [zidentity.admin-rbac.permissions:guest-domains-levels] The Executive Insights permission is given to the leadership team (CEO, COO, CFO and others) to let them access the Executive Insights app. [zidentity.admin-rbac.permissions:executive-insights-module]

**Setting a role's levels.** An admin configuring a role can set each permission only equal to or lower than their own role's level, so a lower-scoped admin cannot create a higher-scoped one; the page's example: an admin whose role has Roles Full and IP Locations View Only can give new roles IP Locations View or None, not Full. [zidentity.admin-rbac.permissions:no-escalation]

## Dependencies between modules

- **Sign-on policy.** An admin without IP Locations Full or View permission is not allowed to access the sign-on policy, even with Admin Sign on Policy Full or View Only. [zidentity.admin-rbac.permissions:signon-needs-ip-locations]
- **User credentials.** User Credentials permissions (the users' security settings) apply only when the admin also has Users and Groups View or Full, and an admin without Users and Groups Full cannot change a user's primary and secondary email addresses even though they are used as credentials. [zidentity.admin-rbac.permissions:credentials-need-users] Users & Groups does not give access to a user's Security Settings (Administration > Authentication > Users > Edit User > Security Settings); that needs Full or View Only on User Credentials. [zidentity.admin-rbac.permissions:users-groups-excludes-security]
- **Roles.** Roles Full allows viewing, adding, editing and deleting roles, and admins with Users and Groups Full or View permission can add or edit roles; Roles View Only shows roles and their configuration. [zidentity.admin-rbac.permissions:roles-module] Editing or deleting an admin role that is currently assigned to admins needs Full on Administrative Entitlements and Full or View Only on Users & Groups. [zidentity.admin-rbac.permissions:assigned-role-edit]
- **Administrative entitlements.** At Administrative Entitlements Full an admin assigns and removes users and groups, and can assign roles with Roles Full or View Only. At Restricted Full an admin can assign roles with Roles Full but not with Roles View Only, and can assign or remove users and groups in individual tenants where they have permission to manage administrators. [zidentity.admin-rbac.permissions:admin-entitlements-role-assignment] An admin with the Administrative Entitlements module reaches the Administrative Entitlements configuration only for services where they are a service admin and their product role has that product's Role Management permission at Full (Internet & SaaS, Private Access, Digital Experience, Client Connector, Branch and Cloud Connector). The page's example: an admin without full access to administrative controls in Private Access sees only Internet & SaaS listed, not Private Access. [zidentity.admin-rbac.permissions:admin-entitlements-product-full] On the Administrative Entitlements page, admins with Full on users and groups view user and group details and all assignments and assign and remove users and groups; the page also lists what admins with View Only on users and groups can do there. [zidentity.admin-rbac.permissions:admin-entitlements-by-users-groups]
- **Service entitlements.** On the Service Entitlements page, admins with Full on users and groups view users, groups and assignments; admins with View Only on users and groups view the subscribed services. [zidentity.admin-rbac.permissions:service-entitlements-by-users-groups]

## What some modules cover

- **Users and Groups.** Users and Groups Full covers viewing users and groups; adding, editing, deleting, activating and deactivating users; adding, editing and deleting groups; importing group details from CSV; renaming groups and assigning users to them; managing attributes; and submitting a Zscaler Support ticket from the Admin Console. View Only shows users, groups and their attributes and also allows a support ticket. [zidentity.admin-rbac.permissions:users-and-groups-full]
- **Authentication Session.** The Authentication Session module covers the session timeout duration, the authentication session for service enrollment, and forced authentication for Private Access reauthentication. [zidentity.admin-rbac.permissions:authentication-session]
- **API Clients & Resources.** API Clients & Resources Full covers adding, editing and deleting API clients and the API Client Access Policy, managing resources and revoking access tokens. Restricted Full allows adding, editing and deleting API clients, but assigning and removing resources only for the Zscaler services the admin or API client is permitted for (for example only Internet & SaaS resources). [zidentity.admin-rbac.permissions:api-clients-module] The API Client Access Policy itself is in [The API Client Access Policy: rules that allow or block a client's resources within time frames](kb:zidentity.api-clients.access-policy).
- **Audit Logs.** Audit Logs has only View Only (view audit logs) and None. [zidentity.admin-rbac.permissions:audit-logs-view-only]

What to check:
1. Whether every role the admin holds was considered, since the effective level of each permission is the highest across them.
2. For an admin who cannot open the sign-on policy, whether they hold IP Locations Full or View.
3. For an admin who cannot change a user's credentials or emails, whether they also hold Users and Groups View or Full (Full for the email addresses).
4. For an admin who cannot assign roles on Administrative Entitlements, which level they hold there and which Roles level goes with it.
5. For an admin who sees only some services on Administrative Entitlements, whether their product role has Role Management Full in each product.
6. Before saying a role has a Linked Services or Remote Assistance module, which page's module list the answer rests on: the Adding Admin Roles page lists Linked Services and the matrix lists Remote Assistance.
