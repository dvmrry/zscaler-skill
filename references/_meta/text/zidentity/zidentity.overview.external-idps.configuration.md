# Configuring an external IdP in Authentication Service: domains, login ID attribute, OIDC and SAML fields, admin MFA enforcement, signing certificates and IdP-initiated sign-in (zidentity.overview.external-idps.configuration)
Also called: Adding OpenID Providers; Adding SAML Identity Providers; Login ID Attribute; Enforce Zscaler MFA for Admins; IdP-initiated sign-in; idp_id; zidServiceId; Request Signing and Decryption Certificate; SAML Request Signing; Identity Vendor

This is the per-IdP configuration form of Authentication Service; what IdPs are, their limits and retention are in [External IdPs in Authentication Service: OIDC and SAML, primary and secondary, limits and retention](kb:zidentity.overview.external-idps), and what each vendor's guide adds is in [Per-IdP integration specifics for Authentication Service: Okta, Microsoft Entra ID, AD FS, PingOne, PingFederate, Auth0 and OneLogin](kb:zidentity.overview.external-idps.integrations).

**Domains.** An OIDC IdP's Domains field selects the domain for which the IdP authenticates users, which lets the Zscaler service show an incoming user the correct IdP; the OIDC and SAML pages say a primary IdP or multiple secondary IdPs can each be assigned a subset of the user domains, and a secondary IdP can be added only if a primary is already configured (the OIDC page's wording). [zidentity.overview.external-idps.configuration:domains]

**Login ID.** For an OIDC IdP the Login ID Attribute is populated with `preferred_username` by default; any attribute in the ID token or the UserInfo endpoint response can be used if its value is in email address format, it must exist in the received tokens and match exactly, and the domain part of the received email addresses must match one of the domains configured in Authentication Service. [zidentity.overview.external-idps.configuration:login-id-oidc] For a SAML IdP the Login ID Attribute is populated with `NameID` by default; any attribute in the SAML assertion can be used if its value is in email address format, and the domain part of the received email addresses must match one of the domains configured in Authentication Service. [zidentity.overview.external-idps.configuration:login-id-saml]

**OIDC.** An OIDC IdP is described either by a metadata URL (pasted and fetched) or by an issuer URL plus an authorization endpoint (where the user is redirected and an authorization code is sent to Authentication Service), a token endpoint (where the code is exchanged for an ID token and access token), a JWKS endpoint (public keys that validate token signatures) and a user information endpoint. [zidentity.overview.external-idps.configuration:oidc-endpoints] Authentication Service's Redirect URI is registered at the OP when configuring it as the relying party; Authentication Service authenticates to the OP's token endpoint with a client ID and client secret using Client Secret Basic or Client Secret Post, and Requested Scopes are included in the authentication request and, depending on the OP, can retrieve more user attributes. The Auth0 guide says the openid, email and profile scopes are added by default when OIDC is selected. [zidentity.overview.external-idps.configuration:oidc-client] An OIDC IdP's advanced options are Login Hint (populates the Login ID field at login and includes the login ID in the OIDC authentication request), Levels to Authentication Context Mapping (maps the IdP's authentication contexts for step-up), an optional Default Requested Authentication Context (the authentication context class reference values passed in the request, defining the authentication method or levels required) and Session Attribute Mapping (maps IdP attributes to session attributes). [zidentity.overview.external-idps.configuration:oidc-advanced]

**SAML.** A SAML IdP is described by a pasted and fetched IdP Metadata URL, an uploaded IdP Metadata file, or the IdP Issuer URI (the entity ID in the IdP's metadata), the IdP Single Sign-On URL and the uploaded IdP Certificates that verify the IdP's digital signature; the SP Entity ID to give the IdP is copied from the console. [zidentity.overview.external-idps.configuration:saml-inputs] An uploaded SAML IdP certificate must be in base-64 encoded PEM format, with a .pem extension and no other periods in the file name; more than one IdP certificate can be uploaded if required. [zidentity.overview.external-idps.configuration:idp-certificate-format] The help says to select Sign SAML response and assertion as the signing option on the IdP because Authentication Service does not process any SAML response that is not signed. [zidentity.overview.external-idps.configuration:signed-responses-only] A SAML IdP's advanced options are SAML Request Signing (its Signing Algorithm shows only when signing is enabled), Login Hint (includes the login ID in the SAML authentication request), Encrypted SAML Assertion, and up to 2 generated request signing and decryption certificates. [zidentity.overview.external-idps.configuration:saml-advanced]

**Signing and decryption certificates.** A Request Signing and Decryption Certificate is added from the Edit Primary or Secondary IdP page with two years of validity; at most two exist at a time, of which only one can be active, an active one cannot be deleted, and each certificate shows a serial number and can be downloaded, possibly for upload to the IdP. [zidentity.overview.external-idps.configuration:signing-certificate-lifecycle] The expiry banner and icons are in [The console shows a banner when an IdP certificate or SAML request signing and decryption certificate expires within 90 days or has expired, and marks enabled SAML certificates with a caution icon when expiry is within 90 days and a red exclamation mark once expired.](kb:zidentity.overview.external-idps:cert-warnings). Deleting a SAML IdP asks the admin to read the confirmation message and enter CONFIRM before clicking Delete. [zidentity.overview.external-idps.configuration:delete-confirm]

**Admin MFA.** The Enforce Zscaler MFA for Admins option makes admins who use an external IdP authenticate with MFA in Authentication Service, whether or not MFA is configured on the external IdP; an email is sent to all super admins in Authentication Service when the option is disabled. [zidentity.overview.external-idps.configuration:enforce-admin-mfa] Whether it starts enabled is open [gap:zidentity.overview.external-idps.configuration:enforce-mfa-default]. Where the console shows it per IdP: [The External Identities page shows, for the primary IdP and for each secondary IdP, whether Authentication Service MFA is enabled or disabled for admins.](kb:zidentity.overview.external-idps:admin-mfa-per-idp).

**Identity Proxy.** When configuring Zscaler Identity Proxy for Cloud Apps, the Is Device Managed session attribute must be mapped to the appropriate IdP attribute, on both the OIDC and the SAML page, and the managed devices settings configured in the Zscaler Admin Console. [zidentity.overview.external-idps.configuration:identity-proxy-device-attribute]

**IdP-initiated sign-in and admin redirect.** For IdP-initiated SSO the value of the idp_id URL parameter is default when the IdP is the primary IdP and, for a secondary IdP, comes from the final segment of its Redirect URI (the Entra ID guide's Home page URL form is `https://<your_domain>.zslogin.net/?idp_id=default` or `...?idp_id=<final_segment_from_redirect_URI>`); the Okta guide uses it for Initiate Login URI and the OneLogin guide for Login URL, with the same two forms. [zidentity.overview.external-idps.configuration:idp-initiated-login-url] The Okta and Auth0 guides say all admins authenticating with SAML for Authentication Service and IdP integrations are redirected to Experience Center, unless the zidServiceId attribute is configured in the IdP within the Authentication Service tenant, in which case they go to the Authentication Service Admin Portal; the Okta guide gives its value as 800000000103, the same for all tenants, and the Entra ID guide scopes the claim to administrator groups and says to contact Zscaler Support to change the default redirection. [zidentity.overview.external-idps.configuration:experience-center-redirect] Whether OIDC admins are redirected the same way is open [gap:zidentity.overview.external-idps.configuration:experience-center-oidc].

**Identity Vendor.** The vendor guides select these Identity Vendor values: Okta, Microsoft Entra ID, PingOne, PingFederate and OneLogin under their own names, Active Directory Federation Service (OIDC section) or Active Directory Federated Service (SAML section) for AD FS, and Others for Auth0. [zidentity.overview.external-idps.configuration:identity-vendor-values]

**Open.** What the SAML SP URL is [gap:zidentity.overview.external-idps.configuration:saml-sp-url], which signing algorithms SAML Request Signing offers [gap:zidentity.overview.external-idps.configuration:signing-algorithms], and what happens at certificate expiry and secret expiry [gap:zidentity.overview.external-idps.configuration:certificate-expiry-behavior] are not stated.

What to check:
1. For an IdP whose users arrive under the wrong IdP, whether its Domains match the domain part of the login ID, and whether the Login ID Attribute is the attribute the IdP actually sends.
2. For a SAML IdP that rejects sign-in, whether the IdP signs both the SAML response and the assertion.
3. For IdP-initiated sign-in, whether the IdP is the primary (idp_id default) or a secondary (the last segment of its Redirect URI).
