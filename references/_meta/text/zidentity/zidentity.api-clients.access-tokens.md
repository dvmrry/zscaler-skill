# ZIdentity-issued access tokens: the Tokens page, when tokens are revoked, and who can revoke them (zidentity.api-clients.access-tokens)
Also called: revoke access token zidentity; authentication service issued tokens; token revoked api client disabled; revoke oneapi token; jti api client token; disabled api client token still works

Access tokens are JSON web tokens that OneAPI verifies before allowing an API client to reach a service's API resources, and they have limited validity. [zidentity.api-clients.access-tokens:jwt-limited-validity] How a client requests a token and presents it is in [How a client gets and uses a OneAPI access token](kb:shared.oneapi.authentication); its lifetime is set per client: [`accessTokenLifeTime` is the lifetime of the access token issued to the client, between 60 and 86400; the create description gives it in seconds and its example as "60 for 60 minutes".](kb:zidentity.api-clients:lifetime-range).

**The Tokens page.** The Authentication Service Issued Tokens page lists each token with its client ID, JTI, issued and expiry times and status (Active, Revoked or Expired), and can be filtered by issue time, expiry time and status and searched by client ID or JTI. [zidentity.api-clients.access-tokens:tokens-page]

**When a token is revoked.** A token is marked revoked when the API client it was assigned to is deleted, when that client's status is disabled, or when an administrator revokes it on the Tokens page; after re-enabling the client (or for a revoked token whose client is enabled) a new token can be generated. [zidentity.api-clients.access-tokens:revoked-states] Only active tokens can be revoked; an admin revokes one from the Tokens page by clicking Revoke for it and confirming with CONFIRM. [zidentity.api-clients.access-tokens:revoke-procedure] A revoked access token can no longer be used to access the Zscaler API resources; a new token has to be generated. [zidentity.api-clients.access-tokens:revoked-unusable]

**Through the API.** An access token can be revoked only by admins. [zidentity.api-clients.access-tokens:admins-only] Tokens cannot be revoked through the API: the contract has no token operation, [The contract has no operations for access tokens (listing or revoking them) or for API client access policy rules; those are managed only in the Admin Console as far as the captured sources show.](kb:zidentity.api:no-token-or-policy-paths).

What to check:
1. For a client that stopped working, the token's status on the Tokens page (searched by client ID or JTI): Revoked, Expired or Active.
2. For a leaked token, whether it was revoked on the Tokens page, or the client disabled, which also revokes its tokens.
