# Legacy Business Insights admin authentication: password expiration, SCIM, SAML, IdP guides and sign-in OTP timeouts (business-insights.legacy.authentication)
Also called: business insights saml; business insights scim; business insights admin password expiration; business insights okta saml; business insights entra id saml

**Password expiration.** In the legacy Business Insights help, Password expiration for admins is optional, and when enabled the validity defaults to 180 days (range 15 to 365 days) with a reminder when 15 days remain; for an account subscribed to Authentication Service, the Administrator Management page links to the Authentication Service Admin Portal, from which admins can be managed. [business-insights.legacy.authentication:password-expiration] In the legacy Business Insights help, Password expiration is not enforced for SAML-based admins, and admin passwords never expire when the setting is not enabled. [business-insights.legacy.authentication:password-expiration-saml] In the legacy Business Insights help, After a password expires an admin must register a new password that differs from the previous one and has at least 8 characters with an uppercase letter, a number and a special character. [business-insights.legacy.authentication:password-expiration-rules]

**SCIM.** In the legacy Business Insights help, The Admin Account Action When SCIM Deletes Linked User Account is Delete (SCIM deletes the admin and its linked user account) or Do Nothing, which is the default and makes SCIM return error 409 (Admin user cannot be deleted); for an account subscribed to Authentication Service, the Administrator Management page links to the Authentication Service Admin Portal, from which admins can be managed. [business-insights.legacy.authentication:scim-delete-action] In the legacy Business Insights help, Disabling an admin's user account through SCIM disables both the admin and its linked user account, and the delete-action setting affects only deleted users, not disabled users. [business-insights.legacy.authentication:scim-scope]

**SAML.** In the legacy Business Insights help, Admin SAML is IdP-initiated and supports SAML 2.0 and later, admins are not added through auto-provisioning, and Zscaler recommends at least one super admin with password authentication enabled in case external SAML servers are unreachable; for an account subscribed to Authentication Service, the Administrator Management page links to the Authentication Service Admin Portal, from which admins can be managed. [business-insights.legacy.authentication:saml-support] In the legacy Business Insights help, Before configuring admin SAML, create the admin accounts, configure an IdP with the relay state field specified, and obtain the IdP's SAML certificate. [business-insights.legacy.authentication:saml-prerequisites] In the legacy Business Insights help, The IdP SAML certificate is the base-64 encoded PEM format, and its file name must be alphanumeric without spaces and have a .pem or .cer extension without other periods. [business-insights.legacy.authentication:saml-certificate-format]

**Okta.** In the legacy Business Insights help, In the Okta SAML guide, the Single sign-on URL and Audience URI (SP Entity ID) are both https://admin.zscaleranalytics.net/idp-auth and the Default RelayState is the Business Insights cloud name. [business-insights.legacy.authentication:saml-okta-urls] In the legacy Business Insights help, In the Okta SAML guide, the certificate to upload is the SHA-2 type SAML signing certificate downloaded with Actions > Download certificate. [business-insights.legacy.authentication:saml-okta-certificate] The SP entity ID differs from the Entra ID guide [divergence:business-insights.legacy.authentication:sp-entity-id].

**Microsoft Entra ID.** In the legacy Business Insights help, In the Microsoft Entra ID SAML guide, the Identifier (Entity ID) is https://admin.zscaleranalytics.net, the Reply URL is https://admin.zscaleranalytics.net/idp-auth, and the Relay State is the Business Insights cloud name and is mandatory. [business-insights.legacy.authentication:saml-entra-urls] In the legacy Business Insights help, The Microsoft Entra ID guide creates the application from the Zscaler Internet Access Administrator tile and requires the Unique User Identifier (Name ID) source attribute to be user.mail, and the certificate is the Base64 certificate. [business-insights.legacy.authentication:saml-entra-app]

**Sign-in OTP.** In the legacy Business Insights help, In the first sign-in flow described for an Authentication Service-enabled account configured with MFA, an email OTP expires after two minutes and Resend is available after 60 seconds. [business-insights.legacy.authentication:auth-service-otp-flow-a] In the legacy Business Insights help, In the section for an Authentication Service subscription, for an account configured with MFA the OTP sent to the admin's email address expires after 15 minutes and Resend is available after 60 seconds. [business-insights.legacy.authentication:auth-service-otp-flow-b] The OTP lifetimes differ [divergence:business-insights.legacy.authentication:otp-expiry], and so do the reset link lifetimes [divergence:business-insights.legacy.authentication:reset-link-expiry].

In the legacy Business Insights help, the Account item in the Admin Portal navigation shows the username, cloud name and organization ID and points to Managing Your Admin Account, whose My Profile page displays the cloud name; the Okta guide places the cloud name on the My Profile page and the Entra ID guide on the Account page. [business-insights.legacy.authentication:cloud-name-location] Admin accounts, roles and scope are in [Legacy Business Insights admin portal: activation, profile, remote assistance, roles, admins, audit logs and ZIA sync pages](kb:business-insights.legacy.admin); the area hub is [Legacy Business Insights help: architecture, data sources and terminology (hub)](kb:business-insights.legacy).

Sources disagree (name both sides):
- The two sign-in flows for an Authentication Service account configured with MFA give different email OTP lifetimes. [divergence:business-insights.legacy.authentication:otp-expiry]
  - zscaler-help: In the flow for an Authentication Service-enabled account, the email OTP expires after two minutes.
  - zscaler-help: In the section for an Authentication Service subscription, the email OTP expires after 15 minutes.
  Impact: The email OTP lifetime for an Authentication Service account is two minutes in one flow and 15 minutes in the other; the page does not say which applies.
- The two sign-in flows for an Authentication Service account give different password and second-factor reset link lifetimes. [divergence:business-insights.legacy.authentication:reset-link-expiry]
  - zscaler-help: In the flow for an Authentication Service-enabled account, the reset link in the email expires after 5 minutes.
  - zscaler-help: In the section for an Authentication Service subscription, the reset link expires after 15 minutes.
  Impact: The reset link lifetime for an Authentication Service account is 5 minutes in one flow and 15 minutes in the other; the page does not say which applies.
- The Okta and Microsoft Entra ID guides give different values for the Business Insights SAML service provider entity ID. [divergence:business-insights.legacy.authentication:sp-entity-id]
  - zscaler-help: The Okta guide sets the SP Entity ID to https://admin.zscaleranalytics.net/idp-auth.
  - zscaler-help: The Microsoft Entra ID guide sets the Identifier (Entity ID) to https://admin.zscaleranalytics.net, with no path.
  Impact: Whether the entity ID carries the /idp-auth path differs between the two IdP guides; the single sign-on and reply URLs both use /idp-auth.
