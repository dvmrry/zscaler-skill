# How Zero Trust Branch logs traffic: architecture, log types and formats, retention and limits, throttling and tenant isolation (zero-trust-branch.operations.logging)
Also called: ztb logs; ztb packet logs; ztb flow logs; ztb log retention; ztb log throttling; ztb analytics data lake

Logging is built on an Analytics Data Lake with two subsystems, the Ingestion and Analytics Engine and the Analytics Data Store, with one engine instance deployed per Zero Trust Branch management instance. [zero-trust-branch.operations.logging:log-architecture] Customer logs are isolated per tenant through dedicated ingestion tables for graph-generation data, separate Analytics Data Store spaces for packet and flow logs, individual cloud storage buckets for syslogs, and dedicated tables for alarms and notifications. [zero-trust-branch.operations.logging:tenant-log-isolation] The wider operations area is in [Where Zero Trust Branch operations are documented: forwarding, Routed Tunnels, segmentation, integrations, logging, monitoring, the Debug Console, troubleshooting and upgrades](kb:zero-trust-branch.operations).

**Log types and formats.** Appliances capture packet logs (all captured packet headers that hit any policy, per packet) and flow logs (session flow details for a source/destination pair and a policy/action set), found under Data Explorer > Zero Trust Branch. [zero-trust-branch.operations.logging:packet-vs-flow-logs] The SIEM page gives a different count of traffic log types [divergence:zero-trust-branch.operations.logging:traffic-log-type-count]. Logs are stored as structured JSON, entries include key fields such as IPTables data and tunnel information, and logs can be exported in JSON or CSV. [zero-trust-branch.operations.logging:stored-log-format] In a traffic log line, the tenant, site and gateway names are joined by double hyphens, the policy name, policy ID and policy action by a hyphen, and the destination and source MAC addresses by a colon. [zero-trust-branch.operations.logging:traffic-log-fields] The SIEM page's count of traffic log types is in [How Zero Trust Branch integrates with other systems: API keys, SIEM syslog, CrowdStrike, Armis and SentinelOne](kb:zero-trust-branch.operations.integrations).

**Retention and limits.** The Analytics Data Store keeps packet logs and flow logs in dedicated tenant spaces and retains logs for up to 7 days. [zero-trust-branch.operations.logging:data-store-retention] Session logs (including flow records) are retained for 7 days by default; longer retention is through export to external SIEM platforms or an extended retention request under the master service agreement. [zero-trust-branch.operations.logging:session-log-retention] The overview and the SIEM page differ on how logs reach a SIEM [divergence:zero-trust-branch.operations.logging:siem-export-path]. The Admin Console displays up to 500 log entries at a time and exported log files can be up to 10 MB; Private Access (ZPA)-related logs do not appear in the Admin Console and are available only in Private Access diagnostics. [zero-trust-branch.operations.logging:console-export-limits] Each node in a traffic chart can represent up to 200 neighboring connections. [zero-trust-branch.operations.logging:traffic-chart-node-limit] The product-level retention terms are in [How long Zscaler keeps the logs of the products on the Logs and Fair Use pages, and where it stores them](kb:shared.logs-fair-use.log-retention).

**Timing and volume.** Flow logs are near real time, but traffic charts need to collect and compile the data, so a 5- to 7-minute delay is expected in traffic charts. [zero-trust-branch.operations.logging:flow-log-delay] The traffic chart delay is given differently on the traffic flow chart page [divergence:zero-trust-branch.operations.logging:traffic-chart-delay]. By default Zscaler logs a traffic flow once per hour per 4-tuple (source IP address, destination IP address, destination port, protocol) for each policy match, throttling is enabled by default in Firewall and Segmentation policies for east–west traffic, and Disable Log Throttling on a policy gives more verbose logging. [zero-trust-branch.operations.logging:log-throttling] Logging levels are Info (the default), Warning, Error and Debug, and Debug produces significantly more logs and is typically enabled only during targeted troubleshooting. [zero-trust-branch.operations.logging:logging-levels] Where a logging level is set is open [gap:zero-trust-branch.operations.logging:logging-level-setting]. The traffic chart is in [How Zero Trust Branch is monitored: the Insights dashboard, traffic flow chart, alarms, SNMP and interface health monitoring](kb:zero-trust-branch.operations.monitoring).

Sources disagree (name both sides):
- The log types page expects a 5- to 7-minute delay in traffic charts, while the traffic flow chart page says it can take up to 10 minutes after an event. [divergence:zero-trust-branch.operations.logging:traffic-chart-delay]
  - zscaler-help: Expect a 5- to 7-minute delay in traffic charts.
  - zscaler-help: It can take up to 10 minutes after an event before traffic is reflected in the traffic flow chart.
  Impact: A chart that is still empty 8 minutes after an event is within one page's stated range but past the other's; treat up to 10 minutes as the outer bound before investigating.
- The log types page says appliances capture two traffic log types, packet logs and flow logs, while the SIEM integration page says Zero Trust Branch generates only one type of traffic log, the session-init logs. [divergence:zero-trust-branch.operations.logging:traffic-log-type-count]
  - zscaler-help: Appliances capture two primary types of traffic logs: packet logs and flow logs.
  - zscaler-help: Zero Trust Branch generates only one type of traffic log, the session-init logs, which are the logs exported to the SIEM server.
  Impact: What reaches a SIEM is session-init logs; whether they correspond to the packet logs, the flow logs or both is not stated, so do not assume the SIEM receives both log types shown in Data Explorer.
- The logging and monitoring overview says logs are exported to external SIEM platforms via the API, while the SIEM integration page says the appliance sends syslog messages directly to the configured syslog server. [divergence:zero-trust-branch.operations.logging:siem-export-path]
  - zscaler-help: Logs can be exported to external SIEM platforms via the API.
  - zscaler-help: The appliance sends syslog messages directly to the configured syslog server.
  Impact: Which path carries SIEM logs, and so where to open firewall access, is not settled by the pages.
