# How Zero Trust Branch segments devices: Airgap, Airgap-Lite and Airgap+ protection, /32 incompatibilities, assets, tags, the NAC MAC list and the Ransomware Kill Switch (zero-trust-branch.operations.segmentation)
Also called: ztb airgap; ztb airgap-lite; ztb airgap plus; ztb /32 incompatible devices; ztb ransomware kill switch; ztb asset quarantine; ztb tags; ztb nac mac list

Zero Trust Branch offers three protection solutions: Airgap assigns a /32 network mask to endpoints, Airgap-Lite uses the same subnet mask the DHCP server provides, and Airgap+ implements micro-subnets with subnet masks between /27 and /30. [zero-trust-branch.operations.segmentation:protection-solutions] Airgap is ideal for environments that require complete isolation between endpoints with all traffic routed through the appliance, and some systems might not support /32 masks because of hardware or software limitations. [zero-trust-branch.operations.segmentation:protection-airgap-use] Where the /32 subnet mask is not supported, admins can choose Airgap+ or Airgap-Lite (if full isolation is not a strict requirement). [zero-trust-branch.operations.segmentation:protection-alternatives-no-32] The listed trade-offs are that Airgap-Lite reduces isolation as compared to Airgap and that Airgap+ adds configuration and maintenance complexity as multiple subnets are managed. [zero-trust-branch.operations.segmentation:protection-tradeoffs] The wider operations area is in [Where Zero Trust Branch operations are documented: forwarding, Routed Tunnels, segmentation, integrations, logging, monitoring, the Debug Console, troubleshooting and upgrades](kb:zero-trust-branch.operations).

**Airgap-Lite.** Device-level Airgap-Lite is set in the Security section of the asset's Properties tab, with the Protection field set to Airgap-Lite, and then the device releases and renews its DHCP lease; the micro-subnets page says to select Network from the Segmentation Granularity drop-down menu. [zero-trust-branch.operations.segmentation:airgap-lite-device] VLAN-level Airgap-Lite enables the mode for multiple devices simultaneously and is set in the Network section of the Edit Airgap VLAN drawer by selecting ON (Airgap-Lite) for DHCP Service. [zero-trust-branch.operations.segmentation:airgap-lite-vlan] After a VLAN-level change, each device in the VLAN runs a DHCP lease release command and then a command to request a new IP address from the DHCP server; the device-level steps also end with a lease release and a request for a new IP address in the device terminal. [zero-trust-branch.operations.segmentation:airgap-lite-vlan-renew] A device running in Airgap-Lite mode shows no check mark in its Airgapped column. [zero-trust-branch.operations.segmentation:airgap-lite-indicator]

**Airgap+.** Airgap+ requires the appliance to operate in server mode for the associated VLAN(s) and is available starting with Airgap OS 7.7.6. [zero-trust-branch.operations.segmentation:airgap-plus-requirements] The micro-subnet layout is in [How Zero Trust Branch Airgap+ micro-subnets work: address layout, DHCP server requirement, VLAN fields and CSV import](kb:zero-trust-branch.operations.micro-subnets).

**Devices that do not work with /32.** Field testing identified Amazon Blink cameras, Apple AirPort Time Capsules, Cisco devices, the LaMetric Connected Clock, legacy HVAC controllers and devices, network printers, Siemens S7 and Rockwell/Allen-Bradley PLCs and EtherNet/IP adapters, and Sonos devices as incompatible with /32 IP configurations; others not listed may behave similarly. The page qualifies several entries: some older versions of Blink cameras might have connectivity and functionality issues, some Cisco devices (such as routers, switches, access points, wireless LAN controllers and IP phones) might not handle /32 segmentation correctly, and certain firmware versions of the LaMetric clock have connectivity problems with /32 addresses, and most printers accept subnet mask configuration in the user interface. [zero-trust-branch.operations.segmentation:ip32-incompatible-devices] For network printers, services such as Bonjour, Line Printer Daemon (LPD) and Server Message Block discovery might break if they cannot communicate with gateway or multicast neighboring endpoints. [zero-trust-branch.operations.segmentation:ip32-printers] Siemens S7 family and Rockwell/Allen-Bradley EtherNet/IP modules expect devices and programming tools to be on the same subnet using conventional subnet masks such as /24. [zero-trust-branch.operations.segmentation:ip32-plcs] Some endpoints that are Purdue Level 2 and below require direct Layer 2 connectivity to function correctly, such as communication between Programmable Logic Controllers (PLCs). [zero-trust-branch.operations.segmentation:ip32-purdue-l2] For devices that cannot operate reliably with /32 addressing, the page recommends deploying them under micro-subnet segmentation with subnet masks in the range of /27 to /30. [zero-trust-branch.operations.segmentation:ip32-workaround-micro-subnets] For devices that don't support /32 addressing where full isolation is not required, the page recommends configuring them with the same subnet mask that the DHCP server provides. [zero-trust-branch.operations.segmentation:ip32-workaround-dhcp-mask]

**Assets and tags.** Zero Trust Branch identifies assets automatically using techniques such as DHCP options, HTTP User-Agent, SSL fingerprint and mDNS, and integration with Armis improves accuracy; discovered assets are tagged automatically and integrated vendors add tags. [zero-trust-branch.operations.segmentation:asset-discovery-tags] Several devices can be edited at once with changes applying to all of them, and the Protection menu offers Airgap, Airgap-Lite and Airgap+. [zero-trust-branch.operations.segmentation:asset-edit] A quarantined device can access the internet but not the private networks, and inbound connectivity is allowed so an admin can connect to it remotely. [zero-trust-branch.operations.segmentation:asset-quarantine] Rather than scanning and discovery, a CSV list of MAC addresses can be uploaded and is used to verify and authenticate devices during NAC; the template has two fields, MAC address and a description, Validate previews the data and Submit adds the devices. [zero-trust-branch.operations.segmentation:nac-mac-upload] Tags let policies be written without IP addresses; they come from auto tagging on auto-discovery, third-party integration (for example Armis) and manual tagging. [zero-trust-branch.operations.segmentation:tag-sources] In the page's example, a tag called microsoft windows kernel 6.1 is applied to Windows 7/Server 2008 machines and used as the source of a policy, so IP address changes need no policy change. [zero-trust-branch.operations.segmentation:tag-example] Third-party discovery integrations are in [How Zero Trust Branch integrates with other systems: API keys, SIEM syslog, CrowdStrike, Armis and SentinelOne](kb:zero-trust-branch.operations.integrations).

**Ransomware Kill Switch.** The Ransomware Kill Switch sets a site's threat level to one of four preset severities: Green (lowest threat level), Yellow (moderate risk), Orange (high risk) and Red (critical risk). [zero-trust-branch.operations.segmentation:rks-levels] A threat level change is confirmed by typing the new level's name and takes effect immediately, and Notification Settings customizes an email template sent on a change to one or more addresses. [zero-trust-branch.operations.segmentation:rks-confirm-notify] When creating a site-level firewall policy for device segmentation you must assign one or more Ransomware Kill Switch threat level color codes, and during an incident only the firewall policies associated with the selected threat level color code are evaluated top-down, stopping at the first matching policy. [zero-trust-branch.operations.segmentation:rks-policy-evaluation] The Hit Count column on the Site Policies tab indicates the number of times a policy was accessed. [zero-trust-branch.operations.segmentation:rks-hit-count] The Ransomware Kill Switch configuration can be fully controlled via APIs for integration with SIEM, SOAR, EDR and XDR systems, and MQTT is used to publish policy updates, configuration changes and Kill Switch changes. [zero-trust-branch.operations.segmentation:rks-api-mqtt] The interfaces and per-tier behavior are not in the captured pages [gap:zero-trust-branch.operations.segmentation:rks-interfaces-and-tiers].
