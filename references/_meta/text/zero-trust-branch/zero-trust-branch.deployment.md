# How a Zero Trust Branch appliance is deployed: activation, ZTP, virtual machines, mainland China, upgrades and admin roles (zero-trust-branch.deployment)
Also called: ztb deployment; deploying a zero trust branch appliance; zero touch provisioning; ZTP; Appliance Version Manager; ztb activation code; ztb vm esxi

Each site uses a single template, which defines the Zero Trust Branch model deployed at the site and settings such as DNS server address, DHCP service type, deployment type, platform and NAT enablement. [zero-trust-branch.deployment:one-template-per-site] The appliance models and their ports are in [Which Zero Trust Branch appliance models exist, how they mount and what their ports do](kb:zero-trust-branch.deployment.appliances), templates and sites in [How Zero Trust Branch templates and sites are configured: deployment types, DNS, DHCP, routing and App Connectors](kb:zero-trust-branch.deployment.templates-and-sites), VLANs in [How Zero Trust Branch VLANs are configured: zones, DHCP granularity, management interfaces and IP reservation](kb:zero-trust-branch.deployment.vlan), high availability and bonding in [How Zero Trust Branch high availability works: standard HA, Enhanced WAN Edge HA, VRRP and ebond bonding interfaces](kb:zero-trust-branch.deployment.high-availability), objects in [What Zero Trust Branch objects are and how each type is defined](kb:zero-trust-branch.deployment.objects) and forwarding and firewall policies in [How Zero Trust Branch forwarding (routing) policies and firewall (security) policies are defined and evaluated](kb:zero-trust-branch.deployment.policies). The product summary is in [Zero Trust Branch: what it is, how it forwards and segments, and how it is deployed](kb:zero-trust-branch.overview) and automation is in [Automating Zero Trust Branch: the Python SDK client, its API-key sign-in, and what no other client covers](kb:zero-trust-branch.api).

**Before activation.** Zscaler provisions the tenant; after that it sends the super admin an email invitation that must be accepted before the super admin can access Zero Trust Branch in the Zscaler Admin Console. [zero-trust-branch.deployment:tenant-provisioning] The appliance requires ports to be open on an upstream L3 device (a firewall or router) for initial activation and ongoing management. [zero-trust-branch.deployment:upstream-ports-requirement] The ports a hardware appliance needs are not in the captured deployment pages [gap:zero-trust-branch.deployment:hardware-activation-ports]. Interfaces with an asterisk are fixed and cannot be changed, even on cloned templates; GE4 is fixed in an HA deployment but can be used for LAN in a standalone deployment, and the other asterisked interfaces are fixed in standalone deployments as well. [zero-trust-branch.deployment:fixed-interfaces]

**Activation.** The serial console connection uses 115,200 baud, 8 data bits, 1 stop bit, no parity and XON/XOFF flow control. [zero-trust-branch.deployment:console-serial-params] Zscaler supports one subinterface per WAN interface, but activation is supported over the WAN main interface (which the page calls tagged), not over a subinterface (which the page calls untagged). [zero-trust-branch.deployment:activation-subinterface] The activation-code method uses the activation code saved when the site was added and requires configuring the appliance with the same parameters used when the site was created; the web proxy step is required only if the appliance is deployed behind a firewall. [zero-trust-branch.deployment:activation-code-method] The activation-URL method carries the WAN interface configuration and the activation code in the URL saved when the site was created; a laptop connected directly to the management port gets an IP address from the appliance. [zero-trust-branch.deployment:activation-url-method] After activation, the site State is Standalone for a standalone appliance, Active for the primary node of an HA cluster and Standby for the secondary node. [zero-trust-branch.deployment:site-state-values]

**After activation.** To process multiple VLANs, the switchport connected to the appliance's LAN-side interface must be a trunk port that allows the VLANs to be protected. [zero-trust-branch.deployment:lan-trunk-requirement] The deployment is not complete until the VLAN to be protected is enabled in the Zscaler Admin Console; for an existing production VLAN the default gateway IP must match the existing SVI address, and for an untagged port the VLAN ID is 1. [zero-trust-branch.deployment:vlan-enable-required] To verify the deployment, check that client traffic goes to the internet via Internet & SaaS (ip.zscaler.com) and that the Auto-provisioned Tunnels tab shows Status Up; editing the IPSec tunnel configuration is optional and only if directed by Zscaler Support. [zero-trust-branch.deployment:verify-deployment] After activation, the appliance automatically establishes an IPSec tunnel to Internet & SaaS (ZIA) through its configured WAN port; the default Zscaler routing policy allows traffic to be sent to Internet & SaaS, and the default (system) firewall policy allows traffic over LANs and WANs. [zero-trust-branch.deployment:post-activation-defaults]

**Virtual machine on ESXi.** The VM page gives two sizing options: 4 vCPU, 16 GB memory, 4 vNICs, 500K sessions and 500 endpoints, with 10 Gbps throughput for unencrypted LAN-to-LAN or LAN-to-WAN flows; or 8 vCPU, 32 GB, 8 vNICs, 1 million sessions and 1,000 endpoints, with 20 Gbps for the same flows; each with 256 GB storage. [zero-trust-branch.deployment:vm-sizing] In the VM port mapping, ge3 is Management, ge2, ge7 and ge8 are WAN, and ge1, ge4, ge5 and ge6 are LAN. [zero-trust-branch.deployment:vm-port-mapping] The ESXi VM wizard selects ESXi 6.7 compatibility, Linux guest OS family with Ubuntu Linux (64-bit), and EFI firmware. [zero-trust-branch.deployment:vm-esxi-settings] On ESXi, the LAN port group uses VLAN ID 4095 as a trunk group, with Promiscuous mode, MAC address changes and Forged transmits set to Accept; the WAN port group is an access group with a VLAN ID between 0 and 4094. [zero-trust-branch.deployment:vm-esxi-portgroups] The VM page says the ISO image is obtained from the Zscaler Admin Console in its prerequisites and from Zscaler Support in the wizard step. [zero-trust-branch.deployment:vm-iso-source] After activating a VM, the gateway runs background scripts for a few minutes during which the site State shows Post Update; when they finish, State changes to Standalone. [zero-trust-branch.deployment:vm-post-update-state]

**Virtual machine ports.** The VM deployment page lists TCP 443 outbound to gwactivation.goairgap.com for appliance activation and TCP 1883 outbound to hub3.goairgap.com for management-plane communication, each marked a mandatory requirement. [zero-trust-branch.deployment:vm-port-activation-mgmt] The management-plane host is named differently on another page [divergence:zero-trust-branch.deployment:management-hub-host]. The VM deployment page lists, as mandatory, TCP 443 outbound to dl.cloudsmith.io for software upgrades, TCP 443 outbound to gateway.<cloud>.net for WAN monitoring, and UDP 51820 outbound to wg.goairgap.com for remote debugging. [zero-trust-branch.deployment:vm-port-upgrade-debug-wanmon] The VM deployment page lists conditional ports: UDP 443 with access type Inbound and the public-routable IP address of the spoke appliance as host, for Routed Tunnels in a Hub-and-Spoke model; UDP 500, UDP 4500 and ESP (IP protocol 50) outbound if connecting to Internet & SaaS; TCP 443 outbound to config.zscaler.com/private.zscaler.com/zpa, prod.zpath.net and private.zscaler.com if connecting to Private Access (ZPA). [zero-trust-branch.deployment:vm-port-conditional] The VM deployment page lists UDP 53 outbound to the DNS service IP if specific DNS servers are used, and UDP 123 outbound to 0.pool.ntp.org through 3.pool.ntp.org if specific NTP servers are used. [zero-trust-branch.deployment:vm-port-optional-dns-ntp]

**Zero Touch Provisioning.** ZTP is supported on appliances running version 8.1.2 or later and is not supported for VM deployment. [zero-trust-branch.deployment:ztp-support] ZTP requires an appliance on 8.1.2 or later, an ISP link that supports DHCP, and the appliance serial number listed in the Appliance Inventory; ZTP does not work with static IP addresses. [zero-trust-branch.deployment:ztp-prerequisites] Appliance Inventory serial numbers are auto-populated during ordering; missing serial numbers are requested through Zscaler Support. [zero-trust-branch.deployment:appliance-inventory] For version 8.1.2, the ZTP-enabled WAN port is ge3 on ZT400, ge5 on ZT600, ge2 on ZT800 and ge2 on ZT8010; by default the gateway listens for ZTP only on the ZTP-enabled WAN ports, so the WAN cable must be connected to such a port before power-on. [zero-trust-branch.deployment:ztp-ports-8-1-2] For 8.1.2P1 and later, the ZTP-enabled WAN ports are ge3 (ZT400), ge5 and ge6 (ZT600), ge2 and ge7 (ZT800), and ge2 and xe7 (ZT8010). [zero-trust-branch.deployment:ztp-ports-8-1-2p1] The ZTP page lists default templates: ZT400 zt400-ha-default, zt400-standalone-default and zt400-standalone-dualwan-default; ZT600 zt600-ha-default, zt600-enhanced-ha-default and zt600-standalone-default; ZT800 and ZT8010 follow the same ha, enhanced-ha and standalone pattern. [zero-trust-branch.deployment:ztp-default-templates] The show ztp activation-state command confirms Authentication State true, ZTP Device true, the current ZTP server, serial number and TPM serial number for a correctly configured appliance, and show ztp tpm-attest validates the hardware identity against the TPM endorsement key certificate. [zero-trust-branch.deployment:ztp-verify]

**Mainland China.** Mainland China proxy use is supported for appliances on Zero Trust Branch 8.1.2-P1 and later; a support ticket with the appliance serial number requests support, and the appliance cannot connect to the proxy until it is authorized to do so. [zero-trust-branch.deployment:china-support] For mainland China, a dedicated connection proxy provides a premium connection to the cloud control plane; it is enabled in zscaler-console via option 1 Configure Appliance, option 3 Configure CNP Client. [zero-trust-branch.deployment:china-cnp]

**Upgrades.** The Appliance Version Manager page says release 8.0.7 introduced Appliance Version Manager, a full image-based upgrade system that supports downgrades, and that before 8.0.7 the legacy incremental method upgraded only selected packages and did not support downgrades. [zero-trust-branch.deployment:avm-intro] The Appliance Version Manager page says appliances on version 8.0.7 or later support both the legacy and Root FS-based Appliance Version Manager methods, and that from version 8.1.1 only the Root FS-based Appliance Version Manager is supported. [zero-trust-branch.deployment:avm-methods] An image upgrade has two stages: downloading and installing the image, which needs no downtime, and activating it, which needs a reboot during scheduled downtime. [zero-trust-branch.deployment:avm-two-stages] The Appliance Version Manager page says it stores up to three image versions (8.0.7 or later); one downloaded image is always the default (factory default) image, which cannot be deleted and is what the appliance rolls back to on a factory reset. [zero-trust-branch.deployment:avm-three-images] A factory reset (UI Delete Site, UI RMA, or airgap-console factory-reset) erases the data partition and restores the factory default Root FS. [zero-trust-branch.deployment:avm-factory-reset] Image downgrade is supported up to version 8.0.7; for an Active/Standby pair, downgrade the Standby appliance first, switch over and validate, then downgrade the Active one. [zero-trust-branch.deployment:avm-downgrade]

**Admin roles.** Zero Trust Branch has no custom roles; the predefined roles are Super Admin, Network Admin, Security Admin and Viewer. [zero-trust-branch.deployment:rbac-predefined-roles] The super admin has full access to security policy configuration, network settings, site and template management and user account creation, and can audit system logs, apply firmware updates, initiate failover and restore the system. [zero-trust-branch.deployment:rbac-super-admin] The network admin role operates independently of the platform's security policy configurations; the security admin can initiate device quarantine and trigger the Ransomware Kill Switch; the viewer cannot alter any configuration settings. [zero-trust-branch.deployment:rbac-role-scope] Beginning with version 8.0.1, Zero Trust Branch uses Authentication Service as its sole identity and authentication management service; users and groups are managed in the Zscaler Admin Console under the Zero Trust Branch service. [zero-trust-branch.deployment:rbac-identity]

What to check:
1. Whether the appliance runs 8.1.2 or later, has a DHCP ISP link and is listed in the Appliance Inventory, and that it is not a VM, before choosing ZTP.
2. Which upgrade method the appliance's version supports according to the Appliance Version Manager page: legacy and Root FS-based on 8.0.7 or later, Root FS-based only from 8.1.1.
3. Whether the VLAN to be protected is enabled in the Zscaler Admin Console, since the deployment is not complete until it is.

Sources disagree (name both sides):
- The VM deployment page names hub3.goairgap.com for TCP 1883 management-plane traffic, while the activation-issues page names hub.goairgap.com for the same port. [divergence:zero-trust-branch.deployment:management-hub-host]
  - zscaler-help: TCP 1883 outbound goes to hub3.goairgap.com for management-plane communication.
  - zscaler-help: The appliance must be allowed outbound connections to hub.goairgap.com on TCP 1883.
  Impact: An upstream firewall rule written from one page may omit the host the other page names.
