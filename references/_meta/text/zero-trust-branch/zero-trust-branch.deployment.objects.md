# What Zero Trust Branch objects are and how each type is defined (zero-trust-branch.deployment.objects)
Also called: ztb objects; ztb user defined groups

Objects are managed in three categories: user-defined, system default, and Microsoft Active Directory objects, which are synced automatically if an AD server is integrated with a site. [zero-trust-branch.deployment.objects:object-categories] The Managing Objects page says user-defined, system default objects can be viewed, edited, cloned or deleted and Microsoft AD objects are read-only, and that deleting an object requires entering DELETE in the confirmation window; the About Objects page lists 'Access details of the object.' among the steps for managing custom objects on its System Default Groups tab. [zero-trust-branch.deployment.objects:object-ad-readonly] The deployment hub is [How a Zero Trust Branch appliance is deployed: activation, ZTP, virtual machines, mainland China, upgrades and admin roles](kb:zero-trust-branch.deployment) and the policies that use objects are in [How Zero Trust Branch forwarding (routing) policies and firewall (security) policies are defined and evaluated](kb:zero-trust-branch.deployment.policies).

**Objects page.** In the objects type table (columns Firewall Policies, Routing Policies, DNS Policies), MAC Address is listed as Source for firewall and routing policies and Not applicable for DNS policies, Time Schedule as Time Schedule Groups for firewall policies only, and DNS Gateway as DNS Gateways for DNS policies only. [zero-trust-branch.deployment.objects:object-types-policy-fields] The Objects page lists objects 5, 10, 25 or 100 per page, shows a Policies count of security, forwarding and DNS policies that use each object, and Dynamic applies only to device objects (quoted from the User Defined Groups list). [zero-trust-branch.deployment.objects:object-page-paging]

**Object types.** A device object groups devices by attribute (manufacturer, operating system, services, network or tags); Dynamic automatically adds newly discovered assets matching the attributes. [zero-trust-branch.deployment.objects:object-device] A domain object takes wildcard domains or FQDNs; top-level domains (e.g., example.com) are not supported, and Any Domain matches *.*; predefined domain objects include All Zscaler App Segments and All Zscaler Domains. [zero-trust-branch.deployment.objects:object-domain] A network object holds CIDR blocks or FQDNs; non-CIDR IP ranges are converted to CIDR, and an FQDN is resolved locally by the appliance and refreshed when the DNS record TTL expires. Member Groups make a super object. [zero-trust-branch.deployment.objects:object-network] A port object accepts protocol:port-number pairs (e.g., udp:8080), protocol:port-range pairs (e.g., TCP:1024-1030) and well-known protocols (e.g., bgp); the Adding Objects page lists zone object types LAN, WAN, Management and HA. [zero-trust-branch.deployment.objects:object-port-zone] The pages disagree on which zones a policy takes [divergence:zero-trust-branch.deployment.objects:policy-zone-types]. A time schedule object combines absolute and periodic time ranges within a time zone and is referenced as time schedule group criteria in security policies; the Adding Objects page says a SaaS Apps object is a list of predefined SaaS apps usable as a destination in security policies or an application-based forwarding policy. [zero-trust-branch.deployment.objects:object-time-saas] The pages disagree on whether a SaaS Apps object applies to forwarding policies, see [How Zero Trust Branch forwarding (routing) policies and firewall (security) policies are defined and evaluated](kb:zero-trust-branch.deployment.policies).

**Gateway objects.** A DNS gateway object holds DNS servers used as redirect targets in a DNS policy rule, with On Failure either forwarding to the original DNS server or returning an error response. [zero-trust-branch.deployment.objects:object-dns-gateway] An Internet & SaaS Gateway object sets primary and secondary Service Edge choices and On Failure Fail-Close (Drop) or Fail-Open (Allow), where Fail-Open allows outbound traffic when both Service Edges are unreachable without inspection; Manual data-center selection requires appliance version 8.3.0 or later. [zero-trust-branch.deployment.objects:object-ziagw-failure]

What to check:
1. Whether the object is a Microsoft Active Directory object, which is read-only, before trying to edit or delete it.
2. Whether the appliance runs 8.3.0 or later before relying on manual data-center selection in an Internet & SaaS Gateway object.

Sources disagree (name both sides):
- The Adding Objects page lists Management and HA zone object types, while the security policy page offers only LAN or WAN zones for the source and destination zone. [divergence:zero-trust-branch.deployment.objects:policy-zone-types]
  - zscaler-help: Zone objects can be LAN, WAN, Management or HA zones.
  - zscaler-help: A security policy's source and destination zone is a LAN or WAN zone.
  Impact: A Management or HA zone object may not be usable as a security policy zone.
