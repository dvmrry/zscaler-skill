# How Zero Trust Branch Airgap+ micro-subnets work: address layout, DHCP server requirement, VLAN fields and CSV import (zero-trust-branch.operations.micro-subnets)
Also called: ztb micro-subnets; ztb airgap+ range start; ztb microsegments

Some Purdue Level 2 and below endpoints require direct L2 connectivity, and Zero Trust Branch identifies and whitelists such endpoints in a special group called Airgap+ and continuously monitors them. [zero-trust-branch.operations.micro-subnets:airgap-plus-purdue] Micro-subnets support masks /27 through /30 and reserve three addresses (network, gateway, broadcast); a /29 gives 8 addresses with 5 left for endpoints. [zero-trust-branch.operations.micro-subnets:mask-range-reserved] The three protection solutions are compared in [How Zero Trust Branch segments devices: Airgap, Airgap-Lite and Airgap+ protection, /32 incompatibilities, assets, tags, the NAC MAC list and the Ransomware Kill Switch](kb:zero-trust-branch.operations.segmentation).

**Requirements and traffic.** Airgap+ is supported only in DHCP server mode, and uses the Zero Trust Branch DHCP server because the micro-subnet allocation must be known to the server. [zero-trust-branch.operations.micro-subnets:dhcp-server-only] Devices in the same micro-subnet communicate directly, and any micro-subnet-to-micro-subnet or external traffic is always routed through the appliance. [zero-trust-branch.operations.micro-subnets:boundary-enforcement]

**Configuring a VLAN.** Enabling Airgap+ on a VLAN takes a Netmask, an Airgap+ Range Start (the network address of the first micro-subnet) and an Airgap+ Range End (the broadcast address of the last micro-subnet). [zero-trust-branch.operations.micro-subnets:vlan-airgap-plus-fields] The Airgap range cannot overlap with Airgap+; in the page's example 10.90.10.8 to 10.90.10.23 defines the /29 micro-subnets, and 10.90.10.x/24 endpoints outside the Airgap+ range are assigned /32 addresses. [zero-trust-branch.operations.micro-subnets:range-overlap] Airgap+ suits deployments where some endpoints cannot get a /32 mask and the device IP address is flexible enough to fit the available micro-subnets; if the IP address is not flexible, Airgap-Lite is used by changing the protection at the asset level; the page's own asset-edit steps instead select Network from a Segmentation Granularity drop-down menu. [zero-trust-branch.operations.micro-subnets:suitability] In the page's example, the IP addresses of the Airgap+ endpoints vlan10-dev3 and vlan10-dev4 are used from the CSV file, while for vlan10-dev1 and vlan10-dev2, which are not part of the micro-subnet, the IP address field is empty and the /32 IP address is assigned by the DHCP server.
