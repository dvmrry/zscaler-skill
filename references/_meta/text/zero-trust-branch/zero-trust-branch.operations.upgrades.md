# How Zero Trust Branch appliance software upgrades run: standalone and HA workflow, the Root FS method and upgrade statuses (zero-trust-branch.operations.upgrades)
Also called: ztb software upgrade; ztb ha upgrade; ztb root fs upgrade; ztb upgrade status post-update; ztb site state standalone

The Sites page in the Zscaler Admin Console shows an Upgrade available button to indicate that a site is eligible for upgrade. [zero-trust-branch.operations.upgrades:upgrade-available-button] Upgrading a standalone appliance briefly interrupts traffic forwarding while it reboots, with no failover because there is no secondary appliance. [zero-trust-branch.operations.upgrades:standalone-interruption] In an HA pair the standby appliance B is upgraded first and becomes Active, then appliance A is upgraded, and both remain in their new Active and Standby states. [zero-trust-branch.operations.upgrades:ha-staged-order] For versions 8.0.7 or later HA appliances need not run the same version, so one can be upgraded and tested first, and an appliance can be reverted to the old version if errors occur after upgrading. [zero-trust-branch.operations.upgrades:ha-mixed-versions] The same page and the HA upgrade page differ on whether the second appliance waits for a test [divergence:zero-trust-branch.operations.upgrades:ha-second-upgrade-start]. The Appliance Version Manager and downgrades are in [How a Zero Trust Branch appliance is deployed: activation, ZTP, virtual machines, mainland China, upgrades and admin roles](kb:zero-trust-branch.deployment), and the wider operations area is in [Where Zero Trust Branch operations are documented: forwarding, Routed Tunnels, segmentation, integrations, logging, monitoring, the Debug Console, troubleshooting and upgrades](kb:zero-trust-branch.operations).

**Root FS method.** The Root FS upgrade method (currently in Preview) downloads up to three image versions, lets one be designated the default so it is applied automatically during a factory reset, and supports only appliances with versions 8.0.6 or later. [zero-trust-branch.operations.upgrades:root-fs-method] From version 8.0.6 the image size was optimized to store up to three images, but if older images such as 8.0.4 HF1 are present the download or installation of the third image might fail for lack of space, which deleting an older image avoids. [zero-trust-branch.operations.upgrades:root-fs-space] The Appliance Version Manager page states the Root FS method's status and version range differently [divergence:zero-trust-branch.operations.upgrades:root-fs-status-and-versions]. The mapping between Airgap OS 7.x and 8.x numbering is not in the captured pages [gap:zero-trust-branch.operations.upgrades:version-numbering].

**Upgrade statuses.** During a standalone upgrade the status moves through Downloading, Updating, Restarting, Initializing and Post-Update to Standalone when the update is completed. [zero-trust-branch.operations.upgrades:standalone-upgrade-statuses] During an HA upgrade the appliance status moves through Downloading, Updating, Restarting, Initializing and Post-Update to Active or Standby; after one appliance completes it becomes Active, the other goes to Standby, and its upgrade starts automatically using the method of the previous appliance. [zero-trust-branch.operations.upgrades:ha-upgrade-statuses]

**State after the upgrade.** The site-details State field of an activated appliance is Standalone for a standalone appliance, Active for the primary node of an HA cluster and Standby for the secondary node. [zero-trust-branch.operations.upgrades:state-field-values] The standalone upgrade page says that after the upgrade the appliance automatically transitions to the Active state. [zero-trust-branch.operations.upgrades:standalone-active-state] The standalone upgrade page disagrees with itself on a standalone appliance's state [divergence:zero-trust-branch.operations.upgrades:standalone-state-after-upgrade]. Activation of a hub or spoke is in [How Zero Trust Branch connects sites over Routed Tunnels: hubs, spokes, activation, sharing, policy-based routing and verification](kb:zero-trust-branch.operations.routed-tunnels).

Sources disagree (name both sides):
- The standalone upgrade page says the appliance transitions to the Active state after the upgrade, while its status table ends in Standalone. [divergence:zero-trust-branch.operations.upgrades:standalone-state-after-upgrade]
  - zscaler-help: After a standalone upgrade the appliance automatically transitions to the Active state.
  - zscaler-help: After a standalone upgrade the status is Standalone once the update is completed.
  Impact: An admin watching a standalone appliance after an upgrade may expect Active or Standalone; the Standalone status matches the State field values recorded for activated appliances.
- The standalone upgrade page calls the Root FS method Preview and supports versions 8.0.6 or later, while the Appliance Version Manager page treats it as a supported method from 8.0.7 and the only method from 8.1.1. [divergence:zero-trust-branch.operations.upgrades:root-fs-status-and-versions]
  - zscaler-help: The Root FS upgrade method is currently in Preview and supports only appliances with versions 8.0.6 or later.
  - zscaler-help: Both legacy and Root FS-based methods are supported on 8.0.7 or later, and from 8.1.1 only the Root FS-based method is supported.
  - zscaler-help: The Appliance Version Manager stores up to three image versions (8.0.7 or later).
  Impact: The pages give 8.0.6 and 8.0.7 as the first Root FS release and disagree on whether it is Preview or the sole method from 8.1.1; check the page for the appliance's version before relying on Root FS.
- The software upgrades page lets an HA pair run different versions so one appliance can be upgraded and tested first, while the HA upgrade page says the second appliance's upgrade starts automatically. [divergence:zero-trust-branch.operations.upgrades:ha-second-upgrade-start]
  - zscaler-help: One appliance can be upgraded and tested for performance and stability before the other.
  - zscaler-help: After the first appliance completes, the other goes to Standby and its upgrade starts automatically.
  Impact: Whether the second HA appliance can be held back for testing is unsettled; the first page ties this to versions 8.0.7 or later and the second does not state a version.
