# How Zero Trust Branch templates and sites are configured: deployment types, DNS, DHCP, routing and App Connectors (zero-trust-branch.deployment.templates-and-sites)
Also called: ztb template; ztb site; ztb site bgp; ztb dhcp options

Predefined templates exist for VM and supported devices in standalone and HA configurations; default templates cannot be deleted or edited but can be cloned. [zero-trust-branch.deployment.templates-and-sites:template-defaults] A template's Deployment Type is standalone (single appliance), standard_mode_ha (active-standby HA) or enhanced_mode_ha (Advanced/WAN Edge HA with active-active WAN links). [zero-trust-branch.deployment.templates-and-sites:template-deployment-types] The deployment hub is [How a Zero Trust Branch appliance is deployed: activation, ZTP, virtual machines, mainland China, upgrades and admin roles](kb:zero-trust-branch.deployment).

**Templates.** A template's DHCP Service can be Internal DHCP Server, DHCP Relay, or Mixed (Per VLAN Server/Relay); Default DHCP Mode for VLAN applies only when Mixed is selected. [zero-trust-branch.deployment.templates-and-sites:template-dhcp-service] Platform for Appliance-1 is vm or a device type, and for an HA deployment the secondary gateway can use a different platform (e.g., VM for an appliance); NAT Enabled is set if the appliance uses NAT for traffic leaving toward the non-Zero Trust Branch network. The secondary WAN DNS is optional. [zero-trust-branch.deployment.templates-and-sites:template-platform-nat] Deleting a template requires entering DELETE in the confirmation dialog. [zero-trust-branch.deployment.templates-and-sites:template-delete-confirm]

**Sites.** When adding a site, the Internet & SaaS location can be an existing location, a new location (saved in the Internet & SaaS tenant with an IPSec VPN tunnel configured), or None for a site with no physical location. [zero-trust-branch.deployment.templates-and-sites:site-location-options] A site's WAN DNS servers and DHCP service are populated from the template and can be overridden for a site that uses a cloned and customized template; appliance names are by default appended with -gw-01 and -gw-02. [zero-trust-branch.deployment.templates-and-sites:site-defaults-overrides] The Add Site drawer displays the site URL and activation code, which must be saved for activating the appliance. [zero-trust-branch.deployment.templates-and-sites:site-activation-values] Site DNS settings include WAN DNS Servers (used for site activation and local system processes), a DNS Proxy Service toggle (disabling it grays out Private DNS Servers), Dynamic DNS Support (forwards DDNS update requests from clients to private DNS servers) and Private DNS Servers (resolve private namespaces and public domains). [zero-trust-branch.deployment.templates-and-sites:site-dns-settings]

**Routing.** A static route has a name, Share Over RT toggle (advertise to other sites and the hub over site-to-site routed tunnels), Network/Mask in CIDR, Nexthop Type (IP or Interface) and a metric that sets priority among routes for the same destination; in HA, interfaces of both gateways can be selected for path redundancy. [zero-trust-branch.deployment.templates-and-sites:site-static-routes] A site BGP peer takes a router ID, neighbor IP and AS, local IP and AS, a password, an EBGP multi-hop count, and a Graceful Restart Time in milliseconds (the Graceful Restart option must be enabled when it is set). [zero-trust-branch.deployment.templates-and-sites:bgp-peer-fields] BGP route filtering uses Include Only or Exclude route maps and IP prefix lists for import and export, and is available only on appliances running version 8.1.2 or later. [zero-trust-branch.deployment.templates-and-sites:bgp-route-filtering]

**App Connectors.** Adding an App Connector to a site provides inbound access to private applications hosted at the branch, and requires the App Connector provisioning key. [zero-trust-branch.deployment.templates-and-sites:app-connector-purpose] Private Access Settings for a site include Use Static App Segment to IP Mappings, a Private Application TCP Idle Timeout in minutes and a Private Access synthetic IP range. [zero-trust-branch.deployment.templates-and-sites:app-connector-pa-settings] Embedded App Connectors are active-standby in standard HA (only one up on the active appliance) and active-active in Enhanced HA (both appliances run an active App Connector with independent connections to the Private Access cloud). [zero-trust-branch.deployment.templates-and-sites:app-connector-ha-behavior] Static Private Access app segment mappings make Zero Trust Branch sites resolve a specific app segment FQDN to the same synthetic IP address, on each App Connector site where Use Static App Segment to IP Mappings is enabled; they are managed on the Private Access DNS tile via CSV import and export. [zero-trust-branch.deployment.templates-and-sites:app-segment-mappings] The import CSV template has columns fqdn, action (create, delete) and description; wildcard FQDNs are not supported for import, and modifying entries means updating the CSV and importing again. The export has columns fqdn, ip and description. [zero-trust-branch.deployment.templates-and-sites:app-segment-csv-format]

**DHCP options.** Predefined site DHCP options include Domain Server (6), Address Time (51), Bootfile Name (67) for PXE network boot and TFTP Server (150), commonly used for VoIP phone provisioning, among others; Custom defines your own option. [zero-trust-branch.deployment.templates-and-sites:dhcp-options-supported] A DHCP option has a code and type that auto-populate for predefined options (a custom option needs a manually entered code and type); the value must match the type, and an optional filter limits the option to devices by attributes such as MAC address or DHCP client identifier. [zero-trust-branch.deployment.templates-and-sites:dhcp-options-fields] Template, site and object count limits are not stated [gap:zero-trust-branch.deployment.templates-and-sites:count-limits].

What to check:
1. Which deployment type the template uses (standalone, standard_mode_ha or enhanced_mode_ha) before assuming how the site's gateways behave.
2. Whether the appliance runs 8.1.2 or later before relying on BGP route filtering.
