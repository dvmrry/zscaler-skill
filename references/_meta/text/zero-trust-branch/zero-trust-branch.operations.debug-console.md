# What the Zero Trust Branch Debug Console documents: site scope, command limits, NTP, IPSec, enrollment files, DNS proxy and SNMP interfaces (zero-trust-branch.operations.debug-console)
Also called: ztb debug console; ztb troubleshooting console; ztb docker logs strongswan; ztb zcc_config.json; ztb dns proxy 1053

The Debug Console is site specific, matching the appliance deployed at that location, and is opened from the site's Troubleshooting left tab > Console top tab. [zero-trust-branch.operations.debug-console:console-site-specific] The pages name the console's location differently [divergence:zero-trust-branch.operations.debug-console:console-location]. In the Debug Console, ping must use an execution count (ping -c) because unbounded ping usage results in failure. [zero-trust-branch.operations.debug-console:ping-bounded] In the Debug Console, tcpdump must use an execution count (-c) because unbounded tcpdump usage results in failure. [zero-trust-branch.operations.debug-console:tcpdump-bounded] The configuration and activation symptoms are in [What the Zero Trust Branch configuration and activation troubleshooting page documents: symptoms and the checks it gives](kb:zero-trust-branch.operations.troubleshooting), and the wider operations area is in [Where Zero Trust Branch operations are documented: forwarding, Routed Tunnels, segmentation, integrations, logging, monitoring, the Debug Console, troubleshooting and upgrades](kb:zero-trust-branch.operations).

**Time and tunnels.** NTP must be configured and the appliance and device clocks synchronized, because inaccurate clocks can make a valid certificate show as expired or not valid and prevent a secure connection; the L3 device must allow UDP 123 traffic sourced from the appliance. [zero-trust-branch.operations.debug-console:ntp-sync] If docker logs strongswan output shows 'auth failed', the check is that the location associated with the site in Internet & SaaS is not deleted and its IPSec credentials are not removed or changed. [zero-trust-branch.operations.debug-console:ipsec-auth-failed]

**Private Access and DNS.** On the appliance, /etc/airgap/zcc/zcc_config.json holds the Internet & SaaS and Private Access org IDs, clouds and Private Access broker, and fqdn.txt and ip.txt list the Private Access application segments downloaded in FQDN and IP address format. [zero-trust-branch.operations.debug-console:zpa-enrollment-files] Client DNS traffic is diverted to the DNS proxy with a DNAT rule in the PREROUTING chain of the NAT table, and the DNS proxy runs on 127.0.0.1:1053. [zero-trust-branch.operations.debug-console:dns-proxy-divert] Appliances log all DNS activities and send a copy to Zero Trust Branch Management for storage; the policy log is /etc/airgap/dns_proxy/policy_logs/dns_policy.log. [zero-trust-branch.operations.debug-console:dns-policy-logs] The DNS policies themselves are in [How Zero Trust Branch forwards branch traffic: default and custom Internet & SaaS gateways, private application connectivity and site DNS policies](kb:zero-trust-branch.operations.sd-wan).

**SNMP.** The Debug Console page says SNMP monitoring can be performed on the management and WAN interfaces and is not supported on the LAN interface. [zero-trust-branch.operations.debug-console:snmp-interfaces] The 8.1.2-P1 release note changes the SNMP defaults [divergence:zero-trust-branch.operations.debug-console:snmp-default-interfaces]. When SNMP monitoring runs over Private Access on the management interface, the packet is received on the management interface and sent to the loopback interface, so the capture is taken on the loopback; a single App Connector runs on an active appliance and its packets are forwarded to the standby gateway over the management interface, and when packets are received from the active gateway on the management interface there are no packets on the loopback interface. [zero-trust-branch.operations.debug-console:snmp-over-private-access] The release notes limit monitoring over Private Access [divergence:zero-trust-branch.operations.debug-console:snmp-standby-monitoring]. The SNMP configuration is in [How Zero Trust Branch is monitored: the Insights dashboard, traffic flow chart, alarms, SNMP and interface health monitoring](kb:zero-trust-branch.operations.monitoring). The DHCP debug level commands are not fully described [gap:zero-trust-branch.operations.debug-console:dhcp-debug-level].

Sources disagree (name both sides):
- The Debug Console page says SNMP monitoring can be performed on the management and WAN interfaces, while the 8.1.2-P1 release note disables SNMP by default on both and leaves it on an in-band loopback interface. [divergence:zero-trust-branch.operations.debug-console:snmp-default-interfaces]
  - zscaler-help: SNMP monitoring can be performed on the management and WAN interfaces.
  - zscaler-help: From 8.1.2-P1 SNMP is disabled by default on WAN and management interfaces, is available on an in-band loopback interface, and is enabled for a server once its IP address is configured.
  Impact: On 8.1.2-P1 or later an SNMP walk against the WAN or management address can fail until an SNMP server IP address is configured; the Debug Console page does not say which release it describes.
- The Debug Console page describes SNMP over Private Access packets being forwarded to the standby gateway, while the 8.1.2 release note says only active appliances can be monitored that way. [divergence:zero-trust-branch.operations.debug-console:snmp-standby-monitoring]
  - zscaler-help: A single App Connector runs on an active appliance and the packets are forwarded to the standby gateway over the management interface.
  - zscaler-help: If the management interface is used to monitor appliances using SNMP over Private Access, only active appliances can be monitored.
  Impact: An admin expecting to poll a standby appliance over Private Access may get no response; the active-only limit is recorded in the 8.1.2 notes, and the Debug Console page does not tie its description to a release.
- The pages name three places for the site console: Troubleshooting > Console, the Console tab on the site details page, and the Appliance Admin Console tab. [divergence:zero-trust-branch.operations.debug-console:console-location]
  - zscaler-help: The Debug Console opens from the Troubleshooting left tab > Console top tab.
  - zscaler-help: The Routed Tunnels page opens the console from the >_Console tab on the site details page.
  - zscaler-help: The SIEM integration page opens the Appliance Admin Console tab under Troubleshooting and clicks Connect.
  Impact: The label to look for differs by page and possibly by release; the pages do not say whether these are one console or different ones.
