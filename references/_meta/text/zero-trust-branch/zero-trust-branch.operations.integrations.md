# How Zero Trust Branch integrates with other systems: API keys, SIEM syslog, CrowdStrike, Armis and SentinelOne (zero-trust-branch.operations.integrations)
Also called: ztb integrations page; ztb api key; ztb siem syslog; ztb crowdstrike zta; ztb armis; ztb sentinelone

The Integrations page (Zero Trust Branch > Resources > Integrations) manages Kibana Credentials, CrowdStrike, SentinelOne, SIEM, Armis, Ordr, ServiceNow and Zscaler Services integrations. [zero-trust-branch.operations.integrations:integrations-page] The Python SDK side of automation is in [Automating Zero Trust Branch: the Python SDK client, its API-key sign-in, and what no other client covers](kb:zero-trust-branch.api), and the wider operations area is in [Where Zero Trust Branch operations are documented: forwarding, Routed Tunnels, segmentation, integrations, logging, monitoring, the Debug Console, troubleshooting and upgrades](kb:zero-trust-branch.operations). The integrations without a captured setup page are open [gap:zero-trust-branch.operations.integrations:uncaptured-integrations].

**API keys.** Integrating with other applications through the Zero Trust Branch APIs needs a unique API key; the key can be viewed and copied only once, at creation, and the key list shows the creation dates. [zero-trust-branch.operations.integrations:api-key-view-once] Revoking an API key deletes it, and any integration using that key for authentication stops working. [zero-trust-branch.operations.integrations:api-key-revoke]

**SIEM.** SIEM integration streams events in real time over syslog, sent by the appliance directly to the configured server, and Zero Trust Branch supports TCP and UDP only; it works over both WAN and Private Access, and only session logs are forwarded. [zero-trust-branch.operations.integrations:siem-syslog] The overview page differs on how logs reach a SIEM [divergence:zero-trust-branch.operations.integrations:siem-export-path]. The SIEM integration page says Zero Trust Branch currently generates only one type of traffic log, the session-init log, which captures Layer 2, 3 and 4 header information when a new session is created. [zero-trust-branch.operations.integrations:siem-session-init] The log types page gives a different count [divergence:zero-trust-branch.operations.integrations:traffic-log-type-count]. SIEM setup needs the SIEM host IP address, protocol and port and connectivity between the SIEM server and the appliance's WAN interface, and the applied configuration can be checked on the appliance in /etc/airgap/policy_container/rsyslog.d/20-siem.conf. [zero-trust-branch.operations.integrations:siem-prereq-verify] The page names the console tab differently from the Debug Console page [divergence:zero-trust-branch.operations.integrations:siem-console-tab]. The log types themselves are in [How Zero Trust Branch logs traffic: architecture, log types and formats, retention and limits, throttling and tenant isolation](kb:zero-trust-branch.operations.logging).

**CrowdStrike.** The CrowdStrike API client secret is only available once at creation, and CrowdStrike recommends giving Zscaler read-only access for hosts, devices, zero trust appliances, user management, sensor download and event streams. [zero-trust-branch.operations.integrations:crowdstrike-secret-scope] The CrowdStrike Zero Trust Assessment score is a real-time risk score from 0 to 100 for each device, and higher scores signify better security. [zero-trust-branch.operations.integrations:crowdstrike-zta-score] As an example, Zero Trust Branch objects can treat endpoints with a risk score above 70 as low risk with full access, 30 to 70 as medium risk with limited access, and below 30 as high risk with no access to applications and networks. [zero-trust-branch.operations.integrations:crowdstrike-risk-bands] Device groups for high-, medium- and low-risk devices are created with the Device Security Posture attribute, which is synced from CrowdStrike during the integration process. [zero-trust-branch.operations.integrations:crowdstrike-posture-attribute] A host's Secure Posture Score is viewed in the Zscaler Admin Console under Dashboard > Asset Intelligence by selecting the host. [zero-trust-branch.operations.integrations:crowdstrike-secure-posture-score] Zero Trust Branch periodically polls CrowdStrike for posture information, score availability depends on the Falcon check-in interval, and real-time enforcement is not guaranteed. [zero-trust-branch.operations.integrations:crowdstrike-polling] The API credential Test or Validate function confirms authentication but not permissions, so a key without the Zero Trust Assessment - Read scope can pass validation and fail at runtime with a 403 – Access denied error. [zero-trust-branch.operations.integrations:crowdstrike-api-scope] On the CrowdStrike integration page, the caveats are that FQDN and wildcard domain rules in security policies require DNS Proxy to be enabled, with IP address-based rules as a fallback, and that assets are identified by MAC address, so a changed network interface can create duplicate devices needing a new score per MAC address. [zero-trust-branch.operations.integrations:crowdstrike-fqdn-identity] CrowdStrike sensor communication can fail silently when SSL inspection is enabled, so SSL inspection bypass is configured for *.cloudsink.net, *.csa.cloudsink.net and *.falcon.crowdstrike.com; without it the sensor might detect tampering or certificate mismatches, causing registration failures or blocked communication. [zero-trust-branch.operations.integrations:crowdstrike-ssl-bypass]

**Armis.** The Armis integration is bidirectional: Armis ingests Zero Trust Branch device posture and policy data, and Zero Trust Branch ingests Armis device intelligence such as classification, tags and risk insights. [zero-trust-branch.operations.integrations:armis-bidirectional] In Armis, the Airgap connection Host is the tenant's API host in the form https://<ztbtenant>-api.goairgap.com. [zero-trust-branch.operations.integrations:armis-host-format] Data from Armis is synced only for assets that have already been discovered; verification, in the Armis management console under Assets, checks that the asset has the airgap:protected tag on its Overview tab. [zero-trust-branch.operations.integrations:armis-sync-scope] Asset discovery and tags are in [How Zero Trust Branch segments devices: Airgap, Airgap-Lite and Airgap+ protection, /32 incompatibilities, assets, tags, the NAC MAC list and the Ransomware Kill Switch](kb:zero-trust-branch.operations.segmentation).

**SentinelOne.** The SentinelOne API token is generated for a new user with the Viewer role, and the SentinelOne Integration drawer takes the API Token and Base URL. [zero-trust-branch.operations.integrations:sentinelone-token] Zero Trust Branch enforces segmentation, quarantine or policy adjustments at the network level based on SentinelOne risk scores and incident detections. [zero-trust-branch.operations.integrations:sentinelone-enforcement]

Sources disagree (name both sides):
- The logging and monitoring overview says logs are exported to external SIEM platforms via the API, while the SIEM integration page says the appliance sends syslog messages directly to the configured syslog server. [divergence:zero-trust-branch.operations.integrations:siem-export-path]
  - zscaler-help: Logs can be exported to external SIEM platforms via the API.
  - zscaler-help: The appliance sends syslog messages directly to the configured syslog server.
  Impact: Which path carries SIEM logs, and so where to open firewall access, is not settled by the pages.
- The SIEM integration page says Zero Trust Branch generates only one type of traffic log, the session-init logs, while the log types page says appliances capture two primary types, packet logs and flow logs. [divergence:zero-trust-branch.operations.integrations:traffic-log-type-count]
  - zscaler-help: Zero Trust Branch generates only one type of traffic log, the session-init logs.
  - zscaler-help: Appliances capture two primary types of traffic logs: packet logs and flow logs.
  Impact: What reaches a SIEM is session-init logs; whether they correspond to the packet logs, the flow logs or both is not stated, so do not assume the SIEM receives both log types shown in Data Explorer.
- The SIEM integration page opens the Appliance Admin Console tab under Troubleshooting, while the Debug Console page opens Troubleshooting left tab > Console top tab. [divergence:zero-trust-branch.operations.integrations:siem-console-tab]
  - zscaler-help: Under Troubleshooting, click the Appliance Admin Console tab and click Connect.
  - zscaler-help: Click Troubleshooting left tab > Console top tab.
  Impact: The tab label to look for may differ by release; the pages do not say whether these are the same console.
