# Landmine policies: what they deploy, which endpoints they select, and how the Windows endpoint deployment is set up (deception.landmine-policies)
Also called: landmine policy; landmine agent; landmine agentless; endpoint deception; policy selection criteria; lure passwords

Landmine decoys are decoy files, credentials and application lures on endpoints; a landmine agent fetches the policies, verifies whether they apply to an endpoint and then deploys the decoys. The article lists techniques T1562.001, T1489, T1485, T1552.001, T1557.001 and T1005. [deception.landmine-policies:what-and-mitre] Landmine policies are additive: a default policy for all endpoints can be layered with specific policies, and the portal evaluates policies for each endpoint and deploys the applicable decoys. In the vendor's example, user john on laptop-1 matches the Default, John and Laptop policies and gets a decoy process (mcafee.exe), a file decoy (password.xlsx) and a decoy Chrome credential (webmail02). [deception.landmine-policies:additive] The modules and lures a policy deploys are in [Landmine decoy modules and lures: what each deploys, on which operating systems, and how it is tested](kb:deception.landmine-decoys), the Active Directory decoys in [Active Directory decoys: domains, decoy users and computers, the deployment script, and the alert triggers that feed them](kb:deception.ad-decoys) and the product hub is [Zscaler Deception: decoys and lures, the Private Access integration, roles, and what can be automated](kb:deception.overview). Limits per feature are not stated in these articles [gap:deception.landmine-policies:ranges-limitations].

**Agent and agentless.** By default a landmine policy is deployed in agent mode; an agentless policy applies only to the agentless version of Landmine and an agent policy only to the agent version. [deception.landmine-policies:agent-default] The Policies page Agentless filter takes All (default), True or False; an X icon marks a policy for the full agent variant of the landmine and a check mark icon a policy for the agentless variant. [deception.landmine-policies:agentless-filter]

**Selection criteria.** The selection criteria are Catch All, Dynamic Rule, User, Group, Hostname (Specific), Hostname (RegEx), DNS Hostname (Specific), DNS Hostname (RegEx), User OU (RegEx), Computer OU (RegEx) and Fallback. [deception.landmine-policies:criteria-list] Dynamic Rule attributes are Process List, Browser History, Installed Programs, Interesting Files and Recent Commands (the Run dialog box), each matched against a Contains field; if any one of the rules matches, the policy is applied at the endpoint. [deception.landmine-policies:dynamic-attributes] For the Group criterion only AD security groups are supported; IdP groups are not supported. [deception.landmine-policies:group-limits] For the Group, User OU (RegEx) and Computer OU (RegEx) criteria, policies are applied to agents within a maximum of one day. [deception.landmine-policies:group-delay] To apply policies to Zscaler Client Connector users, their Zscaler Client Connector username is specified. [deception.landmine-policies:user-ccusername] The Fallback criterion applies the policy to any system with no other policy criteria specified; if the Catch All criterion is specified, Fallback is not applied. [deception.landmine-policies:fallback]

**Lure passwords.** If password settings are not configured or enabled, the system generates realistic lure passwords using default complexity rules; the settings are Must have special characters, Must have at least one uppercase letter, Must have digits, Min Length, Max Length and Password Keywords. [deception.landmine-policies:password-defaults] Customized lure passwords can be placed in browser lures, session lures and file decoys, and when attackers enumerate them the event is logged as an attack. [deception.landmine-policies:password-placement]

**Changing, evaluating and viewing.** Any changes made to a landmine policy can take a few hours to reflect on the endpoints. [deception.landmine-policies:edit-delay] How quickly a policy change reaches endpoints differs between pages [divergence:deception.landmine-policies:policy-change-latency]. Evaluate Policies produces a sample report of the modules deployed for a given User ID, Hostname and OS, with optional Group, Computer OU, User OU, Domain, Display Name and Dynamic Rules; if a user or system matches two or more policies, the report shows the modules of all the matching policies. [deception.landmine-policies:evaluate] The policy details page shows System Details (including the agent type, install time and last connection), Fake Security Processes Details, File Decoys, Advanced Deception Capabilities, Privilege Escalation Details and Session Lures. [deception.landmine-policies:policy-details] Cloud Lures in the policy details show the policy name, usernames, Amazon Web Services (AWS) access key and AWS secret keys. [deception.landmine-policies:details-cloud-keys]

**Endpoint deception through Client Connector for Windows.** For an organization provisioned for Zscaler Internet Access (ZIA), endpoint deception on Microsoft Windows machines through Zscaler Client Connector needs the capability enabled by contacting the Zscaler Account team, and endpoints with Windows 10 (64-bit only) or later with a 64-bit Client Connector upgraded to 4.6.0.123, 4.7.0.47, 4.8.0.88 or 4.9.0.330 or later. [deception.landmine-policies:cc-prereq-versions] The Tunnel Internal Client Connector Traffic option is enabled in the Zscaler Client Connector Portal; by default, traffic sent to the Zscaler Deception Admin Portal is considered internal traffic. [deception.landmine-policies:cc-tunnel-internal] Outbound access on port 443 is needed to the Deception Admin Portal (<your_subdomain>.illusionblack.com), dwv281inkfqg3.cloudfront.net and zcc.ecdn.zscaler.com. [deception.landmine-policies:cc-egress] A standalone landmine agent can migrate automatically during the Zscaler Client Connector upgrade: lures applied and decoys deployed are copied to the new installation location and the standalone landmine agent is uninstalled. [deception.landmine-policies:cc-migration] Zscaler Deception Enabled by Default enables endpoint deception for all Zscaler Client Connector users upgraded to Deception version 4.6 or later for Windows; to enable it for a specific group of users or a device group, it is disabled and a group is selected from the User Groups or Device Groups drop-down menu. [deception.landmine-policies:cc-enable-scope] In the Deception Admin Portal, under Settings > Endpoint Settings > Agent Configuration, the Name, Display Name and Description of the landmine installer or service are customized to prevent the agent from being fingerprinted; in the Zscaler Client Connector Portal, Administration then Zscaler Deception shows the installer settings, which should match them, and Sync gets the latest values if they don't. [deception.landmine-policies:cc-installer-fingerprint] In the Zscaler Client Connector Portal, App Profiles > Windows, the Edit Windows Policy (or Add Windows Policy) window takes a Logout Password, Exit Password and Password to access Deception Settings; the configuration is successful when the Service Status is Running. [deception.landmine-policies:cc-passwords] See also [Endpoint settings (installer, lure refresh, update groups, safe processes) and Admin Portal settings (audit, error and debug logs, license, event and evidence export and delete, retention)](kb:deception.endpoint-settings) and [Landmine agent and agentless: install, requirements, proxies, management and OS feature support](kb:deception.landmine-agents). Which features each installer supports is not stated in these articles [gap:deception.landmine-policies:installer-feature-support].

**Restricted file paths.** Beginning with Zscaler Client Connector-integrated Agent 6.1, landmine validates certain file paths in policies before creating or managing path-based lures and decoys, and rejects paths that target the OS, security, credential or other protected locations; path validation is case insensitive and the blocked paths vary with the endpoint OS. [deception.landmine-policies:restricted-paths-scope] Blocked Windows paths include the Windows installation directory (typically C:\Windows, with System32, SysWOW64, WinSxS and other subdirectories), System Volume Information, Windows Defender under ProgramData, the all-users Startup folder, a user's Vault folder, NTUSER.DAT and UsrClass.dat. [deception.landmine-policies:restricted-paths-windows] Blocked macOS paths include /System/, /opt/homebrew/, /Library/Keychains/ and /private/var/db/auth.db. [deception.landmine-policies:restricted-paths-macos] Blocked Linux paths include /proc/, /var/spool/cron/, /var/lib/docker/ and /run/docker.sock. [deception.landmine-policies:restricted-paths-linux]

What to check:
1. Which selection criterion a policy uses, including whether Catch All is specified, since Fallback is not applied then.
2. Whether a Group criterion relies on AD security groups, since IdP groups are not supported, and that policies under the Group, User OU and Computer OU criteria are applied within a maximum of one day.
3. How quickly a changed policy reaches an endpoint, where one page says it can take a few hours and another says updates are applied as soon as the agent connects.
4. Whether a path-based lure or decoy targets a location the Client Connector-integrated Agent 6.1 landmine rejects.

Sources disagree (name both sides):
- One page says changes to a landmine policy can take a few hours to reflect on the endpoints; the lure refresh interval page says changes to the landmine policies are applied as soon as the landmine agent connects to the Deception Admin Portal. [divergence:deception.landmine-policies:policy-change-latency]
  - zscaler-help: Changes made to a landmine policy can take a few hours to reflect on the endpoints.
  - zscaler-help: Changes to the landmine policies are applied as soon as the landmine agent connects to the Deception Admin Portal, without waiting for the lures to refresh.
  Impact: The pages do not say whether the few hours is the interval between agent connections or a separate delay, so how long a changed policy takes to reach an endpoint is not settled.
