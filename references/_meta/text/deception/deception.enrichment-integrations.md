# Deception and ITDR enrichment integrations: supported sources, credentials needed, and the event-log fields each adds (deception.enrichment-integrations)
Also called: ITDR enrichment integration; ITDR enrichment integrations; Deception enrichment integration; Enrich page

The product hubs are [Zscaler Deception: decoys and lures, the Private Access integration, roles, and what can be automated](kb:deception.overview) and [Identity Protection (ITDR): how it reads identity stores and endpoints, what it needs, and what can be automated](kb:identity-protection.overview). Events can be enriched with contextual information from geolocation tools, third-party threat intelligence databases, sandbox analysis reports, etc.; the Deception page adds that enrichment helps reduce false positives. [deception.enrichment-integrations:enrich-purpose] Enrichment integrations can be configured for AbuseIPDB, GreyNoise Intelligence, Hybrid Analysis, IPinfo, Joe Sandbox, Palo Alto Networks WildFire, Shadowserver, VirusTotal and Zscaler Sandbox (Deception Enrich page); the ITDR Enrich page lists Hybrid Analysis, Joe Sandbox, Palo Alto Networks WildFire, Shadowserver, VirusTotal and Zscaler Sandbox. [deception.enrichment-integrations:enrich-supported-sources]

**ITDR Enrich page.** The ITDR Enrich page lists each integration with Enabled (whether the enrichment integration is enabled or not) and Settings (the name of the third-party security solution). [deception.enrichment-integrations:itdr-enrich-columns]

**Credentials and connectivity.** The Deception AbuseIPDB, GreyNoise Intelligence, Hybrid Analysis, IPinfo, Joe Sandbox and VirusTotal guides each require network connectivity from the admin portal to the vendor, an account, and an API key (IPinfo: an API access token); the Joe Sandbox key is under User Settings > API Key in the Joe Sandbox console. [deception.enrichment-integrations:enrich-api-key-sources] The Palo Alto Networks WildFire enrichment needs an active WildFire account, the WildFire console URL and an API key (copied from My Account in the WildFire console); the configuration window takes the console URL and the API key, and the Deception page adds that Deception evidence files can be sent to the WildFire sandbox. [deception.enrichment-integrations:wildfire-enrichment] The Shadowserver enrichment is enabled by selecting Enabled in the Shadowserver window; its prerequisite is network connectivity from the admin portal to the Shadowserver server. [deception.enrichment-integrations:shadowserver-enrichment]

**Event-log fields added.** In the Deception guide, the additional fields AbuseIPDB enrichment creates in the event logs are prefixed with abuseip: abuseConfidenceScore, countryCode, countryName, ipAddress, ipVersion, isPublic, isWhitelisted, lastReportedAt and totalReports; the integration enriches events from internet-facing decoys. [deception.enrichment-integrations:abuseipdb-fields] In the Deception guide, the additional fields GreyNoise Intelligence enrichment creates in the event logs are prefixed with greynoise: categories, category.activity, category.actor, category.hosting, category.scanner, category.search_engine, category.tool, category.worm, returned_count and status. [deception.enrichment-integrations:greynoise-fields] The additional fields VirusTotal enrichment creates in the event logs are prefixed with vt: positives, total, names, error and permalink. [deception.enrichment-integrations:virustotal-fields] The additional fields Shadowserver enrichment creates in the event logs are prefixed with binary: os_version, trusted_signature, os_name, sig_timestamp, description and fileversion. [deception.enrichment-integrations:shadowserver-fields] In the Deception guide, after IPinfo enrichment is enabled, the enriched IP geolocation data from IPinfo is available in the attacker.country field on the Event Logs page. [deception.enrichment-integrations:ipinfo-field]

**Testing a sandbox integration.** The Deception Hybrid Analysis, Joe Sandbox and Palo Alto Networks WildFire guides test the integration by running an application file on a network decoy with Windows service enabled; when an alert is generated on the Investigate dashboard the evidence file is sent to the sandbox, and the report can then be downloaded for analysis. [deception.enrichment-integrations:sandbox-test-procedure]

What to check:
1. Which product the enrichment answer is about, since the Deception Enrich page lists nine solutions and the ITDR Enrich page lists six.
2. Whether the admin portal has network connectivity to the vendor server and an account and API key, as the AbuseIPDB, GreyNoise Intelligence, Hybrid Analysis, IPinfo, Joe Sandbox and VirusTotal guides require.
