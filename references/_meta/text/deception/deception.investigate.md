# Deception Investigate: the dashboard, containment actions, event logs and evidence (deception.investigate)

See also [Zscaler Deception: decoys and lures, the Private Access integration, roles, and what can be automated](kb:deception.overview), [Deception Miragemaker: strategies, decoy personalities, banners, tags, datalists and ThreatParse rules](kb:deception.miragemaker) and [Deception datasets: application, high-interaction container, SCADA/IoT, keyword, custom service and file datasets, and CVE handlers](kb:deception.datasets).

**Dashboard.** The Investigate dashboard time filter spans the last 10 minutes to all time and by default shows events from the last 7 days. [deception.investigate:dashboard-time-filter] The dashboard Level of Detail filter orders its levels from the Deception Admin Portal, then Decoy Connectors, Decoy Groups and Decoys, and its plus and minus icons increase or reduce the elements shown. [deception.investigate:level-of-detail] The dashboard Threat Level filter selects events by threat severity and offers All, Medium and Higher and Only High options. [deception.investigate:threat-level-filter] The dashboard Layout filter offers Default, Hierarchy (tree layout) and Radial (circular layout); the Demographics filter offers One to Many, Many to One and One to One views of attacker-to-element interaction. [deception.investigate:layout-and-demographics] The Interactive Only filter shows attacks only when attackers and decoys interact, so network reconnaissance attacks are not shown while it is enabled. [deception.investigate:interactive-only] Attacker icons can be shown as identicons, country flags (if available) or tagged names, an attacker icon can be tagged with alternate text, and the country's flag (if available) is displayed in the case of a TI activity. [deception.investigate:attacker-icon-options] A Decoy Connector is a lightweight VM that hosts network decoys and also acts as a network broker connecting the Deception service to on-premises systems and AD decoys. [deception.investigate:dashboard-decoy-connector] The chronology slider graphs attack volume by time, can trim a filtered time range to a subset, and can replay recorded events in the sequence they occurred. [deception.investigate:chronology-slider]

**Queries.** Saved queries appear in the Select Query drop-down; a saved query can optionally record the selected time period and restore it when selected later. [deception.investigate:saved-queries] Deception provides built-in saved queries, for example Cloud Threat Detection, which filters for threat detections related to AWS or Azure. [deception.investigate:saved-query-example] The Investigate query builder accepts field names such as attacker.ip, and Boolean expressions such as (type is "windows") or (type is "network" and sub_type is "file"). [deception.investigate:query-example-syntax] Investigate query filters do not support case-agnostic regular expressions or the case-insensitivity flag (\I). [deception.investigate:query-regex-case] Filter value lists [gap:deception.investigate:filter-value-lists].

**Details panes.** Selecting an element on the alert graph opens a details pane unique to each Deception object and attacker; the object pane shows triggered ThreatParse rules and attacker risk scores, and the attacker pane shows the risk score, first and last event timestamps, triggered ThreatParse rules and any endpoint triage incidents. [deception.investigate:details-panes] View Extended Details shows ThreatParse, Chronology, Network, Event Logs and Evidence tabs. [deception.investigate:extended-details-tabs] For each threat the ThreatParse details page shows a description, attack examples, mitigations, the MITRE ATT&CK ID and tactic, an event occurrence summary and important attacker information such as the submitted username and password. [deception.investigate:threatparse-details-fields] The Chronology page has an events-over-time graph and an activity-over-a-week heatmap in which a brighter spot represents a high volume of activity. [deception.investigate:chronology-page] The Network page lists event logs with the attacker IP address, decoy IP address and port, network protocol, network service and connection duration, and offers a PCAP drop-down whose Build PCAP option builds a consolidated packet capture for the specified period that is then downloaded with Download Available PCAP. [deception.investigate:network-page]

**Containment.** The Actions menu on an attacker can forward the attacker's details to Check Point Firewall, CrowdStrike Falcon Insight, AWS GuardDuty, Fortinet, Microsoft Defender, Palo Alto Networks, VMware Carbon Black EDR, VMware Carbon Black Endpoint Standard, Internet & SaaS (ZIA) or Private Access (ZPA); the settings for these tools must be enabled on the Containment page first. [deception.investigate:containment-targets] Marking an event as safe removes the attacker from the default Admin Portal view and can take up to an hour to be reflected; marking an attacker's IP address as safe marks all past events from it as safe, while new events from that IP address are still generated and displayed; Show marked as safe in the Select Query menu lists them so Mark as unsafe can reverse it. [deception.investigate:mark-safe-behavior] Deleting an attacker removes all previously triggered events for it from the Admin Portal and permanently deletes the ThreatParse data linked to it, while tags associated with the attacker are retained. [deception.investigate:delete-attacker] Selecting the blocklist action redirects to the Blocklist page to create a rule that blocks the attacker's IP from accessing the decoy. [deception.investigate:blocklist-action] Orchestration rules can also automate marking an event as safe and deleting an attacker. [deception.investigate:automated-containment] Setup of these integrations [gap:deception.investigate:enrichment-and-containment-setup].

**Event logs.** The Event Logs tab shows basic event information including Timestamp, Attack Type, Attacker ID, Decoy Name, Decoy Group, Decoy Port, Decoy Connector and Kill Chain Phase, where Attacker ID is the attacker's IP address, and up to 50 columns can be added. [deception.investigate:event-log-columns] Event logs can be exported as Attacker Summary in JSON or CSV, Events as JSON, Event Fields as JSON, Events as CSV, STIX v1.2, STIX v2.1 and Snort Rules. [deception.investigate:event-log-export-formats] Deleting selected events works well when there are fewer than 100 events, deleted events are removed permanently, and Delete All removes at most 100K events at a time so more than 100K events for an entity need repeated runs. [deception.investigate:event-delete-limits] Test Rule runs a custom query-language rule against up to 10 selected events and shows the number that passed and, separately, the list that failed. [deception.investigate:event-test-rule]

**Evidence.** Depending on the decoy interaction, evidence files are Packet Capture (PCAP), RDP recording files (MP4 and SRT), Indicators of Compromise (IOC), Quality of Service (QOS) and HTTP Request (http_request). [deception.investigate:evidence-types] http_request evidence is created for web events across static, dynamic and high-interaction containers when attackers send POST requests with unusually large payloads, applies to TI decoys and internal decoys with the Web Services type, and can be downloaded as a text file. [deception.investigate:evidence-http-request] PCAP evidence files contain one minute or 5 MB of PCAP data, whichever is less, and a unified PCAP for a selected duration can be downloaded from the Network page. [deception.investigate:pcap-evidence-size] Evidence details export as JSON or CSV, and Delete All permanently deletes all evidence files for the specified time period on the Investigate Dashboard from the Decoy Connectors. [deception.investigate:evidence-export-delete]

**Sandbox analysis.** Only IOC evidence files can be sent to a sandbox; Zscaler Sandbox is integrated, and third-party sandboxes must first be configured for enrichment integration. [deception.investigate:evidence-sandbox-submission] Deception supports Palo Alto Networks WildFire, Hybrid Analysis, Joe Sandbox, CrowdStrike Falcon X and VirusTotal as third-party sandboxes. [deception.investigate:evidence-third-party-sandboxes] A Zscaler Sandbox report downloads as JSON, a third-party sandbox report as PDF or JSON, and submission can take a few minutes depending on file type and size. [deception.investigate:sandbox-report-formats] The Zscaler Sandbox report shows a Classification, the threat type of the analyzed file, with an associated threat score. [deception.investigate:sandbox-report-classification] Classification values [divergence:deception.investigate:sandbox-classification-values]. The Zscaler Sandbox report shows classification, file properties (size, signing certificates, MD5, SHA1 and SSDEEP hashes), exploits, network, persistence, security bypass, spyware, stealth and system summary information. [deception.investigate:sandbox-report-sections] Guest operating systems [gap:deception.investigate:sandbox-guest-os].

What to check:
1. Which classification values a Zscaler Sandbox report can carry, since the page gives two lists.
2. Whether an attacker's past events stay hidden after the IP address is marked as safe.
3. Whether a file can be sent to a sandbox from the Evidence page.
4. Whether more than 100K events for one entity are removed in a single Delete All.

Sources disagree (name both sides):
- The Zscaler Sandbox report's Classification line names Benign, Malicious and Suspicious, while the list under it that categorizes the file names Benign, Adware, Anonymizer and Malware. [divergence:deception.investigate:sandbox-classification-values]
  - zscaler-help: The Classification line gives Benign, Malicious, and Suspicious as example threat types.
  - zscaler-help: The sub-list that further categorizes the file gives Benign, Adware, Anonymizer and Malware.
  Impact: The page does not say whether Malicious and Suspicious are values a report shows or whether Adware, Anonymizer and Malware are the categories it uses, so which classification value an evidence file shows is not settled by the page.
