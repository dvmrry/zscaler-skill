# Deception Miragemaker: strategies, decoy personalities, banners, tags, datalists and ThreatParse rules (deception.miragemaker)
Also called: strategy builder; deception strategy; decoy personality; decoy personalities; threatparse rules

By default the Miragemaker module includes preconfigured datasets, ThreatParse rules, templates, strategies, decoy personalities, banners and tags, and custom resources can be created. [deception.miragemaker:module-contents] Banners are metadata about services running on a server and are used in network decoys configured with FTP or web services; tags group various resources across Deception. [deception.miragemaker:banners-and-tags-purpose] See also [Zscaler Deception: decoys and lures, the Private Access integration, roles, and what can be automated](kb:deception.overview), [Deception datasets: application, high-interaction container, SCADA/IoT, keyword, custom service and file datasets, and CVE handlers](kb:deception.datasets) and [Deception Investigate: the dashboard, containment actions, event logs and evidence](kb:deception.investigate).

**Strategies.** Strategy Builder has Deception Strategy, which combines decoy personalities to deploy decoys with a single click, plus Network, Threat Intelligence, Landmine and Active Directory decoy personalities as templates. [deception.miragemaker:strategy-builder-components] Before creating a strategy, identify a use case such as Log4j or Conti Ransomware, a department, the critical decoy types and the total number of decoys. [deception.miragemaker:strategy-prerequisites] A strategy lists personalities or tags to deploy together; the Network Decoys tab has a Use Tag toggle and a Count of decoys per personality or tag, the Personality/Tag drop-down on the Network Decoys and Active Directory tabs lists tags when Use Tag is enabled and personalities otherwise, and the Landmine tab selects personalities. [deception.miragemaker:strategy-structure] Validate ensures the Network, AD and TI decoys exist for the configured landmine lures, and the strategy is saved after it has been validated. [deception.miragemaker:strategy-validate-before-save] Validating a strategy shows the total percentage of enabled landmine lures that have available Network, AD and TI decoys; landmine personalities carry browser, session and memory credential lures. [deception.miragemaker:strategy-validation-result] A single strategy downloads as a JSON file and all strategies export as a .zip containing each strategy's configuration in JSON. [deception.miragemaker:strategy-download-export] What editing or deleting a deployed strategy does [gap:deception.miragemaker:strategy-edit-delete].

**Decoy personalities.** AD decoy personalities are templates for creating AD decoys through deception strategies; Deception provides preconfigured ones and custom ones can be created, and the page (Miragemaker > Strategy Builder > Active Directory Decoy) lists each with a Name and Description. [deception.miragemaker:ad-personalities-page] TI decoy personalities are templates for creating TI decoys through deception strategies; Deception provides preconfigured ones and custom ones can be created, and the page (Miragemaker > Strategy Builder > Threat Intelligence Decoy) lists each with a Name and Description. [deception.miragemaker:ti-personalities-page] A network decoy personality is a template for internal and Zero Trust Network decoys and interactive generative AI decoys, usable manually or through strategies, and configured similarly to network decoys. [deception.miragemaker:network-personality-scope] A network decoy personality sets hostname keywords and subdomains (one per line), tags, a NIC manufacturer whose MAC prefix generates a pseudo MAC address, optional hostname modifiers that generate hostnames at deployment, and an Add to Active Directory option that adds the decoy as an AD object with OS attribute, OU and description. [deception.miragemaker:network-personality-fields] A TI decoy personality sets a decoy type (Static Application, Dynamic Application or High Interaction Container) and one or more application datasets, each with an Allow Port 80 toggle that allows or blocks unencrypted HTTP access to the application decoy. [deception.miragemaker:ti-personality-fields] The Landmine Decoy Personalities page shows Name, an Agentless flag (whether the policy can be applied with or without agents, filterable by true or false), Selection Criterion and Policies. [deception.miragemaker:landmine-personality-list] A landmine decoy personality sets an operating system, tags, an Agentless option to deploy policies without agents and an option for users to review selection criteria when deploying through strategies; its policies cover Selection Criterion, Password Settings, Defense Evasion, Privilege Escalation, Cloud Lures, Browser Lures, Session Lures, File Decoys, Lure Settings and Advanced Deception Capabilities. [deception.miragemaker:landmine-personality-fields] In an AD decoy personality, Pre auth not required makes accounts vulnerable to AS-REP roasting, Make account Kerberoastable configures the serviceprincipalname attribute to make decoys vulnerable to Kerberoasting, and Restrict Logon To configures the logonworkstations attribute. [deception.miragemaker:ad-personality-attack-flags] An AD decoy personality sets usernames (one per line), OU, group membership, description, SPN and the profilePath attribute; Use Modifiers randomly generates usernames from the Usernames values at deployment. [deception.miragemaker:ad-personality-attributes] Default and custom network, Threat Intelligence, landmine and Active Directory decoy personalities download individually as JSON files, and exporting all network, TI, landmine or AD personalities gives a .zip with each personality in its own JSON file. [deception.miragemaker:personality-exports]

**Banners.** SMB banners associate with network decoys that have the Shares service enabled, FTP banners with decoys that have FTP service enabled, and web server banners (typically used in the server response header) with decoys that have web service enabled. [deception.miragemaker:smb-ftp-web-banners] SMB and FTP banners are created with a name entered as the banner message and an operating system; a web server banner is created by entering the banner message in the Name field. [deception.miragemaker:banner-operating-system]

**Tags and datalists.** When a tag is used in a deception strategy, a personality associated with that tag is chosen at random during decoy deployment. [deception.miragemaker:tag-random-selection] All tags export as a JSON file. [deception.miragemaker:tag-export] A datalist holds key-value items in which each key can have multiple values (one per line), and for specific keys at most 20 values can be added. [deception.miragemaker:datalist-structure] Preconfigured datalists are usable in Network Decoy personalities as Active Directory OUs, AD Decoy personalities as Group Memberships, Landmine personalities as Fakes in Defense Evasion, and interactive generative AI decoys as Model Names. [deception.miragemaker:datalist-uses] A datalist downloads individually as a JSON file and all datalists download as a collection in a ZIP file. [deception.miragemaker:datalist-download] Which datalist keys are limited and any limit on tags or banners [gap:deception.miragemaker:resource-limits].

**ThreatParse rules.** The ThreatParse engine translates attack event details into plain English using rules that use parameters such as risk score, conditions, MITRE ID and MITRE tactic; default rules exist for common attack events and custom rules can be added. [deception.miragemaker:threatparse-rule-parameters] The ThreatParse Rules page shows each rule's Title, Description, risk Score, Show in UI and Enabled state; a disabled rule is not triggered for events matching its conditions. [deception.miragemaker:threatparse-rule-list] A custom ThreatParse rule has type Single, triggered by criteria on a single event, or Multi Attacker Facet, triggered by criteria across multiple events. [deception.miragemaker:threatparse-rule-types] A custom ThreatParse rule can move the trigger source (client) to the allowlist, hide the rule on the Investigate page, or delete the event that triggered it; its conditions use the custom query language. [deception.miragemaker:threatparse-rule-actions] A custom ThreatParse rule can carry a mitigation advisory, MITRE ID, CVE ID, MITRE tactic, example threat groups and important event fields. [deception.miragemaker:threatparse-rule-additional-details]

**Defaults.** Default ThreatParse rules, network, TI, landmine and AD decoy personalities, SMB, FTP and web server banners, tags and datalists cannot be edited or deleted. [deception.miragemaker:default-resources-readonly]

What to check:
1. Whether a personality, banner, tag, datalist or ThreatParse rule is a default one before advising an edit or deletion.
2. Whether a strategy that uses a tag picks the personality at random during deployment.
3. Whether a banner is associated with a decoy that has the matching service enabled.
4. Whether the strategy was validated before it is saved.

Not known (open gaps):
- What editing or deleting a deployed strategy does to its decoys [gap:deception.miragemaker:strategy-edit-delete]: settled by lab-test or support-ticket
- Limits on tags, keywords, banners and datalist keys [gap:deception.miragemaker:resource-limits]: settled by source-read or support-ticket
