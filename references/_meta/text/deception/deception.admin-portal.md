# Deception Admin Portal: sign-in, navigation, users and roles, account settings, allowed IPs and QoS events (deception.admin-portal)
Also called: deception admin portal; deception users and roles; allowed ips; ip allowlist; authentication service; qos events

**Signing in.** After an organization is provisioned for Deception, an email provides a link to the Deception instance, a link to set the password, and a security code. [deception.admin-portal:provisioning-email] Following the emailed password link, the user sets a new password, enters the emailed Security Code, and configures two-factor authentication by scanning a QR code with a 2FA app and entering the 6-digit one-time password. [deception.admin-portal:first-sign-in-2fa] The first login displays an EUSA in the Admin Portal, and the license cannot be activated without accepting the EUSA. [deception.admin-portal:eusa]

**Authentication Service and SSO.** When Authentication Service is enabled, no other sign-in methods are allowed, and the Deception tile gives access to the Deception Admin Portal. [deception.admin-portal:auth-service-exclusive] In the Authentication Service sign-in flow, the reset link for a forgotten password or second factor expires after 15 minutes, and an email sign-in OTP expires after 15 minutes with Resend available after 60 seconds. [deception.admin-portal:auth-service-expiries] With SSO configured, clicking Zscaler Login on the Sign In page redirects to the IdP login page and back to the Deception Admin Portal on success; Zscaler recommends configuring primary and secondary external IdPs in the Authentication Service Admin Portal. [deception.admin-portal:sso-sign-in] Zscaler recommends using Authentication Service to add users and roles and to subscribe through Zscaler Support. [deception.admin-portal:auth-service-recommended] With Authentication Service enabled, users cannot be added in the Deception Admin Portal and are created in Authentication Service, only time zone and session inactivity timeout are editable there, and custom roles can be configured but not assigned to users. [deception.admin-portal:auth-service-user-management]

**Navigation.** The Deception dashboard (the Investigate tab) is the landing page showing logged forensics and attacker information graphically; Settings holds prerequisites such as Decoy Connectors, VLANs or subnets, plus users and roles, license consumption and audit trails. [deception.admin-portal:navigation-landing] System Messages shows audit logs, system messages and debug logs; Account Settings resets 2FA, edits profile, time zone and password; Help submits a ticket to Zscaler Support. [deception.admin-portal:navigation-icons] The Orchestrate page is where rules are automated, events are forwarded to SIEM or other log aggregation repositories, threats are contained, alerts enriched, and API tokens created. [deception.admin-portal:orchestrate-page-actions]

**Roles.** The predefined roles are Super admin (highest privilege: users, roles, APIs, modules, audit logs), Administrator, Analyst (which can also block or allowlist an attacker) and Responder. [deception.admin-portal:predefined-roles] Predefined roles cannot be edited or deleted, while a custom role can be edited or deleted in the Admin Portal. [deception.admin-portal:predefined-roles-immutable] Custom roles require super admin privileges and a subscription that supports them; a standard subscription gets an error that custom roles are not available for the plan. [deception.admin-portal:custom-roles-gating] A custom role is built from read or write permissions, and Read:ListUsers and Read:Appliances are mandatory to access modules in the Admin Portal. [deception.admin-portal:custom-role-mandatory-permissions] A user assigned more than one role has the permissions of all the configured roles. [deception.admin-portal:multiple-roles]

**Users.** A user's Login ID must be an email ID; Blocked prevents access, Notify Only gives email notifications without portal access, and Session Inactivity Timeout defaults to 30 minutes. [deception.admin-portal:user-fields] Disable Password Login turns off login with a locally set password while allowing SSO sign-in; the Users and Roles article says that if the option is not selected, Reset 2FA and Change Password will not be available on the Account Settings page. [deception.admin-portal:disable-password-login] User account activity information covers failed login attempts, user creation time, last login time and last password reset time, and user configuration details can be exported as a CSV file. [deception.admin-portal:user-list-and-export] Zscaler Support users who can access the Deception Admin Portal can be viewed, each with a Read-only or Admin role, and support user access can be disabled in the user authentication settings. [deception.admin-portal:remote-assistance]

**Account settings.** The Account Settings article states that the Reset 2FA and Change Password actions are available only if Disable Password Login was selected when the user was added. [deception.admin-portal:account-settings-availability-a] [deception.admin-portal:disable-password-login] [gap:deception.admin-portal:password-actions-condition] Resetting 2FA requires the account password and the current 2FA code, then a new QR code is scanned and a 6-digit OTP submitted. [deception.admin-portal:reset-2fa] The user profile consists of name and time zone; the name is shown in some configurations and on Support tickets, and the time zone is used for automated email alerts. [deception.admin-portal:profile-fields] Changing the password shows a strength meter and sends a confirmation email afterward. [deception.admin-portal:password-change]

**Notifications.** Account Settings notification preferences cover license, security alerts, system health and Zero Trust. [deception.admin-portal:notification-preference-categories] Only super admins can enable email alert notifications for a user, although every configured user can disable them for their own account. [deception.admin-portal:email-notification-permission] The per-user email notification categories are License (about to expire), Security Alerts (user settings changed, such as a password disabled globally), System Health (a component such as a Decoy Connector down, or network connectivity issues), and Zero Trust (IP address or FQDN conflicts with Private Access). [deception.admin-portal:email-notification-categories] The Zero Trust email notification option generates alerts on IP address or FQDN conflicts between Zero Trust Network decoys and Private Access systems; on the Users & Roles page, this notification is applicable if Zscaler Deception is configured in a SaaS environment. [deception.admin-portal:zero-trust-notification-scope]

**Allowed IPs.** The Allowed IPs allowlist entry takes a name and an IP or CIDR (all allows every address) and enables access per module: UI/APIV2, Decoy Connector (also aggregators), Endpoint (Landmine agents) and APIV1. [deception.admin-portal:allowed-ips-modules] Certain IP addresses for aggregators, TI management, Decoy Connectors and ZPA App Connectors are on the allowlist by default, and re-adding them gives an overlapping IP/CIDR found error. [deception.admin-portal:allowed-ips-defaults] Users and components such as Decoy Connectors, aggregators and Landmine agents can be locked out if their IP addresses are not on the allowlist. [deception.admin-portal:allowed-ips-lockout]

**QoS events.** QoS events for Threat Intelligence decoys act as an automated DDoS-protection layer; a QoS event is generated when the threshold of 10,000 events is exceeded within 60 minutes. [deception.admin-portal:qos-ti-threshold] After a QoS event Deception applies a two-hour cool-down during which no new QoS event is generated for the same attacker, and normal detection and logging resume once the attacker's event rate falls below the threshold. [deception.admin-portal:qos-cooldown] [gap:deception.admin-portal:qos-other-decoys]

What to check:
1. Whether Reset 2FA and Change Password are available to a user, which the Account Settings and Users & Roles articles tie to the Disable Password Login option.
2. When Authentication Service is enabled, the users and role assignments are managed in Authentication Service, not the Deception Admin Portal.
3. The module checkbox an allowlist entry needs for a component, and that a missing entry can lock out Decoy Connectors, aggregators and Landmine agents.

- Why Reset 2FA and Change Password need Disable Password Login selected [gap:deception.admin-portal:password-actions-condition]: settled by lab-test or support-ticket
