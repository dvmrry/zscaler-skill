# Interactive and file-based Gen AI decoys: types, datasets, limits, deployment targets and testing (deception.gen-ai-decoys)
Also called: generative AI decoys; Gen AI decoy

Deception supports interactive Gen AI decoys (chatbots, LLM servers, open-source platforms; deployable on Internal, Zero Trust Network (ZPA) or TI decoys) and file-based Gen AI decoys (resources used to set up local LLMs). [deception.gen-ai-decoys:types] Deception provides a Gen AI network decoy personality usable in manual network decoy configuration or in a deception strategy. [deception.gen-ai-decoys:personality] The MCP server decoy is in [Deception's MCP server decoy: an attacker-facing Gen AI service, not a management interface](kb:deception.mcp-server-decoys).

**Interactive decoys.** The interactive Gen AI application datasets are ChatBot (high-interaction) and Apache Airflow, Bento Frontend, ClearML, GitLab GenAI, JupyterHub, Metaflow, MLflow and Ray Serve (static). [deception.gen-ai-decoys:datasets] Up to three interactive Gen AI decoys using the high-interaction dataset can be deployed with Private Access and Internal decoys combined; the count for static datasets depends on the licensing agreement. [deception.gen-ai-decoys:high-interaction-limit] Interactive Gen AI decoys using high-interaction datasets do not support TLS, so TLS ports such as 443 should not be used. [deception.gen-ai-decoys:no-tls] Internet-facing Gen AI decoys via TI decoys use a Gen AI static application dataset; out-of-the-box high-interaction datasets are not supported for TI decoys. [deception.gen-ai-decoys:ti-static-only] To test an interactive Gen AI decoy, browse to the IP address or FQDN of the internal or Zero Trust network decoy with Gen AI service enabled, interact with it, and check the Investigate dashboard. [deception.gen-ai-decoys:test-interactive] To test a file-based Gen AI decoy deployed through a landmine policy, find an active agent with a matched policy under Settings > Endpoint Settings > Agents, note the file path shown in the Details pane, open the file in Windows PowerShell on the endpoint, and verify the event on the Deception dashboard. [deception.gen-ai-decoys:test-file-based]

**File-based decoys.** File-based Gen AI decoys are created from Gen AI file datasets on endpoints via landmine policies, Azure storage account container or file share decoys, AWS S3 decoys, or network decoys via FTP or Share service. [deception.gen-ai-decoys:file-assets] The Gen AI file datasets added are Falcon-7b (an LLM from the Technology Innovation Institute) and GPT-2 Large (an LLM from OpenAI). [deception.gen-ai-decoys:file-datasets] At most two preconfigured file dataset decoys can be deployed on each endpoint, and if more than two are configured any two are selected at random. [deception.gen-ai-decoys:endpoint-max-two] Deploying file-based Gen AI decoys to Azure or AWS requires cloud deception to be set up with that provider first. [deception.gen-ai-decoys:cloud-prereq] Azure file-based Gen AI decoys can be pointed to from landmine policies via cloud lures or session lures, and AWS ones via session lures. [deception.gen-ai-decoys:cloud-lure-pointing] On the Gen AI file-decoy page the Zero Trust Network FTP and Share procedures begin "Create a Zero Trust Network decoy." and their lead-in reads "To deploy a file-based Gen AI decoy via an internal network decoy:". [deception.gen-ai-decoys:ztn-file-service-scope]

**Detection.** Deception captures the prompt sent to a Gen AI decoy and categorizes it with the Gen AI Malicious Input Prompt ThreatParse rule; the malicious classification and category come from enrichment with Deception AI, so the gen ai malicious and gen ai malicious category values might be inaccurate. [deception.gen-ai-decoys:threatparse-rule] The vendor states content generated by the Deception AI is informational only and prone to inaccuracy and AI hallucinations. [deception.gen-ai-decoys:ai-disclaimer]
