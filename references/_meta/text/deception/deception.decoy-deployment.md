# Deploying and stopping decoys, the Deploy Strategy wizard, and Deceive Settings (blocklists, hashed passwords, hostname resolution, decoy groups) (deception.decoy-deployment)

A deployed strategy (single or combined) builds an environment in one click and can be deployed using Internal or Zero Trust Network (ZTN) decoys. [deception.decoy-deployment:strategy-what] The Deploy Strategy page lists each deployed strategy with its Name (the deployment name), Strategy (names of strategies deployed) and Summary (type and total number of decoys created and deployed). [deception.decoy-deployment:strategy-list-columns]

**Deploy Strategy wizard.** Deploying a strategy requires free IP addresses for trunked VLANs or subnets, and, for Internal decoys only, VLANs or subnets trunked or passed through the Decoy Connector's virtual NICs. [deception.decoy-deployment:strategy-prereqs] In the Deploy Network Strategy wizard the Default Automatic Decoys strategy is selected by default, and the landmine policy is enabled by default when Private Access decoys are selected. [deception.decoy-deployment:strategy-defaults] The Set Decoy Limit control scales the decoy counts of the selected strategy by a multiple; in the vendor's example a strategy with 1 Network, 2 TI and 2 AD decoys scaled by 2 yields 2 Network, 4 TI and 4 AD decoys. [deception.decoy-deployment:strategy-decoy-limit] Create Decoys & Deploy creates decoys and deploys them automatically and is for when no decoys are deployed or all active decoys are stopped; Create Decoys creates them to deploy later, and Start Decoys is then needed for the configuration to take effect. [deception.decoy-deployment:strategy-create-vs-deploy] For Private Access decoys in a strategy, Enable Real App adds and deploys decoys on unused ports of a real or production Private Access application segment. [deception.decoy-deployment:strategy-real-app] A deployed strategy's name is saved by default as '<Strategy name> <Date and time>'. [deception.decoy-deployment:strategy-name-default] In a strategy's Network Decoys tab, IPv6 can be configured only if an IPv6 subnet is selected in Network Segment/Subnet; the IPv6 field is applicable to Internal decoys only and does not appear for a Private Access decoy. [deception.decoy-deployment:strategy-ipv6]

**Starting and stopping.** The Deceive Summary page reports deployment health as Ready for deployment (all Decoy Connectors and service back ends up and running) or Action Required (some or all down). [deception.decoy-deployment:health-status] The Deceive Summary page (Deceive > Summary) shows all decoys created and deployed in the Admin Portal, the decoy deployment status percentage and the deployment health of Decoy Connectors and service back ends, and lets an admin start or stop decoys and view deployment logs to troubleshoot. [deception.decoy-deployment:deceive-summary-page-actions] Before configuring a network (Internal or Zero Trust Network) or Threat Intelligence decoy, all active decoys must be stopped, changed, and restarted for the configuration to take effect; stopping and starting affects only network and TI decoys, not landmine or AD decoys. [deception.decoy-deployment:stop-before-change] The edit and delete steps for a network decoy and for a TI decoy include Stop the decoys and Start the decoys. [deception.decoy-deployment:stop-before-edit-delete] Deployment logs show red text for deployment issues and can be filtered to failed entries only with Show Only Failed. [deception.decoy-deployment:deployment-logs]

**Editing a deployed strategy.** Editing a deployed strategy reopens the Deploy Network Strategy window, where each tab is modified and Next is clicked, and Create Decoys or Create Decoys & Deploy is clicked; deleting one needs a confirmation. [deception.decoy-deployment:deployed-strategy-edit]

**Deceive Settings.** Deceive Settings covers a blocklist firewall rule, SHA256 storage of adversary passwords, resolution of adversaries' hostnames and NetBIOS names, and network decoy groups. [deception.decoy-deployment:settings-scope] Blocklisted source traffic to the specified decoys and ports is dropped and not processed or stored, so it appears nothing is running on the destination port. [deception.decoy-deployment:blocklist-effect] A blocklist rule takes source IPs or CIDR blocks, a destination decoy IP (blank applies it to all decoy IPs on the selected Decoy Connector), ports separated by commas, and a Decoy Connector. [deception.decoy-deployment:blocklist-fields] A blocklist rule applied to a TI decoy uses 10.10.10.10 as the destination IP. [deception.decoy-deployment:blocklist-ti] A blocklist takes effect only after the decoys are started; bulk creation applies one rule across multiple Decoy Connectors. [deception.decoy-deployment:blocklist-apply] Blocklists can be deleted individually with the Delete icon, in a selection, or all at once with Delete All. [deception.decoy-deployment:blocklist-delete] By default adversary credentials entered on decoys are usually stored in plain text; enabling Hash Passwords stores them as SHA256 hashes, which shows repeated attempts of the same password without revealing it. [deception.decoy-deployment:hash-passwords] Hostname Resolution Settings resolve adversary hostnames by DNS and/or NetBIOS name, with a preferred method (DNS or NetBIOS) to use if both methods resolve to different results. [deception.decoy-deployment:hostname-resolution] A network decoy group logically organizes network and TI decoys (for example by business function, geographic region or system type) and categorizes detected alerts along those boundaries; it can be created from Deceive Settings or while creating a network decoy. [deception.decoy-deployment:decoy-groups]
