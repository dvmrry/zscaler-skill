# Endpoint settings (installer, lure refresh, update groups, safe processes) and Admin Portal settings (audit, error and debug logs, license, event and evidence export and delete, retention) (deception.endpoint-settings)

The Agent Configuration page customizes the installer properties (name, display name, description) so agents are not fingerprinted, modifies the lure refresh interval, and cleans up duplicate agents automatically. [deception.endpoint-settings:agent-configuration-purpose] Agents are in [Landmine agent and agentless: install, requirements, proxies, management and OS feature support](kb:deception.landmine-agents) and the hub is [Zscaler Deception: decoys and lures, the Private Access integration, roles, and what can be automated](kb:deception.overview).

**Installer properties.** The landmine service name defaults to Landmine and the display name to landmine; the display name and description apply only to Windows agents, Linux always uses the default name for its installation folder, and macOS installs under /Applications in a folder matching the name. [deception.endpoint-settings:installer-name-defaults] Zscaler recommends modifying installer properties before installing any agents; to keep consistency across previous and future installations after agents are deployed, the existing agents must be uninstalled and reinstalled. [deception.endpoint-settings:installer-customize-before] The landmine agent service name should be unique, and the names of services running on the target systems should be checked before configuring it to avoid conflicts. [deception.endpoint-settings:installer-name-unique]

**Lure refresh and clean-up.** The lure refresh interval is set in hours and policy changes apply as soon as the agent connects, without waiting for the lures to refresh. [deception.endpoint-settings:lure-refresh] Auto clean-up deletes landmine agents with duplicate hostnames, keeping the most recently connected ones and those connected for less than 7 days; deleted agents are not uninstalled from the system. [deception.endpoint-settings:auto-cleanup]

**Agent update groups.** After a landmine agent update is released all agents update as soon as they connect to the portal, but phased updates can be done with agent update groups that have criteria to selectively roll out the updates. [deception.endpoint-settings:update-groups-default] Enabling phased updates stops automatic updates for agents that are not in any agent update group. [deception.endpoint-settings:phased-updates-effect] An agent update group selects agents by Hostname List (exact match) or Hostname RegEx, and Zscaler recommends an "All systems" group with the catch-all expression .* enabled after testing so all endpoints are upgraded. [deception.endpoint-settings:update-group-criteria] Agent update group status is downloadable as a CSV and a group's hostnames export as a TXT file; the table shows selection criteria, update progress and update-enabled status. [deception.endpoint-settings:update-group-reporting]

**Safe processes.** Safe processes stop landmine defense-evasion false positives from legitimate security software (antivirus or EDR scans); events are generated only when an attacker interacts with the landmine processes, and Deception ships predesignated internal safe processes that can be enabled or disabled. [deception.endpoint-settings:safe-process-purpose] Safe processes are listed with executable file path and regex, executable file hash, certificate issuer, serial and thumbprint; hash and certificate fields are stated as applicable only to Windows endpoints. [deception.endpoint-settings:safe-process-fields] A safe process is configured for Windows or macOS with at least one identifying field; for Windows, if more than one field is configured the process is classified as safe only if all the field values match. [deception.endpoint-settings:safe-process-match] Enabling Check process tree means decoy interactions involving process trees that include these safe processes do not generate events. [deception.endpoint-settings:safe-process-process-tree] In the Windows safe-process Detection Type and Subtype table the rows are File Decoy read, Process Decoy killed, Ransomware shadowcopy_delete backup_file_delete process_terminate encryption_detected, and PsExec psexec; in the macOS table they are File Decoy read rename delete copy and Process Decoy killed. [deception.endpoint-settings:safe-process-detection-types] Internal safe processes can only be enabled or disabled, not edited otherwise, and cannot be deleted. [deception.endpoint-settings:safe-process-internal]

**Logs.** Audit logs are chronological records of Admin Portal user activities (such as login attempts, decoy creation, modification or deployment, profile updates), have Timestamp, Username, Module and Description fields, and export as CSV. [deception.endpoint-settings:audit-log-content] Error logs record failed events such as invalid user credentials, failed authentication and landmine agent version mismatch, with Timestamp, Category (component that caused the error), Module (entity affected), Message, Metadata, Error and Count fields. [deception.endpoint-settings:error-log-content] Error messages can be deleted or marked as read one at a time, or all at once from the Actions menu. [deception.endpoint-settings:error-log-actions] Admin Portal debug logs can be downloaded for the last 2 hours, 24 hours or 7 days, are prepared as an archive that takes a couple of minutes, and can be deleted from the portal afterward. [deception.endpoint-settings:debug-log-ranges]

**License.** The License tab shows client, plan, expiration, retention policy (days after which events and evidence files are permanently deleted), decoys used out of the plan total, landmine users used out of the plan total, and Admin Portal version. [deception.endpoint-settings:license-tab] What the Landmine Users limit is for a plan is open [gap:deception.endpoint-settings:landmine-user-limits].

**Events, evidence and retention.** Event logs can be exported for a From/To window as serializable JSON, and deleted for a window either entirely or only those marked as safe. [deception.endpoint-settings:event-export-delete] Evidence download and delete operations from a Decoy Connector handle up to 10,000 files or 3 GB of uncompressed evidence at a time, so large date ranges may need repeated runs. [deception.endpoint-settings:evidence-download-limit] On the Retention tab the retention period for event logs, audit logs, etc. is configured; the default is 365 days and can be reduced, data is permanently deleted after it expires, and the policy is defined in the license agreement. [deception.endpoint-settings:retention-default] What the default covers beyond event logs and audit logs is open [gap:deception.endpoint-settings:retention-coverage]. Events marked as safe are retained for 7 days and Okta system logs for threat detection for 14 days, and these retention periods cannot be modified. [deception.endpoint-settings:retention-fixed]

**Internal components.** Show internal components reveals Private Access components, such as Private Access Decoy Connectors and interfaces, in the Admin Portal. [deception.endpoint-settings:internal-components]

**Related subjects.** Policies are in [Landmine policies: what they deploy, which endpoints they select, and how the Windows endpoint deployment is set up](kb:deception.landmine-policies) and decoys in [Landmine decoy modules and lures: what each deploys, on which operating systems, and how it is tested](kb:deception.landmine-decoys). Subnets and aggregators are in [Topology: subnets and interfaces, aggregator sinkholes, ZPA App Connectors and Windows high-interaction VM credentials](kb:deception.topology), and recommended rollout is in [Best-practice guides: decoy minimums, landmine policy tables, containment rule expressions per decoy type, and the use-case recipes still open](kb:deception.best-practices).

What to check:
1. Whether the installer name was customized before agents were installed, since changing it afterward needs the existing agents uninstalled and reinstalled for consistency.
2. Whether phased updates are enabled and an agent is in an update group, since enabling the feature stops automatic updates for agents not in any group.
3. Whether hash and certificate fields on a safe process were set for a Windows endpoint, since the page states them as applicable only to Windows endpoints.
4. Whether an evidence download or delete operation needs repeated runs, since each handles up to 10,000 files or 3 GB of uncompressed evidence at a time.
