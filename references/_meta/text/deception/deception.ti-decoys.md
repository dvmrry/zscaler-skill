# Threat Intelligence (internet-facing) decoys: what they detect, how they are created, exported and tested (deception.ti-decoys)
Also called: TI decoy; Threat Intelligence decoy

Threat Intelligence decoys are unlisted, require reconnaissance (for example DNS bruteforcing or certificate transparency log enumeration) to discover, and give analytics of attacker activity early in the reconnaissance phase of the kill chain. [deception.ti-decoys:what-they-detect] TI decoys detect MITRE ATT&CK techniques T1589.001, T1592, T1594, T1595 and T1595.002 (Reconnaissance) and T1133, T1078 and T1190 (Initial Access). [deception.ti-decoys:mitre] TI decoy alerts ignore random internet noise, giving a strong signal-to-noise ratio, and can be cross-referenced with logs from non-decoy infrastructure. [deception.ti-decoys:signal-noise]

**The page.** The Threat Intelligence Decoys page shows for each decoy the sub-domain FQDN with a status icon, the network name, the type (Static, Dynamic, or High Interaction) and the assigned public IP. [deception.ti-decoys:page-columns] A TI decoy is added as a Static Application (static pages), Dynamic Application (dynamic components that respond to the latest threats) or High Interaction Application (a containerized version). [deception.ti-decoys:types]

**Creating one.** Creating a TI decoy requires permission to create DNS A records for the decoys. [deception.ti-decoys:dns-prereq] For a Deception-hosted TI decoy the Internal NAT IP is always 10.10.10.10; the field does not appear when a TI Decoy Connector is selected as Network Interface. [deception.ti-decoys:internal-nat-ip] Number of trusted proxies defaults to zero and is raised by one per proxy for a decoy behind a WAF, load balancer or CDN; those systems must keep the original attacker IP in the X-Forwarder-For request header. [deception.ti-decoys:trusted-proxies] TI decoy SSL certificates are self-signed by default; a custom certificate takes an unencrypted PEM private key and encrypted keys are not supported. [deception.ti-decoys:ssl] TI decoy Response Headers can add HTTP security headers (X-Content-Type-Options, Referrer-Policy, Permissions-Policy, Content-Security-Policy) and the HSTS header, and custom response headers make the decoy look realistic. [deception.ti-decoys:headers] The TI decoy page's custom response headers step says they are visible in a browser when an adversary accesses an Internal decoy. [deception.ti-decoys:custom-headers-scope] A TI decoy should not be configured behind a proxy that translates IPv6 to IPv4 (such as Cloudflare), since the portal does not alert about the IPv6 connection established; for Cloudflare use a DNS pointer, not a proxied connection. [deception.ti-decoys:cloudflare-ipv6] A TI decoy is placed automatically in a decoy group named Threat Intelligence. [deception.ti-decoys:decoy-group-default]

**AI-Powered Recommendations.** AI-Powered Recommendations generate TI decoys from a domain name; if wildcard DNS is enabled across the root domain Deception cannot recommend decoys, and a hostname that conflicts with an existing application is regenerated up to 5 retries. [deception.ti-decoys:ai-recommendations] In the steps to create TI decoys based on AI-powered recommendations, the steps include "Go to Deceive > Network Decoys > Zero Trust Network." and state that the decoys are deployed and active; the steps to create a TI decoy manually read "Go to Deceive > Threat Intelligence Decoys." [deception.ti-decoys:ai-verify-page]

**Export and test.** TI decoy configuration details are exported as a CSV file with Export Deployment Configuration. [deception.ti-decoys:export-config] TI decoy DNS configuration details can be exported as a CSV file with Export DNS. [deception.ti-decoys:export-dns] To test a deployed TI decoy, enter the decoy's URL in a browser and verify the page matches the application selected; if it has a login field, enter test credentials in both fields; then in Investigate open the threat icon's attacker details with View Extended Details and verify the activity on the ThreatParse and Event Logs tabs. [deception.ti-decoys:test-procedure] With the IPinfo integration enabled, the Deception Admin Portal attempts to geolocate the adversary and uses the country's flag as the threat actor's icon; without it, a unique threat icon is used. [deception.ti-decoys:ipinfo-icon]
