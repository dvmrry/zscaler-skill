# Active Directory decoys: domains, decoy users and computers, the deployment script, and the alert triggers that feed them (deception.ad-decoys)
Also called: active directory decoys; ad decoy user; ad decoy computer; ad domain; decoy deployment script; Start-Deployment.ps1; trigger script; ad triggers; siem triggers; enumeration detection

AD decoys are listed against MITRE ATT&CK T1110 (Brute Force), T1558 (Steal or Forge Kerberos Tickets) and T1087.002 (Account Discovery: Domain Account). [deception.ad-decoys:mitre] A decoy service account detects Kerberoasting attempts, a decoy privileged account detects privilege escalation techniques such as brute force, and decoy dictionary usernames use a popular list of usernames and passwords to detect brute force attacks. [deception.ad-decoys:use-cases] The Active Directory Decoys page actions are Add decoys (an AD decoy user), Delete decoys (one or more AD decoy users), Check decoys (verify that the AD decoy user is deployed) and Upload Enumeration Detection JSON (upload the deployment JSON file). [deception.ad-decoys:page-actions] See also [Landmine policies: what they deploy, which endpoints they select, and how the Windows endpoint deployment is set up](kb:deception.landmine-policies), [Landmine decoy modules and lures: what each deploys, on which operating systems, and how it is tested](kb:deception.landmine-decoys) and [Zscaler Deception: decoys and lures, the Private Access integration, roles, and what can be automated](kb:deception.overview).

**AD domain.** An AD domain can be added and configured with or without credentials; Zscaler recommends configuring it with credentials, as this is a prerequisite for a few features. [deception.ad-decoys:domain-with-without-creds] Adding an AD domain with credentials needs an AD user that can add computer objects to an AD and query LDAP on domain controllers, the root CA certificate of the primary domain controller, and connectivity from one of the Decoy Connectors to the AD domain controller over TCP port 636 (LDAP). [deception.ad-decoys:domain-creds-prereqs] Adding an AD domain without credentials needs the domain name, the FQDN or hostname of the primary domain controller and the NetBIOS name of the AD. [deception.ad-decoys:domain-prereqs] If the credentials setting is disabled, the computer objects must be added without credentials via a PowerShell script; the Username entered for a domain with credentials must have permission to add computer objects to the domain and make LDAP queries to the domain controller, and the Domain CA Certificate (.crt) is uploaded in the PEM format to enable a secure LDAP connection. [deception.ad-decoys:domain-no-creds] Decoy Connector as Receiver for Alerts sends all alerts to the selected Decoy Connector instead of the Deception Admin Portal, and Enable Enumeration Detection activates the enumeration detection feature for the AD domain. [deception.ad-decoys:domain-receiver] When an AD domain is created with credentials a domain CA certificate (.crt) in the PEM format is uploaded to enable a secure LDAP connection; exporting the certificate from AD CS in the Export File Format Base-64 encoded X.509 (.CER) and changing the extension from .cer to .crt produces it. [deception.ad-decoys:root-ca-export]

**Decoy users.** The decoy user's OU is the distinguished name of the organization unit, automatically populated if the AD domain is created with credentials and entered manually otherwise (for example OU=admins,OU=database,DC=example,DC=local); if the OU name is inaccurate, the deployment script throws an error during deployment. [deception.ad-decoys:user-ou] Decoy user attributes include Pre-auth Not Required (makes the account vulnerable to AS-REP roasting), Make Account Kerberoastable (configures the serviceprincipalname attribute), Restrict Logon To (the logonworkstations attribute), Profile Path (the profilePath attribute), Group membership and Description. [deception.ad-decoys:user-attributes] If a decoy user is added to the Protected Groups, enumeration detection doesn't always work because of the SDProp process. [deception.ad-decoys:user-protected-groups] The decoy user status icons are decoy successfully deployed, decoy updated but deployment is pending, decoy deployment pending and decoy deployment failed. [deception.ad-decoys:user-status-retry] If the decoy deployment has failed, Retry Failed Deployments submits the deployment request again. [deception.ad-decoys:user-retry-failed] For AD decoys created using domains managed by server agents, the deployment scripts do not have to be run manually; the server agent automates AD decoy user deployment. [deception.ad-decoys:user-server-agent] What a server agent is and how a domain becomes managed by one is open [gap:deception.ad-decoys:server-agent].

**Decoy computers.** The Decoy Computers page shows each AD decoy computer's OU path, operating system name, IP address and the Last Updated timestamp (password resets, login actions, etc.). [deception.ad-decoys:computers-view]

**Deployment script.** The deployment script must be run to create user accounts in both the credential and credential-less modes; running it needs admin access to the primary domain controller, PowerShell version 3.0 or later, and PSReadLine installed on the AD server to read user inputs. [deception.ad-decoys:script-prereqs] Editing the Default Domain Controllers Policy, Audit Logon, Audit Kerberos Authentication Service, Audit Kerberos Service Ticket Operations and Audit Directory Service Access are each configured for Success and Failure events; enabling the logs increases the volume of logs generated by the AD. [deception.ad-decoys:audit-policies] The deployment script (Start-Deployment.ps1) is copied to the primary domain controller; entering 1 creates a decoy user, 7 verifies the decoy deployment and 8 generates the deployment JSON file. If the script fails to upload the JSON file to the Deception Admin Portal it writes the file to the folder where the script is located, and the file must then be uploaded to the portal. [deception.ad-decoys:script-steps]

**Editing and deleting.** An AD domain managed by a server agent cannot be edited or deleted; after editing a domain the deployment script is downloaded and run again on the primary domain controller. Deleting an AD domain from the Deception Admin Portal does not remove the AD decoy objects created in the domain, and if the domain is created again the deployment scripts and the triggers must be redeployed. [deception.ad-decoys:domain-edit-delete] The page tells the admin that after editing an AD decoy user the deployment script is to be downloaded and run again on the primary domain controller to sync the updated attributes; if the username changes, to remove the existing trigger configuration and import the triggers again; and if a decoy user is deleted and created again, to redeploy the deployment script and import the triggers, which is not needed in an AD domain managed by a server agent. [deception.ad-decoys:user-edit-delete]

**Triggers.** The Deception Admin Portal supports trigger sources Domain controller (Task scheduler), Splunk, IBM QRadar, LogRhythm and Azure Sentinel; alerts can be triggered when AD decoy user accounts are accessed, or when enumeration attempts across AD decoy user or computer objects are detected. [deception.ad-decoys:sources] Importing the trigger script into Task Scheduler needs admin access to the AD domain controller, and all AD domain controllers must have access to the selected Decoy Connector on port 80 or the Deception Admin Portal on port 443. The Windows system can block the trigger script, so the .xml file is unblocked (right-click, Properties) before importing, and it is imported into every domain controller in the AD domain. [deception.ad-decoys:task-scheduler-prereqs]

**Azure Sentinel.** Azure Sentinel forwarding needs all AD servers configured to forward security logs to Azure Sentinel and network connectivity from the Azure Sentinel instance to the Deception Admin Portal on TCP port 443. [deception.ad-decoys:sentinel-prereqs] The Sentinel logic app is created in the same resource group as the log analytics workspace, with a Sliding Window configured for 1 minute, a query copied from the SecurityEvent code of the downloaded trigger script with Time Range "Last hour", an HTTP POST to the URI from the trigger script, and Allow chunking disabled to avoid data trimming. [deception.ad-decoys:sentinel-logic-app] The downloaded Azure Sentinel trigger script has a different SecurityEvent code and a different URI depending on the attack use case (Decoy User Accounts or Enumeration Detection) selected and the domain controller configuration. [deception.ad-decoys:sentinel-script-varies]

**IBM QRadar.** QRadar forwarding needs the AD servers configured to forward logs to QRadar, a Decoy Connector configured as a syslog receiver with the QRadar server's IP address in its allowed IP list, and network connectivity between the QRadar server and the Decoy Connector’s management IP on TCP port 9514. [deception.ad-decoys:qradar-prereqs] For the Decoy Connector's syslog receiver, Source Type is IBM QRadar and Source Allowed IPs is the QRadar server's IP address. [deception.ad-decoys:qradar-source-type] The QRadar forwarding destination is the Decoy Connector’s management IP address configured as a syslog receiver, with Event Format Payload, Destination Port 9514 and Protocol TCP. [deception.ad-decoys:qradar-forwarding] The QRadar event rule is configured with QIDs 5000937, 5000475, 5000945, 5000940, 5000938, 5000581, 5000589, 5000584 and 5000835; only one QID can be added at a time. [deception.ad-decoys:qradar-qids] How the QIDs map to Windows event IDs is open [gap:deception.ad-decoys:qradar-qid-event-mapping].

**LogRhythm.** LogRhythm forwarding needs all AD servers configured to forward security logs to the LogRhythm server and, if the Deception Admin Portal receives logs, connectivity from the LogRhythm server to it on TCP port 443, or, if a Decoy Connector receives logs, connectivity to the Decoy Connector’s management IP on TCP port 80. [deception.ad-decoys:logrhythm-prereqs] In the LogRhythm AI Engine rule, the Group By tab selects event IDs 4625, 4648, 4768, 4769, 4771 and 4776 to forward to the Deception Admin Portal, and the action is a SmartResponse Plugin. [deception.ad-decoys:logrhythm-event-ids] The Event Field Mapping tables map LogRhythm fields to PowerShell parameters and Event Viewer fields per event ID: for event 4625, User (Origin) maps to -TargetUserName (Event Viewer TargetUserName), and for event 4648, User (Origin) maps to -SubjectUserName; if the fields don't match, changes in the actions.xml file for the corresponding SmartResponse plugin might be needed. [deception.ad-decoys:logrhythm-field-mapping]

**Splunk.** Splunk forwarding needs all AD servers configured to forward security logs to the Splunk server and, if the Deception Admin Portal receives logs, connectivity between the Splunk server and it on TCP port 443, or, if a Decoy Connector receives logs, connectivity to the Decoy Connector’s management IP on TCP port 80. [deception.ad-decoys:splunk-prereqs] The Splunk alert is of type Real-Time, triggered Per-Result, with a Webhook trigger action to the URL of the Zscaler Deception API, and the query is copied from the triggers script (.txt file) downloaded from the Deception Admin Portal into the Search textbox. [deception.ad-decoys:splunk-alert] Which event IDs the Splunk and Sentinel queries filter on is not listed in these articles [gap:deception.ad-decoys:splunk-sentinel-event-ids].

What to check:
1. Whether the AD domain was added with credentials, since a few features need them and the OU is auto-populated only then.
2. Whether the deployment script was rerun after editing a domain or decoy user, and the triggers imported again after a username change or recreation.
3. Whether the audit policies named for the Default Domain Controllers Policy are enabled before deployment.
4. Whether every domain controller can reach the Decoy Connector on port 80 or the Deception Admin Portal on port 443 for Task Scheduler alerting.
5. Whether a decoy user placed in Protected Groups is relied on for enumeration detection.
