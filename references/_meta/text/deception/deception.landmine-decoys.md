# Landmine decoy modules and lures: what each deploys, on which operating systems, and how it is tested (deception.landmine-decoys)
Also called: defense evasion; privilege escalation module; file decoys; cloud lures; browser lures; session lures; advanced deception capabilities

The Defense Evasion module creates fake security processes (a Process Name and Process Path) on endpoints to trap adversaries who try to stop security processes such as antivirus, EDR or DLP; it is supported for Windows and macOS endpoints only, and the configured process can take more than two minutes to restart after it is stopped. [deception.landmine-decoys:defense-evasion] The policy that carries these modules is in [Landmine policies: what they deploy, which endpoints they select, and how the Windows endpoint deployment is set up](kb:deception.landmine-policies), the Active Directory decoys they can plant in memory are in [Active Directory decoys: domains, decoy users and computers, the deployment script, and the alert triggers that feed them](kb:deception.ad-decoys) and the product hub is [Zscaler Deception: decoys and lures, the Private Access integration, roles, and what can be automated](kb:deception.overview); see also [Landmine agent and agentless: install, requirements, proxies, management and OS feature support](kb:deception.landmine-agents) and [Endpoint settings (installer, lure refresh, update groups, safe processes) and Admin Portal settings (audit, error and debug logs, license, event and evidence export and delete, retention)](kb:deception.endpoint-settings). The per-feature limits are not stated in these articles [gap:deception.landmine-decoys:ranges-limitations].

**Privilege escalation.** MITM Detection in the Privilege Escalation module is supported on Windows, macOS and Linux endpoints via Landmine Agents only; it has an LLMNR poisoning option and an Interval (in minutes) to broadcast LLMNR name requests, and for each request a hostname is randomly selected, generated at random by the Deception Admin Portal if the field is blank. [deception.landmine-decoys:privesc-mitm] Brute Force Detection is supported on Windows and macOS endpoints via Landmine Agents only; Local Users detects brute force attacks against local admin accounts. With the default values of 5 and 30 minutes, a brute force attack is detected only if there are at least 5 unsuccessful login attempts within 30 minutes. [deception.landmine-decoys:privesc-brute] In-Memory Credentials Detection counters adversaries who harvest credentials from the LSASS process in memory after obtaining administrative or system privileges; Use AD Decoy Users plants decoy credentials using the usernames configured for the AD decoys, Use Additional Custom Credentials deploys them for a specified username and domain, and the detection is supported on Windows endpoints only via Landmine Agents. [deception.landmine-decoys:privesc-memory]

**File decoys.** A custom file decoy can be a Microsoft Office or HTML file (File Type such as PPT, XLSX, DOCX or HTML) placed on a specific path with a specific name; it is supported only for Windows (via both Landmine Agent and Agentless) and macOS (via Landmine Agent) endpoints, with a maximum of two per endpoint and any two selected at random if more are configured. [deception.landmine-decoys:custom-files] Credential file decoys are supported for Windows (via Landmine Agents), macOS (via Landmine Agents) and Linux endpoints (via Landmine Agentless only); the Network Credential section generates CSV files for network and Threat Intelligence (TI) decoys, the Credential section generates TXT files for network, cloud, TI and Active Directory decoys, and at most two credential file decoys are deployed on each endpoint. [deception.landmine-decoys:credential-files] For a credential file decoy, the Hidden option applies only to policies for Windows endpoints applied through Landmine Agents; for policies applied to Linux endpoints through Landmine Agentless, the file can be hidden by prefixing its name with a dot. [deception.landmine-decoys:credential-hidden] Preconfigured file datasets create a directory of decoy files for each endpoint using the file datasets defined in Miragemaker; file decoys using them are supported only for Windows and macOS endpoints via Landmine Agents, with a maximum of two per endpoint. [deception.landmine-decoys:preconfigured-datasets]

**Lure settings and advanced capabilities.** Lure Settings affect all the lures in the landmine policy: Use IP addresses instead of hostnames of decoys in lures ensures IP addresses are used instead of hostnames across the policy, and with Custom Username Configuration enabled and a dataset chosen from the Username Datalist drop-down menu, usernames for session and credential lures are selected randomly from that list. [deception.landmine-decoys:lure-settings] The Advanced Deception Capabilities module provides PsExec Detection, Ransomware Detection and Triage (events for processes making an outbound connection to the network or TI decoys), and is supported on Windows and macOS endpoints via Landmine Agents only. Ransomware Detection, for Windows endpoints running the Endpoint Deception Agent, deploys decoy files and processes commonly targeted by ransomware and identifies in-place encryption of decoy files, encrypt-and-rename or rename-then-encrypt activity, copy-encrypt-delete sequences and attempts to delete Windows volume shadow copies; a detection generates an event in Investigate, and the agent deploys an in-memory mutex that inoculates endpoints against specific ransomware strains. [deception.landmine-decoys:advanced-modules] In the supported features page's Advanced Deception Capabilities table, PsExec Detection, Ransomware Detection and Kerberoast Detection are marked Yes only for the Landmine Agent on Windows, and Triage is marked Yes for the Landmine Agent on Windows and macOS; every Landmine Agentless column is No. [deception.landmine-decoys:advanced-modules-matrix] The Kerberoast Detection (Decoy) option is shown in the Advanced Deception Module for tenants with Deception-only licenses; for tenants with Deception and ITDR licenses it is included in the Active Directory Threat Detection Module under ITDR > Manage > Threat Detection, and it is supported on Windows endpoints via Landmine Agent only. [deception.landmine-decoys:kerberoast-license]

**Testing.** To test defense evasion, the name of a fake security process is noted from the Details pane and the process is terminated in the Windows task manager; an event is recorded in the Investigate dashboard, which can be filtered with type=endpoint and sub_type=fake_process. [deception.landmine-decoys:test-fake-process] For testing, Catch All can be selected as the selection criterion for the landmine policy; it applies policies to all endpoints, so caution is advised. [deception.landmine-decoys:test-catch-all]

**Cloud lures.** Cloud lures are AWS IAM (places credentials of selected decoy AWS IAM users on endpoints), Azure File Shares (mounts selected file share decoys), Azure Service Principals (places secrets of selected service principal decoys), Azure Users (places credentials of selected decoy Azure users), Azure Storage Explorer (access to storage account container decoys via the Azure Storage Explorer app) and GCP Service Account (to access other GCP decoys); the supported AWS and Azure decoys must be configured before the cloud lures. [deception.landmine-decoys:cloud-types] The cloud lures page says the AWS IAM lure creates a hidden folder named .aws under C:\Users\<username>\ on Windows endpoints and under /users/<username>/ on Linux endpoints to store the credentials; service principal decoys and Azure user decoys are not supported on Linux endpoints. The supported features page marks AWS IAM Yes for the Landmine Agent and Agentless on Windows, macOS and Linux. [deception.landmine-decoys:cloud-folders] Where the AWS IAM lure stores credentials on macOS is open [gap:deception.landmine-decoys:cloud-lure-macos-folder]. The Azure Service Principals cloud lure creates a hidden folder named .azure under C:\Users\<username>\ on Windows endpoints to store secrets. [deception.landmine-decoys:azure-sp-folder] The Azure Users cloud lure creates a hidden folder named .azure under C:\Users\<username>\ on Windows endpoints to store secrets. [deception.landmine-decoys:azure-user-folder] With the Azure File Shares cloud lure enabled, the decoy file share is mounted as a network drive on the endpoints. [deception.landmine-decoys:cloud-fileshare]

**Browser lures.** Browser lures add decoy credentials, cookies and bookmarks to browsers such as Google Chrome, Mozilla Firefox and Microsoft Edge on endpoints; Windows endpoints support lures for Chrome, Firefox and Edge, macOS endpoints for Chrome only, and Linux endpoints for Chrome and Firefox. [deception.landmine-decoys:browser-matrix] If the Target decoys field is blank, all of the decoys running the web service are used as a default pool, and a maximum of two decoys are deployed for each browser and the type of lure. [deception.landmine-decoys:browser-targets] For Edge browser lures on endpoints running landmine agent or agentless up to version 4.23, the Force Apply option (disabled by default) disables the Startup boost option in the browser settings; when Startup boost is enabled the browser runs in the background with minimal processes, which can prevent landmine policies from being applied to the browser; for later versions the policies are applied even if Startup boost is enabled in Edge, without Force Apply. [deception.landmine-decoys:browser-edge] For Chrome browsers, a new profile with a random name is created to store lures, maintained as a hidden profile alongside the default user profile. [deception.landmine-decoys:browser-chrome-profile] Passwords for the browser lures are generated according to the rules configured in the Password Settings module. [deception.landmine-decoys:browser-passwords] If the target decoy is an authentication-enabled generative AI decoy and the Credentials lure option is enabled for a browser, adversaries can use the fake credentials stored in the browsers to log in to the generative AI decoys. [deception.landmine-decoys:browser-genai-auth]

**Session lures.** On Windows endpoints the session lures are DbVisualizer and SQuirrel DB (network decoys with MySQL or PostgreSQL), PuTTY and WinSCP Session (SSH service), RDP and Windows Credentials (Windows service), Network Drives (Shares service) and FileZilla (FTP service). [deception.landmine-decoys:session-windows] The RDP session lure adds credentials for the decoy Windows VM to Windows Credential Manager and a file to initiate a connection to it in the current user's Documents folder (%userprofile%\Documents); selecting Hidden prevents users from using the RDP file. [deception.landmine-decoys:session-rdp] On macOS endpoints the session lures page lists FileZilla (FTP service), the /etc/hosts file (Web service and TI decoys), Bash/Zsh History, and the SSH config file, where information to access the decoy SSH servers is placed into /etc/ssh/ssh_config. [deception.landmine-decoys:session-macos] Whether DbVisualizer applies on macOS differs between pages [divergence:deception.landmine-decoys:session-dbvisualizer-macos]. On Linux endpoints the session lures include FileZilla (FTP service), the /etc/hosts file (Web service and TI decoys), Bash/Zsh History (Web, FTP and SSH services and TI decoys, adding commands to the bash or Z shell history) and the SSH Config File (SSH service). [deception.landmine-decoys:session-linux] When no decoy is selected for a session lure, a target decoy is chosen randomly if a decoy with a supported service is enabled and deployed; a maximum of two decoys are deployed for each lure type. [deception.landmine-decoys:session-targets] What the session lure article means by adding the target decoy to "the browser" is open [gap:deception.landmine-decoys:session-lure-browser-wording].

What to check:
1. Which operating systems a module supports, since Defense Evasion is supported on Windows and macOS only and advanced capabilities on Windows and macOS via Landmine Agents only.
2. Whether a custom file decoy, credential file decoy or preconfigured dataset decoy applies to the endpoint's OS and installer type, and that at most two of each are deployed per endpoint.
3. Which browser a lure targets on which OS before relying on it.
4. That Catch All applies a test policy to all endpoints.
