# The AI Guard Topic and Off Topic detectors: OR and AND triggering, topic definitions, limits, threshold and languages (ai-security.ai-guard.detectors.topic)
Also called: off topic detector; off-topic detector; topic detector; ai guard topic definition

The Topic detector flags a prompt when it is semantically related to any configured topic (aggregation OR: triggers if any topic matches), and the Off Topic detector does the inverse, triggering when the prompt does not match any configured topic (aggregation AND: triggers only if no topic matches); the runbook says both use the same underlying model and topic definitions, that the only difference is when they trigger, that Topic is for blocking or logging sensitive subjects (salary, medical, weapons, legal) and Off Topic for keeping users on task, and that they evaluate independently. [ai-security.ai-guard.detectors.topic:two-detectors] This subject is the Topic and Off Topic runbook; the detector list is in [AI Guard's detectors: the capabilities Help lists and the detectors the policy editor configures](kb:ai-security.ai-guard.detectors).

**How matching works.** The runbook says the detector does not perform keyword matching by exact substring but uses semantic understanding (block in writer's block will not trigger a topic about blockchain), does not chunk long prompts so mentions buried deep in very long prompts may be missed, and does not replace content filtering (toxicity, PII, jailbreak) because topic detection is about subject matter, not safety. [ai-security.ai-guard.detectors.topic:semantics] The runbook's example row contradicts its own table [divergence:ai-security.ai-guard.detectors.topic:example-row].

**Topic definitions.** Each topic is a Topic Name plus a Topic Definition, both of which contribute to what the detector matches (the name gives the model additional semantic context, so it should relate to the definition); a definition can be a natural language description, which the runbook says works best for broad semantic matching, or a Keyword List of comma-separated keywords (example: diabetes, thyroid, cancer) that are each evaluated independently and work best for precise, specific terms; the runbook says to avoid parentheses, regex syntax and special characters, and calls a single-word definition such as Manager too vague. [ai-security.ai-guard.detectors.topic:topic-definition]

**Limits and actions.** The runbook gives the Custom Topic (Topic) or Topic Definition (Off Topic) field up to 10 topics, each with a Name and a Definition; each topic can have its own action override so Block and Detect can be mixed in one policy; more than 10 topics per policy increases noise and latency; and each policy has its own Topic and Off-Topic configuration. [ai-security.ai-guard.detectors.topic:limits-actions]

**Threshold.** The Topic and Off Topic runbook gives the threshold a default of 0.7, which Zscaler strongly recommends keeping; its ranges are 0.80 to 1.00 (only strong, direct matches trigger), 0.5 to 0.7 (semantically related content triggers even with different phrasing or indirect discussion, recommended for most production deployments, starting at 0.7) and below 0.50 (loose or tangential connections trigger); for a vague single-word definition such as Manager it says to improve the definition first. [ai-security.ai-guard.detectors.topic:threshold] Whether Off Topic has a threshold at all is disputed in [AI Guard's detectors: the capabilities Help lists and the detectors the policy editor configures](kb:ai-security.ai-guard.detectors).

**Languages and logs.** The runbook says to define the topic in English and that the detector handles 28 languages natively, listing Arabic, Chinese, French, German, Hindi, Japanese, Korean, Portuguese, Russian, Spanish, Thai, Turkish and Vietnamese, and more, out of the box; prompts under about 10 characters do not give the model enough context. [ai-security.ai-guard.detectors.topic:languages] The 28-language count is disputed: [ai-security.ai-guard.detectors:supported-languages](kb:ai-security.ai-guard.detectors:supported-languages). The runbook says the detection log contains the full response JSON, including confidence scores per topic, which is the same data the policy engine uses. [ai-security.ai-guard.detectors.topic:log-scores]
