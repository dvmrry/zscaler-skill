# Cline hooks for AI Guard (Zscaler example): hooks, directions, cancel handling, and the missing-key allow (ai-security.ai-guard.integrations.cline)
Also called: cline aiguard hooks; .clinerules/hooks; TaskComplete; cline cancel

Zscaler's Cline example is a set of hook scripts Cline discovers in the workspace's .clinerules/hooks directory; each calls AI Guard's detection API through the Python SDK.

**What is hooked.** The example ships four Cline hook scripts in `.clinerules/hooks/`: `UserPromptSubmit` and `PreToolUse` scan with direction `IN` and can block, `PostToolUse` scans with `OUT` and can block, and `TaskComplete` scans with `OUT` but cannot cancel (Cline marks it not cancellable). [ai-security.ai-guard.integrations.cline:hooks] The README says no hook sees the model's plain-text reply when no tool runs, and that `PostToolUse` runs only when a tool returns content. [ai-security.ai-guard.integrations.cline:no-reply-hook] A hook blocks by printing `{"cancel": true, "errorMessage": ...}` on stdout and exiting 0, not by exit code 2. [ai-security.ai-guard.integrations.cline:block-signal]

**Which call it makes.** `aiguard_utils.py` loads `.env` from the repository root and then `Cline/.env` with python-dotenv without overriding the environment, reads `AIGUARD_CLOUD` (blank or unset means `us1`) and `AIGUARD_TIMEOUT` (default 30), calls `execute_policy` when `AIGUARD_POLICY_ID` parses as an integer and `resolve_and_execute_policy` otherwise, and logs to `.clinerules/hooks/aiguard.log`. [ai-security.ai-guard.integrations.cline:config] The endpoints are in [Calling AI Guard at runtime: the proxy endpoint, the DAS detection API, its host, direction and policy ID, and throttling in the Python SDK](kb:ai-security.ai-guard.runtime-api).

**Verdicts and failures.** With no `AIGUARD_API_KEY`, every hook allows without scanning, and `UserPromptSubmit`, `PreToolUse` and `PostToolUse` log a warning; the README calls this a local development convenience. [ai-security.ai-guard.integrations.cline:missing-key-allows] In `UserPromptSubmit`, `PreToolUse` and `PostToolUse`, a scan error (including a response without an action) and any action other than `ALLOW`, `BLOCK` or `DETECT` cancel; `BLOCK` cancels with the severity, policy, transaction ID and blocking detectors; `ALLOW` and `DETECT` continue. [ai-security.ai-guard.integrations.cline:errors-cancel]

**What content is scanned.** `PreToolUse` scans `execute_command` on its command and `write_to_file` on its content; for `use_mcp_tool` it scans `query`, `search_query` or `q` when the MCP tool's name contains `search`, `url` or `uri` when it names a fetch, else the first of the `query`, `prompt`, `message` and `content` arguments, else the text `Accessing resource:` with a path-like argument, and only then the whole arguments JSON; any other tool is scanned as its parameters JSON. [ai-security.ai-guard.integrations.cline:pre-tool-extraction] `PreToolUse` sends that content untruncated, unlike the 20000-character cut the other hooks apply. [ai-security.ai-guard.integrations.cline:pre-tool-untruncated] An MCP call that carries any of the named arguments is scanned on that one argument (or only on a path label); its other arguments reach the MCP server unscanned. [ai-security.ai-guard.integrations.cline:mcp-partial-scan] `PostToolUse` scans the tool result with newlines replaced, truncated to 20000 characters; for MCP tools it scans one text combining server, tool, the arguments (truncated) and the output; content under 10 characters is allowed unscanned. [ai-security.ai-guard.integrations.cline:post-tool-content] `TaskComplete` scans the payload's `task` text (truncated to 20000 characters) with direction `OUT` and only logs: a `BLOCK` is written as a would-block alert, and scan errors are logged as audit-only. [ai-security.ai-guard.integrations.cline:task-complete-audit] What the task field holds is open [gap:ai-security.ai-guard.integrations.cline:task-field].

**After the tool has run.** What a PostToolUse cancel achieves is open [gap:ai-security.ai-guard.integrations.cline:post-tool-cancel-effect]. The comparison with other hosts is in [Zscaler's AI Guard integration examples (zguard-ai-integrations): the catalog, the promised fail-closed posture against what each example does, and where each intercepts](kb:ai-security.ai-guard.integrations).

What to check:
1. That AIGUARD_API_KEY is set where Cline launches the hooks: without it every Cline hook allows unscanned.
2. Whether replies the model writes without calling a tool need scanning; no Cline hook sees them.
3. Whether MCP calls carry sensitive data outside the one argument the hook scans.
