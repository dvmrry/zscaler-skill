# How AI Asset Management external integrations work: Amazon S3, Azure Blob Storage, Amazon Security Lake, ServiceNow and Jira (ai-security.asset-management.integrations)
Also called: ai security external integrations; ai security cloud storage integration; ai security security lake; ai security servicenow integration; ai security jira integration

AI Security integrates with Amazon S3, Azure Blob Storage and Amazon Security Lake cloud storage services to send alert data logs, and with ServiceNow and Jira as ITSM tools. [ai-security.asset-management.integrations:supported-services] Only users with the administrator role can configure cloud storage integrations. [ai-security.asset-management.integrations:admin-only] The hub is [AI Asset Management in the AI Security Admin Portal: what it inventories, signing in, first-time configuration order, table behavior](kb:ai-security.asset-management). [gap:ai-security.asset-management.integrations:integration-scope-and-delete]

**Cloud storage integrations.** The list of cloud storage integrations shows Last Sent and a Status of Success, Failed, Paused or Pending for the previous data transfer, with the failure reason on hover. [ai-security.asset-management.integrations:list-status-values] Data transfer is enabled by default on a cloud storage integration; disabling it pauses transfer without deleting the integration, and a transfer in progress completes first. [ai-security.asset-management.integrations:data-transfer-toggle] [gap:ai-security.asset-management.integrations:alert-vs-issue-rules]

**Amazon S3.** The Amazon S3 integration authorizes AI Security through an S3 bucket policy that is copied from the Admin Portal and pasted into the bucket in the AWS console, and takes the bucket name and Folder Location. [ai-security.asset-management.integrations:s3-bucket-policy] For the Amazon S3 integration the bucket default encryption must be Amazon S3 managed keys (SSE-S3) for the connection to succeed; with AWS Key Management Service (SSE-KMS) the connection fails. [ai-security.asset-management.integrations:s3-sse-kms] A new Amazon S3 integration shows Pending until Issue rules are configured and associated with it and AI Security sends data logs, after which the status changes to Success. [ai-security.asset-management.integrations:s3-initial-pending]

**Azure Blob Storage.** The Azure Blob Storage integration sends issue data logs to Blob Storage containers for storage and data analysis by external tools; its status starts as Pending until issue rules are configured and associated and data is sent, then changes to Success. [ai-security.asset-management.integrations:blob-purpose-pending] The Azure Blob Storage integration uses a storage account connection string from the Azure portal; Container Location is optional, but a folder must first be created in Blob Storage before its name is entered. [ai-security.asset-management.integrations:blob-connection-string]

**Amazon Security Lake.** Amazon Security Lake uses the Open Cybersecurity Schema Framework (OCSF) for the alert information and requires the Parquet file format for stored alerts; the AI Security integration exports alert data to a pre-configured S3 bucket. [ai-security.asset-management.integrations:seclake-ocsf-parquet] Zscaler is set up as a custom source in Security Lake using the Security_Finding event class, in the region where the AWS console is connected; the data source name determines the path in the S3 bucket. [ai-security.asset-management.integrations:seclake-custom-source] The custom source takes the AI Security AWS account ID and External ID copied from the Cloud Storage page of the Admin Portal, which identify AI Security as the source writing to the data lake; the ARN IAM role copied after creating the source is entered in the integration. [ai-security.asset-management.integrations:seclake-ids-role] The Security Lake integration takes the IAM role ARN, S3 bucket name, bucket region and folder location, and its Test Connection validates that the S3 bucket exists. [ai-security.asset-management.integrations:seclake-fields-test] A new Amazon Security Lake integration shows Pending until alert rules are configured and associated and AI Security starts sending alert data, after which the status changes to Success. [ai-security.asset-management.integrations:seclake-pending] Alert files in Security Lake are posted when the file size reaches 256 MB or after 5 minutes, under the custom source root path in the folder structure region=<awsregion>/accountid=<cloudaccountid>/eventDay=<YYYYMMDD>. [ai-security.asset-management.integrations:seclake-partitioning] Alerts exported to Security Lake carry static OCSF values category_name Findings, category_uid 2, class_name Security Finding, class_uid 2001, metadata.product.name ai security, metadata.product.vendor_name zscaler and metadata.version 2.2. [ai-security.asset-management.integrations:seclake-ocsf-static] In the OCSF mapping, severity comes from the AI Security cloud alert field risk, finding.uid from alert_id, finding.title from policy_name, time from csp_event_timestamp, status from alert_status and status_detail from alert_status_description. [ai-security.asset-management.integrations:seclake-ocsf-map] Security Lake troubleshooting: a Glue Crawler failing to parse alert data in the bucket typically means the custom source used the wrong event class (it must be Security Finding); a Failed status means AI Security lacks permission on the S3 bucket; alerts present in the Admin Portal but not exported call for checking the alert rule notification configuration and scope. [ai-security.asset-management.integrations:seclake-troubleshoot]

**ServiceNow.** The ServiceNow integration needs an online ServiceNow instance, a ServiceNow user with the roles import_admin, import_set_loader and import_transformer, and an inbound integration using OAuth – Client Credential Grant limited to the Table API and Import Set API. [ai-security.asset-management.integrations:servicenow-prereqs] The ServiceNow integration uses OAuth 2.0 as the authentication method by default, and after saving, the integration appears on the Integrations page and up to an hour should be allowed for data to be pushed into the ServiceNow tables. [ai-security.asset-management.integrations:servicenow-auth-delay] The ServiceNow integration can sync the asset types Agents, Data stores, MCP servers, Guardrails, Models, Workloads, Software Libraries, Code Repositories and Identities, or all of them, and an Issues toggle pushes findings. [ai-security.asset-management.integrations:servicenow-sync] The ServiceNow integration page describes two routing methods for issues: Create Ticket pushes issues to the ServiceNow Import Set (staging) table, and Import Set Table pushes issues directly to the ServiceNow Incident table. [ai-security.asset-management.integrations:servicenow-routing] [gap:ai-security.asset-management.integrations:servicenow-routing-names] The ServiceNow integration takes a Table Prefix for the import set tables, and a downloaded JavaScript script run in the ServiceNow JavaScript console creates the import set tables and necessary roles; Check Tables can fail if the integration user lacks sufficient roles even when the tables exist. [ai-security.asset-management.integrations:servicenow-tables] [gap:ai-security.asset-management.integrations:servicenow-client-secret-field]

**Jira.** AI Security uses Jira APIs to create tickets automatically when sensitive data or misconfigurations are detected in cloud resources; the integration steps validate the Jira connection with Authorize and select the required Jira project from a drop-down menu. [ai-security.asset-management.integrations:jira-purpose] The Jira integration needs an OAuth 2.0 (3LO) app created in the Atlassian Developer console with Jira API scopes (example read:jira-work) and the Admin Portal application URL as its Callback URL; the Client ID and Client Secret are entered in AI Security, which can integrate with Jira cloud versions that support the required authentication mechanism and APIs. [ai-security.asset-management.integrations:jira-oauth]

What to check:
1. The bucket encryption key type on an Amazon S3 integration: SSE-S3 for the connection to succeed, and the connection fails with SSE-KMS.
2. Whether a Security Lake integration still shows Pending: it stays Pending until alert rules are configured and associated and AI Security starts sending alert data.
3. Which event class the Security Lake custom source uses when the Glue Crawler cannot parse the alert data: the page requires the Security_Finding event class.
4. The ServiceNow data delay: the page says to allow up to an hour for data to be pushed into the ServiceNow tables.
