# The AI Guard configuration API: behavior the contract states, limits and errors, and what the Python SDK covers (ai-security.ai-guard.admin-api)
Also called: ai guard api; aiguard api; ai guard admin api; ai guard configuration api; /aiguard/v1; llm-provider-types; referential-check; regenerate application credential; deleteReferences; ai guard 409; ai guard rate limit; ai guard python sdk; client.aiguard; ai guard terraform; ai guard go sdk; ai guard automation

The configuration API's paths, operations and request and response fields are generated from the captured contract and the Python SDK: run `node scripts/kb.mjs surface aiguard` and read `vendor/zscaler-api-specs/automate-zscaler/openapi/aiguard.openapi.json`. This subject holds the behavior around them and where the sources disagree.

**Clients.** Help's AI Guard API page points to the Zscaler Automation Hub API Reference Guide for all available AI Guard API policies, references and summaries, and lists six resource categories: Detection Policies, Detection Policy Match Rules, LLM Application Credentials, LLM Applications, LLM Provider Credentials and LLM Providers. [ai-security.ai-guard.admin-api:help-categories] In the Python SDK every AI Guard configuration resource (detection policies, policy match rules, LLM providers and credentials, LLM applications and credentials) is reached through OneAPI with `ZscalerClient` as `client.aiguard`; only policy detection uses the legacy client. [ai-security.ai-guard.admin-api:python-oneapi] No Go SDK package, Terraform provider resource, Ansible module or MCP server tool calls the AI Guard API; the Python SDK is the only vendored client. [ai-security.ai-guard.admin-api:no-other-clients] The base path is in [The guide's base paths are: ZIA `/zia/api/v1`; ZPA `/zpa/mgmtconfig/v1`, `/zpa/mgmtconfig/v2` and `/zpa/userconfig/v1` (the last for SCIM attribute and group endpoints); ZDX `/zdx/v1`; Authentication Service `/ziam/admin/api/v1`; Client Connector `/zcc/papi/public/v1`; Cloud & Branch Connector `/ztw/api/v1`; Business Insights `/bi/api/v1`; EASM `/easm/easm-ui/v1`; Cellular `/zcell/config/api/v1`; Event Monitoring & Notification `/event-monitoring`; Unified RBAC `/urbac/urbac`; AI Security `/aisecurity/aispm/v1` (AI Infrastructure) and `/aisecurity/airt/api/v2` (AI Red Teaming); AI Guard `/aiguard/v1`.](kb:shared.oneapi.base-urls:base-path-table) and the deprecated `client.zguard` alias in [In the Python SDK, `client.zguard` is a deprecated alias for the `aiguard` property.](kb:shared.terminology.product-names:zguard-alias). Wider client coverage is open [gap:ai-security.ai-guard.admin-api:other-clients].

**Limits and errors.** Every AI Guard API endpoint is limited to 1,000 calls per minute per tenant; responses carry `x-ratelimit-limit`, `x-ratelimit-remaining` and `x-ratelimit-reset`, the last being the seconds left in the current window. [ai-security.ai-guard.admin-api:rate-limit] Errors are RFC 9457 problem details returned as `application/problem+json` with type, title, status, detail and a correlation id; validation errors add a `fields[]` array, and a 401 carries a WWW-Authenticate Bearer header. [ai-security.ai-guard.admin-api:error-format] List operations return the resources inside a JSON object of the form `{ "items": [] }`. [ai-security.ai-guard.admin-api:list-shape] Deleting a policy, provider, provider credential, application or application credential that an active configuration references is blocked with 409 while `deleteReferences` is false, the default; where supported, `deleteReferences=true` removes the references before the delete. [ai-security.ai-guard.admin-api:delete-409]

**Actions.** The contract publishes action operations as colon suffixes on the resource path: `:enable`, `:disable` and `:referential-check` on detection policies, `:referential-check` on providers, provider credentials, applications and application credentials, and `:regenerate` on application credentials. [ai-security.ai-guard.admin-api:colon-action-routes] Enabling or disabling a policy flips its match rules: [Enabling or disabling a detection policy through the API turns every match rule that references it on or off, and the response lists those rules with their new state; disabling does not delete the policy.](kb:ai-security.ai-guard.policies:enable-disable-match-rules).

**Providers and credentials.** The provider-types operations list the supported LLM provider types with server guidance, to be called to discover the correct `servers` keys and values before creating or updating a provider; the contract marks its provider-type list as not exhaustive. [ai-security.ai-guard.admin-api:provider-types] Provider credential secrets are never returned: `apiCredentials` is write-only; an update with new `apiCredentials` rotates the secret, and one with only the name or expiration leaves it unchanged. [ai-security.ai-guard.admin-api:provider-credentials-write-only] Application credentials return their plaintext API key exactly once, on create and on regenerate; regenerate invalidates the previous key, and an update can change only the display name and expiration. [ai-security.ai-guard.admin-api:app-credentials-once] Listing application credentials is per service mode and defaults to PROXY. [ai-security.ai-guard.admin-api:app-credentials-mode] How Help's application names map to provider types is open [gap:ai-security.ai-guard.admin-api:provider-labels].

**What the Python SDK covers.** The Python SDK's policies module defines list, get by ID, get by name, add, update and delete, and no other method. [ai-security.ai-guard.admin-api:python-policies-methods] In each of the Python SDK's provider, provider-credential, application and application-credential modules the `referential_check` method is commented out, with a note that the endpoint returned HTTP 404 for every resource type, including through Postman with a known-good ID, and is to be re-enabled once the endpoint is live. [ai-security.ai-guard.admin-api:python-referential-commented] Eight operations of the contract have no callable Python method: policy enable, disable, referential check and policy summaries, and the referential checks for providers, provider credentials, applications and application credentials. [ai-security.ai-guard.admin-api:python-unwrapped] The SDK's documentation and its code disagree on referential checks [divergence:ai-security.ai-guard.admin-api:referential-check-availability], and its regenerate path differs from the contract's [divergence:ai-security.ai-guard.admin-api:regenerate-path]. Live acceptance of those operations is open [gap:ai-security.ai-guard.admin-api:live-acceptance].

What to check:
1. For a Python script, whether the operation is one of the eight the SDK does not wrap; call it through the raw OneAPI path from the generated surface instead.
2. On a 409 from a delete, which active configuration still references the object, or whether deleteReferences=true is supported for it.
3. Before creating a provider, read the provider type's server guidance from the provider-types operation rather than hard-coding servers.
4. On 429, the per-tenant budget of 1,000 calls per minute and the x-ratelimit headers.

Sources disagree (name both sides):
- Whether the Python SDK offers referential checks. [divergence:ai-security.ai-guard.admin-api:referential-check-availability]
  - sdk-python: The SDK README says the providers, provider-credentials and applications resources run referential checks.
  - sdk-python: The 1.9.39 changelog lists the referential-check endpoints among those added.
  - sdk-python: The code has every referential_check method commented out, citing HTTP 404 from the endpoint.
  - api-specs: The contract publishes the referential checks as colon-suffixed GET operations.
  Impact: A Python user following the README finds no referential_check method; the contract documents the operations, and whether they answer live is unverified.
- The path of the application-credential regenerate action. [divergence:ai-security.ai-guard.admin-api:regenerate-path]
  - sdk-python: The Python SDK posts to /llm-application-credentials/{credential_id}/regenerate, a slash path.
  - api-specs: The contract publishes the action as /v1/llm-application-credentials/{id}:regenerate.
  - zscaler-help: The AI Guard response-codes page lists enable, disable and regenerate actions as POST /{id}/actions.
  Impact: The SDK's regenerate_credential call uses a path the contract does not publish; whether the service accepts it is unverified, so a failed regenerate from Python may be a path problem rather than a permission one.
