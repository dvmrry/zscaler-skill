# Account onboarding in AI Security: supported targets, page metrics, integration tabs and actions, Copilot Studio, GitHub and Azure prerequisites and scopes (ai-security.asset-management.onboarding)
Also called: account onboarding; ai security onboarding; onboard copilot studio; onboard github tenant; onboard azure tenant or management group; zscaler hosted single azure subscription; configured integrations table; orchestrator config status

AI Security supports onboarding AWS accounts, Azure subscriptions, GCP projects and SaaS applications such as Microsoft Copilot Studio; onboarded accounts are continuously monitored and scanned for sensitive data and vulnerabilities, and issues are generated from data security policy violations. [ai-security.asset-management.onboarding:supported-targets] The Step-by-Step Configuration Guide says AWS organizations, Microsoft Azure tenants or GCP organizations can be onboarded into AI Security. [ai-security.asset-management.onboarding:guide-units]

**The Account Onboarding page.** The Account Onboarding page (Administration> Account Onboarding) reports four metrics: Total Environments, Healthy Integrations, Unhealthy Integrations and Pending Configuration, each with a stated definition. [ai-security.asset-management.onboarding:page-metrics] The Configured Integrations table has Integration Alias, Provider, Accounts, Business Units, Health Status, Orchestrator Config Status, Issues and Actions columns; Health Status examples are Passed, Pending and Needs Attention. [ai-security.asset-management.onboarding:table-columns] After onboarding completes successfully, an integration shows Overview, an accounts-detail tab named by account type (Subscriptions, Projects, Accounts or Environments), Issues, and Roles and Templates tabs; while onboarding is in progress or has hit issues, the issue or paused step can be viewed and onboarding resumed. [ai-security.asset-management.onboarding:integration-detail-tabs] Under "Manage the cloud accounts:" the actions are monitoring and autodetection, business unit mapping, on-demand validation, regions, custom tags, notification emails, orchestrator network and orchestrator change, and delete; under "Manage SaaS Applications:" they are add account/environment, update credentials and delete. The custom orchestrator network applies only if the AI Security Connection Status is failed. [ai-security.asset-management.onboarding:manage-actions]

**Microsoft Copilot Studio.** Onboarding a Microsoft Copilot Studio tenant requires choosing an authentication type, Client Secret (a shared secret from the Azure app registration) or Certificate (a PEM file); the choice determines the credentials needed. [ai-security.asset-management.onboarding:copilot-auth] Copilot Studio onboarding needs these roles: Entra ID Application Developer, Cloud Application Administrator and Power Platform Administrator; Power Platform environment System Administrator and Environment Maker; and a Power Automate license. [ai-security.asset-management.onboarding:copilot-roles] The Copilot Studio app registration needs six Microsoft Graph permissions (Application.Read.All, AuditLog.Read.All, Directory.Read.All, LicenseAssignment.Read.All, User.Read.All, User.Read by default), added under Microsoft Graph > Application Permissions, with admin consent, and a client secret that expires after 180 days by default. [ai-security.asset-management.onboarding:copilot-app-registration] Copilot Studio onboarding uses a Power Automate instant cloud flow triggered by an HTTP request, with the Get Connections as Admin action, which generates a flow URL; the flow must be in the environment being onboarded. The Service Reader security role is assigned under Security Roles. [ai-security.asset-management.onboarding:copilot-flow] With the Certificate authentication type, the downloaded PEM file is uploaded to the app registration and Validate is then clicked in the Download Certificate section of AI Security. [ai-security.asset-management.onboarding:copilot-cert]

**GitHub.** The Zscaler GitHub integration app reads GitHub metadata and repository files for scanning; repository access can be All repositories (current and future, including public) or Only select repositories (also including public). [ai-security.asset-management.onboarding:github-access] AI Security checks onboarded GitHub tenants for new repositories twice daily, at 12:00 AM and 12:00 PM UTC. [ai-security.asset-management.onboarding:github-scan-schedule] The agentic frameworks supported for GitHub onboarding are CrewAI, n8n, OpenAI Agents, Langchain, Pydantic AI, Google ADK, LlamaIndex, DeepAgents, Strands, Microsoft Agent Framework and Haystack. [ai-security.asset-management.onboarding:github-frameworks]

**Azure tenant or management group.** Azure onboarding scopes are Tenant (role assignment at the tenant root management group, discovering every subscription), Management Group (a group and its descendants; recommended when coverage is needed for only part of the tenant) and Subscription. [ai-security.asset-management.onboarding:azure-scopes] Role creation is Automated (Zscaler generates Terraform modules for the custom role and role assignment using the azurerm provider) or Manual (custom role created and assigned using the existing workflow). [ai-security.asset-management.onboarding:azure-role-creation-modes] The Azure tenant or management group onboarding page lists these roles: User Access Administrator at the root tenant management group or target subscription (by onboarding scope), Storage Account Contributor on the storage account for the Terraform state file, and Privileged Role Administrator in Microsoft Entra ID to grant API permissions. [ai-security.asset-management.onboarding:azure-roles] The Azure and Entra tenant pages list different roles [divergence:ai-security.asset-management.onboarding:azure-tenant-roles]. The Azure tenant or management group page lists, for its app registration, Microsoft Graph Application.Read.All (Application) and User.Read (Delegated) as mandatory; the other listed permissions are optional, and entitlements are affected if they are not configured. [ai-security.asset-management.onboarding:azure-graph-permissions] Documented tool versions for running the Azure templates, by Environment (Terraform, Azure CLI): Mac v1.10.3, 2.65.0; Cloud Shell - Bash v1.9.5, 2.65.0; Cloud Shell - PowerShell v1.9.5, 2.65.0; Windows - Command line v1.7.5, 2.67.0; Windows - PowerShell v1.9.8, 2.67.0. [ai-security.asset-management.onboarding:azure-tool-versions] Terraform state files must be stored in a storage container, because they are needed to manage resources created by the AI Security Terraform templates and to upgrade to new templates. [ai-security.asset-management.onboarding:azure-tf-state] Up to 30 notification email addresses can be added during Azure onboarding for configuration or permissions issues, and more can be added after onboarding. [ai-security.asset-management.onboarding:azure-notification-emails] In the flow where Zscaler Hosted deployment mode is chosen, the Reader role is granted to the Zscaler service principal at tenant root scope by a PowerShell one-liner; discovery in the next step fails if that step is not completed. Running it requires the Az PowerShell module and a Connect-AzAccount sign-in as User Access Administrator or Owner on the target scope, and the Zscaler app must have admin consent in Azure AD. [ai-security.asset-management.onboarding:azure-reader-discovery] Autodetection can be enabled on a management group where all current subscriptions are selected, to onboard future subscriptions automatically; custom role definitions are created at the tenant root level and propagate to selected subscriptions. For manual role creation the same page says the custom role is defined at the Management Group or Tenant scope depending on the onboarding scope. [ai-security.asset-management.onboarding:azure-scope-autodetect] Every Azure subscription is assigned to a business unit; if no mapping is specified, the Default option is applied. [ai-security.asset-management.onboarding:azure-bu-default] Each scanning service enabled adds a scoped set of Azure permissions to the Scanning custom role; automated role creation uses an Asset Discovery Role Name and a Scanning Role Name. [ai-security.asset-management.onboarding:azure-services-roles] Evidence Storage is optional: AI Security stores snippets of evidence data from discovered files and tables with sensitive data in a chosen storage account container, configured with an Evidence Role Name, Storage Account Resource ID and Container Name. [ai-security.asset-management.onboarding:azure-evidence-storage]

**Zscaler hosted single Azure subscription.** For a single Azure subscription with manual role creation the custom role definition is at the subscription scope and the role assignment is performed at Subscription scope; the optional evidence role is defined at the storage account subscription scope and assigned at the evidence storage account. [ai-security.asset-management.onboarding:azure-single-sub-scope] On the Zscaler hosted single Azure subscription page, granting the API permissions requires the Privileged Role Administrator role in Microsoft Entra ID. [ai-security.asset-management.onboarding:azure-single-sub-privrole] Single-subscription onboarding takes Subscription ID as a field and Subscription Name as an optional field. [ai-security.asset-management.onboarding:azure-single-sub-fields]

What each optional Graph permission enables is open [gap:ai-security.asset-management.onboarding:optional-graph-permissions]. Whether subscriptions can be added or removed from the Accounts tab without re-onboarding is open [gap:ai-security.asset-management.onboarding:accounts-tab-reonboarding].

What to check:
1. Which Azure onboarding scope is in use (Tenant, Management Group or Subscription) before judging the roles and role-assignment level.
2. Whether the Azure Graph permissions marked Mandatory are configured; entitlements are affected if the optional ones are not.
3. For Copilot Studio, the authentication type chosen, Client Secret or Certificate, since it determines the credentials needed.

Sources disagree (name both sides):
- The Azure tenant or management group onboarding page and the Microsoft Entra tenant or management group page list different roles for onboarding a tenant or management group. [divergence:ai-security.asset-management.onboarding:azure-tenant-roles]
  - zscaler-help: The Azure page lists User Access Administrator, Storage Account Contributor and Privileged Role Administrator.
  - zscaler-help: The Entra page lists Global Administrator at Root and, for a management group, Contributor on the orchestrator subscription.
  Impact: Which roles to verify depends on which onboarding page the tenant followed; neither page says it supersedes the other.

Not known (open gaps):
- What each optional Azure Graph permission enables [gap:ai-security.asset-management.onboarding:optional-graph-permissions]: settled by source-read or support-ticket
- Whether adding or removing subscriptions from the Accounts tab requires re-onboarding [gap:ai-security.asset-management.onboarding:accounts-tab-reonboarding]: settled by lab-test or support-ticket
