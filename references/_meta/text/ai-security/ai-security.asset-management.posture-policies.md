# How AI Posture Policies, threat categories and DLP data classification work in AI Asset Management (ai-security.asset-management.posture-policies)
Also called: ai posture policies; ai security policies; data classification ai security; dlp engines ai security

AI Security scans resources against the policies enabled in AWS accounts, Azure subscriptions and Google Cloud Storage, generates issues, and groups policies by threat category; predefined policies align to benchmarks such as NIST, GDPR and PCI, and custom policies can be created. [ai-security.asset-management.posture-policies:policy-scan-scope] AI Security defines five threat categories: AI Data Exposure, AI Governance, AI Safety, Model Lifecycle Risk and Risky Access. [ai-security.asset-management.posture-policies:threat-categories] AI Governance covers breaches from misconfigurations or vulnerabilities such as disabled encryption, logging or backup; AI Safety covers exposure of unsafe responses to users; Risky Access covers insecure user credentials such as users without MFA. [ai-security.asset-management.posture-policies:threat-category-meanings] [divergence:ai-security.asset-management.posture-policies:threat-category-names]

**Managing policies.** The AI Posture Policies page (Policies & Controls > AI Posture Policies) shows each policy's severity (Critical, High, Medium or Low), source (predefined or custom), status (Enabled or Disabled) and category. [ai-security.asset-management.posture-policies:policy-list-fields] Enable is available only when a policy is disabled and Disable only when it is enabled; Change Severity, Edit and Delete are available only when the policy is disabled, and predefined policies cannot be edited, deleted or have their severity changed. [ai-security.asset-management.posture-policies:action-availability] New issues are not generated for disabled policies, but the status of existing issues remains unchanged. [ai-security.asset-management.posture-policies:disabled-policy-issues] Editing a custom policy's title or remediation procedure shows the new information on the Issues page and dashboard, but editing its query logic closes all existing issues and generates new ones from the updated query. [ai-security.asset-management.posture-policies:edit-custom-policy] Deleting a custom policy closes all issues previously generated by it, and only custom policies can be deleted. [ai-security.asset-management.posture-policies:delete-custom-policy] A predefined or an existing custom policy can be cloned, reusing its query structure, to create a custom policy; policies that are temporarily hidden cannot be cloned or viewed. [ai-security.asset-management.posture-policies:clone-policy] Changing a policy's severity affects the risk level of issues triggered by findings of that policy. [ai-security.asset-management.posture-policies:change-severity] Creating a custom policy needs a cloud provider, primary resource type, a query, and a Markdown remediation procedure; Policy Name and Policy Severity (Critical, High, Medium or Low) are given, while description, category and MITRE ATT&CK technique are optional. [ai-security.asset-management.posture-policies:custom-policy-fields] A policy's page has a Policy Overview tab (rationale, related MITRE techniques, policy ID, category, resource type, compliance frameworks, and the policy query) and a Remediation tab, and policies query data stores in AWS, Azure and GCP. [ai-security.asset-management.posture-policies:policy-details-tabs]

**Data classification.** AI Security data classification uses DLP engines and dictionaries synced from Internet & SaaS (ZIA) plus predefined engines; engines can only be viewed in the AI Security Admin Portal and are added or modified in Internet & SaaS given the necessary permissions, and only engines assigned to the AI Security channel in ZIA are displayed and available. [ai-security.asset-management.posture-policies:dlp-engines-source] The sensitivity setting is enabled by default for all DLP engines on the Data Classification page (Administration > Data Classification), and can be disabled for all engines or for a specific engine. [ai-security.asset-management.posture-policies:sensitivity-default] If the sensitivity setting is disabled for all DLP engines, a new DLP engine added in Internet & SaaS (ZIA) is not automatically synced with AI Security and its sensitivity setting must be enabled manually in the AI Security Admin Portal. [ai-security.asset-management.posture-policies:sensitivity-disable-sync] The Data Classification page lists each DLP engine's name, description, type (Predefined or Custom), last modified time, an Enabled toggle for whether it is active, and the Sensitive setting. [ai-security.asset-management.posture-policies:data-classification-table]
