# The AI Guard guardrail server for the TrueFoundry AI Gateway: its endpoints, how it reports a block, user forwarding, and its posture on AI Guard errors (ai-security.ai-guard.integrations.truefoundry)
Also called: ai guard truefoundry; truefoundry custom guardrail ai guard; /input-scan; /output-scan; ai guard user forwarding

The TrueFoundry integration is a small FastAPI server that TrueFoundry's gateway calls as a custom guardrail. The server exposes `POST /input-scan`, which scans the last user message with direction IN, `POST /output-scan`, which scans the assistant's reply with direction OUT, and `GET /health`. It reads both OpenAI request shapes: Chat Completions (`messages`, text parts; the first choice's message content) and Responses (`input`, `input_text` parts; the `output` item of type message and role assistant, `output_text` parts). Each scan uses the SDK's `LegacyZGuardClientHelper` `resolve_and_execute_policy` with a fresh uuid4 transaction ID and the cloud from `AIGUARD_CLOUD` (default us1). [ai-security.ai-guard.integrations.truefoundry:endpoints] A request with no user message, or a response with no assistant content, is answered with an allow verdict and no scan. [ai-security.ai-guard.integrations.truefoundry:skips]

**Reporting a verdict.** Both scan endpoints answer HTTP 200 with `{"verdict": true}` to allow or `{"verdict": false, ...}` with the block details to deny, blocking on anything but ALLOW or DETECT; the code explains that TrueFoundry treats a non-2xx guardrail response as the guardrail failing, which its Enforce But Ignore On Error and Audit modes would let through. [ai-security.ai-guard.integrations.truefoundry:verdict-body] The README describes a 400 response instead [divergence:ai-security.ai-guard.integrations.truefoundry:block-shape].

**AI Guard errors.** When the SDK reports an error, `_scan` logs it at ERROR and raises a plain Exception; both endpoints call `_scan` without a surrounding try block. [ai-security.ai-guard.integrations.truefoundry:scan-error-raises] An AI Guard error therefore reaches TrueFoundry as a non-2xx guardrail failure, so whether the request is blocked or passed is decided by the TrueFoundry guardrail mode, and under Enforce But Ignore On Error or Audit it passes. [ai-security.ai-guard.integrations.truefoundry:error-posture]

**User attribution.** The server passes an end-user identity as `user` to `resolve_and_execute_policy`, taking the first non-empty of the TrueFoundry context's `user.email`, `metadata.user_email`, `user.subjectSlug`, `user.userName`, `user.metadata.displayName`, `user.subjectDisplayName` and `user.subjectId`, and requires `zscaler-sdk-python>=1.11.0`. [ai-security.ai-guard.integrations.truefoundry:user-forwarding] Each scan also forwards a conversation ID as a request header, `AIGUARD_CONVERSATION_ID_HEADER` (default `X-Conversation-Id`), when the TrueFoundry context carries one: the key named by `AIGUARD_CONVERSATION_ID_METADATA_KEY`, then `conversation_id`, `chat_id` and `session_id`, in request metadata before the user's metadata. The code's comment says AI Guard records it only if the tenant lists that header in `headerNames` and names it in `conversationIdHeaderName`. [ai-security.ai-guard.integrations.truefoundry:conversation-id] At the default INFO level (`AIGUARD_LOG_LEVEL`) the server logs each identity candidate it checks, up to the first non-empty one, with its value, and then the identity it chose; the first candidate is the subject's email, which a human subject carries. [ai-security.ai-guard.integrations.truefoundry:identity-logged] The SDK parameter it relies on is [`resolve_and_execute_policy` accepts an optional `user` since release 1.10.0, recorded on the detection event so the user appears on the dashboard, and optional extra `headers` since release 1.10.1, which are merged into the request and let a caller send the tenant's configured custom request headers, including the one AI Guard reads a conversation ID from to correlate multi-turn interactions.](kb:ai-security.ai-guard.runtime-api:resolve-user-headers).

What to check:
1. Which TrueFoundry guardrail mode the scan endpoints run under; with Enforce But Ignore On Error or Audit, an AI Guard outage lets traffic through.
2. Whether the server's INFO logs, which carry end-user identities such as email addresses, go somewhere that may hold them.
