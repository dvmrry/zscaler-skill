# Red Teaming connection types and the fields each needs (REST API, Proxy SDK, OpenAI REST API, Copilot Studio, Glean, Microsoft Teams, Agentforce, Amazon Bedrock AgentCore and Agents), and the connection test (ai-security.ai-red-teaming.connections)
Also called: red teaming connection; configure your connection; red teaming rest api connection; proxy sdk connection; openai rest api connection; copilot studio red teaming; agentforce red teaming; bedrock agentcore red teaming; bedrock agents red teaming; glean red teaming; teams red teaming

The connection page lists three integration methods: API (REST API, Proxy SDK, OpenAI REST API); Platform, where test runs are executed on chatbots accessible through external platforms and the probe uses the platform's APIs (Copilot Studio, Glean, Microsoft Teams, Slack, WhatsApp, Agentforce, Amazon Bedrock AgentCore, Amazon Bedrock Agents); and LLM, where tests are executed directly on the Large Language Model (Azure OpenAI, Azure ML, Anthropic, Databricks, Hugging Face, OpenAI, OpenAI Assistant, Mistral, Gemini, Bedrock). [ai-security.ai-red-teaming.connections:connection-types] After the Configure your connection page is completed, Continue runs a background connection test between AI Security and the AI app; the page's failure checks are that the app is accessible through the internet and not only on the private intranet, that AI Security's IP address is whitelisted, that the {message} and {session_id} tags are in the POST request payload, that the response path format is correct, and that the authentication information is correct. [ai-security.ai-red-teaming.connections:connection-test] Which of them a private app can use is in [Connecting an AI app for red teaming: network type, private access, and the application profile that shapes tests](kb:ai-security.ai-red-teaming.assets). The AI Guard integration for AgentCore, [The AI Guard guard for Amazon Bedrock AgentCore agents: the four legs you call, the tool wrapper, and what each leg sends](kb:ai-security.ai-guard.integrations.aws-bedrock-agentcore), is a guard example, not one of these test targets.

**API connections.** A REST API connection sends the attack message to the asset's URL; its request payload carries the {message} placeholder (where the probe inserts attack messages) and the {session_id} placeholder (a unique string identifying the conversation session, for multi-step testing), can contain additional fixed arguments, and Response Path is the JSON path to the message in the chatbot's API response. [ai-security.ai-red-teaming.connections:rest-api] For a REST API app that works with separate session requests, Open Session and Close Session options are enabled and configured in the integration settings; authentication takes key-value pairs where authorization headers must be included for non-public APIs (alternatively, OAuth can also be used), and OAuth takes a token endpoint URL, Client ID, Client Secret and a space-separated Scope. [ai-security.ai-red-teaming.connections:rest-api-sessions-auth] A Proxy SDK connection takes the target URL, the application's API Key for authentication with the Proxy SDK, an Additional Parameters Payload (a JSON object of custom payload data for POST requests the Proxy SDK sends to the AI app), and custom HTTP headers, which are optional. [ai-security.ai-red-teaming.connections:proxy-sdk] An OpenAI REST API connection chooses the Chat Completions API, which the page calls the traditional industry-standard protocol and a legacy path that may not receive the latest agentic features or reasoning optimizations, or the Responses API, the modern protocol designed to supersede it; it takes the URL, an API Key if applicable, the app's System Prompt, the exact Model name (the connector is not tied to a single model provider), optional custom headers, and Extra LLM Config for request-body parameters such as temperature, top_p or max_tokens, where blank accepts provider defaults. [ai-security.ai-red-teaming.connections:openai-rest-api] A proxy for a non-standard app is generated by [The AI Red Teaming Onboarding Agent: generating a Proxy SDK proxy for a non-standard app, its spec gate, versions and local skill](kb:ai-security.ai-red-teaming.onboarding-agent).

**Platform connections.** A Glean connection is of the Chat type, the default chat type that connects users to the organization-wide Glean assistant, where only the API Token (a client API token with chat scope) and Instance Slug are necessary and Application ID is optional, or of the Agent type, which enables communication with a specific Glean Agent and takes an Agent ID. [ai-security.ai-red-teaming.connections:glean] Microsoft Teams chatbots are Azure bots connected to Microsoft Teams, and testing is performed directly on the Azure bot using the Direct Line API; the Bot ID field takes the Bot handle value and the Bot Secret field takes the Secret key. [ai-security.ai-red-teaming.connections:microsoft-teams] Copilot Studio connects in Non-Auth Mode, a lightweight option that doesn't use tokens, suited to agents that only need public information and resources and that can't enable user-specific features, taking an Agent Secret and a Direct Line Region; or in Auth Mode, for secure user sign-in via OAuth or SSO with access and refresh tokens managed automatically, taking a Client ID, Tenant ID, Environment ID and Schema Name. [ai-security.ai-red-teaming.connections:copilot-studio-modes] For Non-Auth Mode the agent's Web channel security has Require secured access set to On and Authentication set to No authentication; one of the two Direct Line Secrets is the value entered, and Direct Line Region is set to Europe or India when the environment's Region column says so, and otherwise to Global. [ai-security.ai-red-teaming.connections:copilot-studio-non-auth] For Auth Mode the Entra app registration takes Accounts in this organization directory only and a Single-page application (SPA) redirect URL of https://copilot-studio-auth.splx.ai/integrations/copilot-studio-redirect, gets the delegated CopilotStudio.Copilots.Invoke permission from the Power Platform API with admin consent granted, and the agent's Authentication is set to Authenticate with Microsoft; if the Power Platform API is not seen it must first be enabled in the organization, with az ad sp create --id 8578e004-a5c6-46e7-913e-12f58912df43. [ai-security.ai-red-teaming.connections:copilot-studio-auth] An Agentforce connection takes the Organization Domain of the Salesforce org instance, an OAuth Client ID and Client Secret, the Agent ID of the specific Agentforce agent to call, and optional Variables, a JSON object of context and custom variables passed to the agent when starting a session. [ai-security.ai-red-teaming.connections:agentforce]

**Amazon Bedrock.** An Amazon Bedrock AgentCore connection takes the Agent Runtime ARN, the AWS Region where the runtime is deployed, an AWS Access Key Id for an IAM principal that has permission to invoke the runtime, an AWS Secret Access Key (the IAM secret access key paired with the Access Key Id), an optional Qualifier (for example a version or alias; empty uses the runtime's default), a Payload Template sent on each invocation, a Response Path to the text response, and Image, Audios and Documents Response Paths to be left empty when the runtime returns none. [ai-security.ai-red-teaming.connections:bedrock-agentcore] The AgentCore payload template placeholders are {message} (main text message), {session_id} (runtime session ID), {image_url}, {image_base64} (image as base64 data URL), {audio_url}, {audio_base64} (audio as base64 data URL), {document_url} and {document_base64} (document as base64 data URL). [ai-security.ai-red-teaming.connections:agentcore-placeholders] An Amazon Bedrock Agents connection takes the Agent Id, an AWS Access Key Id, an AWS Secret Access Key (the IAM secret access key paired with the Access Key Id), the Agent Alias Id (aliases route traffic to a specific agent version) and the AWS Region where the agent is created; if the agent has Code Interpreter enabled, AWS enforces a limit on concurrent active sessions per account/region (minimum 25), which high-concurrency scans can reach quickly so that requests fail, and the page advises a Rate Limit of 20 or lower and disabling Parallel Requests or keeping concurrency low. [ai-security.ai-red-teaming.connections:bedrock-agents]

**Not documented.** Slack and WhatsApp are listed as platforms but their connection pages are not captured [gap:ai-security.ai-red-teaming.connections:slack-whatsapp].

What to check:
1. When a connection fails its background test, that the app is reachable from the internet, AI Security's IP address is whitelisted, the {message} and {session_id} tags are in the POST payload, the response path is right and the authentication details are right.
2. For an Amazon Bedrock Agent with Code Interpreter enabled, that internal server errors may come from reaching AWS's concurrent active session limit; the page advises a lower Rate Limit (20 or lower) and Parallel Requests disabled or concurrency kept low.
