# How AI Asset Management scan rules, scan scopes, scan types and schedules work, and which systems support vulnerability scanning (ai-security.asset-management.scan-rules)
Also called: ai security scan rule; ai security scan settings; ai asset management scan scope; ai security on-demand scan; ai security delta scan; ai security vulnerability scanning supported systems

AI Security scans cloud data stores through the local scan orchestrator that is deployed in the customer account during onboarding; in a scan rule you choose the resources, the scan type and the scan frequency. [ai-security.asset-management.scan-rules:orchestrator] The hub is [AI Asset Management in the AI Security Admin Portal: what it inventories, signing in, first-time configuration order, table behavior](kb:ai-security.asset-management) and the accounts a rule scans are in [How are onboarded AWS, Azure and GCP accounts managed in AI Security: the Cloud Accounts page, validation, status, issues, deletion, orchestrator changes and the orchestrator itself?](kb:ai-security.asset-management.cloud-accounts).

**Scan rules.** A scan rule can define custom scan types and schedules for individual data stores based on account, region, tags or specific resources. [ai-security.asset-management.scan-rules:rule-granularity] Cloud accounts must be onboarded before a scan rule is configured; overlapping scan rules are allowed but can cause duplicate scans and higher compute costs, and AI Security warns about them during rule creation. A resource deleted from the account after the schedule is set is ignored during the scan. [ai-security.asset-management.scan-rules:rule-prerequisites-overlap] The scan rule description is optional and limited to 500 characters (AWS cloud storage rule page). [ai-security.asset-management.scan-rules:rule-description-limit] Clicking a scan rule name on the Scan Rule tab opens the Scan Rule Details view, which shows Name, Status and Resources Scanned (the number of resources discovered and scanned by the rule); the tab's own rule columns include Scan Status (the state of the scanning process) and Scan Enable/Disable. [ai-security.asset-management.scan-rules:rule-list-fields] By default a scan setting is disabled; after configuring it you must enable it to start the scan, and an enabled rule runs as scheduled. [ai-security.asset-management.scan-rules:rule-default-disabled]

**Scan types.** The About Scan Settings page says that when scanning relational databases such as PostgreSQL, Oracle, SQL Server and MySQL, AI Security uses data sampling to scan a subset of the data instead of the whole database, so database operations are not impacted; the same page's Scan Types table also lists Full Scan for Managed Database. [ai-security.asset-management.scan-rules:database-sampling] In the About Scan Settings Scan Types table, Compute supports the On-Demand Scan, and Storage supports Full Scan, Scan Only New or Modified Files, and Historical Scan over a lookback of up to 365 days. [ai-security.asset-management.scan-rules:scan-types-storage-compute] In the About Scan Settings Scan Types table, Managed Database supports Full Scan and Data Sampling Scan; NoSQL Datastore supports Full Scan and Scan Only Recent Data (also applicable to unmanaged databases); Unmanaged Database supports Data Sampling Scan. [ai-security.asset-management.scan-rules:scan-types-databases] A Full Scan covers both historic and newer data, and the newer data scan is prioritized over the historic data scan. [ai-security.asset-management.scan-rules:full-scan-priority] On the AWS cloud storage rule page the Scan Type page offers Full, Full + Incremental, Incremental, Historical and Historical + Incremental scans; a scan duration (1 Day, 1 Week, 1 Month, Continuous or Custom Duration, the last given in days) is selected for Full + Incremental and Incremental scans, and a lookback period of 1 to 365 days is entered for Historical and Historical + Incremental scans. [ai-security.asset-management.scan-rules:file-scan-types-aws-storage] The Azure Blob Storage and Azure file shares rule pages list Historical + Incremental scans with a lookback period of 1 to 365 days, and scan durations of 1 Day, 1 Week, 1 Month, Continuous or Custom Duration. [ai-security.asset-management.scan-rules:file-scan-types-azure] For Azure NFS file shares AI Security does not support incremental scans (Incremental, Full + Incremental, Historical + Incremental); the page says to run periodic historical scans or schedule frequent full scans instead. The Azure file shares rule scans over SMB and NFS. [ai-security.asset-management.scan-rules:azure-nfs-no-incremental] On the AWS-managed database, AWS NoSQL data store and Azure-managed database rule pages, the Scan Type page offers a Data Sampling Scan (a sample of recent data in the database) or a Full Scan. [ai-security.asset-management.scan-rules:managed-db-scan-types] [gap:ai-security.asset-management.scan-rules:nosql-scan-types]

**Schedules.** On the scan schedule step of the AWS ECR, AWS virtual machine, AWS-managed database, AWS NoSQL, Azure virtual machine, Azure managed database and Azure ACR rule pages, the frequencies are On Demand (Default), Daily, Weekly (day chosen from a drop-down) and Monthly. [ai-security.asset-management.scan-rules:schedule-default-on-demand] On the Microsoft Foundry and Azure OpenAI rule pages the schedule is On-Demand (Default), Daily, Weekly or Monthly, with a specified time for the recurring options (examples Tuesday at 11:59 PM, the 24th at 11:59 PM). [ai-security.asset-management.scan-rules:schedule-ai-services-time] The GitHub rule schedule options are Daily, Weekly, Monthly or On Demand, and the rule must be enabled on the Overview page to initiate the scan. [ai-security.asset-management.scan-rules:github-schedule-enable] On the Azure Blob Storage, Azure file shares, Microsoft Foundry and Azure OpenAI rule pages, the rule is enabled on the Scan Settings page to initiate scheduled or on-demand scans. [ai-security.asset-management.scan-rules:rule-enable-azure-pages]

**Starting, stopping and enabling.** The About Scan Settings page says an on-demand scan can be performed only on databases and virtual machines, and the Running an On-Demand Scan page says it runs instantly on the database or virtual machine and overrides the scheduled scan. [ai-security.asset-management.scan-rules:on-demand-databases-vms] The Starting a Scan page starts a scan on a resource through the On-Demand Scan option on the Actions icon, after which the storage account is queued for scanning. [ai-security.asset-management.scan-rules:start-scan-storage] [divergence:ai-security.asset-management.scan-rules:on-demand-scope] The Stop Scan option is visible only while a scan is In-Progress, and stopping only stops the scan currently in progress; upcoming scans continue as scheduled. [ai-security.asset-management.scan-rules:stop-scan] A Delta scan (Only New Files scan: only new and modified files on the selected cloud storage resource) cannot be stopped; to stop it entirely the scan rule must be disabled. [ai-security.asset-management.scan-rules:delta-scan] New S3 buckets added to a scan rule are included in the Delta scan automatically; the Delta scan starts for them from that point forward and they are scanned with the latest DLP engine configuration; removing an S3 bucket from the rule stops the scan for that bucket. [ai-security.asset-management.scan-rules:delta-s3-membership] Disabling a scan rule lets full scans already in progress complete but disables subsequent incremental scans; to stop a full scan immediately, first stop it from the Actions menu on the Scan Settings page. [ai-security.asset-management.scan-rules:disable-effect]

**Scan scopes.** A scan scope selects the DLP engines used to detect and classify sensitive data in specific file types, and AI Security uses only the specified DLP engines to scan the resources. [ai-security.asset-management.scan-rules:scope-purpose] A scan scope shows scope criteria of DLP Engines, File Type and ML Categories (enabled or disabled), plus the scan rules associated with it. [ai-security.asset-management.scan-rules:scope-detail-fields] The scan scope Select Criteria page offers the DLP Engine choice (all, or specific DLP engines), File Type, and a Machine Learning Document Scan option; file type filters and machine learning document scans are optimized for cloud storage and VM resources. [ai-security.asset-management.scan-rules:scope-criteria] AI Security uses OCR to find sensitive data in image files (examples .png, .jpeg, .tiff, .bmp, .gif) and in images embedded in documents (examples .pdf, .docx, .pptx). [ai-security.asset-management.scan-rules:scope-ocr] A DLP engine must be enabled to be selected in a scan scope; a disabled engine that is selected shows grayed out with a partial selection indicator and is not evaluated by the scanner; a deleted engine is removed from all scan scopes. [ai-security.asset-management.scan-rules:scope-engine-states] A scan scope's General Information holds an Engine Scope Name (described as a concise and descriptive name for the scope) and an Engine Scope Description explaining what the scope covers. [ai-security.asset-management.scan-rules:scope-general-fields] On a scan scope's Select Criteria page, the Specific DLP Engines option is enabled only if specific DLP engines are chosen for the scan. [ai-security.asset-management.scan-rules:scope-specific-engines-enabled] A scan scope can be applied while configuring the scan settings; on the AWS cloud storage rule page it is chosen from a drop-down on the Scan Scope page. [ai-security.asset-management.scan-rules:scope-applied-in-rule] Whether editing or deleting a scope affects rules already using it is open [gap:ai-security.asset-management.scan-rules:scope-edit-delete-effect].

**AWS rules.** On the AWS cloud storage rule page, AI Security automatically excludes active CloudTrail and VPC flow log buckets from sensitive data scans even if they match the scan criteria, and also excludes AWS workloads created using the AWS Marketplace. [ai-security.asset-management.scan-rules:aws-storage-auto-exclusions] On the AWS cloud storage rule page, when several key-value pairs are entered to include buckets, AI Security scans every bucket matching at least one pair (OR logic); the exclude-by-tags option works the same way. [ai-security.asset-management.scan-rules:tag-or-logic] On the AWS cloud storage rule page a folder is excluded by entering the bucket name followed by the folder and a forward slash (example my-bucket/reports/), and wildcards on bucket names (example *logs*, any bucket name containing logs) are supported, and this applies to existing and future S3 buckets. [ai-security.asset-management.scan-rules:s3-exclusion-formats] On the exclusion step of the AWS cloud storage and AWS-managed databases rule pages, if a full scan is already initiated or completed, the excluded bucket, folder or database is excluded in the next incremental scan. [ai-security.asset-management.scan-rules:exclusion-next-incremental] The AWS cloud storage rule page says AI Security cannot detect files that are deleted in the AWS console; the Azure Blob Storage page says the same for Azure, and the AWS NoSQL page for the resource. [ai-security.asset-management.scan-rules:deleted-files-not-detected] Enable Malware Scanning is an option on the AWS cloud storage, AWS virtual machine, Azure Blob Storage, Azure file shares and Azure virtual machine rule pages, and it is disabled by default. [ai-security.asset-management.scan-rules:malware-opt-in] The AWS-managed database rule covers databases such as MySQL, Aurora MySQL and Aurora PostgreSQL, and the AWS NoSQL rule covers NoSQL data stores and DynamoDB (tables chosen manually are entered by name, and excluded tables are entered as ARNs). [ai-security.asset-management.scan-rules:aws-managed-db-nosql-types] The AWS ECR rule needs AWS onboarding templates updated with the IAM permissions for ECR scanning, and its Scan by Last Pulled option scans only images pulled within the chosen timeframe. [ai-security.asset-management.scan-rules:ecr-prerequisites-pulled]

**Azure and GitHub rules.** The Microsoft Foundry and Azure OpenAI rules use Cloud Type Azure with Resource Category AI & Machine Learning; Scan All Resources covers all the subscriptions and their associated Foundry projects or OpenAI services. [ai-security.asset-management.scan-rules:ai-services-category] Azure-managed database rules require the Azure SQL database to have an RBAC policy for the Key Vault; AI Security does not support scanning Azure SQL databases encrypted with a Customer-Managed Key (CMK) without the RBAC policy. The rule covers Azure SQL databases and Azure-managed PostgreSQL Flexible servers. [ai-security.asset-management.scan-rules:azure-sql-cmk-rbac] After completing an Azure-managed database scan, AI Security deletes the restored servers, databases and File System (FS) Analyzer to reduce cost for customers. [ai-security.asset-management.scan-rules:azure-db-restore-cleanup] The Azure ACR rule needs the Azure Container Registry service enabled in the product's Manage Services settings and the latest Azure onboarding templates executed for the ACR IAM permissions; it detects vulnerabilities, AI models, AI packages and MCP servers. [ai-security.asset-management.scan-rules:acr-prerequisites] Scanning a private ACR from a scanner instance requires a bidirectional VNet peering between the scanner VNet and the ACR's VNet, and a Private DNS Zone VNet link from the scanner VNet; if the ACR has IP network rules, the scanner's outbound IPs must be whitelisted. [ai-security.asset-management.scan-rules:acr-private-network] On the Azure ACR rule page repositories are entered by name or in regex format (examples dev* or prod*), and ACR repositories can be selected by image tags with OR logic across key-value pairs. [ai-security.asset-management.scan-rules:acr-repo-patterns] The GitHub rule uses Cloud Type SaaS and Service Type GitHub after the GitHub repositories are onboarded; path exclusions are set per repository as a path or glob pattern with a Regex toggle for advanced matching, Scheduled Full Scan runs a complete scan of all files across every selected repository on a recurring schedule, and without it recurring scans are not scheduled. [ai-security.asset-management.scan-rules:github-rule]

**Virtual machine rules.** On the AWS virtual machine and Azure virtual machine rule pages, Exclude Operating System Directories Files from Scanning is enabled by default (disable it to scan OS directories); the excluded directories include Linux /usr/local/, /var/log/, Windows C:\Windows\ and the package path /opt/elasticbeanstalk/. [ai-security.asset-management.scan-rules:vm-os-directory-exclusion] The Azure virtual machine rule page lists systems excluded from scanning: VMs encrypted using ADE, Windows 10 or 11 desktop VMs, Windows Server 2012 VMs, Azure VMs created using unmanaged disks (.vhd from storage account), and storage accounts with public network access disabled. [ai-security.asset-management.scan-rules:azure-vm-excluded-systems]

**Vulnerability scanning.** AI Security can scan AWS or Azure virtual machines for vulnerabilities such as unencrypted data, publicly exposed instances and unauthorized access to sensitive data, on the operating systems, file systems and programming language libraries it supports. [ai-security.asset-management.scan-rules:vuln-scope] Under the x86 Architecture heading, vulnerability scanning supports among others Oracle Linux 7.0, 7.7, 7.9, 8.3, 8.4, 8.5, 8.6, 8.7, 8.8, 9.0, 9.1, 9.2, Photon 3.0 and 4.0, and Windows Server 2016, 2019 and 2022. [ai-security.asset-management.scan-rules:vuln-os-x86] Under the ARM Architecture heading, vulnerability scanning supports among others Photon 4.0 and 5.0, and SUSE Linux Enterprise Server 15 SP3, 15 SP4 and 15 SP5. [ai-security.asset-management.scan-rules:vuln-os-arm] Vulnerability scanning is supported on file systems including EXT (ext2, ext3, ext4), and not on OS-level encrypted root disks or volumes such as Bitlocker, crypto LUKS or DM crypt. [ai-security.asset-management.scan-rules:vuln-file-systems] Vulnerability scanning of programming language libraries covers Java (jar, war, pom.xml), Go (gobinary, *.sum), Python (Pipfile.lock, poetry.lock, *.egg-info/PKG-INFO, *.dist-info/METADATA), .NET (packages.lock.json), Ruby (Gemfile.lock), Node.js (package-lock.json, yarn.lock), PHP (composer.lock) and Rust (Cargo.lock). [ai-security.asset-management.scan-rules:vuln-libraries] AWS vulnerability scanning is supported for both AWS-managed and customer-managed encryption, but supporting AWS-managed encryption requires at least one customer-managed key in the region. [ai-security.asset-management.scan-rules:vuln-aws-encryption] AWS vulnerability scanning supports a listed set of regions, including us-east-1, af-south-1, ap-southeast-3, eu-central-2, me-central-1 and sa-east-1. [ai-security.asset-management.scan-rules:vuln-aws-regions] Azure vulnerability scanning supports workloads created from images in Azure Compute Gallery and Azure Marketplace, and does not support workloads created from unmanaged OS disks (.vhd). [ai-security.asset-management.scan-rules:vuln-azure-workloads] Azure vulnerability scanning supports a listed set of regions, including Qatar Central, South Africa North, Brazil South, UAE North and West US 3. [ai-security.asset-management.scan-rules:vuln-azure-regions] [gap:ai-security.asset-management.scan-rules:vuln-region-lists-partial]

What to check:
1. Whether the scan rule is enabled: a scan setting is disabled by default and must be enabled to initiate the scan.
2. Whether a running scan can be stopped: Stop Scan is visible only while a scan is In-Progress, and a Delta scan cannot be stopped, only the scan rule disabled.
3. Which resources an on-demand scan runs on: the About Scan Settings page says only databases and virtual machines, while the Starting a Scan page queues a storage account.

Sources disagree (name both sides):
- Which resources an on-demand scan can be run on: the About Scan Settings page says only databases and virtual machines, while the Starting a Scan page runs the On-Demand Scan option on a resource and queues a storage account. [divergence:ai-security.asset-management.scan-rules:on-demand-scope]
  - zscaler-help: An on-demand scan can be performed only on databases and virtual machines.
  - zscaler-help: The Starting a Scan steps select the On-Demand Scan option for the resource to scan, after which the storage account is queued for scanning.
  Impact: Whether a storage resource can be scanned on demand is not settled by the AI Security pages; the same About Scan Settings Scan Types table also lists On-Demand Scan under Compute.
