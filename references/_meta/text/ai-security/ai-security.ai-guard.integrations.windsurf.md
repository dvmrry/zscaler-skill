# Windsurf Cascade hooks for AI Guard (Zscaler example): pre-hooks that block, post-hooks that only audit, and the missing-key allow (ai-security.ai-guard.integrations.windsurf)
Also called: windsurf aiguard hooks; cascade hooks aiguard; pre_user_prompt; pre_run_command; pre_mcp_tool_use; post_cascade_response

Zscaler's Windsurf example is a set of Cascade hook scripts that call AI Guard's detection API through the Python SDK.

**What is hooked.** The example registers five Cascade hooks: `pre_user_prompt`, `pre_run_command` and `pre_mcp_tool_use` scan with direction `IN` and can block with exit 2; `post_mcp_tool_use` and `post_cascade_response` scan with `OUT` for audit only; `show_output` is on for `pre_mcp_tool_use` and both post hooks. [ai-security.ai-guard.integrations.windsurf:hooks] The README says Windsurf post-hooks cannot block or redact content and that `show_output` only displays stdout to the user without changing Cascade's context. [ai-security.ai-guard.integrations.windsurf:post-cannot-block]

**Where Windsurf finds them.** The README says Windsurf loads workspace hooks only from `.windsurf/hooks.json` in the folder opened, and that opening the repository root uses a root-level `.windsurf/hooks.json` included in the repository. [ai-security.ai-guard.integrations.windsurf:workspace-hooks-file] At the pin the repository has no root-level `.windsurf/hooks.json`, so opening the repository root in Windsurf runs none of these hooks; only opening the `Windsurf/` folder does. [ai-security.ai-guard.integrations.windsurf:root-hooks-missing]

**Which call it makes.** `aiguard_utils.py` loads `.env` from the repository root and then `Windsurf/.env` with python-dotenv without overriding the environment, reads `AIGUARD_CLOUD` (blank or unset means `us1`) and `AIGUARD_TIMEOUT` (default 30), calls `execute_policy` when `AIGUARD_POLICY_ID` parses as an integer and `resolve_and_execute_policy` otherwise, and logs to `.windsurf/hooks/aiguard.log`. [ai-security.ai-guard.integrations.windsurf:config] The Windsurf client config still passes `auto_retry_on_rate_limit` and `max_rate_limit_retries`, which the 0.2.0 changelog says were removed from client configs because `LegacyAIGuardClient` discards them. [ai-security.ai-guard.integrations.windsurf:rate-limit-keys] The endpoints are in [Calling AI Guard at runtime: the proxy endpoint, the DAS detection API, its host, direction and policy ID, and throttling in the Python SDK](kb:ai-security.ai-guard.runtime-api).

**Verdicts and failures.** In the three pre-hooks a missing `AIGUARD_API_KEY` allows without scanning; a scan error (including a response without an action), an action other than `ALLOW`, `BLOCK` or `DETECT`, or `BLOCK` exits 2 with the reason on stderr; `ALLOW` and `DETECT` exit 0. [ai-security.ai-guard.integrations.windsurf:pre-handling] `post_mcp_tool_use` scans server, tool, arguments and result in one text (arguments and result each truncated to 20000 characters) and `post_cascade_response` scans the response text truncated the same way; both skip short content and a missing key, exit 0 on scan errors, and on `BLOCK` print an alert saying the content would be blocked. [ai-security.ai-guard.integrations.windsurf:post-handling]

**What content is scanned.** `pre_user_prompt` scans the prompt truncated to 20000 characters, `pre_run_command` scans the whole command line, and `pre_mcp_tool_use` scans one argument: `query`, `search_query` or `q` when the MCP tool's name contains `search`, `url` or `uri` when it names a fetch, else the first of `query`, `prompt`, `message` and `content`, else the text `Accessing resource:` with a path-like argument, else the arguments JSON. [ai-security.ai-guard.integrations.windsurf:pre-content] The same single-argument choice is described for Cline in [An MCP call that carries any of the named arguments is scanned on that one argument (or only on a path label); its other arguments reach the MCP server unscanned.](kb:ai-security.ai-guard.integrations.cline:mcp-partial-scan). The comparison with other hosts is in [Zscaler's AI Guard integration examples (zguard-ai-integrations): the catalog, the promised fail-closed posture against what each example does, and where each intercepts](kb:ai-security.ai-guard.integrations).

What to check:
1. That Windsurf was opened on the folder whose .windsurf/hooks.json points at these scripts; the repository root has none.
2. That AIGUARD_API_KEY is set: without it every Windsurf hook allows unscanned.
3. Treat MCP results and Cascade replies as audited, not enforced: the post-hooks only alert.
