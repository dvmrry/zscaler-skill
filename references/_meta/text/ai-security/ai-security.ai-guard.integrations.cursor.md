# Cursor hooks for AI Guard (Zscaler example): hooks, failClosed, directions, and per-hook verdict and failure handling (ai-security.ai-guard.integrations.cursor)
Also called: cursor aiguard hooks; beforeSubmitPrompt; beforeMCPExecution; afterAgentResponse; updated_mcp_tool_output; failClosed

Zscaler's Cursor example runs Python hook scripts that send prompts, MCP tool input, tool output and the agent's reply to AI Guard's detection API through the Python SDK.

**What is hooked, and when.** The example wires four Cursor hooks: `beforeSubmitPrompt` runs `pre_submit_prompt.py` (direction `IN`), `beforeMCPExecution` runs `pre_mcp_execution.py` (`IN`), `postToolUse` runs `scan_response.py` (also `IN`), and `afterAgentResponse` runs `agent_response_scan.py` (`OUT`), each with a hook timeout of 5000. [ai-security.ai-guard.integrations.cursor:hooks] The Cursor README says `afterAgentResponse` fires on the complete response after streaming ends and cannot intercept mid-stream, and that `postToolUse` skips Cursor's built-in tools so only MCP tool and Shell command output is scanned. [ai-security.ai-guard.integrations.cursor:readme-timing] Whether a blocked reply is hidden is open [gap:ai-security.ai-guard.integrations.cursor:after-response-block].

**The fail-closed setting.** The shipped `Cursor/.cursor/hooks.json` sets `failClosed` false on all four hooks, while `hooks.json.example` sets it true. [ai-security.ai-guard.integrations.cursor:shipped-failclosed-false] The README says `failClosed` true covers a hook process that crashes or exceeds Cursor's own timeout, and that left at false a hook that dies silently allows the action it was meant to scan. [ai-security.ai-guard.integrations.cursor:failclosed-meaning] The README installs the false copy [divergence:ai-security.ai-guard.integrations.cursor:failclosed-setting].

**Which call it makes.** `aiguard_utils.py` loads `.env` from the workspace root and then `Cursor/.env` with python-dotenv, never overriding the process environment, and reads `AIGUARD_API_KEY`, `AIGUARD_CLOUD` (default `us1`) and `AIGUARD_TIMEOUT` (default 3 seconds); it logs to `Cursor/hooks/aiguard.log`. [ai-security.ai-guard.integrations.cursor:config] When `AIGUARD_POLICY_ID` parses as an integer the hooks call `execute_policy` with it; otherwise, including for a value `int()` rejects, they call `resolve_and_execute_policy`. [ai-security.ai-guard.integrations.cursor:policy-id] The endpoints are in [Calling AI Guard at runtime: the proxy endpoint, the DAS detection API, its host, direction and policy ID, and throttling in the Python SDK](kb:ai-security.ai-guard.runtime-api).

**Verdicts and failures, hook by hook.** `scan_content` returns an `error` (with no verdict) for a missing key, an SDK error, a response without an action, or an exception, and its docstring says callers must treat that as a block. [ai-security.ai-guard.integrations.cursor:scan-errors] `pre_submit_prompt.py` scans the first 20000 characters of the prompt; a `BLOCK` prints `continue` false with a user message and exits 2, and a missing key, a scan error or any action other than `ALLOW`, `BLOCK` or `DETECT` also returns `continue` false; `ALLOW` and `DETECT` continue. [ai-security.ai-guard.integrations.cursor:prompt-hook] `pre_mcp_execution.py` scans the whole tool input as compact JSON; a `BLOCK` returns `permission` deny with user and agent messages and exits 2, and a missing key or scan error also denies, but an action other than `ALLOW`, `BLOCK` or `DETECT` is logged as blocking while the hook prints `permission` allow. [ai-security.ai-guard.integrations.cursor:mcp-hook] That tool input reaches AI Guard untruncated, unlike the prompt, tool-output and reply hooks, which cut at 20000 characters. [ai-security.ai-guard.integrations.cursor:mcp-untruncated] `scan_response.py` skips the built-in tools Grep, Read, Write, Delete, Task, Glob, Edit and NotebookEdit, skips empty output, skips the scan for output whose `len()` exceeds `MAX_TOOL_OUTPUT_BYTES` (51200), printing `{}`, and skips the scan with a warning when no API key is set; otherwise it scans the first 20000 characters and, on `BLOCK`, a scan error or an unrecognised action, replaces the output with a notice in `updated_mcp_tool_output`. [ai-security.ai-guard.integrations.cursor:post-tool-hook] Tool output over 51200 characters, and all tool output when the key is missing, reaches the agent unscanned, contrary to the README's fail-closed description; a large MCP result is the case an injection payload can use. [ai-security.ai-guard.integrations.cursor:post-tool-gaps] `agent_response_scan.py` scans the first 20000 characters of the reply with direction `OUT`; on `BLOCK` it writes the reason to stderr and exits 2, but a missing key, a scan error or an unrecognised action exits 0 after logging. [ai-security.ai-guard.integrations.cursor:agent-response-hook] The README describes all hooks as fail-closed [divergence:ai-security.ai-guard.integrations.cursor:readme-fail-posture]. Whether Shell output is replaced at all is open [gap:ai-security.ai-guard.integrations.cursor:shell-output-replacement].

**Across hosts.** The comparison with the other examples is in [Zscaler's AI Guard integration examples (zguard-ai-integrations): the catalog, the promised fail-closed posture against what each example does, and where each intercepts](kb:ai-security.ai-guard.integrations).

What to check:
1. That the installed .cursor/hooks.json sets failClosed true; the shipped copy the README installs says false.
2. That AIGUARD_API_KEY reaches the hooks: without it postToolUse and afterAgentResponse pass everything unscanned while the prompt and MCP hooks block.
3. Whether large MCP results matter for the threat model: output over 51200 characters is never scanned.

  Impact: Following the README installs hooks that, by the README's own account, allow the action when the hook crashes or times out.
- Whether every Cursor hook fails closed. [divergence:ai-security.ai-guard.integrations.cursor:readme-fail-posture]
  - zguard-integrations: The README says the hooks fail closed on a timeout, a network error or a verdict-less response.
  - zguard-integrations: afterAgentResponse exits 0 on a scan error, and postToolUse skips the scan when no key is set.
  Impact: The response-side hooks let content through when AI Guard cannot be reached or is not configured.
