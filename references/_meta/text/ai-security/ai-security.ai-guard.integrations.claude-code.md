# Claude Code hooks for AI Guard (Zscaler example): events hooked, directions, verdict and failure handling, and what content is scanned (ai-security.ai-guard.integrations.claude-code)
Also called: claude code aiguard hooks; scan_user_input.py; scan_mcp_request.py; scan_response.py; scan_url.py; scan_file_read.py; claude-code-aiguard

Zscaler's Claude Code example registers Python command hooks that send prompts, file reads, web-tool inputs, MCP calls and tool results to AI Guard's detection API through the Python SDK. This page covers the hooks in Anthropic/claude-code-aiguard; the on-demand skill is [Claude Code skill for AI Guard (Zscaler example): on-demand scans with scan.py, directions, exit codes and failure handling](kb:ai-security.ai-guard.integrations.claude-code-skill).

**What is hooked.** The example's shipped `settings.json` registers `scan_user_input.py` on `UserPromptSubmit`; on `PreToolUse` it runs `scan_file_read.py` for the `Read` tool, `scan_url.py` for `WebFetch|WebSearch|web_search` and `scan_mcp_request.py` for MCP tools (`mcp__.*`); on `PostToolUse` it runs `scan_response.py` for the web tools and for MCP tools. [ai-security.ai-guard.integrations.claude-code:registered-hooks] With the shipped settings, Claude Code's other tools (Bash, Write and Edit among them) are not scanned before or after they run, and the assistant's own replies are never scanned: only prompts, file reads, web tools and MCP tools reach AI Guard. [ai-security.ai-guard.integrations.claude-code:unscanned-tools] Whether the README agrees is a divergence [divergence:ai-security.ai-guard.integrations.claude-code:file-read-registration].

**When each hook runs.** HOOKS_EXPLAINED.md says `UserPromptSubmit` fires before Claude sees the user's message, `PreToolUse` before any tool execution, and `PostToolUse` after the tool's execution completes. [ai-security.ai-guard.integrations.claude-code:event-timing] A block from `scan_response.py` comes after the web fetch or MCP call has already run: it can withhold the result but cannot undo the call's side effects. [ai-security.ai-guard.integrations.claude-code:post-tool-after-effects]

**Which call it makes.** Prompts, MCP tool input and sensitive file contents are scanned with direction `IN`; the web-tool input (its `url`, `query`, `search_term`, `uri` or `href` field, scanned before the web tool runs) and tool responses are scanned with direction `OUT`. [ai-security.ai-guard.integrations.claude-code:directions] HOOKS_EXPLAINED.md disagrees for URLs [divergence:ai-security.ai-guard.integrations.claude-code:url-direction]. Each hook calls `execute_policy` through `LegacyAIGuardClient` when the policy ID it parsed from `AIGUARD_POLICY_ID` is a non-zero integer, and `resolve_and_execute_policy` when the parse gives None or 0. [ai-security.ai-guard.integrations.claude-code:endpoint-selection] The endpoints themselves are in [Calling AI Guard at runtime: the proxy endpoint, the DAS detection API, its host, direction and policy ID, and throttling in the Python SDK](kb:ai-security.ai-guard.runtime-api). In `scan_user_input.py`, `scan_url.py`, `scan_mcp_request.py` and `scan_file_read.py`, `get_policy_id` strips whitespace and surrounding quotes from `AIGUARD_POLICY_ID` and returns None when `int()` rejects the value. [ai-security.ai-guard.integrations.claude-code:policy-id-parsing] In those four hooks a malformed `AIGUARD_POLICY_ID` therefore falls back to policy resolution (`resolve_and_execute_policy`) without any log line saying the ID was ignored. [ai-security.ai-guard.integrations.claude-code:malformed-policy-id-resolves] `scan_response.py` parses the policy ID with `int(policy_id) if policy_id else None`, without stripping quotes or catching a ValueError, and `main()` calls it before scanning. [ai-security.ai-guard.integrations.claude-code:response-policy-id-unguarded] A non-numeric `AIGUARD_POLICY_ID` in the process environment (or one carrying literal quotes there) makes `scan_response.py` raise `ValueError` and exit with a traceback instead of scanning or emitting a block; the other hooks treat the same value as unset. [ai-security.ai-guard.integrations.claude-code:response-hook-crash] The changelog claims otherwise [divergence:ai-security.ai-guard.integrations.claude-code:quoted-policy-id-fix].

**Configuration.** The hooks read `AIGUARD_API_KEY`, `AIGUARD_CLOUD` (default `us1`) and `AIGUARD_TIMEOUT` (default 30) from the environment, first loading a `.env` beside the hook or in its parent directory without overriding variables already set, and log to `SECURITY_LOG_PATH` (default `~/.claude/hooks/aiguard/security.log`). [ai-security.ai-guard.integrations.claude-code:config] The bundled `aiguard_utils.py`, whose config falls back to a `config.json` (the example file pins `policy_id` 760), is imported by none of the hook scripts: each hook carries its own copy of the client, policy-ID and logging helpers and reads only the environment and `.env`. [ai-security.ai-guard.integrations.claude-code:shared-utils-unused]

**Verdicts and failures.** A missing `AIGUARD_API_KEY`, an error returned by the SDK, or an exception during the call blocks in every hook: the prompt, file-read, URL and MCP hooks return a block naming the cause, and `scan_response.py` withholds the tool response. [ai-security.ai-guard.integrations.claude-code:fail-closed-errors] A response whose `action` is empty (the shape the README gives a soft failure) is treated as `BLOCK` in every hook. [ai-security.ai-guard.integrations.claude-code:no-action-blocks] Every hook blocks only when the upper-cased action equals `BLOCK`: the prompt and file-read hooks log `DETECT` as a warning and allow it, and in all hooks any other action value, including one the hook does not recognise, takes the allow branch. [ai-security.ai-guard.integrations.claude-code:only-block-blocks] The README says unrecognised verdicts block [divergence:ai-security.ai-guard.integrations.claude-code:unknown-verdict]. When the hook's stdin is not valid JSON, or carries no prompt, URL or file path, the hooks exit 0 without scanning. [ai-security.ai-guard.integrations.claude-code:unparsable-input-allows]

**How a block is signalled.** On a block, `scan_user_input.py` writes the reason to stderr, prints a JSON object with `continue` false and exits 2; the `PreToolUse` hooks print the same kind of JSON and exit 0; `scan_response.py` prints it with `hookEventName` `PostToolUse` and exits 0. [ai-security.ai-guard.integrations.claude-code:block-signal] Older documents in the directory describe it differently [divergence:ai-security.ai-guard.integrations.claude-code:block-signal-docs]. What a PostToolUse block does to the result is open [gap:ai-security.ai-guard.integrations.claude-code:post-tool-withholding].

**What content is scanned.** `scan_url.py` scans the first non-empty of the tool input's `url`, `query`, `search_term`, `uri` and `href` fields. [ai-security.ai-guard.integrations.claude-code:url-extraction] A web search is therefore scanned on its query text, when the search tool sends it as `query` or `search_term`. [ai-security.ai-guard.integrations.claude-code:web-search-query] `scan_mcp_request.py` scans the first field of the tool input, among query, message, prompt, text, content, request, input, data, body, url and path, that holds a non-empty string, dict or list (JSON-encoding a dict or list); only when none does it join up to ten strings from the whole input, and it skips content under 5 characters. [ai-security.ai-guard.integrations.claude-code:mcp-extraction] An MCP call is scanned on one argument when any of the listed fields holds a non-empty string, dict or list: a benign `query` or `path` lets the call's other arguments through unscanned. [ai-security.ai-guard.integrations.claude-code:mcp-partial-scan] `scan_response.py` takes the first of the response's result, content, text, body, message, data, output, response and value fields (else the whole response as JSON), skips content under 5 characters, scans only the first 5000 characters, and scans only when those are at least 10 characters long. [ai-security.ai-guard.integrations.claude-code:response-limits] `scan_file_read.py` scans only paths matching its sensitive-file patterns (credentials, keys, `.env` files, SSH files, and names containing secret, password, token or api key among them), reading up to `AIGUARD_MAX_FILE_SCAN_SIZE` characters itself (default 51200); a non-matching, missing, non-regular or unreadable file, or content under 5 characters, is allowed without a scan. [ai-security.ai-guard.integrations.claude-code:file-read-scope]

**Across hosts.** How this compares with the other examples' fail posture and timing is in [Zscaler's AI Guard integration examples (zguard-ai-integrations): the catalog, the promised fail-closed posture against what each example does, and where each intercepts](kb:ai-security.ai-guard.integrations).

What to check:
1. Which events and tools the installed settings.json hooks: the shipped file covers prompts, Read, web tools and MCP tools only, so Bash, edits and the assistant's replies go unscanned unless more hooks are added.
2. That AIGUARD_POLICY_ID is unset or a plain integer; a malformed value is silently ignored by four hooks and crashes the response hook.
3. When testing a hook by hand, read stdout for continue false rather than relying on the exit code.
4. Whether the tool inputs and responses that matter fall inside what the hooks extract: one field of an MCP call, the first 5000 characters of a response, and only sensitive-looking file names.

Sources disagree (name both sides):
- Whether the shipped settings enable file-read scanning. [divergence:ai-security.ai-guard.integrations.claude-code:file-read-registration]
  - zguard-integrations: The Claude Code README says scan_file_read.py is not enabled by the bundled settings.json and must be added by hand.
  - zguard-integrations: The shipped settings.json registers scan_file_read.py on PreToolUse for the Read tool.
  - zguard-integrations: The 0.2.0 changelog says the hook was wired into the shipped settings.json.
  Impact: A reader following the README may believe file reads are unscanned, or add a second Read hook; the README's hand-written settings sample also omits it, while its merge command copies the shipped hooks, Read included.
- Which direction scan_url.py sends. [divergence:ai-security.ai-guard.integrations.claude-code:url-direction]
  - zguard-integrations: HOOKS_EXPLAINED.md says scan_url.py calls AI Guard with direction IN.
  - zguard-integrations: The code sends URLs and search terms with direction OUT, as the README's overview also says.
  Impact: A policy whose URL detectors are set on one direction only may catch or miss URLs depending on which document the operator configured from.
- How the hooks signal a block. [divergence:ai-security.ai-guard.integrations.claude-code:block-signal-docs]
  - zguard-integrations: HOOKS_EXPLAINED.md says scan_mcp_request.py blocks with exit code 2.
  - zguard-integrations: SILENT_BLOCK_FIX.md says every hook, scan_user_input.py included, now blocks with JSON and exit 0.
  - zguard-integrations: The code exits 2 from scan_user_input.py and 0 with JSON from the tool hooks, as the README states.
  Impact: A hand test that reads only the exit code misreads tool-hook blocks as allows; check stdout for continue false.
- What the hooks do with an action they do not recognise. [divergence:ai-security.ai-guard.integrations.claude-code:unknown-verdict]
  - zguard-integrations: The Claude Code README's fail-closed table says any unrecognised verdict is blocked.
  - zguard-integrations: The code blocks only on BLOCK; any other non-empty action is allowed.
  Impact: A new or unexpected verdict value from the API passes in this integration while its README says it blocks.
- Whether every Claude Code hook survives a malformed policy ID. [divergence:ai-security.ai-guard.integrations.claude-code:quoted-policy-id-fix]
  - zguard-integrations: The 0.2.0 changelog says the ValueError crash was fixed across the Claude Code hooks.
  - zguard-integrations: scan_response.py still converts the value with an unguarded int().
  Impact: The response hook alone can still crash on a malformed ID (response-hook-crash).
