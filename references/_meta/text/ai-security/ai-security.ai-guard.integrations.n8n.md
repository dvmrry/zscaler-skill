# n8n node for AI Guard (Zscaler example): an external community node, its operations, and the example chatbot workflow (ai-security.ai-guard.integrations.n8n)
Also called: n8n aiguard; @bdzscaler/n8n-nodes-aiguard; AIGuard_Secure_AI_Chatbot; n8n-nodes-aiguard

Zscaler's n8n integration is a workflow node that scans text with AI Guard wherever a workflow puts it, plus an example chatbot workflow.

**The node.** The n8n integration is the community node `@bdzscaler/n8n-nodes-aiguard`, installed from npm; its source is kept in a standalone repository and published as an npm package independently from the integrations repository. [ai-security.ai-guard.integrations.n8n:node-external] The integrations repository's `n8n` directory ships only the README and the example workflow `AIGuard_Secure_AI_Chatbot.json`, no node source. [ai-security.ai-guard.integrations.n8n:repo-contents] The README describes three operations: Prompt Scan (direction `IN`), Response Scan (`OUT`), and Dual Scan, which scans the prompt and then the response and skips the response scan when the prompt is blocked; the node runs where a workflow places it and does not intercept tool calls or streams. [ai-security.ai-guard.integrations.n8n:operations] The credential holds the API key, a cloud (default `us1`, building `https://api.{cloud}.zseclipse.net`), an optional override URL and an optional policy ID; per node a policy ID override, a transaction ID, a timeout (default 30000 ms) and an environment tag can be set; a policy ID selects `execute-policy`, otherwise `resolve-and-execute-policy`. [ai-security.ai-guard.integrations.n8n:configuration] The endpoints are in [Calling AI Guard at runtime: the proxy endpoint, the DAS detection API, its host, direction and policy ID, and throttling in the Python SDK](kb:ai-security.ai-guard.runtime-api).

**Failures.** The README says the node returns `action` `BLOCK` on internal errors when Continue On Fail is enabled. [ai-security.ai-guard.integrations.n8n:node-error-posture] The rest is open [gap:ai-security.ai-guard.integrations.n8n:node-behaviour].

**The example workflow.** The example workflow `AIGuard_Secure_AI_Chatbot.json` starts from a manual-trigger node named "When chat message received", sets `userMessage` from `$json.chatInput`, runs a prompt scan, then an OpenAI `gpt-4` chat completion on `$json.userMessage`, then a response scan of `$json.message.content`, and returns `$json.message.content` as the safe response. [ai-security.ai-guard.integrations.n8n:template-flow] Both IF nodes in the template treat any action other than `ALLOW` or `DETECT`, a missing one included, as `BLOCK`, test that value for equality with `BLOCK`, and connect their first output to a block-message node. [ai-security.ai-guard.integrations.n8n:template-verdict] A `BLOCK` (or anything the expression maps to it) therefore reaches the block message instead of the model or the reply. [ai-security.ai-guard.integrations.n8n:block-routing] Whether its data flow works is open [gap:ai-security.ai-guard.integrations.n8n:template-data-flow].

What to check:
1. Enable Continue On Fail on AI Guard nodes and branch on action, treating anything but ALLOW or DETECT as a block, as the template's IF nodes do.
2. Test the example workflow end to end before reuse: it reads the prompt and reply from fields the AI Guard node's output may not carry.
