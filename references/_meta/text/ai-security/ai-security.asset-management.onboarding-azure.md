# How is a Microsoft Azure tenant, management group or subscription onboarded to AI Security: roles, templates, network and error fixes? (ai-security.asset-management.onboarding-azure)
Also called: onboard azure ai security; Microsoft Entra tenant onboarding; azure subscription onboarding ai security; azure tree discovery template; azure onboarding template

Onboarding a Microsoft Entra tenant includes providing tenant details, deploying the tree discovery template, selecting the orchestrator subscription and monitoring scope, and deploying the onboarding template. [ai-security.asset-management.onboarding-azure:entra-workflow] The account-level pages are in [How are onboarded AWS, Azure and GCP accounts managed in AI Security: the Cloud Accounts page, validation, status, issues, deletion, orchestrator changes and the orchestrator itself?](kb:ai-security.asset-management.cloud-accounts) and the hub is [AI Asset Management in the AI Security Admin Portal: what it inventories, signing in, first-time configuration order, table behavior](kb:ai-security.asset-management). [gap:ai-security.asset-management.onboarding-azure:entra-details-steps]

**Prerequisites.** To onboard a Microsoft Entra tenant or management group: Global Administrator at Root; for a tenant, User Access Administrator at Root; for a management group, Contributor on the orchestrator subscription and User Access Administrator on the management group. [ai-security.asset-management.onboarding-azure:entra-roles] Entra onboarding requires the Standard_D2s_v3 VM type in the orchestrator region, Access management for Azure resources enabled, and the Microsoft.Storage resource provider registered in the orchestrator subscription so AI Security can validate the storage account. [ai-security.asset-management.onboarding-azure:entra-prereqs] To deploy the Azure subscription templates: User Access Administrator, Contributor and Key Vault Administrator on the orchestrator subscription; User Access Administrator on target subscriptions; Storage Account Contributor on the storage account; Application Administrator in Microsoft Entra ID. [ai-security.asset-management.onboarding-azure:subscription-roles] For an Azure subscription, Microsoft Graph permissions Application.Read.All (Application) and User.Read (Delegated) are mandatory; AuditLog.Read.All, Directory.Read.All, Organization.Read.All, Reports.Read.All, RoleManagement.Read.Directory, RoleManagementPolicy.Read.Directory and UserAuthenticationMethod.Read.All are optional, and entitlements are affected if the optional ones are not configured. [ai-security.asset-management.onboarding-azure:subscription-graph-permissions] The Azure subscription page lists Terraform, Azure CLI and shell versions per environment (Mac, Cloud Shell Bash and PowerShell, Windows command line and PowerShell). [ai-security.asset-management.onboarding-azure:tooling-versions] [gap:ai-security.asset-management.onboarding-azure:entra-roles-table]

**Tenant details.** In the Microsoft Entra tenant details, the role name and service principal name may contain only letters, numbers, hyphens and underscores; the role name is a prefix for all custom roles created during onboarding; the Management Group ID field (multiple IDs allowed) is visible only when Management Group is selected; up to 30 notification emails can be added. [ai-security.asset-management.onboarding-azure:tenant-details] AI Security creates the service principal named in the tenant details in the Microsoft Entra tenant after the tree discovery template is deployed; it defines the access policy and permissions for AI Security to access specific resources within the tenant. [ai-security.asset-management.onboarding-azure:service-principal] The optional Notification Emails field takes up to 30 addresses to notify of configuration or permissions issues with the onboarded tenant, and addresses can be added after onboarding. [ai-security.asset-management.onboarding-azure:notification-emails]

**Templates.** The Azure tree discovery template creates the service principal, a resource discovery role and managed identities, assigns the service principal permission to access tenant resources, and generates the application ID and client secret; the download is a ZIP with two Terraform files (backend.tf and azure_tf_basic.tf). [ai-security.asset-management.onboarding-azure:tree-discovery-template] After deploying the tree discovery template, API permissions must be granted to the service principal in the Azure portal; if AI service data collection is enabled the Custom Role (AI Agent) is also assigned to it at subscription level; validation in the Admin Portal uses the application ID and client secret and checks the custom roles created. [ai-security.asset-management.onboarding-azure:tree-discovery-validation] The Azure onboarding template creates custom roles in the tenant for the orchestrator, target and scanner, virtual machine scale sets for the orchestrator instance, storage accounts (blob containers for diagnostic logs and a queue receiving scan requests) and a NAT gateway. [ai-security.asset-management.onboarding-azure:onboarding-template-contents] Running terraform apply for the Azure onboarding template prompts for the IPv4 address of the system running Terraform (its public IP); AI Security validates the deployment every hour and Validate takes a couple of minutes. [ai-security.asset-management.onboarding-azure:onboarding-template-prompts-validation] Azure template deployment prompts for the public IPv4 address of the system running Terraform; AI Security validates the deployment every hour by checking the roles created and permissions granted, and Validate takes a couple of minutes. [ai-security.asset-management.onboarding-azure:subscription-deploy]

**Orchestrator and monitoring scope.** For Entra tenant onboarding the orchestrator Storage Account Name must be unique and cannot exceed 16 characters; AI Security shows an error if the name already exists, validating uniqueness if Microsoft.Storage is registered. [ai-security.asset-management.onboarding-azure:orchestrator-storage-name] The Deploy private endpoint checkbox sets up a private connection between AI Security and Azure resources, restricting communication over public IP addresses; it can be set or removed after onboarding via Manage Private Endpoint, and with it terraform apply must run from a VM with network line-of-sight to the key vaults. [ai-security.asset-management.onboarding-azure:private-endpoint] On Entra tenant onboarding all services are selected by default and AI Security's permissions are restricted to the selected services; Leverage MIP Label lets AI Security apply Microsoft Information Protection sensitivity labels to Azure File Share, and storage accounts used for logs are excluded automatically. [ai-security.asset-management.onboarding-azure:services-and-mip] Per monitored region the Entra flow takes Subnet ID, Network Security Group ID, an optional Postgres Delegated Subnet ID (only if Database was selected) and a Storage Account Resource ID; the option to use your own existing storage account for scanning logs is only available if Storage was selected, and resources are deployed only in selected regions. [ai-security.asset-management.onboarding-azure:region-config] In the Entra monitoring scope, selecting the management group scans all its subscriptions and Autodetection at management group level includes new subscriptions added later; all subscriptions in the group map to one business unit, a default business unit is assigned initially and can be changed after onboarding. [ai-security.asset-management.onboarding-azure:entra-monitoring-scope] Up to 15 tags can be added to Private DNS zone resources, and values that are only numerical do not count toward the 15-tag limit; Managed Identity resources get only predefined tags. [ai-security.asset-management.onboarding-azure:custom-tags] In Entra onboarding the evidence storage account container cannot be changed once added; a Custom Managed Container needs Storage Account Resource ID, Container Name and a Key Vault Resource ID used to encrypt the evidence data. [ai-security.asset-management.onboarding-azure:evidence-entra]

**Single subscription.** In single Azure subscription onboarding the network configuration is Custom (the organization's resources, requiring Subnet ID and Network Security Group ID) or Zscaler (Zscaler's resources); the optional Postgres Delegated Subnet ID is available only if a database is selected in Configure Services. [ai-security.asset-management.onboarding-azure:subscription-flow-options] For Azure subscriptions, diagnostic logs identify new, modified or deleted files in monitored storage accounts and without them only full scans are supported; evidence is stored in a Custom container or an Automated one created in the orchestrator account. [ai-security.asset-management.onboarding-azure:subscription-diag-evidence] New Azure target subscriptions can be added to an existing onboarded account with the Administrator role or a custom role with the Configure Monitoring Scope permission; the form takes a Subscription ID, an optional Subscription Name and a Business Unit, after which the template is downloaded from Roles and Templates and deployed. [ai-security.asset-management.onboarding-azure:target-subscriptions]

**Changes after onboarding.** The Azure application's client secret has an expiration date and must be renewed for the application to retain AI Security's access; changing it needs the Administrator role or a role with Change Application Details permissions and a new client secret added in the Microsoft Entra tenant first. [ai-security.asset-management.onboarding-azure:client-secret-change] Validate in Change Application Details checks the new client secret against the application ID; an invalid secret, or one that does not match the application, produces an error. [ai-security.asset-management.onboarding-azure:client-secret-validation] Before redeploying the Azure orchestrator template the system's IP address must be added to the Azure storage account and Azure Key Vault IP networks, which is required when multiple users apply Terraform from different IP addresses. [ai-security.asset-management.onboarding-azure:orchestrator-change-prereq] The orchestrator storage account name cannot exceed 16 characters; the storage account stores the target subscriptions' activity logs and is created while running the onboarding template; the Deploy private endpoint checkbox restricts communication over public IP addresses. [ai-security.asset-management.onboarding-azure:orchestrator-change-storage-account] Before running the template on a new Azure orchestrator subscription the previously deployed template is purged with terraform destroy; terraform.tfvars gets a changed random_seed value which must be reused when deploying new templates; if the resource group was deleted manually, the listed resources are imported and the secrets key vault is purged. [ai-security.asset-management.onboarding-azure:orchestrator-change-purge-seed] To reset the orchestrator or monitoring scope subscriptions after deploying the onboarding template, run terraform destroy to purge the template and delete the resources it created, then Reset, Confirm, configure new subscriptions and deploy the onboarding template. [ai-security.asset-management.onboarding-azure:reset-scope] Terraform state files are needed to manage resources created by the AI Security templates and to upgrade to new templates; if they are lost or deleted, purge the resources, then download and rerun the onboarding templates. [ai-security.asset-management.onboarding-azure:entra-state-recovery] Purging Entra onboarding resources includes deleting the auth-plane, worker-plane and control-plane resource groups, purging the z-ais secrets key vaults, deleting the access, analyzer and orchestrator roles on orchestrator subscriptions, the target role on target subscriptions, and the service principal. [ai-security.asset-management.onboarding-azure:entra-purge-list]

**IAM roles and permissions.** On Azure, the resource discovery role is assigned at the management group level, the AI Security Access role at the AI Security resource group level, and the target role at the monitoring scope or target subscriptions level. [ai-security.asset-management.onboarding-azure:iam-role-scopes] The Custom Role (AI Agent) collects data from AI services and is required only when AI service data collection is enabled; it is assigned to the Tree Discovery service principal for each subscription, at subscription level rather than the root management group. [ai-security.asset-management.onboarding-azure:iam-custom-role-ai-agent] The Azure Custom Network Configuration Role permissions (including network security group join at the orchestrator subscription) are conditional and only required if Custom Network is selected. [ai-security.asset-management.onboarding-azure:iam-custom-network-conditional] The Azure target role's Microsoft.KeyVault/vaults/secrets/getSecret/action is conditional and only required if Custom Network is used with Unmanaged DB Scanning. [ai-security.asset-management.onboarding-azure:iam-target-conditional-secret] For Microsoft Information Protection labeling the orchestrator managed identity needs the application permissions Content.Writer (Azure Rights Management Services) and UnifiedPolicy.Tenant.Read (Microsoft Information Protection Sync Service). [ai-security.asset-management.onboarding-azure:iam-mip-api-permissions] The IAM roles and permissions page says all nine of the following API permissions are required for the AI Security service principal registered in Microsoft Entra ID: Application.Read.All, AuditLog.Read.All, Directory.Read.All, Organization.Read.All, Reports.Read.All, RoleManagement.Read.Directory, RoleManagementPolicy.Read.Directory and UserAuthenticationMethod.Read.All as Application type, and User.Read as Delegate type. [ai-security.asset-management.onboarding-azure:iam-service-principal-graph] [gap:ai-security.asset-management.onboarding-azure:iam-ai-agent-notactions]

**Network.** A custom Azure network needs a Control Plane VNet created only in the primary region where the orchestrator runs and a Worker Plane VNet in every region where the resources exist, both in the orchestrator subscription, with non-overlapping CIDR ranges. [ai-security.asset-management.onboarding-azure:network-vnet-topology] In the manual worker plane VNet procedure the subnet gets the service endpoints Microsoft.KeyVault, Microsoft.Sql and Microsoft.Storage.Global with Network Policy for Private Endpoints set to Disabled; Azure PostgreSQL Server scanning needs a network security group and a subnet delegated to Microsoft.DBforPostgreSQL/flexibleServers. [ai-security.asset-management.onboarding-azure:network-subnet-settings] The control plane network security group's allow-outbound rule to AI Security lists, for the US Cloud, destination IPs 35.164.218.12, 34.208.206.171, 52.42.215.70, 35.84.226.159, 52.40.209.233 and 54.191.175.18. [ai-security.asset-management.onboarding-azure:network-us-cloud-ips] The outbound rules to Microsoft Information Protection (service tags AzureInformationProtection, AzureActiveDirectory, AzureFrontDoor.Frontend, AzureFrontDoor.FirstParty) are required if Microsoft Information Protection labeling is enabled. [ai-security.asset-management.onboarding-azure:network-mip-rules-conditional] After the Azure VNet peering is configured, the Peering state becomes Connected and the Sync status Fully Synchronized; the VNet peering step is common to manual and template-based configurations. [ai-security.asset-management.onboarding-azure:network-peering-state] The Azure network template is azure_network_components.zip, containing control-plane and worker-plane folders. [ai-security.asset-management.onboarding-azure:network-template-zip] [gap:ai-security.asset-management.onboarding-azure:network-other-clouds]

**Error fixes.** The Azure error Code RoleAssignmentLimitExceeded (No more role assignments can be created) means the role assignment limit is exceeded; the documented fix is to delete any custom role to make room. [ai-security.asset-management.onboarding-azure:err-role-limit] If the Standard_D2s_v3 VM size is unavailable in the region (Capacity Restrictions), run terraform destroy, download the Azure Onboarding template, and set primary_region in terraform.tfvars to a region where Standard_D2s_V3 is available. [ai-security.asset-management.onboarding-azure:err-vm-size] The InvalidParameter error that securityProfile.encryptionAtHost is not valid because the Microsoft.Compute/EncryptionAtHost feature is not enabled is fixed by registering the EncryptionAtHost feature with az feature register. [ai-security.asset-management.onboarding-azure:err-encryption-at-host] The Terraform error that the state blob is already locked is fixed with terraform force-unlock using the lock ID. [ai-security.asset-management.onboarding-azure:err-state-lock] Documented permission fixes: grant API permissions to the service principal when admin consent has not been granted; enable access management for Azure resources for your ID on an AuthorizationFailed role assignment error; assign Key Vault Administrator when the caller is not authorized to perform the action on the key vault secret. [ai-security.asset-management.onboarding-azure:err-permissions] A key vault key error on control-plane-cmk (client address not authorized) is fixed by rerunning with the correct IP; an AuthorizationFailure on a storage queue is fixed by adding your system's IP address to the storage account and key vault IP networks. [ai-security.asset-management.onboarding-azure:err-network-ip] The ManagementGroupNotFound error while deploying the Tree Discovery template is fixed by correcting the Management Group ID in Tenant Details (Reset, edit, Apply) and redeploying the Tree Discovery template. [ai-security.asset-management.onboarding-azure:err-mgmt-group] If an account moves to Needs Attention while the template is deploying, wait for AI Security's next validation or run the on-demand validation. [ai-security.asset-management.onboarding-azure:err-needs-attention] A key vault key that already exists (control-plane-cmk or worker-plane-cmk) is fixed with terraform import of the azurerm_key_vault_key cmk_key resource. [ai-security.asset-management.onboarding-azure:err-key-import] The Azure error CannotDeleteResource (a private DNS zone cannot be deleted while nested resources exist) is fixed by deleting the resources manually in the Azure portal. [ai-security.asset-management.onboarding-azure:err-delete-resources] For these errors the documented resolution is to rerun the template: RoleDefinitionWithSameNameExists, ContainerOperationFailure (container being deleted), VMAgentStatusCommunicationError, InternalDiskManagementError, RoleAssignmentUpdateNotPermitted, KeyVaultAuthenticationFailure and StorageFailure/EncryptionScopeNotAvailable. [ai-security.asset-management.onboarding-azure:err-rerun] [gap:ai-security.asset-management.onboarding-azure:err-rerun-rows]

What to check:
1. Which roles the signed-in admin needs: for a tenant or management group, Global Administrator at Root plus the tenant or management group roles; for a subscription, the orchestrator-subscription, target-subscription, storage account and Microsoft Entra ID roles.
2. Whether the Graph permissions are required or optional for the service principal: the IAM page says all nine it lists are required, while the subscription page marks Application.Read.All and User.Read Mandatory and the other seven Optional.
3. The documented fix for the exact error code or message against the error-fix claims before suggesting a rerun.
