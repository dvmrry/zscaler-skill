# AI Guard with the Portkey AI Gateway: the native Portkey guardrail as the README describes it, and the client-side SDK scanning examples (ai-security.ai-guard.integrations.portkey)
Also called: ai guard portkey; portkey zscaler guardrail; aiguard_scanner.py; portkey ai gateway ai guard

The Portkey folder offers a guardrail built into Portkey's SaaS gateway, whose code is not in this repository, and example scripts that scan around a self-hosted gateway from the client. The README describes Portkey's native Zscaler AI Guard guardrail on the Portkey SaaS platform: an API key added under Admin Settings, a guardrail with a configurable Policy ID and timeout, `beforeRequestHook` for input and `afterRequestHook` for output, attached to a Portkey config as input and output guardrails. [ai-security.ai-guard.integrations.portkey:native]

**The SDK examples.** The Anthropic example (`test_anthropic.py`) scans the prompt with direction IN using a `str(uuid.uuid4())` transaction ID, prints "Scan error — aborting." and returns when the scan result carries an error, stops unless the action is ALLOW or DETECT, sends the prompt through a local Portkey gateway, then scans the first choice's content with direction OUT and the same transaction ID and withholds it unless ALLOW or DETECT. The README says each test script follows this three-step flow: pre-scan, gateway request, post-scan. [ai-security.ai-guard.integrations.portkey:client-side] The shared scanner calls the SDK's `LegacyZGuardClientHelper` `resolve_and_execute_policy` with the cloud from `AIGUARD_CLOUD` (default us1) and returns an error entry instead of a verdict when the SDK reports one. [ai-security.ai-guard.integrations.portkey:scanner] In the SDK approach the gateway itself does no scanning; a client that does not run the scan reaches the model through the gateway unscanned. [ai-security.ai-guard.integrations.portkey:not-in-gateway]

**SDK version.** The examples require `zscaler-sdk-python>=1.9.44`. [ai-security.ai-guard.integrations.portkey:requirements]
