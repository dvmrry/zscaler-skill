# Who administers AI Guard: system users and RBAC roles (ai-security.ai-guard.admin-access)
Also called: ai guard rbac; ai guard roles; ai guard system users; ai guard admin roles; ai guard viewer editor administrator; ai guard view prompts permission

AI Guard administrators are system users; what each may do is set by an RBAC role.

**System users.** System users are managed through the Authentication Service admin portal and can be viewed in AI Guard: the System Users page under System User Management shows each user's name, email, login type, role, creation date and last-updated date, and system users can be added and edited (name, email and role) from it. [ai-security.ai-guard.admin-access:system-users]

**Roles.** AI Guard RBAC applies to system users managed through Authentication Service and to system users hosted locally in AI Guard. [ai-security.ai-guard.admin-access:rbac-scope] A role combines per-module permissions with scopes: Policies, LLMs, Private AI Apps, Log Exports, User Management and RBAC Management take None, View, Create, Edit or Delete (as does Default Access, which applies permissions to all modules); Dashboard, Insights, Topology and Audit Log take None or View; Policy Testing None, View or Create; Tenant Settings None, View or Edit; API Clients None, View or Delete. [ai-security.ai-guard.admin-access:rbac-permissions] Role templates are Viewer (read-only access to all modules), Editor (read, create and update, no delete) and Administrator (full access to all modules). [ai-security.ai-guard.admin-access:templates] The page's example Customer Service role gives Dashboard and Insights View while leaving Events (View Prompts) unchecked, so seeing prompt content is a permission of its own. [ai-security.ai-guard.admin-access:view-prompts-separate] Roles are assigned to system users from System User Management, by editing or adding a system user and picking the role. [ai-security.ai-guard.admin-access:assign]

What to check:
1. The administrator's role in System User Management and that role's scope on the module in question, including whether it can view prompts.
