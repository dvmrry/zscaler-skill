# Connecting an AI app for red teaming: network type, private access, and the application profile that shapes tests (ai-security.ai-red-teaming.assets)
Also called: connect asset; ai app for red teaming; red teaming application profile; predefined responses; red teaming rate limit; multi-step attacks; private network access type

An asset is connected from AI Infrastructure > AI Assets with the +Connect Asset button and the AI App for Red Teaming option, in three steps: select the connection type, configure the connection, and configure the application. [ai-security.ai-red-teaming.assets:connect-flow] The connection step is in [Red Teaming connection types and the fields each needs (REST API, Proxy SDK, OpenAI REST API, Copilot Studio, Glean, Microsoft Teams, Agentforce, Amazon Bedrock AgentCore and Agents), and the connection test](kb:ai-security.ai-red-teaming.connections); this subject covers the app, its network type and its profile.

**Network type.** Each AI app has a unique name, a business unit and a network type: Public AI Apps are accessible over the public internet; a private AI app is isolated from it with no ingress networking enabled, and the AI Red Teaming workers reach it by the Private Network Access Type chosen, Broker or IP Whitelisting, where the listed IP addresses are added to the allowlist. [ai-security.ai-red-teaming.assets:network-type] The addresses to whitelist are open [gap:ai-security.ai-red-teaming.assets:whitelist-addresses]. For private network access types the supported connection types are the API connections REST API, OpenAI RestAPI and Proxy SDK, and the platform Agentforce; the broker page, under a broker's Assigned AI Apps, lists the Connection Type as REST API, OpenAI-Compatible API, Proxy SDK, and Agentforce. [ai-security.ai-red-teaming.assets:private-connection-types] The broker route is in [The AI Red Teaming broker: outbound WSS tunnel to private apps, provisioning, run manifest, allow-lists and troubleshooting codes](kb:ai-security.ai-red-teaming.brokers).

**Application profile.** Configure your application records the app's name, business unit, description, stage (Development, Production and Staging), availability (Internal or Customer-Facing), whether it is RAG supported, and the system prompt in three parts: the tools and functions it mentions, its confidential part and its non-confidential part. [ai-security.ai-red-teaming.assets:app-profile] Supported Modes records which inputs the app handles, Text, Image, Document (for example PDFs or other file-based content) or Voice (audio), which helps show which testing scenarios apply and ensures compatible adversarial tests are selected. [ai-security.ai-red-teaming.assets:supported-modes]

**How the profile shapes tests.** Attacks are generated in English by default, and for better coverage test variations are also run, translated into the other languages selected; Rate Limit is the maximum number of requests the app can process per minute; Parallel Requests sends requests in parallel, and toggled off sends them to the app one at a time; Multi-Step Attacks allows multi-message attack prompts in the conversation. [ai-security.ai-red-teaming.assets:test-shaping] Predefined Responses are replies expected from the app in specific situations, for example when an adversarial input is sent and the system activates a Guardrail; if the actual response matches one during an adversarial testing scenario the probe test case is marked as passed, matched as Text (exactly identical) or as a Regex pattern. [ai-security.ai-red-teaming.assets:predefined-responses]

**Settings.** An app's detailed information page has a Settings icon that opens AI App Settings, Connection Settings and Probe Settings, where a new probe can also be created; AI App Settings and Connection Settings can be modified or deleted from the Settings tab. [ai-security.ai-red-teaming.assets:settings]
