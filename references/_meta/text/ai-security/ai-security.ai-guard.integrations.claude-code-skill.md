# Claude Code skill for AI Guard (Zscaler example): on-demand scans with scan.py, directions, exit codes and failure handling (ai-security.ai-guard.integrations.claude-code-skill)
Also called: aiguard skill; /aiguard; claude-code-skill; scan.py aiguard

Zscaler's Claude Code skill is a script Claude can run to scan a piece of text with AI Guard on request. It sits beside the always-on hooks in [Claude Code hooks for AI Guard (Zscaler example): events hooked, directions, verdict and failure handling, and what content is scanned](kb:ai-security.ai-guard.integrations.claude-code).

**When it runs.** The skill is an on-demand scanner: it runs when the user invokes `/aiguard` or when Claude decides to invoke it from the auto-invoke rules in `SKILL.md`; its README marks pre-tool, post-tool and streaming scanning as not supported. [ai-security.ai-guard.integrations.claude-code-skill:invocation] `SKILL.md` tells Claude to run the scanner, check the `action` field, and address a `BLOCK` or `DETECT` result before proceeding. [ai-security.ai-guard.integrations.claude-code-skill:workflow] Nothing in the skill stops content by itself: whether a scan happens, and whether its verdict is honoured, depends on the user or the model invoking it and following `SKILL.md`. [ai-security.ai-guard.integrations.claude-code-skill:advisory-only]

**Which call it makes.** In `scan.py` the prompt type scans with direction `IN`; the response and code types scan with `OUT`; the conversation type scans the prompt with `IN` and the response with `OUT`. [ai-security.ai-guard.integrations.claude-code-skill:scan-types] `scan.py` reads `AIGUARD_API_KEY` (required), `AIGUARD_CLOUD` (default `us1`), `AIGUARD_TIMEOUT` (default 30) and an optional `AIGUARD_POLICY_ID` from the process environment; the policy ID is quote-stripped and a value `int()` rejects is treated as unset, so the call goes to `resolve_and_execute_policy`. [ai-security.ai-guard.integrations.claude-code-skill:config] The README's `.env` route (`cp .env.example .env` then `source .env`) leaves the variables unexported unless the shell exports them, so `scan.py` then sees no key and fails closed. [ai-security.ai-guard.integrations.claude-code-skill:env-file-not-exported] The endpoints are in [Calling AI Guard at runtime: the proxy endpoint, the DAS detection API, its host, direction and policy ID, and throttling in the Python SDK](kb:ai-security.ai-guard.runtime-api).

**Verdicts and failures.** A missing key, a missing SDK, an SDK error, a response without an action, or an exception yields JSON with `status` error and `action` `BLOCK`, and the script exits 1. [ai-security.ai-guard.integrations.claude-code-skill:fail-closed] A single scan exits 2 on `BLOCK` and 0 otherwise, reporting `threat_detected` for `DETECT` or any triggered detector and `safe` for the rest, so an unrecognised action exits 0; the conversation type, combining its two scans, turns anything other than `ALLOW` or `DETECT` into `BLOCK`. [ai-security.ai-guard.integrations.claude-code-skill:verdict-exit]

What to check:
1. Do not count the skill as enforcement: it scans only when invoked, and the model decides what to do with the verdict.
2. That AIGUARD_API_KEY is exported in the environment Claude Code runs scripts in, not only written to the skill's .env.
