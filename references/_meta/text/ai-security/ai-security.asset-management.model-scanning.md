# How the AI Asset Management AI model scanner works: the CLI, the integration API key and its arguments (ai-security.asset-management.model-scanning)
Also called: ai model scanner; z-ai-model-scanner; Z_AI_MODEL_SCANNER_API_KEY; model scan management; model scan integration

The AI model scanner is a command-line tool that developers and MLOps engineers run before deploying AI models to production, locally or in CI/CD pipelines, and it sends findings to the AI Security Admin Portal. [ai-security.asset-management.model-scanning:what-scanner-is] The scanner identifies malicious code, backdoors and vulnerabilities in AI models using YARA rules and the Zscaler ThreatLabz AV engine, detects embedded credentials, API keys and sensitive information across all supported file types, and extracts embedded code from pickle files and Lambda layers. [ai-security.asset-management.model-scanning:detections] The hub is [AI Asset Management in the AI Security Admin Portal: what it inventories, signing in, first-time configuration order, table behavior](kb:ai-security.asset-management).

**Admin Portal pages.** The Integration Registration tab of Administration > Model Scan Management lists, per integration, Integration Name, Integration ID, Modified By, Configured On and Status (Enabled or Disabled). [ai-security.asset-management.model-scanning:integration-registration-columns] The Download Model Scanner tab lists scanner binaries by Scanner Name, Scanner Version, Operating System (examples Linux, macOS), Architecture (examples x64, Arm64) and Release Date. [ai-security.asset-management.model-scanning:download-tab-columns] To use the scanner, an integration must first be added and an API key generated in the Admin Portal; the key authenticates the scanner and lets it send scan results back, and it is not recoverable, so it must be copied and stored securely. [ai-security.asset-management.model-scanning:api-key] Regenerating the API key on an integration invalidates the existing key, so every environment or script using the old key must be updated; the page gives exposed, lost or periodic credential rotation as reasons. [ai-security.asset-management.model-scanning:regenerate-key] Deleting a model scan integration requires entering CONFIRM in the text box of the confirmation window. [ai-security.asset-management.model-scanning:delete-integration]

**Running the scanner.** Before running the scanner you need the scanner binary for your operating system from the Model Scan Management page and an API key from the model scan integration; the key is set as the environment variable Z_AI_MODEL_SCANNER_API_KEY. [ai-security.asset-management.model-scanning:prerequisites-env-var] The scanner is run as ./z-ai-model-scanner scan <PATH_TO_MODEL_DIRECTORY> --timeout <timeout in seconds> --output <directory>, where PATH_TO_MODEL_DIRECTORY is the local directory containing the model to scan. [ai-security.asset-management.model-scanning:cli-command] The scanner arguments -o/--output set the report output directory and -f/--format [json] sets the report format; both are marked not required. [ai-security.asset-management.model-scanning:cli-arguments-output] --no-recursive stops the scanner scanning subdirectories (scanning is recursive by default); --max-file-bytes sets a size limit in bytes for scanned files and 0 disables the limit; --timeout is the timeout in seconds for each individual file scan and 0 disables it. [ai-security.asset-management.model-scanning:cli-arguments-scan] --fail-on [none|low|medium|high|critical] sets a severity threshold that makes the scanner exit with a non-zero status code (example --fail-on high fails on any high or critical finding); --profile [primary|primary+secondary|all] controls scan depth: primary is fastest, all most comprehensive, primary+secondary best balanced. [ai-security.asset-management.model-scanning:cli-fail-on-profile] After the command runs, the scanner authenticates with AI Security, downloads the latest rules and scans the specified model files or directories; the Deploying the AI Model Scanner page says the results are available in the Admin Portal on the AI Infrastructure > Model Security page. [ai-security.asset-management.model-scanning:run-behaviour] [divergence:ai-security.asset-management.model-scanning:results-location] [gap:ai-security.asset-management.model-scanning:scanner-argument-details]

What to check:
1. Whether the API key is still held: the page says the key is not recoverable, and regenerating it invalidates the existing key so every environment or script using the old key must be updated.
2. That the key reaches the scanner as the environment variable Z_AI_MODEL_SCANNER_API_KEY.
