# AI Guard with NVIDIA NeMo Guardrails: the ready-to-use custom action and rails, the proposed library plugin, and the defects in both as shipped (ai-security.ai-guard.integrations.nemo-guardrails)
Also called: ai guard nemo; ai guard nemo guardrails; zs-ai-guard.py; CallZscalerAiGuardAction; CallZsAiGuardAction; zscaler aiguard moderation on input; zscaler_aiguard library plugin

The NeMo folder holds a configuration to copy into a NeMo Guardrails project and a library-format plugin written for submission to the NeMo Guardrails repository. `config/` is a standalone NeMo Guardrails configuration (a custom action plus Colang input and output rails), and `library-plugin/` is a library-format plugin (`zscaler_aiguard`) with a system action and Colang 2.0 and Colang 1.0 flows, meant to be submitted to NeMo Guardrails. [ai-security.ai-guard.integrations.nemo-guardrails:two-forms]

**The custom action.** The custom rails scan `$user_message` as the prompt (direction IN) on input and `$bot_message` as the response (direction OUT) on output, and on a block make the bot refuse to respond and stop. [ai-security.ai-guard.integrations.nemo-guardrails:config-rails] The custom action calls `resolve_and_execute_policy` through the SDK's `LegacyZGuardClientHelper` unless `AIGUARD_POLICY_ID` holds an integer, in which case it calls `execute_policy` with it; a non-integer value is logged as a warning and ignored. No transaction ID is sent. [ai-security.ai-guard.integrations.nemo-guardrails:config-endpoint] The custom action starts from a blocked verdict and clears it only when the action is ALLOW or DETECT, so an SDK error, an exception, a None result or a missing action all leave the turn blocked. [ai-security.ai-guard.integrations.nemo-guardrails:config-verdict] The custom action is registered as `CallZsAiGuardAction`, while `config.yml` and `rails.co` refer to `CallZscalerAiGuardAction`. [ai-security.ai-guard.integrations.nemo-guardrails:action-name-mismatch] Whether NeMo still finds the action is open [gap:ai-security.ai-guard.integrations.nemo-guardrails:action-name-resolution].

**The library plugin.** The library plugin imports `LegacyZGuardClientHelper` from `zscaler.zaiguard.legacy`, the module path the repository's 0.2.0 changelog says was wrong and fixed to `zscaler.aiguard.legacy` for NeMo Guardrails among others; the import is lazy, inside `_get_sdk_client`, which `_scan_sync` calls from within the action's try block. [ai-security.ai-guard.integrations.nemo-guardrails:library-import] As shipped, every library-plugin scan fails on the import and the action returns BLOCK, so the flows refuse every user prompt and bot message. [ai-security.ai-guard.integrations.nemo-guardrails:library-always-blocks] The library action returns the verdict's action upper-cased (ALLOW without a scan for empty text, BLOCK on an exception or a None result), and both flow files act only when `$result.action == "BLOCK"`; the action's output mapping, which treats anything but ALLOW or DETECT as a block, is not what the flows test. [ai-security.ai-guard.integrations.nemo-guardrails:library-flows] Once the import is corrected, a verdict-less reply (an HTTP 200 without `action`, such as "Policy not found") becomes the action string `NONE`, which the flows do not treat as a block, so the turn proceeds. [ai-security.ai-guard.integrations.nemo-guardrails:library-no-verdict] The README promises fail-closed handling [divergence:ai-security.ai-guard.integrations.nemo-guardrails:library-fail-closed].

**Versions.** The README requires NeMo Guardrails 0.18.0 or later and installs `zscaler-sdk-python` without a version constraint. [ai-security.ai-guard.integrations.nemo-guardrails:versions] Nothing in the folder pins `zscaler-sdk-python`, so the SDK version is whatever the README's unconstrained install resolves. [ai-security.ai-guard.integrations.nemo-guardrails:sdk-unpinned]

What to check:
1. With the custom config, that the action name in rails.co matches the name registered in actions/zs-ai-guard.py, and that a test prompt actually produces an AI Guard transaction.
2. Do not deploy the library plugin as shipped: its SDK import fails, so every turn is blocked.

- [ai-security.ai-guard.integrations.nemo-guardrails:library-no-verdict] Tier B: Follows from the SDK model setting action to None when the reply has none and from Python's str(None).upper() being "NONE"; whether NeMo applies the output mapping anywhere the flows would see it is not established.
- [ai-security.ai-guard.integrations.nemo-guardrails:sdk-unpinned] Tier B: Rests on a file listing of NemoGuardrails/ at the pin (LICENSE.md, README.md, SUPPORT.md, config/config.yml, config/actions, config/rails, library-plugin/README.md and the zscaler_aiguard package), which has no requirements.txt, pyproject.toml or setup file; an absence from a listing, not a quoted line.

- Whether the NeMo library plugin fails closed on a reply without a verdict. [divergence:ai-security.ai-guard.integrations.nemo-guardrails:library-fail-closed]
