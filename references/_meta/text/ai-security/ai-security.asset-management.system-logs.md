# What the AI Infrastructure scanning system logs show and what the ZS-LP, ZS-DC and ZS-ONBOARDING error codes mean (ai-security.asset-management.system-logs)
Also called: ai infrastructure scanning logs; system logs ai infrastructure scanning; zs-lp error codes; zs-onboarding error codes; zs-dc error codes

The System Logs - AI Infrastructure Scanning article places the page at Administration > System Logs - AI Infrastructure Scanning; the page covers scan events across AWS, Azure and GCP; its Time Range filter offers Last 1 Hour, Last 1 Day, Last 7 Days, Last 30 Days or All Time, and its Environment filter AWS, Azure, GCP, Copilot Studio, GitHub or GitLab. [ai-security.asset-management.system-logs:logs-scope-filters] The Source Status filter on the scan events page selects Active (events for existing resources) or Deleted (events for resources that have been removed), and Severity filters Critical, High, Medium, Low or Unknown. [ai-security.asset-management.system-logs:logs-source-status] Scan event results can be exported as a CSV file to the default downloads folder, also viewable on the Report Management page, and the exported scan event logs cover up to 30 days of scan history. [ai-security.asset-management.system-logs:logs-csv-export] In the scan events table, Timestamp is when the last full scan was initiated for the resource in the user's local time, Event Details is a comma-separated list of scan error messages from the resource's latest scan attempt, and Severity is derived from the scan error or resource tag. [ai-security.asset-management.system-logs:logs-fields] Hidden columns of the scan events table, enabled through the gear icon, include Parent Resource Type, Full Scan Completed At, Scan Updated At, Is Primary and Is Deleted. [ai-security.asset-management.system-logs:logs-hidden-columns] The Report Management page (Administration > Report Management) lists reports with Report Type, which is Excel files only, and a Status of In Progress while generating or Download when ready. [ai-security.asset-management.system-logs:reports-download]

**Error code sources.** The error-code page documents codes from Data Collectors (DC), which collect cloud resource metadata and activity logs from AWS, Azure, GCP, Microsoft Copilot and other providers, and from the Cloud Service Provider onboarding platform, where most non-success events are CONFIGURATION_ERROR and the default successful-validation event is INFORMATION. [ai-security.asset-management.system-logs:codes-sources] ZS-LP-0001 (scan initiated), ZS-LP-0003 (scan completed), ZS-LP-0108 (scan was stopped) and ZS-ONBOARDING-0000 (onboarding validation successful) are listed as informational log entries that are not errors; ZS-LP-0108 sets the resource status to stopped rather than failed. [ai-security.asset-management.system-logs:codes-information] ZS-LP-0005 (resource scan skipped) is intentional with no errors, for example a DB server with no databases attached or a workload with no sub-resources eligible for scanning. [ai-security.asset-management.system-logs:codes-skipped]

**Scanner codes.** Unsupported-configuration codes include ZS-LP-0106 (unsupported OS such as Windows 10/11 or Windows Server 2012, in Azure discovery), ZS-LP-0602 (AWS Marketplace AMI), ZS-LP-0604 (Azure unmanaged disks; only managed disks supported), ZS-LP-0605 (Azure Disk Encryption) and ZS-LP-0611 (GCP CSEK-encrypted disks). [ai-security.asset-management.system-logs:codes-unsupported-os-disk] ZS-LP-0613 means an AWS DynamoDB table lacks Point-in-Time Recovery, which is required to export a consistent snapshot for scanning; ZS-LP-0615 means an Azure PostgreSQL Flexible Server allows only private endpoint connections, so the scanner cannot reach it. [ai-security.asset-management.system-logs:codes-unsupported-data] ZS-LP-0401 is typically an HTTP 401 from the cloud provider API, and ZS-LP-0403 means the scanner authenticated but lacks IAM or RBAC permissions, corresponding to HTTP 403 / AuthorizationFailed. [ai-security.asset-management.system-logs:codes-privileges] ZS-LP-0609 means the volume is encrypted with an AWS-managed key but no Customer Managed Key exists in the region, and a CMK is required to re-encrypt the snapshot for cross-account scanning; ZS-LP-0612 means the KMS/CMK key used to encrypt the volume or snapshot was disabled by the customer. [ai-security.asset-management.system-logs:codes-kms] ZS-LP-0105 means a cloud organization policy such as AWS SCP, GCP Org Policy or Azure Policy blocks the scan, and ZS-LP-0610 means an Azure management lock on the resource, resource group or subscription prevents it. [ai-security.asset-management.system-logs:codes-external-restriction] ZS-LP-0702 (instance quota exceeded) is non-retryable and requires a quota increase request, while ZS-LP-0704 (resource limit exceeded) and ZS-LP-0706 (vCPU limit exceeded for running instances) are retryable and for ZS-LP-0429 (rate limited) the system backs off and the scan is retried. [ai-security.asset-management.system-logs:codes-retry-quota] For ZS-LP-0705, AWS rate-limited concurrent snapshot creation for an EBS volume and the system must wait at least 15 seconds before retrying. [ai-security.asset-management.system-logs:codes-snapshot-throttle] ZS-LP-0700 means Azure preempted the scan, typically because a Spot/low-priority scanner VM was reclaimed, and ZS-LP-0701 means the Azure scanner VM was marked for deletion during the scan. [ai-security.asset-management.system-logs:codes-azure-preempt]

**Collector and onboarding codes.** Data collector code ZS-DC-2004 (CloudTrail bucket or prefix not found) says to verify the bucket name and prefix in the collector configuration, and ZS-DC-4001 (no CloudTrail files in the interval) says to verify CloudTrail is enabled and logging to the correct S3 bucket. [ai-security.asset-management.system-logs:codes-dc-cloudtrail] ZS-DC-1001 maps collector authorization failures to AWS errors including UnauthorizedException and AccessDeniedException, Azure unauthorized (HTTP 401) and GCP PERMISSION_DENIED or UNAUTHENTICATED, ZS-DC-1003 to Azure AuthorizationFailed (HTTP 403) and ZS-DC-1006 to Azure ExpiredAuthenticationToken (HTTP 401). [ai-security.asset-management.system-logs:codes-dc-auth] Onboarding codes such as ZS-ONBOARDING-0082 (Cloud Asset), 0088 (Storage) and 0089 (Compute) are generated when a required GCP API is disabled in the target project. [ai-security.asset-management.system-logs:codes-onboarding-gcp-api] ZS-ONBOARDING-0020 (CloudTrail not configured) and 0021 (CloudTrail misconfigured) are AWS CloudTrail configuration errors; 0022, 0023 and 0024 report denied KMS decrypt, S3 get-bucket-location and IAM list-role-policies. [ai-security.asset-management.system-logs:codes-onboarding-cloudtrail] ZS-ONBOARDING-0040 means validation is pending, 0041 that the control plane network configuration is missing or incorrect, and 0042 the same for the worker plane. [ai-security.asset-management.system-logs:codes-onboarding-network] Onboarding error groups exist for Copilot Studio (including ZS-ONBOARDING-0133, missing MIP label permission), GitHub, GitLab and Azure DevOps repository integrations. [ai-security.asset-management.system-logs:codes-onboarding-integrations]
