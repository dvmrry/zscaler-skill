# AI Guard tenant settings: prompt storage, encryption keys, ZIA sync, block messages, organization restrictions, Anthropic webhook (ai-security.ai-guard.tenant-settings)
Also called: ai guard tenant settings; store prompts responses; ai guard 90 days; ai guard prompt retention; ai guard customer managed key; ai guard kms; ai guard zia user sync; ai guard start sync; custom block message ai guard; delete conversation on response block; organization restrictions; tenancy restriction anthropic openai; enterprise personal account type; anthropic inference hooks; ai guard webhook

Tenant Settings holds AI Guard's tenant-wide behavior. Each section below is one part of that page.

**The tenant.** Tenant Settings shows the tenant name, the mode (Proxy or DaaS), the tenant UUID, and Zscaler's AWS account ID, which is used for optional AWS integrations such as log exports to S3 and customer-managed encryption keys. [ai-security.ai-guard.tenant-settings:basic-info]

**Prompt storage and feedback.** Store Prompts/Responses keeps a history of all prompts and responses for the last 90 days for auditing. [ai-security.ai-guard.tenant-settings:store-prompts] Prompt and response history is kept only when Store Prompts/Responses is enabled; with it off, prompt text should not be expected in AI Guard's history. [ai-security.ai-guard.tenant-settings:history-opt-in] Event detection feedback, when enabled, may be used for local model training and is stored encrypted. [ai-security.ai-guard.tenant-settings:detection-feedback] ZIA's own prompt capture is a separate setting on a different product: [The Capture Prompts option categorizes and stores end-user prompts, up to 2 KB each, for generative AI applications. Prompts are stored in Zscaler logs for the period the organization defines, and authorized users with log access can view them. The option appears only when the selected Gen AI applications support prompt configuration, and the page points administrators to Configuring Advanced Policy Settings.](kb:zia.cloud-app-control.ai-ml-rules:capture-prompts).

**Encryption.** Custom header encryption encrypts the contents of sensitive custom headers and content encryption uses customer-managed keys; enabling either requires a customer-managed key, given as a key ARN, and AWS is currently the only supported KMS provider type. [ai-security.ai-guard.tenant-settings:encryption] Reset reverts changes to the customer key ID and disables both content and custom-header encryption. [ai-security.ai-guard.tenant-settings:reset-disables]

**Users, groups and domains from ZIA.** Policies by user or user group need ZIA synchronization of users, groups and domains, with the ZIA tenant already linked to AI Guard; sync is enabled by toggles under ZIA Information, Start Sync under Advanced Actions syncs immediately outside the scheduled batch window, and synced users and groups appear on the AI Users page. [ai-security.ai-guard.tenant-settings:zia-sync]

**Block messages.** Custom prompt and response block messages are shown in place of a blocked prompt or response, for example to link users to the AI usage policy, and Delete Conversation on Response Block automatically deletes the chat history for response blocks. [ai-security.ai-guard.tenant-settings:block-messages] AI Guard delivers a custom block message by sending it to the LLM with a request to return it to the user; some LLMs may treat that instruction as malicious and refuse or answer unexpectedly. [ai-security.ai-guard.tenant-settings:block-message-llm-caveat]

**Organization restrictions.** Organization Restrictions, currently for Anthropic and OpenAI, tag requests matching a registered Anthropic org ID or OpenAI workspace ID as Enterprise and the rest as Personal; with a provider's toggle on, AI Guard permits the listed organizations and denies all others; with it off, all traffic passes and the list only marks Enterprise accounts; changes can take up to five minutes. [ai-security.ai-guard.tenant-settings:org-restrictions] With Organization Restrictions enabled, policy controls can match on Account Type (Personal, Enterprise or Both), so personal accounts can get different policies from sanctioned workspaces. [ai-security.ai-guard.tenant-settings:org-restrictions-account-type]

**Anthropic webhook.** AI Guard can evaluate prompts through Anthropic Claude's inference hooks and answer allow or deny: in Claude the hook endpoint is `https://api.zseclipse.net/v1/webhook/execute` with Enforce verdicts on and a 1000 ms prompt verdict timeout, and Claude's signing secret is added in AI Guard with the organization's Anthropic UUID; a policy and policy control must then target the webhook traffic. [ai-security.ai-guard.tenant-settings:anthropic-webhook]

**Settings on the AI Guard for Apps page.** The AI Guard for Apps Tenant Settings page has a Network Access Control Policy that takes up to 10 IPv4 CIDR ranges. [ai-security.ai-guard.tenant-settings:network-access-control] The AI Guard for Apps Tenant Settings page allows a maximum of 5 custom request headers, each name at most 64 characters from a-z A-Z 0-9 !#$%&'*+-.^_`|~, case insensitive and unique; a conversation ID header is optional and is used to track related requests, and headers can be marked sensitive for extra protection, except one selected as the Conversation ID Header until it is removed from that role. [ai-security.ai-guard.tenant-settings:custom-headers] On the AI Guard for Apps Tenant Settings page, the Integrations tab has a Red Teaming section with an Enable Red Teaming Integration toggle, used to enable AI Red Teaming after integrating it with AI Guard. [ai-security.ai-guard.tenant-settings:red-teaming-toggle] What the Network Access Control Policy restricts is open [gap:ai-security.ai-guard.tenant-settings:access-and-headers].

What to check:
1. Whether Store Prompts/Responses is on before expecting prompt text in history; it keeps 90 days.
2. For user or group policies, that ZIA user, group and domain sync is enabled and has run (Start Sync forces it).
3. With Organization Restrictions on, that the organization or workspace ID is listed, since unlisted organizations are denied; changes take up to five minutes.
