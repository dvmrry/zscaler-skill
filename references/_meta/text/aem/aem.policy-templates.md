# AEM Tool Coverage, CMDB Hygiene and OS End of Life policies, and updating CMDB asset records (aem.policy-templates)
Also called: tool coverage policy; cmdb hygiene policy; os end of life policy; update cmdb; endoflife.date

**Tool Coverage.** For the Tool Coverage policy the Asset Population is the group of assets required to have a tool installed; an EDR example narrows it to Workstations and Servers (excluding Cloud assets) seen in the last 14 days. [aem.policy-templates:tool-coverage-population] A Tool Coverage policy treats an asset as noncompliant if it is not covered by a critical tool; the template takes the source that should have covered the asset within a number of days (e.g. last 14 days) and a field that indicates lack of coverage (e.g. the Asset Has EDR field returning FALSE). [aem.policy-templates:tool-coverage-scenario] For policy scenarios the Tool Coverage template does not support, the Advanced policy scenario setup defines custom conditions. [aem.policy-templates:advanced-scenario]

**CMDB Hygiene.** The CMDB Hygiene policy tracks assets in a CMDB (for example ServiceNow CMDB) and alerts on missing or conflicting asset information; its asset population typically includes assets currently documented in the CMDB. [aem.policy-templates:cmdb-hygiene-purpose] CMDB Hygiene flags an asset as noncompliant in two common cases, a missing value or conflicting values in critical fields (e.g. Asset Owner ID); each scenario is configured as a separate policy because each may need its own scoring settings, violation titles and descriptions. [aem.policy-templates:cmdb-hygiene-scenarios] In the Conflicting Values scenario, values that don't indicate a conflict (for example Unknown from one source when another source holds a valid owner name) can be excluded from consideration. [aem.policy-templates:cmdb-conflicting-exclude]

**Updating CMDB records.** The page on updating asset records in the CMDB says "this feature" is currently supported only for ServiceNow CMDB, after it describes CMDB Hygiene policy rules; the CMDB Hygiene policy page gives ServiceNow CMDB as an example (e.g.). [aem.policy-templates:cmdb-servicenow-only] The CMDB update page says detected CMDB Hygiene policy violations are grouped into violation tickets based on the policy name and policy assignee, which is the basis of the default grouping rule set; an account can hold several rule sets but only one is active at a time. [aem.policy-templates:cmdb-ticket-grouping] Updating CMDB asset records requires connecting the relevant data source (e.g. ServiceNow Assets) and configuring the CMDB outegration to dispatch assets from AEM to the CMDB. [aem.policy-templates:cmdb-update-prereq] Update CMDB updates all assets associated with the selected ticket, creating a new CMDB record for an asset that does not exist and updating the record with new or modified field values for one that does; the update time can vary, especially for bulk updates. [aem.policy-templates:cmdb-update-behaviour]

**OS End of Life.** The OS End of Life policy uses lifecycle data from the Endoflife.date database; for unsupported operating systems the page says to contact the Zscaler Account team. [aem.policy-templates:os-eol-source] For an OS End of Life policy the asset population can be narrowed to recently active assets running a supported OS, e.g. last seen within the last 7 days with Asset Operating System set to Is Not Empty. [aem.policy-templates:os-eol-population] An OS End of Life policy selects a lifecycle date (End of Life, End of Support or Extended Support) and a condition, Has passed or Is within the next <timeframe>; each option targets a specific lifecycle stage and needs a separate policy. [aem.policy-templates:os-eol-dates-conditions] The supported operating system list is open [gap:aem.policy-templates:supported-os-list]. The OS End of Life dashboard is in [The OS End of Life dashboard is created from a template at Explore > Dashboards > Template Gallery > OS End of Life, with summary tiles, charts and tables on EOL and EOS status.](kb:aem.dashboards:os-eol-access).
