# AEM violation ticket lifecycle: status buckets, statuses and ticket workflows (aem.ticket-lifecycle)
Also called: violation ticket lifecycle; violation ticket workflows; status bucket; lock violation ticket scope triggers; auto-dispatch to external systems; resurface policy violation

The Violation Ticket Lifecycle page lets an organization define status transitions, workflows that open new tickets or aggregate into existing ones, conditions for automatic dispatch to third-party vendors, and rules that automatically lock a ticket. [aem.ticket-lifecycle:lifecycle-page]

**Statuses.** A status bucket is a high-level container grouping violation tickets with similar statuses; buckets can carry Closed or Remediated labels, which provide insights for metrics and calculations and allow viewing all closed violation tickets. [aem.ticket-lifecycle:status-bucket] A status timeline at the top of each violation ticket shows its current status, and the status can be changed manually from a drop-down menu. [aem.ticket-lifecycle:status-timeline] Only the most recently added status bucket or violation ticket status can be deleted, and a violation ticket status can be edited only when no violation ticket currently uses it. [aem.ticket-lifecycle:status-edit-limits] The default bucket and rule configuration is open [gap:aem.ticket-lifecycle:default-configuration].

**Workflows.** The Violation Ticket Workflows page has three rule-set categories: Violation Ticket Status Management (update status), Lock Violation Ticket Scope Triggers (lock a ticket) and Auto-Dispatch to External Systems (create third-party work items and alerts). [aem.ticket-lifecycle:workflow-categories] A Status Management rule has a category: Automatic Violation Ticket Closure, Resurface Policy Violation - Create New Violation Ticket, Resurface Policy Violation - Reopen Violation Ticket, or Custom Status Transition. [aem.ticket-lifecycle:status-rule-categories] The Resurface Policy Violation - Create New Violation Ticket rule triggers even if only one policy violation is active for the specified number of days, and creates a new violation ticket with the resurfaced policy violation (the default THEN). [aem.ticket-lifecycle:resurface-new-ticket] Status Management rule conditions can be limited to violation tickets linked to a third-party tool such as Jira by selecting the checkbox 'A third-party work management item is attached', and AND/OR can add criteria. [aem.ticket-lifecycle:third-party-condition] A Lock Violation Ticket Scope Triggers rule has the condition 'Violation Ticket is manually split or merged' selected by default, and its THEN locks the violation ticket (shown by default). [aem.ticket-lifecycle:lock-scope] Auto-Dispatch to External Systems rules can condition on violation ticket status, severity and assignee, and create a third-party item on a chosen value, with Create New Outegration to configure an outegration for it. [aem.ticket-lifecycle:auto-dispatch]

**Applying rule sets.** For Violation Ticket Status Management, Lock Violation Ticket Scope Triggers and Auto-Dispatch to External Systems rule sets alike, Save makes the rules take effect when new data is ingested into the account and Save & Run applies them immediately to the tickets. [aem.ticket-lifecycle:save-run] The tickets these workflows act on are in [AEM violation tickets: the Violation Tickets page, drawer, split and merge, comments and activity log](kb:aem.violation-tickets).
