# Network Connector platforms, sizing, prerequisites, firewall and install (VPN for Legacy Apps) (zpa.vpn.network-connectors.deployment)

The software-by-platform page says Network Connectors are supported on Linux operating systems. It lists a VMware OVA, and Private Access marketplace entries for AWS, GCP and Microsoft Azure. It says an RPM package is supported for RHEL 9-based Network Connector deployments. [zpa.vpn.network-connectors.deployment:platforms] The prerequisites article says Zscaler recommends, for each Network Connector, 4 GB RAM and 2 CPU cores (Xeon E5 class) for physical machines without hyperthreading. For virtual machines with hyperthreading it recommends 8 cores (Xeon E5 class), with a minimum of 4. It recommends a minimum CPU benchmark score of 2640 with the Intel AES-NI instruction set enabled, 64 GB thin-provisioned disk for all deployment platforms, and a minimum of 1 NIC. With these specifications each Network Connector supports up to 500 Mbps of throughput. [zpa.vpn.network-connectors.deployment:sizing] The recommended memory and the minimum AWS instance size on the same page do not obviously agree [gap:zpa.vpn.network-connectors.deployment:memory-sizing]. For VMware platform deployment, the prerequisites article says the default configuration that lets the host allocate VM resources dynamically is not recommended. The VM setting should reserve 8 GB RAM and a total CPU GHz equal to the number of cores (2 or 8) multiplied by the GHz per core. [zpa.vpn.network-connectors.deployment:vmware-reservation] The prerequisites article says the minimum instance size can support an AWS instance size of 8 vCPU, 32 GiB memory, EBS-only instance storage and up to 10 Gbps network bandwidth. [zpa.vpn.network-connectors.deployment:aws-minimum-instance]

**Prerequisites.** The prerequisites list an Intel x86_64/AMD64-based architecture, systemd, root or sudo access to configure a new package repository and install packages, DNS resolution and network access, a static MAC address, and either an OAuth 2.0 enrollment token or a Network Connector provisioning key. The gateway IP address is available in the Admin Console after a gateway instance is instantiated in VPN Service Edges. [zpa.vpn.network-connectors.deployment:platform-prereqs] After a Network Connector is enrolled, an outbound TLS tunnel over port 443 is established to the Private Access cloud, and outbound VPN tunnels to the VPN Service Edge use the port range 51820 to 53000; software upgrades are completed on a weekly schedule. The prerequisites require TCP 443 to all Public Service Edges and an outbound connection to the VPN Service Edge's IP address on UDP 51820 to 53000 that is not blocked. [zpa.vpn.network-connectors.deployment:tunnels-and-ports] Zscaler recommends treating access to Network Connectors as privileged so only authorized personnel can reach a connector's console, and patching the OS regularly or protecting Network Connectors with firewall policies. [zpa.vpn.network-connectors.deployment:security]

**Firewall.** All Zscaler data centers containing Public Service Edges must be allowed, because a partial firewall configuration can cause connectivity problems for end users, and Zscaler's policy is a 90-day notice for activating additional IP CIDR ranges. Because the service enforces TLS certificate pinning, all inline or man-in-the-middle TLS interception must be disabled, Network Connectors do not function if the certificates the Service Edges present do not verify against Zscaler-trusted public keys, and *.prod.zpath.net should be in the SSL bypass list for traffic from the Network Connector. [zpa.vpn.network-connectors.deployment:firewall]

**Install.** The Linux guide's RPM install configures a repository at https://yum.private.zscaler.com/yum/el9 with gpgcheck=1, installs the np-connector package with yum, and has the reader check that the GPG fingerprint matches a6fe 2422 fce7 e8ac 672e 9e51 644e a315 8765 e1dd. It says a proxy environment needs the proxy server IP address and port configured in /etc/yum.conf, and its steps include setting net.ipv4.ip_forward = 1 and adding the npwg0 interface to the public firewalld zone. [zpa.vpn.network-connectors.deployment:rpm-install] The VMware guide says the Network Connector must be configured with a static private IP address and cannot be configured with a dynamic one. The Linux guide's networking section lists DHCP IP addressing for the App Connector, Private Service Edge or Private Cloud Controller, and static IP addressing for all software components. [zpa.vpn.network-connectors.deployment:static-ip] The Linux guide says RHEL 9 deployments are only supported on ESXi 7.0 Update 2 or later. [zpa.vpn.network-connectors.deployment:esxi-version] The Linux guide's step headings and intro sentence lose the component name in the capture [gap:zpa.vpn.network-connectors.deployment:component-names-missing].

**VMware.** For VMware vCenter, the VMware guide requires vCenter version ESXi 7.0 Update 2 or later. The OVA is deployed with Thin Provision as the virtual disk format and with Power on after deployment not selected. Before powering on, the vApp Options set OVF environment transport to the VMware Tools checkbox and Installation boot to Enable, and the guide says to verify the VMware machine's local time and update it with Network Time Protocol if wrong. [zpa.vpn.network-connectors.deployment:vmware-vcenter] For VMware vSphere Hypervisor (ESXi), the VMware guide says the standalone vSphere Hypervisor edition is not able to parse the extended OVF attributes that allow the provisioning key to be provided during deployment. [zpa.vpn.network-connectors.deployment:vmware-standalone]

**AWS.** The AWS guide says Network Connectors must be deployed in the customer's Virtual Private Clouds, with a pair per VPC for resilience and scalability, deployed across availability zones, and that Zscaler automatically load balances across them. Their security group should accept incoming connections from Client Connector and the VPN Service Edge, permit inbound and outbound access on port 443, and allow inbound SSH. Choosing Disable for Auto-assign Public IP, which assigns a private IP address, is recommended. [zpa.vpn.network-connectors.deployment:aws-placement] The AWS guide has the reader update the Network Connector's security group to temporarily allow inbound access on port 22, and then disable inbound access on port 22 for that security group. [zpa.vpn.network-connectors.deployment:aws-ssh] The AWS guide's auto scaling example selects 2 subnets, a desired capacity of 2, and a metric of Average CPU Utilization with a target value of 50. It says each Network Connector is capable of passing 400 to 500 Mbps, and that this limit is reached at about 50% CPU utilization. [zpa.vpn.network-connectors.deployment:aws-autoscaling]

**Other platforms.** GCP and Azure marketplace images are listed, but the area has no deployment guide for either [gap:zpa.vpn.network-connectors.deployment:gcp-azure-guides].

What to check:
1. Before quoting a Network Connector memory requirement, give the 4 GB recommendation, the 8 GB VMware reservation and the 32 GiB AWS minimum instance together, and note the page does not reconcile them.
2. Before advising on the firewall in front of a Network Connector, check TLS interception is off and *.prod.zpath.net is in the SSL bypass list.
