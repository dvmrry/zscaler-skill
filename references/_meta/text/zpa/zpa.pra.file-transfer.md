# PRA file transfer: in-console transfer, the PRA File Transfer System and the Sandbox integration (zpa.pra.file-transfer)
Also called: pra file transfer; pra file transfer system; my files uninspected files; pra upload failed; pra sandbox integration; pra rdp drive redirection; pra file transfer limits; pra file status malicious

PRA moves files in two ways: directly to and from a console, or through the PRA File Transfer System in the PRA Portal. With the PRA File Transfer System, users upload files from their system to the PRA cloud through the PRA Portal, manage them there and then transfer them to a privileged console. Without the PRA File Transfer System, users upload and download files directly to and from a privileged console. [zpa.pra.file-transfer:fts-model] In-console file transfers, both uploads and downloads, take place in a Zscaler-generated drive on the privileged console. The Upload and Download options are disabled by default but File Transfer can still be opened to view the files, and when they are enabled files can be uploaded and downloaded from the File Transfer window even if the screen is locked. [zpa.pra.file-transfer:in-console-drive]

**Inspection.** Files moved through a privileged console can be downloaded or uploaded with the option to inspect them using Internet & SaaS (ZIA) Sandbox File Transfer. To enable the Inspect option for the File Transfer feature the Internet & SaaS Sandbox integration must be set up first, otherwise the Inspect option is automatically disabled, and the consoles policy is set up after the integration. [zpa.pra.file-transfer:sandbox-inspection] The Sandbox Integration page takes the ZIA Cloud name, a Cloud Service API Key, a ZIA admin username and password, and a Sandbox API Token. All fields must be completed before the admin can move forward, and the page is read-only for Microtenant admins. [zpa.pra.file-transfer:sandbox-integration-fields] If Inspect is enabled, files are inspected before they are uploaded and the step is bypassed otherwise; if there is an issue with the inspection, the upload is paused and the user is notified that the inspection was not completed. [zpa.pra.file-transfer:inspection-flow] The consoles policy side is [The Inspect option for file uploads can be selected only if the Internet & SaaS (ZIA) integration was successful, and inspected files are checked inline with the upload. If the inspection detects malware the upload halts and the files are not uploaded.](kb:zpa.pra.consoles-policy:inspect-needs-zia). What the ZIA admin account and integration require is open [gap:zpa.pra.file-transfer:sandbox-account-requirements].

**Console transfer.** For a Windows-based privileged console using RDP, a remote drive is automatically mounted and handles all transferred files. If the target Windows system has Device and Resource redirection disabled in the local group policy editor, File Transfer is not possible because the drive is not mounted, and Windows version 7 or later is required. [zpa.pra.file-transfer:rdp-drive] An upload from a local machine to a non-writable directory fails. After such a failure, moving from the non-writable directory to a writable one with the File Transfer window open and selecting files makes the upload fail the first time too, and additional attempts to a writable directory should succeed. [zpa.pra.file-transfer:writable-directory]

**The File Transfer System.** For the PRA File Transfer System the admin must also configure a portals policy to enable deleting a file, accessing uninspected files and uploading an inspected file (via DI scan or Sandbox). The files shown on the Uninspected Files page depend on the user's permissions, and analytics for uploaded inspected files are on the Files page (Data Explorer > Privileged Remote Access > Files). [zpa.pra.file-transfer:fts-portals-policy] My Files shows the storage used and the storage limit; up to 10 GB can be stored in My Files, and a file can be up to 1 GB. [zpa.pra.file-transfer:fts-storage-limits] The About page says up to 10 files can be uploaded for each privileged portal. [zpa.pra.file-transfer:fts-files-per-portal] The Uploading page says that when selecting a file to upload, and when selecting the directory to transfer files to, up to 10 files can be uploaded at one time. [zpa.pra.file-transfer:fts-files-at-once] What the per-portal cap counts is open [gap:zpa.pra.file-transfer:fts-file-count-meaning]. Whether the storage limit is per user, portal or tenant, and how long files are kept, is open [gap:zpa.pra.file-transfer:fts-storage-scope].

**My Files.** The My Files page says only these characters can be used when naming a file: & $ , _ - ! @ ( ) [ ]= ' ~ ; and the characters & and + cannot be used in its filter search field. [zpa.pra.file-transfer:fts-file-names] A My Files entry's Status, for the ZIA Integration inspection process, is Uploading, Pending (pending inspection), Uninspected (not inspected, and added to the Uninspected Files page), Success (inspected with no malicious content or malware found), Error (an error during the upload) or Malicious (found malicious during inspection). [zpa.pra.file-transfer:fts-status] Among its columns My Files shows the Detected File Type, the file type detected during inspection, and the Uninspected Files page shows the email of the user who uploaded each file; uninspected files can be downloaded from that page. [zpa.pra.file-transfer:fts-columns] A file cannot be deleted while it is being uploaded or if it contains malicious content, malicious files cannot be transferred, and a cancelled upload does not appear on the My Files page. [zpa.pra.file-transfer:fts-delete-and-transfer]

The Files analytics page is described in [The PRA Files page shows data for files uploaded to My Files in the PRA File Transfer System. Files uploaded through a default PRA Portal can be viewed only in the Global tenant, and files uploaded through a Microtenant PRA Portal only on that Microtenant's Files page. It covers 1 Hour to 14 Days and counts Malicious, Success (successfully inspected) and Uninspected files.](kb:zpa.pra.components:files-page); the permissions that turn each action on are in [PRA consoles policy: file transfer, clipboard, recording and sharing](kb:zpa.pra.consoles-policy) and [PRA portals policy: file, inspection and approval permissions in the PRA Portal](kb:zpa.pra.portals-policy).

What to check:
1. Whether a failed in-console transfer is a non-writable directory or, for an RDP target, redirection disabled in group policy.
2. Whether Inspect is unavailable because the Sandbox integration was not set up first.
3. Whether a blocked upload hit the 10-files-at-one-time limit, the 10-files-per-portal cap, or the storage limit.
4. Whether a file cannot be deleted or transferred because it is uploading or malicious.
