# ZPA event notifications: the catalog, thresholds, throttling and recipients (zpa.troubleshooting.events)
Also called: zpa events diagnostics; zpa event notification; zpa alerts email

Admins subscribe to events to receive email notifications, and the Events Diagnostics page displays these notifications. [zpa.troubleshooting.events:what-it-is] Events Diagnostics shows the last 24 hours by default with no filters applied, and counts events in total and by High, Medium and Low priority. [zpa.troubleshooting.events:range-and-priority]

**The catalog.** The Event Category filter lists Authentication, Backup Configuration, Connectivity and Upgrade, Enrollment, System Resource and Usage Metrics, and the Event Component filter lists App Connectors, Backup and Restore, Cloud Connectors, Private Service Edges and Zscaler Client Connector. [zpa.troubleshooting.events:categories-components] The component filter list leaves out components the event table uses [divergence:zpa.troubleshooting.events:component-list-vs-table], and the Authentication category has no event in the table [gap:zpa.troubleshooting.events:authentication-category-empty].

**Usage Metrics events.** Usage Metrics events take an integer threshold: Application Exceeded Count Limit 4,500 to 6,000 (default 4,500, App Connectors); Bandwidth Utilization Exceeded Limit at least 250 Mbps (default 250); CPU Exceeded Limit, System Memory Exceeded Limit, File Descriptors Exhausted and Source Port Consumption 75% to 99% (default 75); Disk Space Exceeded Limit 0 to 2,048 MB (default 2,048), for the component's available disk space below the threshold. The Events Diagnostics table lists all but the application count for App Connectors, Network Connectors, Private Cloud Controllers and Private Service Edges. [zpa.troubleshooting.events:usage-thresholds] The window over which a threshold is evaluated is open [gap:zpa.troubleshooting.events:threshold-window]. The Network Connector is described in [Network Connectors and Network Connector groups (VPN for Legacy Apps)](kb:zpa.vpn.network-connectors).

**Events that cannot be configured.** The event for the control connection of App Connectors or Private Service Edges disconnecting cannot be configured and is disabled by default; so is the event for an App Connector's CPU missing resources needed for operations. A further event, whose raw logs include the component name, when it was updated and who updated it, cannot be configured either. [zpa.troubleshooting.events:not-configurable]

**Enrollment, connectivity and other events.** The event table lists these events in the Enrollment category: Certificate Signing Request Invalid, Enrollment Certificate Expired and Provisioning Key Utilization Exceeded Limit (each for App Connectors, Private Service Edges and Cloud Connectors), and Certificate Signing Request Not Found, Certificate Signing Request Not Found for Issued Certificate, Duplicate Certificate Signing Request, Enrollment Certificate Invalid, Enrollment Completed, Enrollment Failed, Entity Limit Exceeded, Invalid Fingerprint, Invalid Signature, Issued Certificate Missing, Issued Certificate Revoked, Missing Signature, Provisioning Key Disabled, Provisioning Key Expired, Provisioning Key Mismatched, Provisioning Key Not Found, Public Key in Certificate Signing Request and Issued Certificate Mismatched and Timestamp Expired. The Timestamp Expired description gives as an example an App Connector sending an old timestamp due to a Network Time Protocol error. [zpa.troubleshooting.events:enrollment-events] The Connectivity and Upgrade events listed for App Connectors and Private Service Edges include Control Connection Disconnected, Last Component Disconnected, Upgrade Complete, Outdated Component Manager Version and Upgrade Failed. [zpa.troubleshooting.events:connectivity-events] The table also lists Backup Completed, Backup Failed, Restore Completed and Restore Failed (Backup Configuration, Backup and Restore), SCIM Users Successfully Deleted (Enrollment, Zscaler Client Connector) and Invalid System Listen IP Configuration (System Resource, Private Service Edges), and describes an event for a duplicate serial number during Zscaler Client Connector enrollment. [zpa.troubleshooting.events:other-events]

**Notifications.** A notification's status is Enabled by default, and all categories and all priorities are selected by default; for the App Connectors component all App Connectors are selected by default (the page's quotes give no default for other component types). The Zscaler Client Connector component has no drop-down menu. [zpa.troubleshooting.events:notification-defaults] Throttling is Disabled by default; when Enabled, the Throttling Limit and Throttling Timeout fields appear, and the timeout is an integer in hours. The page's example is a Throttling Limit of 3 with a Throttling Timeout of 1 hour. [zpa.troubleshooting.events:throttling] A notification allows at most 5 recipients, counting Recipients and Distribution Lists together. [zpa.troubleshooting.events:recipients] Whether an event fires once or repeatedly while its condition persists is open [gap:zpa.troubleshooting.events:repeat-firing], as is how this catalog relates to the Event Monitoring API [gap:zpa.troubleshooting.events:event-api-relation].

**The Notifications page.** Notifications carry information about events related to components, event information (the page's example is high CPU) and the relevant values; on the Notifications page (Administration > Alerts > Private Access) each notification shows its recipients, distribution lists, component, categories, priorities (Low, Medium or High), whether limits and timeouts are enforced (Throttling), software components and events, and the Categories field shows All when every available category is selected. [zpa.troubleshooting.events:notifications-page] Notifications managed by Zscaler are read only; the Configuring Notifications page says they cannot be configured, edited or deleted, and About Notifications says they cannot be edited or deleted. [zpa.troubleshooting.events:zscaler-managed-read-only] The recipient limit is stated only on the Events Diagnostics page [gap:zpa.troubleshooting.events:recipient-limit-pages].

**Configuring a notification.** The Component drop-down of the Configuring Notifications page offers App Connectors, Backup and Restore, Cloud Connectors, Federation, Network Connectors, Private Cloud Controller, Private Service Edges, VPN (for Legacy Apps) and Zscaler Client Connector. Within a Microtenant, notifications can be created only for App Connectors, Private Service Edges for Private Access (ZPA) or Private Cloud Controllers. [zpa.troubleshooting.events:notification-components] After a component is selected on the Configuring Notifications page, drop-down menus for Categories, Priorities and selection of the components appear; a drop-down menu for component selection is not available for Backup and Restore, Federation and Zscaler Client Connector. [zpa.troubleshooting.events:component-selection-menu] Besides the categories already listed, the Configuring Notifications page offers Federated Application Configuration (federated application configurations), Federated Policy Configuration (access policies for federated application configurations), Partner Federation Configuration (partner federation configurations) and VPN (for Legacy Apps), for Border Gateway Protocol (BGP) network routes and peers. [zpa.troubleshooting.events:federation-and-vpn-categories] For events that require text input, the Configuring Notifications page says to enter an integer value within the supported range. [zpa.troubleshooting.events:threshold-input] The Throttling Limit is an integer. In the Configuring Notifications page's example (Throttling Limit 3, Throttling Timeout 1 hour, a notification set to trigger when the App Connector CPU is greater than 80%), the recipients receive only three email notifications within the last hour if the App Connector CPU exceeds the 80% threshold. [zpa.troubleshooting.events:throttling-example] A distribution list is entered in the format example@test.com. The sender email domain might be no-reply@private.zscaler.com or no-reply@zpatwo.net, depending on the organization's assigned cloud. [zpa.troubleshooting.events:distribution-list-and-sender]

**Components per event on the Configuring Notifications page.** The About Notifications page describes a notification's Component as the component associated with the notification, giving as examples App Connectors, Backup and Restore, and Cloud Connectors. [zpa.troubleshooting.events:about-notifications-components] On the Configuring Notifications page the CPU Exceeded Limit, Disk Space Exceeded Limit, File Descriptors Exhausted, Source Port Consumption Exhausted and System Memory Exceeded Limit rows list VPN Service Edges after Private Service Edges; the Bandwidth Utilization Exceeded Limit row lists App Connectors, Network Connectors, Private Cloud Controllers and Private Service Edges. [zpa.troubleshooting.events:configuring-usage-components] On the Configuring Notifications page the Control Connection Disconnected, Last Component Disconnected, Outdated Component Manager Version, Upgrade Complete and Upgrade Failed rows list App Connectors, Network Connectors, Private Cloud Controllers and Private Service Edges. [zpa.troubleshooting.events:configuring-connectivity-components] On the Configuring Notifications page the Enrollment Certificate Expired and Enrollment Failed rows list App Connectors, Network Connectors and Private Service Edges, and the Enrollment Completed and Provisioning Key Utilization Exceeded Limit rows list App Connectors, Network Connectors, Private Cloud Controllers, Private Service Edges and Cloud Connectors. [zpa.troubleshooting.events:configuring-enrollment-components] The two pages give different component sets for one event [divergence:zpa.troubleshooting.events:enrollment-cert-expired-components]. The Configuring Notifications page lists CPU Starvation (System Resource) as an event for App Connectors, Private Cloud Controllers and Private Service Edges, describing it as an event indicating when the component's CPU is missing resources needed for operations. [zpa.troubleshooting.events:configuring-cpu-starvation] The pages differ on whether CPU Starvation can be configured [divergence:zpa.troubleshooting.events:cpu-starvation-configurable]. The Configuring Notifications page lists Invalid System Listen IP Configuration (System Resource) for Private Cloud Controllers and Private Service Edges, describing an invalid listen IP address configuration for a Private Service Edge or Private Cloud Controller. [zpa.troubleshooting.events:configuring-listen-ip-event] The pages give different components for that event [divergence:zpa.troubleshooting.events:listen-ip-components]. In the captured pages, the Configuring Notifications event table omits events that Events Diagnostics lists [gap:zpa.troubleshooting.events:events-absent-from-configuring], and the label of the Usage Metrics component is not mapped to the drop-down's [gap:zpa.troubleshooting.events:vpn-service-edges-label].

**VPN (for Legacy Apps) and Federation events.** The Configuring Notifications event table lists these Connectivity and Upgrade events for the VPN (for Legacy Apps) component: BGP Established Peers Count Dropped (BGP peers that dropped from the Established state), BGP Network Routes Peers Count Dropped (network sessions with BGP peers that dropped or had routes withdrawn), BGP Peer Disconnected (the session between BGP peers ended), BGP Peer Extended Downtime (a BGP session down for an extended period of time) and BGP Peer Flapping (a BGP peer session that repeatedly goes down and comes back up). [zpa.troubleshooting.events:bgp-events] The period for an extended downtime is open [gap:zpa.troubleshooting.events:bgp-extended-downtime]. The Configuring Notifications event table lists these events for the Federation component: Federated Access Policy Updated and Federated Application Updated (the configuration of the access policy for federated applications, or of the federated application, is created, updated or deleted) and Partner Federation Updated (the status of the partner federation is updated from Active, Pause or Terminate). [zpa.troubleshooting.events:federation-events]

Sources disagree (name both sides):
- The Event Component filter list versus the components the event table names [divergence:zpa.troubleshooting.events:component-list-vs-table]
  - zscaler-help: The Event Component filter lists App Connectors, Backup and Restore, Cloud Connectors, Private Service Edges and Zscaler Client Connector.
  - zscaler-help: The event table gives Network Connectors and Private Cloud Controllers as components of the Bandwidth Utilization Exceeded Limit event.
  Impact: The filter list does not name Network Connectors or Private Cloud Controllers, which the table gives as components of Usage Metrics events; check the console's actual filter values before relying on either list.
- The components listed for the Enrollment Certificate Expired event differ between Events Diagnostics and Configuring Notifications [divergence:zpa.troubleshooting.events:enrollment-cert-expired-components]
  - zscaler-help: Events Diagnostics lists App Connectors, Private Service Edges and Cloud Connectors for Enrollment Certificate Expired.
  - zscaler-help: Configuring Notifications lists App Connectors, Network Connectors and Private Service Edges for Enrollment Certificate Expired, without Cloud Connectors.
  Impact: Whether Cloud Connectors or Network Connectors can be selected for this event depends on which page is right; check the Add Notification page before relying on either list.
- Whether the CPU Starvation event can be configured, and for which components [divergence:zpa.troubleshooting.events:cpu-starvation-configurable]
  - zscaler-help: Events Diagnostics lists CPU Starvation for App Connectors only and says it cannot be configured and is disabled by default.
  - zscaler-help: Configuring Notifications lists CPU Starvation as an event for App Connectors, Private Cloud Controllers and Private Service Edges, with no note that it cannot be configured.
  Impact: Whether a CPU Starvation notification can be set up, and for which components, depends on which page is right.
- The components of the Invalid System Listen IP Configuration event [divergence:zpa.troubleshooting.events:listen-ip-components]
  - zscaler-help: Events Diagnostics lists Invalid System Listen IP Configuration for Private Service Edges only.
  - zscaler-help: Configuring Notifications lists it for Private Cloud Controllers and Private Service Edges.
  Impact: Whether the event applies to Private Cloud Controllers depends on which page is right.
