# Common ZPA access rule patterns and their ordering (zpa.policy.patterns)
Also called: allow any user any application zpa; block specific users zpa; allow group to segment group; block few users allow rest; block individual users within allowed group; zpa configuration examples

These rule layouts come from the help's configuration examples, and each depends on rule order.

**Allowing.** To let specific users reach specific applications, a rule combines a segment group created for those applications with a SAML attribute for the users. [zpa.policy.patterns:group-to-segment-group] The default block behind them is in [If no access policy rule matches, or no rule is defined at all, access to the application is implicitly set to Block Access.](kb:zpa.policy.evaluation-order:default-access-block), and the blank-field form is in [In the console, leaving the Application Segments, Segment Groups and SAML Attributes fields unselected makes the rule apply to any user from any IdP and any application segment and segment group.](kb:zpa.policy.conditions:blank-criteria-mean-any).

**Blocking.** A rule that denies users access is useful when the number of users blocked is relatively small compared to the number with access. [zpa.policy.patterns:block-useful-for-small-groups] To make applications available to most users but block a few, a rule blocking the specific users is followed by another rule allowing any other users. [zpa.policy.patterns:block-few-allow-rest] To allow a group but block individual users within it, one rule blocks the individuals on the selected application segments or segment groups and a second allows the group; the example selects the Firewall Apps Group in both rules. [zpa.policy.patterns:block-individual-in-allowed-group] Why the block rule must sit above is in [A block rule for specific users must be listed before an allow rule that also covers them, because policy rules are enforced in the order listed.](kb:zpa.policy.access-rule-order:block-before-allow).

What to check:
1. For a rule that blocks a few users, check that an allow rule for everyone else sits below it.
2. For a rule meant to block more than a few users, check whether the default block already covers them.
3. To find why a rule applies to everyone, check whether its application and SAML fields are blank.
