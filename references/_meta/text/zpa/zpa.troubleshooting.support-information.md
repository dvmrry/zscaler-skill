# ZPA Support Information sessions: remote commands on App Connectors, Private Service Edges and Private Cloud Controllers (zpa.troubleshooting.support-information)
Also called: support information; zpa remote commands; zpa pcap from connector; zpa journalctl; zpa support session

Support Information creates sessions that run commands on App Connectors and Private Service Edges, and filters and shows the outputs of those sessions for troubleshooting; the page also names Private Cloud Controllers as data sources. [zpa.troubleshooting.support-information:what-it-is] The Support Information page shows sessions of the last 14 days by default, with ranges from 1 hour to 14 days, and a Custom Range start date must be within the last 6 months. [zpa.troubleshooting.support-information:time-range] The VPN Service Edge and Network Connector counterpart is [VPN Support Information: diagnostic sessions and commands on VPN Service Edges and Network Connectors](kb:zpa.vpn.support-information).

**Sessions and targets.** Filters for App Connectors or App Connector groups, Private Service Edges or Private Service Edge groups, and Private Cloud Controllers or Private Cloud Controller groups cannot be applied at the same time. [zpa.troubleshooting.support-information:filter-exclusive] Sessions that are managed by Zscaler are read only and cannot be configured, edited or deleted. [zpa.troubleshooting.support-information:managed-read-only] Within a Microtenant, an admin can select only the App Connectors, App Connector groups, Private Service Edges, Private Service Edge groups, Private Cloud Controllers and Private Cloud Controller groups that belong to the admin or are configured within the Microtenant. [zpa.troubleshooting.support-information:microtenant-scope] Targets are hostnames or IP addresses separated by commas, with ports after a colon; several ports on one host repeat the host. Ports are not allowed for DNS lookup and restart commands. A session allows at most 10 targets, and a PCAP command at most one target per session. [zpa.troubleshooting.support-information:targets]

**Commands.** The commands listed include DNSLOOKUP A RECORD, DNSLOOKUP AAAA RECORD and DNSLOOKUP SRV RECORD, DROP DB RESTART PROCESS (deletes the local database in the Private Cloud Controller and restarts its process), RESTART PROCESS, RESTART SYSTEM, ICMP PING, TCP PING, PCAP, GET NETWORK INTERFACES (all interfaces or a specific target interface, for an App Connector, Private Service Edge or Private Cloud Controller) and JOURNALCTL. [zpa.troubleshooting.support-information:commands] Canceling a restart command in the Processing state is not supported, and restart commands cannot be run at the same time as a DNS lookup command or another restart command. [zpa.troubleshooting.support-information:restart-rules] A PCAP command runs for 30 seconds to 5 minutes (1 minute by default) and can be limited to a network interface. One PCAP command is allowed per session; a session's PCAP is at most 1 GB, in individual PCAP files of at most 100 MB, and an FQDN argument is at most 51 characters. [zpa.troubleshooting.support-information:pcap] PCAP lets admins troubleshoot connectivity between an App Connector, Private Service Edge or Private Cloud Controller and the Public Service Edge for Adaptive Access Engine, or between those components and applications. [zpa.troubleshooting.support-information:pcap-scope]

**JOURNALCTL.** JOURNALCTL returns service logs or full system logs, with a Max Log Lines field, shown only when a JOURNALCTL command is selected, that defaults to 1,000 with a maximum of 100,000, and a maximum date and time of 4 hours from the current date and time. It is not available on Docker-based App Connectors or Private Service Edges, which don't run systemd or journald; their logs are collected via Docker logs or the containers' JSON logs on the host. [zpa.troubleshooting.support-information:journalctl] JOURNALCTL logs are in general compressed into an LZ4-formatted file and uploaded to an AWS S3 bucket; when compression is skipped (a log file below 4 KB, or the service unavailable when the log is fetched) the file is uploaded uncompressed as downloaded_file.log. [zpa.troubleshooting.support-information:journalctl-output] The release-note entry for the command is in [The July 14, 2026 release summary lists support for the journalctl command for App Connectors, Private Service Edges, Private Cloud Controllers, and Network Connectors to collect service logs or full system logs for remote troubleshooting.](kb:zpa.troubleshooting.signals:journalctl-july14) and the one for Get Network Interfaces in [The July 13, 2026 release summary lists support for a Get Network Interfaces command that collects a list of the network interfaces an App Connector uses, to help with remote troubleshooting.](kb:zpa.app-connectors.deployment:get-network-interfaces-july13).

**Session status, retention and limits.** A session's status is Pending, Processing, Completed, Failed, Cancelled or Partially_completed. Sessions can only be canceled in the Pending or Processing state, and sessions in those states auto-refresh every 60 seconds. [zpa.troubleshooting.support-information:session-statuses] By default all sessions are deleted after 14 days regardless of status, and sessions in a Pending or Processing state are moved to a Cancelled state after 600 seconds (10 minutes), and continue to be moved every 10 minutes. [zpa.troubleshooting.support-information:retention-and-timeout] An App Connector or Private Service Edge in a disconnected state is always in a Failed state for a session; a session that contains some App Connectors or Private Service Edges in a disconnected state and some in a connected state is Partially_completed, and the final session status depends on the combined status of the entities. A paused App Connector or Private Service Edge rejects and does not process new incoming sessions until the paused state expires, and the commands can move to Failed. [zpa.troubleshooting.support-information:disconnected-and-paused] The pause reasons are in [A connector can be paused for certificate expiry, software upgrade, session process restart or session system restart; it logs 'entering PAUSE mode because of' with the reason, and a paused connector can reject remote session commands.](kb:zpa.app-connectors.health:pause-reasons). Session results download as a JSON file, and the Session Output window shows the status of the commands on the App Connector. [zpa.troubleshooting.support-information:session-output] The ranges and limitations page gives Support Information limits of 100 App Connectors, 100 Private Service Edges and 100 Private Cloud Controllers per session, 10 actions and 10 targets per session, and 5 concurrent sessions per customer, counted only for sessions in a Pending or Processing state. [zpa.troubleshooting.support-information:per-session-limits]
