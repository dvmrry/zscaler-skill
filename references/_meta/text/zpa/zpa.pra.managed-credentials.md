# PRA managed credentials: discovery, credential providers, the Managed, Discovered and Ignored lifecycle, and credential classes (zpa.pra.managed-credentials)
Also called: discovered credentials; ignored credentials; credential agent; credential class; credential provider; credential rotation; rotation policy; managed privileged credentials

Privileged credentials can be discovered from external identity sources (for example Active Directory or Entra ID) or created locally in the Zscaler Admin Console. Discovered credentials can be moved into a managed state, where Zscaler automatically rotates the passwords, and these managed credentials can be used in future sessions. [zpa.pra.managed-credentials:sources-and-managed-state]

**Discovery.** Discovering credentials from Active Directory or Entra ID requires a credential agent deployed within the customer infrastructure. [zpa.pra.managed-credentials:credential-agent-required] A credential provider is the external identity source (for example Active Directory or Entra ID) used to discover credentials after the credential agent is set up for a designated identity provider; when one is created, the credential agent application segment can be mapped to that source. [zpa.pra.managed-credentials:credential-provider] A credential provider takes a name (which cannot contain special characters other than periods, hyphens and underscores), an optional description, the Provider Agent Application (the credential agent application), an Identity Provider Type (for example Active Directory or Entra ID), and an Internal Identity Identifier, which is the value of the idp_name field of the identity provider agent's JSON file. [zpa.pra.managed-credentials:provider-fields] The Credential Providers page shows each provider's credential agent application and a Status of OK (the provider can provide discovered credentials), Error (there is an issue with the provider), Validating (validation in progress) or Pending (validation pending), plus the counts of Saved Queries, New Credentials (discovered), Managed Credentials and Ignored Credentials. [zpa.pra.managed-credentials:provider-status] Discovery filters narrow credential results and can be added from the Managed, Discovered or Ignored tab: a filter names a credential provider, a search query (Discovery) and a filter name. Sync Now discovers credentials using the existing discovery filters, the Sync icon discovers credentials in real time, and Last Synced and Scheduled Sync give the date, time and time zone of the last and next credential pull from the provider. [zpa.pra.managed-credentials:discovery-filters] The ZPA release summary lists a PRA credential agent under March 03, 2026 as a feature in limited availability, integrating with Active Directory and Microsoft Entra ID for credential discovery. With the agent deployed, credentials are discovered using LDAP queries from Active Directory or search queries from Microsoft Entra, rotation generates new passwords with defined security requirements, rotation policies set the schedules, and filters pull newly created credentials from Active Directory. [zpa.pra.managed-credentials:release-and-discovery-queries] How the agent is deployed and what discovery queries accept is open [gap:zpa.pra.managed-credentials:credential-agent-details] [gap:zpa.pra.managed-credentials:discovery-query-syntax]. What makes a provider report Error is open [gap:zpa.pra.managed-credentials:provider-error-causes].

**The three pages.** The Managed page lists both local and discovered privileged credentials. Status is the rotation status: Available (discovered credentials that can be used), Local (locally created credentials that can be used) or Rotation Failed (discovered credentials with a failed rotation). Class is the rotation schedule assigned to the credential, and Last Rotation and Next Rotation give the date, time and time zone of the last and next rotation. [zpa.pra.managed-credentials:managed-page] An admin can rotate a privileged credential in real time from the Managed page. [zpa.pra.managed-credentials:rotate-now] The Discovered page lists credentials discovered from external identity sources with their Credential Provider, Discovery Filter and the date, time and time zone of discovery. All or specific credentials can be selected to import or ignore; importing offers a Credential Class and a Credential Pool drop-down. [zpa.pra.managed-credentials:discovered-page] On the Discovered page the Delete icon moves a credential to the Ignored page, and on the Ignored page it moves a credential back to the Discovered page; neither action deletes the credential from the external identity sources. [zpa.pra.managed-credentials:ignore-does-not-delete] Credentials discovered through external identity sources that are not currently in use for privileged consoles can be moved from the Discovered or Managed pages to the Ignored page. Credentials on the Ignored page can be moved to the Managed page to use them for privileged consoles, and the Import icon imports an ignored credential. [zpa.pra.managed-credentials:ignored-lifecycle] On the Managed, Discovered and Ignored pages the Configured within Microtenant filter option is applied by default to show the privileged credentials configured within that Microtenant, the Global option filters the table to what is configured within the Default Microtenant, and the only available operator is Equals. [zpa.pra.managed-credentials:microtenant-filter]

**Credential classes.** A credential class is a rotation schedule that can be assigned to rotate the password for a managed credential, and its rotation policy determines when the rotation for a managed credential is triggered. [zpa.pra.managed-credentials:credential-class] A credential class has a name, an optional description and a rotation frequency (Rotation Policy) of Scheduled, After Each Use or Never. An Interval, an amount plus a type such as Hours, Days or Weeks, appears only when the Scheduled policy is selected. The Credential Classes page shows the number of managed credentials using each class as Members. [zpa.pra.managed-credentials:rotation-policies] The rotation choices are worded differently between the articles [divergence:zpa.pra.managed-credentials:rotation-choices]. The limits on an interval are open [gap:zpa.pra.managed-credentials:interval-limits], and so is whether a locally created credential can rotate [gap:zpa.pra.managed-credentials:local-credential-rotation].

Credential types, pools and the credentials policy are in [PRA credentials, credential pools and the credentials policy](kb:zpa.pra.credentials); the area hub is [Privileged Remote Access: what it is and where each question goes](kb:zpa.pra).

What to check:
1. Whether the rotation answer names the class's Rotation Policy and Interval, since the articles word the choices differently.
2. Whether a credential is Managed, Discovered or Ignored before reasoning about its rotation or use in a console.
3. Whether discovery depends on a credential agent and a credential provider mapped to it.

Sources disagree (name both sides):
- The Managed page words the credential class choices as 30-day rotation, after each use or never; the class pages make the schedule an interval in hours, days or weeks. [divergence:zpa.pra.managed-credentials:rotation-choices]
  - zscaler-help: The class choices are 30-day rotation, after each use, or never rotate.
  - zscaler-help: The Rotation Policy is Scheduled, After Each Use or Never.
  - zscaler-help: A Scheduled class takes an interval amount and type, for example Hours, Days or Weeks.
  Impact: The i.e. wording presents 30 days as the scheduled choice, while the class pages make the schedule an interval of any amount in hours, days or weeks. Do not state 30 days as the only schedule; keep each article attributed.
