# ZPA redirection policy rules: Private Service Edge selection methods and criteria (zpa.policy.redirection-rules)
Also called: redirection policy; private service edge selection method; prefer private service edge over public service edge; redirect default preferred always

Redirection policy rules set criteria for preferring Private Service Edges for Private Access over Public Service Edges for Private Access, based on country code, client type, and SAML and SCIM attributes; the method used to select the Private Service Edge groups to redirect to is Default, Preferred or Always. [zpa.policy.redirection-rules:redirection-purpose]

**Selection methods.** Default uses the current Private Access Service Edge selection algorithm, and Preferred redirects users to the selected Private Service Edge groups if available, with Public Service Edges as a fallback. [zpa.policy.redirection-rules:methods-default-preferred] Always redirects users to the selected Private Service Edge groups, if available, and prevents the use of Public Service Edges; if there are no active Private Service Edges in the selected groups, users are redirected to a Public Service Edge. [zpa.policy.redirection-rules:method-always] How available differs from active under Always is not stated [gap:zpa.policy.redirection-rules:always-available-vs-active]. If Preferred or Always is selected, one or more Private Service Edge groups are selected from the drop-down menu, and the Branch Connector and Cloud Connector client types cannot be used if the Private Service Edge Selection Method is Always. [zpa.policy.redirection-rules:group-selection-and-always-client-types]

**Criteria.** The redirection rule criteria cover client types, countries (multiple country codes are joined by OR), an external IAM IdP, SAML attributes (by default Any SAML attribute), and SCIM user attributes and SCIM groups. [zpa.policy.redirection-rules:criteria-list] The client types listed for a redirection rule are Branch Connector, Client Connector, Client Connector Partner, Cloud Connector and Machine Tunnel, joined by an OR Boolean operator when several are added, and rules using the Branch Connector, Cloud Connector or Machine Tunnel client types additionally can't use SAML and SCIM attributes criteria. [zpa.policy.redirection-rules:client-types] The Terraform client types are in [The redirection rule doc lists exactly five CLIENT_TYPE values: zpn_client_type_machine_tunnel, zpn_client_type_edge_connector, zpn_client_type_zapp, zpn_client_type_zapp_partner and zpn_client_type_branch_connector.](kb:zpa.terraform.policy-rule-resources:redirection-client-types). The 10-condition-set limit is in [The access global rules and policy groups, timeout, client forwarding and Browser Protection rule editors each say the criteria drop-down only displays criteria not already in use by the rule, except for Client Connector Posture Profile condition sets, and that up to 10 condition sets can be added; the redirection editor says the drop-down only displays unused criteria and up to 10 condition sets can be added, with no exception for posture stated.](kb:zpa.policy.conditions:condition-set-limit).

**The rule list.** Private Access applies redirection policy rules in the order they are listed on the Redirection Policy page, the UI displays only the first 100 rules by default, and an existing rule's criteria can be copied to create a new rule. [zpa.policy.redirection-rules:order-and-display] Redirection policy rules that are managed by Zscaler are read only and cannot be configured, edited, or deleted. [zpa.policy.redirection-rules:managed-read-only] A redirection rule name cannot contain special characters except periods, hyphens and underscores. [zpa.policy.redirection-rules:name-characters]

**Open points.** What a rule managed by Zscaler is for, and the redirection limits, are not stated [gap:zpa.policy.redirection-rules:redirection-details-not-stated].

What to check:
1. Check the selection method of the matching rule, since Default keeps the current selection algorithm, Preferred falls back to Public Service Edges and Always prevents them while Private Service Edges are available.
2. If a Branch Connector or Cloud Connector user is not redirected as expected, check whether the rule's method is Always, which the page rules out for those client types.
3. Check the position of the rule in the Redirection Policy page, since rules apply in the listed order.

Not known (open gaps):
- How available differs from active for the Always selection method [gap:zpa.policy.redirection-rules:always-available-vs-active]: settled by lab-test or support-ticket
