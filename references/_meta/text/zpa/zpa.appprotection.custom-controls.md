# AppProtection custom HTTP and WebSocket controls: parameters, operators, limits and regular expressions (zpa.appprotection.custom-controls)
Also called: custom control regex; websocket custom control; max payload size; max fragments per message; regular expression values appprotection

A custom control is a Request control (a message from the client to the server) or a Response control (a response from the server to the client), and one or more control parameters are chosen for the selected type, including Request Uri, Request Body and Response Body. [zpa.appprotection.custom-controls:control-type] WebSocket custom controls act as a Request (client to server) or Response (server to client) and act on Max Payload Size or Max Fragments Per Message. Their actions are Allow and Block, where Block gives the user a 403 response code, and they take a severity. [zpa.appprotection.custom-controls:websocket-controls] The control groups and the rule that an in-use custom control cannot be deleted are in [AppProtection controls: kinds, OWASP groups and versions](kb:zpa.appprotection.controls). All custom controls and all WebSocket custom controls can be edited, even ones currently in use by an AppProtection profile. [zpa.appprotection.custom-controls:edit-in-use]

**Parameters and operators.** The value operators include Regex, Does not match Regex, Contains, Starts with and Ends with. [zpa.appprotection.custom-controls:value-operators] Exists checks that a control type is present and Does not exist checks that it is absent, and each is available only for Request Header, Request Cookie, Query String and Response Header. [zpa.appprotection.custom-controls:exists-operators] Size takes an operator and a value, and if =, > or < is used once when setting up a custom control, it cannot be used again in the same custom control. [zpa.appprotection.custom-controls:size-operator] Request Method is chosen from a list of available options that includes negated entries such as Not PROPPATCH and Not MKACTIVITY. [zpa.appprotection.custom-controls:request-method]

**Limits.** The text field of a custom control definition is limited to 2,500 characters, and only the first 1 MB of Request and Response Headers is inspected. [zpa.appprotection.custom-controls:text-limit] The other limits are open [gap:zpa.appprotection.custom-controls:limits].

**Severity and action.** A custom control's severity is Critical, High, Medium or Low, and in an AppProtection profile it has a paranoia level of 1. Its transaction action is Allow (the user proceeds with the current URL), Block (the user receives a 403 response code) or Redirect (the user is sent to an alternative URL that is entered). [zpa.appprotection.custom-controls:severity-action]

**Regular expressions.** In custom control regular expressions the single-character wildcard, bracket classes, negated bracket classes and the *, ? and + repeats are supported, as is an alternation matching either the expression before or after the operator. The start and end position anchors and back-references to a capture group are not supported, and capture groups are not supported, though parentheses can bound subexpressions. [zpa.appprotection.custom-controls:regex-syntax] Both bounds m and n of a bounded repeat must be between 0 and 100; n is required and m can be omitted (0 is assumed). A repeat of an expression that itself contains a repeat is not supported. [zpa.appprotection.custom-controls:regex-repeats] The page lists shorthand character classes supported by Zscaler, among them the digit class, the non-digit class, the non-whitespace class, the word class, the non-word class and the word boundary; the whitespace class matches any single horizontal whitespace character across a single line. [zpa.appprotection.custom-controls:regex-shorthand] A regex value must begin with a base token, a non-zero-length simple sequence of alphabetic and numeric characters of a known length. The first part can include only literal alphabetic characters, literal numeric characters, special characters, classes of only alphabetic or only numeric characters, bounded repeats and 8 or fewer branches; shorthand characters can be followed by a special character, and a base token can have up to two nested shorthand characters. The initial sequence must be all alphabetic or all numeric, and the base token must end with an expression that is non-alphanumeric. [zpa.appprotection.custom-controls:regex-base-token] Regex values only match at the beginning of a token, at the first alphabetic or numeric character after a non-alphabetic, non-numeric character; in the page's example, [A-Za-z]\d{7} does not match "AA1234567". [zpa.appprotection.custom-controls:regex-token-start] Whether these rules apply to WebSocket controls is open [gap:zpa.appprotection.custom-controls:regex-websocket].

**Names.** A custom control name and a WebSocket control name cannot contain special characters except periods, hyphens and underscores. [zpa.appprotection.custom-controls:name-characters] Whether PROPINFO in the Request Method list is a misspelling is open [gap:zpa.appprotection.custom-controls:propinfo].

What to check:
1. Whether a custom control's regular expression begins with a base token and avoids anchors, back-references and repeats of repeats.
2. Whether a control uses = , > or < more than once for Size.
3. Whether the control being edited is in use by a profile, which does not stop editing.

Not known (open gaps):
- Custom control limits beyond the text field [gap:zpa.appprotection.custom-controls:limits]: settled by source-read or support-ticket
- Whether the regular expression rules apply to WebSocket controls [gap:zpa.appprotection.custom-controls:regex-websocket]: settled by lab-test or support-ticket
- Whether PROPINFO in the Request Method list is a misspelling [gap:zpa.appprotection.custom-controls:propinfo]: settled by tenant-data or support-ticket
