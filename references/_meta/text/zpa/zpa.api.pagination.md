# ZPA list pagination, search syntax and client-side filtering (zpa.api.pagination)
Also called: zpa page size 20 max 500; pagesize; has_next next; resp.search JMESPath; name+EQ+; _post_search_all_pages; CommonFilterSearch; zpa mcp page_size; only first 20 rules; fieldName operator fieldValue; ZPA page size 500; default page size 20; name lookup first two words; RemoveCloudSuffix regex; partial search retry; mcp page_size; zpa list returns only 20 rules; page_size pagesize spelling; mcp list tools pagination zpa; python sdk pagesize wire key

ZPA list calls return one page of 20 rows unless the caller asks for more, up to 500. The Python client's paging is in [Paging through ZPA lists with the Python SDK](kb:zpa.sdk-python.pagination), and the Go paging-envelope defects are in [How the Go SDK pages through ZPA, ZCC and ZTC lists, and when it stops early](kb:shared.sdk-go.list-pagination).

**Page parameters.** ZPA list operations take page and pagesize query parameters; the default page size is 20 and the maximum 500, as the OpenAPI document and the Python SDK README both state. [zpa.api.pagination:page-defaults] The SCIM and receiver lists state the same limits: [The SCIM group list by identity provider (`scimgroup/idpId/{idpId}`) pages with page and pagesize; the default page size is 20 and the maximum is 500.](kb:zpa.scim.api-surface:paging) and [Listing receivers supports pagination with a default page size of 20 and a maximum of 500.](kb:zpa.log-receivers.api:list-pagination).

**Search strings.** ZPA search strings follow the format fieldName operator fieldValue, and the Python SDK converts a plain name into name+EQ+<name>. [zpa.api.pagination:search-format] The Python client's rewrite is in [The executor strips surrounding whitespace from a ZPA `search` string and checks it, ignoring case, for a filter operator: +EQ+, +NE+, +GT+, +LT+, +GE+, +LE+, +CONTAINS+, +STARTSWITH+, +ENDSWITH+, or the URL-encoded %2BEQ%2B, %2BNE%2B, %2BGT%2B, %2BLT%2B, %2BGE%2B and %2BLE%2B. A string with none is rewritten to `name+EQ+<value>`; a string with one is sent as stripped.](kb:zpa.sdk-python.pagination:search-name-wrap). How the Go list helper rewrites and encodes the string is in [For ZPA list endpoints (other than SCIM) the shared pager rewrites a plain search string into `name+EQ+<value>` after deleting every character outside letters, digits, whitespace, `_`, `/`, `-` and `.`. The segment group lookup by name, for one, then compares the listed results to the original name case-insensitively.](kb:zpa.sdk-go.service-defects:search-sanitizer-strips-name-characters).

**Go list helpers.** The Go ZPA GetAllPagesGeneric helper requests every page with DefaultPageSize 500, the maximum the API documents for pagesize, whereas the API's default when none is sent is 20; a posture profile lookup by UDID or a trusted network lookup by network id calls it with an empty search, so it pages through the whole list at 500 per request. [zpa.api.pagination:go-requests-500-per-page] A Go caller that lists through GetAllPagesGeneric therefore never gets the API's default page size of 20. [zpa.api.pagination:go-default-page-size-unused] When the first list request with a multi-word search returns any error, GetAllPagesGenericWithCustomFilters retries once with only the first two words of the search value, and the retry's result and error replace the first attempt's. A name lookup can therefore succeed on a shortened search after the full-name search failed, with the first error discarded. [zpa.api.pagination:partial-search-first-two-words] The Python SDK does not retry a failed list request with a shortened search: list_machine_groups, for example, builds one request with the caller's query parameters and returns the executor's error to the caller. [zpa.api.pagination:python-search-no-retry] RemoveCloudSuffix drops a trailing parenthesised token of letters, digits, hyphen, underscore and dot when it is preceded by one or more characters matching `\s` (tab included) and followed by optional `\s` characters, then trims only literal spaces from the result. [zpa.api.pagination:remove-cloud-suffix-whitespace] The effect on posture profile and trusted network lookups is in [The ZPA posture profile object and where it comes from](kb:zpa.posture-profiles.object-model) and [The ZPA trusted network object and how to fetch it](kb:zpa.trusted-networks.object). The name sanitizer and the microtenant-name resolver are in [ZPA Go SDK service functions that return partial results, send wrong keys, or reject valid input](kb:zpa.sdk-go.service-defects) and [Which object a ZPA Terraform data source actually returns](kb:zpa.terraform.data-source-selection).

**MCP server.** The MCP policy-rule list helper takes an optional page of at least 1 and passes search, page and page_size to a single SDK request, with page and page_size converted to strings, and leaves out any value the caller did not set. [zpa.api.pagination:mcp-passthrough] MCP policy-rule lists are manual pages: the SDK does not auto-page, without page and page_size only the first 20 rules are returned, and page_size above 500 or page below 1 is rejected. [zpa.api.pagination:mcp-manual-pages] The MCP list tools for BA certificates, AppProtection profiles, enrollment certificates, posture profiles, SAML attributes, SCIM attributes, SCIM groups, trusted networks, PRA credentials, PRA portals and provisioning keys each declare the same `page` (at least 1) and `page_size` (1 to 500, API default 20) inputs and forward `page_size` to the SDK as a string. [zpa.api.pagination:mcp-list-tools-same-inputs] The MCP regression test requires page and page_size on the five policy-rule list tools and on eleven further ZPA list tools (BA certificates, PRA credentials and portals, provisioning keys, SAML and SCIM attributes, SCIM groups, AppProtection, posture, trusted network and enrollment certificate reads), and excludes the LSS catalogs. [zpa.api.pagination:mcp-tool-sweep]

What to check:
1. Whether a list that looks truncated at 20 rows was read with a page size, or only the first page.
2. Whether a search string is a plain name, which the SDK converts to a name equality filter, or a full field operator value expression.
3. Whether a client-side filter ran over one page or the whole list.
4. Whether a lookup result came from the full name or from the two-word retry, when a multi-word name search errored first.
5. Whether a name ending in a parenthesised token was compared with that token removed.
6. Whether a request count for a Go lookup that lists through GetAllPagesGeneric should be estimated at 500 items per page.
7. When an MCP list returns about 20 rows for a tenant with more, check whether `page` and `page_size` were passed.
