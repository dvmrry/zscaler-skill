# How application discovery works and how a discovered application is defined (zpa.app-segments.discovery)
Also called: application discovery; applications discovered in past 14 days; discovered applications; application inventory; wildcard application discovery

You can enable application discovery so that when users request applications, Private Access can discover them using specific domain names; Private Access only discovers an application when a user requests access to it. [zpa.app-segments.discovery:what-it-is] When users request access to an application that matches the domain, Client Connector redirects the request to the App Connectors configured for that application, which do a DNS lookup; if the request is successful, the user can access the application and see it listed in the Applications Discovered in Past 14 Days widget on the Applications dashboard. [zpa.app-segments.discovery:how-it-runs]

**Configuring it.** To configure application discovery within an application segment, you must enter FQDNs or domain names, which can be in wildcard format as *.<FQDN or domain name> or .<FQDN or domain name>, and wildcard application segments can be used for it; the About Applications page adds that an application can be defined as an IP subnet to enable discovery. [zpa.app-segments.discovery:entry-forms] Application discovery works efficiently when the TCP and UDP port range specified for the domain is wide, and when the application policy allows access to a broad set of users. [zpa.app-segments.discovery:efficiency] If you want to configure application discovery but have a few applications you do not want to make accessible through Private Access, you can use the Bypass field to disable access to those applications. [zpa.app-segments.discovery:exclude-with-bypass] Matching the DNS search domains is in [What DNS search domains do for application segments and how they must match](kb:zpa.app-segments.dns-search-domains).

**Health.** You can only choose On Access health reporting for discovered applications; the App Connector reports the health of the application as soon as a user accesses it and for up to 30 minutes after the user has completed using it, after which the health status changes to Unknown until a user accesses the application again. [zpa.app-segments.discovery:health-on-access-only] The health modes are in [How App Connectors check and report application health, and what Continuous, On Access and None mean](kb:zpa.app-segments.health-reporting).

**Defining a discovered application.** To create a policy for a discovered application or configure specific settings for it, such as choosing Continuous health reporting or bypass settings, you can define the discovered application explicitly within an application segment from the Applications Discovered in Past 14 Days widget on the Applications dashboard. [zpa.app-segments.discovery:define-discovered] Discovered applications are listed from most to least recent and you can click one to view its diagnostics; if an application was discovered over 14 days in the past, the User Activity diagnostics corresponding to its discovery are not available. [zpa.app-segments.discovery:widget-and-diagnostics-window] How long an application stays listed past the window is open [gap:zpa.app-segments.discovery:listing-past-window].

**Application Inventory.** Application Inventory provides a centralized inventory of predefined private application types, each with a category, and automatically discovers and classifies private application traffic to identify application types without relying on specific ports or protocols; it also works with SSL/TLS-encrypted traffic without requiring traffic decryption. During the current implementation phase it displays only predefined application types, and support for custom application types will be introduced in a future release. [zpa.app-segments.discovery:application-inventory] How types are classified is open [gap:zpa.app-segments.discovery:inventory-classification].
