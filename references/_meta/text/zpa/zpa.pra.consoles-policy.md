# PRA consoles policy: file transfer, clipboard, recording and sharing (zpa.pra.consoles-policy)
Also called: consoles policy; privileged capabilities policy; pra file transfer; pra clipboard; pra file upload inspect; pra vnc sftp port 22; pra share session control monitor; pra join session; pra policy change live session

A consoles policy decides what a user can do inside a console session.

**Controls.** A consoles policy rule is assigned to selected privileged consoles and controls file uploads, file downloads, clipboard copy and paste, session recording, session sharing and joining live sessions. The rule's criteria choose application segments and segment groups, with SAML and SCIM or session and user attributes. [zpa.pra.consoles-policy:scope] Consoles-based control needs the privileged portals and privileged consoles it will be assigned to created first. [zpa.pra.consoles-policy:prerequisites] The Consoles Policy page shows each rule's Rule Order (ZPA applies rules in the listed order and the number can be edited by entering a new value) and its Console Configuration, which lists Clipboard Copy, Clipboard Paste, Download, Inspect Upload, Join Sessions, Record Sessions, Share Sessions Control, Share Sessions Monitor and Upload. [zpa.pra.consoles-policy:console-configuration-column] File Uploads, File Downloads, Clipboard Copy, Clipboard Paste, Record Sessions, Share Sessions Mode and Join Sessions Mode are each disabled by default. [zpa.pra.consoles-policy:defaults-disabled] A feature that is disabled in the consoles policy is not displayed to the user, except File Transfer, which is shown but not functional. [zpa.pra.consoles-policy:disabled-feature-display] The Clipboard article says a disabled Clipboard icon can still be clicked [divergence:zpa.pra.consoles-policy:clipboard-disabled-display].

**File transfer.** The Inspect option for file uploads can be selected only if the Internet & SaaS (ZIA) integration was successful, and inspected files are checked inline with the upload. If the inspection detects malware the upload halts and the files are not uploaded. [zpa.pra.consoles-policy:inspect-needs-zia] For a VNC-enabled console, enabling File Uploads or File Downloads requires the target system to run SSH on port 22 with the same credentials as the VNC login. The connection fails when the end user connects to a target with SFTP disabled. [zpa.pra.consoles-policy:vnc-file-transfer] For a VNC or RealVNC console with File Transfer in a consoles policy, the SFTP service must be enabled on the VNC or RealVNC server before the consoles policy is created, with SFTP authentication matching the VNC or RealVNC configuration. If SFTP is not configured on the VNC target and a consoles policy with file transfer is configured for the console, end users cannot connect to it. [zpa.pra.consoles-policy:vnc-realvnc-sftp]

**Clipboard.** Enabling Clipboard Copy lets a user copy functions from Privileged Remote Access to the local system, and enabling Clipboard Paste lets a user paste functions from the local system to PRA. With multiple privileged consoles open, copied text is carried over to all of the Clipboard-enabled privileged consoles. [zpa.pra.consoles-policy:clipboard-direction] Clipboard operations work only when the selected protocol and remote OS allow them. Non-ASCII characters cannot be copied and pasted if the console uses a VNC, RealVNC or SSH protocol, and operations between a non-Windows OS and a Windows OS can add newline characters. Up to 4,096 characters can be copied and pasted by default, and a larger size of up to 32K characters can be requested through Zscaler Support. [zpa.pra.consoles-policy:clipboard-limits] Whether the 32K increase is per tenant or per console is open [gap:zpa.pra.consoles-policy:clipboard-size-scope]. When Clipboard is enabled, copied content is periodically synced to the privileged console Clipboard if the browser supports it, and websites or other applications on the device can modify the Clipboard before it is pasted into the console. [zpa.pra.consoles-policy:clipboard-sync-and-tamper] When Clipboard Copy and Paste are enabled the functions depend on the browser. In Safari only the Clipboard window can copy and paste within the console; in Chrome a pop-up appears on a paste from the local Clipboard and the user clicks Allow; for pasting from Firefox into the console, dom.events.testing.asyncClipboard and dom.events.asyncClipboard.readText must be set to true on the about:config page. [zpa.pra.consoles-policy:clipboard-browsers]

**Recording and sharing.** Session recording captures screen output. File transfer and clipboard contents are not recorded, to prevent leaking sensitive information such as passwords. [zpa.pra.consoles-policy:recording-excludes-transfers] Share Sessions Mode set to Control lets other users be invited to a session and be given mouse and keyboard control, and set to Monitor lets permitted users such as administrators join live sessions. [zpa.pra.consoles-policy:share-modes]

**Changes and limits.** A change to a consoles policy made during a live privileged session is not reflected until a new live session starts. [zpa.pra.consoles-policy:live-session-changes] When the Clipboard features are enabled in a consoles policy, a new session must be started before the Clipboard permissions take effect, and refreshing the page also refreshes the permissions. If a session is already running when Clipboard is started, the user must terminate it and start a new session to show the Clipboard icon. [zpa.pra.consoles-policy:clipboard-new-session] Whether a page refresh applies a policy change is described two ways [divergence:zpa.pra.consoles-policy:refresh-applies-policy]. A consoles policy allows 5,000 policy rules and 200 privileged consoles per policy. [zpa.pra.consoles-policy:limits] The older Privileged Capabilities Policy name and URL are not confirmed as retired [gap:zpa.pra.consoles-policy:renamed].

Recordings and their statuses are in [PRA session recordings: status, transcoding, playback and sharing](kb:zpa.pra.session-recording). The transfer mechanics and the File Transfer System are in [PRA file transfer: in-console transfer, the PRA File Transfer System and the Sandbox integration](kb:zpa.pra.file-transfer); inviting participants is in [PRA live session sharing: participants, invitations, control and ejection](kb:zpa.pra.live-sessions); the sibling policy for the PRA Portal is [PRA portals policy: file, inspection and approval permissions in the PRA Portal](kb:zpa.pra.portals-policy). What to check:
1. Whether a missing control in the session is simply disabled, since every control defaults to off; the pages disagree on whether a disabled control is displayed.
2. Whether a VNC or RealVNC console with file transfer has SFTP enabled on the server, with SFTP authentication matching the VNC configuration.
3. Whether the policy changed during a live session, which a page refresh may or may not apply.
4. Whether a Clipboard failure is the protocol, browser or character set, using the documented limits.
5. Whether Inspect is selectable, which needs the ZIA integration.

Sources disagree (name both sides):
- Whether a consoles-policy change reaches a live session without a new session: the Configuring Consoles Policies article says changes are not reflected until a new live session is started, and the Clipboard article says refreshing the page also refreshes the permissions. [divergence:zpa.pra.consoles-policy:refresh-applies-policy]
  - zscaler-help: A change made during a live session is not reflected until a new live session is started (claim live-session-changes).
  - zscaler-help: For the Clipboard features, a new session must be started before permissions take effect, and refreshing the page also refreshes the permissions (claim clipboard-new-session).
  Impact: It is not settled whether a page refresh starts a new session, so it is not settled whether a refresh applies a consoles-policy change. An answer about a policy change that has not taken effect should not state either as fact. A lab test of a change followed by a refresh would settle it.
- Whether a disabled consoles-policy feature is displayed to the user: the PRA overview says disabled features are not displayed except File Transfer, and the Clipboard article says Clipboard options are disabled by default but the Clipboard icon can still be clicked. [divergence:zpa.pra.consoles-policy:clipboard-disabled-display]
  - zscaler-help: Disabled features are not displayed, except File Transfer (claim disabled-feature-display).
  - zscaler-help: Clipboard options are disabled by default and the Clipboard icon can still be clicked.
  Impact: The Clipboard article also says that with a session already running the user must start a new session to show the Clipboard icon, so it is not settled when the icon is shown. An answer about a missing or clickable Clipboard icon should not rest on either page alone.
