# PRA credentials, credential pools and the credentials policy (zpa.pra.credentials)
Also called: privileged credentials; credential pool; pra pool exhausted; privileged credentials policy; pra credential type; pra ssh key size; pra credential immutable; pra vnc password; contractor rdp password pool

Credentials decide who logs in to a console, and pools let several users share them.

**Credential types.** Privileged credentials come in three types: Username+Password for RDP with an optional domain, SSH Key with a username, private key and optional passphrase, and Password for VNC or RealVNC. [zpa.pra.credentials:credential-types] The domain needs to be specified only when logging in to an RDP console connected to an Active Directory domain; it can also be included in the username. [zpa.pra.credentials:domain-only-for-ad-rdp] SSH private keys of 2048 bits or smaller can be used for a privileged credential. [zpa.pra.credentials:ssh-key-size] A credential's type cannot be changed after it is created and saved; Username+Password is the type for RDP and SSH Key the type for SSH. [zpa.pra.credentials:type-immutable] A credential made for RDP therefore cannot be switched to serve SSH. [zpa.pra.credentials:rdp-credential-not-for-ssh]

**Pools.** A credential pool maps authentication details to a privileged console through a privileged credentials policy that uses SAML and SCIM criteria, so multiple users can start sessions without entering credentials. [zpa.pra.credentials:pool-purpose] A credential pool has a credential type of SSH, RDP, VNC or RealVNC. [zpa.pra.credentials:pool-type] Before using credential pools an admin must discover credentials from external identity sources such as Active Directory or Entra ID, or create them locally, and must have created the portals and consoles the credentials will be assigned to. [zpa.pra.credentials:pool-sources] A credential pool's Credential Type is a sign-in protocol type: Username+Password for RDP, SSH Key for SSH and Password for VNC or RealVNC. It cannot be changed after the pool is created and saved, and the edit page says the Credential Type field setting cannot be changed. [zpa.pra.credentials:pool-type-immutable] A credential pool groups and organizes existing privileged credentials: it takes a name (which cannot contain special characters other than periods, hyphens and underscores) and the privileged credentials to group together. [zpa.pra.credentials:pool-fields] When all credentials in a pool are exhausted or in use, users are prevented from accessing the privileged console. [zpa.pra.credentials:pool-exhaustion] What happens to a credential when a session ends is open [gap:zpa.pra.credentials:pool-return-and-rotation].

**Credentials page.** The Privileged Credentials page shows data over 1 hour to 365 days. It counts used privileged credentials that are SSH, RDP, VNC and RealVNC enabled, and per credential pool shows Used Credentials, the amount currently being used from the pool, and Total Credentials, the total within the pool. [zpa.pra.credentials:credentials-page]

**Assignment.** A privileged credentials policy rule assigns either one privileged credential or one credential pool to consoles. When a user opens a console with such a policy they reach it without logging in, and deleting the policy removes the assignment so the console prompts for a login again. [zpa.pra.credentials:credentials-policy-assigns] A privileged credentials policy rule maps privileged credentials, or privileged credential pools, to the associated privileged console using SAML and SCIM information, so designated consoles have designated credentials. A privileged credential's protocol can be SSH, RDP, RealVNC or VNC with the related login details. [zpa.pra.credentials:credentials-policy-purpose] Based on the privileged credentials policy, credentials are automatically injected into the privileged console without having to be added manually. [zpa.pra.credentials:credential-injection] To use a privileged credential, a privileged portal and a privileged console must first be created, and they are then assigned to the privileged credential. [zpa.pra.credentials:credential-prerequisites] Credentials-based control needs the privileged consoles it will be assigned to created first, then the privileged credential or privileged credential pools the policy will be applied to. [zpa.pra.credentials:credentials-policy-prerequisites] If the underlying credentials are changed after the privileged credential was created and saved, the new details (for example username, password or private key) must be updated on the privileged credential to continue using it. [zpa.pra.credentials:update-after-change] The Privileged Credentials Policy page lists each rule's Rule Order (ZPA applies rules in the listed order and the number can be edited by entering a new value) and its Credential, the privileged credential or credential pool assigned to the rule. [zpa.pra.credentials:credentials-policy-columns] The Privileged Credentials Policy page says at least two privileged credential policies must be created for the first rule to apply, that the privileged credential of the last policy is not applied to its related console, and that the last policy should be one that is not needed. [zpa.pra.credentials:credentials-policy-last-rule] Why the last policy is not applied is open [gap:zpa.pra.credentials:last-rule-reason]. A privileged credentials policy allows 5,000 policy rules and 1,000 privileged consoles per policy. [zpa.pra.credentials:credentials-policy-limit] Privileged credentials created in the Default Microtenant are inherited across microtenants. [zpa.pra.credentials:microtenant-inheritance] From the Managed page a privileged credential can be deleted or moved into a Microtenant; if privileged credential policies are associated with it, those policies must be deleted to move it to a different Microtenant. [zpa.pra.credentials:move-needs-policy-removal]

What to check:
1. Whether the credential type matches the console protocol, since type cannot change after creation.
2. Whether a failed session start is a pool whose credentials are all in use, before looking at policy or approval.
3. Whether a credentials policy still assigns the credential or pool to the console.
4. Whether the policy that should inject a credential is the last privileged credentials policy, which the page says is not applied, or whether fewer than two policies exist.
5. Whether a pool-sizing or rotation answer rests on the unverified release-at-session-end statement.
