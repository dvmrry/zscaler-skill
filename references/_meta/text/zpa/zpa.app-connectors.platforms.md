# App Connector deployment by VM and cloud platform (zpa.app-connectors.platforms)
Also called: app connector software by platform; app connector deployment guide for linux; app connector deployment guide for amazon web services; app connector deployment guide for microsoft azure; app connector deployment guide for google cloud platform; app connector deployment guide for vmware platforms; app connector deployment guide for microsoft hyper-v; app connector deployment guide for nutanix ahv

The App Connector software page and the per-platform deployment guides say what differs by VM or cloud platform; the shared prerequisites text is in [App Connector deployment, redundancy and limits](kb:zpa.app-connectors.deployment) and container platforms are in [App Connectors on Docker, Kubernetes and OpenShift](kb:zpa.app-connectors.containers).

**Software.** The App Connector software page lists STIG OVAs for Nutanix AHV and VMware, AWS, GCP and Microsoft Azure Marketplace STIG images, RHEL 9 VHDX images for Microsoft Azure Local and Microsoft Hyper-V, Docker Hub, Kubernetes, a Helm Chart that must be installed to deploy on OpenShift, and RPM packages for RHEL 8 and RHEL 9 that need a RHEL operating system already deployed and running. [zpa.app-connectors.platforms:software-by-platform]

**Linux RPM.** In the App Connector Linux guide the zscaler repository for RHEL 9 has baseurl https://yum.private.zscaler.com/yum/el9 with gpgcheck=1 and the el9 gpg key, RHEL 8-based deployments use the el8 baseurl and gpgkey, the reader is to ensure the GPG fingerprint matches a6fe 2422 fce7 e8ac 672e 9e51 644e a315 8765 e1dd, and in a proxy environment the proxy server IP address and port go in /etc/yum.conf. [zpa.app-connectors.platforms:rpm-repository] The App Connector Linux guide says that when the App Connector cannot download the RPM package it must be downloaded on a server; the GPG public key is then imported with rpm --import and the package installed with rpm -i. [zpa.app-connectors.platforms:rpm-offline]

**From the Linux guide.** The App Connector Linux guide says that by default VM-based App Connectors, Private Service Edges and Private Cloud Controllers use DHCP networking on their primary interface; if DHCP is not available a static IP address can be configured on a VM-based App Connector, Private Service Edge, Private Cloud Controller or Network Connector, and a DNS resolver, NTP servers and static routing can be configured from the Admin Console. [zpa.app-connectors.platforms:networking-defaults] The App Connector Linux guide says an App Connector configured to send traffic to a proxy can have a proxy bypass for traffic exempted from the proxy (traffic between the App Connector and the Public or Private Service Edges): entries in /opt/zscaler/var/proxy-bypass are IP addresses, subnets, domains or domains with a prefix wildcard, and zpa-connector is restarted with systemctl. [zpa.app-connectors.platforms:proxy-bypass]

**Amazon Web Services.** The App Connector AWS guide says App Connectors are deployed in the customer's VPCs with a pair per VPC, Zscaler load balances across them, security groups should permit connections to the application servers on the appropriate TCP/UDP ports with ICMP reachability and DNS resolution, no inbound connectivity from the internet is required, Zscaler recommends a private subnet that reaches the internet through a NAT gateway, and only outbound access on TCP port 443 is needed to reach Private Access. [zpa.app-connectors.platforms:aws-placement] The App Connector AWS guide says only certificate-based authentication is allowed with AWS App Connectors and SSH is enabled by default; the security group is updated to temporarily allow inbound port 22, which must be disabled afterwards, and if IMDSv2 is enabled App Connectors fetch the AWS VM ID. [zpa.app-connectors.platforms:aws-login-imdsv2] The App Connector AWS guide's launch-template procedure filters the AMI menu for zpa-connector, has user data that waits for the connector to download its latest build with sleep 60, enters 2 as the group size across 2 subnets, and enters 50 as the target value; it says each App Connector passes 400 to 500 Mbps and an additional one can be added at about 50% CPU utilization, and that OAuth 2.0 enrollment is unavailable with Auto Scaling. [zpa.app-connectors.platforms:aws-auto-scaling] The same guide's private-subnet recommendation and its public IP setting differ [divergence:zpa.app-connectors.platforms:aws-public-ip].

**Microsoft Azure.** The App Connector Azure guide has the reader select the Zscaler Private Access Connector for Azure Compute - Gen 1 image; it says the VM allows inbound SSH on port 22 by default and Zscaler recommends restricting that inbound rule, has the reader create a rule allowing outbound connections for port 443, and says to disable the inbound rule on port 22 for the associated network security group. [zpa.app-connectors.platforms:azure]

**Google Cloud Platform.** The App Connector GCP guide says each VPC must have at least a pair of App Connectors deployed and that they should be deployed across regions and zones, describes n2-standard-4 (4 vCPU, 2 core, 16 GB) and n2-highcpu-4 (4 vCPU, 2 core, 4 GB) as supported specifications, selects Allow full access to all Cloud APIs for Access scopes (said to allow access to the provisioning_key in the secret manager), and enters 2 and 4 as minimum and maximum instances, 80 for Target CPU utilization and 300 for Initialization period. [zpa.app-connectors.platforms:gcp] The firewall step's wording is open [gap:zpa.app-connectors.platforms:gcp-firewall-wording]. The reference Terraform module's GCP defaults are in [Reference Terraform modules for App Connectors on GCP](kb:zpa.app-connectors.gcp-reference-modules).

**VMware.** The App Connector VMware guide's additional vCenter prerequisites are VMware vSphere Hypervisor (ESXi) version 7.0 Update 2 or later, vCenter access to deploy an OVA as a VM, configure the virtual NIC and modify the vApp attributes, and the vSphere Client Integration Plugin; its OVA link is https://dist.private.zscaler.com/vms/VMware/2026.07/zpa-connector-el9-2026.07.ova, the disk format is Thin Provision, Power on after deployment is not selected, OVF environment transport is VMware Tools, Installation boot is Enable, and the local time is to be verified and updated with Network Time Protocol if wrong. [zpa.app-connectors.platforms:vmware-vcenter] The App Connector VMware guide says the App Connector is preconfigured to obtain an IP address on its primary interface via DHCP, and that if the DHCP service is not available in the environment networking tasks must be completed. [zpa.app-connectors.platforms:vmware-dhcp] The App Connector VMware guide says the standalone vSphere Hypervisor edition is not able to parse the extended OVF attributes that allow the provisioning key to be provided during deployment; on that path Power on after deployment is selected, and systemctl daemon-reload is run and zpa-connector started. [zpa.app-connectors.platforms:esxi-standalone]

**Microsoft Hyper-V.** The App Connector Hyper-V guide's prerequisites list a physical server with Windows Server 2025 Standard or Datacenter Edition, Intel VT-x or AMD-V hardware virtualization support, SLAT support, a minimum of 16 GB RAM (recommended based on VM workload requirements) and sufficient local storage for the host OS and VM VHDX files. [zpa.app-connectors.platforms:hyper-v-host] The App Connector Hyper-V procedure requires a physical server with the Hyper-V manager role and uses the VHDX https://dist.private.zscaler.com/vms/Azure/2026.08/zpa-connector-el9-2026.08.vhdx; it selects Generation 1, enters 4096 as startup memory with Dynamic Memory not selected, and enters 2 virtual processors. [zpa.app-connectors.platforms:hyper-v-vm] The processor count the procedure sets is compared with the sizing rule in [App Connector deployment, redundancy and limits](kb:zpa.app-connectors.deployment).

**Nutanix AHV.** The App Connector Nutanix AHV guide uses the VMware image https://dist.private.zscaler.com/vms/VMware/2026.07/zpa-connector-el9-2026.07.ova: the VMDK is extracted from the OVA, imported with Image Type DISK, the CD-ROM disk is removed, and the disk is cloned with Operation Clone from Image Service and Bus Type IDE; Number Of Cores Per vCPU has a minimum required value of 4. [zpa.app-connectors.platforms:nutanix]

What to check:
1. Which software form the connector was built from, before applying an RPM, VM image or cloud image instruction.
2. Whether the AWS connector has a public IP and an inbound port 22 rule left open after enrollment.
3. Whether a VMware standalone ESXi connector missed its provisioning key because of the extended OVF attributes.
4. Whether a connector that sends traffic to a proxy has a proxy-bypass file for traffic to the Service Edges.

Sources disagree (name both sides):
- The App Connector AWS guide recommends a private subnet that reaches the internet through a NAT gateway, while its instance procedure says to choose Enable for Auto-assign Public IP. [divergence:zpa.app-connectors.platforms:aws-public-ip]
  - zscaler-help: Zscaler recommends deploying App Connectors on a private subnet that connects to the internet through a NAT gateway.
  - zscaler-help: The instance procedure chooses Enable for Auto-assign Public IP.
  Impact: A connector built exactly by the procedure gets a public IP address although the same page recommends a private subnet behind a NAT gateway; the page does not say which governs. The sentence it sits beside gives no inbound requirement from the internet either way.
