# Rule fields beyond criteria: reauth, posture notification and profile IDs (zpa.policy.rule-fields)
Also called: reauth_timeout default none; ForceNew reauth; devicePostureFailureNotificationEnabled; zpn_isolation_profile_id; zpn_inspection_profile_id; profile id action mismatch; destroy recreate timeout rule

Some rule fields sit outside the criteria, and their behavior is mostly set by the clients.

**Reauthentication fields.** The Python rule model reads `reauth_timeout` and `reauth_idle_timeout` as None when the rule does not carry them. [zpa.policy.rule-fields:reauth-fields-none] What an unset value means is open [gap:zpa.policy.rule-fields:reauth-unset-meaning]. In the shared policy schema of the Terraform provider, used by the forwarding, access, timeout and redirection rule resources, `reauth_timeout` and `reauth_idle_timeout` are ForceNew, so changing either on an existing rule plans a destroy and recreate. [zpa.policy.rule-fields:reauth-force-new-v1] The v2 timeout rule resource declares `reauth_timeout` and `reauth_idle_timeout` without ForceNew. From v4.4.15 both carry the `DiffSuppressFunc` `suppressEquivalentTimeout`, which hides a difference between two timeouts of the same duration (for example `Never` and `never`, or `60 Minutes` and `1 Hour`); up to v4.4.14 they had no diff suppression. [zpa.policy.rule-fields:v2-timeout-not-force-new] Whether the API refuses an in-place change is open [gap:zpa.policy.rule-fields:reauth-update-refused-by-api].

**Posture notification.** A rule's device posture failure notification flag is the JSON key `devicePostureFailureNotificationEnabled`, and the message it enables displays only for Client Connector 4.8 or later on Windows and 5.0 or later on macOS, with a notification template that enables it. [zpa.policy.rule-fields:device-posture-notification]

**Profile references.** Rules carry the profile references as `zpnIsolationProfileId`, `zpnInspectionProfileId` and `zpnInspectionProfileName`. [zpa.policy.rule-fields:profile-id-fields] The Python `add_isolation_rule` requires `zpn_isolation_profile_id` when the action is isolate and checks nothing about the profile ID for other actions. [zpa.policy.rule-fields:isolation-profile-required-for-isolate] What happens with a mismatched profile ID is open [gap:zpa.policy.rule-fields:irrelevant-profile-id-effect].

The credential references on PRA rules are in [What the ZPA Terraform provider sends and loses when writing policy rules](kb:zpa.terraform.policy-rule-writes). Timeout values are in [ZPA timeout policy rules](kb:zpa.policy.timeout-rules).

What to check:
1. Before changing a timeout on an existing v1 Terraform rule, check whether the resource uses the shared schema that forces a new resource.
2. For a posture block users do not see explained, check the rule's device posture failure notification flag and the client version.
3. For an isolation or inspection rule, check that the profile ID matches the rule's action.

Not known (open gaps):
- What an unset reauth_timeout or reauth_idle_timeout on a rule means [gap:zpa.policy.rule-fields:reauth-unset-meaning]: settled by support-ticket or lab-test
- Whether the ZPA API itself refuses to change reauth timeouts in place [gap:zpa.policy.rule-fields:reauth-update-refused-by-api]: settled by lab-test
- What the API does with a profile ID that does not match the rule's action [gap:zpa.policy.rule-fields:irrelevant-profile-id-effect]: settled by lab-test
