# PRA portals policy: file, inspection and approval permissions in the PRA Portal (zpa.pra.portals-policy)
Also called: portals policy; pra portal policy; portal configuration delete files; access uninspected files; upload inspection sandbox scan; request approvals review approvals; privileged portal policy

A portals policy decides what users of a privileged portal can do in the PRA Portal. Portals policy rules allow deleting uploaded files, uploading inspected files, uploading inspected Internet & SaaS Sandbox files, accessing uninspected files in the PRA File Transfer System pages, and requesting and reviewing privileged approvals on the My Approvals and My Requests pages. Portals policies allow users to access the PRA File Transfer System and My Approvals pages in the PRA Portal they assign the rule to. [zpa.pra.portals-policy:scope]

**Before creating one.** The privileged portals a portals policy will control must be created first, and the Configuring page also names the privileged console the rule applies to. A portals policy for the File Transfer System needs the Internet & SaaS (ZIA) Sandbox integration parameters set up before the policy is created. [zpa.pra.portals-policy:prerequisites]

**Rule options.** A portals policy rule's name cannot contain special characters other than periods, hyphens and underscores, and its description is optional. [zpa.pra.portals-policy:rule-name] A rule's Portal Configuration has Delete Files, Access Uninspected Files (shows uninspected files in the PRA Portal) and Upload Inspection (Sandbox for Internet & SaaS Sandbox inspection, or Scan for inspection other than that), each disabled by default, plus Request Approvals (approval requests can be created in the PRA Portal) and Review Approvals (requests can be reviewed, approved and rejected). [zpa.pra.portals-policy:options-and-defaults] The defaults of Request Approvals and Review Approvals are open [gap:zpa.pra.portals-policy:approval-option-defaults], and so is what the Scan option inspects with [gap:zpa.pra.portals-policy:scan-option].

**Criteria.** A portals policy rule's criteria include a choice of countries, an external IdP attribute configured in Authentication Service (supported only for IdPs created in Authentication Service), at least one required privileged portal, and SAML and SCIM Attributes with SCIM groups, where SAML and SCIM Attributes becomes Session and User Attributes for a tenant subscribed to Authentication Service for users. The criteria drop-down shows only criteria not already in use by the rule. [zpa.pra.portals-policy:criteria] For Private Access to process SAML and SCIM criteria in a portals policy rule, the SAML Attributes for Policy setting (SAML) and the SCIM Attributes and Groups for Policy setting (SCIM) must be enabled on the IdP. The SAML Attributes rule defaults to Any SAML attribute, and multiple attributes, groups or IdPs are joined by OR by default, which can be toggled to AND. If the IdP setting is disabled but the rule has criteria of that kind, OR skips those criteria and evaluates the others, while AND makes Private Access not evaluate the rule. [zpa.pra.portals-policy:saml-scim-evaluation] The access-policy version of these rules is [If the IdP's SAML Attributes for Policy (or SCIM Attributes and Groups for Policy) setting is disabled but a rule has criteria of that kind, an OR operator skips those criteria and evaluates the other kind, while an AND operator makes Private Access not evaluate the rule at all.](kb:zpa.policy.criteria:idp-policy-setting-disabled).

**The page.** The Portals Policy page lists each rule's Rule Order, which is the evaluation order (ZPA applies rules in the listed order, and the number can be edited by entering a new value), and its Portal Configuration, the options set for that rule shown as enabled or disabled. [zpa.pra.portals-policy:table-columns] Which privileged policy options appear alongside the Portals Policy depends on the tenant's Privileged Remote Access subscriptions. [zpa.pra.portals-policy:subscription-visibility]

**Open.** A legacy API article describes the portals policy payload and is not yet read into the graph [gap:zpa.pra.portals-policy:legacy-api-capture].

The permissions this policy gives for file transfer and approvals are used in [PRA file transfer: in-console transfer, the PRA File Transfer System and the Sandbox integration](kb:zpa.pra.file-transfer) and [PRA approvals: requesting, reviewing and expiry](kb:zpa.pra.approvals); the sibling policy for consoles is [PRA consoles policy: file transfer, clipboard, recording and sharing](kb:zpa.pra.consoles-policy).

What to check:
1. Whether a portals policy rule exists for the portal and the user's country, IdP or attributes before blaming the console, since file and approval pages come from it.
2. Whether an option is on, noting that Request Approvals and Review Approvals have no stated default.
3. Whether a SAML or SCIM criterion is skipped or blocks the rule because the IdP's policy setting is disabled.
