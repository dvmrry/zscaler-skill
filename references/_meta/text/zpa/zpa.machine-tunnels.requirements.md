# What a ZPA machine tunnel needs before it can connect (zpa.machine-tunnels.requirements)
Also called: machine tunnel prerequisites; enable machine tunnel for all; machine tunnel platforms; ZPA machine authentication; mtAuthRequired; policyToken machine tunnel; machine tunnel macos; machine tunnel webview2

This subject covers what a machine tunnel needs before it can connect.

**What it is.** A machine tunnel lets a Windows or macOS device establish a connection to a service before the user is logged in to Zscaler Client Connector. Zscaler Client Connector does not support machine tunnels on iOS, Linux, Android or Android on ChromeOS. [zpa.machine-tunnels.requirements:definition] Using a machine tunnel takes four things: machine groups and machine provisioning keys configured in the Admin Console, the keys added to Zscaler Client Connector app profile rules for Windows or macOS, and the Private Access machine tunnel enabled for all. [zpa.machine-tunnels.requirements:components] What the user-tunnel side looks like for comparison is open [gap:zpa.machine-tunnels.requirements:user-tunnel-comparison].

**The tenant switch.** The tenant-wide switch is Enable Machine Tunnel for All, under Administration > Client Connector Entitlement > Private Access, where Edit opens the setting. When it is on, every user with a Machine Token in the app profile can connect to Private Access without being logged in. [zpa.machine-tunnels.requirements:enable-for-all] Turning Enable Machine Tunnel for All off does not drop existing machine tunnels at once: they stay connected until a user's app profile policy is updated and the user logs out. [zpa.machine-tunnels.requirements:disable-keeps-tunnels] Changing the machine token in an app profile, or applying a different app profile, does not override the configuration of an existing machine tunnel. The token must be removed from the profile and the machine tunnel removed in Enrolled Devices, or the client reinstalled. [zpa.machine-tunnels.requirements:existing-config-sticky]

**Authentication before login.** The app profile option ZPA Machine Authentication requires users to authenticate against their identity provider before the machine tunnel starts. [zpa.machine-tunnels.requirements:machine-auth-option] On Windows the same requirement is an install parameter, MTAUTHREQUIRED for MSI and mtAuthRequired for EXE. [zpa.machine-tunnels.requirements:machine-auth-install-parameter] The policyToken install parameter is required when a machine tunnel is configured and users should reach Private Access applications before logging in to the device. The app profile policy it names must use a custom PAC file that bypasses the IdP login page. [zpa.machine-tunnels.requirements:policytoken-required] policyToken is required for pre-login Private Access, and the policy it names must use a PAC file that bypasses the IdP login page. How this interacts with ZPA Machine Authentication is not stated. [zpa.machine-tunnels.requirements:auth-needs-idp-reach] WebView2 authentication is not supported for machine tunnels. [zpa.machine-tunnels.requirements:webview2]

**Enrolling in the group.** In the pre-Windows-login deployment procedure, after the machine provisioning key is added to the Client Connector profile rule, More > Update Policy in Client Connector lets the client enroll in the machine group through that rule. [zpa.machine-tunnels.requirements:update-policy-enrolls]

**Network prerequisites.** With Transparent Proxy-based Interception mode enabled, a machine tunnel needs inbound traffic to ZscalerTunnel allowed in firewall rules, and FileVault disabled so Private Access connections work before a user logs in. [zpa.machine-tunnels.requirements:transparent-proxy-prereqs]

How the machine and user tunnels coexist after login is open [gap:zpa.machine-tunnels.requirements:session-lifecycle]. What to check:
1. Whether the platform is Windows or macOS, the only platforms with machine tunnels.
2. Whether Enable Machine Tunnel for All is on, and that the app profile rule carries a Machine Token.
3. Whether machine authentication is required and the policyToken profile bypasses the IdP login page.
4. Whether a profile or token change was expected to move an existing machine tunnel, which it does not.
5. Whether the device uses Transparent Proxy-based Interception, FileVault or WebView2 authentication.
6. Whether the symptom involves a macOS support step, login coexistence or Group Policy, which no source settles.
