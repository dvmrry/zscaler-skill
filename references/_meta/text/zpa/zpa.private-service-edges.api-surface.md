# Management API endpoints for Private Service Edges, groups and schedules (zpa.private-service-edges.api-surface)
Also called: serviceEdge api; serviceEdgeGroup endpoint; serviceEdgeSchedule; bulkDelete service edges; privateCloudController api; service edge api create; service edge auto delete api; pse api

The management API addresses instances, groups and the auto-delete schedule as separate resources.

**Instances.** Individual Private Service Edge instances are listed with GET /serviceEdge, read, updated and deleted by ID under /serviceEdge/{id}, and deleted in bulk with POST /serviceEdge/bulkDelete. [zpa.private-service-edges.api-surface:instance-endpoints] The API has no create call for a Private Service Edge instance: an instance appears when it enrolls. [zpa.private-service-edges.api-surface:instances-not-created]

**Groups.** Service Edge groups are listed with GET /serviceEdgeGroup and read, updated and deleted by ID, and created with POST /serviceEdgeGroup by the Go SDK. [zpa.private-service-edges.api-surface:group-endpoints] The collection POST is not in the specification [gap:zpa.private-service-edges.api-surface:group-post-not-in-spec].

**Auto-delete schedule.** The auto-delete schedule is read with GET /serviceEdgeSchedule, which returns one schedule object rather than a list, created with POST /serviceEdgeSchedule and updated with PUT /serviceEdgeSchedule/{id}; the body carries frequency, frequencyInterval, deleteDisabled and enabled, and an optional microtenantId query parameter applies. [zpa.private-service-edges.api-surface:schedule-endpoints] The schedule response carries frequency (string), frequencyInterval (integer), deleteDisabled and enabled (booleans), customerId and a read-only id. [zpa.private-service-edges.api-surface:schedule-fields] The accepted values are in [The Service Edge auto-delete schedule resource documents frequency as days only, frequency_interval as 5, 7, 14, 30, 60 or 90 (minimum 5), and delete_disabled as whether Service Edges in a disconnected state are included for deletion.](kb:zpa.private-service-edges.groups:schedule-values); the default cadence is open [gap:zpa.private-service-edges.api-surface:schedule-default-cadence]. Provider defects in the schedule resource: [The schedule resource accepts any ID on import (passthrough importer), and its Read fetches the singleton schedule but never writes the singleton's ID back. Update then builds the PUT path from `d.Id()`.](kb:zpa.terraform.resource-fidelity:schedule-read-never-sets-id).

**Private Cloud Controllers.** Private Cloud Controller groups are listed and created at /privateCloudControllerGroup and read, updated and deleted by ID; Private Cloud Controllers are listed at /privateCloudController and read, updated and deleted by ID. [zpa.private-service-edges.api-surface:private-cloud-endpoints] Two SDK calls have no specification entry [gap:zpa.private-service-edges.api-surface:sdk-only-paths].

[The OpenAPI document gives POST on `/serviceEdgeSchedule` a 204 No Content response while also declaring a body schema for it (ScheduledConfigDTO), and the Python `update_service_edge_schedule` returns a stand-in object holding only the schedule ID when the response has no body.](kb:zpa.api.service-edges-wire:schedule-post-204-with-body-schema)

What to check:
1. Which endpoint the operation uses: instances under /serviceEdge, groups under /serviceEdgeGroup, auto-delete under /serviceEdgeSchedule, and Private Cloud Controllers under their own paths.
2. Whether an operation has no OpenAPI entry, so its behavior rests on the SDK alone.
