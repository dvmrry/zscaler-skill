# How App Connectors check and report application health, and what Continuous, On Access and None mean (zpa.app-segments.health-reporting)
Also called: health reporting; application health check; on access health reporting; none health reporting; health dashboard application

With Health Reporting enabled, the App Connector checks application reachability to the server on each TCP and UDP port in the application segment: for an FQDN it checks all the IP addresses returned by DNS resolution, for an IP address it checks only that address, for TCP access it uses a TCP 3-way handshake, and for UDP access it first performs ICMP-based checks and follows with a TCP-based check if the ICMP check is unsuccessful. [zpa.app-segments.health-reporting:check-method] In the documented example, with IP address 10.1.1.1, TCP port 80 and UDP port 3389, if jira.lanukcorp.com resolves to 10.1.2.1 and 10.1.2.2, the App Connectors for the application perform reachability checks to 10.1.2.1:80, 10.1.2.2:80, 10.1.1.1:80, 10.1.2.1:3389, 10.1.2.2:3389 and 10.1.1.1:3389. [zpa.app-segments.health-reporting:check-example]

**Reporting the result.** If the application reachability check is successful, the App Connector reports the application's health status as Up to the Private Access Central Authority, which uses that information to decide whether an App Connector should be used for accessing a requested application. [zpa.app-segments.health-reporting:up-reported-to-ca] Private Access can randomly select any App Connector in an App Connector group if at least one App Connector in the group has successfully reported reachability to the requested application. [zpa.app-segments.health-reporting:random-selection-in-group] Whether that selection is the same step as the proximity selection is open [gap:zpa.app-segments.health-reporting:selection-step].

**Rate.** App Connectors limit the number of checks to 20 checks per second, so 6,000 checks take 300 seconds, and Zscaler recommends configuring applications so that an App Connector does not have to perform more than 6,000 checks. [zpa.app-segments.health-reporting:check-rate] How often Continuous repeats its checks is open [gap:zpa.app-segments.health-reporting:continuous-interval].

**Modes.** With Continuous, the App Connector continuously performs checks and reports the reachability status of the application. The Health Reporting page says Continuous cannot be configured for application segments configured with more than 10 ports, or for application segments configured for application discovery (domain names in wildcard format or IP subnets such as *.safemarch.com or 10.122.0.0/16). [zpa.app-segments.health-reporting:continuous-mode] The Defined Application Segments page names a different set of excluded segments, so the exclusions are not settled: see the divergence in [Application segment settings that interact: health reporting, connector selection, CNAME, ICMP, encryption and anchoring](kb:zpa.app-segments.settings). With On Access, the App Connector attempts to report the reachability status of the application when a user attempts to access it and continues to check and report for up to 30 minutes after the last user accesses it; while it reports, the status shows Up or Down, and when it stops reporting the status is displayed as Unknown with a question mark icon. [zpa.app-segments.health-reporting:on-access] With None, the App Connector does not check and report reachability to the application, and Private Access assumes the application is always reachable through that App Connector and can select it; the page lists as reasons to use None reducing the number of checks, an application expected to always be reachable, and connecting to an extranet application. [zpa.app-segments.health-reporting:none-mode] Whether None is allowed on discovery segments is open [gap:zpa.app-segments.health-reporting:none-on-discovery].

**Extranet.** For Extranet, the health score represents the health of an IPSec connection between the extranet resource's (partner) data center and the Zscaler cloud; it is a cumulative score of all the components and functions for that connection, and the health of the application itself is not evaluated. [zpa.app-segments.health-reporting:extranet-health-score]

**Restrictions from other features.** If Multimatch is enabled, Health Reporting on an application segment can only be set to On Access or None, and an application with client hostname validation enabled to facilitate client-to-client remote assistance is not shown on the Health dashboard. [zpa.app-segments.health-reporting:multimatch-and-c2c] The Multimatch limits are also in [Multimatch prerequisites, restrictions and App Connector selection](kb:zpa.app-segments.multimatch-requirements).
