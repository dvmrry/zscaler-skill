# Private Service Edge groups: membership, software updates and version profiles (zpa.private-service-edges.groups)
Also called: pse group; private service edge group; pse software update schedule; upgrade_day; upgrade_time_in_secs; version profile private service edge; new release version profile; override_version_profile; pse auto delete; microtenant private service edge; zscaler managed pse group read only

A group is where a Private Service Edge's location, update window and software release track live.

**Membership.** Every Private Service Edge belongs to exactly one group; groups organize Private Service Edges by region or functional area, hold the location, the automated update schedule, the version profile and disaster recovery, and a new group can be created when a Private Service Edge is added with a new provisioning key. [zpa.private-service-edges.groups:group-membership] Private Service Edges that are managed by Zscaler are read only and cannot be configured; Private Service Edge groups that are managed by Zscaler are read only and cannot be edited or deleted. [zpa.private-service-edges.groups:zscaler-managed-read-only] Auto Delete removes stale members: Auto Delete removes disconnected, and optionally disabled, Private Service Edges after a set number of days. [zpa.private-service-edges.groups:auto-delete] The Service Edge auto-delete schedule resource documents frequency as days only, frequency_interval as 5, 7, 14, 30, 60 or 90 (minimum 5), and delete_disabled as whether Service Edges in a disconnected state are included for deletion. [zpa.private-service-edges.groups:schedule-values] The Terraform schedule resource has provider defects: [Up to v4.4.14, creating the Service Edge assistant schedule discarded the object the SDK returns from the POST, then stored the ID of the request as the resource ID. The request ID is read from the resource's own computed `id`. Only the already-exists branch set an ID taken from the server, by reading the singleton schedule. v4.4.15 fixes this for the Service Edge and the App Connector assistant schedules: create stores the ID of the schedule the POST returned (`created.ID`).](kb:zpa.terraform.resource-fidelity:schedule-create-discards-server-id), [Destroying the Service Edge assistant schedule resource makes no API call: the delete function returns nil. Terraform drops the resource from state while the remote schedule is untouched.](kb:zpa.terraform.resource-fidelity:schedule-delete-is-noop).

**Updates.** [When a new version is available, one component in the group is chosen at random and updated; it restarts and is temporarily unavailable, and new application access goes to the other components.](kb:zpa.app-connectors.upgrades:random-one-at-a-time) [The update runs in a 4-hour window that starts at the scheduled time; after one component succeeds another eligible one is chosen, until the window expires or every component in the group has updated.](kb:zpa.app-connectors.upgrades:four-hour-window) [An unsuccessful update is retried at every periodic update until all components are upgraded.](kb:zpa.app-connectors.upgrades:retry-next-window) [From App Connector and Private Service Edge version 24.650.4, a version check and automated upgrade run during the initial connection.](kb:zpa.app-connectors.upgrades:initial-connection-upgrade) A Private Service Edge shows Not Scheduled after creation, Partial Failure if a supporting file fails to update, and Restarting after it downloads a new version and restarts. [zpa.private-service-edges.groups:upgrade-status-values] In the Terraform schema, upgrade_day defaults to "SUNDAY" and upgrade_time_in_secs is a string attribute defaulting to "66600", with no validation. The docs describe the time as an integer in seconds, at least 0 and below 86400, in 15-minute intervals. [zpa.private-service-edges.groups:upgrade-defaults] The window's time zone is not stated [gap:zpa.private-service-edges.groups:upgrade-time-zone].

**Version profiles.** A version profile ties a group to a build: Default is the cloud-wide stable build, Previous Default is the prior stable build that gives rollback and is checked weekly for updates, New Release is the latest build and is checked daily, and Custom is a Support-provided build that may not be visible in the console. [zpa.private-service-edges.groups:version-profiles] The Terraform version_profile_name accepts Default, Previous Default, New Release, Default - el8, New Release - el8 and Previous Default - el8. [zpa.private-service-edges.groups:el8-names] The meaning of el8 is unverified [gap:zpa.private-service-edges.groups:el8-meaning]. A group's Persist Local Version Profile is labelled two ways: the version profile page gives Inherit, applying the customer-level profile, or Override, choosing a profile for that group; the Add Private Service Edge Group page gives Enable, if the group should persist the local Version Profile, with Disabled selected by default. [zpa.private-service-edges.groups:persist-local-version-profile] The Add page's default of Disabled against the schema default of true is open [gap:zpa.private-service-edges.groups:persist-default-wrinkle]. The Terraform default for override_version_profile disagrees with the provider documentation [divergence:zpa.private-service-edges.groups:override-version-profile-default]. What the field does when false is unverified [gap:zpa.private-service-edges.groups:override-profile-inheritance].

**The Add Private Service Edge Group form.** Adding a Private Service Edge group takes a name (no special characters other than periods, hyphens and underscores), an optional description, a Status (Enabled), Persist Local Version Profile (Disabled is selected by default), a Version Profile (default value Default), a Private Service Edge Software Update Schedule by day of the week and start time, and a location whose map marker fills the Latitude, Longitude and Location Address fields, with the country code shown. [zpa.private-service-edges.groups:group-form-fields] A Private Service Edge group can be associated with a Private Cloud for Business Continuity; if the Private Access cloud isn't available, its Private Service Edges contact the Private Cloud Controllers associated with the Private Cloud for the control channel, configuration updates and logging. [zpa.private-service-edges.groups:private-cloud-field] A Private Service Edge group's Alternative Cloud Domain field selects an Alternative Cloud Domain to override the default cloud domain for the group. [zpa.private-service-edges.groups:alternative-cloud-domain] What alternative cloud domains exist and their API field are open [gap:zpa.private-service-edges.groups:alternative-cloud-domain-details].

**Microtenants.** [To configure a Microtenant, App Connectors and Private Service Edges for Private Access must be running version 24.63.1 or later.](kb:zpa.microtenants.limits:connector-versions) [ZPA_MICROTENANT_ID sets the microtenant for resources in a run; the provider documents it as the recommended way to configure microtenant_id, which requires the microtenant license and feature flag on the tenant.](kb:zpa.terraform.provider-config:microtenant-env-var)

Selection settings on the group are in [How clients are steered to a Private Service Edge and which country policy applies](kb:zpa.private-service-edges.client-selection); disaster recovery designation is in [Disaster recovery mode and Private Service Edge groups](kb:zpa.private-service-edges.disaster-recovery).

What to check:
1. Whether an unchangeable group is Zscaler-managed, which is read only in the console.
2. Which version profile applies to the group and whether the group overrides the customer-level profile; read override_version_profile from the live group, not from the Terraform default.
3. Whether the update window has passed: the update runs in a 4-hour window from the group time, one Private Service Edge at a time, and failures are retried next period.
4. Whether a disconnected Private Service Edge was removed by the Auto Delete setting.
5. Whether Microtenant use requires a newer software version.

Sources disagree (name both sides):
- Default of override_version_profile on zpa_service_edge_group [divergence:zpa.private-service-edges.groups:override-version-profile-default]
  - tf-zpa: The provider documentation gives the default as false.
  - tf-zpa: The resource schema sets the default to true.
  Impact: A configuration that omits override_version_profile is planned with true; any wrapper or reading that assumes false will misstate which version profile a group follows.
