# Network Connector enrollment: OAuth 2.0 tokens and provisioning keys (zpa.vpn.network-connectors.enrollment)

A Network Connector can be deployed with OAuth 2.0 enrollment tokens or provisioning keys. The configuration guide's recommended method is an OAuth 2.0 enrollment token retrieved from the Network Connector's console. The VMware guide says the image attempts to use OAuth enrollment tokens by default but applies a provisioning key first if one is available. [zpa.vpn.network-connectors.enrollment:methods] To add a Network Connector with an OAuth enrollment token, the token is first taken from the Network Connector's virtual serial console. On the Add Network Connector page the admin selects an existing Network Connector group and the enrollment certificate as the Signing Certificate, and enters the copied token under Enrollment Tokens. The VMware guide says tokens are valid for 2 hours. [zpa.vpn.network-connectors.enrollment:oauth-add] The prerequisites article requires Manager software and Network Connector version 25.47.3 or later for OAuth 2.0 enrollment. It says the OAuth server only supports IPv4-based communication, so a Network Connector with only an IPv6 address cannot access it, and that if OAuth 2.0 is used the OAuth server FQDN zpa-oauth.private.zscaler.com must be in the allowlist. The AWS guide says OAuth 2.0 enrollment is unavailable with auto scaling. [zpa.vpn.network-connectors.enrollment:oauth-requirements]

**Provisioning keys.** A provisioning key is a text string generated when a new Network Connector is added, and the admin is prompted to enter it when deploying the Network Connector. It functions like an ID for the Network Connector, enabling the Private Access cloud to verify its authenticity and complete deployment. Each key is associated with a specific Network Connector group. [zpa.vpn.network-connectors.enrollment:key-what-it-is] Provisioning keys should be treated as secrets and properly protected because they can create a resource for a tenant, and the key must also be secured and not transmitted or stored in clear text. [zpa.vpn.network-connectors.enrollment:key-secret] View or Export Provisioning Key After Creation is enabled by default. Disabling it hides the key from the Provisioning Key column and disables copying or downloading it after creation, and the option cannot be enabled again after the key is saved. If the key does not appear and no backup is securely stored in an external credential vault, a new key must be generated, and it can be attached to the same Network Connector. [zpa.vpn.network-connectors.enrollment:key-hidden] A provisioning key is associated with a Network Connector group and a signing certificate, described as the enrollment (CA) certificate. All Network Connectors deployed with the key have their certificates signed with that signing certificate. [zpa.vpn.network-connectors.enrollment:key-signing-cert]

**On the connector.** The Linux guide has the admin create a provisioning key file with 644 permissions at /opt/zscaler/var/provision_key, and its echo example writes the key to that file with the key within double quotes. If the provisioning key was not detected when the Network Connector was first started, the Network Connector is in a sleep cycle and looks for the key again every 24 hours. [zpa.vpn.network-connectors.enrollment:key-file] The Linux guide says SSH is not enabled by default on Zscaler-provided virtual appliances and is required for a short time to configure the provisioning key. It says the admin credentials might take up to 15 minutes to apply after the initial boot, and has the admin disable SSH after the Network Connector is enrolled. [zpa.vpn.network-connectors.enrollment:ssh-for-key] The AWS guide says the domain in the provisioning key echo statement depends on which Private Access cloud the tenant is on. [zpa.vpn.network-connectors.enrollment:key-cloud-domain]

**Open.** Whether a key hidden at creation still has a row in the table differs between the pages [divergence:zpa.vpn.network-connectors.enrollment:hidden-key-in-table].

What to check:
1. Before telling an operator to use OAuth enrollment, check the connector and Manager version, IPv4 reachability of the OAuth server, the allowlist entry, and that AWS auto scaling is not in use.
2. Before disabling View or Export Provisioning Key After Creation, note the option cannot be re-enabled once the key is saved.

Sources disagree (name both sides):
- The help pages disagree on whether a provisioning key hidden at creation still has a row in the provisioning keys table. [divergence:zpa.vpn.network-connectors.enrollment:hidden-key-in-table]
  - zscaler-help: About Network Connector Provisioning Keys: the entry is blank when the option was disabled, which implies the row is still present.
  - zscaler-help: Editing Network Connector Provisioning Keys: only keys that can be viewed or exported after creation appear in the table.
  Impact: Whether an admin can still find and edit a key whose view and export was disabled depends on which page is right; the pages do not say which governs.
