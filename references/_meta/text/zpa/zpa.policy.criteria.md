# Criteria available on ZPA access policy rules (zpa.policy.criteria)
Also called: access policy criteria; zpa rule criteria; client types zpa policy; platforms zpa policy; country codes zpa policy; federated applications criteria; saml attributes for policy; chrome posture profile; criteria that cannot be combined

A rule matches only when its criteria all match, and the criteria have limits on how they combine.

**The criteria.** The help lists these access policy criteria: Adaptive Access Profiles, Applications, Branch Connector Groups, Chrome Enterprise Browser, Client Connector Posture Profiles, Client Connector Trusted Networks, Client Types, Cloud Connector Groups, Country Codes, Extranet, Federated Applications, Locations, Machine Groups, Platforms, Risk Scores, SAML Attributes, SCIM Attributes, SCIM Groups, Segment Groups, Tag Groups, Tag Value and Workload Groups. [zpa.policy.criteria:criteria-list] A user's application request must match all the conditions within a policy rule. [zpa.policy.criteria:all-criteria-must-match] A rule can include individual application segments as well as segment groups: segments are used to apply different policies to individual applications, and segment groups to give a set of users similar access across many applications. [zpa.policy.criteria:application-segments-criterion]

**Spellings.** The client type names differ between the help and the wire [divergence:zpa.policy.criteria:client-type-names]. The platform list differs too [divergence:zpa.policy.criteria:platform-values].

**Combination limits.** Web Browser rules cannot use posture or trusted network criteria: [Rules that use the Web Browser or Internet & SaaS Service Edge client types cannot also use posture profiles or trusted networks criteria, which only work with Client Connector.](kb:zpa.browser-access.policy:no-posture-with-web-browser). The Cloud Connector Groups criteria cannot be configured with the SAML and SCIM Attributes criteria. [zpa.policy.criteria:cloud-connector-groups-exclude-saml] A machine group needs the Machine Tunnel client type: [In the console, when a machine group is selected in an access policy or AppProtection policy rule, the Machine Tunnel client type is also required.](kb:zpa.machine-groups.policy-use:console-pairs-client-type). [gap:zpa.policy.criteria:workload-group-cloud-connector-client-type]

**On the global rules and policy groups page.** The page for those rules, whose feature is in limited availability [Global rules and policy groups for access policy are in limited availability, and the pages say to contact Zscaler Support to learn more.](kb:zpa.policy.policy-groups:limited-availability), adds these criteria limits. On the global rules and policy groups configuration page there is no limit to the number of adaptive access profiles that can be selected, and multiple profiles within a rule are joined by an OR Boolean operator by default, which can be toggled to AND. [zpa.policy.criteria:adaptive-access-profile-selection] On the global rules and policy groups configuration page the Adaptive Access Profile criteria is only supported with the Client Connector, Client Connector Partner, Cloud Browser, or Web Browser client types. [zpa.policy.criteria:adaptive-access-client-types] On the global rules and policy groups configuration page the Adaptive Access Profiles criteria cannot be configured with the Branch Connector Groups, Cloud Connector Groups, Locations, and Machine Groups criteria. [zpa.policy.criteria:adaptive-access-exclusions] On the global rules and policy groups configuration page the Cloud Connector Group criteria type cannot be configured with the SAML and SCIM Attributes or Adaptive Access Profiles criteria. [zpa.policy.criteria:cloud-connector-groups-exclude-adaptive] In the policy group instructions of the global rules and policy groups configuration page, a specific workload group is chosen from the drop-down menu to apply the rule action to, and if Workload Group is selected, Cloud Connector as a client type is required; a limited availability notice precedes the item. [zpa.policy.criteria:workload-group-needs-cloud-connector] On the global rules and policy groups configuration page, rules using the Web Browser or ZIA Service Edge client types additionally can't use posture profiles or trusted networks criteria. [zpa.policy.criteria:global-rules-no-posture-web-browser]

**More criteria on that page.** On the global rules and policy groups configuration page the External IAM IdPs criteria is the external IdP attribute configured in Authentication Service and is only supported for IdPs created in Authentication Service. [zpa.policy.criteria:external-iam-idp-criterion] On the global rules and policy groups configuration page the Extranet Location criteria chooses the extranet resource, extranet locations, and extranet location groups to which the policy rule applies; the locations and groups fields are only visible after an extranet resource is selected, and the criteria is not visible within a Microtenant. [zpa.policy.criteria:extranet-location-criterion] On the global rules and policy groups configuration page the Locations criteria lists the location types BC (Branch Connector), CC (Cloud Connector) and NONE (locations other than Branch Connector or Cloud Connector), where NONE location types are also used in Source IP Anchoring configurations in which traffic is routed from these locations to Private Access. [zpa.policy.criteria:locations-types]

**Country.** For Cloud Connectors, Source IP Anchoring traffic and Private Access multi-hop, the country criterion uses the last NATed layer 3 public IP address, so SIPA traffic takes its country from the Internet & SaaS Public Service Edge's public IP. [zpa.policy.criteria:country-last-nat-ip] Browser Access and PRA do not support it: [The Country Codes criteria type is not supported in Browser Access or Privileged Remote Access applications.](kb:zpa.browser-access.policy:country-codes-unsupported).

**Identity criteria.** Using the SAML NameID as a SAML attribute within access and timeout policy rules is not supported; the same value can be used by defining it as a user attribute. [zpa.policy.criteria:nameid-unsupported] If the IdP's SAML Attributes for Policy (or SCIM Attributes and Groups for Policy) setting is disabled but a rule has criteria of that kind, an OR operator skips those criteria and evaluates the other kind, while an AND operator makes Private Access not evaluate the rule at all. [zpa.policy.criteria:idp-policy-setting-disabled] Timing of SCIM data is in [SCIM sync timing before SCIM criteria are used](kb:zpa.policy.scim-sync).

**Federated and Chrome.** The guest partner criteria are in [Federated access policies support only these criteria for the guest partner: Client Type (only Client Connector), Client Connector Posture Profiles, Country Codes, Locations, Machine Groups, Platforms, Risk Scores, SAML and SCIM Attributes, and Trusted Networks.](kb:zpa.b2b-federation.access-policy:guest-criteria-limited). The help presents the Chrome posture profile as an option under Chrome Enterprise Browser, while the Terraform provider validates it as the separate object type CHROME_POSTURE_PROFILE. [zpa.policy.criteria:chrome-posture-profile-sub-option]

**Risk.** The Go SDK reads the valid risk score values from `GET .../riskScoreValues`, with an optional `excludeUnknown` flag. [zpa.policy.criteria:risk-score-values-call]

The AND and OR logic is in [Boolean logic and operand forms of ZPA policy conditions](kb:zpa.policy.conditions).

What to check:
1. Which criteria the rule uses, and whether the request must match every one of them.
2. If the rule is scoped on application segments, remember that a rule may name individual segments as well as segment groups.
3. If a country criterion is used with Source IP Anchoring, Cloud Connector or multi-hop traffic, check which public IP the country is derived from, and that the application is not Browser Access or PRA.
4. If a rule has SAML or SCIM criteria, check the IdP's SAML Attributes for Policy and SCIM Attributes and Groups for Policy settings.
5. If a rule seems unable to combine two criteria, check the combinations the help rules out.
6. If a rule uses Adaptive Access Profiles, check its client types and that it does not also use the criteria the global rules page rules out.
7. When matching a client type or platform name between the console and an export, compare all the spellings the sources use.

Sources disagree (name both sides):
- The About Access Policy article, the Configuring Access Policies article, the global rules and policy groups configuration article and the wire values name client types differently. [divergence:zpa.policy.criteria:client-type-names]
  - zscaler-help: Nine types, ending Web Browser, Internet & SaaS Service Edge and Extranet, with no Cloud Browser.
  - zscaler-help: The list includes Cloud Browser and names the service edge type ZIA Service Edge.
  - zscaler-help: The global rules and policy groups page lists eight client types: Client Connector, Client Connector Partner, Cloud Browser, Cloud Connector, Branch Connector, Machine Tunnel, Web Browser and ZIA Service Edge, so like the Configuring Access Policies article it includes Cloud Browser and names the service edge type ZIA Service Edge.
  - mcp-server: The wire values are zpn_client_type_* strings. Pairing browser_isolation, ip_anchoring and edge_connector with the console's Cloud Browser, service edge and Cloud Connector is an inference; no source states the mapping.
  Impact: A rule exported from the API cannot be matched to console wording by name alone, and the two articles disagree on whether Cloud Browser is a type.
- The About Access Policy article omits iOS from the platform list, while the configuration article and the MCP skill include it. [divergence:zpa.policy.criteria:platform-values]
  - zscaler-help: Four platforms: Windows, macOS, Linux and Android.
  - zscaler-help: Five platforms, with iOS.
  - mcp-server: The wire lhs values are linux, android, ios, mac and windows.
  Impact: Whether iOS can be targeted by a Platforms criterion depends on which article is read.
