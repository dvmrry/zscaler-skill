# ZPA application segments (zpa.app-segments)
Also called: application segment; app segment; which application segment handles this request; overlapping application segments; zpa application segment matching; app segments; application segments

"Which application segment handles this request, and how is it configured?" splits into the questions below.

1. **Which segment is picked when several cover the destination?** Granularity, port misses and carve-outs: [Which application segment a destination maps to when several overlap](kb:zpa.app-segments.matching), with the exact-match behavior itself in [Segment matching and policy search with and without Multimatch](kb:zpa.policy.multimatch).
2. **Does the Bypass setting override that?** [The application segment Bypass setting and how it ranks](kb:zpa.app-segments.bypass).
3. **Can one request match more than one segment?** Multimatch consistency and examples in [Multimatch: one request matching several application segments](kb:zpa.app-segments.multimatch), its prerequisites and restrictions in [Multimatch prerequisites, restrictions and App Connector selection](kb:zpa.app-segments.multimatch-requirements).
4. **What may a segment contain and which settings interact?** Entries, ports and wildcards in [What an application segment can contain: entries, wildcards and ports](kb:zpa.app-segments.definition); health reporting, connector selection, CNAME, ICMP, encryption and anchoring in [Application segment settings that interact: health reporting, connector selection, CNAME, ICMP, encryption and anchoring](kb:zpa.app-segments.settings).
5. **How do health checks, Double Encryption and discovery work?** Health Reporting modes and the check mechanism: [How App Connectors check and report application health, and what Continuous, On Access and None mean](kb:zpa.app-segments.health-reporting). Double Encryption: [What Double Encryption does, when to use it and what it costs](kb:zpa.app-segments.double-encryption). Application discovery and the 14-day widget: [How application discovery works and how a discovered application is defined](kb:zpa.app-segments.discovery). DNS search domains: [What DNS search domains do for application segments and how they must match](kb:zpa.app-segments.dns-search-domains).
6. **Can a segment hold patterns, or route by CNAME?** Asterisk and question-mark patterns in FQDNs: [What pattern matching in FQDN application segments is, its characters, limit and prerequisites, and how it picks App Connectors](kb:zpa.app-segments.pattern-matching). Private link resources matched by returned CNAME: [How private link domains route CNAME-matched traffic to private link resources](kb:zpa.app-segments.private-link-domains).
7. **How are segments created in bulk, recommended or labeled?** AI-powered recommendations: [AI-powered recommendations for application segments: prerequisites, reading a recommendation and settings](kb:zpa.app-segments.ai-recommendations). CSV import and merge: [Application Segment Import: the CSV template, limits, re-import and merge](kb:zpa.app-segments.import). Namespaces and tags: [Tag Management for application segments: namespaces, tags and tag groups](kb:zpa.app-segments.tags). The Defined Application Segments page, with its delete and edit locks: [The Defined Application Segments page: delete and edit locks, status, configuration warnings and filters](kb:zpa.app-segments.admin-console).
8. **What do the API and SDK fields look like?** [Application segment fields in the API and SDK models](kb:zpa.app-segments.api-fields), with move and share in [Sharing and moving between Microtenants](kb:zpa.microtenants.share-and-move).
9. **How are common enterprise applications set up?** Unified communications, FTP, RDP, file servers, Citrix, Configuration Manager, SAP and others: [Configuring application segments for specific enterprise applications: unified communications, FTP, RDP, DFS with Kerberos, Windows domain join, Citrix, GPO, Configuration Manager, IWA with Kerberos reauthentication and SAP](kb:zpa.app-segments.enterprise-apps).
10. **Can a segment reach a user's device instead of a server?** Client-to-client and server-to-client connectivity and the Zscaler IP ranges: [Peer-to-peer connectivity: client-to-client and server-to-client remote assistance, their requirements and setup, and Client Connector IP assignment](kb:zpa.peer-to-peer).
11. **Which tool defects change what is sent?** [What the Python and Go SDKs send for application segments](kb:zpa.app-segments.sdk-behavior), [How the Ansible Browser Access, PRA and Inspection modules reconcile child applications](kb:zpa.app-segments.ansible-children) and the Terraform lifecycle in [What the ZPA Terraform provider sends, keeps and cleans up for application segments and their associations](kb:zpa.terraform.app-segment-lifecycle).

Every segment belongs to a segment group: [ZPA segment groups](kb:zpa.segment-groups). After the segment is chosen, access policy decides whether the request is allowed: [Evaluation order across ZPA policy types](kb:zpa.policy.evaluation-order).
