# Usage insights: policy and segment usage, user-group relationships and quarterly reports (zpa.policy.usage-insights)
Also called: usage page; policy usage report; application segments usage; application and user group relationships; qbr report; where are my apps being served from

Usage insights are the console reports on how users and applications use Private Access. The Usage page provides insights into an organization's usage patterns between users and applications, which can be categorized by application segment, segment group or user group. The page says to review the patterns to design better access policy rules and to download reports of private application usage on a quarterly cadence. [zpa.policy.usage-insights:what-it-is] The rules they inform are in [ZPA policy evaluation](kb:zpa.policy), and the objects they categorize in [ZPA application segments](kb:zpa.app-segments) and [ZPA segment groups](kb:zpa.segment-groups).

**Policy usage.** Policy Usage categorizes users, based on the number of unique users (more than zero) against each access policy rule, into 1 of 10 percentage bars, and each bar indicates a tenth percentage of access policy rules based on usage. Its widgets display the number of most used and the number of least used access policy rules, the latter including unused ones, and a table gives each rule's unique users and Private Access transactions. [zpa.policy.usage-insights:policy-usage] A policy usage report automatically expires after 90 days and cannot be run when there is no more data to add after a recent update. Run Report is disabled for 72 hours before and after 12:00 AM on the first Saturday of every month because of scheduled automatic reports, and customers with the Segmentation Add-On feature can generate one report per day while others can generate one every 90 days. [zpa.policy.usage-insights:run-report] The details report for an access policy automatically refreshes every 30 days. No data is shown for an access policy or an application segment that has had no usage within the time range. [zpa.policy.usage-insights:usage-details]

**Application segments.** Application Segments Usage reports default to a 14 Days time range. An application accessed through different ports or protocols is counted separately for each, the table counts the access policy rules that allowed access to the segment, and a chart shows the top 10 application segments by discovered host count. [zpa.policy.usage-insights:segments-usage]

**Relationships.** Application and User Group Relationships give insight into the relationships of application and user groups to ensure least privileged access. Excluding multiple items uses OR logic, excluding Branch and Cloud Connector access policy rules is supported only for Application Segments, the maximum number of reports to retain is chosen (for example 4, 5 or 6) with older reports deleted, and a SCIM Attribute value can be selected. [zpa.policy.usage-insights:relationships] Only customers with the Segmentation Add-On can generate detailed report views for the last 6 reports (180 days). The sunburst chart shows the remaining items as Others when there are more than 10 for the top inner ring or items are excluded, a maximum of 10 items can be selected, and an application whose ports cannot be classified shows type Unknown, for up to 14 days until classified. [zpa.policy.usage-insights:relationships-reports]

**Quarterly reports.** A new QBR report is generated on the first weekend of every month, or the following weekend if the first weekend falls on the first or second day of the month. The reports are stored as PowerPoint files in the Zscaler cloud, displayed for the last 3 years with up to 12 stored, and give the quarterly overview of the top 10 application segments and data transfer in TBytes. [zpa.policy.usage-insights:qbr] The Where are my apps being served from? page shows hosting providers and details of the App Connectors that have been serving applications for the last quarter, generated on the same schedule as the quarterly business reports. Private applications are filtered by AWS, Azure, Google Cloud or Data Center with at least one selected, and Zscaler uses the user device's location service to determine the general vicinity of the application's location. [zpa.policy.usage-insights:hosting-detection] When hosting provider details are not determined, Unknown appears next to the private application's name in the Bar and Map views. For accurate location tracking for data center environments, the App Connector group's Hosting Detection is set to Manual with host data center information selected or entered. [zpa.policy.usage-insights:hosting-unknown] The reports are called quarterly but generated monthly [gap:zpa.policy.usage-insights:qbr-period].

**Distribution.** Detailed insights report distribution to the organization's cloud storage is configured under Cloud Configuration with a Bucket Name, Region and IAM Role ARN. For an AWS bucket the name should always be ZscalerInsightsReportRole, and Zscaler recommends rotating Microsoft Azure and Google Cloud credentials every 3 months. [zpa.policy.usage-insights:report-distribution] Which object the AWS name belongs to is open [gap:zpa.policy.usage-insights:aws-role-name].

What to check:
1. Whether a missing policy usage report is the 72-hour Run Report window around the first Saturday of the month, or the 90-day and one-per-day report limits.
2. Whether a rule or segment showing no usage data had no usage in the selected range.

Not known (open gaps):
- Whether the AWS name ZscalerInsightsReportRole is the bucket name or the IAM role name [gap:zpa.policy.usage-insights:aws-role-name]: settled by support-ticket or lab-test
- What period a QBR report covers [gap:zpa.policy.usage-insights:qbr-period]: settled by support-ticket or tenant-data
