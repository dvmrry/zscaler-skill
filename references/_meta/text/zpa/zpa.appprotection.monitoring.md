# AppProtection dashboards and diagnostics: violations, API protection, Protocol Discovery and MITRE ATT&CK (zpa.appprotection.monitoring)
Also called: appprotection dashboard; api protection dashboard; protocol discovery dashboard; appprotection diagnostics; mitre att&ck appprotection

These are the console views of AppProtection results, as opposed to the LSS log type in [Where AppProtection events go: the LSS log type and its fields](kb:zpa.appprotection.logging). The controls they report on are in [AppProtection controls: kinds, OWASP groups and versions](kb:zpa.appprotection.controls), and the Active Directory dashboard is in [Active Directory controls: Kerberos, SMB and LDAP inspection](kb:zpa.appprotection.active-directory).

**Dashboard.** The AppProtection dashboard shows data over 1 Hour to 14 Days or a Custom Range, with the end date set to the current time, by default the last hour. Its log information is limited to 14 days, with LSS for longer access, and a minimum of 4 and a maximum of 8 charts can be selected. [zpa.appprotection.monitoring:dashboard-range] The AppProtection dashboard categorizes security violations in the selected time frame by the ThreatLabZ, WebSocket and OWASP predefined top 10 control categories and by severity (Critical, High, Medium, Low). It shows the transaction distribution of traffic with and without violations, and lists top control violations in the ControlNumber:ControlName format. [zpa.appprotection.monitoring:dashboard-widgets]

**Diagnostics.** AppProtection diagnostics count transactions with security profile violations and transactions with no security profile violations. [zpa.appprotection.monitoring:diag-counters] AppProtection diagnostics can filter logs by the control violation action (Allow, Block or Redirect) and by API Discovery, where the API Request and API Discovery filters can be set to True or False. [zpa.appprotection.monitoring:diag-filters] The diagnostics page describes sensitive information entries including AWS-ACCESS-KEY (access key for AWS), CREDIT-CARD (credit card number), GCP-API-KEY (API key for Google Cloud database), CPF (Brazilian CPF number), FACEBOOK-ACCESS-TOKEN (access token for Facebook) and SSN (Social Security number). [zpa.appprotection.monitoring:diag-sensitive-types] An AppProtection diagnostics transaction shows processing times in milliseconds, an Execution Flow of multiple AppProtection control violations in a profile listed in chronological order by number, name, action, severity and category, whether the profile was SSL inspected, and the HTTP response code to the web request. [zpa.appprotection.monitoring:diag-fields] If access is blocked by control 200005, the help says to edit the specific AppProtection profile, click Next on each tab without editing anything, and click Save, then repeat for the other AppProtection profiles to avoid the same control violation. [zpa.appprotection.monitoring:control-200005]

**API Protection.** The API Protection dashboard allows a minimum of 4 and a maximum of 7 charts. It shows recent API activity with sensitive information categories (US Social Security numbers, Brazilian CPF numbers and credit card numbers) and the top 10 API methods, and Zscaler stores only the category and how frequently it appeared. Its tab on the Active Directory Protection dashboard is visible only if the feature is enabled in the account. [zpa.appprotection.monitoring:api-protection]

**Protocol Discovery.** The Protocol Discovery dashboard displays the protocols KRB, LDAP, SMB, HTTP and TLS detected for domains in application segments with AppProtection disabled, up to a domain's 100 most recent transactions and 6,000 application segments for the time range. Its time range is 1 hour to 7 days, with a Custom Range start date within the last 7 days, and items selected for inspection are removed from the widget after inspection is enabled. [zpa.appprotection.monitoring:protocol-discovery] Protocol Discovery diagnostics logs are generated for domains with KRB, LDAP, SMB, TLS and HTTP traffic and are counted for application segments configured for TCP and UDP ports. An entry's Traffic Class is Classified if the App Connector identified the protocol and Unclassified if it could not. [zpa.appprotection.monitoring:protocol-discovery-diag] The diagnostics article describes the segments in two ways [divergence:zpa.appprotection.monitoring:protocol-discovery-scope]. Enabling AppProtection from the dashboard is in [Enabling AppProtection on an application segment](kb:zpa.appprotection.segment-opt-in).

**MITRE ATT&CK.** The MITRE ATT&CK page shows the framework with all the TTPs that show any misconfiguration of policies, application segments, AppProtection profiles and Browser Protection profiles in Private Access. Tiles highlighted in blue are covered by Zscaler protection, and a green, red or orange color at their right side indicates whether the protection is configured, misconfigured or not configured at all. [zpa.appprotection.monitoring:mitre] The meaning of the tile side colors is open [gap:zpa.appprotection.monitoring:mitre-colors].

What to check:
1. Whether traffic blocked by control 200005 is cleared by re-saving each AppProtection profile as the help describes.
2. Whether a missing API Protection tab is because the feature is not enabled in the account.

Sources disagree (name both sides):
- The Protocol Discovery diagnostics article describes its data as for ports enabled with application segments associated with AppProtection, and its default log count as for domains with application segments that have AppProtection disabled. [divergence:zpa.appprotection.monitoring:protocol-discovery-scope]
  - zscaler-help: Diagnostics data is for the ports enabled with application segments associated with AppProtection.
  - zscaler-help: The default table counts Protocol Discovery logs generated for domains with application segments that have AppProtection disabled.
  Impact: Whether Protocol Discovery covers segments with AppProtection disabled, enabled, or both is not settled by the pages.

Not known (open gaps):
- Which tile color means configured, misconfigured or not configured [gap:zpa.appprotection.monitoring:mitre-colors]: settled by lab-test or tenant-data
