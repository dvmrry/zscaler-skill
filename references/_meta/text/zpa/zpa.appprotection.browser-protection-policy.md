# Browser Protection policy rules and profiles: actions, criteria and fingerprint settings (zpa.appprotection.browser-protection-policy)
Also called: browser protection policy; browser protection profile; continuous fingerprint; session fingerprint timeout; monitor or do not monitor

Browser Protection policy rules set up Browser Protection for designated browsers and operating systems: a rule monitors and fingerprints users' browser access sessions based on specific criteria (application segments and SAML and SCIM attributes) and applies a previously created Browser Protection profile with the attributes used to create a fingerprint. [zpa.appprotection.browser-protection-policy:rules-purpose] A Browser Protection profile consists of selected browser and operating system attributes: it curates the attributes used to create a unique browser fingerprint for each user's browser access session (for example OS name, browser engine version, user agent string and geolocation), excludes the attributes that should not be used, and is then added to a Browser Protection policy for Private Access to use. [zpa.appprotection.browser-protection-policy:profile-purpose] Browser Protection is not supported with Isolation. [zpa.appprotection.browser-protection-policy:no-isolation]

**Rules.** A Browser Protection rule's action is Monitor or Do Not Monitor, and the rule names a Browser Protection profile, which the page calls a security profile with a set of common or control-specific actions. [zpa.appprotection.browser-protection-policy:rule-action] A user's application request must match all the conditions within a Browser Protection policy rule, the rules use AND and OR operators, and Private Access applies them in the order they are listed. [zpa.appprotection.browser-protection-policy:criteria-all-match] A rule's criteria are the application segments and segment groups, Client Types, SAML and SCIM Attributes or Session and User Attributes, an External IAM IdP, and User Portals. Applications and User Portals cannot both be selected on one rule. [zpa.appprotection.browser-protection-policy:rule-criteria] The Browser Protection Policy page can be filtered to the rules associated with one Browser Protection profile, by selecting the profile under General Profile Settings. [zpa.appprotection.browser-protection-policy:filter-by-profile] A Browser Protection rule name cannot contain special characters except periods, hyphens and underscores. [zpa.appprotection.browser-protection-policy:rule-name-characters]

**Criteria operators.** What a rule does when a SAML or SCIM criterion is used under AND and the identity provider's setting is disabled differs between the pages [divergence:zpa.appprotection.browser-protection-policy:scim-and-disabled].

**Profiles.** A profile's criteria are Browser attributes, Operating System attributes, and a Collect Location (Use for Fingerprint) checkbox that captures the monitored user's geolocation. [zpa.appprotection.browser-protection-policy:profile-criteria] In a profile's Timeouts section, Continuous Fingerprint continuously monitors the users' browser access fingerprints during a session and is disabled by default. Its time interval is the minimum time before the next fingerprint is captured again for a domain, with a default of 5 minutes and a maximum of 24 hours, and the profile list shows it as the Session Fingerprint Timeout. [zpa.appprotection.browser-protection-policy:continuous-fingerprint] An existing Browser Protection profile can be copied to create a new one. [zpa.appprotection.browser-protection-policy:profile-copy] A Browser Protection profile name cannot contain special characters except periods, hyphens and underscores. [zpa.appprotection.browser-protection-policy:profile-name-characters]

The dashboard and Clientless Access diagnostics that show the fingerprints are in [Browser Protection: monitored users, browser fingerprints and Clientless Access diagnostics](kb:zpa.appprotection.browser-protection); the subscription dependence is in [Which AppProtection capabilities depend on the subscription](kb:zpa.appprotection.entitlement). The client types a rule accepts, the attribute lists and the limits are open [gap:zpa.appprotection.browser-protection-policy:client-types] [gap:zpa.appprotection.browser-protection-policy:attribute-lists] [gap:zpa.appprotection.browser-protection-policy:limits].

What to check:
1. Whether the rule's action is Monitor or Do Not Monitor and which profile it names.
2. Whether Applications and User Portals are both selected on one rule, which the console does not allow.
3. Whether a rule uses SCIM or SAML criteria under AND with the identity provider's setting disabled, and which page's wording is relied on.
4. Whether the Continuous Fingerprint timeout explains how often fingerprints are collected for a domain.

Sources disagree (name both sides):
- On the Browser Protection configuring page, SCIM criteria under AND with the identity provider's setting disabled are said to be evaluated, while the same page says SAML criteria under AND are not evaluated and the client forwarding page says SCIM criteria under AND are not evaluated. [divergence:zpa.appprotection.browser-protection-policy:scim-and-disabled]
  - zscaler-help: Browser Protection page, SCIM under AND: Private Access evaluates the rule, yet the admin must remove the SCIM criteria for it to process the rule.
  - zscaler-help: Browser Protection page, SAML under AND: Private Access does not evaluate the rule.
  - zscaler-help: Client forwarding page, SCIM under AND: Private Access does not evaluate the rule.
  Impact: The Browser Protection page's SCIM wording contradicts its own instruction to remove the criteria and the two sibling statements, so whether such a rule is evaluated or skipped is not settled by the pages.
