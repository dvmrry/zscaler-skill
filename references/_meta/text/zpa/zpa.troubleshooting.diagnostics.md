# ZPA Live Logs and Private Diagnostics: views, time ranges, retention, filters and export (zpa.troubleshooting.diagnostics)
Also called: zpa live logs; private diagnostics; zpa diagnostics console; zpa diagnostics export; zpa extended log search

Live Logs shows real-time events for user activity, user status, application activity and App Connector status, and a Private Service Edge Status page; past events for this data are viewed in Diagnostics. [zpa.troubleshooting.diagnostics:live-vs-past] A Live Logs chart tracks up to 100 of the latest activity logs and updates when Public or Private Service Edges record new logs; the table shows no data by default, and every click on New Logs refreshes the table and removes the older logs. [zpa.troubleshooting.diagnostics:live-chart-100] For troubleshooting, Zscaler recommends filtering Live Logs by User and Application to avoid viewing irrelevant logs, because many applications, users and App Connectors can produce a lot of logs. [zpa.troubleshooting.diagnostics:live-filter-advice]

**Ranges and retention.** The User Activity and User Status diagnostics show events of the last 24 hours by default. On the User Activity diagnostics page a Custom Range start date must be within the last 14 days. [zpa.troubleshooting.diagnostics:default-range] The Live Logs page says Zscaler retains User Activity, User Status and App Connector log information for rolling periods of at least 14 days, and Audit log information for at least 6-month periods, during the subscription term. [zpa.troubleshooting.diagnostics:live-retention] The User Activity diagnostics page says Zscaler retains logs for rolling periods of up to 6 months depending on the subscription, and that a Custom Range can search data within the past 6 months of the current date, beginning from the moment of feature enablement. It adds, under the condition 'When the date range exceeds 14 days:', that not all the log fields are populated and that metrics including aggregates and trends are not available, and that this feature and its procedures are in limited availability. [zpa.troubleshooting.diagnostics:extended-search-la] The Clientless Access diagnostics page gives the at-least-14-days retention statement, while the Chrome Enterprise Browser page gives both the at-least-14-days and the up-to-6-months statements. [zpa.troubleshooting.diagnostics:retention-wording-varies] The 6-month search conflicts with the 14-day Custom Range start on the same page and the 14-day limit on the export page [divergence:zpa.troubleshooting.diagnostics:custom-range-6-months-vs-14-days], and with the Log Streaming Service article's 14 days in the console [divergence:zpa.troubleshooting.diagnostics:console-retention-vs-lss]. Data in the dashboard might be more recent than the data presented within Diagnostics for the same time range. [zpa.troubleshooting.diagnostics:dashboard-fresher]

**Filters and tables.** The Diagnostics settings select the default filter operator, Equals or Contains, with Equals the default, and the selected operator is saved for future sessions. [zpa.troubleshooting.diagnostics:filter-operator-setting] In the User Activity diagnostics query builder, filters using the Contains operator allow at most 7 entries, multiple text entries are separated by a semicolon, the Username filter takes up to 5 usernames, and another admin can paste a copied query by clicking the Clipboard icon. The App Connector Status diagnostics offer a Recent Filters icon for the last 5 applied filters, shown only if a filter has been applied. [zpa.troubleshooting.diagnostics:query-builder-rules] With multiple text entries, a Less Than filter shows transactions starting from the largest entry provided and a Greater Than filter from the smallest entry provided. [zpa.troubleshooting.diagnostics:less-greater-ordering] The User Activity diagnostics table displays 20 transactions by default, and scrolling loads more. [zpa.troubleshooting.diagnostics:table-20-rows]

**Counters.** The User Activity diagnostics count the total number of application requests, Errors, Access Policy Blocks (blocked by an access policy rule), Timeout Policy Blocks (blocked by a timeout policy rule), Successful requests, and Info, the application connections that terminated because the user or App Connector abruptly ended the TLS session (for example a laptop entering sleep mode) or the connection gracefully timed out. [zpa.troubleshooting.diagnostics:ua-counters] The User Status diagnostics count the total number of authentication requests, access errors and successful authentication requests, and the App Connector Status diagnostics count App Connector access errors and successful App Connector requests. [zpa.troubleshooting.diagnostics:status-counters]

**The LSS client user.** The ZPA LSS Client user represents the LSS service, not an actual user; its diagnostic information is captured but not displayed by default, it must be selected explicitly in the User field to show its log information, and each log receiver is displayed as an application. [zpa.troubleshooting.diagnostics:lss-client-user]

**Exporting logs.** Diagnostics log data can be exported as a CSV file, with access governed by the organization's RBAC policies, for a maximum time range of 14 days even with an extended log retention policy. A tenant can generate up to 50 exports and 50 downloads per day; each export is limited to 10,000 entries and 200 MB, with a partial result if either limit is reached first, is processed in the background, and stays available for download for 72 hours before deletion. [zpa.troubleshooting.diagnostics:export-limits] In Manage Exports, downloading is available only for exports with the Ready to Download status and only failed exports can be retried; the Retry option can be used a maximum of 3 times. [zpa.troubleshooting.diagnostics:export-manage]

**Chrome Enterprise Browser.** The Chrome Enterprise Browser diagnostics show managed Chrome Enterprise Browser policy log data and trend data for past events. Its query builder filters include CrowdStrike Agent (Enabled or Disabled), Disk Encryption, Operating System, Safe Browsing Protection Level and Secure Boot Mode, each with a listed set of values, and the page points to the Chrome Verified Access API documentation. [zpa.troubleshooting.diagnostics:chrome-enterprise-log] A Chrome Enterprise Browser entry shows OS Firewall (enabled or disabled), Password Protection Warning Trigger (whether the feature is enabled or disabled), Key Trust Level and Device Affiliation IDs. Separately, a table-level Errors counter gives the total number of Chrome Enterprise browser errors. [zpa.troubleshooting.diagnostics:chrome-enterprise-fields]

**What an entry shows.** The fields of a User Activity entry are in [What a ZPA User Activity entry shows in Diagnostics and Live Logs](kb:zpa.troubleshooting.user-activity-diagnostics), those of a User Status entry in [What a ZPA User Status log record says and does not say](kb:zpa.logs.user-status) and those of the connector and Service Edge status entries in [ZPA status logs for connectors, Private Service Edges and Private Cloud Controllers](kb:zpa.logs.control-session-status). The VPN Diagnostics pages are in [VPN Connected Users and the VPN Diagnostics pages: user logs, traffic flow logs and access policy data](kb:zpa.vpn.diagnostics).

Sources disagree (name both sides):
- The User Activity diagnostics page's 6-month Custom Range search versus its 14-day Custom Range start and the export limit [divergence:zpa.troubleshooting.diagnostics:custom-range-6-months-vs-14-days]
  - zscaler-help: The User Activity diagnostics page says a Custom Range can search data within the past 6 months, in limited availability.
  - zscaler-help: The same page says a Custom Range start date must be within the last 14 days.
  - zscaler-help: The export page says an organization with extended log retention cannot retrieve data beyond 14 days when exporting.
  Impact: The page does not say which Custom Range limit applies to a tenant. Check the range the console accepts before telling an admin how far back a Diagnostics search reaches; an export is limited to 14 days in both readings.
- Console log availability of 14 days in the Log Streaming Service article versus up to 6 months in the Diagnostics pages [divergence:zpa.troubleshooting.diagnostics:console-retention-vs-lss]
  - zscaler-help: The Log Streaming Service article says that for access to logs beyond 14 days in the Admin Console, setting up LSS is necessary.
  - zscaler-help: The User Activity diagnostics page says Zscaler retains logs for rolling periods of up to 6 months depending on the subscription.
  Impact: Which statement holds for a tenant is not stated. Do not tell an admin that LSS is the only route to logs older than 14 days, or that the console keeps 6 months, without checking the tenant's console range and subscription.
