# Disaster recovery activation TXT records and the Zscaler DNS Record Generator (zpa.private-service-edges.disaster-recovery.dns-records)
Also called: dns record generator; disaster recovery txt record; dr txt record; signed dns txt record; unsigned dns txt record; dr_privatekey.pem

The Zscaler DNS Record Generator creates the DNS TXT records and the public and private keys for disaster recovery. The private key signs the DNS TXT record; the public key verifies the activation of Disaster Recovery Mode, is uploaded on the Disaster Recovery Settings page and when configuring Client Connector App Profiles, and a record used this way is a signed disaster recovery activation. For an unsigned activation the public key does not need to be uploaded, and for improved security Zscaler recommends signed DNS TXT records. [zpa.private-service-edges.disaster-recovery.dns-records:generator-role]

**The generator.** The Zscaler DNS Record Generator is only supported for Windows OS devices and must be run as an administrator. [zpa.private-service-edges.disaster-recovery.dns-records:windows-only] In the signed flow the generator writes the private key to Files/dr_privatekey.pem and the public key to Files/dr_publickey.pem; the DNS TXT records, keys and signatures are stored in the Files folder in the folder where the generator is downloaded. Its prompts offer Failopen (the traffic is sent directly) or Failclose (the internet access is disabled), Test to enable Disaster Recovery Test Mode, and Ignore to confirm no end time for disaster recovery. [zpa.private-service-edges.disaster-recovery.dns-records:generator-files] DNS TXT records can be created manually without the Zscaler DNS Record Generator, using a record format similar to the Domain Key Identified Mail (DKIM) record format. [zpa.private-service-edges.disaster-recovery.dns-records:manual-records]

**Record format.** The record tags are v, the version of the DNS record; b, which indicates whether Disaster Recovery Mode is enabled (on) or disabled (off), or Test Mode is enabled (test); m, the Internet & SaaS forwarding profile action, where the traffic is sent directly (fo) or internet access is disabled (fc); and t and x, the optional start and end times in UTC seconds. The activation type tag k supports zia, zpa and all. The tags n (total number of records for a multiple-part activation), p (which part) and bh (signed hash of tag values in RSA-SHA256 and Base64 formats) are only present for signed records. [zpa.private-service-edges.disaster-recovery.dns-records:tags] The activation type (k) supports zia (Internet & SaaS), zpa (Private Access) and all (both Internet & SaaS and Private Access). [zpa.private-service-edges.disaster-recovery.dns-records:activation-types] The Internet & SaaS forwarding profile actions (m) can be skipped if the Admin Console configuration should not be overwritten, and t and x can be skipped for both signed and unsigned activations if specific start and end times are not needed. A given tag is not shown if it does not have a value. [zpa.private-service-edges.disaster-recovery.dns-records:optional-tags] Invalid t, x, n, p and bh tags can cause disaster recovery activation to fail. [zpa.private-service-edges.disaster-recovery.dns-records:invalid-tags] Some tags used in the formats are not defined [gap:zpa.private-service-edges.disaster-recovery.dns-records:tag-definitions].

**Signed and unsigned.** Signed activation requires two parts of the disaster recovery activation TXT records. The body hash (bh) value is in Base64 format (2,048-bit keys signed with the RSA-SHA256 algorithm) and is obtained by concatenating the hash subparts in order; the v, b, t, x and n tags must match across the different DNS TXT records for their bh values to be combined. [zpa.private-service-edges.disaster-recovery.dns-records:signed-two-parts] The pages differ on how many records a domain needs [divergence:zpa.private-service-edges.disaster-recovery.dns-records:record-count]. Unsigned DNS TXT records are given in the format v=1;b=on|off|test;t=<start time>;x=<end time>. [zpa.private-service-edges.disaster-recovery.dns-records:unsigned-format] The unsigned format and its examples differ [divergence:zpa.private-service-edges.disaster-recovery.dns-records:unsigned-format-examples].

**Activation.** If the current epoch time configured in the DNS TXT record is between the start (t) and end (x) times, both values inclusive, disaster recovery is activated. If the record has no designated start and end times, disaster recovery is triggered as soon as the DNS TXT records are uploaded, and the DNS TXT record assigned to the disaster recovery domain name must be unique. [zpa.private-service-edges.disaster-recovery.dns-records:activation-window]

Disaster recovery mode itself, its settings and its snapshots are in [Disaster recovery mode and Private Service Edge groups](kb:zpa.private-service-edges.disaster-recovery); the Client Connector profile that carries the public key is in [App profile failover: disaster recovery, cloud unreachable, captive portals](kb:zcc.app-profiles.failover).

What to check:
1. Whether the record is signed, which needs two TXT records with matching v, b, t, x and n tags, or unsigned.
2. Whether the current epoch time falls between the record's t and x values, inclusive, and whether the domain's TXT record is unique.
3. Which m value a record uses: the page lists fo and fc as supported, and one of its examples gives m=wf.

Sources disagree (name both sides):
- One page says only one DNS TXT record is necessary per unique disaster recovery domain name; the generator page says signed activation requires two parts. [divergence:zpa.private-service-edges.disaster-recovery.dns-records:record-count]
  - zscaler-help: Only one DNS TXT record is necessary per unique disaster recovery domain name.
  - zscaler-help: Signed activation requires two parts of the disaster recovery activation TXT records.
  Impact: A signed activation can be read as one record or as two (n=2, p=1 and p=2); the pages do not say whether the one-record statement applies to unsigned records only.
- The generator page's unsigned format string has no k or m tag while its examples carry both, and one example gives m=wf while the supported m values listed are fo and fc. [divergence:zpa.private-service-edges.disaster-recovery.dns-records:unsigned-format-examples]
  - zscaler-help: Unsigned records are in the format v=1;b=on|off|test;t=<start time>;x=<end time>, with no k or m tag.
  - zscaler-help: The table's example unsigned record is v=1;k=zpa;b=on;m=fo, which carries k and m.
  - zscaler-help: A second example gives m=wf.
  - zscaler-help: The supported m values are fo and fc.
  Impact: The format string has no k or m tag and the examples carry both; one example's m=wf is not among the listed supported values. The page does not say which form a record takes.
