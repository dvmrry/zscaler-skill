# ZPA client forwarding policy rules: actions, precedence and criteria (zpa.policy.forwarding-rules)
Also called: client forwarding policy; bypass zpa; only forward allowed applications; forward to zpa; client forwarding rule criteria

Client forwarding policy rules define when application requests are forwarded to Private Access from Zscaler Client Connector. [zpa.policy.forwarding-rules:forwarding-purpose]

**The three actions.** If Bypass ZPA is selected, applications are marked and bypassed for Private Access and Zscaler Client Connector does not send their requests to Private Access; the setting is the equivalent of Always for the Bypass setting within an application segment, and it is not port specific, so the applications are bypassed on all ports. [zpa.policy.forwarding-rules:bypass-zpa-action] With Only Forward Allowed Applications, Zscaler Client Connector learns about and forwards traffic only for applications a user is allowed to access, a list the access policy determines and the service downloads to Client Connector when it sets up a connection to Private Access; requests for applications not on the list go out on the local network and are not logged in Private Access. [zpa.policy.forwarding-rules:only-forward-allowed] The page's example: when Only Forward Allowed Applications is set for a specific FQDN application segment (abc.example.com) whose access policy is Block, and a wildcard application segment (*.example.com) with an Allow access policy also exists, Client Connector still forwards traffic for abc.example.com to the Private Service Edge because it matches the wildcard domain, and the Private Service Edge then blocks the request under the more specific segment's block policy. [zpa.policy.forwarding-rules:wildcard-example] If Forward to ZPA is selected, Zscaler Client Connector forwards application requests to Private Access, including requests to applications the user is not authorized to access; it is selected by default. [zpa.policy.forwarding-rules:forward-to-zpa] The console names against the API names are in [Rule actions on ZPA policy types](kb:zpa.policy.actions).

**Precedence.** For application segments, the Bypass setting takes precedence over any new client forwarding policy rule. [zpa.policy.forwarding-rules:segment-bypass-takes-precedence] If there are multiple client forwarding policies with both Bypass ZPA and Forward to ZPA rules for a given domain with different ports, the Bypass ZPA rule action takes precedence. [zpa.policy.forwarding-rules:bypass-beats-forward-on-ports] Forwarding comes before access policy: [Client forwarding policy rules are evaluated before access policy rules, and a match in client forwarding policy makes Private Access disregard the other policy rules, including conflicts.](kb:zpa.policy.evaluation-order:client-forwarding-before-access).

**Source IP Anchoring.** For Source IP Anchoring, the client forwarding page's Rule 2 for domain-based applications enables the Forward to ZPA rule action for both Segment Groups and Client Types > ZIA Service Edge. [zpa.policy.forwarding-rules:sipa-rule-2] The other rule is described differently by two pages [divergence:zpa.policy.forwarding-rules:sipa-rule-1-client-types]. The Source IP Anchoring side is in [The client forwarding policy needs separate rules for IP-based and domain-based segments. IP-based: the Only Forward Allowed Applications action. Domain-based: Rule 1 Bypass ZPA for all client types except ZIA Service Edge, and Rule 2 Forward to ZPA for only the ZIA Service Edge client type.](kb:zia.forwarding-control.sipa:client-forwarding-policy).

**Criteria.** The client forwarding rule criteria cover SAML or SCIM criteria, an external IAM IdP, application segments and segment groups, Branch Connector groups, Client Connector Posture Profile condition sets, trusted networks, client types, Cloud Connector groups, Machine groups and platforms. [zpa.policy.forwarding-rules:criteria-list] On the client forwarding page the Cloud Connector Group criteria type cannot be configured with the SAML and SCIM Attributes criteria type, multiple Cloud Connector groups are joined by an AND Boolean operator, and a selected Machine group requires Machine Tunnel as a client type. [zpa.policy.forwarding-rules:criteria-combinations] The client types listed for a client forwarding rule are Branch Connector, Client Connector, Cloud Browser, Machine Tunnel, Web Browser and ZIA Service Edge, and rules using the Web Browser or ZIA Service Edge client types cannot also use the posture profiles or trusted networks criteria. [zpa.policy.forwarding-rules:client-types] The page says client forwarding policies must delegate each app profile to its intended trusted network. [zpa.policy.forwarding-rules:trusted-network-delegation] The page says users must be running Zscaler Client Connector version 2.1.0 to apply the trusted networks criterion to a policy rule. [zpa.policy.forwarding-rules:trusted-network-client-version] The 10-condition-set limit is in [The access global rules and policy groups, timeout, client forwarding and Browser Protection rule editors each say the criteria drop-down only displays criteria not already in use by the rule, except for Client Connector Posture Profile condition sets, and that up to 10 condition sets can be added; the redirection editor says the drop-down only displays unused criteria and up to 10 condition sets can be added, with no exception for posture stated.](kb:zpa.policy.conditions:condition-set-limit).

**Names and limits.** A client forwarding rule name cannot contain special characters except periods, hyphens and underscores. [zpa.policy.forwarding-rules:name-characters] The rule limits are not stated [gap:zpa.policy.forwarding-rules:forwarding-limits].

What to check:
1. Check the rule action, since Bypass ZPA keeps the application off Private Access on all ports and wins over Forward to ZPA on another port.
2. If a blocked application's requests still reach the Private Service Edge under Only Forward Allowed Applications, check for a wildcard application segment that allows it.
3. For Source IP Anchoring forwarding rules, compare both pages' descriptions of the Bypass ZPA rule before choosing its client types.
4. If a rule combines client types and criteria, check the combinations the page rules out.

Sources disagree (name both sides):
- The Source IP Anchoring configuring page and the client forwarding page describe Rule 1, the Bypass ZPA rule for domain-based applications, with different client types, and scope the IP address-based rule differently. [divergence:zpa.policy.forwarding-rules:sipa-rule-1-client-types]
  - zscaler-help: Rule 1 bypasses for the Source IP Anchoring segment groups with all client types except ZIA Service Edge, and the IP address-based rule is scoped to Source IP Anchoring application segments.
  - zscaler-help: Rule 1 bypasses for Segment Groups and the Client Connector client type, and the IP address-based rule is scoped to Source IP Anchoring segment groups.
  Impact: Following one page gives a Rule 1 for every client type except ZIA Service Edge, and following the other gives one for Client Connector only; the pages also differ on whether the IP address-based rule names application segments or segment groups.
