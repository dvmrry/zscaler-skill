# App Connector software and host OS updates (zpa.app-connectors.upgrades)
Also called: app connector upgrade; app connector software update schedule; app connector update failure; upgrade window 4 hour; app connector host os update; update now app connector; app connector version lag; 24.650.4

App Connector software is updated on a group schedule; the host OS is the customer's to patch.

**The scheduled update.** The software update day and time are set on the App Connector group (Update Settings, App Connector Software Update Schedule), and the group's Next Periodic Software Update column shows the result. [zpa.app-connectors.upgrades:schedule-per-group] When a new version is available, one component in the group is chosen at random and updated; it restarts and is temporarily unavailable, and new application access goes to the other components. [zpa.app-connectors.upgrades:random-one-at-a-time] The update runs in a 4-hour window that starts at the scheduled time; after one component succeeds another eligible one is chosen, until the window expires or every component in the group has updated. [zpa.app-connectors.upgrades:four-hour-window] An unsuccessful update is retried at every periodic update until all components are upgraded. [zpa.app-connectors.upgrades:retry-next-window] A connector still on an old version after the scheduled night is one the window did not reach or one whose update failed, and it is picked up in a later periodic update. [zpa.app-connectors.upgrades:leftover-after-window] Whether the window can be extended is unsourced [gap:zpa.app-connectors.upgrades:window-not-extendable].

**First connection and Support.** From App Connector and Private Service Edge version 24.650.4, a version check and automated upgrade run during the initial connection. [zpa.app-connectors.upgrades:initial-connection-upgrade] Zscaler Support may update a component before the next periodic update when its software is not functioning as expected, and informs the tenant's Private Access administrators in advance if an immediate software update is needed. [zpa.app-connectors.upgrades:support-may-update]

**Statuses and manual updates.** A component scheduled to update shows Scheduled; hovering shows the scheduled version and the 4-hour upgrade window, and an App Connector or Private Service Edge that has just been created starts at Not Scheduled. [zpa.app-connectors.upgrades:status-scheduled] Success means the component is on the scheduled version; Failure means the update failed and is retried in every periodic software update, and Zscaler recommends restarting the component's VM to recover. [zpa.app-connectors.upgrades:status-success-failure] Once a component is scheduled for an update, its periodic update time cannot be changed, but it can be updated manually before the scheduled time. Manual update (Update Now) is available only while the status is Scheduled. [zpa.app-connectors.upgrades:schedule-locks-component-time]

**When an update fails.** The help lists causes of an upgrade that stays failed for more than 24 hours: no disk space for the image, an unstable connection between the connector and co2br, and a provisioning key that was deleted in the Admin Console. [zpa.app-connectors.upgrades:failed-over-24h-causes] If none of those apply, the help restarts the connector, then checks logs and network connectivity, then removes the image, version and metadata files so it re-downloads the default version, then wipes and rebuilds the configuration. [zpa.app-connectors.upgrades:revert-to-default-version] Whether an upgrade preserves enrollment is unsourced [gap:zpa.app-connectors.upgrades:upgrade-keeps-enrollment].

**Host OS.** Zscaler updates the connector software, but updates to the host OS and software packages are the organization's responsibility; the software is designed to be compatible with host OS updates. [zpa.app-connectors.upgrades:host-os-is-customer-job] Automated OS security updates exist only for prebuilt App Connector images on RHEL 9.x; connectors installed from an RPM on a custom RHEL 9.x build are not supported. [zpa.app-connectors.upgrades:automated-os-updates-scope] Zscaler recommends updating the OS at least every 5 weeks and validating connectivity to the update servers; prebuilt images must be provisioned to a Private Access tenant to receive updates through the OS package manager. The captured procedure moves RHEL 9.4 and 9.5 to 9.6 and later. [zpa.app-connectors.upgrades:os-update-cadence] A host OS update is estimated at 20 minutes of downtime per component; all connectors in a group should not be updated at once, though several may be updated together if enough running connectors remain to carry the traffic. [zpa.app-connectors.upgrades:os-update-concurrency] Disabling the connector in the Admin Console before stopping its service stops new connections routing to it and lets existing ones finish; stopping the service first forces connection resets. [zpa.app-connectors.upgrades:disable-before-os-update]

**Migrating to RHEL 9.** The App Connector RHEL 9 migration page says to use a fresh install for all deployments, that the EL9 repository must be used with a RHEL 9 base OS and older platform binaries (EL7/EL8) are not supported, that /opt/zscaler/var must be empty before install, that yum upgrades from EL7/EL8 to RHEL 9 are not supported, and that only RHEL 9 repositories and RPMs are supported on RHEL 9. [zpa.app-connectors.upgrades:rhel9-migration-rules] The App Connector RHEL 9 migration page says to verify the version profile is set to Default, Previous Default or New Release, deploy new VMs from the RHEL 9 images with newly created provisioning keys, point the yum repository at https://yum.private.zscaler.com/yum/el9, add the new App Connector groups to each respective server group, optionally disable the App Connector groups 5 minutes before the regional off-hours maintenance window so connections gradually drain down, and remove the CentOS 7 App Connector groups during regional off hours. [zpa.app-connectors.upgrades:rhel9-migration-steps]

**Release artifacts.** The July 23, 2026 release summary lists an App Connector Docker image updated to use high ciphers for microdnf calls, and updated Red Hat Enterprise Linux 9 App Connector images for AWS, GCP, Microsoft Azure, Nutanix AHV and VMware that include a 4 GB boot partition, which exceeds Red Hat's recommendations to help support seamless OS updates. [zpa.app-connectors.upgrades:images-july23] The August 4 Manager software and RPM entry is not in the current capture [gap:zpa.app-connectors.upgrades:july-august-release-artifacts].

Group scheduling fields are in [App Connector groups](kb:zpa.app-connectors.connector-groups); the per-connector update status field is in [App Connector health, status values and telemetry](kb:zpa.app-connectors.health).

What to check:
1. The group's update day and time and whether the failed connector's component status reads Scheduled, Success or Failure.
2. Whether the update window ended before this connector was reached, before treating a lagging version as a fault.
3. For an update failed longer than 24 hours: disk space, the co2br connection, and whether the provisioning key still exists.
4. Whether a host OS update would take every connector in a group down at once.
