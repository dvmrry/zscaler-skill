# VPN Support Information: diagnostic sessions and commands on VPN Service Edges and Network Connectors (zpa.vpn.support-information)
Also called: vpn support information; vpn diagnostic session; vpn diagnostic sessions; crypto ping; vpn pcap; bgp diagnostic commands

VPN Support Information allows creating VPN diagnostic sessions that run commands on VPN Service Edges, Network Connectors and Network Connector groups, and then filtering and viewing the outputs of these sessions. [zpa.vpn.support-information:what-it-is] VPN diagnostics are supported on VPN Service Edge and Network Connector version 26.46.3 and later. [zpa.vpn.support-information:min-version] The App Connector, Private Service Edge and Private Cloud Controller counterpart is [ZPA Support Information sessions: remote commands on App Connectors, Private Service Edges and Private Cloud Controllers](kb:zpa.troubleshooting.support-information).

**Sessions.** By default the data for all users is displayed for diagnostic sessions that occurred in the last 14 days. If the Custom Range option is used, the start date must be within the last 6 months. [zpa.vpn.support-information:time-range] A VPN diagnostic session's status is Completed, Failed, Pending or Processing. Sessions with a Pending or Processing status auto-refresh every 60 seconds, statuses in the VPN Support Information table refresh every 45 seconds, and a JSON file of the session results can be downloaded. [zpa.vpn.support-information:session-status] The App Connector page's session statuses are in [A session's status is Pending, Processing, Completed, Failed, Cancelled or Partially_completed. Sessions can only be canceled in the Pending or Processing state, and sessions in those states auto-refresh every 60 seconds.](kb:zpa.troubleshooting.support-information:session-statuses). For Targets, the destination FQDN or IP address of the session is entered, with multiple hostnames separated by a comma and ports by a colon. [zpa.vpn.support-information:targets]

**Basic commands.** DNSLOOKUP A RECORD, AAAA RECORD and SRV RECORD resolve the respective record, and ports are not specified in DNS lookup commands. ICMP PING tests reachability of a host, TCP PING tests reachability to a port or range of ports for a list of hostnames or IP addresses, RESTART PROCESS restarts the VPN Service Edge or Network Connector process, and RESTART SYSTEM restarts the VPN Service Edge or Network Connector. Canceling a restart command in a Processing state is not supported, and restart commands cannot be run at the same time as a DNS lookup command or another restart command. [zpa.vpn.support-information:basic-commands] CRYPTO PING verifies connectivity between a VPN Service Edge and one or more Network Connectors. It is exclusive and cannot be run with other commands, and it can only be run from a VPN Service Edge. With it selected, the Targets field changes to NP Target Connector, where the destination Network Connector is selected. [zpa.vpn.support-information:crypto-ping]

**BGP commands.** START BGP starts BGP for the selected VPN Service Edge or Network Connector. STOP BGP and RESTART BGP stop and restart BGP for the VPN (for Legacy Apps) feature, STATUS BGP fetches the service status of BGP, RELOAD BGP CONFIG reloads the BGP configuration, and CLEAR BGP resets all BGP sessions, or a specific peer BGP session, forcing a BGP reconnection. [zpa.vpn.support-information:bgp-control] SHOW ROUTE displays all the routes, or routes for a target network, seen by the BGP service, with an optional argument of a valid IPv4 address with an optional CIDR range. SHOW INTERFACES displays all the interfaces or a specific target interface seen by the BGP service. SHOW BGP displays all routes, or routes for a specific target network, learned through the BGP service. SHOW BGP NEIGHBORS displays BGP neighbors with the status, connection details and prefixes exchanged, and SHOW BGP SUMMARY displays a summary of BGP sessions with connection state, uptime and prefixes advertised. [zpa.vpn.support-information:bgp-show] RUNNING CONFIG displays the currently running BGP configuration, FAILED CONFIG displays the last generated BGP configuration that failed to apply to the BGP service, and GENERATED CONFIG displays the last generated configuration. CONFIG VALIDATE triggers validation of the selected config mode (Generated or Override), CONFIG STATUS triggers the validation and provides the config status, CONFIG STATUS DETAILS triggers validation based on the current config mode and provides the detailed output, and GET LOGS fetches the logs of the BGP service. [zpa.vpn.support-information:bgp-config] RELOAD BGP CONFIG shows a Force option, with Disabled selected by default. CONFIG VALIDATE shows a Configuration Mode of Generated or Override, with Override selected by default. GET LOGS shows a Number of Lines field. [zpa.vpn.support-information:command-options]

**PCAP.** A maximum of one PCAP command per session is allowed, the maximum PCAP file size for a single session is 1 GB, and the maximum size of the individual PCAP files is 100 MB. For an FQDN argument the maximum allowed characters is 51. The Duration field, which appears only when a PCAP command is selected, takes a minimum of 30 seconds and a maximum of 5 minutes, with a default of 1 minute if no value is entered, and an Interface field limits the capture to a particular network interface. [zpa.vpn.support-information:pcap]

**JOURNALCTL.** For JOURNALCTL, the Log Type selects whether to return Service Logs or Full System Logs, Max Log Lines has a default of 1,000 and a maximum value of 100,000, and the maximum date and time is 4 hours from the current date and time. [zpa.vpn.support-information:journalctl] The compression and upload of the output is in [JOURNALCTL logs are in general compressed into an LZ4-formatted file and uploaded to an AWS S3 bucket; when compression is skipped (a log file below 4 KB, or the service unavailable when the log is fetched) the file is uploaded uncompressed as downloaded_file.log.](kb:zpa.troubleshooting.support-information:journalctl-output).

**Open.** The per-session limits, concurrent sessions and retention are open [gap:zpa.vpn.support-information:session-limits], and the page carries wording for other components [gap:zpa.vpn.support-information:copied-component-names].

BGP is in [BGP for VPN Service Edges and Network Connectors: AS numbers, failure detection, external routers](kb:zpa.vpn.bgp), the components in [VPN Service Edges: what they are, statuses, client IP pools, update schedule, BGP configuration mode and China](kb:zpa.vpn.service-edges), the console logs in [VPN Connected Users and the VPN Diagnostics pages: user logs, traffic flow logs and access policy data](kb:zpa.vpn.diagnostics) and the hub is [ZPA VPN (for Legacy Apps): what it is, its components and where each question goes](kb:zpa.vpn).

What to check:
1. Whether the VPN Service Edge and Network Connector are at version 26.46.3 or later before a VPN diagnostic session is expected to run.
2. Whether a restart command is queued with a DNS lookup or another restart, since they cannot run at the same time.
3. Whether CRYPTO PING is selected alone and from a VPN Service Edge.
