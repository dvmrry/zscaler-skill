# PRA live session sharing: participants, invitations, control and ejection (zpa.pra.live-sessions)
Also called: pra shared session; pra invite participant; pra session host; pra transfer control; pra eject participant; pra copy invitation; pra shared sessions section

The host of a live privileged session invites other users from within the session. After logging into a privileged console, a user can invite up to 10 additional participants into the live privileged session, and the user who started the session is the host by default. [zpa.pra.live-sessions:participants] An invitee is sent an email with a link to the PRA Portal and a direct link to the live privileged session, and after logging into the PRA Portal can click the console in the Shared Sessions section. The host can click Copy Invitation after clicking Invite to send a pasted link in addition to the automated email. [zpa.pra.live-sessions:invitation]

**Listing and joining.** Shared privileged sessions are listed at the top of the PRA Portal. A session for a console within a Microtenant shows the Microtenant name, one without a folder is from the Default tenant, and an end user can view only the sessions they have been given access to. [zpa.pra.live-sessions:shared-sessions-list] The host receives a notification when a participant joins, disconnects or rejoins. Disconnected participants show as Inactive in the Participants window, and participants who have left the shared session can rejoin. [zpa.pra.live-sessions:disconnect-rejoin]

**Control and removal.** A participant the host gives control to can use the mouse and keypad functions but cannot access clipboard and file transfer features, and the original host can no longer use the mouse or keypad, including the clipboard and file transfer features. The host regains control by clicking Control in the host box, and those functions are restored to the host. [zpa.pra.live-sessions:control-transfer] The host can click Eject in a participant's box to remove them from the privileged session. It can take a few seconds for the user to be ejected, and ejected participants cannot rejoin the same shared session unless they are reinvited. [zpa.pra.live-sessions:eject]

**Open.** How the invite flow ties to the consoles policy sharing modes, and several access and recording questions, are open [gap:zpa.pra.live-sessions:consoles-policy-tie].

The consoles policy that sets Share Sessions Mode and Join Sessions Mode is in [PRA consoles policy: file transfer, clipboard, recording and sharing](kb:zpa.pra.consoles-policy); the PRA Portal itself is in [PRA privileged portals and the PRA Portal: fields, certificates and DNS, what end users see, and console login](kb:zpa.pra.portals).

What to check:
1. Whether the policy rule gives the user a sharing mode before looking at the invitation, since the Accessing page does not link the invite flow to it.
2. Whether a participant who cannot use the clipboard or file transfer was given control, since the participant given control cannot use them.
3. Whether an ejected participant was reinvited.
