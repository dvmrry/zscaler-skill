# ZPA status logs for connectors, Private Service Edges and Private Cloud Controllers (zpa.logs.control-session-status)
Also called: zpn_ast_auth_log record; zpn_sys_auth_log record; app connector status log; private service edge status log; private cloud controller status log; ZPN_TUNNEL_CONTROL; ZPN_ASSISTANT_BROKER_CONTROL; TimestampUnAuthnetication; HostStartTime HostUpTime; ConnectionLogType

The App Connector, Private Service Edge and Private Cloud Controller Status logs share one shape: a control session with a Public Service Edge, a status, and a resource and interface snapshot. Their samples disagree with their tables in several places.

**Session and status.** For Private Service Edge Status and Private Cloud Controller Status logs the expected SessionType is ZPN_TUNNEL_CONTROL, the session from the Private Service Edge or Private Cloud Controller towards the closest Public Service Edge for Private Access; the App Connector Status value is ZPN_ASSISTANT_BROKER_CONTROL (see zpa.app-connectors.health). [zpa.logs.control-session-status:tunnel-control-session] Private Service Edge and Private Cloud Controller Status logs use the same three SessionStatus values as the App Connector Status log: ZPN_STATUS_AUTHENTICATED, ZPN_STATUS_AUTH_FAILED and ZPN_STATUS_DISCONNECTED, the last described as disconnected from a Service Edge for Private Access. [zpa.logs.control-session-status:tunnel-status-values] The App Connector values are in [App Connector health, status values and telemetry](kb:zpa.app-connectors.health). Whether records are also emitted periodically, beyond the authentication that [zpa.logs.control-session-status:emission-live] names, is open [gap:zpa.logs.control-session-status:emission-trigger], as is how to read a pattern of them [gap:zpa.logs.control-session-status:status-reading-guide].

**Timestamps.** The authentication timestamps are described in microseconds and shown as ISO strings, which the default templates produce with the :iso8601 modifier [divergence:zpa.logs.control-session-status:timestamp-format]. The App Connector Status example gives numeric fields such as CPUUtilization and ServiceCount as unquoted numbers and HostStartTime as a quoted string, whereas the App Connector Metrics example gives every value as a quoted string. [zpa.logs.control-session-status:samples-numeric-types] Whether the host time fields are start times or uptimes is open [gap:zpa.logs.control-session-status:host-time-meaning].

**Counters.** The status field tables describe BytesRxInterface as the bytes received on the interface and TotalBytesRx as the total bytes received, and in each status example TotalBytesRx is far smaller than BytesRxInterface: 10902554 against 319831966346 for the App Connector, 5257 against 15435341381 for the Private Service Edge, and 1835 against 65413384825 for the Private Cloud Controller. [zpa.logs.control-session-status:interface-vs-total-sample] What the totals count is open [gap:zpa.logs.control-session-status:total-bytes-scope]. The three status logs carry CPUUtilization and MemUtilization described only as the utilization in %, alongside interface byte, packet, error and discard counters; the App Connector Metrics CPUUtilization is instead the maximum CPU usage in the past 5 minutes. [zpa.logs.control-session-status:resource-fields-at-event] So each status record includes a resource snapshot: its CPU and memory utilization and interface counters as of that record. [zpa.logs.control-session-status:status-resource-snapshot] In the App Connector Status log ServiceCount is the number of services, meaning combinations of domains or IP addresses and TCP or UDP ports, being monitored by the App Connector. [zpa.logs.control-session-status:service-count-monitored]

**Private Service Edge and Private Cloud Controller field names.** The Private Service Edge example and default template carry fields the table lacks [divergence:zpa.logs.control-session-status:pse-sample-fields], and the table spells the unauthentication field differently from both [divergence:zpa.logs.control-session-status:unauthnetication-spelling]. The table's HostStartTime is HostUpTime in the default template [divergence:zpa.logs.control-session-status:pse-host-time-name], and the Private Cloud Controller template reads SiteController variables where the table lists PrivateCloudController names [divergence:zpa.logs.control-session-status:pcc-template-names]. Which version fields are filled is open [gap:zpa.logs.control-session-status:pse-optional-fields]. The Private Cloud Controller Status example has ZEN 'unset' and the same value for PrivateIP and PublicIP, while ZEN is described as the Public Service Edge selected for the connection. [zpa.logs.control-session-status:zen-unset-sample]

**Custom field.** The App Connector Status header suggests adding ConnectionLogType as a custom log field to distinguish AppProtection logs from event logs, with expected values event_log and inspection_log. [zpa.logs.control-session-status:connection-log-type]

**In Diagnostics and Live Logs.** The status diagnostics are views in [ZPA Live Logs and Private Diagnostics: views, time ranges, retention, filters and export](kb:zpa.troubleshooting.diagnostics). Live Logs says that when App Connectors authenticate to the Zscaler cloud, the Public Service Edges or Private Service Edges record the data and send the App Connector logs to Private Access. [zpa.logs.control-session-status:emission-live] In the App Connector Status diagnostics, Authenticated means the App Connector successfully authenticated, Authentication Failed that it was unable to authenticate to the Zscaler cloud, and Disconnected that it successfully disconnected; the Private Service Edge page describes Disconnected as the Private Service Edge successfully disconnecting from the Zscaler cloud. [zpa.logs.control-session-status:status-semantics] In the status diagnostics, App Connector IP is the IP address (and source port) used by the App Connector to connect to the Public or Private Service Edge, and a Private Service Edge's Public IP is the address (and source port) used by the Private Service Edge to connect to Private Access. [zpa.logs.control-session-status:status-ip-fields] The App Connector Status diagnostics list the type of connection the App Connector made as a Connection Type; the list includes the Private Cloud Controller AppProtection Log Connection and the Private Cloud Controller Stats Connection. [zpa.logs.control-session-status:ac-connection-types] The Private Service Edge Status diagnostics name the Service Edge Control Connection, the Service Edge Log Connection and the Private Cloud Controller Control Connection as connection types; for a Private Cloud Controller the only supported connection type is the Private Cloud Controller Control Connection, with a Session Type such as TLS. [zpa.logs.control-session-status:pse-connection-types] An App Connector Status entry that shows Unavailable for the restart reason means the reason for the restart is not available among the listed restart reasons. [zpa.logs.control-session-status:restart-reason] The restart reasons themselves are not listed [gap:zpa.logs.control-session-status:restart-reasons-unlisted].

What to check:
1. Whether a Private Service Edge custom template names the unauthentication field TimestampUnAuthentication, as the default template does, rather than the table spelling TimestampUnAuthnetication.
2. Whether a custom status template uses the default template's variable names, HostUpTime for a Private Service Edge and SiteController, SiteControllerGroup and SiteControllerStartTime for a Private Cloud Controller, rather than the table names.
3. Whether volume figures came from the interface counters rather than TotalBytesRx and TotalBytesTx.
4. Whether the version was read from Version or PackageVersion for a Private Service Edge or Private Cloud Controller.
5. Whether a status record is treated as an event only after confirming what emits it.

Inferred, not quoted (say so when an answer rests on one):
- [zpa.logs.control-session-status:status-resource-snapshot] Tier B: Follows from resource-fields-at-event: the App Connector, Private Service Edge and Private Cloud Controller status pages describe CPUUtilization and MemUtilization only as the utilization in %, with no window, unlike the Metrics log's maximum over the past 5 minutes. No source states that the status values are readings taken at the record's time, or over what period the interface counters accumulate.

Sources disagree (name both sides):
- Status timestamps described in microseconds versus shown as ISO 8601 strings [divergence:zpa.logs.control-session-status:timestamp-format]
  - zscaler-help: The App Connector Status field table describes TimestampAuthentication as a timestamp in microseconds.
  - zscaler-help: The App Connector and Private Service Edge examples show it as an ISO 8601 string, with TimestampUnAuthentication empty.
  - zscaler-help: The default App Connector Status template writes TimestampAuthentication and TimestampUnAuthentication with the :iso8601 modifier ([[zpa/app-connector-status-log]]).
  - zscaler-help: The content-format article shows the :iso8601 modifier rendering a timestamp field as an ISO 8601 string: %s{startrx_us:iso8601} appears as 2017-09-05T09:44:06.363Z.
  Impact: The default templates render the authentication timestamps with :iso8601, so a default-format record carries ISO 8601 strings, as the examples show. A custom template that writes these fields without :iso8601 may produce another form; read the format from the receiver's template rather than assuming microsecond integers. An empty TimestampUnAuthentication on an AUTHENTICATED record is what the examples show.
- Private Service Edge Status fields in the table versus the example and the default template [divergence:zpa.logs.control-session-status:pse-sample-fields]
  - zscaler-help: The field table lists PackageVersion for the Private Service Edge and no Version or PublicIP field.
  - zscaler-help: The example carries both Version (populated) and PackageVersion (empty) and a PublicIP.
  - zscaler-help: The default Service Edge Status template writes Version, PackageVersion and PublicIP ([[zpa/private-service-edge-status-log]]).
  Impact: The example and the default template both carry Version and PublicIP, which the table does not list, so a custom template built from the table omits them. A parser reading the version from PackageVersion gets an empty value from the example; the populated value is in Version. Check which fields a real record carries.
- The Private Service Edge host time field in the table and example versus the default template [divergence:zpa.logs.control-session-status:pse-host-time-name]
  - zscaler-help: The field table names the field HostStartTime, the time in seconds at which the host was started, and the example gives it the value 1916930.
  - zscaler-help: The default Service Edge Status template writes HostUpTime next to ServiceEdgeStartTime ([[zpa/private-service-edge-status-log]]).
  Impact: Field names are exact. The table spells it HostStartTime; the default template writes HostUpTime, so a custom template built from the table name may not emit the field. The example value 1916930 reads as an uptime in seconds rather than a start time; whether the field holds a start time or an uptime is the gap host-time-meaning.
- Private Cloud Controller Status field names in the table versus the default template's variables [divergence:zpa.logs.control-session-status:pcc-template-names]
  - zscaler-help: The field table names the fields PrivateCloudController, PrivateCloudControllerGroup and PrivateCloudControllerStartTime.
  - zscaler-help: The default Private Cloud Controller Status template reads the variables SiteController, SiteControllerGroup and SiteControllerStartTime, and its JSON form labels SiteController as PrivateCloudController ([[zpa/private-cloud-controller-status-log]]).
  Impact: Field names are exact. The table names the variables PrivateCloudController, PrivateCloudControllerGroup and PrivateCloudControllerStartTime; the default template reads SiteController, SiteControllerGroup and SiteControllerStartTime. A custom template built from the table names may not emit these fields; copy the variable names from the default template and check a real record.
- The Private Service Edge unauthentication field name in the table versus the example and the default template [divergence:zpa.logs.control-session-status:unauthnetication-spelling]
  - zscaler-help: The field table spells the field TimestampUnAuthnetication.
  - zscaler-help: The example spells it TimestampUnAuthentication.
  - zscaler-help: The default Service Edge Status template writes it as TimestampUnAuthentication ([[zpa/private-service-edge-status-log]]).
  Impact: Field names are case sensitive and exact. The table spells it TimestampUnAuthnetication; the example and the default template write TimestampUnAuthentication. A custom template built from the table spelling may not emit the field; use the default template's name and check a real record.
