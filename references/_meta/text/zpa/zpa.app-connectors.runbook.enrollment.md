# What the App Connector runbook checks when enrollment fails: sizing, DNS, broker reachability, SSL interception, clock, provisioning key and VM moves (zpa.app-connectors.runbook.enrollment)
Also called: Troubleshooting Enrollment Failure

**Sizing.** The enrollment-failure runbook says to make sure the App Connector deployed follows the correct sizing requirements, to check the build info with the lscpu command, and to make the necessary changes to meet the required settings where the sizing requirements do not match. [zpa.app-connectors.runbook.enrollment:sizing-check]

**DNS.** With no connectivity to the Control Broker the Support Information page cannot run DNS and other commands, DNS must be able to resolve co2br.<cloudname>.net, and the App Connector uses the DNS servers in /etc/resolv.conf. [zpa.app-connectors.runbook.enrollment:dns-on-connector] If DNS resolution from the App Connector is unsuccessful, the runbook says to rectify the DNS issue first, validating network connectivity to the DNS servers and updating the DNS server configuration if needed. [zpa.app-connectors.runbook.enrollment:dns-fix-first]

**Broker reachability.** The runbook checks broker reachability from the App Connector with a ping and an openssl TLS connection to a Public Service Edge for Private Access; if the connection fails it points to network or firewall blocks and a packet capture, which shows any TCP resets (RSTs) or blocks. [zpa.app-connectors.runbook.enrollment:broker-reachability] If there are blocks identified on the network firewall, the runbook says to allow all the IP address ranges listed on config.zscaler.com/private.zscaler.com/zpa for the private.zscaler.com cloud or config.zscaler.com/zpatwo.net/zpa for the zpatwo.net cloud. [zpa.app-connectors.runbook.enrollment:firewall-ranges]

**Certificate causes.** SSL Interception by an intermediate device can make the SSL connection between the App Connector and the Private Access cloud fail; the App Connector prints logs in the journal in that case, and the fix is to allowlist all the Private Access domains or IP addresses listed on the cloud's config.zscaler.com page in the SSL interception device. [zpa.app-connectors.runbook.enrollment:ssl-interception] Another reason for certificate rejection is an App Connector timestamp that does not match the timestamp on the Private Access back-end servers, which can delay the certificate becoming valid and enrolling the App Connector; the runbook says to verify the connector time is properly set and maintained. [zpa.app-connectors.runbook.enrollment:time-sync]

**Key and hardware causes.** A provisioning key not copied correctly can cause enrollment issues: the connector logs show 'Login request failed - http status(401)' and 'Certificate enrollment failed.', and the runbook recommends configuring the provisioning key again and re-enrolling. [zpa.app-connectors.runbook.enrollment:provision-key-copy] Moving an App Connector to new hardware with tools such as VM cloning or Hyper-v Live Migration, or any migration tool that changes the hardware ID including the MAC address, makes enrollment fail with log lines 'Cannot decrypt data from instance_id.crypt' and 'Cannot get instance id'; the runbook recommends re-provisioning the App Connector. [zpa.app-connectors.runbook.enrollment:vm-move]
