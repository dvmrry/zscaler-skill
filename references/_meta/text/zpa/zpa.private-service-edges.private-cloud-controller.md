# Private Cloud Controllers and Private Clouds as the Business Continuity layer (zpa.private-service-edges.private-cloud-controller)
Also called: private cloud controller; privatecloudcontroller; private cloud group; private cloud; zpa business continuity; restart_private_controller; zpa_private_cloud_group; is a private cloud controller a pse group

A Private Cloud Controller is the Business Continuity controller; it is not a Private Service Edge group type.

**Role.** A Private Cloud Controller is a per-tenant controller that users, Private Service Edges and App Connectors use when the Private Access cloud is not available or reachable: it persists a complete copy of configuration and policies and, when Business Continuity is enabled, distributes them to onsite Private Service Edges and App Connectors, acts as an authentication redirection endpoint, allows log streaming to a SIEM, and redirects users to Private Service Edges. [zpa.private-service-edges.private-cloud-controller:controller-role] Private Cloud Controllers must run the same or a later software version as the App Connectors and Private Service Edges for Business Continuity to function properly, and their certificate enrollment is valid for one year; configuring the Certificate Renewal Threshold when adding a Private Cloud refreshes it automatically. [zpa.private-service-edges.private-cloud-controller:controller-version] A Private Cloud is a logical grouping of Private Cloud Controller groups, App Connector groups, Private Service Edge groups and log receivers, required for uninterrupted application access via Business Continuity. [zpa.private-service-edges.private-cloud-controller:private-cloud-grouping] The Python SDK Private Cloud Group carries a site_id, "the unique identifier of the site associated with this Private Cloud Group". [zpa.private-service-edges.private-cloud-controller:controller-group-site]

**Business Continuity Insights.** The Business Continuity Insights page analyzes Business Continuity configurations and Private Cloud Controller data. Its time range runs from one hour to one month or a Custom Range with start and end dates within the last 30 days, by default the last 7 days, and the Users in Business Continuity Mode chart covers a 30-day time range. [zpa.private-service-edges.private-cloud-controller:bc-insights] The Business Continuity Insights page counts the users successfully redirected to the identity provider by the Private Cloud Controller (IdP Successful), the users that successfully redirected to the Private Service Edge (Zscaler Client Connector Successful), and the machine tunnels the controller failed to redirect to the Private Service Edge (Machine Tunnel Failed). Its Transactions in Business Continuity Mode line graph shows trends for allowed, blocked, error and info transactions. [zpa.private-service-edges.private-cloud-controller:bc-redirections]

**Restart.** Whether a restart is graceful is unverified [gap:zpa.private-service-edges.private-cloud-controller:restart-semantics].

**Private Clouds.** Private Clouds, Private Cloud Controllers and Private Cloud Controller groups that are managed by Zscaler are read only and cannot be configured, edited or deleted. With Zscaler-managed Business Continuity, a Private Cloud Controller group, Private Service Edge group and App Connector group can still be associated to a Private Cloud. [zpa.private-service-edges.private-cloud-controller:zscaler-managed-read-only] Disabling a Private Cloud causes all associated Private Cloud Controllers to stop accepting connections from Client Connector, App Connectors and Private Service Edges for Private Access. [zpa.private-service-edges.private-cloud-controller:private-cloud-status] A Private Cloud takes the number of days before the certificate expires at which to automatically renew the enrollment certificate for Private Cloud Controllers, App Connectors and Private Service Edges; the maximum supported value is 180 days. [zpa.private-service-edges.private-cloud-controller:certificate-renewal-threshold] A Private Cloud's control channel option Private Cloud Controller lets App Connectors and Private Service Edges use Private Cloud Controllers for control channels such as configuration downloads, configuration updates and logging during normal operations and when not in Business Continuity; the option Public Cloud has them establish a control channel to the Zero Trust Exchange during normal operations. [zpa.private-service-edges.private-cloud-controller:primary-control-channel-path] Force Business Continuity Mode forces Private Cloud Controllers, App Connectors and Private Service Edges to use Business Continuity and is only available when editing a Private Cloud; Stream Logs through LSS Connectors streams logs to SIEM servers during Business Continuity. [zpa.private-service-edges.private-cloud-controller:force-mode-and-lss]

**Groups.** Every Private Cloud Controller belongs to a specific group and must belong to a single group, and every group must always be associated with at least one provisioning key to serve any application. A group's automated update schedule is set to an off-hours maintenance window in a region, and the group sets the preferred local version profile and a controller location used in application path selection. [zpa.private-service-edges.private-cloud-controller:group-membership] Configuring a Private Cloud Controller group selects the Private Cloud it belongs to, Persist Local Version Profile (Disabled by default), a Version Profile (default value Default), a periodic software update schedule by day of the week and start time, and the location where its controllers are set up. [zpa.private-service-edges.private-cloud-controller:group-fields] The Private Cloud Controller groups page shows, for each group, the Private Cloud Controller Count, the number of enrolled controllers associated with the group; a group's details, opened by clicking its name, include the Enrollment Certificate, the certificate the controller uses for enrollment. [zpa.private-service-edges.private-cloud-controller:group-count-column]

**Provisioning keys.** The provisioning key functions like an ID for the Private Cloud Controller, enabling the Private Access cloud to verify the controller's authenticity and complete the deployment process; each key is associated with a specific group, and multiple keys can be associated with a single group. [zpa.private-service-edges.private-cloud-controller:keys-identify-group] Provisioning keys should be treated as secrets and properly protected because they can create a resource for a tenant, and must be secured and not transmitted or stored in clear text. [zpa.private-service-edges.private-cloud-controller:key-secret] The name entered for a provisioning key is automatically assigned as a prefix for the name of each controller enrolled with it (the help's example: AWS Oregon gives AWS Oregon-1 for the first). When editing a deployed controller's name, the prefix followed by the number of the nth controller deployed with its key should be kept. [zpa.private-service-edges.private-cloud-controller:key-name-prefix] View or Export Provisioning Key After Creation is enabled by default and, if disabled, cannot be enabled at a later time; an existing key offered in the drop-down is only one that can be viewed or exported after creation. If the option was disabled the key entry on the keys page is blank, and if the key does not appear and no backup is securely stored in an external credential vault, a new key must be generated. [zpa.private-service-edges.private-cloud-controller:key-view-export] Maximum Reuse of Provisioning Key is the maximum number of instances where the key can be used to enroll a controller, and can be modified after adding the controller; the Instances of Provisioning Key Reuse field cannot be modified. Private Access tracks the number of controllers enrolled in the group and displays it in that field. If the Provisioning Key Utilization Count is reached the key cannot be copied, and the key can be edited to raise the limit. [zpa.private-service-edges.private-cloud-controller:key-reuse] When a provisioning key is incorrectly copied, the Private Cloud Controller console shows, when it tries to enroll, error:Login request failed - http status(401) and notice:Certificate enrollment failed. [zpa.private-service-edges.private-cloud-controller:key-copy-error-401] All controllers deployed with a key have their certificates signed with its signing certificate; if any are deployed with an expired signing certificate and a new certificate is configured, they automatically redeploy using the new certificate. [zpa.private-service-edges.private-cloud-controller:key-signing-certificate] If a provisioning key is configured using Zscaler Deception or is managed by Zscaler, the edit and delete options are unavailable. [zpa.private-service-edges.private-cloud-controller:key-managed-read-only]

**Deployed controllers.** A deployed controller's Listen IPs are the IP addresses of the Private Cloud Controller system that it listens to for connection requests from clients and App Connectors; if not configured it automatically listens to all interfaces, and the common use case is to not specify any. [zpa.private-service-edges.private-cloud-controller:listen-ips] Completely replacing a deployed Private Cloud Controller requires deleting its configuration and re-enrolling it; the new provisioning key can be applied to the virtual machine image already deployed by replacing the old key. [zpa.private-service-edges.private-cloud-controller:replace-by-reenroll] Sizing, network and enrollment are in [Private Cloud Controller sizing, network requirements, platforms and enrollment](kb:zpa.private-service-edges.private-cloud-controller.deployment); console commands are in [Private Cloud Controller console commands and backup restore](kb:zpa.private-service-edges.private-cloud-controller.troubleshooting); the feature is in [Business Continuity for Private Access: prerequisites, domain names, settings, entering and exiting, limitations](kb:zpa.private-service-edges.business-continuity).

The endpoints for controllers and controller groups are in [Management API endpoints for Private Service Edges, groups and schedules](kb:zpa.private-service-edges.api-surface). Disaster recovery: [Disaster recovery mode and Private Service Edge groups](kb:zpa.private-service-edges.disaster-recovery).

What to check:
1. Whether the question is about a Private Cloud Controller: it is a per-tenant controller for outages of the Private Access cloud, not a Private Service Edge group type.
2. Whether Private Cloud Controllers run the same or a later software version than the App Connectors and Private Service Edges they serve.
3. Whether the restart endpoint is safe on a live controller, which the sources do not settle.

Not known (open gaps):
- Operational semantics of restarting a Private Cloud Controller [gap:zpa.private-service-edges.private-cloud-controller:restart-semantics]: settled by lab-test. Blocks: restarting a controller during Business Continuity
