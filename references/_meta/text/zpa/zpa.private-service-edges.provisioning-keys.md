# Private Service Edge provisioning keys: what a key is, reuse limits, naming, View or Export, signing certificate and the keys page (zpa.private-service-edges.provisioning-keys)
Also called: private service edge provisioning key; pse provisioning key; service edge provisioning key; provisioning key utilization count private service edge; view or export provisioning key after creation private service edge

A Private Service Edge provisioning key is a text string generated when a new Private Service Edge is added and entered when the Private Service Edge is deployed. It functions like a credential: on first contact the Private Service Edge presents a key as its ID, letting the Private Access cloud verify its authenticity and identify its Private Service Edge group (each key is associated with a specific group), and Private Access then automatically completes the deployment. [zpa.private-service-edges.provisioning-keys:what-it-is] Provisioning keys should be treated as secrets and properly protected because they can create a resource for a tenant, and must also be secured and not transmitted or stored in clear text. [zpa.private-service-edges.provisioning-keys:key-is-secret] The help's example key is pipe-separated and begins 1|api.private.zscaler.com| followed by a string beginning 68F0AOEgpcG8McLmwdborq2m6v2A5oNEpSztJ; the page says the domain in the echo statement depends on which Private Access cloud the tenant is on. [zpa.private-service-edges.provisioning-keys:key-format-example]

**Use limits.** Provisioning keys are designed to enable auto-scaling: when a key is generated the number of times it can be used to deploy Private Service Edges can be specified, Private Access tracks the number of times a key is used and displays it on the Private Service Edge Provisioning Keys page, a key used its maximum number of times cannot deploy more Private Service Edges (though the maximum can always be edited), and multiple provisioning keys can be associated with a single Private Service Edge group. [zpa.private-service-edges.provisioning-keys:reuse-and-scaling] Maximum Reuse of Provisioning Key is the maximum number of instances where the key can be used to enroll a Private Service Edge and can be modified after the Private Service Edge is added; the Instances of Provisioning Key Reuse field cannot be modified and shows the number of Private Service Edges enrolled in the group, which helps ensure keys are not being used improperly by unknown parties. [zpa.private-service-edges.provisioning-keys:max-reuse-field] The recommendation on the Add page is worded for App Connectors [gap:zpa.private-service-edges.provisioning-keys:max-reuse-wording]. If the Provisioning Key Utilization Count is reached, the key cannot be copied; a Warning icon appears next to the disabled Copy icon, and the key can be edited to raise the limit. [zpa.private-service-edges.provisioning-keys:exhausted-copy-disabled]

**Naming.** A key's name cannot contain special characters except periods, hyphens and underscores, and is automatically assigned as a prefix for the name of each Private Service Edge enrolled with it, followed by an automatically added number (the page's example: AWS Oregon gives AWS Oregon-1, then AWS Oregon-2). If a Private Service Edge name is edited, the prefix followed by the number indicating that it is the nth Private Service Edge deployed with its key should be kept. [zpa.private-service-edges.provisioning-keys:name-prefix]

**View or Export.** View or Export Provisioning Key After Creation is enabled by default and, if disabled, cannot be enabled at a later time; if it is enabled it can be disabled later. When an existing provisioning key is used on the Add page, only keys that can be viewed or exported after creation appear in the drop-down menu. [zpa.private-service-edges.provisioning-keys:view-export] The keys page's key entry is blank if View or Export Provisioning Key After Creation was disabled, and its Copy icon is hidden for security purposes; if the provisioning key doesn't appear and a backup isn't securely stored in an external credential vault, a new key must be generated, and a new key can be created and attached to the same Private Service Edge. [zpa.private-service-edges.provisioning-keys:key-hidden] The pages differ on whether such a key still appears in the table [divergence:zpa.private-service-edges.provisioning-keys:hidden-key-in-table].

**Adding to an existing group.** To add a Private Service Edge to an existing group with a provisioning key, choose an existing provisioning key associated with the appropriate Private Service Edge group, then copy the key and enter it when deploying the Private Service Edge. [zpa.private-service-edges.provisioning-keys:add-to-existing-group]

**Editing and the certificate.** On the Edit Private Service Edge Provisioning Key page only these fields can be modified: Maximum Reuse of Provisioning Key, Private Service Edge Group, Name and Signing Certificate, and View or Export Provisioning Key After Creation can be disabled later. [zpa.private-service-edges.provisioning-keys:editable-fields] The signing certificate selected for a key is the one Private Access uses to sign certificates it issues to the Private Service Edge; all Private Service Edges deployed with the key have their certificates signed with it, and if any were deployed with a signing certificate that has expired and a new certificate is configured, they automatically redeploy using the new certificate. [zpa.private-service-edges.provisioning-keys:signing-certificate] Provisioning keys that are managed by Zscaler are read only and cannot be edited or deleted. [zpa.private-service-edges.provisioning-keys:zscaler-managed-read-only]

**The keys page.** The Private Service Edge Provisioning Keys page lists each key's Name (clicking the provisioning key shows the signing certificate), the Maximum # of Private Service Edges that can be deployed using the key, the Provisioning Key Utilization Count, the associated Private Service Edge Group and the key itself, and can copy the key to the clipboard, edit its details, delete it and download it to the system in a file format. [zpa.private-service-edges.provisioning-keys:keys-page] The Terraform and API side of the keys is in [For the provisioning-key method, a zpa_provisioning_key is created after the group that references the group's ID and the SERVICE_EDGE_GRP association type; the key is injected into the Private Service Edge VM at deployment.](kb:zpa.private-service-edges.enrollment:tf-provisioning-key); the wire name of View or Export was not checked [gap:zpa.private-service-edges.provisioning-keys:view-export-wire].

What to check:
1. The key's maximum and utilization count before blaming the Private Service Edge for a failed deployment: a key used its maximum number of times cannot deploy more Private Service Edges.
2. Whether the key's View or Export option was disabled, which hides the key and makes a new key necessary without an external vault backup.
3. Whether the key is Zscaler-managed before planning to edit or delete it.

Sources disagree (name both sides):
- Whether a key whose View or Export option was disabled still appears in the provisioning keys table [divergence:zpa.private-service-edges.provisioning-keys:hidden-key-in-table]
  - zscaler-help: About Private Service Edge Provisioning Keys describes a table entry that is blank if the option was disabled, so the row appears with a blank key.
  - zscaler-help: Editing a Private Service Edge Provisioning Key says only keys that can be viewed or exported after creation appear in the table.
  Impact: Whether a key with the option disabled is listed with a blank key or not listed at all is unsettled; the editing note may mean only exportable keys can be edited, but no page says so. The same disagreement is recorded for App Connector keys in zpa.app-connectors.provisioning-keys. Check the keys page before telling an admin where to find such a key.
