# What a ZPA User Activity entry shows in Diagnostics and Live Logs (zpa.troubleshooting.user-activity-diagnostics)
Also called: user activity diagnostics; zpa diagnostics user activity; zpa live logs user activity; zpa hop connection id; zpa transaction trends

The Diagnostics and Live Logs views of a User Activity entry use their own labels and units, and the vendor pages do not equate them with the LSS fields [gap:zpa.troubleshooting.user-activity-diagnostics:console-lss-field-mapping]. How the views are reached, their ranges and their export are in [ZPA Live Logs and Private Diagnostics: views, time ranges, retention, filters and export](kb:zpa.troubleshooting.diagnostics).

**Identity.** The Username shown in User Activity diagnostics is the NameID in the SAML assertion from the IdP and not the username entered in Zscaler Client Connector. Extranet location and sublocation names might also appear with Extranet Application Support, and a Browser Access unauthenticated HTTP preflight OPTIONS request shows the username ZPA BA Unauthenticated. [zpa.troubleshooting.user-activity-diagnostics:username-nameid] That conflicts with the LSS field table [divergence:zpa.troubleshooting.user-activity-diagnostics:username-nameid-vs-lss].

**Status and connection.** The console Status of a User Activity entry is Open Connection (the user is currently connected to the application), Active Connection (the user is currently using it) or Closed Connection (the user's connection has ended). [zpa.troubleshooting.user-activity-diagnostics:connection-states] Whether this column is the LSS ConnectionStatus field is open [What Open, Close and Active mean, and the Policy field when empty](kb:zpa.troubleshooting.log-fields:status-meanings). Connection Type is the connection type of the application request (ZPA, ZDX, Web Probe Cacheless, HTTP Web Probe or HTTPS Web Probe) and is set to ZPA by default. [zpa.troubleshooting.user-activity-diagnostics:connection-type] A User Activity entry's Client Type is Branch Connector, Extranet, Zscaler Client Connector, Client Connector Partner, Web Browser, Web Browser Unauthenticated or ZIA Public Service Edge; the list on the Trends client-type filter also names Cloud Connector, Machine Tunnel and Cloud Browser. [zpa.troubleshooting.user-activity-diagnostics:client-types] If Private Access is unable to determine the user's location, the private IP address is shown. [zpa.troubleshooting.user-activity-diagnostics:location-fallback] Source IP Address and Source Port are the IP address and port of the Branch Connector, Cloud Connector or Service Edge for Internet & SaaS. [zpa.troubleshooting.user-activity-diagnostics:source-ip]

**Service Edges and hops.** A hop occurs when a user's request is forwarded to a Public Service Edge because the App Connector cannot reach the Private Service Edge; the log information shown for the connection is the first part of the hop, and the Private Service Edge then forwards the request to a Public Service Edge. Connections without a hop do not show the Hop Connection ID, and Origin Service Edge shows the original Service Edge if a hop occurs between two or more Service Edges. [zpa.troubleshooting.user-activity-diagnostics:hop] The hop is defined differently on three pages [divergence:zpa.troubleshooting.user-activity-diagnostics:hop-definitions]. As part of setting up the TLS session, a Zscaler hosted Service Edge directs the user's Zscaler Client Connector to connect with another Service Edge at a particular location. Control Service Edge is the name of the control Public Service Edge or Private Service Edge forwarded in the request. [zpa.troubleshooting.user-activity-diagnostics:redirect-icon] The Service Edge section's byte counters include RX From Client and TX To App Connector for a Public or Private Service Edge, RX From and TX To Private Service Edge for a Public Service Edge, and RX From and TX To Public Service Edge for a Private Service Edge. [zpa.troubleshooting.user-activity-diagnostics:byte-directions] Total Bytes is the total bytes (B) and kilobytes (KB) of the request and the response, respectively. [zpa.troubleshooting.user-activity-diagnostics:total-bytes]

**Timing.** In the console, Policy Processing is the latency in milliseconds between the Public or Private Service Edge and the Central Authority, and Connection Setup Time is the latency in milliseconds for the App Connector to set up the connection to the application server. [zpa.troubleshooting.user-activity-diagnostics:policy-processing-ms] The LSS field table describes the policy time differently [divergence:zpa.troubleshooting.user-activity-diagnostics:policy-processing-meaning].

**Special cases.** For an extranet connection, the App Connector fields (Name, IP:Port & Protocol, Location, App Connector ID, Connection Setup Time, App Connector Group Name and App Connector Group ID) appear as Unavailable; a location group field appears as Unavailable if the organization doesn't use location groups. [zpa.troubleshooting.user-activity-diagnostics:extranet-unavailable] If application access for Business-to-Business (B2B) Federation is denied by the default timeout policy rule (7 days), B2B Default Timeout Rule appears in the Timeout Policy Name field. A filter shows requests by the B2B Federation transaction ID, a unique attribute shared with both the host and guest partner for every connection and is used for troubleshooting. [zpa.troubleshooting.user-activity-diagnostics:b2b-default-timeout] If an application is configured for ICMP Access, the IP data appears and the status might show as successful (for example BRK_MT_TERMINATED) after the App Connector is selected, even when the application is unreachable; this can occur if the App Connector is set up to provide on access or no health reporting. [zpa.troubleshooting.user-activity-diagnostics:icmp-success-caveat] With a subscription to Authentication Service for users, the SAML Attributes field is replaced with Session Attributes; with Authentication Service subscribed and the feature enabled for the tenant, SCIM Users is replaced with Authentication Service Users and SCIM Groups with Groups. [zpa.troubleshooting.user-activity-diagnostics:auth-service-fields] The verified and unverified posture profile fields show a list of those profiles, and show Unavailable when there are no posture profiles to display. [zpa.troubleshooting.user-activity-diagnostics:posture-lists]

**Privileged Remote Access.** Credential Login Type is the credential type used to log into a privileged console (password, SSH private key or passphrase); a transferred file's Status shows Success if it was downloaded or uploaded and Denied if not. File inspection needs a privileged capabilities policy for the privileged console set to Enable Inspection and Integrations for the Internet & SaaS Sandbox configured. The PRA error field does not show if there isn't an error, and the session recording field shows Unavailable when no recordings are available and Started when one is in progress. [zpa.troubleshooting.user-activity-diagnostics:pra-fields]

**Filters and Live Logs.** User Activity filters include Path Decision Result Code (the App Connector path decision result code; to learn more, contact Zscaler Support), Dispatcher ID, Service Edge Type (Public or Private), User Platform (Windows, Linux, macOS, iOS or Android), Privileged Session Recording (Started or Available) and Inspection Status (the status of inspection tunnel connections). [zpa.troubleshooting.user-activity-diagnostics:filters-of-note] Live Logs can filter User Activity by the session type of the user, which the page prints as DTLA or TLS, and of the App Connector, DTLS or TLS. [zpa.troubleshooting.user-activity-diagnostics:live-session-type-filter] The Live Logs Application Activity view has a Requested Port & Protocol field, the destination port and protocol of the requested application, and a Routed Through Service Edge filter for requests that go through a Public or Private Service Edge or not. [zpa.troubleshooting.user-activity-diagnostics:app-activity-extra] The values of several fields are named but never listed [gap:zpa.troubleshooting.user-activity-diagnostics:undefined-value-sets].

**Trends.** On the Trends tab, the Info transactions trend varies over time to reflect that transactions have moved from an open state, for ongoing requests, to a closed state (Success); Show Error Codes shows the top errors for the selected time range; the Total Data Transferred Trend shows the total data received, and the Reauth Blocks Trend the number of reauthorization blocks, within the selected time range. [zpa.troubleshooting.user-activity-diagnostics:trends]

Sources disagree (name both sides):
- The User Activity Username as the name entered into Client Connector (LSS field table) versus the SAML NameID (Diagnostics, Live Logs, Users dashboard) [divergence:zpa.troubleshooting.user-activity-diagnostics:username-nameid-vs-lss]
  - zscaler-help: The LSS field table describes Username as the username as entered into Zscaler Client Connector.
  - zscaler-help: The User Activity diagnostics page says the Username is the NameID in the SAML assertion from the IdP, not the username entered in Client Connector.
  - zscaler-help: The Live Logs page gives the same description for the user activity Username.
  - zscaler-help: The Users dashboard gives the same description for Name.
  Impact: The two surfaces describe the same records with different identities. Do not assume the LSS Username matches the console's Username, or that either is the name the user typed, without comparing a record on both surfaces.
- Three descriptions of a hop on the User Activity and User Status pages [divergence:zpa.troubleshooting.user-activity-diagnostics:hop-definitions]
  - zscaler-help: The User Activity page defines a hop as a request forwarded to a Public Service Edge because the App Connector cannot reach the Private Service Edge.
  - zscaler-help: The User Activity hop filter says hops typically go from Client Connector to a Public Service Edge, then to another Public Service Edge managed by Zscaler.
  - zscaler-help: The User Status page says a hop has two parts: Client Connector to a Private Service Edge, then the Private Service Edge to a Public Service Edge.
  Impact: What path a hop describes differs between the pages, so a Hop Connection ID does not tell which components the two parts connect without a record to read.
- Policy Processing as access policy processing time in microseconds (LSS) versus a latency in milliseconds to the Central Authority (console) [divergence:zpa.troubleshooting.user-activity-diagnostics:policy-processing-meaning]
  - zscaler-help: The LSS field table describes PolicyProcessingTime as the time in microseconds taken for processing the access policy associated with the application.
  - zscaler-help: The Diagnostics page describes Policy Processing as the latency in milliseconds between the Public or Private Service Edge and the Central Authority.
  Impact: The unit and the measured interval differ between the descriptions; whether they are the same measure is not stated. Convert units and check a record on both surfaces before comparing console and LSS figures.
