# Private Cloud Controller console commands and backup restore (zpa.private-service-edges.private-cloud-controller.troubleshooting)
Also called: private cloud controller console; private cloud controller troubleshooting; zpa-pcc-restore; pcc show status; restore private cloud controller backup

The Troubleshooting Private Cloud Controllers article provides debugging commands in the Private Cloud Controller console, run from /opt/zscaler/var/pcc/image/bin at a pcc> prompt whose help lists show, check, run-all or tech-support (execute all important commands in one shot), help, usage, version and exit or quit. [zpa.private-service-edges.private-cloud-controller.troubleshooting:console-help]

**Show commands.** The show commands cover journal logs from the last 1 hours, status of a specified object, statistics, connections, current configuration and backups. [zpa.private-service-edges.private-cloud-controller.troubleshooting:show-commands] show status takes pcc for the status of the Private Cloud Controller, system for the system status, cert for the status of the certificate, db or database, and bcp for the status of Business Continuity; the page's output example for bcp includes Running in Normal Mode (Non-BC Mode). [zpa.private-service-edges.private-cloud-controller.troubleshooting:show-status] show stats redirect reports Redirect to PSE - Failed, Redirect to IDP and Redirect to PSE - Successful counts in 1, 5, 15, 30 and 60 minutes. [zpa.private-service-edges.private-cloud-controller.troubleshooting:redirect-stats] The help shows a command for outgoing connections to clients and a command for incoming connections to the server. [zpa.private-service-edges.private-cloud-controller.troubleshooting:connections] The help has commands to view current configuration information for Business Continuity, to show backups for the Private Cloud Controller, and to view logs for the last hour or, with a period such as 3h or 90m, for that period. [zpa.private-service-edges.private-cloud-controller.troubleshooting:config-backups-logs] What the Business Continuity status output looks like in Business Continuity mode is open [gap:zpa.private-service-edges.private-cloud-controller.troubleshooting:bc-mode-output].

**Check commands.** The check commands include check redirect ip <IP-Address> for the IP addresses targeted by the redirect, one for the names of the trusted networks targeted by the redirect, check connection with a period such as 3h or 90m and match sni, ip or user <KEYWORD>, and a command to run all commands needed by Zscaler Support at one time. [zpa.private-service-edges.private-cloud-controller.troubleshooting:check-commands]

**Restoring a backup.** Restoring configuration settings from a Private Cloud Controller backup overwrites all the controller's current configurations. The restore runs zpa-pcc-restore.py restore <label>, where the label is the prefix of the snapshot in the zpa-pcc-restore.py show command (for example 2025-09-30) as long as it uniquely identifies the snapshot; otherwise an error appears and more information must be added. The help's example output shows the backup directory /opt/zscaler/backup/pcc_backup and that the zpa-pcc service will be stopped before restore. [zpa.private-service-edges.private-cloud-controller.troubleshooting:restore] After a restore the help has the reader check the integrity of the database files, verify that Private Service Edges and App Connectors are actively connected to the Private Cloud Controller, and view redirection statistics to ensure that the counters are increasing to verify that the controller is redirecting users. [zpa.private-service-edges.private-cloud-controller.troubleshooting:restore-verify] Whether the service starts again after a restore is open [gap:zpa.private-service-edges.private-cloud-controller.troubleshooting:restore-restart].

The Business Continuity settings that create the backups are in [Business Continuity for Private Access: prerequisites, domain names, settings, entering and exiting, limitations](kb:zpa.private-service-edges.business-continuity); the controller itself is in [Private Cloud Controllers and Private Clouds as the Business Continuity layer](kb:zpa.private-service-edges.private-cloud-controller).

What to check:
1. Whether a restore was run knowing it overwrites all current configuration of the controller.
2. Whether the restore label identifies a single snapshot, which the restore command requires.
3. Whether the redirect counters are increasing after a restore, which is how the help verifies the controller is redirecting users.
