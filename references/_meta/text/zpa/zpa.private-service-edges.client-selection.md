# How clients are steered to a Private Service Edge and which country policy applies (zpa.private-service-edges.client-selection)
Also called: trusted network private service edge; grace distance; public service edge proximity override; is_public; publicly accessible private service edge; why does my client use public service edge instead of pse; rfc 1918 country policy; private service edge location geoip; pse country code policy
Former IDs: zpa-54

Steering to a Private Service Edge is decided by three group settings, and the user's country policy is decided by a separate rule.

**Preference for a Private Service Edge.** A Private Service Edge group can be mapped to the organization's trusted networks; the mapping prioritizes Private Service Edges matching a trusted network when users connect from it. [zpa.private-service-edges.client-selection:trusted-network-priority] Trusted networks are available for Zscaler Client Connectors only and are not supported with Cloud & Branch Connectors. [zpa.private-service-edges.client-selection:trusted-networks-zcc-only] Grace distance (console: Public Service Edge Proximity Override) allows a Private Service Edge group within a specified distance of the user to be prioritized over a closer Public Service Edge for Private Access. [zpa.private-service-edges.client-selection:grace-distance] grace_distance_value is the maximum distance and grace_distance_value_unit is MILES or KMS; in the Terraform schema, setting grace_distance_value or grace_distance_value_unit requires the other two grace distance fields (grace_distance_enabled carries no such constraint). [zpa.private-service-edges.client-selection:grace-distance-fields] In the console, the Distance field listed after Public Service Edge Proximity Override is the maximum distance to Private Service Edge groups that would override a Public Service Edge, in Miles or Kms; it must be a valid positive number (maximum 25,000 miles or 40,233.6 kilometers) with no more than two decimal places, and units must be selected. If several groups share the same latitude and longitude, the Distance of the group with the highest value is applied to all of them. [zpa.private-service-edges.client-selection:grace-distance-limits] Whether grace distance is needed for on-premises users is unverified [gap:zpa.private-service-edges.client-selection:grace-distance-required]. The base ranking is not described [gap:zpa.private-service-edges.client-selection:nearest-by-coordinates].

**Remote users.** The Publicly Accessible setting makes a Private Service Edge group that has trusted-network mapping also available to all users outside those networks; the Private Service Edge must be reachable over a public IP address for remote users to connect. [zpa.private-service-edges.client-selection:publicly-accessible] The API and Terraform field is_public (wire key isPublic) carries that setting; it is a boolean in Terraform that defaults to false and "Enable[s] or disable[s] public access for the Service Edge Group", and the Go SDK sends it as a string. [zpa.private-service-edges.client-selection:is-public-field] A group that has trusted networks mapped but not Publicly Accessible is not offered to users outside those trusted networks. [zpa.private-service-edges.client-selection:outside-users-excluded] The Add page says a Private Service Edge that has a public IP address, or a published IP address set to the public IP address of a SNAT (firewall), is already publicly accessible and the field need not be enabled; a Private Service Edge with neither should have it set to Enabled and also needs a published domain. [zpa.private-service-edges.client-selection:publicly-accessible-when-needed] When Publicly Accessible is disabled on a group without a trusted network, the Private Service Edge's IP address is returned to the client for both on-premises and roaming users located closest to the Private Service Edge, so it should be reachable over a public IP address to mitigate connectivity issues for remote users. [zpa.private-service-edges.client-selection:disabled-without-trusted-network] The Public-tier reading of this field is in [What is_public means on a Service Edge group](kb:zpa.public-service-edges.public-flag).

**Country policy.** After a user connects to a Private Service Edge, the user's location is determined from its public IP address and the country-based policy for that country is enforced. [zpa.private-service-edges.client-selection:public-ip-country] If a user connects to a Private Service Edge with an RFC 1918 address, the location of the Private Service Edge is used to evaluate policies with country criteria. [zpa.private-service-edges.client-selection:rfc1918-uses-pse-location] The location shown for a Private Service Edge is the location where its group is set up, and the group stores location coordinates. [zpa.private-service-edges.client-selection:group-location] A wrong country code on the group is not shown to raise an error [gap:zpa.private-service-edges.client-selection:location-misconfiguration].

**Changing the location.** If the location of a Private Service Edge group is updated for an existing connection, the Private Service Edge uses the old location until its next new connection. [zpa.private-service-edges.client-selection:location-change-old-until-new-connection] Location changes via a GeoIP configuration override are not supported for Private Service Edges. [zpa.private-service-edges.client-selection:geoip-override-unsupported] The delay across the service is unquantified [gap:zpa.private-service-edges.client-selection:location-propagation]. A new Private Service Edge may take time to appear to App Connectors [gap:zpa.private-service-edges.client-selection:new-pse-propagation].

Group settings are in [Private Service Edge groups: membership, software updates and version profiles](kb:zpa.private-service-edges.groups); disaster recovery groups are in [Disaster recovery mode and Private Service Edge groups](kb:zpa.private-service-edges.disaster-recovery).

What to check:
1. Whether the client is on a network mapped as a trusted network on the group, and whether it is a Zscaler Client Connector (trusted networks do not apply to Cloud & Branch Connectors).
2. Whether a closer Public Service Edge wins because grace distance is off or the value is smaller than the distance to the user.
3. Whether remote users are expected to reach the group: Publicly Accessible must be on and the Private Service Edge must be reachable on a public IP.
4. Which location a country-criteria policy used: the user's public IP location, or the Private Service Edge location when the user connected from an RFC 1918 address.
5. Whether a recent group location change applies yet: an existing connection keeps the old location until it reconnects.
