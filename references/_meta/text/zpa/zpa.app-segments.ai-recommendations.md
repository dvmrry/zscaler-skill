# AI-powered recommendations for application segments: prerequisites, reading a recommendation and settings (zpa.app-segments.ai-recommendations)
Also called: AI-powered recommendations; Attack Surface Reduction; ASR; recommended application segments; Activate Recommendations; Generate Recommendations

Private Access analyzes user logs and suggests AI-powered recommendations for application segments. They are application segments pulled according to the filters set in the AI-Powered Recommendations Settings, and can be merged with existing defined application segments, added as newly defined application segments, or ignored. [zpa.app-segments.ai-recommendations:what-it-is]

**Prerequisites and generation.** The page lists a minimum of 100 discovered applications and at least 20 enrolled users as prerequisites. The feature is activated with Activate Recommendations on the AI-Powered Recommendations page, which is populated with data only for users who activated it; if the page is not displayed, the page says to contact Zscaler Support. [zpa.app-segments.ai-recommendations:prerequisites-and-activation] The Next Availability date and the ability to generate AI-powered recommendations are determined by the subscription. Clicking Generate Recommendations overwrites any manually created recommendations. [zpa.app-segments.ai-recommendations:generation] An organization with the Segmentation add-on license can request to raise the total number of recommendations from 100 to 500. [zpa.app-segments.ai-recommendations:segmentation-add-on] The ability to merge an AI-powered recommendation with an existing defined application segment depends on your subscription. [zpa.app-segments.ai-recommendations:merge-subscription] The subscription tiers are open [gap:zpa.app-segments.ai-recommendations:subscription-tiers]. Default-Microtenant-only availability is in [Microtenant limits and unsupported features](kb:zpa.microtenants.limits).

**Reading a recommendation.** Attack Surface Reduction (ASR) is the percentage reduction in the attack surface, that is the percentage difference between potential users and recommended users. [zpa.app-segments.ai-recommendations:attack-surface-reduction] In the Accept Recommendation window, the ASR field includes the operators Equals, Greater Than and Less Than, and the list is sorted in ascending order by ASR by default. [zpa.app-segments.ai-recommendations:asr-operators] In the Add AI-Powered Recommendation window, the prepopulated Attack Surface Reduction entry says that all recommendations that provide greater than a 75% reduction are presented. [zpa.app-segments.ai-recommendations:asr-prepopulated] When exploring recommendations by category, the page offers, under Attack Surface Reduction, the ranges >75%-100% and 0%-75% to view the available recommendations in the table. [zpa.app-segments.ai-recommendations:asr-categories] If SCIM Sync or SCIM Attributes for Policy is not enabled, the user recommendations appear as N/A. [zpa.app-segments.ai-recommendations:users-need-scim] A recommended application segment can be grouped by five categories of grouping reason: IP Similarity, User Access Similarity, Domain Name Similarity, Co-occurring Applications Similarity, and Ports and Protocols Similarity. The merge option combines application segments that have the same grouping reasons. [zpa.app-segments.ai-recommendations:grouping-reasons] How application types are identified is open [gap:zpa.app-segments.ai-recommendations:application-types].

**Acting on one.** Before recommendations are added to application segments, Multimatch must be enabled on the wildcard application segment; otherwise an error message asks for Multimatch to be enabled on the selected wildcard application segment. [zpa.app-segments.ai-recommendations:multimatch-on-wildcard] AI-powered recommendations do not support Extranet, and the step that adds a recommendation populates recommended server groups by default. [zpa.app-segments.ai-recommendations:extranet-and-server-groups] Ignoring a recommendation requires a reason in the Send Feedback window, and the ignored recommendation no longer appears in the table; ignored ones are listed under the Ignored Recommendations filter. The Diagnostics page shows up to 200 applications per recommended application segment and does not show additional ones. The availability of both the ignore functionality and the Diagnostics page depends on your subscription. [zpa.app-segments.ai-recommendations:ignore-and-diagnostics]

**Settings.** The AI-Powered Recommendations Settings exclude wildcards or subnets and selected defined application segments from recommendations, and choose whether recommended users are based on SCIM Group, SCIM Attribute or SAML Attribute. SCIM Sync must be enabled to display the SCIM criteria. [zpa.app-segments.ai-recommendations:settings]

Bulk onboarding from a file is in [Application Segment Import: the CSV template, limits, re-import and merge](kb:zpa.app-segments.import); the segment hub is [ZPA application segments](kb:zpa.app-segments).

What to check:
1. Whether the tenant has at least 100 discovered applications and 20 enrolled users, and whether Activate Recommendations was clicked, before expecting the page to hold data.
2. Whether Multimatch is enabled on the wildcard segment before a recommendation is added to it.
3. Whether SCIM Sync or SCIM Attributes for Policy is enabled when user recommendations show N/A.
4. Which window an ASR statement rests on: the Add window's prepopulated field, the table's category ranges or the Accept window's operators.
