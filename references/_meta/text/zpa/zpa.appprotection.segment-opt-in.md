# Enabling AppProtection on an application segment (zpa.appprotection.segment-opt-in)
Also called: auto appprotection; inspect appprotection application; appprotection application segment; appprotection multimatch; appprotection tls 1.2 cipher; appprotection browser access; use untrusted certificates appprotection; protected applications

AppProtection inspects an application only when the application is set up for it on a segment. When creating an application segment, the web applications that require AppProtection can be identified, with controls from an AppProtection profile applied before Private Access provides access. [zpa.appprotection.segment-opt-in:what-it-is]

**The switch.** The segment's Auto AppProtection setting lets the segment's traffic be inspected by AppProtection; enabling it requires an Enrollment (CA) Certificate. [zpa.appprotection.segment-opt-in:auto-appprotection] AppProtection is enabled per application with the Inspect AppProtection Application checkbox, which is selected by default when AppProtection is enabled. [zpa.appprotection.segment-opt-in:per-application-checkbox]

**Exclusions.** Active Directory Inspection and AppProtection cannot be enabled together on a segment. [zpa.appprotection.segment-opt-in:ad-exclusive] AppProtection is not supported for extranet resources, so the setting is Disabled on such a segment. [zpa.appprotection.segment-opt-in:extranet] The current Multimatch blockers are in [Multimatch prerequisites, restrictions and App Connector selection](kb:zpa.app-segments.multimatch-requirements). When Multimatch is enabled, a Multimatch Validation window lists impacted application segments and conflicting features, with a warning for a conflict. [zpa.appprotection.segment-opt-in:multimatch-validation]

**Application settings.** An AppProtection application takes a web server certificate and a protocol of Dynamic, HTTPS or HTTP. [zpa.appprotection.segment-opt-in:cert-and-protocol] Private Access supports the HTTP and HTTPS protocols for AppProtection applications. [zpa.appprotection.segment-opt-in:protocols] Enabling AppProtection selects Use Untrusted Certificates by default, because it must be selected to verify the CA certificate of AppProtection-enabled applications; with it cleared, the App Connector verifies the server certificate and a self-signed one fails. [zpa.appprotection.segment-opt-in:untrusted-cert] Selecting both Browser Access and AppProtection requires HTTP or HTTPS, and automatically selects Use Untrusted Certificates, which must stay selected for Browser Access. [zpa.appprotection.segment-opt-in:browser-access-combo]

**From Protocol Discovery.** For a displayed application segment that does not yet have AppProtection enabled and that the admin wants to inspect, clicking the segment or one of its domain, port or protocol items on the Protocol Discovery dashboard opens the Enable AppProtection window. If the segment has no domains with AppProtection enabled and no AppProtection profile and policy exist, the AppProtection Profile Type can be adjusted and the Auto create an AppProtection policy checkbox selected. The page says to make sure the AppProtection enrollment (CA) certificate is also generated to use the feature. [zpa.appprotection.segment-opt-in:enable-from-discovery] Protocol Discovery allows AppProtection to be enabled for a domain with a single port or for all of the TCP or UDP ports configured with the application segment, and clicking the same domain with a different port than the inspected one prompts to enable inspection on all the ports for that domain. [zpa.appprotection.segment-opt-in:discovery-port-scope]

**Clients.** With AppProtection enabled on an application, Client Connector access is applied automatically, and users reach it from a web browser that supports TLS 1.2 with cipher suite ECDHE-RSA-AES128-GCM-SHA256, or from Client Connector. [zpa.appprotection.segment-opt-in:access-methods] What happens to a client that does not negotiate that cipher is open [gap:zpa.appprotection.segment-opt-in:non-negotiating-clients], as is whether the constraint still holds on current connector builds [gap:zpa.appprotection.segment-opt-in:cipher-currency].

**Other features.** Whether Private Remote Access and Source IP Anchoring work on a segment with AppProtection is open [gap:zpa.appprotection.segment-opt-in:pra-sipa-compatibility]. Where inspection runs is open [gap:zpa.appprotection.segment-opt-in:placement].

**Programmatic.** In the Python SDK, client.zpa.app_segments_inspection returns an AppSegmentsInspectionAPI, whose add_segment_inspection sets app_types to INSPECT on each apps_config block that has none. [zpa.appprotection.segment-opt-in:sdk-inspect-type] Terraform and Go SDK behavior for inspection application segments is in [What the ZPA Terraform provider sends, keeps and cleans up for application segments and their associations](kb:zpa.terraform.app-segment-lifecycle).

The Active Directory counterpart of this switch: [Active Directory controls: Kerberos, SMB and LDAP inspection](kb:zpa.appprotection.active-directory). The rule that selects the profile: [AppProtection policy rules: actions, criteria and operators](kb:zpa.appprotection.policy).

What to check:
1. Whether the application inside the segment has Inspect AppProtection Application set, rather than only the segment.
2. Whether Active Directory Inspection is on the same segment, which excludes AppProtection.
3. Whether the segment is for extranet resources, where AppProtection is not supported.
4. Whether Multimatch is enabled on a segment that uses AppProtection, using the Multimatch Validation window.
5. That clients are on a browser or Client Connector that supports TLS 1.2 with the stated cipher suite.

Not known (open gaps):
- What happens to a client that does not negotiate the stated TLS 1.2 cipher [gap:zpa.appprotection.segment-opt-in:non-negotiating-clients]: settled by lab-test
- Whether the cipher constraint is current [gap:zpa.appprotection.segment-opt-in:cipher-currency] (data gap): filled by operator; settled by support-ticket or lab-test
- Compatibility of AppProtection with Privileged Remote Access and Source IP Anchoring [gap:zpa.appprotection.segment-opt-in:pra-sipa-compatibility]: settled by lab-test or support-ticket
- Where AppProtection inspection runs in the data path [gap:zpa.appprotection.segment-opt-in:placement]: settled by support-ticket or source-read
