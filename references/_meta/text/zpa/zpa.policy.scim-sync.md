# SCIM sync timing before SCIM criteria are used (zpa.policy.scim-sync)
Also called: scim policy sync; scim attributes in access policy; wait 48 hours scim; scim user not recognized zpa

SCIM criteria depend on user data that the sync must have delivered first.

**Before enabling.** When SCIM is the provisioning method, the initial SCIM cycle should be complete before any SCIM attributes are used in access policies. [zpa.policy.scim-sync:scim-initial-cycle-first] Zscaler recommends waiting a minimum of 48 hours, sometimes up to a week, after SCIM sync is enabled before enabling SCIM policies. [zpa.policy.scim-sync:scim-wait-48-hours]

**What happens meanwhile.** After SCIM is enabled, Zscaler checks whether a user is present in the SCIM database to decide whether the user is allowed or blocked access to ZPA, and if sync is incomplete the ZPA service evaluates policies on the users it does not recognize. [zpa.policy.scim-sync:scim-user-presence-decides] The result for an unrecognized user is open [gap:zpa.policy.scim-sync:mid-sync-result].

The SCIM criteria themselves are in [Criteria available on ZPA access policy rules](kb:zpa.policy.criteria).

What to check:
1. Before enabling SCIM criteria, check that the initial SCIM cycle has completed for the users the rule covers.
2. If SCIM-scoped users are blocked or allowed unexpectedly, check how long ago SCIM sync was enabled.

Not known (open gaps):
- What an unrecognized mid-sync user gets under a SCIM-scoped rule [gap:zpa.policy.scim-sync:mid-sync-result]: settled by lab-test
