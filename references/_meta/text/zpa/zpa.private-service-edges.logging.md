# Private Service Edge logs in the Log Streaming Service (zpa.private-service-edges.logging)
Also called: pse status log; pse metrics log; zpn_sys_auth_log; zpn_pbroker_comprehensive_stats; private service edge lss; pse cpu utilization log

Two Log Streaming Service log types describe a Private Service Edge.

**Types and relay.** The Log Streaming Service has two Private Service Edge log types: Private Service Edge Status, with source log type zpn_sys_auth_log, and Private Service Edge Metrics, with source log type zpn_pbroker_comprehensive_stats. [zpa.private-service-edges.logging:lss-log-types] The Log Streaming Service has two components, a log receiver and an App Connector, and the events it analyzes are reported primarily by Public or Private Service Edges. [zpa.private-service-edges.logging:lss-components] A Terraform LSS configuration for either Private Service Edge log type requires an App Connector group whose ID receives the forwarded logs. [zpa.private-service-edges.logging:lss-relay-group]

**What each holds.** The status log field CPUUtilization is the CPU utilization in percent and the metrics log field CPUUtilization is the maximum CPU usage in the past five minutes; the monitoring guidance reads CPU from the status log. [zpa.private-service-edges.logging:cpu-in-both-logs] The legacy split is unverified [gap:zpa.private-service-edges.logging:metrics-needed-for-capacity].

What to check:
1. Which log type carries the question: status for connection state and auth, metrics for capacity counters, and note that both include CPUUtilization.
2. Whether an App Connector group exists to relay the logs, since the Log Streaming Service needs an App Connector as its relay.

Not known (open gaps):
- Whether only the metrics log supports capacity monitoring [gap:zpa.private-service-edges.logging:metrics-needed-for-capacity]: settled by source-read. Blocks: advising which log type to stream for capacity
