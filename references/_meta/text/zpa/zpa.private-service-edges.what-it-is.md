# What a ZPA Private Service Edge is (zpa.private-service-edges.what-it-is)
Also called: zpa private service edge; zpa pse; on-prem zpa broker; private service edge for private access; is the zpa pse the same as the zia pse; pse vs public service edge zpa

A ZPA Private Service Edge (PSE) is the customer-side session broker of Private Access; Internet & SaaS has its own Service Edges.

**Identity.** A ZPA Private Service Edge is a single-tenant instance broker that provides the functionality of a Public Service Edge for Private Access in the organization's environment. The organization hosts it within its site or on a cloud service, and Zscaler manages it. [zpa.private-service-edges.what-it-is:single-tenant-broker] Like a Public Service Edge, a Private Service Edge manages the connections between Zscaler Client Connector and App Connectors. It registers with the Private Access Cloud, which lets it download the relevant policies and configurations and enforce all Private Access policies, and it caches path selection decisions. [zpa.private-service-edges.what-it-is:broker-function] A ZPA Appliance is a Private Service Edge host platform: the console shows "ZT-8010-Zscaler Red Hat Image" as the host platform for one. [zpa.private-service-edges.what-it-is:zpa-appliance] The appliance is described in [The ZPA appliance: models, hardware and power, ports, installation troubleshooting and enrollment](kb:zpa.software-components.appliance), which describes it as hardware, in limited availability, with ordering left to the Account team [gap:zpa.private-service-edges.what-it-is:pse-hardware-sales]. The deployment guide gives a different Host Platform string for it [divergence:zpa.private-service-edges.what-it-is:appliance-host-platform].

**Not the ZIA product.** Both Internet & SaaS (ZIA) and Private Access have Service Edges, and Private Access runs on a multi-tenant infrastructure separate from that of Internet & SaaS. [zpa.private-service-edges.what-it-is:separate-from-zia] The ZIA inline inspection cluster is [What a ZIA Private Service Edge is, who runs it, and what it is not](kb:zia.private-service-edge.what-it-is). In Private Access the Service Edge does not inspect the data as traffic flows through it, unlike a Service Edge in Internet & SaaS. [zpa.private-service-edges.what-it-is:no-inspection]

**Relation to Public Service Edges.** A tenant's Private Service Edge groups sit alongside Public Service Edges: a group can be configured to be prioritized over a closer Public Service Edge. [zpa.private-service-edges.what-it-is:coexists-with-public] Each deployed Private Service Edge connects to a Public Service Edge, and the console shows which one. The name that Private Service Edges resolve to locate Public Service Edges is pb2br. [zpa.private-service-edges.what-it-is:upstream-public-se] When the Private Service Edge has no direct connection to the App Connector serving an application, or no App Connector can establish a data connection to the Private Service Edge where the user is connected, the Private Service Edge forwards the request to a Public Service Edge (the nearest one, in the no-direct-connection case). The Public Service Edge connects to the closest App Connector it can reach and completes the request through the Private Service Edge with an additional hop. [zpa.private-service-edges.what-it-is:relay-via-public] The Public tier is in [What a ZPA Public Service Edge is](kb:zpa.public-service-edges.what-it-is).

Where it sits in the tunnel path is in [Tunnels, certificates and firewall requirements on the Private Service Edge path](kb:zpa.private-service-edges.data-path); whether to deploy one is in [When a Private Service Edge is warranted](kb:zpa.private-service-edges.when-to-deploy).

What to check:
1. Which product the question is about, since ZPA and ZIA both have a Private Service Edge and they are different products.
2. Whether the question assumes the Private Service Edge inspects traffic, which a Private Access Service Edge does not.
3. Whether a user whose application is unreachable is being relayed through a Public Service Edge because no App Connector has a data connection to the Private Service Edge.
4. Whether a ZPA Appliance host platform appears on the Private Service Edge, to tell the appliance from a customer-built image.
