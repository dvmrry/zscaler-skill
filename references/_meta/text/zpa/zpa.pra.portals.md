# PRA privileged portals and the PRA Portal: fields, certificates and DNS, what end users see, and console login (zpa.pra.portals)
Also called: privileged portal fields; pra portal notification banner; pra portal certificate type; pra portal cname; pra portal approval reviewers; pra portal my web applications; pra console login window; pra ssh key rsa dsa

A privileged portal is configured on the Privileged Portals page and is what end users open as the PRA Portal. A privileged portal takes a name that cannot contain special characters other than periods, hyphens and underscores, a Status (if disabled, the portal is inaccessible to end users), an optional description, and a Notification Banner with message text shown at the top of the PRA portal page. [zpa.pra.portals:portal-fields] The PRA Portal shows any messages from an admin at the top of the page, and an end user can dismiss them with the Close icon. [zpa.pra.portals:admin-messages]

**Certificate and DNS.** A privileged portal's certificate is Managed (a certificate managed by Zscaler, with a domain prefix entered and a domain suffix chosen from a drop-down) or Custom (an existing certificate chosen from the Portal Server Certificate drop-down, which must support the portal FQDN). For a custom certificate the URL must use HTTPS and be an FQDN. [zpa.pra.portals:certificate-type] A privileged portal's FQDN cannot be configured as an application within an application segment. [zpa.pra.portals:fqdn-not-in-segment] For a privileged portal with a custom certificate, the admin copies the portal's CNAME from its expanded row on the Privileged Portals page, adds it to public DNS and verifies that the portal FQDN resolves to it. The article's example record points at a name ending in pra.p.zpa-app.net. [zpa.pra.portals:dns-custom] The same article says Zscaler automatically manages the public DNS for the FQDN of user portals with a Zscaler-managed certificate. [zpa.pra.portals:dns-managed] Managed certificate suffixes are open [gap:zpa.pra.portals:managed-suffixes].

**Portal settings.** A privileged portal's User Portal for Portal Links setting selects a user portal whose Browser Access applications are then found on the My Web Applications tab in the PRA Portal. The My Web Applications icon is enabled if User Portal for Portal Links has been configured. [zpa.pra.portals:portal-links] A privileged portal's Approval Reviewers are administrator email addresses that get email notifications when a privileged approval request has been created, approved and rejected. To use this feature the admin must have a portals policy with Review Approvals enabled. [zpa.pra.portals:approval-reviewers]

**What end users see.** The privileged consoles an end user can see in the PRA Portal are based on the access policies for the application segments assigned to those consoles, and consoles whose policy rule is set to Deny are not visible. [zpa.pra.portals:consoles-shown] The PRA Portal lists the active, expired and future privileged consoles of the portal, including consoles shared by shared application segments at the Microtenant level. An active console shows its end date, a future console its start date, and an active console without a checkmark can be accessed at any time; a console linked to multiple privileged approvals shows only one, in the order Active then Future then Expired. [zpa.pra.portals:consoles-list] The PRA Portal's Microtenant list shows a Microtenant only if the end user can access a privileged console in it, through privileged approvals or PRA-enabled application segments. The characters & and + cannot be used in the PRA Portal search field. [zpa.pra.portals:microtenants-section] In the PRA Portal the Home icon is displayed, and the My Files icon is interactive, only if the PRA File Transfer System feature is enabled. The Settings icon chooses a keyboard language, display resolution and high quality option for the privileged console, and the logo and favicon can be updated on the Company Profile page. [zpa.pra.portals:portal-icons] The PRA Portal is dependent on the default timeout policy rule's authentication timeout. [zpa.pra.portals:session-timeout]

**Protocols and login.** The PRA Portal marks each console's protocol: SSH is used to remotely access Linux/Unix-based systems, RDP Windows-based systems, and VNC Windows-based systems and Mac-based systems (Mac Screen Sharing). Zscaler supports VNC-enabled privileged consoles that are Remote Frame Buffer (RFB) Protocol compliant. [zpa.pra.portals:protocols] In the User Account for RDP Access window the end user enters an optional Domain, a Username and a Password. A domain must be entered in the Domain field and cannot be combined with the username, and an Azure username needs .\AzureAD\ before it for the login to succeed. [zpa.pra.portals:login-rdp] That rule is for the end-user login window; how a privileged credential holds a domain is in [The domain needs to be specified only when logging in to an RDP console connected to an Active Directory domain; it can also be included in the username.](kb:zpa.pra.credentials:domain-only-for-ad-rdp). In the User Account for SSH Access window the end user enters a username and chooses Password or SSH Key; an SSH key is pasted as a private key with an optional passphrase. When authenticating in SSH-enabled privileged consoles only SSH private keys generated with an RSA or DSA encryption algorithm can be used. [zpa.pra.portals:login-ssh] Whether that key rule matches the privileged credential's key check is open [gap:zpa.pra.portals:ssh-key-algorithms]. In the User Account for VNC Access window the end user enters a username and password. If the VNC display is not working correctly, the end user needs to change the display settings on the machine the VNC is accessing. [zpa.pra.portals:login-vnc]

**Keyboard.** When an end user uses the virtual keyboard in an SSH-privileged console, any entered text is not initially visible; turning the keyboard off and on again, or using the scroll bar to scroll down to the typing display screen, addresses it. [zpa.pra.portals:virtual-keyboard] Legacy: with the virtual keyboard on Windows 7 or 8, locking the screen with the keyboard prevents entering the password, and clearing the already selected key fixes it. [zpa.pra.portals:virtual-keyboard-win7-8-legacy]

The same model for user portals is in [Private Access user portals and portal links: what they are, how users reach them, certificates and DNS, links, download links and the acceptable use policy](kb:zpa.user-portal); the permissions a portals policy gives in the PRA Portal are in [PRA portals policy: file, inspection and approval permissions in the PRA Portal](kb:zpa.pra.portals-policy); shared sessions listed in the PRA Portal are in [PRA live session sharing: participants, invitations, control and ejection](kb:zpa.pra.live-sessions); the privileged credential object is in [PRA credentials, credential pools and the credentials policy](kb:zpa.pra.credentials); the PRA Portal's own timeout rule is in [ZPA timeout policy rules](kb:zpa.policy.timeout-rules).

What to check:
1. Whether a portal that end users cannot open is disabled, or has a custom certificate whose CNAME is not in public DNS.
2. Whether a console is missing from the PRA Portal because its policy rule is Deny, or because the user has no access to it.
3. Whether a login failure with a domain account was typed into the end-user window, where the domain goes in the Domain field, or comes from a privileged credential.
4. Whether an SSH key answer rests on the RSA or DSA rule of the login window, which is not compared to the credential's key check.

Not known (open gaps):
- Which domain suffixes a Managed certificate offers [gap:zpa.pra.portals:managed-suffixes]: settled by tenant-data or source-read
- Whether the RSA or DSA key rule of the login window and the privileged credential's key check describe the same constraint [gap:zpa.pra.portals:ssh-key-algorithms]: settled by lab-test
