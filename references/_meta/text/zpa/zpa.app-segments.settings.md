# Application segment settings that interact: health reporting, connector selection, CNAME, ICMP, encryption and anchoring (zpa.app-segments.settings)
Also called: health_reporting; continuous health reporting; select_connector_close_to_app; closer to application; is_cname_enabled; icmp_access_type; double encryption application segment; inspect_traffic_with_zia; source ip anchor segment; tcp keepalive application segment; policy_style

This subject covers the segment settings whose combinations or defaults change behavior.

**Health reporting.** Health Reporting makes the App Connector report application health continuously (Continuous), while a user is accessing it (On Access) or not at all (None), and the console default is On Access. [zpa.app-segments.settings:health-reporting-default] The Terraform schema defaults differently [divergence:zpa.app-segments.settings:health-reporting-default-differs]. Continuous health reporting cannot be chosen for applications configured with more than 10 ports or when any application in the segment is defined with only a wildcard. [zpa.app-segments.settings:continuous-limits] The pages differ on which segments cannot use Continuous [divergence:zpa.app-segments.settings:continuous-excluded-segments]. How the check works and what each mode means: [How App Connectors check and report application health, and what Continuous, On Access and None mean](kb:zpa.app-segments.health-reporting). The Multimatch limits on Health Reporting are in [Multimatch prerequisites, restrictions and App Connector selection](kb:zpa.app-segments.multimatch-requirements).

**Connector selection.** App Connector Selection Method Closer to Application selects the App Connector with the shortest round-trip time toward the requested application; the default is Closer to User. [zpa.app-segments.settings:closer-to-app] The pages differ on the protocols Closer to Application supports [divergence:zpa.app-segments.settings:closer-to-app-protocols]. Closer to Application cannot be enabled when Health Reporting is None, and when the limit of 6,000 health-check targets at the App Connector is exceeded Health Reporting is set to None and a random selection of App Connectors is chosen. [zpa.app-segments.settings:closer-needs-health] Terraform provider v4.4.6 removed `forceNew` from `select_connector_close_to_app` on `zpa_application_segment`, and the current schema declares it as an optional bool. [zpa.app-segments.settings:forcenew-removed] Other Terraform lifecycle effects on segments are in [What the ZPA Terraform provider sends, keeps and cleans up for application segments and their associations](kb:zpa.terraform.app-segment-lifecycle).

**Adaptive Traffic Steering.** Adaptive Traffic Steering in Private Access is a dynamic rerouting feature that uses real-time network health metrics to redirect traffic automatically to alternate paths when degradation is detected, such as packet loss or increased application round-trip time. [zpa.app-segments.settings:adaptive-traffic-steering] Adaptive Traffic Steering is only available for organizations that have Business Continuity configured; it can be enabled when configuring a defined application segment, and enabling it shows a warning that alternate routing paths can introduce higher latency compared to direct connections. [zpa.app-segments.settings:adaptive-traffic-steering-scope] How path health is measured and which segments qualify is open [gap:zpa.app-segments.settings:adaptive-traffic-steering-detail]. Business Continuity: [Business Continuity for Private Access: prerequisites, domain names, settings, entering and exiting, limitations](kb:zpa.private-service-edges.business-continuity).

**CNAME and ICMP.** Client Connector can receive CNAME is enabled by default, so Zscaler Client Connector receives CNAME DNS records from the App Connector; disabling it means App Connectors do not send CNAME DNS records, and it is not applicable to Browser Access applications. [zpa.app-segments.settings:cname-setting] If Zscaler Client Connector is on a macOS or an iOS device and the application needs to be accessed by CNAME, it is best to disable this setting, which is enabled by default and lets Zscaler Client Connector receive CNAME DNS records from the App Connector. [zpa.app-segments.settings:cname-macos-ios] CNAME-based routing to private link resources: [How private link domains route CNAME-matched traffic to private link resources](kb:zpa.app-segments.private-link-domains). ICMP Access is Disabled by default, and when enabled it lets Zscaler Client Connector, Cloud and Branch Connectors or Source IP Anchor send ICMP to the segment's applications, with access policies allowing or blocking the requests. [zpa.app-segments.settings:icmp-default] If ICMP is enabled for an application in one segment and disabled for the same application in another, Zscaler Client Connector considers ICMP enabled for it and forwards the ICMP request to Private Access. [zpa.app-segments.settings:icmp-or-across-segments] Zscaler Client Connector does not intercept ICMP requests for a destination IP that has the same subnet as the user's machine, since this is considered an unreachable host. [zpa.app-segments.settings:icmp-same-subnet] If an application is blocked based on an access policy, Zscaler Client Connector creates a new Microtunnel request for every ICMP echo request. [zpa.app-segments.settings:icmp-blocked-microtunnel-per-echo] For ICMP, the IP data can appear and the Internal Status Code on the User Activity Diagnostics page can show as successful (for example BRK_MT_TERMINATED) after the App Connector is selected, even though the destination is unreachable; this can occur if the App Connector is set up to provide on access or no health reporting, as health reporting does not work well with ICMP. [zpa.app-segments.settings:icmp-health-reporting] ICMP does not work with Double Encryption. [zpa.app-segments.settings:icmp-double-encryption] The API field `icmpAccessType` takes `PING_TRACEROUTING`, `PING` or `NONE`. [zpa.app-segments.settings:icmp-access-type-values]

**Encryption and anchoring.** Double Encryption cannot be enabled when Browser Access or Source IP Anchoring is selected for any application, and should be disabled for extranet application segments. [zpa.app-segments.settings:double-encryption-exclusions] What Double Encryption does and costs: [What Double Encryption does, when to use it and what it costs](kb:zpa.app-segments.double-encryption). Source IP Anchor on a segment is tied to Source IP Anchoring for Internet & SaaS: when enabled the segment can be connected to in Internet & SaaS, and it cannot be deleted while in use by an Internet & SaaS entity. [zpa.app-segments.settings:sipa-link-enabled] Source IP Anchor and Inspect Traffic with ZIA cannot both be enabled on a segment; Source IP Anchor must be disabled first. [zpa.app-segments.settings:sipa-inspect-zia-exclusive] Whether Source IP Anchor excludes Browser Access is open [gap:zpa.app-segments.settings:sipa-browser-access]. The ZIA side of anchoring: [The ZPA Application Segment criterion lists only segments that have Source IP Anchor enabled (up to 255 selectable); in the API it is the `zpaAppSegments` list, documented as Source IP Anchoring-enabled segments.](kb:zia.ssl-inspection.criteria:zpa-segments-sipa-only). Full anchoring mechanics: [Source IP Anchoring across ZIA and Private Access: path, pieces and interactions](kb:shared.source-ip-anchoring).

**Other settings.** Inspect Traffic with ZIA lets a segment use a single posture for securing internet or SaaS and private applications and applies Data Loss Prevention policies to it. [zpa.app-segments.settings:inspect-zia-purpose] TCP Keepalive makes the App Connector periodically send TCP keepalives to an application server a user has accessed on a TCP port, and is disabled by default. [zpa.app-segments.settings:tcp-keepalive] The Terraform provider describes `policy_style` as dual policy evaluation, which resolves the FQDN to the server IP and enforces policy on both: false is NONE (disabled) and true is DUAL_POLICY_EVAL (enabled). [zpa.app-segments.settings:policy-style-tf]

The Python docstring omits one contract value [divergence:zpa.app-segments.settings:icmp-python-docstring-values].

What to check:
1. Whether Health Reporting is Continuous on a segment with more than 10 ports or a wildcard-only entry, which the console does not allow.
2. Whether a connector-proximity change is planned through Terraform, and which provider version is in use.
3. Whether ICMP is enabled on one segment for an application and disabled on another, since the client treats it as enabled.
4. Whether Double Encryption, Source IP Anchoring, Browser Access and Inspect Traffic with ZIA are combined on one segment.

Sources disagree (name both sides):
- The Health Reporting page and the Defined Application Segments page name different segments that cannot use Continuous health reporting. [divergence:zpa.app-segments.settings:continuous-excluded-segments]
  - zscaler-help: Continuous cannot be configured for application segments configured for application discovery, meaning domain names in wildcard format or IP subnets such as *.safemarch.com or 10.122.0.0/16.
  - zscaler-help: Continuous cannot be chosen if any application in the segment is defined with only a wildcard such as *; the page names no other wildcard or subnet exclusion.
  Impact: Both pages also exclude segments with more than 10 ports. Whether a segment with a domain wildcard such as *.safemarch.com or an IP subnet can use Continuous depends on which page is right, so answer from the tenant's console rather than either page.
- Two live pages disagree on which protocols Closer to Application supports: the AI-Powered Recommendations page, which embeds a copy of the segment form, and the Defined Application Segments page (the newer revision). [divergence:zpa.app-segments.settings:closer-to-app-protocols]
  - zscaler-help: Closer to Application supports only TCP applications.
  - zscaler-help: Closer to Application supports TCP and UDP applications, and UDP is enabled by contacting Zscaler Support.
  Impact: Whether Closer to Application applies to a UDP application is not settled; the claim closer-to-app states no protocol scope.
- The help article and the Terraform schema give different defaults for Health Reporting. [divergence:zpa.app-segments.settings:health-reporting-default-differs]
  - zscaler-help: The console default is On Access.
  - tf-zpa: The provider schema defaults `health_reporting` to NONE.
  Impact: A segment created through Terraform without `health_reporting` is sent with NONE, not the console's On Access, and NONE also blocks Closer to Application.
- The OpenAPI document gives `icmpAccessType` three values, while the Python add_segment_provision docstring lists two. [divergence:zpa.app-segments.settings:icmp-python-docstring-values]
  - api-specs: The contract enum is PING_TRACEROUTING, PING and NONE.
  - sdk-python: The Python add_segment_provision docstring says the values are PING and NONE.
  Impact: A caller who trusts the Python docstring will not offer PING_TRACEROUTING; the SDK does not validate the value, so passing it as a raw string is not blocked by the SDK.
