# ZPA Terraform provider configuration: no-credential mode, authentication framework, clouds and rate limits (zpa.terraform.provider-config)
Also called: zpa provider skip_credentials_validation; zpa provider use_legacy_client; zpa provider fedramp gov; zpa provider parallelism; zpa terraform inert client; ZPA_MICROTENANT_ID

The ZPA provider authenticates with OneAPI by default and with the legacy ZPA framework on request, and has an inert mode for configurations that never call the API. The provider implements only the features the public ZPA API exposes, so a feature in the Admin Console may be missing from the provider without the provider lagging. [zpa.terraform.provider-config:api-parity-only]

**No-credential mode.** The attribute is documented for configurations in which every zpa_* resource and data source is conditionally disabled (for example count = 0), and it can be set with ZSCALER_SKIP_CREDENTIALS_VALIDATION. [zpa.terraform.provider-config:skip-credentials-intended-use] With skip_credentials_validation on, the provider never builds the SDK client: it returns an inert client with a configure-time warning, because the OneAPI SDK authenticates inside its constructor. [zpa.terraform.provider-config:skip-credentials-inert-client] Every resource and data source has its create, read, update, delete and import handlers wrapped so that, with the inert client, any attempt to call the API returns a descriptive provider error instead of a nil-pointer panic. [zpa.terraform.provider-config:skip-credentials-guards-crud-import] skip_credentials_validation was added in provider v4.4.11. [zpa.terraform.provider-config:skip-credentials-added-4-4-11]

**Precedence with the environment variable.** The provider reads the explicit skip_credentials_validation value with d.GetOk and consults ZSCALER_SKIP_CREDENTIALS_VALIDATION only when GetOk reports the value as not set. [zpa.terraform.provider-config:skip-flag-env-fallback] Whether an explicit false defeats the environment variable is open [gap:zpa.terraform.provider-config:getok-false-reads-as-unset].

**Authentication framework.** From provider v4.0.0 the provider offers OneAPI (OAuth 2.0 through Zidentity) alongside the legacy ZPA API framework, and the docs recommend the legacy framework for tenants not yet migrated to Zidentity. [zpa.terraform.provider-config:legacy-since-4-0] The provider chooses the legacy ZPA client when use_legacy_client is true, from the provider attribute or, when that is unset, from ZSCALER_USE_LEGACY_CLIENT being the string true. [zpa.terraform.provider-config:legacy-client-switch] The provider docs say OneAPI credentials can be supplied through ZSCALER_CLIENT_ID, ZSCALER_CLIENT_SECRET, ZSCALER_VANITY_DOMAIN and ZSCALER_CLOUD, with customer_id from ZPA_CUSTOMER_ID, and legacy credentials through ZPA_CLIENT_ID, ZPA_CLIENT_SECRET, ZPA_CUSTOMER_ID and ZPA_CLOUD. They also name ZSCALER_PRIVATE_KEY for private_key, which conflicts with client_secret, and ZSCALER_HTTP_PROXY for http_proxy. The provider's config code, not the schema, reads these ZSCALER_* variables when the matching attribute is empty. [zpa.terraform.provider-config:credential-env-vars]

**Clouds.** zscaler_cloud is optional for production commercial clouds and only required for other environments; the documented values are beta for the test commercial cloud and gov or govus for FedRAMP. [zpa.terraform.provider-config:commercial-cloud-optional] OneAPI reaches the government (FedRAMP) clouds through zscaler_cloud (or ZSCALER_CLOUD) set to gov or govus, and the provider documents this as supported only from v4.4.6; earlier versions are not supported. [zpa.terraform.provider-config:fedramp-oneapi-4-4-6] In legacy mode ZPA_CLOUD is needed only for the BETA, GOV, GOVUS, PREVIEW and ZPATWO clouds, and the zpa_cloud validator accepts PRODUCTION, ZPATWO, BETA, GOV, GOVUS, PREVIEW, DEV, QA and QA2 case-insensitively, or any value that begins with https://. [zpa.terraform.provider-config:legacy-cloud-values]

**Microtenant scope.** ZPA_MICROTENANT_ID sets the microtenant for resources in a run; the provider documents it as the recommended way to configure microtenant_id, which requires the microtenant license and feature flag on the tenant. [zpa.terraform.provider-config:microtenant-env-var]

**Rate limits.** Rate limits are handled by the provider: it honours the Retry-After header returned on a 429 response and retries transparently. [zpa.terraform.provider-config:rate-limit-retry-after] The provider's parallelism attribute is deprecated, has no effect, and is to be removed in a future major release. [zpa.terraform.provider-config:parallelism-deprecated-ignored] Provider v4.4.12 deprecated the backoff, min_wait_seconds and max_wait_seconds attributes, which are now ignored; the documented defaults are 100 for max_retries, which is also its maximum, and 240 seconds for request_timeout, where 0 selects the SDK's built-in 60-second timeout. [zpa.terraform.provider-config:retry-tuning-4-4-12] The v4.4.11 release notes removed the older guidance to limit concurrent API calls to one for the access, inspection, timeout, forwarding and isolation policy rule resources, because Terraform's -parallelism flag applies to the whole run and cannot be scoped to a resource type. [zpa.terraform.provider-config:one-concurrent-call-guidance-removed]

**Read failures.** Provider v4.4.7 changed the read functions of zpa_application_segment, zpa_server_group, zpa_service_edge_group and zpa_lss_config_controller so that transient API errors such as cancelled or timed-out requests surface as recoverable Terraform errors instead of crashing the provider. [zpa.terraform.provider-config:read-panics-fixed-4-4-7]

Credential and secret handling is covered in [How the Zscaler Terraform providers store, log, and send secrets](kb:shared.terraform.credential-handling); the equivalent ZIA modes are in [ZIA Terraform provider authentication, client modes and rate limiting](kb:zia.terraform.provider-modes).

What to check:
1. Whether the configuration sets skip_credentials_validation or inherits ZSCALER_SKIP_CREDENTIALS_VALIDATION, since either leaves the provider with no API client.
2. The provider version, which decides whether skip_credentials_validation and FedRAMP OneAPI are available.
3. Whether use_legacy_client or ZSCALER_USE_LEGACY_CLIENT is set, which selects the legacy framework.

Not known (open gaps):
- Whether an explicit skip_credentials_validation = false overrides ZSCALER_SKIP_CREDENTIALS_VALIDATION=true [gap:zpa.terraform.provider-config:getok-false-reads-as-unset]: settled by lab-test or source-read. Blocks: knowing whether setting the attribute to false is enough to switch off an inherited environment variable
