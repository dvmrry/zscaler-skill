# App Connector groups (zpa.app-connectors.connector-groups)
Also called: app connector group; connector group settings; connector group dns resolution; enrollment_cert_id app connector group; user_codes verification; server group to connector group; connector group version profile

The App Connector group is the unit that holds connectors together: it carries the enrollment association, the update schedule, DNS option and location.

**Membership.** Every App Connector belongs to exactly one App Connector group, and a group should always be associated with at least one OAuth 2.0 enrollment token or provisioning key and one server group to serve any application. [zpa.app-connectors.connector-groups:every-connector-one-group] Zscaler recommends deploying App Connectors in groups for high availability and horizontal scaling, per region or functional area, and an existing group can take a new connector without creating a new group. [zpa.app-connectors.connector-groups:groups-for-ha] Application segments reference server groups, and server groups reference App Connector groups. [zpa.app-connectors.connector-groups:segment-server-group-chain] What happens with a missing association is unsourced [gap:zpa.app-connectors.connector-groups:unassociated-group-behavior]. A group configured with Zscaler Deception, or managed by Zscaler, has its edit and delete options unavailable. [zpa.app-connectors.connector-groups:managed-read-only]

**Group settings.** A group sets the automated update schedule for an off-hours window, the preferred local version profile, and the location used in application path selection. [zpa.app-connectors.connector-groups:group-settings] The group's DNS Resolution Option selects IPv4, IPv6 or both for application DNS resolution checks; the default is IPv4 and IPv6, and Terraform's dns_query_type defaults to IPV4_IPV6 with the values IPV4_IPV6, IPV4 and IPV6. [zpa.app-connectors.connector-groups:dns-resolution-option] IPv6 should be selected only with end-to-end IPv6 support, and the connectors' interfaces must match the option for the resolution checks to work. [zpa.app-connectors.connector-groups:ipv6-needs-end-to-end] A new group's Version Profile defaults to Default, the cloud-wide stable and default build, and Persist Local Version Profile defaults to disabled. [zpa.app-connectors.connector-groups:version-profile-defaults] Both reference modules default the group's upgrade day to SUNDAY, upgrade time to 66600 (an integer in seconds) and dns_query_type to IPV4_IPV6. [zpa.app-connectors.connector-groups:module-group-schedule-dns-defaults] Both modules default override_version_profile to false. The Azure module defaults version_profile_id to 0; the AWS module sends 0 when override is false and, when override is true with no explicit ID, resolves the tenant's Default customer version profile. [zpa.app-connectors.connector-groups:module-group-version-profile] city_country is an optional input in both modules (empty by default); the AWS module has no ignore_changes on the group, while the Azure module sets ignore_changes = [city_country] because the API derives the value from latitude and longitude. [zpa.app-connectors.connector-groups:module-city-country]

**Enrollment certificate and user codes.** [When the value is missing or empty, the resolver looks the certificate up by name, fails the operation on a lookup error or an empty ID, and otherwise sets enrollment_cert_id to the resolved ID.](kb:zpa.terraform.group-enrollment:resolver-lookup-by-name) The ZPA Ansible App Connector Group module resolves the enrollment certificate named Connector when enrollment_cert_id is omitted. [zpa.app-connectors.connector-groups:ansible-resolves-cert] The Python SDK documented this behavior without doing it up to v1.11.1 [divergence:zpa.app-connectors.connector-groups:python-cert-docstring-vs-code]. From Python SDK v1.11.2, `add_connector_group` and `update_connector_group` fill in a missing `enrollment_cert_id` by looking up the `Connector` enrollment certificate (the service edge group functions look up `Service Edge`); an ID the caller passes is used as given (#596). v1.11.1 had first corrected the docstring to say the SDK does no lookup (#595). [zpa.app-connectors.connector-groups:python-cert-auto-lookup] What the API does with a create that omits the certificate is still open [gap:zpa.app-connectors.connector-groups:create-missing-cert-error]. The provider verifies user_codes after create when any are set and after update only when user_codes changed; a verification failure returns an error even though the group was already written. [zpa.app-connectors.connector-groups:provider-verifies-user-codes] The same verification step for other group types is in [ZPA Terraform resources: fields not sent, not read back, or written in several non-atomic steps](kb:zpa.terraform.resource-fidelity).

**Tooling fields.** The Python App Connector Group model carries enrollment certificate, version-profile override, site and private cloud identifiers alongside the base group fields. [zpa.app-connectors.connector-groups:python-model-group-fields] Whether a group resource that omits its members block drifts in Terraform is unverified [gap:zpa.app-connectors.connector-groups:group-connector-blocks-drift]. The July 16, 2026 release summary lists an update that lets admins edit App Connector groups on the Where are my apps being served from? page to resolve unknown app hosting and location details. [zpa.app-connectors.connector-groups:served-from-edit-july16]

Provider lookup and delete behavior for groups is in [Which object a ZPA Terraform data source actually returns](kb:zpa.terraform.data-source-selection) and [What the ZPA Terraform provider does when deleting objects with dependents](kb:zpa.terraform.delete-paths). Update scheduling is in [App Connector software and host OS updates](kb:zpa.app-connectors.upgrades); the enrollment methods are in [App Connector enrollment, certificates and re-enrollment](kb:zpa.app-connectors.enrollment).

In the Python SDK model, an App Connector group built from a response that omits praEnabled, wafDisabled, lssAppConnectorGroup or the three tcpQuickAck flags reads each as False, while a group built with no response at all reads lssAppConnectorGroup as None; the OpenAPI document describes wafDisabled as AppProtection being disabled for the group and lssAppConnectorGroup as the group being configured to stream logs to a log receiver. [zpa.app-connectors.connector-groups:group-flag-defaults]

The API reference says the tcpQuickAckApp, tcpQuickAckAssistant and tcpQuickAckReadAssistant fields must all share the same value, and the Terraform documentation repeats it for the three arguments. [zpa.app-connectors.connector-groups:tcp-quick-ack-same-value]

The Python App Connector group model carries an npAssistantGroup object carrying its own mtu, redundantModeEnabled, externalRouters and lanSubnets, each LAN subnet holding an npDnsNsRecord. [zpa.app-connectors.connector-groups:np-assistant-group-model]

The Terraform provider suppresses a plan difference on a connector group's latitude or longitude when the old and new values are equal after rounding to six decimal places. [zpa.app-connectors.connector-groups:tf-coordinates-six-decimals]

The contract and the Python docstring agree on the DNS query values: The OpenAPI document gives `dnsQueryType` on an App Connector Group the values IPV4_IPV6, IPV4 and IPV6, and the Python create docstring lists the same three. [zpa.app-connectors.connector-groups:dns-query-type-contract-values]

The group coordinates are strings with a range check: An App Connector Group's `latitude` is a string in the OpenAPI document, the Go struct and the Terraform schema. The provider's ValidateLatitude checks the parsed value is in -90..90; a value that does not parse is rejected. The connector-level latitude in the same response is a read-only double. [zpa.app-connectors.connector-groups:latitude-longitude-string]

A direct Go update with no certificate ID sends no certificate key: The Go SDK Update for App Connector, Service Edge and Private Cloud groups sends the group object the caller supplies and looks up no enrollment certificate, and `enrollmentCertId` is tagged `omitempty` on the group, so an empty value is left out of the body. [zpa.app-connectors.connector-groups:go-update-no-cert-lookup]

The Go test creates groups with an explicit Connector certificate: The Go App Connector Group integration test looks up the enrollment certificate named Connector and sends its ID in the create request. [zpa.app-connectors.connector-groups:go-test-sends-connector-cert]

The MCP tool resolves the certificate before it calls the SDK: The MCP App Connector Group create tool resolves the tenant's standard Connector enrollment certificate when none is supplied and passes the resolved ID to the Python SDK. [zpa.app-connectors.connector-groups:mcp-create-resolves-cert]

Whether the API rejects a create without the certificate, and under which name, is open [gap:zpa.app-connectors.connector-groups:create-missing-cert-error].

The three TCP quick acknowledgement flags must be equal, and the Terraform resource enforces that itself before calling the API [The App Connector group resource rejects, on create and update, a request whose three tcp_quick_ack flags are not all equal, with the provider-side error that the tcpQuickAck flags need to be consistent; the docs say the three fields must share one value.](kb:zpa.terraform.resource-constraints:quick-ack-flags-checked-by-provider).

What to check:
1. Which server group connects the segment to this group and whether the group has an enrollment key or token, since a group serves traffic only with both.
2. Whether the group's DNS resolution option matches the interfaces the connectors and the application servers support.
3. Whether enrollment_cert_id came from the caller or from the provider or Ansible lookup, before reading a plan diff on it.
4. Whether a user_codes verification error left a group written but unverified.

Sources disagree (name both sides):
- The Python SDK's group create docstring says the provider resolves the enrollment certificate when omitted, but the SDK code does no lookup. [divergence:zpa.app-connectors.connector-groups:python-cert-docstring-vs-code]
  - sdk-python: The docstring tells the caller the certificate is looked up and populated when enrollment_cert_id is not set.
  - sdk-python: add_connector_group sends the caller's keyword arguments as the request body, with no certificate lookup.
  Impact: Up to v1.11.1 the auto-resolution was Terraform-provider and Ansible behavior only, so a direct Python SDK create had to pass enrollment_cert_id explicitly.
  Resolved (fixed-upstream) by zpa.app-connectors.connector-groups:python-cert-auto-lookup: Both positions describe v1.10.0; v1.11.2 does the lookup the docstring described.
