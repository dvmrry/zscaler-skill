# Reference Terraform modules for Private Service Edges on AWS and Azure (zpa.private-service-edges.reference-modules)
Also called: terraform aws private service edge module; terraform azure private service edge module; pse asg; pse vmss; pse onboarding_method; psevm_instance_type; module defaults private service edge

The reference modules deploy Private Service Edge VMs and wrap the group resource.

**Instances.** The AWS Private Service Edge VM module defaults to m5.large and validates the type against t3.xlarge, m5.large, m5.xlarge, m5.2xlarge and m5.4xlarge. [zpa.private-service-edges.reference-modules:aws-instance-type] The Azure Private Service Edge VM module defaults to Standard_D4s_v3 and validates the size against Standard_D2s_v3, Standard_D4s_v3 and Standard_F4s_v2. [zpa.private-service-edges.reference-modules:azure-instance-size] The AWS Auto Scaling Group module defaults to a minimum of 2, a maximum of 4 and a 50 percent average-CPU target. [zpa.private-service-edges.reference-modules:aws-asg-defaults] The Azure VMSS example defaults to a minimum of 2 and a maximum of 10 Private Service Edges. [zpa.private-service-edges.reference-modules:azure-vmss-defaults]

**Onboarding.** The AWS modules default to OAuth2 user-code onboarding, relaying each VM's code through AWS SSM Parameter Store, and require the ZPA Terraform provider 4.4.0 or later for it. [zpa.private-service-edges.reference-modules:aws-oauth-default] The Azure VMSS example defaults onboarding_method to "oauth", relaying user codes through Azure Key Vault, and "provisioning_key" selects the legacy flow. [zpa.private-service-edges.reference-modules:azure-oauth-default] The enrollment mechanics are in [Enrolling a Private Service Edge](kb:zpa.private-service-edges.enrollment).

**Group wrapper.** The AWS group wrapper defaults pse_group_enabled to true, pse_is_public to false, pse_group_upgrade_time_in_secs to "66600" and pse_group_override_version_profile to false. [zpa.private-service-edges.reference-modules:wrapper-defaults] Grace distance and DR mode are not exposed [gap:zpa.private-service-edges.reference-modules:wrapper-omits-grace-dr].

**Not quoted.** The AWS network and IAM resources are unverified [gap:zpa.private-service-edges.reference-modules:aws-security-iam], as is the example catalog [gap:zpa.private-service-edges.reference-modules:example-catalog].

What to check:
1. Which instance type or size the module deploys, since the AWS and Azure defaults differ.
2. Which onboarding method the module used; both default to OAuth2 user codes.
3. Whether the group wrapper sets grace distance or DR mode, which it does not expose.
