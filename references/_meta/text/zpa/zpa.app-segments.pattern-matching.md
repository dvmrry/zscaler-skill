# What pattern matching in FQDN application segments is, its characters, limit and prerequisites, and how it picks App Connectors (zpa.app-segments.pattern-matching)
Also called: pattern matching; application segment patterns; asterisk and question mark in FQDN; pattern matching application segments

Pattern matching is in limited availability; Private Access supports patterns within FQDN-based application segments, which also future proofs the configuration when new servers come online and match the existing patterns, so no configuration changes are required in the application segment definition. [zpa.app-segments.pattern-matching:what-it-is] The asterisk (*) and question mark (?) are the supported characters for pattern configuration in application segments. The page's examples put a pattern in the initial part of the FQDN (*.acme.com, *nonprod.acme.com) or in the middle part (psl*.ms.acme.com, www.jira*.acme.com, *w*.acme.com), and use ? as in w?w.jira.acme.com and w??.jira.acme.com. [zpa.app-segments.pattern-matching:characters-and-forms] The maximum number of patterns an admin can configure is 500. [zpa.app-segments.pattern-matching:limit]

**Prerequisites.** Multimatch must be enabled on the tenant and the specific application segment, and App Connectors must be upgraded to version 24.298.1 or later. Client Connector must be at Windows 4.7.0.88 or 4.6.0.282 or later, macOS 4.5.2.98, iOS 4.4.1, Android 3.10 or Linux 4.2 or later, and for iOS applications the Use Tunnel SDK Version 4.3 or above setting must be enabled in the Zscaler Admin Console. [zpa.app-segments.pattern-matching:prerequisites] The Private Service Edge floor is open [gap:zpa.app-segments.pattern-matching:service-edge-floor]. The same version set is in [Multimatch prerequisites, restrictions and App Connector selection](kb:zpa.app-segments.multimatch-requirements).

**App Connector selection.** Pattern matching does not select the most specific application for App Connector selection, so at least one App Connector group should be available for similar applications; when application access matches multiple application segments for pattern matching, the App Connector selection is based on the most specific application segments that are pattern matching, regardless of the segment that matches the access policy rule. [zpa.app-segments.pattern-matching:connector-selection] In the page's example, a request for important-server1.eu.example.com on TCP port 22 matches AS1, AS2, AS3 and AS4 because these are the most specific application segments with pattern matching, but since AS4 is the wildcard application segment and AS5 does not have Multimatch enabled, App Connector selection applies only to SG1, SG2 and SG3. [zpa.app-segments.pattern-matching:selection-example] How specificity ranks among patterns and what pattern matching does to policy matching is open [gap:zpa.app-segments.pattern-matching:specificity-and-policy].
