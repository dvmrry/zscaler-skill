# DSPM investigation queries (predicates, results, saving) and the Data Discovery, AI Data Access and SaaS Overview dashboards (dspm.investigation)
Also called: dspm investigation; dspm query; dspm predicates; dspm save as policy; dspm data discovery dashboard; dspm ai data access dashboard; dspm saas overview dashboard

An investigation is a query on cloud resources that can be saved as an investigation query or converted into a custom security policy, without creating alerts or filtering the dashboard. [dspm.investigation:purpose] An existing or saved investigation query can be edited, but only saved investigation queries can be deleted. [dspm.investigation:edit-delete] The Investigation page's History tab displays by default all queries the user has created, and the Saved tab shows the saved queries. [dspm.investigation:history-saved]

**Results.** Investigation results show resources with the highest severity first, and sorting on Risk or Resource Name lists highest-risk resources first. [dspm.investigation:results-ordering] From investigation results you can click Save as Policy to convert the query into a custom policy or Export to download an Excel report. [dspm.investigation:results-actions] Custom policies are in [How DSPM data posture policies work: threat categories, custom policy queries, managing policies, and the compliance frameworks that map to them](kb:dspm.policies).

**Predicates.** Investigation predicates and operators are offered in categories to build highly contextual queries, and the combination of predicates and operators is specific to each primary resource. [dspm.investigation:predicate-categories] Access predicates define the network access levels for the resource: Publicly Accessible (true if the resource can be accessed from the internet) and Public Exposure Details (a JSON object, with exposed ports and IP ranges for network-level exposure). [dspm.investigation:access-predicates] The Has Data predicates include Sensitive Data Triggers (number of DLP trigger matches), Sensitive Data Volume (the volume of sensitive data found and the size, in KB, of the file containing it) and Last Completed Scan. [dspm.investigation:has-data-predicates] The Has Malware predicate applies to malware detected in AWS S3 buckets, Azure virtual machines and storage accounts, and GCP storage buckets. [dspm.investigation:malware-predicate] The Has Vulnerability predicate includes CVE ID (as defined in the NVD) and Fix Available (true if a fix is available as defined in the NVD), and Is Vulnerable checks whether the resource contains packages with vulnerabilities. [dspm.investigation:vulnerability-predicates] In investigations, the Guardrails posture predicate checks whether Guardrails is enabled for an AWS Bedrock Agent, and a posture predicate Exposed to AI service returns true if the resource is exposed to an AI service such as Azure AI Foundry. [dspm.investigation:posture-predicates-guardrails] The Has Models predicate is available only for AI-related resource types such as AWS Bedrock, Azure AI Foundry and vertex AI resources, and the Has AI Package Package Status values are Sanctioned, Unsanctioned or Pending. [dspm.investigation:ai-predicates] The investigation posture predicates include Is Dormant (checks whether the user has logged in over the last 90 days) and Stale Access Keys (checks whether access keys have been rotated in the last 90 days). [dspm.investigation:posture-predicates-dormant] The page does not label which cloud each posture table belongs to [gap:dspm.investigation:posture-tables-unlabelled]. Is Dormant and Stale Access Keys are worded differently from the posture state; the open question is recorded under [What Is Dormant means against the Dormant Identity posture state](kb:dspm.inventory:dormant-wording) and the posture state is in [Identity posture thresholds: Stale Password is a password not valid and not changed for more than 90 days, Dormant Identity is inactive for more than 90 days, and Stale Access Key is an access key not rotated for more than 90 days.](kb:dspm.inventory:posture-identity-90-days). The Has Service Account Keys predicate is unavailable for some resources [gap:dspm.investigation:service-account-key-availability]. A label slip on the GCP Logging predicate is noted [gap:dspm.investigation:predicate-label-slips].

**Data Discovery dashboard.** The Data Discovery dashboard has widgets for Data Stores Discovered and Scanned (with Gen AI Classification and DLP Engines tabs), Top Accounts by Sensitive Data, Top Data Stores by Sensitive Data, Data Insights and Data Regions. [dspm.investigation:discovery-widgets] On the Data Discovery dashboard, the Top Accounts by Sensitive Data and Top Data Stores by Sensitive Data widgets list entries in descending order of the amount of sensitive data and alerts triggered. [dspm.investigation:discovery-top-ordering] The Data Regions widget is a world map of the regions where cloud accounts and data stores are located; the Show sensitive data only checkbox limits it to regions with data stores containing sensitive data, and circle size is relative between regions by number of sensitive records. [dspm.investigation:discovery-region-map]

**AI Data Access dashboard.** The AI Data Access dashboard can be filtered by cloud, business unit, account and region, and its AI Metrics tiles are Deployed AI, Data Shared with AI and Open Alerts on AI Resources. [dspm.investigation:ai-access-metrics] On the AI Data Access dashboard, the Show Sensitive Data Only checkbox limits the DLP Engines chart to DLP engines marked as sensitive. [dspm.investigation:ai-access-sensitive-only] One widget repeats another widget's text [gap:dspm.investigation:ai-top-data-shared].

**SaaS Overview dashboard.** The SaaS Overview dashboard categorizes SaaS data loss incidents as Private (compromise sensitive information), Internal (a data security breach within the organization) or External (originated outside the organization). [dspm.investigation:saas-incident-types] The SaaS Overview dashboard has SaaS Incidents and Top Users with SaaS Incidents bar charts and a SaaS Application with Data Exposure table whose columns include Application Tenant Name and Total Incidents. [dspm.investigation:saas-widgets]
