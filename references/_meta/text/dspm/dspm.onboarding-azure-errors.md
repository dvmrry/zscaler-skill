# Which errors the vendor documents while onboarding Azure to DSPM, and the resolution each row gives (dspm.onboarding-azure-errors)
Also called: dspm azure errors; resolving configuration issues microsoft azure; dspm terraform errors azure

The CLI error "Role not found Error: loading Role Definition List: could not find role <role name>" or "Account in pending state from long time" is resolved by rerunning the template. [dspm.onboarding-azure-errors:role-not-found] The Admin Console message "Admin consent has not been granted to the necessary APIs. Please provide consent to the necessary APIs." is resolved by granting API permissions to the service principal. [dspm.onboarding-azure-errors:admin-consent] The Terraform planning error "Invalid value for input variable" is resolved by entering at least one deployment region in the format ["region 1", "region 2"]. [dspm.onboarding-azure-errors:invalid-input-region] The CLI error "Error acquiring the state lock ... state blob is already locked" is resolved with terraform force-unlock <ID>. [dspm.onboarding-azure-errors:state-lock] "Error: Provider produced inconsistent result after apply" is resolved by running terraform destroy, redeploying the Azure onboarding template and using a different container in backend.tf. [dspm.onboarding-azure-errors:inconsistent-result] The ConflictError from an az keyvault update command run by a local-exec provisioner is resolved by running terraform apply -auto-approve -parallelism=1. [dspm.onboarding-azure-errors:conflict-error-parallelism] The "Resource type mismatch" error (a move from null_resource.management_reader to terraform_data.management_reader) is resolved by upgrading Terraform to the latest version. [dspm.onboarding-azure-errors:terraform-version-mismatch] The error that a key "control-plane-cmk" already exists and must be imported into Terraform state is resolved with terraform import for module.control_plane...cmk_key; the worker-plane-cmk variant with terraform import for module.worker_plane["region"]...cmk_key. [dspm.onboarding-azure-errors:cmk-already-exists] Onboarding itself is in [How a Microsoft Azure tenant, management group or subscription is onboarded to DSPM, and the Azure roles and API permissions it needs](kb:dspm.onboarding-azure), with [Data Security Posture Management (DSPM): what it finds in stored data, how it differs from inline DLP, and what can be automated](kb:dspm.overview) and [How DSPM scans: onboarding scope, the in-account orchestrator, data stores, authentication, classification and data residency](kb:dspm.scanning) for DSPM generally.

**Azure authorization and access.** A local-exec provisioner error with AuthorizationFailed on az role assignment create is resolved by ensuring access management for Azure resources is enabled for your ID. [dspm.onboarding-azure-errors:access-mgmt-authfailed] A 403 Forbidden on checking the "api-key" secret in the key vault is resolved by ensuring the Key Vault Administrator role is assigned. [dspm.onboarding-azure-errors:keyvault-403] "Failed to connect to MSI" while retrieving static website properties is resolved with az login; the 403 Authorization_RequestDenied "Insufficient privileges" error from Cloud Shell is also resolved with az login. [dspm.onboarding-azure-errors:msi-connect] The key vault 403 "Client address is not autorized and caller is not a trusted service" is resolved by rerunning the template with the correct IP. [dspm.onboarding-azure-errors:client-address-not-authorized] A 403 AuthorizationFailure retrieving a storage queue is resolved by adding the system IP address to the Azure storage account and key vault IP networks. [dspm.onboarding-azure-errors:storage-authfailure] Azure status 400 with code RoleAssignmentLimitExceeded ("No more role assignments can be created") means the role assignment limit is exceeded; the documented fix is deleting a custom role. [dspm.onboarding-azure-errors:role-assignment-limit]

**Features, capacity and management groups.** The InvalidParameter error that the Microsoft.compute/EncryptionAtHost feature is not enabled for the subscription is resolved by registering the EncryptionAtHost feature with az feature register. [dspm.onboarding-azure-errors:encryption-at-host] In Cloud Shell, the InvalidParameter error that the Microsoft.Compute/EncryptionAtHost feature is not enabled, raised while updating a Linux Virtual Machine Scale Set, is resolved by az feature register and az feature show for EncryptionAtHost in Microsoft.Compute. [dspm.onboarding-azure-errors:encryption-at-host-cloudshell] When the Standard_D2s_v3 SKU fails for capacity restrictions in a location, the documented fix is to run terraform destroy, download the Azure Onboarding template, extract it to a new folder, edit the terraform.tfvars file and set primary_region to a region where Standard_D2s_V3 is available. [dspm.onboarding-azure-errors:vm-size-capacity] During Tree Discovery deployment, ManagementGroupNotFound (404) is resolved by checking the entered Management Group ID in the Tenant Details section and deploying the Tree Discovery template again. [dspm.onboarding-azure-errors:mgmt-group-not-found]

**Account state and Cloud Shell.** If the account moves to Needs Attention during template deployment, the documented resolution is to wait for the next DSPM validation or run the on-demand validation. [dspm.onboarding-azure-errors:needs-attention] If Cloud Shell is stuck while deploying the template, abort the deployment and rerun the template. [dspm.onboarding-azure-errors:cloudshell-stuck]

**Manual deletion.** The 400 errors for a subnet that cannot be deleted because it is in use and for a network security group in use (InUseNetworkSecurityGroupCannotBeDeleted) are resolved by deleting the resources manually in the Azure portal. [dspm.onboarding-azure-errors:manual-delete-subnet] The 409 CannotDeleteResource for a Private DNS zone and the error that a resource group still contains resources are each resolved by deleting the resources manually in the Azure portal. [dspm.onboarding-azure-errors:manual-delete-dns-rg] "User Assigned Identity ... was not found" is resolved by deleting the resource group and rerunning the template. [dspm.onboarding-azure-errors:user-assigned-identity-missing]

**Rerun the template.** The following errors are each documented with the resolution "Rerun the template": a 409 "The specified container is being deleted", VNet peering ReferencedResourceNotProvisioned, VMAgentStatusCommunicationError, RoleDefinitionWithSameNameExists, InternalDiskManagementError, RoleAssignmentUpdateNotPermitted, KeyVaultAuthenticationFailure, and a connection reset ("HTTP response was nil") on service principal creation. [dspm.onboarding-azure-errors:rerun-transient] Some rows are not claimed [gap:dspm.onboarding-azure-errors:rerun-rows-no-cause].

**Two resolutions for one error.** The ManagementPolicyNotFound error ("The key vault key is not found to unwrap the encryption key") appears twice with different documented resolutions: delete the storage account and rerun the template, or rerun the template. [dspm.onboarding-azure-errors:management-policy-not-found]
