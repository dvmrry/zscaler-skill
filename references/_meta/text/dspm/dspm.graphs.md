# DSPM Risk Explorer graphs: supported data stores, attack paths, public exposure and user access paths (dspm.graphs)
Also called: dspm risk explorer; dspm resource inventory graph; dspm public exposure path; dspm user access path; dspm attack path

After DSPM completes the data scan of the resources, the Resource Inventory graph shows data stores containing sensitive records, matching DLP engines and dictionaries, public internet exposure paths and entities with access permissions. [dspm.graphs:graph-scope] The Resource Inventory graph shows attack paths: Public Exposure, Access, Known Vulnerabilities (CVEs), Sensitive Data, Associated Resources and Malware. [dspm.graphs:graph-attack-paths] The nodes and access paths on the graph vary with the primary resource and its associated resources. [dspm.graphs:graph-nodes-vary] The Public Internet node appears when DSPM detects that a resource containing sensitive data is publicly exposed and accessed by unauthorized users. [dspm.graphs:graph-public-internet-node] The Risk Explorer tab of a resource is in [Clicking a Resource Name on the Resource Inventory page opens tabs: Risk Explorer (scan results on a graph), Sensitive Data, Alerts, Access, Vulnerabilities, Malware and Timeline.](kb:dspm.inventory:resource-details-tabs).

**Data stores with graphs.** AWS graphs are available for S3, EC2 instances, RDS instances and clusters (MySQL, PostgreSQL, Aurora MySQL, Aurora PostgreSQL), DynamoDB tables, unmanaged PostgreSQL/MySQL/MS SQL/Oracle databases, Bedrock Knowledge Base and AWS Databricks. [dspm.graphs:graph-aws-stores] GCP graphs are available for BigQuery, Compute Instance, Cloud SQL Instance and Storage Bucket. [dspm.graphs:graph-gcp-stores] AI service graphs include AWS Bedrock Custom Model, AWS Bedrock Imported Model, AWS Bedrock Agent and Azure OpenAI. [dspm.graphs:graph-ai-services] Database graphs are available for managed databases (e.g. AWS RDS, Azure SQL, Snowflake, Databricks), unmanaged cloud and on-premises databases, unmanaged AWS and Azure MongoDB servers, on-premises file servers and on-premises MongoDB servers. [dspm.graphs:graph-db-types] The on-premises database graph shows Table with Sensitive Data, Databases and Admin Principals nodes, and its primary resource shows Data Center ID. [dspm.graphs:graph-onprem-db] In the AWS and Azure data-store graphs, External entities are part of a different cloud account that is not onboarded to the DSPM Admin Portal; the GCP graph says they are users, services or roles of a different cloud account not onboarded to DSPM. [dspm.graphs:graph-external-definition] The Access Levels page defines External differently [divergence:dspm.graphs:external-entity-definition].

**Public exposure path.** The public exposure path is enabled only for EC2 instances, virtual machines and DB cluster resources. [dspm.graphs:public-exposure-scope] Its scope against the storage options is open [gap:dspm.graphs:public-exposure-scope-vs-storage]. For cloud storage buckets and Azure containers the public exposure path offers View Metadata, Verify Exposed Files (anonymously accessible files, exportable as CSV) and Verify Static Website. [dspm.graphs:public-exposure-bucket-actions] AWS exposure types: S3 Block Public Access (account-level protection needs IgnorePublicAcls and RestrictPublicBuckets set to true), bucket ACLs granting AllUsers or AuthenticatedUsers, bucket policies granting principal *, and hosted static websites. [dspm.graphs:exposure-aws] Azure exposure types: a SQL firewall rule allowing 0.0.0.0 - 255.255.255.255, the Allow Azure services exception (reaching every Azure tenant), static websites (the $web container is exposed anonymously regardless of firewall or container ACL) and containers with Anonymous Container Read Access. [dspm.graphs:exposure-azure] GCP exposure fixes: delete the allUsers principal or the allAuthenticatedUsers principal from the bucket's IAM policy bindings. [dspm.graphs:exposure-gcp]

**User access path.** In the AWS user access path graph, clicking an IAM node shows the ARN and Account ID, among other fields. [dspm.graphs:access-path-aws] For AWS, the user access path page says the Resource Inventory graph displays the sensitive records found in the primary resource along with external, federated, roles, services and users that have access to it. [dspm.graphs:access-path-sensitive]

**Triggers.** In the AWS data-store graph, the primary resource's Triggers field is the number of alerts raised for the resource. [dspm.graphs:triggers-aws-graph] In the Azure data-store graph, the primary resource's Triggers field is the number of sensitive records in the resource. [dspm.graphs:triggers-azure-graph] What Triggers counts on a graph primary resource is open [gap:dspm.graphs:graph-triggers-meaning]. Label slips on the GCP pages are noted [gap:dspm.graphs:graph-doc-label-slips].

What to check:
1. Which graph page the Triggers definition comes from: the AWS data-store graph says alerts raised, the Azure data-store graph says sensitive records, and the Databases graph page gives both by example.
2. Which page defines External: the graph pages say a different cloud account not onboarded, the Access Levels page says outside the AWS organization.

Sources disagree (name both sides):
- The graph pages define External entities as part of a different cloud account that is not onboarded to DSPM; the Access Levels page defines an External Account as outside the AWS organization and puts same-organization accounts not onboarded to DSPM under Unmanaged. [divergence:dspm.graphs:external-entity-definition]
  - zscaler-help: External entities are part of a different cloud account that is not onboarded to the DSPM Admin Portal.
  - zscaler-help: An external account is outside the current AWS organization; a same-organization account that is not onboarded is Unmanaged.
  Impact: An entity in another account of the same AWS organization that is not onboarded is External by the graph wording and Unmanaged by the Access Levels wording.
