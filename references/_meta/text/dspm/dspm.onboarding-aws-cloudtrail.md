# How DSPM uses AWS CloudTrail and data events for incremental scans, and what changes when CloudTrail details are reset (dspm.onboarding-aws-cloudtrail)
Also called: dspm cloudtrail; dspm data events; dspm incremental scan aws; cloudtrail integration dspm

DSPM uses CloudTrail trails to analyze logs and perform incremental scans on S3 buckets; Event History records activity in a single AWS account for the last 90 days. [dspm.onboarding-aws-cloudtrail:cloudtrail-trails-used] Incremental scans are named as a scan type in [Data is classified with Zscaler's DLP engines and dictionaries, through full, incremental, historical or sampling scans.](kb:dspm.scanning:classification); the onboarding they belong to is in [How to onboard an AWS organization or standalone account to DSPM: prerequisites, templates, orchestrator, monitoring scope and the IAM roles and condition keys involved](kb:dspm.onboarding-aws), under the hub [Data Security Posture Management (DSPM): what it finds in stored data, how it differs from inline DLP, and what can be automated](kb:dspm.overview) and [How DSPM scans: onboarding scope, the in-account orchestrator, data stores, authentication, classification and data residency](kb:dspm.scanning).

**Integration.** With CloudTrail integration enabled DSPM gets read-only access to the CloudTrail logs needed for incremental scans on the S3 bucket; when disabled, DSPM supports only full scans (organization onboarding page). [dspm.onboarding-aws-cloudtrail:integration-incremental-vs-full] On the standalone target-account page, enabling CloudTrail integration gives DSPM read-only access to CloudTrail logs for incremental scans on the S3 bucket, and when disabled DSPM supports only full scans. [dspm.onboarding-aws-cloudtrail:standalone-integration-incremental-vs-full] For standalone onboarding, CloudTrail is configured for management and data events so DSPM can do incremental scans on S3 buckets, with the Write checkbox selected for All current and future S3 buckets. [dspm.onboarding-aws-cloudtrail:prereq-s3-data-events-write] In organization onboarding, configuring CloudTrail for management and data events is described as an optional step if you want to configure CloudTrail while onboarding. [dspm.onboarding-aws-cloudtrail:org-prereq-optional]

**Log paths.** In organization onboarding, during initial onboarding DSPM looks for log files at prefix/<organization ID>/<management account ID> for an Organization CloudTrail and prefix/<management account ID> for an Account CloudTrail, and after onboarding checks each target account; for Control Tower the organization ID is entered as prefix. [dspm.onboarding-aws-cloudtrail:log-paths-checked] An organization CloudTrail shares the CloudTrail events of the management and member accounts of the organization to the same CloudTrail S3 bucket. [dspm.onboarding-aws-cloudtrail:org-cloudtrail-type] Whether the Control Tower prefix has an example value is open [gap:dspm.onboarding-aws-cloudtrail:control-tower-prefix-example].

**Changing CloudTrail details.** Changing CloudTrail details requires an Administrator role or any role with Edit Cloud Accounts permission. [dspm.onboarding-aws-cloudtrail:change-permission] Resetting the organization CloudTrail details disables the existing CloudTrail and moves all onboarded accounts to Needs Attention until the new CloudTrail is validated; successful validation shows status Enabled and a validation problem shows Failed. [dspm.onboarding-aws-cloudtrail:change-org-effects] Updating an account CloudTrail disables the existing CloudTrail only for that account, without affecting other accounts in the organization, and the account is Needs Attention until the new one validates. [dspm.onboarding-aws-cloudtrail:change-account-effects] As a cross-account CloudTrail prerequisite, the resource discovery role created by DSPM is edited under DSPM-CLOUDTRAIL-KMS-POLICY to add the S3 bucket account ID where the KMS key is present. [dspm.onboarding-aws-cloudtrail:cross-account-kms-policy]

**Data events.** DSPM supports ingestion of data events (activities on or within AWS data stores such as reading or writing an S3 bucket or GetObject API operations) to analyze activity logs. [dspm.onboarding-aws-cloudtrail:data-events-definition] Data events can be enabled or disabled; when enabling, the Data Events template is run on the account holding the CloudTrail S3 bucket, and disabling stops DSPM collecting data events from the bucket. [dspm.onboarding-aws-cloudtrail:data-events-enable-disable]

What to check:
1. Whether CloudTrail integration is enabled, since the pages say DSPM supports only full scans when it is disabled.
2. Which log path DSPM looks at for an Organization CloudTrail and an Account CloudTrail during initial organization onboarding.
3. What the pages say happens to accounts while an organization or account CloudTrail is reset and not yet validated: Needs Attention until validated; the CloudTrail status Enabled or Failed is given for the organization reset only.
