# What the DSPM Resource, Data and Identity Inventory pages show, and how posture states and risk are defined (dspm.inventory)
Also called: dspm resource inventory; dspm data inventory; dspm identity inventory; dspm data duplications; dspm posture states; dspm risk score; dspm page views; dspm report management

The Resource Inventory page (Data Security > DSPM > Resource Inventory) lists scanned resources with columns including Risk Level (Critical, High, Medium or Low), Posture, Open Alerts, Total Scanned, Data Scanned and Last Completed Scan. [dspm.inventory:resource-inventory-columns] On the Resource Inventory page, the DLP Engines and DLP Dictionaries columns give the number of sensitive records matching the engine or dictionaries, and Document Types are those detected by machine-learning-based DLP dictionaries. [dspm.inventory:resource-inventory-engine-counts]

**Scan status and export.** On the Resource Inventory page, hovering over a Failed or Unsupported Latest Scan Status label shows an error message containing the error timestamp, resource ID and error reason. [dspm.inventory:resource-scan-status-error] The status values are held in [DSPM scan statuses are Disabled (scan turned off and does not run), Scheduled (planned to run at a specified time), On-Demand (manually triggered by the user) and In Progress (actively running, for both full and incremental scans).](kb:dspm.scan-rules:scan-statuses) and the pages differ on them [divergence:dspm.inventory:scan-status-labels] [gap:dspm.inventory:scan-status-values]. Resource Inventory results export as an Excel file; Zscaler recommends applying filters before exporting if not all records appear in the downloaded report. [dspm.inventory:resource-export]

**Resource details tabs.** Clicking a Resource Name on the Resource Inventory page opens tabs: Risk Explorer (scan results on a graph), Sensitive Data, Alerts, Access, Vulnerabilities, Malware and Timeline. [dspm.inventory:resource-details-tabs] The Risk Explorer graph is covered in [DSPM Risk Explorer graphs: supported data stores, attack paths, public exposure and user access paths](kb:dspm.graphs). The Timeline tab of a resource shows events related to configuration changes, and the resource timeline is limited to a maximum of 30 days. [dspm.inventory:timeline-limit] The Timeline tab shows an Events Over Time chart and an Events Found list with Event Time, Principal, Principal Type, Event Name and IP Address. [dspm.inventory:timeline-fields] DSPM detects vulnerabilities in Amazon EC2 instances and virtual machines; the Vulnerabilities tab lists, per package, name, version, file path, whether vulnerabilities are present and a severity count (Critical, High, Medium, Low), with a CVE tab for CVE details. [dspm.inventory:vulnerability-tab] The Sensitive Data tab shows Matched Files/Matched Tables (files or tables that matched the DLP engines) and Triggers (records that matched); for files a Hash is identical for identical files, and for tables it shows the Column containing sensitive data. [dspm.inventory:sensitive-data-tab] The Malware tab shows Total Malware Files, malware types with counts (e.g., Virus, Exploit) and, per file, malware name and type, with a Malware Type filter. [dspm.inventory:malware-tab]

**Access tab.** The Access tab lists entities with IAM permissions to the resource, with fields such as Policy ARN (AWS) and Target Entity (Snowflake). [dspm.inventory:access-tab-levels] For AWS, Azure, GCP, unmanaged database and Snowflake resources the Access tab Access Level is Read, Edit or Full Access. [dspm.inventory:access-level-values] For AWS resources the Access tab shows Has Access Keys, where access keys are long-term credentials for an IAM user or the AWS account root user. [dspm.inventory:access-tab-aws-keys] During data scanning DSPM discovers entity types, such as Onprem Unmanaged MySQL Server User and Snowflake User. [dspm.inventory:entity-types-groups] IAM External Account is an account outside the current AWS organization, while IAM Unmanaged Role and IAM Unmanaged User are in another account of the same organization that is not managed or onboarded to DSPM. [dspm.inventory:entity-types-external] The entity-type lists are only sampled [gap:dspm.inventory:entity-type-lists].

**Data Inventory.** The Data Inventory page reports on files and tables across cloud, on-premises and SaaS environments and is updated continuously as new cloud accounts are onboarded and data stores, files and tables are updated. [dspm.inventory:data-inventory-scope] The Data Inventory lists each file or table with columns including Severity of Last Incident, File MD5, Collaboration Scope, Public URL and the number of external collaborators. [dspm.inventory:data-inventory-columns] The file or table details view has tabs: Entitlements (files only; extra detail only for on-premises SMB file shares), Evidence (only if evidence collection was enabled and configured before the scan), File Activity (files only) and Data (tables only). [dspm.inventory:data-inventory-detail-tabs] AWS DynamoDB tables do not support column-level scanning. [dspm.inventory:dynamodb-column-scan]

**MIP labels.** On the Data Inventory page, the icon for applying a MIP label to individual files is enabled only for on-premises files and for users assigned the Apply Label permission. [dspm.inventory:mip-label-list-page] MIP labels can be applied manually to files in on-premises file shares on file servers and in Azure file shares, which requires the permission to apply MIP labels, and for Azure file shares M365 tenant sync must be enabled first. [dspm.inventory:mip-label-details-page] The two pages state different file-share scopes [gap:dspm.inventory:mip-label-scope]. With multiple M365 tenants, Azure file shares offer labels from the corresponding tenant while on-premises file shares offer labels from all available M365 tenants. [dspm.inventory:mip-label-tenants] For a MIP label action, the status shown on the file details page's File Activity tab is Completed (applied), Failed (not applied) or Requested Action (in progress). [dspm.inventory:mip-label-status] The label feature itself is in [Microsoft Information Protection (MIP) accounts and label retrieval](kb:zia.dlp.mip-labels). The permission and tenant-sync pages are only partly held [gap:dspm.inventory:referenced-pages-not-captured].

**Identity Inventory.** The Identity Inventory page lists identities detected in all onboarded AWS, Azure and GCP accounts, including managed and unmanaged databases and Snowflake. [dspm.inventory:identity-inventory-scope] The Identity Inventory Entity Category values are AI Agent Identity, Domain, External, Federated, Internal Application, Microsoft Application, Role, Service, Service Account, System-Assigned Managed Identity, Third-Party Application, Unknown and User-Assigned Managed Identity. [dspm.inventory:identity-entity-categories] Identity Inventory columns include Entity Source (the identity repository, e.g. Entra ID), Target Environments, Sensitive Data Stores and Files & Tables. [dspm.inventory:identity-columns]

**Data Duplications.** DSPM detects duplicate files across cloud, SaaS and on-premises environments. [dspm.inventory:duplicates-detection] A file or table's details view in the Data Inventory shows duplicate copies based on matching hash values. [dspm.inventory:duplicates-by-hash] The Data Duplications page's Copies column counts all copies including the original, File Size is in kilobytes, and a file's File access tab lists users who accessed it in the last 7 days. [dspm.inventory:duplicates-columns] Data Duplications can export a Summary View (current page view with filters and visible columns) or a Full View (every duplicate instance), and the Full View is a ZIP of up to 10 files of at most 50,000 rows each, within a 500,000-row limit. [dspm.inventory:duplicates-export]

**Page views and reports.** Saved page views (filters, visible columns, sorting) are available on the Resource Inventory, Data Inventory, Data Duplications and Alerts pages, are per user and invisible to others, and the default view cannot be changed or deleted. [dspm.inventory:page-views] Deleting a saved page view requires typing CONFIRM in the Delete View window. [dspm.inventory:page-views-delete] Report Management holds reports on alerts, data inventory and policies; reports are available as Excel files only, with status In Progress or Download. [dspm.inventory:report-management]

**Posture states.** Posture icons: Bad Posture means data is not encrypted; Partially Good means partly encrypted, for example with platform-managed keys (PMK), which is more secure than no encryption but less than customer-managed keys (CMK); no icon is good. [dspm.inventory:posture-icons] Resource posture states cover Encryption (including Encrypted, CMK Encrypted, PMK Encrypted and Partial Encryption), Public Exposure, Logging (including Partial Logging), Backup, Data Retention and Exposure to AI Services. [dspm.inventory:posture-resource-states] The Guardrails posture (Enabled or Disabled) is stated for AWS Bedrock Agent or Azure AI Foundry. [dspm.inventory:posture-guardrails] Identity posture thresholds: Stale Password is a password not valid and not changed for more than 90 days, Dormant Identity is inactive for more than 90 days, and Stale Access Key is an access key not rotated for more than 90 days. [dspm.inventory:posture-identity-90-days] Investigation words the dormant check differently [gap:dspm.inventory:dormant-wording]. Identity MFA posture covers MFA Status (MFA Enabled, MFA Disabled) and MFA Method (Weak MFA, Strong MFA, MFA Not Registered). [dspm.inventory:posture-mfa] SCP Status posture is SCP Applied or No SCP Applied, meaning a Service Control Policy is or is not applied to the AWS account. [dspm.inventory:posture-scp] The scan-time posture check categories are in [How DSPM scans: onboarding scope, the in-account orchestrator, data stores, authentication, classification and data residency](kb:dspm.scanning).

**Risk.** DSPM security risk combines likelihood (derived from policies matching attack vectors in the data store) and impact (based on sensitivity level of the data found and its volume). [dspm.inventory:risk-definition] DSPM scans the entire data in a store but calculates impact only on the portion of data at risk; in the documented example an encrypted EBS volume with 100 sensitive records contributes nothing to the EC2 risk score while an unencrypted one with 50 represents most of it. [dspm.inventory:risk-true-impact] The risk score's likelihood follows matched policies, so modifying policy severity changes it, and impact follows sensitive data, so running the sensitive data configuration affects it; there is currently no other way to override the risk score. [dspm.inventory:risk-score-inputs]

What to check:
1. Which page states a MIP label scope: the Data Inventory list icon says on-premises files only, the file details page also names Azure file shares.
2. Whether a posture or risk answer rests on the stated 90-day identity thresholds or on the rule that impact is calculated on the portion of data at risk.

Sources disagree (name both sides):
- The Resource Inventory page names Failed and Unsupported as Latest Scan Status labels; the Understanding Scan Status page lists only Disabled, Scheduled, On-Demand and In Progress as supported statuses. [divergence:dspm.inventory:scan-status-labels]
  - zscaler-help: Latest Scan Status shows Failed and Unsupported labels for failed or unsupported scans.
  - zscaler-help: The supported statuses are Disabled, Scheduled, On-Demand and In Progress.
  Impact: A scan status answer cannot treat the four-status list as complete for what Latest Scan Status displays.
