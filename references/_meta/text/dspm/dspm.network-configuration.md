# How to set up a custom DSPM network on AWS, Azure and GCP (control plane and worker plane) and change the orchestrator network (AWS and Azure) (dspm.network-configuration)
Also called: custom network configuration; control plane VPC; worker plane VPC; orchestrator network; Managing Orchestrator Network

For a custom AWS network, a control plane VPC is created only in the orchestrator's primary region and a worker plane VPC in every region where resources exist, both in the orchestrator account, with non-overlapping CIDRs. [dspm.network-configuration:aws-planes] For a custom Azure network, a control plane VNet is created only in the orchestrator's primary region and a worker plane VNet in every region where resources exist, both in the orchestrator subscription, with non-overlapping CIDRs. [dspm.network-configuration:azure-planes] For a custom GCP network, a control plane VPC is created only in the orchestrator's primary region and a worker plane VPC in every region where resources exist, both in the orchestrator project, with non-overlapping CIDRs. [dspm.network-configuration:gcp-planes] [Data Security Posture Management (DSPM): what it finds in stored data, how it differs from inline DLP, and what can be automated](kb:dspm.overview) [How DSPM scans: onboarding scope, the in-account orchestrator, data stores, authentication, classification and data residency](kb:dspm.scanning) [What the DSPM orchestrator and scanner instances are: architecture, sizing, default scanner types, tags and DSPM service IPs](kb:dspm.orchestrator)

**AWS.** Manual AWS control plane VPC settings: at least 1 AZ, 1 public subnet, 1 private subnet and a NAT gateway in 1 AZ. [dspm.network-configuration:aws-control-vpc] Manual AWS worker plane VPC settings: at least 2 AZs, 2 public and 2 private subnets, at least 50 IPs available in the private subnet, and a NAT gateway in 1 AZ. [dspm.network-configuration:aws-worker-vpc] The AWS control plane security group has no inbound rules and an outbound rule of type HTTPS to 0.0.0.0/0. [dspm.network-configuration:aws-control-sg] The AWS worker plane security group allows inbound HTTPS from the control plane VPC and PostgreSQL and MYSQL/Aurora from the worker plane VPC; outbound it lists HTTPS 0.0.0.0/0, PostgreSQL 0.0.0.0/24, MYSQL/Aurora 0.0.0.0/24 and Custom TCP 0.0.0.0/0. [dspm.network-configuration:aws-worker-sg] The /24 destinations are open [gap:dspm.network-configuration:aws-worker-cidr-24]. A DB subnet group, built from the worker plane VPC with at least two AZs and their private subnets, is required for DSPM to scan RDS databases. [dspm.network-configuration:aws-db-subnet-group] The AWS control plane and worker plane VPCs are peered so they can communicate (a step common to manual and template-based setups); the request starts in Pending acceptance, is accepted (Accept request), and route tables on both VPCs are updated. [dspm.network-configuration:aws-peering]

**AWS templates.** The AWS CloudFormation option is a ZIP with two YAML files, deployed as a control plane stack (aws_control_plane_network_components_cft.yml) and a worker plane stack (aws_worker_plane_network_components_cft.yml) (repeated for all other worker regions); the old control plane infrastructure must be deleted before a new control plane stack. [dspm.network-configuration:aws-cloudformation] The AWS Terraform option is a ZIP with a control plane and a worker plane folder; the state file keys are dspm-control-plane-network-configuration.tfstate and dspm-worker-plane-network-configuration-<region>.tfstate. [dspm.network-configuration:aws-terraform] The templates themselves are not captured [gap:dspm.network-configuration:network-templates-not-captured].

**Azure.** Manual Azure VNets: control plane subnet address space preferably /24, worker plane preferably /20; virtual network encryption is selected if the scanning VMs have network acceleration enabled. [dspm.network-configuration:azure-vnet-sizing] In both manual Azure VNets (control plane and worker plane), the subnet gets a NAT gateway and a network security group, service endpoints Microsoft.KeyVault, Microsoft.Sql and Microsoft.Storage.Global, and Network Policy for Private Endpoints set to Disabled. [dspm.network-configuration:azure-service-endpoints] Scanning Azure PostgreSQL Server requires a network security group for it and a delegated subnet, delegated to Microsoft.DBforPostgreSQL/flexibleServers. [dspm.network-configuration:azure-postgres-subnet] The Azure control plane network security group is configured with rules named for denying all inbound communication to the orchestrator, allowing inbound from the control plane to the worker plane, denying all outbound communication from the orchestrator at lesser priority, and allowing outbound from the orchestrator to the scanner, to DSPM and to Azure cloud. [dspm.network-configuration:azure-control-nsg] Which Azure destination IPs cover India is open [gap:dspm.network-configuration:azure-india-ip]. If Microsoft Information Protection labeling is enabled, the Azure control plane NSG needs further outbound allow rules to the AzureInformationProtection, AzureActiveDirectory, AzureFrontDoor.Frontend and AzureFrontDoor.FirstParty service tags and to an Outlook MIP IP range list. [dspm.network-configuration:azure-mip-rules] The Azure worker plane NSG has outbound allow rules for database ports: SQL 11000-11999, MongoDB 27017, PostgreSQL 5432, MySQL 3306 and Oracle 1521. [dspm.network-configuration:azure-worker-db-ports] The MS SQL port on the page is open [gap:dspm.network-configuration:azure-mssql-port]. The Azure control plane region is given in a format supported by the cloud provider, such as centralus or eastus, and the worker plane has a separate Postgres subnet address range. [dspm.network-configuration:azure-template-vars] After peering the Azure control and worker VNets (common to manual and template-based setups) the Peering state shows Connected and the Sync status Fully Synchronized. [dspm.network-configuration:azure-peering]

**GCP.** The GCP control plane VPC and worker plane VPC use Custom subnet creation mode, and Cloud NAT gateway resources are created for new worker plane subnets and regions. [dspm.network-configuration:gcp-subnets] The GCP control plane firewall includes a rule to allow outbound communication from the orchestrator to DSPM. [dspm.network-configuration:gcp-control-firewall] GCP worker plane firewall rules cover inbound from the orchestrator to the scanner VPC, outbound from the scanner to DSPM and outbound from the scanner to Cloud SQL (named allow-db-outbound-rule, ports 3306, 5432 and 1433). [dspm.network-configuration:gcp-worker-firewall] Which VPC each worker rule belongs to is open [gap:dspm.network-configuration:gcp-rule-vpc]. Private service access in the GCP worker plane VPC is used for scanning Cloud SQL instances: an automatic IP range with prefix length 16 named private-service-access-ip-range, after which Google adds peering to servicenetworking. [dspm.network-configuration:gcp-private-service-access] GCP control and worker plane VPCs are peered from each VPC side: the peering status in the control plane VPC is Inactive after it is created, and after successful configuration it is Active for both. [dspm.network-configuration:gcp-peering] A Cloud NAT gateway is region-specific and network-specific and is created for each combination; in the primary region one gateway is created for the control plane VPC and one for the worker plane VPC, with NAT type Public. [dspm.network-configuration:gcp-cloud-nat]

**Changing the orchestrator network.** The orchestrator network can be modified when the existing network is being decommissioned or deleted or an incorrect network was selected, only when the DSPM Connection Status is failed for the custom network configuration type; the orchestrator template must be rerun afterwards. [dspm.network-configuration:orch-network-change] [DSPM Connection Status: Successful means the orchestrator instance is connected, Failed means it cannot establish a connection with DSPM, and Waiting for connection means the orchestrator template is not yet deployed in the CSP.](kb:dspm.cloud-accounts:connection-status) Modifying the orchestrator network requires an Administrator role or a custom role with the Configure Monitoring Scope permission. [dspm.network-configuration:orch-network-prereq] On the Managing Orchestrator Network page, which gives fields for AWS and Azure only, modifying the orchestrator network takes an orchestrator region plus, for AWS, Subnet ARN and Security Group ID, and for Azure Subnet ID, Network Security Group ID and a Storage Account Name of at most 16 characters. [dspm.network-configuration:orch-network-fields] What it takes on GCP is open [gap:dspm.network-configuration:orch-network-gcp]. In the Azure orchestrator network change, the storage account stores activity logs of the target subscriptions and DSPM displays an error message if its name is already registered with Microsoft.Storage; a new subnet from a different VNet needs a terraform destroy on the scale set first. [dspm.network-configuration:orch-network-azure-storage]
