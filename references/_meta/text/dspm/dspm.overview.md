# Data Security Posture Management (DSPM): what it finds in stored data, how it differs from inline DLP, and what can be automated (dspm.overview)
Also called: dspm; data security posture management; zscaler dspm; dspm vs dlp; data at rest posture; dspm api

DSPM examines data at rest in cloud and on-premises stores, where inline DLP watches data in motion. DSPM is an AI-powered solution that protects data stored on-premises and in the cloud by continuously scanning it for misconfigurations, vulnerabilities and permissions that might contribute to attack vectors; it shows where sensitive data resides, classifies it, detects duplicate data and misconfigured stores holding it, and contextualizes exposure and posture. [dspm.overview:what-it-is]

**What it reports.** It scans data for issues such as data exposure, publicly exposed sensitive data, over-privileged access without proper RBAC, and sensitive data exposed to unmanaged services and models, and identifies policy violations at the resource and data level mapped to compliance frameworks. [dspm.overview:misconfigurations] It prioritizes risk by severity, with step-by-step remediation guidance and configurable near-real-time alerts and notifications. [dspm.overview:prioritization] Zscaler's DSPM product page says it deep-scans AI models for vulnerabilities across the OWASP Top 10 for LLMs, pinpointing vulnerabilities, misconfigurations and permissions, with step-by-step remediation guidance. [dspm.overview:marketing-owasp-llm]

**Against inline DLP.** Zscaler's DSPM product page describes the two separately in its FAQ: DSPM protects data, both local and in the cloud, against unauthorized access, misuse or theft by continuously monitoring, updating and refining security measures, while cloud DLP monitors and inspects data on a network to prevent data exfiltration; the page says DSPM is natively integrated with the Zscaler Data Security platform. [dspm.overview:at-rest-vs-in-flight] Zscaler's DSPM product page says it covers all data stores, including IaaS, SaaS, on-premises and endpoint, discovers and classifies structured and unstructured data across IaaS, SaaS, on-premises, AI and endpoint, and finds sensitive data across hybrid and multicloud environments. [dspm.overview:marketing-scope] The help pages document onboarding for cloud accounts and on-premises stores: [DSPM scans AWS, Azure and GCP data stores (storage services, virtual machines with their disks, and databases) and on-premises databases for sensitive data, vulnerabilities and misconfigurations.](kb:dspm.scanning:scope). It classifies with the same DLP engines and dictionaries as the rest of Zscaler DLP ([Data is classified with Zscaler's DLP engines and dictionaries, through full, incremental, historical or sampling scans.](kb:dspm.scanning:classification)), and DSPM appears as a channel of a DLP engine: [The DLP Engines page shows, per engine, the channels associated with it; the captured row names Network Share, Personal Cloud Storage, Printing, or Removable Storage, and also Endpoint DLP, SaaS Security, DSPM, Inline Web, and Email DLP.](kb:zia.dlp.engines:engine-channels).

**Configuration guide.** The step-by-step guide lists nine configuration steps: set up your account, set up the DLP engines and define sensitive data, onboard cloud accounts, configure scan settings, users, business units, data posture policies, alert rules, and 3rd-party integrations and notifications. [dspm.overview:guide-steps] After the organization is provisioned for DSPM, an email arrives to complete the registration. [dspm.overview:guide-registration] The step-by-step configuration guide says DSPM uses predefined DLP engines and dictionaries that are synced from Internet & SaaS (ZIA) to classify data types. [dspm.overview:guide-dlp-engines] The step-by-step configuration guide says AWS organizations, Microsoft Azure tenants or GCP organizations can be onboarded into DSPM, which then monitors the data in the cloud accounts for vulnerabilities and threats. [dspm.overview:guide-cloud-providers] The step-by-step configuration guide says that after cloud accounts are onboarded, scan settings are configured, and DSPM scans the resources in the onboarded accounts, classifies the data, detects vulnerabilities and generates alerts; it also says accounts can be mapped to business units and user access can be restricted to specific business units (see dspm.roles:business-unit-definition). [dspm.overview:guide-scan-and-bu] The step-by-step configuration guide says DSPM offers predefined data posture policies for compliance across multiple CSPs and also supports custom policies, and offers incident management by integrating with ITSM tools and cloud storage services. [dspm.overview:guide-policies-alerts]

**How it scans.** Scope, onboarding, scanners, authentication and residency are in [How DSPM scans: onboarding scope, the in-account orchestrator, data stores, authentication, classification and data residency](kb:dspm.scanning).

## Automation

No vendored client covers DSPM: the Go and Python SDKs, the Terraform providers, the Ansible collections, the MCP server, the OneAPI Postman collection and the captured Automate contract have no DSPM service. [dspm.overview:no-client-surface] Whether DSPM has an admin API is open [gap:dspm.overview:api-and-scanner-contract].
