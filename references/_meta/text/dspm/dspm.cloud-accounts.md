# The DSPM Cloud Accounts page: onboarding and orchestrator status, issues, templates, validation, business units, deletion, and per-account settings (services, tags, regions, evidence storage) (dspm.cloud-accounts)
Also called: about cloud accounts; dspm onboarding status; dspm connection status; dspm configuration status; dspm custom tags; dspm evidence configuration; Manage Regions; Manage Services

The Cloud Accounts help describes onboarding AWS accounts, Microsoft Azure subscriptions and GCP projects, which DSPM continuously monitors and scans for sensitive data and vulnerabilities, alerting on data security policy violations. [dspm.cloud-accounts:onboarding-units] [Data Security Posture Management (DSPM): what it finds in stored data, how it differs from inline DLP, and what can be automated](kb:dspm.overview) [The models that can be onboarded are an AWS Organization or Standalone Account, an Azure Tenant or Management Group, and a GCP Organization.](kb:dspm.scanning:onboarding-types)

**Manage menu.** The Cloud Accounts Manage menu offers Monitoring & Autodetection, Business Units Mapping, Manage Regions, Manage Custom Tags, Manage Notification Emails, Managing Orchestrator Network (Custom), On Demand Validation, Configure New Orchestrator (Zscaler) and Delete Account; Managing Orchestrator Network applies only if the DSPM Connection Status is failed. [dspm.cloud-accounts:manage-menu] Provider-specific Manage actions: AWS has Manage CloudTrail, Manage Services, Manage Evidence and Manage Data Events; Azure has Change Application Details, Manage Private Endpoint, Manage Services and Manage Evidence; GCP has Update Service Account and Update Private Key. [dspm.cloud-accounts:manage-menu-csp] Which providers have Manage Evidence and Manage Services is disputed [divergence:dspm.cloud-accounts:manage-menu-providers]. [Resetting the organization CloudTrail details disables the existing CloudTrail and moves all onboarded accounts to Needs Attention until the new CloudTrail is validated; successful validation shows status Enabled and a validation problem shows Failed.](kb:dspm.onboarding-aws-cloudtrail:change-org-effects) [Changing the AWS orchestrator account is available only for AWS accounts onboarded through Zscaler network configuration mode, and requires an administrator role or a custom role with the Configure New Orchestrator permission.](kb:dspm.onboarding-aws:change-orchestrator-scope) [New AWS accounts can be added to the monitoring scope but existing target accounts cannot be removed; managing it needs an Administrator role or a role with Configure Monitoring Scope permission.](kb:dspm.onboarding-aws:monitoring-scope-add-only) [The service account private key is generated in JSON format when the tree discovery template is applied; it can be replaced at any time by uploading a JSON key file in the Update Private Key window, and DSPM shows an error if the key is invalid or does not match the service account.](kb:dspm.onboarding-gcp:private-key-update) What two of these actions do is not described [gap:dspm.cloud-accounts:manage-actions-undescribed].

**Account page and status.** After successful onboarding an account page shows Overview, an Accounts, Subscriptions or Projects tab by cloud, Issues, and Roles and Templates. [dspm.cloud-accounts:account-tabs] The Overview Account Status chart uses Successfully Configured (configured and validated), Needs Attention (misconfigurations or permission issues) and Pending Configuration (roles and permissions yet to be configured and validated). [dspm.cloud-accounts:account-status] The Overview Orchestrator Details show number of custom tags, primary region, network type, a DSPM Connection Status described as Successful or Failed, a Configuration Status described as Successful, Warning, Failed or Pending Validation, and Last Connected. [dspm.cloud-accounts:orchestrator-details-overview] For AWS, the Overview shows CloudTrail details and Data Events panes, which the page says are available only for AWS organizations, and an Evidence pane (S3 bucket name, storage type Zscaler or Custom, bucket account ID). [dspm.cloud-accounts:overview-aws-panes] The account list shows Last Validated (the date and time the account is validated to check all configurations); the CloudTrail details are in the Details view opened by clicking an account's name and are shown only for AWS accounts; several accounts can be selected to change the business unit or delete them together. [dspm.cloud-accounts:account-details]

**Orchestrator status.** DSPM Connection Status: Successful means the orchestrator instance is connected, Failed means it cannot establish a connection with DSPM, and Waiting for connection means the orchestrator template is not yet deployed in the CSP. [dspm.cloud-accounts:connection-status] Configuration Status: Successful means all resources are deployed and permissions configured; Warning means some resources or permissions are unavailable, tampered with or not visible; Failed means the orchestrator cannot launch scanner instances or roles and permissions are missing; Pending means the orchestrator account changed or the template is not yet deployed. [dspm.cloud-accounts:configuration-status] What Pending Validation means is open [gap:dspm.cloud-accounts:pending-validation]. [What the DSPM orchestrator and scanner instances are: architecture, sizing, default scanner types, tags and DSPM service IPs](kb:dspm.orchestrator)

**Validation.** DSPM runs a health validation service that checks onboarding templates are deployed and roles and permissions are configured, and validates cloud accounts every hour; an on-demand validation can run without waiting. [dspm.cloud-accounts:health-validation] What a failed validation does beyond the status values is open [gap:dspm.cloud-accounts:validation-failure-effect].

**Issues.** The Issues tab lists issues detected in the onboarded AWS organization, GCP organization or Azure tenant with resolution steps, and an account or project with an issue moves to Needs Attention until it is resolved; unaddressed issues might impact scanning. [dspm.cloud-accounts:issues] Onboarding issues include, for AWS, role not found in the orchestrator or target accounts and CloudTrail configuration problems; for Azure, admin consent not granted, invalid client secret and application object unavailable; for GCP, missing permissions in the service account and missing resources in the Orchestrator project. [dspm.cloud-accounts:issue-types] What the suspended and deleted issues mean is open [gap:dspm.cloud-accounts:issue-meanings].

**Roles and templates.** Roles and Templates offers downloadable templates: AWS includes Monitoring Scope and Data Events, in CloudFormation or Terraform; Azure includes Azure Onboarding; GCP includes GCP Onboarding; the downloaded file name includes the template version number, and an AWS external ID can be viewed and copied. [dspm.cloud-accounts:templates] Acknowledging a new template overrides the existing one and is limited to the Administrator role, while a role with View Cloud Accounts can only view or download; acknowledging for one organization or tenant updates all onboarded ones; until acknowledged, validations continue on the existing template. [dspm.cloud-accounts:template-acknowledge] DSPM templates can be redeployed to upgrade to a new template, when custom roles created during onboarding have issues, or to modify or delete a role. [dspm.cloud-accounts:template-redeploy]

**Business unit.** A business unit assigned to an OU or management group applies to all accounts in it, changing it overrides the current assignment, and it requires the Administrator role or a role with the Business Unit Mapping permission. [dspm.cloud-accounts:business-unit]

**Deleting an account.** Deleting an account cannot be reverted; it does not delete resources created while deploying templates, which must be removed manually (terraform destroy); deleting a single or multiple accounts removes them only from the DSPM Admin Portal; it requires an Administrator role or a role with Delete Account permissions. [dspm.cloud-accounts:delete-effects] Deleting an account closes its alerts, disables alert rules or ignore filters and scan configurations scoped only to it, and marks its custom policies invalid. [dspm.cloud-accounts:delete-module-impact] What all the resources within the account are deleted covers is open [gap:dspm.cloud-accounts:delete-all-resources].

**Services.** After onboarding the services to scan can be selected and DSPM permissions are restricted to those services; the Unmanaged Database option is enabled only for organizations or tenants onboarded via custom configuration. [dspm.cloud-accounts:services]

**Custom tags.** Custom tags are key-value pairs applied to DSPM-created resources while deploying templates; managing them needs an Administrator role or Configure Monitoring Scope permission, and an edit overrides the existing tag once templates are deployed while a delete removes the tag after deployment. [dspm.cloud-accounts:tags-meaning] AWS custom tag rules: case-sensitive; keys 1-127 characters, values up to 256; tags shouldn't start with aws. [dspm.cloud-accounts:tags-aws] Azure custom tag rules: keys case-insensitive, keys 1-128 characters, values up to 256 characters. [dspm.cloud-accounts:tags-azure] GCP custom tag rules: keys and values only lowercase letters, numbers, _ or -; keys start with a lowercase letter and are 1-63 characters. [dspm.cloud-accounts:tags-gcp] Custom tags must not use the predefined DSPM tags, including z-dspm-tenant-id, z-dspm-tenant-name, z-dspm-resource, z-lp-resource-type, z-dspm-integration-id, z-dspm-scanner-resource and z-dspm-scan-id, nor microsoft or windows (a partial list of the page's entries). [dspm.cloud-accounts:tags-reserved]

**Regions.** Regions can be selected to deploy scanner instances so as to control resource allocation and cost; it needs an Administrator role or Configure Monitoring Scope permission, and after template deployment later scans cover the selected regions. [dspm.cloud-accounts:regions] With the custom network configuration, each selected region needs AWS Subnet ARN, Security Group ID and, if required, a DB Subnet Group ARN, or Azure Subnet ID, Network Security Group ID and, if required, a Postgres Delegated Subnet ID; and with the Zscaler network configuration the regions are chosen by checkbox. [dspm.cloud-accounts:regions-custom-fields] For AWS, added regions are applied by adding stacks to the orchestrator StackSet and replacing the StackSet template; for Azure the Azure Onboarding template and for GCP the GCP Onboarding template is redeployed. [dspm.cloud-accounts:regions-deploy] [How to set up a custom DSPM network on AWS, Azure and GCP (control plane and worker plane) and change the orchestrator network (AWS and Azure)](kb:dspm.network-configuration)

**Evidence storage.** DSPM generates evidence data for files and tables with sensitive data and can store snippets in an AWS S3 bucket or Azure storage account container, either existing in a region selected while onboarding or newly created by DSPM in the orchestrator account. [dspm.cloud-accounts:evidence-storage] The evidence S3 bucket or storage account container cannot be changed after it is added; only the evidence configuration can be enabled or disabled, and disabling stops DSPM sending evidence data to the storage account. [dspm.cloud-accounts:evidence-immutable] Custom evidence storage takes, for AWS, an S3 bucket name, a 12-digit bucket account ID and a KMS key ARN used to encrypt the evidence, and for Azure a storage account resource ID, container name and key vault resource ID used to encrypt the evidence; the Zscaler Managed options create the storage in the orchestrator account. [dspm.cloud-accounts:evidence-aws-azure] For Azure Zscaler Managed Container evidence storage, if Deploy private endpoint for secure communication was selected during onboarding, the system's IP address must be added to the orchestrator account's key vault before running the evidence template; Zscaler recommends the latest onboarding templates. [dspm.cloud-accounts:evidence-azure-keyvault] GCP evidence storage is a Custom Bucket by name or a Zscaler Managed Bucket that DSPM creates in the orchestrator project. [dspm.cloud-accounts:evidence-gcp]

What to check:
1. Which article the status value comes from (Viewing the Onboarding Status or Viewing the Orchestrator Status, which both describe the Overview Orchestrator Details section) before quoting its values, since the pages list different values.
2. Which role the template acknowledgement needs.
3. Whether deleting the account leaves resources created while deploying templates in place.

Sources disagree (name both sides):
- Which providers have Manage Evidence and Manage Services: the About page lists them for AWS and Azure only, while the evidence page has a GCP Manage Evidence procedure and the services page opens with cloud accounts of AWS, Azure or GCP. [divergence:dspm.cloud-accounts:manage-menu-providers]
  - zscaler-help: The About page lists Manage Services and Manage Evidence under AWS and Azure, and GCP only Update Service Account and Update Private Key.
  - zscaler-help: The evidence page gives a GCP Manage Evidence procedure with a bucket entered by name and a bucket DSPM creates in the orchestrator project.
  - zscaler-help: The services page has the reader pick a cloud account (AWS, Azure, or GCP) and then Manage Services.
  Impact: Do not rule out Manage Evidence or Manage Services on a GCP account from the About page's list alone; the evidence page documents the GCP evidence procedure.
