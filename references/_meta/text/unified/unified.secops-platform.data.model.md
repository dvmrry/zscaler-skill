# The Agentic SecOps Platform data model: entity types, Data Model Management, field settings, processing and Entity Management Runs (unified.secops-platform.data.model)
Also called: data model; data model management; entity types; entity management runs

The data model is an entity-based relational database that provides the canonical schema for entities and fields, defining names, types, relationships, defaults, fallback logic and how conflicting values from multiple sources are resolved. [unified.secops-platform.data.model:dm-definition] Data flows through the model in these steps: create a source and ingest, map ingested fields (mapping is configured per source and all fields have preconfigured defaults), create merge and unification rules, then view the unified records in UVM, AEM, Agentic SOC and Identity Protection. [unified.secops-platform.data.model:dm-pipeline] The help advises consulting the Zscaler Account team before changing the data model, warning that uninformed changes can cause fragmented or duplicated data, and advises starting with defaults and adding unification overrides only when business outcomes require them. [unified.secops-platform.data.model:dm-change-caution]

## Entity types

The core UVM entities the page describes are Global Vulnerability (a publicly disclosed NVD vulnerability with a CVE ID), Finding (an instance on a component of an asset), Asset, Component and Ticket. [unified.secops-platform.data.model:et-uvm] Each occurrence of a global vulnerability on an asset or component is a unique finding linked back to the global vulnerability entity. [unified.secops-platform.data.model:et-global-vuln] Assets can be servers, endpoints, code repositories, containers and images, and components can be software, packages or operating systems. [unified.secops-platform.data.model:et-asset-component-kinds]

**Other applications.** An AEM violation ticket consolidates policy violations, and its default grouping rule is based on the policy assignee and policy name. [unified.secops-platform.data.model:et-violation-ticket] Agentic SOC has Alert (a security notification from third-party products and Zscaler, aggregated and reduced via agentic AI) and Incident (a grouping of alerts representing the full attack story) entities, and Identity Protection has an identity finding entity. [unified.secops-platform.data.model:et-soc-identity]

## Data Model Management

Data Model Management (Configure > Data Model) shows each entity or field's Entity Type, System Name (the database name used in queries and field-value calculations), Type, Tags (defined by Zscaler, not configurable), Visibility and Allow Manual Override. [unified.secops-platform.data.model:dm-mgmt-page] Field types are Text, Number, Boolean, Date, Date & Time, and the Repeated variants of each. [unified.secops-platform.data.model:dm-field-types] The reconciliation defaults table names further types [divergence:unified.secops-platform.data.model:field-type-list]. Changing entities and fields requires a role with Read, Create, Edit and Delete permissions under the Platform - Model Management resource. [unified.secops-platform.data.model:dm-role]

**Adding entities and fields.** Adding an entity is irreversible: entities cannot be deleted from the data model except through Zscaler Support, and a new entity is created with the default fields First Seen, Last Seen, Tags, Sources, ID, Locked, State, Created, Last Update, Last State Transition, Key, Name and Type. [unified.secops-platform.data.model:dm-add-entity] Adding a field is irreversible: fields cannot be deleted from the data model except through Zscaler Support. [unified.secops-platform.data.model:dm-add-field] Relationships between entities and their fields are defined on Configure > Relations, and proper relations prevent orphan records. [unified.secops-platform.data.model:dm-relations]

**Field settings.** Field visibility controls whether a field is viewable in UVM, AEM and other SecOps applications; hidden fields are still processed, aggregated and unified. [unified.secops-platform.data.model:dm-visibility] Every field has a default formula (calculations are Python script shown in the field drawer), and the help recommends using field unification rules to modify it; null and error handling each default to Set Null. [unified.secops-platform.data.model:dm-calculation] The two pages give Unlink & Override opposite directions [divergence:unified.secops-platform.data.model:unlink-override-direction]. Allow Manual Updates lets users change a field value after unification, can be restricted to roles or resources, and the optional Require Reason on update toggle, when enabled, offers Always (selected by default) or Specific conditions; some fields and entities do not allow it. [unified.secops-platform.data.model:dm-manual-updates] A field's Usage tab lists the reports, views, dashboards, data model fields, data source mappings, UI configurations and measurements that include the field, and shows only sections where the field is in use. [unified.secops-platform.data.model:dm-usage-tab]

**Processing.** Process All or Process by entity manually applies unification rules and reconciliation logic outside scheduled runs; Process by entity offers the options Run selected and dependent projects or Run selected projections only. [unified.secops-platform.data.model:dm-process] Which "projects" and "projections" the options mean is not defined [gap:unified.secops-platform.data.model:dm-projects-undefined].

**Entity Management Runs.** Entity Management Runs have statuses Completed, Canceled, Failed and Partially Completed; a Partially Completed run had some data manipulation errors and should be processed again manually. [unified.secops-platform.data.model:dm-run-status] Entity Management run types include Agg process (manual Process or Process All), Batched (its configured schedule), Auto-batched (platform-managed batch process) and Post manual operation (a user overriding a field value); all are categorized as Aggregate runs, and the full list is available from Zscaler Support. [unified.secops-platform.data.model:dm-run-types] The source runs list defines Batched differently [divergence:unified.secops-platform.data.model:batched-run-type]. How long run history is kept is not stated [gap:unified.secops-platform.data.model:dm-run-retention].

Sources disagree (name both sides):
- The Data Model Management page lists the available field types as Text, Number, Boolean, Date, Date & Time and their Repeated variants; the attribute reconciliation defaults table has rows for IP, Fix and Message field types and none for Date & Time. [divergence:unified.secops-platform.data.model:field-type-list]
  - zscaler-help: The available field types are Text, Number, Boolean, Date, Date & Time and the Repeated variants.
  - zscaler-help: The reconciliation defaults table gives IP, Fix and Message fields their own defaults.
  Impact: Do not give the field type list as closed or complete; the reconciliation table names IP, Fix and Message types that the list omits, and it has no Date & Time row.
- Unlink & Override in the Data Model drawer removes the field from field unification rules; on the Data Unification - Fields page the same action overrides the data model logic, which the field unification page describes as a unidirectional update. [divergence:unified.secops-platform.data.model:unlink-override-direction]
  - zscaler-help: In the Data Model drawer, Unlink & Override removes the field from field unification rules.
  - zscaler-help: Field unification rules override the data model logic, and the data model does not update them back.
  Impact: Name which page's Unlink & Override is meant; the two pages give it opposite directions.
- The Entity Management Runs list defines Batched as a run initiated by its configured schedule; the source runs list defines Batched as a run initiated as part of a platform-managed batch process. [divergence:unified.secops-platform.data.model:batched-run-type]
  - zscaler-help: Entity Management Runs: Batched is a scheduled run.
  - zscaler-help: Source runs: Batched is a platform-managed batch run.
  Impact: Do not carry the meaning of Batched from one run list to the other.
