# Admin portal automation: playbooks, automation rules, runs, manual triggering and their audit logs (unified.secops-platform.console.automation)
Also called: secops platform SOAR; playbooks; automation rules; Select Playbook

**How automation fits together.** Automation is the platform's SOAR capability: playbooks are collections of actions that run as one workflow, automation rules trigger one or more playbooks when conditions are met, and it covers alerts, incidents, users and identity findings. [unified.secops-platform.console.automation:soar-components] A typical automation runs in four steps: a security alert, evaluation of the automation rule against its conditions and filters, running the associated playbook when they are met, and the playbook performing its configured actions. [unified.secops-platform.console.automation:workflow-steps] A playbook's entity type (Alert, Incident, User or Identity Finding) must match the entity type of the automation rule that runs it. [unified.secops-platform.console.automation:entity-type-match]

**Playbooks.** The Playbooks page (Agentic SOC or Identities > Automations > Playbooks) lists name, description, entity type, owner, last update, number of runs, successful and failed runs, and whether the playbook is active; playbooks can be duplicated, edited, deleted and exported, and the page links to a Template Gallery of preconfigured playbook templates. [unified.secops-platform.console.automation:playbook-list-columns] A playbook has a user list allowed to edit it, and an Allow Manual Triggering option with a list of users who may trigger it and the applications in which it is enabled. [unified.secops-platform.console.automation:playbook-permissions] A playbook can be created from scratch, from a template-gallery template (Save as New), or from a JSON export, which carries name, description, entity type, actions, permissions and status; importing a name that already exists produces an error. [unified.secops-platform.console.automation:playbook-creation-routes] Deleting a playbook gives no warning and takes effect immediately, and importing a JSON file into an existing playbook overwrites it (creating a new playbook from the JSON preserves the existing one). [unified.secops-platform.console.automation:playbook-delete-import] Duplicating a playbook makes a copy with the original name and Copy appended. [unified.secops-platform.console.automation:playbook-duplicate]

**Runs.** A playbook run has the status Completed, Canceled (intentionally stopped by the user) or Failed (an error stopped it), and a triggering type of Manual (initiated by a user) or Automatic (initiated by an automation rule). [unified.secops-platform.console.automation:playbook-run-status] In a run, Triggered By is System when an automation rule fired on met conditions, or User when someone clicked Process or Process All. [unified.secops-platform.console.automation:playbook-run-triggered-by] The button labels differ from the manual-trigger procedure [gap:unified.secops-platform.console.automation:triggered-by-button-labels]. Expanding a run shows per action its name, status (Completed or Failed), failure reason, start and end times, total time and the JSON payload. [unified.secops-platform.console.automation:playbook-action-detail] Playbooks can be triggered manually on incidents and alerts in Agentic SOC, and on users and identity findings from Identities, through Select Playbook and the Response Action drawer, which lists only playbooks of that entity type. [unified.secops-platform.console.automation:manual-trigger-entities]

**Automation rules.** An automation rule's trigger is one of Create, Update or Delete of the entity, and the rule's Active setting is enabled by default. [unified.secops-platform.console.automation:rule-triggers] Rule filters combine conditions on entity fields with AND (more than one condition must be met) or OR (either condition), and one or more playbooks are chosen from the Playbook Inventory. [unified.secops-platform.console.automation:rule-conditions] The Automation Rules page can filter rules by entity, status or trigger, show or hide linked playbooks, and unlink a playbook from a rule. [unified.secops-platform.console.automation:rules-page]

**Audit logs.** A playbook's audit log (Edit Playbook > More > Audit Logs) shows time, operation, type and user name with the JSON differences of each change, and its Download icon downloads the logs of the last 90 days. [unified.secops-platform.console.automation:playbook-audit-logs] An automation rule's audit log (Edit Automation Rule > More > Audit Logs) lists time, operation, type and user name, and its download covers the last 90 days. [unified.secops-platform.console.automation:rule-audit-logs]

**Open items.** The action catalog, templates and rule operators are not listed [gap:unified.secops-platform.console.automation:action-catalog].
