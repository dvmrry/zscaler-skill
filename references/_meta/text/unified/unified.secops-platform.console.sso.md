# Admin portal SSO: generating SAML details and the Entra ID, Okta, PingOne, PingFederate and SecureAuth setups (unified.secops-platform.console.sso)
Also called: secops platform SSO; Generate SAML Details; app.avalor.io

SSO account authentication needs a SAML Entity ID and Reply URL generated in the platform (Generate SAML Details in the Authenticate section); the Authentication Type list stays disabled until the organization email domain is entered and saved. [unified.secops-platform.console.sso:saml-prerequisite] The SAML section also takes the identity provider name, the XML metadata from the provider, an option to disable the onboarding welcome emails for new SSO users, and a default idle period before SSO users are logged out (for example Never, 1 hour, 2 hours). [unified.secops-platform.console.sso:saml-options]

**Providers.** The platform has setup pages for five SSO providers: Microsoft Entra ID, Okta, PingOne, PingFederate and SecureAuth. [unified.secops-platform.console.sso:provider-pages] For each of the five providers the page says SSO is configured per email domain, users with matching addresses are redirected to the provider, each user needs an account with the same email address in both the platform and the provider, and once SSO is enabled for a domain it becomes the only authentication method. [unified.secops-platform.console.sso:domain-redirect-only-method] The captured Entra ID, Okta and PingFederate pages list these steps: Entra ID has Step 1 Generate SAML Details, Step 2 Register an Application in Microsoft Entra ID, Step 3 Share Metadata With Zscaler; Okta has Step 1 Generate SAML Details, Step 2 Create a Bookmark App, Step 3 Create an App Integration, Step 4 Share Metadata With Zscaler; PingFederate has Step 1 Generate SAML Details, Step 2 Register an Application in PingFederate, Step 3 Share Metadata With Zscaler. [unified.secops-platform.console.sso:provider-step-outlines] The step content of the Entra ID, Okta and PingFederate pages is open [gap:unified.secops-platform.console.sso:idp-setup-outlines].

**PingOne and SecureAuth.** In PingOne the SAML application is named "Agentic SecOps Platform- Authentication Only", gets the Reply URL as ACS URL and the Entity ID, maps the emailaddress claim to the Email Address attribute as Required, and is hidden from the Application Portal. [unified.secops-platform.console.sso:pingone-app-settings] In SecureAuth the SAML application uses an SP Initiated connection by redirect, the generated entity ID as IdP Issuer and the Reply URL as ACS, SAML assertion encryption disabled, and a SAML attribute carrying the user email under the emailaddress namespace. [unified.secops-platform.console.sso:secureauth-app-settings] For PingOne and SecureAuth, the provider's XML metadata is pasted into the SAML XML MetaData field (a metadata URL is also supported but pasting is recommended), or shared with the Zscaler account team when the Authenticate section is not visible. [unified.secops-platform.console.sso:metadata-sharing]

**IdP-initiated login.** The platform does not natively support IdP-initiated login; the PingOne page works around it with an Application Portal Link whose URL is https://app.avalor.io?domain=<Your Org Domain>, and the SecureAuth page uses the same host as the SP Login URL. [unified.secops-platform.console.sso:no-idp-initiated-login] Whether that host is current is open [gap:unified.secops-platform.console.sso:login-host-current].
