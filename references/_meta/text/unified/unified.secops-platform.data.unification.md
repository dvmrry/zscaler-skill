# Entity and field unification in the Agentic SecOps Platform: merge rules, field rule sets, reconciliation defaults and precedence over grouping and incident rules (unified.secops-platform.data.unification)
Also called: data unification; entity unification; field unification; Priority By Source; attribute reconciliation

Data unification has two components, entity unification (merging duplicate records into one, preserving raw data for lineage) and field unification (attribute reconciliation, then attribute transformation). [unified.secops-platform.data.unification:uni-two-parts] Attribute reconciliation conflicts are resolved by system defaults or Priority By Source logic; attribute transformation then applies business logic to classify and enrich data. [unified.secops-platform.data.unification:uni-reconciliation-default] Unification rules run when entity data is ingested, when the entity is directly processed or indirectly affected by a related entity, and when manual processing is triggered, including ticket split or merge and Process or Process All on the Data Unification pages. [unified.secops-platform.data.unification:uni-when-run]

## Entity unification

An entity merge rule is an if-then statement whose Then fields cluster matching entities into one; multiple Then fields are combined with logical AND, and AND/OR can combine If conditions. [unified.secops-platform.data.unification:ent-rule-logic] Selecting Exclude Nulls from Merge, which is recommended, avoids merging entities with null values in the defined fields. [unified.secops-platform.data.unification:ent-exclude-nulls] An entity rule set that includes at least one conditional merging rule must also include a fallback rule that names a single field to merge on without conditions, otherwise the rule set cannot be saved. [unified.secops-platform.data.unification:ent-fallback]

**Applying rules.** Saving an entity unification rule set applies the rules on the next data ingestion, while Save & Run applies them immediately to the data in the account. [unified.secops-platform.data.unification:ent-save-run] The order of rules in an entity unification rule set does not affect application order; each data point is evaluated against all rules. [unified.secops-platform.data.unification:ent-rule-order] Manually processing an entity without processing its related entities can cause data misalignment until the next full data run, and newly configured entity rules apply on the following data run by default. [unified.secops-platform.data.unification:ent-manual-process] Entity management runs are viewed by clicking Configure in the Agentic SecOps Platform Admin Portal, going to Data Unification > Fields (field unification page) or Data Unification > Entities (entity unification page) and clicking the See Logs icon, which opens the Entity Management Runs page. [unified.secops-platform.data.unification:managing-runs-path] Entity unification and field unification both require a role with Read, Create, Edit and Delete permissions under the Platform - Model Management resource. [unified.secops-platform.data.unification:ent-role]

## Field unification

On initial account setup all deduplicated fields are populated with default values, and every field rule set includes a fallback rule with no conditional logic that can be edited but not removed or deleted. [unified.secops-platform.data.unification:fld-defaults-fallback] Managing field unification rule sets covers Process Entity Rule Sets, viewing Entity Management Runs, and editing, copying/pasting and deleting rule sets; managing rules covers cloning, editing and deleting a rule, though the fallback rule in every rule set can't be removed or deleted. [unified.secops-platform.data.unification:managing-actions] A field rule set is either Conditions (the default, available for fields of all entity types) or Priority By Source, which orders sources by precedence and is not available for Ticket fields. [unified.secops-platform.data.unification:fld-set-types] A conditions rule sets the field value using Value, Field, Smart Text, Expression or Empty, with options varying by field type; field unification conditions are not case sensitive. [unified.secops-platform.data.unification:fld-value-methods] The ticket-title definitions of Smart Text and Expression are in [Ticket titles are set by Smart Text (free text plus field names as tokens in double curly brackets) or by an Expression that applies custom value transformations.](kb:uvm.tickets:title-methods); what they do in a field rule is not defined [gap:unified.secops-platform.data.unification:fld-methods-undefined].

**Priority By Source and ordering.** Priority By Source rules evaluate sources in the defined order and return the first non-null value, moving to the next source when the previous one provides none; an expression can transform the returned value. [unified.secops-platform.data.unification:fld-priority-by-source] Field unification rules in a rule set run sequentially in order of appearance, a field is unified by the first rule that applies, and the fallback rule applies if none does; order can be changed by dragging. [unified.secops-platform.data.unification:fld-rule-order] Rule previews show the top 50 entities; Save applies field rules on the next data ingestion, while Save & Run reruns the rules for the current entity and all related entities, with a full rerun of all entities on the next data run. [unified.secops-platform.data.unification:fld-preview-save]

**Uses.** Common field unification uses are classifying assignment and ownership fields (Asset Owner ID, Ticket Assignee) and enriching attributes from tags (Asset Is Crown Jewel, Asset Business Criticality). [unified.secops-platform.data.unification:fld-use-cases] The rule bodies of these examples are not in the capture [gap:unified.secops-platform.data.unification:fld-examples-headings-only].

## Precedence over other settings

The first time a field unification rule is configured for a field, the system prompts to unlink and override the data model logic; later data model changes for that field are not reflected in the field unification rule. [unified.secops-platform.data.unification:fld-vs-model] Creating or updating a ticket grouping rule in UVM or AEM unidirectionally overrides the matching field unification rule; grouping rules configured in field unification do not sync back to the grouping rules setup page. [unified.secops-platform.data.unification:fld-vs-grouping] When an incident is created, its incident rule unidirectionally overrides field unification rules for the incident Title, Type and Grouping Details fields. [unified.secops-platform.data.unification:fld-vs-incident] There are three incident types: Custom (from custom incident rules), Platform (from default incident rules, which can be modified) and AI (created by the Correlation agent). [unified.secops-platform.data.unification:incident-types] Some rule setups can reference either the original source value (the raw value from the source before processing or deduplication) or the merged entity value (the unified platform value), but not all rule setups support original source values. [unified.secops-platform.data.unification:orig-vs-merged]

## Reconciliation defaults

Default reconciliation for conflicting values is MAJORITY for Text fields (most frequent value), MAX for Number fields, MAX for Boolean fields (TRUE if at least one value is TRUE) and MAX for Date fields (most recent date). [unified.secops-platform.data.unification:recon-text-number] Repeated fields, IP fields and Fix fields default to COLLECT_DISTINCT_FLAT (a list of distinct values), and Message fields default to MAX. [unified.secops-platform.data.unification:recon-repeated] First Seen fields (all entity types) default to MIN, the earliest date, and Last Seen fields default to MAX, the most recent date. [unified.secops-platform.data.unification:recon-first-last-seen] Where merged Asset records give multiple Asset Operating System values, the system selects the value that appears most frequently; defaults can be adjusted on request or replaced with Priority By Source. [unified.secops-platform.data.unification:recon-os-example]
