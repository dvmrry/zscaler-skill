# Agentic SecOps Platform data sources, outegrations and data management: hub (deployment flows, catalogs, outegration wizard) (unified.secops-platform.data)
Also called: secops platform data sources; data source catalog; outegration catalog; deploying data source configurations; deploying outegration configurations; managing data sources; managing outegrations

The recommended data source flow triggers an initial extraction, maps the ingested fields, then runs the source a second time to apply the mapping rules, after which it syncs on a schedule. [unified.secops-platform.data:ds-run-map-rerun] Another page says a new source's data arrives on the next data run [divergence:unified.secops-platform.data:ds-first-run]. Auto-scheduling, which coordinates source runs as a single process, is recommended; the setting is enabled by default and can be adjusted to your data windows. [unified.secops-platform.data:ds-auto-scheduling] How often a source refreshes is not stated [gap:unified.secops-platform.data:refresh-cadence].

**Before and after configuring.** Before configuring a data source, the vendor-side credentials should have read-only permissions for the targeted streams, the vendor may require the platform's public IP addresses to be allowlisted, and API keys, secrets and tokens entered in the platform are encrypted. [unified.secops-platform.data:ds-prereqs] The help names the telemetry each application needs: UVM scanners and CSPM tools; AEM CMDBs, IT asset management tools and cloud inventories; Identity Protection IAM directories and Zscaler Client Connector endpoint telemetry; Agentic SOC EDR, identity and Zscaler network telemetry. [unified.secops-platform.data:ds-app-inputs] When no data source exists for a tool, the AnySource connector can ingest proprietary or unsupported data feeds, for example through an AWS S3 bucket. [unified.secops-platform.data:ds-anysource-fallback] Email notifications can be enabled for failures related to source runs and ETL processing, and audit logs track changes to data source instances, mappings and scheduling settings. [unified.secops-platform.data:ds-monitoring] The Managing Data Sources page lists these actions: configure auto-scheduling, edit, delete, deactivate, view source runs, map source data, process, rerun last execution and view the audit logs. [unified.secops-platform.data:ds-manage-actions]

**Data source catalog.** The data source catalog table lists supported data sources by vendor, the streams each supports, and the type of data each stream retrieves. [unified.secops-platform.data:ds-catalog-shape] Microsoft Intune appears as two data sources: Microsoft Intune Assets, which retrieves Intune devices mapped to assets, and Microsoft Intune Audit Events, which retrieves audit events and logs using the Microsoft Graph API. [unified.secops-platform.data:catalog-intune] The Entra ID data source lists four streams: Administrative Units, Applications, Devices, and Users & Groups. [unified.secops-platform.data:catalog-entra] The catalog lists Qualys streams for host data, vulnerabilities and policy compliance, and separate Qualys streams for web applications and their findings. [unified.secops-platform.data:catalog-qualys] The catalog lists Google Sheets as a source that retrieves data from a specified spreadsheet and can optionally filter by sheet, and Freshservice as a source that retrieves ticket data. [unified.secops-platform.data:catalog-sheets-freshservice] Among the CrowdStrike streams the catalog lists are CrowdStrike Vulnerabilities, Managed Hosts and Environmental Assets, CrowdStrike CSPM indicators of misconfiguration (IOM) and of attack (IOA), and CrowdStrike Identity Protection Security Assessment and Domain Users. [unified.secops-platform.data:catalog-crowdstrike] Rows for some sources that other captured pages cover are missing from the table [gap:unified.secops-platform.data:ds-catalog-rows].

**Outegrations.** Creating Outegrations lists the steps Connect, Settings and Mapping; the Settings step says all outegrations require selecting an entity to create the outegration from, and work management outegrations can configure the Create Ticket button. [unified.secops-platform.data:og-wizard] The AWS S3 guide's steps differ [divergence:unified.secops-platform.data:og-wizard-steps]. For outegrations that support bidirectional synchronization, the deployment flow includes configuring a webhook to receive updates from the third-party system; an outegration can be deactivated to stop outbound activity without removing its configuration. [unified.secops-platform.data:og-flow] UVM uses outegrations to send remediation tasks to external ticketing and workflow systems, and AEM uses them to route asset exposure findings and operational context into external systems. [unified.secops-platform.data:og-app-use] Outegration activity is monitored through activity logs, email notifications can be enabled for outegration failures, and audit logs track changes to outegration configurations and mappings. [unified.secops-platform.data:og-monitoring] The Managing Outegrations page lists these actions: edit mapping, edit details and settings, delete, clone, deactivate and see the activity log. [unified.secops-platform.data:og-manage-actions]

**Outegration catalog.** In the outegration catalog, Jira, Freshservice, Azure DevOps and ServiceNow list a webhook guide for bidirectional sync, while Kafka, GCP Storage, ServiceNow CMDB, Tenable and Email are listed as Not supported. [unified.secops-platform.data:og-catalog-webhooks] The outegration catalog assigns categories: Kafka and Email are Alerts, Jira, Freshservice, Azure DevOps and ServiceNow are Work Management, GCP Storage is Storage, ServiceNow CMDB is CMDB and Tenable is Scanner. [unified.secops-platform.data:og-catalog-categories] The catalog lists Jira (Cloud and Data Center) as dispatching Agentic SecOps Platform tickets to a Jira project as mapped issue types such as Task or Bug. [unified.secops-platform.data:og-catalog-jira] The connectors the per-connector guides document and the webhook guides are not among these articles; the webhook guides are covered in [UVM ticketing outegrations (Jira, ServiceNow, Freshservice, Azure DevOps), the ServiceNow CMDB outegration, their webhooks and mapping](kb:uvm.outegrations.ticketing) [gap:unified.secops-platform.data:og-catalog-coverage].

Sources disagree (name both sides):
- Creating Outegrations gives Connect, Settings and Mapping as the creation steps and says all outegrations require selecting an entity; the AWS S3 outegration guide lists its steps as Connect, Settings, and Configure Reports or Define Dispatch Criteria, with no Mapping step. [divergence:unified.secops-platform.data:og-wizard-steps]
  - zscaler-help: Creating Outegrations: every outegration has Settings, where an entity is selected, and Mapping steps.
  - zscaler-help: The AWS S3 guide has Connect, Settings and a reports or dispatch criteria step, with no Mapping step.
  Impact: Do not state the Connect, Settings, Mapping sequence or entity selection as holding for every outegration; the Google Cloud Storage outegration guide uses none of those step names.
- Deploying Data Source Configurations says that after the source is created you must trigger the initial extraction; Creating data sources and the suppression rules page say the new data is retrieved on the next data run, or the source runs automatically on its schedule, with Process Now to retrieve immediately. [divergence:unified.secops-platform.data:ds-first-run]
  - zscaler-help: The initial extraction must be triggered.
  - zscaler-help: New data is retrieved on the next data run, or immediately with Process Now.
  Impact: Do not say whether a new source needs a manual first run without naming that the pages differ.
