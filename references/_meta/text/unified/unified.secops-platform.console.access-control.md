# Admin portal roles, users and content permissions: system and custom roles, resource categories, RBAC and ABAC, and the scope of content permissions (unified.secops-platform.console.access-control)
Also called: secops platform roles; secops platform content permissions; No Access role

**System roles.** System roles are predefined, cannot be modified, and are updated automatically when new features are introduced, while permissions for new features must be added manually to custom roles. [unified.secops-platform.console.access-control:system-roles-fixed] The set of system roles differs between UVM, AEM and Agentic SOC, and a role's permissions are seen by clicking the role name on the Roles page to open its matrix. [unified.secops-platform.console.access-control:system-roles-per-app] The role names and matrices are open [gap:unified.secops-platform.console.access-control:system-role-list].

**Custom roles.** Custom roles grant Read, Create, Edit, Delete and Audit permissions per resource, selecting a higher-level permission such as Edit enables the required lower-level ones such as Read, and the system Admin role cannot be duplicated. [unified.secops-platform.console.access-control:custom-role-permissions]

**Roles page actions.** The Roles page in the Agentic Security Operations Platform (Agentic SecOps Platform) gives a centralized view of all system and custom roles, and the page lists the actions Edit Users in the Role, Duplicate a Role, Edit a Custom Role and Delete a Role. [unified.secops-platform.console.access-control:roles-page-actions] System roles cannot be modified [unified.secops-platform.console.access-control:system-roles-fixed] and the Admin role cannot be duplicated [unified.secops-platform.console.access-control:custom-role-permissions].

**Resource categories.** The Platform resource category of a custom role covers Model Management, Data Source Mapping, Data Source, User Saved Views, Outegrations and Authentications. [unified.secops-platform.console.access-control:resources-platform] The Explore category's table of key analytics resources has Search (view and search logs) and Reports & Dashboards (view and manage custom dashboards and reports). [unified.secops-platform.console.access-control:resources-explore] The Vulnerabilities App category (UVM) lists Dashboards & Analytics, Tickets Page, Tickets Settings, Findings Page, Assets Page, Exceptions Page and Exceptions Settings; ticket settings cover scoring, grouping rules and life-cycle customization and exception settings cover the form, assignment rules and notifications. [unified.secops-platform.console.access-control:resources-uvm] The Assets App category (AEM) lists Violations Tickets, Policy Violations, Policy Violations Outegrations, Policy Rule, Analytics & Insights, Assets Page and Asset Outegrations. [unified.secops-platform.console.access-control:resources-aem] The Agentic SOC category lists Dashboards & Analytics, Incidents Page, Incident Settings and Alerts Page. [unified.secops-platform.console.access-control:resources-agentic-soc] The categories do not cover Identity Protection or automation [gap:unified.secops-platform.console.access-control:resource-categories-coverage].

**When a role takes effect.** The custom role page says the selected users' roles are updated immediately. [unified.secops-platform.console.access-control:role-timing-immediate] The Managing User Roles page says assigned roles are applied on the user's next browser refresh. [unified.secops-platform.console.access-control:role-timing-refresh] The two pages disagree [divergence:unified.secops-platform.console.access-control:role-update-timing].

**Users.** Users are given RBAC roles and optionally ABAC permissions, and can be deactivated or deleted; the Create User page asks for email, first and last name, an optional default (main) account and a role. [unified.secops-platform.console.access-control:user-access-model] A new user without a selected role gets the default No Access role, and removing a user's role without assigning another leaves the default role, which grants no permissions but keeps the user's access to the system. [unified.secops-platform.console.access-control:user-default-no-access] What deactivating and deleting a user do is open [gap:unified.secops-platform.console.access-control:deactivate-delete-scope].

**Content permissions.** Role permissions control the actions a user can perform, while content permissions limit the data the user can view and act on; assignments take effect on the user's next browser refresh. [unified.secops-platform.console.access-control:content-permission-purpose] Content permissions apply only to an account's mapped data, so they do not restrict unmapped data such as Logs or Data Mapping access granted by a role. [unified.secops-platform.console.access-control:content-permission-scope] Content restrictions on scheduled reports and custom dashboard exports follow the permission set of the user who created the report or dashboard, not the receiver, so a delivered report can include data the receiver could not access directly. [unified.secops-platform.console.access-control:content-permission-scheduled-exports] A content permission set's filter conditions pick a field, an operator and a value, and are combined with AND (applies only if all conditions are met) or OR (applies if any condition is met). [unified.secops-platform.console.access-control:content-permission-conditions] A dynamic condition grants access based on the current user's email address using the {user_email} value (the example uses the Assignee Email field), and only the Equals operator is supported. [unified.secops-platform.console.access-control:content-permission-dynamic] With manual content validation, content permissions can restrict which values users may pick when manually updating a field, for example letting security analysts choose Benign, False Positive, Inconclusive or Suspicious on an incident Verdict while reserving Malicious and True Positive for senior security analysts or incident responders. [unified.secops-platform.console.access-control:content-permission-manual-override] Content permissions can be assigned only after a user is created and saved; removing a permission set removes the access limit it set, so the user is no longer limited to the data it defined. [unified.secops-platform.console.access-control:content-permission-assign]
