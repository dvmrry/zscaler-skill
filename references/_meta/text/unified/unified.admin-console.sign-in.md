# Signing in to the Zscaler Admin Console: URLs, sign-in methods, lockouts, password and MFA reset, and the upgrade to Experience Center (unified.admin-console.sign-in)
Also called: console.zscaler.com; admin console login; admin console lockout; Having trouble signing in; upgrade to experience center; beta.console.zscaler.com

The Zscaler Admin Console is the unified user interface for Experience Center, reached at https://console.zscaler.com once the organization is provisioned; an admin with access to multiple Zscaler clouds or tenants selects one at sign-in, the selection is saved for future logins, and the default cloud and tenant can be changed in Account Settings. [unified.admin-console.sign-in:console-url] Depending on the organization's authentication preference, the admin signs in to Authentication Service with a Password, Multi-Factor Authentication (MFA) or a Security Key or Biometric; based on the organization's MFA policy, two-factor authentication (2FA) is required. [unified.admin-console.sign-in:sign-in-methods]

**Sessions.** Admins are automatically logged out after a configurable number of inactive minutes; the page points to Configuring the Authentication Session. [unified.admin-console.sign-in:inactivity-logout] How the session timeout applies to admin console sessions is open [gap:unified.admin-console.sign-in:session-timeout-scope].

**Locked out.** An admin or user with access to Internet & SaaS (ZIA) features within the Zscaler Admin Console who has 5 unsuccessful login attempts within one minute is locked out for 5 minutes, the failed attempts are recorded in the audit log and audit logs are stored for up to 6 months; one with access to Private Access (ZPA) application features who has three unsuccessful login attempts is locked out for 30 minutes, though another admin with the same level of access or a full admin can reset the password. [unified.admin-console.sign-in:lockouts] The Experience Center audit log words the lockout for any admin account [divergence:unified.admin-console.sign-in:lockout-scope]. The password-policy deactivation in [Deactivate user after unsuccessful attempts deactivates the account after that many failed logins; the default is 10, settable from 3 to 10.](kb:zidentity.authentication-methods:password-lockout) is a different mechanism, and how the console lockouts relate to it is open [gap:unified.admin-console.sign-in:lockout-vs-password-policy].

**Resetting a password or second factor.** The sign-in page says that the reset email sent by Having trouble signing in? > Reset Password, Reset Second Factor or Reset Security Key or Biometric carries a link that expires after 5 minutes. [unified.admin-console.sign-in:reset-link-signin-page] On the Resetting the Login Credentials or MFA page, the link to reset the password is sent to the user's email address and remains valid for 15 minutes, after which it must be resent; the user must verify with the registered MFA option to reset a password and can reset it after successful verification. [unified.admin-console.sign-in:self-recovery] The two pages give the link a different lifetime [divergence:unified.admin-console.sign-in:reset-link-lifetime]. If the user cannot use a configured MFA method in certain scenarios (e.g., using a new device), the user informs another Authentication Service administrator to reset the MFA methods for their user account; an administrator might delete the configured MFA option from the user's Security Settings section; the user is then prompted to reconfigure MFA the next time they log in to Zscaler Admin Console. [unified.admin-console.sign-in:mfa-reset] The Resetting page says administrators can also delete the Email OTP option for users who have opted it as their MFA option. [unified.admin-console.sign-in:email-otp-deletion] The Authentication Service entitlements page differs from this [divergence:unified.admin-console.sign-in:email-otp-delete].

**Upgrading to Experience Center.** Upgrading to Experience Center requires administrative users who have already migrated to Authentication Service, for a centralized identity experience to access ZIA, ZPA, Digital Experience (ZDX), Client Connector and other Admin Portals; admins take no further action and, on receiving the migration notification, log in to the Zscaler Admin Console with their existing Authentication Service credentials; the page also tells the organization to migrate its end users to Authentication Service. [unified.admin-console.sign-in:upgrade-prerequisites] After migration the login learns the admin's identity and redirects the admin to the tenant: irrespective of the Zscaler cloud the tenant belongs to, the login URL is https://console.zscaler.com for the production cloud and https://beta.console.zscaler.com for the beta cloud; all existing configurations are retained, and Experience Center can also be reached through the banner on the Authentication Service Admin Portal. [unified.admin-console.sign-in:login-urls] Government clouds are not covered [gap:unified.admin-console.sign-in:login-urls-scope]. Access to the current standalone portals (Admin Portals) will continue to be supported at this time, and all portals can be accessed via Authentication Service. [unified.admin-console.sign-in:standalone-portals] When that stops is open [gap:unified.admin-console.sign-in:standalone-portals-end].

What to check:
1. Which product's features the locked-out admin or user has access to, since the console's lockout rule differs between Internet & SaaS and Private Access access.
2. Do not give a reset link's lifetime as one value; the pages say 5 and 15 minutes.
3. Do not tell an admin whether the Email OTP option can be deleted without naming that the pages differ.

Sources disagree (name both sides):
- The Signing in page says the password reset link expires after 5 minutes; the Resetting the Login Credentials or MFA page says the link remains valid for 15 minutes. [divergence:unified.admin-console.sign-in:reset-link-lifetime]
  - zscaler-help: The password reset link within the email expires after 5 minutes.
  - zscaler-help: The link to reset the password remains valid for 15 minutes, after which it must be resent.
  Impact: An admin who clicks the link between 5 and 15 minutes after the email is sent gets an expired link by one page and a valid one by the other; neither page says which governs.
- The Resetting page says administrators can delete the Email OTP option for users who chose it as their MFA option; the Authentication Service entitlements page says authenticators can be deleted except the email authenticator. [divergence:unified.admin-console.sign-in:email-otp-delete]
  - zscaler-help: Administrators can delete the Email OTP option for users who have configured it as an MFA method.
  - zscaler-help: Authenticators can be deleted except the email authenticator (existing claim zidentity.users.security-settings:authenticators).
  Impact: Neither page says whether the entitlements page's email authenticator is the Email OTP MFA option, so whether an admin can delete it, and from which page, is unsettled.
- The Experience Center audit log page gives one lockout for any admin account (five failed attempts in one minute, five minutes); the Signing in page applies that rule to Internet & SaaS feature access and gives Private Access application access three attempts and 30 minutes. [divergence:unified.admin-console.sign-in:lockout-scope]
  - zscaler-help: An admin account that makes five unsuccessful login attempts within one minute is locked out for five minutes.
  - zscaler-help: An admin or user with access to Private Access application features is locked out for 30 minutes after three unsuccessful login attempts.
  Impact: For an admin with Private Access application access, the audit log page implies five attempts and five minutes where the Signing in page gives three attempts and 30 minutes; both pages describe signing in to the Zscaler Admin Console, and neither says how the rules combine.
