# Experience Center guided onboarding: adding users, traffic forwarding, and the security policy steps it walks through (unified.onboarding)
Also called: guided onboarding; setting up secure access; onboarding wizard; Test Security; Activate & Launch

The onboarding workflow is for new tenants: it is a streamlined workflow to add users, distribute the Zscaler Client Connector app and secure traffic by enabling policies that Zscaler recommends as a best practice. [unified.onboarding:for-new-tenants] Guided onboarding has four steps (set up users, set up traffic forwarding, set up security policies, fine-tune the security setup); Skip bypasses all or part of it and goes directly to the Experience Center home page, and the skipped parts must then be configured manually. [unified.onboarding:steps-and-skip] The Test Security button checks the status of the current security configuration, to show current vulnerabilities, using Zscaler's Internet Threat Exposure Analysis, and the test can be returned to after onboarding to see how the organization is protected. [unified.onboarding:test-security]

**Step 1: users.** During onboarding a user is either an End User, a regular user who does not require administrator access, assigned to the Authentication Service Dynamic Group Registered Domains group, or a Full Admin, an administrator with full access to add, edit, import and delete users within the Zscaler Admin Console, assigned to the Authentication Service Global Administrators group and commonly called a super admin. [unified.onboarding:onboarding-roles] Zscaler Global Administrators is the name on [The predefined groups are Dynamic Group Administrators (administrative entitlements), Zscaler Global Administrators (the initial group, with global administrative entitlements), Zscaler Emergency Access (the Private Access emergency access entitlement), Dynamic Group Guest Domains (users from guest domains) and Dynamic Group Registered Domains (users from registered domains). Predefined groups cannot be edited or deleted.](kb:zidentity.groups:predefined-groups), and whether the two names are one group is open [gap:unified.onboarding:global-admins-group-name]. While onboarding to Experience Center for the first time, a super admin can import users via the identity provider (IdP), import user details using a CSV file, or add individual users. [unified.onboarding:add-user-methods]

**Importing from an IdP.** The page says to ensure the IdP is set up for SAML authentication and SCIM provisioning. The connection takes a unique name, a Domain (selected from the domains associated with the Authentication Service account), a Login ID Attribute (the IdP attribute used as the Authentication Service login ID) and a protocol, OIDC (Redirect URI filled in automatically, Client ID, Client Secret, Metadata URL) or SAML (SP Entity ID and SP URL filled in automatically, Metadata URL); for SAML, Fetch next to the Metadata URL box retrieves the metadata and the IdP Entity URL, IdP Single Sign-On URL and IdP Certificate are then displayed. [unified.onboarding:idp-import] Under Provisioning, Generate Token generates a bearer token used by the IdP to connect to Zscaler, or a toggle skips the step and disables SCIM provisioning; the Disconnect <IdP Name> link at the top of the page removes all imported users from Zscaler and cannot be undone. [unified.onboarding:idp-provisioning] The token's lifetime and the list of commonly used IdPs are open [gap:unified.onboarding:idp-token-and-list].

**Uploading a CSV.** The onboarding CSV template's header row is Action, Login Name, Display Name, First Name, Last Name, Primary Email, Secondary Email, Language, Department, Timezone, Password Reset and Group Names. A + row adds a user and needs values in at least Primary Email, Login Name, First Name and Last Name; a - row deletes a user and needs only the Login Name. The first line is retained as the header row, the file name has a .csv extension, each user is on a separate line with an email address whose domain name was defined in the Zscaler Admin Console, the password can be left blank to avoid uploading passwords in clear text, and one-time passwords can let users log in and set passwords. [unified.onboarding:csv-upload] The template's example row puts the group names Group1, Group2 and Group3 after the Password Reset value. [unified.onboarding:csv-example-groups] If the authentication method is a one-time token or one-time link, the Primary Email field must contain a valid email address; the Secondary Email can specify any domain, but it must be a valid email address. [unified.onboarding:csv-email-rules] Whether the Group Names column takes any number of group values, and the file's row limit, are open [gap:unified.onboarding:csv-group-names]. The Authentication Service import page is in [The help says up to 1,000 users can be imported at one time by CSV file, from a template downloaded with Download Sample in the Import User drawer; the header row is retained, the file name has a .csv extension, each user is on a separate line with an email domain defined in the portal, and in the Action column + adds a user (Primary Email, Login Name, First Name and Last Name filled in) and - deletes one (Login Name filled in).](kb:zidentity.users:csv-import-format).

**Adding and editing individually.** Adding a user individually takes the user's first and last name and email address within the organization, and the role to assign; end-user entitlements are viewed at Administration > Entitlements > End User Entitlements and admin entitlements at Administration > Admin Management > Role-Based Access Control > Administrative Entitlements. [unified.onboarding:individual-users] After users are onboarded and before onboarding is completed, their details can be edited (name, email address, or role between End User and Full Admin) or the users deleted; at least one user must be a Full Admin, and deleting or removing admin privileges from the only Full Admin prompts the admin to select a different user to become a Full Admin; individual users imported from an IdP cannot be deleted. [unified.onboarding:editing-users] During onboarding users can only be assigned the Full Admin or End User role; after onboarding is completed any Full Admin can assign users to other admin roles in the Zscaler Admin Console, and user details are updated on the Users page (Administration > Identity > Authentication Service > Users). [unified.onboarding:roles-after-onboarding]

**Step 2: traffic forwarding.** In the traffic forwarding step the admin sends users a link to install Zscaler Client Connector, and users must have administrator permissions on their devices that allow them to install applications; the platforms are selected on the Clients page; if a VPN is in use, its IP addresses and hostnames are entered so that Zscaler ignores traffic to those addresses and the VPN continues to work; and by default users receive automatic software updates to Client Connector, which a toggle disables. [unified.onboarding:traffic-forwarding]

**Step 3: security policies.** The onboarding security policies are URL Filtering (block, isolate or allow internet destinations by URL category), SSL/TLS Inspection (configure what types of SSL/TLS traffic is inspected), Cyber Threat Protection (review additional protection policies for cyber threats such as botnets, phishing and malware), Data Protection (review policies that ensure sensitive data is not inadvertently leaked) and Privacy (configure how users' personally identifiable information (PII) is protected), with Miscellaneous settings to block countries and to add the company logo to banners, emails and user notifications. [unified.onboarding:policy-types] Which categories the recommended URL Filtering, cyber threat and data protection setups use appears only in screenshots [gap:unified.onboarding:default-categories].

**URL Filtering.** The onboarding URL Filtering page shows a recommended setup, and predefined URL categories are dragged to the Block, Isolate or Allow columns: blocked categories cannot be accessed, isolated categories open in a remote browser in a Zscaler data center so no active content from the web page reaches the user's device, and allowed categories open normally within the user's browser. [unified.onboarding:url-filtering] The URL Filtering product page is [ZIA URL Filtering](kb:zia.url-filtering).

**SSL/TLS Inspection.** The SSL/TLS Inspection review step says Zscaler installs its recommended SSL/TLS Inspection policies by default. Separately, the step's Exempted Categories review says the Healthcare and Finance categories are not inspected because they might contain a user's personally identifiable information (PII); categories that are not exempted have their SSL/TLS traffic inspected under All Users, All Other Destinations; and Zscaler's intermediate root certificate is installed under SSL Root Certificate. [unified.onboarding:ssl-defaults] Zscaler's other pages on exempting Healthcare and Finance differ from this review step:[Writing SSL/TLS inspection exemptions without exempting too much](kb:zia.ssl-inspection.exemptions). By default Zscaler inspects SSL/TLS traffic from Microsoft's web-based applications such as OneDrive; Microsoft's recommended setting, which exempts that traffic, is selected as M365 Exempted under Advanced SSL Settings and saved. [unified.onboarding:ssl-m365]

**Cyber threat and data protection.** During onboarding Zscaler sets up its default cyber threat protection policies: Isolation (suspicious URLs not yet categorized, including newly registered URLs, dormant URLs and URLs not yet observed and categorized by Zscaler, open in a remote browser in a Zscaler data center), Botnet Protection, Phishing & Fraud Protection (also blocking adware, spyware, web spam and cryptomining), Malicious Active Content Prevention, P2P File Sharing Protection, Malware Protection (inbound and outbound traffic, HTTP, FTP and FTP over HTTP, using signature-based detection and malware feeds from trusted industry partners) and Zero-Day Attack Protection (zero-day threats isolated and analyzed in a sandbox environment). [unified.onboarding:cyber-defaults] During onboarding Zscaler sets up its default set of data protection policies; the review shows Visibility & Classification (Data Loss Prevention (DLP) dictionaries contain algorithms to inspect user traffic for potential data leakage, such as bank information, PII and sensitive file formats) and the Data Classification Dashboard (high-level visibility and insight into the organization's DLP content). [unified.onboarding:data-protection-defaults] The product subjects are [ZIA Advanced Threat Protection](kb:zia.atp) and [ZIA Data Loss Prevention](kb:zia.dlp).

**Privacy.** On the onboarding privacy page, when the setting to collect device owner information and traffic is enabled, administrators can view user device information (device hostname, device owner and device name) in dashboards, reports or insights; the setting is enabled by default and should be disabled where required by law, such as regions governed by the General Data Protection Regulation (GDPR). [unified.onboarding:device-info-default] On the onboarding privacy page, when Enable automatic crash reporting is enabled the Zscaler service uploads reports of system crashes experienced by users for analysis, which might contain user identifiable information; the page says this setting is disabled by default in compliance with GDPR. [unified.onboarding:crash-reporting-setting] The Client Connector page on crash reporting differs from this [divergence:unified.onboarding:crash-reporting-default]:[The Android app uploads crash reports automatically, and they might contain user-identifiable information; Disable Automatic Crash Reporting stops the uploads, though Zscaler recommends leaving reporting on.](kb:zcc.web-privacy.collection:crash-reports).

**Miscellaneous.** The Miscellaneous page's Block Countries setting can block internet traffic to and from web servers based in specific countries. [unified.onboarding:blocked-countries] What blocking by country does is in [Blocked Countries allows or blocks requests to any country in the world, based on the ISO3166 mapping of countries to their IP address space. Websites are blocked based on the location of the web server.](kb:zia.atp.blocked-countries:web-server-location). The company logo used in application banners, notifications and emails sent to users regarding security issues must be 300 x 220 pixels or less, 10 KB or less, and a PNG, JPG or GIF file; if the logo needs to be edited later, the page points to Administration > Account Management > Branding. [unified.onboarding:onboarding-logo] The limit differs from the other logo pages [gap:unified.onboarding:logo-identity]: [Experience Center account management: organization profile, subscriptions, branding, and Zscaler service in Russia](kb:unified.account-management).

**Finishing.** The final onboarding step displays all the policy configurations the admin selected, each can be changed by clicking the Edit icon to return to that section, and Activate and Launch activates Zscaler with the selected policies and launches the Networking dashboard in the Zscaler Admin Console. [unified.onboarding:review-and-activate] When the initial policy configuration is defined, Activate & Launch enables the selected policies and launches the Zscaler Admin Console, where the Networking dashboard is displayed by default. [unified.onboarding:activate-and-launch]

  - zscaler-help: The Enable automatic crash reporting setting is disabled by default in compliance with GDPR.

  Impact: The default and the recommendation differ between the two pages; neither says the onboarding toggle and the Client Connector option are the same setting, so whether one governs the other is unsettled.
