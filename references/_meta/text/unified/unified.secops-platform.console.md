# The Agentic SecOps Platform admin portal: supported browsers, egress IPs, status board, account settings, failure emails, AI capabilities and audit logs (unified.secops-platform.console)
Also called: Agentic SecOps Platform admin portal; Agentic Security Operations Platform Admin Portal; secops platform account settings; secops platform audit logs

The admin portal is actively tested on the two most recent versions of Safari, Chrome, Edge and Firefox; older versions of these and other browsers are expected to work but are not actively tested. [unified.secops-platform.console:browsers] The sign-in article lists three topics: signing in, accessing the Admin Settings and navigating within the admin portal. [unified.secops-platform.console:signin-article-outline] The platform status board presents historic and current incidents and lets you report issues, subscribe to updates and feeds, see the current status of the admin portal, and view incident history and historical uptime. [unified.secops-platform.console:status-board]

**Egress addresses.** The page says the listed addresses are the source of all egress traffic from the Zscaler tenant for the platform and its applications (e.g. UVM, AEM); the US region lists three /32 addresses, and for the EU region the page points to the Zscaler Hub IP Addresses list. [unified.secops-platform.console:public-ips] The EU entry is worded differently on the Azure Blob connector page [divergence:unified.secops-platform.console:eu-egress-pointer].

**Account settings.** Account Settings > General Settings holds the tenant name and account type, a logo (JPG, GIF or PNG), the organization email domain, and two checkboxes: one lets all admins view private dashboards and reports, the other lets viewers change dashboard-level filters but not save them. [unified.secops-platform.console:account-general] The Authenticate section of Account Settings offers two authentication types for users of the tenant: SAML through an identity provider, or username and password. [unified.secops-platform.console:account-authentication] Single sign-on setup is in [Admin portal SSO: generating SAML details and the Entra ID, Okta, PingOne, PingFederate and SecureAuth setups](kb:unified.secops-platform.console.sso).

**Failure emails.** Failure email notifications are set in the Email Notifications section of Profile Settings and require a role with Edit permission under the Platform - Outegrations resource. [unified.secops-platform.console:failure-email-prerequisite] Failure notifications can be enabled for three alert types: source runs (which fail for causes such as API rate limits, expired or invalid credentials, schema changes or upstream outages), ETL and data pipeline processing (data type mismatches, out-of-range or invalid values), and outegrations (for example expired Jira tokens stopping ticket creation). [unified.secops-platform.console:failure-email-alert-types] Failure notification emails default to Daily and the frequency cannot be modified; the delivery time is set in the admin's local time, and the email goes to the address of the admin who enabled the notifications. [unified.secops-platform.console:failure-email-schedule]

**AI capabilities.** AI capabilities (for example Remediation Copilot and Mapping Copilot) are switched on or off with Enable AI Capabilities in Account Settings, and the change applies at the account level to all users. [unified.secops-platform.console:ai-capabilities-toggle] The page says AI capabilities process data within Zscaler's secured services without using it to train the underlying models and without sending it to external third parties, and that the system attempts to strip PII before processing, so users should still be cautious with sensitive information. [unified.secops-platform.console:ai-capabilities-privacy]

**Audit logs.** Audit logs record user-initiated actions, including changes to grouping rules, severity, score and SLA settings, roles and content permissions, UI configurations, account and user settings, data source mapping, instances and scheduling, outegrations, and dashboards and reports. [unified.secops-platform.console:audit-log-events] Audit logs are retained for 90 days; to extend retention the logs can be exported to an Amazon S3 bucket or any other configured log destination. [unified.secops-platform.console:audit-log-retention] Audit logs are opened from the More menu of a user, account, source, outegration or report configuration page (for SOC Workbench from Settings > Scoring, Severity or UI Config); the Audit Logs page for a user can be filtered and sorted by operation, type and user name and downloaded as CSV. [unified.secops-platform.console:audit-log-page] Audit log export is scheduled in the Audit Logs Export section, reached through Profile menu > Account Settings although the page introduces the steps as being 'for a user', with Enable Scheduling, the entity types to include, a Daily or Hourly frequency and a storage outegration as the destination. [unified.secops-platform.console:audit-log-export] Whether the playbook and rule logs share that retention is open [gap:unified.secops-platform.console:audit-log-retention-scope].

**Open items.** What the sign-in article leaves out is open [gap:unified.secops-platform.console:signin-outline-only]. The account type values are not defined [gap:unified.secops-platform.console:account-type-values].

Sources disagree (name both sides):
- Both pages list the same three US egress addresses, but for the EU the public IP addresses page points to the Zscaler Hub IP Addresses list while the Azure Blob connector page says 'Refer to the Zscaler Config.' [divergence:unified.secops-platform.console:eu-egress-pointer]
  - zscaler-help: The EU addresses are the recommended IP addresses listed in Zscaler Hub IP Addresses.
  - zscaler-help: The EU addresses are found by referring to the Zscaler Config.
  Impact: It is unclear whether the two pages point to the same EU address list; an allowlist for the EU region should not rest on either wording alone.
