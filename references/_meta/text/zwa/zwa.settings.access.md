# Workflow Automation access: roles and permissions, admin assignments, approvers and integration users (zwa.settings.access)
Also called: zwa roles; admin assignment; restricted workflow access; DLP Super Admin; DLP Incident Manager; integration users

Admins are provisioned in the Zscaler Admin Console with full or restricted workflow access; an admin assignment defines the incident group permissions of a restricted-access admin, only full-access admins can add assignments, and a restricted admin must have an assignment before managing incidents on the Incidents page. [zwa.settings.access:full-vs-restricted] What full access means across the roles and assignments pages is open [gap:zwa.settings.access:full-access-meaning]. The account-wide settings are in [Workflow Automation account settings: notification expiry, digests and reminders, approver domains, user data source, obfuscation and quarantine release](kb:zwa.settings).

**Roles.** A role sets, per Workflow Automation feature, one of Delete, Edit, View or None; Delete is available only for the Incidents feature, is the highest permission and includes edit and delete, and View gives no ability to edit data. [zwa.settings.access:permission-levels] The Roles page provides the default roles DLP Super Admin, DLP Admin and DLP Incident Manager, which cannot be edited or deleted; admins with full access can create more roles. DLP Super Admin has full access (i.e., edit access) to all DLP incident features and can also delete incidents; DLP Admin has full access to all DLP incident-related features except Audit Logs, API Management and Integrations; DLP Incident Manager has full access to incident-management features such as viewing incident details and notifying users, as well as adding approvers. [zwa.settings.access:default-roles] Only admins with full access to Workflow Automation can configure roles and assign them to restricted-workflow-access admins; multiple roles can be assigned to one admin; with an Authentication Service subscription roles are assigned only from Authentication Service; the Product of a role is DLP by default and cannot be changed. [zwa.settings.access:role-assignment-rules] A role sets permissions for these categories: Analytics, Incidents, Workflows and Mappings, Workflow Templates, Incident Group and Mappings, Priorities, Notification Templates, Survey Templates, Template Mappings, API Management, Audit Logs, Labels, Integrations, Account Settings, Notification Center and Approvers. [zwa.settings.access:permission-categories] Which admin role gets API Management by default is open [gap:zwa.settings.access:admin-role-api-management].

**Admin assignments.** Before adding an admin assignment, the restricted admins must be provisioned in the Zscaler Admin Console, incident groups configured and mapped, DLP admin digest templates configured and mapped, the digest flags and obfuscation settings configured, and roles and permissions configured. [zwa.settings.access:assignment-prerequisites] Admin assignments also define the DLP admin digest notification settings and the user data obfuscation settings for both full and restricted admins, and the data privacy settings (generate presigned links, see trigger data) for restricted admins. [zwa.settings.access:assignment-settings] A restricted admin is given edit access (can act on incidents) and view access (can only view) per incident group; a full-access admin can have edit access to specific groups or All and has no View field. [zwa.settings.access:assignment-incident-groups] The Auto Assign Incidents setting of an admin assignment is enabled by default; when it is not enabled the admin is not automatically assigned incidents, and incidents of an incident group are automatically assigned to the restricted admins with edit access to that group. [zwa.settings.access:assignment-auto-assign] In an admin assignment the digest channels are Email, Slack and Teams, limited to the channels enabled on Account Settings; priorities are Critical, High, Medium and Low; frequencies are Hourly, Daily and Weekly; and if the digest is enabled, channel, priority and frequency must all be selected. [zwa.settings.access:assignment-digest-fields]

**Privacy overrides.** Data privacy overrides, available only for restricted admins and defaulting to the organization settings, are Hide Evidence Data (blocks generating presigned links to violation content on Incident Details) and Hide Trigger Data (blocks seeing trigger data); Hide Evidence Data takes precedence over the DLP application integration Hide Evidence Data - Admin setting and Hide Trigger Data over the Hide Trigger Data - Admin setting. [zwa.settings.access:assignment-data-privacy] An admin assignment can override the organization's obfuscation settings for that admin, choosing from User Name, User Email, Recipient Email, Manager Name, Client IP, Manager Email, Device Name, Phone Number and Trigger Data, or Obfuscate All, and Recipient Email covers the External, Internal and Triggered Recipients attributes. [zwa.settings.access:assignment-obfuscation-override] The Notification Time Zone of an admin assignment is optional and sets the time zone for time-related merge tags in that admin's notifications, where the Time merge tag is the time the incident occurred; a restricted admin must log out and log in again to see added assignments. [zwa.settings.access:assignment-time-zone-and-visibility]

**Approvers.** Approvers, each with a Name and an Email, are configured by admins with access to Workflow Automation; an incident can be escalated to an approver for review and response, and an approver can be anyone, such as the end user's manager. [zwa.settings.access:approvers]

**Integration users.** Integration users are required to integrate with a ticketing application such as ServiceNow or Jira Software: the ticket action on Incident Details creates and assigns a ticket in that application to a user chosen from those already on the Integration Users page, and the ticket information then shows in the Ticket section. [zwa.settings.access:integration-users-purpose] An integration user is added by selecting the tenant ID of the ticketing integration and entering an email address, and only users available in the selected ticketing integration application can be added; the integration types are ServiceNow and JiraCloud. [zwa.settings.access:integration-users-fields]
