# Incident groups, group mappings (properties, operations, rule order, default group) and priorities (zwa.incidents.group-mapping)
Also called: incident group mapping; zwa mapping properties; zwa mapping operations; default incident group; zwa priorities; CONTAINS_EXACT; matchingPolicies.rules

Admins with Full or Restricted access to Workflow Automation can add incident groups, but only admins with Full access can map them. [zwa.incidents.group-mapping:group-access] A mapped incident group can be deleted only after its incident group mappings have been deleted. [zwa.incidents.group-mapping:group-delete-order] The groups an incident is assigned and how its priority follows from them are in [Workflow Automation incidents: where they come from, who gets them, statuses, search limits and closing or deleting](kb:zwa.incidents).

**Priorities.** An incident group can be assigned a priority of critical, high, medium or low, and incident groups must be added before priorities are managed. [zwa.incidents.group-mapping:priority-values] On the Priorities page, changing the incident group on a priority row removes the priority from the previous incident group and adds it to the new one. [zwa.incidents.group-mapping:priority-change-group]

**Mapping access.** Only admins with full access to Workflow Automation can map incident groups, and incident groups are then assigned to restricted-access admins on the Admin Assignment page. [zwa.incidents.group-mapping:mapping-access]

**Mapping properties.** The Source DLP type choices for an incident group mapping are Any, Email, Endpoint, Inline and SaaS Security; Any appears by default. [zwa.incidents.group-mapping:mapping-source-type] All attributes in an incident transaction are available as mapping properties; the selectable properties vary with the Source DLP type chosen, and a property can be a number, string, date or Boolean. [zwa.incidents.group-mapping:property-types] User attributes chosen for obfuscation cannot be used as mapping properties, and a user with obfuscation enabled cannot edit existing mappings that were created using an obfuscation field. [zwa.incidents.group-mapping:mapping-obfuscation] Several User Info mapping properties exist only when CSV is selected as the primary user data source on the Account Settings page: Home Country, Job Title, Location, Organization Hierarchy, Phone Number, Project IDs, Termination Date, User Role, Worker Type, and the Skip Level Managers properties. [zwa.incidents.group-mapping:csv-only-properties] Mapping properties with a stated Source DLP type scope: Client IP and Protocol are available only for Inline; Device Name, Device OS, Device Trust Level and the Endpoint Info properties only for Endpoint; the Application Info properties only for Inline, SaaS Security and Email; Severity is not available for Email. [zwa.incidents.group-mapping:source-scoped-properties]

**Operations and predicates.** Mapping operations are tied to property types: AFTER and BEFORE to Date; CONTAINS_EXACT and NOT_CONTAINS_EXACT to Array of strings, Number and Boolean; EQUALS and NOT_EQUALS to String, Number and Date; IN_IPv4_SUBNET and IN_IPv6_SUBNET to IP Address; LIKE to String; LESS_THAN and GREATER_THAN to Number; EXISTS to all types. [zwa.incidents.group-mapping:operations-by-type] LIKE does a partial substring comparison; EXISTS takes no property value; the CONTAINS example maps incidents that violated several rules including Block-HIPAA-SSN to one group using matchingPolicies.rules[*].name with CONTAINS_EXACT. [zwa.incidents.group-mapping:operation-semantics] A new predicate row is added with the AND function selected; OR or AND can be chosen when another predicate is added, and NOT can be selected. [zwa.incidents.group-mapping:predicate-functions] A mapping statement can hold up to 100 predicates. [zwa.incidents.group-mapping:predicate-limit] What NOT, EXISTS and LIKE do beyond that is open [gap:zwa.incidents.group-mapping:operation-details].

**Rule order.** Rules equate to statements; all rules are processed for an incident transaction, so a transaction matching several rules can be assigned to multiple incident groups, and the order of rules is set with the up and down arrows. [zwa.incidents.group-mapping:rule-processing] When no other incident group mapping matches an incident, Workflow Automation uses the default incident group. [zwa.incidents.group-mapping:default-group]

What to check:
1. Whether an admin who cannot map incident groups has Full access to Workflow Automation, since only Full access maps them.
2. Whether an incident group still has mappings before deleting it.
3. Whether a mapping property is CSV-only or scoped to a Source DLP type when it is missing from the property list.

Not known (open gaps):
- What NOT does to an operation, how EXISTS treats an empty array, and whether LIKE is case sensitive [gap:zwa.incidents.group-mapping:operation-details]: settled by lab-test or source-read
