# Incidents-page filters, the Incident Summary page and duplicate incidents (zwa.incidents.filters-summary)
Also called: zwa incident filters; incident summary; duplicate incidents; summary criteria; zwa saved criteria

On the Incidents page, some filters take predefined values (for example Duplicated Incidents) and others require a text string (for example Remediation Owner Email and Hostname or Application). [zwa.incidents.filters-summary:filter-kinds] Text-string filters are not case sensitive; commas separate multiple values, several words in one value are ANDed, and the URL and Referrer URL filters take a complete URL or host name. [zwa.incidents.filters-summary:filter-text-ops] Triggered Dictionary Matches and Total Dictionary Matches take an operator (>, ≥, <, ≤ or =) and a number of matches. [zwa.incidents.filters-summary:filter-match-count] If User Name, Client IP or Recipient Email is chosen for obfuscation, incidents cannot be filtered using those obfuscated attributes, and obfuscating Recipient Email disables the External Recipients, Internal Recipients and Triggered Recipients filters. [zwa.incidents.filters-summary:filter-obfuscation] Search and date range on the Incidents page are in [Workflow Automation incidents: where they come from, who gets them, statuses, search limits and closing or deleting](kb:zwa.incidents).

**Duplicate incidents.** A duplicate incident occurs when a user violates the same DLP rule multiple times within two hours, and only Inline incidents are tracked for duplicates, not SaaS Security, Email or Endpoint. [zwa.incidents.filters-summary:duplicate-window] Duplicates are judged on host name from URL, end user email, MD5 hash of the content and file name, all of which must be present; for DLP rules without content inspection (Engines attribute External DLP) the MD5 need not be present. [zwa.incidents.filters-summary:duplicate-attributes] Workflow Automation looks back only two hours, so a site such as Gmail that keeps sending duplicates until the page is refreshed or the tab closed produces a new duplicate incident every two hours. [zwa.incidents.filters-summary:duplicate-lookback] The Incidents page shows the total count of duplicate incidents for an incident and can filter by duplicate incidents. [zwa.incidents.filters-summary:duplicate-ui] Whether the window rolls from the first or latest duplicate is open [gap:zwa.incidents.filters-summary:duplicate-window-rolling]. The drawer's duplicate dialog is in [The Incident Details drawer: fields by Source DLP type, actions and status changes, quarantine release errors, tickets and privacy gates](kb:zwa.incidents.details).

**Incident Summary page.** The Incident Summary page starts empty, takes the same filters as the Incidents page, allows at most two summary criteria, and can group counts by Priority or Severity. [zwa.incidents.filters-summary:summary-criteria-limit] The Attachments summary criterion has values Yes and No; Source DLP Type values are Inline, Email, Endpoint and SaaS Security. [zwa.incidents.filters-summary:summary-criteria-values] The summary table shows up to 10,000 rows with a Total column and priority or severity columns: Critical appears only when grouped by priority and Info only when grouped by severity. [zwa.incidents.filters-summary:summary-table] The Incident Summary page defaults to the current calendar week (Sunday through Saturday) and offers hour, day, week, month and custom ranges; the custom range supports incidents up to 6 months old within a three-month window. [zwa.incidents.filters-summary:summary-time-range] The summary table exports to CSV; saved summary criteria can be set as default, and a second criterion can be added to a saved set only if one criterion is already saved. [zwa.incidents.filters-summary:summary-export-saved] The Incident Summary page offers 10, 20, 25, 50 or 100 items per page, defaulting to 10; the Selected Criteria page opened from a count is similar to the Incidents page except that no action can be taken on an incident. [zwa.incidents.filters-summary:summary-paging]

What to check:
1. Whether an incident that seems not to have a duplicate is outside the Inline Source DLP type or missing one of the attributes duplicates are judged on.
2. Whether a filter that cannot be used is on an attribute chosen for obfuscation.

Not known (open gaps):
- Whether the two-hour duplicate window rolls from the first or the latest duplicate [gap:zwa.incidents.filters-summary:duplicate-window-rolling]: settled by lab-test or source-read
