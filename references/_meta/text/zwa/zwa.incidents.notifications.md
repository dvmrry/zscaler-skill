# User, escalation and digest notifications and reminders as the recipient sees them: contents, link lifetime, privacy gates, quarantine release and policy exceptions (zwa.incidents.notifications)
Also called: zwa user notification; zwa escalation notification; zwa digest notification; notification reminders; incident detail link; justification survey; dlp admin digest

A user or escalation notification carries the incident time, an Incident Detail Link, the incident ID, hostname or application, priority, and the admin's note only if one was entered. [zwa.incidents.notifications:notification-contents] The end user, escalation, user digest and DLP admin digest notification pages each say the incident link is only valid for 24 hours. [zwa.incidents.notifications:link-24h] The link lifetime differs between pages [divergence:zwa.incidents.notifications:link-lifetime]. Notification emails might be tagged as spam and land in the recipient's spam folder, depending on their email settings. [zwa.incidents.notifications:spam-folder] The admin actions that send them are in [The Incident Details drawer: fields by Source DLP type, actions and status changes, quarantine release errors, tickets and privacy gates](kb:zwa.incidents.details).

**Escalation.** An escalation notification goes to a manager or approver; an incident can be escalated when the end user's justification is not acceptable or the incident is of high severity and priority, and if the organization accepts the justification the manager or approver is not notified. [zwa.incidents.notifications:escalation-trigger] In an escalation notification, the Notification Response History table logs notifications to the originating user and escalations to the manager or approver, with roles Originating User, Manager or Approver. [zwa.incidents.notifications:response-history]

**Survey.** The notification survey's Justification Type is False Positive, Manager Approved or Others, with a free-text Justification Reason. [zwa.incidents.notifications:survey-types] A policy exception section appears in end user and escalation notifications only when generated through a custom workflow with a policy exception tile, and only for incidents of Source DLP type Inline; approving takes a duration in minutes and creates a subrule that applies only to the incident's user. [zwa.incidents.notifications:survey-policy-exception] The source DLP types the policy exception covers differ between pages [divergence:zwa.incidents.notifications:policy-exception-source-types].

**Privacy and Email incidents.** In an end user notification the presigned evidence link needs Hide Evidence Data - End User unselected, and the field that displays the trigger data needs Hide Trigger Data - End User unselected, on the AWS, Azure and GCP DLP integration pages. [zwa.incidents.notifications:end-user-privacy-flags] Which flags gate a manager's or approver's evidence link and trigger data in an escalation notification differs between pages [divergence:zwa.incidents.notifications:escalation-privacy-flags]. In the user digest justify flow the evidence link depends on Hide Evidence Data - End User, and in the approve flow on Hide Evidence Data - Manager/Approver being unselected. [zwa.incidents.notifications:digest-approver-privacy-flags] The Release Email to Recipients section in user and escalation notifications appears only for Email incidents with a quarantine action when the option these pages name Enable Email Quarantine Release for End Users is on; Do not release is selected by default. [zwa.incidents.notifications:email-quarantine-release] On the end user notification page the Overview Severity field is not available for Email incidents and the Policy section is only available for Email incidents, and the user digest page says the Generate Presigned Link field is not available for Email incidents. [zwa.incidents.notifications:email-na-fields] The settings behind these flags are in [Workflow Automation integrations: DLP GCP privacy settings, Slack, Microsoft Teams, ServiceNow and Jira Software](kb:zwa.incidents.integrations). Which flag gates the approver's trigger data in the digest is not settled [gap:zwa.incidents.notifications:approver-trigger-gate].

**Reminders.** Notification reminders must be configured on the Account Settings page (enable, frequency, maximum number) before they are sent, and are identical to the original notifications. [zwa.incidents.notifications:reminders-config] Reminders stop after a response to the original or a reminder notification or once the configured maximum has been sent; when reminders are sent the system updates the Number of Attempts information and logs the reminder activity on the State Changes tab. [zwa.incidents.notifications:reminders-stop-log] The interval and maximum ranges are in [Workflow Automation account settings: notification expiry, digests and reminders, approver domains, user data source, obfuscation and quarantine release](kb:zwa.settings). The default frequency and maximum are not stated [gap:zwa.incidents.notifications:reminder-defaults].

**Digests.** The user digest page says that when a channel is enabled for the User Digest notification flags on Account Settings, a digest template is used to send a user digest daily to all users with assigned incidents; default templates are Digest - Email, Slack and Teams, and the default digests list the number of open incidents and of open high-priority incidents. [zwa.incidents.notifications:user-digest] The digest frequency differs between pages [divergence:zwa.incidents.notifications:user-digest-frequency]. The user digest page's incident list shows New, Investigating, Validating with User, Justification Response Received (the label this page uses) and Escalated incidents with Justify or Approve actions; the counts are accurate only as of generation time. [zwa.incidents.notifications:user-digest-incidents] A DLP admin digest needs DLP Admin Digest Notification Flags enabled on Account Settings and the admin's digest frequency, channel and priority set on what this page calls the Admins page; default templates are DLP Admin Digest - Email, Slack and Teams, and the default digests list the number of new incidents, of open incidents and of state changes. [zwa.incidents.notifications:admin-digest] The DLP admin digest default frequency and the send time are not stated [gap:zwa.incidents.notifications:digest-defaults].

What to check:
1. Whether a notification link that has expired is the reason a recipient cannot open the incident, against both the 24 hours the notification pages state and the expiration period set on Account Settings.
2. Whether a missing notification email is in the recipient's spam folder.
3. Whether an end user's missing evidence link or trigger data follows from the Hide Evidence Data - End User and Hide Trigger Data - End User settings.
4. Whether a manager's or approver's missing evidence link or trigger data follows from the Manager/Approver or the End User flags, which the pages disagree on.

Sources disagree (name both sides):
- The notification pages say the incident link is only valid for 24 hours, while Account Settings sets a justification link expiration period in days that defaults to one day and has a maximum of 30. [divergence:zwa.incidents.notifications:link-lifetime]
  - zscaler-help: The link is only valid for 24 hours.
  - zscaler-help: The expiration period defaults to one day and can be set up to 30 days.
  Impact: A tenant with an expiration period longer than one day may have links that stay valid past 24 hours, so 24 hours is not a safe test of an expired link.
- The end user notification page says the policy exception section is only available for Source DLP type Inline, while the custom workflow page supports Policy Exception tiles for Inline and Email. [divergence:zwa.incidents.notifications:policy-exception-source-types]
  - zscaler-help: The policy exception section is only available for incidents of Source DLP type Inline.
  - zscaler-help: Policy Exception tiles are supported for Source DLP types Inline and Email.
  Impact: Whether an Email incident's notification carries the policy exception section is not settled between the pages.
- The escalation notification page gates the evidence link on Hide Evidence Data - End User, while the AWS integration page assigns approvers and managers responding to an escalation notification the Manager/Approver flags. [divergence:zwa.incidents.notifications:escalation-privacy-flags]
  - zscaler-help: In an escalation notification the evidence link depends on Hide Evidence Data - End User; the trigger data field likewise depends on Hide Trigger Data - End User.
  - zscaler-help: Hide Evidence Data - Manager/Approver governs presigned evidence links for approvers and managers responding to an escalation notification.
  Impact: For a manager or approver, which Hide flag (End User or Manager/Approver) explains a missing evidence link or trigger data is not settled.
- The user digest page says the digest is sent daily, while Account Settings offers Hourly, Daily and Weekly frequencies with daily as the default. [divergence:zwa.incidents.notifications:user-digest-frequency]
  - zscaler-help: The user digest is sent daily.
  - zscaler-help: The digest frequency is Hourly, Daily or Weekly, and daily if none is entered.
  Impact: A user digest that arrives hourly or weekly is consistent with Account Settings but not with the digest page's daily wording.

Not known (open gaps):
- Which flag gates the approver's View Trigger Data in the user digest approve flow [gap:zwa.incidents.notifications:approver-trigger-gate]: settled by lab-test or source-read
- Default frequency and maximum for notification reminders [gap:zwa.incidents.notifications:reminder-defaults]: settled by lab-test or source-read
- Default frequency of the DLP admin digest and send time of the daily user digest [gap:zwa.incidents.notifications:digest-defaults]: settled by lab-test or source-read
