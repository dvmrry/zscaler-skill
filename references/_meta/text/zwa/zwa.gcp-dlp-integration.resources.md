# GCP resources for the DLP integration: Deployment Manager end of support, permissions, prefix, KMS, retention, buckets, Pub/Sub and service account roles (zwa.gcp-dlp-integration.resources)

**Deployment.** The page says Google is discontinuing support for Google Cloud Deployment Manager on March 31, 2026, after which the cloud resources must be created manually, and that Zscaler is in the process of defining a replacement process. [zwa.gcp-dlp-integration.resources:deployment-manager-eol] On the Deployment Manager stack path only (the page's section on creating cloud resources with a DLP GCP integration cloud resource stack), the deployment needs editor, resource manager and pubsub admin permissions on the storage accounts used; editor is held by default, and the missing resource manager and pubsub admin permissions are granted to <PROJECT_NUMBER>@cloudservices.gserviceaccount.com as roles/resourcemanager.projectIamAdmin and roles/pubsub.admin. [zwa.gcp-dlp-integration.resources:deployment-permissions] The replacement process is open [gap:zwa.gcp-dlp-integration.resources:deployment-replacement].

**Names and encryption.** The prefix identifies the created resources and cannot contain dots; the derived variables (marked 'no need to change these') give the service account zscaler-sa-${PREFIX}, buckets ${PREFIX}-data and ${PREFIX}-metadata, and the Pub/Sub topic ${PREFIX}-file-events-topic. [zwa.gcp-dlp-integration.resources:prefix-and-names] On the Deployment Manager stack path, buckets use Google-managed encryption by default; a customer-managed KMS key can be supplied as kms_key in the format projects/my-project/locations/us-central1/keyRings/my-key-ring/cryptoKeys/my-key, and with your own KMS key the kms keys add-iam-policy-binding command must be run before creating the deployment or the deployment fails. [zwa.gcp-dlp-integration.resources:kms-key] The page's Deployment Manager KMS binding command is printed as gcloud kms keys add-iam-policy-binding <KEY_NAME> --location <LOCATION> --keyring --member ... with no value after --keyring and no --role, and its own example (--keyring zwa-key-ring) also gives no --role; a command copied as printed is incomplete. [zwa.gcp-dlp-integration.resources:kms-binding-command-incomplete] In the manual procedure the optional customer-managed KMS key is applied to each bucket with gcloud storage buckets update and --default-kms-key="${KMS_KEY}", with KMS_KEY the full key resource name. [zwa.gcp-dlp-integration.resources:manual-kms-key]

**Buckets and notifications.** In the manual procedure the data bucket is configured with versioning, uniform access control, and optional retention policies and KMS encryption; the page's intro line for the metadata bucket names only its own optional retention policy, but the metadata bucket's steps also set versioning and the optional KMS key, as for the data bucket. [zwa.gcp-dlp-integration.resources:data-bucket-settings] The deployment command can optionally take retention_period_data and retention_period_metadata (in days) to manage the lifecycle of the data and metadata buckets; for the data bucket in the console this is a lifecycle rule with the action Delete and an Age condition in days. [zwa.gcp-dlp-integration.resources:retention-period] In the manual procedure the Pub/Sub topic receives notifications when new objects are uploaded to the metadata bucket; the GCS service account is granted roles/pubsub.publisher on the topic, and the metadata bucket notification uses event type Object finalization (OBJECT_FINALIZE) with payload format JSON API v1. [zwa.gcp-dlp-integration.resources:pubsub-notification]

**Service account.** In the manual procedure the Zscaler service account is granted Storage Object Viewer and Storage Legacy Bucket Reader on both the data and metadata buckets (both roles on each bucket), Pub/Sub Editor on the project, and Service Account User on itself. [zwa.gcp-dlp-integration.resources:service-account-roles] A private key is created for the newly created service account as a JSON key, and a file with the key values is downloaded; those values are required when creating the DLP GCP integration in the Zscaler Admin Console. [zwa.gcp-dlp-integration.resources:service-account-key] The expiry of the JSON key is open [gap:zwa.gcp-dlp-integration.resources:key-expiry].

The integration object is in [The GCP DLP application integration for Workflow Automation: Cloud-to-Cloud only, fields, validation and privacy settings](kb:zwa.gcp-dlp-integration).

What to check:
1. Whether the cloud resources are created manually, given the Deployment Manager end of support.
2. Which path created the resources: on the Deployment Manager stack path with a customer-managed KMS key, whether the kms keys add-iam-policy-binding command was run before the deployment; on the manual path, whether --default-kms-key was set on each bucket.
3. On the manual path, whether the service account holds both Storage Object Viewer and Storage Legacy Bucket Reader on each of the data and metadata buckets.
