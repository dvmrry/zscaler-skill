# Workflow Automation workflows: the nine templates, custom workflows, mappings and what the API does not cover (zwa.workflows)
Also called: zwa workflow; workflow templates; workflow mapping; auto notify; auto escalate; auto close incident; zwa automation api

Admins remediate incidents either manually from the Incidents and Incident Details pages (for example investigate, notify user, escalate, create ticket, close) or through predefined and custom workflows that automatically perform actions such as notify user, escalate, create ticket and close incident, and can use both. [zwa.workflows:manual-or-automatic] Users, managers and approvers respond to actions a workflow generates in the same way as to the same actions performed manually. [zwa.workflows:same-responses]

**Templates.** A predefined workflow is based on one of nine templates: Auto Close Data Protection Incident With Resolution Label, Auto Close Data Protection Incident (both set the status to Resolved, the first adding a resolution label), Auto Create Tickets (in a ticketing integration such as ServiceNow or Jira Software), Auto Escalate (to the user's manager, or an approver if no manager is found), Auto Notify (through email, Slack or Microsoft Teams), and four notify variants: notify and close if the user does not respond within a configured number of seconds, notify and escalate concurrently without waiting, notify then escalate to the manager or approver after a configured time, and notify then optionally escalate to the manager after a configured time. [zwa.workflows:predefined-templates] The Workflow Templates page lists each template with its name, description and Counts, the number of workflow definitions created from it; that page says adding a workflow for your organization requires selecting one of the provided templates. [zwa.workflows:templates-counts] The Workflow Templates page and the custom workflow description differ on whether a template is required [divergence:zwa.workflows:template-required]. The Add Workflow procedure for the resolution label template names it Auto Close Data Loss Protection Incident With Resolution Label, and its Workflow Template field defaults to that name. [zwa.workflows:resolution-label-template-name] The Notification Channel fields of workflow templates appear only if Workflow Automation is integrated with Slack or Microsoft Teams; otherwise notifications are by email. [zwa.workflows:channel-fields-conditional]

**Predefined workflow fields.** The Auto Notify User and Close Incident template waits a configured number of seconds for the user response before closing the incident; Auto Notify User and Escalate waits before escalating to the manager and approver; Auto Notify User and Escalate to Manager waits before escalating to the manager. [zwa.workflows:predefined-wait-times] The Auto Create Tickets workflow offers the ticketing services JiraCloud and ServiceNow; choosing JiraCloud shows a Jira Project field filled from the projects Workflow Automation fetches at Jira Software onboarding; the default ticket assignee must have been added to the Integration Users. [zwa.workflows:predefined-ticketing] When closing an incident, a workflow can associate only one resolution label value with a resolution label name, and the Resolution Label Value field becomes available only if the selected label has configured values. [zwa.workflows:predefined-resolution-label] In the Auto Escalate, Auto Notify User and Concurrently Escalate and Auto Notify User and Escalate templates the approver chosen must already exist on the Approvers page. [zwa.workflows:predefined-escalation-approver] For the Auto Escalate, Auto Notify, Auto Notify User and Close Incident, Auto Notify User and Concurrently Escalate, Auto Notify User and Escalate and Auto Notify User and Escalate to Manager templates, the languages offered depend on the mapped templates, and a language not available in a mapped template set makes Workflow Automation default the notifications to English. [zwa.workflows:predefined-language-fallback] When a predefined workflow is edited, the workflow detail fields can be changed except the Workflow Template field, and the changes apply to future incidents mapped to the workflow without affecting current workflow executions; a workflow is deleted with the Delete icon in the Action column next to it on the Workflows page. [zwa.workflows:edit-and-delete-rules]

**Custom workflows and mappings.** A custom workflow is built by choosing and configuring its steps and actions without a template. [zwa.workflows:custom] After configuring a predefined or custom workflow, the admin must map it to one or more incident transaction attributes; the workflow then triggers automatically for incidents with those attributes. [zwa.workflows:mapping-required] Only admins with full access to Workflow Automation can map a workflow, from either the Workflows page or the Workflow Mappings page. [zwa.workflows:mapping-permission] What full access means here is open [gap:zwa.workflows:full-access-meaning]. The custom builder is in [The Workflow Automation custom workflow builder (Beta): tiles, connection rules, time zones, justification conditions and publishing](kb:zwa.workflows.custom-builder) and the mapping statements in [Workflow Automation workflow mappings: statement order, Source DLP types, properties, operations and predicates](kb:zwa.workflows.mappings).

**Status and cloning.** A workflow has status Draft or Published; only custom workflows can be Draft, only published custom workflows are used for incident remediation, and a custom workflow must be Published before it can be mapped. [zwa.workflows:status-draft-published] Only custom workflows, draft or published, can be cloned. [zwa.workflows:clone-rules]

**Programmability.** The Workflow Automation API reference groups its operations under DLP Incidents, API Authentication, Audit Logs, CSV User Attributes and Email Quarantine. [zwa.workflows:api-tags] No captured API or SDK configures workflows, templates or mappings: the API reference has no workflow group, and the Python and Go SDKs expose only DLP incident and audit log services. [zwa.workflows:no-workflow-api] Whether workflows can be configured through any API is open [gap:zwa.workflows:workflow-api].
