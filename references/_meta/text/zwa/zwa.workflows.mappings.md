# Workflow Automation workflow mappings: statement order, Source DLP types, properties, operations and predicates (zwa.workflows.mappings)
Also called: workflow mapping statements; mapping rules; CONTAINS_EXACT; IN_IPv4_SUBNET; mapping predicates

Only admins with full access to Workflow Automation can map workflows, and workflows must have been added before they can be mapped. [zwa.workflows.mappings:permission-and-prereq] The workflows themselves are in [Workflow Automation workflows: the nine templates, custom workflows, mappings and what the API does not cover](kb:zwa.workflows) and [The Workflow Automation custom workflow builder (Beta): tiles, connection rules, time zones, justification conditions and publishing](kb:zwa.workflows.custom-builder).

**Evaluation.** Mapping statements are evaluated in the order configured and the first matching statement is used; if none matches an incident no workflow is triggered automatically, and statements can be reordered with the up and down arrows, processing stopping at the first match. [zwa.workflows.mappings:evaluation-order] A mapping statement is scoped to a Source DLP type of Any, Email, Endpoint, Inline or SaaS Security, with Any selected by default. [zwa.workflows.mappings:source-dlp-types] A statement can have up to 100 predicates. [zwa.workflows.mappings:predicate-limit] Adding a predicate to a condition selects the AND function automatically, and the functions are NOT, OR and AND; an advanced mapping shows multiple nested conditions. [zwa.workflows.mappings:predicate-functions]

**Properties.** All attributes in an incident transaction are available as properties, varying with the selected DLP type; a property can be a number, string, date or Boolean, though the operations table also uses Array of strings and IP Address property types, and some properties offer values for the organization filtered by DLP type (for example Severity, Source Actions, Matching Policies.Rules[*].name). [zwa.workflows.mappings:property-types] A workflow cannot be mapped to obfuscated attributes, and a user with workflow mapping permissions who has obfuscation enabled cannot edit existing mappings that were created with an obfuscated field. [zwa.workflows.mappings:obfuscated-properties] Some mapping properties exist only for particular Source DLP types: Application Info for Inline, SaaS Security and Email; Endpoint Info for Endpoint; Protocol for Inline; Severity not for Email; Client IP for Inline; Device Name, Device OS and Device Trust Level for Endpoint. [zwa.workflows.mappings:property-availability-by-type] These user properties are available for mapping only if CSV is the primary user data source on Account Settings: Home Country, Job Title, Location, Organization Hierarchy, Phone Number, Project IDs, Termination Date, User Role, Worker Type and the Skip Level Managers properties. [zwa.workflows.mappings:property-availability-csv] The property list shows Is Copilot Accessible under the SaaS Security Source DLP Type group and ZDP Mode under the Endpoint Source DLP Type group. [zwa.workflows.mappings:property-list-by-type] The full per-type property table is not restated [gap:zwa.workflows.mappings:property-list].

**Operations.** EQUALS and NOT_EQUALS apply to string, number and date properties and are not case sensitive; LIKE applies to string properties and does a partial substring comparison; EXISTS applies to all property types and takes no property value. [zwa.workflows.mappings:op-equals-like-exists] CONTAINS_EXACT (for array of strings, number and Boolean properties) matches when the property contains the exact full value entered, with no partial comparison and without case sensitivity, and suits multi-valued properties such as matchingPolicies.rules[*].name; NOT_CONTAINS_EXACT is its negation for the same property types. [zwa.workflows.mappings:op-contains-exact] AFTER and BEFORE apply to date properties, LESS_THAN and GREATER_THAN to number properties, and IN_IPv4_SUBNET and IN_IPv6_SUBNET to IP address properties. [zwa.workflows.mappings:op-date-number-ip]
