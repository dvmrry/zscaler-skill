# What the user sees in isolation: experience modes, menus, Original URL, bookmarks, mobile, translation, read-only and extensions (zbi.end-user-experience)
Also called: Native Browser Experience; Browser-in-Browser Experience; Zero Trust Mode menu; isolation right-click menu; Original URL isolation; read-only isolation; isolation language translation; isolation multiple sessions; isolation mobile

**Experience modes.** Admins select the isolation experience per isolation profile, in both Internet & SaaS and Private Access profiles, from two options: Native Browser Experience and Browser-in-Browser Experience. [zbi.end-user-experience:two-modes] In Native Browser Experience the Zero Trust Mode menu and other session controls are hidden by default but remain reachable through the checkmark Zero Trust Mode icon, and features such as tab affinity are disabled by default but still accessible. [zbi.end-user-experience:native-menu-hidden] Zscaler distinguishes Native Browser Experience from Original URL: in Native Browser Experience the entire isolation container is hidden, not just the isolation URL, and the user does not leave isolation, whereas Original URL essentially means leaving isolation completely. [zbi.end-user-experience:native-vs-original-url] In Browser-in-Browser Experience the isolation URL can be copied, reloaded and manually edited, and the editable URL bar lets the user browse to a page of their choice if the defined policy allows it. [zbi.end-user-experience:bib-url-bar-editable] In Browser-in-Browser Experience each native browser tab maps to a tab on the isolation browser, and tabs opened for one isolation session cannot be carried to a separate browser window. [zbi.end-user-experience:bib-tab-affinity] Browser-in-Browser Experience is not available if the admin selects Original URL in the Security settings during profile configuration. [zbi.end-user-experience:bib-not-with-original-url]

**Menus.** The Zero Trust Mode menu gives access to pinned and supported browser extensions, Protected Storage (file transfers for the session), a Clipboard icon for clipboard notifications and restrictions, Print, Troubleshoot (debug session, network latency and session logs, ip.zscaler.com) and Information (settings configured by the admin, with a Restricted Actions list); the default Native Browser Experience setting hides the menu. [zbi.end-user-experience:zero-trust-mode-menu] The isolation right-click menu is available in both experience modes; a custom right-click menu offered by the web application replaces the default isolation menu, and when printing is disabled for the profile the print option is absent and a message says it is disabled by policy. [zbi.end-user-experience:right-click-menu] The right-click menu article says the Zero Trust Mode menu displays only in Browser-in-Browser Experience Mode. [zbi.end-user-experience:menu-mode-right-click-article] The Zero Trust Mode menu article says all capabilities of an isolated session in Native Browser Experience Mode are accessible via the Zero Trust Mode menu. [zbi.end-user-experience:menu-mode-menu-article] Which mode shows the Zero Trust Mode menu is in dispute [divergence:zbi.end-user-experience:menu-in-native-mode].

**Original URL.** With the Original URL feature enabled, Internet & SaaS evaluates link redirects; a link to a domain different from the one at the start of isolation renders in the user's local browser outside the isolation session, and the Back button returns the user to the ongoing isolated session. The option is enabled per Internet & SaaS isolation profile. [zbi.end-user-experience:original-url-behavior] The Internet & SaaS profile wizard describes Enable Original URL as showing the original URL in the browser bar. [zbi.end-user-experience:original-url-profile-description] Where the setting appears is open [gap:zbi.end-user-experience:original-url-setting-scope].

**Sessions and bookmarks.** A user can have multiple active isolation sessions using different browsers or incognito windows; a second window of the same browser type continues the same session unless it is an incognito window, and the limit is 10 active sessions per user at a time. [zbi.end-user-experience:multiple-sessions] Bookmarks from the original browser can be used in an isolated session and show as isolation URLs there; the isolation URL can be shared inside the organization and with third parties, and a recipient sees a redirect notice and, on confirmation, goes to the original non-isolated URL. [zbi.end-user-experience:bookmarks] Cookies across sessions are in [Persistent State and cookie persistence in isolation: what is purged, what is restored, retention and size limits](kb:zbi.persistent-state).

**Mobile.** Zero Trust Browser mobile isolation is supported on iOS and Android, applies to mobile browser-based applications and not native mobile applications, and is available only for Android 13 and later and iOS 17 and later. [zbi.end-user-experience:mobile-scope] Mobile isolation is described as triggered by a Private Access Isolate policy; the isolation browser uses a mobile user agent, the same profile configuration applies to mobile and desktop, Zscaler Support is the contact if capabilities differ, and mobile users can use the Original URL feature. [zbi.end-user-experience:mobile-behavior]

**Language.** Isolation automatically translates a web page to the user's language when a new isolated session begins, using local browser settings; users can pick another language manually, and admins enable translation per isolation profile. [zbi.end-user-experience:language-translation] Zscaler-generated isolation browser elements such as notifications, warnings and menu items are rendered in the language of the user's browser settings, and this is supported even when translation is disabled for the profile. [zbi.end-user-experience:language-localization]

**Read-only and extensions.** Read-only isolation, enabled per profile, stops text entry anywhere on the page, pasting into text fields and virtual keyboard input, shows an error when a user tries to enter text, and still allows Enter, Escape and the arrow keys for navigation. [zbi.end-user-experience:read-only-mode] Browser extensions in isolation are enabled in Private Access isolation profiles, up to five per profile, selected from a predefined list; an extension's authenticated state is preserved if Persistent State is enabled and the configured extensions are restored in the new container after idle timeout. [zbi.end-user-experience:extensions-in-isolation]

What to check:
1. Which experience mode the user's isolation profile selects, and whether Original URL is enabled, since Browser-in-Browser Experience is not available with it.
2. Whether the user already has 10 active isolation sessions.
3. Whether the Zero Trust Mode menu is expected in the mode the user is in.

Sources disagree (name both sides):
- The right-click menu article says the Zero Trust Mode menu displays only in Browser-in-Browser Experience Mode, while the Zero Trust Mode menu article says the capabilities of Native Browser Experience Mode are accessible via that menu. [divergence:zbi.end-user-experience:menu-in-native-mode]
  - zscaler-help: The Zero Trust Mode menu displays only in Browser-in-Browser Experience Mode.
  - zscaler-help: All capabilities of an isolated session in Native Browser Experience Mode are accessible via the Zero Trust Mode menu.
  - zscaler-help: In Native Browser Experience the Zero Trust Mode menu is hidden by default but still accessible through the checkmark Zero Trust Mode icon.
  - zscaler-help: The Debug Mode steps start from clicking the checkmark Zero Trust Mode icon, pointing to the Zero Trust Mode menu in Native Browser Experience.
  - zscaler-help: The network latency steps start from clicking the checkmark Zero Trust Mode icon, pointing to the Zero Trust Mode menu in Native Browser Experience.
  Impact: An answer about whether a Native Browser Experience user has the Zero Trust Mode menu depends on which article is followed; both are quoted, neither is settled.
