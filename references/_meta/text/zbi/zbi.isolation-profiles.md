# Isolation profiles: the object every isolation rule names, its defaults and the open lifecycle questions (zbi.isolation-profiles)
Also called: isolation profile; cbi profile; browser isolation profile; default isolation profile; defaultProfile; isDefault; cbiProfile; zpn_isolation_profile_id

Default isolation profiles are created automatically for every organization that has Cloud Browser, and admins can create multiple isolation profiles for both Internet & SaaS and Private Access in the Zscaler Admin Console. [zbi.isolation-profiles:default-profiles] Isolation profiles can be edited at any time, and each profile has a banner theme for the isolation end user notification and a choice of root certificates; the configuration guide gives these steps for Internet & SaaS and Private Access profiles alike. [zbi.isolation-profiles:per-profile-banner-cert]

**Defaults.** Each default isolation profile is automatically named Default Isolation Profile <Tenant ID> <Cloud Name>. [zbi.isolation-profiles:default-profile-name] Admins can edit the default isolation profiles but not delete them; using them is not required, and they are used only if the organization creates no isolation profiles of its own. [zbi.isolation-profiles:default-profile-edit-delete-use] On the default isolation profiles the only security control enabled automatically is viewing Office files in isolation; all other security controls are disabled by default. [zbi.isolation-profiles:default-profile-controls]

**Which profile a rule needs.** An Internet & SaaS policy whose action is Isolate must reference an isolation profile; the profiles determine how the user interacts with the isolated page, where the isolation containers are spun up and what the isolation experience looks like. [zbi.isolation-profiles:zia-profile-required-for-isolate] To configure Zero Trust Browser for a Private Access application a Private Access isolation profile must be used; it determines attributes of the isolation browser, how it handles web requests and the level of interaction with the user's native browser. [zbi.isolation-profiles:pa-profile-required] Before creating a Private Access isolation profile, Zero Trust Browser must be enabled for the organization in Private Access. [zbi.isolation-profiles:pa-profile-prerequisite]

**Profile settings.** In an Internet & SaaS isolation profile, choosing the recommended PAC file URL fills the Automatic proxy configuration URL field with the recommended PAC file from the Hosted PAC Files list, and the isolation browser applies the PAC file in the endpoint experience containers so that internet traffic from the isolated browser is also forwarded through the Internet & SaaS cloud. [zbi.isolation-profiles:zia-pac-file-url] The Internet & SaaS isolation profile setting Override PAC file and return traffic to ZIA Public Service Edge can be enabled or disabled; the article explains that the Public Service Edges use auto-geoproximity, so traffic returns to the Service Edge closest to the user, not to the isolation browser. [zbi.isolation-profiles:zia-override-pac-geoproximity] Both the Internet & SaaS and the Private Access isolation profile wizards require at least two regions on the Regions tab; on the Internet & SaaS side containers are leased to the user only from the selected regions, based on the least network latency. [zbi.isolation-profiles:regions-at-least-two] The Internet & SaaS isolation profile Security tab has separate copy-and-paste and file-transfer settings for local computer to isolation and for isolation to local computer; for file transfer from isolation to the local computer, if enabled, the admin selects Flattened PDF (CDR), Sandbox Scanned file or the Original File. [zbi.isolation-profiles:zia-copy-paste-file-transfer] In the Private Access isolation profile, enabling file transfer from the local computer to isolation lets the admin enable or disable Isolation to Local Computer (Flattened Files Only) so transferred files are flattened only; enabling file transfer from isolation to the local computer automatically disables that flattened-only option. [zbi.isolation-profiles:pa-file-transfer-flattened] Allowing the microphone and camera in an isolated session (an optional setting in both profile types) requires Turbo Mode to be enabled and is not supported on mobile devices. [zbi.isolation-profiles:mic-camera-needs-turbo] With Application Deep Linking enabled the admin adds the allowed application links to a list; if the feature is disabled for the profile, or the application is not on the list, the user sees an error that the application is not allowed by policy. [zbi.isolation-profiles:deep-linking-allow-list] Internet & SaaS isolation profiles can enable watermarking, displaying the User ID, a Date & Timestamp in UTC and a custom Watermark Message; the Private Access profile offers checkboxes for User ID, Date & Timestamp (UTC) and Message. [zbi.isolation-profiles:watermark-contents] The Private Access isolation profile has an Allow Local Browser Rendering setting that lets the browser render local files while in isolation. [zbi.isolation-profiles:pa-local-browser-rendering] When Debug Mode is enabled in an isolation profile, the admin can set a password for the ZIP file created at the end of a debug troubleshoot and should share it with the user associated with the profile. [zbi.isolation-profiles:debug-mode-zip-password] The Persist URL bar setting is described differently per profile type: Internet & SaaS says it gives a persisting isolation URL bar, and Private Access says it lets the last accessed URL reappear in a new session; in Private Access the Default isolation banner is selected automatically for new profiles and for preconfigured default profiles. [zbi.isolation-profiles:experience-tab-url-bar-banner]

**Deleting.** Private Access isolation profiles used in Private Access isolation policies cannot be deleted. [zbi.isolation-profiles:pa-profile-in-use-not-deletable] The Private Access delete page says otherwise [divergence:zbi.isolation-profiles:pa-profile-delete-rule].

**Internet & SaaS side.** The Internet & SaaS API lists the cloud browser isolation profiles offered in the Isolation Profile field of URL Filtering and Cloud App Control rules; each entry has an `id` (a UUID), a `name`, a `url` and a `defaultProfile` flag that marks a default profile. [zbi.isolation-profiles:zia-profile-list] On the Internet & SaaS side, `defaultProfile` says whether a profile is a default profile, and the contract says Zscaler sets this field. [zbi.isolation-profiles:zia-default-flag] Whether an Internet & SaaS profile and a Private Access profile with the same purpose are one object is open [gap:zbi.isolation-profiles:zia-zpa-profile-identity].

**Private Access side.** Private Access profiles are written through the CBI configuration API, whose wire details are in [Cloud Browser Isolation and AppProtection API: paths, writes and version handling](kb:zpa.api.cbi-appprotection-wire); the provider's constraints, including at least two regions, are in [The CBI external profile docs say flattened_pdf must be false when upload_download is all and upload_download must be none or upstream when flattened_pdf is true; they also say at least two regions are required.](kb:zpa.terraform.resource-constraints:cbi-profile-constraints). The provider's isolation profile data source can return a different profile than the ID given: [The isolation profile data source has the same fallback: an `id` that matches no profile in the list is ignored and the `name` lookup supplies the result.](kb:zpa.terraform.data-source-selection:invalid-id-falls-back-to-name-isolation-profile).

**Settings.** The setting names are visible in the Miscellaneous & Unknown profile, [The preconfigured profile's automatic settings are: name Misc & Unknown; Turbo Mode enabled; the recommended PAC file URL with Override PAC File disabled; Debug Mode disabled; the default Zscaler root certificate; copy and paste, file transfer and print disabled; Read-Only Isolation enabled; viewing office files in isolation, local browser rendering, application deep linking and Votiro CDR disabled; region selection All; the default isolation banner; Persist Browser Isolation URL bar disabled; Native Browser Experience; watermarking disabled; and Persistent State disabled.](kb:zbi.misc-unknown-subscription:fixed-settings), but what some of them do is still not quoted [gap:zbi.isolation-profiles:setting-semantics]. How region selection bears on data residency is open [gap:zbi.isolation-profiles:region-residency]. Which regions can be selected is open too [gap:zbi.isolation-profiles:region-list].

**Lifecycle.** How default profiles are created and whether their default flag can change is open [gap:zbi.isolation-profiles:default-lifecycle]. What happens when a profile a rule still names is deleted is open [gap:zbi.isolation-profiles:delete-referenced], and so is how a profile change reaches sessions already running [gap:zbi.isolation-profiles:update-propagation].

One region is named in the release notes: The July ZIA release summary says Canada was added as an isolation region in Zero Trust Browser, selectable when configuring isolation profiles for Internet & SaaS (ZIA). [zbi.isolation-profiles:canada-region]

What to check:
1. Whether the profile a rule names still exists, on the side (Internet & SaaS or Private Access) the rule belongs to.
2. Whether the profile's settings were changed while the user's session was running.

Sources disagree (name both sides):
- The Private Access profile creation article says profiles used in Private Access isolation policies cannot be deleted, while the Private Access delete page says the profile can be deleted at any time. [divergence:zbi.isolation-profiles:pa-profile-delete-rule]
  - zscaler-help: Private Access isolation profiles used in Private Access isolation policies cannot be deleted.
  - zscaler-help: After creating a Private Access isolation profile, it can be deleted at any time.
  Impact: An answer on whether a profile in use can be deleted depends on which article is followed; both are quoted, neither is settled.
