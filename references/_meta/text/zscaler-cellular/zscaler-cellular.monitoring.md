# Cellular monitoring: network events, geofence anomaly detection and audit logs (zscaler-cellular.monitoring)
Also called: cellular network events; sim session start end; cellular anomaly detection; geofence violation; sim location group; cellular audit logs; anomaly policy; zcell anomaly policy; anomaly detection policy

Three views cover what happens to SIMs after deployment: network events, anomaly detection and the audit log.

**Network events.** The Network Events page logs network and authorization events for all SIMs provisioned to the organization, with time filters, so SIM transitions between online and offline can be tracked. [zscaler-cellular.monitoring:network-events] Each network event shows ICCID, recorded time, EID (only when eSIMs are listed), IMSI, country, operator, a category of session start, session end, online/offline status or authorization, an event status and an event sub status. [zscaler-cellular.monitoring:network-event-fields] The Network Event Details drawer, opened by clicking an event's ICCID, shows ICCID, SIM Name, IMSI, Country, Operator, Timestamp, IP Address, Source System, Location Details (LAC, CID, MCC, MNC), RAT Type, Data Cap Reached, Event Name, Session ID, SIM ID and SIM EID, plus the Connection Status Log. [zscaler-cellular.monitoring:event-details-fields] The Connection Status Log in the Event Details drawer lets you view, download and copy the network event details in JSON format. [zscaler-cellular.monitoring:event-json-log] Tower-location history built from network events is an API read: [Tower-location history (`/sims/{iccid}/tower-locations`) returns a SIM's cell-tower points sourced from network events, newest first; its `days` lookback (1 to 60, default 30) is deprecated and ignored when `startDate` and `endDate` (epoch seconds) are given, while each point's `timestamp` is in Unix epoch milliseconds.](kb:zscaler-cellular.api.wire-notes:tower-history).

**Anomaly detection.** Anomaly detection uses metadata, geolocation and network usage patterns to detect when tracked devices move beyond a defined geofence; once a SIM Location Group's geofence is linked to an enabled policy, movement outside the boundary is flagged as a violation. [zscaler-cellular.monitoring:geofence-detection] A SIM Location Group defines a geofence and the SIM-enabled devices to be monitored within it, and these groups form the basis for network anomaly detection policies; the Anomaly Dashboard gives visibility into policy configurations and detects anomalies when devices operate beyond the designated geofence area. [zscaler-cellular.monitoring:location-groups] The API contract's operation to create an anomaly policy takes a `policyType` whose only value is `geoFencing`, and the policy list filter has the same single value. [zscaler-cellular.monitoring:api-policy-type-geofence-only] Group, dashboard and policy pages are in [Cellular SIM Location Groups, the Anomaly Dashboard and geofence anomaly detection policies](kb:zscaler-cellular.anomaly-policies). The console's policy page says geofencing is the only policy type currently available ([Configuring a geofence anomaly detection policy needs SIM Location Groups created first; the Policy Details tab has Rule Name, an optional description and Rule Status, geofencing is the only policy type currently available, and after adding the policy you are redirected to the Anomaly Dashboard, where the Enable toggle in the Enabled column runs it.](kb:zscaler-cellular.anomaly-policies:policy-config)); whether a later release adds others is open [gap:zscaler-cellular.monitoring:non-geofence-anomalies].

**Audit logs.** Cellular audit logs record administrative actions in the Cellular configuration, under Data Explorer > Audit Logs > Cellular. [zscaler-cellular.monitoring:audit-scope] Each audit entry shows timestamp, principal ID (the user or system that acted), action (for example Create or Update), resource type (for example Tag, SIM to Tag Mapping or Anomaly Policy), resource name, resource ID and a view of the changes. [zscaler-cellular.monitoring:audit-fields]

**Retention.** The Cellular logs-and-fair-use page gives a retention period and NSS streaming for Cellular logs ([Zscaler Cellular (SIM and Cellular Edge) logs are retained a rolling up to 180 days and audit logs a rolling six months, viewable or streamable via NSS; storage is US or EU chosen at deployment.](kb:shared.logs-fair-use.log-retention:cellular)), but no captured page ties them to the Network Events or Audit Logs pages; per-event JSON download is the only export the console pages state. Whether either console log is kept that long or can reach a SIEM is open [gap:zscaler-cellular.monitoring:retention-and-export].

What to check:
1. For a SIM going offline, the session and online/offline events around that time on the Network Events page.
2. For a missing geofence violation, whether the SIM Location Group is linked to a policy and the policy is enabled.

Not known (open gaps):
- Retention, export and streaming of network events and audit logs [gap:zscaler-cellular.monitoring:retention-and-export] (data gap): filled by none; settled by source-read. Blocks: answering how far back Cellular events can be investigated and whether they can reach a SIEM
- Anomaly types other than geofence in later releases [gap:zscaler-cellular.monitoring:non-geofence-anomalies]: settled by source-read. Blocks: answering whether usage spikes or other behavior raise Cellular anomalies
