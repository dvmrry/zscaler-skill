# Who resolves DNS for each forwarding method (zia.traffic-forwarding.dns-resolution)
Also called: dns resolution forwarding methods; who does the dns lookup; local dns resolution client side

The vendor's DNS resolution article has one table row per forwarding method; DNS policy is in [ZIA DNS Control](kb:zia.dns-control) and ECS injection into customer queries is in [EDNS Client Subnet (ECS) injection and ECS prefix objects](kb:zia.dns-control.ecs).

**PAC and tunnels.** For Explicit Proxy (PAC forwarded) traffic, Zscaler performs DNS resolution for the proxied traffic; for traffic exempted based on the PAC file, the resolution is performed locally on the client side. [zia.traffic-forwarding.dns-resolution:pac-explicit] For Transparent Proxy (GRE and IPSec) traffic, Zscaler performs DNS resolution only if the server is configured on the client side and is a public DNS server (such as Cloudflare, Infoblox or OpenDNS) or a private DNS server hosted on the internet (such as AWS or Azure); if not, the client resolves locally before forwarding the traffic to Zscaler. [zia.traffic-forwarding.dns-resolution:tunnel-transparent] For all traffic forwarded to Zscaler through any port or protocol, Zscaler performs the DNS resolution for the clients, and might use DNS servers running within its data centers or a third-party DNS service. [zia.traffic-forwarding.dns-resolution:all-ports]

**Client Connector.** For Client Connector traffic in tunnel mode with local proxy, Zscaler performs DNS resolution for the proxied traffic; traffic exempted by the App Profile's PAC file or the Forwarding Profile's PAC file is resolved locally on the client side. [zia.traffic-forwarding.dns-resolution:zcc-local-proxy] For Client Connector traffic in tunnel mode, a DNS resolution is first performed locally on the client side for all the traffic, then Zscaler performs a second resolution for the proxied traffic; for traffic exempted based on the App Profile's PAC file or on VPN gateway bypasses, the result of the initial client-side resolution is used. [zia.traffic-forwarding.dns-resolution:zcc-tunnel] Whether that row means Z-Tunnel 1.0 is open [gap:zia.traffic-forwarding.dns-resolution:tunnel-row-version]. Where Destination Include or Exclude Ranges and Domain Inclusions or Exclusions for DNS Requests apply, Zscaler performs the resolution when a public DNS server is used (one in the Destination Include Range, or a domain matching the Domain Inclusions for DNS Requests) and the client resolves locally when a local DNS server is used (one in the Destination Exclude Range, or a domain matching the Domain Exclusions for DNS Requests). The traffic is then proxied or bypassed based on the include or exclude range, Z-Tunnel 2.0 Domain-Based bypass configurations, or VPN gateway bypasses, and for proxied traffic Zscaler has an option to redo the DNS resolution. [zia.traffic-forwarding.dns-resolution:z-tunnel-2] Where the option to redo the resolution is set is open [gap:zia.traffic-forwarding.dns-resolution:redo-resolution-setting].

Not known (open gaps):
- Whether the Client Connector tunnel mode row means Z-Tunnel 1.0 [gap:zia.traffic-forwarding.dns-resolution:tunnel-row-version]: settled by source-read or lab-test
- Where the option to redo DNS resolution for proxied Z-Tunnel 2.0 traffic is configured [gap:zia.traffic-forwarding.dns-resolution:redo-resolution-setting]: settled by source-read or support-ticket
