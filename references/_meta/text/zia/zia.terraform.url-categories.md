# Terraform custom and predefined URL category resources (zia.terraform.url-categories)
Also called: zia_url_categories terraform; zia_url_categories_predefined; custom url category val dlp; delete url category still in use terraform; url category import terraform

Terraform manages custom categories with `zia_url_categories` and edits predefined ones with `zia_url_categories_predefined`. `zia_url_categories` imports only custom categories, by category ID or name; built-in categories cannot be imported. [zia.terraform.url-categories:import-custom-only] `zia_url_categories_predefined` imports only predefined categories, by category ID or display name; custom categories use `zia_url_categories`. [zia.terraform.url-categories:predefined-import-only]

**Custom categories.** Provider v4.7.23 fixed `zia_url_categories` planning failing after import, or whenever the API returned `urls` in a different order from the HCL, and re-ordering URLs in the configuration produces no diff. From v4.8.16 removing the `urls` argument is a planned change that removes every URL. [zia.terraform.url-categories:url-order-diff-suppressed] Provider issue #575 reported that a custom URL category of about 19,000 `urls` entries took 15 to 20 minutes per plan on v4.7.18 while the same data came back from the ZIA REST endpoint in about 5 seconds. A repository member replied that v4.7.22 cut a 20,000 URL fresh create from several minutes to about 35 seconds and a refresh from many minutes to about 20 seconds. These figures are the reporter's and the vendor's. [zia.terraform.url-categories:issue-575-large-category-refresh] The numeric `val` attribute is the category's unique ID and the one to use when referencing the category in other resources such as DLP web rules. [zia.terraform.url-categories:val-for-dlp-reference] From provider v4.7.26 deleting a custom URL category first detaches it from every rule that references it, avoiding the API error for a category still in use. [zia.terraform.url-categories:delete-detaches-v4-7-26] How that detach is written: [ZIA Terraform operations that take several API writes with no rollback](kb:zia.terraform.multi-step-writes). The provider documentation says up to 48 custom URL categories can be added per organization. [zia.terraform.url-categories:tf-limit-48-custom] That disagrees with the help page [divergence:zia.terraform.url-categories:custom-category-cap-48-vs-64]. Plan time for very large categories is unmeasured [gap:zia.terraform.url-categories:large-category-plan-time]. Provider issue #615, closed as completed on 2026-10-29, reported against v4.8.13 that removing a URL from `urls` on `zia_url_categories` also removes the desired `db_categorized_urls` entries from the category in ZIA even when `db_categorized_urls` is unchanged in configuration, that planned changes to `db_categorized_urls` are then not applied, and that the next plan shows drift. The reporter's explanation is that ZIA applies the action to every list in the payload. A repository member's comments advise upgrading to v4.8.16 and then to v4.8.17; a commenter reported that removing only some `urls` was still broken on v4.8.16, and a later comment confirmed that 4.8.17 resolves the issue. [zia.terraform.url-categories:issue-615-remove-clears-other-lists] From provider v4.8.17, adding or removing some of the `urls` no longer removes other entries of the category: its incremental requests empty `dbCategorizedUrls` and `ipRanges`, and updates that change `urls` together with `db_categorized_urls` or `ip_ranges`, or of a category with keyword-retaining, IP-range-retaining, regex or regex-retaining entries, update the category as a whole. From v4.8.16, removing every entry from `urls`, or replacing all of them, no longer fails with `INVALID_INPUT_ARGUMENT` when the category has other entries, such as `db_categorized_urls`. [zia.terraform.url-categories:keeps-other-lists-v4-8-17] A comment in the provider source states that, verified against the API, REMOVE_FROM_LIST sent with the full desired `dbCategorizedUrls` and `ipRanges` removed them from the category, while keywords, which the API replaces when present, were kept. This is the vendor's statement, not a test in this repository. [zia.terraform.url-categories:provider-comment-remove-from-list-effect] Whether the service behaves as that report says is open [gap:zia.terraform.url-categories:issue-615-reproduction].

**Predefined categories.** It is one of the Early Access resources listed in [The provider documentation marks `zia_url_categories_predefined`, `zia_sandbox_behavioral_analysis_v2`, `zia_extranet`, `zia_dc_exclusions` and `zia_sub_cloud` as Early Access features.](kb:zia.terraform.early-access:early-access-resources). `zia_url_categories_predefined` changes the URL, IP-range and parent-retaining IP-range lists of a predefined category with incremental `REMOVE_FROM_LIST` and `ADD_TO_LIST` operations, and replaces `keywords` and `keywords_retaining_parent_category` with a plain PUT. Its documentation says instead that all list fields, keywords included, use incremental operations rather than a full replacement. [zia.terraform.url-categories:predefined-incremental] The `description` attribute is not supported on predefined categories because the API accepts it in the PUT but does not return it in the GET, which would cause persistent drift. [zia.terraform.url-categories:predefined-description-drift] Importing a predefined category that already has custom URLs, keywords or IP ranges captures them in state, and the next apply attempts to remove any that the HCL omits. [zia.terraform.url-categories:predefined-import-captures-existing]

What to check:
1. Whether a DLP rule references the category by `val` rather than by name.
2. Whether an import of a predefined category lists every custom item the HCL should keep before the next apply.
3. Which custom category cap applies to the tenant, since the provider docs and the help page differ.

Sources disagree (name both sides):
- How many custom URL categories a tenant can hold by default. [divergence:zia.terraform.url-categories:custom-category-cap-48-vs-64]
  - tf-zia: The Terraform resource documentation says up to 48 custom URL categories per organization.
  - zscaler-help: The Ranges and Limitations help page gives 64 as the default limit for custom categories.
  Impact: Do not quote 48 as the tenant limit from the provider docs alone; the help page figure is 64, raisable through Support, and which is current for a given tenant is not settled here.

Not known (open gaps):
- How long a plan or refresh takes for a custom category with tens of thousands of URLs [gap:zia.terraform.url-categories:large-category-plan-time]: settled by lab-test. Blocks: saying that planning a large custom URL category is slow or fast
- Whether ZIA applies REMOVE_FROM_LIST to the other lists in the payload [gap:zia.terraform.url-categories:issue-615-reproduction]: settled by lab-test. Blocks: saying that a URL removal on a custom category keeps its db_categorized_urls entries
