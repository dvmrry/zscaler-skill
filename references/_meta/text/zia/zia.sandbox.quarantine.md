# Files stuck in Sandbox quarantine (zia.sandbox.quarantine)
Also called: file stuck in quarantine; one-time download link; dynamic hash; PSE cache lag; allow and scan; patient 0

A file "stuck in quarantine" has three documented causes. Quarantine itself needs Advanced Sandbox (see [What Sandbox analyzes and why a file may not be](kb:zia.sandbox.coverage)).

For one-time download links the URL stops serving the file after the first request, so later download attempts return 404 or 403 from the origin. Web Insights shows "Sent for Analysis" for the first transaction and "Allowed" afterwards, with the server-side 404. [zia.sandbox.quarantine:one-time-links] Whether Allow and scan also fixes a one-time link is open [gap:zia.sandbox.quarantine:one-time-link-remedy].

Some sites generate a unique file per request, so each request has a different MD5 and starts a new quarantine. Web Insights shows several "Sent for Analysis" entries for the same URL with different MD5 hashes. [zia.sandbox.quarantine:dynamic-hash] The documented remedy for the dynamic-hash case is a Sandbox rule for the affected domain set to "Allow and scan" instead of quarantine. The file is delivered immediately while Sandbox analyzes in the background, and a Patient 0 alert fires if it is malicious. [zia.sandbox.quarantine:allow-and-scan-remedy] The rule field that selects that behavior, and the other first-time operations, are in [Sandbox rules: first-time file behavior and the default rule](kb:zia.sandbox.rules).

After analysis completes on one Public Service Edge the result may not yet be cached on another, so a user at a different location may briefly see the quarantine page again; it resolves once the cache propagates. A report showing Benign while the file is still quarantined means the cache has not caught up, and the user should retry shortly. [zia.sandbox.quarantine:pse-cache-lag] Sandbox propagates the hash of a malicious file to all Public Service Edges for Internet & SaaS, which the help page describes as a real-time denylist. [zia.sandbox.quarantine:hash-propagation] What to do when a quarantine persists after a Benign verdict is open [gap:zia.sandbox.quarantine:persistent-quarantine-escalation]. Confirm with the report: [Sandbox reports, quota, and trusting report content](kb:zia.sandbox.report).

**The quarantine page.** Quarantine as a First-Time Action needs Advanced Sandbox. The service quarantines the unknown file, sends it to the Sandbox and shows a quarantine notification, which can be customized on the End User Notifications page. Analysis might take a few minutes depending on the file's size and type; a safe file starts downloading automatically, and an unsafe one might be blocked depending on the Sandbox policy. [zia.sandbox.quarantine:quarantine-page] Refreshing the quarantine page, manually or automatically, creates a new quarantine transaction log for the file without changing the wait for the Sandbox analysis. [zia.sandbox.quarantine:refresh-new-log] How long the analysis takes is open in [Unverified legacy statement: dynamic analysis takes 3 to 10 minutes](kb:zia.sandbox.submission:dynamic-analysis-duration).

What to check:
1. Whether the URL still serves the file, since a one-time link stops serving it after the first request.
2. Whether the MD5 differs between attempts in the logs, which points to a per-request file.
3. What the report says for the MD5, since a Benign report with the file still quarantined means the cache has not caught up.

Not known (open gaps):
- Whether Allow and scan also fixes a one-time download link [gap:zia.sandbox.quarantine:one-time-link-remedy]: settled by lab-test or operator-experience
- What to do when a quarantine persists after the verdict is Benign [gap:zia.sandbox.quarantine:persistent-quarantine-escalation]: settled by support-ticket or operator-experience
