# Sandbox custom MD5 hash list (zia.sandbox.md5-blocklist)
Also called: custom md5 block list; behavioralAnalysisAdvancedSettings; file hash count; CUSTOM_FILEHASH_DENY; block a known bad hash; fileHashesToBeBlocked

When an operator already knows a hash is bad, the custom MD5 list is the manual lever. Sandbox keeps a custom list of MD5 file hashes it blocks, under /zia/api/v1/behavioralAnalysisAdvancedSettings: GET reads the list and PUT updates it, and the Python SDK says passing an empty list clears the blocklist. [zia.sandbox.md5-blocklist:endpoint] The list has two wire shapes. A flat `fileHashesToBeBlocked` array of strings, and a richer `md5HashValueList` of objects with `url` (the MD5), `urlComment` and `type`. The Python SDK documents `type` as CUSTOM_FILEHASH_DENY or CUSTOM_FILEHASH_ALLOW; the Go source illustrates it only as "MALWARE". [zia.sandbox.md5-blocklist:two-shapes] In the Go SDK the list is `Get` (flat), `Getv2` (rich), `Update` (flat), `Updatev2` (rich) and `GetFileHashCount`. In the Python SDK `get_behavioral_analysis` reads it, `add_hash_to_custom_list` writes the rich shape, and `get_file_hash_count` reads the count. [zia.sandbox.md5-blocklist:sdk-functions] Because the Python type includes CUSTOM_FILEHASH_ALLOW, the same list may hold allow entries as well as deny entries, so "blocklist" can understate what is in it. [zia.sandbox.md5-blocklist:allow-entries]

**Clearing it.** To clear the list, send `md5HashValueList` as an empty array. The Go payload field deliberately has no `omitempty` because the API requires the key even as `[]`; dropping the key does not clear the list. [zia.sandbox.md5-blocklist:clear-with-empty-array]

**Headroom.** A sub-endpoint, /behavioralAnalysisAdvancedSettings/fileHashCount, returns `blockedFileHashesCount` and `remainingFileHashes`, the used and unused quota for blocking MD5 hashes. `remainingFileHashes` is how many more can be added. [zia.sandbox.md5-blocklist:hash-count] The ceiling itself is open [gap:zia.sandbox.md5-blocklist:quota-cap].

The MCP workflow checks a suspect file by reading the blocked-hash list and looking for its MD5, and reads the hash count to see overall usage. [zia.sandbox.md5-blocklist:mcp-check] Detonation reports are in [Sandbox reports, quota, and trusting report content](kb:zia.sandbox.report); the rules that handle everything else are in [Sandbox rules: first-time file behavior and the default rule](kb:zia.sandbox.rules).

**In the help.** The help places the custom MD5 lists on the Sandbox policy's Advanced Policy Settings page: a denylist of hashes to block specific files applicable to Sandbox analysis, and an allowlist of hashes to allow specific files access. When adding to the allowlist an entry can carry a comment after two forward slashes, which the page words as a comment on a URL entry, and Remove All deletes all the custom file MD5 hashes from the list. [zia.sandbox.md5-blocklist:help-allow-and-deny-lists]

**Terraform.** The provider registers both `zia_sandbox_behavioral_analysis` and `zia_sandbox_behavioral_analysis_v2` as resources and data sources. [zia.sandbox.md5-blocklist:tf-both-resources-registered] The v2 resource documentation says the original `zia_sandbox_behavioral_analysis` resource is still available, but the provider encourages users to move to the new format, and that the original will eventually be deprecated. [zia.sandbox.md5-blocklist:tf-v2-encouraged] Whether v2 is already required for new configurations is open [gap:zia.sandbox.md5-blocklist:tf-v2-supersedes-v1]. The Terraform resources `zia_sandbox_behavioral_analysis` (flat) and `zia_sandbox_behavioral_analysis_v2` (rich) both read and write the same object: the SDK's `Get` and `Getv2` read, and `Update` and `Updatev2` PUT, the single behavioralAnalysisAdvancedSettings endpoint, differing only in payload shape. [zia.sandbox.md5-blocklist:tf-v1-v2-same-endpoint] Whether the two can be declared together is open [gap:zia.sandbox.md5-blocklist:tf-v1-v2-coexistence].
