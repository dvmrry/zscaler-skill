# Revoke, ban and end user review in 3rd-Party App Governance: what each does and where it is recorded (zia.app-governance.remediation)

Revoke (supported by Google) removes all permissions granted for the app and does not prevent users from installing the app and giving consent in the future, though app classification and policies can be used to prevent reinstalling. Ban (supported by Microsoft) blocks access to the app, preventing users from using it in the future. An app can also be revoked for individual users, and banning for individual users is not currently supported. [zia.app-governance.remediation:revoke-vs-ban] The default email sent by revoke or ban can be viewed but not edited. Emails cannot be sent when revoking domain-wide applications authorized at the organization level for all users. After an app is banned or revoked, its status changes in 3rd-Party App Governance. [zia.app-governance.remediation:revoke-notification-email] The consent a platform needs for these actions is in [Connecting SaaS platforms to 3rd-Party App Governance: supported platforms, platform admin roles, permissions requested and tenant status](kb:zia.app-governance.platforms).

**End User Review.** In the end user review process, users confirm via Slack or email whether they are using the apps currently enabled for them. Based on the response, their access to the app is either automatically revoked or maintained, and the response is recorded as a User Activity in 3rd-Party App Governance. [zia.app-governance.remediation:end-user-review] In both the Slack message and the email review form, "I'm using this app" maintains access to the app, and "I'm not using this app" and "I don't remember installing it" revoke it. [zia.app-governance.remediation:review-responses] Depending on the platform (for example Google), access to the app can be automatically revoked. If all users of an app each confirm that the app is not in use and the platform supports the Revoke action, access is automatically revoked and the App Status changes to Deleted in the App Inventory. [zia.app-governance.remediation:review-auto-revoke] After users submit their responses, the responses are recorded in the Activities tab of the App Panel and User Panel and in the Audit Log. To see user responses as they are received, enable the User Responded to App Review policy and configure notifications. [zia.app-governance.remediation:review-records]

**On many apps at once.** Bulk actions on selected apps include Add To Inventory (from the app catalog), Change Classification and Set Automated Workflow. After the end user review or revoke/ban process is complete, a summary shows the number of apps for which the action was successful, failed or non-applicable. [zia.app-governance.remediation:bulk-actions] Policies can run the same actions automatically: [3rd-Party App Governance policies and notification channels, including the NSS channel](kb:zia.app-governance.policies). The status a revoked or reviewed app takes is in [An app's status, risk score, findings and classification in 3rd-Party App Governance (the App Panel)](kb:zia.app-governance.app-risk).
