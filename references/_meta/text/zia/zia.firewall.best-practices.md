# Recommended Firewall Filtering, DNS Control and IPS Control rules (zia.firewall.best-practices)
Also called: firewall best practices; recommended firewall policy; Default Firewall Filtering Rule; Block Malicious IPs and Domains; Default Cloud IPS Rule; Critical Risk DNS Categories

The Best Practices for Firewall Control Policy article provides recommendations and best practices for configuring and using the Zscaler Firewall Control policy with Standard or Advanced Firewall. [zia.firewall.best-practices:scope]

**Firewall Filtering rules.** The article recommends enabling the predefined Default Firewall Filtering Rule with the Block action and assigning it the lowest rule order, so that any traffic not explicitly allowed to the internet is blocked, and reviewing the Firewall logs to assess traffic match and impact. It is supported in Standard and Advanced Firewall. [zia.firewall.best-practices:default-rule] The article recommends enabling the predefined Block Malicious IPs and Domains rule and assigning a very high rule order; the rule blocks IP addresses and FQDNs resolved to highly risky IP addresses. It is supported in Standard and Advanced Firewall. [zia.firewall.best-practices:block-malicious] The article recommends configuring the recommended Firewall rule as an Allow rule that includes only HTTP, HTTPS and DNS as network service conditions, at a high rule order. The rule allows traffic that is managed more granularly by the web proxy and the DNS Control to pass through the Firewall checks at the Network and Transport layers and be managed in those modules, where all web and DNS rules are defined. [zia.firewall.best-practices:recommended-policy] The Recommended Firewall Control Policy page configures the recommended rule with rule order 1 or the highest order applicable to admin-defined rules (as opposed to system-defined rules like Office 365 One Click Rule and Zscaler Proxy Traffic), Device Groups including Cloud Browser isolation, No Client Connector and OS types, the HTTP, HTTPS and DNS network services, and the Allow action for Network Traffic. It says those services must be allowed through the firewall for the DNS Control and Web (secure web gateway) modules to evaluate the traffic. [zia.firewall.best-practices:recommended-rule-settings] By default the HTTP network service uses port 80, HTTPS uses 443 and DNS uses 53. To send custom network services to the DNS Control and Web modules for evaluation, they must be configured in Advanced Settings using the Services Forwarded to HTTP Web Proxy and Services Applicable to DNS Transaction Policies options, and Zscaler recommends against changing the default ports for the HTTP, HTTPS and DNS network services. [zia.firewall.best-practices:recommended-service-ports] The predefined rules named here are described in [Default and predefined Firewall Filtering rules: what each does and what can be changed](kb:zia.firewall.predefined-rules). The article recommends rules that block ICMP and QUIC using the network service criteria at a high rule order, and says the Block/ICMP rule action must be used for both, which for QUIC ensures a rapid failover to other options and a better user experience. It suggests considering adding UDP port 80 to the default QUIC network service, or defining a new network service with that port in the Block rule. The QUIC rule ensures that only web traffic supported by the web proxy is allowed, and the ICMP rule ensures that only ICMP for authorized users is allowed and reduces the attack surface for ICMP tunneling. [zia.firewall.best-practices:icmp-quic] The article recommends a rule that blocks SMB using the network service criteria at a moderate rule order, and says that in general there is no requirement to allow SMB to the internet in most environments, and that the Default Firewall Filtering Rule and strictly defined rule sets typically remove the need to explicitly block SMB. [zia.firewall.best-practices:smb] Zscaler recommends creating any Allow rule using at least three or more conditions, including user, group, department, source or destination IP address, network service, application service and network application, and strongly recommends against using network applications as the only rule condition in any Allow or Block rule. Rules using network application criteria require Advanced Firewall. [zia.firewall.best-practices:allow-rule-conditions]

**DNS Control rules.** For DNS Control, the article recommends enabling the predefined Critical Risk DNS Categories rule with the Block action configured for DNS categorizations as well as DNS tunnels at a high rule order, and considering enabling all predefined rules related to blocking risky DNS at a moderate to high rule order. Standard Firewall includes support for blocking DNS categorizations; DNS tunnel block requires Advanced Firewall. [zia.firewall.best-practices:dns-rules]

**IPS Control rules.** For IPS Control, the article recommends enabling the predefined Default Cloud IPS Rule with the Block action at the lowest rule order; the rule covers all low false-positive IPS detections created by ThreatLabz that must be blocked. It suggests considering higher-order rules for internal security teams and other sensitive users, groups, departments or locations who might need access to malware for research or exclusion from non-web IPS protections. The row says it requires Advanced Firewall. [zia.firewall.best-practices:ips-default]

What the tiers include is in [Which firewall features need Advanced Firewall](kb:zia.firewall.licensing); the firewall as a whole is in [ZIA Firewall Control](kb:zia.firewall).
