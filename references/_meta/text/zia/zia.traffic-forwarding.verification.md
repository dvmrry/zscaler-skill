# ip.zscaler.com and the vendor's causes when traffic does not land on the nearest Public Service Edge (zia.traffic-forwarding.verification)
Also called: ip.zscaler.com; my ip address service; is my traffic going to zscaler; not going to nearest service edge; whoami.akamai.net

ip.zscaler.com is the page that shows a device whether its traffic reaches the Zscaler service. To check if a user's traffic is going to the Zscaler service, go to ip.zscaler.com on the user's device. It shows the Zscaler cloud and the location of the Public Service Edge, the egress IP address and the virtual IP address of the Public Service Edge, the Zscaler hostname of the edge instance processing the traffic, the egress IP address of the network from which the edge receives traffic, and the IP address of the gateway. The page says the service might not recognize IPv6 traffic passing through the Zscaler cloud. [zia.traffic-forwarding.verification:ip-zscaler-com]

**When the edge is not the nearest.** How the nearest edge is chosen is in [Service Edges: the data plane, its form factors, and how traffic reaches one](kb:shared.cloud-architecture.service-edges) and the variables in [Zscaler PAC file variables: gateways, hosts, load-balancing tokens, subclouds and Client Connector](kb:shared.pac-files.variables). When a PAC file uses gateway.<zscaler_cloud> (for example gateway.zscaler.net:80) and the DNS server is not in the same geographic region as the organization's Internet gateway location, the DNS server returns the IP address of the Public Service Edge in the data center closest to it, which might not be the closest to the user. Resolving whoami.akamai.net gives the IP address of the DNS server that resolved the Zscaler gateway name. The fix the article gives is ${GATEWAY}:80 for the primary proxy and ${SECONDARY_GATEWAY}:80 for the secondary. [zia.traffic-forwarding.verification:gateway-name-dns-mismatch] Specifying the IP address of a Zscaler data center in a PAC file is not recommended, as it might cause problems when the user is remote and far from the Public Service Edge; the gateway-variable method is preferred because the service uses the GeoIP coordinates of the source IP address to determine the nearest Public Service Edge. [zia.traffic-forwarding.verification:hardcoded-dc-ip]

**Denylisted source IP.** Internet Access > Tools > Denylist IP Check shows whether the Zscaler service is placing service access from an IP address on the denylist due to suspicious traffic activity: a denylisted IP address is shown with additional comments, and otherwise there are no results. [zia.traffic-forwarding.verification:denylist-ip-check] The vendor's performance test is in [Measuring ZIA performance: the Cloud Performance Test and why common speed tests mislead](kb:zia.troubleshooting.performance-testing).
