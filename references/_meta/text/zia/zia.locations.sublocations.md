# Sublocations: what they are, the auto-created other sublocations, naming and limits (zia.locations.sublocations)
Also called: sublocation; sub-location; other sublocation; other6; nested location; sublocation limit; delete parent location; reparent sublocation; sublocation name uniqueness
Former IDs: zia-17, zia-18, zia-19, zia-20

A sublocation is a location nested under a parent location that references IP addresses encapsulated in a GRE or IPSec tunnel, or passed to the service in X-Forwarded-For headers. It is the same location object as a parent, distinguished by `parentId`: a missing or 0 `parentId` means a parent location. [zia.locations.sublocations:what-it-is] Sublocations let one tunnel carry several networks with different treatment: policy by IP address, authentication enforced on the corporate network and off for guest, bandwidth control per sublocation with unused bandwidth staying available at the parent, and separate reporting for networks or offices that share an egress IP. [zia.locations.sublocations:what-it-is-for]

**Auto-created `other`.** After a sublocation is added to a location, the service creates a sublocation named `other` for traffic from that location whose IP address is not in any defined sublocation; with IPv6 enabled on the location it also creates `other6`. Both can be renamed, and the API flags them with `otherSubLocation` and `other6SubLocation`. [zia.locations.sublocations:other-auto-created] With IPv6 enabled on a location, adding a sublocation creates Other6 for all IPv6 addresses that connect to the service from that location; creating sublocations for specific IPv6 addresses or networks is currently not supported. [zia.locations.sublocations:ipv6-other6-only] When a sublocation is added to a location that has Enable IPv6 on, the service creates `other` and `other6`, existing rules that referred to the parent location now refer to the `other` sublocation, and rules must be configured by hand for the sublocation just created. [zia.locations.sublocations:other-takes-parent-rules] Tightening policy on defined sublocations does not tighten `other`: traffic from unmatched IPs is handled under whatever rules reach `other`, so review the rules that apply to `other` whenever sublocation rules change. [zia.locations.sublocations:other-is-a-policy-gap] How the default rule catches traffic no rule matches is in [URL Filtering rule order and first match](kb:zia.url-filtering.rule-order).

**Names and limits.** The documented limit is 2,000 sublocations per location, which Zscaler Support can raise to 16K; the Configuring Sublocations article states the limit as "up to 16K sublocations per location". [zia.locations.sublocations:cap-2000] The console rejects a location or sublocation name that already belongs to an existing location or sublocation; a previously deleted name can be reused when creating a new one but not when renaming an existing one. [zia.locations.sublocations:name-in-use-error]

**The console list.** The View Sublocation page lists up to 100 sublocations per page. Its Proxy Ports and Use XFF from Client Request columns show the parent location's values; Authentication shows the sublocation's setting and, with Enable IP Surrogates, its Idle Time to Disassociation; Bandwidth shows the sublocation's download and upload limits in Mbps when Enforce Bandwidth Control is enabled for it; Firewall Filtering is described as whether Firewall Control is enabled for the location; and Scope Type is available only for the Workload traffic type location type. [zia.locations.sublocations:view-page]

**Finding and changing sublocations.** Sublocations are listed by parent through `GET /locations/{locationId}/sublocations`; the same `DELETE /locations/{locationId}` removes a location or a sublocation. The Ansible module records that the top-level `/locations` listing does not return sublocations. [zia.locations.sublocations:separate-list-endpoint] The Python SDK's `update_location` accepts `parent_id`, so a PUT can in principle move a location between parent and sublocation roles; no source says what the API requires of such a change. [zia.locations.sublocations:parent-id-writable] The Go SDK lookups that wrongly report a sublocation as missing are in [ZIA Go SDK service functions that return wrong results, mutate inputs, or reject valid input](kb:zia.sdk-go.service-defects), and the Terraform data source gaps are in [What ZIA Terraform data sources return, drop, or get wrong](kb:zia.terraform.data-source-fidelity). Parent deletion with sublocations is open [gap:zia.locations.sublocations:parent-delete-behavior], and so are reparenting [gap:zia.locations.sublocations:reparenting-rules] and depth [gap:zia.locations.sublocations:depth-limit].
