# Security policies runbook: Sandbox symptoms (licensing, no active content, quarantine, Patient 0, MD5 report) (zia.troubleshooting.security-policies-runbook.sandbox)
Also called: Sandbox Licensing Restrictions; No Active Content; Patient 0 alert; Sandbox Patient 0 Events

**Before troubleshooting.** The runbook says to confirm that Sandbox is responsible for the block or unexpected behavior before troubleshooting, notes that Malware Protection, File Type Control or other upstream security solutions can also impact file downloads, and states that SSL Inspection is a prerequisite for Sandbox policies to apply: if traffic isn't getting SSL inspected, Sandbox policies do not apply. [zia.troubleshooting.security-policies-runbook.sandbox:prerequisite-and-scope]

**Web Insights values.** In the runbook's Sandbox Web Insights examples, an Allowed Benign or Allowed Sent for Analysis transaction has Threat Super Category Sandbox and Blocked Policy Type None; Quarantined, ML Quarantined and Isolate and Scan actions show Threat Category Sent for Analysis and Blocked Policy Type Sandbox; Sandbox Block Inbound Response and ML Block show Sandbox Malware, Sandbox Adware, Sandbox Anonimyzer, Sandbox Offensive Security Tools or Sandbox Ransomware as Threat Category. The runbook says to use its Sandbox troubleshooting steps if the Threat Super Category value matches Sandbox. [zia.troubleshooting.security-policies-runbook.sandbox:log-rows]

**File blocked by Sandbox.** For a file blocked by Sandbox, the runbook says to examine the Blocked Policy Type field in Web Insights to identify the Blocked Policy Name (examples: Quarantine Malicious and Catch_All, both Blocked Policy Type Sandbox), open the MD5 hash link to the Sandbox report, and treat the block as expected when the report classifies the file as malicious (Class Type). [zia.troubleshooting.security-policies-runbook.sandbox:blocked-by-sandbox]

**File not sent to Sandbox.** For a file not sent to Sandbox, the runbook says to check the MD5 field in Web Insights for a Sandbox report: a report means the file was already analyzed (with date and time of analysis), while no report means it was possibly excluded from Sandbox analysis due to licensing, policy settings, or file characteristics. [zia.troubleshooting.security-policies-runbook.sandbox:not-sent-md5-check] The runbook's In-line Sandbox table lists the Basic File Types as Windows Executable (.exe, .exe64, .scr), Windows Library (.dll64, .dll, .ocx, .sys) and .zip with a File Size of 2 MB or less, and the Advanced File Size as 'Up to 20 MB, 2 MB SWF, and 50 MB APK Archive and .exe are supported for 50 MB'; with a Basic Sandbox subscription only files that match the Basic Sandbox criteria are analyzed. [zia.troubleshooting.security-policies-runbook.sandbox:basic-vs-advanced-coverage] The runbook's In-line Sandbox table marks Basic as not offering AI-Driven Quarantine, File Quarantine, Reporting, URL Categories, API or Patient 0 and as having a Single default rule for Policy Control, with In-Line Blocking limited to URLs in specific Suspicious Destinations categories; Advanced has granular quarantine-based policies, holds files until confirmed Sandbox clean, and blocks in All URL Categories. [zia.troubleshooting.security-policies-runbook.sandbox:basic-vs-advanced-features] [gap:zia.troubleshooting.security-policies-runbook.sandbox:basic-advanced-icon-rows] For Microsoft Office documents and PDFs, Sandbox performs an initial static analysis on the Public Service Edge; a file new to the Zscaler cloud is checked for active content (e.g., macros, embedded scripts, suspicious objects), and if none is found it is classified as benign, isn't sent to the Sandbox, and Web Insights shows Allowed - No Active Content as the Policy Action. [zia.troubleshooting.security-policies-runbook.sandbox:no-active-content]

**File stays in quarantine.** The runbook says a file that remains in quarantine indefinitely can be due to one-time download links or dynamically generated files; for expired or one-time download links its log checks are Sent for Analysis in the Threat Category field on the first download transaction, later Allowed transactions for the same URL, and a Response Code of 404 - File not found or 403 - Forbidden from the destination server; for dynamic file generation (changing hashes) its check is multiple Sent for Analysis entries in the Threat Category field for the same URL with different MD5 hashes. [zia.troubleshooting.security-policies-runbook.sandbox:quarantine-not-releasing] The runbook's solution for a file that stays in quarantine is a Sandbox rule for the affected domain that allows and scans files instead of holding them in quarantine; if the file is later classified as malicious the customer receives a Patient 0 alert, and exceptions should be created only for necessary domains, not broad categories of files. [zia.troubleshooting.security-policies-runbook.sandbox:quarantine-solution]

**Patient 0 alerts.** An Advanced Sandbox subscription is required to configure and receive patient 0 alerts; when the first-time action of a Sandbox rule is configured to allow and scan unknown files, the service allows users to download files that match the rule criteria and sends the files to the Sandbox for behavioral analysis, and a patient 0 event occurs when a user downloads an unknown file that is scanned and found to be malicious, with alert emails within approximately two hours. [zia.troubleshooting.security-policies-runbook.sandbox:patient-0-alerts] To receive patient 0 alerts the runbook says to go to Administration > Account Management > Alerts > Add Alert Definition > Alert Name > Patient 0, then add an alert subscription under Publish Alerts enabling Critical Patient 0 alerts; the Sandbox Patient 0 Events widget displays the patient 0 events in the organization, including Alert Time, Threat and Allowed Transactions. [zia.troubleshooting.security-policies-runbook.sandbox:patient-0-setup]

**Quarantine page for a file analyzed as benign.** When the Quarantine page is displayed even though the same file was previously analyzed and classified as benign, the runbook says this could happen when the file analysis result is not present in the Public Service Edge at the time of download; it says this behavior is by design (each Public Service Edge updates independently based on geographic location, and after the initial download in each location the file is fast-pathed for subsequent users), that a different MD5 for the same file means a reanalysis is expected, and that the user might have to wait and retry the download. [zia.troubleshooting.security-policies-runbook.sandbox:md5-after-benign]

**MD5 is not a link.** An Advanced Sandbox subscription is required to access Sandbox reports, and the MD5 hash is only a clickable hyperlink when the Threat Super Category value is Sandbox; for any other Threat Super Category the MD5 is displayed as plain text. [zia.troubleshooting.security-policies-runbook.sandbox:md5-not-hyperlink]
