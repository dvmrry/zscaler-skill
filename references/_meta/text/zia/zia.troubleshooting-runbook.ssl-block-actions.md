# Runbook: SSL and HTTP-tunnel block outcomes (bad SSL record, undecryptable traffic, server probe failure, domain fronting, HTTP tunnel) (zia.troubleshooting-runbook.ssl-block-actions)
Also called: Blocked due to bad SSL record; Undecryptable traffic block; Blocked due to server probe failure; Access denied due to domain fronting; Not allowed to use HTTP tunnel

**Bad SSL record.** The Blocked Due to Bad SSL Record page describes the SSL connection as blocked due to the forwarding of non-SSL traffic to ports configured for HTTPS Services; Zscaler marks the transaction protocol as Tunnel SSL when some non-HTTP data is sent after an SSL handshake, and the Block Undecryptable Traffic option in the SSL Inspection Policy controls the behavior for such transactions. [zia.troubleshooting-runbook.ssl-block-actions:bad-ssl-record-cause] A client packet capture opened in Wireshark showing Data or HTTP rather than Transport Layer Security after TCP confirms non-TLS data was sent on the connection. [zia.troubleshooting-runbook.ssl-block-actions:bad-ssl-record-pcap] For bad SSL record blocks, the page offers a domain-specific SSL Inspection rule with Block Undecryptable Traffic disabled, or, if all undecryptable traffic to HTTPS ports must stay blocked, a Do Not Inspect rule for the domain. [zia.troubleshooting-runbook.ssl-block-actions:bad-ssl-record-solutions]

**Undecryptable traffic.** The Zscaler service treats a transaction as undecryptable when the website uses one of the unsupported ciphers EXP, DSS, RC4-MD5, RC4-SHA, DES-CBC-SHA, DES-CBC3-SHA or 3DES-CBC-SHA (this page's seven-cipher list); the page's example shows Blocked due to Server Probe failure as the Policy Action and Not Inspected because of undecryptable traffic as the SSL Policy reason. [zia.troubleshooting-runbook.ssl-block-actions:undecryptable-unsupported-ciphers] The shorter list for sites that only use unsupported ciphers is in [Which TLS versions and cipher suites SSL/TLS inspection supports, and what happens to the rest](kb:zia.ssl-inspection.cipher-suites). Non-SSL traffic from applications using ports configured as HTTPS Services under Services Forwarded to HTTP Web Proxy is identified as undecryptable. [zia.troubleshooting-runbook.ssl-block-actions:undecryptable-non-web-over-ssl] If a trusted domain needs non-SSL communication using HTTPS ports, the page says to configure a Do Not Inspect rule for it or disable the Block Undecryptable Traffic option; for a nonstandard TCP port considered undecryptable, it says to review whether HTTPS applications use that port and update the services configured as HTTPS Services. [zia.troubleshooting-runbook.ssl-block-actions:undecryptable-solutions]

**Server probe failure.** A server probe failure block applies when the Service Edge cannot connect to the target website by TCP or TLS, which happens when the web server does not tolerate SSL Inspection or does not complete the TCP handshake. [zia.troubleshooting-runbook.ssl-block-actions:server-probe-cause] With the SSL Inspection action Do Not Inspect and Evaluate Other Policies, the error can still appear when the domain part of a URL is blocked in an access control policy, because the service must decrypt a blocked transaction to show the End User Notification. [zia.troubleshooting-runbook.ssl-block-actions:server-probe-eun-decrypt] For server probe failures the page suggests disabling Block Undecryptable Traffic in an Inspect rule for the domain, or as a workaround setting the rule action to Do Not Inspect and Bypass Other Policies. [zia.troubleshooting-runbook.ssl-block-actions:server-probe-solutions]

**Domain fronting.** The runbook defines domain fronting as the domain in the SNI extension or Connect request differing from the one later supplied in the Host header. [zia.troubleshooting-runbook.ssl-block-actions:domain-fronting-definition] To diagnose a domain-fronting denial, confirm Block Domain Fronting under Administration > Advanced Settings is enabled, then compare the URL with the Domain Fronted SNI and Domain Fronted Host Header web log columns; a difference means access is denied as configured. [zia.troubleshooting-runbook.ssl-block-actions:domain-fronting-diagnosis] Zscaler does not recommend disabling Block Domain Fronting because it is a global setting; the page suggests exempting a trusted URL or Cloud App, or a Do Not Inspect SSL rule for a trusted application's domain. [zia.troubleshooting-runbook.ssl-block-actions:domain-fronting-solutions]

**HTTP tunnel.** The Not Allowed to Use HTTP Tunnel page says Block Tunneling to Non-HTTP/HTTPS Ports, under Administration > Advanced Settings > HTTP Tunnel Control, is enabled by default for explicit proxy mode, blocks HTTP Connect requests from ports not defined under HTTP/HTTPS services, and does not apply to transparent proxy mode (its examples: IPSec, GRE without Zscaler Client Connector, or PAC file). [zia.troubleshooting-runbook.ssl-block-actions:http-tunnel-block] Which ports the control blocks is in dispute [divergence:zia.troubleshooting-runbook.ssl-block-actions:tunnel-ports-fixed-vs-defined], and so is whether PAC is transparent [divergence:zia.troubleshooting-runbook.ssl-block-actions:pac-explicit-vs-transparent]. The menu path of Advanced Settings in these pages is in dispute [divergence:zia.troubleshooting-runbook.ssl-block-actions:advanced-settings-menu-path]. To check an HTTP tunnel block, find the services forwarded to the HTTP Web Proxy under Advanced Settings, look up their ports in Network Services, and check the Web Insights logs; if the transaction port is not among them, it is correctly blocked. [zia.troubleshooting-runbook.ssl-block-actions:http-tunnel-troubleshoot] Zscaler does not recommend disabling the Block Tunneling option because it is global; instead create a custom network service with the port under TCP Destination Ports, add it under Services Forwarded to HTTP Web Proxy, and add a firewall control policy allowing the port. [zia.troubleshooting-runbook.ssl-block-actions:http-tunnel-solution] For firewall rules to apply to remote user traffic forwarded via Z-Tunnel 1.0 or PAC, enable Enable Firewall for Z-Tunnel 1.0 and PAC Road Warriors. [zia.troubleshooting-runbook.ssl-block-actions:http-tunnel-firewall-zt1]

Sources disagree (name both sides):
- The advanced settings page says Block Tunneling to Non-HTTP/HTTPS Ports restricts CONNECT requests to ports 80 and 443; the runbook says it blocks CONNECT requests from ports not defined under HTTP/HTTPS services, and fixes a block by adding a network service to those services. [divergence:zia.troubleshooting-runbook.ssl-block-actions:tunnel-ports-fixed-vs-defined]
  - zscaler-help: The option restricts HTTP CONNECT requests to the standard HTTP/HTTPS ports 80 and 443.
  - zscaler-help: The option blocks HTTP Connect requests from all ports not defined under HTTP/HTTPS services.
  Impact: Whether adding a port to the HTTP Services list lets CONNECT through depends on which reading holds; the runbook's own fix assumes the services list, not the fixed ports 80 and 443.
- The HTTP tunnel runbook lists a PAC file as an example of transparent proxy mode, while the explicit proxy page describes a browser configured to use a PAC file as explicit mode. [divergence:zia.troubleshooting-runbook.ssl-block-actions:pac-explicit-vs-transparent]
  - zscaler-help: The Block Tunneling option is not applicable to transparent proxy mode, with IPSec, GRE without Zscaler Client Connector, or a PAC file given as examples.
  - zscaler-help: In explicit mode the browser is configured manually, or with a PAC file, to send traffic to a Service Edge.
  Impact: Whether Block Tunneling applies to traffic sent by a PAC file depends on which page is read; the same runbook says the option is enabled by default for explicit proxy mode.
- The runbook pages give the menu path Administration > Advanced Settings, while the XFF runbook page and the July 2026 release summary give Policies > Common Configuration > Advanced > Advanced Settings. [divergence:zia.troubleshooting-runbook.ssl-block-actions:advanced-settings-menu-path]
  - zscaler-help: Block Domain Fronting is under Administration > Advanced Settings.
  - zscaler-help: Advanced Settings, including Domain Fronting, is under Policies > Common Configuration > Advanced > Advanced Settings.
  Impact: The console path to the Advanced Settings options named in these pages depends on which page is read; the pages do not say whether the menu moved or one path is stale.
