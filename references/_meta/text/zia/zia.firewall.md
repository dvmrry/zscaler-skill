# ZIA Firewall Control (zia.firewall)
Also called: firewall control; firewall policy; firewall filtering; firewall vs url filtering; why was my traffic blocked and it is not a url filter rule; ftp control

When traffic is blocked and no URL Filtering rule explains it, Firewall Control is one place to look. It handles flows at the IP and port level, ahead of the web policies: see [Where the firewall sits in the traffic path](kb:zia.firewall.traffic-path). Malware Protection and Advanced Threat Protection are covered in [ZIA Malware Protection](kb:zia.malware-protection) and [ZIA Advanced Threat Protection](kb:zia.atp).

Configuring Firewall policies requires the Firewall Filtering, NAT Control and DNS Control policies, as applicable, and each has its own rules. IPS Control is a separate policy on its own page; it is enabled for locations through the firewall settings and is available only with Advanced Firewall. FTP Control settings inside Firewall are documented separately. [zia.firewall:four-policies]

The Understanding Firewall Capabilities page says the Zscaler cloud provides integrated cloud-based next-generation firewall capabilities that allow granular control over an organization's outbound TCP, UDP and ICMP traffic, and lists these Firewall policies: Firewall Filtering (allow or block specified traffic, and how sessions are logged), NAT Control (destination NAT, redirecting to specific IP addresses or ports), DNS Control (allow or block DNS requests, redirect requests to a different DNS server, or substitute the IP address in a DNS response) and IPS Control (control and protect traffic from intrusion over all ports and protocols using signature-based detection). [zia.firewall:capabilities-policies] Whether IPS Control is counted among the firewall policies differs between two help pages [divergence:zia.firewall:ips-control-counted].

Firewall Control is enabled per location, so a location without it enabled gets no firewall policy enforcement. [zia.firewall:per-location] The firewall can be enabled on a per-location basis: Enforce Firewall Control on the location enables the service's firewall controls, and Enable IPS Control enables its IPS controls (available with Advanced Firewall). The page's prerequisites are the policy resources (Users, Groups, Departments, Locations and Sublocations; Time Intervals; Network Applications, with network application groups created as needed; Network Services, modified to edit services, add custom services and create groups; Source and Destination IPv4 Address Groups; and IPv6 Configuration), the necessary rules defined for each policy, and, if non-standard ports carry HTTP, HTTPS, DNS, FTP, RTSP or PPTP traffic, the service configured to use custom ports for them. [zia.firewall:enable-on-location] A Firewall policy requires the organization to forward its IP traffic from a known location. To apply Firewall policies at the user level, user authentication and surrogate IP must be enabled; otherwise the Zscaler Firewall service applies organization and location policies. [zia.firewall:requirements] Configuring Firewall policies might also need IPv6 configuration to be enabled, source and destination IP groups, modified network services, network application groups and custom ports. [zia.firewall:related-config]

**Ports.** Zscaler listens on default ports for six kinds of traffic: 80 HTTP, 443 HTTPS, 53 DNS, 21 FTP, 554 RTSP and 1723 PPTP. An organization that uses other or additional ports for these types of traffic can configure the service to use custom ports. [zia.firewall:default-ports] To make the service accept traffic from other ports, an admin creates a custom service with the appropriate ports and then, in Advanced Settings, configures the service to accept traffic from those ports: the HTTP Services and HTTPS Services lists under Services Forwarded to HTTP Web Proxy, the DNS Services list under Services Applicable to DNS Transaction Policies, and the FTP Services, RTSP Services and PPTP Services lists under Services Forwarded to FTP Proxy, to RTSP and to PPTP. The Advanced Settings page says the configurations it lists can be modified as needed if the Firewall service is enabled. [zia.firewall:custom-port-services] An Advanced Settings option, when enabled, redirects non-standard port traffic, including HTTP, HTTPS, FTP, DNS, RTSP and PPTP traffic, to the web module for inspection; the page says it can be used to identify and redirect traffic destined to non-standard ports when these ports are not explicitly defined in any network services (custom or predefined). RTSP and PPTP are applicable only with transparent mode connectivity to the Public Service Edge (GRE or IPSec tunnels with no PAC file). [zia.firewall:auto-proxy-redirect-behavior] The Advanced Settings page lists an option named Auto Proxy Forwarding for Non-Defined Ports. [zia.firewall:auto-proxy-option-name] The Advanced Settings option Auto Proxy Forwarding for Non-Defined Ports is the option that redirects non-standard port traffic to the web module for inspection when enabled. [zia.firewall:auto-proxy-non-defined-ports] The capabilities table lists Non-Standard Traffic Redirection, which redirects outbound HTTP, HTTPS, FTP, DNS, RTSP and PPTP traffic destined for non-standard ports to the web proxy, as N/A on Standard Firewall and Supported on Advanced Firewall. [zia.firewall:non-standard-traffic-redirection] For the Auto Proxy feature to redirect web traffic, the Firewall must identify web flows that are HTTP or HTTPS by an Allow rule with HTTP and HTTPS as Network Application conditions (requires Advanced Firewall). The Firewall then registers the IP address and port combination as a web destination in the Public Service Edge where the traffic landed. The next time a session is directed to that destination (from the same user or a user of a different organization) and arrives on the same Service Edge, it is redirected to and inspected by the web module from the first packet; if the traffic is sent to a different Service Edge, the destination must be rediscovered and registered on that Service Edge. [zia.firewall:auto-proxy-discovery] What happens to traffic on a non-default web port when that option is off is open [gap:zia.firewall:custom-port-handling].

**FTP Control.** [FTP Control settings are configured within Firewall: the firewall policy help points to FTP Control for them.](kb:zia.ftp-control.scope:ftp-sits-in-firewall) [By default the service does not allow users from a location to upload or download files from FTP sites that use FTP over HTTP; only native FTP traffic is allowed. With FTP Control, Zscaler provides access control for both native FTP and FTP over HTTP.](kb:zia.ftp-control.scope:ftp-default) [The service supports passive FTP only. If the destination server does not support passive FTP, the service shows an alert message in the user's browser.](kb:zia.ftp-control.scope:ftp-passive-only) [URL Filtering rules take precedence over the FTP Control policy.](kb:zia.ftp-control.scope:ftp-url-filtering-precedence) The settings are described in [ZIA FTP Control](kb:zia.ftp-control).

What to check:
1. Whether Firewall Control is enabled for the location.
2. Whether the tenant is licensed for the criterion the rule needs.
3. Whether the traffic is on a port the service treats as HTTP, DNS or FTP.
