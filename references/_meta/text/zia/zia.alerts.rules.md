# Security & UEBA alert rules: alert types, triggers, exceptions and webhooks (zia.alerts.rules)
Also called: alert rules; configuring an alert rule; ueba alert rule; alert exceptions; webhooks; inline alert types; api alert types; place user in group

Alert rules raise the alerts shown in [Security & UEBA alerts: ongoing alerts, alert history and alert details](kb:zia.alerts.security-ueba); the email alert definitions are in [ZIA email alerts: event classes, thresholds, severities, subscriptions and the resend interval](kb:zia.alerts). The Alert Rules page gives a graphical representation of the top 5 security and UEBA alerts by the rule type and the number of rules enabled or disabled, and lists the preconfigured rules in a table where the alert can be enabled or disabled. The table shows Alert Class (UEBA or Security), Applies To (organization or a location), Recipients (the number of recipients receiving the triggered alert) and Alert Type. [zia.alerts.rules:rules-page] When adding an alert rule, the Alert Name has a maximum length of 31 characters, and the Alert Class is Security by default. [zia.alerts.rules:definition]

**Security rules.** A security alert rule's event type is selected from Advanced Threat Protection, Malware or Sandbox. The time interval can be 10 minutes, 15 minutes, 30 minutes, 45 minutes or 1 hour, and filters can be applied to Department, Location, System Impacted and Users. The rule triggers when the criteria have been met at least a set number of times in the last set number of time intervals, and Send Alert Update every set number of intervals can be enabled. [zia.alerts.rules:security-trigger]

**UEBA rules.** For a UEBA alert rule the page's drop-down offers Access, Data or Privilege, and the alert types depend on the selected event type, with each channel type having different alert types; the channel is chosen between Inline and API. The alert trigger criteria fields vary based on the selected alert type and are not available for all alert types; they include No of Failed Logins, Tenants, a number of files that triggers the rule for bulk upload or download of data, Doc Type, DLP Engines (one or multiple), a data type that is All Data Types by default, a count for bulk sharing of data, Activity and Countries. [zia.alerts.rules:ueba-trigger] For the Inline channel, the alert type table lists uploads in a short period of invoices, tax documents, resumes, medical documents, real estate documents, legal documents, court form documents, technical documents, transportation and motor documents, immigration documents, insurance documents, corporate finance documents and corporate legal documents; data exfiltration by password protected or encrypted docs; upload to and from high risk countries; bulk upload and bulk download of sensitive data; and Bulk Activity, which lets multiple activities for the SaaS Security API be tracked for a user. [zia.alerts.rules:inline-alert-types] For the API channel, the alert type table lists Impossible Travel, Multiple Failed Logins, Bulk Download of Data, Bulk Upload of Data, Code Repo Shared Externally, Code Repo Made Public, Bulk Files Delete, Bulk Share of Data and Excessive Admin Activities. [zia.alerts.rules:api-alert-types] Whether these names match the provider's closed list is open [gap:zia.alerts.rules:terraform-name-match].

**Actions, recipients and exceptions.** For UEBA alerts the action is Trigger an Alert or Place user in group, the latter with a User Group and Time Interval; recipients can be a webhook selected from the list and email addresses or email aliases. [zia.alerts.rules:ueba-actions-recipients] What placing a user in a group does is open [gap:zia.alerts.rules:place-user-in-group]. A UEBA alert provides the option to exempt multiple users from an alert rule; by retaining specific users in the exceptions list, the alert does not evaluate them against the traffic for the selected applications. [zia.alerts.rules:exceptions]

**Webhooks.** Webhook configuration allows alerts for the configured events in the alert rule to be delivered to third-party applications (for example ServiceNow, Splunk) for incident management. A webhook's Name is displayed when configuring the alert rule; its Status can be set to Disabled and is Enabled by default; its URL is that of the webhook provider; its Authentication Type is Basic (Username and Password) or Token (Bearer Token); and Test Webhook checks the configuration. [zia.alerts.rules:webhooks] What a webhook delivery carries is open [gap:zia.alerts.rules:webhook-delivery].

What to check:
1. Which channel and event type the UEBA rule uses, since the alert types depend on them.
2. Whether the user is on the rule's Exceptions list before concluding the rule did not evaluate them.
