# Zscaler-managed Dedicated IP: provisioning, IP addresses, gateways and migration from Source IP Anchoring (zia.forwarding-control.dedicated-ip)
Also called: dedicated ip; zscaler-managed dedicated ip; dedicated source ip; dedicated ip gateway; dedicated ip forwarding rule

Traffic through Zscaler has the client device IP address translated by NAT into a Zscaler-managed IP address from a common pool before it is forwarded to the destination, because of Zscaler's proxy architecture. Where the source IP must be fixed and unique for an organization, dedicated IP addresses can be self-managed or provisioned by Zscaler, and Zscaler recommends them only for applications that mandate IP-based authentication. [zia.forwarding-control.dedicated-ip:common-pool-nat] Zscaler offers four solutions for dedicated source IP addresses: Zscaler-Managed Dedicated IP, Customer-Managed Dedicated IP (or Source IP Anchoring), Private Service Edge for Internet & SaaS (ZIA) and Virtual Service Edge for Internet & SaaS (ZIA). [zia.forwarding-control.dedicated-ip:solutions]

**Provisioning.** The Zscaler Account team enables the Dedicated IP feature for an Internet & SaaS tenant, given a list of Zscaler data centers where dedicated IP addresses are needed. An organization is assigned two IP addresses for each subscribed data center, which can be increased based on entitlement, and dedicated IP gateways are configured after provisioning. [zia.forwarding-control.dedicated-ip:provisioning] Zscaler recommends subscribing to the Dedicated IP service at a minimum of two Zscaler data centers for redundancy. [zia.forwarding-control.dedicated-ip:two-data-centers] The IP Addresses page shows and downloads the IP addresses dedicated to the organization at the Zscaler data centers it chooses, can download all available data center details to a CSV file, and lists the IPv4 address of the data center. [zia.forwarding-control.dedicated-ip:ip-addresses-page]

**Gateways.** Only data centers available on the IP Addresses page, those with a dedicated IP address assigned to the organization, can be selected as a dedicated IP gateway's primary and secondary data centers. By default the primary data center forwards all traffic and the secondary acts as a backup. Selecting Auto lets the Zscaler service assign a data center based on geographical proximity to the Public Service Edge servicing the traffic, and a default gateway is created automatically when dedicated IP addresses are allocated. [zia.forwarding-control.dedicated-ip:gateway-config] The number of gateways per tenant is open [gap:zia.forwarding-control.dedicated-ip:gateway-limit], and so is how Auto relates to the primary and secondary data centers [gap:zia.forwarding-control.dedicated-ip:auto-vs-primary]. The forwarding method that uses a gateway is in [Forwarding methods and their required fields](kb:zia.forwarding-control.methods).

**Migrating from Source IP Anchoring.** Zscaler recommends starting a migration from Source IP Anchoring with a small controlled group of users. A DNS Control rule that allows DNS traffic for the target applications must be placed above the Forward to ZPA Resolver rules, and is optional if the applications are resolved within the organizational infrastructure. The dedicated IP forwarding rules get a higher rule order (a lower rule number) than the existing Source IP Anchoring forwarding rule, so they are evaluated first. To revert, the DNS rule and the dedicated IP forwarding rule are disabled, and after all users have moved and traffic is stable the Private Access (Source IP Anchoring) forwarding rules are disabled and the associated App Connectors deprovisioned. [zia.forwarding-control.dedicated-ip:migration-steps] Whether the resolver rules the article names are the predefined ones is open [gap:zia.forwarding-control.dedicated-ip:resolver-rule-names].

Not known (open gaps):
- How many dedicated IP gateways a tenant can have [gap:zia.forwarding-control.dedicated-ip:gateway-limit]: settled by source-read or support-ticket
- How Auto relates to the primary and secondary data centers of a dedicated IP gateway [gap:zia.forwarding-control.dedicated-ip:auto-vs-primary]: settled by lab-test or support-ticket
- Whether the migration article's Forward to ZPA Resolver rules are the predefined DNS Control resolver rules [gap:zia.forwarding-control.dedicated-ip:resolver-rule-names]: settled by source-read or tenant-data
