# Surrogate IP: mapping a private IP to an authenticated user (zia.authentication.surrogate-ip)
Also called: surrogate IP; IP surrogate; surrogate_ip; idle_time_in_minutes; surrogate_ip_enforced_for_known_browsers; surrogate_refresh_time_in_minutes; surrogate_refresh_time_unit; display_time_unit; enforce_surrogate_ip_for_windows_app; idle time to disassociation; wrong user attribution; NAT surrogate; VDI surrogate

Surrogate IP is the answer to "this user is logged in, so why was this request treated as the location?" It is a per-location opt-in. Surrogate IP maps a user to a private IP address so the user's policies, rather than the location's, apply to traffic that cannot be authenticated: applications that do not support cookies, HTTPS that is not decrypted, and unknown user agents. All private IPs a user browses from are mapped to the user, and the transactions are attributed to the user in the logs. The mapping is created when the user authenticates. [zia.authentication.surrogate-ip:definition] With Surrogate IP a user authenticated in one browser is not asked again in another browser or a non-browser application; with it disabled, authenticating in Chrome then opening Firefox prompts again. Zscaler recommends it for non-browser apps such as Windows Store apps. [zia.authentication.surrogate-ip:browser-benefit]

**How the mapping behaves.** A private IP maps to only one user at a time. The mapping is kept until the configured idle time ends, the user logs out of the session or the service, or another user sends authenticated transactions from the same IP, which remaps it to the new user. [zia.authentication.surrogate-ip:one-user-at-a-time] If the mapping for an IP changes more than 3 times in a minute (three different users authenticating from the same private IP within a minute), the service stops mapping users to that IP for 5 minutes and applies the location's policies to the transactions that cannot be authenticated during that time. [zia.authentication.surrogate-ip:churn-disables]

**What it cannot work with.** Surrogate IP requires one IP per user as the service sees it, so NAT cannot be used: all users behind it look like one address. Supported forwarding is a GRE or IPSec tunnel without NAT, forward proxy chaining with XFF forwarding turned on for the location or sublocation, or a dedicated proxy port, and Enforce Authentication must be on for the location or sublocation. [zia.authentication.surrogate-ip:no-nat] On a location with at least one subscribed dedicated proxy port, Surrogate IP maps the public IP address rather than the private one to the user, so user-level policy can apply to remote user traffic that cannot be authenticated. [zia.authentication.surrogate-ip:dedicated-port] Zscaler does not recommend Surrogate IP with multi-session VDI: every user on the machine shares one private IP, so transactions can be attributed to the wrong user in the logs. [zia.authentication.surrogate-ip:no-vdi] Sublocations associated with a location do not inherit its IP Surrogate setting. [zia.authentication.surrogate-ip:not-inherited]

**Configuring it.** The Terraform location resource carries the Surrogate IP configuration as surrogate_ip, idle_time_in_minutes (user mapping idle time in minutes) with display_time_unit, surrogate_ip_enforced_for_known_browsers, and surrogate_refresh_time_in_minutes with surrogate_refresh_time_unit. Both unit fields accept MINUTE, HOUR or DAY. [zia.authentication.surrogate-ip:location-fields] Enforce Surrogate IP for Known Browsers makes the service authenticate known browsers from the existing IP-to-user mapping even on sites that support cookies, so the browser does not complete HTTP redirects for every transaction (useful on high-latency links). The service authenticates known browsers from the existing mapping rather than waiting for a cookie. When off, browsers are authenticated by cookie or the other configured methods. Supported Authentication Methods must then be Cookie or Cookie and Proxy, and Basic authentication requires Cookie and Proxy. [zia.authentication.surrogate-ip:known-browsers] The refresh time for re-validating surrogacy must be shorter than the DHCP lease time, otherwise wrong user policies might be applied, and Zscaler recommends a refresh shorter than the Idle Time to Disassociation. [zia.authentication.surrogate-ip:refresh-vs-lease]

**What Terraform rejects.** On create and update, the provider rejects: surrogate_ip without an idle time; surrogate_ip without auth_required; enforcing for known browsers without surrogate_ip; and enforcing for known browsers when both the refresh minutes are 0 and the refresh unit is empty. [zia.authentication.surrogate-ip:provider-checks] The Surrogate IP dependency checks run inside the provider's location create and update functions, not in a plan-time diff hook; the plan-time CustomizeDiff on the location resource checks only the manual group exclusion. [zia.authentication.surrogate-ip:provider-checks-apply-time] Other provider behavior for locations is in [ZIA Terraform resource fields that are not sent, not read back, or sent wrongly](kb:zia.terraform.field-fidelity).

**Windows app traffic.** The provider's advanced settings resource has `enforce_surrogate_ip_for_windows_app`, described as enforcing Surrogate IP authentication for Windows app traffic. [zia.authentication.surrogate-ip:windows-app-flag] In Advanced Settings, under Windows App Traffic Authentication, Enforce Surrogate IP Authentication exists because some Windows 8 Metro apps use Internet Explorer as their user agent but do not support cookies or redirects, so the service does not allow traffic to these sites. Enabling the option allows the service to use the user-to-device mappings to apply the appropriate user policies to the traffic of the top Windows 8 Metro apps, and the Surrogate IP feature must be enabled. [zia.authentication.surrogate-ip:windows-app-setting] The provider's enforce_surrogate_ip_for_windows_app flag corresponds to the console's Enforce Surrogate IP Authentication option under Windows App Traffic Authentication, which the page describes for Windows 8 Metro apps. [zia.authentication.surrogate-ip:windows-app-flag-is-metro] The page that holds the setting is routed in [ZIA Advanced Settings page: its sections, three settings explained here, and where other sections are routed](kb:zia.advanced-settings).

The ZIA traffic forwarding reference architecture recommends enabling Surrogate IP for all fixed site locations and for all transparent forwarding types. [zia.authentication.surrogate-ip:fixed-site-recommendation]

The reference architecture states a lower churn threshold than the help [divergence:zia.authentication.surrogate-ip:churn-threshold].

What to check:
1. The forwarding method, since NAT in the path leaves users without one IP each.
2. Whether Enforce Authentication is on for the sublocation the traffic maps to.
3. Whether the source is a shared or multi-session VDI address.
4. Whether the idle and refresh times are set against the DHCP lease.
5. Whether devices that cannot authenticate, such as printers or servers, sit in a sublocation without Enforce Authentication.
