# DNS Control actions and what each API action requires (zia.dns-control.actions)
Also called: dns control actions; redirect request; redirect response; REDIR_REQ; REDIR_RES; REDIR_ZPA; BLOCK_WITH_RESPONSE; block_response_code; redirect_ip; dns_gateway required; edns_ecs_object

The console's rule actions are Allow, Block, Block with Response Code, the Redirect Request variants (keep sender protocol, using DoH, using TCP, using UDP), Redirect Response, and Resolve by ZPA (resolving Private Access application domain names); together they allow or block traffic, redirect requests to specific DNS servers, or redirect users by overwriting DNS responses. [zia.dns-control.actions:console-actions] Plain Block is silent, and which API enum value it maps to is open [gap:zia.dns-control.actions:block-returns-nxdomain]. The current console actions are Allow, Block (silent), Block with Response Code, Redirect Request & Keep Sender Protocol, Redirect Response, Redirect Request Using DoH, Using TCP, Using UDP, and Resolve by ZPA. [zia.dns-control.actions:console-actions-current] Block with Response Code supports response codes 1 (FormErr), 2 (ServFail), 3 (NXDomain), 4 (NotImp) and 5 (Refused). [zia.dns-control.actions:response-codes] Zscaler advises using NXDomain only with request or response category criteria, avoiding catch-all categories such as Miscellaneous, preferring Refused or ServFail otherwise, and never applying a response code to a whole DNS request type (for example blocking all A or AAAA with NXDomain), which would likely cause a DNS outage. [zia.dns-control.actions:nxdomain-caution]

**Redirects.** Redirect Response replaces the resolved IP address in the DNS response with a configured IP address; it acts on the response side but can match request-side or response-side conditions. [zia.dns-control.actions:redirect-response] Redirect Request Using DoH translates UDP or TCP requests to DoH; Using TCP and Using UDP accept DoH or their own protocol but do not translate UDP-to-TCP or TCP-to-UDP; and the DNS gateway list is limited to gateways configured for that protocol. [zia.dns-control.actions:redirect-protocol-translation] Resolve by ZPA applies only to Private Access application segments that have Source IP Anchoring enabled, and takes an IP pool configured for location or remote-user traffic. [zia.dns-control.actions:resolve-by-zpa-scope] Logging is fixed at Full. Web EUN works with Block; Client Connector EUN works with Block, Block with Response Code and Redirect Response; with both on, Web EUN takes precedence. [zia.dns-control.actions:logging-and-eun]

The API action enum has ten values: `ALLOW`, `BLOCK`, `REDIR_REQ`, `REDIR_RES`, `REDIR_ZPA`, `REDIR_REQ_DOH`, `REDIR_REQ_KEEP_SENDER`, `REDIR_REQ_TCP`, `REDIR_REQ_UDP`, `BLOCK_WITH_RESPONSE`. [zia.dns-control.actions:api-enum] The commented-out validator requires: `redirectIp` for REDIR_RES; a `zpaIpGroup` with an ID for REDIR_ZPA; a `dnsGateway` (with both ID and Name) for REDIR_REQ_DOH, REDIR_REQ_TCP and REDIR_REQ_UDP; and both a `dnsGateway` (ID and Name) and non-empty `protocols` for REDIR_REQ_KEEP_SENDER. [zia.dns-control.actions:validator-requirements] The Go SDK contains a per-action field validator for DNS rules, but it is commented out; the live Create and Update call no validator, so the SDK does not enforce the dependencies below. [zia.dns-control.actions:validator-inactive] Intended use cases for the redirect actions are open [gap:zia.dns-control.actions:redirect-use-cases]. The SDK describes `dnsGateway` as used when the action redirects DNS requests to an external DNS service, and `zpaIpGroup` as the ZPA IP pool used to resolve ZPA application domains to ephemeral IPs. [zia.dns-control.actions:field-comments] `ednsEcsObject` is described as the EDNS ECS object which resolves the DNS request, and the validator ties it to no action. [zia.dns-control.actions:edns-general]

**Block with a response.** `blockResponseCode` holds the DNS response code sent to the client when the action is configured to block and send a response code. [zia.dns-control.actions:block-response-code] The API format of the response codes is open [gap:zia.dns-control.actions:block-response-code-values], and the SDKs word the trigger differently [divergence:zia.dns-control.actions:block-response-wording].

Whether redirectIp applies only to REDIR_RES [gap:zia.dns-control.actions:redirect-ip-binding], whether plain REDIR_REQ needs a gateway [gap:zia.dns-control.actions:redir-req-gateway], and whether ednsEcsObject must accompany zpaIpGroup [gap:zia.dns-control.actions:edns-ecs-zpa-pairing] are all open.

DoH-specific actions and the DoH protocol value are discussed in [DNS over HTTPS in DNS Control](kb:zia.dns-control.doh); the ZPA resolver rules are in [Predefined DNS Control rules and the ZPA resolvers](kb:zia.dns-control.predefined-rules) (no page states which API action they use). Wire keys and client behavior: [DNS Control rule resource over the API](kb:zia.dns-control.api-rules).

What to check:
1. Whether the companion field the action needs is set, since the SDK validator that checks it is commented out.
2. Which action sends the block response code, since the SDKs word the trigger differently.
3. Whether a Block returns a response code or is silent, as the console describes Block.

- [zia.dns-control.actions:edns-general] Tier B: The 'ties to no action' half rests on the absence of any ednsEcsObject clause in the commented-out validator.

Sources disagree (name both sides):
- Which action sends the block response code [divergence:zia.dns-control.actions:block-response-wording]
  - sdk-python: The response code is sent when the action is BLOCK.
  - sdk-go: The code is sent when the action is 'block and send response code', which reads as BLOCK_WITH_RESPONSE.
  Impact: A rule with action BLOCK and a blockResponseCode may or may not return that code; the enum has a separate BLOCK_WITH_RESPONSE value. Do not promise a client-visible response code from BLOCK.
