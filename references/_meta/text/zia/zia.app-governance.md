# 3rd-Party App Governance: governing third-party apps, add-ons and extensions connected to SaaS platforms, and its portal, roles and dashboard (zia.app-governance)
Also called: 3rd-party app governance; third-party app governance; apptotal.zscaler.com; app governance portal

3rd-Party App Governance discovers, manages, reduces and controls the attack surface that third-party apps, extensions and add-ons introduce to corporate SaaS applications, and keeps an app inventory showing what is connected, the risks posed and how each app is used. [zia.app-governance:what-it-is] It classifies apps as sanctioned or unsanctioned, alerts on drift in app usage or security posture, notifies when apps are introduced in violation of corporate policy or compliance, and can run remediation such as banning an app or revoking its token manually or automatically, with end users involved in review. It gives visibility over first-, second- and third-party API integrations. [zia.app-governance:capabilities] Its connection to SaaS Security (the data-at-rest scanning hub) is in [ZIA CASB (SaaS Security API): scanning data at rest in sanctioned SaaS applications](kb:zia.casb), and the out-of-band CASB portfolio view is [CASB: ZIA inline controls plus out-of-band SaaS security, not one product](kb:portfolio.casb).

**Getting in.** The 3rd-Party App Governance Admin Portal is reached upon invitation, at https://apptotal.zscaler.com/. The configuration guide's prerequisite is authorization to access the portal, with the Zscaler Account team as the contact. [zia.app-governance:portal-access] The Admin Portal page says authentication is performed using Google, Azure AD federation or Okta, that passwords are not supported, and that SAML federation with the customer's own identity provider is supported on enterprise tiers. [zia.app-governance:sign-in-methods] The sign-in providers the page names disagree [divergence:zia.app-governance:sign-in-providers]. From the Zscaler Admin Console the portal opens by SSO for subscribers to the 3rd-Party App Governance service, at Analytics > Reports > SaaS Security Report > 3rd-Party App Governance. It also requires access to the Data Loss Prevention (DLP) feature and a 3rd-Party App Governance Admin or a Super Admin role, and with a subscription it can be reached from several locations on the SaaS Security Report and SaaS Assets Report. [zia.app-governance:admin-console-sso] The Admin Console report page names a different license for the same path [divergence:zia.app-governance:report-license-gate].

**The Admin Console report page.** The 3rd-Party App Governance Report identifies all the third-party applications that employees are using, for the tenant selected under the Tenant option. With the Advanced Posture Management license enabled the user is redirected to the 3rd-Party App Governance Admin Portal; without it, the report page is visible with an upgrade banner. [zia.app-governance:report-gate] The report's application states are Discovered (discovered, but no action taken yet), Allowed (explicitly allowed), Blocked (explicitly blocked), Restricted (an admin has allowed the application to specific users) and Reauthorized. [zia.app-governance:report-states] On the report's application page an admin can allow the use of the application for all users, restrict it to specific users, or revoke it for all users (the Blocked state), and can download a CSV file with all the permissions listed. [zia.app-governance:report-actions]

**Roles and licensing.** The page lists three predefined roles that can be assigned to users. Admin is the default super admin role with full access including user management, policy editing, integrations and security actions. User can edit policies, upload apps, export data and acknowledge findings but cannot manage platform-wide settings or integrations. Viewer can view data and export reports but cannot take action or make changes. Role assignments are managed through Zscaler Support. [zia.app-governance:roles] How the Admin Console role maps to these roles is open [gap:zia.app-governance:role-mapping]. Connecting a platform, alerting through outbound integrations such as Slack, the automated workflow in policies (supported on Google and partially on Microsoft) and the contents of the App Panel each depend on the 3rd-Party App Governance license. [zia.app-governance:license-dependent] How this license relates to Advanced SSPM is open [gap:zia.app-governance:license-relationship]. The portal has an Audit Log icon that shows changes made by users and admins, and a Reports menu with predefined reports and custom reports. [zia.app-governance:portal-audit-log]

**The dashboard.** The dashboard contains 7 predefined widgets with information about potentially risky apps and their usage among users. When first accessed it is empty until a platform is connected or apps are searched for and added manually. [zia.app-governance:widgets] The integrations banner has an All button clicked by default, so the dashboard shows the status of all integrations, and it appears on all pages of the portal. It can filter platforms by labels such as Legacy, Staging and Production, and shows a Pending icon while onboarded tenants are being processed and an Error icon on an error. Adding or managing labels needs user or admin permissions. [zia.app-governance:integrations-banner] The Overview widget shows the number of active apps, the number of apps classified as risky, the number of users affected by risky apps and the number of deactivated apps, with a filter for the number of active apps over a time period, and a breakdown of apps by whether they are potentially harmful, dormant or overprivileged. [zia.app-governance:overview-widget] The dashboard defines findings as security posture issues identified in an app that indicate their risk and severity, lists the latest app activities ordered by severity as Top Security Events, and says most insights concern breaches, credentials exposure or any event that puts the app's or publisher's users at risk. [zia.app-governance:highlights-widget] Drop-down menus on the dashboard display apps by either Severity or Usage, apps by Risk Score, Popularity, High Privilege or Low Usage, and users by VIP, Privileged, Apps or Findings. [zia.app-governance:map-and-lists] How far back the over-time graphs and filters reach is open [gap:zia.app-governance:retention].

  - zscaler-help: Authentication is performed using Google, Azure AD federation, or Okta.

- The Admin Console route into the 3rd-Party App Governance Admin Portal is gated on a 3rd-Party App Governance subscription by the portal page and on the Advanced Posture Management license by the report page. [divergence:zia.app-governance:report-license-gate]
  - zscaler-help: The portal page gates the SSO route from Analytics > Reports > SaaS Security Report > 3rd-Party App Governance on having subscribed to the 3rd-Party App Governance service.
  - zscaler-help: The report page redirects to the portal from Analytics > Reports > SaaS Security Report > 3rd-Party App Governance when the Advanced Posture Management license is enabled.
  Impact: Which license opens the portal from the Admin Console is not settled, which bears on the open license-relationship gap here and in zia.sspm; a licensing answer has to name both.
