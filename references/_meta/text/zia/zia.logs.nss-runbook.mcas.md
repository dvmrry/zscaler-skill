# NSS runbook: validating an MCAS feed and its curl checks (zia.logs.nss-runbook.mcas)
Also called: MCAS Feed; Microsoft Cloud App Security feed troubleshooting

**Validating the feed.** To validate an MCAS feed, the Admin Console Test under Partner Integrations > Microsoft Cloud App Security checks that URLs sync (admin needs write access), cat /sc/conf/zbridge-mcas.properties shows the config, and getsminfo=nss_feed_info_all shows the feed. [zia.logs.nss-runbook.mcas:portal-test-and-config] Admins might need to update MCAS configurations after changes on the Microsoft side; if a change errors or does not reach zbridge-mcas.properties, the runbook says to contact Zscaler Support. [zia.logs.nss-runbook.mcas:config-change-support] The runbook checks that the zbridge service is running with /sc/bin/smctl.sh on the NSS server. [zia.logs.nss-runbook.mcas:zbridge-service]

**Curl checks.** For token-based MCAS authentication, the runbook has the admin copy the MCAS domain and Authorization token from zbridge-mcas.properties and run a curl against /api/discovery_block_scripts/ expecting 200 OK with the list of MCAS applications. [zia.logs.nss-runbook.mcas:token-curl] For OAuth MCAS authentication, the runbook has the admin copy the configuration values from zbridge-mcas.properties and POST to the MCAS authorization URL with scope, client_id, client_secret and grant_type=client_credentials. [zia.logs.nss-runbook.mcas:oauth-curl] The MCAS curl should return 200 OK (or the Bearer Token for OAuth); any other response indicates an issue, with common causes a configuration issue, URLs blocked by an intermediate device, or the MCAS server dropping the connection due to an unexpected cert or header value. [zia.logs.nss-runbook.mcas:curl-expected-and-causes]

**Capture and escalation.** The runbook says to take a packet capture on the tap interface (service interface) to see the conversation between NSS and MCAS, to contact Zscaler Support if there are no anomalies but the MCAS logs continue to be missing, and that /sc/log/zbridge.log contains event logs related to the MCAS feed. [zia.logs.nss-runbook.mcas:capture-and-escalate]
