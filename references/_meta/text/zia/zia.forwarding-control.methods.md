# Forwarding methods and their required fields (zia.forwarding-control.methods)
Also called: forward_method; forwarding method; ZPA ECZPA DIRECT PROXYCHAIN; ENATDEDIP; GEOIP; dest_addresses cannot be set

Every rule has one forward method, and the method decides which other fields are required, allowed or ignored. The console offers these forwarding methods: ZPA (to a Private Access App Connector through the Private Access gateway), Direct, Proxy Chaining (to a third-party proxy service), Dedicated IP (through a dedicated IP gateway) and GeoIP (source IP address mapped to the location of the originating request). [zia.forwarding-control.methods:console-methods] Direct forwards the traffic to the destination server using the Zscaler service IP address. [zia.forwarding-control.methods:direct-meaning]

The Terraform provider accepts ten `forward_method` values: INVALID, DIRECT, PROXYCHAIN, ZIA, ZPA, ECZPA, ECSELF, DROP, ENATDEDIP and GEOIP. The Python SDK's add-rule docstring lists the same ten; its update-rule docstring lists only the first eight. [zia.forwarding-control.methods:enum-values] The Terraform provider's accepted forward_method values include INVALID, ZIA, ECZPA, ECSELF and DROP, none of which is among the methods the console offers (ZPA, Direct, Proxy Chaining, Dedicated IP, GeoIP). [zia.forwarding-control.methods:provider-exceeds-console] The published contract disagrees on those values [divergence:zia.forwarding-control.methods:contract-enum]. The Terraform documentation describes ENATDEDIP as the Dedicated IP method and GEOIP as Zscaler automatically selecting the nearest data center from the data center mappings on the Geo IP page. The documentation also says ZPA requires `zpa_gateway` and `zpa_app_segments`, and PROXYCHAIN requires `proxy_gateway`. [zia.forwarding-control.methods:tf-doc-meanings] A Dedicated IP rule chooses a dedicated IP gateway; selecting the Default gateway lets the Zscaler service pick the optimal data center. The default gateway is created when dedicated IP addresses are allocated, cannot be edited or deleted, and directs traffic to the geographically nearest data center that has a dedicated IP address assigned. [zia.forwarding-control.methods:dedicated-ip-gateway]

What ZIA, DROP, ECSELF and INVALID do is open [gap:zia.forwarding-control.methods:method-semantics], and what happens when no rule matches is open [gap:zia.forwarding-control.methods:no-match-default].

**Terraform plan-time checks.** At plan time, for rules of type FORWARDING, the provider requires `zpa_app_segments` and `zpa_gateway` when the method is ZPA; requires `proxy_gateway` when it is PROXYCHAIN; and rejects `zpa_gateway`, `proxy_gateway`, `zpa_app_segments`, `zpa_application_segments` and `zpa_application_segment_groups` when it is DIRECT (PROXYCHAIN rejects the ZPA ones). These checks do not run for other methods or other rule types. [zia.forwarding-control.methods:provider-field-requirements] The provider rejects `dest_addresses`, `dest_countries` and `dest_ip_categories` on any rule whose method is not PROXYCHAIN, DIRECT, ENATDEDIP or GEOIP. That excludes ZIA, ZPA, ECZPA, ECSELF, DROP and INVALID, not only ZPA, and the check is outside the type-FORWARDING condition. [zia.forwarding-control.methods:dest-fields-gate] The ZPA gateway itself is in [The Private Access gateway object in ZIA](kb:zia.forwarding-control.zpa-gateway). ZPA rules reference application segments through `zpa_app_segments`; ECZPA rules (Zscaler Cloud Connector) use `zpa_application_segments` and `zpa_application_segment_groups` instead. The published API contract carries all three. [zia.forwarding-control.methods:eczpa-selectors] The provider never sends the ECZPA or IPv6 selectors it accepts: [ZIA Terraform resource fields that are not sent, not read back, or sent wrongly](kb:zia.terraform.field-fidelity).

Criteria and ordering are in [Forwarding Control rule criteria, limits and ordering](kb:zia.forwarding-control.rules).

What to check:
1. When a plan is rejected, check the rule's method first, then the field named in the error.
2. When a rule exists but forwards unexpectedly, read its `forwardMethod` from the tenant before reasoning about its other fields, since the method decides which of them are required, allowed or ignored.

Sources disagree (name both sides):
- Whether ENATDEDIP and GEOIP are valid forwardMethod values [divergence:zia.forwarding-control.methods:contract-enum]
  - api-specs: The published ZIA OpenAPI contract for creating a forwarding rule lists eight values and not ENATDEDIP or GEOIP.
  - tf-zia: The Terraform provider accepts ten values, adding ENATDEDIP and GEOIP, and the console offers Dedicated IP and GeoIP methods.
  Impact: Do not treat ENATDEDIP or GEOIP as invalid because the contract omits them, nor assume the API accepts every value the provider validates. Read existing rules from the tenant to see which values occur.
