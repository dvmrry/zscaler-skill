# What stops working when traffic bypasses SSL/TLS inspection (zia.ssl-inspection.bypass-impact)
Also called: ssl bypass impact; dlp not working https; why wasn't this caught; features that need ssl inspection; sandbox ssl bypass; malware not detected https

Exempting traffic from inspection is a decision about every feature that reads content, not only about TLS. These ZIA security features need decrypted traffic to work on encrypted transactions: Anti-Virus/Malware, Cloud Sandbox, Advanced Threat Prevention, Isolation, Data Loss Prevention, File Type Control, Inline CASB and the Intrusion Prevention System. [zia.ssl-inspection.bypass-impact:dependent-features] Zscaler cannot see inside uninspected traffic, so embedded threats, inbound or outbound, are not detected. [zia.ssl-inspection.bypass-impact:uninspected-blind]

When a dependent feature missed something on HTTPS, check whether the traffic matched a Do Not Inspect rule before looking at the feature's own policy. [zia.ssl-inspection.bypass-impact:check-ssl-first]

**What still applies without decryption.**
- On Do Not Inspect with Evaluate Other Policies, URL Filtering and Cloud App Control still evaluate the destination domain, so a block on the domain fires while path-, method- and payload-based rules do not; Do Not Inspect with Bypass Other Policies skips both entirely. [zia.ssl-inspection.bypass-impact:evaluate-variant-keeps-domain-checks] The behavior of each variant is in [Where SSL inspection sits in ZIA web policy evaluation (the two passes)](kb:zia.ssl-inspection.pipeline); the URL Filtering criteria that need decryption are in [How URL Filtering rule criteria combine](kb:zia.url-filtering.criteria).
- Whether policy is evaluated at all for traffic on the global SSL bypass list is a separate tenant switch: [Advanced URL Filtering settings that change outcomes](kb:zia.url-filtering.advanced-settings).

**Google CAPTCHA and geolocation.** A user entering a search string in google.com may get a CAPTCHA screen to complete before search results are displayed. Zscaler forbids use of its proxy services for automated testing in its contract, but some customers doing automated queries on Google trigger a CAPTCHA response, which can affect other users sending traffic through the same Zscaler IP address. Zscaler recommends enabling SSL/TLS Inspection so it can insert an XFF header in each request, which allows Google to isolate the offending client without affecting other clients; it should be enabled for either google.com or the Web Search URL category. [zia.ssl-inspection.bypass-impact:google-captcha] A Google geolocation error is a Google homepage and search results that do not match the user's location, for example a Miami user shown Spanish results and https://google.com.mx. The page says these occur when Zscaler data center IP ranges are incorrectly interpreted by Google's Geo-IP mapping system, which Zscaler addressed by sharing its IP ranges with Google, barring a rare corruption of the Geo-IP system. It also says that in certain regions they occur when customers send data to Zscaler from countries where Zscaler has no data center, in which case Google returns content based on the IP address of the Zscaler data center. For this case Zscaler recommends that customers turn on SSL/TLS Inspection, which allows Google to read a customer's actual IP address along with the data center IP address and return geolocalized content, and the page says customers who cannot enable SSL/TLS can run into this issue. Users can use Google's NCR plugin for Chrome to bookmark google.com/ncr, and inconsistencies can be logged with Google or taken up with the ISP at the Google ISP Portal. [zia.ssl-inspection.bypass-impact:google-geolocation] Zscaler and Google are in constant communication about Zscaler's multi-tenant data center footprint and IP address ranges, the Zscaler Operations team performs automated monitoring for Google reCAPTCHA and geolocation issues, and Zscaler has an agreement with Google to use XFF headers to isolate offending Zscaler clients. The page says its suggestions reduce the likelihood of these issues but might not completely resolve them. [zia.ssl-inspection.bypass-impact:google-mitigations]

Sandbox coverage for files delivered over HTTPS is in [ZIA Sandbox](kb:zia.sandbox). For deciding what to exempt in the first place, see [Writing SSL/TLS inspection exemptions without exempting too much](kb:zia.ssl-inspection.exemptions); for what cannot be inspected regardless, [What SSL/TLS inspection cannot inspect: pinned apps, client certs, QUIC, BYOD, IoT](kb:zia.ssl-inspection.uninspectable).
