# Tenant restriction does nothing: bypass rule ahead of the login inspection rule (zia.saas-apps.tenant-restriction-order)
Also called: personal microsoft account still works; tenant restriction not working; tenant profile configured but personal account signs in; office 365 one click tenant restriction; click-to-run bypass tenant restriction; Restrict-Access-To-Tenants not injected; ssl rule order microsoft login services

When the tenant profile is correct but personal accounts still sign in, check the SSL Inspection order before the profile ([SaaS apps that break or misbehave behind ZIA](kb:zia.saas-apps) lists the other causes). Walk it in this order.

**1. Does the login traffic get decrypted at all?** Tenant restriction works by ZIA adding headers to the login request ([How a tenant profile is enforced: the headers ZIA inserts](kb:zia.tenant-profiles.wire-mechanic)), which needs decryption, and Help requires an SSL Inspection rule that selects Microsoft Login Services and ranks above the Office 365 One Click rule ([SSL/TLS inspection rules a tenant profile depends on](kb:zia.tenant-profiles.ssl-prerequisite)). With the Microsoft-Recommended One Click configuration on, its predefined SSL/TLS Inspection rule exempts any Microsoft 365 traffic from SSL/TLS Inspection and, as Help words it, from other web policies such as URL Filtering and Cloud App Control; Evaluate Other Policies can be chosen instead, in which case those policies can match on the undecrypted traffic, though the policy action is likely limited to the domain portion and not the full URL. [zia.saas-apps.tenant-restriction-order:one-click-rule-exempts-web-policies] That predefined rule cannot be deleted, but its rule order, admin rank, status, label and description can be changed, as can the choice between Evaluate Other Policies and Bypass Other Policies under Do Not Inspect. [zia.saas-apps.tenant-restriction-order:one-click-rule-order-editable]

**2. Which rule matches first?** SSL Inspection rules are first match ([SSL/TLS inspection rule order, predefined and default rules, limits](kb:zia.ssl-inspection.rules)). If a Do Not Inspect rule for Microsoft 365 traffic (the O365 One Click rule, or the Click-to-Run exemption) sits earlier in the SSL Inspection order than the Microsoft Login Services inspection rule and matches the login request, the login is not decrypted, so Microsoft's tenant-restriction headers cannot be inserted and the tenant profile has no effect. [zia.saas-apps.tenant-restriction-order:bypass-first-disables-restriction]

**3. Is it the stronger exemption?** If the matching exemption is the Bypass Other Policies variant (the Click-to-Run rule in the Leading Practices table), Cloud App Control is skipped as well, and the Cloud App Control rule that carries the tenant profile never evaluates. [zia.saas-apps.tenant-restriction-order:bypass-other-policies-skips-profile] The difference between the two predefined exemption styles is in [Writing SSL/TLS inspection exemptions without exempting too much](kb:zia.ssl-inspection.exemptions) and [Where SSL inspection sits in ZIA web policy evaluation (the two passes)](kb:zia.ssl-inspection.pipeline).

**4. Fix.** The fix is to place the SSL Inspection rule that selects Microsoft Login Services as the cloud application above the One Click rule (and, by inference, the Click-to-Run exemption), rather than changing the tenant profile. [zia.saas-apps.tenant-restriction-order:order-fix]

Whether the failure leaves no error and no log is open [gap:zia.saas-apps.tenant-restriction-order:silent-failure]. Whether Google and Webex tenant restriction fail the same way is open [gap:zia.saas-apps.tenant-restriction-order:same-shape-google-webex]. Whether the Click-to-Run exemption and the One Click rule are one rule is open [gap:zia.saas-apps.tenant-restriction-order:click-to-run-versus-one-click].

What to check:
1. Whether the login traffic is decrypted: the SSL Inspection rule that matches the Microsoft login hosts is reached first and has an inspect action.
2. Whether the Microsoft-Recommended or Legacy One Click option is on, and whether the Click-to-Run exemption is present.
3. Whether the profile's Version 1 or Version 2 flag and personal-domain flag are set as intended, before changing the profile.
4. Whether the tenant profile needs reconfiguring, decided only after the inspection order is ruled out.
