# Azure Virtual WAN integration: prerequisites, limitations, service principal, hub sync and errors (zia.traffic-forwarding.azure-vwan)
Also called: Azure Virtual WAN; Azure VWAN; Azure vwan hub; Partner Integrations - SDWAN

The integration uses Microsoft's Azure Virtual WAN APIs to discover and configure Azure hubs. When it is configured the Zscaler service can sync hub information from Azure, and a one-click process then creates outbound IPSec tunnels from any hub to the nearest Zscaler data center, configuring the hubs and provisioning Locations and VPN Credentials for them in the Admin Console. [zia.traffic-forwarding.azure-vwan:what] For Azure Virtual WAN, the Integrating with Microsoft Azure Virtual WAN procedure must be completed before hubs can be synced and tunnels configured. The configuration steps are to find the closest Zscaler data center and configure the hub to create an outbound tunnel to it, fetch the IPSec pre-shared key for the VPN site from the hub, provision the hub's IP address for the Zscaler cloud and organization, create the VPN credentials from that key and the hub's IP address, and create a Zscaler location for the hub with those credentials. [zia.traffic-forwarding.azure-vwan:azure-vwan] When an Azure hub's configuration completes the Tunnel Status is Configured and the IP Address is shown, while VPN Connection is unlisted or unknown at that point; the VPN Connection column shows the primary tunnel status of configured hub locations. [zia.traffic-forwarding.azure-vwan:azure-vwan-status]

**Prerequisites and limitations.** Setup needs a valid Azure VWAN subscription, which is an additional cost, at least one configured Azure hub, and Zscaler added as a Security Partner Provider. If the Zscaler VWAN Hub is not configured as a Security Partner Provider in Microsoft Azure, it fails to sync with the Admin Console. [zia.traffic-forwarding.azure-vwan:prerequisites] Redundant tunnels are not supported: only one outbound tunnel from an Azure VWAN hub to a Zscaler tenant is supported, so there is no failover to another Zscaler data center based on unavailability or load. [zia.traffic-forwarding.azure-vwan:single-tunnel-no-failover] Azure Government is not supported. Sublocations are not supported; only Zscaler locations are. There is no multi-tenancy: traffic from multiple VNETs belonging to the same organization goes through the same VWAN hub to the Zscaler tenant. [zia.traffic-forwarding.azure-vwan:scope-limits] Each Azure VWAN hub supports one Zscaler cloud, so multiple clouds, including beta and production, need additional VWAN hubs. The page gives the current VWAN hub limit as one hub per region per subscription and refers to Azure documentation for updates. Each Zscaler cloud supports one Azure tenant, and tunnels cannot be terminated to multiple Azure VWAN hubs across multiple subscriptions. [zia.traffic-forwarding.azure-vwan:cloud-tenant-cardinality] In Azure VWAN environments, routes defined in the default route table as static routes do not propagate as expected, and the page recommends BGP peering instead of static route configurations. [zia.traffic-forwarding.azure-vwan:static-routes-bgp]

**Service principal.** Step 1 collects the Application ID, Application Key, Tenant ID and Subscription ID for Step 2 of the integration procedure. The registered Zscaler application must be assigned a role to access resources in Azure VWAN; the procedure selects the resource group set up for Azure VWAN and the Contributor role, and Zscaler recommends a separate resource group for Azure VWAN to reduce the scope of the changes the service principal can perform. The app registration's supported account types is Accounts in this organizational directory only. [zia.traffic-forwarding.azure-vwan:service-principal] The Application Key is the key value of a service principal authentication key; its Value appears after saving, must be copied then, and cannot be retrieved later. The Zscaler service uses the Application ID and the key Value to authenticate to Azure. The Tenant ID is the Directory ID. [zia.traffic-forwarding.azure-vwan:application-key] What happens when the secret expires, and whether a role narrower than Contributor works, are open [gap:zia.traffic-forwarding.azure-vwan:secret-and-role].

**Console setup and sync.** The integration is configured in the Admin Console under Internet Access > Partner Integrations - SDWAN, on the Azure Virtual WAN tab, with the credentials entered under Azure AD Authentication Credentials. Test reports whether the Azure integration with Zscaler succeeded. When the credentials are validated, Sync syncs the Azure hubs, and the Azure Hub Locations Sync section then shows the last sync timestamp and the number of hub sites successfully synced. [zia.traffic-forwarding.azure-vwan:console-setup] The Azure Virtual WAN Locations tab lists all Azure hub locations with their Azure Region. Initially the tunnel configuration is Not Configured and the Azure Sites, Zscaler Location, IP Address and VPN Connection columns are empty; editing each location starts its tunnel configuration. [zia.traffic-forwarding.azure-vwan:synced-hubs-initial] If Test is unsuccessful, the page says to ensure the Zscaler VWAN Hub is properly configured as a Security Partner Provider to avoid sync failures with the Admin Console. [zia.traffic-forwarding.azure-vwan:test-failure]

**Errors.** Azure Virtual WAN authentication errors: INVALID CREDENTIALS when any of Tenant ID, Subscription ID, Application ID and Application Secret is not configured; DUPLICATE ITEM when the Subscription ID is already associated with another organization; ACCESS FAILURE when the Subscription ID is not available for the account, likely entered incorrectly; NOT AUTHORIZED when an Azure API called by the Zscaler UI returned 401 or 403 (contact Azure support); ACCESS FAILURE when authenticating with the Azure portal returned 404 (contact Azure support); and UNEXPECTED ERROR (contact the Zscaler Support Engineer). [zia.traffic-forwarding.azure-vwan:auth-errors] How to tell the two ACCESS FAILURE causes apart is open [gap:zia.traffic-forwarding.azure-vwan:access-failure-causes].

What to check:
1. Whether the design needs failover to another Zscaler data center, since an Azure VWAN hub supports one outbound tunnel to a Zscaler tenant.
2. Whether the Zscaler VWAN Hub is configured as a Security Partner Provider in Azure when the sync or Test fails.

Not known (open gaps):
- Secret expiry and whether a role narrower than Contributor works [gap:zia.traffic-forwarding.azure-vwan:secret-and-role]: settled by lab-test or support-ticket
- Telling the two ACCESS FAILURE causes apart [gap:zia.traffic-forwarding.azure-vwan:access-failure-causes]: settled by source-read or support-ticket
