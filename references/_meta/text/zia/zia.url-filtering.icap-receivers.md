# ICAP receivers for URL Filtering (zia.url-filtering.icap-receivers)
Also called: ICAP Receiver; URL Filtering ICAP; icaps

Zscaler's ICAP Receiver feature forwards the inbound and outbound traffic of all the sites of the selected URL categories in the URL Filtering policy rule to an ICAP server, and consists of adding ICAP receivers and associating them to a URL Filtering policy. Secure or unencrypted ICAP servers can be configured, but Zscaler recommends sending transaction information via secure ICAP. The article is about ICAP receivers for the URL Filtering policy only. [zia.url-filtering.icap-receivers:overview]

**Where it runs.** The ICAP Receiver feature works only with Private Service Edges and Virtual Service Edges for Internet & SaaS (ZIA), and is not enabled by default on them. [zia.url-filtering.icap-receivers:edge-requirement] The enabling steps go to the /sc/sme/conf folder, edit the sc.conf file with `vi sc.conf`, enter the following parameters in the sc.conf file and save: [SME] icap_respmod_enable=1, icap_respmod_max_request_size=10000, icap_respmod_request_max_fails=3, icap_respmod_request_max_age=60 and icap_respmod_http_max_hold_time=1. The page then says to ensure the entries are saved in the sc.conf file with `cat sc.conf`. The restart step for the Virtual Service Edge instance runs `/sc/update/vzen stop sme` and `/sc/update/vzen start sme`. [zia.url-filtering.icap-receivers:enablement] What the enabling parameters do is open [gap:zia.url-filtering.icap-receivers:sc-conf-parameters], and so is whether the step also applies to Private Service Edges [gap:zia.url-filtering.icap-receivers:private-service-edge-step].

**Defining a receiver.** A receiver's Status toggle allows the service to send communications to the ICAP receiver; if it is disabled, the service does not send the information to that receiver. [zia.url-filtering.icap-receivers:receiver-status] The receiver URI must follow the format icaps://<FQDN or IP address>:<port number>/<servicepath>. The Receiver URI field is prepopulated with icaps:// because Zscaler recommends secure ICAP, and icap:// can be used to send unencrypted ICAP over plain text, for example for debugging. FQDNs or IP addresses of ICAP receivers and load balancers are accepted. A port number must be included and must match the port the network firewall accepts ICAP traffic on, and Zscaler recommends port 1344. The service path specifies whether the receiver monitors outgoing or incoming traffic, and the page's unencrypted example for Vontu is icap://metascan.corp.safemarch.com:1344/reqmod. [zia.url-filtering.icap-receivers:receiver-uri] The use of the downloadable certificate is optional and is only required if the ICAP server is using mutual authentication. After download, the certificate is installed in the ICAP server tunnel configuration. [zia.url-filtering.icap-receivers:mtls-certificate]
