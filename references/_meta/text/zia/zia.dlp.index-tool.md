# DLP Index Tool: configuration object, VM requirements and deployment notes for VMware, AWS and Azure, SSO and VM commands (zia.dlp.index-tool)
Also called: index tool; dlp index tool; edm index template; idm index template; zadp; adp_client.ova; index tool sso; index tool explicit proxy

The Index Tool builds the index templates used when creating custom DLP dictionaries and engines: once an Index Tool configuration exists and its VM is installed and running, admins log in to the tool to create and modify EDM and IDM index templates, and it shows a dashboard of the templates with details, last-modified date and time, and status. The VM can run on an AWS EC2 instance, an Azure VM or on-premises. [zia.dlp.index-tool:what-it-is] Zscaler updates the Index Tool automatically. Admins are notified in the tool, cannot change the upgrade time, and the upgrade waits for running operations to finish; it takes about one hour, during which the tool is unavailable. [zia.dlp.index-tool:automatic-upgrade] The templates it builds are in [Exact Data Match: index templates, data types, primary and secondary fields, dictionary matching and template processing](kb:zia.dlp.exact-data-match) and [Indexed Document Match: IDM templates, limits, scheduling and match accuracy](kb:zia.dlp.indexed-document-match). The dictionaries that use its templates are in [DLP dictionaries: predefined, cloned and custom](kb:zia.dlp.dictionaries); Endpoint DLP's use of it is in [Endpoint IDM, Endpoint EDM and Share Files Externally](kb:zia.dlp.endpoint-sensitive-information). Its VM has the same three-platform deployment shape as [Zscaler Incident Receiver: requirements per platform, storage, health check and VM commands](kb:zia.dlp.incident-receiver).

**The console object.** An Index Tool configuration in the Admin Console has a unique VM Name, a Status of Enabled or Disabled, and an Enable Single Sign-On setting. After it is saved its SSL certificate can be downloaded; the VM Name cannot be changed afterwards, and regenerating the certificate requires updating the VM with the new file. The page also offers the VM download (.ova) and a new client certificate upload. [zia.dlp.index-tool:configuration-object] What the provisioning blob data is for is open [gap:zia.dlp.index-tool:provisioning-blob], and whether the configuration has an API object is open [gap:zia.dlp.index-tool:api-object].

**Sizing.** All three deployment pages require 4 CPUs, so that hash generation performance is not impacted, and recommend 16 GB of RAM when the index templates hold less than 300 million records and 64 GB when they hold more. [zia.dlp.index-tool:sizing-common] How records relate to the cells used for the AWS instance type is partly answered for EDM [gap:zia.dlp.index-tool:records-vs-cells]: the vendor's example multiplies records by columns [An organization can create up to 64 EDM templates. The cell usage shown in the Admin Console and the Index Tool helps size a template's data records; in the vendor's example, a CSV file with 40K records of 3 columns each uses 120K cells. The number of records in a template affects how much memory (RAM) to allocate for the Index Tool VM.](kb:zia.dlp.exact-data-match:template-and-cell-limits).

**VMware.** On VMware, a new or clean deployment needs a VM image on Zscaler OS version 24, on ESX/ESXi 6.0 or later with one virtual NIC and a 600 GB disk (under 300 million records) or 1 TB (over). For templates under 300 million records the image can be downloaded from the Admin Console, and the page gives the official MD5 for /sc/adp/vm/adp_client.ova as f6793ec81fa7bcb3cd128ce37ced6fa9. The VM starts on DHCP by default, and the zsroot user's initial password is randomly generated. [zia.dlp.index-tool:vmware-deployment] How the image is obtained for templates over 300 million records is open [gap:zia.dlp.index-tool:large-template-image], and whether the image is the one named in [An on-premises VM needs a hypervisor of VMware ESX/ESXi version 6.0 or later or Oracle VM VirtualBox, 4 CPUs, 8 GB RAM, a 600 GB disk and 1 virtual NIC. The image is an OVA downloaded from the Incident Receiver page, and the page lists f6793ec81fa7bcb3cd128ce37ced6fa9 as the official MD5 for /sc/adp/vm/adp_client.ova.](kb:zia.dlp.incident-receiver:onprem-vm-spec) is open [gap:zia.dlp.index-tool:shared-image].

**AWS.** On AWS the Index Tool VM is requested from Zscaler Support for the customer's shared AWS account and region, and Support provides the shared AMI ID and description. The security group's outbound rules take the IPs listed on the Zscaler Index Tool Requirements page at config.zscaler.com, inbound rules carry only necessary traffic, and the VM needs no open port for internet traffic. The page's sizing example ties instance type to the planned number of cells (t2.large or t3.large below 500 million cells, t2.xlarge or t3.xlarge above), and a public IP changes when the instance is shut down and restarted. [zia.dlp.index-tool:aws-deployment] The contents of the requirements list are not captured [gap:zia.dlp.index-tool:requirements-list-not-captured].

**Azure.** On Azure, the Index Tool VHD shared access signature (SAS) token must be obtained from Zscaler Support first; without it the tool cannot be set up. Deployment uses two VHD files (OS and data), each offered for 600 GB and 1,100 GB disks, copied from a regional source (USA, Europe or Australia) into the customer's storage account, whose networking must allow public access from all networks; all Index Tool resources must use the resource group's region. The VM is deployed by downloading a JSON parameter file and using it to deploy the Azure VM instance, 1,100 GB VHDs need an E8 VM size, and the tool is ready to configure when the serial console prompts to change the zsroot password. [zia.dlp.index-tool:azure-deployment]

**Differences between the three pages.** The three deployment pages differ in what each states [gap:zia.dlp.index-tool:family-absences].

**Certificate, login and start-up.** The VMware, AWS and Azure pages each install the SSL client certificate downloaded from the Admin Console with sudo zadp configure <SSL_certificate_zip_filename>, ask for the domain name used in the Index Tool's FQDN, and offer the default passphrase file /home/zsroot/zscaler_zadp_webui_certificate_pass.txt. The VMware page asks for a passphrase and a confirmation, says the step generates a self-signed server certificate (its example is *.mycompany.com), and gives sudo zadp install-server-cert for installing a server certificate followed by a service restart; the AWS and Azure pages also give sudo zadp install-server-cert. On the VMware page the tool is reached at https://<IP Address of the Index Tool VM> and logged in to with Admin Console credentials. [zia.dlp.index-tool:certificate-install] The EDM and IDM template articles tell admins to go to https://<IP Address of the Index Tool VM> to access the Index Tool and log in with their Zscaler Admin Console credentials, and describe an Indexed Document Match Templates dashboard and an Exact Data Match Templates dashboard, each with a Create New Template action. [zia.dlp.index-tool:login-and-dashboards] On the VMware page, a successfully configured Index Tool downloads the latest install package automatically before it starts. Because the tool gives access to highly sensitive information, the page says everyone with access to it must be authorized and authenticated. [zia.dlp.index-tool:startup-update-and-access] The VMware, AWS and Azure pages each say to update zadp_ui_port in the /sc/conf/sc.conf file to a port number higher than 1,000. [zia.dlp.index-tool:non-elevated-port]

**Network modes.** In explicit proxy mode DNS and NTP are not tunneled, so an internal DNS server is needed. The VMware page says the tool needs resolution for the current Master CA IP, the update server and the NTP server, and lists smcacluster, update1, update2 and zdistribute under the Zscaler cloud name plus the NTP servers 0, 1 and 2.freebsd.pool.ntp.org, which can be overridden. Because the proxy configuration does not allow authentication, the proxy must allow the VM's IP/MAC without user and password, and must allow SSL bypass to the IPs listed at config.zscaler.com/<Zscaler cloud Name>.net/edm. The AWS and Azure pages give the same internal DNS statement and the same IP list location. [zia.dlp.index-tool:explicit-proxy-requirements] The command that sets the proxy differs between the pages [divergence:zia.dlp.index-tool:explicit-proxy-command]. The AWS page also spells another command differently [gap:zia.dlp.index-tool:change-password-spelling].

**Maintenance and commands.** The VMware page describes remote access for Zscaler Support without opening an inbound firewall connection: disabled by default and enabled only for as long as needed, sudo zadp support-access-start creates a long-lived SSH tunnel to the Zscaler cloud with remote port forwarding, sudo zadp support-access-stop brings it and all remote connections down, and the page also lists sudo zadp support-access-status. [zia.dlp.index-tool:support-access] The VMware page's VM commands table includes: update-now, which needs the service stopped; force-update-now, which updates to the latest version regardless of the installed one and stops the service first; status; troubleshoot, which checks the installed certificate, the zcloud server configuration, all services and whether an update is needed; collect-diagnostics, which builds a file for Zscaler Support; and configure-syslog-server, which forwards file SFTP events and critical changes to monitored configuration files to an external syslog server over UDP port 514, which cannot be changed. [zia.dlp.index-tool:vm-commands]

**Single sign-on.** Single sign-on to the Index Tool can be configured through the customer's IdP instead of logging in with a username and password; the page walks through Okta (a SAML 2.0 app) and Microsoft Entra ID. The IdP's single sign-on, audience and reply URLs are <Index tool URL>/ssoLogin, Okta's Name ID format is Unspecified, and IdP usernames must match the admins' usernames on the Zscaler service. The Admin Console side takes the IDP URL, an Issuer of <Index Tool URL>/ssoLogin (case-sensitive), the IdP's SSO certificate and a SAML Issuer ID used to verify the IdP. [zia.dlp.index-tool:sso]

What to check:
1. Which deployment page (VMware, AWS or Azure) the VM was built from before reading a specification or command off one of them, since the pages state different requirements.
2. Whether the VM's RAM matches the number of records in the index templates, since the pages recommend different RAM above and below 300 million records.

Sources disagree (name both sides):
- The VMware page sets the explicit proxy with one command, while the AWS and Azure pages use another. [divergence:zia.dlp.index-tool:explicit-proxy-command]
  - zscaler-help: The VMware page runs sudo zadp configure-network for explicit proxy mode.
  - zscaler-help: The AWS page runs sudo zadp configure-proxy. Its note that AWS manages network configuration so the network cannot be configured directly names the Incident Receiver VM, which looks like text copied from the Incident Receiver page.
  - zscaler-help: The Azure page runs sudo zadp configure-proxy.
  Impact: Which command sets an explicit proxy depends on which page is followed, and which platform accepts which command is unstated.
