# Cloud App Control and SSL inspection: what CAC can see (zia.cloud-app-control.ssl-visibility)
Also called: cac ssl inspection; one click office 365; ucaas one click; zoom one click; ms o365 optimize; cac granular action not working; cac and ssl bypass

CAC and SSL inspection interact in two ways: what CAC sees, and which settings turn off interception for a whole vendor's destinations. The general pipeline is in [Where SSL inspection sits in ZIA web policy evaluation (the two passes)](kb:zia.ssl-inspection.pipeline); this page covers what matters to CAC rules.

**Settings that turn off interception for whole vendors.** Enabling the Microsoft-recommended One Click Office 365 Configuration turns off SSL/TLS interception for all Microsoft 365 destinations. Disabling it and using the pre-existing configuration keeps granular controls. [zia.cloud-app-control.ssl-visibility:one-click-m365] The Understanding Microsoft 365 article says Microsoft 365 applications rely on tunnel protocols such as MAPI/RPC over HTTPS (Outlook) and non-web protocols such as RTMP, SIP (Lync) and Autodiscover, and that, to comply with Microsoft's connectivity principles and recommendations, the Microsoft-Recommended One Click Office 365 Configuration can be enabled for all Microsoft 365 application URLs. To inspect Microsoft 365 web apps that run in a browser, such as SharePoint, Yammer and Office online, content inspection and SSL Inspection can be enabled through the Office 365 One Click Configuration option, which chooses individual cloud applications; Zscaler strongly recommends the Microsoft-Recommended configuration for better performance. [zia.cloud-app-control.ssl-visibility:m365-inspection-choice] The per-application Office 365 One Click Configuration option is not described [gap:zia.cloud-app-control.ssl-visibility:office365-per-app-option]. Enabling the one-click option for Zoom, GoTo, RingCentral, Webex or Talkdesk turns off SSL/TLS interception for all of that vendor's destinations; to keep granular controls the option must be disabled and cloud application and firewall network application policies configured instead. [zia.cloud-app-control.ssl-visibility:one-click-ucaas] The MS O365 Optimize URL category carries the note to bypass its sites from SSL/TLS Inspection and authentication. [zia.cloud-app-control.ssl-visibility:o365-optimize-bypass]

**What that does to CAC.** For traffic that is not decrypted, including destinations covered by the one-click options, Cloud App Control can use only the domain-level information from the first pass (CONNECT host or SNI), so it has less to identify the application with than for decrypted traffic. [zia.cloud-app-control.ssl-visibility:domain-level-only-when-not-decrypted] How CAC maps requests to applications on shared hostnames is open [How CAC picks the cloud application for a URL on a shared hostname](kb:zia.cloud-app-control.rule-criteria:app-identity).

What to check:
1. Whether a one-click or Optimize bypass setting stops interception for an app before reading that app's CAC rule, since these settings turn off interception for whole vendors.
2. Whether the traffic is decrypted before promising granular actions, since granular actions need SSL/TLS Inspection.
