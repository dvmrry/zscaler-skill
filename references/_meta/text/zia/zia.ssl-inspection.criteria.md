# SSL/TLS inspection rule criteria and the ones that silently don't match (zia.ssl-inspection.criteria)
Also called: ssl inspection criteria; ssl rule not matching; ssl rule platforms; NO_CLIENT_CONNECTOR; connect user-agent; road warrior kerberos; destination group ignored sni

"Why didn't this SSL rule match?" can be a criterion that was ignored or cannot be evaluated for this traffic. Start with the expression. An SSL/TLS inspection rule matches when this expression is true: Source IP Groups AND [URL Categories OR Cloud Applications OR Destination Groups OR Forwarding Gateways] AND ZPA Application Segment AND [Location Groups OR Locations] AND [Users OR Groups OR Departments] AND [Device Groups OR Devices OR Remote Users with Kerberos] AND Device Trust Level AND User Agent AND [Endpoint Applications OR Endpoint Application Tags] AND Endpoint Application Risk Level. [zia.ssl-inspection.criteria:operator-expression] Criteria in different groups of the match expression are ANDed, so adding a criterion from another group narrows a rule; only values inside a bracketed group widen it. [zia.ssl-inspection.criteria:second-dimension-narrows] Device trust levels, device groups and devices are documented as applicable to devices managed by Client Connector, and when none is set the criterion is ignored during evaluation; an unset `platforms` list means the rule applies to all device platforms. [zia.ssl-inspection.criteria:zcc-criteria-unset-ignored]

**Criteria that need a careful reading.**
- **Destinations.** Destination groups in an SSL/TLS inspection rule may be IP, FQDN or Wildcard FQDN groups; countries and custom categories configured in a destination group are ignored. [zia.ssl-inspection.criteria:destination-group-types] IP address-based destination groups in a rule's criteria are ignored during policy evaluation when the HTTPS request carries an SNI value. [zia.ssl-inspection.criteria:dest-ip-groups-ignored-with-sni] Whether a rule scoped only by IP destination groups then matches every request with SNI or none of them is not documented [gap:zia.ssl-inspection.criteria:ip-dest-group-ignored-effect].
- **User agent.** The CONNECT User-Agent criterion applies only to SSL/TLS traffic forwarded in explicit proxy mode (PAC or PAC over tunnel); it does not apply to transparent proxy (tunnel) or Z-Tunnel 1.0 traffic, which has no user-agent context. [zia.ssl-inspection.criteria:connect-user-agent-explicit-only]
- **ZPA.** The ZPA Application Segment criterion lists only segments that have Source IP Anchor enabled (up to 255 selectable); in the API it is the `zpaAppSegments` list, documented as Source IP Anchoring-enabled segments. [zia.ssl-inspection.criteria:zpa-segments-sipa-only] The criterion has no counterpart on URL Filtering or Cloud App Control rules [gap:zia.ssl-inspection.criteria:absent-from-url-filtering-and-cac].
- **Kerberos.** When `roadWarriorForKerberos` is true, the rule applies to remote users that use PAC with Kerberos authentication. The console's Remote Users with Kerberos criterion applies only to remote user traffic with Kerberos authentication forwarded via PAC files, not via Client Connector. [zia.ssl-inspection.criteria:road-warrior-kerberos] `roadWarriorForKerberos` is the API form of the console's Remote Users with Kerberos criterion. [zia.ssl-inspection.criteria:road-warrior-kerberos-is-console-criterion]

**Platform.** `platforms` is a list of Client Connector device platform tokens: `SCAN_IOS`, `SCAN_ANDROID`, `SCAN_MACOS`, `SCAN_WINDOWS`, `SCAN_LINUX`, and `NO_CLIENT_CONNECTOR`. The Python SDK model forms it as a plain list of `str`. [zia.ssl-inspection.criteria:platforms-values] The console most likely surfaces the platform criterion as Device Groups by OS type: the Leading Practices Guide writes rules as 'Device Group is Android, iOS, Windows, or macOS' and 'Device Group is No Client Connector', which matches the `platforms` tokens, so `NO_CLIENT_CONNECTOR` is the 'inspect Client Connector devices, exempt the rest' selector. [zia.ssl-inspection.criteria:platforms-label-inferred] Device Trust Level values High, Medium and Low apply only to Client Connector traffic; Unknown applies to all traffic. [zia.ssl-inspection.criteria:device-trust-scope]

**Identity.** User, Group and Department criteria work only when traffic arrives through Client Connector (preferred) or through GRE/IPsec with Enforce Surrogate IP; without either the service cannot identify the user before inspection to properly apply user-based policies. Device Group criteria need Client Connector. [zia.ssl-inspection.criteria:identity-needs-zcc-or-surrogate-ip] This is the same constraint as the first pass in [Where SSL inspection sits in ZIA web policy evaluation (the two passes)](kb:zia.ssl-inspection.pipeline), which is evaluated before decryption on the CONNECT or SNI alone.

How the matching rule is chosen is in [SSL/TLS inspection rule order, predefined and default rules, limits](kb:zia.ssl-inspection.rules); what it then does is in [What an SSL/TLS inspection action does: Inspect, Do Not Inspect, Block and their settings](kb:zia.ssl-inspection.actions). The URL Filtering criteria tree is a different expression with different fields: [How URL Filtering rule criteria combine](kb:zia.url-filtering.criteria).

What to check:
1. Whether a criterion in the rule's expression is ignored or cannot be evaluated for this traffic, starting from the operator expression.
2. Which destination type to scope an SSL rule by: FQDN groups, URL categories or cloud applications rather than IP groups, unless the target has no SNI.
