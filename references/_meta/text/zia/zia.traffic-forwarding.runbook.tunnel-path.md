# Runbook: MTR collection, WinMTR for Client Connector and PAC, and latency checks for GRE and IPSec gateways (zia.traffic-forwarding.runbook.tunnel-path)
Also called: How to Collect MTR; Validate the Network Path; WinMTR

**MTR collection.** In the GRE section, the runbook runs a forward MTR from the GRE gateway to the Zscaler GRE VIP, sent outside the tunnel to capture all ISP-level hops, for at least 300 packets; the Linux command is mtr –nrc <packet-count> <GRE-VIP>, with flags -n (no host-name resolution), -r (report mode) and -c (packet count); other options are -z (BGP AS number per hop), -T (TCP instead of ICMP), -s (probe packet size) and -h. [zia.traffic-forwarding.runbook.tunnel-path:mtr-linux] On Windows the runbook uses WinMTR, with the Zscaler IP or URL (for performance issues, the IP from ip.zscaler.com) as host, Resolve names deselected so every hop's IP shows, run for at least 300 packets and saved with Export TEXT as a .txt file; it applies to Client Connector (Z-Tunnel 1.0 and Tunnel with Local Proxy) and PAC files. [zia.traffic-forwarding.runbook.tunnel-path:winmtr] PAC file diagnosis is in [Runbook: PAC file, explicit proxy and DPP outages, PAC causes and authentication loops](kb:zia.traffic-forwarding.runbook.pac).

**Analysis.** In the GRE section, MTR results are analyzed for high latency or consistent packet loss along the path; routing loops or abnormal paths might require involving the ISP. [zia.traffic-forwarding.runbook.tunnel-path:mtr-analysis] In the GRE section the recommended latency thresholds for the round trip time (RTT) to the Zscaler GRE VIP are approximately 60ms per 4000km in developed regions, up to a maximum of 100ms per 4000km for less developed regions. [zia.traffic-forwarding.runbook.tunnel-path:latency-thresholds] Which regions count as developed is open [gap:zia.traffic-forwarding.runbook.tunnel-path:region-definition]. Suboptimal routing is called a common issue in the GRE latency check; if confirmed, the runbook says to raise a ticket with the ISP and optimize IP SLA health-policy thresholds by increasing timeout intervals to tolerate latency spikes. [zia.traffic-forwarding.runbook.tunnel-path:suboptimal-routing]

**IPSec section.** In the IPSec section, the runbook runs a forward MTR from the IPSec gateway to the Zscaler IPSec VIP, verifies the RTT to the Zscaler IPSec VIP against approximately 60ms per 4000km for developed regions and up to 100ms per 4000km for less-developed regions, and if suboptimal routing is confirmed says to raise a ticket with the ISP and optimize IP SLA health-policy thresholds by increasing the timeout interval; its Linux MTR command there still reads mtr –nrc <packet-count> <GRE-VIP>. [zia.traffic-forwarding.runbook.tunnel-path:ipsec-mtr-and-latency]
