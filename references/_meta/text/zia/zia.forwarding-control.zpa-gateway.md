# The Private Access gateway object in ZIA (zia.forwarding-control.zpa-gateway)
Also called: zpa gateway; private access gateway; zia_forwarding_control_zpa_gateway; Auto ZPA Gateway; zpa_server_group; zpa_tenant_id

Source IP Anchoring needs an object on the ZIA side that a rule can point at. A Private Access gateway is configured in the Zscaler Admin Console under Infrastructure > Internet & SaaS > Private Access GW, mapping a Private Access server group and its application segments that need Source IP Anchoring. Using it requires the ZIA tenant to be paired with the Private Access tenant with Source IP Anchoring enabled. [zia.forwarding-control.zpa-gateway:zia-side-object] After a server group is chosen, the gateway form lists all application segments with Source IP Anchoring enabled that are associated with that server group. [zia.forwarding-control.zpa-gateway:segments-follow-group] Zscaler provides a predefined gateway, enabled by default and not editable, to direct Private Access application segment traffic marked for inspection from Internet & SaaS to Private Access, and separate custom gateways can be configured to forward Source IP Anchored traffic to Private Access. [zia.forwarding-control.zpa-gateway:predefined-gateway-help] The Private Access GW page describes a Server Groups field, the server group configured for the gateway, and an Application Segments field, the application segments associated with the configured server group. [zia.forwarding-control.zpa-gateway:gateway-page-fields]

**Fields.** In the Terraform resource a gateway has a name, optional description, `type` (ZPA for Zscaler Internet Access or ECZPA for Cloud Connector), a required `zpa_server_group` (`external_id` and `name`) and optional `zpa_app_segments` (each `name` and `external_id`). The Python SDK adds `zpa_tenant_id`, the ZPA tenant where Source IP Anchoring is configured. [zia.forwarding-control.zpa-gateway:fields] The Python SDK returns `(None, None, ValueError("zpa_app_segments is required"))` when `zpa_app_segments` is missing or empty on add or update, although the Terraform resource treats the argument as optional. [zia.forwarding-control.zpa-gateway:sdk-requires-segments]

**From the rule.** In a ZPA forwarding rule the Forward to Gateway field is enabled only when the selected application segments require Source IP Anchoring and share a common Private Access gateway; an empty list means no common gateway exists for the selected segments. [zia.forwarding-control.zpa-gateway:rule-needs-common-gateway] Configuring a ZPA forwarding rule through Terraform needs the ZPA provider as well as the ZIA provider, because the server group and application segments are ZPA objects referenced by their external IDs. [zia.forwarding-control.zpa-gateway:needs-zpa-provider] The rule side is in [Forwarding methods and their required fields](kb:zia.forwarding-control.methods).

**Provider behavior.** The provider refuses create, update and delete for a gateway named Auto ZPA Gateway, with an error saying the predefined gateway cannot be deleted. [zia.forwarding-control.zpa-gateway:auto-gateway-name] What the Auto ZPA Gateway does is open [gap:zia.forwarding-control.zpa-gateway:auto-gateway-behavior]. The provider reads a gateway by listing all gateways and filtering, and resolves an import by name the same way, because by its own comments the API returns incorrect application segments for a get by ID or by name. [zia.forwarding-control.zpa-gateway:read-via-get-all]

**XFF header.** The Advanced Settings field Insert XFF Header for ZPA Traffic inserts the XFF header for traffic forwarded from Internet & SaaS to Private Access through a Private Access gateway (Source IP Anchored and Internet & SaaS-inspected Private application traffic). The field is enabled by default and is disabled if the XFF header should not be inserted for outbound requests; it is available only if the Zscaler account has either Source IP Anchoring or Private Access App Inspection. [zia.forwarding-control.zpa-gateway:insert-xff-for-zpa]

The Private Access side that makes the anchoring work is in [Source IP Anchoring: what it needs on each side](kb:zia.forwarding-control.sipa); the ZPA-method delay is in [Terraform behavior of ZPA-method forwarding rules](kb:zia.forwarding-control.terraform).
