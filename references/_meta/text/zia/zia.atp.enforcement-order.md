# Where Malware Protection and ATP checks fall in the web enforcement order (zia.atp.enforcement-order)
Also called: policy enforcement order; order of enforcement atp; http get request order; http post request order; response scanning order; atp before url filtering; malware protection runs when

Where a check falls decides which block the user sees. Three orders apply, depending on what the web module is looking at. When the web module finds a transaction violates a policy, the Public Service Edge blocks it immediately and does not enforce the policies that follow; the firewall module does not evaluate it, though firewall logs still show the web transaction as blocked. [zia.atp.enforcement-order:first-violation-blocks]

**Request, GET.** For an HTTP GET request the order is: 1 Custom Malicious URLs (ATP denylist), 2 Cloud App Control, 3 URL Filtering, 4 Security Exceptions, 5 Browser Control, 6 Country-Based Blocking, 7 IPS Signature Detection, 8 Suspicious Content Protection (Page Risk), 9 P2P Control, 10 Bandwidth Control. Malware Protection and Sandbox are not in the GET request list. [zia.atp.enforcement-order:get-order]

**Request, POST.** For an HTTP POST request the order is: 1 Custom Malicious URLs, 2 Cloud App Control, 3 URL Filtering, 4 Security Exceptions, 5 Browser Control, 6 Country-Based Blocking, 7 Malicious URL Block (an extensive URL database), 8 IPS Signature Detection, 9 Suspicious Content Protection, 10 Malware Protection, 11 File Type Control, 12 Data Loss Prevention, 13 P2P Controls, 14 Bandwidth Control. [zia.atp.enforcement-order:post-order] In the POST request and in the response, the Malware Protection check comes after the ATP checks, so an ATP block ends the transaction before file scanning would run. [zia.atp.enforcement-order:mp-after-atp-checks]

**Response.** For an HTTP response the order is: 1 Security Exceptions, 2 IPS Signature Detection, 3 Suspicious Content Protection, 4 Sandbox check for known malicious files, 5 Malware Protection, 6 File Type Control, 7 Sandbox analysis of unknown files, 8 AI/ML-based content categorization, 9 Bandwidth Control. [zia.atp.enforcement-order:response-order] The custom malicious URL list and country blocking, which the GET and POST request orders include, are not among the nine steps of the response order. [zia.atp.enforcement-order:response-omits-url-checks]

What an exception skips is in [ATP Security Exceptions (the allowlist): what it skips and what it does not](kb:zia.atp.security-exceptions); the denylist check is [ATP Blocked Malicious URLs list: capacity, matching and API](kb:zia.atp.blocked-urls); country blocking is [ATP Blocked Countries: server location, not user location](kb:zia.atp.blocked-countries); Page Risk is [ATP Page Risk threshold and how the score is built](kb:zia.atp.page-risk). Domain-level checks on encrypted traffic happen before decryption: [Where SSL inspection sits in ZIA web policy evaluation (the two passes)](kb:zia.ssl-inspection.pipeline). Cloud App Control and URL Filtering ordering is in [Cloud App Control versus URL Filtering: which applies](kb:zia.cloud-app-control.precedence) and [URL Filtering rule order and first match](kb:zia.url-filtering.rule-order).

What to check:
1. Whether the transaction is a GET request, a POST request or a response, since each has its own order.
2. Which numbered step is the earliest one that could have fired, since the first violation blocks the transaction.
