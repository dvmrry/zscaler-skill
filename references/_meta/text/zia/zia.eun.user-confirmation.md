# User Confirmation notification templates for the DLP Confirm action: channels, introductory text, languages, link syntax and shared settings (zia.eun.user-confirmation)
Also called: user confirmation notification; Confirm action message; confirmation message; user confirmation template; justification options

If an activity is part of a necessary workflow, Endpoint DLP and Inline Web DLP policy rules can be configured with a Confirm action that requires users to explain the activity and provide justification for why it requires sensitive data. [zia.eun.user-confirmation:confirm-action-purpose] When user activity triggers a rule that uses a Confirm action, the service sends the default confirmation message based on the channel assigned to the rule (Network Share, Personal Cloud Storage, Printing, Removable Storage or Inline Web DLP). The default message for each channel gives users a standardized set of justification options that cannot be configured, the language that begins each message can be customized, and the messages can be configured to use the company name and logo. [zia.eun.user-confirmation:default-message-per-channel] For rules configured with an action other than Confirm (Allow, Block or Protect), the service provides a set of EUN messages that are customized separately. [zia.eun.user-confirmation:other-actions-use-euns]

**Custom messages.** A custom user confirmation message has a Name and a Channel it applies to, and only its introductory text can be edited. A language can be selected from a drop-down menu to show the introductory text for the message in that language: English (default), Chinese (Traditional), French, German, Japanese or Spanish. If the endpoint OS is set to one of the supported languages the message appears in that language on the endpoint, and in English if the OS language is unsupported; the Preview shows the options in English while they appear in the correct language on endpoints. [zia.eun.user-confirmation:custom-message-and-languages] Links can be embedded in the message content with the format __url[Link text | example.com], for example __url[Learn more | https://acme.com/policy], and line breaks can be introduced with the //n character. [zia.eun.user-confirmation:message-syntax] How a rule picks a custom message over a channel's default, and how many custom messages a channel can have, are open [gap:zia.eun.user-confirmation:custom-message-selection]. The maximum length of the introductory text is open [gap:zia.eun.user-confirmation:intro-text-length].

**Shared settings.** The settings page sets the Company Name that appears on each user confirmation message (by default Zscaler), the Company Logo at the top of each message, which must be a PNG file that is 10 KB or smaller (by default the Zscaler logo), and for Endpoint DLP the time messages remain on screen (5, 10 or 30 minutes). The General Details settings are shared with the Client Connector EUN General Details settings. [zia.eun.user-confirmation:global-settings] How the two logo limits relate is open [gap:zia.eun.user-confirmation:logo-limits]. The on-screen duration for Inline Web DLP confirmations is open [gap:zia.eun.user-confirmation:inline-duration].

The Allow, Block and Protect EUNs for Client Connector are in [Client Connector-based end user notifications from the ZIA side: prerequisites, channels, details, shared settings and languages](kb:zia.eun.client-connector); the Confirm action itself is in [Endpoint DLP policy rules: channels, criteria, actions (Allow, Block, Confirm, Protect) and notifications](kb:zia.dlp.endpoint-rules) and [Web DLP policy rules: order, criteria and actions](kb:zia.dlp.rules); the auditor email template is a different object in [DLP notification templates: auditor email subject, macros, attachments and TLS](kb:zia.dlp.notification-templates). Which API object holds the templates is open [gap:zia.eun.user-confirmation:api-object].
