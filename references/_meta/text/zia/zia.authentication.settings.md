# The organization-wide authentication settings object (zia.authentication.settings)
Also called: authSettings; auth settings; org_auth_type; orgAuthType; saml_enabled; kerberos_enabled; kerberos_pwd; auto_provision; directory_sync_migrate_to_scim_enabled; password_strength; password_expiry; one_time_auth; authentication_settings; authSettings/lite

Everything organization-wide about how users authenticate sits in one object. The organization's default authentication settings are one object, read and written at /authSettings. A separate GET /authSettings/lite returns the same model, but authFrequency, authCustomFrequency, lastSyncStartTime and lastSyncEndTime are not applicable to the Lite API. [zia.authentication.settings:org-object]

**Values.** The spec lists these values: orgAuthType is ANY, NONE, SAFECHANNEL_DIR, MICROSOFT_ACTIVE_DIR, OPENLDAP_DIR, NOVELL_DIR, IBM_DOMINO_DIR, SUN_DIR or SMAUTH_ENTERPRISE_HOSTED; oneTimeAuth is OTP_DISABLED, OTP_TOKEN or OTP_LINK; passwordStrength is NONE, MEDIUM or STRONG; passwordExpiry is NEVER, ONE_MONTH, THREE_MONTHS or SIX_MONTHS. The Python SDK's passwordStrength and passwordExpiry docstrings give the same values. [zia.authentication.settings:enum-values] The frequency field is covered in [Authentication frequency and cookie lifetime](kb:zia.authentication.frequency).

**What depends on what.** Setting orgAuthType to an LDAP-based type requires a complete LdapProperties configuration, and enabling SAML (samlEnabled) requires complete SamlSettings. [zia.authentication.settings:ldap-and-saml-completeness] passwordStrength and passwordExpiry apply to form-based authentication of hosted DB users only, not to SAML or directory authentication. [zia.authentication.settings:hosted-db-only] oneTimeAuth (OTP_DISABLED, OTP_TOKEN or OTP_LINK) is described for orgAuthType NONE, where administrators must provide new users' passwords and a one-time token or link with a temporary password is emailed to new users; with SAML single sign-on enabled the one-time token is not applicable and the field has no effect. [zia.authentication.settings:one-time-auth]

**Fields that bite.** kerberosPwd is read-only and can be set only through the generateKerberosPassword API. The Python AuthenticationSettings model's request_format still maps kerberos_pwd to kerberosPwd, though update_authentication_settings sends the caller's keyword arguments as the body. [zia.authentication.settings:kerberos-pwd-read-only] autoProvision enables SAML auto-provisioning. [zia.authentication.settings:auto-provision] directorySyncMigrateToScimEnabled disables directory synchronization for the user repository type so that SCIM provisioning or SAML auto-provisioning can be enabled; it is the setting for migrating from directory synchronization to SCIM. [zia.authentication.settings:scim-migration-flag] For the SCIM side see [ZIA SCIM provisioning](kb:zia.scim).

**The Default Settings page.** In the article's Authentication Service context, the Default Settings page displays limited options and the authentication settings are managed with Authentication Service; the article lists configuring the authentication frequency and Kerberos authentication as what an administrator does on the page. [zia.authentication.settings:default-settings-page] What holds these settings under Authentication Service is open [gap:zia.authentication.settings:authentication-service-scope]. With Authentication Service for Admins, the default method for user authentication to the Zscaler service is managed with the Authentication Profile; with Authentication Service for Admins and Users, user authentication is managed by Authentication Service. [zia.authentication.settings:who-manages-auth] Active Directory (AD) and OpenLDAP user repositories are available only when SCIM provisioning is disabled and SAML auto-provisioning is enabled for only one identity provider. [zia.authentication.settings:repository-types-availability] Zscaler recommends SAML Single Sign-On (SSO) as the authentication type, and at least one IdP must be configured to enable SAML. With AD or OpenLDAP user repositories, Form-Based authentication requires Disable Directory Sync & Enable SCIM Provisioning to be disabled, and SAML requires SCIM provisioning to be disabled and SAML auto-provisioning enabled for only one IdP. [zia.authentication.settings:auth-type-preconditions] When the Zscaler service provider (SP) signing SSL certificate is about to expire or has expired, the page shows the SP SSL Certificate Expiration Date for the SAML signing certificate, with a Caution icon when the certificate expires within 30 days. [zia.authentication.settings:sp-cert-expiry]

**Directory sync to SCIM in the console.** Disable Directory Sync & Enable SCIM Provisioning appears only when Active Directory or OpenLDAP is chosen for the User Repository Type and SAML for the Authentication Type. Enabling it makes the service disable directory synchronization, so the Authentication Wizard and the Advanced Configuration options for AD and OpenLDAP disappear along with the Directory Synchronization section; SCIM provisioning or SAML auto-provisioning can then be enabled for the IdPs, and the Form-Based option for Authentication Type becomes unavailable. [zia.authentication.settings:migration-switch-effects] The AD-to-SCIM migration guide documents how to revert from SCIM to AD provisioning: disable Enable SCIM Provisioning, disable Disable Directory Sync & Enable SCIM Provisioning on the Default Settings tab, disable the SCIM configuration in the IdP application, then click Sync Now on the Default Settings page. The guide's migration steps also instruct to make sure not to disable that option or change the repository types. [zia.authentication.settings:scim-revert-procedure] What state survives a revert, and whether the flag can be undone beyond that procedure, is open [gap:zia.authentication.settings:scim-migration-reversibility].

**Passwords for hosted users.** For Form-Based hosted users the console's Password Strength offers None (no restriction on strength or complexity, not recommended), Medium (at least 8 characters with at least one non-alphabetic character) and Strong (at least 8 characters with at least one digit, one capital letter and one special character); only ASCII characters are allowed for the password. [zia.authentication.settings:password-policy] The Password Expiration default is Never, but Zscaler strongly recommends setting the duration higher. [zia.authentication.settings:password-expiry-default] Two help pages name a different default strength [divergence:zia.authentication.settings:password-strength-default].

What to check:
1. Which password strength the tenant has set before stating a default for hosted users.
2. The exact value names against the spec.
3. Whether the field being set is read-only, as kerberosPwd is.

Sources disagree (name both sides):
- Two help pages name a different default Password Strength for Form-Based hosted users. [divergence:zia.authentication.settings:password-strength-default]
  - zscaler-help: Medium is the default password strength.
  - zscaler-help: None is the default password strength.
  Impact: Do not state the default strength a tenant starts with; read the live passwordStrength value. The enum-values claim lists NONE, MEDIUM and STRONG without a default, so it does not conflict.
