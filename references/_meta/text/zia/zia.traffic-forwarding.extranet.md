# Extranet Application Support: extranets, traffic selectors, extranet locations and traffic flow (zia.traffic-forwarding.extranet)
Also called: extranet; Extranet Application Support; traffic selector; B2B Exchange; extranet location

Extranet Application Support lets Private Access users reach private applications hosted on a business partner's network, and lets partners establish IPSec tunnels directly to the Zero Trust Exchange, for bidirectional resource access through secure IPSec tunnels without partners installing additional hardware or software. [zia.traffic-forwarding.extranet:what] Extranet Application Support is not enabled by default; it is obtained through the Zscaler Account team. [zia.traffic-forwarding.extranet:not-default] The Zscaler service facilitates the creation and management of extranets and Private Access manages user access to extranet resources. After an extranet location is configured, an admin can use it to configure server groups and application segments managed with Private Access access policies, and the VPN credentials associated with the extranet location to create the IPSec tunnel. [zia.traffic-forwarding.extranet:zpa-side]

**The extranet object.** Each extranet has traffic selectors and DNS servers specified for it. A traffic selector is an IPSec traffic-steering rule for forwarding traffic between tunnels; each can contain multiple IP address ranges and uses IKEv2. When an extranet is assigned to a location, specific traffic selectors and DNS servers can be selected, or the defaults designated during configuration are used. [zia.traffic-forwarding.extranet:extranet-object] A default traffic selector and a default DNS server must be selected for an extranet. A traffic selector range's end value must be greater than its starting address, and the range must include a minimum of 20 IP addresses. A DNS server entry takes the IP addresses of DNS Server 1 and DNS Server 2. [zia.traffic-forwarding.extranet:configuration-rules] The limits table lists 1,000 extranets, 5,000 extranet locations, 16 traffic selectors per extranet and 16 DNS servers per extranet; its Access Policy row, under Policies, also lists 50 locations and 10 location groups for extranet application support. [zia.traffic-forwarding.extranet:limits] What an ephemeral DNS response is, and why a selector needs at least 20 addresses, are open [gap:zia.traffic-forwarding.extranet:extranet-mechanics].

**Extranet locations.** Extranet locations must have a VPN credential assigned. To use extranet resources, the extranet must be assigned to a location, whose Location Type is set to Extranet. A shared public IP address is not to be chosen for a specific tenant's location, and Enforce Firewall Control is enabled automatically for extranet locations and cannot be disabled. [zia.traffic-forwarding.extranet:extranet-locations] After a location is assigned to an extranet it is automatically added to a dynamic location group for the extranet resource, which the Zscaler service creates if none exists for that extranet. [zia.traffic-forwarding.extranet:auto-dynamic-group] Group conditions are in [Location groups: manual and dynamic, conditions, limits, predefined groups](kb:zia.locations.groups); the Ansible module's extranet fields are in [Locations through the API, SDK, Terraform and Ansible](kb:zia.locations.automation); the location-level behavior is partly open there {{gap:zia.locations.automation:extranet-locations-depth}}.

**IPSec.** Extranet Application Support does not support NULL encryption for IPSec IKE Phase 2 configuration, and Zscaler recommends an AES-GCM-based encryption algorithm instead. [zia.traffic-forwarding.extranet:no-null-phase2] The general IPSec settings are in [IPSec device settings Zscaler recommends: ciphers, PFS, NAT-T and DPD](kb:shared.ipsec.device-settings).

**Traffic flow.** For a user reaching a partner application, a Public Service Edge for Private Access checks the user's eligibility and, once the user is authorized, sends a request to a Public Service Edge for Internet & SaaS, which forwards it through an IPSec tunnel to the partner's IPSec gateway. The request goes to the designated DNS server and then through the right tunnel to the partner data center based on the designated traffic selector, and after DNS resolution the Internet & SaaS edge sends the application payload back to the Private Access edge. [zia.traffic-forwarding.extranet:flow-user-to-partner] For a partner user reaching the organization's applications, if the DNS request is valid the Internet & SaaS Public Service Edge sends an ephemeral DNS response back to the partner user; the partner user's traffic is inspected by Internet & SaaS policies and validated by the Private Access access policy, and the application is delivered from the organization's data center through the App Connector, the Zero Trust Exchange and the IPSec tunnel. [zia.traffic-forwarding.extranet:flow-partner-to-org]

**Console page and logs.** The Extranet page (Private Access > B2B Exchange > Extranet) shows the traffic selectors and DNS servers configured for each extranet, marking the default traffic selector and default DNS server with a check mark, and lets an admin view insights and insights logs for configured extranets. [zia.traffic-forwarding.extranet:page-and-insights] The Extranet filters of the Insights logs are in [ZIA Insights Logs: log families, time frame, export and background queries, filters and console-only columns](kb:zia.insights.logs).

**Private Access API lookups.** The Extranet API document, titled Zscaler Private Access API Portal, has three GET operations under /mgmtconfig/v1/admin/customers/{customerId}: extranetResource/partner returns the extranet's partner details; location/extranetResource/{zpnErId} returns its location details, including sublocations when fetchSubLocations is set; and locationGroup/extranetResource/{zpnErId} returns its location group details, including special location groups when isSpecialLocationGroupInclude is set. zpnErId is the ID of the extranet resource, and the operations page results with a default page size of 20 and a maximum of 500. [zia.traffic-forwarding.extranet:zpa-api-lookups] The partner and location lookups return a paged list of name and ID pairs. The location group lookup returns location groups, each with a required id, a name (the name of the extranet location group) and ziaLocations (the extranet locations that can reach the application via an IPSec tunnel). [zia.traffic-forwarding.extranet:zpa-api-shapes] How these lookups relate to the extranet values in server groups and application segments is open [gap:zia.traffic-forwarding.extranet:zpn-er-id-link]. Sources not read for this subject are open [gap:zia.traffic-forwarding.extranet:unread-sources].

What to check:
1. Whether the extranet has a default traffic selector and a default DNS server, and whether each selector range holds at least 20 addresses.
2. Whether the extranet location has a VPN credential and the Extranet Location Type before expecting the extranet to be usable.
3. Whether the partner's IPSec Phase 2 proposal uses NULL encryption.
