# DLP dictionaries: predefined, cloned and custom (zia.dlp.dictionaries)
Also called: dlp dictionary; predefined dlp dictionary; custom dlp dictionary; clone a predefined dictionary; confidence score threshold; dlp dictionary types; edm dictionary; idm dictionary; mip label dictionary; validateDlpPattern

Dictionaries answer "what is being looked for". A dictionary never appears on a rule directly; engines wrap dictionaries and rules reference engines ([DLP engines: the unit a rule references](kb:zia.dlp.engines)).

A DLP dictionary contains a set of algorithms designed to detect a specific kind of information in users' traffic and activities. [zia.dlp.dictionaries:dictionary-definition] Zscaler provides predefined dictionaries that an admin can modify and, in some cases, clone; custom dictionaries cover content the predefined ones do not. [zia.dlp.dictionaries:predefined-and-custom] A help article on predefined DLP dictionaries lists the predefined dictionaries and marks with an asterisk those that Endpoint DLP does not support. [zia.dlp.dictionaries:predefined-catalog] `list_dict_predefined_identifiers` takes a dictionary name, not an ID: it calls `list_dicts()` with no arguments, picks the first dictionary whose name equals the argument, and returns a ValueError in the error slot if none matches. The docstring lists ASPP_LEAKAGE, CRED_LEAKAGE, EUIBAN_LEAKAGE, PPEU_LEAKAGE and USDL_LEAKAGE as the supported names. [zia.dlp.dictionaries:python-predefined-lookup-by-name]

Cloning is limited to a set of identification-based predefined dictionaries (Credit Cards, Social Security Numbers, National Identification Numbers and similar), with at most 4 clones per predefined dictionary. A clone records its source in `dictTemplateId`. [zia.dlp.dictionaries:cloning-is-limited] Clones of one predefined dictionary can carry different Confidence Score Thresholds and dictionary-specific parameters. Help says cloning is supported for identification-based predefined dictionaries (for example Credit Cards, Social Security Numbers, National Identification Numbers), with up to 4 clones per predefined dictionary; a clone's description cannot exceed 255 characters. [zia.dlp.dictionaries:cloning-help]

Each dictionary's confidence score threshold (where it applies) helps determine what counts as a violation. For predefined dictionaries the threshold is a Low, Medium or High level whose criteria are described per dictionary in the help article, and the API carries it as `confidenceThreshold` with the values `CONFIDENCE_LEVEL_LOW`, `CONFIDENCE_LEVEL_MEDIUM` and `CONFIDENCE_LEVEL_HIGH`. [zia.dlp.dictionaries:confidence-threshold-decides-violation] For predefined dictionaries whose Confidence Score Threshold can be edited, the value is Low, Medium or High. A lower threshold makes the dictionary more aggressive, needing less matching content before it triggers; a higher threshold needs more exact format and verification requirements to be met and might need more instances of matching content. [zia.dlp.dictionaries:confidence-threshold-aggressiveness] A dictionary also has a `thresholdType` of `VIOLATION_COUNT_ONLY`, `CONFIDENCE_SCORE_ONLY` or `VIOLATION_AND_CONFIDENCE`, so a dictionary can be gated by match count, by confidence, or by both. The API reference marks `thresholdType` read-only. [zia.dlp.dictionaries:threshold-type-values]

**Predefined dictionary fields.** On a predefined dictionary, Proximity Length, High Confidence Phrases and Custom High Confidence Phrases appear only when the dictionary's Confidence Score Threshold is High, where applicable. Proximity length defines how close a high confidence phrase must be to an instance of the pattern, in any direction, from 0 to 10,000 bytes, with 0 disabling the option; High Confidence Phrases shows Zscaler's default phrases, and up to 256 custom phrases can be added, one per line. [zia.dlp.dictionaries:predefined-high-confidence-fields] The BIN Number field appears only for the predefined credit card dictionary or its clones and includes or excludes up to 512 Bank Identification Numbers; the Social Security Numbers field appears only for the predefined Social Security Numbers (US) dictionary or its clones and includes or excludes up to 512 values. [zia.dlp.dictionaries:bin-and-ssn-lists]

A custom dictionary is one of three types in the API: patterns and phrases (`PATTERNS_AND_PHRASES`), exact data matching (`EXACT_DATA_MATCH`) or indexed data matching (IDM, `INDEXED_DATA_MATCH`). Patterns and phrases each carry a count action of all matches or unique matches. [zia.dlp.dictionaries:custom-dictionary-types] Help lists four kinds of standalone custom dictionary: Exact Data Match (EDM) index templates, Indexed Document Match (IDM) index templates, Microsoft Information Protection (MIP) labels, and custom phrases and alphanumeric patterns. Choosing EDM selects existing EDM templates and data fields from them; IDM selects existing IDM templates with match accuracy levels; MIP lists MIP labels in a table for selection. [zia.dlp.dictionaries:custom-dictionary-kinds-help] Pattern and phrase authoring, match types and sub-dictionaries are in [Custom Patterns & Phrases dictionaries: pattern syntax, phrase matching, match types and sub-dictionaries](kb:zia.dlp.dictionary-patterns). The Python dictionary create and update helpers take `phrases` and `patterns` as lists of tuples following the docstring's (`action`, `pattern`) convention and rewrite them to `{"action": ..., "phrase": ...}` and `{"action": ..., "pattern": ...}` objects before sending. [zia.dlp.dictionaries:python-phrase-pattern-tuples] In a custom dictionary, each `exactDataMatchDetails` entry references an EDM template by `schemaId` (with its primary and secondary field selections), and each `idmProfileMatchAccuracy` entry references an Indexed Document Match profile with a match accuracy. [zia.dlp.dictionaries:edm-idm-reference-objects] The schemas and profiles themselves have separate endpoints in the Go SDK: [The Go SDK has separate endpoints for ICAP servers (`/icapServers`), Incident Receiver servers (`/incidentReceiverServers`), DLP notification templates (`/dlpNotificationTemplates`), IDM profiles (`/idmprofile`) and EDM schemas (`/dlpExactDataMatchSchemas`).](kb:zia.dlp.incident-forwarding:supporting-objects-endpoints). The templates are built in the Index Tool ([DLP Index Tool: configuration object, VM requirements and deployment notes for VMware, AWS and Azure, SSO and VM commands](kb:zia.dlp.index-tool)); EDM templates, fields and matching are in [Exact Data Match: index templates, data types, primary and secondary fields, dictionary matching and template processing](kb:zia.dlp.exact-data-match) and IDM templates and match accuracy in [Indexed Document Match: IDM templates, limits, scheduling and match accuracy](kb:zia.dlp.indexed-document-match). How exact data matching hashes and handles source data is open [gap:zia.dlp.dictionaries:edm-mechanics].

**MIP labels.** A rule's Document Properties content location matches file metadata such as MIP labels. [zia.dlp.dictionaries:mip-labels-dictionary] A MIP-label dictionary needs a MIP account added in the Admin Console and its labels retrieved from Microsoft first. Once saved, its Dictionary Type shows as Microsoft Information Protection (MIP) and cannot be changed; at most 256 labels can be selected per custom dictionary, and deleted labels, including labels deleted on Azure, show with a strikethrough and cannot be selected. [zia.dlp.dictionaries:mip-dictionary-type] Help and the Terraform provider have a MIP dictionary type that the OpenAPI `dictionaryType` enum does not list [divergence:zia.dlp.dictionaries:mip-type-vs-api-enum], and whether the API returns MIP_TAG for it is open [gap:zia.dlp.dictionaries:mip-label-api-representation]. The MIP account and label retrieval are in [Microsoft Information Protection (MIP) accounts and label retrieval](kb:zia.dlp.mip-labels).

The Python SDK's `validateDlpPattern` helper warns that the endpoint returns a valid response but does not fail for obviously wrong patterns, and that the API documentation does not describe its request. Do not treat a passing validation as proof a custom pattern is well formed. [zia.dlp.dictionaries:validate-pattern-unreliable]

A tenant can hold 801 custom dictionaries with DLP Dictionary Expansion enabled and 160 without it, at most 64 custom parent dictionaries, and 63 sub-dictionaries per parent. [zia.dlp.dictionaries:dictionary-limits]

When Terraform reads or writes dictionaries, the provider has its own field-handling defects, covered in [ZIA Terraform resource fields that are not sent, not read back, or sent wrongly](kb:zia.terraform.field-fidelity) and [What ZIA Terraform data sources return, drop, or get wrong](kb:zia.terraform.data-source-fidelity).

What to check:
1. Whether a match count, a confidence level, or both gate the dictionary, given its thresholdType.
2. Which Low, Medium or High level applies, read from that dictionary's own criteria in the help article.
3. Whether the custom pattern is well formed, since a passing validation does not prove it.
