# Default and predefined Firewall Filtering rules: what each does and what can be changed (zia.firewall.predefined-rules)
Also called: Default Firewall Filtering Rule; Zscaler Proxy Traffic; Block Malicious IPs and Domains; Block All IPv6; Office 365 One Click Rule firewall; predefined firewall rules

Firewall Filtering ships with a default rule and a few predefined rules, some of which appear only after a related setting is enabled. Some predefined Firewall Filtering rules are visible only after certain related settings are enabled for the first time. The Office 365 One Click Rule appears on the Firewall Filtering Policy page only after the Enable Microsoft-Recommended One Click Office 365 Configuration option on the Advanced Policy Settings page is enabled for the first time. [zia.firewall.predefined-rules:conditional-visibility]

**The default rule.** The Zscaler service provides a default Firewall Filtering rule that blocks all traffic from the network to the internet. It always maintains the lowest precedence (the lowest rule order) and cannot be deleted, and admins with the super admin role can modify certain attributes of it, such as the action, logging mode and end user notification. [zia.firewall.predefined-rules:default-rule-blocks-all] When the firewall is enabled, Zscaler's Default Firewall Filtering Rule blocks all traffic from the network to the internet, so the rule must be modified or Firewall Filtering rules with a higher order configured to allow traffic. [zia.firewall.predefined-rules:default-rule-when-enabled] The default rule handles all traffic that does not match any user-defined rule with a higher rule order. Only admins with the super admin role can modify it, its criteria are fixed and not shown on the Edit Rule page, and Block/Drop, which silently drops all matching packets, is its default action. [zia.firewall.predefined-rules:default-rule-edit] The actions it offers are in [Firewall rule actions](kb:zia.firewall.actions).

**Zscaler Proxy Traffic.** Zscaler Proxy Traffic allows HTTP tunnel traffic, such as HTTP CONNECT requests, to flow through the Zscaler Firewall engine without bypassing the Proxy engine. By default it is enabled and has the highest precedence (rule order 1). Zscaler recommends keeping it enabled if the organization uses HTTP CONNECT requests (it can be disabled otherwise), its Network Services attribute is preset to Zscaler Proxy Network Service (all Zscaler-specific web proxy ports and customer-specific DPPC ports), its URL Categories attribute is preset to Zscaler Proxy IPs, and Zscaler recommends not editing its attributes. [zia.firewall.predefined-rules:proxy-traffic-rule]

**Block Malicious IPs and Domains.** The Block Malicious IPs and Domains rule blocks traffic in the Zscaler Firewall directed to destinations that are malicious IP addresses or domains (FQDNs) categorized as malicious. It is created in an enabled state with a higher rule order, and the admin can prioritize it as needed. For false positives, custom rules can be created with higher ranks or the rule disabled. Its destination IP criteria are non-modifiable, and its Logging option is Full Logging by default. [zia.firewall.predefined-rules:block-malicious-rule]

**Block All IPv6.** The Understanding Predefined Firewall Filtering Rules page says that when IPv6 support is enabled at the organization level, the Block All IPv6 rule is created to block IPv6 traffic from the organization to any destination through the Zscaler service. It is created enabled, with the highest precedence (top Rule Order) among rules assigned an admin rank of 7, with the Block/Drop action and Aggregate logging. It is deleted when IPv6 support is disabled and recreated enabled with Block/Drop when IPv6 support is enabled again. [zia.firewall.predefined-rules:block-all-ipv6] Where the rule sits differs between two help pages [divergence:zia.firewall.predefined-rules:block-all-ipv6-placement]. The IPv6 settings side is in [IPv6 through ZIA: forwarding per method, prerequisites, processing and policy](kb:zia.traffic-forwarding.ipv6).

**Office 365 One Click Rule.** The Office 365 One Click firewall rule is not configurable and cannot be deleted. It is created to handle Microsoft 365 traffic through the Firewall module without inspecting it, and allows Microsoft 365 traffic whose destination IP address matches Microsoft 365 categories. It appears at rule order one with the enabling admin's rank if that rank is greater than or equal to that of the Firewall rule with top order, and at rule order one with rank 7 if admin rank is disabled. [zia.firewall.predefined-rules:o365-firewall-rule] When Microsoft 365 traffic is sent to the firewall, the service fingerprints the application, and all the fingerprinted information is logged and viewable on the Microsoft 365 dashboard. [zia.firewall.predefined-rules:o365-fingerprint]

The recommended settings for these rules are in [Recommended Firewall Filtering, DNS Control and IPS Control rules](kb:zia.firewall.best-practices), and the Terraform names the provider refuses to delete are in [Firewall rule order, admin rank and predefined rules](kb:zia.firewall.rule-order).

- Where Block All IPv6 sits: the predefined-rules page creates it at the top rule order among rank-7 rules, while the IPv6 settings page recommends giving it the lowest precedence, after the Default Firewall Filtering Rule. [divergence:zia.firewall.predefined-rules:block-all-ipv6-placement]
  - zscaler-help: The rule is created with the highest precedence (top Rule Order) among rules assigned an admin rank of 7.
  - zscaler-help: Zscaler recommends assigning these rules the lowest precedence, following the Default Firewall Filtering Rule.
