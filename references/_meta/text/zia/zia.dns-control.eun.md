# DNS Control end user notifications: static web, advanced web and Client Connector EUNs (zia.dns-control.eun)
Also called: dns eun; blockpage.zscaler.com; static web eun; dns basic web eun; dns advanced web eun; 34.215.46.88

DNS Control has three EUN types, all configured at the individual rule level: the DNS Basic Web EUN (Static Web EUN), the DNS Advanced Web EUN (integrated with the Internet & SaaS web proxy) and the Zscaler Client Connector-based EUN. [zia.dns-control.eun:eun-types] The one-sentence summary of EUN logging is in [DNS Control actions and what each API action requires](kb:zia.dns-control.actions).

**Basic (static) web EUN.** The Basic (static) web EUN is enabled per rule by manually configuring an EUN IP address with the Redirect Response action. Zscaler hosts it at the fixed IP 34.215.46.88 and the FQDN blockpage.zscaler.com, a CNAME record that resolves to IP addresses that could change. It applies to DNS A requests, is static and non-customizable, is primarily designed for HTTP-based web EUN requests with potential HTTPS compatibility depending on browser behavior, suits unauthenticated users such as guest Wi-Fi, and its requests can reach the EUN web server via Internet & SaaS or directly through the internet. [zia.dns-control.eun:basic-web-eun] The static DNS EUN web server (34.215.46.88/blockpage.zscaler.com) only responds to web requests and drops all other traffic, such as ping traffic. [zia.dns-control.eun:static-server-web-only] The static DNS EUN web page is displayed only if the browser falls back to HTTP on receiving the "HTTP 400 Bad Request" response from the EUN web server and then makes an HTTP GET request using HTTP; otherwise it is not displayed. It might also not be displayed for blocked domains that use HTTP Strict Transport Security (HSTS). [zia.dns-control.eun:static-page-http-fallback] The page does not say whether AAAA queries can reach the static page [gap:zia.dns-control.eun:static-eun-aaaa].

**Advanced web EUN.** The Advanced web EUN is enabled per rule with the Block action plus an option to enable the web EUN notification, and is supported only with the Block action. The EUN page is served only for A and AAAA DNS record types. Requests must reach Internet & SaaS via GRE, IPSec or Z-Tunnel 2.0, or come from a known location. For HTTPS a Zscaler intermediate CA certificate or an organization-configured custom certificate completes the TLS handshake, but in guest Wi-Fi environments without the certificate on the device a certificate error or warning displays. Its customization settings are shared by other browser-based EUNs. [zia.dns-control.eun:advanced-web-eun]

**Client Connector EUN.** The Client Connector EUN is enabled per rule for the Block, Block with Response Code and Redirect Response actions, with an option to select the default or custom notification message. It is supported for all DNS transactions managed by DNS Control, including DNS over UDP, TCP and HTTPS, on Windows devices running Zscaler Client Connector version 4.8 and later over Z-Tunnel 2.0. The DNS Advanced Web EUN and the Client Connector EUN cannot function simultaneously: when both are enabled, the Web EUN takes precedence and only it is displayed to users. [zia.dns-control.eun:cc-eun]

**Certificates, bypasses and DoH.** If a web request to the static DNS EUN web server is sent via Internet & SaaS, the browser needs to trust the Zscaler Certificate Authority certificate (or an SSL/TLS Inspection bypass policy is configured), and the Internet & SaaS security policies must allow the traffic. If the request goes directly to the internet, the certificate shown for blockpage.zscaler.com is issued by a well-known CA, for which the page's example is DigiCert Global, and when it goes through Internet & SaaS with SSL/TLS Inspection the certificate is issued by the Zscaler Intermediate Root CA. [zia.dns-control.eun:static-certs] Zscaler considers it preferable to bypass web traffic destined for the DNS EUN web server so it reaches the internet directly instead of going via Internet & SaaS. With Client Connector, 34.215.46.88 is added to the IPv4 Exclusion list under App and IP Bypass > IP Bypasses and blockpage.zscaler.com to the VPN Gateway Bypass list under App and IP Bypass > Global Bypasses, and with a PAC file the same entries are added to the PAC file. [zia.dns-control.eun:bypass-static-eun] If the web request to the DNS EUN web server is sent via Internet & SaaS, the page says to add an SSL/TLS Inspection bypass policy for this web traffic, creating that policy for a custom URL category with the rule actions set to Do Not Inspect and Bypass Other Policies. [zia.dns-control.eun:ssl-bypass-for-eun] For the DNS Control policy to be applied to DoH traffic, DoH traffic must be sent using a tunnel (GRE, IPSec or Z-Tunnel 2.0) and SSL/TLS Inspection must be enabled for that traffic. In the page's guest Wi-Fi scenario, DoH traffic is not sent to Internet & SaaS, so the DNS Control policy is not applied to it. [zia.dns-control.eun:doh-applicability] If the client browser is using secure DNS or DoH, the page says to add a firewall filtering rule that blocks QUIC as a network service, or to ensure the Default Firewall Filtering Rule is blocking QUIC, or alternatively to block QUIC in the browser itself, because some secure DNS or DoH providers might use QUIC as the underlying transport protocol; when QUIC is blocked it has a failsafe to fall back to TCP. [zia.dns-control.eun:block-quic-for-doh] The DoH control itself is in [DNS over HTTPS in DNS Control](kb:zia.dns-control.doh).
