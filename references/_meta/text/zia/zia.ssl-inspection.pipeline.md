# Where SSL inspection sits in ZIA web policy evaluation (the two passes) (zia.ssl-inspection.pipeline)
Also called: two-pass model; does ssl inspection happen before url filtering; sni pass; connect pass; do not inspect evaluate other policies; do not inspect bypass other policies; policy enforcement order
Former IDs: zia-11, zia-12

"Does SSL inspection happen before or after URL Filtering?" has no one-word answer, and the flat answer ("before") loses the behavior that matters most.

Web traffic is evaluated by the firewall module first; only traffic that passes it reaches the web module. A firewall allow does not override a web-module block. [zia.ssl-inspection.pipeline:firewall-first]

Before any decryption, URL Filtering and Cloud App Control evaluate on the destination domain alone: the CONNECT request in explicit proxy mode, the TLS Client Hello SNI in transparent mode. [zia.ssl-inspection.pipeline:first-pass-on-domain] Only domain-based policies run in that first pass: Known Malicious URLs (Advanced Threat Protection), Cloud App Control, URL Filtering (matching the domain against URL categories and custom categories), and Bandwidth Control. [zia.ssl-inspection.pipeline:first-pass-subset] A first-pass block on a destination known to contain an advanced threat ends the connection immediately, without an end user notification even when SSL/TLS Inspection is enabled: a block on the CONNECT host header returns HTTP 403, a block on the SNI resets the connection. With SSL/TLS Inspection disabled and Show EUN for Blocked Traffic off, any first-pass block ends the connection the same way. [zia.ssl-inspection.pipeline:first-pass-block]

The SSL inspection policy is evaluated on the same CONNECT or SNI information and decides whether the connection is decrypted. [zia.ssl-inspection.pipeline:ssl-decision-between] If the connection is inspected: When the connection is inspected and allowed, ZIA decrypts the following HTTP transactions and enforces policy on them. [zia.ssl-inspection.pipeline:second-pass-after-decrypt] On inspected HTTPS, URL Filtering therefore evaluates twice: first on the domain, then on the full decrypted request. "SSL inspection happens before URL Filtering" is wrong: the SSL decision sits between the two URL Filtering passes and gates only the second. [zia.ssl-inspection.pipeline:url-filtering-twice]

When SSL inspection does not decrypt but other policies are still evaluated (Do Not Inspect with Evaluate Other Policies), only the domain-level pass happens: a URL Filtering block on the domain still fires, while path-, method-, and payload-based rules and decrypt-dependent features (DLP, sandbox, malware) do not. [zia.ssl-inspection.pipeline:not-inspected-domain-only] Do Not Inspect with Bypass Other Policies skips URL Filtering and Cloud App Control entirely for that traffic, not just decryption; Zscaler advises against it for custom exemptions. [zia.ssl-inspection.pipeline:bypass-other-policies] Under transparent forwarding, SSL inspection exemption policies are evaluated on the IP address as well as the SNI, and most IP addresses are categorized Miscellaneous or Unknown, so exempting that category exempts almost all traffic. Under explicit forwarding only the SNI is evaluated. [zia.ssl-inspection.pipeline:transparent-matches-destination-ip] So at a location forwarding through a GRE or IPSec tunnel, an SSL inspection exemption for the Miscellaneous or Unknown category exempts almost all of that location's traffic. [zia.ssl-inspection.pipeline:tunnel-locations-misc-exemption]

With SSL inspection off but Show EUN for Blocked Traffic on, ZIA still decrypts the first HTTPS transaction of a blocked connection to show the notification; the help's policy evaluation workflow places this case under the SSL/TLS Inspection enabled scenario. [zia.ssl-inspection.pipeline:eun-inspects-first-transaction] User-scoped rules can only apply in the first pass if the user is known then (Surrogate IP or Client Connector); without user context on a location with authentication enabled, ZIA skips that evaluation to avoid an incorrect decision. [zia.ssl-inspection.pipeline:user-context-needed]

Criteria that need the full request are covered in [How URL Filtering rule criteria combine](kb:zia.url-filtering.criteria); Cloud App Control's place in each pass is in [Cloud App Control versus URL Filtering: which applies](kb:zia.cloud-app-control.precedence).
