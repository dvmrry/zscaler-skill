# Runbook diagnostics: HAR analysis, QUIC detection, XFF compatibility and SSL configuration checks (zia.troubleshooting-runbook.diagnostics)
Also called: HAR file capture; is the website using QUIC; XFF header test; validate SSL configuration of a web server

**Capturing headers.** In Chromium versions 130 and later the exported HAR file has less detail; to capture all data, adjust the Developer Tools settings by selecting Allow to generate HAR (with sensitive data) and use the Export menu option to export sensitive data. [zia.troubleshooting-runbook.diagnostics:har-chromium-130] For non-browser applications such as Outlook, Teams and Slack, the runbook says a third-party application such as Fiddler or Charles Proxy is needed to capture HTTP headers; it says these applications insert themselves as the system proxy. [zia.troubleshooting-runbook.diagnostics:har-thick-apps] With Zscaler Client Connector not enabled, Fiddler Classic is configured to decrypt HTTPS under Tools > Options > HTTPS, and the capture is saved via File > Save > All sessions as a *.saz file. [zia.troubleshooting-runbook.diagnostics:har-fiddler-no-zcc]

**Analyzing headers.** Most browsers export HTTP headers to a .har file, while Fiddler typically saves a .saz file. [zia.troubleshooting-runbook.diagnostics:har-formats] The HTTP version of a request, shown in the Google HAR analyzer, helps show whether it was proxied through Zscaler: generally the response is HTTP 1.1 unless the organization enabled and configured H2. [zia.troubleshooting-runbook.diagnostics:har-http-version-proxied] For Tunnel 1/Explicit Proxy the remote address can be checked for a Proxy VIP; the remote IP identifies the node a request lands on, but the Zscaler admin portals are behind the cloudfront CDN so their IP is an AWS one. [zia.troubleshooting-runbook.diagnostics:har-remote-ip]

**QUIC.** In Google Chrome developer tools, QUIC shows as h3 when the Protocol column is selected; a valid response code such as 200 for an h3 transaction means the request succeeded using QUIC. [zia.troubleshooting-runbook.diagnostics:quic-browser-h3] To find QUIC in Firewall Insights logs, filter on the Network Service QUIC; if a header trace shows QUIC but there are no firewall log entries for that time, the runbook says the QUIC traffic did not go to the Zscaler service. [zia.troubleshooting-runbook.diagnostics:quic-firewall-insights] In Wireshark the display filter quic and tls.handshake.type==1 lists the handshakes using QUIC; no packets means the capture started after the website was already open or the website does not use QUIC. [zia.troubleshooting-runbook.diagnostics:quic-wireshark]

**XFF.** When a website is accessible only with SSL inspection disabled, the runbook has the reader test XFF compatibility on a test laptop with direct internet access: in Google Chrome, install the ModHeader extension, enter the XFF header name and a valid IP value, confirm at https://ip.zscaler.com that the traffic is not going through the Zscaler service, then try the website with and without the header. [zia.troubleshooting-runbook.diagnostics:xff-test-method] When SSL Inspection is enabled for a domain the Zscaler service almost always inserts the XFF header; Not Inspected in the SSL Policy Reason column means the Zscaler cloud could not have inserted it in such transactions. [zia.troubleshooting-runbook.diagnostics:xff-insertion-default] The Zscaler service does not insert XFF for domains in the Miscellaneous or Legal Liability categories, to prevent the organization's egress IPs from being denylisted. [zia.troubleshooting-runbook.diagnostics:xff-not-inserted-misc-legal] XFF is also not inserted when the transaction does not go through a Public Service Edge and XFF insertion is disabled on the Virtual Service Edge (xff_enable=0 in /sc/sme/conf/sc.conf), or for Source IP Anchoring traffic when Insert XFF Header for ZPA Traffic is disabled. [zia.troubleshooting-runbook.diagnostics:xff-not-inserted-vse-sipa] For a location with Use XFF from Client Request enabled, the service uses the private IP in the incoming XFF for sublocation detection and logs it in the Client IP column; the Service Edge replaces such headers with one holding the client's external IP before forwarding. [zia.troubleshooting-runbook.diagnostics:xff-from-client-request] Some websites (the page names agriculture.canada.ca and talabat.com) do not return a valid response to a request containing XFF; they may return an error or time out and almost never say XFF was the reason. [zia.troubleshooting-runbook.diagnostics:xff-incompatible-sites] If the website is trusted and business policy allows, turning off SSL Inspection for the domain automatically disables XFF insertion. [zia.troubleshooting-runbook.diagnostics:xff-solution] Whether XFF is always or almost always inserted is in dispute [divergence:zia.troubleshooting-runbook.diagnostics:xff-always-vs-almost-always].

**SSL configuration of a web server.** In SSL Labs, if any of the Certificate, Protocol Support, Key Exchange or Cipher Strength summary indicators is not green, it helps explain why the certificate was considered bad or untrusted. [zia.troubleshooting-runbook.diagnostics:sslv-ssllabs-indicators] The page lists strong ciphers as ECDHE/DHE for forward secrecy, AES-256/AES-128, GCM/CBC and SHA256/SHA384, and says a server answering with Cipher is RC4-SHA or similar accepts weak ciphers. [zia.troubleshooting-runbook.diagnostics:sslv-openssl-ciphers] With openssl, identical Issuer and Subject values mean a self-signed certificate, which must never be seen for a public production website; a chain count of 1 means the only certificate's issuer must be in the application's trusted CA store, and a complete chain has each certificate's AKI matching the next certificate's SKI. [zia.troubleshooting-runbook.diagnostics:sslv-selfsigned-chain]

Sources disagree (name both sides):
- One runbook page says the Public Service Edge always inserts the XFF header when SSL inspection is enabled for a website; the XFF test page says it almost always does and lists exceptions. [divergence:zia.troubleshooting-runbook.diagnostics:xff-always-vs-almost-always]
  - zscaler-help: With SSL inspection enabled for a website, the Public Service Edge always inserts the XFF header with the client's external source IP.
  - zscaler-help: With SSL Inspection enabled for a domain the service almost always inserts XFF, and the page then lists cases where it does not.
  Impact: The XFF test page lists exceptions (Miscellaneous or Legal Liability categories, a Virtual Service Edge with insertion disabled, Source IP Anchoring) that the other page's Public Service Edge statement does not mention; the pages do not say whether those exceptions also apply there.
