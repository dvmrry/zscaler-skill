# Endpoint DLP API families in the SDKs and Terraform provider (zia.dlp.endpoint-dlp)
Also called: endpoint dlp api; endPointDlpRules; dlpEndpointResource; endpoint dlp resource groups; endpoint dlp custom apps; endpoint dlp sub rules; endpoint dlp terraform; zia_endpoint_dlp_rules; endpoint dlp channels

Endpoint DLP is not a flag on an inline DLP rule. It is several management families, and the evidence for them is client code and Terraform, not the vendor contract. Rules in both cases reference engines ([DLP engines: the unit a rule references](kb:zia.dlp.engines)); dictionary support differs, see [DLP dictionaries: predefined, cloned and custom](kb:zia.dlp.dictionaries).

The Go SDK manages Endpoint DLP as separate families, each with its own path: the application catalog (`/endPointApplications`) and custom applications (under `/endPointApplications/customApps`), application groups (`/endPointApplicationGroups`), endpoint resources (`/dlpEndpointResource`), resource groups (`/endPointDlpResourceGroups`), and rules with their exception (sub) rules (`/endPointDlpRules`). [zia.dlp.endpoint-dlp:families] The Go SDK release notes list Endpoint DLP exception (sub) rule create, update and delete under `/endPointDlpRules/{id}/subRule`. [zia.dlp.endpoint-dlp:release-note-sub-rules] Endpoint resources are grouped by four channels, PRINTING, REMOVABLE_DRIVE_TRANSFER, NETWORK_DRIVE_TRANSFER and PERSONAL_CLOUD_STORAGE, and channel-scoped reads take one of those values in the path. [zia.dlp.endpoint-dlp:resource-channels]

The console and enforcement behaviour of Endpoint DLP is in [How Endpoint DLP reaches the endpoint: prerequisites, policy delivery, offline enforcement, scans, and what the vendor says about evaluating all rules and exception rules](kb:zia.dlp.endpoint-enforcement), [Endpoint DLP policy rules: channels, criteria, actions (Allow, Block, Confirm, Protect) and notifications](kb:zia.dlp.endpoint-rules), [Endpoint DLP resources and resource tags: network shares, printers, removable storage, endpoint applications](kb:zia.dlp.endpoint-resources), [Endpoint Data Scan configuration: scan reporting, End User Reports, continuous and real-time classification, exemption, trusted applications, channel exceptions, activation](kb:zia.dlp.endpoint-settings) and [Endpoint IDM, Endpoint EDM and Share Files Externally](kb:zia.dlp.endpoint-sensitive-information).

The Endpoint DLP families are outside the current Automate API capture, so their fields cannot be checked against the vendor contract; the capture's divergence report lists the Go SDK and Terraform as their official surfaces. [zia.dlp.endpoint-dlp:outside-automate-capture] Whether a tenant is entitled to Endpoint DLP is open [gap:zia.dlp.endpoint-dlp:tenant-entitlement].

**SDK behavior.** The Go SDK's `GetAllEndpointApplications` and `GetAllEndpointApplicationsLite` page through the results themselves, requesting 5000 per page. [zia.dlp.endpoint-dlp:go-aggregates-pages] The Python SDK's endpoint application list issues one request and returns that response's current page, so it does not reproduce the Go aggregation; callers must page themselves. [zia.dlp.endpoint-dlp:python-single-page] The Endpoint DLP accessors are registered on the unified Python `ZIAService` client and not on the legacy client. [zia.dlp.endpoint-dlp:python-unified-client-only] For paging details across ZIA lists see [How the Go SDK pages through ZPA, ZCC and ZTC lists, and when it stops early](kb:shared.sdk-go.list-pagination).

In the Python SDK, custom-app list and get decode `EndpointApplicationsCustomApps`, but create and update declare and decode `DlpEndpointResource`. [zia.dlp.endpoint-dlp:python-custom-app-model-mixup] The Go shared endpoint-application request serializer sends only non-empty `resourceId` and `zappId`, because the API rejects writes that carry the read-only `version` and `versions` objects. [zia.dlp.endpoint-dlp:go-request-serializer] The shared Go model types `versions` as one `Versions` struct, while the custom-application response model types the same wire key as a list; the two response shapes are not interchangeable. [zia.dlp.endpoint-dlp:go-versions-shape-differs] Zero-value request structs for the resource channels are covered in [Why Terraform cannot clear some fields: omitted zero values and empty objects in SDK writes](kb:shared.sdk-go.zero-value-writes) and [ZIA Terraform resource fields that are not sent, not read back, or sent wrongly](kb:zia.terraform.field-fidelity).

**Terraform.** Terraform provider v4.8.0 added Endpoint DLP custom applications, application groups, resources, resource groups, rules and sub-rules, plus data sources for applications, rules, channels and resource group tags. Release context: Go SDK v3.8.41 and Python SDK v1.9.39 introduced the families; Terraform v4.8.0 added the provider side. [zia.dlp.endpoint-dlp:terraform-resources] Provider read and data source defects for these objects are in [What ZIA Terraform data sources return, drop, or get wrong](kb:zia.terraform.data-source-fidelity) and [When the ZIA Terraform provider reports success after an error, or crashes](kb:zia.terraform.error-handling).
