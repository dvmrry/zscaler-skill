# DLP engines: the unit a rule references (zia.dlp.engines)
Also called: dlp engine; can a dlp rule use my custom dictionary; engine expression; dlp engine boolean operators; predefined dlp engine; validateDlpExpr; dlp engine channels; endpoint dlp channels

A DLP engine is a collection of one or more DLP dictionaries, and any mix of cloned, predefined and custom dictionaries can be added to one. [zia.dlp.engines:engine-definition] DLP policy rules and Endpoint DLP policy rules must reference engines, not dictionaries. To use a custom dictionary in a rule, put it in an engine first. [zia.dlp.engines:rules-reference-engines] The Web DLP rule object carries a `dlpEngines` list and no field for dictionaries, so the indirection is an API-level requirement as well as a console one. [zia.dlp.engines:api-rule-has-engines-only] The dictionaries themselves are in [DLP dictionaries: predefined, cloned and custom](kb:zia.dlp.dictionaries); the rule side is in [Web DLP policy rules: order, criteria and actions](kb:zia.dlp.rules).

Zscaler provides predefined engines (the Match Only example names a PCI engine and a HIPAA engine) and supports custom ones. An admin can edit or clone a predefined engine as well as create a custom engine. [zia.dlp.engines:predefined-engines-exist] The Understanding DLP Engines page says the service provides 5 predefined engines (HIPAA, GLBA, PCI, Offensive Language, and Self-Harm & Cyberbullying) that contain default dictionaries, and that the Self-Harm & Cyberbullying engine is meant for K-12 educators and is enabled through the Zscaler Account team. [zia.dlp.engines:predefined-five-understanding] The number of predefined engines and who enables the Self-Harm & Cyberbullying engine differ between two help pages [divergence:zia.dlp.engines:predefined-engine-count] [divergence:zia.dlp.engines:self-harm-contact]. Any predefined or custom engine can be duplicated (cloned) to copy its functionality for a different use, with a name specified for the new engine. [zia.dlp.engines:clone-engine]

**Predefined engine contents.** The Editing Predefined DLP Engines page gives the dictionaries behind the original engines: HIPAA uses Social Security Numbers (US) and Medical Information; GLBA uses Social Security Numbers (US) and Financial Statements; PCI uses Credit Cards and Social Security Numbers (US); Offensive Language uses Adult Content; Self-Harm & Cyberbullying uses the Self-Harm & Cyberbullying dictionary. [zia.dlp.engines:predefined-original-composition] The editing page also lists CCPA, Credentials and Secrets, DPDPA, Finance, FISMA, GDPR, Legal, LGPD, Medical, NIST RMF for DoD IT, PDPA, PII (US) and PIPEDA engines, each marked available by default for tenants enabled on April 4, 2025 or later, with access for other tenants requested from Zscaler Support. [zia.dlp.engines:predefined-2025-engines] The editing page gives these dictionaries behind the CCPA, Credentials and Secrets, DPDPA, Finance, FISMA, Legal, LGPD, Medical, NIST RMF for DoD IT, PDPA, PII (US) and PIPEDA engines: CCPA uses Social Security Numbers (US), Tax Identification Number (US), Names (US), Medical Information, Diseases Information, Drugs Information and Credit Card; Credentials and Secrets uses Credentials and Secrets; DPDPA uses Aadhaar Card Number (India); Finance uses Financial Statements, ABA Bank Routing Number, Credit Cards and International Bank Account Number (IBAN); FISMA uses Credit Cards, Diseases Information, Drugs Information and Social Security Numbers (US); Legal uses Legal Document; LGPD uses CNPJ Number (Brazil) and Individual Taxpayer Registry ID (Brazil); Medical uses Medical Information, Diseases Information, Drugs Information, National Provider Identifier Number (US), NDC Number (Package), NDC Number (Product) and Treatments Information; NIST RMF for DoD IT uses Credit Cards, Diseases Information, Drugs Information, Social Security Numbers (US), Names (US) and Medical Information; PDPA uses NRIC Numbers (Singapore) and Credit Cards; PII (US) uses Social Security Numbers (US) and Tax Identification Number (US); PIPEDA uses Names (Canada), Social Insurance Number (Canada), ABA Bank Routing Number and Credit Cards. The page also lists the dictionaries behind the GDPR engines, beginning with Unified Civil Number (Bulgaria), not enumerated here. [zia.dlp.engines:predefined-2025-composition] For CCPA, FISMA, GDPR, LGPD, NIST RMF for DoD IT, PDPA, PII (US) and PIPEDA the page lists a High Volume engine (a high threshold, more than 25 matches) and a Low Volume engine (a low threshold, more than one match). Finance, Legal and Medical are described as ML-based engines. [zia.dlp.engines:predefined-volume-variants] What ML-based means for the Finance, Legal and Medical engines is open [gap:zia.dlp.engines:ml-based-engines], and so is which engines tenants enabled before that date see by default [gap:zia.dlp.engines:predefined-engine-visibility].

**Composition.** An engine combines dictionaries with Boolean operators into a logical expression. The API expresses this as `engineExpression`, using All (AND), Any (OR), Exclude (NOT) and Sum (the total number of content matches). [zia.dlp.engines:boolean-composition] On the wire an expression references dictionaries by ID, each wrapped in a `D` prefix and an `.S` suffix and compared with a number, for example `((D63.S > 1) AND (D38.S > 0))`. The engine object stores the expression as one string; it has no separate list of dictionaries. [zia.dlp.engines:expression-wire-form] The API has an endpoint that validates an engine expression. [zia.dlp.engines:validate-expression-endpoint]

**Operators and match counts.** Engine expressions use the operators All (AND), Any (OR), Exclude (AND NOT) and Sum; Sum sets the total number of matches that triggers a group of dictionaries and is available for count-based dictionaries such as Credit Cards and Social Security Numbers. The root expression allows only All, Any and Sum, and a subexpression cannot be added to an expression or subexpression that uses Sum, though Sum can be used inside a subexpression. [zia.dlp.engines:operators-and-root] The match count is the threshold that triggers a dictionary or group of dictionaries, and they trigger only when they find more matches than the number entered: with Sum over 3 dictionaries and a count of 6, the policy triggers at 7 or more matches across them. With multiple dictionaries each carrying its own count, a dictionary triggers only when its own threshold is reached. One dictionary can sit in several engines with a different count in each. [zia.dlp.engines:match-count-semantics] What the API's `.S` suffix means is open [gap:zia.dlp.engines:expression-threshold-meaning]. A predefined dictionary's Confidence Score Threshold is set in the dictionary itself, not in the engine. [zia.dlp.engines:confidence-set-in-dictionary]

**Builder.** In the engine builder, Sum needs two or more dictionaries and a match count; All, Any or Exclude need a dictionary, and certain dictionaries require a match count. A match count is any value less than 1,000. Each level allows up to 4 subexpressions, 4 operators and 16 dictionaries per operator, and an engine description cannot exceed 255 characters. [zia.dlp.engines:builder-limits] When an engine uses a parent dictionary a sub-dictionary can also be selected, and must be when the parent has no patterns or phrases. Parent and sub-dictionaries in an engine are evaluated separately and can match independently; sub-dictionaries appear in brackets in the expression. [zia.dlp.engines:parent-sub-in-engines] If an expression sent through the API is broken or not recognized, even though it is correct in form (the page says "synthetically correct"), the console's engine builder cannot parse it: the Edit DLP Engine window shows it in a Reference Expression field and displays a blank Engine Builder section, and the expression must be recreated by hand. The page's examples of unparseable expressions are (D63.S > 0 AND NOT D39.S > 0), (D63.S > 0 OR NOT D39.S > 0 AND NOT D125.S > 0) and (SUM(D63.S, D246.S) > 2). [zia.dlp.engines:api-expression-unparseable]

The DLP Engines page shows, per engine, the channels associated with it; the captured row names Endpoint DLP, SaaS Security, DSPM, Inline Web, and Email. [zia.dlp.engines:engine-channels] Creating an engine requires selecting a channel, and excluding a channel can reduce noise from engines used unnecessarily. Channels can also be overridden from the DLP Engines table, but a channel cannot be removed from an engine used in an active policy. [zia.dlp.engines:channels-required]

A tenant can hold 480 custom engines with DLP Engine Expansion enabled and 58 without it. [zia.dlp.engines:engine-limits] The Understanding DLP Engines page gives a different custom engine ceiling [divergence:zia.dlp.engines:custom-engine-ceiling].

Terraform's handling of engines and rules has its own defects; see [ZIA Terraform resource fields that are not sent, not read back, or sent wrongly](kb:zia.terraform.field-fidelity). The Terraform `zia_dlp_engines` documentation says to contact Zscaler Support to have the POST, PUT and DELETE API methods enabled for the organization before using the resource. [zia.dlp.engines:tf-custom-engine-writes-need-support]

What to check:
1. Whether the custom dictionary is in an engine, and whether that engine is on the rule, since a rule cannot reference a dictionary directly.
2. Whether the D<number> terms of an engine expression are resolved to dictionary IDs, since the engine object carries only the expression string.
3. Whether a channel-scoped engine triggers on web traffic, which a lab test would show.
4. Which of the pages that disagree on the custom engine ceiling or the predefined engine count the answer rests on, and say so rather than choosing one.
5. Whether an engine whose expression came through the API opens in the Engine Builder or only in a Reference Expression field, since the API reference's own SUM example has the same shape as one the help lists as unparseable.

- Two help pages give different ceilings for custom DLP engines. [divergence:zia.dlp.engines:custom-engine-ceiling]
  - zscaler-help: The Understanding DLP Engines page says a maximum of 512 custom DLP engines can be created.

  Impact: A count of custom engines near the ceiling cannot be judged against one number; which page is current and whether DLP Engine Expansion explains the difference is not stated.
- The Understanding page lists 5 predefined engines, while the Editing page lists more engines marked by tenant enablement date. [divergence:zia.dlp.engines:predefined-engine-count]
  - zscaler-help: The Understanding DLP Engines page says the service provides 5 predefined engines and names them.
  - zscaler-help: The Editing Predefined DLP Engines page lists further engines, such as CCPA, available by default for tenants enabled on April 4, 2025 or later.
  Impact: How many predefined engines a tenant has depends on the page read and the tenant's enablement date; the pages do not say whether the Understanding page predates the newer engines.
- The two pages name different contacts for enabling the Self-Harm & Cyberbullying engine. [divergence:zia.dlp.engines:self-harm-contact]
  - zscaler-help: The Understanding DLP Engines page says to contact the Zscaler Account team.
  - zscaler-help: The Editing Predefined DLP Engines page says to contact Zscaler Support.
  Impact: Who enables the engine depends on the page followed.
