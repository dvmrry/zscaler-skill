# Microsoft Defender for Cloud Apps (MCAS) integration: the MS Defender Unsanctioned Apps URL category sync (zia.url-categories.mcas-sync)
Also called: mcas; microsoft cloud app security; MS Defender Unsanctioned Apps; unsanctioned apps sync; configure-mcas2

The MCAS integration turns the applications MCAS marks unsanctioned into a custom URL category. When MCAS and Zscaler are integrated, Zscaler syncs unsanctioned application URLs to a custom URL category called MS Defender Unsanctioned Apps. The integration enables discovery of unsanctioned applications and automatic update of the category based on the organization's web transaction logs streaming from Internet & SaaS (ZIA) through NSS to MCAS. [zia.url-categories.mcas-sync:what] The partner integrations overview and the MCAS page differ on whether a block rule is applied for the admin [divergence:zia.url-categories.mcas-sync:mcas-block-rule].

**Authorizing it.** The integration uses the OAuth 2.0 method, which grants access based on the application's context, with permissions set at the application level and not inherited by the user. The Entra ID application's supported account types are Accounts in this organizational directory only (single tenant), its client secret value is displayed only once, and it uses the discovery.manage permission, required to upload data and generate block scripts, with admin consent granted. [zia.url-categories.mcas-sync:oauth-app] The Admin Console takes the Client ID (the Application (client) ID), the client secret value and not the client secret ID, the scope (Microsoft currently defines 05a65629-4c1b-48c1-a78b-804c4abdd4af for MCAS, entered with /.default), the Authentication URL https://login.microsoftonline.com/<Tenant ID>/oauth2/v2.0/token and the API URL for the tenant. If the configuration is not valid, the reason for the failure appears on the page and is logged in the audit logs (Administration > Admin Management > Audit Logs > Internet & SaaS). Clearing the configuration stops the syncing but does not remove the MS Defender Unsanctioned Apps category, as it might be in use by configured policies. [zia.url-categories.mcas-sync:console-fields]

**NSS side.** In configuring the partner integration in the Admin Console, the NSS Subscription step also requires an active NSS web log subscription or trial, a healthy NSS web server enabled and an MCAS NSS feed configured for that server. After the configuration is validated on the Partner Integrations page, the OAuth 2.0 authentication parameters are pushed to the MCAS NSS feed configuration (in the backend only), then to the Zscaler Central Authority, which pushes it to NSS. For the MCAS NSS feed to perform optimally, the VM deployed for the NSS web server requires a minimum of 8 GB of RAM. [zia.url-categories.mcas-sync:nss-prereqs] For automatic log upload the MCAS data source selects Zscaler QRadar LEEF as the Source and Syslog - UDP as the Receiver type, and the NSS service is configured by running sudo nss configure-mcas2 on the NSS VM and then restarted with sudo nss restart; the command sudo nss configure-mcas used for token-based integrations does not work for OAuth 2.0-based integrations. NSS gets the logs from the Zscaler Nanolog, converts them to the MCAS NSS feed output format (LEEF) and sends them for uploading to MCAS. [zia.url-categories.mcas-sync:log-upload] The shared NSS subjects are [NSS feed destination and delivery settings by feed kind: TCP, HTTP, Cloud NSS and MCAS](kb:shared.nss.feed-settings) and [Operating and troubleshooting a deployed NSS VM: the nss command set, error codes and connection checks](kb:shared.nss.vm-operations).

**Sync and enforcement.** The first unsanctioned Cloud App URL sync occurs within two hours, and syncs to the custom URL category occur every two hours after that. If the organization exceeds the maximum custom category limit, the sync fails; a sync not occurring every two hours goes to Zscaler Support. [zia.url-categories.mcas-sync:sync-timing] The category limit that fails the sync is not on the page [gap:zia.url-categories.mcas-sync:category-limit]. The MS Defender Unsanctioned Apps URL category must be assigned to a URL filtering rule to block the traffic to those destinations, and Zscaler recommends SSL inspection for that category in case some sanctioned applications are uniquely identified by a full URL rather than just a domain name. On an MCAS authentication validation error with a valid and verified configuration, at least one application must be categorized as unsanctioned within the MCAS portal. [zia.url-categories.mcas-sync:enforcement-and-troubleshooting]

**Token-based integrations.** An existing MCAS partner integration using token-based authentication remains supported for backward compatibility, but no configuration changes can be made to it and a new token-based integration cannot be created. After conversion the token method is no longer available as an option, and without an existing token-based integration it is not available in the Admin Console at all. [zia.url-categories.mcas-sync:token-legacy]

What to check:
1. Whether the MS Defender Unsanctioned Apps category is used by a URL Filtering rule, since the MCAS page says it must be assigned to one to block; the overview page's block rule is a divergence, not a settled default.
2. Whether the sync is failing because of the organization's custom category limit.

Sources disagree (name both sides):
- The partner integrations overview says URLs of applications unknown to Zscaler are denylisted through a custom category with a block policy rule applied to it, while the MCAS page says the category must be assigned to a URL Filtering rule to block. [divergence:zia.url-categories.mcas-sync:mcas-block-rule]
  - zscaler-help: The service denylists the URLs using a custom category with a block policy rule applied to it.
  - zscaler-help: The admin must assign the category to a URL filtering rule to block the traffic.
  Impact: Whether a block rule exists for the synced category without the admin creating one is stated differently; the pages do not say whether the overview's rule is automatic.
