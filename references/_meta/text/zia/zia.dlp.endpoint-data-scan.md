# Endpoint Data Scan reports: the daily data-at-rest report, User and Device Investigation, DLP Operational and the End User Report (zia.dlp.endpoint-data-scan)
Also called: Endpoint Data Scan; Endpoint Data Scan report; User Investigation; Device Investigation; DLP Operational; End User Report

Endpoint Data Scan provides visibility into sensitive data stored locally within all the endpoints connected to the organization's traffic. The report runs daily automatically, and considers a file sensitive if it contains at least one DLP engine or AI & ML category match. [zia.dlp.endpoint-data-scan:what-and-cadence] The report opens in a new browser tab, and its Account section shows the username, organization name, organization ID and cloud name. [zia.dlp.endpoint-data-scan:report-sections]

**The Endpoint Data Scan page.** The Endpoint Data Scan page exports to PDF and shows Total Files Scanned as a count with accumulated size, and its top users can be exported to CSV. Top DLP Engines and Departments cover the last 14 days, and the trend graph shows no data if filters are applied. [zia.dlp.endpoint-data-scan:report-page] On the Sensitive File Range Distribution, the admin specifies the Medium range and the Low and High ranges are set automatically to match. [zia.dlp.endpoint-data-scan:range-distribution] For a specific user the report shows top DLP engines, AI & ML categories, file types and a 30-day activity trend, and admins can download a report with metadata for all the user's detected sensitive files. [zia.dlp.endpoint-data-scan:per-user-drilldown]

**User Investigation.** User Investigation shows each user's Incidents (user activities that triggered Endpoint DLP rules over the last one month), Activities (user actions that triggered DLP engines over the last one month) and Sensitive Files Discovered, which is updated every day. It filters by User, Department, Endpoint Name, Risk, Last Updated and Last Data Scan, and exports to CSV. [zia.dlp.endpoint-data-scan:user-investigation] A user's Overview shows the Indicators of Intent rules the user triggered in the last 30 days, a section that is currently in Limited Availability. It also shows the user's total exfiltration attempts (allowed and blocked) and top destinations for the last 30 days. [zia.dlp.endpoint-data-scan:user-overview] A user's Data at Rest table shows the top 20 sensitive files based on DLP engines and AI & ML category match, with the dictionaries each file triggered; exporting the data gives the complete list of sensitive files discovered. [zia.dlp.endpoint-data-scan:user-data-at-rest]

**The user timeline.** The user Timeline has Outbound events (created from DLP engine or AI & ML category matches on sensitive file exfiltration to Removable Storage, Printer, Network Share or Personal Cloud Storage, without any rule being triggered), Inbound events (sensitive files arriving from web, removable storage and network share on a DLP engine match, aggregated by source over a rolling 15 minutes), Incidents (Endpoint DLP or Device Control rules triggered) and Indicators of Intent. [zia.dlp.endpoint-data-scan:user-timeline-event-types] The user Timeline filters on Type, Channel, Destinations, Destination Type, Severity, DLP Engines, AI & ML Categories, Transaction ID and Rule Name. An event's date is the local time at the endpoint, and its Policy & Detection shows the triggered rule with the other rules that matched. [zia.dlp.endpoint-data-scan:user-timeline-details] How the Inbound, Outbound and Indicators of Intent events map to the NSS Endpoint DLP record type is open [gap:zia.dlp.endpoint-data-scan:timeline-nss-mapping].

**Device Investigation.** Device Investigation shows endpoint health, hovering over an unhealthy endpoint's error giving the reason, and a Nearby Sharing status. Allowed means Endpoint DLP enables nearby sharing but does not override or enforce it if another product blocks it, Blocked means Endpoint DLP prevents file transfers to nearby sharing devices, and Disabled means Endpoint DLP does not restrict nearby sharing. It exports to CSV. [zia.dlp.endpoint-data-scan:device-investigation] Device Investigation filters on Endpoint DLP Version, Endpoint DLP Policy Version, Device Control Policy Version, Endpoint DLP Mode, Zscaler Client Connector Version and Anti Tampering Status. An endpoint's details show Sensitive Files Discovered from the last scan, performed every day, with a 30-day trend, and an Overview with the Endpoint DLP Installation Time and Device Control Policy Version. [zia.dlp.endpoint-data-scan:device-investigation-details] What the Endpoint DLP Mode values are is open [gap:zia.dlp.endpoint-data-scan:endpoint-dlp-mode-values].

**DLP Operational.** DLP Operational shows Total Endpoints (Windows and macOS devices on which Endpoint DLP is installed) and Users in Exemption Mode. The time frame that defines an endpoint's active status is Last 3 Days, Last 7 Days or Last 14 Days, and the report exports as CSV or PDF. [zia.dlp.endpoint-data-scan:dlp-operational] DLP Operational action items include endpoints with anti-tampering disabled, a share of users in exemption mode above a threshold, endpoints offline for over two weeks, HDD scanning disabled, the Endpoint Data Scan report disabled, and macOS endpoints with Full Disk Access disabled. Full Disk Access being disabled prevents Endpoint DLP from functioning properly, and the page says to configure a Mobile Device Management (MDM) profile to enforce it. [zia.dlp.endpoint-data-scan:dlp-operational-action-items] An endpoint is considered to be using the latest version of the policy if both the Endpoint DLP policy version and the Device Control policy version are the latest, else it is considered to be using the earlier version. [zia.dlp.endpoint-data-scan:dlp-operational-policy-version] How a user enters exemption mode is an open question recorded in [Endpoint Data Scan configuration: scan reporting, End User Reports, continuous and real-time classification, exemption, trusted applications, channel exceptions, activation](kb:zia.dlp.endpoint-settings).

**The End User Report.** After the Endpoint Data Scan completes, the end user receives a notification with the number of sensitive files found locally. End users can open the latest report from the desktop context menu (Zscaler > Open Data Scan Report) and filter it by date, file type or file content; DLP engine details appear if configured by the admin. [zia.dlp.endpoint-data-scan:end-user-report-viewing] The settings that govern it are in [Endpoint Data Scan configuration: scan reporting, End User Reports, continuous and real-time classification, exemption, trusted applications, channel exceptions, activation](kb:zia.dlp.endpoint-settings).

**Related.** The inventory pages are in [Endpoint inventory and Application Investigation: detected removable storage, printers, portable devices and applications](kb:zia.dlp.endpoint-inventory), Indicators of Intent in [Indicators of Intent: predefined risky-behaviour rules on the endpoint and their exceptions](kb:zia.dlp.endpoint-intent) and Device Control in [Device Control rules per device class, the default rule, first-match evaluation and device control resources](kb:zia.dlp.endpoint-device-control).

What to check:
1. Whether a count on the Endpoint Data Scan page is a filtered view, since the trend graph shows no data when filters are applied.
2. Which policy version an endpoint counts as using in DLP Operational: both the Endpoint DLP and Device Control versions must be the latest.
