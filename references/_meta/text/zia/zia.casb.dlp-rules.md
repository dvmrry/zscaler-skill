# CASB Data at Rest Scanning DLP rules (zia.casb.dlp-rules)
Also called: casbDlpRules; data at rest scanning dlp; saas dlp rule; OFLCASB_DLP_REPORT_INCIDENT; casb dlp action; collaboration scope; trusted users trusted domains; saas security dlp policy

A Data at Rest Scanning DLP rule is read in four steps: where it sits, who and what it scopes, what it inspects, and what it does.

**Where it sits.** Data at Rest Scanning DLP rules are evaluated in ascending rule order, and a disabled rule keeps its place in the order while the service skips it and moves to the next rule. [zia.casb.dlp-rules:rule-order-ascending] A rule's admin rank is a value from 0 to 7 (0 is the highest), an administrator cannot choose a rank higher than their own, a rule with a higher rank always precedes a rule with a lower rank in the order, and the API requires `rank` when admin rank-based access restriction is enabled. [zia.casb.dlp-rules:admin-rank] Terraform documents `order` for CASB rules as a positive whole number starting at 1 with no gaps; zero and negative values are rejected. At v4.8.10 through v4.8.13 the page said that after deleting a rule the remaining orders must be re-adjusted so the API honours the order; from v4.8.14 it says to renumber the remaining rules so the orders stay contiguous, and that the deletion and the renumbering can be applied together in one `terraform apply`. [zia.casb.dlp-rules:order-contract] Predefined CASB rules can be reordered through Terraform but not destroyed, and not all attributes available on custom rules apply to them. [zia.casb.dlp-rules:predefined-rules] A scan uses all applicable DLP engines for the application tenant in addition to the rule's selected engines when it inspects content, but the service enforces the DLP policy only by the highest priority DLP rule; the other engines are used for sensitive information discovery, which is viewable in the SaaS Assets Summary Report. [zia.casb.dlp-rules:enforce-highest-priority-rule] Whether evaluation stops at the first match, and what highest priority means against rule order, is open [gap:zia.casb.dlp-rules:first-match]. The About Data at Rest Scanning DLP page says its policy rules are evaluated in ascending numerical order, and that Entity Groups are the SharePoint groups the policy applies to. [zia.casb.dlp-rules:entity-groups-and-page] Data at Rest Scanning policy rules trigger on DLP Engines AND SaaS Application Tenants AND [Owners OR Groups OR Departments] AND Collaboration Scope AND File Type AND [Trusted Domains OR Trusted Users]. [zia.casb.dlp-rules:policy-execution] The category tokens and the separate DLP and malware lists are in [CASB rule types: the eight categories and their separate rule lists](kb:zia.casb.rule-types).

**Who and what it scopes.** A rule whose `cloudAppTenants` is not set applies to all tenants. [zia.casb.dlp-rules:tenants-empty-means-all] A rule with no users, groups or departments applies to all of them, and a rule with no `fileTypes` applies across all file types. [zia.casb.dlp-rules:scope-empty-means-all] When no value is set, `devices`, `deviceGroups` and `deviceTrustLevels` are ignored during policy evaluation; High, Medium and Low Trust apply only to Zscaler Client Connector traffic, while Unknown applies to all traffic. [zia.casb.dlp-rules:device-fields-ignored] An email rule selects senders as Any or up to 32 users, and groups as Any or up to 32 groups. [zia.casb.dlp-rules:senders-groups-32] For email rules the components (body, attachments and subject) cannot be changed, and the recipients condition cannot be changed: the rule applies only when at least one recipient is from outside the organization and that recipient is not an external trusted user or is not using an external trusted domain. [zia.casb.dlp-rules:email-fixed-fields] The `domains` field names the external organization sharing a channel and applies only when `contentLocation` is CONTENT_LOCATION_SHARED_CHANNEL. [zia.casb.dlp-rules:shared-channel-domains] The collaborator criteria `numberOfInternalCollaborators` and `numberOfExternalCollaborators` take one named range: 1 to 10, 11 to 100, 101 to 1000 or 1001 and above. [zia.casb.dlp-rules:collaborator-count-ranges]

**Trusted users and domains.** A rule can name trusted users or trusted domains but not both; the service treats them as internal, and a file matching all criteria together with the trusted users or domains is not a violation and is not acted on. [zia.casb.dlp-rules:trusted-exclusive] A domain profile or recipient profile used when onboarding a tenant is not available in a DLP rule, because it is already considered internal. [zia.casb.dlp-rules:tenant-profiles-considered-internal] The toggles `includeCriteriaDomainProfile`, `includeEmailRecipientProfile` and `includeEntityGroups` decide whether `criteriaDomainProfiles`, `emailRecipientProfiles` and `entityGroups` count as criteria; when false they are excluded from the criteria. [zia.casb.dlp-rules:criteria-toggles]

**What it inspects.** A rule's Content Matching selects up to 4 DLP engines, or Any engine. [zia.casb.dlp-rules:engines-max-4] Setting `withoutContentInspection` to true sets Content Matching to None for the rule. [zia.casb.dlp-rules:without-content-inspection] The `components` criterion accepts ANY and component values for email body, attachment and subject, ITSM objects and attachments, CRM chatter messages, CRM attachments in objects, CRM cases, collaboration messages and attachments, Gen AI messages and attachments, and file attachments. [zia.casb.dlp-rules:components-enum] The `fileTypes` criterion accepts ANY, NONE and FTCATEGORY_ file type categories; the API reference lists the full set. [zia.casb.dlp-rules:file-types-enum] For Microsoft Teams, Slack and Webex Teams, keywords within a file are detected regardless of length, but a term searched in a message or chat must be at least 8 bytes or it is not detected by the DLP action. [zia.casb.dlp-rules:collab-short-terms] Generative AI scanning includes attachments uploaded via Custom GPT and predefined GPT but takes no DLP or malware action on them because the download URL is unavailable, and it excludes text fields such as Description, Instructions, Name and Conversation Starters and malware in a conversation prompt. [zia.casb.dlp-rules:genai-scan-exceptions] Whether Gen AI messages include responses is open [gap:zia.casb.dlp-rules:genai-prompt-response]. File size and extracted-text limits are in [DLP file size, archive and text limits: why DLP did not catch a large file](kb:zia.dlp.inspection-limits); engines and dictionaries are in [DLP engines: the unit a rule references](kb:zia.dlp.engines).

**What it does.** The actions available on a rule depend on the selected SaaS application tenant, and the report-only action reports the incident and makes no changes to the file's collaboration scope. [zia.casb.dlp-rules:actions-depend-on-tenant] The Box, Google Drive and Atlassian label actions are offered only when a single tenant with defined labels is chosen; Google Drive and Atlassian tenants onboarded earlier must be reauthorized before Zscaler can see their labels. [zia.casb.dlp-rules:label-actions-single-tenant] The "After Expiry" sharing actions are available only for Google Drive; a custom expiration cannot be less than 7 days away, a periodic period keeps enforcing the rule on new and existing files while it is enabled and is extended when a collaborator is added, and a fixed expiration date makes the policy inactive after that date and is not extended. [zia.casb.dlp-rules:expiry-actions] A watermark action can retain the existing versioning, treating the watermarked file as a new version, or delete it, treating the watermarked file as a new file; on Confluence tenants watermarks are applied only to files attached to pages. [zia.casb.dlp-rules:watermark-versioning] A rule's severity is RULE_SEVERITY_HIGH, MEDIUM, LOW or INFO, and the Information level exists to track low-risk incidents that must be observed. [zia.casb.dlp-rules:severity-values] The meaning of each token is open [gap:zia.casb.dlp-rules:action-token-meanings]. Quarantine is in [CASB quarantine and tombstone files](kb:zia.casb.quarantine).

**Buckets.** For Amazon S3 and Google Cloud Platform tenants, buckets and a bucket owner can be chosen only after the rule is saved and a scan schedule exists. [zia.casb.dlp-rules:buckets-need-saved-rule-and-schedule] For a public cloud storage application rule, Buckets, Bucket Owner, Blob Containers and Blob Container Owner cannot be changed when the rule is first defined: after saving the rule, a scan schedule is created for the tenant and bucket or blob container names are selected there to create the list available to the DLP and Malware Detection policies, and only then can the rule be edited to configure those fields. [zia.casb.dlp-rules:storage-containers-after-schedule]

**Exceptions.** Data at Rest Scanning DLP policy exceptions are optional for sanctioned SaaS applications, for example for a CEO whose sent emails should not be inspected or a security research group's malicious files repository. Each application type's section has a user field plus Groups and Departments: Senders for collaboration and email applications, Owners for CRM, file sharing and ITSM applications, and Editors for source code repository applications. [zia.casb.dlp-rules:dlp-policy-exceptions] Exceptions for folders and users that cover both policies are in [Data at Rest Scanning (scanning) exceptions for file sharing applications exempt specific folders or users from the Data at Rest Scanning policy, which consists of the DLP and Malware Detection policies: the service completely ignores the files within an exempted folder and does not evaluate an exempted user. A folder exception takes the folder's full path and a user exception the owner, and up to 64 exceptions for folders and users can be added.](kb:zia.casb.scans:scanning-exceptions).

**Notification and forwarding.** A rule sends no notification unless an auditor and a notification template are selected. [zia.casb.dlp-rules:notification-needs-auditor] Data at Rest Scanning DLP has three evidence collection methods: an email notification for a rule violation; an incident receiver, which forwards the content that caused the violation to an on-premises incident receiver or to the organization's public cloud; and, for file sharing applications, a link to the file causing the violation. [zia.casb.dlp-rules:evidence-collection] A rule can forward incidents to a DLP incident receiver, which the Data at Rest Scanning DLP policy article (configuring-data-rest-scanning-dlp-policy) calls an on-premises receiver, or, with Cloud-to-Cloud Forwarding, to a public cloud such as Amazon S3, Microsoft Azure or Google Cloud Platform, and the API carries the choice in `receiver`. [zia.casb.dlp-rules:incident-receiver-field] How forwarding to an Incident Receiver or a cloud works is in [Where a DLP match goes: notification, ICAP, Incident Receiver and Cloud-to-Cloud](kb:zia.dlp.incident-forwarding), and where an Incident Receiver can run is in [Zscaler Incident Receiver: requirements per platform, storage, health check and VM commands](kb:zia.dlp.incident-receiver).

**Access and contract.** The rule field `accessControl` is the access privilege of the rule under the administrator's Role Based Authorization state, one of NONE, READ_ONLY or READ_WRITE. [zia.casb.dlp-rules:access-control-field] The API contract requires a rule `name`, while the Terraform provider does not mark it required. [zia.casb.dlp-rules:name-required-in-contract]

Inline DLP rules are a different list: [Web DLP policy rules: order, criteria and actions](kb:zia.dlp.rules).

What to check:
1. Whether a schedule runs the policy, then where the rule sits among rules of its own category and whether a higher-ranked rule precedes it.
2. Which tenants the rule covers, remembering that an empty tenant list means all tenants.
3. Whether trusted users or domains, or an onboarding profile, make the content count as internal.
4. Whether the action is offered for the application and whether a message term is shorter than 8 bytes.
5. Whether the question needs first-match behavior or the meaning of an action token, which no source states.

Not known (open gaps):
- Whether evaluation stops at the first matching Data at Rest Scanning DLP or malware rule [gap:zia.casb.dlp-rules:first-match]: settled by lab-test or support-ticket. Blocks: stating which rule acts on content that matches several
- What each DLP action token does [gap:zia.casb.dlp-rules:action-token-meanings]: settled by lab-test or source-read
- Whether Gen AI messages cover both prompts and model responses [gap:zia.casb.dlp-rules:genai-prompt-response]: settled by lab-test
