# Where File Type Control sits in the inspection order (zia.file-type-control.pipeline)
Also called: file type control before dlp; file type control order; file type control ssl bypass; 400 mb file limit; file too large file type control; file size scan limit

**Does the traffic reach it?** File Type Control needs decrypted HTTPS, like DLP and Sandbox; see [These ZIA security features need decrypted traffic to work on encrypted transactions: Anti-Virus/Malware, Cloud Sandbox, Advanced Threat Prevention, Isolation, Data Loss Prevention, File Type Control, Inline CASB and the Intrusion Prevention System.](kb:zia.ssl-inspection.bypass-impact:dependent-features). For FTP, File Type Control applies to the extracted files: [DLP, Sandbox and File Type Control policies can also be applied to files extracted from FTP and FTP over HTTP.](kb:zia.ftp-control.scope:dlp-sandbox-ftc-on-extracted).

**Where is it in the order?** For an HTTP POST request, File Type Control checks the POST after Malware Protection and before Data Loss Prevention. For a GET or POST response, it checks the files in the response after Malware Protection and before the Sandbox analysis of unknown files. [zia.file-type-control.pipeline:post-and-response-position] The DLP side, including the example of a File Type Control block that keeps DLP from firing, is in [In the vendor's example, where File Type Control blocks outbound PDFs and the DLP policy blocks documents containing US Social Security numbers and notifies auditors, a PDF containing credit card numbers is blocked by File Type Control rather than DLP: the DLP policy is never triggered, and the auditor is not notified that a user attempted to send Social Security numbers out of the organization.](kb:zia.dlp.evaluation:earlier-block-skips-dlp).

**Is the file too large?** The ZIA limits table allows 2,048 File Type Control Policy rules. [zia.file-type-control.pipeline:rule-count-limit] File scanning has a 400 MB file size limit, and the File Type Control Policy File Size entry in the ZIA limits table is also 400 MB. [zia.file-type-control.pipeline:scan-limit-400mb] 409,600 KB, the largest value the Minimum and Maximum File Size criteria accept, is 400 MB, so the per-rule size bounds can express the whole range up to the scanning limit and no further. [zia.file-type-control.pipeline:limit-equals-size-field-max] What the service does with files above the limit is open [gap:zia.file-type-control.pipeline:over-limit-handling]. Sandbox's own size handling is in [What Sandbox analyzes and why a file may not be](kb:zia.sandbox.coverage). Where archive extraction happens relative to DLP is open [gap:zia.file-type-control.pipeline:archive-extraction-and-dlp-handoff].

What to check:
1. Whether a File Type Control rule is a Block, since a block ahead of DLP keeps the DLP policy from triggering for that file.
2. Whether a file above the 400 MB limit is handled as the tenant expects, since the service's handling is open.

Inferred, not quoted (say so when an answer rests on one):
- [zia.file-type-control.pipeline:limit-equals-size-field-max] Tier B: Arithmetic only: 409,600 KB / 1,024 = 400 MB. The vendor does not state that the two numbers are the same limit.

Not known (open gaps):
- What happens to files above 400 MB [gap:zia.file-type-control.pipeline:over-limit-handling]: settled by lab-test or support-ticket. Blocks: advising whether a large download is blocked, allowed or skipped
- Archive extraction at File Type Control and the DLP handoff [gap:zia.file-type-control.pipeline:archive-extraction-and-dlp-handoff]: settled by source-read or lab-test. Blocks: advising where nested archives are stopped
