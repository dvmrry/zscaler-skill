# How Endpoint DLP reaches the endpoint: prerequisites, policy delivery, offline enforcement, scans, and what the vendor says about evaluating all rules and exception rules (zia.dlp.endpoint-enforcement)
Also called: endpoint dlp prerequisites; endpoint dlp offline; endpoint dlp most restrictive; endpoint dlp exception rules; endpoint dlp policy enforcement; endpoint dlp rule selection

Endpoint DLP policy complements Zscaler DLP policy by extending the monitoring of sensitive data to the activities end users take on endpoints: printing, saving to removable storage devices, saving to network shares, or uploading to personal cloud storage accounts. [zia.dlp.endpoint-enforcement:scope-channels] When Endpoint DLP policy is configured and activated in Internet & SaaS (ZIA), endpoints automatically use Zscaler Client Connector to retrieve the policy from the Zscaler cloud. After that, the policy is enforced and incidents are logged even if endpoints have no network connection. [zia.dlp.endpoint-enforcement:delivery-and-offline] The device control activation article (activating device control policy rules, configuration and indexed documents changes) states that Endpoint Data Loss Prevention (DLP) pulls the policy every 15 minutes. [zia.dlp.endpoint-enforcement:policy-pull-interval] Whether that pull also covers rules activated in ZIA is open [gap:zia.dlp.endpoint-enforcement:policy-pull-vs-activation].

**Prerequisites.** The Endpoint DLP step-by-step article lists endpoints running Windows 11 or Windows 10 version 2004 (Build 19041) or later (64-bit), and endpoints running macOS 14, 15, or 26 (Sonoma, Sequoia, or Tahoe). It lists Zscaler Client Connector version 4.3.0 or later on Windows and 4.2.0 or later on macOS, and Endpoint DLP file paths included in the allowlist for Zscaler Client Connector. [zia.dlp.endpoint-enforcement:prerequisites] The prerequisites list virtual desktop infrastructure (VDI) support for VMware vSphere-hosted VDI and Amazon WorkSpaces VDI. [zia.dlp.endpoint-enforcement:vdi-support] For Endpoint Data Scan to properly scan all the endpoints connected to the organization's traffic, five URLs must be on the allowlist: endpoints.prod.us-east-1.m0.dataprotection.zscaler.net, endpoints.prod.us-east-1.w1.dataprotection.zscaler.net, endpoints.prod.eu-central-1.w2.dataprotection.zscaler.net, storage.prod.eu-central-1.w2.dataprotection.zscaler.net and storage.prod.us-east-1.w1.dataprotection.zscaler.net. [zia.dlp.endpoint-enforcement:data-scan-allowlist-urls]

**Scans.** At startup, Endpoint DLP runs inventory and classification scans on an endpoint, and classification scans always run after inventory scans. Each time the Endpoint DLP policy changes, an inventory and classification scan runs on the endpoint, and whenever the DLP engines or dictionaries are modified, a classification scan is applied on the endpoint. [zia.dlp.endpoint-enforcement:startup-and-change-scans]

**Logs.** Nanolog Streaming Service (NSS) feeds can be configured to specify the data from the Endpoint DLP logs that the NSS sends to the organization's security information and event management (SIEM) system. [zia.dlp.endpoint-enforcement:nss-feed]

**Choosing a rule.** When a user performs a monitored activity that involves sensitive data, the Endpoint DLP rule engine evaluates all rules; if multiple rules match, it selects the rule with the most restrictive action and the highest rule order. [zia.dlp.endpoint-enforcement:all-rules-most-restrictive] What counts as the highest rule order, and how the actions rank, is open [gap:zia.dlp.endpoint-enforcement:highest-rule-order-direction] and [gap:zia.dlp.endpoint-enforcement:action-ranking]. In the vendor's Example 1, R1 (order 1, Confirm), R2 (order 2, Block, Engineering) and R3 (order 3, Block) all match; R2 and R3 have the most restrictive action, R2 is described as having the higher rule order and is executed with severity Medium and no email notification, and R1 and R3 are logged as having matched. This supports only the example. [zia.dlp.endpoint-enforcement:tie-break-example] Before executing a matching rule, the Endpoint DLP rule engine looks for exception rules, which inherit rule order from their parent rules. It evaluates exception rules according to rule order and selects the first matching exception rule, which takes the place of the parent rule. [zia.dlp.endpoint-enforcement:exception-rules-replace-parent] In the vendor's exception example, R2.1 (Confirm, for Director or VP) replaces R2 when the user is a Director of Engineering, the matched rules are R1, R2.1 and R3, and the engine executes R3 because it has the most restrictive action; R1 and R2.1 are logged as having matched. This supports only the example. [zia.dlp.endpoint-enforcement:exception-still-competes] Which criteria an exception may change is open [gap:zia.dlp.endpoint-enforcement:exception-rule-criteria].

The inline pipeline is in [Why DLP did or did not fire: pipeline position, evaluation mode and exemptions](kb:zia.dlp.evaluation); the rule fields are in [Endpoint DLP policy rules: channels, criteria, actions (Allow, Block, Confirm, Protect) and notifications](kb:zia.dlp.endpoint-rules) and the settings in [Endpoint Data Scan configuration: scan reporting, End User Reports, continuous and real-time classification, exemption, trusted applications, channel exceptions, activation](kb:zia.dlp.endpoint-settings).
