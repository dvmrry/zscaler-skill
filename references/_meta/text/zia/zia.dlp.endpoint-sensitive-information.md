# Endpoint IDM, Endpoint EDM and Share Files Externally (zia.dlp.endpoint-sensitive-information)
Also called: endpoint idm; endpoint edm; edm optimizer; edm prefilter; share files externally; secure file viewer; indexed document match endpoint

**Endpoint IDM.** Endpoint IDM fingerprints are distributed to all Data Loss Prevention (DLP) endpoints. The Endpoint IDM operates in parallel to the Inline DLP IDM, enforcement and detection are independent, and reindexing of IDM files using the Endpoint DLP is required. The feature is in limited availability; access is through the Zscaler Account team. [zia.dlp.endpoint-sensitive-information:endpoint-idm-independent] Total Size of Fingerprints indicates the total size of all distributed indexed document fingerprints, and the admin can set the limit up to 100 MB. [zia.dlp.endpoint-sensitive-information:fingerprint-size-limit] The settings article lists the match tests per accuracy level. Low: a user-uploaded document matches at least 25% of an indexed document, or an indexed document matches at least 50% of the user-uploaded document. Medium: the same two tests at 50% and 75%. High: a user-uploaded document matches at least 75% of an indexed document. The endpoint determines match accuracy in priority order High, Medium, then Low, and halts once a valid match is confirmed. Exclude 100% Match stops the dictionary triggering for documents that are a 100% match of already indexed documents. [zia.dlp.endpoint-sensitive-information:idm-match-accuracy] Users can select up to 20 files per operation, with a maximum of 100 MB per file and a total maximum file size per session of 1 GB. Authorized users right-click sensitive files on their endpoint and select Index Documents, which creates and uploads file fingerprints to the cloud; the admin activates the policy, distributing the updated IDM package to all endpoints, and configures Endpoint DLP rules using the IDM-linked DLP engines. [zia.dlp.endpoint-sensitive-information:idm-process-and-limits]

**Endpoint EDM.** Unlike methods such as IDM or OCR that are processed entirely on the device, full EDM inspection uses a local prefiltering mechanism that identifies candidate files on the endpoint, and only the flagged candidate files are transmitted to the cloud for comprehensive evaluation. After the cloud confirms a match, the classification result is stored locally on the endpoint, which uses it to enforce DLP policies across removable storage, network shares, personal cloud storage, application file access and printing, including when the device is offline. [zia.dlp.endpoint-sensitive-information:edm-hybrid] The Understanding Exact Data Matching page says Endpoint EDM follows the same process as inline web DLP, as the rule evaluation for endpoint EDM occurs in the cloud: define a dictionary with the EDM type, add it to a DLP engine, and select it within Endpoint DLP rules. Continuous Classification and EDM Settings must be enabled in the Configurations tab. The EDM Optimizer must use the exact same CSV file that was uploaded to the Index Tool, with at least three columns designated as a Dictionary or a Regular Expression, and the tool validates that the selected column types match at least 90% of the CSV data. After the EDM is activated, the prefilter criteria are automatically pushed to all managed endpoints. [zia.dlp.endpoint-sensitive-information:edm-setup] EDM is not supported for Clipboard, and printing is only supported on Windows when using Microsoft Office or Adobe Reader. [zia.dlp.endpoint-sensitive-information:edm-limitations] The EDM page shows the combined count of data entries across all active EDM prefilter files, and the users authorized to use the EDM Optimizer utility on their local systems. Each prefilter has a Status (for example Active, Inactive, or Pending), and the Edit icon disables the exact data match prefilter file. [zia.dlp.endpoint-sensitive-information:edm-page]

**Share Files Externally.** Share Files Externally settings for external domains are None (prevent files being shared with any external domain), Specific Domains (restrict sharing to a predefined list of authorized domains) and Any Domain (allow sharing with all external domains without restriction). Specific Users grants external file sharing permission only to a defined list of users, groups, or departments. To enable changes, the change must be activated. [zia.dlp.endpoint-sensitive-information:share-externally-settings] In the Secure File for External Sharing window the user can add up to 10 email recipients and click Protect File, and recipients must belong to the authorized domains configured in the Share Files Externally Settings page. The system encrypts the file locally and converts it into a secure HTML format, and the file is not transported by Zscaler during this step. The recipient must download the Zscaler Secure File Viewer tool for their operating system, and the system verifies the email's authorization and sends a One-Time Password (OTP) to the recipient's inbox. The feature encrypts files without automatically sharing them, so the protected files can be shared via email, removable storage or any other method. [zia.dlp.endpoint-sensitive-information:share-externally-flow] Admins can monitor all decryption attempts and successful access events, and revoke access to any file at any time by deleting it from the list or editing the authorized recipient list. The list shows Shared With (the external email recipients authorized to decrypt and view the file) and a History of Shared Date, Recipient, and Action. [zia.dlp.endpoint-sensitive-information:share-externally-admin-control]
