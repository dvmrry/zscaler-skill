# Value encodings and caveats of ZIA web log fields (zia.logs.web-field-semantics)
Also called: sip 0.0.0.0; respcode 403 blocked; cip vs cintip; host vs url field; domain fronting fields; riskscore threatseverity; dlprulename trig_dlprulename; byte counters web log; prompt_req; urlcat urlsupercat urlclass; reason field

Several web log fields have encodings, fallbacks and conditions that the field list alone does not show. These are the ones the vendor field CSV states.

**Network and destination.** The sip field shows 0.0.0.0 when the request was blocked. [zia.logs.web-field-semantics:sip-blocked] The respcode field is the response code sent to the client, and the service generates a 403 Forbidden response for blocked transactions. [zia.logs.web-field-semantics:respcode-403] A 403 in respcode on a blocked transaction is the service's own response and does not show that the origin server answered 403. [zia.logs.web-field-semantics:respcode-not-origin] Whose response code the field holds is described two ways [divergence:zia.logs.web-field-semantics:respcode-origin]. The cip field is the internal client IP when it is visible, for example through a GRE tunnel or an XFF header, and otherwise equals cintip; cintip is the NATed public IP and differs from cip only when the internal address is visible. [zia.logs.web-field-semantics:cip-cintip] The host field takes the host value from the HTTP request line when present and the Host header otherwise. [zia.logs.web-field-semantics:host-fallback] The url field excludes the protocol identifier, http:// or https://. [zia.logs.web-field-semantics:url-no-scheme] df_hostname holds the TLS SNI when it differs from the HTTPS Host header, and df_hosthead marks an FQDN mismatch between the request URL and the Host header; each appears only when there is a mismatch. [zia.logs.web-field-semantics:domain-fronting] The TLS Inspection requirement for df_hostname is in [df_hostname is populated only when TLS Inspection is enabled.](kb:zia.logs.field-enablement:df-tls). For traffic processed through Isolation, userlocationname holds the actual origination point while location holds the Isolation Location; for other traffic userlocationname is None. [zia.logs.web-field-semantics:isolation-location] With Source IP Anchoring for a URL or domain, the Web Insights Logs show the IP address 0.0.0.1 for the server to indicate the internal redirection, because the client request is forwarded to Private Access and the server IP is not logged at the proxy layer. [zia.logs.web-field-semantics:sipa-server-ip] The web Insights Logs protocol values are DNS over HTTPS, FTP (native FTP servers), FTP over HTTP, HTTP, HTTP Proxy (HTTP CONNECT requests to a ZIA Public Service Edge IP), HTTPS (inspected), SSL/TLS (not inspected), Tunnel (unidentified encrypted traffic such as Telnet or SSH inside HTTP or HTTPS), Tunnel SSL/TLS (an undecodable protocol inside SSL/TLS), WebSocket and WebSocket SSL/TLS; inspection of bidirectional WebSocket text-based content is enabled by contacting Zscaler Support. [zia.logs.web-field-semantics:protocol-values] Some web protocol filter values mean control was handed to the firewall, for example Tunnel and Tunnel SSL/TLS: the firewall completes the remaining inspection and applies a policy according to the rules, and the page recommends always checking the firewall logs to confirm. [zia.logs.web-field-semantics:tunnel-handoff] The Web and Firewall Insights Logs filters on flow type list Direct, Intranet, Loopback, Unclassified, VPN, VPN Tunnel, ZIA and ZPA. [zia.logs.web-field-semantics:flow-type-values]

**Threat and risk.** The service computes the Page Risk Index for each page by weighing page locations, destination reputation and suspicious-looking content, on a 0 to 100 scale from lowest to highest risk. [zia.logs.web-field-semantics:riskscore-factors] threatseverity relates to the riskscore bucket, so a riskscore from 90 to 100 gives Critical. [zia.logs.web-field-semantics:severity-from-score] malwarecat holds the malware category detected in the transaction and also indicates whether a file was submitted to the Sandbox engine and the analysis result. [zia.logs.web-field-semantics:malwarecat-sandbox] Where the score comes from is open [gap:zia.logs.web-field-semantics:riskscore-lineage]. The Web Insights Logs severity values map to the suspicious content value: Critical for 90–100, High for 75–89, Medium for 46–74, Low for 1–45 and None for 0. [zia.logs.web-field-semantics:severity-buckets] In the web Insights Logs filters, the threat category filter lists threats detected by Malware Protection and the advanced threat category filter lists threats detected by Advanced Threat Protection; one filter lists the values Advanced Threats, Sandbox and Viruses & Spyware, and another Malware, Sandbox, Spyware and Virus. [zia.logs.web-field-semantics:threat-engines]

**Placeholders.** app_risk_score displays None when the risk index is unavailable, and ua_token displays None when no user agent token exists. [zia.logs.web-field-semantics:none-sentinels]

**Rules and DLP.** dlprulename applies only to Allow rules; trig_dlprulename names the DLP rule that triggered the transaction, allowed or blocked; all_dlprulenames combines other_dlprulenames and trig_dlprulename. [zia.logs.web-field-semantics:dlp-rule-fields] The rule-name fields for blocks are covered in [Which rule decided a web transaction, from the logs](kb:zia.logs.web-rule-attribution). The reason field's documentation refers readers to the Policy Reasons article for the reasons behind policy actions. [zia.logs.web-field-semantics:reason-pointer] Whether the logged values are exactly the article's strings is open [gap:zia.logs.web-field-semantics:reason-structure], and one of its rows contradicts itself [divergence:zia.logs.web-field-semantics:business-site-cautioned].

**Categories.** The category fields' relation is open [gap:zia.logs.web-field-semantics:url-category-fields].

**Sizes.** respsize includes the response header and payload, and totalsize is the sum of the total request size and total response size. [zia.logs.web-field-semantics:sizes] In Web Insights Logs, Received Bytes is how many bytes the destination web server returned for each HTTP request, Sent Bytes the size of the HTTP request sent to it, and Total Bytes the sum of the two. [zia.logs.web-field-semantics:byte-columns] Their measurement point is open [gap:zia.logs.web-field-semantics:byte-counters].

**Insights Logs values.** Besides All (the default), the web Insights Logs policy action filter values are Allow; Allowed - No Active Content (unknown PDF or Microsoft Office downloads allowed as benign by Sandbox static analysis); Allowed and No Scan (unknown files allowed but not scanned under the Sandbox policy); Allowed with caution; Block; Blocked - Tenant Restricted (Tenant Restriction policies); Blocked with caution; and Isolate (sent to Zero Trust Browser). [zia.logs.web-field-semantics:policy-action-values] URL Categorization Method gives the source of a URL's category: Database A (the service's proprietary URL database), Database B (a third-party vendor's database), AI/ML-based content categorization (pages in neither database classified with AI/ML tools), User-Defined (defined by an administrator) or None (in no database). [zia.logs.web-field-semantics:url-categorization-method] The cloud application sanctioned or unsanctioned status filter shows N/A when the URL is unknown and no cloud application is tagged in the transaction. [zia.logs.web-field-semantics:app-status-na] When an internet gateway location is specified and authentication is not required, the web Insights Logs user and department fields show the gateway location's name. [zia.logs.web-field-semantics:user-gateway-name] DLP Policy Action shows None when the rule has no Auditor or Incident Receiver notification configured. [zia.logs.web-field-semantics:dlp-policy-action-none] The filter for SSL/TLS Inspection policy actions lists Blocked, Inspected, N/A and Not inspected because of failed client SSL/TLS handshake, HSM error, mutual TLS authentication, O365 bypass, SSL/TLS policy, UCaaS bypass, undecryptable traffic, Zscaler best practices or Zscaler service domains. [zia.logs.web-field-semantics:ssl-policy-reason-values] The reason wording differs between the console and the NSS page [divergence:zia.logs.web-field-semantics:ssl-reason-wording]. The filter for client SSL/TLS handshake failure reasons lists Access Denied, Bad Cert Status Resp or Hash Value, Bad or Unsupported Certificate, Bad Record Mac, Certificate Revoked or Expired, Certificate Unknown, Certificate Unobtainable, Close Notify or Client TCP Reset, Decode Error, Decrypt Error, Handshake Failure, Illegal Parameter, Insufficient Security, Internal Error, N/A, No Application Protocol, No Renegotiation, Other Handshake Error, Protocol Version, Record Overflow, Unexpected Message, Unknown CA, Unknown PSK Identity, Unrecognized Name, Unsupported Extension and User Canceled; the page refers to RFC 2246 The TLS Protocol. [zia.logs.web-field-semantics:client-handshake-failure-reasons] Client Key Exchange Proposal and Client Digital Signature Proposal give what the client proposed in the TLS handshake as Classical, Hybrid, PQC or Unknown, or None when the supported_groups or signature_algorithms extension was not present; the filters page describes None as all non-TLS related transactions. [zia.logs.web-field-semantics:client-proposals]

**Client Connector and generative AI.** bypassed_traffic is a numeric flag where 1 means the traffic bypassed Zscaler Client Connector. [zia.logs.web-field-semantics:bypass-flag] What prompt_req records is open [gap:zia.logs.web-field-semantics:prompt-scope].

What to check:
1. Whether an empty or zero sip, or a 403 in respcode, comes from a block before reading it as an origin result.
2. Which client IP field to use when the internal address matters.
3. Whether riskscore alone supports a threat conclusion, or the threat fields must be read with it.
4. Which DLP rule field names the rule for an allowed versus a blocked transaction.
5. Whether a byte count is safe to use for volume before relying on it.

Inferred, not quoted (say so when an answer rests on one):
- [zia.logs.web-field-semantics:respcode-not-origin] Tier B: Follows from the NSS description of respcode as the code sent to the client; the Web Insights Logs Response Code column describes the destination server's response instead, so this rests on one side of the divergence respcode-origin, and the source does not spell out the origin case.

Sources disagree (name both sides):
- The Web Insights Logs Response Code column is the destination server's response, while the NSS web output format describes respcode as the HTTP response code sent to the client. [divergence:zia.logs.web-field-semantics:respcode-origin]
  - zscaler-help: The Response Code column is the destination server's response.
  - zscaler-help: respcode is the HTTP response code sent to the client, and the service generates a 403-Forbidden response for blocked transactions.
  Impact: Whether a 403 or another code in the feed's respcode is the origin's answer or the service's depends on which page is read; the pages do not say whether the console column and the NSS field are the same value.
- The Web Insights Logs filters page words one SSL/TLS policy reason as Not inspected because of O365 bypass, while the NSS web output format words it as Not inspected because of Microsoft 365 bypass. [divergence:zia.logs.web-field-semantics:ssl-reason-wording]
  - zscaler-help: The reason reads Not inspected because of O365 bypass.
  - zscaler-help: The reason reads Not inspected because of Microsoft 365 bypass.
  Impact: A match on the reason string needs both spellings unless one page is shown to be the feed's wording; the pages do not say which a feed carries.
- In the Policy Reasons article, the Cloud App Control reason Not allowed the use of this business site says the transaction was not allowed, while the same row's description says it was cautioned. [divergence:zia.logs.web-field-semantics:business-site-cautioned]
  - zscaler-help: The reason string says the use of the business site was not allowed.
  - zscaler-help: The row's description says the transaction was cautioned.
  Impact: Whether a record with this reason was blocked or cautioned cannot be told from the article; the record's action field says which.
