# Forwarding Control rule criteria, limits and ordering (zia.forwarding-control.rules)
Also called: forwarding control criteria; forwarding rule limits; forwarding rule order; forwarding rule 1024; nw_services block; road warrior forwarding rule; advanced firewall subscription forwarding

Any Forwarding Control policy, including Source IP Anchoring, that uses user conditions (users, groups, departments or device groups) requires an Advanced Firewall subscription. [zia.forwarding-control.rules:subscription] The About Forwarding Control page says any Forwarding Control policy, including Source IP Anchoring, based on user conditions such as custom application service groups, users, groups, departments or device groups requires a subscription to the Advanced Firewall. [zia.forwarding-control.rules:subscription-custom-app-groups] A tenant can create up to 1,024 Forwarding rules. [zia.forwarding-control.rules:rule-limit] The Forwarding Control page lists rules in ascending rule order by default and paginates up to 500 rules per page. Its Forwarding Method column shows Direct, Proxy Chaining, Dedicated IP, GeoIP or ZPA, and its ZPA Application Segment column populates values only for the Private Access Forwarding rules. [zia.forwarding-control.rules:page-listing]

**Matching.** Within the Who, Where and When tab, criteria combine as [Users OR Groups OR Departments] AND [Locations OR Location Groups] AND Device Groups; Services is Network Service Groups OR Network Services; Source is Source IPv4 Groups OR IP Addresses; Destination is Destination Groups OR Destination IP Address/Wildcard FQDN OR Countries OR URL Categories; and the tabs combine with AND. [zia.forwarding-control.rules:criteria-logic] A criterion left without values is set to Any and is ignored during policy evaluation. [zia.forwarding-control.rules:unset-is-any] A rule can select up to 32 users, 32 groups, 32 departments, 32 locations and 32 location groups; Zscaler Support can raise the user, group, department and location limits. [zia.forwarding-control.rules:identity-limits] Sources differ on those numbers [divergence:zia.forwarding-control.rules:selector-limits]. Selecting the Road Warrior location applies a rule only to remote users' traffic, and rules for other locations also apply to remote user traffic from those locations. Rules for the Road Warrior location apply to Z-Tunnel 1.0 and PAC only when Enable Firewall for Z-Tunnel 1.0 and PAC Road Warriors is on in Advanced Settings. [zia.forwarding-control.rules:road-warrior] The firewall has a Z-Tunnel 1.0 and PAC option of the same name: [Where the firewall sits in the traffic path](kb:zia.firewall.traffic-path). To match on the address in the X-Forwarded-For header, use the Locations criterion rather than Source IP Groups, because the sublocation is what detects the source address from that header. [zia.forwarding-control.rules:xff-uses-locations] For IPv6, the console accepts only the All IPv6 group as a source or destination group; custom IPv6 groups and individual, subnet or range IPv6 addresses are not supported. Source and destination IP address entries are IPv4 only. [zia.forwarding-control.rules:ipv6-all-group] Forwarding rules that match on wildcard FQDNs only evaluate correctly if client DNS requests are forwarded to the Zscaler service. [zia.forwarding-control.rules:wildcard-fqdn-dns]

**Order.** Rules are evaluated in ascending rule order. A rule's admin rank is 0 to 7 (0 is the highest), and a rule with a higher admin rank always precedes a rule with a lower admin rank. [zia.forwarding-control.rules:order-and-rank] A rule created in the console starts Disabled and must be enabled to be enforced. A disabled rule can hold a rule order; evaluation skips it and moves to the next rule. [zia.forwarding-control.rules:disabled-rules] Whether evaluation stops at the first match is open [gap:zia.forwarding-control.rules:first-match]. The same ordering model is described for URL Filtering in [URL Filtering rule order and first match](kb:zia.url-filtering.rule-order).

**Terraform.** The published contract requires `forwardMethod`, `name` and `rank` to create a rule; the Terraform resource instead requires `forward_method` and `order` and treats `rank` as optional. [zia.forwarding-control.rules:required-members] In Terraform, `nw_services` on a forwarding rule is a nested block with an `id` list, not a scalar; resolve the named service first and pass its ID. [zia.forwarding-control.rules:nw-services-block] Order handling through Terraform has its own traps: [How the ZIA Terraform provider applies rule order](kb:zia.terraform.rule-order); ZPA-method delays are in [Terraform behavior of ZPA-method forwarding rules](kb:zia.forwarding-control.terraform).

For anchored traffic, the Private Access side is in [Source IP Anchoring: what it needs on each side](kb:zia.forwarding-control.sipa).

**Add Forwarding Rule.** In the Add Forwarding Rule pages, the rule name cannot exceed 63 characters and the optional description cannot exceed 10,240 characters. [zia.forwarding-control.rules:name-description-limits] The ZPA and Direct methods are also in [The console offers these forwarding methods: ZPA (to a Private Access App Connector through the Private Access gateway), Direct, Proxy Chaining (to a third-party proxy service), Dedicated IP (through a dedicated IP gateway) and GeoIP (source IP address mapped to the location of the originating request).](kb:zia.forwarding-control.methods:console-methods) and [Direct forwards the traffic to the destination server using the Zscaler service IP address.](kb:zia.forwarding-control.methods:direct-meaning). For a Forwarding rule, the ZPA forwarding method sends traffic to a Private Access App Connector through the Private Access gateway, and Direct sends it straight to the destination server using the Zscaler service IP address. [zia.forwarding-control.rules:method-zpa-direct] For the Private Access page: The Device Groups criterion takes a group by device platform for Zscaler Client Connector traffic, or Cloud Browser Isolation, IoT or No Client Connector for isolation traffic, IoT traffic or traffic not tunneled through Zscaler Client Connector; the Cloud Browser Isolation and IoT groups exist only if Zero Trust Browser and IoT discovery are enabled. [zia.forwarding-control.rules:device-groups] The Source IP Addresses criterion takes IPv4 only, as an individual address (192.0.2.1), a subnet (192.0.2.0/24) or an address range (192.0.2.1 - 192.0.2.5). [zia.forwarding-control.rules:source-ip-formats] The Admin Rank option appears if Admin Ranking is enabled on the Advanced Settings page, and the admin's own rank determines the values selectable (a rank higher than the admin's own cannot be chosen). [zia.forwarding-control.rules:admin-rank-bounds] To apply a Forwarding rule to unauthenticated traffic the rule must apply to all locations, and, when the policy for unauthenticated users is enabled under Advanced Settings, selections in the Users and Departments fields can target it. [zia.forwarding-control.rules:unauthenticated-and-app-criteria] The Application Service Groups criterion accepts any number of application service groups, and the service provides predefined and custom application services. [zia.forwarding-control.rules:app-service-groups] The gateway field's dependency on application segments is in [In a ZPA forwarding rule the Forward to Gateway field is enabled only when the selected application segments require Source IP Anchoring and share a common Private Access gateway; an empty list means no common gateway exists for the selected segments.](kb:zia.forwarding-control.zpa-gateway:rule-needs-common-gateway). The Application Segment criterion and the page's wording of the ZPA method are open [gap:zia.forwarding-control.rules:sipa-page-details].

What to check:
1. Whether the rule is enabled, and its rule order and rank against other enabled rules that match.
2. Whether the Road Warrior scope matches how the user connects.
3. Whether unset criteria are intended as Any.

Sources disagree (name both sides):
- How many users, groups and locations a Forwarding Control rule can select [divergence:zia.forwarding-control.rules:selector-limits]
  - zscaler-help: Up to 32 locations, 32 users, 32 groups and 32 departments, raisable through Support.
  - tf-zia: The Terraform documentation says up to 8 locations and 4 users (and 8 groups); the resource schema sets no maximum for these blocks.
  Impact: Do not reject a plan or design because of the Terraform documentation's smaller numbers; the console figure is 32, and the provider does not enforce the smaller ones.

Not known (open gaps):
- Application Segment criterion and the ZPA method wording on the Private Access Forwarding rule page [gap:zia.forwarding-control.rules:sipa-page-details]: settled by source-read or lab-test
- Whether Forwarding Control stops at the first matching rule [gap:zia.forwarding-control.rules:first-match]: settled by lab-test. Blocks: stating which rule governs when two enabled rules both match
