# Which TLS versions and cipher suites SSL/TLS inspection supports, and what happens to the rest (zia.ssl-inspection.cipher-suites)
Also called: supported cipher suites; ssl inspection tls versions; tls 1.3 inspection; unsupported ciphers rc4; perfect forward secrecy ssl inspection

Zscaler supports hardware-based inspection with TLS versions 1.3, 1.2, 1.1 and 1.0 and with Perfect Forward Secrecy (PFS) cipher suites across all TLS versions; the Public Service Edge prefers and proposes the highest TLS version and strongest cipher suites on the client side (client to Public Service Edge) and server side (Public Service Edge to server) connections. [zia.ssl-inspection.cipher-suites:versions-and-preference] What the supported TLS versions are differs between the help pages [divergence:zia.ssl-inspection.cipher-suites:supported-tls-versions].

**Supported suites.** The supported TLS 1.3 cipher suites are TLS_AES_256_GCM_SHA384 (0x1302), TLS_CHACHA20_POLY1305_SHA256 (0x1303) and TLS_AES_128_GCM_SHA256 (0x1301). [zia.ssl-inspection.cipher-suites:tls13-suites] The Understanding SSL/TLS article says PFS uses either the standard Diffie-Hellman ephemeral key exchange (DHE) or the Elliptic Curve Diffie-Hellman ephemeral key exchange (ECDHE), with the server generating different session keys for each conversation with the client, and points to Zscaler SSL/TLS Support for the supported DHE and ECDHE cipher suites. [zia.ssl-inspection.cipher-suites:pfs-key-exchanges] For PFS the supported ECDHE cipher suites depend on the TLS protocol. For TLS 1.0 and 1.1 they are TLS_ECDHE_ECDSA_WITH_AES_128_CBC_SHA, TLS_ECDHE_ECDSA_WITH_AES_256_CBC_SHA, TLS_ECDHE_RSA_WITH_AES_128_CBC_SHA and TLS_ECDHE_RSA_WITH_AES_256_CBC_SHA. For TLS 1.2 the table adds the ECDSA and RSA AES-128 and AES-256 GCM suites and, for each of ECDSA and RSA, the AES-128 CBC SHA256 and AES-256 CBC SHA384 suites, as well as the four CBC SHA suites above. [zia.ssl-inspection.cipher-suites:ecdhe-suites] The supported DHE cipher suites for PFS are TLS_DHE_RSA_WITH_AES_256_CBC_SHA and TLS_DHE_RSA_WITH_AES_128_CBC_SHA on TLS 1.0 and 1.1; on TLS 1.2 the table lists those two plus TLS_DHE_RSA_WITH_AES_256_GCM_SHA384, TLS_DHE_RSA_WITH_AES_128_GCM_SHA256, TLS_DHE_RSA_WITH_AES_256_CBC_SHA256 and TLS_DHE_RSA_WITH_AES_128_CBC_SHA256. [zia.ssl-inspection.cipher-suites:dhe-suites] The RSA key-exchange cipher suites listed are TLS_RSA_WITH_AES_256_CBC_SHA and TLS_RSA_WITH_AES_128_CBC_SHA on TLS 1.0 and 1.1; on TLS 1.2 the table lists those two plus TLS_RSA_WITH_AES_256_GCM_SHA384 and TLS_RSA_WITH_AES_128_GCM_SHA256. [zia.ssl-inspection.cipher-suites:rsa-suites] By default ECDSA authentication is supported only on server-side (Service Edge to server) SSL connections; ECDSA can be supported on the client side (client to Service Edge) if Custom Certificate Compliance is enabled and an ECDSA custom intermediate certificate is configured. [zia.ssl-inspection.cipher-suites:ecdsa-scope]

**Unsupported suites.** Zscaler does not support certain cipher suites due to security or compatibility issues, among them RC4-MD5, RC4-SHA, DES-CBC-SHA, DES-CBC3-SHA and 3DES-CBC-SHA. [zia.ssl-inspection.cipher-suites:unsupported-suites] Zscaler does not perform SSL/TLS Inspection for websites that only use unsupported protocols: it treats their traffic as undecryptable and allows or blocks it depending on the SSL/TLS Inspection policy set for undecryptable traffic. The page's sample is a website that only supports RC4-MD5-based ciphers. [zia.ssl-inspection.cipher-suites:unsupported-only-is-undecryptable] The setting that decides allow or block is Block Undecryptable Traffic in [What an SSL/TLS inspection action does: Inspect, Do Not Inspect, Block and their settings](kb:zia.ssl-inspection.actions); the guide's recommendation to block it is in [What SSL/TLS inspection cannot inspect: pinned apps, client certs, QUIC, BYOD, IoT](kb:zia.ssl-inspection.uninspectable). The list items EXP and DSS are too short to quote, so the full list is not carried [gap:zia.ssl-inspection.cipher-suites:unsupported-list-remainder].
