# Listing URL Filtering rules and URL categories without truncation (zia.url-filtering.list-pagination)
Also called: url filtering pagination; only 100 url filtering rules; missing url filtering rules; url categories only 20; GetAll truncated; list_rules page_size

The Go SDK's `GetAll` for URL Filtering rules walks pages through `common.ReadAllPages`, which requests `pageSize=1000` by default and stops at the first page shorter than the page size. [zia.url-filtering.list-pagination:go-readallpages-1000] Zscaler documents reading every URL Filtering rule by first getting the total from `GET /urlFilteringRules/count`, then requesting each page from 1 to the total divided by the page size, rounded up; its example uses a page size of 100, "or any desired size up to a max limit". [zia.url-filtering.list-pagination:vendor-count-then-loop] The December 19, 2025 ZIA release note says `page` and `pageSize` query parameters are available for `GET /urlFilteringRules`, and that default values are used when they are not specified. [zia.url-filtering.list-pagination:page-parameters-added] Treat a URL Filtering rule list whose length is a round page size, such as 100, as possibly truncated and confirm the total with `GET /urlFilteringRules/count`: if the endpoint returns fewer rules per page than the 1000 the Go SDK requests, `ReadAllPages` takes the first page for the last and stops without an error. [zia.url-filtering.list-pagination:silent-truncation] Because evaluation stops at the first matching rule, a rule list that stops short can leave out rules that bear on which rule wins, so a precedence answer built from it can be wrong. [zia.url-filtering.list-pagination:incomplete-list-misleads-precedence]

The Python SDK's `list_rules` sends one request with caller-chosen `page` and `page_size` and returns that page only; callers must page themselves. [zia.url-filtering.list-pagination:python-single-request] zscalerctl reads `/zia/api/v1/urlFilteringRules` page by page with a page size of 100; its comment says that size matches Zscaler's published pagination example and the observed default boundary. [zia.url-filtering.list-pagination:zscalerctl-url-rules-reader-pages-100]

**Categories.** The Go SDK's URL categories `GetAll` makes a single `Read` of `/urlCategories`; its comment says the API does not support pagination and returns all results in a single response. [zia.url-filtering.list-pagination:categories-single-read] zscalerctl records two behaviors of `/urlCategories` on different tenants: one returned 20 records for a 5,000-record request (2026-07-29), and another returned the whole collection on every request whatever `page` and `pageSize` said (2026-10-14); what decides which a tenant does is not known, so its reader learns the response width and keeps paging. [zia.url-filtering.list-pagination:categories-two-behaviors] [divergence:zia.url-filtering.list-pagination:categories-single-response]

What to check:
1. Whether a URL Filtering rule list that stops at a round number, such as 100, is complete: compare it with `GET /urlFilteringRules/count` before reasoning about precedence.
2. Whether a URL category inventory read in one SDK call is complete: page it, or compare its count with the console.
