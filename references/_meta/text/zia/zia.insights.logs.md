# ZIA Insights Logs: log families, time frame, export and background queries, filters and console-only columns (zia.insights.logs)
Also called: insights logs; web insights logs; log viewer; export to background; job center; show delayed logs; download display logs; sandbox verdict insights logs

Insights Logs cover Web (transactions from any device), Mobile (transactions from the browsers of mobile devices only, shown by device OS), Firewall, DNS, Tunnel (GRE and IPSec tunnel health, status and algorithms), SaaS Security, Endpoint DLP, Email DLP, Extranet and Sandbox Verdict. [zia.insights.logs:families] The NSS field types for these families are [ZIA web log (NSS web feed)](kb:zia/web-log), [ZIA firewall log (NSS firewall feed)](kb:zia/firewall-log), [ZIA DNS log (NSS DNS feed)](kb:zia/dns-log), [ZIA tunnel log (NSS tunnel feed)](kb:zia/tunnel-log), [ZIA Endpoint DLP log (NSS Endpoint DLP feed)](kb:zia/endpoint-dlp-log), [ZIA Email DLP log (NSS Email DLP feed)](kb:zia/email-dlp-log), [ZIA Sandbox Verdict log (NSS Sandbox Verdict feed)](kb:zia/sandbox-verdict-log) and [ZIA SaaS Security log (NSS SaaS Security feed)](kb:zia/saas-security-log).

**Time frame and export.** On the Insights Logs pages a custom time frame can end up to 92 days after its start date. [zia.insights.logs:custom-92] The About Insights Logs page says Download exports the transactions as CSV, up to 1 million records at a time in options of 100K, 250K, 500K or 1 million, and Display streams them on screen, up to 25K lines at a time in options of 1K, 5K, 10K or 25K. Exports are limited to 20 requests per hour, and the service stays usable while an export runs. [zia.insights.logs:download-display] The export ceiling differs between pages [divergence:zia.insights.logs:export-ceiling]. A query that runs longer than 30 seconds can be moved to the background and followed in the Job Center, where it keeps running if the admin leaves the page and stops once it reaches the selected record limit. The organization may hold 10 background exports, completed or in progress; an admin exports one query to the background at a time and cannot start one while another query is in progress, but can run a foreground query while a background query runs. Reports can be downloaded or viewed for only 72 hours after they complete. [zia.insights.logs:background-export] How far back a window may start, and whether the retention applies to every family, is open [gap:zia.insights.logs:lookback-retention].

**Filters.** In Insights Logs, multi-value filters such as Users, Departments and Locations take up to 200 values and can include or exclude them; certain filters, string-match ones such as Threat Category, also support the operators Does Not Contain, Does Not Start With, Does Not End With, Is Null and Is Not Null. [zia.insights.logs:filter-operators] The About Insights Logs page lists a columns article for each of Web, Mobile, Firewall, DNS, Tunnel, Endpoint DLP, Email DLP, Extranet and Sandbox Verdict Insights Logs. [zia.insights.logs:columns-per-family] Tunnel Insights Logs filters are Extranet Name (default Any), Location (default All, with Hide Deleted to remove deleted locations), Location Group (default None), Location Type (default None), Tunnel Destination IP and Tunnel Source IP (each taking individual addresses separated by commas, a range or a subnet mask), Tunnel Type (default All; All, GRE or IPSec) and VPN Credential (default All). The page says multi-value filters take up to 200 values in a single filter. [zia.insights.logs:tunnel-filters] Some filter combinations that appear together in Insights Logs when applied do not appear together in Insights; the page's example is the Department and Location filters. [zia.insights.logs:insights-vs-logs-filter-combos] The Web, Mobile, Firewall and DNS Insights Logs filters each offer a way to view delayed logs; the Firewall and DNS pages call it Show Delayed Logs. [zia.insights.logs:delayed-logs] What makes a log delayed is open [gap:zia.insights.logs:delayed-logs-meaning]. In the Firewall Insights Logs filters, Device Hostname, Device Name and Device Owner are not available to admins with device information obfuscation enabled. [zia.insights.logs:device-obfuscation] The Firewall Insights Logs Location filter lists Road Warrior, the default location for transactions that did not originate from a predefined location, and shows 200 results at a time; the Web Insights Logs columns page says a transaction that did not originate from a location defined in the service is recorded as coming from a remote user. [zia.insights.logs:road-warrior] In the Web Insights Logs search, a URL, Path, Host or Domain can be entered, and the console may recommend switching among them for optimized and accelerated results; for example, a search of www.zscaler.com as a URL can prompt a recommendation to search it as Host to minimize processing time. [zia.insights.logs:url-search]

**Web columns.** On the Web Insights Logs page, Proxy Latency (ms) is the time the Public Service Edge added, Server Trans. Time (ms) the time the destination server took to accept the GET request and return all content to the cloud, and Client Trans. Time (ms) the sum of Proxy Latency, Server Trans. Time and the client's time to upload the whole request payload. [zia.insights.logs:web-latency-columns] The Mobile page defines the client transaction time differently [divergence:zia.insights.logs:client-trans-time]. The Web Insights Logs column with supported values Full and Partial marks policy applied from an incomplete or cached tenant, user or location configuration, an extremely rare result of transient network disruption, and the distinction applies only when Behavior When Partial Configuration Available is set to Best Effort Policies in Advanced Settings. [zia.insights.logs:web-configuration-column] What sets the Behavior When Partial Configuration Available option is open [gap:zia.insights.logs:partial-config-setting]. The Web Insights Logs Email Recipients column applies to email applications and shows up to 16 recipient addresses. [zia.insights.logs:email-recipients-16] Which console columns the NSS web feed carries is open [gap:zia.insights.logs:web-columns-no-nss-label].

**Mobile.** Mobile Insights Logs add Mobile Application, Mobile Application Category, Mobile Application Class and Mobile Device Type columns; the filter on the action the service took for mobile device traffic offers All, Allow or Block, and the filter on application class offers All, General, Privacy or Security. [zia.insights.logs:mobile-columns] The Mobile Insights Logs Rule Name column is displayed only when the traffic was blocked and by default not for allowed traffic. [zia.insights.logs:rule-name-blocked-mobile] Whether Mobile logs are a subset of the web records is open [gap:zia.insights.logs:mobile-vs-web].

**Endpoint DLP.** In Endpoint DLP Insights Logs, Action Taken is Allow, Block, Confirm Allow, Confirm Block or Exempted, and Record Type is DLP Incident or Sensitive Activity. [zia.insights.logs:edlp-actions-records] The Endpoint DLP ZDP Mode column shows Exemption Mode when the user has turned on exemption mode in Zscaler Client Connector to bypass the Endpoint DLP rules for an activity, and Block Mode when exemption mode is off. [zia.insights.logs:edlp-zdp-mode] The Endpoint DLP filter values for a user's confirmation are Cancel, Confirm or Timeout (timed out before the user confirmed), and the justification values are Other, the data contains only my personal information, the data does not contain sensitive information, a necessary business workflow, accidental, or the user didn't justify in time. [zia.insights.logs:edlp-confirm] The Endpoint DLP Insights Logs filters list the activity types Download, Email Sent, File Copy, File Read, File Write, Print and Upload; the channels Network Share, Personal Cloud Storage, Printing and Removable Storage; and the item types Clipboard Text, Email, Email Attachment, Embedded File, File, HTTP Request and Printed Text. [zia.insights.logs:edlp-activity-channel-item] The Channel filter lacks two channels the rules name [gap:zia.insights.logs:edlp-channels].

**Email DLP.** Email DLP Insights Logs filters offer the actions Allow, Block and Custom Header Insertion, and the record types DLP Incident, Scan and Sensitive Activity. [zia.insights.logs:email-dlp-actions-records] In Email DLP Insights Logs, User is the sender provisioned to Internet & SaaS and External User a sender who is not; Triggered Recipients received the email and a policy action was taken, Other Recipients received it with no policy triggered; Personal Email shows when the email goes to the user's personal address; Scan Time is the milliseconds from Zscaler receiving the email until policy evaluation completes. [zia.insights.logs:email-dlp-people]

**Extranet.** Extranet Insights Logs carry the Zscaler data center IPSec IP and VPN port (Extranet Gateway IP and Port), the partner-side public IP and port that establish the IPSec VPN tunnel (Extranet Location IP and Port), and a Protocol of ICMP, TCP or UDP. [zia.insights.logs:extranet-columns] Extranet Insights Logs filters include Extranet Name (limiting the data to the business partner name configured by the organization), Extranet Location (default Any), Extranet Location IP, Extranet Location Port, Extranet Gateway IP, Extranet Gateway Port (the page says to enter a value from 1 to 65,536), Extranet Tunnel Data Center, Client Tunnel IP and VPN Credentials (default All). [zia.insights.logs:extranet-partner-filters] Among the Extranet Insights Log filters are Client Destination Name (a destination FQDN), Client Source IP, Server Destination IP and Server Source IP, and the Client Source, Server Destination and Server Source ports. Client Source IP and Server Destination IP are entered by choosing Match with an IP address, a range or an IP address and netmask. Inbound Bytes limits the data to packets sent from the server to the client within a size range, and Outbound Bytes to packets received by the server within a size range. The Protocol filter defaults to None and lists ICMP, TCP and UDP. [zia.insights.logs:extranet-endpoint-and-byte-filters] In the Extranet Insights Logs filters, Device Hostname, Device Name and Device Owner are not available to admins with device information obfuscation enabled, and the Device Name and Device Owner filters take all or part of the value with an operator such as Contains, Starts With, Ends With, Exact Match, Does Not Contain, Does Not End With, Not Null or Is Null. The Location filter includes Road Warrior, the default location for transactions that did not originate from a predefined location, and lists 200 results at a time; Location Type defaults to None and its list includes Workload Traffic Group. [zia.insights.logs:extranet-device-and-location-filters] The Extranet logs have no NSS type and an empty Status filter [gap:zia.insights.logs:extranet-logs].

**Sandbox Verdict.** Sandbox Verdict Insights Logs give an overview of recent cloud sandbox analysis activity; they are viewable by tenants already using Standard or Advanced Sandbox and are enabled through the Zscaler Account team. [zia.insights.logs:sandbox-verdict-prereq] Sandbox Verdict Insights Logs show Analysis Completed Time, Download File Type, File MD5 (which opens the Sandbox Detail Report), File SHA256, Tactic (MITRE ATT&CK technique and tactic IDs), Threat Name and Verdict, whose verdicts include Benign, Suspicious and Sandbox subtypes such as Ransomware and Sandbox Offensive Security Tools; the Verdict filter offers verdict types related to Sandbox, Advanced Threat Protection, Malware Protection and others. [zia.insights.logs:sandbox-verdict-columns] The Sandbox Action filter default differs between Web and Mobile [gap:zia.insights.logs:sandbox-action-default].

**Console columns and NSS fields.** No source maps the Endpoint DLP, Email DLP and Sandbox Verdict console columns to NSS fields [gap:zia.insights.logs:console-to-nss-mapping]. The Threat Severity filters omit None [gap:zia.insights.logs:severity-none-filter]. A port is described as an address in two columns articles [gap:zia.insights.logs:port-described-as-address].

What to check:
1. Whether a large export is limited by the Insights Logs page's 1 million, by the Ranges and Limitations 100K, or by the 20 requests per hour, before promising a record count.
2. Whether a long query was moved to the background and has passed the 72 hours its report stays available.
3. Whether a count from the console excludes delayed logs, which no source defines.
4. Which definition of Client Trans. Time the page in front of the admin uses, Web or Mobile.
5. Whether a console column has an NSS label before mapping it to a feed field.

Sources disagree (name both sides):
- The Insights Logs CSV export ceiling is 1 million records on the About Insights Logs page, 100K entries in the Ranges and Limitations table, and 100K lines on the SaaS Security Insights Logs page. [divergence:zia.insights.logs:export-ceiling]
  - zscaler-help: An export holds up to 1 million records, in options of 100K, 250K, 500K or 1 million.
  - zscaler-help: Exported Transactions is limited to 100K entries.
  - zscaler-help: The SaaS Security Insights Logs page exports up to 100K lines of data at a time.
  Impact: An export between 100K and 1 million records is allowed by one page and over the limit on the others; the pages do not say whether the table row covers the Web, Mobile, Firewall, DNS and Tunnel exports or the SaaS Security page's 100K is the only scope of that figure.
- Client Trans. Time (ms) is defined with the client's upload time on the Web Insights Logs page and without it on the Mobile page. [divergence:zia.insights.logs:client-trans-time]
  - zscaler-help: The sum of Proxy Latency, Server Trans. Time and the client's time to upload the entire request payload.
  - zscaler-help: The sum of the Proxy Latency and Server Time columns, with no upload time.
  Impact: The same column name gives a different number on the two pages if the upload time is not zero; the pages do not say whether Mobile logs omit it or the Mobile page is incomplete.
