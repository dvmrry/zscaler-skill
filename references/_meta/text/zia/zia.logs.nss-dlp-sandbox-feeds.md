# Cloud and HTTP NSS feeds for Email DLP, Endpoint DLP and Sandbox Verdict logs: settings, certificates and filters (zia.logs.nss-dlp-sandbox-feeds)
Also called: email dlp nss feed; endpoint dlp nss feed; sandbox verdict nss feed; http nss feed email dlp; cloud nss feed sandbox verdict

**HTTP feeds.** The HTTP NSS feed articles for Email DLP and Endpoint DLP each say that, before configuring HTTP NSS feeds, the tasks for the virtual appliance in the NSS Deployment Guides for the platform must be completed. [zia.logs.nss-dlp-sandbox-feeds:http-dlp-prerequisite] In the HTTP NSS feed articles for Email DLP and for Endpoint DLP, a self-signed or internally issued certificate that passes the SIEM connectivity test can be used only after it is configured in the VM instance with `nss add-cert-to-trust <self-signed certificate>`, giving the path of the certificate from the NSS node. [zia.logs.nss-dlp-sandbox-feeds:http-dlp-self-signed] The HTTP Endpoint DLP and HTTP Sandbox Verdict feed articles list an NSS Server field and say a configured NSS server is required to add an NSS feed. [zia.logs.nss-dlp-sandbox-feeds:endpoint-dlp-nss-server] Whether the HTTP Email DLP article omits that field is open [gap:zia.logs.nss-dlp-sandbox-feeds:email-dlp-nss-server]. The same prerequisite and certificate steps for the HTTP Sandbox Verdict article are in [The HTTP Firewall, HTTP SaaS Security and HTTP Sandbox Verdict NSS feed articles each say that before configuring HTTP NSS feeds, the tasks for the virtual appliance in the NSS Deployment Guides for the platform must be completed.](kb:shared.nss.feed-settings:http-prerequisite) and [In the HTTP Firewall, HTTP SaaS Security and HTTP Sandbox Verdict NSS feed articles, a self-signed certificate is configured by running `nss add-cert-to-trust <self-signed certificate>` in the VM instance, with the path of the certificate from the NSS node in place of the placeholder.](kb:shared.nss.feed-settings:http-self-signed-command).

**Cloud and HTTP feeds.** In the Cloud NSS feed articles for Email DLP, Endpoint DLP and Sandbox Verdict logs, the HTTPS URL must carry a publicly trusted SSL certificate because self-signed or internally issued certificates do not pass the SIEM connectivity test, and OAuth 2.0 Authentication is enabled by default if applicable to the SIEM type. [zia.logs.nss-dlp-sandbox-feeds:cloud-cert-oauth] The Cloud NSS feed article for Endpoint DLP logs has Log Type set by selecting Endpoint DLP, and offers filters by users, departments, File Type Category, File Type, DLP Engines, DLP Dictionaries, Severity and Record Type. [zia.logs.nss-dlp-sandbox-feeds:cloud-endpoint-dlp] The Cloud NSS feed articles for Email DLP (Log Type Email DLP), Endpoint DLP (Log Type Endpoint DLP) and Sandbox Verdict (Log Type Sandbox Verdict) show NSS Type as NSS for Web by default, Status Enabled by default, and JSON output by default with Tab-separated and Custom as alternatives; the HTTP Sandbox Verdict article carries the same NSS Type line. [zia.logs.nss-dlp-sandbox-feeds:cloud-defaults] In the Cloud NSS feed articles for Email DLP, Endpoint DLP and Sandbox Verdict logs and in the HTTP Sandbox Verdict article, SIEM Rate stays Unlimited unless the output must be throttled; SIEM Rate Limit (Events per Second) is available only when Limited is selected, and a limit too low for the traffic volume causes log loss. [zia.logs.nss-dlp-sandbox-feeds:cloud-siem-rate] In the Cloud NSS Email DLP, Endpoint DLP and Sandbox Verdict feed articles and the HTTP Email DLP, Endpoint DLP and Sandbox Verdict feed articles, if JSON is the Feed Output Type, special characters such as a backslash in string fields might cause a SIEM parsing issue, and the fix is to enter a comma, backslash and quotation marks as the Feed Escape Character and use hex-encoded fields such as elogin in the Feed Output Format. [zia.logs.nss-dlp-sandbox-feeds:email-dlp-json-escaping] The SIEM type list and the rate limit range are open [gap:zia.logs.nss-dlp-sandbox-feeds:cloud-siem-type].

**Filters.** The Email DLP feed filters (Cloud and HTTP articles) include Users and Departments under Who, DLP Engines and DLP Dictionaries (transactions where data leakage was detected based on those engines or dictionaries), Record Type (DLP Incident, Scan, Sensitive Activity), Policy Action (allowed, blocked or Custom Header Insertion) and Severity as configured in the Outbound Email Policy. [zia.logs.nss-dlp-sandbox-feeds:email-dlp-filters] The HTTP Endpoint DLP feed filters include File Type Category and File Type (detected from the content) and Severity (of the incidents detected by the Endpoint DLP policy), each allowing multiple selections. [zia.logs.nss-dlp-sandbox-feeds:endpoint-dlp-filters] The Cloud Sandbox Verdict feed filters include Threat Names, Download File Type, MD5 hash, SHA-256 hash and, under Sandbox Verdict, Sandbox Verdicts (with an optional Benign selection) and MITRE ATT&CK tactic (for example TAC028) and technique (for example T1005); with no tactics or no techniques specified, verdicts for any MITRE ATT&CK tactic or technique are displayed. [zia.logs.nss-dlp-sandbox-feeds:sandbox-filters-cloud] Under the Cloud Sandbox Verdict feed's Threat Names filter, an item list shows up to 500 items on a page, can be searched, and can be cleared with Remove All or per page with Remove Page, with a confirmation window. [zia.logs.nss-dlp-sandbox-feeds:sandbox-item-lists]
