# Runbook: URL category conflicts, Miscellaneous and Newly Registered and Observed Domains handling (zia.troubleshooting-runbook.url-category-conflicts)
Also called: Resolve user-defined category conflicts; Specific criteria in the access control policy do not match; Categorization Method column

**Categorization method.** The runbook's Categorization Method web log column (named URL Categorization Method on the Web Insights columns page) shows Database A (Zscaler's proprietary URL database), Database B (a third-party vendor's database), AI/ML-based content categorization, User-Defined, or None. [zia.troubleshooting-runbook.url-category-conflicts:categorization-method-values]

**User-defined categories.** Adding a domain such as drive.google.com to the Custom URLs field of a user-defined category removes it from the predefined category FileHost for that customer, and policies for FileHost do not apply to it; the page's .office365.com example says O365 traffic might then not show in an Office365 report and could get undesirable SSL Inspection enforcement. [zia.troubleshooting-runbook.url-category-conflicts:custom-urls-removes-predefined] The page recommends adding such URLs to the URLs retaining Parent Category field so all access control policy rules are enforced for both user-defined and predefined categories, with no impact on predefined reports and dashboards. [zia.troubleshooting-runbook.url-category-conflicts:parent-category-field-recommended] When adding a specific subdomain to a Custom Category, the page says to add it to all existing user-defined categories that contain the top-level domain unless the policy should apply only to the most specific match. [zia.troubleshooting-runbook.url-category-conflicts:conflict-solution]

**Most specific match examples.** In the page's first example (CAT1 holds .google.com and CAT2 holds drive.google.com, both in Custom URLs), a Google Drive request is evaluated only against CAT2, and without a matching CAT2 rule it is implicitly allowed unless an explicit block or bottom rule applies. [zia.troubleshooting-runbook.url-category-conflicts:most-specific-match-example1] In the second example (CAT3 and CAT4 entries in the URLs retaining Parent Category field), drive.google.com matches CAT3 and FileHost, and www.google.com matches .google.com in both CAT3 and CAT4 so rules for CAT3, CAT4 and WebSearch are selected and the topmost rule is enforced. [zia.troubleshooting-runbook.url-category-conflicts:most-specific-match-example2] In the third example, with drive.google.com added directly to authentication exemptions and CAT5 holding .google.com in the Parent Category field, a Google Drive request matches only the FileHost policy while other .google.com subdomains match CAT5 and the applicable predefined categories. [zia.troubleshooting-runbook.url-category-conflicts:most-specific-match-example3] When the correct category is enforced but a different one is logged, a Block configured for at least one matching category and Allow for others blocks access if the Block rule is above the Allow rule; otherwise only URL Filtering allows it and the effective action depends on the remaining modules. [zia.troubleshooting-runbook.url-category-conflicts:logged-category-differs]

**Miscellaneous and NROD.** Adding a URL to a user-defined URL category removes it from the Miscellaneous category by design; for Miscellaneous or Unknown URLs, the retaining-parent-category fields behave like Custom URLs and Custom Keywords. [zia.troubleshooting-runbook.url-category-conflicts:misc-removed-by-custom] With Suspicious New Domains Lookup enabled under URL & Cloud App Control > Advanced Policy Settings, Newly Registered or Observed Domains are also classified under Miscellaneous; the service considers such a domain suspicious for 30 days after detection. [zia.troubleshooting-runbook.url-category-conflicts:suspicious-new-domains] If different policy rules exist for Miscellaneous and Newly Registered and Observed Domains, the rule at the top is enforced; to block NROD while allowing Miscellaneous, the NROD block rule must be above the Miscellaneous allow rule. [zia.troubleshooting-runbook.url-category-conflicts:misc-nrod-rule-order] The runbook says not every URL to be allowed needs a custom category; if the business must block Professional Services for the criteria, create a Custom URL category allowing only a set of URLs while still blocking the parent category. [zia.troubleshooting-runbook.url-category-conflicts:allow-one-url-professional-services]

**AI/ML-based content categorization.** With AI/ML-based Content Categorization enabled, enforcement for SSL-inspected transactions to Miscellaneous URLs is deferred until the server responds; if the server does not respond or the client terminates the connection on a timeout, the policy might not be applied and received bytes show 0, and disabling the feature is a global change. [zia.troubleshooting-runbook.url-category-conflicts:aiml-defers-enforcement] When only the first request through a data center shows Miscellaneous or Newly Registered and Observed Domains and later ones a more specific category, AI/ML-Based Content Categorization is a possible cause; because the transaction was already decrypted, the SSL inspection bypass is not enforced for the dynamic category but other policies for it are applied. [zia.troubleshooting-runbook.url-category-conflicts:aiml-two-categories] The SSL inspection of Miscellaneous that makes the early decryption happen is described in [Runbook: policy configured but the logs show a different outcome](kb:zia.troubleshooting-runbook.policy-mismatch).
