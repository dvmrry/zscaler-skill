# What a URL category entry may contain, and category limits (zia.url-categories.entry-format)
Also called: url format guidelines; invalid url entry; custom url category limits; custom category quota; keyword matching; regex url category; tld category

These rules decide whether an entry is accepted at all, which matters most for automation: Adding URLs to a custom category is all-or-nothing: one invalid URL rejects the whole request with an error. [zia.url-categories.entry-format:bulk-add-all-or-nothing]

The basic shape: Entries must be lowercase, ASCII, in `host.domain` form, and must not include a scheme (`http://`). [zia.url-categories.entry-format:format-rules] A URL entry is at most 1,024 characters, its domain at most 255 characters before any colon, and each domain label at most 63 characters. [zia.url-categories.entry-format:length-limits] URL Filtering does not support non-English characters outside the ISO/IEC 8859-1 character set. [zia.url-categories.entry-format:non-english] Underscores are rejected in the TLD and in the second-level domain when a subdomain is present (`www.safe_march.com`), but allowed in subdomains, paths, and in the SLD of a URL with no subdomain (`safe_march.com`); a lone `_` cannot be a subdomain. [zia.url-categories.entry-format:underscore-rules] A bare TLD such as `.gov` cannot be added as a URL entry. [zia.url-categories.entry-format:no-tld-only]

Custom keywords match anywhere in the whole URI, so a `gambling` keyword also matches a search URL such as `www.google.com/search?q=gambling`. [zia.url-categories.entry-format:keywords-whole-uri]

Custom categories can match by regex (`urlType: REGEX` with `regexPatterns`) instead of exact entries; patterns are 3 to 255 characters, at most 256 across all categories, and the feature must be enabled by Zscaler Support. [zia.url-categories.entry-format:regex-patterns] So tenant entries that look odd as exact URLs may be regex patterns, and the console walkthrough is not a guide to them. [zia.url-categories.entry-format:regex-patterns-in-tenant-data] Custom categories have a `type` (`URL_CATEGORY` or `TLD_CATEGORY`). When listing, no type filter returns predefined plus custom `URL_CATEGORY` categories, and `ALL` returns predefined plus custom categories of every type. [zia.url-categories.entry-format:category-type-filter] The `type` filter rests on SDK and MCP behavior, not the captured contract [divergence:zia.url-categories.entry-format:type-filter-parameter]. The Python SDK creates a custom TLD category with type TLD_CATEGORY and supplies its entries, written in the format '.tld', in the `urls` list. [zia.url-categories.entry-format:tld-category-urls-field] (see [Which field holds TLD entries in a TLD_CATEGORY custom category](kb:zia.url-categories.entry-format:tld-category-entries)).

Default limits: 25K custom URLs or TLDs (a count that includes the custom URLs/TLDs in all URL and TLD categories, plus auth exemption URLs, ATP blocked malicious URLs, SSL Inspection blocked URLs, FTP Control allowed URLs and bandwidth class domains; more via a Custom URLs subscription), 64 custom categories (1,024 via Support), 256 keywords per category with 2,048 across all categories, 2,048 keywords retaining their parent category across all categories, and a combined 2,048 custom keywords plus retaining-parent keywords per organization. [zia.url-categories.entry-format:category-quotas] How entries match requests once accepted is in [How URL category entries match requests (wildcards)](kb:zia.url-categories.entry-matching).

**Custom category fields.** The Custom URL Categories page says up to 64 custom categories can be created, category names can only contain alphanumeric characters, underscores, hyphens, dots, parenthesis and spaces, and the description cannot exceed 256 characters. [zia.url-categories.entry-format:custom-category-name-rules] IP addresses entered in Custom URLs can only match if the IP address is accessed directly in the URL (for example https://192.168.1.10). The field supports IPv6 addresses either in full or short form. [zia.url-categories.entry-format:custom-url-ip-entries] Custom keywords and keywords retaining parent category must each be between 3 and 255 characters, and policies including either trigger if the keyword is a full or partial match of the URI. [zia.url-categories.entry-format:custom-keyword-lengths] The Custom IP Ranges field is not available by default and Zscaler Support enables it, and IPv6 ranges are not supported for it. IPv6 ranges are also not supported for IP Ranges Retaining Parent Category. [zia.url-categories.entry-format:custom-ip-ranges] The Custom URLs list offers Remove 25K Items (the first 25,000 items) or Remove Page, and the Custom Keywords list offers Remove All or Remove Page. [zia.url-categories.entry-format:list-removal-options]

The page's 64-category figure sits against the 1,024 maximum Support can raise it to in [zia.url-categories.entry-format:category-quotas], and the page does not mention that raise [gap:zia.url-categories.entry-format:custom-category-limit-raise].

**TLD categories.** TLD categories can be selected in the DNS Control, File Type Control, Firewall Filtering, IPS Control, Sandbox, DLP Policy with Content Inspection, DLP Policy without Content Inspection, Forwarding Control, SSL/TLS Inspection and URL Filtering policies. [zia.url-categories.entry-format:tld-category-policies] A TLD category's URL Super Category is set to User-Defined and cannot be configured, and entries can have up to two levels of domains (for example .co.uk, .gov.in). [zia.url-categories.entry-format:tld-category-fixed] On the TLD Categories page, the No. of Top Level Domains column displays up to 20 TLDs when the number under it is clicked, and the complete list can be viewed in the edit mode of the TLD category page. [zia.url-categories.entry-format:tld-list-display]

**Listing.** The MCP URL-category list tool exposes `custom_only`, `type`, `search` and `contains_url`; its source says `/urlCategories` does not paginate and that page and page_size inputs had been silently ignored by the API. The captured Automate operation lists `customOnly` and `includeOnlyUrlKeywordCounts` as its only query parameters. [zia.url-categories.entry-format:mcp-list-unpaginated] Whether the keyword-counts parameter trims the response is disputed [divergence:zia.url-categories.entry-format:keyword-counts-parameter]. The Python SDK has a `list_categories_lite` wrapper for the lightweight category list, and the MCP URL-category tool deliberately does not use it: its source says `/urlCategories/lite` takes no parameters, so it cannot filter, and it omits `configuredName`, the only handle a custom category has. [zia.url-categories.entry-format:mcp-lite-not-used]

- Whether includeOnlyUrlKeywordCounts trims the response [divergence:zia.url-categories.entry-format:keyword-counts-parameter]
  - api-specs: Automate: the parameter, when true, makes the response include only URL and keyword counts for custom categories.

  Impact: Do not rely on the parameter to shrink the listing; the observation is one tenant capture, not proof that every tenant ignores it.
- Whether the type query parameter exists [divergence:zia.url-categories.entry-format:type-filter-parameter]
  - sdk-python: The Python SDK documents a `type` filter and the MCP tool sends it upstream.
  - mcp-server: The MCP list tool sends `type` as an upstream query parameter.
  - api-specs: The captured Automate operation lists only customOnly and includeOnlyUrlKeywordCounts as query parameters.
  Impact: The type filter rests on SDK and MCP behavior, not on the captured contract.
