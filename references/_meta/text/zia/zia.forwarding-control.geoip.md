# Geolocalization IP (GeoIP) forwarding: when it applies, how it is enabled and the supported-country table's example rows (zia.forwarding-control.geoip)
Also called: geoip; geolocalization ip; geo ip forwarding; GEOIP forwarding method

For users in a country not serviced by a Zscaler Point-of-Presence (PoP), the Geolocalization IP (GeoIP) feature can be used to access local content or destinations that restrict access based on the source IP address, and GeoIP forwarding policies forward traffic using IP addresses mapped to the location of the originating request. [zia.forwarding-control.geoip:purpose] When Zscaler does not host a data center in a country and a user from that country accesses a local destination with source IP address-based access restrictions, the traffic is routed to the geographically closest Zscaler data center outside the country. [zia.forwarding-control.geoip:without-geoip] The page says to consult the compliance or legal team to ensure the GeoIP configuration complies with applicable local laws. [zia.forwarding-control.geoip:compliance-check]

**Enabling and rules.** If GeoIP is not already available on an Internet & SaaS tenant, Zscaler Support is contacted to enable it, after which Zscaler enables GeoIP as a traffic forwarding method in the Zscaler Admin Console. [zia.forwarding-control.geoip:enablement] A GeoIP forwarding rule does not need forwarding gateway configuration: Zscaler automatically forwards the traffic with a source IP address mapped to the country where the traffic originates, and if no criteria are chosen all the traffic egresses with GeoIP addresses based on the source country. [zia.forwarding-control.geoip:no-gateway-needed] The Zscaler service determines the country the user is in from the user's source IP. If the user is in a country that hosts a Zscaler data center, the traffic is serviced by the local data center and egresses with a country-local source IP address, and the GeoIP rule does not apply. [zia.forwarding-control.geoip:country-determination]

**Limits of the mapping.** In some cases destination websites might not honor the source IP for country mapping to determine the location of the user. The page's alternatives are deploying App Connectors in the region for Source IP Anchoring with local IP addresses, or deploying Virtual Service Edges or Private Service Edges for Internet & SaaS in the region for local IP addresses. [zia.forwarding-control.geoip:destinations-may-ignore] The page has a table of the currently supported countries for the GeoIP feature; its example rows are Czechia and Serbia, labeled Europe, and its worked example forwards the traffic of a user located in Czechia towards the destination with a Czechian source IP address. [zia.forwarding-control.geoip:supported-countries] Licensing and the region labels are open [gap:zia.forwarding-control.geoip:licensing] [gap:zia.forwarding-control.geoip:region-labels].
