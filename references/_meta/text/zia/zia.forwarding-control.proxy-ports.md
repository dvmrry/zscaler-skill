# Dedicated proxy ports (zia.forwarding-control.proxy-ports)
Also called: dedicated proxy port; proxy port forwarding; enforce authentication proxy port; sd-wan proxy port zia

A dedicated proxy port is a forwarding option for gateways that cannot build tunnels. Dedicated proxy ports let an internet gateway or SD-WAN device forward user traffic to a port number assigned to the organization. It is an additional subscription service, recommended only when the gateway cannot provide GRE or IPSec tunnels, and the ports are tied to locations you designate. [zia.forwarding-control.proxy-ports:what] Users on a dedicated proxy port must authenticate, because anyone can send traffic to the port. For remote users reaching proxy ports by PAC file, the page says they need to use one; deploying Zscaler Client Connector is the more robust method. [zia.forwarding-control.proxy-ports:authentication]

**Configuration.** Ports are configured on the Location Management page by adding the assigned ports and selecting Enforce authentication. Zscaler recommends enabling Surrogate IP on proxy ports and for remote users. [zia.forwarding-control.proxy-ports:configuration] The reference architecture lists these location settings for proxy ports: NAT disabled, Surrogate IP enabled and authentication at the location enabled. [zia.forwarding-control.proxy-ports:required-settings] An organization can subscribe to one or more ports, associate them with a location, and forward remote user traffic to them. [zia.forwarding-control.proxy-ports:subscribe-and-associate] Zscaler Support is contacted to subscribe to the proxy ports; Enforce Authentication is selected under Gateway Options; and after the ports are configured in the Admin Console, remote users' PAC files are edited to forward their traffic to the subscribed ports. [zia.forwarding-control.proxy-ports:setup] The port number ranges, the number of ports a location can take and the name of the external-IP mapping setting are open [gap:zia.forwarding-control.proxy-ports:port-details].

**Client Connector.** Client Connector can use a dedicated proxy port: on the Dedicated Proxy Port page (Infrastructure > Client Connector > Dedicated Proxy Port) an admin enables Dedicated Proxy Port and selects an available port, and Client Connector attempts connections with that port before using 443 or 80, in that order. [zia.forwarding-control.proxy-ports:client-connector-port] The mode, versions and platforms are open [gap:zia.forwarding-control.proxy-ports:client-connector-port-details]. Forwarding profiles: [ZCC forwarding profiles](kb:zcc.forwarding-profiles).

**What the port gives remote users.** With SSL Inspection enabled at the location, the service can apply all the SSL settings, including URL category and custom domain decryption exclusions, to remote user traffic on the port, whereas remote user traffic typically goes to port 9443, where the SSL exclusion settings are not applied. The port also lets remote users authenticate automatically with the SAML IdP. [zia.forwarding-control.proxy-ports:ssl-and-saml] The port supports FTP over HTTP for remote users and lets the service identify a remote user's organization and show its logo on the login page; with SAML authentication, remote users are not prompted for their login name. [zia.forwarding-control.proxy-ports:ftp-and-logo] The port can apply the location's policies, instead of the default policy, to remote user traffic that cannot be authenticated, such as transactions that use unknown agents or non-HTTP protocols. [zia.forwarding-control.proxy-ports:location-policy-for-unauthenticated] The service can also be enabled to map users to their external IP addresses, so it can apply user-level policies to remote user traffic it cannot authenticate. [zia.forwarding-control.proxy-ports:external-ip-mapping]

**Authentication and precedence.** Authentication must be enforced on the location associated with the ports; the service blocks traffic it cannot authenticate (an unknown user-agent or a non-HTTP protocol) if it is from an IP address that an authenticated user has not used. [zia.forwarding-control.proxy-ports:auth-enforced] Traffic from a known location that arrives at a subscribed proxy port gets the known location's policies, not those of the location associated with the port. [zia.forwarding-control.proxy-ports:known-location-wins]

Surrogate IP is covered in the legacy [Source IP Anchoring across ZIA and Private Access: path, pieces and interactions](kb:shared.source-ip-anchoring). Forwarding rules for such traffic: [Forwarding methods and their required fields](kb:zia.forwarding-control.methods).
