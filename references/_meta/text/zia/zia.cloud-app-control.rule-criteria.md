# What a Cloud App Control rule matches on (zia.cloud-app-control.rule-criteria)
Also called: cac rule criteria; cloud applications or risk profile; how does cac identify the app; url to cloud app mapping; cloud app lookup
Former IDs: zia-09

A Cloud App Control rule matches on the logical expression: [Cloud Applications OR Cloud Application Instances OR Cloud Application Risk Profile] AND [Groups OR Users OR Departments] AND [Location Groups OR Locations] AND Time AND [Devices OR Device Groups OR Device Trust Level OR CONNECT User-Agent OR User Risk Profile]. [zia.cloud-app-control.rule-criteria:criteria-expression] Compare this with URL Filtering, where the criteria are URL categories rather than applications: [How URL Filtering rule criteria combine](kb:zia.url-filtering.criteria).

**Naming applications.** A rule names its applications either through the Cloud Applications field or through a Cloud Application Risk Profile, not both. [zia.cloud-app-control.rule-criteria:apps-or-risk-profile] A rule that selects a Risk Profile applies to every cloud application whose attributes satisfy the profile, so one such rule can cover many applications at once. [zia.cloud-app-control.rule-criteria:risk-profile-covers-all] When a rule names a Risk Profile, the question "why did this rule catch that app" becomes a question about the app's attributes: [Cloud Application Risk Profiles in Cloud App Control](kb:zia.cloud-app-control.risk-profiles).

**Mapping a URL to an application.** Zscaler documents the Admin Console URL Lookup tool and the urlLookup API as the way to look up the cloud application for a URL. [zia.cloud-app-control.rule-criteria:url-lookup-tool] The Help article on configuring URL categories through the API describes the /urlLookup endpoint as returning the URL categories a URL belongs to, with custom URL classification not returned and URLs not under a predefined URL category returned as MISCELLANEOUS_OR_UNKNOWN. [zia.cloud-app-control.rule-criteria:urllookup-returns-categories] How CAC maps a request to an application on a shared hostname is open [gap:zia.cloud-app-control.rule-criteria:app-identity]. Whether CAC can see enough to identify the app depends on decryption: [Cloud App Control and SSL inspection: what CAC can see](kb:zia.cloud-app-control.ssl-visibility).

**Selection limits.** On the Consumer, Instant Messaging and AI & ML rule pages, Users, Groups, Departments, Locations and Location Groups each take Any or up to 32 selections, and Time takes Always or up to two time intervals; the pages say to contact Zscaler Support to increase the limit of Users, Groups, or Departments and of Locations. [zia.cloud-app-control.rule-criteria:criteria-selection-caps] On the Consumer, Instant Messaging and AI & ML rule pages, Cloud Applications takes Any (all cloud applications in the rule's category) or any number of cloud applications, and by default the field displays the first 100 cloud applications. Cloud Application Instances allows a maximum of 8 instances per rule and appears only if the instance's parent application is selected as the cloud application. [zia.cloud-app-control.rule-criteria:cloud-apps-field] On the Consumer, Instant Messaging and AI & ML rule pages, with the Policy for Unauthenticated Traffic enabled, Special Users can be selected for all unauthenticated users or specific types of them, and Special Departments for all unauthenticated transactions; any rule that applies to unauthenticated traffic must apply to all groups and departments, by selecting Any for Groups and Departments. [zia.cloud-app-control.rule-criteria:unauthenticated-traffic]

**Device and user criteria.** On the Consumer rule page, Device Groups selects the group for Zscaler Client Connector traffic by device platform, or Cloud Browser Isolation, IoT or No Client Connector for isolation traffic, IoT traffic or traffic not tunneled through Client Connector; the Cloud Browser Isolation and IoT groups are available only if Zero Trust Browser (formerly Isolation) and IoT discovery are enabled for the organization, respectively. For Devices and for Device Groups, selecting no value ignores the criterion in the policy evaluation. [zia.cloud-app-control.rule-criteria:device-criteria] On the Consumer rule page, Device Trust Level High Trust, Medium Trust and Low Trust evaluation applies only to Zscaler Client Connector traffic while Unknown evaluation applies to all traffic, and the trust levels come from the organization's posture configurations. Users are assigned a risk score from their browsing activities, and by default the User Risk Profile levels are Low (0 to 29), Medium (30 to 59), High (60 to 79) and Critical (80 to 100). [zia.cloud-app-control.rule-criteria:device-trust-and-user-risk] Cloud App Control policy rules can also be applied to IoT devices from a location or sublocation that has the Enforce IoT Policy Control option enabled, including devices identified and classified by Zscaler AI/ML under the IoT group in the Device Groups criterion. [zia.cloud-app-control.rule-criteria:iot-devices] On the Consumer rule page the rule form shows an Adaptive Access Profile field that the page says is currently not functional in the Zscaler Admin Console; the page says to contact the Zscaler Account team to subscribe to Experience Center to use this feature. [zia.cloud-app-control.rule-criteria:adaptive-access-not-functional] What subscribing to Experience Center changes is open [gap:zia.cloud-app-control.rule-criteria:adaptive-access-experience-center].

2. Whether a predicted CAC rule for a URL is confirmed by a test, since the mapping on a shared hostname is open.
