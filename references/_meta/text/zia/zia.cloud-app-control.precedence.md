# Cloud App Control versus URL Filtering: which applies (zia.cloud-app-control.precedence)
Also called: cac vs url filtering; cloud app control precedence; allow cascading to url filtering; cascading; cac allows url filter blocks; why does cac allow override a url block

Neither "Cloud App Control always wins" nor "the stricter policy wins" holds. The rule that matters is about the allow path.

By default, Cloud App Control takes precedence over URL Filtering. [zia.cloud-app-control.precedence:cac-first] By default, when a Cloud App Control rule explicitly allows the transaction, URL Filtering is not applied at all, so a URL Filtering block on the same site does not fire. [zia.cloud-app-control.precedence:cac-allow-skips-url-filtering]

Enabling Allow Cascading to URL Filtering in Advanced Settings makes the service apply the URL Filtering policy even when a Cloud App Control rule allows the transaction, so a URL Filtering block then applies. [zia.cloud-app-control.precedence:cascading-allow-path] In the help's example, with Allow Cascading to URL Filtering enabled, Facebook blocked by a Cloud App Control rule stays blocked even though URL Filtering allows it. [zia.cloud-app-control.precedence:cac-block-final]

When the user requests a cloud app that no Cloud App Control rule covers, the service still evaluates and applies URL Filtering, although the Cloud App Control default policy behavior is Allow All. [zia.cloud-app-control.precedence:no-cac-rule-url-filtering-runs] A Cloud App Control allow rule scoped to one department matches only that department's users, so for everyone else no Cloud App Control rule matches and URL Filtering evaluates normally. [zia.cloud-app-control.precedence:scoped-allow-leaves-others-to-url-filtering]

Each Cloud App Control rule has its own Cascade to URL Filtering option (`cascadingEnabled`). It appears only when the Allow Cascading to URL Filtering option on the Advanced Settings page is disabled, and when enabled it enforces the URL Filtering policy on a transaction even after that rule explicitly allows it. URL Filtering does not apply if the rule blocks. [zia.cloud-app-control.precedence:per-rule-cascade] Enabling the cascading option in Advanced Settings allows cascading to URL filtering globally for all Cloud App Control policies, irrespective of the cascading settings at the policy level. It does not apply to the Microsoft 365 One Click predefined Cloud App Control rules within the Collaboration & Online Meetings, Productivity and CRM Tools, File Sharing, Hosting Providers, IT Services and Webmail cloud app categories; to cascade there the page says to create a rule above the predefined rule. [zia.cloud-app-control.precedence:global-cascade-overrides] Within Cloud App Control, rules evaluate top-down in ascending order, and a disabled rule is skipped while keeping its place, the same as URL Filtering. [zia.cloud-app-control.precedence:cac-rule-order] The MCP rule helpers define `order` as a positive 1-based integer where lower values are evaluated first, default it to 1 on create when omitted, and send it on update only when the caller provides it. The cloud app control create input describes it as "Evaluation order (lower=first)." [zia.cloud-app-control.precedence:mcp-order-surface] The MCP create workflow skill states that Cloud App Control rules sit in one top-to-bottom table per rule type where the first match wins, and that a more general rule above a more specific one shadows it. [zia.cloud-app-control.precedence:mcp-skill-first-match-shadowing] Zscaler advises documenting the Allow Cascading to URL Filtering settings, to understand the flow of the evaluated rules and help internal personnel and Zscaler Support troubleshoot issues. [zia.cloud-app-control.precedence:document-cascading] As an operations prerequisite Zscaler says to generally allow Cloud App Control policies over URL Filtering rules to use the predefined cloud applications. [zia.cloud-app-control.precedence:prefer-cac-for-predefined-apps] Each pass of the pipeline evaluates CAC before URL Filtering: see [Where SSL inspection sits in ZIA web policy evaluation (the two passes)](kb:zia.ssl-inspection.pipeline).

**Cascade per action.** On the Consumer rule page, the Cascade to URL Filtering option is offered under the Allow, Caution and Isolate actions. [zia.cloud-app-control.precedence:cascade-per-action] Whether a Conditional allow offers it is open [gap:zia.cloud-app-control.precedence:cascade-conditional].

**Rank, view and expiry.** On the Consumer rule page, with Admin Rank enabled the rule's admin rank is a value from 0 to 7 (0 is the highest), the admin cannot select a rank higher than their own, the admin's assigned rank determines the rule order values they can select, and a rule with a higher admin rank always precedes a rule with a lower admin rank. The About page says the Admin Rank column is visible only if Admin Rank is enabled in Advanced Settings. [zia.cloud-app-control.precedence:admin-rank] The Cloud App Control policy page can display rules by the selected application category, which is selected by default, or in a view that lists all Cloud App Control rules with the predefined rules first, followed by configured rules. [zia.cloud-app-control.precedence:rules-view-predefined-first] On the Consumer rule page, Enable Rule Expiration sets a validity period for the rule with a start date and time, an end date and time and a time zone. The page says the feature can temporarily allow or block access to an application if configured rules block or allow it, respectively; after the rule expires, Zscaler either blocks or allows the traffic based on the default rules configured for the organization. [zia.cloud-app-control.precedence:rule-expiration] What the organization's default rules are is open [gap:zia.cloud-app-control.precedence:expiry-default-rules].

**Microsoft 365 One Click rules.** The page says a predefined rule is created under each of these cloud app categories on the Cloud App Control Policy page, allowing Cloud App Control traffic destined to the listed Microsoft 365 applications: Collaboration & Online Meetings (Yammer, SharePoint Online, Microsoft Teams, Microsoft Sway), Productivity and CRM Tools (Common Microsoft 365 Applications, Microsoft Dynamics 365, Microsoft Delve, Microsoft Power BI, Microsoft Planner), File Sharing (OneDrive), Hosting Providers (Microsoft Azure), IT Services (Microsoft Azure AD, Microsoft Intune) and Webmail (Outlook). The rules are not configurable and cannot be deleted, but their rule orders can be changed if necessary. [zia.cloud-app-control.precedence:one-click-predefined-rules] The options that create them are in [Microsoft 365 One Click configurations: the two options, where each is set, and the DNS Control rule](kb:zia.advanced-settings.m365-one-click).

What to check:
1. Whether the tenant-wide Allow Cascading to URL Filtering option is on, before reading any rule.
2. Whether an individual rule cascades on its own Cascade to URL Filtering option, not only through the Allow Cascading to URL Filtering option in Advanced Settings.
