# Endpoint DLP resources and resource tags: network shares, printers, removable storage, endpoint applications (zia.dlp.endpoint-resources)
Also called: dlp resources; endpoint resources; dlp & endpoint resources; resource tags; endpoint application tags; endpoint application risk level

Creating a resource is the first step in setting up Endpoint DLP policies and in customizing Endpoint Context data. For Endpoint DLP, resources can be created for network shares, printers, removable storage devices, and applications; for Endpoint Context, application details can be specified. [zia.dlp.endpoint-resources:resource-types] The resources page is called DLP Resources if the organization has licensed only Endpoint DLP, Endpoint Resources if it has licensed only Endpoint Context, and DLP & Endpoint Resources if it has licensed both. [zia.dlp.endpoint-resources:page-name-by-license] The DLP Resources page is available if the organization has licensed Endpoint DLP but not Endpoint Context, and on it the page says to contact the Zscaler Account team to access the feature. [zia.dlp.endpoint-resources:endpoint-apps-account-team] The Zscaler service automatically supports Box, Dropbox, Google Drive, iCloud for macOS, and OneDrive personal cloud storage accounts, and no extra configuration is available for those services as DLP resources. [zia.dlp.endpoint-resources:personal-cloud-built-in] What Endpoint Context is and what it shows is in [Endpoint Context: endpoint application telemetry from Client Connector, the policies that use it, and the Application Investigation page](kb:zia.endpoint-context).

**Fields.** A network share's server entry can use regular expressions and CIDR ranges for advanced matching; the vendor's examples are regex:^(?i)srv* (all network servers starting with "srv", case-insensitive) and cidr:192.168.1.0/24. The share is scoped either to all files and directories on the server or to files in listed directories and subdirectories. [zia.dlp.endpoint-resources:network-share-fields] For a network share limited to listed directories, the Directory Paths field takes paths such as /<folder>/<subfolder> separated by line breaks. [zia.dlp.endpoint-resources:directory-paths-entry] A printer resource takes a Domain (the name of the domain where the printer is located), a Printer Name (as it appears in the OS list of printers) and an IP Address. [zia.dlp.endpoint-resources:printer-fields] A removable storage device resource needs at least one of the criteria Vendor ID (the manufacturer), Product ID or Serial Number. [zia.dlp.endpoint-resources:removable-storage-fields] The Windows application criteria are Original File Name (the original file name of the executable, located on the Details tab in the Properties for the executable file), File Name (the name of the executable that runs the application) and Digitally Signed. The macOS application criteria are Bundle ID (the bundle identifier that uniquely identifies the application), File Name and Digitally Signed. Digitally Signed is Any (no signature check), Yes (signature required) or No (signature not required) in the Windows drawer, whose application Description cannot exceed 255 characters. [zia.dlp.endpoint-resources:application-fields] In the Edit macOS Application drawer, the application Description cannot exceed 255 characters. [zia.dlp.endpoint-resources:macos-description-limit]

**Applications.** Endpoint applications are Well-Known (frequently seen in the Zero Trust Exchange security cloud, a dynamic classification), Discovered (found on endpoints by the Zscaler service) or Custom (added to a tenant by an administrator). [zia.dlp.endpoint-resources:application-types] Endpoint Application Risk Level is the calculated risk level of an application based on multiple properties and behaviors, and it can change based on the latest data. The service uses four risk levels; all applications might initially appear as Unknown until risk identification is complete. Applications identified as Discovered or Well-Known cannot be deleted. [zia.dlp.endpoint-resources:application-risk-level] Options can be configured for custom applications but most options can only be viewed for well-known applications and applications discovered by the Zscaler service. Version and Application Risk Level are not editable, but Application Risk Level Override can be set to Unknown, Low, Medium, or High to override the risk level the service set. [zia.dlp.endpoint-resources:application-edit-and-override]

**Import and tags.** Multiple resources can be imported at once from a CSV file, with a sample template available to download for each resource type; importing multiple applications is not supported. The row formats shown are <name>,<description>,<server name>,<paths>; <name>,<description>,<UNC>,<IP address>,<domain>; and <name>,<description>,<vendor ID>,<product ID>,<serial number>. [zia.dlp.endpoint-resources:csv-import] In the network share import, the imported resources can be added to a new tag (New Tag, with a name and description) or to an existing tag selected from the Select Tag drop-down menu. [zia.dlp.endpoint-resources:csv-import-tags] For Endpoint DLP, resource groups are replaced by resource tags: groups already configured are automatically converted to resource tag groups, and policies that used resource groups are automatically updated to use the converted resource tag groups. Grouping resources lets Endpoint DLP policy rules apply to multiple resources at the same time. [zia.dlp.endpoint-resources:tags-replace-groups] If the organization has licensed Endpoint Context but not Endpoint DLP, it cannot create tags for network shares, network printers, or removable storage devices. The Endpoint Application Tags tab contains both prebuilt lists of applications by category or theme from Zscaler, such as “Certificate Pinned” or “AI Browsers”, and custom application lists, and Edit can be clicked on an existing customized prebuilt list. [zia.dlp.endpoint-resources:tags-by-licence-and-prebuilt] The API and Terraform names for these objects are in [Endpoint DLP API families in the SDKs and Terraform provider](kb:zia.dlp.endpoint-dlp).

Whether these resources are the same objects as the device control resources is open in [Device Control rules per device class, the default rule, first-match evaluation and device control resources](kb:zia.dlp.endpoint-device-control). The rules that use them are in [Endpoint DLP policy rules: channels, criteria, actions (Allow, Block, Confirm, Protect) and notifications](kb:zia.dlp.endpoint-rules).
