# ZIA DNS gateways: protocol translation, primary/secondary failover, failure behavior, DoH path (zia.dns-control.gateways)
Also called: DNS Gateway; DNS Protocol Translation; dns high availability; Zscaler Trusted DNS Resolver gateway

DNS Gateway extends DNS Control with DNS high availability and protocol translation for lookups by external DNS services. An admin selects the protocols (DoH, UDP or TCP) the external service supports, and DNS filtering rules redirect traffic to the external DNS services over the specified protocol. [zia.dns-control.gateways:purpose] Translation to DoH lets an organization encrypt its users' unencrypted DNS queries and route them to any third-party DNS service using DoH, and the page lists compliance with requirements such as employing Protective DNS as a use. [zia.dns-control.gateways:doh-purpose] The DNS Protocol Translation feature of DNS Gateway is available with Advanced Firewall. [zia.dns-control.gateways:translation-licensing] DNS Insights Logs show the DNS traffic redirected to external resolvers via DNS Gateways, and the same data can be tracked in charts in the DNS Overview dashboard. [zia.dns-control.gateways:visibility]

**Protocol translation.** If an incoming DNS request uses a protocol different from the configured server-side protocol, the service translates it, sends it to the external DNS service, applies configured policies to the response and returns it over the inbound protocol. A UDP client request can go to a UDP or DoH server, a TCP request to a TCP or DoH server, and a DoH request to a UDP, TCP or DoH server; UDP to TCP and TCP to UDP are not supported. [zia.dns-control.gateways:protocol-translation]

**Health and failover.** With primary and secondary resolvers configured, the service checks the DNS server's responses to judge its health and fails over to the secondary when the primary is unavailable. The help's signals include an unreachable or timing-out server, an unresolvable server FQDN, a DoH server that gives no DNS response, SERVFAIL or other response codes, and a response timeout. [zia.dns-control.gateways:health-signals] Requests go to the primary resolver and move to the secondary when the primary returns no response to a query; once the secondary responds, later requests go to it, and if it becomes unavailable they return to the primary. Switching halts when both fail to respond, the gateway is marked down and its configured failure behavior is triggered, while periodic probe queries resume forwarding when either server recovers. [zia.dns-control.gateways:failover-sequence] The probe interval and response timeout are open [gap:zia.dns-control.gateways:probe-timing].

**Failure behavior.** The Failure Behavior of a ZIA DNS gateway is an action for when the configured DNS service is unavailable or unhealthy, with three choices. Return Error Response returns SERVFAIL to the client (with both services configured, only when both are unavailable); Allow and Ignore DNAT Rules sends the request to the originally requested resolver over the original protocol without the configured DNAT rules; Forward to Zscaler Trusted Resolver sends it to the Zscaler Trusted DNS Resolver, usable as failover for DNS over UDP, TCP and DoH. [zia.dns-control.gateways:failure-behaviors] How the three behaviors appear in dnsgw_flags is open [gap:zia.dns-control.gateways:flags-mapping]. All DNS traffic can also be resolved with the Zscaler Trusted DNS Resolver. Standard DNS (destination port 53) can use the predefined Zscaler Trusted DNS Resolver NAT Control rule, and DoH can use a DNS filtering rule associated with the default Zscaler Trusted DNS Resolver gateway. [zia.dns-control.gateways:trusted-resolver-paths] Whether the default Trusted Resolver gateway is the predefined gateway object is open [gap:zia.dns-control.gateways:predefined-gateway].

**Writing one.** An organization can have up to 254 DNS gateways. A gateway name must be unique, may contain only alphanumeric characters and cannot exceed 255 characters. [zia.dns-control.gateways:count-and-name] A gateway's protocols are chosen from DNS over HTTP (DoH), UDP and TCP. The primary server is an IP address or FQDN, the secondary is optional but recommended for failover, and the port fields for the selected protocols are optional, defaulting to 53 for UDP and TCP and 443 for DoH. [zia.dns-control.gateways:servers-ports] A DoH server's FQDN or IP address may carry a custom URL path that must end with the dns-query string (for example doh.dnsserver.com/path/to/destination/dns-query). A custom path is supported only for DoH queries, its length including dns-query cannot exceed 1,024 characters, and the DoH JSON API form (.../resolve?) is not supported. [zia.dns-control.gateways:doh-custom-path] The help disagrees on the path with TCP or UDP selected [divergence:zia.dns-control.gateways:doh-path-with-tcp-udp].

Cloud & Branch Connector has its own gateways with different limits: [Cloud & Branch Connector DNS gateways: resolvers, failure behavior, predefined gateways](kb:cloud-connector.dns.gateways). The log fields are in [DNS Gateway fields in the DNS log: slot, server protocol and flags](kb:zia.logs.dns-gateway-fields).
