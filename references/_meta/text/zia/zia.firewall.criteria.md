# Firewall Filtering rule criteria (zia.firewall.criteria)
Also called: firewall rule criteria; endpoint applications; context shield; eun template; is_eun_enabled; source countries; device trust level firewall

An unset source IP list means the rule is not restricted to a specific source address, and unset destination countries mean it is not restricted to specific destination countries. [zia.firewall.criteria:unset-unrestricted] If `sourceCountries` has no value it is ignored during policy evaluation and the rule applies to all source countries; when set, `excludeSrcCountries` decides whether the listed countries are included or excluded. [zia.firewall.criteria:source-countries-ignored] High, Medium and Low device trust evaluation applies only to Zscaler Client Connector traffic, while the Unknown level applies to all traffic; with no value the criterion is ignored. [zia.firewall.criteria:device-trust-scope] Not every criterion a firewall rule can carry is available to every tenant: users, groups, departments and network applications need Advanced Firewall. [zia.firewall.criteria:criteria-tier-gated]

Licensing for each criterion is in [Which firewall features need Advanced Firewall](kb:zia.firewall.licensing). How many of each a rule can hold is in [Firewall rule, criteria and group limits](kb:zia.firewall.limits), and the destination and port building blocks are in [IP destination groups](kb:zia.firewall.destination-groups) and [Network services (port criteria)](kb:zia.firewall.network-services). For the URL Filtering counterpart see [How URL Filtering rule criteria combine](kb:zia.url-filtering.criteria).

**Terraform-only attributes.** The Terraform resource has a boolean `exclude_context_shield_end_point`: when true, the context shield end point is excluded from the rule. [zia.firewall.criteria:context-shield-exclusion] The API capture's firewall filtering rule schema does not list `excludeContextShieldEndPoint`. [zia.firewall.criteria:context-shield-not-in-capture] The Terraform resource schema has optional `is_eun_enabled` (Web EUN enabled for the rule) and `eun_template_id` (the associated EUN template ID); the data source page documents both. [zia.firewall.criteria:eun-attributes] The upstream report of a plan diff on `eun_template_id` is open [gap:zia.firewall.criteria:eun-template-plan-diff]. The Terraform resource has `end_point_applications` (with `zapp_id`) and `end_point_application_groups` (with `group_id`) blocks, and its docs say they can only be set when `data_transfer_method` is APPLICATION_FILE_ACCESS. [zia.firewall.criteria:endpoint-app-blocks] The documented `data_transfer_method` condition cannot be met on this resource: the firewall filtering rule schema has no `data_transfer_method` attribute, and the block descriptions say 'DLP policy rule', which suggests the text was carried over from the DLP resource. [zia.firewall.criteria:endpoint-app-condition-unmeetable] Whether these criteria match anything is open [gap:zia.firewall.criteria:endpoint-app-semantics].

How the provider flattens and reads these rules, including the collection data source that drops fields, is in [What ZIA Terraform data sources return, drop, or get wrong](kb:zia.terraform.data-source-fidelity).

What to check:
1. Which criteria are actually set, since an empty one means any value.
2. Whether the tenant is licensed for the identity or application criterion the rule sets.
3. Whether an endpoint-application block does what its attribute name suggests before relying on it.
