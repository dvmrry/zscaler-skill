# SSL/TLS inspection rules a tenant profile depends on (zia.tenant-profiles.ssl-prerequisite)
Also called: tenant restriction ssl inspection; Microsoft Login Services ssl rule; Google Login Services; Webex Login Services; office 365 one click rule order; tenant profile not working ssl

A tenant profile on a CAC rule is not enough: the Help article requires an SSL/TLS Inspection rule. When a tenant profile is associated with a cloud application rule, the application must be selected as a criterion in an SSL/TLS Inspection rule. [zia.tenant-profiles.ssl-prerequisite:ssl-rule-required]

**Login service per application.**
- For Office 365, the SSL/TLS Inspection rule selects Microsoft Login Services as the cloud application and must sit at a rule order higher than the Office 365 One Click Rule. [zia.tenant-profiles.ssl-prerequisite:office365-rule] The Help article requires a higher rule order than the Office 365 One Click Rule; see [Zscaler ships predefined special rules: Zscaler-Recommended Exemptions (enabled by default), O365 tenant restriction inspection rules, an O365 One Click rule, a UCaaS One Click rule, and an Unauthorized Traffic Bypass for IoT Classifications rule. The help page calls them not editable, to be implemented as is, but they can be enabled or disabled. The IoT rule is disabled by default and cannot be deleted; for that rule only rule order, admin rank, status, label and the Evaluate/Bypass choice can change.](kb:zia.ssl-inspection.rules:predefined-rules) for the predefined rules.
- For Google Apps, the SSL/TLS Inspection rule selects Google Login Services as the cloud application. [zia.tenant-profiles.ssl-prerequisite:google-rule]
- For Webex Teams and Webex Meetings, the SSL/TLS Inspection rule selects Webex Login Services as the cloud application. [zia.tenant-profiles.ssl-prerequisite:webex-rule]

For Microsoft Version 1 there is a related authentication caveat: For the Microsoft Version 1 profile, the Help form says not to exempt the tenant domains from authentication. [zia.tenant-profiles.ssl-prerequisite:microsoft-no-auth-exemption]

The reason for the requirement is covered in [How a tenant profile is enforced: the headers ZIA inserts](kb:zia.tenant-profiles.wire-mechanic). What happens if the rule is missing or the traffic is bypassed is not documented; see gap `bypassed-traffic-behavior` there and [What stops working when traffic bypasses SSL/TLS inspection](kb:zia.ssl-inspection.bypass-impact). How the AI & ML rule page treats SSL/TLS inspection for ChatGPT profiles: [In the AI/ML rule UI, Tenant Profiles appears only when ChatGPT is the selected cloud application, and the applications selected under the tenant profiles must not be exempted from SSL/TLS Inspection.](kb:zia.cloud-app-control.ai-ml-rules:tenant-profiles-visibility). Pipeline position of inspection: [Where SSL inspection sits in ZIA web policy evaluation (the two passes)](kb:zia.ssl-inspection.pipeline).

What to check:
1. Whether the login-service application, not the content application, appears as a criterion in an inspection rule ahead of any rule that bypasses it.
