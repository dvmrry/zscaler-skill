# How the Internet & SaaS NSS support troubleshooting runbook triages a case and routes it to its pages (zia.logs.nss-runbook)
Also called: Nanolog Streaming Service (NSS) Support Troubleshooting Runbook; NSS troubleshooting runbook; NSS runbook

The runbook follows a three-stage diagnosis rule: localize where the issue occurs, isolate the affected component or service path, then diagnose the root cause from the available data. [zia.logs.nss-runbook:three-stage] The NSS server type (VM-based or Cloud NSS) is confirmed in the Admin Console either from the configured feed type under Nanolog Streaming Service or from the listed subscriptions. [zia.logs.nss-runbook:confirm-server-type] In the runbook's Cloud NSS troubleshooting section, the first step is determining whether the issue affects a newly deployed (provisioned) Cloud NSS or an already working setup. [zia.logs.nss-runbook:cloud-first-question] The VM-based NSS section of the runbook also covers Microsoft Cloud App Security (MCAS) issues. [zia.logs.nss-runbook:vm-scope-includes-mcas]

**Routing by symptom.** Unhealthy server, alerts and build upgrades: [NSS runbook: VM-based NSS Unhealthy server, alerts and build upgrade checks](kb:zia.logs.nss-runbook.vm-health). Failed connections: [NSS runbook: connectivity failures between NSS and the Central Authority, Nanolog server and SIEM](kb:zia.logs.nss-runbook.connectivity). Missing or delayed logs: [NSS runbook: missing and delayed logs on VM-based NSS, smstat counters and where the loss occurs](kb:zia.logs.nss-runbook.log-loss) and [NSS runbook: Cloud NSS new, stopped, missing and delayed logs, parsing errors and the SIEM connectivity test errors](kb:zia.logs.nss-runbook.cloud-nss). Duplicate logs and missing fields: [NSS runbook: duplicate logs, missing log fields and SIEM-side checks](kb:zia.logs.nss-runbook.log-integrity). MCAS feeds: [NSS runbook: validating an MCAS feed and its curl checks](kb:zia.logs.nss-runbook.mcas). Cloud NSS provisioning, SIEM test and parsing checks: [NSS runbook: Cloud NSS new, stopped, missing and delayed logs, parsing errors and the SIEM connectivity test errors](kb:zia.logs.nss-runbook.cloud-nss).

**Commands and special cases.** Health and network commands, packet captures and NSS log files are in [NSS runbook data collection: health and network commands, packet capture and NSS log files](kb:zia.logs.nss-runbook.diagnostics). Private and multi-cluster Nanolog, SIEM rate, explicit proxy, log replay, password reset and third-party software are in [NSS runbook corner cases: private and multi-cluster Nanolog, SIEM rate, explicit proxy, log replay, password reset and third-party software](kb:zia.logs.nss-runbook.corner-cases). Vulnerability and hardening answers are in [NSS runbook: vulnerability scan findings, ZSOS patching and hardening answers](kb:zia.logs.nss-runbook.security).

**Before escalating.** Before escalating a VM-based NSS issue to Zscaler Support the runbook asks for a detailed description of the nature and impact, scope, deployment environment details (platform OS, SIEM vendor, special deployment cases), health and connectivity screenshots and the zscaler.log and smmonitor.log files for the time of the issue. [zia.logs.nss-runbook:escalation-info]
