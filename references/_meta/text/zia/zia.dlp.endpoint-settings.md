# Endpoint Data Scan configuration: scan reporting, End User Reports, continuous and real-time classification, exemption, trusted applications, channel exceptions, activation (zia.dlp.endpoint-settings)
Also called: endpoint data scan settings; continuous classification; real-time classification; exemption duration; trusted applications; end user report settings; endpoint configuration activation

The Endpoint Data Scan and End User Report setting enables or disables sensitive data reporting to the cloud, and Report Endpoint Data Scan, when enabled, lets the data be viewed on the Endpoint Data Scan page. [zia.dlp.endpoint-settings:scan-reporting-toggle] A scan exception's Condition Type for entities is User, User Group, Department, or Endpoint, and the file Condition is Path Starts With, Path Contains, or xattr (for macOS). A directory path ending with a backslash excludes only its subdirectories, not the files in the root directory; removing the trailing backslash excludes the entire folder, its root files, and all subdirectories. [zia.dlp.endpoint-settings:scan-exceptions]

**End User Reports.** End User Reports are hidden by default. Admins can define the days (default Monday to Friday) and hours (default 09:00 to 17:00) for report display, and whether to expose Dictionaries, DLP Engines, and AI & ML Categories, all of which are disabled by default. The message shown to end users is the default one or a custom one. [zia.dlp.endpoint-settings:end-user-report-settings] Both the End User Reports article and the Endpoint Data Scan settings article give 10 as the default file count threshold for displaying the End User Report. [zia.dlp.endpoint-settings:end-user-report-threshold-default] The threshold minimum is stated two ways [divergence:zia.dlp.endpoint-settings:end-user-report-threshold-minimum].

**Classification.** Continuous Classification enhances performance by enforcing rules immediately, eliminating the need for real-time file classification; when disabled, files are classified during exfiltration based on the configuration settings. The available file sizes are 30 MB, 50 MB, and 100 MB, and files exceeding the set size are evaluated in real time. By default only SSD drives are scanned, and the page says this is available only for Windows. The service checks CPU usage every minute and resumes scanning when usage drops below the limit. Optional toggles run continuous classification on OCR and let Endpoint DLP send EDM candidate files for cloud inspection. [zia.dlp.endpoint-settings:continuous-classification] Continuous classification can be excluded for files that are created or modified by specific applications. [zia.dlp.endpoint-settings:continuous-classification-app-exceptions] The maximum file size for real-time content inspection is 30 MB, 50 MB or 100 MB, and for larger files an Endpoint DLP rule with file size criteria is configured. The real-time classification timeout is 15, 30, 60 or 120 seconds (default 30 seconds), and the Timeout Action is Allow or Block (default Allow). Real-time OCR runs for printing, clipboard, removable storage, network shares, and personal cloud storage, and is not available for application file access. [zia.dlp.endpoint-settings:real-time-classification]

**Exemption and confirmation.** The Exemption Duration for Endpoint DLP and Device Control, during which user activities are not blocked but are monitored, can be set to 5 Minutes, 10 Minutes, 15 Minutes, 60 Minutes, 2 Hours, 6 Hours, or 12 Hours. [zia.dlp.endpoint-settings:exemption-duration] How a user enters exemption mode is open [gap:zia.dlp.endpoint-settings:exemption-mode]. Two settings each select a rolling window during which subsequent confirmation prompts for the same actions are suppressed: one for Endpoint DLP channels, where incidents are still reported per file based on the user's initial response, and one for Inline Web DLP. [zia.dlp.endpoint-settings:confirmation-suppression] Enabling File Protection Option for End Users lets end users manually encrypt files from the desktop Context menu (Right-click > Zscaler > Protect); this option does not impact the Remove Protection option in the Context menu. [zia.dlp.endpoint-settings:user-file-protection]

**Logging and exclusions.** Enabling Report All DLP Engines, Dictionaries, and AI & ML Categories Detected in the File logs all DLP engine, dictionary, and AI & ML category matches found in the file, including non-contributing rule matches, in Endpoint DLP Insights Logs; disabling it logs only matches that contributed to rules. [zia.dlp.endpoint-settings:report-all-matches] Whether this setting also changes the NSS fields is open [gap:zia.dlp.endpoint-settings:insights-logs-vs-nss]. Trusted Applications are applications excluded from Endpoint DLP monitoring; the page says this can improve compatibility or performance for trusted applications such as XDR, indexers, or antivirus tools that do not pose an exfiltration risk, and reduces Endpoint DLP event volume. [zia.dlp.endpoint-settings:trusted-applications]

**Channel settings.** Use Add-ins for Supported Applications on Windows activates add-ins for Microsoft Office Word, Excel, and PowerPoint; when disabled, Endpoint DLP inspects only the text sent for printing and does not perform a complete full file inspection, so file metadata such as MIP labels and full size is unavailable. Console applications (Windows only) can be monitored for print activity by a selected option. Printers needing special handling can be given override actions: Non-Intrusive Block (recommended for printers without pause/resume support), Monitor Only (allow and monitor the print job even when the rule is Block) or Disabled (exclude the printer from all DLP inspection, rule enforcement, and reporting). [zia.dlp.endpoint-settings:printer-channel-settings] Events triggered by macOS outside bundle helper executables can be excluded from Application File Access monitoring. Monitored macOS Unsigned Applications, edited with Edit List, specifies unsigned macOS applications to monitor or block using the Application File Access rule, and unsigned macOS applications are excluded from Application File Access monitoring to reduce potential performance impact. [zia.dlp.endpoint-settings:application-file-access-settings] For Clipboard, console applications (Windows only) can be monitored by a selected option, and specified applications and entities can be excluded from being intercepted by Endpoint DLP clipboard rules. [zia.dlp.endpoint-settings:clipboard-settings] Specific devices can be excluded from removable storage rule enforcement, a setting designed to exclude local hard drives incorrectly identified as removable storage devices by the operating system. Specific applications can be excluded from Endpoint DLP removable storage rules and network share rules, and File Save Control excludes specific applications for which the file save behavior is set to Monitor Only. [zia.dlp.endpoint-settings:removable-and-network-share-settings]

**Activation.** Changes made to device control policy rules, endpoint configurations, and indexed documents must be activated to be enforced. The Activation menu shows the status for Policy, Configuration, and Indexed Documents changes as No Activations Pending (changes activated) or Pending Activation (changes saved but not activated). [zia.dlp.endpoint-settings:activation]

Rule fields are in [Endpoint DLP policy rules: channels, criteria, actions (Allow, Block, Confirm, Protect) and notifications](kb:zia.dlp.endpoint-rules), and how policy reaches endpoints is in [How Endpoint DLP reaches the endpoint: prerequisites, policy delivery, offline enforcement, scans, and what the vendor says about evaluating all rules and exception rules](kb:zia.dlp.endpoint-enforcement).

Sources disagree (name both sides):
- The End User Reports article gives the file count threshold range as 1 to 100,000; the Endpoint Data Scan settings article gives 10 to 100,000. Both give a default of 10. [divergence:zia.dlp.endpoint-settings:end-user-report-threshold-minimum]
  - zscaler-help: The threshold ranges from 1 to 100,000, with a default of 10.
  - zscaler-help: The threshold is a value between 10 and 100,000, with a default of 10.
  Impact: A threshold between 1 and 9 is allowed by one article and outside the range of the other; the pages do not say which governs.
