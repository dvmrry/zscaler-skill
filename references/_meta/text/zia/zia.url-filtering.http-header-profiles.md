# HTTP Header Control: header profiles (criteria) and header insertion profiles, their logic, limits and disallowed keys (zia.url-filtering.http-header-profiles)
Also called: HTTP Header Control; HTTP header profile; HTTP header insertion profile; request header insertion; tenant restrictions header; disallowed header keys

HTTP Header Control has two kinds of profile, both associated with URL Filtering rules. To enable the HTTP Header Control feature, contact Zscaler Support, as both the About HTTP Header Profile and the About HTTP Header Insertion Profile pages say. [zia.url-filtering.http-header-profiles:enablement]

**Header profiles (criteria).** The HTTP header profile lets an admin create criteria for various HTTP request headers, and consists of adding HTTP header profiles and associating them to a URL Filtering policy rule. The About page lists as benefits creating policies based on client request headers and modifying request headers in the egress traffic for tenant control. The list's Criteria column shows the criteria (Origin, Referer and User Agent), and the profile name is displayed when configuring the URL Filtering policy rules. [zia.url-filtering.http-header-profiles:header-profile-what] Within a header profile the criteria combine as Origin AND Referer AND User Agent: if multiple HTTP header criteria are added, OR is applied between the same header types and AND between different header types. The page's example evaluates as [Origin 1 OR Origin 2] AND Referer AND [User Agent 1 OR User Agent 2]. [zia.url-filtering.http-header-profiles:criteria-logic] The User Agent header criterion controls access to browsers and has a Browser (a custom browser can be entered by selecting Other), an Operator (>, <, =, ≠, or Any, where Any implies all the versions for the browser) and a Version, which does not appear when the Operator is Any. [zia.url-filtering.http-header-profiles:user-agent-criterion] The Browser choices are not listed [gap:zia.url-filtering.http-header-profiles:user-agent-browser-choices]. The Origin header criterion adds the cloud applications or URL categories from which the request originates, and the Referer criterion the cloud applications or URL categories that refer to other applications (the page's example is allowing www.youtube.com when the referer is Google Classroom); Cloud Applications selects cloud applications or cloud application categories. [zia.url-filtering.http-header-profiles:origin-referer-criteria] A header profile takes up to 16 HTTP header criteria and a description of at most 10,240 characters; the Ranges & Limitations page lists 16 HTTP headers per HTTP Header Profile and 16 HTTP header profiles per rule. [zia.url-filtering.http-header-profiles:header-profile-limits]

**Header insertion profiles.** The HTTP header insertion profile lets an admin add custom HTTP request headers and modify existing ones, and consists of adding HTTP header insertion profiles and associating them to a URL Filtering policy rule. The About page lists adding custom request headers to egressing traffic with the allow action configured, and the list's HTTP Headers column shows the headers as key-value pairs. [zia.url-filtering.http-header-profiles:insertion-profile-what] In a header insertion profile each header key is limited to 128 characters and only request headers are to be entered, each value is limited to 1,024 characters, up to 16 HTTP headers can be added, and the description cannot exceed 10,240 characters. The Ranges & Limitations page lists 16 HTTP headers per insertion profile, 16 insertion profiles per rule, and the same 128 and 1,024 character limits. [zia.url-filtering.http-header-profiles:insertion-key-value-limits] Sixteen HTTP header keys are not allowed in a header insertion profile: content-security-policy, etag, expires, last-modified, location, proxy-authenticate, public-key-pins, retry-after, server, set-cookie, strict-transport-security, timing-allow-origin, vary, www-authenticate, x-content-type-options and x-frame-options. [zia.url-filtering.http-header-profiles:insertion-disallowed-keys] Whether this object is the registered action profile type is open [gap:zia.url-filtering.http-header-profiles:action-profile-identity].

Where the profiles enter a rule's criteria and actions is in [How URL Filtering rule criteria combine](kb:zia.url-filtering.criteria) and [URL Filtering actions and their prerequisites](kb:zia.url-filtering.actions); the provider's fields are in [Terraform user agent validation and isolation on URL Filtering rules](kb:zia.terraform.url-filtering-rules). How many profiles an organization can hold, whether other rule types can use them and what modifying request headers means for a criteria-only profile are open [gap:zia.url-filtering.http-header-profiles:profile-counts] [gap:zia.url-filtering.http-header-profiles:other-rule-types] [gap:zia.url-filtering.http-header-profiles:modify-meaning]. Whether inserting into HTTPS needs the request decrypted is open [gap:zia.url-filtering.http-header-profiles:insertion-decryption].

What to check:
1. Whether a header insertion profile uses a key from the disallowed list, since those keys are not allowed.
2. Whether a header profile has more than 16 criteria or an insertion profile more than 16 headers.
