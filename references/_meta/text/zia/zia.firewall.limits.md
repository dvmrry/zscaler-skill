# Firewall rule, criteria and group limits (zia.firewall.limits)
Also called: firewall rule limit; 10 rules standard firewall; 1021 rules; users per rule 32; fqdn per group 100; custom ips signature limit; terraform firewall maxitems

Capacity figures for the firewall come from the product's limits table, and the Terraform provider applies different numbers of its own [divergence:zia.firewall.limits:time-window-cap].

**Rule counts.** Firewall Filtering is capped at 1,021 rules with Advanced Firewall and 10 on the standard tier. The row is labeled 'including DNAT' and notes up to 4,000 with strict criteria. [zia.firewall.limits:filtering-rule-cap] The About Firewall Filtering page paginates Firewall Filtering policy rules at up to 500 per page, and for organizations that have subscribed to the enhanced limit of 4,000 Firewall Filtering rules, at up to 100 per page. [zia.firewall.limits:filtering-page-size] For organizations subscribed to the enhanced Firewall Filtering limit, a generic text search is replaced by category-based filtering that requires the admin to select a category and searches across all pages in it. The enhanced limit requires an audit of each proposed customer tenant seeking to upgrade, and the Zscaler Account team gives the qualified use cases. [zia.firewall.limits:enhanced-limit-ui-and-audit] What counts as strict criteria is open [gap:zia.firewall.limits:strict-criteria-4000]. NAT Control is capped at 1,023 rules per organization, and IPS Control policy rules fall under the "All Other Policy Rules" limit of 1,024 rules (listed with DLP and Inline Web DLP), which the Zscaler Account team may raise to 2,048. [zia.firewall.limits:nat-and-ips-rule-caps] How NAT rules count against the Filtering row is open [How DNAT rules count against the rule caps](kb:zia.firewall.nat:dnat-count-bucket). Other policies' caps are in [ZIA URL Filtering](kb:zia.url-filtering), [ZIA SSL/TLS inspection](kb:zia.ssl-inspection) and [ZIA DNS Control](kb:zia.dns-control).

**Per-rule criteria.** The help's limits table gives, for all policy rule types, per rule: up to 32 users, 32 groups, 32 departments, 32 locations, 32 location groups, 8 times, 64 devices, 8 device groups and 8 workload groups. [zia.firewall.limits:per-rule-identity-caps] Per rule: up to 1,000 source IP or destination groups, 1,000 service groups or application groups, 8,000 source IP entries, 8,000 destination IP entries and FQDNs, and 5,000 destination FQDNs. [zia.firewall.limits:per-rule-address-caps]

**Groups and signatures.** An organization can have up to 4,000 source IP address groups and 4,000 destination groups. [zia.firewall.limits:group-count-caps] The same page also lists the two kinds together at that number [divergence:zia.firewall.limits:group-count-scope]. A group holds up to 8,000 FQDN or IP address entries, and the total across groups must stay within the overall base IP limit. Source and destination groups together hold up to 16K IP address entries per organization, which Zscaler Support may raise to 64K and which requires Advanced Firewall. [zia.firewall.limits:group-entry-caps] Per organization, destination groups can hold up to 5,000 FQDNs, or 16,000 with Advanced Firewall. [zia.firewall.limits:dest-group-org-caps] The per-group FQDN limit, 100 by default, is in [IP destination groups](kb:zia.firewall.destination-groups), and the service count in [Network services (port criteria)](kb:zia.firewall.network-services). An organization can have up to 500 custom IPS signature rules and 64 custom IPS threat categories. [zia.firewall.limits:custom-ips-caps] The caps on network service groups, network application groups, custom application service groups, DNS gateways and ECS prefixes are in [An organization can create up to 121 network service groups, each holding up to 8,000 network services; the add form lets any number of custom and predefined services be selected, and a group's description cannot exceed 10,240 characters.](kb:zia.firewall.network-services:service-group-sizes), [A network application group combines predefined network applications into logical groups reusable across Firewall Filtering rules to allow or block traffic. An organization can create up to 126 groups, each holding up to 8,000 network applications, and a group's description cannot exceed 10,240 characters.](kb:zia.firewall.network-applications:group-object), [An organization can configure up to 128 custom application service groups, each with at most 32 IP addresses or wildcard FQDNs, and 4,096 in total across the 128 groups.](kb:zia.firewall.application-services:custom-caps), [An organization can have up to 254 DNS gateways. A gateway name must be unique, may contain only alphanumeric characters and cannot exceed 255 characters.](kb:zia.dns-control.gateways:count-and-name) and [An organization can have at most 128 ECS prefixes, including the default prefix.](kb:zia.dns-control.ecs:prefix-count).

**What the provider enforces.** The Terraform provider caps `time_windows` at 2, `labels` at 1, `nw_services` at 1,024 and `workload_groups` at 255 on a firewall filtering rule, and declares no cap on users, groups, departments, locations, location groups, source and destination IP groups, network service groups or application groups. [zia.firewall.limits:provider-caps] The places it differs from the product table are [divergence:zia.firewall.limits:time-window-cap] and [divergence:zia.firewall.limits:workload-group-cap]. The other provider behavior is in [ZIA Terraform resource fields that are not sent, not read back, or sent wrongly](kb:zia.terraform.field-fidelity).

What to check:
1. Which tier the tenant is on, since the standard tier has a 10-rule cap on Firewall Filtering.
2. Which cap the failing criterion hits, and whether that number comes from the product table or from the provider schema.

Sources disagree (name both sides):
- The product allows 8 times per rule; the Terraform provider schema allows 2 on a firewall filtering rule. [divergence:zia.firewall.limits:time-window-cap]
  - zscaler-help: Up to 8 times per rule.
  - tf-zia: At most 2 time_windows.
  Impact: A rule with 3 to 8 time intervals is valid in the product but cannot be expressed through this resource.
- The product allows 8 workload groups per rule; the Terraform provider schema allows 255. [divergence:zia.firewall.limits:workload-group-cap]
  - zscaler-help: Up to 8 workload groups per rule.
  - tf-zia: Schema allows 255.
  Impact: The provider will not reject a plan with more than 8 workload groups, so the failure, if any, would come from the API; no source shows the response.
- The limits page's Firewall section gives 4,000 source IP address groups and 4,000 destination groups; its Other section gives 4,000 groups for source IP and destination groups as one row. [divergence:zia.firewall.limits:group-count-scope]
  - zscaler-help: Source IP address groups and destination groups are each listed at 4,000 groups.
  - zscaler-help: Source IP and destination groups are listed together at 4,000 groups.
  Impact: Whether an organization can have 4,000 groups of each kind or 4,000 in all is not settled by the page.
