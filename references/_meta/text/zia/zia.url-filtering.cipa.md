# The CIPA Compliance Rule and the Enable CIPA Compliance option (zia.url-filtering.cipa)
Also called: CIPA; CIPA Compliance Rule; Enable CIPA Compliance; CIPA Compliance Report

Zscaler provides a predefined URL filtering rule (CIPA Compliance Rule) and a control (Enable CIPA Compliance) to enable the predefined rule, and a CIPA Compliance Report with insights into the traffic and users blocked from accessing the prohibited content based on the rule. The rule is activated by enabling the Enable CIPA Compliance option from Data Security > Inline CASB > Advanced Policy Settings. [zia.url-filtering.cipa:components]

**Turning it on.** The page says the Enable CIPA Compliance option cannot be enabled when: the number of URL filtering policy rules exceeds the limit; a rule with rule order 1 exists with a higher admin rank; the CIPA Compliance Rule is activated under Internet Access > Policy > URL Filtering; and the Advanced URL Filtering Options Enable Suspicious New Domains Lookup, Enable AI/ML-based Content Categorization, Enable Embedded Sites Categorization and Enforce SafeSearch are enabled. After the last group the page says "You cannot disable the following options". [zia.url-filtering.cipa:enable-conditions] When the CIPA Compliance Rule is activated for the first time, it takes the highest precedence (rule order 1) by default and the rule order is automatically incremented by 1 for the other rules. If the logged-in user does not have an admin rank, the rule is created with an admin rank 7. No custom URL filtering rule can be created with the name CIPA Compliance Rule. [zia.url-filtering.cipa:first-activation] The meaning of the rule-count limit is open [gap:zia.url-filtering.cipa:rule-count-limit].

**Turning it off.** When Enable CIPA Compliance is disabled, the CIPA Compliance Rule gets disabled under Internet Access > Policy > URL Filtering but the disabled rule can still be viewed, and the Advanced URL Filtering Options are set to the recommended policy settings. The rule can be viewed once the Enable CIPA Compliance option has been selected at least once, and it can be deleted only when the Enable CIPA Compliance toggle is disabled. [zia.url-filtering.cipa:disable-behavior] The disabling warning text is open [gap:zia.url-filtering.cipa:disable-warning-text].

**What the rule matches.** The rule's URL categories are all the predefined categories under the URL super category Legal Liabilities, with predefined URLs and keywords, from Adult Sex Education to Weapons/Bombs in the page's list; the custom categories under Legal Liabilities are excluded. URL categories cannot be added to or deleted from the predefined list, but custom URLs and keywords (CIPA related) can be added or deleted in any predefined category under Legal Liabilities. [zia.url-filtering.cipa:rule-categories] The rule's request methods are listed as OPTIONS, GET, HEAD, POST, PUT, DELETE, TRACE, CONNECT, OTHER and ALL. The page marks these attributes Non-editable: applicable to all users, groups, departments, locations and location groups in the organization, applicable at any time and to all protocols, access denied to all the sites that fall under the specified URL categories, no exception allowed for the blocked sites, and no redirect URL configured. [zia.url-filtering.cipa:fixed-attributes]

**Reporting.** The CIPA Compliance Report is viewed on the Standard Reports tab, in the Liability Exposure section, and can be scheduled by selecting CIPA Compliance Report as the Report in the Add Scheduled Report window. [zia.url-filtering.cipa:report-location] How the option appears in the API is open [gap:zia.url-filtering.cipa:api-representation].
