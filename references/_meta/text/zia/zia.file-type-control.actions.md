# File Type Control actions, direction and defaults (zia.file-type-control.actions)
Also called: file type control action; caution block allow file; upload download file type; file type default allow; file type control notification; file type control pcap

By default the service allows upload and download of all file types. File Type Control restricts that; Zscaler also publishes a recommended policy. A newly added rule's status is Disabled until it is enabled. [zia.file-type-control.actions:default-allow-all] Disabled rules can hold a rule order; evaluation skips them and moves to the next rule. A rule can carry an expiration, after which it keeps its place in the order but is not evaluated. [zia.file-type-control.actions:disabled-rules-hold-order]

**When a rule matches.** A rule's action is Allow, Caution or Block. Caution displays a warning before the service lets the user perform the action. A block displays a notification whose content is set on the End User Notification page. [zia.file-type-control.actions:actions] A browser notification template can be selected for the rule; the field appears when the action is Caution or Block. [zia.file-type-control.actions:browser-notification-template] Each rule's action applies to uploads, downloads or both. [zia.file-type-control.actions:operation] So a file type can be allowed in one direction and blocked in the other. [zia.file-type-control.actions:operation-split-directions] When Traffic Capture is enabled, the Capture option appears for rules whose action is Block, and captured traffic is stored as PCAP files. [zia.file-type-control.actions:capture-on-block]

Caution for traffic with no user to acknowledge is open [gap:zia.file-type-control.actions:caution-without-a-user], and the fate of unscannable or unknown files that no rule names is open [gap:zia.file-type-control.actions:unscannable-and-unknown-default].

**Recommended policy.** Zscaler recommends the Caution action for Executable downloads and the Block action for Executable uploads, each for websites under any URL category. With Advanced Sandbox, the Sandbox policy can be configured to quarantine executable downloads for the first-time action, and depending on corporate policy additional rules can block downloads from URL categories such as Adult Material, Drugs, Gambling, Illegal or Questionable, Militancy/Hate and Extremism, Tasteless, Violence and Weapons/Bombs. [zia.file-type-control.actions:recommended-policy] The recommended-policy page's example Rule #1 has Rule Order 1, File Types Executable, Action Caution and Upload/Download set to Download; its example Rule #2 has Rule Order 2, File Types set to all file types, Action Allow and Upload/Download set to Download. This describes the two examples only. [zia.file-type-control.actions:recommended-example-rules] The page's text and its example rules differ on executable uploads [divergence:zia.file-type-control.actions:recommended-uploads-vs-examples].

FTP Control has no action selector of its own; see [FTP Control settings and API object](kb:zia.ftp-control.settings). A File Type Control rule's Protocols criterion includes FTP over HTTP (files from FTP over HTTP websites) and Native FTP (files from native FTP servers); both require a Firewall subscription. [zia.file-type-control.actions:ftp-via-protocol-criterion] See [File Type Control API shape: rules, categories and custom types](kb:zia.file-type-control.api-shape) for the wire values. How the criteria decide a match is in [File Type Control rule criteria](kb:zia.file-type-control.criteria), and where File Type Control sits relative to DLP and scanning is in [Where File Type Control sits in the inspection order](kb:zia.file-type-control.pipeline).
