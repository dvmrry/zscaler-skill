# IP destination groups (zia.firewall.destination-groups)
Also called: destination group; ip destination group; DSTN_IP; DSTN_FQDN; DSTN_DOMAIN; DSTN_OTHER; excludeType; override append ips

Firewall Filtering rules point at destination groups for their destination criterion. A destination group's type is one of DSTN_IP, DSTN_FQDN, DSTN_DOMAIN or DSTN_OTHER. The Python SDK rejects any other value for the list filter and the MCP tool enforces the same four values on input. [zia.firewall.destination-groups:type-values] `addresses` may hold destination IP addresses, FQDNs or wildcard FQDNs. [zia.firewall.destination-groups:addresses-forms]

**Which fields go with which type.** By the MCP field descriptions and the SDK examples, `addresses` is required for DSTN_IP and DSTN_FQDN, while `countries` and `ip_categories` are used with DSTN_OTHER. [zia.firewall.destination-groups:field-pairing] The MCP input model checks that `type` is one of the four values but does not cross-check it against `addresses`, `countries` or `ip_categories`, so a DSTN_IP group with no addresses is not rejected by that client-side model. [zia.firewall.destination-groups:pairing-not-enforced] `ip_categories` on a destination group accepts only custom categories (the SDK example is CUSTOM_01). [zia.firewall.destination-groups:ip-categories-custom-only] `isNonEditable` is applicable only to predefined groups, which cannot be modified. [zia.firewall.destination-groups:non-editable-predefined] What a DSTN_DOMAIN group contains is open [gap:zia.firewall.destination-groups:domain-type-fields].

**The list filter and the update call.** The SDK documents the list filter `excludeType` as excluding all groups that match the given type; the Python parameter name and the Go name carry the same query key. [zia.firewall.destination-groups:exclude-type-excludes] The API capture words the same parameter differently [divergence:zia.firewall.destination-groups:exclude-type-wording]. On update, the `override` query parameter controls how IPs are merged: false appends the supplied IPs to the existing set, otherwise the existing IPs are overridden, and the default is true. The Go client sends `override` only when its pointer is set. [zia.firewall.destination-groups:override-appends]

**Size.** Destination groups hold up to 8,000 IP entries and FQDNs per group, but only 100 FQDNs per group (8,000 with Advanced Firewall). [zia.firewall.destination-groups:fqdn-per-group-caps] What happens past the FQDN cap is open [gap:zia.firewall.destination-groups:fqdn-cap-overflow]. Other caps are in [Firewall rule, criteria and group limits](kb:zia.firewall.limits). Destination groups are served at `/ipDestinationGroups` (list, create) and `/ipDestinationGroups/{id}` (get, update, delete) in the API capture and both SDKs. [zia.firewall.destination-groups:endpoint]

**What the help says a group holds.** Destination IP groups can be applied to policies such as Firewall Filtering, NAT Control, DNS Control, IPS Control and Forwarding Control, and combine destination IP addresses and FQDNs, destination countries and URL categories into groups for security policies. [zia.firewall.destination-groups:dg-purpose] Destination IPv4 and IPv6 addresses are managed in separate groups. Two predefined groups, All IPv4 and All IPv6, contain all addresses of their type; custom IPv6 groups are not currently supported, and only the predefined All IPv6 group is available. [zia.firewall.destination-groups:dg-ip-families] In SSL/TLS Inspection and DNS Control policies, IP-based destination groups used in rule criteria are ignored during policy evaluation if an SNI value is present in HTTPS requests. [zia.firewall.destination-groups:dg-sni-ignored] A custom destination group can be created by specifying IPv4 addresses (an individual address or an address range), FQDNs, wildcard FQDNs, server-location countries or custom URL categories. The console offers FQDN for applications with multiple or frequently changing IPv4 addresses, Wildcard FQDN to extend the policy to subdomains of the stated URL, and Other when no IPv4 addresses, FQDNs or domains are associated. [zia.firewall.destination-groups:dg-console-types] A destination group can identify destinations by the server's location (Any includes all countries) and by the domain's URL category, using any number of custom URL categories; multiple countries or categories, or both, can be selected. [zia.firewall.destination-groups:dg-other-type] A destination group name may contain only alphanumeric characters, underscores, hyphens and periods, and its description cannot exceed 10,240 characters. [zia.firewall.destination-groups:dg-name-description]

**Wildcard FQDNs.** In the help's example the wildcard FQDN *.safemarch.com matches atlanta.safemarch.com, serv3.serv2.serv1.atlanta.safemarch.com/company/webinars, safemarch.com and safemarch.com/company/webinars. [zia.firewall.destination-groups:wildcard-match] The wildcard character preceding the leading period is optional (*.safemarch.com and .safemarch.com are equivalent), and a wildcard is allowed only as the leftmost label, only once per entry, and only as a prefix search (sub1.*.safemarch.com, *.*.safemarch.com and partial matches such as .safe*.com are not allowed). [zia.firewall.destination-groups:wildcard-syntax] To evaluate wildcard FQDNs against non-web traffic, Zscaler requires the IP address the FQDN resolves to. The page also says to forward all DNS traffic to the Zscaler service if wildcard FQDNs are configured in policies, and that a subscription or Internet & SaaS (ZIA) edition with DNS Control is required, which it says is included in Advanced Firewall and DNS Control subscriptions and Internet & SaaS editions. Wildcard FQDN matching against web traffic (HTTP and TLS/SNI) can function without meeting these conditions. [zia.firewall.destination-groups:wildcard-nonweb]

What to check:
1. Whether the group's type matches the fields it sets, following the pairing rules.
2. Whether a rule still references the group before deleting it, since the delete helper sweeps firewall filtering rules only.
3. Whether the override flag is set deliberately on an update that edits addresses, since the default replaces the existing set.

- The API capture and the SDKs describe the `excludeType` list filter differently. [divergence:zia.firewall.destination-groups:exclude-type-wording]
  - api-specs: Filter based on the IP destination group's type.
  - sdk-python: Exclude all groups that match the specified type.
  Impact: Read literally, the capture suggests an include filter; passing excludeType=DSTN_IP expecting only IP groups would return everything except them.
