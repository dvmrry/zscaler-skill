# Runbook: unable to access a site or blocked for browsing a category (zia.troubleshooting-runbook.access-failures)
Also called: Not allowed to browse this category; Unable to access specific websites or applications

**Not allowed to browse this category.** To list transactions blocked for category browsing, set the web log filter Blocked Policy Type to URL Filtering; the Blocked Policy Name column gives the rule whose URL Categories should be noted. [zia.troubleshooting-runbook.access-failures:browse-category-filter] When the Protocol column shows SSL the URL column holds only the FQDN, so a URL filtering policy based on the URL path or keywords requires SSL Inspection to be configured for that traffic. [zia.troubleshooting-runbook.access-failures:browse-ssl-fqdn-only] If no URL Filtering rule should have allowed the transaction, the page suggests creating a rule just above the block rule for one test user and adding the desired criteria if it grants access. [zia.troubleshooting-runbook.access-failures:browse-test-user-rule]

**Source IP allowlists.** If a site is inaccessible from a test system that bypasses Zscaler, the runbook says it uses source-IP access control; standard web servers check the XFF header against their allowlist if present and otherwise the IP header source. [zia.troubleshooting-runbook.access-failures:source-ip-allowlist] The page says that with SSL inspection enabled for a website the Public Service Edge always inserts the XFF header with the client's external source IP, with limits: it does not help when SSL inspection cannot be enabled, or when the server does not use XFF for allowlisting. [zia.troubleshooting-runbook.access-failures:xff-always-inserted] The XFF insertion exceptions and the test for a site that works only with inspection off are in [Runbook diagnostics: HAR analysis, QUIC detection, XFF compatibility and SSL configuration checks](kb:zia.troubleshooting-runbook.diagnostics). Other options listed are the Dedicated IP feature via the Zscaler account team, sending the traffic via a Private or Virtual Service Edge, or asking the site owner to allowlist the Service Edge subnets published for the cloud on the Config Portal. [zia.troubleshooting-runbook.access-failures:source-ip-alternatives]

**DNS, IPv6 and protocol.** For DNS, check that Client Connector's app profile DNS inclusion and exclusion criteria are correct, and look in DNS Insights for failures in the DNS Error Code column such as Server Failure or a timeout, with the Server IP column naming the DNS server. [zia.troubleshooting-runbook.access-failures:dns-checks] If client IPs are IPv6, the page says IPv6 must be enabled in the tenant and traffic correctly forwarded; IPv6 is a common cause when a site works for some users but not others with the same access level. [zia.troubleshooting-runbook.access-failures:ipv6-cause] For H3/QUIC this page says Zscaler Advanced Firewall processes it as general UDP traffic without enforcing any policy; for H2 it says Enable HTTP/2 must be selected in the relevant SSL Inspection Policy. [zia.troubleshooting-runbook.access-failures:http-protocol-quic-h2] Whether QUIC gets any policy is in dispute [divergence:zia.troubleshooting-runbook.access-failures:quic-policy-enforcement]; see [QUIC and HTTP/3 behind ZIA: where it escapes and how to block it](kb:zia.saas-apps.quic-conferencing) and [Recommended Firewall Filtering, DNS Control and IPS Control rules](kb:zia.firewall.best-practices).

**Scope and browser.** To tell whether the problem is global, the page compares user, group, location and policy action in Web Insights, for example filtering on Allowed; if only user-, group- or department-based rules fail it points to authentication settings, and it suggests testing an authentication exemption. [zia.troubleshooting-runbook.access-failures:scope-comparison] For a site that works in another browser, the page says to confirm the browser version is allowed in the Browser Control policy under Secure Browsing. [zia.troubleshooting-runbook.access-failures:browser-control]

Sources disagree (name both sides):
- The access runbook says Zscaler Advanced Firewall does not enforce any policy on H3/QUIC traffic, while the QUIC conferencing and firewall best-practices pages block QUIC with a Firewall Filtering rule. [divergence:zia.troubleshooting-runbook.access-failures:quic-policy-enforcement]
  - zscaler-help: Zscaler Advanced Firewall processes H3/QUIC as general UDP traffic and does not enforce any policy on it.
  - zscaler-help: A Firewall rule using the QUIC network service criteria blocks QUIC.
  Impact: Whether a QUIC flow is policy-enforced depends on which page is read; the pages do not say if the runbook means the web policies (URL Filtering, SSL Inspection) rather than Firewall Filtering rules on the QUIC network service.
