# Bandwidth Control rules: terms, order and rank (zia.bandwidth-control.rules)
Also called: bandwidth control rule order; bandwidth rule not firing; bandwidth rule criteria; bandwidth control admin rank; disabled bandwidth rule

A rule ties bandwidth classes to enforcement terms. Each rule defines a maximum and minimum bandwidth for the bandwidth classes in the rule, along with other parameters such as location and time of day. [zia.bandwidth-control.rules:rule-terms] The terms themselves, and how minimum and maximum behave, are in [How Bandwidth Control allocates bandwidth: minimum, maximum, contention](kb:zia.bandwidth-control.allocation).

**Does the rule apply to this traffic?** Rule conditions are grouped: Locations OR Location Groups, AND Time, AND (Bandwidth Classes AND Protocols). The relationship between the categories is AND. [zia.bandwidth-control.rules:criteria-expression] The Adding Rules article joins the categories with AND and groups the conditions as Where: [Locations AND Location Groups], When: Time, and What: [Protocols AND Bandwidth Classes]. [zia.bandwidth-control.rules:criteria-expression-adding-page] The two pages group Locations and Location Groups differently [divergence:zia.bandwidth-control.rules:locations-location-groups-operator]. When a Bandwidth Control rule lists locations or a time window, it does not apply to traffic from another location or outside that window, however well the traffic's class and protocol match. [zia.bandwidth-control.rules:non-matching-location-or-time-skips-rule] Location scope is covered in [Which traffic Bandwidth Control covers: locations and limits](kb:zia.bandwidth-control.location-scope).

**Writing a rule.** A rule takes Any or up to 32 locations, which must have Bandwidth Control enabled with download and upload limits; the article says to contact Zscaler Support to increase the default limit for Locations. Location Groups take Any or up to 32 and, if none is selected, the field is Any by default and the criterion is ignored during policy evaluation. Time takes up to two time intervals and is Always by default. Any number of bandwidth classes can be selected once URLs or cloud applications have been added to predefined or custom bandwidth classes. [zia.bandwidth-control.rules:scope-limits] The rule name is system-generated and can be edited, and cannot exceed 63 characters. The description cannot exceed 10,240 characters. A rule label is optional. [zia.bandwidth-control.rules:name-and-description-length] The location limit differs between sources: [zia.bandwidth-control.api-surface:locations-per-rule](kb:zia.bandwidth-control.api-surface:locations-per-rule).

**Order.** Bandwidth Control rules are evaluated in ascending numerical rule order, and the default rule is evaluated last. [zia.bandwidth-control.rules:ascending-order] Bandwidth is allocated by rule order, so classes that need priority, such as business-critical applications, belong near the top of the rules. [zia.bandwidth-control.rules:order-is-priority] Whether the order matches the first-match-wins model of [URL Filtering rule order and first match](kb:zia.url-filtering.rule-order) is open [gap:zia.bandwidth-control.rules:multi-rule-class]. The default rule's fixed last position is in [The default rule and unreferenced classes](kb:zia.bandwidth-control.default-rule).

**Disabled rules and rank.** A disabled Bandwidth Control rule is not enforced but keeps its place in the rule order, and the service skips it and moves to the next rule. [zia.bandwidth-control.rules:disabled-holds-slot] A new rule's status is Disabled by default and the rule must be enabled to be enforced on traffic. Disabled rules can be assigned a rule order, and during evaluation the service skips them and moves to the successive ones. [zia.bandwidth-control.rules:new-rule-disabled] With admin ranking enabled in Advanced Settings the rule list shows an Admin Rank column, and the admin rank limits the rule order values an administrator can select. [zia.bandwidth-control.rules:admin-rank] Admin Rank is 0 to 7, with 0 the highest, and the option appears if Admin Ranking is enabled on the Advanced Settings page. An admin cannot select a rank higher than their own, and a rule with a higher admin rank always precedes a rule with a lower one. [zia.bandwidth-control.rules:admin-rank-range] Provider reorder and rank behavior for bandwidth rules is in [The ZIA provider's reorder registry: keys, locks and lifecycle across rule resources](kb:zia.terraform.rule-order.registry).

What to check:
1. Whether the rule is enabled, since a disabled rule keeps its place in the order but is not enforced.
2. Whether the rule's location and time criteria match the traffic, stating that the pages differ on how Locations and Location Groups combine rather than choosing one.
3. Whether an earlier rule holds the same class, since bandwidth is allocated by rule order.
4. Whether the location enforces Bandwidth Control and has limits, since rules do not shape its traffic otherwise.
