# NSS runbook: Cloud NSS new, stopped, missing and delayed logs, parsing errors and the SIEM connectivity test errors (zia.logs.nss-runbook.cloud-nss)
Also called: Cloud NSS troubleshooting; Zscaler Authentication Bridge; SIEM Connectivity Test

**New and stopped setups.** For a newly deployed or migrated Cloud NSS, the runbook checks the subscriptions in the Admin Console, notes an instance can be provisioned but not fully enabled on the backend, and says to follow the working-setup scope if it is enabled but shows unhealthy. [zia.logs.nss-runbook.cloud-nss:new-instance-subscriptions] For a setup that recently stopped working, the runbook runs the Admin Console SIEM connectivity test; if the console shows healthy but the SIEM gets no logs it continues with Logs are Missing. [zia.logs.nss-runbook.cloud-nss:recently-stopped]

**Missing and delayed logs.** Cloud NSS missing-logs prechecks: instance and SIEM in the same Geo, Cloud NSS IP ranges allowlisted by region, at least one active feed, private Nanolog reachable, Max Batch Size sized per the deployment guide, and any SIEM rate calculated from log volume and EPS. [zia.logs.nss-runbook.cloud-nss:missing-logs-prechecks] In its Logs are Delayed steps the runbook checks Max Batch Size against its 16 KB default and recommends 512 KB for Splunk, Sumologic and other SIEM types, 8 MB for S3, and 1 MB for DNS, Tunnel and other log types such as SaaS Security. [zia.logs.nss-runbook.cloud-nss:logs-delayed-batch-size] In its Logs are Delayed steps the runbook says to perform all the prechecks described in the previous section, checks that SIEM Rate is an optimal value for the log volume and SIEM EPS, and has Zscaler Support take packet captures. [zia.logs.nss-runbook.cloud-nss:logs-delayed-siem-rate]

**Parsing errors.** A connectivity test returning a 400 response code is the indicator of SIEM parsing errors. [zia.logs.nss-runbook.cloud-nss:parsing-400] For SIEM parsing issues the runbook checks SIEM event logs, that correlation rules are enabled, the Feed Escape Character, that the feed format uses hex-encoded fields for string fields like url and useragent, and says JSON Array Notation can be enabled for troubleshooting if it was disabled. [zia.logs.nss-runbook.cloud-nss:parsing-checks] JSON Array Notation lets the NSS stream a batch of logs as a JSON array: individual logs ordered in a list, separated by commas and surrounded by square brackets. [zia.logs.nss-runbook.cloud-nss:json-array-notation] For a JSON-format feed the runbook says the escape character should always be ,/" and describes it as comma, backslash, double quote. [zia.logs.nss-runbook.cloud-nss:json-escape-character] [divergence:zia.logs.nss-runbook.cloud-nss:json-escape-notation]

**SIEM connectivity test.** The Admin Console SIEM connectivity test request flows from CA to the NSS to the Zscaler Authentication Bridge (ZAB) to the SIEM, with ZAB doing a sample log upload and passing back the response. [zia.logs.nss-runbook.cloud-nss:siem-test-flow] A successful SIEM connectivity test returns a 200-series response code, and any other code is the actual error code returned by the SIEM, indicating an issue between ZAB and the SIEM. [zia.logs.nss-runbook.cloud-nss:siem-test-response] [divergence:zia.logs.nss-runbook.cloud-nss:non-2xx-meaning] For Cloud NSS connectivity-test errors, reachability errors (SIEM Host not Reachable, SIEM Host Port not Reachable) mean confirming the SIEM listens on the configured IP and port, and generic errors (SIEM Host down, SIEM Host unresponsive) mean validating the SIEM topology and allowlisting the Cloud NSS IPs if needed. [zia.logs.nss-runbook.cloud-nss:error-routing-reachability] Errors about the SIEM response (Error in SIEM authentication, Invalid SIEM redirect response) go to the SIEM team, SSL certs missing for SIEM Host means contacting Zscaler to add certs, Invalid SIEM URL format means validating the feed's SIEM configuration, and Zscaler internal errors mean a support ticket. [zia.logs.nss-runbook.cloud-nss:error-routing-response]

**Exception table.** Some SIEM test errors are exceptions, not SIEM responses: NoRouteToHostException is SIEM Host not Reachable, PortUnreachableException is SIEM Host Port not Reachable, UnknownHostException is Invalid SIEM Hostname, NoHttpResponseException is SIEM Host busy, ConnectTimeout and HttpHostConnectException are SIEM Host down, SocketTimeoutException is SIEM Host unresponsive. [zia.logs.nss-runbook.cloud-nss:siem-test-exceptions-network] In the SIEM test, SSLHandshakeException shows SSL certs missing for SIEM Host, SSLException shows SSL Error, ProtocolException HTTP shows Error with SIEM Host, MalformedChallengeException shows Error in SIEM authentication, RedirectException shows Invalid SIEM redirect response, URIException shows Invalid SIEM URL format, RuntimeException shows Error parsing SIEM URL. [zia.logs.nss-runbook.cloud-nss:siem-test-exceptions-protocol] In the SIEM test, UnknownException shows Zscaler Internal Error 0, BindException 1, ConnectionPoolTimeoutException 2, SocketExceptions 3 and IOExceptions 4. [zia.logs.nss-runbook.cloud-nss:siem-test-exceptions-internal]

Sources disagree (name both sides):
- The runbook writes the JSON feed escape character as ,/" with a slash, while the general NSS feed guidelines write it as ,\" with a backslash. [divergence:zia.logs.nss-runbook.cloud-nss:json-escape-notation]
  - zscaler-help: The escape character is written ,/" and described as comma, backslash, double quote.
  - zscaler-help: Enter a comma, backslash and quotation marks, written ,\", as the Feed Escape Character.
  Impact: The runbook's ,/" has a slash where its own description and the feed guidelines have a backslash. Do not give an admin ,/" to type; give the feed guidelines' form and say the runbook writes it differently.
- The runbook's parsing steps say a 400 response from the connectivity test indicates SIEM parsing errors, while its SIEM test description says any non-2XX response indicates a connectivity issue between ZAB and the SIEM. [divergence:zia.logs.nss-runbook.cloud-nss:non-2xx-meaning]
  - zscaler-help: A 400 from the connectivity test indicates SIEM parsing errors.
  - zscaler-help: Any non-2XX response code indicates a connectivity issue between ZAB and the SIEM.
  Impact: A 400 is both a parsing indicator and a non-2XX connectivity-issue response. Do not tell an admin a 400 is only parsing, or only connectivity; check the SIEM side.
