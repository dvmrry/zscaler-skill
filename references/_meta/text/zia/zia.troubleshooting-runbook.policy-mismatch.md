# Runbook: policy configured but the logs show a different outcome (zia.troubleshooting-runbook.policy-mismatch)
Also called: Block policy configured but access gets allowed; Inspected despite a Do Not Inspect action; Cloud app block action configured for one activity but all activities get allowed

**Entries that bypassed the service.** A web log entry with the Bypassed Transaction column showing Yes did not go through the Zscaler service and was logged because flow logging is enabled. [zia.troubleshooting-runbook.policy-mismatch:bypassed-transaction-column] Intermittently allowed traffic to a domain could be because those transactions do not go to the Zscaler service at all. [zia.troubleshooting-runbook.policy-mismatch:intermittent-allowed-not-forwarded] If firewall logs show the traffic, specific nonstandard web ports can be configured as web traffic, and dynamic nonstandard ports can use Auto Proxy Forwarding. [zia.troubleshooting-runbook.policy-mismatch:firewall-logs-nonstandard-ports]

**Do Not Inspect and Evaluate Other Policies.** With SSL Inspection action Do Not Inspect and Evaluate Other Policies, only the domain part of the URL is used for policy evaluation, and "other policies" means only URL Filtering and Cloud App Control policies since all the others require SSL Inspection. [zia.troubleshooting-runbook.policy-mismatch:dni-evaluate-others] On the Block Policy Configured page, for an SSL Inspection rule with action Do Not Inspect and Evaluate other policies and Show Notifications for blocked traffic enabled, the service decrypts to show the End User Notification; having more Layer 7 information it may then enforce an allow policy on additional criteria, so the transaction can be allowed without any EUN. [zia.troubleshooting-runbook.policy-mismatch:eun-forces-decrypt]

**Inspected despite Do Not Inspect.** Traffic from a known location explicitly forwarded to the Zscaler service on port 9443 is always decrypted by the Service Edge regardless of the SSL Inspection rules. [zia.troubleshooting-runbook.policy-mismatch:port-9443-always-decrypted] On the Inspected Despite Do Not Inspect page, a transaction decrypted only to show the End User Notification (generally because the policy decision based on the SSL handshake was to block it) is eventually allowed without any EUN, or blocked if it matches a more specific policy rule, once the Service Edge has more Layer 7 information. [zia.troubleshooting-runbook.policy-mismatch:eun-inspected-despite] With AI/ML-based content categorization enabled and SSL inspection configured for Miscellaneous, the service initially inspects the transaction; the web log can then show the transaction inspected under a category such as Finance, and the page says that in this case it was inspected because the URL was initially categorized as Miscellaneous. [zia.troubleshooting-runbook.policy-mismatch:aiml-inspected-despite]

**Policy order and authentication.** Without cascading at the global or rule level, an explicit Allow in Cloud App Control bypasses URL Filtering, and a Block in Cloud App Control ends policy evaluation. [zia.troubleshooting-runbook.policy-mismatch:cac-vs-url-filtering] A special NoAuth user or the location name in the web log user field indicates an authentication failure or exemption, and rules with users, groups or departments as criteria cannot be evaluated for such transactions. [zia.troubleshooting-runbook.policy-mismatch:noauth-user-field] For Connect requests or undecrypted SSL traffic from a known location, policy is enforced only on the host part of the URL if Enforce Authentication is not enabled for the location; otherwise Connect transactions always show Allowed, because the Service Edge allows SSL handshakes and Connect requests from Enforce Authentication locations to obtain the authenticated user. [zia.troubleshooting-runbook.policy-mismatch:connect-enforce-auth] To avoid SSL inspection for a domain the page says to use the SSL Inspection action Evaluate Other Policies, or else enable an IP surrogate on the location or Policy for unauthenticated traffic under Administration > Advanced Settings. [zia.troubleshooting-runbook.policy-mismatch:connect-solutions] The menu path for Advanced Settings differs between pages, see [Runbook: SSL and HTTP-tunnel block outcomes (bad SSL record, undecryptable traffic, server probe failure, domain fronting, HTTP tunnel)](kb:zia.troubleshooting-runbook.ssl-block-actions).

**Isolation.** Per the Specific Criteria page, isolation (Zero Trust Browser) is supported only for HTTP and HTTPS in the Protocol column; transactions logged as SSL need SSL Inspection enabled for the domains. [zia.troubleshooting-runbook.policy-mismatch:isolation-protocol]

**Cloud app activities.** For Cloud App activity rules the SSL Inspected web log column must show yes; with Do Not Inspect & Evaluate Other Policies only the domain part of the URL is available, so activities such as upload and download cannot be told apart. [zia.troubleshooting-runbook.policy-mismatch:cloud-app-activity-needs-inspection] A recently updated cloud app can leave the signature outdated for a specific activity, so the Policy Action can be both Blocked and Allowed for the same request method and app; Zscaler maintains signatures and releases them following the Trust Portal service update schedule. [zia.troubleshooting-runbook.policy-mismatch:cloud-app-signature-outdated] If the request method is not POST, the Service Edge typically does not detect the activity as POST, and a different cloud app name in the web logs should be used as the Cloud App rule criterion. [zia.troubleshooting-runbook.policy-mismatch:cloud-app-non-post]
