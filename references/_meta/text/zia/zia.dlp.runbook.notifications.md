# DLP runbook: web DLP email and ICAP notification issues, attachment limit, SMTP codes and ICAP connectivity checks (zia.dlp.runbook.notifications)
Also called: Web DLP Email or ICAP Notification Issue; DLP email notification not received

**Delivery channels.** Zscaler supports sending DLP violation notification delivery using email or Internet Content Adaptation Protocol (ICAP); the ICAP option (subscription required) can be integrated with a third-party ICAP server or Zscaler Incident Receiver. [zia.dlp.runbook.notifications:delivery-channels]

**Email attachment size.** Zscaler supports a 25 MB limit for DLP email notification attachments by default; the admin still receives the DLP email notification but without the violation content attachment, with a message such as 'NRIC-Large.xlsx not attached - its size 51530124 bytes exceeds archive size limit of 25MB'. [zia.dlp.runbook.notifications:email-attachment-limit] [gap:zia.dlp.runbook.notifications:email-limit-knob] For large violation content the runbook suggests the ICAP method (integration with a third-party ICAP server, Zscaler Incident Receiver, or Zscaler Workflow Automation), or, for a strong, valid use case to send large violation content using email, a Provisioning support case with Zscaler Support with the details. [zia.dlp.runbook.notifications:email-large-content-options]

**Email not arriving.** If the DLP policy is triggered as per Zscaler logs but no email notification reaches the configured auditor email address, the runbook says to ensure the auditor email address is correct, testing with a different email address in a different domain (e.g., gmail.com or yahoo.com) as a problem isolation step, not a workaround or solution, that needs internal approval, and to filter the Web Insights logs to DLP transactions and, in the Policy Action column, ensure the notification for DLP was triggered as either Violates Compliance Category, archived to mailbox, or Allowed and archived to mailbox, in the runbook's wording. [zia.dlp.runbook.notifications:smtp-troubleshooting] The Policy Reasons article lists these DLP Policy Reason values: 'Violates Compliance Category' (the transaction was blocked due to a DLP policy violation), 'Violates Compliance Category, archive to mailbox' (blocked, and an email was sent to the auditor's mailbox), 'Violates Compliance Category, archive to mailbox failed' (blocked, and sending the email to the auditor's mailbox failed), 'Allowed and archived to mailbox' (allowed, and an email was sent to the auditor's mailbox) and 'Allowed and archived to mailbox failed' (allowed, and sending the email to the auditor's mailbox failed). [zia.dlp.runbook.notifications:smtp-policy-reasons] Zscaler Support can check the SMTP code for a particular email delivery using the DLP Identifier field from Web Insights logs; the runbook lists the first digit as the category (2.x.x success, 3.x.x positive intermediate reply, 4.x.x transient or temporary error, 5.x.x permanent error) and the codes 220 (service ready), 250 (message delivered successfully), 421 (service not available, temporary issue with the server), 450 (mailbox unavailable, temporary), 451 (requested action aborted, local error in processing), 500 (syntax error, command unrecognized), 550 (mailbox unavailable or not found, permanent error) and 554 (transaction failed, general error). [zia.dlp.runbook.notifications:smtp-codes] For an email notification issue, the runbook's data checklist asks for relevant configuration screenshots of the DLP rule name and the auditor email address. [zia.dlp.runbook.notifications:support-data-email]

**ICAP.** Zscaler supports secure or unencrypted ICAP receivers on the DLP notification and recommends sending transaction information via secure ICAP; secure ICAP is required to set up the stunnel application. [zia.dlp.runbook.notifications:icap-secure] For an ICAP notification issue the runbook says to ensure the necessary firewall configuration according to Zscaler's Config page, listing DLP ICAP Requirements (https://config.zscaler.com/<zscaler cloud>/icap), DLP Incident Receiver (/dlp-incident-receiver), Internet & SaaS Advanced DLP (Private Service Edge) (/zia-private-dlp) and Private Service Edge for Internet & SaaS Access Requirements (/zia-sedge); to perform a telnet to the external ICAP server IP address and port (e.g., 1344) behind an allowed network; and, if it is ICAP, to check the stunnel configuration according to the tunnel application guide; and to change the configuration to an unencrypted ICAP URL and test again. [zia.dlp.runbook.notifications:icap-troubleshooting] For an ICAP notification issue, the runbook's data checklist asks for relevant configuration screenshots of the DLP rule name, the DLP rule’s DLP Incident Receiver setting and the DLP Incident Receiver’s configuration. [zia.dlp.runbook.notifications:support-data-icap]
