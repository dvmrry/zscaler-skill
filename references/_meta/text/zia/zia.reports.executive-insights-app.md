# Executive Insights mobile app: access errors, data freshness and widgets (zia.reports.executive-insights-app)
Also called: executive insights app; executive insights mobile app; email address is not valid executive insights; stuck on select tenant; executive insights stale data

Using the app requires the Internet & SaaS subscription. Executives are authorized by an IT admin or Network Security team adding role-based access control roles for Internet & SaaS in the Admin Console or Authentication Service, and an administrator can authorize an executive to view the data of multiple organizations. The app is installed from the Play Store (Android) or App Store (iOS). Login uses the corporate email address associated with the Zscaler account; the login fails if the email address is not authorized, and the user selects a tenant on the Select Organization screen and can switch tenants in the User Profile section. [zia.reports.executive-insights-app:install-and-login] The Executive Insights App admin role is a default role that gives the admin the permissions and scope required to access the app but not the Admin Console. In the Edit Administrator Role window the field Enable Permissions for Executive Insights App gives the admin assigned the role that access and cannot be modified; User Names, Device Information and Gen AI Prompt can each be set to Visible or Obfuscated for admins with the role when they view data in the app. [zia.reports.executive-insights-app:app-role-field] In the app's troubleshooting table an Invalid Email Address issue shows the error "Email Address is not valid. Contact support if you have any further questions." on the Confirmation Code screen; the page's remedy is to ensure in the Zscaler Admin Console that the user exists and is assigned a role with permission to access the Executive Insights App. [zia.reports.executive-insights-app:invalid-email] When a user can log in to the app but cannot see their tenant organization on the Select Tenant screen, the page says to ensure, in that tenant's Admin Console under Administration > Legacy Admin Management > Internet & SaaS, that the user exists and is assigned a role with permission to access the app. [zia.reports.executive-insights-app:select-tenant] Some users can log in successfully but get the error "Contact your IT admin to provide you access to a tenant." The page says this happens only in the case of Authentication Service-based authentication, when the user has been given an Authentication Service role with permission to access the app but no Internet & SaaS Administration Management access for any tenant. The remedy is to go, in the Admin Console, to Administration > Legacy Admin Management > Internet & SaaS and ensure two things: the user exists, and the user has a role with permission to access the app. [zia.reports.executive-insights-app:auth-service-access] The two published copies of the errors page give different Admin Console paths for these checks [divergence:zia.reports.executive-insights-app:admin-path].

**Login and connectivity messages.** On the Login screen an invalid entry shows "You have entered an invalid email. Please try again." and the user must enter their correct email address; a wrong confirmation code shows "Validation failed. Please re-enter the correct confirmation code or have a new one sent." [zia.reports.executive-insights-app:login-errors] Without connectivity the Login screen shows "No internet connection. Make sure Wi-Fi or cellular data is turned on. Then try again." and "We are unable to proceed with the next steps due to a connectivity issue. Please check your connection and ensure all the necessary applications are active."; after entering a one-time password, the Confirmation Code screen can show "Connection issue detected. Please check your network connection. If you are using Zscaler Client Connector, ensure you're successfully authenticated for Private Access." [zia.reports.executive-insights-app:connectivity-errors] The app tries to determine the subscriptions included for the tenant on the Select Tenant screen, which might fail due to network connectivity issues or reachability of the API endpoint; in rare cases of API endpoint reachability issues the user must retry selecting the tenant. [zia.reports.executive-insights-app:select-tenant-loader]

**Confirmation code and Client Connector.** If the user sees the countdown timer on the confirmation code screen, the page says the API call to send the code succeeded and the email was sent from the back end; the user checks the spam folder. Generating multiple codes within a short span might lead to using the wrong code, in which case the user closes and reopens the app to restart login. [zia.reports.executive-insights-app:confirmation-code] For a user running Zscaler Client Connector on the phone, the page says to ensure that Private Access on Client Connector is turned on and that authentication has not expired. [zia.reports.executive-insights-app:client-connector] Whether the app's role can be given to a user who also needs Admin Console access in the same role is open [gap:zia.reports.executive-insights-app:role-combination].

**Data freshness.** The app's data refreshes once a day, so the data for today is visible only tomorrow. The refresh starts at the UTC day boundary (00:00 UTC): users in UTC+ time zones keep seeing data two days older until their local time crosses it, and even after the boundary it might take a few hours to process, which the page says varies with system load and other factors. [zia.reports.executive-insights-app:data-freshness] The app prefetches all the data and stores it in the cache on startup. For stale widgets the page's steps include forcing the latest data to be fetched from the back end. The page also says to confirm the user is not using the Demo mode, as it contains mock data, and that it is possible that no data is available for that tenant for the selected time range. [zia.reports.executive-insights-app:stale-data-checks] When the app's data does not match the product consoles, the page says to verify that the user selected the correct tenant on the Profile screen, then close the app, clear the app data and restart it, which forces the latest data to be fetched from the back end. [zia.reports.executive-insights-app:wrong-data]

**Screens and widgets.** ZDX and Risk360 support only the most current data and fixed time ranges, and the tenant must be provisioned on Risk360 before data shows on its screen. Widgets are rendered based on the subscriptions included for the user's tenant. Zscaler Sandbox threats data is aggregated monthly at the end of the month: the Last 7, Last 14 or Last 30 Days filters show only last month's data, Last 90 Days lets the user select any of the past three months, and a month with no threats does not show up in the selection. [zia.reports.executive-insights-app:screens-and-widgets] The two published copies of the errors page differ on where the ZDX subscriptions are checked [divergence:zia.reports.executive-insights-app:zdx-subscription-location]. News items are published periodically across Zscaler's official channels, such as News and Announcements, Blog and Zscaler Trust Portal. For news items in the For You section under Threats Detected, a status of Partially Covered or Not Covered is shown, and the page recommends reaching out to the Zscaler Account team for complete coverage and enhanced protection. [zia.reports.executive-insights-app:news]

The monthly Executive Insights Report is a different surface: [Executive Insights, company summary (CIO, CSO), QBR, Industry Peer Comparison and CIPA Compliance reports](kb:zia.reports.executive).

What to check:
1. Whether the user exists in the tenant and holds a role with permission to access the app, before treating an Email Address is not valid error or a missing tenant as an app fault; the two copies of the page give different Admin Console paths for the check.
2. Whether the data the user is looking at is the previous day's data, and whether the app is in Demo mode, before treating a widget as stale.
