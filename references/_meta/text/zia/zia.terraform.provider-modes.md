# ZIA Terraform provider authentication, client modes and rate limiting (zia.terraform.provider-modes)
Also called: zia provider skip_credentials_validation; zia provider fedramp gov; zia sandbox token terraform; terraform 429 retry-after zia; EDIT_LOCK_NOT_AVAILABLE terraform; zia provider parallelism

The ZIA Terraform provider supports OneAPI and the legacy framework, and has a no-credential mode and its own rate-limit handling. Since provider v4.0.0 the ZIA provider offers backwards compatibility with the legacy Zscaler API framework alongside OneAPI. [zia.terraform.provider-modes:legacy-compat-since-4-0] The provider chooses the legacy ZIA client when use_legacy_client is true, from the provider attribute or, when that is unset, from ZSCALER_USE_LEGACY_CLIENT being the string true. [zia.terraform.provider-modes:legacy-client-switch] Provider issue #598 reported that on v4.8.3 with ZSCALER_USE_LEGACY_CLIENT=true, `zia_url_filtering_and_cloud_app_settings` read through the legacy client but sent its PUT to the OneAPI host, which answered 401, because the resource called `service.Client.ExecuteRequest` directly instead of a method that checks `UseLegacyClient`. It was closed as completed on 2026-08-06; on 2026-08-07 a repository member's comment asked for an upgrade to the latest minor release, v4.8.5, saying the issue was largely due to upstream API changes, and a non-member replied that they would test in the morning. [zia.terraform.provider-modes:issue-598-put-bypassed-legacy-client]

**Government clouds.** OneAPI reaches the government (FedRAMP) clouds through the `gov` and `govus` cloud values, and the provider documents this as supported only from v4.7.25; earlier versions are not supported. [zia.terraform.provider-modes:fedramp-gov-values]

**Configuration-only mode.** With `skip_credentials_validation` (or `ZSCALER_SKIP_CREDENTIALS_VALIDATION`) the provider skips credential validation and never builds the API client, because the OneAPI SDK performs an OAuth handshake in its constructor. [zia.terraform.provider-modes:skip-credentials-builds-no-client] The documented use of `skip_credentials_validation` is a configuration in which every `zia_*` resource and data source is conditionally disabled (for example `count = 0`); plan and apply then succeed with a warning even without credentials. [zia.terraform.provider-modes:skip-credentials-intended-use] With that flag set, every resource and data source CRUD function is wrapped so that one which does attempt an API call returns an explanatory error instead of dereferencing a nil service. [zia.terraform.provider-modes:skip-credentials-calls-fail] The `skip_credentials_validation` attribute was added in provider v4.8.7. [zia.terraform.provider-modes:skip-credentials-since-4-8-7]

**Sandbox credentials.** Sandbox authentication uses its own token and cloud, set through `ZSCALER_SANDBOX_TOKEN` and `ZSCALER_SANDBOX_CLOUD` or the `sandbox_token` and `sandbox_cloud` attributes. [zia.terraform.provider-modes:sandbox-auth-variables] The legacy variables are no longer supported, and a resource page still names them: [zia.terraform.sandbox-resources:sandbox-token-variable-names](kb:zia.terraform.sandbox-resources:sandbox-token-variable-names).

**Rate limiting.** When ZIA answers HTTP 429, the provider waits the interval in the `Retry-After` header and retries the request transparently, so exceeding a rate limit costs a short delay rather than a failed apply. [zia.terraform.provider-modes:retry-after-transparent] The provider documentation says to run Terraform with its default settings, with nothing to configure to stay within the rate limits. [zia.terraform.provider-modes:keep-default-parallelism] The provider-block `parallelism` attribute is deprecated and ignored. [zia.terraform.provider-modes:parallelism-ignored] The provider documentation gives `/staticIP` as an example of an endpoint limited to 1 POST request per second, while some endpoints allow several per second. [zia.terraform.provider-modes:static-ip-post-1-per-second] Zscaler's legacy ZIA API rate limit summary lists /staticIP at 2/sec and 1000/hr for GET and 1/sec and 400/hr for POST (a resource URI by method table). [zia.terraform.provider-modes:static-ip-legacy-rate-row] Whether the OneAPI endpoint has the same limit is open [gap:zia.terraform.provider-modes:static-ip-oneapi-limit]. The Terraform ZIA provider sets its own default retry count of 100, which its source describes as deliberately above the SDK default so that bulk applies survive sustained rate limiting. [zia.terraform.provider-modes:provider-default-retries-100]

**Coverage.** The provider maintains parity with publicly available API endpoints. [zia.terraform.provider-modes:provider-tracks-public-api] So the presence of a Terraform resource or data source shows API coverage, not that a given tenant is entitled to or has enabled the feature. [zia.terraform.provider-modes:object-presence-not-entitlement]

**Write lock.** An HTTP 409 reporting `EDIT_LOCK_NOT_AVAILABLE` or `Failed during enter Org barrier` means another session is modifying the configuration, not that a rate limit was exceeded. [zia.terraform.provider-modes:write-lock-is-not-rate-limit] How applies compete for that lock: [Activating ZIA changes from Terraform: methods, session end and concurrent applies](kb:zia.terraform.activation-methods).

What to check:
1. Whether a provider that errors on every resource was configured with `skip_credentials_validation`, which builds no client.
2. Whether a 409 on a write is tenant write-lock contention rather than rate limiting before changing the run's parallelism.
3. Whether the provider version is at least v4.7.25 before configuring a FedRAMP cloud.
