# ZIA SSL/TLS inspection (zia.ssl-inspection)
Also called: ssl inspection; tls inspection; ssl/tls inspection policy; zia ssl policy; is this traffic inspected; ssl inspection overview; ssl inspection broke a site; https site fails behind zscaler

"Is this traffic inspected, and what does that change?" needs several questions answered in order. Skipping one is how SSL answers go wrong.

1. **Where does the SSL decision sit?** Between two passes of URL Filtering and Cloud App Control, and what survives without decryption depends on Evaluate versus Bypass Other Policies: [Where SSL inspection sits in ZIA web policy evaluation (the two passes)](kb:zia.ssl-inspection.pipeline). How it applies by traffic source and forwarding port (known locations, Client Connector, dedicated port, 9443, 8800): [How SSL/TLS inspection applies by traffic source: known locations, Client Connector, a dedicated proxy port, and ports 9443, 80/443/9400/9480 and 8800](kb:zia.ssl-inspection.traffic-sources).
2. **Which rule matches?** First match by ascending order, with predefined and default rules you did not write: [SSL/TLS inspection rule order, predefined and default rules, limits](kb:zia.ssl-inspection.rules). Whether its criteria can match this traffic at all (destination groups with SNI, user agents, identity, platform): [SSL/TLS inspection rule criteria and the ones that silently don't match](kb:zia.ssl-inspection.criteria).
3. **What does the rule do?** Certificates, OCSP, SNI, TLS floors, HTTP/2 and notifications: [What an SSL/TLS inspection action does: Inspect, Do Not Inspect, Block and their settings](kb:zia.ssl-inspection.actions). The same settings as a nested wire object, with tokens, casing and validators: [SSL/TLS inspection rule wire format: the nested action object, tokens and casing](kb:zia.ssl-inspection.api-shape).
4. **Could it be inspected at all?** Who signs the certificate and where the root must be trusted: [SSL/TLS inspection certificates: who signs, and where the root must be trusted](kb:zia.ssl-inspection.certificates). The intermediate CA object itself: [Intermediate CA certificates for SSL/TLS inspection: protection types, limits, key types, CSR signing, chain upload and the default](kb:zia.ssl-inspection.intermediate-ca). Installing the root in tools with their own trust store: [Installing the inspection root in applications that keep their own trust store, per tool](kb:zia.ssl-inspection.app-trust-stores). Supported TLS versions and cipher suites: [Which TLS versions and cipher suites SSL/TLS inspection supports, and what happens to the rest](kb:zia.ssl-inspection.cipher-suites). Pinned apps, client certificates, QUIC, BYOD and IoT: [What SSL/TLS inspection cannot inspect: pinned apps, client certs, QUIC, BYOD, IoT](kb:zia.ssl-inspection.uninspectable).
5. **What does an exemption cost?** How to write one safely: [Writing SSL/TLS inspection exemptions without exempting too much](kb:zia.ssl-inspection.exemptions). What stops working behind it: [What stops working when traffic bypasses SSL/TLS inspection](kb:zia.ssl-inspection.bypass-impact).

Terraform and SDK defects for SSL rules are not repeated here; the validator and plan-time checks are in [ZIA Go SDK service functions that return wrong results, mutate inputs, or reject valid input](kb:zia.sdk-go.service-defects).

The SSL/TLS Inspection reference architecture says Zscaler recommends inspecting 100% of traffic to protect against threats hiding in encrypted channels. [zia.ssl-inspection:recommend-inspect-all] The exemption side is in [Zscaler strongly recommends inspecting all traffic and placing a bypass only for controlled, understood exceptions, and only after consulting legal counsel for the impacted region.](kb:zia.ssl-inspection.exemptions:bypass-only-controlled).
