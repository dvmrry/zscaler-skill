# Submitting files to Sandbox and out-of-band inspection (Discan) (zia.sandbox.submission)
Also called: discan; zscsb submit; submit file for inspection; out-of-band file inspection; sandbox submission api

Two SDK calls push a file to Sandbox outside the normal download path. The submit call sends a raw or archive file to Sandbox for analysis (up to 100 files per day). Files are scanned by Zscaler antivirus and sent to the sandbox; the `force` parameter makes the sandbox reanalyze a file that already has a verdict. The verdict is read afterwards from the report endpoint. [zia.sandbox.submission:submit] A file whose type is not covered by the default policy rule is analyzed only if a Sandbox policy rule includes that file type; otherwise the response shows "Unknown". [zia.sandbox.submission:submit-needs-rule] Advanced Sandbox allows 100 API file submissions per day by default; the quota can be raised through the Zscaler account team or Support. [zia.sandbox.submission:daily-quota] Reading the result is covered in [Sandbox reports, quota, and trusting report content](kb:zia.sandbox.report), and the rule fields in [Sandbox rules: first-time file behavior and the default rule](kb:zia.sandbox.rules).

**Discan.** Discan submits a file for out-of-band inspection that yields a real-time verdict for known and unknown files, using Malware Prevention, Advanced Threat Prevention, the Sandbox cloud effect, AI/ML analysis and third-party threat intelligence. It supports the file types of the Malware Protection and ATP policies, limits each file to 400 MB, and includes no dynamic file analysis. The Go SDK calls it `Discan` (POST /zscsb/discan); the Python SDK calls it `submit_file_for_inspection`. [zia.sandbox.submission:discan]

The public Automate capture no longer lists `POST /zscsb/submit` or `POST /zscsb/discan`; the pinned Go and Python SDKs still construct both paths. This shows a gap between publication and clients, not that the backend routes were retired. [zia.sandbox.submission:automate-publication] Whether the two routes still work on a tenant is open [gap:zia.sandbox.submission:submission-route-status].

**The Sandbox Scanning Portal.** With Advanced Sandbox, suspicious files can be submitted by hand through the Sandbox Scanning Portal, where the engine executes and monitors them in a controlled sandbox, records and analyzes malicious behavior, and applies the organization's Malware Protection and Sandbox policies. No Sandbox analysis is done if the file is blocked by Malware Protection, is clean, or was analyzed before. [zia.sandbox.submission:scanning-portal] A portal upload's file name cannot contain spaces. Its status is a blocked sign (blocked by the Malware Protection or Sandbox policies, with the reason shown) or a check mark, which indicates one of the results the page lists, one being that the file was unknown and sent for analysis. File contents are treated as confidential and not viewable in the portal. [zia.sandbox.submission:scanning-portal-results] To tell whether a portal upload was clean or sent for analysis, the Sandbox logs must be viewed. Filtering by Sandbox MD5, no log means the file is clean and a log means it is unknown and sent for analysis. Filtering by Uploaded URL with https://filecheck.zscaler.com/<Uploaded URL>, a display of None means clean and Sent for Analysis means the engine is analyzing the file. Files uploaded simultaneously share the first segment of the Uploaded URL. [zia.sandbox.submission:scanning-portal-check-status] The portal's limits are open [gap:zia.sandbox.submission:portal-limits].
