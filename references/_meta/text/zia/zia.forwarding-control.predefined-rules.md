# Predefined Forwarding Control rules (zia.forwarding-control.predefined-rules)
Also called: ZIA Inspected ZPA Apps; Fallback mode of ZPA Forwarding; Client Connector Traffic Direct; ZPA Pool For Stray Traffic; zpaBrokerRule; predefined forwarding rule cannot be deleted

Some Forwarding Control rules exist before anyone writes one. ZIA Inspected ZPA Apps is a predefined Forwarding rule, enabled by default, that sends Private Access application segment traffic whose Inspect Traffic with ZIA field is enabled to ZIA for inspection. It cannot be edited, and exists only with Private Access App Inspection. [zia.forwarding-control.predefined-rules:inspected-zpa-apps] The API's `zpaBrokerRule` member is a read-only boolean described as the predefined ZPA Broker Rule generated by Zscaler. [zia.forwarding-control.predefined-rules:broker-rule-flag]

The Terraform provider recognises four rule names as predefined: Client Connector Traffic Direct, ZPA Pool For Stray Traffic, ZIA Inspected ZPA Apps and Fallback mode of ZPA Forwarding. It checks the name on create, update and delete and returns an error saying the rule cannot be deleted. [zia.forwarding-control.predefined-rules:provider-names] The documentation's guidance is looser than the code [divergence:zia.forwarding-control.predefined-rules:terraform-management]. The provider documentation says predefined rules can be managed for reordering but not destroyed, and not all attributes apply to them; it also says not to import or manage default rules because the API does not support managing them. [zia.forwarding-control.predefined-rules:tf-docs-handling]

The About Forwarding Control page names three predefined rules for forwarding to Private Access. Fallback mode of ZPA Forwarding forwards source-IP-anchored traffic that matches the fallback Private Access IP pools to Private Access, and is only enabled during Internet & SaaS control plane maintenance. ZIA Inspected ZPA Apps forwards Private Access application segment traffic for Internet & SaaS inspection that has the Inspect Traffic with Internet & SaaS field enabled. ZPA Pool For Stray Traffic drops Private Access traffic that does not match any IP address range from the Private Access IP pool. [zia.forwarding-control.predefined-rules:zpa-predefined-three] The About Forwarding Control page says the predefined rules are enabled by default and cannot be deleted, and that only the Rule Label can be modified, not other attributes. [zia.forwarding-control.predefined-rules:predefined-help-statement] Whether those rules are enabled by default [divergence:zia.forwarding-control.predefined-rules:enabled-by-default] and what on them can be changed [divergence:zia.forwarding-control.predefined-rules:predefined-rule-editability] differ between the sources. With Extranet Application Support enabled, three default rules are added: Allow Extranet DNS Traffic, which allows DNS traffic from extranet locations; Extranet Traffic to ZPA, which forwards all extranet traffic to Private Access; and Stray Extranet Traffic from ZPA, which drops all extranet traffic that does not match any IP address range from any extranet IP pool. A default IP pool is created for extranet traffic and custom pools can be configured. [zia.forwarding-control.predefined-rules:extranet-rules]

What Client Connector Traffic Direct does is open [gap:zia.forwarding-control.predefined-rules:other-purposes]. Ordering and enablement of any rule: [Forwarding Control rule criteria, limits and ordering](kb:zia.forwarding-control.rules).

Sources disagree (name both sides):
- Whether the predefined Forwarding Control rules are enabled by default: the About Forwarding Control page says Fallback mode of ZPA Forwarding is disabled by default and, separately, that the predefined rules are enabled by default. [divergence:zia.forwarding-control.predefined-rules:enabled-by-default]
  - zscaler-help: Fallback mode of ZPA Forwarding is disabled by default and is only enabled during Internet & SaaS control plane maintenance.
  - zscaler-help: The predefined rules are enabled by default.
  Impact: Do not state that every predefined Forwarding rule is enabled; the page itself names one that is disabled by default. Whether the general sentence excludes that rule is not stated.
- What can be changed on a predefined Forwarding rule: the About Forwarding Control page allows only the Rule Label, the Forwarding rule configuration page says of ZIA Inspected ZPA Apps that it cannot be edited, and the Terraform documentation says predefined rules can be managed for reordering. [divergence:zia.forwarding-control.predefined-rules:predefined-rule-editability]
  - zscaler-help: Only the Rule Label can be modified on the predefined rules.
  - zscaler-help: ZIA Inspected ZPA Apps, the one rule this page describes, cannot be edited.
  - tf-zia: Predefined rules can be managed through the provider for reordering; destroy is unsupported and not all attributes apply.
  Impact: An answer about editing or reordering a predefined rule depends on the source: give all three and say that the provider code rejects updates by name (see terraform-management).
- Whether Terraform can manage predefined Forwarding Control rules [divergence:zia.forwarding-control.predefined-rules:terraform-management]
  - tf-zia: Predefined rules can be managed for reordering; only destroy is unsupported.
  - tf-zia: The update function rejects any request whose name is one of the four predefined names, with an error that says the rule cannot be deleted.
  Impact: A plan that updates or reorders a predefined rule through the resource may fail instead of reordering. Treat reordering predefined rules through this resource as untested and read the error, not the documentation.
