# File Type Control rule criteria (zia.file-type-control.criteria)
Also called: file type control criteria; file type control rule; unknown file type; undetectable file; active content; unscannable file; password-protected file; archive file types; file size min max

A rule fires when all of these hold: File Types AND URL Categories AND Cloud Applications AND Application Segment; Users OR Groups OR Departments; Location Groups OR Locations; Time; Device Groups OR Devices; Protocols; Device Trust Level; Minimum File Size; Maximum File Size. [zia.file-type-control.criteria:criteria-expression] For cloud applications, devices, device groups, device trust level and the file size bounds, selecting no value ignores the criterion. File Types is a required criterion. [zia.file-type-control.criteria:empty-criteria-ignored]

- **File types.** A rule reaches unknown file types by selecting Undetectable File under Other. The service first checks the file header using true file type detection; if the file is still unknown it performs MIME type checks and tags as unknown anything outside the well-defined MIME types for common applications. [zia.file-type-control.criteria:unknown-file-types] Zscaler-defined file types are considered before custom file types, and custom file types inside archives are not detected. [zia.file-type-control.criteria:custom-types-order] To recognize the file types inside archives, the service scans ZIP, 7-Zip, GZIP, TAR and RAR files. [zia.file-type-control.criteria:archive-formats-scanned] How other archive formats are treated is open [gap:zia.file-type-control.criteria:archive-contents-rules].
- **Size.** Minimum and Maximum File Size take a value from 0 to 409,600 KB. The API field names are `minSize` and `maxSize`, in KB. [zia.file-type-control.criteria:size-bounds] This is separate from the scanning limit in [Where File Type Control sits in the inspection order](kb:zia.file-type-control.pipeline).
- **Active content.** Active Content applies the rule to files with active content, and only for Microsoft Word, Excel, PowerPoint and PDF files. File Types must be set to one of those formats. [zia.file-type-control.criteria:active-content] The Terraform provider rejects `active_content` at plan time unless `file_types` is set and holds only FTCATEGORY_MS_WORD, FTCATEGORY_MS_POWERPOINT, FTCATEGORY_PDF_DOCUMENT or FTCATEGORY_MS_EXCEL, and rejects `unscannable` together with `active_content`. [zia.file-type-control.criteria:provider-active-content-checks]
- **Unscannable files.** Unscannable Files applies the rule only to files the service cannot scan: an unrecognized format, excessive size, corruption or recursive compression. With it on, the rule applies to no other files. [zia.file-type-control.criteria:unscannable]
- **Password-protected files.** Password-Protected File applies the rule only to files with password protection, and only for 7-Zip, RAR, Zip, Zipx, password-protected Microsoft Office documents, password-protected or encrypted files, and PDF. The contract adds that traffic is evaluated against this criterion only when upload and download of password-protected files is allowed at the organization level through Security Exceptions in Malware Protection. [zia.file-type-control.criteria:password-protected] A Terraform apply cannot turn this setting on; see [The file type control rule resource has no `password_protected` attribute and never references the field, while the SDK model sends `passwordProtected` without `omitempty`. Every create and update therefore carries `passwordProtected:false`.](kb:zia.terraform.field-fidelity:file-type-password-protected-never-mapped).

**Who the rule applies to.** A rule's Locations and Location Groups each take Any or up to 32 entries, and Time takes Always or up to two time intervals. A rule for unauthenticated traffic must apply to all Groups and Departments. [zia.file-type-control.criteria:scope-limits]

Protocol selection and the wire values are in [File Type Control API shape: rules, categories and custom types](kb:zia.file-type-control.api-shape); what a match does is in [File Type Control actions, direction and defaults](kb:zia.file-type-control.actions).

What to check:
1. Whether a file is unrecognized, reached through Undetectable File under Other.
2. Whether a rule on an inner file type fires through an allowed archive, which is open.

Not known (open gaps):
- Rules matching files inside archives and unlisted archive formats [gap:zia.file-type-control.criteria:archive-contents-rules]: settled by lab-test or source-read. Blocks: advising whether a rule on executables covers executables inside archives
