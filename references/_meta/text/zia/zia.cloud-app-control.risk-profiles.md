# Cloud Application Risk Profiles in Cloud App Control (zia.cloud-app-control.risk-profiles)
Also called: cloud application risk profile; risk profile composition; risk index; why was this app caught by my risk rule; medium-risk block rule

A Risk Profile lets a rule match applications by attribute instead of by name. It is how "block every unsanctioned, high-risk file-sharing app" is written without listing apps. A Cloud Application Risk Profile is created under Data Security > Inline CASB > Risk Profiles (Add Cloud Application Risk Profile) and then associated with Cloud App Control rules; the profile name is what the rule form displays. [zia.cloud-app-control.risk-profiles:where-configured]

**How a profile combines its attributes.** A profile is a series of AND operators between its attributes (Application Status, Hosting Information, Security Information). The attributes that allow multiple values (Risk Index, Certificates Supported, Data Encryption in Transit, SSL Cert Key Size) are OR between their own values. [zia.cloud-app-control.risk-profiles:composition] Zscaler's example profile is [Risk Index (1 OR 3 OR 5)] AND [Application Status (Sanctioned)] AND [Certificates Supported (AICPA OR GDPR)] AND [SSL Pinned (Yes)]. [zia.cloud-app-control.risk-profiles:example]

**What it can test.** The core attributes are Risk Index (1 to 5, 1 lowest risk), Application Status (Sanctioned or Unsanctioned), Tags, Certificates Supported (include or exclude), Password Strength (Good, Poor, Unknown), Data Encryption in Transit (SSLv2, SSLv3, TLSv1.0, TLSv1.1, TLSv1.2, TLSv1.3, Unknown) and SSL Cert Key Size (256, 384, 768, 1024, 2048, 3072, 4096, 8192 Bits, Unknown). [zia.cloud-app-control.risk-profiles:core-attributes] Beyond the core attributes the form lists these hosting and security characteristics (from Poor Terms of Service and Admin Audit Logs through SSL Pinned, MFA Support, Evasive, Weak Cipher Support, Published CVE Vulnerability and Vulnerable to Heartbleed, Poodle and Logjam, to Sender Policy Framework, DomainKeys Identified Mail, Domain-Based Message Authentication and Malware Scanning for Content), each set to Yes, No or Unknown. [zia.cloud-app-control.risk-profiles:hosting-security-characteristics] Applications with risk index overrides set on the Application Information page are evaluated in the policy when the Risk Index criterion matches. [zia.cloud-app-control.risk-profiles:risk-index-overrides]

**Cloud application tags.** A cloud application tag groups cloud applications (custom, predefined or both, across categories) to the organization's needs. The feature has three parts: creating the tag, associating it with cloud applications, and creating risk profiles with it, so Cloud App Control policies can act on tag-based risk profiles. [zia.cloud-app-control.risk-profiles:tags-what] An organization can create at most 16 cloud application tags, each up to 127 characters, and a tag is created by entering a Tag Name. [zia.cloud-app-control.risk-profiles:tags-limit] Tags are managed on the Cloud Application Tags page (Data Security > Inline CASB > Application Tags), whose columns are not editable. [zia.cloud-app-control.risk-profiles:tags-page] Tags are attached to applications on the SaaS Applications page: the page lets administrators tag cloud applications with predefined and custom labels, and both the Edit Predefined Cloud Application drawer and the Edit Custom Cloud Application drawer include Tags. [zia.cloud-app-control.risk-profiles:tags-attached-on-applications-page] Whether predefined tags exist is open [gap:zia.cloud-app-control.risk-profiles:tag-association]. The page is in [SaaS Applications page: application status, tags and custom cloud applications](kb:zia.cloud-app-control.custom-applications).

A rule that selects a profile applies to every matching app, so one rule can account for many blocks: [What a Cloud App Control rule matches on](kb:zia.cloud-app-control.rule-criteria). On the Application Information page, the fields for the application's integrations, the vendors that host its data, the countries in which its data resides, its data retention policy, its data retention type and whether it deletes a user's data on request are each populated by Zscaler 3rd-Party App Governance. [zia.cloud-app-control.risk-profiles:attribute-sources-3p] Where the other attribute values come from is open [gap:zia.cloud-app-control.risk-profiles:attribute-sources]. The Application Information page itself is in [Shadow IT Report (also SaaS Security Report, ZINS): shadow IT discovery, risk index and API surface](kb:portfolio.saas-security-report).

What to check:
1. Whether each selected criterion of the rule's profile is satisfied by the app's current attribute values, since the attributes combine with AND.
2. Whether the match is explained from the rule's profile and the app's attributes, not from the app's name.
3. Whether a Risk Index override on the app explains a change in matching, since overrides are evaluated when the Risk Index criterion matches.
