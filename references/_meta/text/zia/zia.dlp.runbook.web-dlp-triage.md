# DLP runbook: web DLP policy not working as expected, with evaluation mode, log fields, exemptions, rule criteria, engines and multipart checks (zia.dlp.runbook.web-dlp-triage)
Also called: Web DLP Policy (Inline DLP, OCR, EDM, and IDM) Not Working as Expected; Cloud App & URL Exceptions for DLP

**Evaluation order.** By default the Zscaler service evaluates inline DLP policy rules according to rule order, with the evaluation stopping at the first match; if Evaluate All Rules mode is enabled for the organization, it evaluates all rules and enforces the rule with the most restrictive action, using rule order only when multiple rules with the same action are matched. [zia.dlp.runbook.web-dlp-triage:evaluation-mode]

**Did the transaction match.** The runbook says to look at the Web Insights logs for the Blocked Policy Type value and the Allowed DLP Rule Name for the reported transaction, and that if the Blocked Policy Type and Allowed DLP Rule Name isn't None the request matched the DLP policy; if the web transaction is not visible in the Internet & SaaS Web Insights logs, it is possible that the transaction is not reaching Zscaler. [zia.dlp.runbook.web-dlp-triage:log-fields-and-match] [divergence:zia.dlp.runbook.web-dlp-triage:match-rule-none-values] In the runbook's Web Insights examples, rows with Blocked Policy Type Data Loss Prevention show a Blocked Policy Name (DLP_Block_SSN, DLP_Password, DLP_NRIC_SEA) with DLP Engine and DLP Dictionaries values; the DLP_Password and DLP_NRIC_SEA rows show Allowed DLP Rule Name None and the DLP_Block_SSN row shows DLP_Pre724_otherDoc. [zia.dlp.runbook.web-dlp-triage:log-examples]

**SSL inspection and exemptions.** The runbook checks that SSL inspection is enabled if the traffic is HTTPS and, under Policies > Data Protection > Common Resources > Advanced Settings, whether the request traffic is included in the Cloud App & URL Exceptions for DLP configuration: Exempted Cloud Applications, Exempted URLs, Exempted User-Defined URL Categories, and Exempt URL Encoded Data (bypasses scanning content type application/x-www-form-urlencoded); it says these configurations are a global setting. [zia.dlp.runbook.web-dlp-triage:ssl-and-exemptions]

**EDM, IDM and OCR settings.** In Advanced Settings, the runbook says Exact Data Match > Check for Popular Formats, when enabled, reduces false positives on non-standard formats; that Exact Data Match (EDM) and Indexed Document Match (IDM) require the Advanced DLP suite; and that the Optical Character Recognition (OCR) settings are enabled to apply DLP policy on image files. [zia.dlp.runbook.web-dlp-triage:edm-ocr-settings]

**Rule criteria.** To check whether a transaction matches a DLP rule, the runbook lists source-related criteria (Users, Groups, Departments, User Risk Profile, Locations, Location Groups, Source IP Groups), destination-related criteria (URL Categories, Cloud Applications, Cloud Application Instances, Private Access Application Segment) and other criteria (Time, Protocols, File Type, Data Size (KB)); the DLP policy applies AND logic to the URL Categories and Cloud Applications fields. [zia.dlp.runbook.web-dlp-triage:rule-criteria] [divergence:zia.dlp.runbook.web-dlp-triage:websocket-protocol-scope]

**Engines and dictionaries.** If Content Matching is enabled, the runbook says to record which DLP Engines are selected, view each engine and take a screenshot or record the Expression Preview, and check the settings and values in each related DLP Dictionary, noting for a Predefined Type the Confidence Score Threshold and Proximity Length and special configurations like Custom High Confidence Phrases. [zia.dlp.runbook.web-dlp-triage:engine-dictionary-check] If the current DLP Notification Template does not include "${DLPTRIGGERS}", the runbook says to create a new template in the Message as HTML section, and its example HTML message includes ${ENGINES_IN_RULE} for the Triggered DLP Violation Engines (assigned to the hit rule) and ${DLPTRIGGERS} for the DLP Triggers match. [zia.dlp.runbook.web-dlp-triage:notification-template-dlptriggers] [gap:zia.dlp.runbook.web-dlp-triage:confidence-and-proximity-values]

**Single or multipart POST.** If no issue is found in the DLP Engines or DLP Dictionaries, the runbook says to check whether the content is POST using single or multipart form submission; in a multipart payload upload the data is divided into multiple parts with their own headers and boundaries, each part is evaluated against Zscaler's DLP rules, and part of a multipart/form-data payload submission might hit the DLP rule. [zia.dlp.runbook.web-dlp-triage:multipart]

Sources disagree (name both sides):
- The runbook says a request matched the DLP policy if the Blocked Policy Type and Allowed DLP Rule Name aren't None, while its own example rows show matches with one of the two None. [divergence:zia.dlp.runbook.web-dlp-triage:match-rule-none-values]
  - zscaler-help: A request whose Blocked Policy Type and Allowed DLP Rule Name aren't None matched the DLP policy.
  - zscaler-help: The DLP_Password row has Blocked Policy Type Data Loss Prevention with Allowed DLP Rule Name None, and the DLP_Block_SSN row has Blocked Policy Type Data Loss Prevention with Allowed DLP Rule Name DLP_Pre724_otherDoc.
  Impact: The Allowed DLP Rule Name field applies only to Allow rules, not Block, and logging it needs Zscaler Support, per the NSS web log format article, so None in either field is not proof that no rule matched. The DLP_Block_SSN row shows both a block and an Allowed DLP Rule Name. Do not tell an admin that a None value means no match without checking the rule action.
- The runbook notes WebSocket Protocol is now supported in the DLP rule, while the Evaluate All Rules article says the WebSocket protocol is supported only for the Microsoft Copilot application. [divergence:zia.dlp.runbook.web-dlp-triage:websocket-protocol-scope]
  - zscaler-help: WebSocket Protocol is now supported in the DLP rule, with no application limit stated.
  - zscaler-help: The WebSocket protocol is supported only for the Microsoft Copilot application.
  Impact: The runbook gives no scope for its note and the other article gives no date. Do not say WebSocket DLP applies to all applications or only to Copilot without naming the page; see [[zia.dlp.rules]].
