# File Type Control runbook: archives blocked by inner file type, the Malware Protection Unscannable Files override, and misidentified file types (zia.file-type-control.runbook.misdetection-and-overrides)
Also called: archive files blocked despite allow policy; not allowed to upload/download unscannable file formats

**Archives.** When users report that archive files (e.g., ZIP) are blocked despite having an allow policy, the runbook says the contents in the archive might trigger policy rules: Zscaler uses deep packet inspection to analyze files inside archives, and if a blocked file type (e.g., an image file) exists within the archive, the entire archive is blocked, which is confirmed using the Web Insights Logs under the Blocked Policy Name field. [zia.file-type-control.runbook.misdetection-and-overrides:archive-blocked-by-inner-type] For the goal of blocking image files while allowing archive files, the runbook's example configures a policy to block image files first, followed by an allow rule for archive files, and says that in this case a ZIP file containing blocked file types (e.g., images) is blocked by the image file rule; it says any priority rule blocking access to the actual file inside the archive blocks the connection, and to ensure rules blocking the specific inner file types are deprioritized after the allow rule for archives. [zia.file-type-control.runbook.misdetection-and-overrides:archive-rule-order]

**Unscannable Files override.** Even if a file type (e.g., .bz2) is allowed by a File Type Control policy, users can encounter a block message stating Not allowed to upload/download unscannable file formats, because Zscaler Malware Protection > Unscannable Files Block settings take precedence over File Type Control policies; if the Malware Protection setting is configured to block unscannable files, it overrides File Type Control allow rules. [zia.file-type-control.runbook.misdetection-and-overrides:unscannable-precedence] The runbook lists these causes of unscannable files: Unrecognized file format (malformed, truncated, or encrypted files), Excessive file size (files, e.g., Microsoft Office documents, exceeding specific size limits, such as 400 MB), and Excessive compression (files compressed or archived more than 5 times). [zia.file-type-control.runbook.misdetection-and-overrides:unscannable-causes] [gap:zia.file-type-control.runbook.misdetection-and-overrides:unscannable-size-rule] [divergence:zia.file-type-control.runbook.misdetection-and-overrides:oversize-precedence] To fix an unscannable block, the runbook says to review the Web Insights Logs to confirm Blocked Policy Type as Malware Protection, go to Policies > Cybersecurity > Malware Protection > Security Exceptions, add the specific URLs under Do Not Scan Content from these URLs, and test and confirm that the file is uploaded or downloaded. [zia.file-type-control.runbook.misdetection-and-overrides:unscannable-fix]

**Misidentified file types.** A Dynamic Link Library (.dll) file might be detected as an .exe file, resulting in a block if .exe files are restricted; the runbook says Zscaler does not solely rely on file extensions to identify file types and instead validates the true file type by analyzing the file signature. [zia.file-type-control.runbook.misdetection-and-overrides:misidentified-type] The runbook lists these causes: Mismatch Between File Extension and True File Type, where the file extension was renamed manually without altering the file’s contents, corrupted or incomplete files that could have been partially overwritten, leading to incorrect magic bytes, and website-specific behaviors where some websites can use non-standard file naming conventions or mechanisms. [zia.file-type-control.runbook.misdetection-and-overrides:misidentification-causes] To identify a file's true type the runbook says it can analyze its hex signature on a Linux OS, using a file utility to confirm the true file type; it then says to compare the identified file type with the policy rules and, if the true type is blocked due to policy restrictions, to modify the File Type Control policy specific to this domain or file type, if appropriate, or contact the destination vendor for clarification and identifying the mismatch between the file signature and file extension. [zia.file-type-control.runbook.misdetection-and-overrides:true-type-check]

Sources disagree (name both sides):
- The File Type Control runbook lists excessive file size as a cause of unscannable files and says a Malware Protection setting that blocks unscannable files overrides File Type Control allow rules, while the security policies runbook says an over-limit file whose type the service can identify is allowed or blocked by File Type Control policy. [divergence:zia.file-type-control.runbook.misdetection-and-overrides:oversize-precedence]
  - zscaler-help: Excessive size makes a file unscannable, and a Malware Protection block on unscannable files overrides File Type Control allow rules.
  - zscaler-help: An over-limit file whose type the service can identify is allowed or blocked based on File Type Control policy.
  Impact: Neither page reconciles the two. Do not say an oversize file is blocked as unscannable, or is decided by File Type Control, without naming both pages; the earlier File Type Control pipeline gap on files above 400 MB is not answered by either.
