# Sandbox rules: first-time file behavior and the default rule (zia.sandbox.rules)
Also called: sandbox rule; sandboxRules; firstTimeOperation; ALLOW_SCAN; byThreatScore; Default BA Rule; sandbox rule order 127; AI instant verdict

Sandbox rules decide what happens to a file the engine has not seen before, which is what makes them the lever for quarantine problems ([Files stuck in Sandbox quarantine](kb:zia.sandbox.quarantine)). A rule's action, `baRuleAction`, is ALLOW or BLOCK. [zia.sandbox.rules:ba-rule-action] `firstTimeEnable` says whether a First-Time Action is configured, and `firstTimeOperation` is what happens when users download an unknown file for the first time: ALLOW_SCAN, QUARANTINE, ALLOW_NOSCAN or QUARANTINE_ISOLATE. [zia.sandbox.rules:first-time-operation] The console's "Allow and Scan" first-time action corresponds to `firstTimeOperation = ALLOW_SCAN`, so the quarantine remedy for dynamic-hash files can be configured through the API. [zia.sandbox.rules:allow-and-scan-is-allow-scan]

**Detection options.** `mlActionEnabled` turns on the AI Instant Verdict option, which has the service use AI analysis to assign threat scores to unknown files. It is available only with specific first-time actions such as Quarantine and Allow and Scan. [zia.sandbox.rules:ml-action] `byThreatScore` is a minimum threat score that can be set between 40 and 70. [zia.sandbox.rules:threat-score-range]

**Scope.** A rule is scoped by threat categories (`baPolicyCategories`, for example ADWARE_BLOCK, BOTMAL_BLOCK, RANSOMWARE_BLOCK, SUSPICIOUS_BLOCK), file types (`fileTypes`), URL categories, users, groups, departments, locations, location groups, time windows, Client Connector devices and device groups, and ZPA Application Segments, which apply only to the ZPA Gateway forwarding method; the rule also carries `labels`. [zia.sandbox.rules:scope-fields] If Internet & SaaS inspects Private Access traffic, uploads to Private Access assets are sandboxed when the file is unknown to the service. [zia.sandbox.rules:zpa-uploads] Which file types exist for the tenant's tier is in [What Sandbox analyzes and why a file may not be](kb:zia.sandbox.coverage).

**Order.** Sandbox rules are evaluated in ascending numerical order, and `order` sets the position of the rule. [zia.sandbox.rules:rule-ordering] Whether the first matching rule decides or later rules also apply is open [gap:zia.sandbox.rules:first-match-semantics].

**Default rule.** The Terraform provider identifies the default Sandbox rule by `order == 127` or the name "Default BA Rule". It skips that rule when computing the next order, removes it from state on read "to prevent drift", and filters it out of rule lists. The API model carries a `defaultRule` boolean. [zia.sandbox.rules:default-rule-marker] The default rule is always the last rule checked, and rules are applied in rule order from first to last. [zia.sandbox.rules:default-rule-last] The provider hard-codes 127 for it, and whether the API reserves that slot is open [gap:zia.sandbox.rules:default-order-semantics]. Reorder handling in the provider is in [How the ZIA Terraform provider applies rule order](kb:zia.terraform.rule-order), and the update path that indexes an empty rule list is in [When the ZIA Terraform provider reports success after an error, or crashes](kb:zia.terraform.error-handling).

**Through the API.** The Python SDK has full CRUD for sandbox rules (`list_rules`, `get_rule`, `add_rule`, `update_rule`, `delete_rule`) over /sandboxRules, and its rule model carries `firstTimeEnable`, `firstTimeOperation`, `mlActionEnabled` and `byThreatScore`, as the Go SDK's does. [zia.sandbox.rules:python-crud] First-time behavior (`firstTimeEnable`, `firstTimeOperation`) is configurable through either SDK. [zia.sandbox.rules:first-time-configurable-both-sdks]

**Criteria in the console.** Adding rules to the Sandbox policy requires Advanced Sandbox; with it, different rules can apply to different sets of users or locations. [zia.sandbox.rules:advanced-needed-for-rules] A Sandbox rule matches on the expression File Types AND [URL Categories OR Sandbox Categories] AND [Users OR Groups OR Departments] AND [Location Groups OR Locations] AND Protocols AND ZPA Application Segment. [zia.sandbox.rules:criteria-expression] Whether the console offers the time and device fields that the API model carries is open [gap:zia.sandbox.rules:time-device-criteria]. On a Sandbox rule, Users, Groups, Departments, Locations and Location Groups each take up to 32 values, and an empty field is Any (applies to all). Zscaler Support can raise the user, group, department and location limits. A rule that applies to unauthenticated traffic must apply to all groups and departments. [zia.sandbox.rules:identity-location-caps] The ZPA Application Segment criterion takes up to 255 Private Access application segments and lists only segments with Source IP Anchoring enabled; no value ignores the criterion. Choosing Inspect App Segments applies the rule to all Private Access segments paired to the Internet & SaaS tenant, an option available only if SIPA App Segments is enabled for the organization. [zia.sandbox.rules:zpa-segment-criterion] The Sandbox Categories criterion offers six malicious file types: Sandbox Adware, Sandbox Malware/Botnet (a catchall for malicious files outside the other categories), Sandbox P2P/Anonymizer, Sandbox Offsec Tools, Sandbox Ransomware and Sandbox Suspicious (files that show some malicious behaviors but are not fully classified as malware). [zia.sandbox.rules:sandbox-categories] A Sandbox rule's Protocols criterion is FTP over HTTP, HTTP, HTTPS (HTTP downloads encrypted by SSL/TLS) or Native FTP. Its URL Categories criterion is Any when empty and can also take custom TLD categories. [zia.sandbox.rules:protocols-and-url-categories]

**Actions in the console.** A Sandbox rule's console actions include Action for Subsequent Downloads (files the Sandbox already analyzed), which is Allow or Block; Block shows a block notification and prevents the download of a malicious file. First-Time Action (unknown files) is Allow and scan (download allowed, file sent for behavioral analysis, a patient 0 event if found malicious), Allow and do not scan (download allowed, file not sent) or Quarantine (file held during analysis behind a quarantine notification, then downloadable if safe and blocked if unsafe). [zia.sandbox.rules:console-actions] The API's QUARANTINE_ISOLATE value has no console description in these pages [gap:zia.sandbox.rules:quarantine-isolate-console]. AI Instant Verdict can be enabled when First-Time Action is Quarantine or Allow and Scan. A file the AI analysis scores above 90 is treated as high-confidence malicious and blocked; a score of 70 to 90 under an Allow and scan rule sends the file to quarantine for further analysis, after which Action for Subsequent Downloads decides. On the default rule the field cannot be modified. [zia.sandbox.rules:ai-instant-verdict-thresholds] Minimum Threat Score (40 to 70) is available when the rule selects the Sandbox Suspicious category and First-Time Action is Quarantine; files below the value are allowed to download. Without it, Sandbox Suspicious files are blocked by default, and with Action for Subsequent Downloads set to Block, known Sandbox Suspicious files are blocked immediately unless the minimum score lets them through. [zia.sandbox.rules:minimum-threat-score-conditions] No end user notification is shown for Allow on Action for Subsequent Downloads (a known-malicious file downloads), for Allow and do not scan, or for Allow and scan. Block on Action for Subsequent Downloads shows the block EUN, which is customized on the End User Notifications page under Security Violation Notifications. [zia.sandbox.rules:allow-and-block-eun]

**Order and status in the console.** Sandbox rules are evaluated in ascending numerical order; with Admin Rank enabled the admin's rank bounds the rule order values that can be chosen. A disabled rule is not enforced but keeps its place in the order and is skipped. A rule needs a unique name and its description cannot exceed 10,240 characters. [zia.sandbox.rules:order-status-details]

**Default and recommended rules in the help.** The default Sandbox rule cannot be deleted, and Zscaler recommends not changing it. Its Rule Status (enabled and enforced), Rule Label, ZPA Application Segment and Action for Subsequent Downloads (Block by default; Allow lets malicious files download but logs them) can be changed; its File Types, URL Categories, Protocols and First-Time Action cannot. [zia.sandbox.rules:default-rule-editable-fields] The default rule analyzes Windows executables and Windows library files, also inside ZIP archives, downloaded from URLs in Suspicious Destinations, and applies to the Sandbox Adware, Sandbox Malware/Botnet and Sandbox P2P/Anonymizer categories over the protocols the page lists. [zia.sandbox.rules:default-rule-criteria] The help pages disagree on how many Sandbox categories the default rule covers [divergence:zia.sandbox.rules:default-rule-categories], and the other side is [The default Sandbox rule analyzes Windows executable and library files of 2 MB or less downloaded from suspicious URL categories (including Anonymizer, FileHost, Shareware Download, Web Host and Miscellaneous or Unknown), also when they are inside ZIP archives. A file the service has never seen is allowed and sent to the Sandbox engine; malicious Adware, Malware & Botnets and P2P & Anonymizers files are blocked.](kb:zia.sandbox.coverage:help-default-rule). Advanced Sandbox ships three deactivated default rules meant as a starting point: Sandbox_Docs_Trusted (rule order 1; Microsoft Office group and PDF; First-Time Action Allow & Scan; intended for a custom URL category of trusted sites the admin creates and adds), Sandbox_Docs_Archives (order 2; Office, PDF and Archives groups; Quarantine; for all URL categories other than that trusted-sites category) and Sandbox_Exes_Web (order 3; Executable and Web Content groups; Quarantine). Each has admin rank 7, all Sandbox categories, all four protocols, AI Instant Verdict enabled and Block for subsequent downloads. [zia.sandbox.rules:advanced-default-rules] Zscaler recommends configuring the Sandbox policy according to the organization's tolerance: low tolerance for downloading malware suggests Quarantine as First-Time Action on a majority of URL categories; low tolerance for download delays and end-user interruptions from quarantining files suggests Allow and Scan on all or a majority of URL categories; and, under Low Tolerance for Suspicious Files, a low tolerance for miscellaneous files employees might want to download or install suggests Allow and Scan on a variety of file types including Archives, Executables and PDF files. [zia.sandbox.rules:tolerance-recommendations]
