# CrowdStrike and Microsoft Defender for Endpoint integrations and the endpoint hits reports (zia.sandbox.edr-integrations)
Also called: crowdstrike integration; microsoft defender for endpoint integration; endpoint hits report; view crowdstrike endpoint hits; edr integration; contain endpoint

The EDR integrations extend Sandbox detections to the endpoints exposed to the malicious file. The CrowdStrike integration leverages CrowdStrike APIs to provide endpoint detection and response (EDR) visibility for Sandbox-detected malware: after it is configured the service calls the CrowdStrike Falcon API and requests information for endpoints exposed to the malicious file, and CrowdStrike uses the new file signature to detect compromised points throughout the organization's network. Information about the affected endpoints is in the Sandbox logs and reports of the Admin Console. [zia.sandbox.edr-integrations:what-crowdstrike] The Microsoft Defender for Endpoint integration leverages Microsoft Defender for Endpoint APIs to provide EDR visibility for Sandbox-detected malware: when configured the service calls the Defender API and requests information for endpoints exposed to the malicious file. Endpoints can also be isolated, automated investigation and remediation (AIR) started and malicious file executions stopped from the Admin Console, and the service creates an indicator of compromise (IOC) in Defender to prevent future executions of the file. [zia.sandbox.edr-integrations:what-defender]

**CrowdStrike setup.** The CrowdStrike integration requires CrowdStrike Falcon, a CrowdStrike admin account with the Falcon Administrator role and Zscaler Advanced Sandbox. The API client's scopes are Detections read only, Hosts read and write and IOCs (Indicators of Compromise) read only; the client secret cannot be retrieved later. The API Auth FQDN is typically api.crowdstrike.com, and only alphanumeric symbols are accepted for the Customer ID, with any dashes removed. [zia.sandbox.edr-integrations:crowdstrike-prereqs-and-credentials]

**Microsoft Defender for Endpoint setup.** The Microsoft Defender for Endpoint integration requires a Defender for Endpoint admin account, able to grant the required permissions (a global admin account or any admin account with that ability), and Zscaler Advanced Sandbox. After authorization the Zscaler SaaS Connector and Directory (Tenant) ID appear. [zia.sandbox.edr-integrations:defender-prereqs]

**Endpoint hits reports.** After the Sandbox analyzes a file, clicking the MD5 hash offers View CrowdStrike Endpoint Hits or View Microsoft Defender Endpoint Hits. The CrowdStrike report shows the file's Sandbox Category (Sandbox Malware/Botnet, Sandbox P2P/Anonymizer or Sandbox Adware), Sandbox Score, Threat Name, File Type, File Size, MD5, SHA-1, SHA-256 and SSDEEP, then per endpoint the CrowdStrike Agent ID, Hostname, Internal IP, External IP, OS Version, First Seen, Last Seen, File Status and Endpoint Status; the Defender report names its identifier Microsoft Defender Agent ID. The page lists uses as tracing patient 0 events if the service is configured to allow unknown files while sandboxing, threat hunting, and incident responses from an infection caused by lateral movement or an out-of-band channel (for example USB). [zia.sandbox.edr-integrations:endpoint-hits-report] In the CrowdStrike report File Status is Seen (the CrowdStrike Falcon agent saw the file on the host), Detected (it triggered a detection based on a process or operation associated with the file) or Prevented (it blocked such a process or operation). Endpoint Status is Normal (active and not quarantined), Contained (quarantined), Containment Pending (being quarantined) or Lift Containment Pending (being removed from quarantine). Contain calls the CrowdStrike API to quarantine the endpoint and appears only if the endpoint status is Normal. [zia.sandbox.edr-integrations:crowdstrike-statuses] In the Microsoft Defender report File Status is Seen, Detected, Quarantined (the agent stopped the ongoing processes of the file and removed it from the host) or Remediated (the agent used automated investigation and remediation (AIR) to remediate the file). Endpoint Status is Active (not quarantined) or Isolated (quarantined). Isolate appears only if the endpoint status is Active; Stop Current Executions stops ongoing processes of the file on the endpoint, Trigger Alert & Start AIR triggers an alert and starts AIR, and Prevent Future Executions stops future processes of the file on all endpoints. [zia.sandbox.edr-integrations:defender-statuses]

**Open points.** What cadence the endpoint hits are refreshed at, and what is audited in ZIA, is open [gap:zia.sandbox.edr-integrations:edr-cadence-audit].

What to check:
1. Whether the tenant has Advanced Sandbox and the partner product before expecting an endpoint hits report.
2. Whether a Contain or Isolate action is available, since each appears only for an endpoint in the Normal or Active status.
