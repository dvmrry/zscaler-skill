# QUIC and HTTP/3 behind ZIA: where it escapes and how to block it (zia.saas-apps.quic-conferencing)
Also called: quic bypasses inspection; http/3 zscaler; block quic firewall rule; udp 443 z-tunnel 1.0; z-tunnel 2.0 quic; teams webex media quality zscaler; chrome quic certificate error

QUIC (HTTP/3 over UDP, see [SaaS apps that break or misbehave behind ZIA](kb:zia.saas-apps) for the other causes) is the reason an app can seem to ignore SSL inspection: SSL/TLS Inspection needs TCP session information, and QUIC does not use TCP. The headline fact, that Zscaler recommends blocking QUIC so the browser falls back to TCP, is in [What SSL/TLS inspection cannot inspect: pinned apps, client certs, QUIC, BYOD, IoT](kb:zia.ssl-inspection.uninspectable). Zscaler cannot examine QUIC sessions when SSL/TLS Inspection is on, and users may also see certificate errors when QUIC is used. [zia.saas-apps.quic-conferencing:cert-errors]

How to block it depends on how the traffic reaches Zscaler ([Where the firewall sits in the traffic path](kb:zia.firewall.traffic-path) covers the firewall path).

- **GRE, IPSec or Client Connector with Z-Tunnel 2.0:** For traffic arriving through a GRE or IPSec tunnel, or Client Connector with Z-Tunnel 2.0, QUIC is blocked with a Firewall Filtering rule on the QUIC network service, which forces the browser back to TCP 80 and 443. Z-Tunnel 2.0 can send all ports and protocols. [zia.saas-apps.quic-conferencing:tunnel2-firewall-rule] The default Firewall Filtering rule (lowest rank) normally blocks QUIC unless it is specifically allowed, but admin-created permissive rules above it often let QUIC through, so a QUIC block rule may need to precede them. [zia.saas-apps.quic-conferencing:default-rule-blocks] QUIC can use UDP destination port 80 as well as 443, so to include port 80 in the QUIC network service, the predefined network service can be modified or a custom network service configured. [zia.saas-apps.quic-conferencing:udp-80] Rule placement follows the usual firewall order: [Firewall rule order, admin rank and predefined rules](kb:zia.firewall.rule-order).
- **Z-Tunnel 1.0:** If only Client Connector traffic on Z-Tunnel 1.0 (which sends all proxy-aware traffic or port 80 and 443 traffic, depending on the forwarding profile configuration) is sent to Zscaler, or for remote users, the help says to create a block rule on the device firewall for UDP 80 and 443. [zia.saas-apps.quic-conferencing:tunnel1-device-firewall] So when the only traffic sent to Zscaler is Client Connector traffic on Z-Tunnel 1.0, or TCP 80 and 443 over a tunnel, QUIC UDP does not reach Zscaler at all, and no Zscaler Firewall Filtering rule inspects or blocks it. [zia.saas-apps.quic-conferencing:tunnel1-udp-leaves]
- **TCP 80 and 443 only:** If only TCP 80 and 443 go over the tunnel to Zscaler, QUIC is blocked on the branch firewall. [zia.saas-apps.quic-conferencing:tcp-only-branch]
- **Without a firewall change:** QUIC can also be discouraged with a DNS Control rule that blocks the HTTPS resource record type with a Server Failure response, because browsers use those records to choose HTTP/3 and the Zscaler web proxy currently does not support HTTP/3. [zia.saas-apps.quic-conferencing:dns-https-records] The DNS Control mechanics are in [ZIA DNS Control](kb:zia.dns-control).

Conferencing media behavior is open [gap:zia.saas-apps.quic-conferencing:conferencing-media].
