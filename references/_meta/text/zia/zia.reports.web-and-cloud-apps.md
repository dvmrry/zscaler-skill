# Web and cloud app reports: Post-Quantum Cryptography Visibility, Instance and Resource Discovery, and Gen AI Security (zia.reports.web-and-cloud-apps)
Also called: post-quantum cryptography visibility report; PQC visibility report; instance discovery report; resource discovery report; gen ai security report

These are the interactive and console reports that read web traffic for three questions: which TLS key exchange and signature algorithms clients and servers use, which SaaS tenants and resources users reach, and which Gen AI applications and prompts are in use. The report hub is [ZIA reports: which subject describes each report family](kb:zia.reports).

**Post-Quantum Cryptography Visibility.** The Post-Quantum Cryptography page names ML-KEM for key exchange and ML-DSA/SLH-DSA for digital signatures, and says TLS 1.3 can be extended to support ECC, PQC and Hybrid PQC key exchange. [zia.reports.web-and-cloud-apps:pqc-nist] ZIA logs the TLS server's chosen key exchange and signature algorithms and the client's proposals for both SSL-intercepted and bypassed traffic, as the Client Digital Signature Proposal, Client Key Exchange Proposal and the client-side and server-side key exchange and digital signature algorithms. Client key exchange and signature algorithm offers are classified as PQC, Non-PQC, Hybrid or Unknown. [zia.reports.web-and-cloud-apps:pqc-logging] The Post-Quantum Cryptography Visibility Report is at Analytics > Reports > Interactive Reports > Standard Reports > Web Activity > Post-Quantum Cryptography Visibility. [zia.reports.web-and-cloud-apps:pqc-report-location] In the report's PQC vs. Classical Key Exchange chart, the Classical section holds transactions whose Client Key Exchange type is Classical or Unknown, and the PQC section holds those whose Client Key Exchange offer is PQC or Hybrid. [zia.reports.web-and-cloud-apps:pqc-buckets] PQC support requires TLS 1.3 and cannot be negotiated in TLS 1.2 and earlier versions; the report shows TLS versions between the client and the Public Service Edge, and between the Public Service Edge and the server. [zia.reports.web-and-cloud-apps:pqc-tls13] The article names console log columns only, so which web log fields they map to is open [gap:zia.reports.web-and-cloud-apps:pqc-column-fields].

**Instance Discovery and Resource Discovery.** The Instance Discovery Report is enabled by contacting the Zscaler Account team. It discovers corporate and non-corporate tenants of SaaS applications for use in tenant profiles and instance profiles, to enforce control through cloud app control and DLP policies; it shows Google Cloud Platform data by default and can be filtered to the last 1 day, 7 days, 15 days, month or quarter. [zia.reports.web-and-cloud-apps:instance-enable-and-use] The Instance Discovery Report page's table gives the instance levels per application: Microsoft Azure Domain > Tenant > Resource, Google Cloud Platform Organization > Project > Resource, SharePoint Domain > Site, Slack Domain > Workspace, Salesforce and ServiceNow Tenant, and Domain only for Box, Google Drive, Google Gemini, Gmail, OneDrive, Microsoft Outlook, Microsoft Teams and Microsoft Copilot. [zia.reports.web-and-cloud-apps:instance-levels] The Resource Discovery Report page lists level-one Domains for Box, Google Drive, Google Gemini, Gmail, Microsoft Outlook, Microsoft Teams, Microsoft Azure, Microsoft Copilot and OneDrive and level-one Tenants for Salesforce and ServiceNow, and for two-level applications lists Workspaces for Slack, Sites for SharePoint and Tenants for Microsoft Azure. [zia.reports.web-and-cloud-apps:resource-discovery-levels] Azure appears at different levels on the two pages [divergence:zia.reports.web-and-cloud-apps:azure-instance-levels]. On the Resource Discovery Report, View Logs opens the Web Insights Logs page filtered, for Google Cloud Platform for example, on organization ID (App Instance Level 1), project ID (App Instance Level 2) or resource type (App Instance Level 3), depending on the hierarchical level selected. For a resource card the details are shown as <organization ID>/<project ID>/<resource type>, and once an item in a column is selected the CSV export is no longer available for that column. [zia.reports.web-and-cloud-apps:resource-discovery-logs] What else Instance Discovery needs, and what an instance profile is, are open [gap:zia.reports.web-and-cloud-apps:instance-prerequisites].

**Gen AI Security Report.** The Gen AI Security Report can be filtered for the last 1 day, 7 days, 15 days, month or quarter, and classifies the prompts entered into categories using small language models. [zia.reports.web-and-cloud-apps:genai-time-and-slm] View Prompts redirects to Web Insights Logs with the prompt filter Not Null applied, and the View Prompts tab is visible only when the prompt settings are enabled for individual AI applications. [zia.reports.web-and-cloud-apps:genai-view-prompts] The page gives two locations for the prompt settings [divergence:zia.reports.web-and-cloud-apps:genai-prompt-settings-path]. Analyze More filters the data on Policy Actions (All, Allowed, Blocked or Isolated), Application Status (All, Sanctioned or Unsanctioned) and Content Type (DLP Dictionaries, DLP Engines, Document Classification or Prompt Classification), and Create Policy opens the Add AI & ML Rule window. [zia.reports.web-and-cloud-apps:genai-analyze-filters] Gen AI Application Usage and Gen AI Usage Trends show the top 6 Gen AI applications used in the organization, and the report shows the total number of sensitive content items discovered per application, based on DLP engines and DLP dictionaries. [zia.reports.web-and-cloud-apps:genai-top6] The rule side is [AI & ML Applications rules: granular actions, prompt capture, tenant profiles](kb:zia.cloud-app-control.ai-ml-rules); the report's retention is open [gap:zia.reports.web-and-cloud-apps:genai-retention].

What to check:
1. Whether Instance Discovery was enabled through the Zscaler Account team before concluding the report is empty or missing.
2. Which instance levels the application has before reading a level column, and which page the answer quotes, since the Azure levels differ between the Instance and Resource Discovery pages.
3. Whether the traffic was TLS 1.3 before reading a Classical share as a gap in PQC support, since PQC cannot be negotiated in TLS 1.2 or earlier.
4. Whether prompt settings are enabled for the individual AI applications before expecting the View Prompts tab, and which console location the page means.

Sources disagree (name both sides):
- The Instance Discovery Report page gives Microsoft Azure three instance levels, while the Resource Discovery Report page lists Azure among the level-one Domains and under the two-level applications as Tenants. [divergence:zia.reports.web-and-cloud-apps:azure-instance-levels]
  - zscaler-help: The Instance Discovery Report table gives Microsoft Azure the levels Domain, Tenant and Resource.
  - zscaler-help: The Resource Discovery Report lists Microsoft Azure among the Domains for applications with one level, and lists Tenants: Microsoft Azure under Applications Supporting Two Levels of Discovery.
  Impact: How many levels Azure has, and so which columns the Resource Discovery Report shows for it, depends on which page is read, so an answer has to name the page.
- The Gen AI Security Report page names two different places for the prompt settings that make the View Prompts tab visible. [divergence:zia.reports.web-and-cloud-apps:genai-prompt-settings-path]
  - zscaler-help: The prompt settings for individual AI applications are in Data Security > Inline CASB > Advanced Policy Settings.
  - zscaler-help: The prompt settings for individual AI applications are in URL & Cloud App Control > Advanced Policy Settings > Gen AI Prompt Configuration.
  Impact: The same page gives two navigation paths and does not say which is current, so an answer that names a console location has to name both.
