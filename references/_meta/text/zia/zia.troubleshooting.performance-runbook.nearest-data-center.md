# Performance runbook: why a user is not connecting to the nearest data center (MaxMind, subcloud, Auto Geo Proximity) (zia.troubleshooting.performance-runbook.nearest-data-center)
Also called: getGatewayEndpoints; MaxMind geo IP; Auto Geo Proximity flag; geo IP override

**Checking the nearest data center.** To check whether a user is connected to the nearest data center, the runbook uses https://pac.<cloudname>.net/getGatewayEndpoints?srcip=x.x.x.x with the user's egress IP; the output shows the three nearest public data centers, excluding regional surcharge data centers. [zia.troubleshooting.performance-runbook.nearest-data-center:get-gateway-endpoints] The runbook gives incorrect geo IP mapping in MaxMind and incorrect subcloud configuration as reasons a user may not reach the nearest data center. [zia.troubleshooting.performance-runbook.nearest-data-center:not-nearest-causes]

**MaxMind.** Zscaler uses MaxMind for geo IP tagging: Client Connector presents its public egress IP to the PAC server on first turn-on, and the PAC server looks the IP up in MaxMind's database and assigns the nearest data center. [zia.troubleshooting.performance-runbook.nearest-data-center:maxmind-mechanism] If MaxMind maps a user's public IP to an incorrect location, Zscaler cannot return the nearest data center and Client Connector connects elsewhere with suboptimal performance; the runbook checks the egress IP at maxmind.com/en/geoip-demo. [zia.troubleshooting.performance-runbook.nearest-data-center:maxmind-wrong-location] A customer can request a geo IP correction from MaxMind, which performs corrections only twice a week, so the correction may be delayed. [zia.troubleshooting.performance-runbook.nearest-data-center:maxmind-customer-correction] On a customer's request, Zscaler can override the geo IP of an IP address; after a manual override Zscaler stops using the MaxMind geo tags to determine the nearest Zscaler data center and bases the IP mapping on the data from the local database. The request is a Zscaler Support case. [zia.troubleshooting.performance-runbook.nearest-data-center:zscaler-geo-ip-override]

**Subcloud and Auto Geo Proximity.** A subcloud is a subset of public data centers or Private Service Edges to which users can be pointed; the runbook says a misconfiguration can send users elsewhere, that if a subcloud is already provisioned in the Zscaler Admin Console the check is whether the desired data center is part of it, that the App Profile PAC file should have no special statements forwarding a country or egress IP to a specific data center, and that a missing data center or a new subcloud is requested through Zscaler Support with the subcloud name. [zia.troubleshooting.performance-runbook.nearest-data-center:subcloud-checks] A data center with Auto Geo Proximity enabled shows a green checkbox next to its Proxy Hostname on config.zscaler.com; data centers without the flag are not part of ${GATEWAY} and ${COUNTRY_GATEWAY} PAC resolution by default, which applies to a few Regional Surcharge and some newly provisioned data centers. [zia.troubleshooting.performance-runbook.nearest-data-center:auto-geo-proximity] To connect to a data center without the Auto Geo Proximity flag, users must use a subcloud that includes it or add a PAC statement for that data center to the App Profile PAC file; the runbook gives Taiwan to Taipei PAC samples. [zia.troubleshooting.performance-runbook.nearest-data-center:non-proximity-dc-access] If the nearest data center has Auto Geo Proximity enabled but the user still cannot connect to it, the runbook calls MaxMind incorrectly geotagging the IP the most probable cause. [zia.troubleshooting.performance-runbook.nearest-data-center:agp-enabled-not-nearest]

**Country Gateway Variable.** For content localization, users closer to a data center in a neighbouring country should use the Country Gateway Variable to reach an in-country data center if available; it supports auto geo proximity and the subcloud. [zia.troubleshooting.performance-runbook.nearest-data-center:country-gateway-variable]
