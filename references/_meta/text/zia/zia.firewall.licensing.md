# Which firewall features need Advanced Firewall (zia.firewall.licensing)
Also called: basic firewall; standard firewall; advanced firewall; firewall license; firewall tier; user group criteria not available firewall

The firewall comes in a standard and an Advanced tier. Configuring and applying firewall policies based on users, groups, departments or network applications requires Advanced Firewall. [zia.firewall.licensing:identity-and-apps-need-advanced] IPS Control is available only with Advanced Firewall. [zia.firewall.licensing:ips-needs-advanced] A standard-tier tenant can hold Firewall Filtering rules, up to the standard-tier cap. [zia.firewall.licensing:standard-tier-has-rules]

What the API returns when a gated criterion is submitted on the standard tier is open [gap:zia.firewall.licensing:standard-tier-criteria].

**The Standard and Advanced Firewall table.** The Standard and Advanced Firewall table lists firewall policies based on five criteria: Network and Application Services (5-tuple firewall), FQDN Filtering (FQDN and wildcard FQDN), Location Awareness (known locations, sublocations and remote users), User Awareness (users, groups and departments) and Application Awareness (network applications using deep packet inspection). Standard Firewall is Supported with limitations: User Awareness and Application Awareness criteria are not supported and only 10 Firewall Filtering rules are allowed. Advanced Firewall is Supported. [zia.firewall.licensing:capability-table-criteria] In the Standard and Advanced Firewall table, Destination NAT and FTP Traffic Control are Supported on both Standard Firewall and Advanced Firewall. [zia.firewall.licensing:both-tiers] In the Standard and Advanced Firewall table, DNS Security and Control is Supported on Standard Firewall with only 64 rules allowed, and Supported on Advanced Firewall. DNS Tunnel and DNS Application Control is N/A on Standard Firewall and Supported on Advanced Firewall. The DNS Dashboards, Insights, and Logs row is Supported on Standard Firewall with a logging limitation: DNS tunnel and DNS application information are not populated in DNS logs. [zia.firewall.licensing:dns-tiers] The 64-rule DNS figure is attached to different tier names on two pages [divergence:zia.firewall.licensing:dns-64-rules-tier]. In the Standard and Advanced Firewall table, IPS Control, including custom IPS signature rules, and Non-Standard Traffic Redirection are N/A on Standard Firewall and Supported on Advanced Firewall. [zia.firewall.licensing:advanced-only] In the Standard and Advanced Firewall table, Firewall and IPS Dashboards, Insights, and Logs are Supported on Standard Firewall with logging limitations that include full logging for each blocked flow but aggregated logging every 15 minutes for allowed flows. [zia.firewall.licensing:standard-logging] In the Standard and Advanced Firewall table, the Forwarding Control policy (including Source IP Anchoring) is Supported with limitations on Standard Firewall: users, groups, departments, custom application service groups or device groups criteria are not supported in it. It is Supported on Advanced Firewall. [zia.firewall.licensing:standard-forwarding-control] Wildcard FQDN support for non-web traffic requires an Internet & SaaS edition that includes parsing of DNS traffic via DNS Control/Security; the page says this is available across all new Internet & SaaS editions (2023 editions) and earlier editions with Advanced Firewall. Wildcard FQDN match against web traffic (HTTP and TLS/SNI) can function without parsing DNS packets. [zia.firewall.licensing:wildcard-fqdn-edition]

**Other gated features in the help.** [Advanced Firewall is required to identify and control network application traffic using DPI.](kb:zia.firewall.network-applications:dpi-licensing) [Advanced Firewall is required for configuring custom application service groups.](kb:zia.firewall.application-services:custom-licensing) [The DNS Protocol Translation feature of DNS Gateway is available with Advanced Firewall.](kb:zia.dns-control.gateways:translation-licensing) [ECS support requires a subscription that includes advanced functionalities of DNS Control.](kb:zia.dns-control.ecs:subscription) [To evaluate wildcard FQDNs against non-web traffic, Zscaler requires the IP address the FQDN resolves to. The page also says to forward all DNS traffic to the Zscaler service if wildcard FQDNs are configured in policies, and that a subscription or Internet & SaaS (ZIA) edition with DNS Control is required, which it says is included in Advanced Firewall and DNS Control subscriptions and Internet & SaaS editions. Wildcard FQDN matching against web traffic (HTTP and TLS/SNI) can function without meeting these conditions.](kb:zia.firewall.destination-groups:wildcard-nonweb)

The rule cap and the FQDN-per-group cap also differ by tier: [Firewall rule, criteria and group limits](kb:zia.firewall.limits).
