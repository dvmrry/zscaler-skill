# The Virtual Service Edge install sequence on the VM: image, certificate, network, build and verification (zia.virtual-service-edge.bring-up)
Also called: vse install-cert; vse download-build; vse configure-network; vse certificate; vse enforce-password-complexity; vse nitrox; vzen install-cert

The on-VM steps repeat across the platform pages, and each claim here names the page it quotes. The Virtual Service Edge certificate is used to authenticate each Virtual Service Edge instance to the Zscaler cloud, so a certificate is downloaded for each instance added: a cluster of two Virtual Service Edges needs two. The VM is downloaded by clicking Download VM and selecting Virtual Service Edge VM; the Hyper-V page selects Hyper-V VHDX file instead, and tells the reader to contact Zscaler Support for the image if that download fails. [zia.virtual-service-edge.bring-up:vm-and-certificate]

**Login and password.** On the Nutanix page the console login is username zsroot and password zsroot, after which the VM prompts for a new password. `sudo vzen enforce-password-complexity` is optional (the ESXi dual-arm page marks it "(Optional)" for those who want Zscaler to enforce password complexity) and expires the current password; the new one can be a 24-character password with characters from at least three of the listed categories, or a 16-character password containing characters from all the categories, or a passphrase of at least 4 words forming 32 to 40 characters with enough different characters. [zia.virtual-service-edge.bring-up:default-login-and-password-rules] The first-login behavior the cluster article gives is in [Who runs a Virtual Service Edge: access, logging, hardening and monitoring](kb:zia.virtual-service-edge.operations).

**Network.** On the Nutanix page `sudo vzen configure-network` takes the DNS server address, used for name resolution of Zscaler cloud domains and also for domain names in the proxy traffic, and the management interface IP with CIDR netmask used for SSH or FTP; the page then gives a command to verify the configured information. On the AWS page the management IP, the gateway IP for management and the resolvers are obtained from DHCP, and the command does not allow modifying the management IP and gateway IP. [zia.virtual-service-edge.bring-up:configure-network]

**Certificate and build.** On the Nutanix page the certificate bundle is uploaded to the management IP address using SCP, FTP or SFTP and installed with `sudo vzen install-cert <cert-bundle.zip>`, using the absolute file path when not in the file's directory. The initial build is around 1 GB; it is installed automatically and the Virtual Service Edge starts automatically after installation completes. [zia.virtual-service-edge.bring-up:install-cert-and-build]

**Verifying the build.** The pages verify a build differently. On the Nutanix page the status output should show the Virtual Service Edge service and LB running, and `sudo vzen troubleshoot connection | grep 9422` should show an established connection. On the GCP page the checks are that the SME and smcdsc are running, that the authentication state is SMAUTHENG_READY_STATE, that there are two connections over 9442, and that cloud-config and log-stream sessions are present. [zia.virtual-service-edge.bring-up:verify] The commands behind these checks are in [The vzen command line for configuring and troubleshooting a Virtual Service Edge](kb:zia.virtual-service-edge.troubleshooting).

**Cavium NITROX card.** On the ESXi dual-arm page, if the Cavium NITROX card was installed in the server, it is selected in the Mark devices for passthrough window; in the later step that adds the card to the Virtual Service Edge VM, the VM must be powered off. `sudo vzen install-nitrox` is also run. [zia.virtual-service-edge.bring-up:nitrox-install]

The Admin Console steps that precede these are in [The Virtual Service Edge cluster: limits, object, build order and Location binding](kb:zia.virtual-service-edge.clusters), and the per-platform VM requirements are in [Deploying a Virtual Service Edge on Azure, AWS (with or without GWLB) and GCP](kb:zia.virtual-service-edge.cloud-deployment) and [Where a Virtual Service Edge runs and which platforms can cluster](kb:zia.virtual-service-edge.platforms).
