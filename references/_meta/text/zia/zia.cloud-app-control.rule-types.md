# Cloud App Control categories (rule types), limits and predefined rules (zia.cloud-app-control.rule-types)
Also called: cloud app categories; cac rule type; cac rule limit; 127 rules per category; iot classification rules; allow unauthenticated traffic for iot classifications; granular controls categories

Cloud App Control is organised by category, and the category is a rule's type. Cloud applications are organised into 19 categories; 8 of them also support granular controls (the specific actions a user can take within the application), and the other 11 support allow or block per category. [zia.cloud-app-control.rule-types:nineteen-categories] The category names are AI & ML Applications, Collaboration & Online Meetings, Consumer, Custom Applications, DNS Over HTTPS Services, File Sharing, Finance, Health Care, Hosting Providers, Human Resources, Instant Messaging, IT Services, Legal, Productivity & CRM Tools, Sales & Marketing, Social Networking, Streaming Media, System & Development and Webmail. [zia.cloud-app-control.rule-types:category-names]

**Granular controls.** The eight categories with granular controls, and what makes the controls appear, are: AI & ML Applications (ChatGPT or Microsoft Copilot with Application Access Allow), Collaboration & Online Meetings (Microsoft Teams, SharePoint Online, Slack or Webex Meetings with Application Access Allow), File Sharing (all apps; more controls for Box, Dropbox, OneDrive, OneDrive for Business or Google Drive with Viewing Allow), Instant Messaging (all apps with Chatting Allow), Social Networking (all apps; more for LinkedIn with Viewing Allow), Streaming Media (all apps with Viewing/Listening Allow), System & Development (all apps; more for GitHub with Viewing Allow), and Webmail (all apps with Viewing Mail Allow). [zia.cloud-app-control.rule-types:granular-categories] The AI & ML category has its own rule flow and its own granular action list: [AI & ML Applications rules: granular actions, prompt capture, tenant profiles](kb:zia.cloud-app-control.ai-ml-rules). How granular actions appear in the API: [Cloud App Control actions and action discovery](kb:zia.cloud-app-control.actions).

**Limits.** The Cloud App Control rule limit is 127 rules per cloud app category (raisable to 2,048 through Zscaler support), not a tenant-wide cap. [zia.cloud-app-control.rule-types:rule-cap-per-category] Order is also kept per rule type: the provider scopes lists by rule type and registers reorders per type from v4.8.7, see [The ZIA provider's reorder registry: keys, locks and lifecycle across rule resources](kb:zia.terraform.rule-order.registry).

**Predefined rules.** Zscaler ships Allow Unauthenticated Traffic for IoT Classifications predefined rules for each cloud application category. They are disabled by default and cannot be deleted; only Rule Order, Rule Status, Rule Label and Description can be edited. Their purpose is to temporarily allow unauthenticated traffic that other rules could block, so that Zscaler AI/ML can classify devices. [zia.cloud-app-control.rule-types:iot-predefined-rules] Rule order and disabled-rule semantics are in [Cloud App Control versus URL Filtering: which applies](kb:zia.cloud-app-control.precedence).

**What the category pages name.** Four category rule pages name the activities the action applies to: Webmail (Viewing Mail, Sending Mail, and Sending Attachment; Allow or Block for Sending Mail and Sending Attachment), Social Networking (Viewing and Posting; Allow or Block for Posting), Streaming Media (Viewing/Listening and Uploading) and System & Development (Viewing and Uploading, with the label "You can only choose Allow or Block"). [zia.cloud-app-control.rule-types:action-labels-by-category] System & Development's label says only Allow or Block is available, while its own page goes on to describe other actions [divergence:zia.cloud-app-control.rule-types:system-development-allow-block-only]. The Custom Applications rule page says cloud applications that do not belong to any of the predefined categories can be added to the Custom Applications category, in two parts: adding the application to Zscaler for discovery and usage metrics if it is not already present, and associating it with the Custom Applications for Cloud App Control rule. [zia.cloud-app-control.rule-types:custom-applications-category] The category rule pages name example applications: Consumer (eBay, Groupon, PayPal), Finance (American Express at Work, Blockchain, J.P. Morgan), Health Care (American Medical, eClinicalWorks, WonderDoc), Human Resources (BambooHR, Jobvite, Workday), Legal (Amicus Attorney, DirectLaw, Eclipse Legal Systems), Sales & Marketing (Marketo, SuccessFactors), Hosting Providers (AWS, IBM SmartCloud), Productivity & CRM Tools (Salesforce, Evernote, Microsoft 365), IT Services (identity and device management tools such as Okta or AirWatch), DNS Over HTTPS Services (Cloudflare DNS, Google DNS, Quad9) and Collaboration & Online Meetings (Webex, GoTo Meeting, Yammer). These are examples, not category membership lists. [zia.cloud-app-control.rule-types:category-examples]

**Granular actions on the category pages.** The Collaboration & Online Meetings rule page lists granular actions for Webex Meetings (Sharing, Editing, Creating, Downloading, Chatting, Uploading, Inviting, Meeting), Slack (Chatting, Creating, Deleting, Downloading, Editing, Huddle, Inviting, Login, Uploading), Nulab (Login), SharePoint Online (Sharing, Editing, Renaming, Creating, Downloading, Deleting, Uploading) and Microsoft Teams (Chatting, Screen Sharing). A Domain Profiles field for the Login granular action takes up to 8 domain profiles, and selecting no profiles applies the granular action to all the profiles. [zia.cloud-app-control.rule-types:granular-collab] The File Sharing rule page lists granular actions for Box (Creating, Deleting, Downloading, Editing, Inviting, Login, Renaming, Sharing), Dropbox (Creating, Deleting, Downloading, Editing, Inviting, Renaming, Sharing), OneDrive (Creating, Deleting, Downloading, Editing, Renaming, Sharing), OneDrive (Personal) (Creating, Deleting, Downloading, Editing, Renaming) and Google Drive (Creating, Deleting, Downloading, Editing, Form Sharing, Renaming, Sharing). It also says selecting no form applies the granular action to all the forms, and selecting no file applies it to all the files. [zia.cloud-app-control.rule-types:granular-file-sharing] The Social Networking rule page lists granular actions for LinkedIn (Chatting, Commenting, Creating, Editing, Posting, Sharing, Uploading), X (formerly Twitter) (Login) and Facebook (Login). [zia.cloud-app-control.rule-types:granular-social] On the System & Development rule page, the GitHub application supports the additional granular actions Commenting, Creating, Editing, Login, Reaction and Sharing, which can be allowed or blocked; for granular actions to work as expected, SSL/TLS Inspection must be enabled for the application. [zia.cloud-app-control.rule-types:granular-sysdev] On the IT Services rule page, Google Login Services has a Login granular action that applies to Gmail, Google Drive, Google Gemini and YouTube, and the page says up to 8 domain profiles can be selected; Yahoo Login Services has a Login granular action that applies to Yahoo! Mail. If these applications are selected together, only the common granular actions among them appear, and SSL/TLS Inspection must be enabled for the application for granular actions to work as expected. [zia.cloud-app-control.rule-types:granular-it-services] On the Productivity & CRM Tools rule page, the Zendesk application supports a Login granular action, which can be allowed or blocked; for the granular action to work as expected, SSL/TLS Inspection must be enabled for the application. [zia.cloud-app-control.rule-types:granular-productivity] Which categories and applications have granular controls differs between the categories page and the category pages [divergence:zia.cloud-app-control.rule-types:granular-controls-outside-granular-categories] [divergence:zia.cloud-app-control.rule-types:granular-app-lists-by-category]. Which granular actions every application in File Sharing, Social Networking, Streaming Media and System & Development has is open [gap:zia.cloud-app-control.rule-types:granular-all-apps-not-enumerated]. On the Collaboration & Online Meetings rule page, to allow Slack audio and video calls the allow rule must include both Amazon Chime and Slack under Cloud Applications. [zia.cloud-app-control.rule-types:slack-calls-need-chime]

**Tenant Profile and YouTube.** Under the Allow action, a rule's Tenant Profile field appears only when specific applications are selected as the cloud application: Hosting Providers (Amazon Web Services, Google App Engine, Google Cloud Compute, Google Cloud Platform, IBM SmartCloud), Productivity & CRM Tools (Docusign, Google Analytics), IT Services (Google, Microsoft, Webex and Zoho Login Services), File Sharing (Dropbox, Google Drive, Google Photos), Webmail (Gmail), Social Networking (Google+, Google Groups), System & Development (GitHub, Google App Maker, Google Developers), Streaming Media (Google Video, YouTube) and Collaboration & Online Meetings (Google Calendar, Google Keep, Google Meet, Google Sites, Slack, Webex Teams, Webex Meetings, Zoom). [zia.cloud-app-control.rule-types:tenant-profile-field-by-category] How many tenant profiles one rule can take depends on the application. Hosting Providers page: multiple profiles per rule for Google Cloud Platform only if the Allow Cloud Storage Resources field selection is the same for the profiles. IT Services page: under Version 1, multiple profiles per rule only if the tenant directory ID and the Allow Personal Office 365 Domains field selection are the same for the profiles; under Version 2, only one profile per rule. System & Development page: for GitHub, only one tenant profile. [zia.cloud-app-control.rule-types:tenant-profile-multi-profile-limits] On the Hosting Providers page the applications selected under the tenant profiles must not be exempted from SSL Inspection, and on the Productivity & CRM Tools page Docusign and Google Analytics must not be exempted from SSL/TLS Inspection. [zia.cloud-app-control.rule-types:tenant-profile-ssl-exemption] On the Streaming Media rule page, a rule allowing specific YouTube channels, categories or both through tenant profiles does not mean other YouTube channels and categories are blocked; blocking them takes a separate rule that blocks YouTube. Access to certain content might be blocked even though it seems to belong to an allowed YouTube category, because YouTube might categorize that content under other categories. [zia.cloud-app-control.rule-types:youtube-tenant-profile-caveats] Zscaler supports YouTube for Schools, which lets schools access educational videos on YouTube EDU and specify which videos students may access. For example, a Streaming Media rule can allow YouTube access to students and associate a tenant profile with the YouTube School ID; when a student makes an HTTP request to YouTube, the cloud inserts a custom header with the school's ID. Internet & SaaS (ZIA) logs YouTube for Schools transactions separately from YouTube transactions, and the transactions log shows YouTube EDU in the Application field. [zia.cloud-app-control.rule-types:youtube-for-schools]

**Rule fields shared by the category pages.** On the Consumer, Instant Messaging and AI & ML rule pages, a rule's name must be unique or the default name, and its optional description cannot exceed 10,240 characters. [zia.cloud-app-control.rule-types:description-length]

Sources disagree (name both sides):
- Whether IT Services and Productivity & CRM Tools have granular controls [divergence:zia.cloud-app-control.rule-types:granular-controls-outside-granular-categories]
  - zscaler-help: The categories page lists IT Services and Productivity & CRM Tools under the categories with the allow or block options, not under those with granular controls (capture 2026-10-18).
  - zscaler-help: The IT Services rule page gives Google Login Services and Yahoo Login Services a Login granular action.
  - zscaler-help: The Productivity & CRM Tools rule page gives Zendesk a Login granular action that can be allowed or blocked.
  Impact: An answer about which categories can be controlled per action should not rely on the categories page alone; it counts 8 categories with granular controls (claim nineteen-categories), while these two pages describe a Login granular action for IT Services and Productivity & CRM Tools.
  Resolved (source-rank) by zia.cloud-app-control.rule-types:granular-it-services: The category rule pages are the more specific pages and were updated after the categories page; the categories page may be stale. Whether Zscaler counts Login as a granular control is not stated.
- Which applications in Collaboration & Online Meetings, Social Networking and File Sharing have granular controls [divergence:zia.cloud-app-control.rule-types:granular-app-lists-by-category]
  - zscaler-help: The categories page names Microsoft Teams, SharePoint Online, Slack and Webex Meetings for Collaboration & Online Meetings; LinkedIn for extra controls in Social Networking; and Box, Dropbox, OneDrive, OneDrive for Business and Google Drive for extra controls in File Sharing, with Viewing set to Allow (capture 2026-10-18).
  - zscaler-help: The Collaboration & Online Meetings rule page also lists a Login granular action for Nulab.
  - zscaler-help: The Social Networking rule page also lists a Login granular action for X (formerly Twitter) and for Facebook.
  - zscaler-help: The File Sharing rule page names OneDrive and OneDrive (Personal), not OneDrive for Business, and labels the action Application Access where the categories page says Viewing.
  Impact: An answer about which applications in these categories have granular controls, or which activity the action's Allow gates, should not rely on one page alone.
  Resolved (source-rank) by zia.cloud-app-control.rule-types:granular-collab: The category rule pages are the more specific pages, so their application lists are preferred for those applications; the categories page's list of conditions for granular controls remains stated in claim granular-categories.
- Which actions a System & Development rule offers [divergence:zia.cloud-app-control.rule-types:system-development-allow-block-only]
  - zscaler-help: The System & Development page's Actions label says only Allow or Block can be chosen for Viewing and Uploading.
  - zscaler-help: The same Actions section then describes Caution, Conditional and Isolate.
  Impact: The page does not say whether the Allow or Block restriction covers Viewing, Uploading or both; Social Networking and Webmail scope the same wording to one activity (claim action-labels-by-category). An answer about System & Development actions should not state one side as settled.
