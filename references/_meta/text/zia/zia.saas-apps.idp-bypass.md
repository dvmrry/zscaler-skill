# Login and MFA endpoints: inspect, bypass or exempt from authentication (zia.saas-apps.idp-bypass)
Also called: duo through zscaler; mfa endpoint ssl bypass; idp ssl bypass; duosecurity.com bypass; entra external mfa duo; auth exemption versus ssl bypass; login.windows.net exempt

For identity and MFA endpoints (see [SaaS apps that break or misbehave behind ZIA](kb:zia.saas-apps) for the other causes) the question is whether the traffic must be decrypted (a control needs to read or edit it) or must not be (the client refuses the certificate).

**Must be inspected.** Microsoft login hosts need decryption for tenant restriction, and the SSL rule that selects them has to win the order: [Tenant restriction does nothing: bypass rule ahead of the login inspection rule](kb:zia.saas-apps.tenant-restriction-order); the hosts and headers are in [How a tenant profile is enforced: the headers ZIA inserts](kb:zia.tenant-profiles.wire-mechanic). Webex Login Services follows the same prerequisite in [SSL/TLS inspection rules a tenant profile depends on](kb:zia.tenant-profiles.ssl-prerequisite).

**Must not be inspected.** A client that pins its own CA bundle cannot be inspected: [What SSL/TLS inspection cannot inspect: pinned apps, client certs, QUIC, BYOD, IoT](kb:zia.ssl-inspection.uninspectable). Which Duo hostnames to bypass is open [gap:zia.saas-apps.idp-bypass:duo-endpoints]. How narrowly to write any such bypass is in [Writing SSL/TLS inspection exemptions without exempting too much](kb:zia.ssl-inspection.exemptions). In the guide's example rule set, the Click-to-Run exemption uses the stronger Bypass Other Policies setting ([Writing SSL/TLS inspection exemptions without exempting too much](kb:zia.ssl-inspection.exemptions), `predefined-exemptions-differ`); whether it is the only such rule is gap `only-bypass-other-policies-rule`.

**Authentication exemptions are a different list.** The authentication exemption list and an SSL Inspection bypass are separate configuration objects with separate effects: an exemption skips the authentication challenge for a destination, while a Do Not Inspect rule skips decryption; exempting a host from one does not exempt it from the other. [zia.saas-apps.idp-bypass:auth-exemption-not-ssl-bypass] Enabling the Microsoft-Recommended One Click option adds one for Microsoft: Enabling the Microsoft-Recommended One Click configuration also makes the Zscaler service configure an authentication exemption for Microsoft domains automatically. [zia.saas-apps.idp-bypass:one-click-auth-exemption] The product-wide 25,000-entry pool the exemption URLs draw on is described in [Destinations that skip authentication](kb:zia.authentication.exemptions); it is shared with custom URL categories and other lists, so it is not an independent 25,000-entry list as the old catalog implied. In the Entra ID SAML and SCIM guide, the Authentication Exemptions section has login.windows.net, login.microsoftonline.com, .windowsazure.com, aadcdn.msauth.net and aadcdn.msftauth.net entered in Exempted URLs. [zia.saas-apps.idp-bypass:entra-login-hosts-exempted] The other typical entries are open [gap:zia.saas-apps.idp-bypass:auth-exempt-login-hosts].
