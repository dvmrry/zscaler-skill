# FTP Control scope, protocols and precedence (zia.ftp-control.scope)
Also called: ftp control scope; ftp location; ftps; ftp malware scan; ftp url filtering precedence; ftp not working from home; remote user ftp

Who and what FTP Control reaches is narrower than the feature name suggests. Work through four questions.

1. **Where is the user?** The FTP Control policy applies to traffic from the known locations of an organization. For a remote user on a dedicated port the service supports FTP over HTTP, and it can scan the content their browser downloads from FTP sites for viruses and spyware. [zia.ftp-control.scope:location-scope] Whether native FTP works for an unlocated user is open [gap:zia.ftp-control.scope:remote-user-native-ftp].
2. **Which protocols?** The service supports FTPS (FTP over TLS) in passive mode, implicit or explicit. Explicit FTPS needs a proxy set in the FTP client. It also supports FTP over HTTPS. [zia.ftp-control.scope:ftps-supported] The service supports passive FTP only. If the destination server does not support passive FTP, the service shows an alert message in the user's browser. [zia.ftp-control.scope:ftp-passive-only] By default the service does not allow users from a location to upload or download files from FTP sites that use FTP over HTTP; only native FTP traffic is allowed. With FTP Control, Zscaler provides access control for both native FTP and FTP over HTTP. [zia.ftp-control.scope:ftp-default] Whether FTP over HTTPS needs decryption for content inspection is open: see gap `ftp-over-https-decrypt`, and check [What stops working when traffic bypasses SSL/TLS inspection](kb:zia.ssl-inspection.bypass-impact).
3. **Does URL Filtering decide first?** FTP Control settings are configured within Firewall: the firewall policy help points to FTP Control for them. [zia.ftp-control.scope:ftp-sits-in-firewall] URL Filtering rules take precedence over the FTP Control policy. [zia.ftp-control.scope:ftp-url-filtering-precedence] User-, department- or group-level URL filtering rules blocking access to specific sites are not enforced for FTP sites, because FTP does not support cookies. Only rules applied to all users are enforced, so a catch-all URL filtering rule that blocks gambling sites also blocks ftp://ftp.site.com. [zia.ftp-control.scope:url-filtering-only-all-user-rules] A user-scoped URL Filtering rule therefore never explains an FTP block; look for an all-users rule in [URL Filtering rule order and first match](kb:zia.url-filtering.rule-order).
4. **What scans the files?** FTP Control extracts files and runs a security scan. DLP, Sandbox, File Type Control, URL Filtering and Bandwidth Control can each be configured by protocol, FTP over HTTP or native FTP, and FTP is logged in full in Firewall Insights. [zia.ftp-control.scope:files-extracted-and-scanned] Scanning of FTP over HTTP and native FTP traffic is enabled or disabled on the Malware Protection page; the FTP Control page allows or blocks that traffic. In Malware Protection, the Protocol Inspection section has Inspect FTP over HTTP and Inspect FTP toggles. Each scans all files, including those with up to 5 layers of recursive compression, in the direction the Traffic Inspection setting selects. [zia.ftp-control.scope:malware-toggles] DLP, Sandbox and File Type Control policies can also be applied to files extracted from FTP and FTP over HTTP. [zia.ftp-control.scope:dlp-sandbox-ftc-on-extracted] File Type Control behavior on those files is in [ZIA File Type Control](kb:zia.file-type-control).

The settings that open FTP at all are in [FTP Control settings and API object](kb:zia.ftp-control.settings).
