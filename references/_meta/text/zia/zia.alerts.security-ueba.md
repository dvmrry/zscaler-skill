# Security & UEBA alerts: ongoing alerts, alert history and alert details (zia.alerts.security-ueba)
Also called: security alerts; ueba alerts; ongoing alerts; alert history; alert summary; alerts dashboard; indexed by

The email alerts are in [ZIA email alerts: event classes, thresholds, severities, subscriptions and the resend interval](kb:zia.alerts). The Security & UEBA alerting framework is a solution to view, manage, create and adjust alert rules. Security alerts constantly filter and evaluate all the logs generated from the organization's traffic to trigger new alerts and provide high-level statistics of each event type and threat severity. UEBA alerts monitor and analyze user activities such as logins, file accesses, data transfers and application usage to detect deviations from normal behavior, and are available for Inline and API channels. [zia.alerts.security-ueba:framework] Alert rules need to be enabled and alert notification delivery set up, by email aliases or webhooks; generated alerts are then investigated by viewing the available widgets or the alert summary table. [zia.alerts.security-ueba:delivery] The rules that raise them are in [Security & UEBA alert rules: alert types, triggers, exceptions and webhooks](kb:zia.alerts.rules).

**Ongoing alerts.** The Ongoing Alerts Overview displays the top 5 threats and event types for each tenant and the number of ongoing alerts, impacted systems, impacted departments and impacted locations. Ongoing alerts can be viewed for a period of 1 hour to 14 days. [zia.alerts.security-ueba:ongoing-overview] In the Alert Summary, Alert ID is the alert ID created by the service, Client IP is the IP address of the client for which the alert is triggered, Client Ext. IP is the internet gateway location IP address, Alert Rule Name is the alert name added during creation of the rule and Department is the department impacted by a particular threat or part of a preconfigured alert. Advanced filters offer Equals, Ends with, Starts with, Contains and the negations Does not equal, Does not start with, Does not end with and Does not contain. The page says the table can be sorted to prioritize incidents based on most impacted users, most blocked transactions or most frequently seen activity, while its Sort By control sorts by the most impacted systems (the default), last known attempt, most allowed transactions or longest duration; the table downloads as a CSV file. [zia.alerts.security-ueba:summary-filters] Indexed By is the unique identifier value by which alerts are indexed for aggregating systems impacted as part of the same incident; all alerts attempt to be indexed by the available threat name or other unique identifiers such as Hostname, Server Destination IP or MD5 hash. Location is the internet gateway location from which the alert originated, and a transaction that did not originate from a location defined in the alert rule is recorded as coming from a remote user. [zia.alerts.security-ueba:indexed-by-and-location]

**Alert history.** The Alert History page displays all alerts whose evaluation status is ended, up to 14 days from the time the status was changed to Ended. The summary table can be customized to show the security alerts or UEBA alerts by selecting Security or UEBA in the Customize View drop-down menu. [zia.alerts.security-ueba:history] How long alerts are kept beyond 14 days is open [gap:zia.alerts.security-ueba:retention].

**Alert details.** A security alert's details show Alert Overview (alert rule name, alert ID, whether the alert applies to the organization or a department, the event type and the type of policy action), Alert Details (first and last attempt, allowed versus total transactions, evaluation status and duration), File Information (file type and sandbox information) and First Destination (destination IP, hostname, URL category, application type, category and risk score), with View All Logs for the Insight Logs of the alert. Impacted Systems shows a breakdown by department and location, with IP addresses, event timestamps and a count of allowed over total transactions, and authenticated users can view additional device, OS and traffic forwarding method metadata. [zia.alerts.security-ueba:security-details] A UEBA alert's Alert Overview shows the alert rule name, alert ID, identified user, type of policy action, event type, associated tenant, start and end time, the timestamp of when the alert was generated, the user risk score and API logs (the SaaS Security Activities Report). Description shows a graph of the sensitive files downloaded by a user, Create Exception adds the user to the alert exception list, and the details can be downloaded as a PDF. [zia.alerts.security-ueba:ueba-details]

**Relation to email alerts.** Whether these alerts share a limit or subscription with the email alerts is open [gap:zia.alerts.security-ueba:shared-limits].

What to check:
1. Whether an alert rule is enabled and has a delivery set up before concluding no alert fired.
2. Whether the alert's age is within the 14 days the ongoing view or history shows, since older alerts are not described.
