# ATP Security Exceptions (the allowlist): what it skips and what it does not (zia.atp.security-exceptions)
Also called: atp allowlist; security exceptions; bypassUrls; atp bypass urls; allowlist cryptomining; exempt from atp; allowlist skips sandbox

Security Exceptions is ATP's allowlist.

Trusted partner or vendor sites whose webmail or file downloads might be blocked by antivirus, anti-spyware or anti-malware policies can be exempted from inspection by adding them to the ATP security exceptions list; users can then download content from those URLs without the traffic being inspected. [zia.atp.security-exceptions:purpose] URLs on the allowlist take precedence over the ATP options on the policy page: an allowlisted URL hosted on a web server in a blocked country is still reachable. [zia.atp.security-exceptions:precedence-over-options] Allowlisted sites are exempted from any form of security scanning, so Zscaler recommends keeping the number of trusted sites on the allowlist to a minimum. Specific cryptomining destinations are a named use of exceptions. [zia.atp.security-exceptions:exempt-from-all-scanning]

**What it skips.** A URL in Security Exceptions makes the Public Service Edge skip the Malware Protection, Advanced Threat Protection and Sandbox policies for that transaction. [zia.atp.security-exceptions:skips-mp-atp-sandbox] Sandbox is in that list, so an exception also changes file-analysis outcomes: [Which engine blocked the file, and what a Sandbox verdict means](kb:zia.sandbox.verdicts). Checks that run before it are not skipped, such as Cloud App Control and URL Filtering ([Where Malware Protection and ATP checks fall in the web enforcement order](kb:zia.atp.enforcement-order)).

**Against the denylist.** The help page and the enforcement-order document disagree [divergence:zia.atp.security-exceptions:allowlist-vs-malicious-url-check]. The denylist is [ATP Blocked Malicious URLs list: capacity, matching and API](kb:zia.atp.blocked-urls), and no source shows what a tenant does with a URL on both lists [gap:zia.atp.security-exceptions:order-vs-allowlist-live].

**One list, two pages.** The allowlist is entered as Do Not Scan Content from these URLs on the Security Exceptions tab of either the Malware Protection or the ATP page, and it also applies to Sandbox. The Malware Protection page says the same allowlist applies to ATP and Sandbox. [zia.atp.security-exceptions:shared-list] On the ATP page's Security Exceptions tab, the Do Not Scan Content from these URLs field takes URLs to allowlist for ATP or URLs not to inspect for ATP, up to 1,024 URLs entered by pressing Enter after each entry. [zia.atp.security-exceptions:atp-tab-url-limit] The allowlist holds up to 1,024 URLs, shows up to 500 items per page, and can be cleared with Remove All or one page at a time with Remove Page. This is far smaller than the 25K Blocked Malicious URLs list. [zia.atp.security-exceptions:allowlist-capacity] The ATP Security Exceptions page's item-list paragraph offers Remove 25K Items, which removes the first 25K items from the list, or Remove Page for one page, and its removal steps offer Remove All for all configured security exceptions; the allowlist page's list controls are Remove All and Remove Page (see allowlist-capacity). [zia.atp.security-exceptions:atp-page-removal] URL Filtering is exempted by a separate procedure from the scan allowlist: the URLs go in a custom URL category with a URL Filtering Allow rule ordered above the rule that blocks them. [zia.atp.security-exceptions:url-filtering-separate] The ATP Security Exceptions page says the allowlist also applies to the Malware Protection and Sandbox policies, and that allowlisting URLs and files completely requires also configuring the URL Filtering, File Type Control and IPS Control policies. [zia.atp.security-exceptions:atp-page-allowlist-scope] The help page also says the allowlist applies to URL Filtering, which the enforcement order contradicts [divergence:zia.atp.security-exceptions:allowlist-vs-url-filtering-order]. The Malware Protection side of the tab is in [ZIA Malware Protection](kb:zia.malware-protection); URL Filtering order is in [URL Filtering rule order and first match](kb:zia.url-filtering.rule-order).

**In the API.** The API object is securityExceptions, whose required bypassUrls array the spec describes as allowlist URLs not inspected by the ATP policy. It is read with GET and written with PUT of the whole list. [zia.atp.security-exceptions:wire-allowlist] The country case is in [ATP Blocked Countries: server location, not user location](kb:zia.atp.blocked-countries).

What to check:
1. Whether the narrowest entry that fixes the case is enough, since an exception hides every ATP and Malware Protection detection for that URL.
2. Whether the URL is also on the denylist, and what the tenant then does with it.

Sources disagree (name both sides):
- Whether the Security Exceptions allowlist applies to URL Filtering. [divergence:zia.atp.security-exceptions:allowlist-vs-url-filtering-order]
  - zscaler-help: The allowlist applies to URL Filtering as well as the security policies.
  - zscaler-help: The ATP allowlist/denylist page says allowlisted URLs are accessible even if they would otherwise be blocked by "other security measures or policies"; it does not name URL Filtering.
  - zscaler-help: The ATP Security Exceptions page says allowlisting URLs and files completely also requires configuring URL Filtering, File Type Control and IPS Control.
  - zscaler-help: URL Filtering is step 3 and Security Exceptions step 4 of the GET request order, so URL Filtering is evaluated before the exception can skip anything.
  Impact: Do not tell an operator that a Security Exceptions entry stops a URL Filtering block; use the custom category and Allow rule procedure.
- Whether an allowlisted URL is still stopped by the Blocked Malicious URLs list. [divergence:zia.atp.security-exceptions:allowlist-vs-malicious-url-check]
  - zscaler-help: The allowlist takes precedence over all the options listed after it, which include Blocked Malicious URLs.
  - zscaler-help: The ATP allowlist/denylist page says allowlisted URLs are accessible even if they would otherwise be blocked by "other security measures or policies"; it does not name the Blocked Malicious URLs list.
  - zscaler-help: In the GET request order the custom malicious URL (denylist) check is step 1 and Security Exceptions is step 4, so the denylist is checked before the exception can skip anything.
  Impact: A URL on both the denylist and the allowlist may still be blocked on the request. Do not tell an operator that adding a URL to Security Exceptions overrides an entry in Blocked Malicious URLs.

Not known (open gaps):
- Whether PUT with an empty bypassUrls list clears every exception [gap:zia.atp.security-exceptions:empty-replacement]: settled by lab-test. Blocks: Whether a write built from an empty list removes every exception.
- Observed result for a URL on both the denylist and the allowlist [gap:zia.atp.security-exceptions:order-vs-allowlist-live]: settled by lab-test
