# Bulk location and sublocation changes by CSV: row types, field rules, export and limits (zia.locations.csv-import)
Also called: location csv; import locations from csv; configuring multiple locations and sublocations; download csv locations; sample import csv; override existing entries locations; sublocationip; bulk add locations

The location CSV format has a line shape for each row type: Location and SubLocation rows enter those words, and the format lines led by + give IP (a location name and an address), sublocationip (a sublocation name, an address and the parent location's name), VPN (a location name, VPN type and VPN username), PORT (a location name and a dedicated port), VirtualServiceEdge and VirtualServiceEdgeCluster (each a location name and the Virtual Service Edge or cluster name). [zia.locations.csv-import:row-types] The Download CSV export cannot be used to add or delete locations or location features; a new CSV file must be created, and a file in the wrong format returns an error. A field that is not required and not used is left blank so the service knows it is skipped, values are not case sensitive, one file can add or delete several types of information, and each additional IP address for a location needs its own row. [zia.locations.csv-import:format]

**Location rows.** On a Location row Country and Time Zone are required, and Location-Type sets the location's primary web traffic type. [zia.locations.csv-import:required-fields] IP is required unless a Dedicated Port, VPN-Type/VPN-userName, or a Virtual Service Edge cluster or cluster name is given, and VPN-type and Dedicated Port follow the same pattern; a value in Dedicated Port also requires Auth to be enabled. [zia.locations.csv-import:identifying-field] Location row dependencies: Auth-Enable is required with a Dedicated Port or Surrogate IP; SurrogateIP-Enable requires Auth to be enabled; SurrogateIP-Enforced-KnownBrowsers requires Surrogate IP; AUP-Enable and Caution-Enable each require Auth to be disabled; aupBlockInternetAccess-Enable and aupForceSSLInspection-Enable require AUP-Enable; Caution-Enable also needs traffic forwarded by a GRE or IPSec tunnel without NAT or by forward proxy chaining with XFF-Enable on for the location; IPS-Enable requires firewall controls; Kerberos-Enable requires Auth. [zia.locations.csv-import:field-dependencies] The location CSV page says GRE tunnels are bound to locations only, not sublocations. [zia.locations.csv-import:gre-location-only] A location row's Managed By field takes the name of the partner managing the location, or is left blank if no partner manages it; the valid partner names include Cisco Viptela, Citrix SD-WAN, CloudGenix, HPE Aruba, Riverbed SteelConnect, Silver Peak and VMware VeloCloud. [zia.locations.csv-import:managed-by] The allowed Location-Type values are open [gap:zia.locations.csv-import:location-type-values]. The Download (Mbps) field is described two ways [divergence:zia.locations.csv-import:download-field-direction]. Whether sublocations inherit the row's group is disputed [divergence:zia.locations.csv-import:group-inheritance], and the page's single-Virtual-Service-Edge remark is one side of [zia.virtual-service-edge.cloud-deployment:standalone-production](kb:zia.virtual-service-edge.cloud-deployment:standalone-production).

**Sublocation rows.** A SubLocation row cannot carry a value for VPN-type, Dedicated port, VirtualServiceEdgeName or VirtualServiceEdgeClusterName (each is an empty comma) and must name its parent location. The location type WORKLOAD is entered for a sublocation of a parent location created in the Zscaler Admin Console. [zia.locations.csv-import:sublocation-rows] The group question is also in [A location can join a group independently of its sublocations and a sublocation independently of its parent, and a location or sublocation can belong to several manual and dynamic groups at once.](kb:zia.locations.groups:membership-independent).

**Export and import.** Download CSV allows one file per hour, takes longer when there are thousands of locations, and its file cannot be used to import location and sublocation modifications because it uses a different format. The limits table also lists Download CSV file as one file per hour. [zia.locations.csv-import:download] The export's format is open [gap:zia.locations.csv-import:download-format]. An import file must be in the same format as the Sample Import CSV file Zscaler provides. Override Existing Entries is selected to update existing locations, including deleting them, as well as add new ones; adding a location that already exists without it returns an error that identical locations cannot be imported. [zia.locations.csv-import:import] How many locations an import can add differs between pages [divergence:zia.locations.csv-import:import-count], and the sublocation count is part of [zia.locations.sublocations:default-cap](kb:zia.locations.sublocations:default-cap).

What to check:
1. Whether a Download CSV export is being reused as an import file, since the export cannot add or delete locations.
2. Whether a location's group membership is relied on for its sublocations, since the pages differ on inheritance.

Sources disagree (name both sides):
- Whether a sublocation inherits its parent location's location-group membership: the location CSV page says it does, About Location Groups says the two join groups independently, and Understanding Sublocations gives a sublocation of a console-created parent the Workload Traffic Group by default. [divergence:zia.locations.csv-import:group-inheritance]
  - zscaler-help: In the CSV's Group Name field, any sublocations inherit the group membership from their parent location.
  - zscaler-help: A location joins a group independently of its sublocations, and a sublocation independently of its parent.
  - zscaler-help: A sublocation added to a console-created location gets the Workload Traffic Group as its default group.
  Impact: A policy scoped to a location group may or may not reach a parent's sublocations depending on which page is read; the CSV sentence may describe only the CSV Group Name column, which the page does not say. The existing claim is [[zia.locations.groups:membership-independent]].
- The location CSV page describes the Download (Mbps) field for a location as the maximum upload bandwidth limit, and the same field for a sublocation as the maximum download bandwidth limit. [divergence:zia.locations.csv-import:download-field-direction]
  - zscaler-help: In the Location section the Download (Mbps) field is the maximum upload bandwidth limit.
  - zscaler-help: In the SubLocation section the Download (Mbps) field is the maximum download bandwidth limit.
  Impact: A CSV that sets bandwidth control from the location description may put the upload limit in a field the sublocation section calls the download limit.
- How many locations a CSV import can add: the import article says up to 32,000 locations, while the limits table gives 1,000 imported locations per CSV file. [divergence:zia.locations.csv-import:import-count]
  - zscaler-help: An import can add up to 32,000 locations and 16K sublocations per location.
  - zscaler-help: 1,000 imported locations per CSV file.
  Impact: The 32,000 may be an organization total reached over several files, but the import article does not say so; a bulk load sized to one page may break the other.
