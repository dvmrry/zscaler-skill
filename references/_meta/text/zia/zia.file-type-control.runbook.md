# How the Internet & SaaS File Type Control policy troubleshooting runbook confirms fault and checks detection, SSL inspection, protocol and rule criteria (zia.file-type-control.runbook)
Also called: Internet & SaaS File Type Control Policy Support Troubleshooting Runbook; file type control troubleshooting runbook

Zscaler's File Type Control policy enables administrators to create filtering rules to restrict the upload or download of specific file types, including unknown or unrecognized ones, and Zscaler leverages file signatures, MIME types, and extensions to detect a file’s true type. [zia.file-type-control.runbook:detection-method]

**Confirm File Type Control is responsible.** The runbook says it is essential to confirm whether File Type Control is responsible for the block or unexpected behavior before troubleshooting, since security policies such as Malware Protection, Sandbox, Cloud App Control, or other upstream security solutions can also impact file upload/download, and to validate this by reviewing the End User Notification or the Web Insights Logs. [zia.file-type-control.runbook:validate-fault] In the runbook's Web Insights examples, File Type Control shows Blocked Policy Type File Type Control with Policy Action values 'File Type download cautioned', 'File Type upload cautioned' or 'File Type upload/download cautioned' for cautions, and 'Not allowed to access this file type' or 'Not allowed to upload/download files of this type' for blocks, with Download File Type and Download File Name fields. [zia.file-type-control.runbook:log-values]

**SSL Inspection and protocol.** File Type Control policies require SSL Inspection to function properly; the runbook says to filter logs for the affected domain and inspect the SSL Policy Reason column, and if the SSL Policy Reason is Bypassed, to review and update the SSL Inspection policies so SSL Inspection is applied appropriately. [zia.file-type-control.runbook:ssl-inspection] The runbook says to ensure the protocol involved in the transaction is supported by File Type Control policies, listing FTP over HTTP and Native FTP among the supported protocols, to filter Web Insights Logs and review the Protocol column, and that if the protocol is unsupported, File Type Control policies are not applicable. [zia.file-type-control.runbook:supported-protocols]

**Rule criteria.** If the File Type Control policy relies on specific attributes (e.g., URL Category, Cloud App, User, Location), the runbook says to ensure these conditions match by filtering Web Insights Logs for the affected domain and reviewing these key fields and any other fields configured as the policy criteria, and to adjust the policy if the conditions do not align. [zia.file-type-control.runbook:rule-match-fields] For rules using Active Content (which only applies to Microsoft Office and PDF files) or Unscannable Files criteria, the runbook says to check the Web Insights logs for the Unscannable Type entry (if None is logged, the file was successfully scanned and rules targeting Unscannable Files do not apply) and to temporarily deselect the Active Content or Unscannable Files criteria in the policy to identify whether these settings are causing the issue. [zia.file-type-control.runbook:active-content-unscannable-criteria]

**Archives, overrides and misdetection.** Archive blocks, the Malware Protection Unscannable Files override and misidentified file types are in [File Type Control runbook: archives blocked by inner file type, the Malware Protection Unscannable Files override, and misidentified file types](kb:zia.file-type-control.runbook.misdetection-and-overrides).
