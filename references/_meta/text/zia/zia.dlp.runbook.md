# How the Internet & SaaS DLP policies troubleshooting runbook routes a case: feature enablement, fine-tuning, web DLP triage and notification issues (zia.dlp.runbook)
Also called: Internet & SaaS DLP Policies Support Troubleshooting Runbook; DLP policies troubleshooting runbook

The DLP runbook has headings for DLP feature configuration assistance or policy fine-tuning, a web DLP policy (Inline DLP, OCR, EDM, and IDM) not working as expected, and a web DLP email or ICAP notification issue. [zia.dlp.runbook:runbook-sections]

**Where the sections go.** Policy fine-tuning is in [DLP runbook: policy fine-tuning with Minimum Data Size, file type fallback, catch-all rules and dictionary combinations](kb:zia.dlp.runbook.fine-tuning). The web DLP triage order, log fields and rule criteria are in [DLP runbook: web DLP policy not working as expected, with evaluation mode, log fields, exemptions, rule criteria, engines and multipart checks](kb:zia.dlp.runbook.web-dlp-triage). Email and ICAP notification checks are in [DLP runbook: web DLP email and ICAP notification issues, attachment limit, SMTP codes and ICAP connectivity checks](kb:zia.dlp.runbook.notifications).

**Feature enablement.** The runbook's examples of DLP features that need a license or enablement: the Files tab correlated view requires a license for SaaS Security Data at Rest Scanning DLP and a configured DLP scan; SaaS Security API Data at Rest Scanning DLP policy rules without content inspection are enabled by contacting Zscaler Support; new predefined DLP engines are available by default for tenants enabled on April 4, 2025, or later, with existing tenants contacting Zscaler Support. [zia.dlp.runbook:enablement-examples] For a DLP feature that is not available, the runbook routes to the Zscaler Account team when the feature might require an additional subscription or SKU, and to Zscaler Support, with a Provisioning support case giving the feature details and the Help Portal or Release Notes reference link, when the feature is not enabled automatically for all users. [zia.dlp.runbook:enablement-routes]

**Support data.** The runbook's data checklist for a web DLP support case: HTTP Header HAR file, a packet capture (the Packet Capture option for Zscaler Client Connector, or the Wireshark capture method without it), Web Insights logs with all fields selected, the violation content notification email or JSON file, sample test data, and temporarily enabled Remote Assistance; highly sensitive data can be removed or obfuscated while it is still able to trigger the DLP issue. [zia.dlp.runbook:support-data-checklist]
