# Zscaler Identity Proxy: Zscaler as the SAML IdP for cloud apps, unmanaged-device actions and its error codes (zia.authentication.identity-proxy)
Also called: identity proxy; ID proxy; Zscaler ID; Identity Proxy Settings; identity proxy error codes; Zscaler as IdP for cloud apps

The Zscaler Identity Proxy makes Zscaler the identity provider for a cloud app so that users must reach the app through the Zscaler service: corporate-account sign-ins that do not go through Zscaler fail. The named apps are Box, Google Apps, Microsoft 365, Salesforce, GitHub, ShareFile, ServiceNow and Slack; Other Cloud Apps covers other apps with standard SAML authentication. [zia.authentication.identity-proxy:what-it-does] SSL/TLS Inspection must be enabled for the organization location before Zscaler is configured as the IdP for the named cloud apps. [zia.authentication.identity-proxy:ssl-prerequisite] A cloud app configured as the IdP for authentication cannot be used for Identity Proxy; for example, with Microsoft Entra ID as the IdP, Office 365 cannot be configured for Identity Proxy. [zia.authentication.identity-proxy:idp-app-excluded]

**Unmanaged devices.** The SaaS tenant uses the Identity Proxy as its IdP, and the proxy authenticates the user against the customer's own IdP. When that IdP indicates an unmanaged endpoint (based on the device identity attribute) and the original request was not made through the Public Service Edge, the configured action applies: Block, or Browser Isolate, which redirects the user to Zero Trust Browser. Zero Trust Browser traffic is always proxied through the Service Edge, where policies are enforced and transactions logged. [zia.authentication.identity-proxy:unmanaged-device-flow] A device counts as managed if its traffic is proxied through Zscaler and matches device attributes. With Authentication Service those are the Is Device Managed attributes it sends, and the option is greyed out if they are not configured there. Without it they are the Device Trust Attribute and Device Trust Attribute Value of the default IdP, and the option is greyed out if the IdP does not specify them. [zia.authentication.identity-proxy:managed-device-detection] For unmanaged devices the Action is Browser Isolate, which isolates the traffic in a remote browser using the selected isolation profile, or Block. [zia.authentication.identity-proxy:unmanaged-actions] Which log records an Identity Proxy decision is open [gap:zia.authentication.identity-proxy:decision-log], as is whether Other Cloud Apps get the same detection and actions [gap:zia.authentication.identity-proxy:other-cloud-apps-detection] and what the device identity attribute is beyond those two options [gap:zia.authentication.identity-proxy:device-identity-attribute].

**Settings and per-app setup.** For each app the Identity Proxy Settings page shows the SAML version (fixed); the Identity Proxy URL, a unique URL Zscaler generates that is set as the app's SAML SSO IdP (fixed); the Issuer Entity ID, the random part of that URL; the HTTP-POST binding Zscaler uses to send the assertion; NameID as user identifier, mapped to the Zscaler login name; the Response Signing SAML Certificate, the certificate the Identity Proxy uses for signing SAML responses; and a Certificate link that downloads the Zscaler certificate for the cloud app. [zia.authentication.identity-proxy:settings-page] The value of the SAML version it shows is not given [gap:zia.authentication.identity-proxy:saml-version-value]. The app instance's ACS URL is shown for Box, auto-filled for Office 365, built from the domain for Google Apps (the only app with a Domain field) and copied from the app's Login URL for the rest. Entity ID is auto-populated for most apps; Salesforce's is copied from the app, and GitHub's is the ACS URL without the trailing /saml/consume. [zia.authentication.identity-proxy:app-instance-urls] The admin picks the certificate the Identity Proxy signs SAML responses with, and Zscaler recommends the one with the longest validity. Its expiration date is shown when it is about to expire or has expired, with a Caution icon within 30 days of expiry. [zia.authentication.identity-proxy:signing-certificate] Identity Transformation passes the Zscaler login name as is, replaces its domain with a chosen domain (Zscaler recommends not using this for GitHub), or removes the domain to pass only the user ID. Pass-on Group Details sends all the user's groups in the response under the Group Identifier Name, and is set to Disable for GitHub, which does not support groups. [zia.authentication.identity-proxy:identity-transformation] Whether an API surface exists for Identity Proxy Settings was not checked [gap:zia.authentication.identity-proxy:api-surface].

**Notes for individual apps.** For Microsoft 365 the domain is federated through a PowerShell template whose logon URL is https://idp.<Zscaler Cloud Name>/samlsso/<Issuer Entity Id> and logoff URL https://logout.<Zscaler Cloud Name>/, with SAMLP as the preferred protocol; success shows as login.microsoftonline.com redirecting to IdP.<Zscaler Cloud Name>. [zia.authentication.identity-proxy:m365-federation] The Google Apps setup applies only if Identity Proxy is enabled for the whole organization (a specific organization unit is covered in Google's documentation), and Google users assigned administrator roles cannot use SSO. [zia.authentication.identity-proxy:google-limits] App-side settings the guide requires include HTTP POST for the service-provider request binding in Salesforce, the User Field set to email in ServiceNow, and Sign the Response deselected in Slack. [zia.authentication.identity-proxy:app-side-settings]

**Error codes.** Identity Proxy error codes are shown when the cloud app's (service provider's) authentication request fails. [zia.authentication.identity-proxy:when-shown] Organization and configuration codes: 0x1388 organization not found (invalid or deleted); 0x1389 Identity Proxy disabled for the app (enable Zscaler as its IdP proxy); 0x13B7 cloud app disabled (enable it); 0x13CA IdP disabled during authentication (enable it). These say to retry after a few seconds and contact Support if the error persists: 0x13B8 app configuration modified, 0x13C9 organization deleted, and 0x13CC and 0x13CD app configuration disabled or deleted during authentication. [zia.authentication.identity-proxy:org-and-config] User codes: 0x13AF to 0x13B3, 0x13BC and 0x13D0 user not found (it may have been deleted; re-add it); 0x13C1 hosted-database user entered the wrong password; 0x13C6 user authenticated with another organization that has no identity proxy (log out and sign in with the right account). These say to retry and then contact Support: 0x13C2 and 0x13C3 ZAB unreachable, 0x13C4 ZAB user wrong password, 0x1398 to 0x139A invalid user, cookie or session, 0x13CB invalid cookie, and 0x13B4 and 0x13B5 invalid domain (user transformation failed). [zia.authentication.identity-proxy:user-codes] SAML request codes, all with the action to retry after a few seconds and contact Support if the error persists: 0x138B invalid request; 0x1396 no ID; 0x139B invalid timestamp; 0x139C invalid version; 0x139D, 0x13CE, 0x13CF and 0x13D1 outdated request; 0x13A4 app not supported; 0x13A5 request from an unknown Public Service Edge; 0x13A6 invalid SAML endpoint; 0x13A9 (printed as '0x 13A9') and 0x13AA no SAML request in the payload; 0x13AB and 0x13AC decode failure; 0x13AD request path too long; 0x13AE wrong cloud; 0x13BD request took too long; 0x13C7 no key to sign the response; 0x13C8 wrong binding (no POST received). [zia.authentication.identity-proxy:saml-request-codes] Transient cloud issues are 0x138A, 0x138C to 0x1395, 0x139E to 0x13A1, 0x13A3 and 0x13BE to 0x13C0; internal errors are 0x13B6, 0x13B9, 0x13BA, 0x13C5 and 0x13D2. For all of them the action is to retry after a few seconds and contact Zscaler Support if the error persists. [zia.authentication.identity-proxy:transient-and-internal] The table has no row for some codes inside its range [gap:zia.authentication.identity-proxy:missing-codes], and where the user sees a code is not stated [gap:zia.authentication.identity-proxy:where-code-shown]. Codes shown on other failed logins are in [ZIA authentication error codes: generic, directory, Kerberos and Identity Proxy](kb:zia.authentication.error-codes).

What to check:
1. Whether an Identity Proxy sign-in failure shows a code, and what the code's row says to do, before treating it as a SAML or IdP fault.
2. Whether the app is already the IdP for authentication, since such an app cannot be used for Identity Proxy.
