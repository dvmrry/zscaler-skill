# NSS runbook data collection: health and network commands, packet capture and NSS log files (zia.logs.nss-runbook.diagnostics)
Also called: Data Collection and Analysis; NSS health checks; NSS network connectivity checks

**Health.** The runbook's basic health commands on the NSS server are top (processes, CPU, uptime, load, memory), sudo nss status, /sc/bin/smctl.sh status (smstat, Nanolog server and smcdsc services), sudo nss checkversion and uname a for the ZscalerOS version. [zia.logs.nss-runbook.diagnostics:health-commands] The runbook lists the NSS feed alerts to look for: SIEM connection down, Zscaler CA connection down, Nanolog connection down, memory low, disk space low, poor NSS-to-SIEM connection, CPU utilization high and memory swap high. [zia.logs.nss-runbook.diagnostics:feed-alert-list]

**Network checks.** Network connectivity checks use sudo nss troubleshoot connection, which the runbook words as checking that all three necessary connections towards CA, Zscaler Nanolog server, and NSS are stable, sudo nss troubleshoot netstat | grep tcp for established connections, and sudo nss test-firewall, which probes DNS resolution and outbound connections to narrow down DNS, NTP or TCP problems. [zia.logs.nss-runbook.diagnostics:connectivity-commands] The runbook wants the Service and Management IP addresses unique and in the same subnet; different subnets are accepted but not recommended, and sharing one IP between the interfaces prevents them functioning correctly. [zia.logs.nss-runbook.diagnostics:interface-ip-rules] MAC addresses of the service and management interfaces should be unique, checked with ifconfig (or smmgr smnet='ifconfig') and against the VM host (Azure/AWS/VMware). [zia.logs.nss-runbook.diagnostics:mac-addresses] From the service interface, /sc/bin/smmgr -ys smnet='<command>' runs ping, trace and route (sudo /sc/bin/smmgr -ys smnet=help lists supported commands), and the connect script run from the service interface tests TCP or SSL connections to the CA, Nanolog server or SIEM. [zia.logs.nss-runbook.diagnostics:smmgr-smnet-and-connect] What the sample outputs of these commands show [gap:zia.logs.nss-runbook.diagnostics:image-only-outputs] is open.

**Packet capture.** Captures go on the management interface for config download, updates, ARP and NTP issues, and on the service interface for missing or delayed logs or connectivity to CA, Nanolog server or SIEM, where the payload to the SIEM can be read in plain text. [zia.logs.nss-runbook.diagnostics:pcap-interface-choice] Management-interface captures use the general tcpdump command and service-interface captures use /sc/bin/smtcpdump.sh; the service interface is found with cat /sc/conf/sc.conf | grep smnet_pktdev and validated against ifconfig. [zia.logs.nss-runbook.diagnostics:pcap-commands] NSS hosted on Azure or other platforms which support Bridged networking shows an additional interface called bridge0; the runbook says a pcap on this interface captures all relevant communication flows. [zia.logs.nss-runbook.diagnostics:pcap-bridge0]

**Log files.** The runbook says configuration files are under /sc/conf and /etc; /sc/log has no defined retention (older files are overwritten when /sc is full) while logs in /var are rotated per newsyslog.conf. [zia.logs.nss-runbook.diagnostics:log-file-locations] The runbook assigns /sc/log/nssscripts.log (commands executed on the NSS in sequence), /sc/log/autoupgrade.log (upgrade logs), /var/log/snmpd.log (SNMP monitoring), /var/log/messages (kernel, SSH, NTP) and /etc/resolv.conf (DNS servers and manual entries). [zia.logs.nss-runbook.diagnostics:log-file-purposes] The runbook suggests find / -iname *.log to list log files, ls -ltrh for timestamps of rotated files, and grep -v to invert a search, for example excluding ntpdate from /var/log/messages. [zia.logs.nss-runbook.diagnostics:log-search-tips]
