# Per-IdP configuration specifics: SAML and SCIM for Entra ID, Okta, Ping and Google Workspace; SAML only for AD FS, OneLogin and CA SSO (zia.authentication.idp-integrations)
Also called: Entra ID SAML; Okta SAML SCIM; PingOne; PingFederate; Google Workspace SAML; AD FS; OneLogin; CA Single Sign-On; SiteMinder; SAML configuration guide

The IdP object itself (fields, default IdP, criteria) is in [The ZIA SAML identity provider object: limits, default IdP, criteria, fields, migration and Client Connector Portal as IdP](kb:zia.authentication.identity-providers); this subject holds what each vendor's configuration guide says differently.

**Features.** The Okta guide lists Just-in-Time (JIT) Provisioning (SAML auto-provisioning) among the supported SAML features, and the SCIM features supported by the Zscaler and Okta integration as Create Users, Update User Attributes, Deactivate Users and Group Push. Deactivate Users means a user deleted or deactivated in Okta, or with Internet & SaaS unassigned, is also deactivated in the Zscaler service. [zia.authentication.idp-integrations:okta-features] The PingOne guide lists the SCIM features supported by the Zscaler and PingOne integration as Create Users, Update User Attributes, Delete Users and Group Push. [zia.authentication.idp-integrations:pingone-features] The Google Workspace guide lists Deactivate Users among its supported SCIM features, and says Google Workspace does not support Sign SAML Request, On-Demand Provisioning for Users or Group Push. On the Deprovisioning page the administrator specifies an action and time for when an app is turned off for a user, a user is suspended from Google, and a user is deleted from Google. [zia.authentication.idp-integrations:google-features] In the Okta, PingOne and Google Workspace guides' SP-initiated SSO flow, the user is redirected to https://gateway.<Zscaler cloud Name>.net and prompted for a username. [zia.authentication.idp-integrations:sp-initiated-gateway]

**Prerequisites.** For Okta, a SCIM provisioning subscription for Okta is needed (the guide says to contact the Okta representative). In the Okta app, the Your Zscaler Domain field takes the cloud name (for example zscalerbeta.net), and the guide says a wrong value prevents authenticating via SAML to Zscaler. [zia.authentication.idp-integrations:okta-prerequisites] The PingFederate and PingOne guides each list a server with the Zscaler Connector add-on as a prerequisite. The PingFederate guide defers SAML SSO and SCIM provisioning configuration to the PingFederate documentation. [zia.authentication.idp-integrations:ping-prerequisites] For Microsoft Entra ID, a premium subscription is highly recommended to avoid restricted functionality, and groups must be assigned to the enterprise application for Entra ID to send group memberships to Zscaler. The guide recommends the provisioning scope Sync only assigned users and groups, lists an optional setting under which deleting groups and users over a threshold requires admin approval, and says that for Seamless SSO the domain hint ?whr=<your organization's domain> must be appended to the Login URL. [zia.authentication.idp-integrations:entra-prerequisites]

**Request signing.** The Okta guide says Sign SAML Request must be disabled in the Zscaler Admin Console, because Okta doesn't support signed SAML responses from the service provider. [zia.authentication.idp-integrations:okta-no-signing] The Entra ID and PingOne guides both say Zscaler recommends the SHA-2 (256-bit) signature algorithm. In Entra ID, Require verification certificates is enabled, and Allow requests signed with RSA-SHA1 is enabled if SHA-1 (160-bit) was selected in the Admin Console; in PingOne, Enforce Signed AuthRequest is enabled. [zia.authentication.idp-integrations:entra-pingone-signing]

**SAML attributes.** In the Entra ID guide the Zscaler IdP's Login Name Attribute is NameID, User Display Name Attribute displayName, Group Name Attribute groups and Department Name Attribute Department, each case-sensitive. The claim steps select the source attribute Cloud-only group display names in one step and sAMAccountName in another for groups, and user.department for the department. [zia.authentication.idp-integrations:entra-saml-attributes] In the Okta guide the User Display Name Attribute is DisplayName, the Group Name Attribute memberOf and the Department Name Attribute Department, each case-sensitive. Zscaler recommends the memberOf condition be a regular expression .*, so all groups the user belongs to are sent in the SAML assertion. [zia.authentication.idp-integrations:okta-saml-attributes] In the PingOne guide the User Display Name Attribute is displayName, the Group Name Attribute memberOf and the Department Name Attribute department, each case-sensitive. [zia.authentication.idp-integrations:pingone-saml-attributes] In the Google Workspace guide the User Display Name Attribute is DisplayName and the Department Name Attribute is Department (case-sensitive), the Group Name Attribute is optional and can be left blank, and the Name ID format is EMAIL with Name ID from Basic Information > Primary email. [zia.authentication.idp-integrations:google-saml-attributes] In the OneLogin guide, the default values select Email for the NameID (Login). [zia.authentication.idp-integrations:onelogin-nameid]

**Hosts to exempt from authentication.** The Entra ID guide has login.windows.net, login.microsoftonline.com, .windowsazure.com, aadcdn.msauth.net and aadcdn.msftauth.net entered as exceptions in Exempted URLs. It says this option only applies to user traffic from known locations, and that if PAC files are used, exceptions must go in the PAC file exemption list or authentication fails; the PAC line it gives exempts only login.windows.net, login.microsoftonline.com and *.windowsazure.com. [zia.authentication.idp-integrations:entra-exempt-hosts] The other guides name the hosts to enter in Exempted URLs in the Authentication Exemptions section: the required Okta domains (the Okta PAC example uses *.okta.com and *.oktacdn.com), the required PingOne domains, accounts.google.com for Google Workspace, app.onelogin.com for OneLogin, and the organization's AD FS URL for AD FS 3.0. The CA Single Sign-On guide instead says to enter the redirected URL in the PAC file exemption list, otherwise authentication fails. [zia.authentication.idp-integrations:other-exempt-hosts] The exemption lists themselves are in [Destinations that skip authentication](kb:zia.authentication.exemptions).

**PingOne SCIM connection.** In PingOne the SCIM connection is created by selecting SCIM Outbound, with User Resource /Users, Group Resource /Groups, SCIM Version 2.0, Authentication Method OAuth 2 Bearer Token and Auth Type Header Bearer. [zia.authentication.idp-integrations:pingone-scim-settings]

**Older IdPs.** The AD FS 3.0 guide covers Windows Server 2012 R2 running Active Directory Federation Services 3.0 as the IdP. For the login-name claim it says to choose SAM-Account-Name if the Zscaler service hosts one domain for the organization and otherwise User-Principal-Name, and not E-Mail-Addresses, because users can have multiple email addresses and that could result in multiple user credentials; the outgoing claim types are Name ID and memberOf. It does not recommend Is-Member-Of-DL, because groups can be displayed as LDAP paths instead of group names, and says AD FS 3.0 federates all user groups by default. [zia.authentication.idp-integrations:adfs-3-claims] The AD FS 2.0 guide covers Windows Server 2008 R2 running Active Directory Federation Services 2.0 as the IdP. It says to select SAM-Account-Name only if one domain is hosted by the Zscaler service, otherwise User-Principal-Name, and that AD FS 2.0 federates all the groups of a user by default. [zia.authentication.idp-integrations:adfs-2-claims] The CA Single Sign-On guide covers CA SiteMinder version R12 SP3 CR5 as the IdP. It says the default CA SSO SAML portal URL might be unusable because RelayState is dropped, resolved by using the Redirect script; that Zscaler expects a POST Binding, which isn't the default for CA SSO; and that a CA SSO bug provides multi-valued Group data in an invalid format Zscaler can't use, handled with the FMATTR function. [zia.authentication.idp-integrations:casso-quirks] Whether SCIM works with the SAML-only guides is open [gap:zia.authentication.idp-integrations:saml-only-guides-scim].

What to check:
1. Which IdP vendor the tenant uses and whether it supports signed SAML requests, before enabling Sign SAML Request.
2. Whether the IdP's login hosts are in the Exempted URLs list, and in the PAC file's exemption list when PAC files are used.
3. Whether the SAML attribute names the IdP sends match the Login Name, User Display Name, Group Name and Department Name attributes configured on the Zscaler IdP, which are case-sensitive.

Not known (open gaps):
- Whether SCIM works with AD FS, OneLogin and CA SSO [gap:zia.authentication.idp-integrations:saml-only-guides-scim]: settled by source-read or support-ticket
