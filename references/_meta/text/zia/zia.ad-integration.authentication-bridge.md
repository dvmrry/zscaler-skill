# Deploying the Zscaler Authentication Bridge (ZAB): requirements, certificates, commands and renewal (zia.ad-integration.authentication-bridge)
Also called: Zscaler Authentication Bridge; ZAB deployment; ZAB requirements; ZAB certificate renewal; ZAB client certificate; zab commands; ZAB VM

The ZAB is a virtual machine for provisioning and authenticating users; what it does and how it pairs with other methods is in [ZIA provisioning methods and which authentication each allows](kb:zia.ad-integration.provisioning-methods). The Zscaler Authentication Bridge (ZAB) is a virtual machine (VM) that can be used to provision and authenticate users. If an organization is subscribed to multiple ZABs, only one can synchronize its users; the article's example deploys two ZABs and says the service automatically uses the healthy one to sync users. To use the ZAB for authentication too, the configured ZAB URL must be able to address both ZABs; the user is redirected to that URL during the password authentication phase, and the article says round-robin DNS or a load balancer can achieve an active deployment. [zia.ad-integration.authentication-bridge:what-and-multiple]

**Requirements.** The deployment article lists, for a ZAB, a new or clean deployment requiring the VM image running Zscaler OS version 24 (the article scopes only this item to new or clean deployments), VMware ESX/ESXi version 6.0 and later, 2 GB of RAM minimum (increasing with the number of users), a 64-bit Xeon CPU with two cores assigned to the VM, and one network interface with a static IP address used for control and data connections to the Zscaler cloud, for the connection to the directory server and for SSH. A ZAB subscription is required and only super admins can deploy a ZAB. The firewall requirements for outbound connections to the Zscaler service are at https://config.zscaler.com/<Zscaler Cloud Name>/zab. When downloading the VM, a Number of Users entered in the console lets the service provide recommended specifications, and the ZAB's Status is enabled by default. [zia.ad-integration.authentication-bridge:requirements] The sizing figures are open [gap:zia.ad-integration.authentication-bridge:zab-sizing].

**Certificates.** The ZAB uses an SSL certificate to authenticate itself to the Zscaler service, installed with the zab install-client-cert ZabCert.zip command. To serve the form over a webpage the ZAB has an HTTPS server component: a server certificate from an issuing authority must be used if the ZAB is used for user authentication, which prevents a server certificate warning in the browser, while if the ZAB only provisions users the system can generate a self-signed certificate. [zia.ad-integration.authentication-bridge:certificates] To renew the ZAB server certificate, the certificate files (Server Certificate .pem, Certificate Key .key, Root Chain .pem) are copied by SCP to var/cacert, installed from the directory during the maintenance window, and the ZAB service restarted with its status validated. The article validates by establishing an SSL connection to the ZAB with OpenSSL to confirm the new certificate is returned, then setting the browser proxy to gateway.<Zscaler cloud name>.net:9443 with the ZAB hostname added to proxy bypass, and using a dummy user@domain.com account on the Zscaler authentication page to be redirected to the ZAB. [zia.ad-integration.authentication-bridge:server-certificate-renewal]

**Commands.** The ZAB ships with the username and password zsroot, and Zscaler strongly recommends changing the default password. The deployment steps use zab configure for the network settings, then zab dump-config, zab update-now, zab start, zab enable-autostart and zab status. The article also gives commands that test access to the outbound firewall, collect the ZAB log and configuration files, and allow Zscaler Support remote access, including SSH access, both disabled by default. [zia.ad-integration.authentication-bridge:default-credentials-and-commands] With a local NTP server, the article's crontab entry */10 * * * * ntpdate <NTP Server Name> runs the time synchronization command every 10 minutes. [zia.ad-integration.authentication-bridge:ntp-crontab]

**Pointing synchronization at it.** The Authentication Wizard for the ZAB sets Authentication Agent Hosting to Enterprise. Authentication Agent Address is the ZAB URL if the ZAB is used for user authentication; if another authentication mechanism (for example SAML or OpenLDAP) is used it can be any IP address. The Bind DN can be any user account that queries the directory server, not necessarily an administrator. [zia.ad-integration.authentication-bridge:sync-wizard-settings] The synchronization settings themselves are in [Directory (LDAP/AD) synchronization behavior](kb:zia.ad-integration.directory-sync).

**Nested groups.** Enabling nested groups on the ZAB, with the zab enable-nested-groups command, allows the Zscaler service to flatten and sync user group membership for nested groups; zab disable-nested-groups is the counterpart command. [zia.ad-integration.authentication-bridge:nested-groups-command] The directory sync article says nested groups are not supported, and the scope is open: [zia.ad-integration.directory-sync:nested-groups-support](kb:zia.ad-integration.directory-sync:nested-groups-support).

What to check:
1. Whether the ZAB authenticates users or only provisions them, since a server certificate from an issuing authority is required only for authentication.
2. Whether more than one ZAB is subscribed and the configured ZAB URL addresses all of them.
