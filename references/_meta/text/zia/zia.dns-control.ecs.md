# EDNS Client Subnet (ECS) injection and ECS prefix objects (zia.dns-control.ecs)
Also called: EDNS Client Subnet; ECS injection; ECS prefix; synthetic ECS prefix

Internet & SaaS (ZIA) supports EDNS Client Subnet (ECS) in DNS queries to obtain geolocated responses from DNS resolvers. Client Subnet is an option in Extension Mechanisms for DNS (EDNS(0)) that lets the requesting client's IP address or subnet information be passed in DNS requests. [zia.dns-control.ecs:what-is] When DNS queries are forwarded through the Zscaler service, resolution is geo-optimized for the Service Edge because the external DNS service receives the query from the Service Edge's public IP address; the ECS option passes the client's masked IP address instead. [zia.dns-control.ecs:why-it-matters] ECS support requires a subscription that includes advanced functionalities of DNS Control. [zia.dns-control.ecs:subscription]

**What is sent.** The ECS value is typically a prefix taken from the client's public IP address by masking bits (for example 2.2.2.0/24 is sent as the ECS value). The prefix length can range from /20 to /24, the default prefix is /24, and a synthetic ECS prefix can be configured instead of deriving one from the client's address. [zia.dns-control.ecs:prefix-length-default] An admin can retain an ECS prefix already present in client DNS queries, with the option Retain ECS prefix if present so the configured prefix does not override it. If Zscaler inserts the prefix, the corresponding ECS option in the DNS response might be removed before the response reaches the client. [zia.dns-control.ecs:retain-insert] Zscaler supports ECS prefixes of the IPv4 family only and does not process IPv6-family ECS prefixes in client DNS queries. The Zscaler Trusted Resolver does not currently support the ECS option. [zia.dns-control.ecs:ipv4-only]

**Scope and caution.** Zscaler supports ECS irrespective of the traffic forwarding method the client uses. A resolver that does not support ECS ignores the extension and returns a regular response, and ECS is supported for A, AAAA, CNAME, MX, NS and PTR records. [zia.dns-control.ecs:scope] Some DNS resolvers ignore the ECS value and others return a REFUSED error code, so Zscaler recommends validating the provider's ECS handling before configuring injection and exercising caution to avoid exposing clients' IP network information. Too long prefixes may be rejected by certain resolvers, whereas very short ones may not geolocate the clients. [zia.dns-control.ecs:resolver-caution]

**Prefix objects.** An ECS prefix object has a unique name (alphanumeric only, at most 255 characters), a prefix length of /20 to /24 or a static IPv4 prefix with subnet mask that may be private or public, and an optional description of at most 255 characters. With /24 and client address 2.2.2.2 the Client Subnet value is 2.2.2.0, and a static 2.2.2.2/24 also gives 2.2.2.0. [zia.dns-control.ecs:object-fields] An organization can have at most 128 ECS prefixes, including the default prefix. [zia.dns-control.ecs:prefix-count] An admin can configure a list of ECS prefixes and designate one to be embedded in DNS queries arriving at the Service Edges; after configuring prefixes, the ECS option must be enabled and a prefix designated in the Advanced Settings. [zia.dns-control.ecs:enabling] In Advanced Settings, Enable ECS Option for Locations and Remote Users includes the ECS option in all DNS queries originating from all locations and remote users. The ECS Prefix field appears when that option is enabled and selects the ECS prefix to use in DNS queries; the page says to configure the ECS prefix objects first so they can be prepopulated for selection. [zia.dns-control.ecs:advanced-settings-option] Configured ECS prefixes can be viewed, a prefix can be deleted, and DNS Insights Logs show the logs recorded for DNS traffic that contains the ECS prefix. [zia.dns-control.ecs:default-delete-visibility] How the designated prefix relates to a DNS rule's ECS object is open [gap:zia.dns-control.ecs:designation-vs-rule].
