# Where a Virtual Service Edge runs and which platforms can cluster (zia.virtual-service-edge.platforms)
Also called: vse platforms; vse hyper-v cluster; vse azure aws gcp; vse nutanix; vse esxi version; vse zscaler os 24; vse vmotion; vse vm image; vse cluster mode platform

**What it is.** A Virtual Service Edge uses a VM to function as a full-featured Public Service Edge dedicated to the organization's traffic, performing the same service as the Public Service Edges in the Zscaler cloud, including Firewall, Sandbox and DLP. [zia.virtual-service-edge.platforms:full-featured-dedicated] Zscaler typically recommends forwarding traffic to the Public Service Edges. An organization with different traffic-flow needs can extend the Zscaler architecture to its premises by licensing and deploying Virtual Service Edges, with Zscaler's approval. [zia.virtual-service-edge.platforms:approval-and-licence] The documented reasons are locations with geopolitical requirements and regulations, high latency to a Public Service Edge, applications that require the organization's IP address as the source IP address, and users who need localized content. [zia.virtual-service-edge.platforms:reasons-to-deploy] Those are the same reasons the hardware form factor lists ([When a Private Service Edge is warranted](kb:zia.private-service-edge.when-to-deploy)); the choice between them is operating model and ceiling, not feature set. The per-VM ceiling is in [How much a Virtual Service Edge VM can do](kb:zia.virtual-service-edge.sizing).

**Where it runs.** Virtual Service Edges are supported on VMware ESX/ESXi, Microsoft Azure, AWS EC2, Microsoft Hyper-V and Google Cloud Platform. [zia.virtual-service-edge.platforms:supported-platforms] The Virtual Service Edges page offers downloads of the Virtual Service Edge VM, the SNMP MIB files, the Hyper-V VM and the Nutanix VM. [zia.virtual-service-edge.platforms:image-downloads] The ZIA release summary entry dated July 13, 2026 lists Virtual Service Edge configuration as supported on the Nutanix platform, with the Nutanix VM image downloadable on the Virtual Service Edges page. [zia.virtual-service-edge.platforms:nutanix-release-entry] Nothing else is established for it ([What Nutanix support establishes](kb:zia.virtual-service-edge.platforms:nutanix-support-scope)). A new or clean Virtual Service Edge deployment requires a VM image running Zscaler OS version 24 or later. [zia.virtual-service-edge.platforms:os-24-or-later] vMotion is supported only on VMware ESXi 7.0 and above. [zia.virtual-service-edge.platforms:vmotion-esxi-7]

**Which platforms can cluster.** When adding a Virtual Service Edge the Deployment Mode can be Cluster or Standalone only on VMware ESXi; on other platforms only Standalone is selectable. The SDK's field documentation says the same. [zia.virtual-service-edge.platforms:cluster-mode-selectable-on-esxi] In public cloud environments the native cluster mode of deployment is not supported, and public cloud load balancers provide redundancy between Virtual Service Edges. The page lists Microsoft Azure, AWS EC2, Microsoft Hyper-V and GCP in that sentence. [zia.virtual-service-edge.platforms:public-cloud-no-native-cluster] Hyper-V is where the documentation disagrees with itself ([zia.virtual-service-edge.platforms:hyper-v-cluster-mode](kb:zia.virtual-service-edge.platforms:hyper-v-cluster-mode)); treat ESXi as the only platform with an unambiguous native cluster. The cluster mechanics for that case are [The Virtual Service Edge cluster: limits, object, build order and Location binding](kb:zia.virtual-service-edge.clusters) and [How a Virtual Service Edge cluster spreads and returns traffic](kb:zia.virtual-service-edge.load-balancing).

**The comparison with the hardware form factor.** In the Private versus Virtual Service Edge comparison, the Virtual Service Edge is easy to deploy and can handle remote user traffic; it can be deployed flexibly in the DMZ, the internal network or the public cloud, is horizontally scalable, needs no wait for shipping and no public IPs, and has a built-in load balancer. The organization is responsible for deployment, configuration and maintenance, though upgrades are automatic, and it provides the hardware and hypervisor while Zscaler provides the host software. An SSL acceleration card is recommended for deployments requiring a throughput of 100 Mbps or more to perform SSL inspection, and the page says Virtual Service Edges must be deployed either in clusters or standalone for production. [zia.virtual-service-edge.platforms:comparison-vse]

**Microsoft Hyper-V.** The Hyper-V page says Zscaler supports a standalone Virtual Service Edge for production deployments on Microsoft Hyper-V. It lists Windows Server 2019 with the Hyper-V feature enabled, a minimum of 48 GB RAM and 3 network interfaces (1 for management, 1 for the Virtual Service Edge and 1 for the Load Balancer), and a Generation 1 VM. Promiscuous Mode must be enabled using the Microsoft NDIS capture on the virtual switch, because Zscaler load balancers and Virtual Service Edges use CARP, and the commands must be run as an administrator. MAC address spoofing on the third NIC facilitates sending of frames by the Virtual/Cluster IP, and Zscaler recommends different servers for each instance to achieve fault tolerance. [zia.virtual-service-edge.platforms:hyper-v] The page's memory figures differ [divergence:zia.virtual-service-edge.platforms:hyper-v-memory].

**Nutanix.** The Nutanix page says Virtual Service Edges can be deployed in a cluster or in standalone mode with Nutanix, and Zscaler recommends clusters to achieve redundancy and update software seamlessly during scheduled update cycles. A cluster can contain a maximum of 16 instances, each needing a subscription license count, and the hypervisor is Nutanix AHV (AOS 6.x and later; verified on AOS 7.3). [zia.virtual-service-edge.platforms:nutanix-modes] The Nutanix VM image is created with image type DISK, 4 vCPUs, 48 GB memory, Legacy BIOS boot and a SCSI bus disk of 500 GB (thin provisioned), for which Zscaler recommends SSDs. [zia.virtual-service-edge.platforms:nutanix-vm] On Nutanix AHV no equivalent of the promiscuous mode toggle is needed, and CARP advertisements (multicast 224.0.0.18) reach every instance automatically. Where anti-spoofing is enforced (for example a Nutanix Flow microsegmentation policy), MAC spoofing on the vNICs must be explicitly allowed and CARP/VRRP multicast permitted. The page lists a dedicated AHV network on its own VLAN, a standard NIC in Access mode (kNormalNic) rather than kDirectNic or SR-IOV, IGMP snooping left disabled because enabling it can prune CARP multicast and HA might fail, and an uplink bond of active-backup or LACP with balance-tcp, not balance-slb. [zia.virtual-service-edge.platforms:nutanix-carp-network]

The public cloud pages are in [Deploying a Virtual Service Edge on Azure, AWS (with or without GWLB) and GCP](kb:zia.virtual-service-edge.cloud-deployment) and the VM install sequence is in [The Virtual Service Edge install sequence on the VM: image, certificate, network, build and verification](kb:zia.virtual-service-edge.bring-up).

One more disagreement to know about: the minimum ESXi version differs between the specifications table and the cluster configuration article ([zia.virtual-service-edge.platforms:esxi-minimum-version](kb:zia.virtual-service-edge.platforms:esxi-minimum-version)).

What to check:
1. Which platform the deployment runs on, since only VMware ESXi offers Cluster as a deployment mode.

Sources disagree (name both sides):
- The memory the Hyper-V page requires for a Virtual Service Edge VM. [divergence:zia.virtual-service-edge.platforms:hyper-v-memory]
  - zscaler-help: The requirements list gives a minimum of 48 GB RAM.
  - zscaler-help: The VM-creation step sets the startup memory to 32768 MB.
  Impact: A VM built by following the creation step has less memory than the listed minimum; the page does not say whether the memory is raised later.
- Whether Microsoft Hyper-V supports the native Virtual Service Edge cluster mode. [divergence:zia.virtual-service-edge.platforms:hyper-v-cluster-mode]
  - zscaler-help: The Hyper-V configuration page builds a CARP cluster, with the load balancer enabling CARP on the third NIC and MAC spoofing allowing the virtual or cluster IP to send frames.
  - zscaler-help: Hyper-V has a maximum of 16 VMs per cluster and uses the in-built load balancer in cluster mode.
  - zscaler-help: Hyper-V is listed with Azure, AWS and GCP as an environment where native cluster mode is not supported.
  - zscaler-help: Only VMware ESXi can select the Cluster deployment mode; every other platform, Hyper-V included, selects Standalone.
  Impact: A Hyper-V cluster design cannot be assumed to work from the documentation. Two statements and the SDK's field documentation point to ESXi as the only clustering platform; the sizing table and one recommendation say Hyper-V clusters. Confirm with Zscaler before planning one.
- The minimum VMware ESXi version. [divergence:zia.virtual-service-edge.platforms:esxi-minimum-version]
  - zscaler-help: VMware ESXi 6.0 and later.
  - zscaler-help: VMware ESX/ESXi v5.0 and later for a Virtual Service Edge cluster.
  Impact: Low for new builds, which will be on a current ESXi release, but a legacy host on ESXi 5.x is documented as supported in one place and not the other.
