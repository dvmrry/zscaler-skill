# Source IP Anchoring Direct during ZIA disaster recovery (zia.forwarding-control.sipa-direct)
Also called: sipa direct; source ip anchoring direct; zia disaster recovery sipa; forward to zpa during dr

Source IP Anchoring Direct is a Private Access change, made on the Private Access side while ZIA is in disaster recovery. Source IP Anchoring Direct is a set of Private Access configurations that keeps Source IP Anchoring forwarding working while ZIA is in disaster recovery mode; the Source IP Anchoring configurations must be changed to it for the duration of the event. [zia.forwarding-control.sipa-direct:definition] To switch, change the domain-based client forwarding rule from Bypass ZPA to Forward to ZPA, and the IP-based rule from Only Forward Allowed Applications to Forward to ZPA. [zia.forwarding-control.sipa-direct:switch-rules] When the disaster recovery event ends, revert both client forwarding rules (Forward to ZPA back to Bypass ZPA, and back to Only Forward Allowed Applications) and restore the Source IP Anchoring access policy rules. [zia.forwarding-control.sipa-direct:revert-rules]

Two access policy patterns prevent Source IP Anchoring Direct from working: any rule that blocks access to Zscaler Client Connector, and any rule that results in the Default Rule. Zscaler recommends an access policy that allows access to the applications from Zscaler Client Connector. [zia.forwarding-control.sipa-direct:access-blockers] The standard IP-based Source IP Anchoring access policy contains a rule that blocks Client Connector client types, which is the pattern the Direct page says prevents Source IP Anchoring Direct, so IP-based segments need an access rule allowing Client Connector for the duration of the event. [zia.forwarding-control.sipa-direct:standard-block-conflict]

The baseline configuration this reverts to is in [Source IP Anchoring: what it needs on each side](kb:zia.forwarding-control.sipa). Why the normal path needs this change is open [gap:zia.forwarding-control.sipa-direct:mechanism].
