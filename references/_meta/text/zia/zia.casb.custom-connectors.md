# Custom Zscaler connectors for Slack, Salesforce, Microsoft and Google tenants: credentials, scopes and permissions (zia.casb.custom-connectors)
Also called: custom connector; client-side connector onboarding; authorizing a custom zscaler connector; minimum set of credentials; zscaler_quarantine library; private key pem onboarding

A custom connector is the client-side way to authorize a SaaS tenant with a minimum set of credentials. The service supports custom, client-side connector onboarding for access to Salesforce, to Gmail, Google Cloud Platform, Google Drive and Google Workspace, and to specific Slack workspaces. For Salesforce, the Microsoft applications and those Google applications, the service can use a minimum set of credentials instead of full administrator credentials; for Slack it enables selective monitoring of specific workspaces within the Slack enterprise account for DLP and Malware scanning. [zia.casb.custom-connectors:purpose] How tenants are listed and reauthorized is in [CASB tenants: connecting a SaaS application, states and reauthorization](kb:zia.casb.tenants).

**Slack.** A custom connector for Slack for DLP and Malware scanning needs the Slack workspace ID, client ID and client secret during tenant onboarding in the Admin Console, plus the right permissions; the Slack app's distribution is activated under Manage Distribution in Settings to allow installation. [zia.casb.custom-connectors:slack-credentials] The Slack app's bot token scopes are channels:manage, channels:read, chat:write, groups:write, im:write, mpim:write, groups:read, im:read, files:write and mpim:read; its user token scopes are admin.teams:read, auditlogs:read, channels:read, discovery:read, discovery:write, files:read, im:read, files:write and team:read. The discovery:read and discovery:write scopes are request-only, with the page asking to share the App ID. [zia.casb.custom-connectors:slack-scopes] The Slack workspace ID depends on the account type, Enterprise Grid or Non-Grid (Enterprise Select, Pro or Business+). For Enterprise Grid it is copied with Copy Workspace ID under All Workspaces; for Non-Grid it is the T-prefixed ID, the segment after /client/ in a URL such as https://app.slack.com/client/TXXXXXXX/CXXXXXXX. [zia.casb.custom-connectors:slack-workspace-id]

**Salesforce.** A Salesforce custom connector for SSPM Scan needs the client ID, client secret, integration user's username and instance URL in the Admin Console; DLP and Malware scanning SaaS API onboarding additionally needs the Malware and DLP quarantine library names. The two libraries are named Zscaler_Quarantine (unique name Malware_Quarantine) and Zscaler_DLP_Quarantine (unique name DLP_Quarantine), with permission set to Library Administrator. [zia.casb.custom-connectors:salesforce-credentials] In the sandbox steps the Salesforce user is created with the Salesforce user license and a System Administrator profile, and the permission set's license is Salesforce; the production steps give the permission set's license as Salesforce API Integration and refer to the Salesforce integration user created in the previous section. [zia.casb.custom-connectors:salesforce-user] In the sandbox steps the Salesforce external client app has Distribution State Local, callback URL https://test.salesforce.com and scopes Perform Requests at any time (refresh_token, offline_access) and Manage user data via APIs (api). It enables the JWT Bearer Flow and requires a secret for the Web Server Flow and the Refresh Token Flow. Its OAuth policies pre-authorize admin approved users, relax IP restrictions, keep the refresh token valid until revoked and set a session timeout of 1,440 minutes (24 hours), and its app policy profile is Minimum Access - API Only Integrations. [zia.casb.custom-connectors:salesforce-client-app] The sandbox steps for Salesforce uncheck the Lock sessions to the IP address from which they originated checkbox and check Enable Salesforce CRM Content. [zia.casb.custom-connectors:salesforce-org-settings] The custom onboarding process for Salesforce requires uploading the private key file to the Admin Console. Zscaler recommends a certificate authority-signed (CA-signed) certificate, and a self-signed certificate can also be used if a CA-signed one cannot be obtained. [zia.casb.custom-connectors:salesforce-key] Authorizing a Salesforce tenant in the Admin Console selects Custom for SaaS Connector and, in the sandbox steps, Sandbox Account for the Tenant Type. An optional section, Configure External Trusted Domains & User Profiles, allows up to 1,000 domains and up to 1,000 email addresses. [zia.casb.custom-connectors:salesforce-authorize] The tenants page limits trusted domains and users to email tenants [divergence:zia.casb.custom-connectors:trusted-profiles-scope], and the SSPM permissions page is in [For Salesforce the page says Manage Sharing and Manage Certificates are not read-only and inevitable because Salesforce has no granular permission for them, and that the Metadata API permission is inevitable because no read-only equivalent exists. Modify All Data is marked required only for remediation.](kb:zia.sspm.permissions:salesforce-inevitable-write). The sandbox permissions table lists, for DLP and Malware onboarding, Manage Salesforce CRM Content, Query All Files, Access Libraries, View All Users, Manage Chatter Messages and Direct Messages and Manage Unlisted Groups with the action Scanning, together with View Event Log Files with Scanning and Modify All Data with Apply Policy Actions, and, for SSPM, Query All Files, View Health Check, Modify All Data, Modify Metadata Through Metadata API Functions, Manage Certificates and Manage Sharing with the action SSPM Scan. [zia.casb.custom-connectors:salesforce-permissions] The production permissions table maps View Event Log Files to Generate SaaS Activities and Modify All Data to Scanning, and has a Field Permissions row, Read Access for Description, Subject, and Type Fields, with Scanning. Its SSPM rows include Modify All Data with SSPM Scan. [zia.casb.custom-connectors:salesforce-production-permissions] The Modify All Data row for SSPM differs between the two pages [divergence:zia.casb.custom-connectors:salesforce-modify-all-data]. What the production steps give and omit is open [gap:zia.casb.custom-connectors:salesforce-production-values].

**Microsoft.** Microsoft custom connectors cover Exchange, Microsoft Information Protection (MIP) Labels, OneDrive, SharePoint, Microsoft Azure Blob Storage, Teams, Dynamics 365, Copilot and Microsoft 365. Choosing the client secret option requires the Client ID, Client Secret and Tenant ID; choosing the private key option requires the Client ID, Tenant ID and the Private Key PEM file. [zia.casb.custom-connectors:microsoft-apps-and-methods] The private key requirement for MIP disagrees with the page's own table and steps [divergence:zia.casb.custom-connectors:microsoft-mip-client-secret]. Zscaler recommends creating a new connector for each Microsoft application. The app registration's supported account types are set to Accounts in any organizational directory (Any Microsoft Entra ID tenant - Multitenant), with Web as the redirect platform and the Zscaler account URL (for example https://console.zscaler.com/). The client secret value is displayed only once, and specific API permissions are assigned for each connector, with Grant admin consent where required, such as SharePoint permissions. [zia.casb.custom-connectors:microsoft-registration] The private key method uses private_key.pem (an AES-256 encrypted RSA private key, used to create combined.pem), certificate.pem (a self-signed certificate, uploaded in the Azure portal) and combined.pem (the private key and certificate together, uploaded on the Internet & SaaS onboarding page); the password is entered when prompted. [zia.casb.custom-connectors:microsoft-pem-files] To authorize a custom connector, the Azure login URL is first updated manually to grant permissions on the tenant: https://login.microsoftonline.com/common/adminconsent for Microsoft 365 and Microsoft 365 GCC tenants and https://login.microsoftonline.us/common/adminconsent for Microsoft 365 GCC High and Microsoft 365 DoD tenants, each with the client_id, a state of administration/add-casb-tenants and the redirect_uri; MIP uses a state of administration/mip-labels. [zia.casb.custom-connectors:microsoft-consent-url] For Microsoft Azure Blob Storage the application needs extra role assignments in Azure, Storage Blob Data Contributor and Storage Account Contributor. Copilot registration is completed by running a script through the Power Platform API or PowerShell for Power Platform administrators. An MIP account displays Validation Successful if authorized and, on Validation Failed, can be reauthorized with Reauthorize on the Edit MIP Account window. [zia.casb.custom-connectors:microsoft-app-specifics] Dynamics 365 has no permissions table [gap:zia.casb.custom-connectors:dynamics-permissions].

**Google.** The Google connector steps create a service account key of type JSON, and the private key JSON file downloaded while creating the service account is uploaded with Authorize. Domain wide delegation is managed with MANAGE DOMAIN WIDE DELEGATION, the Gmail service account is given the Pub/Sub Admin role, and a value entered at onboarding is treated as the tenant ID, from which Zscaler internally fetches the tenant domain. [zia.casb.custom-connectors:google-service-account] For a Google Cloud Platform connector the admin is told to use the role name exactly as provided and not to modify or rename the role. With one of the permission types the page describes, Report Incident and Action None policy actions function and Sign-in Events, Webhooks and other policy actions do not; another configuration gives the connector sufficient permission to register webhooks while keeping the read role intact on Google Cloud Storage, and Sign-in Events do not function with a further set of permissions. If Zscaler_Read_role is modified, a scan restart is mandatory for the changes to take effect. [zia.casb.custom-connectors:gcp-roles] For a GCP storage scan the service account is created without granting access or permissions to the project and added as an IAM member of the organization with Zscaler_Read_Role or Zscaler_ReadWrite_Role. Audit logs are enabled for Google Cloud Storage and the Cloud Logging API with Data Write, Data Read and Admin Read. At onboarding the Connector Role is Read or Read Write, and with Read Write the Quarantine Bucket name is also entered. [zia.casb.custom-connectors:gcp-setup]

What to check:
1. Whether the application's connector uses the credential type the page requires, and for MIP use the divergence rather than either statement.
2. Whether a Salesforce SSPM question about Modify All Data rests on the divergence, not on one page's table.
3. Whether a trusted-domain question for a Salesforce tenant rests on the divergence with the tenants page.

Sources disagree (name both sides):
- The Salesforce custom connector page lists Modify All Data under SSPM onboarding with the action SSPM Scan, while the SSPM permissions page marks it required only for remediation. [divergence:zia.casb.custom-connectors:salesforce-modify-all-data]
  - zscaler-help: Modify All Data is listed with the action SSPM Scan.
  - zscaler-help: Modify All Data is marked No in three columns and Yes in one, with the purpose To perform remediation.
  Impact: Whether a Salesforce SSPM scan needs Modify All Data, or only remediation does, depends on which page governs; the pages do not say. The connector page also lists Modify All Data for DLP and Malware, with Apply Policy Actions in the sandbox table and Scanning in the production table. The graph's claim in zia.sspm.permissions:salesforce-inevitable-write follows the SSPM page.
- The tenants page says external trusted domains and users apply only to email SaaS application tenants, while the Salesforce (CRM) custom connector authorization offers External Trusted Domains and User Profiles. [divergence:zia.casb.custom-connectors:trusted-profiles-scope]
  - zscaler-help: The trusted domains count applies only to email SaaS application tenants.
  - zscaler-help: The Salesforce authorization step offers an optional trusted domains and user profiles section with up to 1,000 domains.
  Impact: Whether trusted domains and users apply to a Salesforce tenant is stated both ways; the graph's claim zia.casb.tenants:trusted-profiles-email-only follows the tenants page. The relation of the 1,000-entry figure to the 32-profile limit is not stated.
- The Microsoft connector page says MIP requires the private key method and the client secret method is not available, while its own table marks MIP Yes in both method columns and its MIP account steps enter a Client Secret. [divergence:zia.casb.custom-connectors:microsoft-mip-client-secret]
  - zscaler-help: MIP, SharePoint, Copilot and Microsoft 365 require the private key method; the client secret method is not available.
  - zscaler-help: The table row for MIP reads Yes | Yes, and a step enters Client ID, Client Secret and Tenant ID.
  Impact: Whether an MIP connector can be onboarded with a client secret is stated both ways on one page; the page does not say which governs.
