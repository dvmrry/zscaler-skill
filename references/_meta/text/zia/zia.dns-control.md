# ZIA DNS Control (zia.dns-control)
Also called: dns control; dns control policy; zia dns policy; dns filtering rule; firewall dns rules; why is dns control not firing

DNS Control is a module of Zscaler Firewall: its best practices apply when DNS traffic is forwarded to the Zscaler service and inspected by the DNS Control module of Zscaler Firewall. [zia.dns-control:firewall-module] DNS Control lets an admin define rules that control DNS requests and responses. [zia.dns-control:scope] Whether a URL Filtering block also affects resolution is open [gap:zia.dns-control:url-filtering-independent]. The web side is in [ZIA URL Filtering](kb:zia.url-filtering).

DNS Control requires the firewall to be configured for locations, and a Firewall Filtering rule that allows DNS traffic (Network Services condition matches DNS). [zia.dns-control:firewall-prereq] The Zscaler service directs users' DNS requests that are forwarded via GRE tunnels, IPSec tunnels, or Zscaler Client Connector using Z-Tunnel 2.0. [zia.dns-control:dns-via-forwarding] DNS Control applies to recursive and iterative requests, but iterative requests need extra policy configuration to transit the Zscaler service. [zia.dns-control:iterative-needs-config] If no values are selected for the DNS Services option (Services Applicable to DNS Transaction Policies in Advanced Settings), DNS Control policies are not enforced on the organization's traffic. Zscaler might still resolve DNS queries if the predefined NAT rule Zscaler Trusted DNS Resolver is enabled, and that rule can be manually disabled. [zia.dns-control:dns-services-empty] The custom service that sets the DNS ports is in [To make the service accept traffic from other ports, an admin creates a custom service with the appropriate ports and then, in Advanced Settings, configures the service to accept traffic from those ports: the HTTP Services and HTTPS Services lists under Services Forwarded to HTTP Web Proxy, the DNS Services list under Services Applicable to DNS Transaction Policies, and the FTP Services, RTSP Services and PPTP Services lists under Services Forwarded to FTP Proxy, to RTSP and to PPTP. The Advanced Settings page says the configurations it lists can be modified as needed if the Firewall service is enabled.](kb:zia.firewall:custom-port-services).

**Evaluation.** DNS Control rules are evaluated in ascending numerical order. [zia.dns-control:ascending-order] A disabled DNS Control rule keeps its place in the rule order; the service skips it and moves to the next rule. [zia.dns-control:disabled-skipped] Whether a match stops evaluation is open [gap:zia.dns-control:first-match]. The DNS Control policy has default rules that allow all DNS traffic. They always hold the lowest precedence; their actions can be modified but they cannot be deleted. [zia.dns-control:default-rules] A tenant can hold up to 1,000 DNS Control rules with Advanced DNS Control and 64 with Essential. [zia.dns-control:limits] The DNS Security and Control reference architecture says that when the DNS request reaches the ZTE, no DNS requests can bypass inspection unless authorized, since users can be restricted to only using DNS servers the organization specifies. [zia.dns-control:dns-proxy-inspection]

[Cloud & Branch Connector DNS gateways are a Cloud & Branch Connector feature with their own page (Zero Trust Cloud > Gateways > DNS Gateway): they redirect DNS requests received by the Connector to specific DNS servers.](kb:cloud-connector.dns.gateways:cbc-gateways-differ) [Cloud & Branch Connector has its own DNS Policies feature, configured on its own page (Zero Trust Cloud > Policy > DNS Forwarding), with rules evaluated in ascending order.](kb:cloud-connector.dns.policies:cbc-has-dns-policies) The ZIA DNS Control action that redirects to a gateway is covered in [DNS Control actions and what each API action requires](kb:zia.dns-control.actions), and the ZIA gateway object in [ZIA DNS gateways: protocol translation, primary/secondary failover, failure behavior, DoH path](kb:zia.dns-control.gateways).

What to check:
1. Whether the location has the firewall configured, before reading the DNS Control rule list.
2. Whether a domain that must be unreachable is blocked in both URL Filtering and DNS Control.
3. Which product a "DNS gateway" refers to, since Cloud & Branch Connector gateways are a separate feature.

Not known (open gaps):
- Whether the first matching DNS Control rule ends evaluation [gap:zia.dns-control:first-match]: settled by lab-test. Blocks: stating which rule decides a query when several match
- Whether a URL Filtering block leaves DNS resolution untouched [gap:zia.dns-control:url-filtering-independent]: settled by lab-test. Blocks: telling an operator whether blocking a domain needs rules in both modules
