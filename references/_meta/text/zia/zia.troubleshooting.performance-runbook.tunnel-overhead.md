# Performance runbook: Check for Traffic Imbalance, Z-Tunnel 2.0 over GRE or IPSec, tunnel limits and gateway-variable load distribution (zia.troubleshooting.performance-runbook.tunnel-overhead)
Also called: Check for Traffic Imbalance; traffic imbalance; Z-Tunnel 2.0 over GRE; Z-Tunnel 2.0 over IPSec; GATEWAY_FX

**GRE.** Under its Check for Traffic Imbalance heading, the runbook says sending Client Connector Z-Tunnel 2.0 over a GRE tunnel is not a recommended setup because of added overhead and causes suboptimal traffic processing. [zia.troubleshooting.performance-runbook.tunnel-overhead:ztunnel2-over-gre] To detect Z-Tunnel 2.0 over GRE, the runbook finds the GRE egress IP at ip.zscaler.com and looks in Web Insights for a transaction with Traffic Forwarding: Zscaler Client Connector over GRE and a Zscaler Client Connector Tunnel Version of Z-Tunnel 2.0 TLS, ztunnel_2.0 dtls1.0, ztunnel_2.0 dtls1.2 or ztunnel_2.0 udp. [zia.troubleshooting.performance-runbook.tunnel-overhead:check-ztunnel2-over-gre] [divergence:zia.troubleshooting.performance-runbook.tunnel-overhead:tunnel-version-values] For Z-Tunnel 2.0 behind GRE, the runbook recommends Z-Tunnel 1.0 for On-Trusted networks with IP surrogacy enabled on all locations for both Known or Unknown User agents, or bypassing Zscaler's recommended hub IPs by policy based routing so Z-Tunnel 2.0 goes direct, ensuring the public egress IP is configured and associated as a Known Location; GRE is supported to 1 Gbps per tunnel if the inner endpoint IPs are not NAT'd, and more tunnels with different public source IPs are suggested. [zia.troubleshooting.performance-runbook.tunnel-overhead:gre-recommendations] [divergence:zia.troubleshooting.performance-runbook.tunnel-overhead:gre-source-ips-vs-fallback] [divergence:zia.troubleshooting.performance-runbook.tunnel-overhead:switch-to-ztunnel1-vs-adopt-2]

**IPSec.** Sending Client Connector Z-Tunnel 2.0 over an IPSec tunnel is not a recommended setup because of added overhead and causes suboptimal traffic processing. [zia.troubleshooting.performance-runbook.tunnel-overhead:ztunnel2-over-ipsec] To detect Z-Tunnel 2.0 over IPSec, the runbook finds the IPSec egress IP at ip.zscaler.com and looks in Web Insights for Traffic Forwarding: Zscaler Client Connector over IPSec Tunnel with a Tunnel Version of Z-Tunnel 2.0 TLS, ztunnel_2.0 dtls1.0, ztunnel_2.0 dtls1.2 or ztunnel_2.0 udp. [zia.troubleshooting.performance-runbook.tunnel-overhead:check-ztunnel2-over-ipsec] For Z-Tunnel 2.0 behind IPSec, the runbook recommends Z-Tunnel 1.0 for On-Trusted networks with IP surrogacy enabled on all locations for both Known or Unknown User agents, or bypassing the hub IPs by policy based routing, ensuring the public egress IP is configured and associated as a Known Location, states a 400 Mbps limit per public source IP address, and suggests multiple tunnels with different source IPs or with the same source IP using NAT-T and source port randomization with IKEv2. [zia.troubleshooting.performance-runbook.tunnel-overhead:ipsec-recommendations]

**Explicit and PAC.** For Explicit/PAC or Client Connector Tunnel 1.0/TWLP, the runbook recommends ${GATEWAY_FX} in the PAC file for the Client Connector method and ${GATEWAY_Fn} for the PAC method, more NAT pool IPs per proxy instance, and Z-Tunnel 2.0 with the egress IP in a Known Location. [zia.troubleshooting.performance-runbook.tunnel-overhead:explicit-pac-tunnel1-recommendations] [gap:zia.troubleshooting.performance-runbook.tunnel-overhead:gateway-fn-undefined] [gap:zia.troubleshooting.performance-runbook.tunnel-overhead:on-trusted-undefined]

Sources disagree (name both sides):
- The runbook tells the reader to look in Web Insights for a Traffic Forwarding value of Zscaler Client Connector over GRE or over IPSec Tunnel and a Tunnel Version of Z-Tunnel 2.0 TLS or ztunnel_2.0 dtls/udp values; the NSS web log format lists a different set of forwarding method values, none of them over GRE or over IPSec Tunnel, and gives ZTUNNEL_1_0 as its ztunnelversion example. [divergence:zia.troubleshooting.performance-runbook.tunnel-overhead:tunnel-version-values]
  - zscaler-help: Web Insights shows Traffic Forwarding: Zscaler Client Connector over GRE (or over IPSec Tunnel) and a Zscaler Client Connector Tunnel Version of Z-Tunnel 2.0 TLS or ztunnel_2.0 dtls1.0, dtls1.2 or udp.
  - zscaler-help: The NSS ztunnelversion field is described by the example ZTUNNEL_1_0, and the trafficredirectmethod values end with PAC_IPSEC and Zscaler Client Connector (Zscaler App), with no over GRE or over IPSec Tunnel value.
  Impact: The labels the runbook says to search for are the Insights UI labels for these fields (zia/web-log#trafficredirectmethod and #ztunnelversion); a search for them in NSS-fed logs may not match the values the NSS format lists, and shared.log-correlation.zcc-in-zia holds an open gap on the ztunnelversion values.
- The runbook recommends configuring more GRE tunnels with different public source IP addresses; the Z-Tunnel 2.0 requirement is a NAT device that uses a single IP for all connections from one device, otherwise the client falls back to Z-Tunnel 1.0. [divergence:zia.troubleshooting.performance-runbook.tunnel-overhead:gre-source-ips-vs-fallback]
  - zscaler-help: For Z-Tunnel 2.0 behind GRE, configure more GRE tunnels with different public source IP addresses.
  - zscaler-help: Z-Tunnel 2.0 needs a single IP for all connections from one device, or its control and data connections can land on different Service Edges and it falls back to Z-Tunnel 1.0.
  Impact: Whether adding GRE tunnels with different source IPs helps or triggers fallback depends on whether one device's connections can leave through more than one of them; see zia.traffic-forwarding.mixed-deployments:gre-ztunnel2-egress.
- For Z-Tunnel 2.0 behind GRE or IPSec the runbook recommends switching to Z-Tunnel 1.0 for On-Trusted networks, while its Explicit/PAC recommendation says to adopt Z-Tunnel 2.0; the Client Connector runbook's switch to Z-Tunnel 1.0 is described as not recommended as a permanent solution. [divergence:zia.troubleshooting.performance-runbook.tunnel-overhead:switch-to-ztunnel1-vs-adopt-2]
  - zscaler-help: Switch to Z-Tunnel 1.0 for On-Trusted networks behind a GRE tunnel.
  - zscaler-help: Zscaler recommends adopting Z-Tunnel 2.0.
  - zscaler-help: In the Client Connector runbook's MTU steps, switching to Z-Tunnel 1.0 is a testing workaround that is not recommended as a permanent solution.
  Impact: Whether Z-Tunnel 1.0 is a standing recommendation for On-Trusted networks behind GRE or IPSec or only a temporary test depends on which page is read; Z-Tunnel 1.0 does not intercept non-web traffic.
