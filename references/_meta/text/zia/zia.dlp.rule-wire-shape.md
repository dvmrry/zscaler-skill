# Web DLP rule API fields, enums and fields the contract does not document (zia.dlp.rule-wire-shape)
Also called: webDlpRules api; dlp rule action enum; dlp rule severity; withoutContentInspection; ocrEnabled; dlp receiver icapServer deprecated; dlpContentLocationsScopes; deeplyNestedContentEnabled; timeoutFailClosedEnabled; webDlpGlobalOptions; dlp matchOnly sdk docstring

This is the API view of a Web DLP rule. Reach for it when a question names a field, an enum value or an SDK call, or when the console and the API disagree.

**Where it lives.** Web DLP rules are managed at `/zia/api/v1/webDlpRules`, and tenant-wide DLP advanced settings at `/zia/api/v1/webDlpGlobalOptions`. [zia.dlp.rule-wire-shape:endpoint] The `webDlpGlobalOptions` resource holds tenant-wide DLP settings: application and URL exemptions, `exemptUrlEncodedData`, inline, SaaS Security and email OCR flags, `enableEvaluateAllDlpRules`, EDM format flags, and `httpGetCustomUrlCategories` (the URL categories to associate with Inspect HTTP GET Requests). [zia.dlp.rule-wire-shape:global-options-fields]

**Enums.** The API reference lists the rule `action` values as ANY, NONE, BLOCK, ALLOW and ICAP_RESPONSE; none of them is named Confirm, the action the console offers in Evaluate All Rules mode. [zia.dlp.rule-wire-shape:action-enum] A rule's `severity` is one of RULE_SEVERITY_HIGH, RULE_SEVERITY_MEDIUM, RULE_SEVERITY_LOW or RULE_SEVERITY_INFO. [zia.dlp.rule-wire-shape:severity-enum] How the Confirm action is represented in the API is open [gap:zia.dlp.rule-wire-shape:confirm-action-wire-value].

**Match Only is not a size switch.** The `matchOnly` field is the Match Only criterion for DLP engines, not a file-size switch. File size gating is `minSize`, in KB. [zia.dlp.rule-wire-shape:match-only-field] The Python docstring conflicts with the vendor reference [divergence:zia.dlp.rule-wire-shape:match-only-docstring].

**Sub-rules and rules without inspection.** A rule can carry `subRules` (exception rules) and a `parentRule` ID; every attribute of the rule model applies to a sub-rule. [zia.dlp.rule-wire-shape:sub-rules-model] The mode requirement and what exception rules do are in [Why DLP did or did not fire: pipeline position, evaluation mode and exemptions](kb:zia.dlp.evaluation). `withoutContentInspection` true marks a DLP rule without content inspection. The matching console workflow uses external DLP engines to detect data and forward information to a third-party DLP solution. [zia.dlp.rule-wire-shape:without-content-inspection]

**OCR, content locations and scoping.** OCR of images appears in two places: a per-rule `ocrEnabled` field in the Go SDK rule struct and Python add and update calls, and a tenant-wide `enableInlineDlpOcr` flag in the DLP global options. The API reference's rule fields do not list `ocrEnabled`. [zia.dlp.rule-wire-shape:ocr-two-switches] `dlpContentLocationsScopes` takes ANY, HTTP_BODY, FILE_CONTENT, DOCUMENT_PROPERTIES and FILENAME, and the API reference says it does not apply to DLP rules without content inspection. The 2026-06-21 overlay records it as absent from the Terraform provider. [zia.dlp.rule-wire-shape:content-locations-field] The help article for rules without content inspection has a Content Locations field [divergence:zia.dlp.rule-wire-shape:content-locations-without-inspection]. Besides users, groups, departments and locations, the rule model scopes by included and excluded domain profiles (up to 8), source IP groups, workload groups, URL categories, cloud applications, user risk score levels, time windows and rule labels. It also carries per-rule handles for a notification template, an auditor and an external auditor email, and a ZCC notification flag. [zia.dlp.rule-wire-shape:scoping-and-handles]

**Incident receiver fields.** The rule fields `icapServer` and `zscalerIncidentReceiver` are deprecated and calls using them would not succeed; `receiver` replaces both, with a `type` of ICAP, ZIR or C2CIR and a tenant reference. [zia.dlp.rule-wire-shape:receiver-replaces-icap-fields] The destinations themselves are in [Where a DLP match goes: notification, ICAP, Incident Receiver and Cloud-to-Cloud](kb:zia.dlp.incident-forwarding).

**Fields only live reads show.** A downstream clean-room check saw `deeplyNestedContentEnabled` and `timeoutFailClosedEnabled` in live Web DLP rule reads. Neither is in the checked-in Automate contract, its same-day recapture, the Go or Python SDKs, or the Terraform provider, and their write status is unknown. [zia.dlp.rule-wire-shape:live-read-only-fields] The six Web DLP operation pages were recaptured on 2026-06-21 and their hashes matched the checked-in reference, so the checked-in contract was current for that surface and still lacked the two live-read fields. [zia.dlp.rule-wire-shape:recapture-negative-control]

How the Terraform provider and Go SDK mishandle these rules (nil dereferences under the rule lock, ordering, zero-value writes, data source output) is in [When the ZIA Terraform provider reports success after an error, or crashes](kb:zia.terraform.error-handling), [The ZIA provider's reorder registry: keys, locks and lifecycle across rule resources](kb:zia.terraform.rule-order.registry), [What ZIA Terraform data sources return, drop, or get wrong](kb:zia.terraform.data-source-fidelity), [ZIA Terraform resource fields that are not sent, not read back, or sent wrongly](kb:zia.terraform.field-fidelity) and [How the Go SDK encodes ZIA writes (omitted zero values, empty responses)](kb:zia.sdk-go.write-encoding); the Cloud-to-Cloud receiver's secret handling is in [How the Zscaler Terraform providers store, log, and send secrets](kb:shared.terraform.credential-handling).

Sources disagree (name both sides):
- Whether the Content Locations criterion applies to DLP rules without content inspection. [divergence:zia.dlp.rule-wire-shape:content-locations-without-inspection]
  - api-specs: The API reference's description of dlpContentLocationsScopes says the criterion is not applicable to DLP rules without content inspection.
  - zscaler-help: The help article for rules without content inspection has a Content Locations field described as selecting the content locations that are inspected for sensitive data.
  Impact: Whether a rule without content inspection takes content locations is not settled; the API reference says the criterion does not apply to such rules while the console article for that rule kind has the field. Do not state either as fact.
- The Python SDK's add-rule docstring describes `match_only` as matching file size, while the API reference, the Go SDK and the help article describe it as the engine Match Only criterion. [divergence:zia.dlp.rule-wire-shape:match-only-docstring]
  - sdk-python: match_only relates to file size.
  - api-specs: matchOnly is the match only criteria for DLP engines.
  Impact: An agent reading the SDK docstring would explain a missing detection as a file-size effect when Match Only excluded the transaction.
  Resolved (source-rank) by zia.dlp.rule-wire-shape:match-only-field: The vendor API reference and help article outrank an SDK docstring.
