# How SSL/TLS inspection applies by traffic source: known locations, Client Connector, a dedicated proxy port, and ports 9443, 80/443/9400/9480 and 8800 (zia.ssl-inspection.traffic-sources)
Also called: ssl inspection deployment scenarios; ssl inspection port 9443; ssl inspection remote users; ssl inspection dedicated proxy port; ssl inspection kerberos port 8800

For HTTPS from a known location, Zscaler recommends enabling authentication so URL and Cloud App Control policies apply at the user level; with authentication disabled the service applies location-based URL and Cloud App Control policies and cannot apply any user or group policies, so the appropriate location must be specified in the Location setting of those policies. The deployment best practices likewise say to enable user authentication so the service can apply user policies. [zia.ssl-inspection.traffic-sources:known-location-authentication]

**Remote users.** For remote users, or users from an unknown location, the deployment scenarios page says extra steps are needed and the recommended option is to install and use Client Connector on their machines. [zia.ssl-inspection.traffic-sources:remote-users-client-connector] Users who connect to Public Service Edges on port 9443 have all HTTPS connections subject to SSL/TLS Inspection, and lose the ability to bypass traffic by URLs and URL categories from SSL/TLS scanning and authentication; a user who forwards to port 9443 without the certificate installed sees certificate warnings. The deployment best practices add that the list of URL categories and cloud apps not decrypted does not apply to remote users who configure their browsers or PAC files to send traffic to port 9443. [zia.ssl-inspection.traffic-sources:port-9443] For remote users who forward traffic to Zscaler on ports 80, 443, 9400 and 9480, the deployment scenarios page says SSL/TLS traffic is not intercepted and policies are not implemented on it, a first HTTPS transaction from an unregistered IP address is blocked so the user must first access an HTTP page and authenticate, and SSL/TLS and authentication bypass are not applied. [zia.ssl-inspection.traffic-sources:ports-80-443-9400-9480] What SSL/TLS inspection does for remote users on those ports differs from the rule criteria page [divergence:zia.ssl-inspection.traffic-sources:remote-port-interception]. Remote users might forward traffic on port 8800, where Public Service Edges attempt to authenticate the user with Kerberos; the organization might choose to inspect that HTTPS traffic by enabling Enable SSL/TLS Inspection for Remote Users with Kerberos under Internet Access > Policy > SSL/TLS Inspection. [zia.ssl-inspection.traffic-sources:port-8800-kerberos] Whether that setting is now the Remote Users with Kerberos rule criterion is not stated [gap:zia.ssl-inspection.traffic-sources:kerberos-setting-or-criterion].

**Dedicated proxy port.** If the organization has subscribed to a dedicated port and has gateway locations created on it, whether SSL/TLS traffic is inspected can be defined by the location configuration, and because the port is unique to the organization it is used as an identifier to apply the organization's SSL/TLS and authentication bypasses. [zia.ssl-inspection.traffic-sources:dedicated-port] On a dedicated port, a first transaction from an unregistered IP that is an HTTPS request must be authenticated before the service accepts it, to ensure Zscaler is not used as an open proxy by unauthorized users. If Show Notifications is enabled under Internet Access > Policy > SSL/TLS Inspection, the transaction is intercepted and checked for a valid authentication cookie and the user is redirected for authentication if there is none; if Show Notifications is disabled the transaction is dropped and the user must first access an HTTP page and authenticate. [zia.ssl-inspection.traffic-sources:dedicated-port-first-https] Which feature needs the dedicated-port subscription on the deployment page's port 9443 sentence is not stated [gap:zia.ssl-inspection.traffic-sources:port-9443-subscription].

What each port is for is in [Dedicated proxy ports](kb:zia.forwarding-control.proxy-ports) and [Writing a PAC file for Zscaler: function, return statements, ports and performance rules](kb:shared.pac-files.syntax); how unauthenticated traffic is treated is in [What happens to traffic with no user identity](kb:zia.authentication.unauthenticated-traffic); the rule criteria are in [SSL/TLS inspection rule criteria and the ones that silently don't match](kb:zia.ssl-inspection.criteria).

Sources disagree (name both sides):
- The deployment scenarios page says SSL/TLS traffic from remote users on ports 80/443/9400/9480 is not intercepted and has no policies; the SSL/TLS inspection rule page has a criterion that applies to traffic forwarded in explicit proxy mode (PAC or PAC over tunnel). [divergence:zia.ssl-inspection.traffic-sources:remote-port-interception]
  - zscaler-help: Remote users on ports 80/443/9400/9480 get no SSL/TLS interception and no policies on that traffic.
  - zscaler-help: The criterion applies only to SSL/TLS traffic forwarded in explicit proxy mode (PAC or PAC over tunnel), not to transparent proxy (tunnel) or Z-Tunnel 1.0 traffic.
  Impact: The pages may describe different eras or different user populations; neither says whether a rule's criteria are evaluated for remote PAC traffic on those ports, so the question is open between them.
