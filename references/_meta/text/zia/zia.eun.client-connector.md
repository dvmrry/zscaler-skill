# Client Connector-based end user notifications from the ZIA side: prerequisites, channels, details, shared settings and languages (zia.eun.client-connector)
Also called: Client Connector EUN; Zscaler Client Connector-based EUN; ZIA EUN message; Inline Web DLP EUN; Firewall EUN; DNS Control EUN; IPS Control EUN; Endpoint DLP EUN; Install Endpoint ZDP; Open Corporate Policy; Request Exemption

For Inline Web DLP and Cloud App Control EUNs, Client Connector needs Endpoint DLP (which includes EUN) or EUN as a standalone feature, which requires Windows 4.6.0.123 or later or macOS 4.3.1.56 or later; in Internet & SaaS, Zscaler Support is contacted to enable EUN for each of the two policies. [zia.eun.client-connector:prereqs-inline-web-and-cac] Endpoint DLP EUNs need Endpoint DLP enabled in Client Connector and the Endpoint DLP policy enabled in Internet & SaaS. [zia.eun.client-connector:prereqs-endpoint-dlp] Firewall Filtering, DNS Control and IPS Control EUNs are supported on Windows devices running Client Connector 4.8 or later over Z-Tunnel 2.0. In Internet & SaaS they need Firewall Filtering enabled with Advanced Firewall, DNS Control enabled with Advanced DNS (provided by the Advanced Firewall), and IPS Control enabled through Advanced Firewall. [zia.eun.client-connector:prereqs-firewall-dns-ips] Platforms other than Windows and macOS are not mentioned for these notifications [gap:zia.eun.client-connector:other-platforms].

**App profile.** For Inline Web DLP and Cloud App Control EUNs the app profile (Windows or macOS) must have Install Endpoint ZDP enabled; these EUNs are supported as a standalone feature without Endpoint DLP, the Endpoint ZDP agent activating Endpoint DLP (which includes EUN) or standalone EUN depending on the organization's subscription. Endpoint DLP EUNs need Endpoint DLP in Client Connector, and the same app profile step with Install Endpoint ZDP. [zia.eun.client-connector:app-profile-web] For Firewall Filtering, DNS Control and IPS Control EUNs the app profile is for Windows only, with the Zscaler Notification Framework enabled and a Notification Template selected that has ZIA Firewall and Firewall Popup, DNS and DNS Popup, or IPS and IPS Popup notifications enabled respectively. [zia.eun.client-connector:app-profile-network] After customizing the notifications, the respective policy rules are configured to show EUNs when a specific rule action is triggered and to select the notification message to display. [zia.eun.client-connector:rule-binding] The Client Connector side of these notifications is in [Client Connector notification templates: per-profile notification settings](kb:zcc.notifications.templates) and [The Zscaler Notification Framework: Client Connector's own pop-ups](kb:zcc.notifications.framework).

**Channels and details.** Inline Web DLP messages use the Inline Web channel with an Allow message (the service allows and logs the activity) and a Block message, and are supported for DLP rules with and without content inspection. Additional details are File Name, Destination, Rule Name, URL Category, URL and DLP Engines. [zia.eun.client-connector:channel-inline-web] Cloud App Control messages use the Cloud Application channel with a preconfigured message for the Block action, and EUNs are supported only for Block rules where application access is allowed but certain interactions are blocked (for example viewing a social networking site is allowed but posting content is blocked). Additional details are Destination, Rule Name, App Activity, URL and App Category. [zia.eun.client-connector:channel-cloud-application] Endpoint DLP has a default notification for each supported channel, including Printing, Removable Storage, Network Share and Personal Cloud Storage. Each of those four channel sections lists an Allow and a Block message, and Removable Storage also has Protect, shown when the service encrypts an affected file (recipients must use the Zscaler service to decrypt it). Rules with the Confirm action use an EUN message customized separately. [zia.eun.client-connector:channels-endpoint-dlp] In the Removable Storage section of the Endpoint DLP page, messages can include File Name, Destination, Rule Name and DLP Engines as additional details. [zia.eun.client-connector:details-endpoint-dlp] Firewall Filtering messages use the Firewall channel and apply to all block actions of the policy, including Block/Drop, Block/ICMP and Block/Reset. The EUN is for non-web traffic and fires only on a policy match with non-HTTP/HTTPS traffic: traffic on standard web ports such as 80, 443 and 8080 identified as HTTP or HTTPS does not trigger it. Additional details are Network Service, Server Destination IP, Network Application, Application Service Group, Client Source IP, Server Destination Port and Server Destination Protocol. [zia.eun.client-connector:channel-firewall] DNS Control messages use the DNS channel and notify when a DNS Control block or a DNS redirect happens: the Block message applies to both Block and Block with Response Code actions, and Redirect Response covers a DNS redirect. Additional details are Request Category, Response Category, Resolved IP, DNS Tunnel, Requested Domain, Server IP, Protocol and Resolved IP-Based Country. [zia.eun.client-connector:channel-dns] IPS Control messages use the IPS channel and notify when traffic is allowed or blocked by the IPS Control policy. Allow covers potentially malicious activity that the configured IPS policy allows, and the Block message applies to both Block/Drop and Block/Reset actions. Additional details are Threat Name, Threat Category, Threat Severity, Threat Score, Network Service, Server Destination IP and Destination Country. [zia.eun.client-connector:channel-ips]

**Message syntax and shared settings.** On the Inline Web DLP page, links are embedded in message content as __url[Link text | example.com] (with a double underscore at the beginning) and line breaks are introduced with //n; custom notification messages can be edited, but the Channel field cannot be modified. [zia.eun.client-connector:message-syntax] Organization name, logo, support details and notification duration, among other general settings, are shared by all Client Connector-based notifications across policies, and changes to the General Details are mirrored in the User Confirmation notification settings. [zia.eun.client-connector:shared-settings] Notification actions are Learn More (opens the Notifications tab in Client Connector; enabled by default and non-editable), Do Not Disturb (opens the More tab), Open Corporate Policy (opens the URL entered), Open Containing Folder (opens the folder where files that triggered the block rule are quarantined; applicable only for Endpoint DLP policies that quarantine the original file) and Request Exemption (opens the Data Protection tab; applicable only for Endpoint DLP rules with the Block action). [zia.eun.client-connector:notification-actions] The logo must be a PNG file with a size limit of 20x20 pixels. Under Duration, the notification is set to close automatically or manually by the user; with the Auto Close option a duration after which it closes is chosen from a drop-down menu. [zia.eun.client-connector:logo-and-duration] The Auto Close duration values are not listed [gap:zia.eun.client-connector:auto-close-values]. The support URL can contain a query string using the variables $filename, $destination, $triggered_rule, $action, $url, $url_category, $app_activity, $app_category and $zcc_user; in the vendor's example a ticket URL with name=$zcc_user and url_accessed=$url is prepopulated with the user's name and the URL that triggered the policy. [zia.eun.client-connector:support-url-variables]

**Languages.** Client Connector EUNs support English, Chinese (Traditional), French, German, Japanese and Spanish, chosen from the OS language setting, with English displayed by default if the OS language is not one of them. Only the default messages are translated to all the languages; modifying the message in one language does not change the same message in the others, and customized messages are not translated automatically. [zia.eun.client-connector:languages]

The browser route is in [ZIA end user notifications: browser templates, browser appearance and the Client Connector-based route](kb:zia.eun).

What to check:
1. Whether the policy is one of those with a Client Connector EUN, then which prerequisites its row lists in Client Connector and in ZIA.
2. Whether a Firewall Filtering EUN is expected for web traffic, since traffic on ports 80, 443 and 8080 identified as HTTP or HTTPS does not trigger it.
