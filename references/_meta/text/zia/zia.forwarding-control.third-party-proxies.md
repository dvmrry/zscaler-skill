# Third-Party Proxy Chaining from ZIA: proxies, proxy gateways and fail-close (zia.forwarding-control.third-party-proxies)
Also called: third-party proxy chaining; zia third-party proxy; proxy gateway; gateway for proxies; fail close proxy gateway; insert x-authenticated-user; forward to third-party proxy; zia downstream proxy; zia as child proxy

Third-Party Proxy Chaining sends selected outbound web traffic from Zscaler on to a third-party proxy service, for example for extra security layers or compliance. Forwarding rules decide which traffic goes, Zscaler forwards matching web traffic to the proxies in the policy, and Zscaler acts as a child (downstream) proxy to the third-party service. [zia.forwarding-control.third-party-proxies:what-it-is] The opposite direction, a customer's proxy chaining into ZIA, is in [Proxy chaining to ZIA: setup, XFF handling and limits](kb:zia.traffic-forwarding.proxy-chaining).

**Setup.** Setup is three steps: configure proxies for the third-party service, create a gateway for those proxies, then add a Forwarding rule with the Proxy Chaining method whose Forward to Gateway is that proxy gateway. [zia.forwarding-control.third-party-proxies:setup-order] The rule criteria are the Proxy Chaining forwarding method covered in [Forwarding Control rule criteria, limits and ordering](kb:zia.forwarding-control.rules) and [Forwarding methods and their required fields](kb:zia.forwarding-control.methods).

**Proxies.** A proxy object has a name, the third-party service's IP address or FQDN, the port on which it listens for requests forwarded from Zscaler, an optional root certificate, and an optional description of up to 256 characters. [zia.forwarding-control.third-party-proxies:proxy-object] The Configuring Third-Party Proxies page says the proxy's root certificate is the one the third-party proxy uses to perform SSL/TLS inspection, that Zscaler uses it to validate the SSL leaf certificates signed by the upstream proxy, and that it appears in the drop-down list only if it is uploaded from the Internet Access > Resources > Root Certificates page. [zia.forwarding-control.third-party-proxies:proxy-root-certificate] The two proxy pages describe the root certificate's use differently [divergence:zia.forwarding-control.third-party-proxies:proxy-root-cert-role]; the root certificate's Type is in [If the upstream proxy (third-party proxy service) performs SSL/TLS Inspection, Zscaler requires installing the proxy service's root certificates to sign the MITM certificates; the certificate is added with Type Proxy Chaining from a PEM file.](kb:zia.ssl-inspection.certificates:root-certs-proxy-chaining). Insert X-Authenticated-User, disabled by default, puts the authenticated user ID in the X-Authenticated-User HTTP header so upstream proxies need not re-authenticate users. For unauthenticated traffic the header value is Unknown, and the third-party proxies should be set to reauthenticate users when they see Unknown. [zia.forwarding-control.third-party-proxies:x-authenticated-user] Whether the Base64 option for that header appears in the console is open [gap:zia.forwarding-control.third-party-proxies:base64-header]. The default limit is 8 third-party proxies, raisable to 255 through Zscaler Support. [zia.forwarding-control.third-party-proxies:proxy-limit]

**Gateways.** A proxy gateway names a primary proxy and a secondary proxy, used when the primary is unreachable, and a Fail Close setting for when both are unreachable: Enable (the default) drops the traffic, Disable sends it directly to the web server without the proxy service. Its description is optional and cannot exceed 256 characters. [zia.forwarding-control.third-party-proxies:gateway-object] The Configuring Gateways for Proxies and Configuring Third-Party Proxy Chaining pages say up to 32 gateway objects can be created. [zia.forwarding-control.third-party-proxies:gateway-limit] The gateway limit differs between pages [divergence:zia.forwarding-control.third-party-proxies:proxy-gateway-limit]. The overview says a gateway can also define SSL/TLS inspection of the proxy chain traffic, but no field is listed [gap:zia.forwarding-control.third-party-proxies:gateway-ssl-inspection]. How unreachable is detected is open [gap:zia.forwarding-control.third-party-proxies:unreachable-detection].

**Scope.** Whether chaining carries only web traffic is open [gap:zia.forwarding-control.third-party-proxies:chaining-scope]. What the `type` values on proxies and gateways mean is open [gap:zia.forwarding-control.third-party-proxies:proxy-type-values], and whether gateways can be created through the API or Terraform is open [gap:zia.forwarding-control.third-party-proxies:gateway-api-creation].

What to check:
1. Whether the proxy gateway named by the Proxy Chaining forwarding rule exists and has both a primary and a secondary proxy.
2. What the gateway's Fail Close setting is, since it decides whether traffic is dropped or goes directly to the web server when both proxies are unreachable.
3. Which page a proxy or gateway limit or the root certificate's role is read from, since the pages disagree.

Sources disagree (name both sides):
- The configure pages give 32 as the gateway object limit, while Ranges and Limitations gives 8 by default and 255 at most. [divergence:zia.forwarding-control.third-party-proxies:proxy-gateway-limit]
  - zscaler-help: The Configuring Gateways for Proxies page (and the Configuring Third-Party Proxy Chaining page) say up to 32 gateway objects can be created.
  - zscaler-help: The Ranges and Limitations page gives a default of 8 gateways, raisable to 255 through Zscaler Support.
  Impact: How many proxy gateways a tenant can create cannot be stated as one number; the pages do not say which is current.
- The two proxy pages describe the proxy's root certificate as used for different things: Zscaler performing inspection, or Zscaler validating leaf certificates signed by the upstream proxy. [divergence:zia.forwarding-control.third-party-proxies:proxy-root-cert-role]
  - zscaler-help: The About Third-Party Proxies page says the root certificate is used by Zscaler to perform SSL/TLS inspection on the traffic it forwards.
  - zscaler-help: The Configuring Third-Party Proxies page says Zscaler uses it to validate the SSL leaf certificates signed by the upstream proxy.
  Impact: Which party inspects the proxied traffic, and what Zscaler does with the certificate, depends on the page read.
