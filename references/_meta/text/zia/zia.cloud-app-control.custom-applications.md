# SaaS Applications page: application status, tags and custom cloud applications (zia.cloud-app-control.custom-applications)
Also called: SaaS Applications page; custom cloud application; custom applications category; application status sanctioned unsanctioned; predefined cloud application

The SaaS Applications page allows adding custom cloud applications, and lists all supported cloud applications with their category and risk index so Cloud App Control rules can be defined for apps not yet discovered in the Shadow IT Report. It also edits the status of all cloud applications (as the Application Information page does), tags applications with predefined and custom labels, and creates cloud app instances that distinguish corporate and personal instances. [zia.cloud-app-control.custom-applications:saas-applications-page]

**Status.** An application's status is Sanctioned (approved for the organization's use because it meets all its security requirements) or Unsanctioned (not approved because of its attack vulnerability). The status is chosen when adding a cloud application risk profile, which a Cloud App Control rule then selects as a criterion; the page's status filter criterion also offers All, Unclassified and Under Review. [zia.cloud-app-control.custom-applications:application-status] What the Unclassified and Under Review statuses mean is open [gap:zia.cloud-app-control.custom-applications:status-values].

**Rows and editing.** Each application row shows its name, category, status (Sanctioned or Unsanctioned), type (All, Custom or Predefined), tags and description, and a risk index from 1 to 5 (1 the lowest risk). A predefined application's name links to its Application Information page, which shows its security attributes. A predefined application's Application Status, Risk Index and Tags can be edited, and a custom one's Cloud Application Name, Application Status, Risk Index, Tags, URLs and Description. A custom cloud application can be deleted. [zia.cloud-app-control.custom-applications:columns-and-editing]

**Custom cloud applications.** A custom cloud application adds an application not already present in Zscaler for discovery and usage metrics (for example number of users, bytes uploaded or downloaded), and associates it with the Custom Applications Cloud App Control rule. By default all custom applications are placed in the Custom Applications category, which is independent of other categories and so cannot be edited. [zia.cloud-app-control.custom-applications:custom-app-purpose] A custom cloud application has a name (displayed when configuring Custom Applications rules), a status of Sanctioned or Unsanctioned, a risk index from 1 to 5, tags, URLs or IP addresses added with Add Items, and an optional description of at most 10,240 characters. [zia.cloud-app-control.custom-applications:custom-app-fields] An organization can have 64 custom cloud applications, each with up to 128 URLs. [zia.cloud-app-control.custom-applications:custom-app-limits] How URLs are formatted and whether IP addresses count toward the URL limit is open [gap:zia.cloud-app-control.custom-applications:url-format-and-limit].

**Caveats.** Risk attributes are not captured for custom cloud applications, SSL/TLS Inspection must be enabled for the custom cloud application lookup, and Custom Applications is enabled by contacting Zscaler Support. If Zscaler creates a predefined cloud application with a URL used in a custom one, the predefined application takes precedence and rules created with the custom application are ineffective; Zscaler notifies customers about the categorization change through Trust Posts. [zia.cloud-app-control.custom-applications:custom-app-caveats]

The Custom Applications rule is in [Cloud App Control categories (rule types), limits and predefined rules](kb:zia.cloud-app-control.rule-types). Tags and risk profiles are in [Cloud Application Risk Profiles in Cloud App Control](kb:zia.cloud-app-control.risk-profiles). Instances of an application are in [Cloud application instances: identifiers, supported applications and limits](kb:zia.cloud-app-control.app-instances).

What to check:
1. Whether a rule written with a custom application is ineffective because Zscaler later created a predefined application with the same URL, and whether SSL/TLS Inspection is enabled for the custom application lookup.
2. Whether the application is Sanctioned or Unsanctioned, since a risk profile can use the status as a Cloud App Control criterion.
3. Whether the custom application is at the 64-application or 128-URL limit before adding one.
