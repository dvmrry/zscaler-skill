# Python SDK errors, accessors and misspelled names on the ZIA client (zia.sdk-python.client-errors-and-accessors)
Also called: zscaler python sdk raiseException; ZscalerAPIError; dns_gatways; BrowserControlSettingsPI; get_custom_file_tytpe; dns_gateways attribute error; isNameL10nTag none; python sdk no exception classes; client.zia.url_filtering; client.zia.activate; url_filtering_rules accessor wrong; python sdk zia call names

This describes the Python SDK as a client, not ZIA behavior. It covers how a failing call surfaces, how service objects are obtained, and the property and method names a script has to write exactly.

**Getting a service.** The OneAPI client builds one `ZIAService` and keeps it. `ZIAService` stores only the request executor, and its service properties, such as `user_management` and `activate`, construct a new API client object on each access. [zia.sdk-python.client-errors-and-accessors:accessor-new-instance] No API client object is kept between accesses to a `ZIAService` property; what persists below the service object is the shared request executor. [zia.sdk-python.client-errors-and-accessors:no-api-object-kept-between-accesses]

**Accessor names.** The URL Filtering rules client is the `url_filtering` property of the ZIA service, and its rule methods are list_rules, get_rule, add_rule, update_rule and delete_rule. [zia.sdk-python.client-errors-and-accessors:url-filtering-accessor] There is no `url_filtering_rules` property on the ZIA service; that name is the URL filtering model module, and the client is `url_filtering`. [zia.sdk-python.client-errors-and-accessors:url-filtering-accessor-no-rules-property] The URL categories client is the `url_categories` property, with list_categories, get_category and delete_category among its methods. [zia.sdk-python.client-errors-and-accessors:categories-accessor] Activation is `client.zia.activate`, an `ActivationAPI` with the methods `status`, `activate`, `get_eusa_status` and `update_eusa_status`. [zia.sdk-python.client-errors-and-accessors:activation-accessor] The activation class has no `get_status` method; the activation status call is `status`. [zia.sdk-python.client-errors-and-accessors:activation-accessor-no-get-status] There is no `client.zia.activation` property; a caller looking for one must use `client.zia.activate`. [zia.sdk-python.client-errors-and-accessors:activation-accessor-no-activation]

**Errors.** [A non-2xx REST response is turned into a `ZscalerAPIError` built from the URL, the response and the parsed body, and the request executor hands it back in the error slot. A response whose Content-Type is JSON but whose body does not parse is returned as an `HTTPError` carrying the status code and body text.](kb:shared.sdk-python.errors:api-error-object) [The client setting `raiseException` defaults to False. When it is true the same API errors are raised as `ZscalerAPIException` (or `HTTPException`) instead of being returned in the error slot.](kb:shared.sdk-python.errors:raise-exception) [The Python SDK defines its own exception classes: `HTTPError` and `ZscalerAPIError` in `zscaler/errors`, `ZscalerAPIException` and `HTTPException` in `zscaler/exceptions`, and `RateLimitExceededError` in `zscaler/utils.py`.](kb:shared.sdk-python.errors:exception-classes) The tuple return and the rule that a caller must test the error slot are in [What the Python SDK returns: result, response and error, and why try/except misses API errors](kb:zia.sdk-python.response-shape).

**Misspelled names.** The unified ZIA service and the legacy ZIA client expose the DNS gateway client as the property `dns_gatways` (misspelled), imported from the module `zscaler/zia/dns_gatways.py`. [zia.sdk-python.client-errors-and-accessors:dns-gateway-accessor-misspelled] No `dns_gateways` property exists on either the unified ZIA service or the legacy ZIA client, so the correctly spelled name fails. [zia.sdk-python.client-errors-and-accessors:dns-gateway-no-correct-spelling] The browser control settings client class is spelled `BrowserControlSettingsPI` (no `A`), and the unified service and the legacy client both import and return it under that name; the property is spelled correctly as `browser_control_settings`. [zia.sdk-python.client-errors-and-accessors:browser-control-class-misspelled] The custom file types client names its single-item getter `get_custom_file_tytpe` (misspelled); it has no `get_custom_file_type`, which is the name a reader would expect. [zia.sdk-python.client-errors-and-accessors:custom-file-type-getter-misspelled]

**A fixed response-parsing bug.** Before Python SDK 1.9.22, response keys with a digit-letter boundary such as `isNameL10nTag` or `ipV6Enabled` were re-cased by a generic camel-case helper (`L10n` became `L10N`), so the model field came back as `None`. The release replaced the normalizer with the SDK's own `to_lower_camel_case`, and the current response formatter uses it. [zia.sdk-python.client-errors-and-accessors:l10n-key-corruption-fixed] Release 1.9.22 gave `list_network_services_lite()` a dedicated `NetworkServicesLite` model with a nested `NetworkServiceExtensions` block that exposes the `extensions.tag` payload. [zia.sdk-python.client-errors-and-accessors:network-services-lite-model] Paging and search behavior of the same client is in [How the Python SDK builds, pages and retries ZIA requests](kb:zia.sdk-python.request-conventions).

What to check:
1. Whether a failing call returns an error object or raises, since that is a client setting and not a property of the call.
2. Which spelling an attribute or method takes before writing it, because several are misspelled in the SDK and an expected name raises AttributeError.
3. Which SDK release a tenant script runs when a lite network-service field reads None.
4. That the accessor and method names in a script exist on the pinned SDK, rather than copying them from older notes.
