# CASB SaaS Security Insights logs: what the records mean, filtering, export and streaming (zia.casb.insights-logs)
Also called: saas security insights logs; casb logs; saas security report; shadow it report; insights log columns; run id; scan id; dlp identifier; cloud nss saas security; export 100K; 180 days

Insights logs are the record of what each scan did. SaaS Security Insights logs show every scan performed by the Zscaler SaaS Connector for a SaaS application tenant and are stored for 180 days on the Nanolog servers. [zia.casb.insights-logs:retention-180]

**Columns and filters.** Each application category has its own set of columns and its own set of filters, with column sections for Collaboration, CRM, Email, File, Gen AI, ITSM, Public Cloud Storage and Repository. [zia.casb.insights-logs:columns-per-category] The category filter sentence lists Collaboration, CRM, Email, File, Gen AI, ITSM and Repository, without Public Cloud Storage, although the article has Public Cloud Storage columns and filters. [zia.casb.insights-logs:category-filter-omits-storage] SaaS Security Insights charts each file scanned; its unit is the number of scans, message scans or file scans depending on the application category, and the category filter offers All, Collaboration, CRM, Email, File, Gen AI, ITSM, Public Cloud Storage or Repository; as an example, selecting the application category Email limits the Application filter to email apps. [zia.casb.insights-logs:saas-insights-units] SaaS Security Insights data types include one for the incident type (DLP or Malware); one that automatically changes the application category to Email when selected; one that defaults the category to File but also works with Collaboration, CRM, Gen AI, ITSM, Public Cloud Storage and Repository; and the application category type, whose own description lists CRM, file, email, Gen AI, ITSM and repository. [zia.casb.insights-logs:saas-insights-data-types] Amazon S3, Google Cloud Platform and Microsoft Azure are enabled for SaaS Security Insights by contacting the Zscaler Account team. [zia.casb.insights-logs:saas-insights-clouds] The SaaS Security 100K export figure is one of three on different pages [zia.insights.logs:export-ceiling](kb:zia.insights.logs:export-ceiling).

**Reading a record.** The User column shows the name of the gateway location when an internet gateway location is specified and authentication is not required; the Department column shows it when authentication is not required and the traffic comes from a location specified in the service. [zia.casb.insights-logs:user-shows-location] File owners not provisioned to the Internet & SaaS service appear under Non-Provisioned Owner, and once such an owner inside the organization is provisioned the service logs them under User. [zia.casb.insights-logs:non-provisioned-owner] Logged Time is when the service performs a scan, evaluates policies and logs the result; Scan Time is the milliseconds the policy took to scan content within the tenant. [zia.casb.insights-logs:logged-time] A Run ID identifies each run, where a run is a scan being stopped and started; a Scan ID identifies each scan defined in the Historic Scan Configuration; and a File ID lets an administrator follow the scan trail of a file scanned more than once. [zia.casb.insights-logs:run-scan-file-ids] The DLP Identifier is sent in the alert email to auditors whenever a DLP rule is hit and the alert is configured, and works as a filter to find the exact record. [zia.casb.insights-logs:dlp-identifier] For email records the Owner Name is the owner of the mailbox holding the questionable email, which is the sender for a DLP finding and the recipient for a malware finding. [zia.casb.insights-logs:email-owner-name] Gen AI records add a Bot Name (the bot that responded to the DLP), a Sender Type (bot, system or user) and a Transaction Message that gives the reason a transaction failed and shows N/A for successful ones. [zia.casb.insights-logs:genai-columns] The scan identifiers matter when restarting a scan: [CASB scan schedules: states, historical data, stop and restart](kb:zia.casb.scans). When the SaaS application detects malware itself, no rule action is logged: [No Data at Rest Scanning DLP or Malware policy rule action is performed when the SaaS application itself detects the malware, and in that case the Zscaler service does not run its own anti-virus.](kb:zia.casb.malware-rules:saas-detection-skips-action).

**Filtering and export.** Filters such as Users, Departments and Locations take up to 200 values and can include or exclude them, and string-match filters such as Threat Super Category also accept Does Not Contain, Does Not Start With, Does Not End With, Is Null and Is Not Null. [zia.casb.insights-logs:filters-200-values] A custom time frame can end up to 92 days after its start date. [zia.casb.insights-logs:custom-range-92] A CSV download exports only the visible columns, up to 100K lines at a time, and at most 20 export requests are allowed per hour. [zia.casb.insights-logs:csv-export] Whether a Sub-URL field exists here is open [Whether the Sub-URL limit applies to SaaS Security logs](kb:zia.casb.limits:sub-url-in-saas-logs), with the length limit.

**Streaming.** Cloud NSS allows one feed per log type per Cloud NSS instance, with SaaS Security given as a log type, and streams logs from the Zscaler cloud to a SIEM without the need to deploy an NSS virtual machine for Web or Firewall; the feed output format (for example JSON) is selected per feed. [zia.casb.insights-logs:cloud-nss-feed] The Insights logs article describes the NSS virtual machine as streaming web traffic logs in real time from the Nanolog to a SIEM. [zia.casb.insights-logs:nss-vm-described-as-web] Whether a VM-based feed can carry SaaS Security is open [gap:zia.casb.insights-logs:nss-vm-saas-security]. [The limits page's Cloud & Branch Connector section lists 2 NSS servers and 8 feeds per server, with 1,024 users, departments, locations, clients and threat names per feed.](kb:shared.nss.feeds:cbc-nss-limits) The feed's field names are open [gap:zia.casb.insights-logs:nss-feed-fields], and a licensing requirement is open [gap:zia.casb.insights-logs:cloud-nss-licensing]. Audit-log streaming is in [Streaming the ZIA admin audit log to a SIEM (Cloud NSS ADMIN_AUDIT)](kb:zia.audit-logs.streaming).

A SaaS Security feed over Cloud NSS follows the feed delivery rules: [A Cloud NSS feed treats HTTP 200 or 204 from the SIEM as a successful batch, treats 400 as a parsing error and drops the batch, and retries the same batch on any other code for up to one hour before dropping it.](kb:shared.nss.reliability:cloud-nss-http-codes)

The feed is configured in the admin portal: Cloud NSS feeds are configured on the Cloud NSS Feeds page under Data Explorer > Log Streaming > Internet Log Streaming - Nanolog Streaming Service > NSS Collector Feeds. [zia.casb.insights-logs:cloud-nss-config-location]

The Shadow IT Report can be scheduled daily, weekly or monthly and downloaded as CSV. [zia.casb.insights-logs:shadow-it-report-csv] Whether Shadow IT discovery events also appear in the Insights logs or the feed is open [gap:zia.casb.insights-logs:shadow-it-in-insights-logs].

Inline cloud app traffic is in the web feed instead: The web NSS feed output format includes the cloud application fields appname, appclass and app_risk_score, and prompt_req, the prompt entered by the user in a generative AI application. [zia.casb.insights-logs:web-nss-cloud-app-fields]

The web feed appclass vocabulary differs from the SaaS Security categories: The Web NSS appclass examples are Administration, Collaboration and Web Mail, drawn from the Cloud App Control Policy page; Administration and Web Mail are not among the eight SaaS Security log categories (Collaboration, CRM, Email, File, Gen AI, ITSM, Public Cloud Storage and Repository). [zia.casb.insights-logs:web-appclass-vocabulary]

The field that discriminates a record's category is open [gap:zia.casb.insights-logs:record-category-discriminator].

What to check:
1. Whether a finding is older than the 180-day retention, and whether the time frame stays within 92 days of its start.
2. Whether the Run ID and Scan ID place a record in the scan run being investigated.
3. Whether an empty User or Department column reflects a gateway location or a non-provisioned owner.
4. Whether the question needs the SaaS Security feed fields or licensing, which no source states.
