# Firewall rule actions (zia.firewall.actions)
Also called: block_drop; block_reset; block_icmp; eval_nwapp; bypass_ips; firewall action values; full logging firewall

A firewall rule's action decides what happens to the flow once the rule matches.

A Firewall Filtering rule's action is one of ALLOW, BLOCK_DROP, BLOCK_RESET, BLOCK_ICMP or EVAL_NWAPP. [zia.firewall.actions:filtering-action-values] An IPS Control rule's action is one of ALLOW, BLOCK_DROP, BLOCK_RESET or BYPASS_IPS. [zia.firewall.actions:ips-action-values] BYPASS_IPS is the API value for the IPS Control option that lets specific traffic bypass Zscaler's IPS. Firewall Filtering has no such value. [zia.firewall.actions:bypass-ips-is-bypass]

The Firewall Insights Logs Action filter describes Block/Drop as silently blocking matching packets; Block/ICMP as dropping them and sending the client an ICMP error message of Type 3 (Destination Unreachable) and code 9 or 10; and Block/Reset as, for TCP traffic, dropping all matching packets and sending the client a TCP reset, and for non-TCP traffic the same as Block/Drop. IPS Drop and IPS Reset are the IPS rule counterparts. [zia.firewall.actions:block-wire-behavior] The help pages give different ICMP codes for Block/ICMP [divergence:zia.firewall.actions:block-icmp-code]. The default Firewall Filtering rule's edit page describes Allow as allowing packets that match the rule to pass through the firewall, and Block/Reset as, for TCP traffic, dropping all matching packets and sending the client a TCP reset, and for non-TCP traffic the same as Block/Drop. [zia.firewall.actions:allow-and-reset-descriptions] What EVAL_NWAPP does, and whether a rule with it ends evaluation, is open [gap:zia.firewall.actions:action-semantics]. The Firewall Filtering Capture option requires Traffic Capture to be enabled in Advanced Settings and appears only when Block is selected for Network Traffic; it stores the traffic captured during a block action in PCAP files for later analysis. [zia.firewall.actions:capture-action] Aggregate logging groups together individual sessions based on user, rule, network service and network application and records them periodically, approximately every 15 minutes. Full logging logs all sessions matching the rule individually in detail, with some exceptions. [zia.firewall.actions:logging-modes] On Standard Firewall the Aggregate or Full logging option is not selectable: aggregate logging is used for all traffic on Allow rules, full logging for Allow rules requires Advanced Firewall or the Full Logging license, and Block rules log in full. On Advanced Firewall both options are selectable: full logging on an Allow rule applies to all traffic except web (HTTP/HTTPS) and FTP/FTPS sessions managed by the secure web gateway, which are always aggregated in Firewall logs because web transactions are logged in detail in Web logs, and full logging on a Block rule applies to all traffic. [zia.firewall.actions:logging-by-tier] The Terraform docs say only Block rules support full logging on a Firewall Filtering rule and that full logging on all other rules requires the Full Logging license. The docs describe Aggregate as grouping sessions by user, rule, network service and network application and recording them periodically. [zia.firewall.actions:full-logging-block-only] The Terraform docs and the help differ on full logging for Allow rules [divergence:zia.firewall.actions:full-logging-allow-rules]. End user notification on a Firewall Filtering rule is supported only with Block actions and requires Advanced Firewall; it is supported on Windows devices running Zscaler Client Connector version 4.8 or later over Z-Tunnel 2.0. [zia.firewall.actions:eun-support] The log fields that record the action are in [Where the firewall sits in the traffic path](kb:zia.firewall.traffic-path).

3. Whether an answer about what the client sees on a block action rests on the Insights console descriptions, and whether an answer about EVAL_NWAPP rests on a source, since none documents it.

Sources disagree (name both sides):
- Whether Allow rules can use full logging: the Terraform docs say only Block rules support it and other rules need the Full Logging license, while the help's default-rule table has Advanced Firewall Allow rules logging in full (except web and FTP sessions) and the Standard column needs Advanced Firewall or the Full Logging license. [divergence:zia.firewall.actions:full-logging-allow-rules]
  - tf-zia: Only Block rules support full logging; full logging on all other rules requires the Full Logging license.
  - zscaler-help: On Advanced Firewall, full logging on an Allow rule applies to all traffic except web (HTTP/HTTPS) and FTP/FTPS sessions; on Standard Firewall, full logging for Allow rules requires Advanced Firewall or the Full Logging license.
  Impact: Do not say Allow rules cannot use full logging, or that only a license enables it; give both sources and check the tenant's firewall tier and licenses.
- The ICMP code Block/ICMP sends: the default-rule edit page gives Type 3 Code 13, while the Firewall Insights Logs filter page gives code 9 or 10. [divergence:zia.firewall.actions:block-icmp-code]
  - zscaler-help: Block/ICMP sends an ICMP error of Type 3 (Destination Unreachable) and Code 13 (Communication Administratively Prohibited).
  - zscaler-help: Block/ICMP sends an ICMP error of Type 3 (Destination Unreachable) and code 9 or 10 (network/host administratively prohibited).
  Impact: Do not state one ICMP code as settled for Block/ICMP; give both help positions. No lab observation is recorded, and a packet capture of a Block/ICMP rule would settle it.
