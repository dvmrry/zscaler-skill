# DLP notification templates: auditor email subject, macros, attachments and TLS (zia.dlp.notification-templates)
Also called: DLP notification template; dlp auditor email; dlp email macros; DLP Violation subject; dlpNotificationTemplates

DLP notification templates define the email notifications sent to the organization's auditors when a DLP policy is triggered, and DLP policy rules can reference them. The Configuring page says templates can be referenced when configuring policy rules for inline web DLP, SaaS Security Data at Rest Scanning DLP, Outbound Email DLP and Endpoint DLP; the About page names inline web and SaaS Security API DLP policies. [zia.dlp.notification-templates:what-it-is] The DLP Notification Templates page lists each template's Name and its Subject, the subject text including any macros, and lets an admin edit or delete a template. [zia.dlp.notification-templates:templates-page] Whether a rule sends a notification at all, and the end user notification, are in [Where a DLP match goes: notification, ICAP, Incident Receiver and Cloud-to-Cloud](kb:zia.dlp.incident-forwarding).

**Subject line.** By default, the Subject line uses the text DLP Violation: with the ${TRANSACTION_ID} and ${RULENAME} macros, which list the ID of the transaction that triggered the DLP rule and the triggered rule's name; the text can be modified. For Outbound Email DLP notification templates the Subject field is populated the same way, but the service does not support the ${RULENAME} macro in their subject line. [zia.dlp.notification-templates:default-subject] The inline web DLP subject-line macros are ${ACTION}, ${DEPARTMENT}, ${DLPMD5}, ${ENGINE_EXPRESSION}, ${ENGINES}, ${FILENAME}, ${FILESIZE}, ${REFERRER_URL}, ${RULENAME}, ${TIMESTAMP}, ${TOTAL_TRIGGERED_DICTIONARIES}, ${TOTAL_TRIGGERED_ENGINES}, ${TRANSACTION_ID}, ${URL} and ${USER}. ${DLPMD5} and ${TRANSACTION_ID} can be used as a filter in the Web Logs to find the relevant transactions, and ${USER} gives "unknown" if the user's name is unavailable. [zia.dlp.notification-templates:inline-subject-macros]

**Macros per channel.** The Configuring page gives a subject-line macro list and a message-body macro list for each of Inline Web DLP, SaaS Security Data at Rest Scanning DLP, Outbound Email DLP and Endpoint DLP, and the About page says the notification template macros for inline web DLP and SaaS Security API DLP are different. [zia.dlp.notification-templates:macros-per-channel] For inline web DLP and SaaS Security Data at Rest Scanning DLP, the ${TRANSACTION_ID}, ${USER}, ${URL}, ${TYPE}, ${DLPMD5}, ${ENGINES_IN_RULE} and ${DICTIONARIES} macros are included in the notification by default. [zia.dlp.notification-templates:default-included-macros] Which subject-line macros the Outbound Email and Endpoint lists accept beyond those shown, and the page's "all three notification template types" wording against its four lists, are open [gap:zia.dlp.notification-templates:subject-macro-coverage].

**Message body.** A template has a Message as Plain Text and a Message as HTML, a customized message delivered through email (Delivery Status Notification) to the auditor when a policy triggers and blocks content. The two fields are independent, so a change in one must be made by hand in the other. An admin can edit the Name, Subject, Message as Plain Text and Message as HTML fields later, and enable or disable the Attach Violating Content and Use TLS settings. [zia.dlp.notification-templates:message-formats] In the inline web DLP message-body list, ${DICTIONARIES} lists the triggered dictionaries with the match count (for dictionaries such as Credit Cards) or score (for machine learning dictionaries such as Financial Statements or Source Code). ${TYPE} is the Cloud App category of the destination traffic, or "Web Posting" if the destination matches none. ${SEVERITY} is the triggered rule's severity (for example Information, Low, Medium or High), and ${CLIENT_IP} is the user's IP address, if available. [zia.dlp.notification-templates:body-macro-semantics] In the inline web DLP message body, ${DICTIONARIES_IN_RULE} and ${DICTIONARIES_NOT_IN_RULE} share a maximum limit and list up to 25 dictionaries combined, and ${ENGINES_IN_RULE} and ${ENGINES_NOT_IN_RULE} share a maximum limit and list up to 25 engines combined; if more than 25 are triggered the IN_RULE macro is prioritized. In the vendor's dictionary example, of 35 triggered dictionaries the 15 in the rule are all listed and ${DICTIONARIES_NOT_IN_RULE} lists only 10 of the other 20. [zia.dlp.notification-templates:body-list-limits] The inline web DLP, SaaS Security Data at Rest Scanning DLP and Endpoint DLP message-body lists each give ${DLPTRIGGERS}, which lists the content that matched a dictionary; each says the service reports 25 items by default, with a possible increase to 125 items through Zscaler Support. The inline web and SaaS entries add a 15-byte prefix and suffix around the DLP trigger. ${OTHER_MATCHED_RULES} specifies up to 8 rules that were matched but not triggered for a violation, and applies only to organizations with Evaluate All Rules mode enabled; otherwise it does not return a value. [zia.dlp.notification-templates:dlptriggers-and-other-rules] Channel-specific body macros: ${CASB} gives the name of the SaaS application tenant, the file path of the file that triggered the SaaS Security Data at Rest Scanning DLP rule, collaborators and collaboration scope. ${EMAIL_DETAILS} returns a table common to all recipients with details about the email that triggered the DLP rule, and ${EMAIL_TRIGGERED_RECIPIENTS} returns a dynamic table of details about the email's recipients. Endpoint DLP has ${EPDLP_*} macros such as ${EPDLP_ACTTYPE}, ${EPDLP_CHANNEL}, ${EPDLP_DEVNAME}, ${EPDLP_SRCNAME} and ${EPDLP_DSTNAME}, and ${EPDLP_CON_ACT} and ${EPDLP_CON_JUS} apply only when the rule Action is Confirm. [zia.dlp.notification-templates:saas-email-endpoint-body-macros]

**Attachments and TLS.** Attach Violating Content adds an attachment of the violating content to the notifications emailed to auditors. Use TLS sends the notification email over a TLS connection and needs the email recipient's SMTP server to support TLS; Zscaler recommends TLS because any email sent might contain sensitive content. The attachments and the violating content in them are never stored on disk; the attachments, violating content and body of the notification emails are placed in RAM, the service creates and sends an encrypted email through TLS, and all data is then deleted from RAM. [zia.dlp.notification-templates:attach-and-tls]
