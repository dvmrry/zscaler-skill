# How the Internet & SaaS performance troubleshooting runbook scopes a slowness case and routes it to its pages (zia.troubleshooting.performance-runbook)
Also called: Internet & SaaS Performance Support Troubleshooting Runbook; internet and saas performance runbook

**Scope.** The runbook focuses on user traffic forwarded to Zscaler public data centers only, and its Zscaler Public Data Center section assumes all customer traffic is being affected by specific locations. [zia.troubleshooting.performance-runbook:public-dc-scope] The Internet & SaaS performance runbook starts by asking whether all traffic is affected or only non-web traffic, to see whether web and non-web traffic follow different routes. [zia.troubleshooting.performance-runbook:scope-traffic-type] When only non-web traffic is affected, the runbook has you ensure users forward the non-web traffic for the affected service through Zscaler, filtering Web Insights logs for an affected user or location and checking the Traffic Forwarding column to validate the forwarding method. [zia.troubleshooting.performance-runbook:validate-forwarding-method]

**Web and all traffic.** Under its Web Only or All Traffic heading, the runbook checks whether the user is connected to the nearest Zscaler data center, using the getGatewayEndpoints URL on the PAC server with a srcip parameter. [zia.troubleshooting.performance-runbook:nearest-dc-branch] The runbook splits slowness by whether the issue affects Z-Tunnel 2.0 only, a specific destination or a poor Speedtest result: for specific destinations it first checks which public data centers the destinations are routed to, for a poor Speedtest result it goes to the Zscaler Public Data Center section if there is an actual impact on end user performance, and its Zscaler Public Data Center section reviews performance for traffic from all destinations. [zia.troubleshooting.performance-runbook:destination-split]

**Non-web traffic.** To validate that a user forwards non-web traffic to Zscaler, the runbook checks Firewall Insights on Top 100 Network Service for non-web traffic and for services such as DNS, ICMP, SNMP and SFTP. [zia.troubleshooting.performance-runbook:firewall-insights-nonweb] With PAC or Z-Tunnel 1.0, non-web traffic is not forwarded to Zscaler, so the runbook says to check the internal network (PBR or routing) for non-web traffic going to Zscaler or to local breakouts. [zia.troubleshooting.performance-runbook:pac-ztunnel1-nonweb] With GRE, IPSec or Z-Tunnel 2.0, non-web traffic can be forwarded with additional configuration; if it is absent from Firewall Insights logs, the runbook says to check PBR, routing or the Client Connector forwarding profile. [zia.troubleshooting.performance-runbook:gre-ipsec-ztunnel2-nonweb]

**Z-Tunnel 2.0.** If the forwarding method is Z-Tunnel 2.0, the runbook compares Z-Tunnel 2.0, PAC and manual proxy; slowness only with Z-Tunnel 2.0 goes to Client Connector troubleshooting, slowness with both Z-Tunnel 1.0/PAC and Z-Tunnel 2.0 goes to the speedtest section. [zia.troubleshooting.performance-runbook:ztunnel2-only-routing] The Client Connector side is in [How the Client Connector performance troubleshooting runbook classifies slowness by pattern and routes it to its pages](kb:zcc.troubleshooting.performance-runbook).

**Runbook pages.** Manual proxy, direct access, Trust Portal and speed test checks are in [Performance runbook isolation tests: manual proxy, direct access, Trust Portal and speed tests](kb:zia.troubleshooting.performance-runbook.isolation-tests), and the nearest data center checks are in [Performance runbook: why a user is not connecting to the nearest data center (MaxMind, subcloud, Auto Geo Proximity)](kb:zia.troubleshooting.performance-runbook.nearest-data-center). GRE and IPSec tunnel limits are in [Performance runbook: Check for Traffic Imbalance, Z-Tunnel 2.0 over GRE or IPSec, tunnel limits and gateway-variable load distribution](kb:zia.troubleshooting.performance-runbook.tunnel-overhead), WinMTR is in [Performance runbook: collecting and reading a WinMTR](kb:zia.troubleshooting.performance-runbook.mtr), and ZDX, Bandwidth Control and additional checks are in [Performance runbook: ZDX evaluation, Bandwidth Control throttling and additional network checks](kb:zia.troubleshooting.performance-runbook.zdx-and-bandwidth). The Cloud Performance Test itself is in [Measuring ZIA performance: the Cloud Performance Test and why common speed tests mislead](kb:zia.troubleshooting.performance-testing).
