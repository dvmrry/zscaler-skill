# Endpoint DLP policy rules: channels, criteria, actions (Allow, Block, Confirm, Protect) and notifications (zia.dlp.endpoint-rules)
Also called: endpoint dlp rule; endpoint dlp channel; endpoint dlp confirm action; endpoint dlp protect; zenc; lost and found; application file access; endpoint dlp clipboard

An Endpoint DLP rule's Channel selects whether the rule applies to Printing, Removable Storage, Network Share, Personal Cloud Storage, Application File Access, or Clipboard. To access the Application File Access and Clipboard features, the page says to contact the Zscaler Account team. An exception rule's Channel is inherited from the parent rule and cannot be changed. [zia.dlp.endpoint-rules:channels] The Endpoint DLP policy page describes its Channel column as the rule's resource channel (Printing, Removable Storage Devices, Network Share, or Personal Cloud Storage), its Exceptions column as the number of exceptions associated with the rule, its Action column as Allow, Block, or Confirm, and its Severity column as High, Medium, Low, or Information. One or more labels can be selected from the Rule Label drop-down menu to filter the table. [zia.dlp.endpoint-rules:policy-page-columns]

**Who and where.** For the DLP rule to trigger, the Zscaler service must detect at least one of the rule's selected users, groups, or departments. For User Risk Profile, selecting no value ignores the criterion in the policy evaluation. [zia.dlp.endpoint-rules:who-criteria] The User Risk Profile levels are Low (user risk scores 0 to 29), Medium (30 to 59), High (60 to 79) and Critical (80 to 100). [zia.dlp.endpoint-rules:user-risk-levels] A rule selects Devices and Device Groups (Any includes all) and Device Trust Level (High Trust, Medium Trust, Low Trust, or Unknown); the trust levels assigned to the devices are based on the posture configurations in the Zscaler Admin Console. [zia.dlp.endpoint-rules:where-criteria]

**Content.** Content Matching selects up to 4 DLP engines. If None is selected, the Zscaler service does not use DLP engines to scan the content and instead functions as a filter, only flagging content based on the criteria specified. The list of available file types changes based on whether DLP engines are used for content inspection. [zia.dlp.endpoint-rules:content-matching] The Endpoint DLP policy rules article says the Zscaler DLP engines support files up to 100 MB, and that the maximum size also applies to files extracted from archive files. The other articles' figures are in zia.dlp.inspection-limits. [zia.dlp.endpoint-rules:file-size-limit] The default minimum data size, 0 KB, means there is no minimum data size requirement. [zia.dlp.endpoint-rules:minimum-data-size]

**Channel targets.** The rule fields that name targets appear by channel: Printers and Printer Tag only for Printing, Removable Storage Device Tags only for Removable Storage, Network Share Tags only for Network Share, and Personal Clouds only for Personal Cloud Storage (iCloud is supported only for macOS). Application File Access takes up to 8 Applications or up to 8 Application Tags and requires an application or application tag. Clipboard takes up to 8 Destination Applications or up to 8 Destination Application Tags, and selecting Any applies the rule to all destination applications. [zia.dlp.endpoint-rules:channel-target-fields] The service enforces Application File Access rules when users open files that contain sensitive information, and does not monitor activity the application takes after opening the file (for example sending or transferring). Zscaler recommends not using an Application File Access rule with browsers or email clients, because the service cannot distinguish some necessary destinations and blocks legitimate transactions. [zia.dlp.endpoint-rules:application-file-access-semantics] Which direction a Clipboard rule monitors is disputed [divergence:zia.dlp.endpoint-rules:clipboard-direction]. Resources and tags are in [Endpoint DLP resources and resource tags: network shares, printers, removable storage, endpoint applications](kb:zia.dlp.endpoint-resources).

**Actions.** Allow allows and logs the activity and Block blocks and logs it. With Confirm the user can either justify the activity to continue or cancel it, and the service logs the activity in both cases. Confirm is supported only for the Removable Storage, Network Share, Printing, and Personal Cloud Storage channels; with the Printing channel, end users on macOS get a prompt to justify the activity but cannot cancel it, and the service monitors and reports the activity instead. [zia.dlp.endpoint-rules:actions-allow-block-confirm] On Removable Storage and Network Share, if a user saves a file directly to a destination without a detectable source path (for example with Save As in Word), the service does not block the operation. It creates a placeholder file and notifies the user that the original is in a Lost & Found location: /ProgramData/Zscaler/ZDP/User Files/<username>/Lost and Found/ on Windows or /Library/Application Support/Zscaler/ZDP/User Files/<username>/Lost and Found/ on macOS. For Personal Cloud Storage the placeholder ensures the service does not repeatedly block the sync attempts for the original file. [zia.dlp.endpoint-rules:block-without-source-path] Protect appears only when the Channel is Removable Storage. It encrypts only the affected files, not the removable storage device, saving a separate encrypted (.zenc) file on the device without altering the original file or its path. After encryption the file can only be decrypted by members of the same organization running Endpoint DLP, no additional key management is needed because the key is unique to each organization, and it is designed for short-term file transfers, not long-term backup. [zia.dlp.endpoint-rules:protect-action] Users who receive an encrypted file on a removable storage device must right-click it and select Decrypt. Decrypted files are placed in /ProgramData/Zscaler/ZDP/Decrypted Files/<username>/ on Windows or /Library/Application Support/Zscaler/ZDP/Decrypted Files/<username>/ on macOS. When the file is cut and pasted onto the device, the service saves the .zenc file to the device and a copy of the decrypted file in a directory the page names. [zia.dlp.endpoint-rules:protect-decrypt-paths] How the actions rank is open [gap:zia.dlp.endpoint-rules:action-ranking-ref], and so are the API wire values for the newer channels and these actions [gap:zia.dlp.endpoint-rules:wire-values].

**Details and notifications.** A rule's description cannot exceed 10,240 characters. A disabled rule is not actively enforced but keeps its place in the rule order; the service skips it and moves to the next rule. Severity is High, Medium, Low, or Information. [zia.dlp.endpoint-rules:details-limits] If no auditor and notification template are selected, no notification is sent for the rule. Email Auditor Type is Hosted database or External to the organization. End User Notification is Show or Hide, and the Notification Message is the channel's default EUN message or a custom one; the type of EUN messages on the endpoint depends on the rule's Action, and custom messages can be configured for the Allow, Block, and Protect actions. [zia.dlp.endpoint-rules:notifications]

Rule selection when several rules match is in [How Endpoint DLP reaches the endpoint: prerequisites, policy delivery, offline enforcement, scans, and what the vendor says about evaluating all rules and exception rules](kb:zia.dlp.endpoint-enforcement). Forwarding after a match is in [Where a DLP match goes: notification, ICAP, Incident Receiver and Cloud-to-Cloud](kb:zia.dlp.incident-forwarding).

Sources disagree (name both sides):
- The rule article describes a Clipboard rule as monitoring content pasted into the destination applications; the resources article describes applications as the source content is copied from. [divergence:zia.dlp.endpoint-rules:clipboard-direction]
  - zscaler-help: This setting monitors for sensitive content pasted from users' clipboards into the specified applications.
  - zscaler-help: You can then use applications to create rules that prevent users from copying sensitive content to their clipboard from the applications.
  Impact: Whether a Clipboard rule's applications are the paste destination or the copy source is unclear; the rule article's fields are named Destination Application, and the pages do not say which direction governs.
