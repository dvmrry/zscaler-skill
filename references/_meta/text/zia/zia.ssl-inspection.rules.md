# SSL/TLS inspection rule order, predefined and default rules, limits (zia.ssl-inspection.rules)
Also called: ssl rule order; ssl inspection rule limit; 255 ssl rules; predefined ssl rule; default ssl rule; ssl rule name length; zia-66

Which SSL rule applies is a first-match question with three wrinkles: rules you did not write (predefined and default), read-only flags that break writes if echoed back, and a size ceiling on the rule set.

**Order.** SSL/TLS inspection rules are evaluated in ascending numerical order, top-down, and the first match decides. [zia.ssl-inspection.rules:ascending-order] A disabled SSL/TLS inspection rule is skipped but keeps its place in the rule order. [zia.ssl-inspection.rules:disabled-holds-slot] To inspect something an exemption would otherwise cover, place an inspection rule before the exemption; for example inspect Client Connector device groups first, then exempt the locations. [zia.ssl-inspection.rules:inspect-before-exempt]

**Predefined and default rules.** Zscaler ships predefined special rules: Zscaler-Recommended Exemptions (enabled by default), O365 tenant restriction inspection rules, an O365 One Click rule, a UCaaS One Click rule, and an Unauthorized Traffic Bypass for IoT Classifications rule. The help page calls them not editable, to be implemented as is, but they can be enabled or disabled. The IoT rule is disabled by default and cannot be deleted; for that rule only rule order, admin rank, status, label and the Evaluate/Bypass choice can change. [zia.ssl-inspection.rules:predefined-rules] On the predefined One Click rule in SSL/TLS Inspection, the Rule Order, Admin Rank, Rule Status, Rule Label and Description can be modified, and under the Do Not Inspect action the admin can choose Evaluate Other Policies (URL Filtering and Cloud App Control) or Bypass Other Policies; other attributes cannot be edited. With the SSL/TLS bypass, policy application is limited by the lack of decryption: subsequent policy action is likely limited to only the domain portion and not the full URL, so for sample.com/chatBotAI only sample.com is seen. [zia.ssl-inspection.rules:one-click-rule-edit] The Understanding Predefined Firewall Filtering Rules page says that if "this rule" is enabled, any Microsoft 365 traffic is exempted from SSL/TLS Inspection and other web policies such as URL Filtering and Cloud App Control, and that a URL policy created to block OneDrive or SharePoint is not applied. [zia.ssl-inspection.rules:one-click-exempts-web-policies] Whether the Evaluate Other Policies choice and that exemption agree is open [gap:zia.ssl-inspection.rules:one-click-evaluate-vs-exempt]. The Leading Practices rule set ends with a Default rule whose action is Do Not Inspect with Evaluate Other Policies. The row above it, rule 7, is Inspect All with criteria Any/Any/Any and action Inspect, and the guide's list of the rule set describes item 7 as the new default that inspects everything not exempted. [zia.ssl-inspection.rules:default-rule] Whether the Default action interacts with URL Filtering's own default is still open: see [Where SSL inspection sits in ZIA web policy evaluation (the two passes)](kb:zia.ssl-inspection.pipeline).

**Flags.** `predefined` is a read-only boolean marking Zscaler's predefined SSL rules, `defaultRule` is a boolean marking the default rule (the contract does not mark it read-only), and `accessControl` is a read-only privilege (`NONE`, `READ_ONLY`, `READ_WRITE`) on the rule based on the admin's role-based access. [zia.ssl-inspection.rules:marker-fields] Predefined SSL rules cannot be deleted; through the provider certain attributes such as description, state and labels can still be changed on them, though not all custom-rule attributes apply, and Default Rules must not be imported or managed because the API does not support managing them. [zia.ssl-inspection.rules:predefined-management] The API rejects a PUT on a predefined SSL rule that carries the server-managed fields `predefined`, `defaultRule` and `accessControl` (the contract marks only `predefined` and `accessControl` read-only); the provider clears all three in its reorder callback, so a reorder that reads a rule and writes it back must do the same. Do not echo them back. [zia.ssl-inspection.rules:strip-readonly-on-put] The Terraform side of reordering is in [How the ZIA Terraform provider applies rule order](kb:zia.terraform.rule-order).

**Size and shape.** The tenant can hold 255 SSL Inspection rules, made up of 245 custom and 10 predefined. The limits table lists no support-raise path for this row, unlike the 1,024 'All Other Policy Rules' row, which is annotated as raisable to 2,048 by contacting the Zscaler Account team. [zia.ssl-inspection.rules:rule-cap] A rule name can be at most 31 characters. [zia.ssl-inspection.rules:name-length] The SSL inspection rule list returns every rule in one response; the Go SDK reads it with a single call because the API does not support pagination. [zia.ssl-inspection.rules:no-pagination]

**Zscaler's own exception list.** The Zscaler exception list for SSL/TLS inspection includes a few dozen known domains or destinations, such as Zscaler service IP addresses for Zscaler best practices, contactservice.zoom.us for UCaaS bypass and self.events.data.microsoft.com for Microsoft 365 bypass events, which cannot be SSL/TLS inspected for various reasons. These domains are not exposed as they are subject to change, and the percentage of traffic automatically SSL/TLS bypassed is relatively small (less than 1%). [zia.ssl-inspection.rules:zscaler-exception-list] A predefined rule automatically exempts known destinations that cannot be SSL/TLS inspected when it is enabled. To inspect certain domains from the exempted list, an inspection rule is created with a higher rule order; the page says to disable the predefined rule for SSL/TLS inspecting all domains. Transactions not SSL/TLS inspected or blocked after an inspection can be found under the SSL/TLS Policy Reason filter in Web Insights Logs. [zia.ssl-inspection.rules:zscaler-exception-handling]

Criteria are in [SSL/TLS inspection rule criteria and the ones that silently don't match](kb:zia.ssl-inspection.criteria), actions in [What an SSL/TLS inspection action does: Inspect, Do Not Inspect, Block and their settings](kb:zia.ssl-inspection.actions), and exemption design in [Writing SSL/TLS inspection exemptions without exempting too much](kb:zia.ssl-inspection.exemptions).
