# Network applications and network application groups: DPI identification, undetermined-app outcomes, rule placement (zia.firewall.network-applications)
Also called: network application; network application group; DPI application identification; Allow due to insufficient app data; Blocked by Web Proxy Policy

Network applications are predefined applications maintained by Zscaler from Layer 7 information. The service identifies them dynamically with Deep Packet Inspection (DPI), controls their traffic with Firewall Filtering rules to allow or block it, and lets them be grouped but not edited or deleted. [zia.firewall.network-applications:definition] A network application's Category is the classification that groups it into a specific category. [zia.firewall.network-applications:category-attribute] Advanced Firewall is required to identify and control network application traffic using DPI. [zia.firewall.network-applications:dpi-licensing]

**How identification works.** Network service and application service rule conditions match on the first packet, whereas DPI often needs more than one packet of traffic directed to the destination to be allowed and assessed before it can determine the network application. [zia.firewall.network-applications:dpi-multi-packet] If DPI cannot determine the network application after examining sufficient data, the Firewall module matches the assessed packets to a policy action, based on Firewall rule evaluation at the base protocol (TCP or UDP), the encryption protocol (SSL/TLS) or the high-level protocol (HTTP or HTTPS). [zia.firewall.network-applications:dpi-undetermined] The meaning of sufficient data is open [gap:zia.firewall.network-applications:sufficient-data].

**Two logged outcomes.** If the DPI session terminates unexpectedly (for example non-gracefully, without a FIN or RST) before the application is determined, the transactions for the allowed packets are logged with the Allow due to insufficient app data action, assuming no higher-ranked Firewall rule blocked the base, encryption or high-level protocol first. [zia.firewall.network-applications:allow-insufficient-data] If the DPI session terminates because a web policy (for example URL Filtering or Cloud App Control) blocked the traffic, the Firewall module logs the transaction with an implicit rule, Blocked by Web Proxy Policy. Sessions are logged individually with Full Logging and the Block/Drop action in Firewall Insights Logs, and their full details are in Web Insights Logs. [zia.firewall.network-applications:blocked-by-web-policy] Which log value carries the first outcome is open [gap:zia.firewall.network-applications:insufficient-data-log-value].

**Rule placement.** Zscaler advises placing a rule whose only condition is network applications in a lower order than rules where a first packet match is possible, keeping first-packet block rules at a higher order than network-application rules, and combining network applications in a higher-order rule with other conditions such as users, network services and destination IP addresses. [zia.firewall.network-applications:placement-advice] What higher and lower order mean in rule numbers is open [gap:zia.firewall.network-applications:order-direction].

**Groups.** Zscaler provides a predefined Microsoft Office 365 network application group that is ready to use in policies. [zia.firewall.network-applications:o365-group] A network application group combines predefined network applications into logical groups reusable across Firewall Filtering rules to allow or block traffic. An organization can create up to 126 groups, each holding up to 8,000 network applications, and a group's description cannot exceed 10,240 characters. [zia.firewall.network-applications:group-object] The members of the Microsoft Office 365 group are open [gap:zia.firewall.network-applications:o365-members].
