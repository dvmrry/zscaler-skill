# Performance runbook isolation tests: manual proxy, direct access, Trust Portal and speed tests (zia.troubleshooting.performance-runbook.isolation-tests)
Also called: manual proxy test; direct access test; speedtest poor result

**Manual proxy and direct access.** To compare Z-Tunnel 2.0 with PAC or a manual proxy, the runbook's manual proxy test finds the connected data center at ip.zscaler.com, logs out of Client Connector, finds the FQDN of the data center's PAC VIP at config.zscaler.com, sets the manual proxy under the browser's Internet Options > Connections > LAN Settings to that FQDN on port 80/443 with the IdP authentication domains bypassed, and visits an HTTP site to complete cookie authentication. [zia.troubleshooting.performance-runbook.isolation-tests:manual-proxy-test] For a specific destination, the runbook tests an affected user on a non-Zscaler network such as guest Wi-Fi or a mobile hotspot; if loading is normal directly, it collects a Wireshark capture, a browser header trace and an MTR to the destination. [zia.troubleshooting.performance-runbook.isolation-tests:direct-access-test] For a specific destination and for all destinations, if loading is slow with direct access, the runbook says to involve the destination's webmaster. [zia.troubleshooting.performance-runbook.isolation-tests:direct-access-slow]

**Trust Portal.** For a specific destination, the runbook checks the Trust Portal for open cloud incidents on the domain or data center; if an incident post is active, it checks whether the affected website works through a different data center, and suggests redirecting or bypassing the traffic by PAC or policy based routing change. [zia.troubleshooting.performance-runbook.isolation-tests:trust-portal-specific-destination] For all destinations, the runbook's incident check is headed Check for Any Active Cloud Incidents on Zscaler Admin Console and its text says to check for open incidents for the affected domain or data center on Trust Portal; if an incident post is active, it checks whether a different data center improves performance and performs traffic failover per the forwarding method. [zia.troubleshooting.performance-runbook.isolation-tests:trust-portal-all-destinations]

**Speed tests.** The runbook says Speedtest results alone are insufficient to determine a performance issue; if there is an actual impact on end user performance it goes to the Zscaler Public Data Center section, and if users have no significant day-to-day issues even with low Speedtest results their actual performance is likely unaffected. [zia.troubleshooting.performance-runbook.isolation-tests:speedtest-not-sufficient] The runbook recommends the Zscaler Cloud Performance Test Tool over Speedtest or iperf; its indicators include a map view, latency, jitter and packet loss, and the More Diagnostics tab compares Client Connector and direct speeds for Z-Tunnel 2.0 only. [zia.troubleshooting.performance-runbook.isolation-tests:cloud-performance-test] The runbook says even the Zscaler speed test does not guarantee a subscribed bandwidth: bandwidth is typically shared, so a 50 Mbps link does not mean the test returns 50 Mbps. [zia.troubleshooting.performance-runbook.isolation-tests:speedtest-bandwidth-shared] The runbook suggests using Windows Task Manager's Performance tab on the active network connection while downloading several large files from different servers, and comparing Send and Receive throughput with and without Zscaler. [zia.troubleshooting.performance-runbook.isolation-tests:task-manager-throughput] [gap:zia.troubleshooting.performance-runbook.isolation-tests:manual-proxy-port]
