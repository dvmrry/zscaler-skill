# Which engine blocked the file, and what a Sandbox verdict means (zia.sandbox.verdicts)
Also called: blocked by sandbox vs malware protection vs atp; blocked policy type; sandbox says benign but file is blocked; benign verdict

"ZIA blocked my file" has three candidate engines, and the first question is which one logged the block. The Blocked Policy Type field in Web Insights logs identifies which security control is responsible for a block: Sandbox, Malware Protection, or Advanced Threat Protection. The log also carries Policy Action and Threat Super Category. [zia.sandbox.verdicts:blocked-policy-type] Only the Sandbox case has an API investigation path. For a Sandbox block the investigation is API-driven: take the file's MD5 hash, if available from the Web Insights logs, and fetch its Sandbox report, check the quota, the blocked-hash list and the hash count. The tools are the report, quota, behavioral-analysis and file-hash-count calls. [zia.sandbox.verdicts:sandbox-row] The report side is in [Sandbox reports, quota, and trusting report content](kb:zia.sandbox.report). The MCP server has no tool to investigate a Malware Protection or ATP block: its guidance for those two policy types is advisory, and a transaction is attributed through Web Insights logs. The SDKs expose Malware Protection and ATP only as policy settings and lists, not per-transaction verdicts. [zia.sandbox.verdicts:mp-atp-no-transaction-api] The Python SDK exposes Malware Protection (`malware_protection_policy`) as get/update pairs for the malware policy, malware inspection, malware protocols and malware settings, and ATP (`atp_policy`) as get/update settings plus security-exception and malicious-URL list calls. None returns a per-transaction verdict. [zia.sandbox.verdicts:mp-atp-python-surfaces] Their policy configuration is covered in [ZIA Malware Protection](kb:zia.malware-protection) and [ZIA Advanced Threat Protection](kb:zia.atp); the console diagnosis workflow is [Diagnosing a Malware Protection or ATP block from the logs](kb:zia.atp.block-diagnosis).

**Classification.** A Sandbox report's Classification type is MALICIOUS, SUSPICIOUS or BENIGN. MALICIOUS means the block is expected; BENIGN means Sandbox should not be the blocker and the investigation moves to other policies; SUSPICIOUS calls for reading the behavioral indicators in the full report. [zia.sandbox.verdicts:classification-types] In the web Insights Logs Sandbox filter, one category is a catchall for any non-malicious file sample with a Sandbox Threat Score equal to or less than 70, the service calls samples scoring between 40 and 70 suspicious because they might need additional review, Sandbox Suspicious is for files that exhibit some malicious behaviors but are not fully classified as malware, and Sent for Analysis is for unknown results sent to the Sandbox for behavioral analysis. [zia.sandbox.verdicts:sandbox-filter-results] The Sandbox Verdict Insights Logs are in [ZIA Insights Logs: log families, time frame, export and background queries, filters and console-only columns](kb:zia.insights.logs).

**Web Insights columns.** In the Web Insights Sandbox logs, Policy Action records what the Sandbox engine did: Sent to Analysis (sent for behavioral analysis and the user can download), Quarantined (sent for analysis and the user cannot download until it completes) or Blocked (blocked immediately because of a previous Sandbox analysis of a known MD5). [zia.sandbox.verdicts:web-insights-policy-action] The Threat Category column shows Benign, Sandbox Adware, Sandbox Anonymizer, Sandbox Malware or Sent for Analysis; when a file sent for analysis is classified malicious, the new category is appended (for example Sent for Analysis - Sandbox Malware/Anonymizer/Adware). [zia.sandbox.verdicts:web-insights-threat-category] The column lists fewer malicious categories than the rule criterion offers [gap:zia.sandbox.verdicts:threat-category-values]. Threat Name gives the exact malware name (for example Trojan.Zbot) or the malware category from observed behavior. With Advanced Sandbox the MD5 value opens the Sandbox Detail Report. Suspicious Content shows the file's raw Page Risk Index score, set to 100 if the file is blocked for other security reasons. [zia.sandbox.verdicts:web-insights-threat-name-md5-suspicious] The two columns spell the unknown-file label differently [gap:zia.sandbox.verdicts:sent-label-spelling].

A BENIGN Sandbox verdict covers only Sandbox. A file Sandbox cleared can still be blocked by Malware Protection, ATP or File Type Control, and URL Filtering can block before Sandbox is reached. The source's first suspects for a block under a BENIGN verdict are Malware Protection and ATP. [zia.sandbox.verdicts:benign-not-clean] Eligibility, meaning whether Sandbox saw the file at all, is in [What Sandbox analyzes and why a file may not be](kb:zia.sandbox.coverage); URL Filtering order is in [ZIA URL Filtering](kb:zia.url-filtering).

What to check:
1. Which engine logged the block, from the Blocked Policy Type in the logged transaction.
2. Whether the MD5 in the same log line is used to fetch the Sandbox report, for a Sandbox block.
3. Whether the report's classification is MALICIOUS, SUSPICIOUS or BENIGN before deciding what blocked the file.
