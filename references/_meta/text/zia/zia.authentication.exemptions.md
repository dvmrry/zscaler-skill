# Destinations that skip authentication (zia.authentication.exemptions)
Also called: exemptedUrls; authSettings/exemptedUrls; zia_auth_settings_urls; auth_bypass_urls; auth_bypass_apps; auth_bypass_url_categories; kerberos_bypass_urls; digest_auth_bypass_urls; basic_bypass_apps; basic_bypass_url_categories; authentication exemption; cookie authentication exempt list

There are two layers of exemption, and they are managed in different places.

**The URL-level list.** The URL-level exempt list is read at GET /authSettings/exemptedUrls and changed with POST /authSettings/exemptedUrls, which requires an action query parameter of ADD_TO_LIST or REMOVE_FROM_LIST. It lists URLs exempted from cookie authentication. [zia.authentication.exemptions:exempt-list-endpoint] The Python SDK adds or removes exempt URLs with a POST to `/authSettings/exemptedUrls?action=ADD_TO_LIST` or `REMOVE_FROM_LIST` carrying `{"urls": [...]}`, then sleeps 2 seconds and returns a fresh `get_exempted_urls()` read, not the POST response. [zia.authentication.exemptions:python-exempt-list-refetch] The spec text for the list's own field disagrees with the endpoint [divergence:zia.authentication.exemptions:exempt-list-description]. Exempted URL Categories are a global exemption and the Exempted URLs list is a local one; traffic to either is marked against the location, not the user. [zia.authentication.exemptions:global-exempt-categories]

**Through Terraform.** The zia_auth_settings_urls resource holds the whole list in one urls set capped at 25,000 items in the schema; its delete is a no-op. Changing the list reads the current list, then adds and removes the differences in separate calls. [zia.authentication.exemptions:tf-list-resource] Updating it reads the current list, then adds and removes the differences in separate calls, so a failure between them leaves the list half-changed: [ZIA Terraform operations that take several API writes with no rollback](kb:zia.terraform.multi-step-writes).

**Capacity.** The product's 25K limit for custom URLs and TLDs is one pool shared across custom URL categories, Auth Exemption URLs in Advanced settings, blocked malicious URLs, SSL inspection blocked URLs, FTP allowed URLs and bandwidth class domains; duplicates count once, and more can be subscribed to. [zia.authentication.exemptions:shared-url-pool] The 25,000 items the Terraform schema allows in the exempted-URL list is the size of the whole shared custom URL pool, so unless the pool is extended by subscription, this list alone cannot use that many when other custom URL lists are populated. [zia.authentication.exemptions:schema-cap-exceeds-pool-share]

**Per-method exemptions in advanced settings.** Advanced settings carry exemptions per authentication method, each as lists of custom URLs, cloud applications and URL categories: cookie authentication (auth_bypass_urls, auth_bypass_apps, auth_bypass_url_categories), Kerberos (kerberos_bypass_urls, kerberos_bypass_apps, kerberos_bypass_url_categories), Digest (digest_auth_bypass_urls, digest_auth_bypass_apps, digest_auth_bypass_url_categories), and Basic (basic_bypass_apps, basic_bypass_url_categories; there is no Basic URL list). [zia.authentication.exemptions:bypass-by-method] The service can exempt specific URL categories, URLs, cloud app categories or specific cloud apps from cookie authentication, Kerberos authentication and digest authentication; for Basic authentication and JSON Web Token (JWT) authentication it can exempt specific URL categories, cloud app categories or specific cloud apps. For Basic, the page says specific URLs can be exempted by adding them to a custom category and exempting the category. For Basic and JWT, the page says the feature is not enabled by default and to contact the Zscaler Account team to have it enabled. [zia.authentication.exemptions:per-method-console] For the cookie authentication exemptions, by default up to 64 custom categories can be added to Exempted URL Categories and up to 25K custom URLs (across all categories) to Exempted URLs. For item lists, up to 500 items can be viewed on a page, the list can be filtered by searching, and the first 25K items (Remove 25K Items) or only items from a specific page (Remove Page) can be removed, with a confirmation window. [zia.authentication.exemptions:exemption-list-limits] The page that holds these sections is routed in [ZIA Advanced Settings page: its sections, three settings explained here, and where other sections are routed](kb:zia.advanced-settings). Category-based exemptions rely on category membership, which is covered in [ZIA URL Filtering](kb:zia.url-filtering) and the category subjects it links.

Traffic that skips the challenge is attributed to the location: [What happens to traffic with no user identity](kb:zia.authentication.unauthenticated-traffic).

**Why a destination is exempted.** Some client applications and websites do not support cookie-based authentication or do not respond when the service sends an HTTP 307 redirect to authenticate the browser; the article's example is that the AIM client application and some Microsoft 365 applications do not respond to the redirect. The article suggests tools like Fiddler or Wireshark to find the URL the application or website is trying to access. [zia.authentication.exemptions:why-exempt] The console's Authentication Exemptions section has Exempted URL Categories (URL categories exempted from cookie authentication), Exempted URLs (URLs exempted from cookie authentication) and Exempted Applications (cloud applications or cloud application categories exempted from cookie authentication). [zia.authentication.exemptions:console-exempt-lists] The URL exemption configuration applies only to traffic originating from known locations configured in the Admin Console, excluding locations created with the dedicated proxy port. For authentication exemptions to work with dedicated-proxy-port locations, unauthenticated users must authenticate and authenticated users must first visit a website that does not bypass authentication or SSL inspection. The PAC-file exception is likewise applicable only to traffic generated from a known location. [zia.authentication.exemptions:known-location-scope]

**PAC file alternative.** If adding URLs to the authentication exemptions list in the Admin Console is not feasible, the article says the PAC file can be edited to add an exception; its example returns "PROXY ${GATEWAY}:9480; PROXY ${SECONDARY_GATEWAY}:9480; DIRECT" for the hosts it lists. [zia.authentication.exemptions:pac-exemption-example]

What to check:
1. Whether the client is at a known location and not at a dedicated-proxy-port location, since the console URL exemption applies only to known-location traffic.
2. Which method challenged the request, and which of that method's lists covers the destination.
3. Whether the destination matches the list by URL, app or category, since category exemptions depend on category membership.
