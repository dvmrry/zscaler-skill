# The vzen command line for configuring and troubleshooting a Virtual Service Edge (zia.virtual-service-edge.troubleshooting)
Also called: vzen cli; vzen status; vzen troubleshoot connection; vzen collect-diagnostics; vzen test-firewall; vzen dump-config; vse troubleshooting commands; vse remote support

The troubleshooting page lists the commands run within the VM console. By default root login is not permitted, so admins use sudo. The page documents `sudo vzen start sme` to start the Virtual Service Edge instance, `sudo vzen start smlb` to start the load balancer service, `sudo vzen halt` to shut down the operating system, `sudo vzen enable-autostart` to start the service automatically after a reboot, and `sudo vzen cleanup` to remove a previous installation. [zia.virtual-service-edge.troubleshooting:service-control]

**Reading state.** `sudo vzen dump-config` displays the cloud name, the primary DNS IP, and the management and service IPs with the default gateway for each. `sudo vzen checkversion` displays the update server's IP address, the installed software version and the latest available version. `sudo vzen status` displays running or stopped with a PID for the Central Directory Service Client (CDSC), and running or stopped with a PID for an LB cluster and not installed for a standalone LB. [zia.virtual-service-edge.troubleshooting:config-and-version] `sudo vzen troubleshoot connection` probes the connection for some time and displays one of three statuses for cloud-config, log-stream, SMBA (if configured) and LB status: Stable (the connections are stable); Suspicious (at least one disconnection to the Zscaler Central Authority in the last two hours, for which the page says to contact Zscaler Support); or Not present (no connectivity). `sudo vzen troubleshoot netstat listen` shows the ports on which the Zscaler services listen. [zia.virtual-service-edge.troubleshooting:connection-status]

**Network checks.** `sudo vzen test-firewall` probes the active firewall configuration by attempting to resolve DNS names and establishing outbound connections to the Zscaler cloud, and the page says to run it on the ESXi console to avoid SSH connection disruption. The TCP connectivity test, `sudo ZSINSTANCE=/sc/sme/ /sc/sme/bin/smmgr -ys host=<Domain Name> -ys port=80 -ys waittime=15 -ys connect=tcp`, reports "Failed to resolve" if the domain name is invalid and "Connection timed out" if the TCP connection is not established. [zia.virtual-service-edge.troubleshooting:firewall-and-tcp-tests] The page gives commands to ping a public IP address, show the Virtual Service Edge interface status, view its route table and ARP table, show active connections on the service IP address, and show all interfaces in the VM. [zia.virtual-service-edge.troubleshooting:network-inspection]

**For Support.** `sudo vzen collect-diagnostics` collects configuration, vital health statistics and error statistics into a local .tgz file in the /sc/sme/log/ folder, which the page says to email to Zscaler Support. The logs to share with Support are zscaler.log in /sc/sme/log/ and /sc/smlb/log/ and autoupgrade.log in /sc/update/log/. An admin can request remote assistance so Zscaler Support logs in to the instance without opening a firewall connection for inbound traffic; the feature is disabled by default and must be enabled explicitly for the duration required. [zia.virtual-service-edge.troubleshooting:diagnostics-for-support]
