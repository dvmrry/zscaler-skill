# HTTP CONNECT tunnel control and the domain fronting blocks in Advanced Settings (zia.advanced-settings.http-tunnel-control)
Also called: HTTP Tunnel Control; Inspect Tunneled HTTP Traffic; Block Tunneling to Non-HTTP/HTTPS Ports; Block Non-RFC Compliant HTTP Traffic on HTTP/HTTPS Ports; Block Domain Fronting; Block CONNECT Host and SNI Mismatch

A client can send an HTTP CONNECT method request to establish a tunnel connection to a remote server through the Zscaler service, which then tunnels the traffic to the destination server on behalf of the client. The HTTP CONNECT method is typically used to initiate an SSL/TLS connection, but it can be used for tunneling purposes. [zia.advanced-settings.http-tunnel-control:connect-tunnels]

**The three tunnel options.** Inspect Tunneled HTTP Traffic, enabled by default, lets the service enforce configured policies on tunneled HTTP traffic sent via a CONNECT request: for example, with it enabled and a CONNECT request to www.cnn.com:80, the service applies the configured web policies to the HTTP traffic it forwards to www.cnn.com. With it disabled, the service does not apply the policies to that traffic. [zia.advanced-settings.http-tunnel-control:inspect-tunneled-http] Block Tunneling to Non-HTTP/HTTPS Ports, enabled by default, lets the service restrict HTTP CONNECT requests to the standard ports 80 and 443. Disabling it allows CONNECT requests to non-standard ports in addition to 80 and 443: for example, a CONNECT request for SSH to port 22 is allowed when it is disabled. [zia.advanced-settings.http-tunnel-control:block-non-http-ports] Block Non-RFC Compliant HTTP Traffic on HTTP/HTTPS Ports, disabled by default, lets the service block traffic that is not compliant with HTTP RFC standards: for example, binary traffic or other non-RFC compliant traffic such as HTTP/0.9 is blocked through ports 80 and 443. Disabling it allows non-RFC compliant traffic over HTTP/HTTPS ports. [zia.advanced-settings.http-tunnel-control:block-non-rfc]

**Domain fronting blocks.** Block Domain Fronting lets the service block HTTP or HTTPS transactions that have an FQDN mismatch between the request URL and the request's host header, or between the SNI (Server Name Indication) and the inner request's host header. The service does not consider it a mismatch if either of the fields (host header and FQDN URL, or host header and SNI) is empty. URL Category Exemptions and Exempted Cloud Applications for Block Domain Fronting can be configured. [zia.advanced-settings.http-tunnel-control:block-domain-fronting] Block CONNECT Host and SNI Mismatch blocks forward proxy connections where the CONNECT host does not match the SSL/TLS client hello SNI; on a mismatch, the SNI is logged into the URL web log field and the CONNECT host into the Domain fronted host header web log field. URL Category Exemptions and Exempted Cloud Applications for it can be configured. Where an upstream proxy puts the IP into the CONNECT host name received by Zscaler, that results in a mismatch and the traffic is blocked; the page says that in this case you can enable the Prefer SNI over CONNECT Host for DNS option. [zia.advanced-settings.http-tunnel-control:connect-sni-mismatch] The related DNS option is in [DNS optimization: proxy-side DNS lookup that overrides the client-resolved IP](kb:zia.advanced-settings.dns-optimization).

The settings page is routed in [ZIA Advanced Settings page: its sections, three settings explained here, and where other sections are routed](kb:zia.advanced-settings); the API fields and the log fields are in [Advanced settings: SNI handling lists and a misdocumented global SSL bypass setting](kb:zia.api.advanced-settings-wire) and [Value encodings and caveats of ZIA web log fields](kb:zia.logs.web-field-semantics).

What to check:
1. Whether Block Tunneling to Non-HTTP/HTTPS Ports is on before explaining a refused CONNECT to a port other than 80 or 443.
2. Whether an upstream proxy puts an IP address in the CONNECT host before explaining a CONNECT host and SNI mismatch block.
