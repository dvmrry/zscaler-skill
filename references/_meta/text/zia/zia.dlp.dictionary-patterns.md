# Custom Patterns & Phrases dictionaries: pattern syntax, phrase matching, match types and sub-dictionaries (zia.dlp.dictionary-patterns)
Also called: dlp regex syntax; custom dictionary pattern; dlp phrase matching; match any patterns and any phrases; near not near proximity; dlp sub-dictionary; parent dictionary; lookaround dlp pattern; count unique

Custom phrases and alphanumeric patterns can be added as a standalone custom dictionary, one of the kinds alongside EDM index templates, IDM index templates and MIP labels. [zia.dlp.dictionary-patterns:what-it-is] The dictionary kinds and the predefined and clone model are in [DLP dictionaries: predefined, cloned and custom](kb:zia.dlp.dictionaries).

**Patterns.** A custom dictionary can contain up to 8 patterns, each at most 256 bytes, and the tokens (?i and ?-i) switch case-insensitive matching. [zia.dlp.dictionary-patterns:pattern-limits] Patterns use POSIX ERE metacharacters. The table marks . [] [^ ] ^ $ * ? + and | supported; capture groups are not supported (parentheses may bound subexpressions) and capture-group references (\n) are not supported. For {m,n}, Zscaler recommends a range as small as possible on the most specific preceding characters, and a range that is too wide might not be accepted. [zia.dlp.dictionary-patterns:pattern-metacharacters] The shorthand classes \d, \D, \s, \S, \w, \W and \b are listed as supported; \s matches a single horizontal whitespace character on one line (a space or tab), and \w matches ASCII word characters [a–zA–Z0–9_]. [zia.dlp.dictionary-patterns:pattern-shorthand-classes] A repeat of an expression that itself contains a repeat (*, +, ? or {m,n}) is supported, and patterns no longer need to begin with a base token (a simple alphanumeric sequence of known length). [zia.dlp.dictionary-patterns:nested-repeats-and-base-tokens] A custom dictionary whose patterns use lookaround constructs (zero-length assertions) must use the Match Any Patterns and Any Phrases match type and have at least one phrase. [zia.dlp.dictionary-patterns:lookaround-requirements]

**Count actions.** The action the dictionary takes on detecting valid matches of a pattern or phrase is either Count All, which counts every match, including identical ones, toward the match count, or Count Unique, which counts each unique match once regardless of how many times it appears. [zia.dlp.dictionary-patterns:count-actions]

**Phrases.** A custom dictionary can contain up to 512 phrases, each 3 to 128 bytes. Phrase matching is not case-sensitive and ignores punctuation. The page says quotes around a phrase make the dictionary detect only phrases that exactly match it in the order given, yet its own example says “security service” matches “security-service,” and “security,service,”, so how exact a quoted match is stays open. [zia.dlp.dictionary-patterns:phrase-limits-and-matching] The service matches phrases fuzzily so that capitalization or spacing differences and noise words (such as spurious words or HTML tags) between words do not hide them. When that causes false positives, quotes or double quotes around the words disable fuzzy matching so only the phrase within the quotes matches, with different types of whitespace between the words ignored. [zia.dlp.dictionary-patterns:fuzzy-matching] Whether a quoted phrase still matches across punctuation is open [gap:zia.dlp.dictionary-patterns:fuzzy-quoted-example]. A checkbox (Non-delimited Unicode Phrase matching in the Add DLP Dictionary window) lets Unicode phrases match when they are adjacent to other characters with no delimiter between them. [zia.dlp.dictionary-patterns:unicode-non-delimited]

**Match types and proximity.** A Patterns & Phrases dictionary has a Match Type. Match Any (the default) triggers when any one pattern or phrase matches; Match All triggers when all patterns and phrases match; Match Any Patterns and Any Phrases triggers on any one pattern plus any one phrase and needs at least one of each to match; Match Near or Not Near Phrases triggers when phrases from two groups appear near or not near each other. [zia.dlp.dictionary-patterns:match-types] Proximity applies only to the Match Any Patterns and Any Phrases and Match Near or Not Near Phrases match types. Near defaults to 0 bytes and accepts up to 10,000 bytes; Not Near requires 1 to 10,000 bytes; Proximity Length takes 0 to 10,000 bytes, where 0 disables it. [zia.dlp.dictionary-patterns:proximity-for-match-types] How the help's four match types map to the API's `customPhraseMatchType` is open [gap:zia.dlp.dictionary-patterns:match-type-wire-form]. The size of the Near and Not Near phrase groups is open [gap:zia.dlp.dictionary-patterns:near-group-limits].

**Parent and sub-dictionaries.** Patterns and Phrases dictionaries can be parent dictionaries or sub-dictionaries, with one level of nesting (a sub-dictionary cannot be a parent) and up to 63 sub-dictionaries per parent; neither can be cloned. A parent may hold patterns or phrases or be left blank as a container, each sub-dictionary needs at least one pattern or phrase, and a sub-dictionary is added to an existing Patterns and Phrases dictionary. Parent dictionaries and sub-dictionaries are not supported for Endpoint DLP. [zia.dlp.dictionary-patterns:parent-and-sub-dictionaries] How an engine evaluates them is in [When an engine uses a parent dictionary a sub-dictionary can also be selected, and must be when the parent has no patterns or phrases. Parent and sub-dictionaries in an engine are evaluated separately and can match independently; sub-dictionaries appear in brackets in the expression.](kb:zia.dlp.engines:parent-sub-in-engines).

What to check:
1. Whether a pattern that uses lookaround is in a dictionary whose Match Type is Match Any Patterns and Any Phrases and that has at least one phrase.
2. Whether a phrase false positive comes from fuzzy matching, which quotes around the phrase turn off.
3. Whether the dictionary is a parent or sub-dictionary when it is meant for Endpoint DLP, which does not support them.
