# ZIA authentication error codes: generic, directory, Kerberos and Identity Proxy (zia.authentication.error-codes)
Also called: authentication error code; Internet & SaaS Authentication Error Codes; error code 471000; kerberos error code; ldap error code; identity proxy error code; 0x1389; 211000; 421000

The Internet & SaaS Authentication Error Codes page has a table of codes the Zscaler service displays when user authentication fails, a table of codes it displays when it can't authenticate a user, Kerberos codes shown on an error page when Kerberos authentication fails, and Identity Proxy codes displayed when the service provider's (cloud app's) authentication requests fail. [zia.authentication.error-codes:tables-on-page]

**Generic codes.** Code 211000 occurs when gateway-redirected traffic is forwarded from a location where authentication is disabled; the page says to check whether the gateway-redirected traffic and the actual traffic have different routing. Code 421000 occurs when the organization information extracted from the user cookie does not match the organization's DPPC port used for forwarding; the page says to clear the cookies and try again, and if the error persists to export logs and contact Zscaler Support. [zia.authentication.error-codes:generic-codes]

**Directory codes.** Code 100 (ldapsearch could not be done) is an invalid LDAP filter, fixed by checking the filter syntax in the Admin Console and that the same filter works with ldapsearch. Code 103 (user not found on the LDAP servers) is a failed ldapsearch for the user, which can use email or username depending on advanced search status; code 112 is a problem with the advanced search filter used for logins; for both the page says to check that a manual ldapsearch returns users with the same query or filter. Code 113 (user not in the list of synchronized users) is fixed by synchronizing the user data and retrying. [zia.authentication.error-codes:dir-search-and-sync-list] Code 101 is an incorrect login password, fixed by correcting the password. Code 105 (error performing a Bind with the user's credentials) means the DN might be invalid, fixed by checking that a manual Bind works with the same credentials. Code 110 (LDAP Bind failed) means the admin's LDAP Bind password might be wrong, fixed by checking it. Code 104 (the user's DN could not be found) is the user's DN not being readable due to LDAP library issues, and the page says to consult the LDAP admin. [zia.authentication.error-codes:dir-bind-and-password] Codes 102 (the server closed the LDAP connection unexpectedly; "This should only be a transient error"), 114 (connection to the directory server reset) and 115 (an admin activated new configuration settings in the Admin Console) are each fixed by retrying. Code 111 is an internal error and the page says to retry or contact Zscaler Support. [zia.authentication.error-codes:dir-connection-and-config] Codes 106 (internal error) and 116 (login failed, the user was deleted) both occur when a deleted user tries to log in; the page says to check whether the user is in the list of synchronized users and to synchronize the users (116: synchronize the user data and retry). [zia.authentication.error-codes:dir-deleted-user] Code 108 (LDAP context not found) occurs when a user in a second directory tries to log in with no secondary LDAP configuration; the page says Zscaler must unset flags in the database for secondary users or do a sync-preview sync once for the organization. Code 109 occurs when a user tries to log in during synchronization, and the page says to wait until the synchronization is completed. [zia.authentication.error-codes:dir-secondary-and-sync-running]

**Kerberos codes.** Code 391000 is a generic "page cannot load" error (contact Zscaler Support). Codes 441000 and 461000 mean the user was deleted or cannot be found in the registered domain (add the user). Code 451000 means the realm is not a registered domain on the Zscaler service (contact Zscaler Support to add the realm). [zia.authentication.error-codes:krb-simple-codes] Code 471000 means the proxy authorization header does not contain the encoded Kerberos ticket, which the page says in almost all cases means NTLM was used. Occurrence 1: traffic went to the Public Service Edge IP address with the default Zscaler PAC file instead of the Kerberos PAC file, fixed by using the Kerberos PAC file. Occurrence 2: the user's computer lacks the GPO updates, the domain controller lacks them, or the user is not logged in to the domain, with a traffic capture showing no query to the domain controller for the Zscaler ticket; the fix is to verify the registry settings, the domain controller's GPO configuration and the domain login. [zia.authentication.error-codes:krb-471000-pac-and-gpo] For code 471000, occurrence 3 is AES encryption not enabled in the realm trust on the domain controller (a capture shows ETYPE_NOSUPP errors), fixed by selecting the AES option in the trust. Occurrence 4 is a realm trust that is not configured or was configured with an incorrect password (a capture shows PRINCIPAL_UNKNOWN): check the realm name is in upper case and the Zscaler cloud name is correct, otherwise regenerate the trust password in the Admin Console, delete the trust on the domain controller and create a new one. Occurrence 5 is the user's computer being unable to connect to the domain controller (after clearing tickets and refreshing the browser, no Kerberos tickets are listed, including the domain controller's); for a DirectAccess user the page gives a command to see whether the client considers the workstation inside or outside the intranet. [zia.authentication.error-codes:krb-471000-trust-and-connectivity] Code 48100 (as printed) is an invalid encoding of Kerberos credentials, possibly header corruption by an intermediate proxy or L7 device (contact Zscaler Support). Codes 491000 and 501000 are an invalid Kerberos token or username: occurrence 1 is an incorrect computer time (ensure it is correct and synchronizes with an NTP server, since Kerberos is very sensitive to clocks being in sync), occurrence 2 is other issues (contact Zscaler Support). Code 510000 means the login name exceeds the maximum allowed characters (contact Zscaler Support). [zia.authentication.error-codes:krb-token-and-name] A standalone Internet & SaaS Error Codes for Kerberos Authentication page opens by saying the Zscaler service displays a page with an error code if Kerberos authentication fails, and has rows for codes 391000, 441000 and 461000, 451000, 471000 (Occurrence 1), 48100 (printed with five digits) and 510000. [zia.authentication.error-codes:kerberos-standalone-page] Code 48100 is printed with five digits [gap:zia.authentication.error-codes:printed-forms]. The deployment and trust facts behind these causes are in [Deploying and troubleshooting Kerberos authentication: ports, location behavior, trust, GPO and ticket checks](kb:zia.authentication.kerberos).

**Identity Proxy codes.** The Identity Proxy table is owned by [Zscaler Identity Proxy: Zscaler as the SAML IdP for cloud apps, unmanaged-device actions and its error codes](kb:zia.authentication.identity-proxy).

What to check:
1. Which table the code belongs to (generic, directory, Kerberos or Identity Proxy), then the row for that exact code.
2. For a Kerberos 471000, which of the five occurrences matches the symptoms in the traffic capture or ticket listing.
