# Runbook: SSL Policy Reason values and what causes each (zia.troubleshooting-runbook.ssl-policy-reasons)
Also called: SSL Policy Reason Runbook; Not Inspected because of mutual TLS authentication; Not inspected because of Zscaler best practices; Zscaler Service Domains reason; HSM error reason

**Mutual TLS.** Zscaler does not support mutual TLS authentication for decryption, so a Service Edge cannot decrypt a transaction when the remote server requires client certificates; if inspection is required and undecryptable traffic is set to block, these transactions are blocked. [zia.troubleshooting-runbook.ssl-policy-reasons:mtls-not-decrypted] For a trusted domain, an SSL Inspection rule with Block Undecryptable Traffic disabled lets transactions needing a client certificate go uninspected and be allowed. [zia.troubleshooting-runbook.ssl-policy-reasons:mtls-allow]

**UCaaS One Click.** Enabling a UCaaS One Click option creates a predefined SSL Inspection rule with action Do Not Inspect for the corresponding destinations; the page names Zoom, GoTo, RingCentral and Webex as the UCaaS vendors. [zia.troubleshooting-runbook.ssl-policy-reasons:ucaas-bypass] A UCaaS One Click Rule is also created automatically in Firewall Control and DNS Control (to allow traffic) and in Cloud App Control under the Collaboration & Online Meetings category. [zia.troubleshooting-runbook.ssl-policy-reasons:ucaas-other-rules] Disabling the UCaaS option removes the automatically created rules; to retain the One Click options while enforcing SSL Inspection on some transactions, the page says to order more specific SSL Inspection rules above the UCaaS One Click rule. [zia.troubleshooting-runbook.ssl-policy-reasons:ucaas-solutions]

**Microsoft 365 Bypass.** The runbook's Not Inspected Because of Microsoft 365 Bypass section covers URLs not inspected because of a Microsoft 365 bypass; with One Click configuration enabled (by default), Microsoft 365 traffic is optimized through the Zscaler systems and bypasses SSL inspection and preauthentication layers. [zia.troubleshooting-runbook.ssl-policy-reasons:m365-bypass] Enabling the Microsoft-recommended One Click configuration automatically creates an SSL Inspection policy that identifies Microsoft 365 web traffic (based on REST API) and bypasses SSL Inspection (and authentication); other Zscaler policies are also bypassed for this traffic. [zia.troubleshooting-runbook.ssl-policy-reasons:m365-one-click-rule] To have Microsoft 365 application traffic inspected, the runbook says to disable the One Click rule or change the SSL Inspection policy order; to use Tenant Restriction with One Click enabled, create an SSL Inspection rule for Microsoft Login Services with a rule order higher than the Office 365 One Click Rule. [zia.troubleshooting-runbook.ssl-policy-reasons:m365-solutions] The One Click option itself is in [Microsoft 365 One Click configurations: the two options, where each is set, and the DNS Control rule](kb:zia.advanced-settings.m365-one-click).

**Undecryptable traffic.** The policy action for transactions logged Not Inspected Because of Undecryptable Traffic is controlled by the Block Undecryptable Traffic option in the SSL Inspection Policy. [zia.troubleshooting-runbook.ssl-policy-reasons:undecryptable-reason-control]

**Zscaler best practices.** Transactions to the predefined URL category Zscaler-Recommended Exemptions are not inspected; the category holds a few dozen trusted destinations that cannot be SSL inspected for reasons such as certificate pinning, and the matching traffic is commonly under 1%. [zia.troubleshooting-runbook.ssl-policy-reasons:best-practices-category] Zscaler recommends not inspecting these domains, but the rule can be disabled with Edit, or left enabled with higher-order Inspect rules for specific domains outside the list. [zia.troubleshooting-runbook.ssl-policy-reasons:best-practices-solutions] The web logs can be searched with the SSL Policy Reason field for the reason Not inspected because of Zscaler best practices. [zia.troubleshooting-runbook.ssl-policy-reasons:best-practices-search]

**Service domains and HSM.** The Zscaler Service Domains reason means the transaction went to domains Zscaler owns, covering service domains used for control plane traffic; Zscaler strongly recommends against inspecting such traffic. [zia.troubleshooting-runbook.ssl-policy-reasons:service-domains] The HSM error reason indicates a problem with the Hardware Security Module during SSL inspection; it is rare, typically caused by API errors, and recurring cases should go to Zscaler Support with the Web Insights logs. [zia.troubleshooting-runbook.ssl-policy-reasons:hsm-error]

**SSL policy.** The runbook writes the reason as Not Inspected because of SSL Policy, logged when an SSL Inspection rule has action Do Not Inspect; changes to the default Zscaler Recommended Exemptions rule can also produce it, and the SSL Policy Name column identifies the rule. The Web Insights filter lists the value as Not inspected because of SSL/TLS policy. [zia.troubleshooting-runbook.ssl-policy-reasons:ssl-policy-reason-do-not-inspect] To inspect transactions bypassed by an SSL policy rule, add an Inspect rule with more specific criteria just above the rule shown in the Web Insights logs. [zia.troubleshooting-runbook.ssl-policy-reasons:ssl-policy-reason-inspect-above] The filter values are listed in [Value encodings and caveats of ZIA web log fields](kb:zia.logs.web-field-semantics); whether the logged field matches them is open [gap:zia.troubleshooting-runbook.ssl-policy-reasons:logged-value-spelling].

Not known (open gaps):
