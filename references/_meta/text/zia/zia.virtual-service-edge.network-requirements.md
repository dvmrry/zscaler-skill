# Addresses, interfaces, outbound connectivity and ports for a Virtual Service Edge (zia.virtual-service-edge.network-requirements)
Also called: vse ip addresses; vse proxy ip; vse management ip; vse lb ip; vse outbound firewall; vse port 443; vse enable-stdport; vse ipv6; vse nat; vse hub ips
Former IDs: zia-37

**Interfaces and addresses.** Each VM has 3 network interfaces (management, the Virtual Service Edge, and the load balancer). They should be on the same VLAN, which should be accessible by user traffic and have outbound internet access. [zia.virtual-service-edge.network-requirements:three-interfaces] The management IP address is used for SSH to the VM and to download Virtual Service Edge builds; the proxy IP address carries proxied traffic and the outbound control connection, is used for the load balancer's health monitoring, and listens for user traffic in a standalone; the load balancer IP address makes an outbound control connection and receives initial user requests; the cluster IP address provides fault tolerance and listens for user traffic. The proxy, load balancer and cluster addresses must be in the same subnet or VLAN. The load balancer and cluster addresses are not required for a standalone. [zia.virtual-service-edge.network-requirements:four-address-roles] Cluster-level fields are in [The Virtual Service Edge cluster: limits, object, build order and Location binding](kb:zia.virtual-service-edge.clusters); the API names are in [The vZEN API: Virtual Service Edge clusters and nodes](kb:zia.virtual-service-edge.api-surface).

**Reaching the Zscaler cloud.** Virtual Service Edges require only outbound connections to the Zscaler cloud. The firewall must allow the outbound connections on the Virtual Service Edge config page (config.zscaler.com/<Zscaler Cloud Name>/zia-v-sedge) and access to and from the IP addresses on the Zscaler Hub IP Addresses page (config.zscaler.com/<Zscaler Cloud Name>/hubs). [zia.virtual-service-edge.network-requirements:outbound-only] By default the Virtual Service Edge communicates with the Zscaler cloud on ports 9422, 9431 and 9442. `sudo vzen enable-stdport` with the subcommand ca, cds, smsm or all moves authentication and policy retrieval, network-configuration download, log transmission to Nanolog, or all three to port 443; the Virtual Service Edge must then be restarted and the firewall changed to allow outbound only on port 443. [zia.virtual-service-edge.network-requirements:default-ports-and-443] The Virtual Service Edge cluster configuration article tells the reader to view the firewall requirements at config.zscaler.com/<Zscaler Cloud Name>/fcr, a different address from the Virtual Service Edge config page (config.zscaler.com/<Zscaler Cloud Name>/zia-v-sedge) that its own port-443 section and the About Virtual Service Edges article name. [zia.virtual-service-edge.network-requirements:cluster-article-firewall-page]

**The port 443 switch, reversed.** The Nutanix page gives `vzen disable-stdport`, whose ca subcommand prevents the Virtual Service Edge from authenticating and retrieving policy on port 443. The page says that if a standard port is enabled a stable Virtual Service Edge or LB connection exists, and uses `sockstat | grep smcdsc` to check. [zia.virtual-service-edge.network-requirements:disable-stdport]

**IPv6.** Virtual Service Edges support IPv6 traffic only if it is forwarded through IPSec or GRE tunnels, and IPv6 is enabled and configured for the organization through Zscaler Support. [zia.virtual-service-edge.network-requirements:ipv6-tunnel-only] The forwarding page names GRE alone [divergence:zia.virtual-service-edge.network-requirements:ipv6-gre-only]. The hardware form factor has different, native IPv6 options: [Addresses, NAT, IPv6 and ports a Private Service Edge needs](kb:zia.private-service-edge.ip-requirements).

**Dual-arm layouts.** The dual arm configuration is for an environment that requires Virtual Service Edges to use two zones, a disconnected network or an isolated internet zone from the internal users, and another that faces the internet. The page has three deployments: standalone mode with external or no load balancer, cluster mode with user traffic on one arm, and cluster mode with user traffic on both arms. [zia.virtual-service-edge.network-requirements:dual-arm-purpose] In the dual arm standalone deployment the internal-facing proxy IP address (em1) is entered in the Proxy IP Address field with Standalone as the Deployment Mode, em2 is the internet-facing Proxy interface configured in /sc/sme/conf/vzen_custom.conf, and em3 is not required if em0 is configured to connect to Zscaler cloud nodes. The em0 and em2 interfaces are added to the internet-facing network and em1 and em3 to the internal-facing network, and Zscaler performs ICMP and HTTP monitoring from the switch or vswitch to the Virtual Service Edge. [zia.virtual-service-edge.network-requirements:dual-arm-standalone-interfaces] The dual arm standalone deployment can be tested by connecting to the em2 IP address and port 80, and if smnet_route is configured the server is accessed through the em1 interface. If SSL decryption is enabled the Zscaler root certificate must be installed, authentication can be disabled for servers without federated user identities, and depending on whether the deployment is explicit or transparent VMware-specific parameters such as Promiscuous Mode might be needed. [zia.virtual-service-edge.network-requirements:dual-arm-standalone-behavior] In the dual arm cluster layouts each Virtual Service Edge needs two additional IPs with user traffic on one arm and three additional IPs with user traffic on both arms. For both arms, em4 is the internet-facing LB service interface, used for downloading policies and uploading logs from the Zscaler Central Authority, and the configuration sets ifconfig_em4="down promisc" and ifconfig_em2="down promisc". If internal users are not on the same VLAN as the internal network, reverse routes must be added, and the new interfaces' VLAN mapping is checked by MAC address because the order might differ on the VM. [zia.virtual-service-edge.network-requirements:dual-arm-cluster-layouts] Forwarding to the cluster is in [Sending traffic to a Virtual Service Edge: GRE, PAC, L2 redirect, home users and Kerberos host names](kb:zia.virtual-service-edge.forwarding).

**NAT.** Whether a Virtual Service Edge can sit behind 1:1 static NAT is open [gap:zia.virtual-service-edge.network-requirements:vse-nat-topology].

What to check:
1. Which Zscaler cloud the tenant is on, so the outbound firewall pages are read for that cloud.
2. Read both published firewall pages for the tenant's cloud, the Virtual Service Edge config page and the fcr page.

Sources disagree (name both sides):
- Whether Virtual Service Edge IPv6 traffic is supported over GRE only, or over IPSec or GRE tunnels. [divergence:zia.virtual-service-edge.network-requirements:ipv6-gre-only]
  - zscaler-help: The cluster configuration article says IPv6 traffic is supported if forwarded via IPSec or GRE tunnels.
  - zscaler-help: The Nutanix page repeats the IPSec or GRE statement.
  - zscaler-help: The forwarding page says IPv6 traffic is supported if it is only forwarded via GRE tunnels.
  Impact: Whether IPv6 over an IPSec tunnel to a Virtual Service Edge is supported depends on which page is followed; the pages do not say which governs.

Not known (open gaps):
- Whether a Virtual Service Edge can sit behind 1:1 static NAT [gap:zia.virtual-service-edge.network-requirements:vse-nat-topology]: settled by source-read or support-ticket
