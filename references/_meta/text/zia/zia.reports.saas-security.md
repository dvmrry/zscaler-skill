# SaaS Security report pages: SaaS Assets Summary, Assets and Assets with Incidents, Activities, Copilot Readiness Assessment and SaaS Workflows (zia.reports.saas-security)
Also called: saas assets summary report; saas assets report; assets with incidents; saas security activities report; microsoft copilot readiness assessment; saas workflows

These are the report pages for SaaS Security: what was found in connected SaaS applications, and the audit trail of user and admin activity in them. The scan log they drill into is [CASB SaaS Security Insights logs: what the records mean, filtering, export and streaming](kb:zia.casb.insights-logs), and restoring a quarantined file is in [CASB quarantine and tombstone files](kb:zia.casb.quarantine). The report hub is [ZIA reports: which subject describes each report family](kb:zia.reports).

**SaaS Assets Summary Report.** The SaaS Assets Summary Report summarizes SaaS Security discovery and remediation activities and is the starting point for investigating what data is affected and identifying risky users. It shows the past 24 hours by default, or the last 7, 15 or 30 days, or a custom range up to the last 90 days. [zia.reports.saas-security:summary-what] The summary report's application categories are Collaboration (Slack, Webex Teams, Microsoft Teams, Zoom), CRM (Salesforce, Dynamic 365), Email (Exchange, Gmail), File Sharing (Box, OneDrive, SharePoint, ShareFile, Dropbox, Confluence, Smartsheet, Google Drive), Gen AI (ChatGPT), ITSM (ServiceNow, Jira Software, JumpCloud), Source Code Repository (GitHub, GitLab, Bitbucket) and Public Cloud Storage (Amazon S3, Google Cloud Platform, Microsoft Azure); Amazon S3, Google Cloud Platform and Microsoft Azure are enabled by contacting the Zscaler Account team. [zia.reports.saas-security:summary-categories] The summary report defines an incident as a triggered DLP or malware policy, caused when a file is scanned for the first time or when a change in the file violates the policy. [zia.reports.saas-security:incident-definition] The summary report describes unknown_saas_user* as a user who can access the SaaS application but is not added to the Zscaler service. [zia.reports.saas-security:unknown-saas-user] The Risky Cloud SaaS Applications widget shows each application, its category, its threat index, its net usage (GB) and the recommended configuration. [zia.reports.saas-security:risky-apps-widget] The ITSM list differs from the Assets Report's [divergence:zia.reports.saas-security:itsm-apps].

**Assets Report.** The SaaS Assets Report shows the current state of files, email messages and objects, for a chosen application category, over the current day, current week, last 24 hours, last 7 days or a custom range up to the last 90 days. [zia.reports.saas-security:assets-what] On the Assets Report the number of violations in a column is for current scan results, whereas the SaaS Security Insights Logs page shows all scans. [zia.reports.saas-security:assets-current-vs-all] The Assets Report's category lists are collaboration (Slack, Webex Teams, Zoom, Microsoft Teams), CRM (Salesforce, Dynamic 365), email (Exchange, Gmail), file sharing (Box, Confluence, OneDrive, ShareFile, SharePoint, Dropbox, Smartsheet, Google Drive), Gen AI (ChatGPT), ITSM (Jira Software, ServiceNow) and source code repository (GitLab, Bitbucket, GitHub). [zia.reports.saas-security:assets-category-apps] In the Assets Report the exposure of a container is public, private, external or internal, and the exposure of a repository is public or private. [zia.reports.saas-security:assets-exposure-values] The Assets Report's 3rd-Party Integrations tab shows 3rd-Party App Governance data for Slack, Microsoft Teams, OneDrive, SharePoint, Google Drive, Exchange, Gmail, Salesforce and Dynamic 365, with counts of integrations that are potentially harmful or vulnerable, dormant and overprivileged; seeing more information needs an Internet & SaaS (ZIA) super admin and an organization subscribed to 3rd-Party App Governance. [zia.reports.saas-security:assets-3p-tab] The previous-scan option and how long the data is kept are open [gap:zia.reports.saas-security:assets-scan-and-retention].

**Assets with Incidents.** The Assets with Incidents page opens with filters preset to the application or tenant and time frame chosen for further analysis, and lets the user view a Current Scan, a Previous Scan or All Scans. [zia.reports.saas-security:awi-scan-scope] On the Assets with Incidents page, Quarantine or Remove on a collaboration application message or file appears as a separate incident entry with the most current Last Scan Time and the Action updated to the remediation selected, and the Collaboration Scope column is only available for MS Teams. [zia.reports.saas-security:awi-remediation-entry] Restores are covered in [In the File Sharing section of the Assets with Incidents page, Restore restores a quarantined file to its original location, after which subsequent policy scans bypass the restored file until it is modified, and is available only for quarantined files; Restore Admin Quarantine restores a file previously quarantined to the admin-specified location. Elsewhere on the page, restoring a quarantined message or file is for Slack only, and restoring a quarantined malware file to its original location needs the file to have been quarantined with the Quarantine Malware action in the DLP Malware policy and is currently available only for Salesforce.](kb:zia.casb.quarantine:restore-from-assets-report). Remediation actions are not supported for the Smartsheet application. For file sharing, the actions Remove Internal Sharing Links After Expiry, Remove External Sharing Links After Expiry, Remove Collaborators After Expiry and Remove Sharing After Expiry are each currently available only for Google Drive, a manual file expiration date must meet or exceed the original expiration period, and Remove Watermark is not available for image files. [zia.reports.saas-security:awi-file-sharing-actions] A group is classified as an external collaborator group if even one member is an external collaborator, regardless of how many internal members it contains. [zia.reports.saas-security:awi-external-group] A column on the file sharing tab does not populate user details, and another does not populate timeline details, for applications where it is not supported; for Smartsheet only the user who performed the first activity from the time of the file scan is displayed, and for Dropbox only the user who last modified a shared file. [zia.reports.saas-security:awi-last-shared-caveats] For Gen AI applications the remediation action listed on the Assets with Incidents page is View Scan History, which redirects to the SaaS Security Insights Logs page. [zia.reports.saas-security:awi-genai-view-only]

**Activities.** The Activities page is an audit trail of the activities end users and admins perform in SaaS applications, filtered by tenant, user, activity role type and time frame (the last 24 hours, 7, 30 or 90 days, or custom); the Activity filter is currently not supported for Smartsheet, and sync activities apply only to File Sharing applications such as OneDrive and SharePoint. [zia.reports.saas-security:activities-what] The Raw Activities table shows the event time, source location (city and country), source IP and object names and types, and the page's activity filter options include Login Fail, Logout Compromised, Risky Download, Risky Share, Risky Upload and DLP Sensitive Email Sent. [zia.reports.saas-security:activities-columns] Whether the page is the source of the NSS SaaS Security Activity feed is open [gap:zia.reports.saas-security:activities-nss-feed].

**Microsoft Copilot Readiness Assessment.** The Microsoft Copilot Readiness Assessment supports Microsoft SharePoint, Microsoft OneDrive and Microsoft Teams, and Microsoft Exchange is not supported. [zia.reports.saas-security:copilot-apps] The assessment defines a sensitive asset as any document with a DLP dictionary, DLP violation or DLP engine match, and its time range offers Current Day, Current Week, Last 24 Hours, Last 7 Days, Last 15 Days or Custom. [zia.reports.saas-security:copilot-sensitive-asset] For remediation actions on OneDrive, SharePoint and Teams to succeed, the organization's OneDrive, SharePoint and Teams tenants must be onboarded, DLP policies targeting them defined and activated, and active scanning configured and enabled for the onboarded tenants. [zia.reports.saas-security:copilot-prereqs] MIP labels are onboarded two ways on the page [divergence:zia.reports.saas-security:mip-onboarding]. Apply MIP Label applies a Microsoft Purview Information Protection (formerly Microsoft Information Protection) label to Excel, Word, PowerPoint and PDF files within MIP onboarded tenants. [zia.reports.saas-security:copilot-mip-label-files] Bulk actions take a maximum batch size of 1,000 assets and at most 10 bulk remediation jobs in progress at a time; an action on an asset must complete before another is applied to it, and bulk remediation is not supported for assets previously quarantined. Only Report Incident is supported for Microsoft Teams although other actions remain visible in the menu, and remediation is not supported for Teams channels with special characters in their names. [zia.reports.saas-security:copilot-bulk-limits] In the Exposure widget, Org-Wide counts the assets that have an internal shareable link and External Link counts the assets that have external users or an external shareable link, and the widget's internal-collaborator bands are 10-99 users, 100-999 users, more than 1,000 users and 10,000 users or more. Assets Exposed Org-Wide and Assets Exposed Using External Link options are not supported for MS Teams. [zia.reports.saas-security:copilot-exposure] The exposure boundaries differ between its widgets and the drill-down [divergence:zia.reports.saas-security:copilot-exposure-bands]. The View All drill-down of all assets filters exposure by Org-Wide, External Link, <10 Users, 10–99 Users, 100–999 Users, 1000–9999 Users and >=10000 Users, and lists each asset's risk, DLP classification and counts of internal and external collaborators. [zia.reports.saas-security:drilldown-exposure] The Risk column's values are open [gap:zia.reports.saas-security:copilot-risk-values].

**SaaS Workflows.** SaaS Workflows automate routine, manual tasks across SaaS applications, orchestrating actions such as bulk remediation, access and content clean-up and exposure reduction, using predefined rules and logic. A remediation job's Job ID is generated by the bulk remediation action, an in-progress job shows the email address of the admin who created it, and jobs can be searched by part or all of the job ID. [zia.reports.saas-security:workflows-what] Clicking View Logs on a SaaS Workflows job redirects to the SaaS Security Insights Logs page. [zia.reports.saas-security:workflows-logs] Which workflows exist besides remediation jobs, and a job's result values, are open [gap:zia.reports.saas-security:workflows-scope].

What to check:
1. Whether a count in the Assets Report is for the current scan before comparing it with the SaaS Security Insights Logs, which show all scans.
2. Whether the application supports the remediation the question asks about before promising it, since Slack, Salesforce, Google Drive and Smartsheet each differ.
3. Whether the Copilot assessment prerequisites are met and which application the assets are in before reading a failed remediation as a product fault.
4. Which page's exposure boundaries a figure was read from, since the Copilot widgets and drill-down differ.

Sources disagree (name both sides):
- The SaaS Assets Summary Report page lists JumpCloud among its ITSM applications, while the Assets Report page lists only Jira Software and ServiceNow. [divergence:zia.reports.saas-security:itsm-apps]
  - zscaler-help: The summary report's ITSM applications are ServiceNow, Jira Software and JumpCloud.
  - zscaler-help: The Assets Report's ITSM applications are Jira Software and ServiceNow.
  Impact: Whether JumpCloud data appears in the Assets Report is not settled by the two pages, so an answer about ITSM coverage has to name the report.
- The Copilot Readiness Assessment page's widgets and the drill-down page use different exposure boundaries for the 100-999 and 1,000 or more internal-collaborator bands. [divergence:zia.reports.saas-security:copilot-exposure-bands]
  - zscaler-help: The Exposure widget's bands are 100-999 users and more than 1,000 users.
  - zscaler-help: The Top Owners section's bands are 100-1000 and more than 1,000 internal collaborators.
  - zscaler-help: The drill-down's exposure levels are <10, 10–99, 100–999, 1000–9999 and >=10000 users, so its upper bands start at 1000 and 10000 rather than at more than 1,000.
  Impact: A count read from one widget may not match the same band on another page; 1,000 sits in the 100-1000 band on one page and the 1000-9999 band on another, so an answer has to name the page.
- The Copilot Readiness Assessment page says MIP labels can be onboarded by a Zscaler-defined connector or certificate-based authentication, and also says applying labels requires certificate-based authentication. [divergence:zia.reports.saas-security:mip-onboarding]
  - zscaler-help: The prerequisites list onboards MIP labels using either a Zscaler-defined connector or certificate-based authentication.
  - zscaler-help: To apply labels, the MIP labels must first be onboarded using certificate-based authentication.
  Impact: The page does not say whether the connector method covers every remediation action but not applying labels, or whether the two statements conflict, so a label question has to name which action is meant.
