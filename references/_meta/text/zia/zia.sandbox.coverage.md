# What Sandbox analyzes and why a file may not be (zia.sandbox.coverage)
Also called: basic vs advanced sandbox; file not sandboxed; sandbox not analyzing; no active content; sandbox file size limit; sandbox file types

A "why wasn't my file sandboxed" question starts with the tenant's Sandbox tier. Basic Sandbox analyzes only .exe, .dll, .scr, .ocx, .sys and .zip files up to 2 MB. Advanced Sandbox covers all common types including Office, PDF, APK and scripts, up to 20 MB (50 MB for .exe files and archives). [zia.sandbox.coverage:tier-limits] Basic Sandbox has no quarantine, no Patient 0 alerts and no Sandbox report API; its URL category filtering is limited to a subset of categories. [zia.sandbox.coverage:basic-lacks-features] A file whose type or size does not match the subscription level is not analyzed by Sandbox. Files over the size limit are handled by File Type Control instead. [zia.sandbox.coverage:out-of-scope-not-analyzed] A Basic tenant that downloads a `.docx`, or a 3 MB `.exe`, gets no Sandbox analysis for it. Layer attribution is in [Which engine blocked the file, and what a Sandbox verdict means](kb:zia.sandbox.verdicts).

**Pre-checks.** For Office documents and PDFs, ZIA runs static analysis first. A file with no macros, embedded scripts or suspicious objects is classified benign without Sandbox analysis, and Web Insights logs show "Allowed - No Active Content". [zia.sandbox.coverage:static-fast-path] An "Allowed - No Active Content" log entry means the static pre-check found nothing to detonate; it is not evidence that Sandbox analyzed and cleared the file. [zia.sandbox.coverage:no-active-content-reading] A file whose MD5 was already analyzed and classified benign may be passed without re-analysis. [zia.sandbox.coverage:previously-analyzed]

**Default rule.** The vendor's description of what the default rule covers: The default Sandbox rule analyzes Windows executable and library files of 2 MB or less downloaded from suspicious URL categories (including Anonymizer, FileHost, Shareware Download, Web Host and Miscellaneous or Unknown), also when they are inside ZIP archives. A file the service has never seen is allowed and sent to the Sandbox engine; malicious Adware, Malware & Botnets and P2P & Anonymizers files are blocked. [zia.sandbox.coverage:help-default-rule] Advanced Sandbox can scan files larger than 2 MB and lets the admin choose which file types are analyzed. Sandbox supports sizes up to 50 MB for Windows EXEs, Android APKs and archives, and the Advanced Detections package analyzes EXE and DLL files up to 200 MB. [zia.sandbox.coverage:help-size-ceilings] The MCP skill and the help page differ on the Advanced ceiling for some types [divergence:zia.sandbox.coverage:advanced-size-ceiling].

**Decryption.** Cloud Sandbox is among the Zscaler features that depend on SSL inspection to work on encrypted transactions. If a DO_NOT_INSPECT or DO_NOT_DECRYPT SSL rule matches the traffic, Sandbox cannot see the file. [zia.sandbox.coverage:needs-decryption] What a non-decrypting SSL rule leaves in force is in [Where SSL inspection sits in ZIA web policy evaluation (the two passes)](kb:zia.ssl-inspection.pipeline).

The source's order for a file that was not sent to Sandbox is: SSL inspection, file type against tier, file size against tier, static no-active-content pre-check, file already analyzed and cached as benign. [zia.sandbox.coverage:not-analyzed-checklist] Whether SSL inspection is checked before or after the report lookup is open [gap:zia.sandbox.coverage:check-order-vs-report].

**Prerequisites in the help.** Files are sent for sandboxing only if Inspect Inbound Traffic and Inspect Outbound Traffic are enabled in the Malware Protection policy, and SSL/TLS inspection must be enabled for any traffic the Sandbox policy is configured for. [zia.sandbox.coverage:malware-protection-prerequisite] The default-rule page says Sandbox analyzes only downloaded files, which the Private Access upload claim in [If Internet & SaaS inspects Private Access traffic, uploads to Private Access assets are sandboxed when the file is unknown to the service.](kb:zia.sandbox.rules:zpa-uploads) contradicts [divergence:zia.sandbox.coverage:downloads-only].

**File types in the help.** The Sandbox policy page lists these file types a rule can select: 7-Zip, Bzip2, Optical Disc Image, Tape Archive, Roshal Archive, Zip, ZIP with Suspicious Script File, Microsoft Software Installer, Visual Basic Script, Windows Executable, Windows Library, Windows PowerShell Script, Windows Batch File, Microsoft Excel, PowerPoint, RTF and Word, Android Application Package, PDF, Windows Script, Python Source Code, Pickle, Python Dynamic Module, Python Script, Adobe Flash, HTML Application and Java Applet, each with the extensions the page gives. [zia.sandbox.coverage:selectable-file-types] For unknown PDF and Microsoft Office files the service first runs a static analysis for active content: files with active content go to behavioral analysis, and files without it are classified benign and allowed to download. [zia.sandbox.coverage:static-precheck-help]

**Files outside the default rule.** A file that does not match the default Sandbox rule's criteria is allowed to download even if it is malicious. With Standard Sandbox, such an allowed malicious file shows Not Subscribed in the Threat Name column. [zia.sandbox.coverage:outside-default-rule-allowed] What happens on Advanced Sandbox to a file no rule matches is open [gap:zia.sandbox.coverage:advanced-out-of-scope-action].

What to check:
1. Whether the tenant's tier covers the file's type and size.
2. Whether the file was not sent to Sandbox, by walking SSL inspection, file type, file size, the static pre-check and the previously-analyzed MD5, in that order.
3. Whether the SSL rule that matched the source URL is a DO_NOT_INSPECT or DO_NOT_DECRYPT rule.
4. Whether the file was an upload or a download, since the help pages disagree on whether Sandbox analyzes uploads.

Sources disagree (name both sides):
- The MCP skill and the help page give different Advanced size ceilings. [divergence:zia.sandbox.coverage:advanced-size-ceiling]
  - mcp-server: 20 MB generally, 50 MB for .exe files and archives; APK is not in the 50 MB group.
  - zscaler-help: 50 MB for Windows EXEs, Android APKs and archives; no general 20 MB figure; 200 MB with Advanced Detections.
  Impact: A size-limit answer for an APK, or for any type with a limit above 20 MB, depends on which source is used; the 200 MB package tier is absent from the MCP skill.
  Resolved (source-rank) by zia.sandbox.coverage:help-size-ceilings: The vendor help page outranks the MCP skill; the general 20 MB figure for other types remains unconfirmed by help (see gap other-types-ceiling).
- The default-rule help page says Sandbox analyzes only downloaded (inbound) files, while the Sandbox overview says uploads to Private Access assets are sandboxed. [divergence:zia.sandbox.coverage:downloads-only]
  - zscaler-help: Sandbox analyzes only downloaded (inbound) files. The sentence sits on the default-rule page and may describe only that rule, but it is not worded that way.
  - zscaler-help: When Internet & SaaS inspects Private Access traffic, uploads to Private Access assets are sandboxed if the file is unknown (the existing claim zia.sandbox.rules:zpa-uploads).
  Impact: Whether an upload can be sandboxed depends on which page is used; the Malware Protection prerequisite that requires outbound inspection as well is unexplained by the inbound-only sentence.
