# Microsoft Information Protection (MIP) accounts and label retrieval (zia.dlp.mip-labels)
Also called: mip account; microsoft information protection labels; mip label retrieval; sensitivity labels zia; purview labels dlp; validation failed mip; tenant inactive

MIP sensitivity labels are maintained by Microsoft; adding a MIP account in the Admin Console lets the service retrieve them for use in DLP. They let inline web DLP policies detect files tagged with these labels when evaluating transactions, and Data at Rest Scanning policies auto-classify sensitive files. [zia.dlp.mip-labels:what-and-why] Labels are added to a custom dictionary as described in [A MIP-label dictionary needs a MIP account added in the Admin Console and its labels retrieved from Microsoft first. Once saved, its Dictionary Type shows as Microsoft Information Protection (MIP) and cannot be changed; at most 256 labels can be selected per custom dictionary, and deleted labels, including labels deleted on Azure, show with a strikethrough and cannot be selected.](kb:zia.dlp.dictionaries:mip-dictionary-type).

**Adding an account.** The Adding a MIP Account page has the admin choose a SaaS connector: a Zscaler-defined connector grants the Zscaler service full administrator privileges to the application (authorized by signing in to Microsoft and accepting the requested permissions), while a custom connector grants only the necessary permissions and needs permissions configured in Azure to supply a Client ID, Client Secret and Tenant ID. The account name must be unique. [zia.dlp.mip-labels:connector-options] The Copilot Readiness Assessment page names different onboarding options, recorded in [zia.reports.saas-security:mip-onboarding](kb:zia.reports.saas-security:mip-onboarding). The adding page says the MIP account displays Validation Successful if it is authorized and Validation Failed if it is not; a failed account can be reauthorized from the Edit MIP Account window. [zia.dlp.mip-labels:validation-result]

**Statuses and activation.** The MIP Labels page lists each account's label count and status, including when its information was last retrieved from Microsoft. The page's status values are Active (labels are retrieved), Retrieval Pending (fetching in progress; validation succeeded and the account is active), Tenant Inactive (labels are not retrieved), Validation Failed and Validation Success. The page must be refreshed explicitly to show the current state, and an account's labels can be downloaded as a CSV file. [zia.dlp.mip-labels:account-statuses] The adding page says to change the account's status from Validation Successful to Active in the Edit MIP Account window for the service to scan and retrieve labels, and to Tenant Inactive to stop; the retrieving page says to change the account's Label Retrieval field to Activate, and that disabling the field stops retrieval. [zia.dlp.mip-labels:start-stop-retrieval] The status names and the activation control differ between the pages [divergence:zia.dlp.mip-labels:mip-status-and-control]. How Retrieval Pending becomes Active is open [gap:zia.dlp.mip-labels:retrieval-pending-to-active].

**Retrieval.** Labels must be published in Microsoft before they can be retrieved. The first scan and retrieval takes a few minutes, then retrieval runs automatically every 12 hours. Retrieved labels are added to the MIP account and can be used with inline web DLP policies; the labels of the different MIP accounts are shown when configuring an inline web DLP policy. [zia.dlp.mip-labels:retrieval-cadence] What happens in existing dictionaries when a label is deleted in Microsoft is open [gap:zia.dlp.mip-labels:deleted-label-effect], and how Data at Rest Scanning uses labels to auto-classify is open [gap:zia.dlp.mip-labels:dar-classification]. Whether an API object represents the account is open [gap:zia.dlp.mip-labels:api-object].

What to check:
1. Which page the status name or the activation control was read from before telling an admin what to click, since the pages name them differently.
2. Whether the labels are published in Microsoft and the account's labels have been retrieved, before expecting them in a dictionary or an inline web DLP policy.

Sources disagree (name both sides):
- The three MIP pages name the success state and the activation control differently. [divergence:zia.dlp.mip-labels:mip-status-and-control]
  - zscaler-help: The MIP Labels page names the state Validation Success.
  - zscaler-help: The adding page names the state Validation Successful and controls retrieval with the account status, Active to start and Tenant Inactive to stop.
  - zscaler-help: The retrieving page controls retrieval with a Label Retrieval field, Activate to start and disabling it to stop.
  Impact: An admin told which control to use depends on the page followed, and the pages do not say whether the status and the Label Retrieval field are the same control.
