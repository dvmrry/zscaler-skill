# CASB tenants: connecting a SaaS application, states and reauthorization (zia.casb.tenants)
Also called: casb tenant; saas application tenant; casbTenant; reauthorization required; reAuth; validation failed; tenant limit 16; external trusted domains

Tenants are how a SaaS application is connected to Zscaler for scanning. Zscaler Data at Rest Scanning provides visibility and security for the sanctioned SaaS applications used in the organization, and a SaaS application is authorized with Zscaler by adding it as a tenant. [zia.casb.tenants:tenant-authorizes-app]

**Naming and features.** A tenant name must be unique, and it is the name shown when configuring the Data at Rest Scanning DLP policy, the Malware Detection policy, Workflow Automation or Scan Configuration. [zia.casb.tenants:tenant-name-unique] When adding a tenant the administrator selects the functionality to enable, from App Governance, DLP and Malware scanning SaaS API, SSPM Scan, or Workflow Automation, where the application supports it. The /casbTenant/lite filterByFeature parameter filters tenants by feature: CASB, WORKFLOW_AUTOMATION, SSPM, ACTIVITY_REPORT, TP_APP_REPORT, RT_DLP, APP_GOVERNANCE, REDACTION and CASB_ENTITY_GROUP. [zia.casb.tenants:onboarding-features] Choosing DLP and Malware Scanning SaaS API at onboarding asks for a DLP Quarantine Location (a folder path or URL for relocated files) and a DLP Admin Email ID for supported file share applications. [zia.casb.tenants:onboarding-quarantine-location]

**States and reauthorization.** The console shows a tenant as Active (policies are enforced), Inactive (policies are not enforced), Validation Failed (the admin credentials could not be validated or the application authorized) or Reauthorization Required. [zia.casb.tenants:tenant-states] A tenant in Reauthorization Required is fixed by editing the tenant and choosing Reauthorize, which logs in to the SaaS application and gives Zscaler access again; reauthorizing GitHub also requires revoking the existing Zscaler OAuth application authorization in the GitHub portal. [zia.casb.tenants:reauthorize-procedure] A tenant record carries a boolean `reAuth`, documented by the Terraform provider as enabling tenant re-authentication, and a `lastTenantValidationTime`. [zia.casb.tenants:reauth-flag] The tenant validation status endpoint returns a list of states that includes CASB_TENANT_NORMAL_RETHORIZATION and CASB_TENANT_CONNECTOR_RETHORIZATION alongside the active, inactive and validation states, with an error code and message for a failed validation. [zia.casb.tenants:validate-status-states] The validation status response also carries a `tenantAuthorizationInfo` object whose members include credential fields such as `accessToken`, `clientId`, `clientSecret`, `botToken` and `credJson`. [zia.casb.tenants:validate-status-carries-authorization-info] What a tenant in this state does to its scans is open [gap:zia.casb.tenants:reauth-effect].

**Validation error codes.** The tenant validation error codes page lists: 1 and 500, an internal error (retry after a few minutes); 2, validation timed out or was interrupted, with at least one minute needed to validate a tenant; 4, the service is unable to validate the tenant, possibly because of an ongoing release upgrade or a network issue; 201 - 299, serialization of the JSON response failed; 400 - 499, an error authenticating or authorizing the SaaS application (check that the Enterprise ID is valid and the right permissions were given); and 501 - 599, an internal server error from the SaaS application provider. Each says to contact Zscaler Support if the error persists. [zia.casb.tenants:validation-error-codes] The article does not define the other codes or say these are the API's `errorCode` values [gap:zia.casb.tenants:validation-code-ranges].

**ServiceNow object types.** For a ServiceNow tenant the service provides a default list of the most commonly used object types and more can be added; the Default Object Types are those that can be scanned with the Data at Rest Scanning DLP policy. For the additional object types included, the policy scans only the fields specific to description, short_description and close_notes. [zia.casb.tenants:servicenow-object-types]

**Component groups.** For SaaS applications with many component sites, such as SharePoint, groups of sites that share the same DLP policies can be created instead of a policy per site. A group is created under a SaaS Application Tenant and can contain a maximum of 10,000 sites, added manually with Add Sites (select the desired sites from a drop-down list and click Done) or with Import Sites from a CSV file. The Groups tab edits existing groups, and the Components tab lists all sites, tenants and site type by group, with Site Type available only for sites linked to a group. [zia.casb.tenants:component-groups] Which other applications support site groups is open [gap:zia.casb.tenants:component-group-scope].

**Webhook.** The Go SDK's tenant struct carries a boolean `tenantWebhookEnabled`, documented by the Terraform provider as whether the tenant webhook feature is enabled. [zia.casb.tenants:webhook-flag]

**Webex Teams.** For a Webex Teams tenant both onboarding options allow rules for messages, but file attachments need the tenant onboarded for Real-time DLP, and DLP and Malware scanning SaaS API and Real-time DLP cannot be enabled at the same time for the tenant. [zia.casb.tenants:webex-realtime-dlp] Adding Webex Teams as a SaaS application tenant allows the Zscaler service to act as a smart host where Webex Teams can send messages and files for content inspection. Webex Teams messages are managed by web DLP policies and file attachments by Data at Rest Scanning DLP policies, which need SaaS Security scan schedules to inspect content; logs for messages that triggered inline DLP rules are in the Web Insights Logs for Webex, and logs for files that triggered the real-time SaaS Security DLP rules are in the SaaS Security Insights Logs page for Webex. [zia.casb.tenants:webex-realtime-dlp-flow]

**Email tenants.** External trusted domain profiles and external trusted user profiles apply only to email SaaS application tenants. [zia.casb.tenants:trusted-profiles-email-only] For an Exchange tenant, the Zscaler service treats email addresses from the added external trusted domains as trusted, internal users. [zia.casb.tenants:trusted-treated-internal] [gap:zia.casb.tenants:gmail-trusted-domains] The Salesforce custom connector authorization offers trusted domains and user profiles too, which the tenants page limits to email tenants: see [zia.casb.custom-connectors:trusted-profiles-scope](kb:zia.casb.custom-connectors:trusted-profiles-scope).

**Ownership.** A tenant records whether it was created in Internet & SaaS (ZIA) or Digital Experience (ZDX); a tenant created in ZDX cannot be deleted in ZIA, and edits in ZIA to such a tenant are allowed on any field except those relating to Workflow Automation. [zia.casb.tenants:owner-zia-or-zdx]

**Limits.** Up to 16 tenants can be added for each sanctioned SaaS application; Zscaler Support can be asked for an increase. [zia.casb.tenants:tenant-limit-16] Up to 32 external trusted domain and user profiles can be added for each sanctioned SaaS application. [zia.casb.tenants:trusted-profile-limit-32]

**Public cloud storage.** Amazon S3, Google Cloud Platform and Microsoft Azure are enabled for an organization by contacting the Zscaler Account team. [zia.casb.tenants:public-cloud-enablement]

**Creation.** The ZIA OpenAPI document defines only GET operations for CASB tenants (list, scan info, validation status and policy tags), and the Terraform provider exposes the tenant only as a read-only data source, so a tenant cannot be created through the documented API. [zia.casb.tenants:no-create-endpoint]

**Not a Tenant Profile.** A CASB tenant is not a Tenant Profile: tenants are chosen when configuring the Data at Rest Scanning DLP policy, the Malware Detection policy and Scan Configuration, while a tenant profile is associated with a Cloud App Control policy rule. [zia.casb.tenants:not-a-tenant-profile] Tenant Profiles are in [Tenant Profiles: SaaS tenant restriction](kb:zia.tenant-profiles). The tenant list call and its filters are in [CASB API, SDK and Terraform surface](kb:zia.casb.api-surface).

**Open point.** Whether the credential Zscaler holds is wider than scanning needs is open [gap:zia.casb.tenants:oauth-scope].

What to check:
1. Whether the tenant shows Active, or Reauthorization Required or Validation Failed, before assuming a scan or rule is running against it.
2. Whether the tenant the rule names is a CASB tenant and not a Tenant Profile used by Cloud App Control.
3. Whether the application already has 16 tenants when a new one will not add.
4. Whether the question needs what reauthorization does to scans, which no source states.
