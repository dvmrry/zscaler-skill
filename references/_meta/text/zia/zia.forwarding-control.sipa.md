# Source IP Anchoring: what it needs on each side (zia.forwarding-control.sipa)
Also called: source ip anchoring; sipa; app connector source ip; source ip anchor option; sipa client forwarding policy; sipa access policy

Source IP Anchoring sends selected ZIA traffic out through a Private Access App Connector. With Source IP Anchoring the destination sees the IP address of the Private Access App Connector deployed for it as the source. Traffic goes through the intranet to internal destination servers and through the internet to external ones. [zia.forwarding-control.sipa:purpose] Anchored traffic is forwarded to Private Access through the ZIA threat and data protection engines, and Source IP Anchored traffic can also be governed by DLP (with and without content inspection), File Type Control, Firewall Filtering, IPS Control, Sandbox and SSL/TLS Inspection policies. [zia.forwarding-control.sipa:inspected-first] Source IP Anchoring does not need a Private Access license, but a Source IP Anchoring subscription is required. [zia.forwarding-control.sipa:licensing] When Private Access is used solely for Source IP Anchoring, the initial setup still needs company and administrator information, App Connector enrollment certificates (only those are sufficient) and configured App Connectors. [zia.forwarding-control.sipa:pa-solely] Source IP Anchoring does not support RTSP. It supports ICMP only on ICMP-enabled Private Access application segments, only echo requests or responses, not traceroute, with a maximum ICMP payload of 990 bytes. [zia.forwarding-control.sipa:protocol-limits]

1. **ZIA.** A forwarding rule with the ZPA method and a gateway: [Forwarding methods and their required fields](kb:zia.forwarding-control.methods), [The Private Access gateway object in ZIA](kb:zia.forwarding-control.zpa-gateway). To support Source IP Anchoring for Z-Tunnel 1.0 traffic, Enable Firewall for Z-Tunnel 1.0 and PAC Road Warriors must be on in Advanced Settings. [zia.forwarding-control.sipa:ztunnel1-option] Rule scope for remote users: [Forwarding Control rule criteria, limits and ordering](kb:zia.forwarding-control.rules).
2. **Private Access.** On the Private Access application segment, the Source IP Anchor option must be enabled and Use Client Forwarding Policy selected under Bypass. [zia.forwarding-control.sipa:segment-settings] The client forwarding policy needs separate rules for IP-based and domain-based segments. IP-based: the Only Forward Allowed Applications action. Domain-based: Rule 1 Bypass ZPA for all client types except ZIA Service Edge, and Rule 2 Forward to ZPA for only the ZIA Service Edge client type. [zia.forwarding-control.sipa:client-forwarding-policy] The access policy needs separate rules for IP-based and domain-based segments. IP-based: Rule 1 blocks all client types except ZIA Service Edge (preventing application download on Client Connector), and Rule 2 allows only ZIA Service Edge. Domain-based: allow the ZIA Service Edge client type. [zia.forwarding-control.sipa:access-policy] If Source IP Anchoring traffic is restricted to certain users in the Zscaler Admin Console, do not add user-based SAML/SCIM criteria to the access policy for the Source IP Anchoring application segment. [zia.forwarding-control.sipa:no-user-criteria]
3. **DNS.** The ZPA resolver rules for Road Warrior and Locations, their order and enablement: [Predefined DNS Control rules and the ZPA resolvers](kb:zia.dns-control.predefined-rules).

If the ZIA tenant is in disaster recovery, the Private Access side changes: [Source IP Anchoring Direct during ZIA disaster recovery](kb:zia.forwarding-control.sipa-direct). What happens when the gateway's server group has no healthy connectors is open [gap:zia.forwarding-control.sipa:unhealthy-connectors]. Why anchoring is wanted is partly answered by [A fixed egress address: Source IP Anchoring, Dedicated IP or BYOIP](kb:shared.source-ip-anchoring.egress-options); the rest, and where the connector may sit, is open [gap:zia.forwarding-control.sipa:anchor-rationale], and what a segment without the Source IP Anchor option does is open [gap:zia.forwarding-control.sipa:missing-anchor-flag]. Customer-owned addresses are a different feature: [Customer-owned Dedicated IP addresses (BYOIP)](kb:zia.forwarding-control.byoip).

What to check:
1. When anchored traffic leaves from the wrong address or fails, check the three layers in order: the ZIA forwarding rule, the Private Access segment and client forwarding and access policy, then DNS.
