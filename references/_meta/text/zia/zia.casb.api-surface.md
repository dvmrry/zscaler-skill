# CASB API, SDK and Terraform surface (zia.casb.api-surface)
Also called: casbTenant lite; casbTenant scanInfo; casbDlpRules all; zia_casb_dlp_rules; zia_casb_tenant; saas security api sdk; domainProfiles lite; quarantineTombstoneTemplate lite; casbEmailLabel lite

This subject is the API shape of CASB; behavior is in the subjects it points to.

**Tenant calls.** The documented tenant calls are all GET: the tenant list `casbTenant/lite`, scan configuration `casbTenant/scanInfo`, validation status `casbTenant/validate/status/{tenantId}`, and the policy tags `casbTenant/{tenantId}/tags/policy`. [zia.casb.api-surface:tenant-read-endpoints] The tenant list filters use camelCase names (`activeOnly`, `includeDeleted`, `scanConfigTenantsOnly`, `includeBucketReadyS3Tenants`, `filterByFeature`, `appType`, `app`, `page`, `pageSize`), and `activeOnly` defaults to true. [zia.casb.api-surface:tenant-list-filters] The Python SDK documents the tenant filters as snake_case (`active_only`, `scan_config_tenants_only`, `filter_by_feature`) and the Terraform data source takes the same snake_case arguments, while the Go SDK passes the caller's keys through unchanged. [zia.casb.api-surface:snake-case-wrappers] The scan information and tenant policy tags calls page with `page` (default 1) and `pageSize` (default 500); the tenant list declares no defaults, and the Go SDK reads all three through its all-pages helper. [zia.casb.api-surface:scan-info-paging] The Go SDK reads scan information as the tenant name, tenant ID, SaaS application, an integer `scanAction`, and a `scanInfo` object with `cur_scan_start_time`, `prev_scan_end_time` and `scan_reset_num`; the OpenAPI document declares `scanInfo` as an object with no members. [zia.casb.api-surface:scan-info-members] Tenant behavior is in [CASB tenants: connecting a SaaS application, states and reauthorization](kb:zia.casb.tenants) and scan behavior in [CASB scan schedules: states, historical data, stop and restart](kb:zia.casb.scans).

**Rule calls.** Each rule kind has the same endpoint set: create and list at `/casbDlpRules` and `/casbMalwareRules`, list everything at `/all`, and get, update and delete at `/{ruleId}`. [zia.casb.api-surface:rule-endpoints] How `ruleType` scopes them is in [The rule endpoints take `ruleType` as an optional query parameter on list, get and delete. The Go SDK's GetByRuleType, GetByRuleID and Delete each send one ruleType, and the Terraform DLP rule resource reads a rule through GetByRuleID with the rule's type and, on create, lists the rules of the new rule's type through GetByRuleType; the Python SDK requires rule_type to list rules and makes it optional on get and delete.](kb:zia.casb.rule-types:ruletype-scoped-calls). In the Go SDK, `GetByRuleType` and `GetByRuleID` make a single read for one rule type, while `GetAll` pages through `/all` with the all-pages helper; Update sends the rule to the `/%d` rule-ID path with no `ruleType`, and Delete requires the rule type. [zia.casb.api-surface:go-rule-reads] Paging pitfalls for ZIA lists are in [How the Go SDK pages through ZPA, ZCC and ZTC lists, and when it stops early](kb:shared.sdk-go.list-pagination).

**Helper lists.** Three helper lists are `lite` GET operations: domain profiles (`/domainProfiles/lite`), quarantine tombstone templates (`/quarantineTombstoneTemplate/lite`) and CASB email labels (`/casbEmailLabel/lite`). [zia.casb.api-surface:helper-lite-endpoints] The Go SDK reads domain profiles from `/domainProfiles`, which its source comments as publicly available but absent from the swagger, and comments out the `/domainProfiles/lite` endpoint because it misses important attributes. [zia.casb.api-surface:go-domain-profiles-unlisted] The Python SDK reads domain profiles from `/domainProfiles/lite`. [zia.casb.api-surface:python-domain-profiles-lite] The SDKs disagree on which list to read [divergence:zia.casb.api-surface:domain-profiles-endpoint].

**SDKs.** The Python SDK has a client class for each of the DLP rules (`CasbdDlpRulesAPI`), the malware rules (`CasbMalwareRulesAPI`) and the tenant, scan and helper calls (`SaaSSecurityAPI`). [zia.casb.api-surface:python-clients] The enabled-to-state conversion for CASB DLP rules is covered with the other rule modules in [The same `enabled` to `state` conversion on create is also in the Python bandwidth control, cloud firewall filtering, firewall DNS, firewall IPS, forwarding control, file type control, web DLP rule and CASB DLP rule modules.](kb:zia.sdk-python.request-conventions:enabled-to-state-more-modules).

**Terraform.** Terraform has resources `zia_casb_dlp_rules` and `zia_casb_malware_rules`, and read-only data sources `zia_casb_tenant`, `zia_casb_tombstone_template` and `zia_casb_email_label`. [zia.casb.api-surface:terraform-resources] A CASB DLP or malware rule imports with `<RULE_TYPE:RULE_ID>` or `<RULE_TYPE:RULE_NAME>` as the import ID. At v4.8.13 both rule resource pages said a custom rule is removed by pointing Terraform's `-target` flag at it; the v4.8.14 changelog says deleting the rule with `-target` first is no longer needed. [zia.casb.api-surface:terraform-import-and-target] The order, contiguity and predefined-rule constraints are in [Terraform documents `order` for CASB rules as a positive whole number starting at 1 with no gaps; zero and negative values are rejected. At v4.8.10 through v4.8.13 the page said that after deleting a rule the remaining orders must be re-adjusted so the API honours the order; from v4.8.14 it says to renumber the remaining rules so the orders stay contiguous, and that the deletion and the renumbering can be applied together in one `terraform apply`.](kb:zia.casb.dlp-rules:order-contract) and [Terraform documents the same constraints for malware rules as for DLP rules: `order` is a positive whole number starting at 1 with no gaps, and predefined rules can be reordered but not destroyed.](kb:zia.casb.malware-rules:malware-order-contract); the shared registry defect is in [SaaS Security DLP and malware rules still use one registry key and one starting-order scalar each (`casb_dlp_rules`, `casb_malware_rules`), while their callbacks and the SDK list and get functions are scoped by a `ruleType` query parameter taken from the registering rule. Not fixed as of v4.8.17.](kb:zia.terraform.rule-order.registry:casb-rules-one-key-for-all-types), and the field defects in [ZIA Terraform resource fields that are not sent, not read back, or sent wrongly](kb:zia.terraform.field-fidelity).

What to check:
1. Whether a tenant filter uses the API camelCase name when it is written outside Terraform and the Python SDK.
2. Whether a Go SDK rule list for one type is a single read, and use GetAll for the complete set.
3. Whether domain profile attributes came from the lite list or the full list before comparing SDKs.

Sources disagree (name both sides):
- The OpenAPI document and the Python SDK use the domain profile `lite` list; the Go SDK reads `/domainProfiles` instead. [divergence:zia.casb.api-surface:domain-profiles-endpoint]
  - api-specs: Only `/domainProfiles/lite` is documented, and it returns the domain profile summary.
  - sdk-go: The `lite` endpoint misses important attributes, so the SDK reads the full `/domainProfiles` list, which the swagger does not list.
  Impact: A client built from the OpenAPI document sees a smaller domain profile than the Go SDK returns, so profile attributes seen through one are not evidence for the other.
