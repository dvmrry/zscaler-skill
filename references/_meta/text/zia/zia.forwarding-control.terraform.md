# Terraform behavior of ZPA-method forwarding rules (zia.forwarding-control.terraform)
Also called: 60 second delay zpa forwarding rule; no longer an active Source IP Anchored App Segment; forwarding control terraform retry

When a forwarding rule's planned method is ZPA, the provider sleeps 60 seconds before creating it. Up to v4.8.13 its update path also slept 60 seconds before invoking Update; from v4.8.14 the update sleeps 60 seconds, once, inside the step that writes the rule, and an update in which only `order` changed returns without writing, so it does not sleep. The provider's documentation gives the reason as letting ZIA and ZPA synchronize and replicate resource IDs. [zia.forwarding-control.terraform:zpa-delay] A pause of about a minute per ZPA-method rule during an apply is the provider's deliberate 60 second sleep, not by itself a sign of failure. [zia.forwarding-control.terraform:zpa-delay-expected]

For ZPA-method rules, a 400 response containing "is no longer an active Source IP Anchored App Segment" is retried, up to three attempts in all, with a 30 second wait after each failed attempt, on both create and update. [zia.forwarding-control.terraform:zpa-retry] The Private Access side of a persistent failure is in [Source IP Anchoring: what it needs on each side](kb:zia.forwarding-control.sipa).

The delay and retry do not apply to forwarding rules with other methods such as DIRECT. [zia.forwarding-control.terraform:other-methods-unaffected]

Other provider behavior for this resource: required and forbidden fields per method are in [Forwarding methods and their required fields](kb:zia.forwarding-control.methods); predefined rule handling in [Predefined Forwarding Control rules](kb:zia.forwarding-control.predefined-rules); the gateway resource's read workaround in [The Private Access gateway object in ZIA](kb:zia.forwarding-control.zpa-gateway); selectors the provider never sends in [ZIA Terraform resource fields that are not sent, not read back, or sent wrongly](kb:zia.terraform.field-fidelity); order handling in [How the ZIA Terraform provider applies rule order](kb:zia.terraform.rule-order).

Older providers lack the Dedicated IP and GeoIP methods: In the ZIA provider, the `ENATDEDIP` forward method was added to `zia_forwarding_control_rule` in 4.7.0 and its forward method validation was fixed in 4.7.4; the `zia_dedicated_ip_proxy` data source arrived in 4.7.9, and support for the `GEOIP` forward method in 4.7.15. [zia.forwarding-control.terraform:method-version-history]
