# An app's status, risk score, findings and classification in 3rd-Party App Governance (the App Panel) (zia.app-governance.app-risk)

An app's status is Enabled (enabled on the SaaS platform with enabled users assigned), Deleted (differs for each platform), Disabled (differs for each platform) or Not Installed (added to the inventory but not present on the SaaS platform admin console). [zia.app-governance.app-risk:app-status] Deleted means, per platform, Microsoft Azure: deleted from the admin console; Google Workspace: no longer on the platform and user tokens revoked; Slack: the last uninstallation date is later than the last consent date or no users use the app; Okta, GitHub and Salesforce: no entity received from the platform API after a certain threshold; Atlassian: not applicable. [zia.app-governance.app-risk:status-deleted-per-platform] The threshold in that definition is not stated [gap:zia.app-governance.app-risk:deleted-threshold]. Disabled means, per platform, Microsoft Azure: the service principal is disabled; Google Workspace: the users granted access are no longer active; Okta: the core apps are inactive; GitHub: the user account is suspended; Slack, Salesforce and Atlassian: not applicable. [zia.app-governance.app-risk:status-disabled-per-platform] The App Panel is part of the portal in [3rd-Party App Governance: governing third-party apps, add-ons and extensions connected to SaaS platforms, and its portal, roles and dashboard](kb:zia.app-governance).

**Risk score.** The risk score is automatically calculated by the system based on the compounded risk the app poses, app attributes, findings and blast radius, and dismissing or resolving findings can influence it. [zia.app-governance.app-risk:risk-score-basis] The App Panel's table of components used to calculate each app's risk score gives Findings, Permissions, Non-Contextual Findings and Non-Contextual Permissions values of 0.7, 0.3, 0.75 and 0.25 for Google Workspace and Microsoft; 0.7, 0.3, 0.7 and 0.3 for GitHub, Salesforce, ServiceNow, Box, Zoom and Webex; 0.6, 0.4, 0.75 and 0.25 for Slack and Atlassian; 0.6, 0.4, 0.85 and 0.15 for Chrome Extensions; and 0.6, 0.4, 0.5 and 0.5 for Okta. [zia.app-governance.app-risk:risk-score-components] A risk score defined by an admin overrides any future system recalculations, and the admin can revert to the default score. [zia.app-governance.app-risk:risk-score-override] The scale and the way components combine are open [gap:zia.app-governance.app-risk:risk-score-scale]. A Zscaler-verified app can still be malicious or pose a risk due to a compromised publisher, vulnerabilities and overprivileged permissions. [zia.app-governance.app-risk:zscaler-verified]

**Findings.** Each finding has a short background, recommendation, MITRE mappings and a severity level that impacts the app risk score. A finding's status is Unattended (the default for any new finding), Dismissed or Resolved. Updating the status recalculates the app risk score and is recorded as an activity on the Activities tab and in the audit log, and setting the status back to Unattended reverts it to the default. [zia.app-governance.app-risk:findings]

**Classification.** The Classifying Apps page lists Unclassified (the default state of any new application), Sanctioned, Reviewing (under investigation) and Unsanctioned. The classification stays assigned through the app's lifecycle, for example if the app is revoked and a user reinstalls it, and stays the same unless an administrator changes it, which is recorded as an activity. Policies can automatically assign a classification to apps that meet their criteria. [zia.app-governance.app-risk:classification] The dashboard names one value differently [divergence:zia.app-governance.app-risk:classification-reviewing]. Policies can assign it: [3rd-Party App Governance policies and notification channels, including the NSS channel](kb:zia.app-governance.policies).

**The App Panel.** The App Panel shows a blast radius (users with access, accessible services such as Gmail, and the access type such as Broad Data Access), usage details (who first authorized the app and who performed the last activity), a breakdown of the API calls the app generates, a VirusTotal link, activities filterable by User Activity, Security Event, Findings and Threat Insights, and forensics information (seen IP addresses, redirect and login URLs, and an image of the consent screen). Adding notes needs user or admin permissions. [zia.app-governance.app-risk:app-panel-tabs] The App Panel's Details tab describes consent types: Domain wide (granted tenant-wide by the admin) and Individual (granted per user), both supported on Google, and Delegated (the app acts on behalf of the user) and Application (the app acts on its own behalf), both supported on Microsoft. [zia.app-governance.app-risk:consent-types]

Sources disagree (name both sides):
- The Classifying Apps page names the value Reviewing, and the dashboard page describes the classification breakdown with the word reviewed. [divergence:zia.app-governance.app-risk:classification-reviewing]
  - zscaler-help: The classification value is Reviewing.
  - zscaler-help: The dashboard's Apps by Classification breakdown lists unclassified, reviewed, sanctioned or unsanctioned.
  Impact: Neither page says whether Reviewing and reviewed are the same value, so a filter or policy condition on this value should be checked against the console wording.
