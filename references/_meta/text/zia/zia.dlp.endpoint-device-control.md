# Device Control rules per device class, the default rule, first-match evaluation and device control resources (zia.dlp.endpoint-device-control)
Also called: Device Control; device control policy; Nearby Sharing; removable storage rule; printer rule

Administrators can define device control policy rules, which differ from the endpoint DLP rules, for the usage of devices based on criteria such as user, department, endpoint and device. The About page lists removable storage devices, floppy disks (supported on Windows only) and portable (MTP) devices among the classes, and says rules intercept as soon as the device is plugged into the endpoint, even before data is exfiltrated. [zia.dlp.endpoint-device-control:what-and-classes] Device Control includes a default rule whose action, severity, description and end user notifications can be modified. The default rules cannot be deleted but can be edited, and when the default rule is disabled, no other rules are enforced. [zia.dlp.endpoint-device-control:default-rule] Device control rules are evaluated in sequential order starting from rule order 1. If a rule matches, the policy is enforced based on that rule, and if no rules match, the default rule is applied. The printer rule article adds that rule evaluation stops at the first match. [zia.dlp.endpoint-device-control:first-match-evaluation]

**Actions.** The vendor's pages list different actions for Device Control rules [divergence:zia.dlp.endpoint-device-control:action-lists]. The portable device, CD/DVD, floppy disk and nearby sharing rule articles each list Allow or Block as the actions to select for a violation that matches the rule criteria. [zia.dlp.endpoint-device-control:other-class-actions] What None and Read Only mean is open [gap:zia.dlp.endpoint-device-control:none-and-read-only].

**Criteria.** The removable storage, printer and portable device rule articles each state that the rule triggers on [device AND (Users OR User Groups OR Departments) AND (Device OR Device Group) AND Network Type AND Device Trust Level AND User Risk Profile], with Removable Storage, Printers or Portable Devices as the device term. The CD/DVD, floppy disk and nearby sharing articles give the same expression without a device term. The removable storage article says a criterion that is not selected is ignored. [zia.dlp.endpoint-device-control:criteria-logic] The removable storage rule's Network Type selects one or more of Trusted, Off-Trusted or VPN, and the endpoints must run specific Zscaler Client Connector versions for rule enforcement. The removable storage, printer, portable device, CD/DVD, floppy disk and nearby sharing articles each give Windows 4.8.600 or later and macOS 4.7.1 or later. [zia.dlp.endpoint-device-control:network-type-criterion] A printer rule's description cannot exceed 250 characters and its severity is High, Medium, Low or Info. The printer and removable storage articles each say the default rule of that class can be edited but not deleted. [zia.dlp.endpoint-device-control:rule-details-limits]

**Per-class rules.** A removable storage rule's devices can be uploaded from a CSV file up to 50 MB. Each CSV row creates a rule criterion, and when subsequent CSV files are imported under the same rule, new rows are appended and existing criteria are not updated, duplicated or deleted. A device's Serial Number and the Client Connector user's email address each default to Any. [zia.dlp.endpoint-device-control:device-per-user] Nearby Sharing rules can fully block file transfers to nearby devices: on Windows, file transfer over Bluetooth, Nearby Share and Phone Link, and on macOS, AirDrop, Universal Clipboard, iPhone Sync & Mirroring and file transfer over Bluetooth. When Bluetooth is disabled as part of nearby sharing blocking, it applies only to file transfer over Bluetooth and does not block devices such as headphones, keyboards or mice. [zia.dlp.endpoint-device-control:nearby-sharing] Floppy disk rules are only supported for Windows devices. [zia.dlp.endpoint-device-control:floppy-windows-only]

**Resources and activation.** A device control resource's Vendor ID applies to removable storage and portable devices only, and its UNC path applies to printers only. A printer resource takes an IP address or CIDR and a UNC path, and removable storage and portable device resources each take a serial number. [zia.dlp.endpoint-device-control:resources] Whether these are the same objects as the Endpoint DLP resources is open [gap:zia.dlp.endpoint-device-control:two-resource-pages]. Activation of device control rules is covered in [Changes made to device control policy rules, endpoint configurations, and indexed documents must be activated to be enforced. The Activation menu shows the status for Policy, Configuration, and Indexed Documents changes as No Activations Pending (changes activated) or Pending Activation (changes saved but not activated).](kb:zia.dlp.endpoint-settings:activation).

**Related.** Endpoint DLP rules evaluate differently, in [How Endpoint DLP reaches the endpoint: prerequisites, policy delivery, offline enforcement, scans, and what the vendor says about evaluating all rules and exception rules](kb:zia.dlp.endpoint-enforcement); the devices the inventory detects are in [Endpoint inventory and Application Investigation: detected removable storage, printers, portable devices and applications](kb:zia.dlp.endpoint-inventory).

What to check:
1. Which actions a Device Control rule offers for its device class, since the About page and the per-class rule pages list different actions.
2. Whether the default rule is disabled, since no other rules are enforced when it is.
3. Whether the endpoint's Client Connector version supports the Network Type criterion before relying on it.

Sources disagree (name both sides):
- The Device Control About page lists the rule actions as Allow, Block and Read-Only, while the removable storage and printer rule pages add None and the printer page omits Read Only. [divergence:zia.dlp.endpoint-device-control:action-lists]
  - zscaler-help: The action taken when the policy rule is triggered is Allow, Block or Read-Only.
  - zscaler-help: A removable storage rule's action is Allow, Block, Read Only or None.
  - zscaler-help: A printer rule's action is Allow, Block or None.
  Impact: Whether None is a selectable action on every Device Control rule, and whether Read Only exists beyond removable storage, cannot be settled from the pages, which do not agree on the list.
