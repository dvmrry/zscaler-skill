Before deleting a group-like object, the ZTC provider edits the forwarding rules that reference it to drop the object. The helper matches the ZIA one in structure, and so do most of its faults. {{ztc-helper-matches-zia-except-rule-type}} The ZIA version is covered in [[zia.terraform.delete-detach]]; the claims here are quoted from the ZTC code, not inherited. {{helper-callers}} {{helper-label-selects-nothing}}

Which rules are swept. {{helper-sweeps-forwarding-rules-only}} {{rule-types-are-separate-endpoints}} DNS rules reference IP groups too. {{dns-rules-reference-ip-groups}} {{ip-group-delete-follows-detach}} {{ip-group-references-in-dns-rules-not-detached}}

Network service groups sweep a different field. {{service-group-delete-sweeps-nw-application-groups}} {{forwarding-rule-separates-service-groups}} {{service-group-delete-follows-detach}} {{service-group-references-not-detached}} {{service-group-delete-can-strip-unrelated-application-groups}}

Failures hidden for every caller. {{get-failure-skips-update-silently}} {{reread-result-discarded}} {{five-second-sleep-per-rule}} {{update-is-put-of-snapshot}} {{stale-snapshot-put}} {{masked-read-failure-reaches-delete}}

IP pool groups have no detach step at all. {{ip-pool-delete-calls-no-detach}} Whether that matters, and whether DNS forwarding objects ever hold a pool reference, is not shown by the code (gap `ip-pool-references`).

What to check: before destroying a network service group, list the forwarding rules that use it (`nwServiceGroups`) and detach it by hand or in the same plan. Before destroying an IP source or destination group, also list DNS rules that use it (`srcIpGroups`, `destIpGroups`). Before destroying an IP pool group, list every rule or gateway that references it. After a destroy, re-read the rules that used the object rather than trusting a successful apply, and (if the PUT replaces the whole rule, gap `put-semantics`) avoid editing a rule while a destroy is detaching from it. Whether ZTC refuses or accepts a delete with live references is unproven here (gap `in-use-enforcement`), as are ID collisions (`id-namespace`) and stale-PUT handling (`put-semantics`). Protection of predefined rules against deletion is in [[cloud-connector.terraform.rule-protection]]; rule ordering is in [[cloud-connector.terraform.rule-order]].
