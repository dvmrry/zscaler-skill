This subject collects the client-side behavior of the ZTC Terraform provider that is not about rule order: how it configures its SDK client, which arguments it quietly ignores, and where a read or update does something other than what its schema promises. Every claim is about what the provider and the Go SDK send and how they react; what the ZTC API does with it is stated as a gap where it matters.

Configuration builds the client twice, and the SDK makes that expensive. {{configure-builds-client-twice}} {{sdk-construction-authenticates}} {{discarded-client-keeps-renewing}} For token handling inside the SDK see [[shared.sdk-go.auth-lifecycle]]. The advertised concurrency control is not wired in either. {{parallelism-not-enforced}} An operator who lowers `parallelism` to stay under rate limits gets no change in request concurrency from this provider setting.

Text and list arguments are where the provider's own helpers change what Terraform sees. {{multiline-normalizer-doubles-dollar}} {{multiline-diff-suppress-ignores-clears}} {{multiline-helpers-on-nine-resources}} After editing any of those nine resources, check that a removed description is really removed on the server, and that a plan run after applying a description containing `$` comes back clean (gap `dollar-description-diff`). Omitted zero values and empty lists in SDK writes are the broader mechanism behind other clears that cannot be sent; they are in [[shared.sdk-go.zero-value-writes]], not repeated here.

Some arguments are accepted and then ignored. {{dns-rule-zpa-ip-group-dropped}} {{forwarding-rule-no-nw-application-groups}} For the DNS rule, `zpa_ip_group` is accepted by the schema but never sent or read; for the forwarding rule, `NwApplicationGroups` is in the SDK model and the request builder but not in the schema, and is never read. Before relying on a rule created or updated through these resources, read the rule back from the API and compare the ZPA IP group (DNS rules) and the network application groups (forwarding rules) with what you intended.

Reads and updates have their own edge cases. {{forwarding-rule-read-cannot-clear-state}} {{ip-destination-update-gate-wider-than-create}} {{location-read-unguarded-response}} {{location-read-nil-response-reachability}} Update-time list panics and the parking of rules are in [[cloud-connector.terraform.rule-order]]; protection of predefined rules is in [[cloud-connector.terraform.rule-protection]].

Data sources can declare more than they fill. {{location-management-non-editable-never-set}} Do not use that attribute to decide whether a location can be changed. The provider also reports a stale version to the API. {{version-metadata-user-agent}} Match provider behavior to a release by the tag you installed, not by the version in a request log.

The reorder coordinator has one defect that is about synchronization rather than ordering, so it is stated here. {{reorder-done-channel-read-after-unlock}} {{reorder-race-outcomes}} How the coordinator decides what to write, and what it leaves unwritten, is in [[cloud-connector.terraform.rule-order]]; for the open questions on the server side see that subject's gaps.
