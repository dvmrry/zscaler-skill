Installation Guide

Install the Zscaler skill as a source-backed knowledge base, then attach private runtime data without committing tenant material to the public checkout.

Public repo contains
Skill logic, HTML docs, reference notes, verification scripts, and vendored source trees.
Public repo omits
Tenant snapshots, credentials, work-machine runtime data, and private mirror pointers.
Install model
Clone with submodules, register the repo as a skill, then mount runtime data from a private source if tenant-aware answers are needed. The default mount is _data/.
Related
Operator Guide · references/_meta/tooling.md · Data contract · docs/getting-started.md

At a glance

  • Submodules matterThe vendor/ tree carries SDKs, Terraform providers, Ansible modules, MCP code, and captured contract data used for citations and reconciliation.
  • Skill loading is localMost file-based agents load the repo through SKILL.md or a thin runtime adapter that points back to canonical files under agents/.
  • Tenant data is separate_data/ is the default ignored runtime-data mount. Populate it from a private repo, local directory, or sanitized read-only dump; local installs may configure a different mount path.
  • Private mirrors can add pointersInternal forks may know where runtime data lives. The public install guide names the hook point, not the private URL.
§ 1 · Before cloning

Prerequisites

The skill itself is mostly files. The helpers around it need a small toolchain.

Git
Required for the checkout and the vendored submodules.
Node 18+
Required for deterministic helper scripts such as setup-data-mount.mjs and check-data-contract.mjs.
Python 3.10+ and uv
Used by hygiene, citation, and validation scripts. Dependencies install on demand through uv.
A file-based agent runtime
Claude Code-style skill loading is the documented path. Other runtimes can load the portable .agents/skills/ wrappers if they honor SKILL.md-style instructions.
Optional private data source
Needed only for tenant-specific answers. General product behavior works without a runtime-data mount.
Optional zscalerctl companion
Pre-release tenant-observation companion. When installed, it should produce read-only JSON, dumps, or diffs that this skill interprets.
§ 2 · Checkout

Get the skill

Clone recursively so the source-backed references can resolve their citations.

git clone --recursive <fork-or-upstream-url> zscaler-skill
cd zscaler-skill

# If you cloned without --recursive:
git submodule update --init --recursive

# Optional but recommended for contributors:
git config core.hooksPath .githooks
Why recursive clone matters Many reference citations point into vendor/. A bare checkout can still render prose, but audit and reconciliation work becomes misleading because the source files are absent.
§ 3 · Agent loading

Load it in an agent

The public install path uses a local symlink. Internal mirrors may automate this step, but the resulting shape is the same: the runtime can see the skill directory.

mkdir -p ~/.claude/skills
ln -s "$(pwd)" ~/.claude/skills/zscaler

Start a new agent session and confirm the skill appears in the runtime's skill list. The broad entry point is @zscaler; procedural roles such as /z-investigator and /z-soc are thin loaders around canonical workflows under agents/.

LayerPurposeDo not edit as source of truth
agents/Canonical workflow logic and role harnesses.No — this is the source of truth.
.agents/skills/Portable skill wrappers for runtimes that support open skill loaders.Yes, keep them thin.
.claude/, .devin/Runtime adapters and command shims.Yes, adapter files should point back to canonical workflows.
§ 4 · Private mirrors and runtime data

Private mirrors and runtime data

This is the boundary that is easy to misrepresent: the public repo knows how to mount runtime data, but it should not know your private tenant URLs or credential paths.

Intentional omission If an internal mirror carries pointers that let slash commands discover private runtime data automatically, keep those pointers in the private mirror or private runtime configuration. Do not copy private repo URLs, tenant names, secrets, or work-machine paths into the public install guide.

The public shape is:

node scripts/setup-data-mount.mjs \
  --data-url <private-git-url-or-local-path> \
  --data-ref <branch-or-tag> \
  --mode checkout

node scripts/check-data-contract.mjs

An internal mirror can make this nicer with a local zscaler-skill-setup.json that sets runtimeData.mountPath and runtimeData.tracking. Use tracking: "tracked" when the work mirror intentionally commits runtime data directly; use tracking: "ignored" for local-only mounts. If setup needs to clone or copy a runtime-data source, the same config may set runtimeData.source and runtimeData.ref. The public template uses environment variables such as ${ZSCALER_SKILL_RUNTIME_SOURCE} so private URLs stay outside committed docs.

Once the companion CLI is official, the intended provenance model is: zscalerctl is the tenant-observation producer, and the runtime-data mount stores its fast local snapshots and diffs.

§ 5 · Tenant snapshots

Tenant snapshots

Tenant-aware answers require a snapshot or explicit command output. Credentials and live reads are intentionally outside this repo.

Populate out of band.Use a private work mirror, a sanitized export, or read-only zscalerctl output.
Mount runtime data.The expected layout is documented in docs/data-contract/; _data/ is the default mount path.
Validate the contract.Run node scripts/check-data-contract.mjs after mounting.
Ask bounded questions.Name the product, object, cloud, and whether the agent may inspect snapshots only or propose read commands.

Without a snapshot, the skill should still answer general Zscaler behavior, but it should decline tenant-specific truth with a useful next step.

§ 6 · Verify setup

Verify setup

These checks confirm that source files, docs, and optional runtime data are visible.

# Source-backed references can resolve vendor paths.
test -d vendor/zscaler-sdk-go
test -d vendor/terraform-provider-zia

# Optional runtime data is mounted and shaped correctly.
find _data/snapshot -mindepth 1 -type f -print -quit
node scripts/check-data-contract.mjs

# HTML docs have no broken internal links.
./scripts/check-doc-links.py
Preview locally To inspect the HTML docs while editing, run python3 -m http.server 8765 --directory docs, then open http://127.0.0.1:8765/index.html.
§ 7 · Troubleshoot

Troubleshoot install issues

SymptomLikely causeFix
References cite missing vendor/... filesSubmodules were not initialized.Run git submodule update --init --recursive.
Tenant-specific answers decline_data/snapshot/ is empty or not mounted.Mount runtime data and run check-data-contract.mjs.
Skill does not appear in the agent runtimeThe runtime cannot see the skill directory or symlink.Confirm the symlink target exists and restart the agent session.
Commands mention private runtime-data paths that do not existThe instructions came from a private mirror assumption.Replace the placeholder with the local runtime-data source, or use the public manual mount path.
