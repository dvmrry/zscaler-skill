# zscaler-skill v0.19.0

The knowledge base is now a graph of quoted claims, not a set of Markdown docs.

- **v0.18.3:** 261 Markdown files under `references/`.
- **v0.19.0:** 1,687 subjects holding 19,938 claims, built from 4,665 captured help pages and 32 pinned vendor
  sources.
  - 18,846 claims are Tier A: each quotes its source, and `kb.mjs validate` checks every quote against the pinned
    file.
  - 1,049 are Tier B: inferences with their conditions stated.
  - 43 are Tier C: derived from other claims through a stated chain.
  - Where the sources say nothing, the graph records one of 3,094 open gaps. Where they disagree, it records one
    of 988 divergences, instead of picking a side.

Agents enter through a generated spine, one tree per product with typed edges between areas, and read what they
need with `node scripts/kb.mjs read`. The route is the same in Claude Code (`SKILL.md`) and in Devin, Codex, Pi and
Windsurf (`AGENTS.md`, `.devin/rules` or the `@zscaler` loader, then `agents/zscaler/prompt.md`).

## Upgrading from v0.18.3

### Reading the knowledge base

- **The Markdown reference docs are gone.** That is every `references/<product>/*.md` and the portfolio map. A
  link or a generated adapter that names one of them no longer resolves. Agents start at
  `references/_meta/spine/<product>.json` and read subjects, areas, config types or log fields with
  `node scripts/kb.mjs read <id>`.
- **`node scripts/kb.mjs` replaces the old helpers.** Its main commands:
  - `read`, `resolve` and `map` for agents;
  - `surface` and `releases` for the generated layers;
  - `check`, `validate` and `lint` for maintainers.

  `kb.mjs --help` lists them all.
- **The layout is documented** in [`docs/kb-layout.md`](https://github.com/dvmrry/zscaler-skill/blob/v0.19.0/docs/kb-layout.md).
  The record contracts are in `references/_meta/schema/`.

### Company data

- **Company knowledge moved.** It was Markdown under `_data/knowledge/`. It is now the company overlay:
  - JSON records at `_data/overlay/knowledge/<scope>/company.<scope>.<slug>.json`, or under
    `$ZSCALER_KB_OVERLAY`;
  - each record attached to the public claim, subject, type or log field it extends, narrows, contradicts or
    maps;
  - `validateOverlay` checks every record against the public IDs.

  `node scripts/check-data-contract.mjs` warns while old Markdown records remain. See
  [`docs/data-contract/knowledge.md`](https://github.com/dvmrry/zscaler-skill/blob/v0.19.0/docs/data-contract/knowledge.md).
- **`overlay.json` declares which tiers a company has.**
  - IaC repos go under `iac`, each of kind `terraform` (HCL, reported as a file and resource address) or `json`
    (resolved by JSON Pointer).
  - The live read-only tier goes under `live`, through `zscalerctl`.
  - `_data/snapshot/` is no longer read. Tenant state comes from the IaC repos or a live read.
- **The IaC kinds are `terraform` and `json` only.** An overlay from the pre-release trials that declares any
  other kind must change it to `json`. The pointers stay the same.
- **Public IDs can still move before 1.0.** When one does, `validateOverlay` reports
  `about unknown public ID <id>`, and the commit names the move.

### Releases

From this release, each version ships with a notes file in `docs/releases/`, written in the pull request that
releases it. `CHANGELOG.md` keeps the history up to v0.18.3. See
[`docs/release.md`](https://github.com/dvmrry/zscaler-skill/blob/v0.19.0/docs/release.md).

## Generated layers

Four layers are generated from the pinned sources and never hand-edited. Each one's generator has a `--check`
mode that CI runs.

- **API surfaces** (`references/_meta/surfaces/`, 15 products), read with `kb.mjs surface`:
  - each OneAPI path, 905 in all, joined to the Go and Python SDK packages that call it and to 390 Terraform
    resources and data sources;
  - a legacy layer of 1,363 operations from 172 legacy API reference pages;
  - 244 operations that an SDK still calls but the OneAPI spec does not list.
- **Release notes** (`references/_meta/releases/`), read with `kb.mjs releases`: 117 release-note pages, holding
  1,926 releases and 3,586 entries, verbatim.
- **Log types:**
  - 32 NSS and LSS log types (ZIA, ZPA and ZTW), with per-field evidence;
  - the LSS status codes on the ZPA log types;
  - SIEM field mappings that a company overlay can attach.
- **Config types:** 212 tenant object types from the pinned public `zscalerctl` catalogue, with their fields and
  reference edges. Each is joined to its Terraform resource where the provider has one. With the log types that
  makes 5,258 fields.

## Quality and maintenance

- **`kb.mjs check <subject>`** validates and lints the subjects a change touches. `kb.mjs validate` anchors every
  quote in the graph. `scripts/check-full.mjs` is the CI gate.
- **`scripts/claim_audit.py`** asks a model whether each Tier A claim's quotes state the claim, with a calibrated
  rubric. Its record is `references/_meta/claim-audit.json`.
- **`scripts/kb-drift.mjs`** reports, when a pin moves, which claims cite the files that changed.
  `scripts/kb-refresh.mjs` runs the weekly refresh. It refetches the help and issue captures, regenerates the log
  types and records, and writes the drift review. The weekly workflow opens the result as a pull request; Renovate
  moves the submodule pins.
- **`scripts/kb-eval.mjs`** is a retrieval eval run by hand on your own Claude quota, never in CI. It has 18
  questions worded the way people ask, with Haiku 5.5 as the test subject. This release states about 76% of the
  gold facts; v0.18.3 states 53%. See
  [`docs/evals.md`](https://github.com/dvmrry/zscaler-skill/blob/v0.19.0/docs/evals.md).

## Known issues

- **Reading a whole area can return 130–150 KB**, more than a runtime shows inline. Agents then search the saved
  output by the question's words and can miss claims that are in it. Reading the subjects a spine area lists
  works better than reading the area.
- **`kb.mjs read` exits 0 when nothing resolves.** Check its output, not its exit code.
- **Some spine area summaries describe the area loosely**, and the spine has no index from product names to IDs.
  An agent can open a neighbouring area first.
- **The investigator, auditor, SOC, architect and retro workflows** still resolve before they read the spine.
  Ad-hoc questions take the newer route.
