# zscaler-skill v0.20.2

Some ZPA clouds now return a SCIM group's `id` as a string, though the API contract types it as an integer. The
graph now records that mismatch, the Go SDK and ZPA Terraform provider releases that read both forms, and a Go SDK
fix for large IDs that came back rounded. 3 new Tier A claims and 1 divergence, on three subjects. The graph holds
19,948 claims, 3,097 gaps and 990 divergences.

## SCIM group IDs

- **`zpa.api.idp-scim-wire`** has a new divergence. The OpenAPI schema types a SCIM group's `id` as an int64
  integer, but the Go SDK's release notes say some ZPA clouds now return it as a string. A customer saw
  lookups start failing between 9 and 16 November 2026 (terraform-provider-zpa issue #705).
  - Go SDK 3.8.60 reads a SCIM group's `id`, `idpId`, `creationTime` and `modifiedTime` as either a number or a
    number in a string.
- **`zpa.scim.api-surface`:**
  - ZPA provider 4.4.18 fixes `zpa_scim_groups` lookups, and SCIM group conditions in policy rules, on those
    clouds. It also stops rounding large `idp_id` values, and keeps the configured `idp_name` when the API returns
    none.
  - The `group-fields` claim now says the contract types the id as an integer.

## Large IDs in the Go SDK

- **`shared.sdk-go.request-handling`:** before Go SDK 3.8.60, the step that unescapes HTML in `name` and
  `description` read the response as floating-point numbers. So integers above 2^53, such as 18-digit IDs sent as
  JSON numbers, came back rounded. 3.8.60 keeps them exact in the OneAPI client and in the legacy ZPA, ZIA SCIM,
  ZCC, ZDX and ZWA clients.

## Upgrading from v0.20.1

Nothing to change. No public ID was removed, and no command or output changed.
