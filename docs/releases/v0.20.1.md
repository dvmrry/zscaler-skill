# zscaler-skill v0.20.1

The graph now covers the ZIA cloud application API: which calls list applications and tags, what a bulk update
changes, and what the API cannot change. 6 new claims (5 Tier A), 1 open gap and 2 divergences, on three
subjects. The graph holds 19,945 claims, 3,097 gaps and 989 divergences.

## Cloud applications and tags through the API

- **`zia.cloud-app-control.custom-applications`** has a new API section:
  - GET `/cloudApplications/lite` lists predefined and custom cloud applications by ID and name, a page at a time.
  - PUT `/cloudApplications/bulkUpdate` sets the status and custom tags of the applications whose IDs it names. Its
    status values are `UN_SANCTIONED`, `SANCTIONED` and `ANY`. It is rate-limited to 1 call per minute and 4 per
    hour.
  - GET `/customTags` lists the custom tags.
  - GET `/cloudApplications/policy` and `/cloudApplications/sslPolicy` list the applications that policies use.
  - The Go SDK makes the three Shadow IT Report calls from its `shadowitreport` package, and the Python SDK from
    its `shadow_it_report` module. Python's `bulk_update` always sends a status, even when only the tags change.
  - **No call adds a custom application or sets its URLs.** That is done on the SaaS Applications page. This is a
    Tier B claim: it rests on searches of the API reference and both SDKs, which it names.
- **`zia.cloud-app-control.risk-profiles`:** custom tags are listed and assigned through the API. `/customTags`
  has only GET, so the API does not create tags.
- **Open:** whether a bulk update replaces an application's tags or adds to them, and what `ANY` does when set.
- **Divergences:**
  - the Go SDK sends the page parameter as `PageNumber`, but the reference names it `pageNumber`;
  - the Python SDK sends each tag as a string ID with no name, but the reference types the ID as an integer beside
    a name.
