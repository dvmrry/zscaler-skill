# zscaler-skill v0.20.0

Agents now read the public knowledge base as plain files, with their file tools, instead of through a shell
command. On 18 user-worded questions the answers stated the same facts at about a quarter less cost. The one command
an answer still takes, `read --company`, now prints a company's records in order and within a budget, and a second
call reads any record it only listed.

- **v0.19.0:** each subject was read with `node scripts/kb.mjs read`.
- **v0.20.0:** `references/_meta/text/` holds the same reading text as 2,274 Markdown files:
  - 1,705 subject and area files;
  - 244 log and config types;
  - 325 ZPA status codes and ZIA policy reasons, each in its own file.
- **The graph:** 1,687 subjects, 19,939 claims (18,847 Tier A), 3,096 gaps (2,783 still open) and 987
  divergences. Four refreshes since v0.19.0 kept it current with Zscaler's help site: they re-captured 754 changed
  pages and added 14 new ones.

## Reading the knowledge base

- **Subjects are files.** Each subject is at `references/_meta/text/<product>/<subject id>.md`. A log type is at
  `references/_meta/text/types/<type id>.md` with every field, and a pasted error code or policy reason has its own
  file under `references/_meta/text/codes/`. Agents open them with file tools and search the directory for the
  codes and names a user pastes.
- **Each file lists its links as file paths.** These are ranked as `read` follows them, each with the claim behind
  it. 1,397 files add a "Configured via and see also" block that names the edges `read` does not follow. 379 of
  them name the config types that configure the subject, so a change request can open the right type.
- **`kb.mjs read` still works.** It prints the same text, plus the company records when an overlay is configured.
- **Measured on two sets of questions** (2026-11-09, two runs each, paired by question):

  | Question set and route | Facts stated | Total prompt tokens | Cost | Turns |
  |---|---|---:|---:|---:|
  | 18 user-worded questions, Devin route | unchanged | −10% | −25% | +30% |
  | 18 user-worded questions, Claude Code | unchanged | −3% | −26% | +42% |
  | 20 feature-interaction questions, Devin route | −2.2 points (95% CI −6.4 to +1.1) | −4% | −5% | +28% |

  The extra turns are file reads, one per subject. Shell calls fell. The last two fixes to the reading text came
  after these runs and are not measured.

## Company records

`node scripts/kb.mjs read --company <subject | type> ...` prints only the company overlay's records, for the one
call an overlay answer takes beside the text files.

- **What it prints whole:** the records about the named subjects first, then the rest of their areas', then the
  records of the subjects they link to (headed `(linked subject)`), the most strongly linked first, while they fit a
  budget of 4,000 tokens. The rest it lists one line each, and past a second limit names them by ID. It opens with a
  count of what it printed, listed and found cited.
- **Cited records:** a record that a printed record cites by ID or by its file's path is listed too. One that is no
  longer active says whether it was retired, promoted or skipped as invalid.
- **Records by ID:** `read --company <record id> ...` prints those records whole, however the ID was copied: comma
  separated, in brackets or backticks, or as the record's file path. This is the second call: the agent makes it
  only for records its answer needs and the first call did not print. A listed line is not to be used or cited
  on its own.
- **Long IaC values print as a shape.** A value over about 300 characters of JSON prints its length and shape: an
  object its members in key order, with short values whole and the rest by size; an array its length and the items
  that fit; a string its opening. The line says it is a shape and where the whole value is. `resolve` still returns
  whole values.
- **Field maps:** a mapping printed under a subject keeps the fields that subject binds and every field the call
  names, and says how many more it maps. Reading the record by ID shows them all.
- **Faster:** each overlay file is parsed once and each IaC file dated once per command, and listed records are not
  dated at all. An IaC file that isn't JSON now fails only the pointers into it, not the whole overlay.

See [`docs/data-contract/knowledge.md`](https://github.com/dvmrry/zscaler-skill/blob/v0.20.0/docs/data-contract/knowledge.md).

## Upgrading from v0.19.0

- **Refresh copied adapters.** `SKILL.md`, `agents/zscaler/prompt.md`, `AGENTS.md`, `agents/loading-discipline.md`
  and the Devin rule have all changed:
  - they send agents to the text files first;
  - they allow one second `read --company` call, by record ID, for the listed records an answer needs;
  - they open IaC files with file and search tools rather than parsing them in a shell.

  A downstream installation that copies or generates these files needs the new ones.
- **Point IaC pointers narrowly.** Since a long value prints as its shape, a pointer at the part a record is about
  (`.../domain_names`, not the whole rule) shows that part. Existing pointers still work.
- **`read --company` output changed.** It has a count line, new headings and one-line listings. A script that
  parsed it should use `resolve --company`, whose JSON is unchanged.
- **Four public IDs are gone.** An overlay record whose `about` names one now fails `validateOverlay` with
  `about unknown public ID <id>`.

  | Removed ID | Now |
  |---|---|
  | `zia.casb.tenants:trusted-profiles-email-only` | `zia.casb.tenants:trusted-profile-counts`; the tenants page no longer limits trusted domains and users to email tenants |
  | `zidentity.overview.external-idps.integrations:entra-app-count` | `zidentity.overview.external-idps.integrations:entra-provisioning-modes`; the Entra ID guide now configures SCIM on the Gallery app |
  | `zia.casb.custom-connectors:trusted-profiles-scope` (divergence) | removed; the two pages no longer disagree |
  | `identity-protection.alerts:verdict-values-differ` (divergence) | removed; the two verdict lists now agree |

- **Node.** The minimum is still 24.19.0. `.node-version` now follows Node's current release (26.13.0), and a
  separate CI job tests the minimum. The Node 26 Linux binaries need `libatomic.so.1`, which some minimal
  container images lack.

## Changed Zscaler documentation

- **ZCC notification templates:** Zscaler put Modern and Legacy template docs up on 2026-11-10 and reverted them
  to the Windows 4.8 and later text on 2026-11-11. The graph follows the current pages, and an open gap records
  the withdrawn text.
- **ZPA appliances:** the pages now cover a smaller ZS-ZPA-APPL-800 App Connector appliance. Each claim names the
  model it describes.
- **Updated sources:**
  - the ZIA Terraform provider (v4.8.18) and the ZPA provider (v4.4.17);
  - the Python SDK (v1.11.5);
  - the Go SDK, `zscalerctl`, the Splunk SDK and the AWS Cloud Connector templates, each moved to a newer
    commit.

## Known not to work

- A phrase search over `references/_meta/text/` mostly hits other subjects' link lines, because each link line
  repeats the claim behind it.

## For maintainers

- **Refresh:**
  - a daily pass acts on discovery, capturing new help pages and Automate changes;
  - the weekly full pass now checks four pages at a time and fits its 90-minute limit.
- **`kb-reanchor`:** it repairs quotes that a reworded page broke, using a local model.
  - It explains why a quote broke and can anchor a repeated quote to its section.
  - It retries once, covers divergence positions, and checks where each repair landed.
  - On the 2026-11-12 refresh it fixed 68 of 84 broken entries. Its repairs are still reviewed before merge.
- **`kb-eval`:** it judges both JSON output shapes, counts every shell call and takes `--model`.
- **Repo:** `CODEOWNERS` limits merge approval to the owner.
